短い答え — 制約が決まればツールもほぼ決まる

ツール選びは好みの問題に見えますが、制約を二つ確定させるだけで候補は2〜3個に絞れます。第一に、エディタを変えられるか。第二に、支出に上限を掛ける必要があるか。この二つを決めてからモデルの性能を見れば十分です。順序を逆にすると、性能の良いツールを選んだあとで社内承認に止められます。

  • エディタを変えられない → GitHub Copilot、JetBrains AI、Amazon Q Developer。既存のIDEに付きます
  • エディタを変えてよい → Cursor、Devin Desktop、Zed。専用エディタが候補になります
  • ターミナルとCIで動かす → Claude Code、OpenAI Codex CLI、Gemini CLI
  • モデル提供者を自分で選びたい → Cline、Zed、Aider。自前のAPIキーを差す構造です
  • すでにAWS契約があり新規ベンダー登録が面倒 → Amazon Q Developer。既存の請求書に合流します
  • 支出上限が必須 → GitHub Copilotの予算管理と通知、Claude for TeamsとEnterpriseの座席割当と支出上限、Amazon Q Developerの座席定額
  • 月の支出を1ドル単位で読みたい → JetBrains AI。1クレジットが1ドルに固定されており換算が要りません
  • ほぼ費用をかけずに始めたい → Gemini CLIはGoogleアカウントのログインで1日1,000リクエスト、Copilot Freeは月2,000のコード補完、ClineとAiderはツール自体が無料でモデルだけ従量です

ここで答えが出たなら、以降は根拠の確認として読んでください。出なかったなら、5章と7章が判断を作ります。

2026年5月以降に実際に変わったこと

この記事の初版は2026年5月でした。3か月のあいだに料金構造が変わり、ツールが一つ名前を失いました。

WindsurfがDevin Desktopになった

2026年6月2日、CognitionがWindsurfをDevin Desktopとして刷新しました。既存利用者には自動更新で配信され、プランと設定はそのまま維持されます。ローカルエージェントのCascadeは7月1日までで、その後はRustで書き直したDevin Localを使うことになります。刷新の中身は名前ではなく、複数のエージェントをカンバンで管理するAgent Command Centerと、エージェント間でコンテキストを共有するSpacesです。単一エディタからエージェントのオーケストレーターへ性格が移りました。

実務で引っかかるのは自動化です。CIパイプラインやスクリプトからcascadeを直接呼んでいたなら、その呼び出しはすでに切れています。社内wikiにWindsurf時代の文書リンクを貼っていたならdevin.aiへ転送されるので、アンカー文言も合わせて整理が要ります。

GitHub CopilotがプレミアムリクエストからAIクレジットへ移った

以前のCopilotは「Proは月300プレミアムリクエスト」のようにリクエスト数で数えていました。今はプランごとにドル表記のAIクレジットが付きます。Proは月10ドルに15ドル分、Pro+は39ドルに70ドル分、Maxは100ドルに200ドル分です。個人プランにMaxが新設され、BusinessとEnterpriseには組織単位のクレジットプールが付きます。

リクエスト数から金額に変わったのは利用者に有利な変化です。リクエスト数の時代はモデルごとの倍率を知らないと残量が計算できませんでしたが、今は残クレジットがそのまま残額です。ただし高価なモデルを使えば同じリクエストでもクレジットは速く減ります。Copilotのコードレビューには2026年6月1日からモデル倍率13が適用されます。

Cursorの個人プランが3段階になった

月20ドルのProの上にPro Plus 月60ドルとUltra 月200ドルができました。それぞれサードパーティモデルの利用が20ドル分、70ドル分、400ドル分含まれます。Ultraは200ドルで400ドル分を使う構造なので単価では最も有利ですが、それだけ使わなければ200ドルを捨てるだけのプランでもあります。

Copilotの無料・個人プランで学習の既定値が変わった

2026年4月24日から、GitHubはFreeとProの利用者の入力・出力・コード片と関連コンテキストをAIモデルの学習に使えるよう方針を変えました。設定にAllow GitHub to use my data for AI model trainingというトグルがあり、切るのは利用者の役目です。BusinessとEnterpriseの顧客データは学習に使わないと同じ文書が明記しています。個人プランで会社のコードを触る運用があるなら、この一行が導入検討で最初に引っかかります。

クレジットの読み方

JetBrainsの方式がいちばん読みやすいです。1クレジットが1ドルに固定されているので、残クレジットがそのまま残額です。公式文書は1クレジットでできることの目安も示しています。AIチャットでのコード生成が約10回、エディタ内のコード生成が約40回、コード説明が約25回、ドキュメント作成が約280回、コミットメッセージ生成が約140回です。同じ1ドルがコミットメッセージ140個を買い、チャットのコード生成10個を買います。この14倍の差がクレジット課金の本質です。

Copilotもクレジットをドルで表記しますが、モデル倍率が別にあります。文書は各モデルに複雑さと資源消費に応じたプレミアムリクエスト倍率があると説明し、コードレビュー機能には2026年6月1日から倍率13が適用されると明記しました。コードレビューをPRごとに自動で回す設定にすると、クレジットは想定よりはるかに速く枯れます。

ここから出てくる運用の原則は単純です。高い機能は人が明示的に呼んだときだけ動かし、自動トリガーは安い機能にだけ掛ける。これを守らないと、クレジット残量のグラフが月初の一週間で崖のように落ちます。

トークン単価から組織単位の予算まで遡る設計はAIトークン費用を組織単位で統制するで別に扱いました。

この表で分かれる箇所

空欄が多い行ほど、導入後の予算会議で説明しづらくなります。とくにCursorのチーム分析は活動量の指標に寄っていて、支出の内訳は同じ画面にありません。チャット何回、タブ補完何件、AIが書いた行の比率は出るのに、誰がいくら使ったかが同じ場所にない。活動は見えて金は見えない構造なので、超過請求が出たときに原因を人単位で特定しにくくなります。

反対の端がClaude Codeです。/usageがセッションのトークン統計とプラン残量を並べて示し、直近の利用をスキル・サブエージェント・プラグイン・MCPサーバー別に割って比重を表示します。長いコンテキストやキャッシュミスが直近利用の10パーセント以上を占めるとそれも別に示します。組織側はOpenTelemetryでclaude_code.cost.usage(USD)、claude_code.token.usage、claude_code.lines_of_code.countといった指標を自前の監視基盤へ出せます。ベンダーのダッシュボードを待たずに社内Grafanaに開発者別の費用パネルを立てられる唯一の軸です。

公式文書が示す基準線も役に立ちます。企業導入の平均は開発者1人あたり稼働日約13ドル、月150〜250ドルで、利用者の90パーセントは稼働日30ドル未満と書かれています。この数字は見積もりではなくパイロット結果を突き合わせる基準として使うのが正解です。自チームの平均が稼働日40ドルなら使い方に問題があり、5ドルならツールが実際には使われていません。

金額がまったく表示されないツールで費用を自分で測る方法はAIコーディングツールから金額が消えたに手順として整理しました。

コンテキストが費用に変わる区間

エージェント型で費用を膨らませるのはモデルではなく習慣です。Claude Codeの公式文書が挙げる原因は具体的です。

  • 長いセッション。会話全体がリクエストごとに送られるので、一日じゅう開いたセッションで一行の質問をしてもその日の会話全体分の利用が発生します
  • キャッシュミス。キャッシュ寿命を超えて間を空けたあとの最初のメッセージはコンテキスト全体を再処理します。寿命はサブスクリプションで1時間、usage creditsを使い始めると5分、APIキーやクラウド提供者では既定で5分です
  • MCPサーバーの多さ。ツール定義が窓を食います。文書はgh・aws・gcloudのようなCLIツールのほうがMCPサーバーよりコンテキスト効率が良いと勧めています
  • エージェントチーム。メンバーがプランモードで動くとき標準セッションの約7倍のトークンを使います。既定で無効なのはそのためです
  • 大きなコンテキストの圧縮。/compactは要約する会話を読む必要があるので、それ自体が大きなリクエストです。連続性が要らないなら費用0の/clearのほうが良いです

この一覧をチームのオンボーディング文書の最初のページにそのまま貼ると、パイロットの費用は目に見えて下がります。超過支出の多くは難しい作業ではなく消していないセッションから出ます。

パイロット運用の規則

  • 人数は5〜8人。うち半分はツールに懐疑的な人で埋めます。熱心な利用者だけを入れると結果は常に良く出ます
  • 同じ作業を二つのツールでやらせないこと。時間が倍かかるのに比較情報はあまり増えません。ツールごとに違う種類の作業を任せるほうが良いです
  • 1週目が終わったら利用画面をチームに公開します。支出が見えた瞬間に習慣が変わります
  • オンボーディング文書の最初のページに/clear・/compactのようなコンテキスト管理コマンドとモデル選択の基準を書きます
  • エージェントチームや並列実行の機能は2週目に開けます。1週目から開けると費用データが汚れます
  • 終わってから契約するのではなく、パイロット中に上限設定と支出レポートを実際に押してみます。画面があることと使えることは別です
  • パイロットのリポジトリは実際の業務コードにします。サンプルプロジェクトはコンテキストが小さく、費用も品質も実際と違って出ます
  • 最終日の振り返りは指標を先に読み、感想を後に聞きます。順序を変えると印象が数字の解釈を覆います

費用が跳ねる箇所と止め方

予算超過はたいてい劇的な事件ではなく、繰り返される小さな習慣から出ます。症状から原因を引く表のほうが実務では役に立ちます。

症状原因対応
月初の一週間でクレジットが半分高い機能が自動トリガーに掛かっている(コードレビューなど)自動トリガーを切り、人が呼んだときだけ実行。Copilotのコードレビューは倍率13
一行の質問でも利用量が大きく計上されるセッションを消さないので会話全体が毎回送られる作業が変わったら/clear。連続性が要るときだけ/compact
昼食後の最初のリクエストがやけに高いキャッシュ寿命が切れてコンテキスト全体を再処理休憩後は新しいセッションで始めるか、要約から再開する
似た作業なのに人によって5倍の差既定モデルを最上位にしたまま変えない既定を中位モデルにして、難しい作業だけ上位モデル
会話を始めただけでコンテキストが半分MCPサーバーが多すぎるか指示ファイルが長い使っていないサーバーを無効化し、長い指示はスキルへ分離
並列作業のあとに利用量が急増エージェントチームが各自コンテキストを保持するチーム規模の縮小、メンバーのモデルを中位に、終わったら終了
ログ解析の作業だけ高い大量の出力がそのままコンテキストに入るフックで前処理して必要な行だけ渡すか、サブエージェントへ委任
超過請求が出たのに誰の分か分からない利用者別に帰属させる手段がないツール選定へ戻る。これは運用では解けない

最後の行がこの記事の要約です。前の七つは運用で直せますが、帰属の手段がないツールを選んだことは運用では直せません。だからコスト可視性を性能と同じ等級の選定基準に上げる必要があります。

チームの使い方の習慣移らないいちばん高い
利用量・費用の履歴たいてい移らない基準線を積み直す必要がある
エディタ自体を変えた場合拡張・ショートカット・設定がすべて絡む高い

乗り換え費用を下げる実用的な方法は二つです。第一に、自動化はツールのコマンドではなくシェルスクリプトを呼ぶようにします。スクリプトの中でだけツールを呼べば、入れ替えのときファイル一つを直すだけで済みます。Cascadeが終了したとき慌てたのはパイプラインから直接呼んでいたチームだけでした。第二に、指示はリポジトリにコミットします。ツールのアカウントの中にだけある設定は契約が終われば一緒に消えます。

日本で導入するとき

価格表がすべて米ドルなので、日本での導入では表に載っていない項目が判断を左右します。

支払いと経費処理

  • ほとんどが海外事業者の決済なので、円換算のタイミングとカード会社の海外手数料が毎月上乗せされます。表のドル金額と会計に載る金額は一致しません
  • 適格請求書ではなくインボイスだけが発行される場合が多いです。経費処理の手順を決済の前に確認するほうが早いです
  • 年額前払いの割引が大きいところがあります。Claude Proは年額なら月17ドル(200ドル前払い)、月払いは20ドルです。Team Standardは年額で座席20ドル、月払い25ドルです
  • すでにAWS契約があるならAmazon Q Developerが手続き上いちばん短いです。既存の請求書に合流するので新規ベンダー登録も決済手段の追加も要りません。ツールの性能と関係なくこの一点で決まる組織があります

法人導入でよく引っかかる点

  • 個人プランを各自で契約して経費精算する運用は手軽に見えますが、GitHub Copilot Free・Proの学習既定値のため業務コードを扱う用途には向きません。組織プランへ上げないとポリシーを強制できません
  • 閉域や制限のあるネットワークでは、ツールが外部へ何を送るかの一覧が要ります。Claude Codeはテレメトリ・エラー報告・フィードバック送信をそれぞれ環境変数で止められ、まとめて止める変数もあります。ファイアウォール申請の根拠になります
  • 監査対応が要るなら画面しかないツールは厳しいです。利用者別の支出をCSVやAPIで取り出せるかを契約前に確認してください
  • 座席数の少ないチームは最低契約条件を確認する必要があります。Zed Businessは注文書契約で最低25席、それ未満はセルフサーブ扱いです
  • 年度予算を先に固める組織では従量課金は稟議を通りにくいです。上限を設定できるツール(GitHub Copilotの予算管理、Claude for Teamsの座席割当、Amazon Q Developerの座席定額)を先に候補へ置くほうが速いです
  • SSOを前提にするならプランの等級を先に見ます。多くのツールでSSO・SCIMはチーム以上の等級でしか開きません

実務的な組み合わせ

日本の中小規模の開発組織で承認までいちばん速く着く組み合わせは、座席定額のツールを全員に配り、エージェント型は少数に個別承認です。前者は予算が固定なので説明しやすく、後者は人数が少ないので超過分が抑えられます。逆に全員へ従量制のツールを開けると、二か月目の請求書で問題が起きます。

よくある質問

一つだけ選ぶなら何を見ますか

エディタを変えられるか、支出上限が必要かの二つを先に確定してください。この二つで候補が2〜3個に絞られ、そのあとでモデルの性能を比べれば十分です。性能から見ると良いツールを選んだあとで社内承認に止められます。

定額なのになぜ上限に当たるのですか

今の個人プランはほとんどが定額の中に利用予算を含んでいます。Copilot Proは10ドルに15ドル分のクレジット、Cursor Proは20ドルに20ドル分のモデル利用、JetBrains AI Proは10ドルに10クレジット、Zed Proは10ドルに5ドル分のトークンです。予算を使い切ると上限に当たるか超過分が請求されます。

複数のツールを併用するのは無駄ではありませんか

軸が違えば無駄ではありません。エディタ内蔵型一つとターミナル型一つは仕事が重なりません。同じ軸のツールを二つ置くのが無駄です。

オープンソースのツールを使えばデータは安全ですか

クライアントがオープンソースであることと、データが学習に使われないことは別です。Cline・Gemini CLI・Aiderのいずれもプロンプトはモデル提供者のサーバーへ行きます。読むべき文書はその提供者の規約です。

Cascadeを呼ぶスクリプトがまだ残っている場合は

2026年7月1日以降は動きません。Devin Localの呼び出しへ変える必要があります。あわせて整理すべきは社内文書のwindsurf.comリンクです。devin.aiへ転送されます。

モデルの価格はどこで見ますか

ツールの料金とモデルのAPI単価は別の軸です。100万トークンあたりの単価とキャッシュ・バッチの割引は2026年 AIモデル徹底比較にまとめてあります。
