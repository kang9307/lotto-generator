把十个合成一个，权限也合成了一个 - 整合型工具的真实取舍

省下菜单栏位置和内存的代价是什么被汇聚到了一处

2026-09-04 IT/技术

你大概见过菜单栏上挤着九个图标的画面。一个是剪贴板历史，一个是窗口布局，一个是温度显示，一个是全局快捷键，一个是屏幕截图。每一个都是若干年前某一天为了消掉恰好一个不便而装的，当时那是对的选择。问题在于同样的选择重复了九次。

所以把它们合成一个的提议听起来总是很有吸引力。十二个变成一个，位置省了，要管的对象也少了。这笔账对了一半。它漏掉的是，在变少的东西旁边还有一些东西会汇聚到一处，而汇聚的那一侧通常要等出了事才看得见。

这篇文章不是在挑某个应用，而是在把合并这个形态成立的条件和不成立的条件数清楚。开头从 macOS 讲起，但这笔账本身与操作系统无关。在 Windows 和 Linux 上，同样的问题只是换了个形态出现。

本文整理的是整合型工具与独立工具之间的结构性取舍，不是对任何具体产品的推荐或评价，也不涉及安装与设置方法。文中引用的操作系统行为和权限说明，均为2026年9月时在各厂商官方文档中确认过的内容。

起因 - 一个图标顶替十二个的提议

2026年9月初，韩国开发者社区介绍了一款把 macOS 小工具捆到一起的开源应用。仓库的说明是免费开源的 macOS 菜单栏工具集，逐应用音量调节与输出设备切换、系统监控、带实时窗口预览的应用切换器、窗口布局、剪贴板历史、文本片段展开、屏幕截图与录制、命令面板、应用卸载与清理，全都在同一份清单里。它用 Swift 编写，许可证是 GPL-3.0，要求 Apple Silicon 和 macOS 14 Sonoma 及以上。

仓库创建于2026年6月12日，按2026年9月4日查询到的数值，星标15,004个、复刻527个、未关闭的 issue 327个。这意味着三个月内聚集了相当多的关注。对于一直用三个不同应用分别做窗口切换、窗口布局和应用卸载的人来说，把它们收成一个是个实打实的提议。

从这里开始，本文关心的不是那个应用，而是合并这一形态本身。这类提议会周期性地出现，每一次都需要同样的一笔账。什么变少了，什么汇聚到了一处，汇聚起来的东西塌掉时波及范围有多大。

小工具为什么会越堆越多

常驻小工具几乎无一例外地诞生于操作系统不提供的那些小缺口。缺口个个都小。需要的不是刚才复制的那个，而是往前数三个复制的那个。想把两个窗口各放在半屏上。想看的不是电量百分比而是瓦数。想按规则把两百个文件重命名。

缺口小，解决办法也就小。下载一个应用放进菜单栏就完事了，而那一刻的判断多半是对的。问题是这个判断在几年里下了九次，而删除的判断一次也没下过。常驻进程很安静，不再用它之后仍然挂在那里，而挂着这件事本身也被忘掉了。

堆积的方式有一些共同点。知道这些，日后挑选清理对象时会派上用场。

  • 引入成本几乎为零。下载后启用就结束了，因此在引入的那一刻根本不会发生权衡
  • 成本在之后出现，而且是分散出现的。几十兆内存和一格菜单栏在当下感觉不到
  • 没有触发删除的契机。小工具很少通过坏掉来提醒自己的存在，它只是安静地一直转
  • 功能重叠了也察觉不到重叠。三个应用各自带屏幕截图，只要快捷键不同，重叠就浮不上来
  • 操作系统后来把这功能做成内置了，小工具照样留着。因为用惯了，或者因为不知道内置功能已经有了

归结起来，小工具堆积不是疏忽的结果，而是引入便宜、删除没有契机这一结构的结果。理解了这个结构，才能准确看清合并到底解决了什么。把同类的账套用到软件更换这件事上的做法，在换用轻量替代软件之前里按六个维度处理过。

合并真正换来的东西

为了不让这篇变成贬低合并的文章，得先把收益一侧数准。而收益是实实在在的。

第一是菜单栏的位置。它容易被当成口味问题，实际上却是有限资源。菜单栏右侧的宽度是固定的，用菜单多的应用时图标就会被截掉看不见。带摄像头刘海的机型宽度更窄。

第二是进程数与登录项的数量。十个变一个，登录后同时醒来的进程也就少了那么多。资源占用具体降多少是另一个问题，但数量减少这件事本身是确定的。

第三是设置的一致性。十个独立工具彼此不知道对方的快捷键。装了新工具，旧工具的快捷键就悄悄失灵，找原因还得花不少时间。放在一个应用里，应用知道冲突，通常还会告诉你。

第四是更新与信任判断的落点变成一个。十个工具意味着分别信任十位开发者的决定，也意味着每次操作系统大版本更新时做十次兼容性确认。合并之后这些变成一次。

第五则是授予权限的次数。不必给五个工具授权五次，给一个应用授权一次就行。表面上这是明摆着的收益。但这一项正是本文的转轴，因为减少的是授予的次数，而不是授予出去的权限总量。

合并会失去的五样

失去的一侧可以归成五样。要紧的是这五样并非彼此独立，而是一个会把另一个放大。

失去的东西用独立工具时用整合应用时真正出问题的时刻
单点故障坏一个，只有那一项功能停坏一个，十项功能一起停更新之后，操作系统大版本升级之后
权限的并集每个工具只持有自己功能需要的那部分一个进程持有全部该应用被入侵，或所有与维护的主体发生变更时
更换成本只把不满意的那一个换掉无法局部更换，全都绑在一起发现只有某一项功能不合自己的工作时
功能深度专用工具有长年打磨出来的细节成为覆盖常见用法的平均实现那项功能正是自己工作核心的时候
维护风险停了一个，其余九个还活着十样一次性消失开发停摆之后操作系统往上升一级时

先看单点故障。常驻应用在每次操作系统大版本更新时都会坏一次。这不是开发者能力的问题，而是因为存在紧贴系统行为的功能，下面一变，架在上面的东西也跟着晃。十个独立工具里坏掉两三个，和一个整合应用坏掉导致十项功能同时停摆，并不是同一量级的事件。前者是不便，后者是工作中断。

更换成本让人看清独立工具最实用的长处是什么，那就是局部更换的可能性。窗口布局不满意，只换那一个就行。整合应用里做不到，实际发生的情形通常是这样：整合应用照开着，为了那一项功能再多开一个单独的应用。合并的理由当场就消失了。

功能深度更接近于设计上难以避免的一侧。覆盖常见用法是合理的决定，也符合大多数人。错位发生在那项功能恰好是自己工作核心的那批人身上。一天用一百次剪贴板历史的人需要搜索语法、是否保留格式、排除特定应用的规则，而这类细节往往积累在只做这一项功能做了很多年的工具里。

维护风险展示了合并如何重新分配风险。十个独立工具是分散在十个人身上的风险，停了三个还有七个活着。整合应用则是把这份风险压在一处的形态。如果是开源，还留有复刻的可能，但复刻可行和真有人在维护是两回事。

  • 五样里有四样要等时间过去才会显现，靠引入头一周的满意度是判断不出来的
  • 单点故障和维护风险是同一条轴的短版本与长版本，前者讲的是几天，后者讲的是几年
  • 更换成本随合并的程度而变，如果每项功能都能单独开关，就能缓解相当一部分
  • 功能深度对每个人来说出问题的位置都不同，因此是最难靠别人的评价来判断的一项
  • 剩下的那一样，权限的并集，性质不同。它是结构的问题，不是时间的问题

权限的并集才是这个问题的核心

macOS 把常驻小工具所需的权限按功能拆开了。它们在系统设置的隐私与安全性项目里各自成为单独的清单，Apple 还为每一项写了一句话说明它允许什么。照原样读这些句子，正是本节的要点。

权限Apple 的说明（2026年9月时点）要求该权限的常见功能
辅助功能允许应用运行脚本和系统命令以控制你的 Mac窗口布局、窗口大小调整、快捷键扩展、自动化
输入监控允许应用监控来自鼠标或触控板的输入，并查看你在键盘上输入的内容全局快捷键、文本片段展开
屏幕与系统音频录制允许应用录制你的屏幕和音频，或仅录制音频屏幕截图、窗口预览、读取其他应用的窗口标题
完全磁盘访问允许应用访问你计算机上的所有文件，包括来自其他应用的数据、Time Machine 备份中的数据，以及针对本机所有用户的某些管理设置应用卸载与清理工具、缓存清理
麦克风允许应用访问你 Mac 上的麦克风屏幕录制时同步录入语音

使用独立工具时，这些权限分别附着在不同的进程上。窗口布局工具只持有辅助功能，截屏工具只持有屏幕录制，清理工具只持有完全磁盘访问。各自只持有自己工作所需的那一份，超出的部分由系统拦住。

合成一个之后，一个进程持有全部五项。做出功能的并集，权限的并集就会跟着来。这不是应用贪心，而是要做那些功能就真的需要那些权限。窗口布局需要辅助功能，窗口预览需要屏幕录制。功能诚实地在使用那些权限。

那么变的是什么。有两点。第一，权限是按应用而不是按功能授予的。就算决定不再使用窗口布局功能，给那个应用的辅助功能权限也会一直留着，直到用户自己进系统设置去收回。关掉功能和收回权限是两个不同的动作。

第二，出事时的波及范围变了。窗口布局工具被入侵，出问题的是移动窗口的权限；而持有全部五项的应用被入侵，屏幕、输入和所有文件会一次性卷进去。这不是概率的事，而是范围的事。

辅助功能权限所允许的范围究竟有多大

五项之中尤其宽的是辅助功能。Apple 的说明只有一句：允许应用运行脚本和系统命令以控制你的 Mac。句子短，但控制这个词所含的范围很宽。它可以读取并操作其他应用的界面元素，也可以制造出按键输入。窗口布局之所以可行，正是因为这一点，它在访问其他应用的窗口这个对象并改变其位置和大小。

更明确的信号是 Apple 自己如何给这项权限分类。Apple 的平台安全文档写道，辅助功能和自动化能力需要用户许可，以确保它们不会绕过其他保护措施。也就是说，这项权限不是与其他权限并列的一项，而是因为可能越过其他权限而被单独圈起来的那一项。

屏幕录制权限也比名字更宽。从 macOS 10.15 起，窗口列表 API 返回的窗口名称值被绑到了屏幕录制权限上，Apple 开发者论坛上 Apple 工程师的回复确认了这一行为。应用切换器要显示其他应用的窗口标题，就需要屏幕录制权限，原因就在这里。窗口标题里原样包含着打开的文档名称、对话对象的名字、正在访问的页面标题。即便不做任何录制，仅凭标题就能还原出这个人此刻在做什么的相当一部分。

Apple 在屏幕录制设置界面附上的提示也值得一读：如果允许第三方应用或网站录制你的屏幕和音频，它们收集的任何信息都受其条款和隐私政策的约束。也就是说，授予权限之后的管控在于那个应用的政策，而不在操作系统。系统替你做的事，到门口问一次为止。

这里要澄清一个误解。权限强，并不等于那个应用在做坏事。要点不是权限的大小，而是权限汇聚的地点有几处。同样的五项是分散在五处还是集中在一处，决定了出问题时的结果。

开源能减少这个问题，但消不掉。能读源码和自己确实读了是两回事，而分发出来的二进制是不是从那份源码来的，需要可复现构建之类的另一套机制才能确认。开源的实际收益是可审计性，而不是审计已完成。设备的控制权在哪里发生分离，在买下了却不完全属于你的部分里另行处理过。

什么该合并、什么该分开放

到这里就可以做出判断标准了。轴有三条，三条都是关于自己使用方式的问题，而不是关于产品的问题。

轴该问什么合并更好的情形分开放更好的情形
使用频率一天用几次一周用几次的程度。不需要深度，平均实现就够了一天几十次。专用工具打磨出的细节会立刻让人怀念
权限强度这项功能需要哪种权限压根不需要权限的功能，比如单位换算、取色、计算器需要完全磁盘访问或屏幕录制的功能。分开可以缩小范围
不可替代性它停了工作是否也跟着停没有也能过的便利功能，几天不用也没关系已经成为工作流一部分的功能，不放进单点故障里

三条轴指向同一个方向时答案很好办。偶尔用、不需要权限、没有也行的功能，全合并进去几乎没有损失。反过来，每天用、权限强、没有就麻烦的功能，分开放更好。

难的是轴互相矛盾的时候。典型例子是剪贴板历史。每天用几十次，没有立刻就不便，同时还把经过的一切都存下来。可是这项功能的风险并不出现在权限清单里。风险不在权限，而在存储本身。从密码管理器复制出来的值、一次性验证码，会原样留在那份历史里。

所以剪贴板历史无论放在哪一边，都会成为必须确认其策略的功能。可以参照的基准线在 Windows 那边有成文的记载。Microsoft 明确写道，Windows 的剪贴板历史最多保留25项，每项最大4MB，支持文本、HTML 和位图格式，并且每次重启电脑时除已固定的项目外都会被清空。保留数量和清除时点被白纸黑字写下来，这件事本身就是标准。挑工具时该问的不是功能清单，而是有没有这样的句子。

  • 合并之前先数一数 — 现在开着的小工具里，最近一个月真正用过的有几个。把没用的删掉，合并的理由就少了一半
  • 先从权限看起 — 看整合应用要求的权限清单，看看其中有没有是为你不会用的功能而需要的。有的话就关掉那项功能，权限也不给
  • 不要一次全搬过去 — 从权限弱、不常用的功能开始搬。剪贴板历史和清理工具放到最后
  • 删除之前留个缓冲期 — 用整合应用过上两周左右再删掉独立工具。这是留一条退路的廉价办法
  • 看能不能按功能关闭 — 整合应用如果可以单独停用某项功能，更换成本和权限问题会同时得到缓解。这接近于挑选整合应用时最重要的条件

操作系统一直在吸收小工具

小工具这种东西本来就带着临时性的性质。它为填补缺口而生，缺口一旦被填上就失去了存在的理由。这不是失败而是正常的结局，而且近几年确实发生过好几次。

功能还属于小工具领域的年代现在（2026年9月时点）
窗口平铺（macOS）由第三方窗口管理工具负责从 macOS 15 Sequoia 起内置。系统设置的桌面与程序坞里有把窗口拖到屏幕边缘以平铺、拖到菜单栏以填满屏幕、按住 Option 键拖动以平铺、平铺窗口留边距等选项
窗口贴靠（Windows）由第三方工具负责Windows 11 和 10 的贴靠布局。Win+Z 打开布局候选，Win+方向键贴靠
剪贴板历史（Windows）第三方剪贴板管理器用 Win+V 开启的内置功能。25项，每项4MB，文本、HTML 和位图
启动项管理专用的清理工具Windows 在设置和任务管理器里，macOS 在系统设置的通用中的登录项
工具捆包本身个人开发者各自的独立应用Microsoft PowerToys。25个以上的免费开源工具由厂商自己捆好发布

这张表的最后一行很有意思。PowerToys 把用于窗口布局的 FancyZones、用于按键重映射的 Keyboard Manager、用于批量重命名的 PowerRename、作为剪贴板粘贴扩展的 Advanced Paste 等等打成一个包提供。这是操作系统厂商自己做整合型工具的案例。这里还有一处设计值得留意：PowerToys 让每个工具都可以单独启用和停用。合起来了却保留成模块，而这正是缓解上一节所说的更换成本和权限问题的实际办法。

吸收这条趋势给整合应用制造了一个独有的问题。十项功能里有三项成了系统内置时，整合应用没法把那三项拆下来。用独立工具的人删掉三个应用就行，整合应用的用户则要带着重复继续用下去。那三项当初要求的权限通常也照样留着。

反过来也有不会被吸收的领域。温度和风扇转速的显示、卸载应用后残留文件的清理这类东西，操作系统厂商没什么理由特意去做。小工具在那些位置能活得很久。挑选合并对象时想一想这项功能属不属于会被吸收的那一侧，是一种廉价的预判。

用数值测量常驻成本的方法

合并了会更轻，这是一个可以验证的主张形式。可是大多数人不去验证，而是凭体感来说。体感多半是错的。人有一种偏见，总觉得刚删掉的那个很重，而对开着十个应用时的状态，记忆并不准确。

macOS 有活动监视器，这里要用两个标签。内存标签显示内存压力、物理内存、已用内存、已缓存文件和已用交换空间，已用内存又分为应用内存、联动内存和已压缩。Apple 把内存压力说明为以图形方式表示内存服务处理需求的效率，并写明该值综合考虑了可用内存、交换率、联动内存和文件缓存内存。能耗标签用四列显示各应用的能耗信息，窗口下方放着整体能耗影响的图表。

读法上有一个常见的错误，就是把各个进程的内存数字加起来求总和。既然 Apple 自己把压力定义为多个值的合成，那么应用内存的总和很大但内存压力低，那就不是问题。开发工具占用大量内存为什么本身不构成问题，在开发工具为什么吃内存里以语言服务器为例整理过。

  • 比较两种状态。只开整合应用的10分钟，和把独立工具全开的10分钟。看的是差值而不是绝对值
  • 做同样的工作。编辑器和浏览器按同样的配置打开，做同样的事。否则你测到的就不是小工具而是那天的工作量
  • 不要靠一次快照下判断。常驻应用大多是周期性醒来的，那个周期必须落在观察窗口内
  • 电池要看能耗影响。剩余百分比的下降速度会随屏幕亮度和无线环境大幅波动，不适合用来比较
  • 把结论以数值写下来。为了下次同样的问题来的时候不必重测，那天的数值必须留存

Windows 这边也有成文的基准。任务管理器启动应用标签所显示的启动影响由 CPU 时间和磁盘 I/O 判定，Microsoft 把标准写成这样：高是启动时 CPU 超过1秒或磁盘 I/O 超过3MB，中是 CPU 300毫秒至1000毫秒或磁盘300KB 至3MB，低是 CPU 少于300毫秒且磁盘少于300KB。看过这些数值之后，重这个词指的是多大量级，心里就有感觉了。

登录项与启动时间

常驻小工具几乎全都要求自动启动，因为不要求就没有用处。所以小工具变多，等同于登录后同时醒来的进程变多。

在 macOS 13 及以上，登录项位于系统设置的通用之中，里面有两份性质不同的清单。一份是登录时打开的项目，另一份是允许在后台运行的清单。Apple 说明后者是允许应用在未打开时也执行检查软件更新或同步数据这类任务。在 macOS 14 及以上，用新注册框架注册的项目会出现在这份清单里。

值得打开这个界面看一次的理由很明确：清单比你记得的要长。有时应用已经删了，条目却还留着；有时会有自己没印象装过的辅助进程。清单一长，登录后最初的几十秒里就会有多个进程同时争用磁盘和 CPU。

Windows 在设置和任务管理器两处管理。Linux 遵循 XDG 自动启动规范，用户项以 .desktop 文件放在 ~/.config/autostart，系统级项放在 /etc/xdg/autostart。同名文件出现在多个目录时，只使用优先级较高的那一个。标记为 Hidden=true 的文件必须被忽略，因此用户关掉系统级自动启动的办法就是在个人目录里放一个同名文件。OnlyShowIn 和 NotShowIn 可以按桌面环境控制，这两个键不会同时写在一个文件里。

在这一点上整合应用明显占优，登录项减到一个。这份收益没有理由否认，而且实实在在。只不过这份收益必须和权限的并集一起放上天平，这才是本文通篇的论旨。

免费、付费、订阅 - 可持续性这条另一轴

一个小工具五年后是否还活着，与定价模式有关，但方向并不是人们通常以为的那样。付费未必长久，免费也未必停摆。只是轴不同而已。

  • 一次性买断 — 没有持续收入。每次操作系统更新所需的应对成本要靠新增销售来承担，销售一减少，应对就会变慢
  • 订阅 — 换来了应对的余力，代价是不用的月份也要付费，而且付款一停功能就停。同时也产生了增加功能的理由，本来小巧的工具往往会变大
  • 免费开源 — 维持的依据不是合同，而是开发者的时间和意愿。作为交换，即使停摆源码还在，许可证允许的话还能复刻
  • 捆绑或附带服务 — 有别的收入来源，工具本身可以免费。那个收入来源一转向，最先被清理掉的就是工具

继续使用已停止开发的工具，其风险与前面说的权限直接相连。常驻小工具持有强权限，一旦发现漏洞却不修，那份权限就会原样留作攻击面。一个独立工具变成这样，和持有五项权限的整合应用变成这样，波及范围不同。

比定价模式更可靠的信号在履历那一侧。下面五项在仓库或发布页上大多可以确认。

  • 最近的发布间隔 — 是否几个月至少还出一次。最后一次发布是什么时候
  • 响应操作系统大版本更新所用的时间 — 这是该项目真实的体力。看从发布公告到应对版本之间的间隔
  • issue 积压的速度与关闭的速度 — 比起数量，两个速度之间的关系更重要
  • 维护者有几个人 — 如果只有一个人，那个人不在了的计划有没有写在什么地方
  • 许可证是否允许复刻 — 开源这个说法和可以复刻并维持下去这个说法，会因许可证而不同

在 Windows 与 Linux 上形态不同

以上这些在 macOS 上格外清晰是有原因的，因为macOS 把权限做成清单展示出来。你能在界面上确认自己允许了什么，所以合并的成本也看得见。在别的操作系统上，同样的问题换了个形态。

环境小工具所需要的东西用户能够管控的地点这个结构造成的结果
macOS按功能拆开的权限需要逐项批准在系统设置的隐私与安全性中按应用收回能以清单看到自己给了什么。但批准太频繁，容易一次性全点掉
Windows普通桌面应用无需这类单独批准即可运行大致只有启动项管理和管理员权限提升根本没有可以查看自己允许了什么的界面，合并的成本浮不上来
Linux / X11能连到 X 服务器就行，技术上很容易自动启动靠 XDG 规范。隔离需要另外的沙箱正如 Wayland 文档所指出的，X11 客户端之间既无保护也无隔离
Linux / Wayland必须经由合成器提供的通道合成器的门户设置与权限策略全局快捷键、屏幕共享这类功能变难，并且依赖各合成器的实现

Linux 这边需要再多说几句。Wayland 官方文档明确写道，Xwayland 不会保护也不会隔离 X11 客户端彼此，除非合成器选择为每个应用单独启动 Xwayland 实例；同一份文档解释说，通常不这么做是因为许多 X11 应用需要通过 X 服务器互相通信。而 X11 客户端与 Wayland 客户端之间则被写为天然隔离。也就是说，即使在同一块屏幕里，隔离水平也因应用而异。

因此要不要合并这个问题，在不同环境里有不同的解法。在 macOS 上看权限清单判断即可，清单看得见这件事本身就让判断变容易。在 Windows 上判断依据不在界面上，只能靠用户自己记住装过什么，而 Microsoft 用 PowerToys 展示了一方提供者把工具捆好并允许按功能关闭的形态。在 Linux 上，显示服务器的选择已经预先决定了答案的很大一部分。

有一点在任何环境里都一样：常驻的东西要付常驻的代价。它占位置、拉长启动时间、持有权限，并承担与那份权限相称的风险。一直开着会改变什么，在终端一直开着会改变什么里从另一个角度处理过。

怎么读成熟度 - 星标数说不了的事

再看一遍引出这篇文章的那个应用的数字。仓库创建日期是2026年6月12日，按2026年9月4日的查询基准，星标15,004个、复刻527个、未关闭的 issue 327个。把这些数字说得了的和说不了的分开来看会更好。

说得了的很清楚：关注度高，问题反馈活跃。没人用的项目不会有327个未关闭的 issue。这是有真实用户的证据。

说不了的同样清楚：星标是关注度的指标，不是稳定性的指标。它在被社区介绍之后涨得最快，而星标数与这个应用能否平安越过下一次操作系统更新之间，没有直接关系。未关闭的 issue 数也可以有两种读法，可能是因为用户多，也可能是因为处理积压了，光看数量分不出是哪一种。该看的是开启速度与关闭速度之间的关系。

是个三个月的项目，这个事实也意味着一件事：它还没有经历过几次操作系统大版本更新。对于要求强权限、紧贴系统行为的常驻应用来说，这份通过的履历比任何别的数字都实在，而它是时间过去了才会产生的信息。

这不是对那个项目的评价。任何成熟的工具起初都是三个月的项目。要点只是，在挑选要求强权限的应用时，时间这条轴无法用星标数来替代。而对这条轴有一个非常廉价的应对办法，就是等。如果现在用的独立工具实际上并不让你为难，那么图标有九个这件事本身还算不上为难。

总结

把十个小工具合成一个，得到的和失去的都实实在在。得到的第一天就看得见，失去的要等出了事才看得见。这笔账的全部，就是提前把失去的一侧数清楚。

失去得最多的既不是内存也不是位置，而是权限汇聚的地点。macOS 把辅助功能写为允许应用运行脚本和系统命令以控制你的 Mac，而 Apple 的安全文档把这项权限归类为因为可能绕过其他保护措施而需要单独同意的权限。原本分在五处各一项的权限变成一处五项时，变的不是概率而是范围。

判断标准有三条。常用的东西专用工具更好，权限强的东西分开放更安全，没有就麻烦的东西不放进单点故障里。其余的合并通常划算。如果要选整合应用，还有一个条件：功能能不能单独关闭。能，则更换成本和权限问题同时缓解；不能，则两个问题一起变大。

最后，记住小工具这种东西的性质会有帮助。它是临时填补操作系统尚未做的事情的东西。就像窗口布局曾经是这样、剪贴板历史曾经是这样，如今小工具在做的事情里有一部分几年后会变成内置功能。是不是在把永久的权限交给临时填补的东西，只要确认这一点就够了。

未能确认的部分

  • 引出本文的那个应用实际的内存、CPU、电池消耗未能确认，这也是文中没有这些数值的原因。整合在资源方面划算这个主张，只有各自在自己的机器上比较两种状态才能确认
  • 活动监视器能耗标签的四列各自是什么，未能在 Apple 支持文档中找到名称与定义。仅从文档确认到该标签用四列显示各应用信息、下方有整体能耗影响图表这一步
  • macOS 是否具备系统级的剪贴板历史功能，未能在 Apple 支持文档中找到该功能。因此文中的剪贴板数值只引用了有成文记载的 Windows 一侧的值
  • 比较整合型应用与独立工具之间安全事故频率的资料未能找到。本文的权限讨论只基于权限一旦汇聚影响范围就会扩大这一结构性理由，而不是基于事故统计
  • GitHub 的星标、复刻、issue 数量是2026年9月4日的查询值，未能确认有研究验证过这些数字与软件质量之间的关系
  • Windows 上普通桌面应用在哪些操作上会被要求单独的用户批准，其完整清单未能确认。正文只写到 Microsoft 有成文记载的启动项管理与启动影响判定标准为止
