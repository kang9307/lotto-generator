引言 - 同样的管道符号，流动的东西不同

bash和PowerShell都用|连接命令，但这条线上流动的东西不同。Microsoft Learn的about_Pipelines说明，管道运算符把前一个命令的结果送给下一个命令，并明确送出的是对象。第一个命令发出的对象送到第二个命令，第二个命令处理后的对象再送到第三个命令。同一篇文档还写道，PowerShell的管道是面向对象的，不支持原始字节数据，标准输入(stdin)也不会连接到PowerShell管道的输入。这与bash管道把一个进程的输出文本接到下一个进程输入的方式形成对照。

结果差别很大。在文本管道中，每个工具都要自己解释列位置和分隔符。ls -l | awk '{print $5}'里的$5，依赖的是「第五列」这个约定；在对象管道中，则通过Length这个属性名取值。理解了这一差别，不必背命令对照表也能完成大部分翻译。反过来，不了解这一差别，就会遇到敲了同名别名却不支持选项，或者输出相似但排序、比较结果不同的情况。

这里讨论的主线是概念(对象与文本)和对照表。grep与awk的语法和选项汇总，见Linux Grep 与 AWK 使用指南；汇总故障日志的实战做法，见Linux 日志分析命令完全指南。扩展到批处理文件和任务计划程序的自动化入门，见Windows任务自动化入门指南；在Windows上原生引入UNIX工具时与PowerShell别名重名的问题，见Microsoft Coreutils for Windows。

下面反复验证的差异可以归纳为五点。

  • 管道中流动的是对象，而不是字符串。
  • 解释通配符和选项的主体是各个cmdlet，而不是shell。
  • 大小写的默认值与grep相反。Select-String和比较运算符默认不区分大小写。
  • 即使别名与bash命令同名，选项体系也不是bash的。
  • 对象转换为字符串的那一刻，值可能因显示宽度而被截断。

ls | grep为什么变成Where-Object - 输出不是字符串

第一个对应，是从文件列表中只挑出以.log结尾的。在bash中，是从列表文本中挑选行。

$ ls | grep '\.log$'
                    app.log
                    old.log

在PowerShell中，是筛选Get-ChildItem发出的对象的Name属性。

Get-ChildItem | Where-Object { $_.Name -like '*.log' } | Select-Object Name, Length | Format-Table -AutoSize
Name    Length
                    ----    ------
                    app.log    532
                    old.log     36

输出的表是文本，但在管道中流动时它们是对象。Where-Object做的不是扫描行字符串，而是把每个对象的Name属性与通配符模式比较。这一点可以通过运行确认。

$first = Get-ChildItem | Select-Object -First 1
                    $first.GetType().FullName
                    (Get-ChildItem | ForEach-Object { $_.GetType().Name } | Group-Object | ForEach-Object { $_.Name + ' x' + $_.Count }) -join ', '
                    Get-ChildItem -File | Get-Member -MemberType Property | Where-Object { $_.Name -in 'Name','Length','LastWriteTime','Extension' } | Select-Object Name, Definition | Format-Table -AutoSize
System.IO.DirectoryInfo
                    DirectoryInfo x1, FileInfo x5
                    
                    Name          Definition
                    ----          ----------
                    Extension     string Extension {get;}
                    LastWriteTime datetime LastWriteTime {get;set;}
                    Length        long Length {get;}
                    Name          string Name {get;}

第一个元素是System.IO.DirectoryInfo，整个列表是一个目录对象加五个文件对象。文件对象带有的不是字符串，而是Length(long)、LastWriteTime(datetime)这样有类型的属性。由此可以得出两点：第一，不需要靠数列号的awk；第二，大小的比较和排序按数值顺序而不是字符顺序进行。

第二个对应，是只取出大小这一列。在bash中用awk取ls -l的第五列(已排除目录行)。

$ ls -l | awk '$1 !~ /^d/ && NF > 2 {print $5}'

                    9
                    2002
                    36

Get-ChildItem -File | Select-Object -ExpandProperty Length

值相同，但获取的方式不同。前者在ls -l的输出格式改变时会失效，后者只要属性名还在，就不受格式影响。按大小排序时差别更明显。排序数字列时，bash的sort默认按字符顺序，必须加-n。

$ printf '10\n9\n100\n' | sort
                    10
                    100
                    9
                    $ printf '10\n9\n100\n' | sort -n

                    10

PowerShell的Sort-Object遵循输入的类型。字符串'10','9','100'按字符顺序排列，转换成数字后的值按数值顺序排列。文件对象的Length本来就是long，所以不加任何选项就是数值排序。

'10','9','100' | Sort-Object
                    '10','9','100' | Sort-Object { [int]$_ }
                    Get-ChildItem -File | Sort-Object Length -Descending | Select-Object -First 2 Name, Length | Format-Table -AutoSize
10
                    100
                    9
                    9
                    10
                    100

                    ----     ------
                    notes.md   2002
                    app.log     532

前两个结果，在字符串时与bash顺序相同(10, 100, 9)，转换类型后与-n排序相同(9, 10, 100)。第三个结果按名称和大小显示最大的两个文件。对象转换为字符串，只发生在发生转换的地方。把文件对象放进字符串里，只剩下名字。

从表中可以读出的规则如下。

  • 文件列表的筛选是属性比较，而不是名称字符串的搜索。扩展名直接用Extension，大小直接用Length访问。
  • 取出某一列的awk '{print $N}'，变成Select-Object -ExpandProperty 属性名。
  • 排序遵循输入的类型。要按数值排序，值必须是数值类型，如果是字符串，则需要[int]之类的转换。
  • find如果直接写这个名字，运行的是Windows的find.exe(针对PATH中没有Git的usr\bin的会话，第9节)。

Select-String不是grep - MatchInfo与默认值的差异

Select-String的文档把这个cmdlet介绍为可以像Unix的grep或Windows的findstr.exe那样使用。二者相似但不相同。在同一个文件里搜索ERROR，两边的结果就出现分歧。bash区分大小写，找到3条。

$ grep -n ERROR app.log
                    3:2026-10-05 09:01:12 ERROR db timeout after 30s
                    7:2026-10-05 09:03:02 ERROR upstream 502
                    10:2026-10-05 09:05:00 ERROR db timeout after 30s
Select-String -Path .\app.log -Pattern 'ERROR'
app.log:3:2026-10-05 09:01:12 ERROR db timeout after 30s
                    app.log:5:2026-10-05 09:01:20 INFO  retry succeeded after error in cache
                    app.log:7:2026-10-05 09:03:02 ERROR upstream 502
                    app.log:10:2026-10-05 09:05:00 ERROR db timeout after 30s

PowerShell一侧是4条。第5行含有小写的error。Select-String文档在-CaseSensitive参数处写道，默认情况下匹配不区分大小写。grep正相反，默认区分大小写，要忽略大小写需加-i。把两边的数量对照起来是这样。

$ grep -c error app.log
                    1
                    $ grep -ci error app.log
                    4
'matches for error (no flag): ' + @(Select-String -Path .\app.log -Pattern 'error').Count
                    'matches for error -CaseSensitive: ' + @(Select-String -Path .\app.log -Pattern 'error' -CaseSensitive).Count
matches for error (no flag): 4
                    matches for error -CaseSensitive: 1

输出开头的app.log:3:是文件名和行号。这是MatchInfo对象的显示格式而不是文本，读取属性就能看出来。

$m = Select-String -Path .\app.log -Pattern 'ERROR' | Select-Object -First 1

大小写的默认值并不只存在于Select-String。about_Comparison_Operators写道，字符串比较除非使用显式区分大小写的运算符，否则不区分大小写，-replace默认也不区分大小写。移植sed 's/error/X/g'时，这个差异会原样显现。

$ echo 'Error ERROR error' | sed 's/error/X/g'
                    Error ERROR X
                    $ echo 'a.b.c' | sed 's/./-/g'
                    -----
'ERROR' -eq 'error'      -> True
                    'ERROR' -ceq 'error'     -> False
                    'ERROR db' -match 'error'  -> True
                    'ERROR db' -cmatch 'error' -> False
                    'ERROR db' -like 'error*'  -> True
                    'Error ERROR error' -replace 'error','X' -> X X X
                    'Error ERROR error' -creplace 'error','X' -> Error ERROR X
                    'a.b.c' -replace '.','-'    -> -----
                    'a.b.c' -replace '\.','-'   -> a-b-c
                    'a.b.c'.Replace('.','-')    -> a-b-c

上面的块是逐行运行PowerShell，并以「表达式 -> 结果」的形式输出的内容。-replace的第一个操作数是正则表达式，所以'.'匹配所有字符，这点与sed相同，只有大小写的默认值相反。像-ceq、-cmatch、-creplace这样加上c，就会区分大小写。

  • 即使概念同名，默认的大小写规则也可能相反，所以对比数量的统计，要先决定是否使用-CaseSensitive。
  • 给Select-String传文件对象就是搜索内容，传字符串或Out-String -Stream的结果就是搜索这些行。
  • 模式默认是正则表达式，字面搜索用-SimpleMatch，相当于grep的-F。

用Group-Object、Sort-Object、Measure-Object替代sort | uniq -c | wc

统计日志级别(INFO、WARN、ERROR)各有多少条的汇总，在bash中这样写：取出第三列并排序，统计相同的值，再按数量重新排序。

$ awk '{print $3}' app.log | sort | uniq -c | sort -rn
                          6 INFO
                          3 WARN
                          3 ERROR

在PowerShell中，取列的位置用-split加索引，计数再排序的位置用Group-Object和Sort-Object。

Get-Content .\app.log | ForEach-Object { ($_ -split '\s+')[2] } | Group-Object | Sort-Object Count -Descending | Select-Object Count, Name | Format-Table -AutoSize
Count Name
                    ----- ----
                        6 INFO
                        3 ERROR
                        3 WARN

两个输出中，数量相同的WARN和ERROR顺序相反。数量相同时的先后并不是确定的约定，所以最好避免依赖顺序的处理。Group-Object返回的也是对象而不是字符串，所以数量这一列通过Count属性访问。

$g = Get-Content .\app.log | ForEach-Object { ($_ -split '\s+')[2] } | Group-Object | Select-Object -First 1
                    $g.GetType().FullName
                    $g | Get-Member -MemberType Property | Select-Object Name | Format-Table -AutoSize
Microsoft.PowerShell.Commands.GroupInfo
                    
                    Name
                    ----
                    Count
                    Group
                    Name
                    Values

GroupInfo的Group属性里装着按该值归并的原始项目，因此不止数量，还可以继续处理每组的内容。行数和合计由Measure-Object负责。wc -l变成Measure-Object -Line或数组的.Count，awk '{sum += $5}'变成-Property Length -Sum。

'wc -l       -> ' + (Get-Content .\app.log | Measure-Object -Line).Lines
                    'count       -> ' + @(Get-Content .\app.log).Count
                    Get-ChildItem -File | Measure-Object -Property Length -Sum -Average -Maximum -Minimum | Format-List Count, Sum, Average, Maximum, Minimum
wc -l       -> 12
                    count       -> 12
                    Count   : 5
                    Sum     : 2586
                    Average : 517.2
                    Maximum : 2002
                    Minimum : 7

bash的wc -l < app.log同样返回12。一次Measure-Object就能同时得到数量、合计、平均、最大和最小，这是它比一行awk统计方便的地方。去重的sort -u是Sort-Object -Unique，'b','a','b','c','a' | Sort-Object -Unique的结果是a、b、c。

about_Pipelines的「逐个处理」规则会在统计中决定结果。通过管道送入时，对象逐个流动并被计数，但把数组作为参数整体传递时，会被当作一个对象。

'[1,2,3] | Measure-Object            -> ' + (1,2,3 | Measure-Object).Count
                    'Measure-Object -InputObject @(1,2,3) -> ' + (Measure-Object -InputObject @(1,2,3)).Count
                    '@{a=1;b=2} | Measure-Object          -> ' + (@{a=1;b=2} | Measure-Object).Count
[1,2,3] | Measure-Object            -> 3
                    Measure-Object -InputObject @(1,2,3) -> 1
                    @{a=1;b=2} | Measure-Object          -> 1

结果与文档中的示例相同。数组被展开得到3，哈希表没有被展开，得到1。要让哈希表逐项流动，文档写道需要调用GetEnumerator()。

  • Get-Content的结果是行数组，所以行数直接用.Count读取。没有结果时是$null，因此用@(...)包起来再读数量。
  • 索引规则不同。awk的$3对应-split之后的[2]。
  • 通过管道送入还是作为参数传递，一次处理的单位会不同。数量对不上时，先怀疑这个差别。

变量与环境变量 - $x不会传给子进程

bash的export FOO=bar对应的是$env:FOO = 'bar'。普通变量$x只存在于PowerShell会话内，环境变量$env:Y则会被子进程继承。这个区分与bash中是否有export所划的界线相同。两边做了同样的试验。

$ x=shell-only
                    $ export Y=exported
                    $ bash -c 'echo "x=[$x] Y=[$Y]"'
                    x=[] Y=[exported]
$x = 'shell-only'
                    $env:Y = 'exported'
                    'bash $PATH -> [' + $PATH + ']   (the PowerShell variable $PATH is empty)'
                    '$env:PATH has entries: ' + (($env:PATH -split ';').Count -gt 3)
                    'child process sees:'
                    powershell.exe -NoProfile -File C:\demo\child.ps1
                    (Get-ChildItem Env: | Where-Object { $_.Name -eq 'Y' }).Value
                    Remove-Item Env:\Y
                    'after Remove-Item Env:\Y -> [' + $env:Y + ']'
bash $PATH -> []   (the PowerShell variable $PATH is empty)
                    $env:PATH has entries: True
                    child process sees:
                    x=[] Y=[exported]
                    exported
                    after Remove-Item Env:\Y -> []

子进程(child.ps1在一行中输出$x和$env:Y)看到的是与bash相同的x=[] Y=[exported]。一个陷阱在于名字。bash的$PATH是环境变量，而PowerShell的$PATH只是一个未定义的普通变量，所以是空的。环境变量要用$env:PATH读取，分隔符是;。删除环境变量用Remove-Item Env:\Y，全部环境变量可以通过Env:驱动器用Get-ChildItem列出。

  • 需要export的值，用$env:名称创建，只在脚本内部使用的值就用普通变量。
  • $PATH这样在bash中熟悉的名字，在PowerShell中可能是个空变量。不要忘记$env:前缀。
  • 环境变量可以通过Env:驱动器像文件一样列出和删除。

谁来展开通配符 - 是cmdlet而不是shell

在bash中，*.log在命令运行之前就由shell展开成文件列表，并作为参数传入。同样的输入在bash中验证如下。

$ echo *.log
                    app.log old.log
                    $ node -e "console.log(JSON.stringify(process.argv.slice(1)))" *.log
                    ["app.log","old.log"]

PowerShell则不同。about_Wildcards说明，通配符用于-like运算符或「任何接受通配符的参数」，并说明每个cmdlet的帮助主题会写明哪些参数接受通配符。因此，未展开的字符串会原样传给原生程序。

'Get-ChildItem *.log ->'
                    (Get-ChildItem *.log).Name
                    'Write-Output *.log ->'
                    Write-Output *.log
                    'native program (node) args for *.log ->'
                    node -e "console.log(JSON.stringify(process.argv.slice(1)))" *.log
                    'cmd /c echo *.log ->'
                    cmd /c echo *.log
Get-ChildItem *.log ->
                    app.log
                    old.log
                    Write-Output *.log ->
                    *.log
                    native program (node) args for *.log ->
                    ["*.log"]
                    cmd /c echo *.log ->
                    *.log

Get-ChildItem *.log由cmdlet自己解释模式，返回两个文件。相反，Write-Output *.log、原生程序(node)和cmd /c echo收到的是*.log这几个字符本身。没有shell代为展开，所以要把文件列表交给原生程序，需要先用Get-ChildItem取得名称再作为参数传递。解释通配符的主体不同还带来另一个后果：方括号是通配符字符，所以名字里含方括号的文件，直接写是找不到的。

'Test-Path file[1].txt              -> ' + (Test-Path 'C:\demo\t\file[1].txt')
                    'Test-Path -LiteralPath file[1].txt -> ' + (Test-Path -LiteralPath 'C:\demo\t\file[1].txt')
                    'Get-ChildItem file[1].txt (count)   -> ' + @(Get-ChildItem 'file[1].txt' -ErrorAction SilentlyContinue).Count
                    'Get-ChildItem file[[]1].txt (count)  -> ' + @(Get-ChildItem 'file[[]1].txt' -ErrorAction SilentlyContinue).Count
                    'Get-ChildItem -LiteralPath (count)  -> ' + @(Get-ChildItem -LiteralPath 'file[1].txt').Count
                    'Get-ChildItem -Filter file[1].txt   -> ' + @(Get-ChildItem -Filter 'file[1].txt').Count
Test-Path file[1].txt              -> False
                    Test-Path -LiteralPath file[1].txt -> True
                    Get-ChildItem file[1].txt (count)   -> 0
                    Get-ChildItem file[[]1].txt (count)  -> 1
                    Get-ChildItem -LiteralPath (count)  -> 1
                    Get-ChildItem -Filter file[1].txt   -> 1

about_Wildcards写道，方括号是匹配字符范围或特定字符集合的通配符，要访问名字含通配符字符的文件必须转义，其中一种方法就是-LiteralPath参数。file[1].txt这个模式匹配的是file1.txt，所以在这个文件夹中是0条。-LiteralPath和[[]形式找到了1条，-Filter也是1条。同一篇文档还写道，文件系统项目的通配符匹配与字符串的匹配工作方式不同。最后是-Include的行为。

'-Include *.log alone      -> ' + @(Get-ChildItem -Include *.log).Count
                    '-Include with C:\demo\t\* -> ' + @(Get-ChildItem C:\demo\t\* -Include *.log).Count
                    '-Filter *.log             -> ' + @(Get-ChildItem -Filter *.log).Count
-Include *.log alone      -> 0
                    -Include with C:\demo\t\* -> 2
                    -Filter *.log             -> 2

单独使用-Include时，这个文件夹里是0条，在路径末尾加上\*后得到2条。只用名称模式时，-Filter返回了同样的2条。移植bash的ls *.log，最简单的形式是Get-ChildItem -Filter *.log。

  • 要把通配符列表交给原生程序，PowerShell不会展开，需要自己根据Get-ChildItem的结果构造参数。
  • 名字里含[或]的文件，用-LiteralPath访问。
  • -Include与路径模式一起使用和单独使用的结果不同，所以对简单的名称模式，-Filter更容易预测。
  • 文档写道，即使同样是*，-like运算符和文件系统项目的匹配规则也不同。

在对象管道的末端，屏幕上看到的表，是把对象的属性按格式变成字符后的结果。此时如果控制台宽度不够，列就会被截断。验证所用的对象有四列，是Path值为117个字符的两行数据。控制台宽度是120。

保存到文件时也会发生同样的事。用Out-File把同一批对象写入文件再读回来，显示格式的截断被原样保留了下来。

控制台宽度为120时，文件中最长的一行是119个字符，而Path属性的实际长度是117个字符。文件里存入的只是用于显示的字符串，并没有保存对象的值。如果要做需要用到值的后续处理，就不要做成表，而是直接选取属性并以CSV之类的数据格式输出。

Get-ChildItem -File -Filter *.log | Select-Object Name, Length | ConvertTo-Csv -NoTypeInformation
"Name","Length"
                    "app.log","532"
                    "old.log","36"

Out-String的两种形式也需要区分。基本形式把加了格式的整个结果变成一个字符串，-Stream则每行变成一个字符串。要逐行传给Select-String，就需要-Stream。

$s = Get-ChildItem -File -Filter *.log | Out-String
                    $s.GetType().Name + ', lines = ' + ($s -split "`r?`n").Count
                    $l = Get-ChildItem -File -Filter *.log | Out-String -Stream
                    $l.GetType().Name + ' of ' + $l.Count + ' lines'
String, lines = 12
                    Object[] of 11 lines

格式化cmdlet(如Format-Table)发出的不是可用于排序或筛选的原始对象，而是格式指令对象。因此Format-*只在管道的最末端使用。对两项的文件列表应用Format-Table Name后得到的对象类型及其Name属性，验证如下。

$ft = Get-ChildItem -File | Select-Object -First 2 | Format-Table Name
                    ($ft | ForEach-Object { $_.GetType().Name }) -join ', '
                    'Name property on those objects: [' + (($ft | ForEach-Object { $_.Name }) -join '') + ']'
FormatStartData, GroupStartData, FormatEntryData, FormatEntryData, GroupEndData, FormatEndData
                    Name property on those objects: []
  • 控制台上看到的表是显示而不是值。需要值时，在使用Format-*之前先完成Select-Object或Where-Object。
  • 需要宽列时，用Out-String -Width、-Wrap、Format-List中的一种避免截断。
  • 把值传给文件或其他工具时，使用ConvertTo-Csv之类的数据格式，而不是表格式。
