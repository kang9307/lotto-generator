ホームラボで作るAI開発プラットフォーム

クラウドコスト・プライバシー問題の出口 — Ollama・vLLM・Open WebUI スタック、ハードウェア、電力、実現可能性を2026年6月時点の実務視点で分析

2026-06-17 開発・インフラ

はじめに：なぜ自宅にAI開発基盤を作るのか

2026年6月時点で、開発者コミュニティに興味深い流れが鮮明になってきた。クラウドAI APIから始めて、気づけば自宅のサーバーを引っ張り出すパターンだ。動機は二つに集約される。一つはコスト、もう一つはプライバシーだ。

ChatGPT Plusは月約2,000〜3,000円、Claude Proも同水準だ。トークン単位のAPI課金は、コードベース全体をコンテキストに乗せるエージェント型ワークフローでは請求額が跳ね上がる。そして率直に言おう。会社のコード、内部設計資料、顧客データを外部APIに送ることに抵抗を感じるチームは少なくない。ホームラボAI開発プラットフォームは、この二つの問題に正面から向き合う。

2026年6月、Hacker NewsやGeekNewsで話題になったrsgm.devの投稿は、OpenCode + Forgejo + GitOpsの組み合わせでセルフホスト型AIコーディングパイプラインを構築した事例を共有した。ワークフローはシンプルだ。AIがコードを書いてPRを開き、人間がレビューして承認すればGitOpsがデプロイする。外部APIへの依存度を自社GPUで置き換えることで、コストが固定されコードが外に出なくなる。

この記事ではその事例を出発点にしつつ、複製はしない。2026年6月時点のホームラボAI開発プラットフォームの現実的なスタック、ハードウェア選択、電力コスト、そして実際に導入する際の考慮点を、本稿独自の視点で分析する。

1. なぜ今なのか — セルフホスティングが現実的になった背景

1.1 オープンウェイトモデルの品質が閾値を超えた

2025〜2026年にかけて、オープンウェイトLLMの品質が急速に向上した。Llama、Qwen、Mistral、Gemma、DeepSeekの各系列が相次いで公開され、クラウドAPIなしでも開発補助用途に使えるモデルを自宅で動かすことが技術的に現実となった。2026年時点では、Qwen 2.5 32Bを4ビット量子化してRTX 3090で動かすと、多くのコード補助タスクでGPT-3.5を超える体感が得られると開発者コミュニティで報告されている。

特にOllamaの登場が決定的だった。パッケージマネージャーのようにollama pull qwen2.5:14bの一行でモデルをダウンロードし、自動でREST APIが開く。以前はCUDA環境設定に一日を費やしていたのが、今ではインストールから最初の推論まで30分で完結する。

1.2 エージェント型ワークフローがコスト問題を加速させた

ホームラボへの関心をさらに高めたのは、単純なチャットではなくエージェント型コーディングだ。AIがリポジトリ全体を読み、複数ファイルにわたる変更を計画し、テストを実行してイテレーションを繰り返すワークフローは、Q&Aに比べてトークン消費量が桁違いに多い。大規模なコードベースを扱う開発者がClaude Codeなどのツールを積極的に使うと、月のAPI費用が数千円から数万円に跳ね上がるケースもある。そこで「GPUを一台買った方が安いのでは」という計算が始まる。

1.3 プライバシーが最優先要件になった

金融・医療・公共機関はもちろん、競争が激しいスタートアップでも、ソースコードが外部APIサーバーに送られることを規定や戦略上の理由で避けたいケースは多い。自社GPUで推論すれば、プロンプトが社内ネットワーク外に出ない。この「データ統制」は、価格比較より先に来る意思決定であることが多い。

2. 2026年ホームラボAIスタック — レイヤー別構造

2.1 推論ランタイム層：OllamaとvLLM

Ollamaは単独ユーザー環境の事実上の標準だ。モデル管理、GPU オフロード、REST API提供が一つのデーモンに統合されている。NVIDIA CUDA、AMD ROCm、Apple Silicon Metalをすべてサポートし、設定ファイル不要で動く。欠点は複数ユーザーの同時リクエスト処理性能がvLLMに及ばない点だ。

vLLMはチームサービング・バッチ推論・高スループットのシナリオ向けだ。PagedAttentionによるGPUメモリの効率的な管理で、同時リクエストが増えるほどOllamaを大きく上回るスループットが出る。ただし設定が複雑で、GPU環境によってはビルドが難しい。個人ホームラボの出発点としては過剰であり、チームができるかサービング需要が高まってから移行を検討すればよい。

2.2 プロキシ/ルーティング層：LiteLLM

LiteLLMはホームラボスタックの縁の下の力持ちだ。Ollama、vLLM、OpenAI、Anthropicその他数十のAPIを単一のOpenAI互換エンドポイントとして束ねる。アプリやツールでエンドポイントURLを一箇所変えるだけでバックエンドモデルを切り替えられる。ホームラボモデルをメインにしつつ、特定タスクでだけクラウドAPIにフォールバックするハイブリッド運用が、このレイヤーのおかげでシンプルになる。

2.3 インターフェース層：Open WebUI

Open WebUIはOllamaの上にChatGPTスタイルのWebインターフェースを重ねる。ドキュメントアップロード、RAG（検索拡張生成）、ツール呼び出し、マルチユーザー認証、会話履歴が含まれる。チームが同じホームラボLLMをブラウザで共有する最も手軽な方法だ。インストールはDocker Composeファイル一つで完結する。

2.4 開発ツール層：IDE統合

コーディング補助が目的なら、Continue.dev（VS Code/JetBrainsプラグイン）、Aider（ターミナルベース）、OpenCode（エージェント）をOllamaまたはLiteLLMに接続する。Continue.devはインライン補完とチャットをローカルモデルで動かす。rsgm.devのケースで注目すべきはOpenCodeで、Gitアクセス権を与えてPRを開かせることで「AIが提案し人間が承認する」GitOpsパイプラインが実現する。

2.5 ワークフロー自動化層：n8n

n8nはLLMをメール・Webhook・データベース・スマートホームなどと接続するビジュアルワークフローツールだ。OllamaでローカルLLMを立ち上げ、n8nで「新しいGitHub Issueが作られたら要約してSlackに送る」といったパイプラインを組める。コードレスで設定でき、セルフホスト可能な点がホームラボとよく合う。

3. ハードウェア選択 — GPUとVRAMの現実

3.1 VRAMが決定的

ローカルLLM推論では、VRAMがCPUクロック速度よりずっと重要だ。モデル全体またはその大半がVRAMに乗ることでGPUアクセラレーションが有効になる。VRAMに収まらない分はシステムRAMにオフロードされ、推論速度が大幅に低下する。

  • 7Bモデル、4ビット量子化：VRAM 4〜6GB — RTX 3060（12GB）で余裕
  • 13Bモデル、4ビット量子化：VRAM 8〜10GB — RTX 4070（12GB）以上推奨
  • 32Bモデル、4ビット量子化：VRAM 約20GB — RTX 3090（24GB）・RTX 4090（24GB）が適合
  • 70Bモデル、4ビット量子化：VRAM 40〜48GB — RTX 3090 2枚またはA6000（48GB）が必要

3.2 2026年コスパ最良：RTX 3090

2026年時点で、中古RTX 3090（24GB VRAM、TDP 350W）がホームラボAI推論のコスパ最良GPUとして一貫して挙がる。32Bモデルをネイティブにカバーし、70Bも量子化込みで動かせる。消費電力はRTX 4090（450W）より低い。中古価格は地域・状態によるが、概ね7〜10万円台が目安だ。純粋なLLM推論目的であれば3090が2026年現在の選択筆頭だ。

RTX 4090は同じ24GBでも推論速度が3090比30〜40%速いが、新品価格は2倍以上になる。複数ユーザーの同時サービングや動画生成を並行する用途では投資価値があるが、個人開発用ホームラボの出発点としては過剰になりやすい。

4. 電力コスト計算

4.1 日本の電力単価での試算

日本の従量電灯Bの第3段階（120kWh超）は地域・時期によって異なるが、概ね28〜32円/kWh前後が目安だ（2026年6月時点）。RTX 3090（TDP 350W）システムを1日8時間・GPU負荷70%で稼働させた場合の試算：GPU実効消費280W + システム120W = 合計400W。月8時間×30日=240時間。400W×240h=96kWh。30円/kWhで計算すると月約2,880円の追加電気代だ。

24時間フル稼働では同条件で月約8,640円となる。ChatGPT Plus（月約3,000円）やClaude Pro（同程度）の代替として考えると、1日8時間運用での電気代だけで見ればほぼ同水準になる。

4.2 投資回収の現実

中古RTX 3090が7万円、システム全体で12万円の初期投資と仮定しよう。APIコストを月5,000円削減できるとして、電気代2,880円を引いた純節約は約2,120円/月。初期投資回収には約57ヶ月（約5年）かかる計算だ。純粋なコスト節減だけでは、ホームラボは必ずしも経済合理的ではない。

ただしこの計算が見落とすものがある。回数制限のない実験自由度、完全なデータプライバシー、量子化・システムプロンプトによる深い制御、そして何より学習の価値だ。推論インフラを自分で運用することで、AIシステムエンジニアとして不可欠な実践知識が身につく。この価値はスプレッドシートに収まらない。

5. ホームラボが適さないケース

5.1 最高品質が必要なタスク

2026年6月時点で、最上位の32Bオープンウェイトモデルとフロンティアクラウドモデル（Claude Opus 4.8、GPT-5）の間には、複雑なタスクにおいて体感できる品質差がまだある。本番マイグレーションのコードレビュー、複雑なシステムアーキテクチャ設計、高精度な法律・医療文書分析では、ローカルモデルの限界が現れやすい。

5.2 API費用が少ない場合

月のAPI費用が2,000〜3,000円以下なら、10万円以上のハードウェア投資の回収は5年以上かかる。この規模ではクラウドAPIの方が経済合理的だ。

5.3 メンテナンス負荷

マネージドクラウドと異なり、ホームラボはCUDAドライバの更新、モデルバージョン管理、ハードウェア障害対応、バックアップなどをすべて自分で行う必要がある。この運用負荷は、インフラをいじること自体を楽しめるエンジニアには「おまけ」だが、ソフトウェア開発本業に集中したい人には実質的なコストになる。

6. 結論 — ホームラボAIプラットフォームが合う人

2026年6月時点で、以下の三タイプには真剣な選択肢だ。

プライバシー最優先の環境：コード・データを外部に送れない金融・医療・公共機関、または機密保持が重要なスタートアップ。コスト計算と関係なく、ローカル推論が唯一の選択肢になる。

インフラを自分で学びたいエンジニア：GPUサーバーを実際に運用し、推論ランタイムの内側を理解し、LiteLLMの設定を手で触る経験が目的なら、ホームラボは最高の学習環境だ。コスト節減より学習がROIだ。

月5,000円以上のAPIコストが継続しているチーム：この規模からはハードウェア投資の収支が2〜3年以内に合ってくる可能性がある。特にハイブリッド構成（ローカルOllama + クラウドフォールバック）から始めればリスクなく移行速度を調整できる。

最も実用的な答えは2026年時点でもハイブリッドだ。日常タスクはローカル、品質が決定的なタスクはLiteLLM経由でクラウドAPI。ホームラボはオール・オア・ナッシングである必要はない。
