JavaScript Basic Syntax Guide

A quick reference to JavaScript fundamentals

2025-06-01 Dev & Infra

JavaScript is the most widely used programming language in web development. This article walks through the core syntax and key concepts you need to know to get started.

Everything here follows the modern standard, meaning ES2015 (ES6) and later. Standardized in 2015, ES6 introduced let, const, arrow functions, template literals, classes, and modules all at once, and it effectively turned JavaScript into a different language. Plenty of older tutorials still lean on var and ==, but if you are learning today there is no reason to inherit those habits. This guide explains not only what to write, but why the older approach is worth avoiding.

Every example is written so you can paste it straight into your browser's developer console (F12) or into Node.js, and the comments show the actual output. Reading is not enough: running each snippet and checking the result is by far the fastest way to make the basics stick. When an output surprises you, change the values on the spot and experiment.

Here is what this guide covers:

  • Scope and hoisting: how long a variable lives and what happens if you touch it too early
  • Data types: the seven primitive types and what typeof reports for each

  • Conditionals and loops: when to reach for if, switch, for...of, or for...in
  • Functions: declarations, expressions, arrow functions, and how this differs

  • Common mistakes: twelve traps almost every beginner hits at least once

Variable Declaration

In JavaScript, you can declare variables using the var, let, and const keywords.

// var (function scope)
var x = 5;

// let (block scope)
let y = 10;

// const (constant, cannot be reassigned)
const PI = 3.14;

These three keywords are not just different spellings. They differ in scope, in whether redeclaration and reassignment are allowed, and in what happens when you access them before the declaration line. The table below lays it out.

Aspectvarletconst
ScopeFunction scopeBlock scope { }Block scope { }
ReassignmentAllowedAllowedNot allowed (TypeError)
Redeclaring the same nameAllowed (silently overwrites)Not allowed (SyntaxError)Not allowed (SyntaxError)
Access before declarationReturns undefinedReferenceError (TDZ)ReferenceError (TDZ)
Initializer requiredOptionalOptionalRequired
Added to the global object at top levelYesNoNo
Recommended in new codeDo not useOnly when the value changesDefault choice

The working rule is short. Declare with const by default, downgrade to let only when you genuinely need to reassign, and never reach for var in new code. That habit encodes "this value will not change" directly into the source, which reduces the amount of mutable state a future reader has to track. Switch to let at the exact moment reassignment becomes necessary and not a line earlier.

Scope: where a variable stays alive

var is function scoped, so a variable declared inside an if or for block escapes that block and remains reachable throughout the whole function. let and const are block scoped and simply do not exist outside their braces. A throwaway variable that was meant to live for three lines but survives to the end of the function is a classic starting point for bugs.

// var: function scoped, declaration hoisted (value is undefined)
function varScope() {
  console.log(typeof value); // "undefined" - not an error
  if (true) {
    var value = 1;
  }
  return value;              // 1 - still reachable outside the if block
}

// let: block scoped
function letScope() {
  if (true) {
    let value = 1;
    console.log(value);      // 1
  }
  // console.log(value);     // ReferenceError: value is not defined
}

console.log(varScope());     // 1
letScope();

A few points worth remembering about scope:

  • Every pair of braces { } — if, for, while, or a bare block — forms a boundary for let and const.
  • An inner scope can read variables from the enclosing scope, but never the other way around.
  • Redeclaring the same name in an inner scope creates shadowing, which hides the outer variable. If that was not intentional, rename one of them.
  • Omitting the keyword entirely and writing x = 1 creates a global in sloppy mode. Adding 'use strict' at the top of the file, or using ES modules (type="module"), turns that mistake into an error.

Hoisting and the temporal dead zone

The engine processes declarations before it runs your code. var is initialized to undefined at that point, so reading it above its declaration line yields undefined instead of an error. The program keeps running with a value that is not there yet, which makes the resulting bug hard to trace.

let and const are hoisted too, but they stay uninitialized. The stretch between the start of the block and the declaration line is called the temporal dead zone (TDZ), and touching the variable inside it throws a ReferenceError. Failing loudly is far safer than quietly working with the wrong value.

// var: one shared binding for the whole loop → 3, 3, 3
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log('var:', i), 0);
}

// let: a fresh binding on every iteration → 0, 1, 2
for (let j = 0; j < 3; j++) {
  setTimeout(() => console.log('let:', j), 0);
}

This snippet shows the practical consequence of the difference more sharply than any definition. var i is a single binding shared across the loop, so by the time the callbacks run it already holds 3. let j creates a separate binding per iteration, so each callback remembers its own value. Developers used to work around this with immediately invoked functions; today, simply using let makes the problem disappear.

What const protects and what it does not

const does not mean "the value never changes." It means you cannot assign a different value to that binding. Objects and arrays declared with const can still have their properties and elements modified. Freezing the contents requires Object.freeze(), and even that only freezes one level deep.

const config = { retry: 3 };
config.retry = 5;             // OK - inner values can still change
console.log(config.retry);    // 5

// config = { retry: 5 };     // TypeError: Assignment to constant variable.

const frozen = Object.freeze({ retry: 3 });
frozen.retry = 5;             // silently ignored in sloppy mode
console.log(frozen.retry);    // 3

In short, const locks the binding while Object.freeze() locks the surface of the object. Conflating the two — assuming "it is a const, so it is safe" — is how you miss a shared object being mutated somewhere else in the codebase.

Data Types

JavaScript provides the following basic data types:

  • String: text values
  • Number: numeric values
  • Boolean: logical values (true/false)
  • null: an intentional absence of value
  • undefined: a variable that has not been assigned a value
  • Object: collections of key-value pairs
  • Symbol: a unique and immutable primitive type
let name = "John Doe";  // String
let age = 25;           // Number
let isActive = true;    // Boolean
let user = {            // Object
  name: "John Doe",
  age: 25
};

To be precise, every JavaScript value is either one of the seven primitive types or an object. Primitives are plain values without methods or properties of their own, and they are immutable: an operation that feels like "changing" a primitive actually produces a new value and reassigns it. Objects, by contrast, group several values together, and a variable holds a reference to the object rather than the object itself.

Checking types with typeof

console.log(typeof "hi");         // "string"
console.log(typeof 42);           // "number"
console.log(typeof 10n);          // "bigint"
console.log(typeof true);         // "boolean"
console.log(typeof undefined);    // "undefined"
console.log(typeof Symbol("id")); // "symbol"
console.log(typeof null);         // "object" ← a bug from the first implementation
console.log(typeof [1, 2]);       // "object" ← arrays are objects too
console.log(typeof function(){}); // "function"

// So arrays and null need dedicated checks
console.log(Array.isArray([1, 2])); // true
const v = null;
console.log(v === null);            // true

typeof null returning "object" is a leftover from JavaScript's original implementation. A fix was proposed but rejected because it would break existing sites, so the quirk is permanent. That means you should test for null with === null and for arrays with Array.isArray().

Type conversion: make it explicit

When you combine values of different types, JavaScript quietly converts one of them for you. That convenience comes with rules that are not intuitive, and it is where beginners stumble most often. Stating your intent with Number(), String(), and Boolean() is far safer than relying on the implicit path.

// String → Number
console.log(Number("42"));                 // 42
console.log(Number(""));                   // 0    ← an empty string becomes 0
console.log(Number("42px"));               // NaN
console.log(parseInt("42px", 10));         // 42   ← reads as far as it can
console.log(Number.parseFloat("3.14abc")); // 3.14

// Number → String
console.log(String(42));       // "42"
console.log((42).toString(2)); // "101010"  ← binary string

// The traps of implicit coercion
console.log(1 + "2");  // "12"  + concatenates when either side is a string
console.log("3" - 1);  // 2     - converts the string to a number first
console.log([] + {});  // "[object Object]"
  • Always pass a radix to parseInt(). Writing parseInt("08", 10) makes the intent unambiguous.
  • Values read from form inputs (input.value) are always strings. Convert with Number() before doing arithmetic.
  • Only + doubles as string concatenation; -, *, and / always try numeric conversion. That asymmetry is why "3" - 1 === 2 but 1 + "2" === "12".
  • Use Number.isNaN() and Number.isFinite() for numeric checks. The global isNaN() coerces its argument first, so isNaN("abc") is true.

Truthy, falsy, and the ?? operator

Values that behave like false inside a condition are called falsy; everything else is truthy. There are exactly eight falsy values, so it is worth memorizing the whole list.

0The number zero"0" (a non-empty string)
-0Negative zero[] (an empty array)

const falsyValues = [false, 0, -0, 0n, "", null, undefined, NaN];
console.log(falsyValues.every(v => !v)); // true - all eight are falsy

// || filters out every falsy value, so it also replaces 0 and ""
const count1 = 0 || 10;  // 10 ← usually not what you meant

// ?? only substitutes for null or undefined (ES2020)
const count2 = 0 ?? 10;  // 0  ← what you meant

console.log(count1, count2); // 10 0

Writing "use a default when the value is missing" with || also overwrites legitimate but falsy values such as the number 0 or an empty string. The nullish coalescing operator ?? only reacts to null and undefined, which prevents that class of bug entirely.

Operators and Comparison: === Instead of ==

Loose equality == converts one operand when the two types differ, and the conversion rules are convoluted enough that the outcome is hard to predict. It is one of the most common sources of logic bugs in JavaScript. Strict equality === returns false immediately whenever the types differ, so there is only one rule to remember. Unless you have a specific reason, always use === and !==.

Comparison== result=== resultWhy
1 vs "1"truefalseThe string is converted to a number
0 vs ""truefalseThe empty string converts to 0
0 vs falsetruefalseThe boolean converts to the number 0
[] vs falsetruefalse[] → "" → 0
null vs undefinedtruefalse== treats only these two as equal
null vs 0falsefalsenull equals nothing except undefined
NaN vs NaNfalsefalseNaN is not even equal to itself
{a:1} vs {a:1}falsefalseObjects compare by reference, not contents
 
console.log(1 == "1");            // true  - the string is converted
console.log(1 === "1");           // false - different types, always false
console.log(null == undefined);   // true
console.log(null === undefined);  // false
console.log([] == false);         // true  - [] → "" → 0
console.log(0 == "");             // true

console.log(NaN == NaN);          // false - NaN differs from itself
console.log(Number.isNaN(NaN));   // true  - the correct check
console.log(Object.is(NaN, NaN)); // true  - Object.is treats NaN as equal

A few more things to keep in mind when comparing values:

  • The one genuinely useful case for == is value == null, a compact way to test for null and undefined together. Everywhere else, use ===.
  • === on objects and arrays only checks whether the references match. Comparing contents requires checking each property or writing a helper.
  • Detect NaN with Number.isNaN() or Object.is(). The expression x === NaN is always false.
  • Relational operators such as < and > still coerce, unlike ===. Normalizing with Number() before comparing is the safer habit.

Conditionals and Loops

Conditionals branch the flow of a program, and loops apply the same work to many values. Use if...else for a two-way decision, switch when one value is matched against several candidates, and the ternary operator when only the resulting value changes.

const score = 87;

// if / else if / else
if (score >= 90) {
  console.log("A");
} else if (score >= 80) {
  console.log("B");   // ← this runs
} else {
  console.log("C");
}

// Ternary operator: concise when you are picking a value
const grade = score >= 80 ? "pass" : "fail";

// switch: forgetting break makes execution fall through
switch (grade) {
  case "pass":
    console.log("congratulations");
    break;
  default:
    console.log("try again");
}

Choosing a loop

There are many loop forms but only a few see daily use. The baseline rule is simple: use for...of to walk the values of an array and for...in to walk the keys of an object. The names look alike, so pin down the difference early.

const scores = [90, 75, 88];

// for...of : iterates values (recommended for arrays)
for (const s of scores) {
  console.log(s);        // 90, 75, 88
}

// for...in : iterates keys (for objects; avoid on arrays)
const user = { name: "John Doe", age: 25 };
for (const key in user) {
  console.log(key, user[key]);  // name John Doe / age 25
}

// Need the index alongside the value? Use entries()
for (const [i, s] of scores.entries()) {
  console.log(i, s);     // 0 90 / 1 75 / 2 88
}

// while: when the iteration count is not known up front
let n = 3;
while (n > 0) {
  n--;
}
  • for...in hands back array indices as strings and also walks inherited properties, so it should not be used on arrays.
  • Declare the loop variable with const by default. for...of creates a fresh binding each round, so const is enough unless you reassign it.
  • break stops the loop entirely; continue skips only the current iteration.
  • break does not work inside forEach(). If you need an early exit, use for...of or reach for some() / every().
  • If the goal is to transform or filter an array, map() and filter() state the intent far more clearly than a manual loop.

Functions

Functions are a key concept that improves code reusability.

// Function Declaration
function add(a, b) {
  return a + b;
}

// Function Expression
const multiply = function(a, b) {
  return a * b;
};

// Arrow Function
const divide = (a, b) => a / b;

These three forms differ in more than syntax: hoisting behaviour and how this is resolved are not the same. When you are unsure which to pick, use the table below as your default.

Default and rest parameters, and this in arrow functions

ES2015 added several features that make functions much shorter to write. Default parameters, rest parameters, and template literals show up in almost every modern codebase, so they are worth learning now.

// Default parameters (ES2015)
function greet(name, greeting = "Hello") {
  return `${greeting}, ${name}`;   // template literal
}
console.log(greet("John"));        // "Hello, John"

// Rest parameters: collect an unknown number of arguments into an array
function sum(...numbers) {
  return numbers.reduce((acc, n) => acc + n, 0);
}
console.log(sum(1, 2, 3, 4));      // 10

// An arrow function has no this of its own; it uses the enclosing this
const timer = {
  label: "timer",
  startArrow() {
    setTimeout(() => console.log(this.label), 0);            // "timer"
  },
  startFunc() {
    setTimeout(function () { console.log(this.label); }, 0);  // undefined
  }
};
timer.startArrow();
timer.startFunc();
  • Choose an arrow function when a callback needs the surrounding object's this. It removes the old const self = this and .bind(this) workarounds.
  • Conversely, do not define object methods as arrow functions: this will not point at the object. The shorthand method syntax (startArrow() { }) is the correct form.
  • An arrow function whose body is a single expression can drop the braces and the return. Once you add braces, the return becomes mandatory.
  • To return an object literal directly, wrap it in parentheses: () => ({ id: 1 }). Without them the braces are parsed as the function body.

Arrays and Loops

Arrays and loops let you process collections of data efficiently.

// Array declaration
const fruits = ["apple", "banana", "orange"];

// for loop
for (let i = 0; i < fruits.length; i++) {
  console.log(fruits[i]);
}

// forEach method
fruits.forEach(fruit => {
  console.log(fruit);
});

// map method (returns a new array)
const fruitLengths = fruits.map(fruit => fruit.length);

In real projects, array methods are used far more often than for loops, because the method name states what you are trying to do and the code reads faster as a result. Here are the ones worth knowing first.

const products = [
  { name: "keyboard", price: 45000 },
  { name: "mouse", price: 25000 },
  { name: "monitor", price: 300000 }
];

// filter: keep only the elements that match
const cheap = products.filter(p => p.price < 100000);
console.log(cheap.length);   // 2

// map: transform each element
console.log(products.map(p => p.name));  // ["keyboard", "mouse", "monitor"]

// reduce: collapse into one value (the second argument is the seed)
const total = products.reduce((acc, p) => acc + p.price, 0);
console.log(total);          // 370000

// find / some / every
console.log(products.find(p => p.price > 100000).name); // "monitor"
console.log(products.some(p => p.price > 100000));      // true
console.log(products.every(p => p.price > 10000));      // true

Methods that mutate versus methods that copy

The most frequent source of accidents with array methods is forgetting which ones modify the original. sort(), reverse(), splice(), and push() mutate in place, while map(), filter(), slice(), and concat() build a new array. ES2023 added toSorted(), toReversed(), toSpliced(), and with(), which do the same work without touching the original.

const nums = [3, 1, 2];
const sorted = nums.sort((a, b) => a - b);
console.log(nums, sorted === nums);  // [1,2,3] true ← the original changed

// toSorted leaves the original alone and returns a new array (ES2023)
const base = [3, 1, 2];
const copy = base.toSorted((a, b) => a - b);
console.log(base, copy);             // [3,1,2] [1,2,3]

// Without a comparator, numbers are sorted as strings
console.log([10, 9, 100].sort());               // [10, 100, 9]  ← the trap
console.log([10, 9, 100].sort((a, b) => a - b)); // [9, 10, 100]

By default sort() converts each element to a string and orders them lexicographically, which is why [10, 9, 100] becomes [10, 100, 9]. When sorting numbers you must pass the comparator (a, b) => a - b.

Working with Objects

An object is a collection of key: value pairs that groups the properties of a single thing. Destructuring and the spread operator, both added in ES2015, shorten object-handling code noticeably.

const user = { name: "John Doe", age: 25, address: { city: "Seoul" } };

// Destructuring assignment (ES2015)
const { name, age } = user;
console.log(name, age);            // John Doe 25

// Spread to copy and override part of it (the original is untouched)
const updated = { ...user, age: 26 };
console.log(updated.age, user.age); // 26 25

// Optional chaining (ES2020): undefined instead of an error
console.log(user.address?.city);    // "Seoul"
console.log(user.company?.name);    // undefined

// Iterating keys and values
console.log(Object.keys(user));     // ["name", "age", "address"]
Object.entries({ a: 1, b: 2 }).forEach(([k, v]) => console.log(k, v));
  • Destructuring works in function parameters too. Writing function f({ name, age }) { } means callers no longer have to remember argument order.
  • The spread operator ... copies and merges both objects and arrays, and later values win over earlier ones.
  • Optional chaining ?. is especially useful for nested data such as API responses, where a branch may or may not exist.
  • Object.keys(), Object.values(), and Object.entries() turn an object into an array so you can chain array methods onto it.
  • To use a variable as a key, use bracket notation: obj[key] looks up the variable's value, while obj.key looks up the literal string "key".

Shallow copies and deep copies

The spread operator and Object.assign() perform a shallow copy: only the top level is recreated, and nested objects and arrays still point at the originals. That is why editing the inside of a "copy" can change the source.

const original = { name: "John Doe", tags: ["a", "b"] };

const shallow = { ...original };
shallow.tags.push("c");
console.log(original.tags);   // ["a","b","c"] ← the original changed too

const deep = structuredClone(original);  // deep copy (modern browsers, Node 17+)
deep.tags.push("d");
console.log(original.tags.length, deep.tags.length); // 3 4

When you need a genuine deep copy, the built-in structuredClone() is the simplest option. The old JSON.parse(JSON.stringify(obj)) trick is not recommended: it turns Date objects into strings and drops undefined, functions, Map, and Set.

Async Basics: Promises and async/await

JavaScript runs on a single thread and does one thing at a time. So that the page does not freeze while a slow operation such as a network request finishes, those operations are handled on a "tell me when you are done" basis. The object that represents such a pending result is a Promise, and async/await is the syntax that lets promise-based code read like ordinary sequential code.

function delay(ms, value) {
  return new Promise(resolve => setTimeout(() => resolve(value), ms));
}

// When the next step needs the previous result → sequential (about 100ms)
async function runSequential() {
  const a = await delay(50, "A");
  const b = await delay(50, "B");
  return a + b;
}

// When the calls are independent → parallel (about 50ms)
async function runParallel() {
  const [a, b] = await Promise.all([delay(50, "A"), delay(50, "B")]);
  return a + b;
}

// Errors are caught with try/catch
async function safeRun() {
  try {
    return await delay(10, "ok");
  } catch (err) {
    console.error("failed:", err);
    return null;
  }
}

runSequential().then(r => console.log("sequential:", r)); // "AB"
runParallel().then(r => console.log("parallel:", r));     // "AB"
safeRun().then(r => console.log("safeRun:", r));          // "ok"
  • await is only valid inside an async function, with top-level ES modules as the exception. Using it in a plain function is a syntax error.
  • An async function always returns a promise. Even if you return a plain value, the caller has to unwrap it with await or .then().
  • Lining up independent requests as consecutive await statements makes them needlessly slow. Group them with Promise.all() instead.
  • Catch errors from async functions with try/catch. If you use a .then() chain, always terminate it with .catch().

Twelve Mistakes Beginners Make

Almost everyone learning JavaScript runs into the items below at least once. Knowing them in advance cuts a lot of debugging time.

  1. Comparing NaN with ===. NaN === NaN is false. Use Number.isNaN(x) or Object.is(x, NaN).
  2. Expecting 0.1 + 0.2 === 0.3 to be true. Floating point makes the actual value 0.30000000000000004. Compare with a tolerance, or work in integer units.
  3. Reaching for == out of habit. 0 == "" and [] == false are both true, which is hard to predict. Make === your default.
  4. Defining object methods as arrow functions. An arrow function has no this of its own, so it cannot read the object's properties. For callbacks, however, arrow functions are exactly right.
  5. Reading an async result synchronously. The line right after fetch() has no value yet. Wait with await or handle it inside .then().
  6. Using the return value of an async function directly. If the console prints Promise { <pending> }, you forgot an await.
  7. Calling sort() on numbers without a comparator. They are ordered as strings, producing [10, 100, 9]. Pass (a, b) => a - b.
  8. Forgetting return inside a map() callback. An arrow function with braces and no explicit return fills the array with undefined.
  9. Comparing object or array contents with ===. Different references are unequal even with identical contents. Compare the properties instead.
  10. Mistaking a shallow copy for a deep one. { ...obj } copies one level. For nested structures, use structuredClone().
  11. Doing arithmetic on strings. "5" + 3 is "53". Convert with Number() first.
  12. Supplying defaults with ||. A value of 0 or "" gets replaced too. Use ??.
// Mistake 2: floating point
console.log(0.1 + 0.2);          // 0.30000000000000004
console.log(0.1 + 0.2 === 0.3);  // false

const almostEqual = (a, b) => Math.abs(a - b) < Number.EPSILON;
console.log(almostEqual(0.1 + 0.2, 0.3)); // true

// Working in the smallest integer unit and dividing at the end is safe
console.log((0.1 * 10 + 0.2 * 10) / 10);  // 0.3

// Mistake 8: the map callback has no return
console.log([1, 2, 3].map(n => { n * 2; }));      // [undefined, undefined, undefined]
console.log([1, 2, 3].map(n => n * 2));          // [2, 4, 6]

Most of these come from trusting JavaScript to "figure it out for you." Getting into the habit of spelling out type conversions and copies in the code eliminates more than half of them.

Frequently Asked Questions

How do you declare variables in JavaScript?

You can declare variables with the var, let, and const keywords. Each has different characteristics, so you choose the one that fits the situation. In practice, use const by default, switch to let only when the value has to be reassigned, and avoid var in new code because of its function scoping and hoisting behaviour.

What are JavaScript's basic data types?

They are string, number, boolean, null (an intentional absence of value), undefined (no value assigned), object, and symbol, a unique and immutable type. Adding BigInt for large integers brings the primitive types to seven in total, with objects being the only values handled by reference. typeof null reports "object" because of an early bug in the language, so test for it with === null.

Why are functions an important concept in JavaScript?

Functions are the key mechanism for reusing code. Wrapping repeated logic in a function lets you call it whenever you need it. In JavaScript functions are also values, so you can store them in variables and pass them as arguments, which is what makes higher-order methods such as map() and filter() and event callbacks possible.

What role do arrays and loops play?

Arrays and loops let you process many pieces of data efficiently: you collect values that would be tedious to handle individually into an array, then walk through it. That said, when the goal is to transform or filter data, array methods such as map(), filter(), and reduce() express the intent more clearly than a manual for loop.

What can you do once you learn JavaScript's basic syntax?

With the fundamentals in place you can build a wide range of web applications, and variables, data types, functions, arrays, and loops are the starting point. Adding DOM manipulation and fetch is enough to build a working web page, and moving on to modules and classes leads naturally into learning a framework.

Once you have the fundamentals of JavaScript down, you can build a wide range of web applications on top of them.
