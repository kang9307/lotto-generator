Complete Guide to Ceph Reef Read Balance: Core Feature for Performance Innovation

2025-07-15 Dev & Infra

The Read Balance feature introduced in Ceph Reef Release (18.2) is a core technology that revolutionizes distributed storage performance. In this guide, we walk through Read Balance from an expert perspective -- covering how it works, how to implement it in practice, and the performance improvements you can expect.

This guide dives deep into the internals of Read Balance, showing you how it differs from the legacy Primary-only read path and why it matters for modern read-intensive workloads.

What Is Ceph Reef Read Balance?

Read Balance is a groundbreaking feature that intelligently distributes read operations across multiple OSD replicas in a Ceph cluster. Previously, reads were serviced only by the Primary OSD, but now you can take advantage of every replica to maximize read performance.

Key Innovations

  • Optimized load distribution: Completely eliminates the Primary OSD bottleneck
  • Higher performance: Up to 300% higher read throughput
  • Lower latency: More than 50% improvement in average response time
  • Automatic optimization: Real-time, load-aware automatic adjustments

The Legacy Pain Points and How Read Balance Solves Them

Limitations of the Traditional Ceph Read Mechanism

Traditionally, Ceph served reads exclusively from the Primary OSD. That design caused several issues:

+-----------------------------------------+
|     Legacy read path (pain points)      |
+-----------------------------------------+
|  Client -> Primary OSD (overloaded)     |
|                |                        |
|           Secondary OSD (idle)          |
|           Secondary OSD (idle)          |
|                                         |
|  Result: bottlenecks, degraded perf     |
+-----------------------------------------+

The Read Balance Solution

+-----------------------------------------+
|   Read Balance approach (the fix)       |
+-----------------------------------------+
|  Client -> Primary OSD (balanced)       |
|        \  Secondary OSD (actively used) |
|        \  Secondary OSD (actively used) |
|                                         |
|  Result: balanced distribution,         |
|          optimized performance          |
+-----------------------------------------+

How Read Balance Works

1. Dynamic Load-Balancing Algorithm

Read Balance continuously monitors the load on each OSD in real time and selects the optimal target for each read.

# Pseudocode for the Read Balance algorithm
def select_read_osd(pg_replicas, read_request):
    # Check the current load for each OSD
    osd_loads = {osd: get_osd_load(osd) for osd in pg_replicas}

    # Weight-based selection (lower load -> higher probability)
    weights = calculate_weights(osd_loads)
    selected_osd = weighted_random_choice(pg_replicas, weights)

    return selected_osd

3. Network-Latency-Aware Selection

# OSD selection based on network latency
def select_optimal_osd(client_location, osd_replicas):
    latencies = {}
    for osd in osd_replicas:
        latencies[osd] = measure_network_latency(client_location, osd)

    # Prefer the OSD with the lowest latency
    return min(latencies, key=latencies.get)

Configuring and Implementing Read Balance

Enabling the Basic Settings

# Enable Read Balance globally
ceph config set global osd_read_ec_check_for_errors false
ceph config set global osd_read_ec_check_for_corruption false
ceph config set global bluestore_prefer_deferred_size_hdd 32768

# Enable read balancing
ceph config set osd osd_read_ec_check_for_errors false
ceph config set osd osd_read_ec_check_for_corruption false

# Client-side settings
ceph config set client rbd_read_from_replica_policy balance
ceph config set client rbd_read_from_replica_policy_auto_timeout 30

Per-Pool Fine-Grained Settings

# Read Balance settings for a specific pool
ceph osd pool set mypool read_tier replica
ceph osd pool set mypool read_balance_score_threshold 0.5

# Per-replica weight configuration
ceph osd pool set mypool replica_read_preference primary:0.3,secondary:0.7

# Read policy configuration
ceph osd pool set mypool read_policy balance
ceph osd pool set mypool read_failover_timeout 5

Advanced Tuning Parameters

# Advanced settings for performance tuning
ceph config set osd osd_op_queue_mclock_anticipation_timeout 0
ceph config set osd osd_op_queue_mclock_skip_benchmark true
ceph config set osd osd_mclock_max_capacity_iops_hdd 1000
ceph config set osd osd_mclock_max_capacity_iops_ssd 80000

# Read-priority tuning
ceph config set osd osd_op_queue_cut_off high
ceph config set osd osd_client_op_priority 63
ceph config set osd osd_recovery_op_priority 3

Common Issues and Solutions

1. Uneven Read Distribution

# Issue: read load concentrated on certain OSDs
# Fix: re-adjust weights
ceph osd reweight-by-utilization 105

# Adjust the read-balancing threshold
ceph osd pool set mypool read_balance_score_threshold 0.3

# Reset replica preference
ceph osd pool set mypool replica_read_preference random:1.0

2. Consistency Issues

# Issue: read consistency problems
# Fix: when strong consistency is required, force Primary reads
ceph config set client rbd_read_from_replica_policy primary

# Apply consistency mode for specific applications only
ceph auth get-or-create client.app1 mon 'allow r' osd 'allow rwx pool=mypool'
ceph config set client.app1 rbd_read_from_replica_policy primary

3. Increased Network Latency

# Issue: latency caused by reads from remote replicas
# Fix: prefer reads from locally close replicas
ceph config set client rbd_read_from_replica_policy localized

# Latency threshold
ceph config set client rbd_read_from_replica_policy_auto_timeout 15

# Topology-aware configuration
ceph osd crush set-device-class ssd osd.0 osd.1 osd.2
ceph osd crush rule create-replicated ssd_rule default host ssd
