가변 폰트로 차트를 그린다? 2026년 데이터 시각화의 새로운 흐름 - Datatype과 그 너머

차트 라이브러리 없이 CSS font-variation-settings 한 줄로 KPI를 그리는 법

2026-05-20 IT/기술

들어가며: 폰트가 차트가 되는 순간

2026년 5월, GeekNews(hada.io 토픽)에 흥미로운 글이 올라왔습니다. Frank Tisellano가 만든 Datatype이라는 가변 폰트인데, 발상이 단순하면서도 신선합니다. "데이터를 막대그래프로 그리지 말고, 폰트 굵기로 표현해 보자"는 것입니다. 매출이 늘어나면 숫자가 굵어지고, 줄어들면 가늘어집니다. 차트 라이브러리도, 캔버스도 없습니다. 그냥 텍스트입니다.

본 글은 Datatype 자체를 소개하는 글이 아닙니다. Datatype이 보여준 발상을 출발점 삼아, 가변 폰트(Variable Fonts)가 2026년 데이터 시각화에서 어떤 가능성을 가지는지를 기술적으로 분석합니다. 핵심은 폰트 표준 자체가 이미 강력한 시각화 도구라는 사실이며, 우리는 그 가능성을 놓치고 있었다는 점입니다.

1. 가변 폰트(Variable Fonts)란 무엇인가

가변 폰트는 2016년 OpenType 1.8에 도입된 OpenType Font Variations 표준에서 출발합니다. 기존 폰트는 Regular, Bold, Light처럼 각 굵기별로 별개의 파일(보통 8~16개)을 가졌습니다. 가변 폰트는 이를 단 하나의 파일 안에 압축하고, 그 사이의 무한히 많은 중간값을 보간(interpolation)으로 만들어 냅니다.

이 보간을 가능하게 하는 것이 축(Axis) 개념입니다. 표준이 정의한 다섯 가지 등록 축은 다음과 같습니다.

  • wght (Weight): 100(Thin) ~ 900(Black) 사이의 굵기
  • wdth (Width): 좁은 폰트 ~ 넓은 폰트
  • slnt (Slant): 기울기(이탤릭)
  • ital (Italic): 이탤릭 활성 여부
  • opsz (Optical Size): 본문/제목용 최적화

그 외에도 폰트 제작자는 자체적인 커스텀 축을 정의할 수 있습니다. Datatype이 사용한 것이 바로 이 영역입니다.

1.1. 일반 폰트와 무엇이 다른가

실무에서 가장 크게 체감하는 차이는 파일 크기와 유연성입니다.

항목일반 폰트(정적)가변 폰트
파일 구성굵기별 8~16개 .woff2단일 .woff2 한 개
총 용량(라틴)200~400KB(다중)80~150KB
총 용량(한글)3~6MB(다중)800KB~1.5MB
중간 굵기불가(450 같은 값 없음)1단위로 자유 조절
애니메이션변환 시 깜빡임부드러운 트랜지션

1.2. 브라우저 호환성

2018년부터 Chrome, Safari, Firefox, Edge가 모두 가변 폰트를 지원합니다. 2026년 기준으로는 IE11을 제외하면 사실상 100% 지원이며, 모바일 사파리·안드로이드 크롬 또한 안정적입니다. font-variation-settings 속성과 font-weight: 1 9999 범위 지정이 핵심 API입니다.

2. Datatype의 발상 - "데이터를 폰트 축으로"

일반적으로 가변 폰트의 wght 축은 디자이너가 미리 정해둔 값(예: 400, 700)을 사용합니다. Datatype의 통찰은 이 값을 데이터로 동적 제어하자는 것입니다. CSS 변수 하나만 있으면 됩니다.

.chart-value {
  font-family: "DataTypeVariable", sans-serif;
  font-variation-settings: 'wght' var(--value);
  transition: font-variation-settings 0.3s ease;
}

이제 HTML에서 데이터를 직접 매핑할 수 있습니다.

<span class="chart-value" style="--value: 850">1,250</span>  <!-- 큰 매출 → 굵게 -->
<span class="chart-value" style="--value: 320">430</span>     <!-- 작은 매출 → 가늘게 -->
<span class="chart-value" style="--value: 600">780</span>     <!-- 중간 → 중간 굵기 -->

차트 라이브러리(D3.js, Chart.js, ECharts)를 전혀 부르지 않았습니다. 캔버스도, SVG도 없습니다. 그런데도 사용자는 한눈에 "어느 숫자가 큰지" 알아챕니다. 시각화의 본질이 데이터를 시각 속성에 매핑하는 것이라면, 폰트 굵기야말로 가장 자연스러운 시각 속성 중 하나입니다.

2.1. 접근성(Accessibility)의 무료 보너스

이 방식의 숨겨진 강점은 접근성입니다. 캔버스로 그린 차트는 스크린 리더가 읽지 못합니다. SVG는 ARIA 속성을 일일이 붙여야 합니다. 그러나 가변 폰트 시각화는 그저 텍스트입니다. NVDA, JAWS, VoiceOver가 그대로 "850, 430, 780"이라고 읽어 줍니다. 시각 장애 사용자에게도 데이터가 전달되는, 진정한 의미의 보편적 시각화입니다.

3. 실무 활용 시나리오 5가지

발상이 매력적이어도 실무에 적용할 곳이 없으면 의미가 없습니다. 다음은 가변 폰트 시각화가 즉시 효과를 내는 다섯 가지 시나리오입니다.

시나리오 1: 대시보드 KPI 카드

월간 매출, 가입자 수, 전환율 등 단일 숫자가 큰 시각적 무게를 가져야 하는 자리에 가장 적합합니다. 숫자 자체가 굵기로 변동을 보여주므로 별도 차트 위젯이 필요 없습니다. Vue·React에서 props로 weight 값만 전달하면 끝납니다.

시나리오 2: 데이터 테이블의 셀 강조

1,000행짜리 매출 테이블에서 값이 큰 행을 시각적으로 강조하고 싶을 때, 색상은 색약자에게 약하고 막대 차트는 행마다 추가 공간이 필요합니다. 가변 폰트 굵기는 같은 줄 안에서 즉시 차이를 드러냅니다.

td.amount {
  font-variation-settings: 'wght' calc(300 + (attr(data-value number) / 1000) * 600);
}

(2026년 5월 기준 attr() type은 일부 브라우저 한정이므로 실무에서는 JS로 CSS 변수 주입을 권장.)

시나리오 3: 인포그래픽·인쇄 매체

가변 폰트는 인쇄에서도 그대로 굵기를 보존합니다. 잡지·연차보고서·발표 슬라이드에서 막대그래프를 텍스트로 대체하면, 종이 위에서도 데이터가 살아 있는 디자인이 됩니다. 신문 헤드라인의 굵기를 기사 중요도에 자동 매핑하는 실험도 가능합니다.

시나리오 4: 실시간 모니터링 패널

서버 CPU 사용률, 트레이딩 종목 변동률을 가변 폰트 굵기로 표시하면 깜빡이는 게이지 위젯보다 시선 부담이 적습니다. transition 속성으로 부드러운 보간을 주면 데이터가 "숨쉬는" 느낌을 줍니다.

시나리오 5: 한글 가변 폰트 - Pretendard 활용

한국어 환경에서 가장 보편적인 가변 폰트는 Pretendard Variable입니다. KPub Sans, Noto Sans KR Variable도 활용 가능합니다. 한국 디자이너·개발자가 즉시 적용 가능한 패턴입니다.

@import url("https://cdn.jsdelivr.net/gh/orioncactus/pretendard@v1.3.9/dist/web/variable/pretendardvariable.css");

.kpi-number {
  font-family: "Pretendard Variable", sans-serif;
  font-variation-settings: 'wght' var(--data-weight);
}

4. D3.js / Chart.js와의 정량 비교

가변 폰트 시각화는 만능이 아닙니다. 어떤 영역에서 강하고 어떤 영역에서 약한지 정량적으로 비교해 봅시다.

기준가변 폰트 방식Chart.js / D3.js
초기 로딩 크기폰트 파일 80~150KB라이브러리 200~500KB
스크린 리더 접근성네이티브 텍스트(우수)ARIA 별도 작업 필요
인터랙션CSS hover·transition만줌·툴팁·드릴다운 풍부
학습 곡선매우 낮음(CSS 한 줄)중간 ~ 가파름
차트 표현력단일 값·텍스트 중심scatter·heatmap 등 풍부

요약하면 가변 폰트 시각화는 단일 값의 강조와 텍스트 우선 환경에서 강하고, 복잡한 다차원 차트와 인터랙티브 대시보드에서는 약합니다. 둘은 대체재가 아니라 보완재로 보는 것이 정확합니다.

5. 한국어 환경에서의 활용 - 한글 가변 폰트의 현실

한글 가변 폰트는 라틴 폰트에 비해 파일이 큽니다. 이유는 단순합니다. 라틴 알파벳은 글리프(glyph)가 약 200~300개지만, 한글은 KS X 1001 표준 음절만 2,350자, 유니코드 한글 음절 전체로는 11,172자입니다. 게다가 가변 폰트는 모든 글리프에 대해 보간 데이터를 별도 저장해야 합니다.

그래서 실무에서는 다음 두 가지 최적화가 필수입니다.

  • 서브셋(Subset): 사이트에서 실제 사용하는 글자만 추출. pyftsubset이나 글리프해커 같은 도구로 1.5MB → 300KB 수준까지 감량.
  • 분할 로드(unicode-range): CSS의 @font-face에 unicode-range를 명시해 필요한 블록만 다운로드.
@font-face {
  font-family: "Pretendard Variable";
  font-weight: 45 920;
  font-style: normal;
  font-display: swap;
  src: url("/fonts/pretendard-var-ko.woff2") format("woff2-variations");
  unicode-range: U+AC00-D7A3;  /* 한글 음절 영역만 */
}

6. 한계와 주의점

가변 폰트 시각화를 실무에 도입하기 전에 다음을 점검해야 합니다.

6.1. 표현 가능한 차트 형태의 제한

본질적으로 가변 폰트는 1차원 값을 시각 속성 하나에 매핑하는 데 최적화됩니다. scatter plot(2축), heatmap(2차원), line chart(시계열 추세)처럼 다차원·시계열 표현은 부적합합니다. 이 경우는 여전히 D3·ECharts·Vega-Lite가 정답입니다.

6.2. 폰트 로딩 전 FOUT 처리

가변 폰트가 로드되기 전에는 시스템 폰트가 fallback으로 표시되며, 이때 weight 매핑이 작동하지 않아 데이터가 모두 같은 굵기로 보입니다. font-display: swap과 <link rel="preload">를 함께 써서 FOUT 시간을 최소화하거나, 폰트 로딩 완료 전에는 시각화 영역에 로딩 스피너를 두는 것이 안전합니다.

6.3. 인쇄 매체에서의 weight 정확도

모니터에서 보간된 weight 350과 인쇄 출력의 weight 350은 미세하게 다를 수 있습니다. RIP(래스터 이미지 프로세서)에 따라 보간 알고리즘이 달라지기 때문입니다. 정밀 인쇄가 필요한 매체는 100, 300, 500, 700, 900처럼 정수 단위 weight만 사용하는 것을 권장합니다.

6.4. 디자인 시스템과의 정합

기존 디자인 시스템이 Regular/Bold 두 가지 weight만 정의했다면, 가변 폰트 시각화는 그 사이를 자유롭게 사용합니다. 디자인 시스템 가이드를 먼저 "가변 친화"로 갱신해야 디자이너와 개발자 사이에 충돌이 없습니다.

7. 누구에게 추천하고 누구에게 부적합한가

본 글의 분석을 종합하면 가변 폰트 시각화의 적합도는 명확하게 갈립니다.

추천 대상부적합 대상

8. 결론 - 가변 폰트는 시각화 패러다임의 조용한 확장

Datatype은 거창한 라이브러리가 아닙니다. 한 사람의 디자이너가 만든 작은 폰트 하나입니다. 그러나 그것이 보여준 발상은 본질적입니다. 차트는 캔버스 위에 그려지는 그림이 아니라, 데이터에 시각 속성을 매핑하는 모든 행위라는 사실을 다시 일깨워 주었습니다.

2026년의 웹은 점점 더 가볍고, 접근 가능하고, 인쇄 친화적인 방향으로 진화하고 있습니다. 가변 폰트는 그 흐름과 정확히 맞물립니다. 차트 라이브러리 200KB를 부르기 전에, 폰트 파일 100KB 안에 이미 답이 있을지도 모릅니다. 본 글이 그 가능성을 한 번 더 들여다보는 계기가 되기를 바랍니다.
