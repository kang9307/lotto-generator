null 과 키 없음은 다른 상태다 - PATCH 가 값을 지워버리는 이유

RFC 7396 Merge Patch의 null 삭제 의미와 Python·Node·PowerShell 5.1이 null 과 없는 키를 읽는 방식을 127.0.0.1 서버 실측으로 대조

출력은 Windows 10 Pro의 Git Bash(curl 8.12.1), Python 3.13.3, Node.js v22.16.0, Windows PowerShell 5.1.19041.6456에서 직접 실행한 그대로이고, 인용한 문구는 RFC 7396·RFC 8259·MDN·Python 문서에서 열어 확인한 것이다. 서버는 127.0.0.1에만 바인딩한 소형 Python http.server이며 실험 뒤 직접 띄운 프로세스만 종료했다. PowerShell 오류 메시지는 UI 문화권을 en-US로 지정한 이 환경의 문구이다.

서론 - 필드 하나를 고쳤는데 다른 값이 함께 사라진다

프로필의 bio 하나만 바꾸려고 {"bio":"new"}를 PATCH로 보냈는데 응답에 name과 nickname이 없다. 서버 코드는 평범한 body.get(...)일 뿐이다. 이 사고의 뿌리는 서버가 「키가 없다」와 「값이 null이다」를 같은 상태로 읽은 데 있다. JSON 문서에서 두 상태는 글자가 다르다. 한쪽에는 "x":null이 적혀 있고 다른 쪽에는 x라는 이름이 아예 없다. 그런데 언어의 읽기 API는 둘을 같은 값으로 돌려주는 기본 동작을 갖는 경우가 많다.

용어를 먼저 정한다. 「null」은 JSON 리터럴 null이다. 「키 없음」은 객체 안에 그 이름의 멤버가 없는 상태이다. undefined는 JavaScript의 값이며 JSON 문법에는 없다. 세 표현은 {"x":null}, {}, 그리고 JavaScript에서 {x: undefined}를 직렬화한 결과이다. 아래에서는 이 셋을 Python·Node·PowerShell이 어떻게 읽고 쓰는지 출력으로 보이고, PATCH에서 어떤 상태 변화로 이어지는지를 서버에 직접 요청을 보내 확인한다.

다루는 질문은 다음과 같다.

  • JSON 문법과 RFC 7396은 null과 키 없음을 각각 어떻게 정의하는가.
  • Python의 dict.get, Node의 d.x, PowerShell의 $o.x는 두 상태를 구별하는가.
  • 구별하지 못하는 get 패턴이 PATCH에서 값을 지우는 과정은 어떻게 재현되는가.
  • 구별하는 안전한 패턴은 무엇이고 출력은 어떻게 달라지는가.
  • 직렬화 단계에서 키가 사라지는 경우는 어떤 도구의 어떤 값인가.

문서가 정한 것 - JSON 문법, Merge Patch, 언어 문서

근거가 되는 문장을 먼저 모은다. 아래 목록의 영어 문장은 원문 그대로이다.

  • RFC 8259 3절: A JSON value MUST be an object, array, number, or string, or one of the following three literal names: false, null, true. 값의 목록에 undefined는 없다.
  • RFC 8259 4절: The names within an object SHOULD be unique. 객체는 이름과 값의 쌍이며 이름이 없는 멤버는 객체 안에 존재하지 않는다.
  • RFC 7396 개요: Null values in the merge patch are given special meaning to indicate the removal of existing values in the target. 패치 안의 null은 값이 아니라 삭제 지시이다.
  • RFC 7396 1절: ...do not make use of explicit null values. The merge patch format is not appropriate for all JSON syntaxes. 문서가 null을 값으로 쓰는 경우에는 이 형식이 맞지 않는다고 스스로 적는다.
  • Python 문서의 dict.get: If default is not given, it defaults to None, so that this method never raises a KeyError. 반환값만으로는 없는 키와 값이 None인 키를 가를 수 없다.
  • MDN in 연산자: A property may be present in an object but have value undefined. Therefore, "x" in obj is not the same as obj.x !== undefined.

RFC 7396의 의사 코드(2절)는 한 줄로 요약된다. 패치의 멤버 값이 null이면 대상에 그 이름이 있을 때 지우고, null이 아니면 값을 재귀적으로 병합한다. 패치에 이름이 없는 멤버는 처리 대상이 아니므로 대상에 그대로 남는다. 「null은 삭제, 키 없음은 변경 없음」이라는 구별이 이 형식의 전부이고, 따라서 서버가 두 상태를 구별하지 못하면 형식 자체가 성립하지 않는다.

Python - get의 기본값은 키가 없을 때만 쓰인다

import json
                    
                    for text in ['{"x": null}', '{}']:
                        d = json.loads(text)
                        print(text.ljust(11), '| repr:', repr(d), '| get("x"):', repr(d.get('x')),
                              '| get("x", 0):', repr(d.get('x', 0)), '| "x" in d:', 'x' in d)
                    
                    # Python has no undefined; None is serialized as null and the key stays
                    print(json.dumps({'x': None}), json.dumps({}))
                    
                    MISSING = object()  # sentinel: a value no JSON document can contain
                    
                    def classify(d, key):
                        v = d.get(key, MISSING)
                        if v is MISSING:
                            return 'missing'
                        return 'null' if v is None else 'value'
                    
                    for text in ['{"x": null}', '{}', '{"x": 0}', '{"x": ""}']:
                        print(text.ljust(11), '->', classify(json.loads(text), 'x'))

출력은 다음과 같다.

{"x": null} | repr: {'x': None} | get("x"): None | get("x", 0): None | "x" in d: True
                    {}          | repr: {} | get("x"): None | get("x", 0): 0 | "x" in d: False
                    {"x": null} {}
                    {"x": null} -> null
                    {}          -> missing
                    {"x": 0}    -> value
                    {"x": ""}   -> value

d.get("x")는 두 문서에서 모두 None이다. 구별은 기본값 인자에서 나타난다. d.get("x", 0)는 키가 없을 때만 0을 돌려주고, 값이 null인 키에서는 None을 그대로 돌려준다. 기본값은 「키가 없을 때」의 값이지 「값이 비었을 때」의 값이 아니다. "x" in d는 키 존재 여부만 답하므로 두 문서에서 True와 False로 갈린다.

json.dumps({"x": None})은 {"x": null}을 만든다. Python에는 undefined가 없으므로 값이 비었다는 표현은 항상 None이고, 직렬화해도 키는 null로 남는다. 키 없음을 만들려면 딕셔너리에서 그 키를 넣지 않거나 지워야 한다. 센티널 MISSING = object()를 기본값으로 쓴 classify는 네 입력을 null·missing·value·value로 가른다. 빈 문자열과 0은 null이 아니라 값이다.

Node - undefined는 읽기에서 갈리고 직렬화에서 사라진다

for (const text of ['{"x": null}', '{}']) {

                    }

                    console.log('default {}           ->', readDefault({}));
                    console.log('default {x: null}    ->', readDefault({ x: null }));
                    console.log('default {x: undefined} ->', readDefault({ x: undefined }));
                    console.log('??      {x: null}    ->', ({ x: null }).x ?? 'DEFAULT');
                    console.log('??      {}           ->', ({}).x ?? 'DEFAULT');
                    
                    function classify(o, k) { return !(k in o) ? 'missing' : (o[k] === null ? 'null' : 'value'); }
                    for (const t of ['{"x":null}', '{}', '{"x":0}']) console.log(t.padEnd(10), '->', classify(JSON.parse(t), 'x'));

                    {}          | d.x: undefined | d.x === undefined: true | "x" in d: false | Object.hasOwn: false

                    default {x: null}    -> null

JSON.parse가 만든 객체에서 {"x": null}의 d.x는 null이고 {}의 d.x는 undefined이다. 즉 Node는 읽기에서 두 상태를 값으로 구별한다. d.x === undefined가 키 없음을, d.x === null이 null을 가른다. in과 Object.hasOwn은 키 자체의 존재를 답하며 두 문서에서 true/false로 갈린다.

구별이 사라지는 곳은 기본값 문법이다. 구조 분해의 기본값 { x = "DEFAULT" }는 undefined일 때만 작동하므로 {}와 {x: undefined}에서는 DEFAULT를, {x: null}에서는 null을 돌려준다. 반대로 ??는 null과 undefined를 모두 기본값으로 바꿔 두 상태를 하나로 합친다. 같은 「기본값」이라는 이름의 문법이 한쪽은 구별하고 한쪽은 합친다.

PATCH 엔드포인트 - RFC 7396 의미를 구현한 127.0.0.1 서버

서버 하나에 세 갈래 처리기를 둔다. /naive는 body.get이 None이면 필드를 지우고, /skipnull은 None이면 건너뛰며, /merge는 RFC 7396의 의사 코드를 그대로 옮긴 merge_patch를 쓴다. 상태는 메모리의 딕셔너리이고 POST /reset으로 되돌린다. 모든 파일은 임시 폴더 안에서만 만들고, 소켓은 루프백(127.0.0.1)에만 열며, 180초가 지나면 스스로 종료하는 안전장치를 넣었다.

import json, os, sys, threading
                    from http.server import BaseHTTPRequestHandler, HTTPServer
                    
                    INITIAL = {'name': 'kim', 'nickname': 'kk', 'bio': 'hello'}
                    FIELDS = ['name', 'nickname', 'bio']
                    STATE = {'naive': dict(INITIAL), 'skipnull': dict(INITIAL), 'merge': dict(INITIAL)}
                    
                    
                    def apply_naive(user, body):
                        # get() returns None for a missing key and for an explicit null alike
                        for k in FIELDS:
                            v = body.get(k)
                            if v is None:
                                user.pop(k, None)
                            else:
                                user[k] = v
                    
                    
                    def apply_skipnull(user, body):
                        for k in FIELDS:
                            v = body.get(k)
                            if v is not None:
                                user[k] = v
                    
                    
                    def merge_patch(target, patch):
                        # the MergePatch pseudo-code of RFC 7396 section 2
                        if isinstance(patch, dict):
                            if not isinstance(target, dict):
                                target = {}
                            for name, value in patch.items():
                                if value is None:
                                    if name in target:
                                        del target[name]
                                else:
                                    target[name] = merge_patch(target.get(name), value)
                            return target
                        return patch
                    
                    
                    class H(BaseHTTPRequestHandler):
                        def log_message(self, *a):
                            pass
                    
                        def _send(self, code, obj):
                            raw = json.dumps(obj, sort_keys=True).encode()
                            self.send_response(code)
                            self.send_header('Content-Type', 'application/json')
                            self.send_header('Content-Length', str(len(raw)))
                            self.end_headers()
                            self.wfile.write(raw)
                    
                        def _which(self):
                            first = self.path.strip('/').split('/')[0]
                            return first if first in STATE else None
                    
                        def do_GET(self):
                            w = self._which()
                            self._send(200, STATE[w]) if w else self._send(404, {'error': 'unknown path'})
                    
                        def do_POST(self):
                            if self.path != '/reset':
                                return self._send(404, {'error': 'unknown path'})
                            for k in STATE:
                                STATE[k] = dict(INITIAL)
                            self._send(200, {'reset': True})
                    
                        def do_PATCH(self):
                            w = self._which()
                            if w is None:
                                return self._send(404, {'error': 'unknown path'})
                            body = json.loads(self.rfile.read(int(self.headers.get('Content-Length', 0))))
                            if w == 'naive':
                                apply_naive(STATE[w], body)
                            elif w == 'skipnull':
                                apply_skipnull(STATE[w], body)
                            else:
                                STATE[w] = merge_patch(STATE[w], body)
                            self._send(200, STATE[w])
                    
                    
                    if __name__ == '__main__':
                        srv = HTTPServer(('127.0.0.1', int(sys.argv[1])), H)  # loopback only
                        print('pid', os.getpid(), 'listening on 127.0.0.1:' + sys.argv[1], flush=True)
                        t = threading.Timer(180, lambda: os._exit(0))  # safety: exit by itself after 180 s
                        t.daemon = True
                        t.start()
                        srv.serve_forever()

클라이언트는 curl이다. 같은 세 요청을 세 처리기에 차례로 보낸다. 요청은 필드 하나만 바꾸는 {"bio":"new"}, 필드 하나를 지우는 {"nickname":null}, 아무것도 바꾸지 않는 {}이다. 요청마다 상태를 초기값(name=kim, nickname=kk, bio=hello)으로 되돌린다.

B=http://127.0.0.1:18765
                    patch() {
                      printf 'PATCH /%s %-24s -> ' "$1" "$2"
                      curl -s -X PATCH -H 'Content-Type: application/merge-patch+json' -d "$2" "$B/$1"
                      echo
                    }
                    reset() { curl -s -X POST "$B/reset" > /dev/null; }

                      reset; patch $h '{"bio":"new"}'

                    == naive
                    PATCH /naive {"bio":"new"}            -> {"bio": "new"}
                    PATCH /naive {"nickname":null}        -> {}
                    PATCH /naive {}                       -> {}
                    == skipnull
                    PATCH /skipnull {"bio":"new"}            -> {"bio": "new", "name": "kim", "nickname": "kk"}
                    PATCH /skipnull {"nickname":null}        -> {"bio": "hello", "name": "kim", "nickname": "kk"}
                    PATCH /skipnull {}                       -> {"bio": "hello", "name": "kim", "nickname": "kk"}
                    == merge
                    PATCH /merge {"bio":"new"}            -> {"bio": "new", "name": "kim", "nickname": "kk"}
                    PATCH /merge {"nickname":null}        -> {"bio": "hello", "name": "kim"}
                    PATCH /merge {}                       -> {"bio": "hello", "name": "kim", "nickname": "kk"}
                    == nested object (merge)
                    PATCH /merge {"bio":"new","extra":{"a":1}} -> {"bio": "new", "extra": {"a": 1}, "name": "kim", "nickname": "kk"}
                    PATCH /merge {"extra":{"a":null,"b":2}} -> {"bio": "new", "extra": {"b": 2}, "name": "kim", "nickname": "kk"}

/naive에 {"bio":"new"}를 보내면 응답은 {"bio": "new"} 하나뿐이다. 요청에 없던 name과 nickname이 지워졌다. 처리기는 필드 목록을 돌며 body.get(k)를 읽는데, 요청에 없는 이름은 None이 되고 None은 삭제로 처리되기 때문이다. 이 결과는 위 코드와 출력이 직접 보여 준다. {}를 보내도 응답은 {}이다. 아무것도 바꾸지 않는 요청이 모든 필드를 지운다.

/skipnull은 반대쪽 오류를 보인다. 키 없음에서는 안전하지만 {"nickname":null}을 보내도 nickname이 kk로 남는다. 지우라는 요청이 조용히 무시된다. /merge만 세 요청 모두 의도대로 움직인다. bio만 바뀌고, nickname만 사라지고, {}는 아무것도 바꾸지 않는다. 중첩 객체에서도 {"extra":{"a":null,"b":2}}가 extra 안의 a만 지운다.

요청/naive (None 이면 삭제)/skipnull (None 이면 건너뜀)/merge (RFC 7396)
{"bio":"new"}name·nickname 삭제bio 만 변경bio 만 변경
{"nickname":null}모든 필드 삭제nickname 유지(무시됨)nickname 만 삭제
{}모든 필드 삭제변경 없음변경 없음

구별하는 안전 패턴 - 센티널, in, 객체 펼치기

앞 절의 merge_patch는 name in target과 for name, value in patch.items()로 구별한다. 패치 객체를 이름 단위로 순회하면 요청에 있는 키만 방문하므로 없는 키는 건드릴 수 없다. 규칙은 하나이다. 키의 존재는 in(또는 순회)으로 묻고, 값이 null인지는 그 뒤에 묻는다. 존재를 값으로 추정하지 않는다.

센티널은 기본값 자리에 JSON이 만들 수 없는 값을 놓는 방식이다. Python의 object()는 어떤 JSON 문서에서도 나올 수 없으므로 d.get(key, MISSING)의 반환이 MISSING이면 키 없음이다. 객체 기본값은 펼치기 문법에서 보인다. 아래는 기본값 객체 위에 요청 본문을 얹는 코드와 출력이며, Python의 {**defaults, **body}도 같은 방식이다.

const defaults = { name: 'kim', nickname: 'kk' };
                    console.log(JSON.stringify({ ...defaults, ...JSON.parse('{}') }));
                    console.log(JSON.stringify({ ...defaults, ...JSON.parse('{"nickname": null}') }));
                    const undef = { ...defaults, ...{ nickname: undefined } };
                    console.log(undef, 'nickname' in undef, JSON.stringify(undef));
{"name":"kim","nickname":"kk"}
                    {"name":"kim","nickname":null}
                    { name: 'kim', nickname: undefined } true {"name":"kim"}
import json
                    defaults = {'name': 'kim', 'nickname': 'kk'}
                    print({**defaults, **json.loads('{}')})
                    print({**defaults, **json.loads('{"nickname": null}')})
                    print(json.dumps({**defaults, **{'nickname': None}}))
{'name': 'kim', 'nickname': 'kk'}
                    {'name': 'kim', 'nickname': None}
                    {"name": "kim", "nickname": null}

{}를 얹으면 기본값이 그대로 남고, {"nickname": null}을 얹으면 nickname이 null로 바뀐다. 구별이 유지된다. 그런데 JavaScript에서 {nickname: undefined}를 얹으면 기본값 kk가 undefined로 덮이고, 직렬화하면 nickname 자체가 사라져 {"name":"kim"}만 남는다. 펼치기는 키의 존재를 기준으로 덮어쓰기 때문이다. 이 동작은 in이 true를 출력한 줄이 보여 준다.

  • 센티널: get(key, MISSING)처럼 JSON이 만들 수 없는 값을 기본값에 둔다.
  • in·Object.hasOwn·속성 목록: 값을 읽기 전에 키의 존재를 먼저 묻는다.
  • 패치 객체 순회: 요청에 있는 이름만 방문하므로 없는 이름은 변경 대상이 되지 않는다.
  • 객체 기본값 + 펼치기: 키가 없으면 기본값이 남지만, JavaScript의 undefined 값은 키가 있는 것으로 덮어쓴다.

직렬화 단계에서 키가 사라지는 경우 - 도구별 대조

읽기에서 구별을 지켰더라도 클라이언트가 보낼 때 구별이 사라지면 같은 사고가 난다. Node의 JSON.stringify를 먼저 본다.

console.log(JSON.stringify({ x: undefined }));
                    console.log(JSON.stringify({ x: null }));
                    console.log(JSON.stringify({ a: 1, x: undefined, b: 2 }));
                    console.log(JSON.stringify([undefined, null, function () {}]));
                    console.log(JSON.stringify(undefined));
                    const merged = Object.assign({ x: 1 }, { x: undefined });
                    console.log(merged, Object.keys(merged), JSON.stringify(merged));
{}
                    {"x":null}
                    {"a":1,"b":2}
                    [null,null,null]
                    undefined
                    { x: undefined } [ 'x' ] {}

MDN의 JSON.stringify 문서는 이렇게 적는다. undefined, Function, and Symbol values are not valid JSON values. If any such values are encountered during conversion, they are either omitted (when found in an object) or changed to null (when found in an array). 출력이 이를 그대로 보여 준다. 객체의 x: undefined는 키째 사라지고, 배열의 undefined와 함수는 null이 된다. 최상위 undefined는 JSON 텍스트가 아니라 값 undefined를 돌려준다. 마지막 줄의 Object.assign 결과는 키가 남은 { x: undefined }이지만 직렬화는 {}이다.

이 차이가 PATCH에서 어떤 상태 변화가 되는지는 같은 서버의 /merge에 세 도구가 만든 본문을 그대로 보내 확인한다. 세 도구 모두 「nickname을 비우겠다」는 같은 의도로 코드를 썼다.

B=http://127.0.0.1:18765
                    send() {
                      printf '%-10s body=%-20s -> ' "$1" "$2"
                      curl -s -X PATCH -H 'Content-Type: application/merge-patch+json' -d "$2" "$B/merge"
                      echo
                    }
                    reset() { curl -s -X POST "$B/reset" > /dev/null; }
                    
                    js=$(node -e "console.log(JSON.stringify({nickname: undefined}))")
                    py=$(python -c "import json; print(json.dumps({'nickname': None}))")
                    ps=$(powershell -NoProfile -Command "[pscustomobject]@{ nickname = \$null } | ConvertTo-Json -Compress")
                    reset; send node "$js"
                    reset; send python "$py"
                    reset; send powershell "$ps"
node       body={}                   -> {"bio": "hello", "name": "kim", "nickname": "kk"}
                    python     body={"nickname": null}   -> {"bio": "hello", "name": "kim"}
                    powershell body={"nickname":null}    -> {"bio": "hello", "name": "kim"}

Node의 {nickname: undefined}는 본문이 {}가 되어 상태가 그대로이다. 지우려던 요청이 아무 일도 하지 않았다. Python의 {"nickname": None}과 PowerShell의 $null 속성은 본문에 "nickname":null이 실려 삭제된다. 같은 의도의 코드가 도구에 따라 「지우지 못함」과 「지움」으로 갈린다.

도구와 값직렬화된 본문/merge 에 보낸 뒤 nickname
Node {nickname: undefined}{}유지(kk)
Node {nickname: null}{"nickname":null}직렬화 결과 {"nickname":null} 로부터 삭제가 예상됨
Python {"nickname": None}{"nickname": null}삭제
PowerShell $null 속성{"nickname":null}삭제

증상에서 원인으로 - 점검 순서와 인접 글

앞의 출력에서 증상과 원인의 대응이 나온다. 점검은 증상별로 한 단계씩 좁힌다.

  • 필드를 하나만 바꿨는데 다른 필드가 지워진다: 서버 처리기가 get의 None을 삭제로 쓰는지 본다(/naive의 증상).
  • 값을 비우라는 요청이 무시된다: null이 건너뜀 처리되는지 본다(/skipnull의 증상).
  • JavaScript 클라이언트의 삭제 요청이 서버에서 아무 일도 하지 않는다: 본문에 undefined가 들어 있는지, JSON.stringify 결과에 키가 있는지 본다.
  • null을 값으로 저장해야 하는 필드가 있다: RFC 7396의 의사 코드에서는 null이 항상 삭제이므로 그 필드는 Merge Patch로 표현할 수 없다. 별도 형식이나 필드 단위의 명시적 값을 쓴다.
  • 배열을 일부만 바꾸려 한다: 의사 코드에서 객체가 아닌 패치는 대상 전체를 교체하므로 배열은 통째로 보낸다.

주변 주제는 다른 글에서 다룬다. 같은 이름이 두 번 나오는 문서가 파서마다 어떻게 읽히는지는 JSON 중복 키 글에, 큰 정수가 JSON을 지나며 달라지는 문제는 JSON 숫자 정밀도 글에 있다. SQL 쪽의 NULL이 비교를 어떻게 바꾸는지는 NOT IN과 NULL 글이, JSONB 컬럼을 부분 갱신하는 연산자는 PostgreSQL JSONB 글이 다룬다. 기본 인자에 None을 파수꾼으로 두는 관용구는 Python 가변 기본 인자 글과 이어진다. 범위는 JSON 문서 안의 null과 키 없음, 그리고 PATCH의 의미까지이다.

확인하지 못한 것

  • Go·Java·Rust 등 다른 언어의 JSON 라이브러리가 두 상태를 어떻게 읽는지. 이 PC에서 실행한 것은 Python·Node·PowerShell 5.1뿐이다.
  • PowerShell 7(pwsh)에서 ConvertFrom-Json이 두 상태를 읽는 방식. 이 PC에는 pwsh가 없다.
  • RFC 6902(JSON Patch)와의 비교 실행. 본문에서 다룬 것은 RFC 7396뿐이다.
  • PATCH 본문이 객체가 아닐 때(배열·문자열)의 서버 동작. RFC 의사 코드는 대상 전체를 교체한다고 적지만 이 서버의 해당 경로는 실행하지 않았다.
  • 중복 키가 있는 PATCH 본문, 그리고 큰 정수·소수가 담긴 본문의 처리. 인접 글의 주제이다.
  • 운영 중인 웹 프레임워크(Django REST framework, Express 등)가 PATCH 본문을 어떻게 해석하는지. 직접 만든 소형 서버만 실행했다.
  • Linux·macOS에서의 출력. 본문의 출력은 모두 Windows 10에서 나왔다.
