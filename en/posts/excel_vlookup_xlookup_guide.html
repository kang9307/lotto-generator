The Complete VLOOKUP and XLOOKUP Guide - From Syntax to Errors to the INDEX+MATCH Alternative

A practical walkthrough of Excel's lookup functions, the errors that trip people up, and exactly what XLOOKUP fixes

Jul 24, 2026 IT/Tech

Intro: When You Need a Lookup Function

There is a recurring moment in spreadsheet work: a value you need is scattered across another sheet or table. You need a company name from a company code, a unit price from a product code, a department name from an employee ID. Doing this lookup work by hand, row by row, is slow and error-prone. Excel has offered VLOOKUP for this problem for decades, and Microsoft 365 added XLOOKUP in 2019 to replace it.

As of July 2026, this guide first lays out VLOOKUP's syntax and its most common errors, then walks through exactly what XLOOKUP improves, and finally covers the INDEX+MATCH alternative for situations where neither function is available - all with real formula examples. Most people who land on this article are staring at an error message right now, so the error-fixing section gets special attention.

1. VLOOKUP Basics - Syntax and Its Four Arguments

1.1 Breaking Down VLOOKUP's Syntax

VLOOKUP stands for Vertical Lookup - it searches a vertically arranged table. The syntax is:

=VLOOKUP(lookup_value, table_array, col_index_num, [range_lookup])

It takes exactly four arguments. First, lookup_value is the value you are searching for. Second, table_array is the full range containing the data, and the lookup value must exist in the leftmost column of this range. Third, col_index_num is a number specifying which column to return, counted from the left edge of table_array. Fourth, range_lookup set to FALSE (or 0) finds only an exact match, while TRUE (or 1, or omitted) finds an approximate match.

As a practical example, say a product table has product codes in column A, product names in column B, and unit prices in column C. To pull the unit price for the code in cell A2:

=VLOOKUP(A2, Products!$A$2:$C$100, 3, FALSE)

Here, 3 means the third column from the left of the range (unit price), and FALSE means find only a row where the product code matches exactly. Locking the range with $ (absolute reference) keeps the table range from shifting when you copy the formula down.

1.2 Exact Match vs. Approximate Match

If you omit the fourth argument or set it to TRUE, VLOOKUP runs in approximate-match mode: when there is no exact match, it finds the closest value that is less than or equal to the lookup value. This is useful for converting scores to letter grades or applying tiered rates, but it only works correctly if the first column of the table is sorted in ascending order. Conversely, whenever you need an exact match only - product codes, account numbers, anything with a one-to-one identity - you must set the argument to FALSE explicitly. Omitting this argument is the single most common cause of VLOOKUP errors.

2. Common VLOOKUP Errors and How to Fix Them

2.1 #N/A - Value Not Found

#N/A means the lookup value could not be found in the table. Check these four causes in order.

  • Data-type mismatch: the lookup value is text while the table stores numbers, or vice versa. Fix with =VALUE(A2) or =TEXT(A2,"0") to align the type.
  • Invisible spaces: values copied from another system often carry hidden leading or trailing spaces. Strip them with =TRIM(A2).
  • Lookup value not in the leftmost column: VLOOKUP only searches the first column of table_array. If the column holding your lookup value sits in the middle or on the right of the table, it will never be found.
  • Missing fourth argument: falls back to approximate match, either returning the wrong value silently or failing outright because the table is not sorted.

To hide the raw error, wrap the formula in IFERROR:

=IFERROR(VLOOKUP(A2, Products!$A$2:$C$100, 3, FALSE), "Check code")

2.2 Column-Index Errors - #REF! and the Wrong Column

If the third argument, col_index_num, exceeds the number of columns in table_array, you get a #REF! error. A more dangerous failure mode is when no error appears but the formula returns the value from the wrong column. Inserting or deleting a column in the middle of the table does not automatically update col_index_num, so the formula silently shifts to point at the wrong data. The reliable fix is to stop hardcoding col_index_num and calculate it dynamically with MATCH:

=VLOOKUP(A2, Products!$A$2:$D$100, MATCH("Price", Products!$A$1:$D$1, 0), FALSE)

This way, even if column order changes, the formula relocates the column by its header name (Price), so it never quietly breaks.

2.3 Sort Issues - The Approximate-Match Trap

If the fourth argument is TRUE or omitted, and the table's first column is not sorted, VLOOKUP returns a completely wrong value with no error at all. This is the most dangerous failure mode precisely because nothing alerts you. Unless you are certain you need approximate match, it is safer to make FALSE your default habit.

3. Enter XLOOKUP - What It Actually Improves

XLOOKUP was designed to directly target VLOOKUP's structural weaknesses. Its syntax:

=XLOOKUP(lookup_value, lookup_array, return_array, [if_not_found], [match_mode], [search_mode])

Only the first three arguments are required; the remaining three are optional. Here are the four key improvements over VLOOKUP.

3.1 Lookup in Any Direction - Fixing VLOOKUP's Core Limitation

In VLOOKUP, the lookup range and return range are bound together inside a single table_array, and the lookup value must sit in that table's leftmost column. XLOOKUP specifies the lookup array and the return array completely independently. So even if product names live in column C and product codes in column A, you can look up a product code by product name - a leftward search - with no workaround.

=XLOOKUP(A2, Products!C:C, Products!A:A, "Not found")

With VLOOKUP, this would have required reordering columns or building a helper column.

3.2 Exact Match by Default - Fewer Silent Mistakes

When you omit XLOOKUP's fifth argument (match_mode), exact match is the default. This structurally reduces the class of VLOOKUP accidents where approximate match kicks in unintentionally and quietly returns the wrong value.

3.3 The if_not_found Argument - A Clean Alternative to #N/A

The fourth argument lets you directly specify what to show when there is no match.

=XLOOKUP(A2, Products!A:A, Products!C:C, "Not found")

VLOOKUP needed a separate IFERROR wrapper around the whole function to achieve this; XLOOKUP handles it in one call.

3.4 Reverse Search - The search_mode Argument

Setting the sixth argument (search_mode) to -1 searches the table from the last row backward. This is useful when the same value appears multiple times and you want the most recent entry - for example, pulling the latest unit price from a transaction history. VLOOKUP has no equivalent option at all.

=XLOOKUP(A2, TransactionHistory!A:A, TransactionHistory!D:D, "No history", 0, -1)

4. The INDEX+MATCH Alternative

4.1 Syntax and How It Works

If you need leftward lookup on an older Excel version without XLOOKUP, INDEX+MATCH is the answer. MATCH finds the position (which row number) of the lookup value, and INDEX returns the value sitting at that position - two functions working together.

=INDEX(return_column, MATCH(lookup_value, lookup_column, 0))

For example, with product codes in column A and unit prices in column C, the formula to find a unit price by product code is:

=INDEX(Products!C:C, MATCH(A2, Products!A:A, 0))

MATCH's third argument 0 means exact match. Unlike VLOOKUP, INDEX+MATCH has no constraint on the left-right position of the lookup column versus the return column.

4.2 When to Reach for INDEX+MATCH

Three situations favor INDEX+MATCH. First, on Excel 2016 or 2019, which do not support XLOOKUP. Second, when columns get added or removed frequently, making column numbers unstable - calculating the column position dynamically with MATCH is far safer. Third, on very large tables where calculation speed matters. That said, where XLOOKUP is available, its shorter syntax and if_not_found argument usually make it the better first choice.

5. Practical Examples

5.1 Price-Table Matching

The most common real-world pattern: pulling a unit price (column C) from a separate price sheet using a product code from an order form (column A), then multiplying by quantity (column B) to get a line total.

' XLOOKUP version
=XLOOKUP(A2, PriceList!A:A, PriceList!C:C, 0) * B2

' VLOOKUP version
=VLOOKUP(A2, PriceList!$A$2:$C$500, 3, FALSE) * B2

Setting if_not_found to 0, or wrapping the VLOOKUP version in IFERROR, keeps a missing match from cascading into a multiplication error.

5.2 Multi-Condition Lookup

Sometimes you need to match a row where two conditions - say, branch and product code - are both true at once. The most intuitive method is to concatenate the two values with the & operator into a single lookup value.

=XLOOKUP(A2&B2, Inventory!A:A&Inventory!B:B, Inventory!D:D, "Not in stock")

To do the same thing with INDEX+MATCH on an older Excel version, use an array formula:

=INDEX(Inventory!D:D, MATCH(1, (Inventory!A:A=A2)*(Inventory!B:B=B2), 0))

Because this is an array formula, older Excel requires confirming it with Ctrl+Shift+Enter. In Microsoft 365's dynamic-array Excel, a plain Enter works fine.

6. Version Compatibility - If You Cannot Use XLOOKUP

As of July 2026, XLOOKUP is supported in Microsoft 365 subscription Excel, Excel 2021, Excel 2024, and Excel for the web. It is not available in the perpetual-license versions Excel 2016 and Excel 2019. Since many organizations still run those older perpetual versions, check the recipient's Excel version before sharing a file with others. If compatibility is a concern, VLOOKUP or INDEX+MATCH is the safer choice, and Google Sheets supports its own XLOOKUP function with similar behavior.

7. Performance Tips

  • Avoid referencing an entire column: something like A:A references the whole column and can slow calculation down. Scope the range to where your data actually lives, or use a Table object so the range expands automatically.
  • Prefer exact match: approximate match requires sorting and is heavier on large datasets. Use it only when you actually need it.
  • Don't recompute the same lookup repeatedly: if many cells reference the same lookup_array/return_array, lock them with absolute references ($) so the range does not get recalculated as you copy the formula.
  • Use a helper column: if multi-condition lookups are very frequent, precompute the concatenated key in a helper column instead of concatenating with & every time, which speeds up lookups noticeably.

Conclusion

VLOOKUP remains the most widely used lookup function, but it carries three structural weaknesses: no leftward lookup, an approximate-match default, and a fixed column number. XLOOKUP was built to answer exactly those three, with independent lookup and return ranges, an exact-match default, the if_not_found argument, and reverse search. Where XLOOKUP is not available, INDEX+MATCH remains a solid alternative. If a formula in your own workbook keeps throwing #N/A today, check the cause in this order - data type, spaces, sort order - and consider switching to XLOOKUP or INDEX+MATCH where you can.
