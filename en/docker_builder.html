🌐 Running Web Applications

Run an Nginx Web Server

docker run -d --name my-nginx -p 8080:80 -v /host/html:/usr/share/nginx/html nginx:latest
  • -d: Run in the background (detached)
  • --name my-nginx: Assign a container name
  • -p 8080:80: Map host port 8080 to container port 80
  • -v /host/html:/usr/share/nginx/html: Mount HTML files

Apache Web Server (with environment variables)

docker run -d --name my-apache -p 8081:80 -e APACHE_SERVER_NAME=localhost -v /host/www:/var/www/html httpd:latest
  • -e APACHE_SERVER_NAME: Set the server name via environment variable
  • httpd:latest: Apache HTTP Server image

🗄️ Running Databases

MySQL Database

docker run -d --name my-mysql -p 3306:3306 -e MYSQL_ROOT_PASSWORD=[YOUR_PASSWORD] -e MYSQL_DATABASE=mydb -v mysql-data:/var/lib/mysql mysql:8.0
  • MYSQL_ROOT_PASSWORD: Root user password
  • MYSQL_DATABASE: Database to create automatically
  • mysql-data:/var/lib/mysql: Volume for persistent data storage

PostgreSQL Database

docker run -d --name my-postgres -p 5432:5432 -e POSTGRES_PASSWORD=[YOUR_PASSWORD] -e POSTGRES_DB=mydb -v postgres-data:/var/lib/postgresql/data postgres:15
  • POSTGRES_PASSWORD: PostgreSQL password
  • POSTGRES_DB: Default database name

💻 Development Environments

Node.js Development Environment

docker run -it --name node-dev -p 3000:3000 -v /host/project:/app -w /app node:18 bash
  • -it: Interactive terminal mode
  • -w /app: Set working directory
  • bash: Start with a shell command

Python Development Environment

docker run -it --name python-dev -v /host/code:/workspace -w /workspace python:3.11 python
  • python:3.11: Python 3.11 image
  • python: Start the Python interpreter

🔧 Microservice Deployment

RESTful API Service

docker run -d --name api-service --restart=always -p 8000:8000 -e API_KEY=secret -e DB_HOST=db-container --network=app-network my-api:v1.0
  • --restart=always: Always restart
  • --network=app-network: Custom user-defined network
  • API_KEY, DB_HOST: Per-service environment variables

Load Balancer (Nginx)

docker run -d --name load-balancer -p 80:80 -v /host/nginx.conf:/etc/nginx/nginx.conf:ro --network=app-network nginx:alpine
  • nginx.conf:ro: Mount the config file as read-only
  • nginx:alpine: Lightweight Alpine-based image

🐳 Docker Compose Example

An easy way to manage complex multi-container applications.

Web Application + Database Stack

version: '3.8' services: web: image: nginx:latest ports: - "8080:80" volumes: - ./html:/usr/share/nginx/html depends_on: - db networks: - app-network db: image: mysql:8.0 environment: MYSQL_ROOT_PASSWORD: password MYSQL_DATABASE: webapp volumes: - db-data:/var/lib/mysql networks: - app-network volumes: db-data: networks: app-network:
  • depends_on: Define service dependencies
  • networks: Network for inter-service communication
  • volumes: Persistent data storage
💡 Usage: Save the above as a docker-compose.yml file and run docker-compose up -d.

❓ Frequently Asked Questions

Is anything I type sent to a server?

No. The command is generated entirely by JavaScript in your browser; image names, environment variables, and other values you enter are never sent to or stored on any server.

Can I run the generated command directly on a production server?

Review it before applying it to production. In particular, rm, prune, and down --volumes delete containers, volumes, and data. This tool also covers only the most common options, and recent Docker versions use docker compose instead of docker-compose.

How do I add multiple volumes or environment variables?

Enter one item per line in the volume mount and environment variable fields; each line is automatically converted into a -v or -e option in the generated command.
