CodeBurn — AIコーディングツールの支出をローカルで分析する

Claude Code・Cursor・Codexのコストがなぜ予測不能になるのか、そしてローカル可視化ツールでどう制御するか — AIコーディングFinOps実践分析

2026-06-18 開発・インフラ

はじめに：請求書を見て初めて知るコスト

AIコーディングツールを本格的に使い始めた開発者なら、一度は経験するはずだ。サブスクリプションを支払ったのに、月末の請求書が想定をはるかに超えている。あるいはチームにツールを展開したら、メンバーごとの使用量の差が激しすぎて予算が立てられない。2026年に入ってこの問題は無視できない規模に達した。

Uberは約5,000人のエンジニアにClaude Codeを展開し、わずか4ヶ月で年間AI予算を使い果たした。ヘビーユーザーには月500〜2,000ドルの請求が届いた。ある企業はトークン単価を正確に把握しないままClaude APIを開放し、30日間で5億ドルの請求書を受け取ったという報道もあった。Microsoftは社内のClaude Codeライセンスを大規模に整理し、6月30日までにGitHub Copilot CLIへの移行を進めた。すべてのケースに共通する根本原因がある。支出が見えていなかった。

こうした背景の中で、オープンソースCLIツールCodeBurnがGeekNewsに投稿され注目を集めた。「AIトークンがどこに消えているかを見せる」という単純な前提のツールだが、その基本的な可視性がなぜ重要なのかを本稿で深く分析する。2026年6月時点のAIコーディングツールのコスト構造とFinOps実践を合わせて考察する。

1. AIコーディングツールのコストはなぜ予測が難しいのか

AIコーディングツールの課金モデルは従来のSaaSと根本的に異なる。席数でも時間数でもなく、トークンで課金される。そして「何をしたか」と「いくら請求されるか」の関係が直感に反する。

1.1 トークン課金の落とし穴

Claude Codeを例に取ると、基本サブスクリプション（月20ドル）には一定のクレジットが含まれるが、2026年6月15日からAgent SDKとヘッドレス実行は別のAPIクレジットプールから差し引かれる。一つのセッションで消費するトークンは、タスクの複雑さやコンテキストサイズ、繰り返し回数によって1万から10万トークン以上まで大きく変わる。開発者は「何回質問したか」という感覚で使うが、課金は「何トークン使ったか」で行われる。この認知と請求のずれが予算超過の温床だ。

1.2 エージェントモードによるコスト増幅

一問一答よりもエージェントモードでコストが急増する。エージェントは同じファイルを繰り返し読んでは修正し、エラーを確認してまた修正するループを実行する。各ステップでコンテキスト（入力トークン）が積み上がる。リトライループが発生すると、コストは指数関数的に増える。同じ目的の作業でも、エージェントモードは単純な質問の10倍以上のトークンを消費することがある。

1.3 チーム規模での使用量格差

チームにAIコーディングツールを展開すると、個人の使用パターンの差が極端に開く。常時エージェントワークフローを走らせる開発者もいれば、補完機能の補助程度にしか使わない人もいる。平均値に基づいた予算計画はすぐ崩れる。プロジェクトやチームごとにタグ付けをしていないと、異常な支出も請求書が届くまでわからない。

1.4 隠れた間接コスト

業界分析によると、AIが生成したコードのレビュー、デバッグ、モニタリングにかかる間接コストが総コストの40〜60%を占めるという。AIの出力を確認する時間、誤った提案を修正する繰り返し、コンテキストを再設定するオーバーヘッドがここに含まれる。トークン単価だけを見ると安く見えても、実際の生産性対比コストはまったく異なる絵になり得る。

2. CodeBurnとは — ローカルファースト分析アプローチ

CodeBurnは2026年4月にMITライセンスでオープンソース公開されたAIコーディングコスト分析CLIツールだ。インストール不要でnpx codeburn一つで即座に実行できる。

2.1 核心設計原則：ローカル、非侵襲、オープン

CodeBurnの最も重要な設計決定は、ラッパーもプロキシもAPIキーも不要という点だ。Claude Code、Cursor、Codexなどのツールがディスクに書き出すセッションデータを直接読み取る。トラフィックを中間で捕捉しないため既存のワークフローを変える必要がなく、コードやプロンプトが外部サーバーに送られることもない。コスト計算にはLiteLLMのリアルタイム単価データを使用する。プライバシーと非侵襲性が最優先設計思想だ。

2.2 サポートツールと提供形態

2026年6月時点で、CodeBurnはClaude Code、Codex(OpenAI)、Cursor、GitHub Copilot、JetBrains AI、Gemini CLI、Cline、Devinなど25種類以上のツールに対応する。提供形態は3つだ。グラジェントチャートとキーボードナビゲーションを備えたインタラクティブな端末ダッシュボード（TUI）、macOSメニューバーアプリ、そしてエージェントが自分の支出を照会できるMCPサーバーだ。

2.3 3つの主要分析機能

13カテゴリータスク分類器が一つ目だ。AIとのすべてのやりとりを、コーディング、デバッグ、機能開発、リファクタリング、テスト、ドキュメント作成など13カテゴリーに自動分類する。LLM呼び出しなしの決定論的処理で、分類自体にトークンが消費されない。どの種類の作業がトークンを最も消費しているかが一目でわかる。

One-Shot Rate（初回成功率）追跡が二つ目だ。AIによる編集の何パーセントがリトライなしで成功したかを追跡する。この指標が低いカテゴリーは、AIが同じ目標に対して繰り返し失敗しながらトークンを浪費しているシグナルだ。改善のためのプロンプト調整、モデル変更、作業分割の根拠になる。

optimizeコマンドが三つ目だ。セッションデータと~/.claude/設定をスキャンして浪費パターンを探す。キャッシュヒット率の低下、実際には使っていないMCPサーバー、肥大化したCLAUDE.mdファイルを検出し、節約できるトークンとドル金額の見積もりと修正方法をコピーペースト形式で提示する。

3. AIコーディングコストをFinOps問題として捉える

FinOps財団の2026年State of FinOpsレポートによると、グローバルなFinOps担当者の98%がAI支出管理を担当している。2024年の31%から急増した数字だ。AIコーディングツールのコストは、部門の裁量支出から正式な財務ガバナンスの対象に移行しつつある。クラウドコスト管理の歩みと同じ軌跡だ。

3.1 クラウドコスト管理の教訓

クラウドコスト管理は予測可能な段階を経た。まず可視化ツールが登場し、次にタグ付けの標準化が来て、その後予算アラートが整備され、やがてFinOpsが組織文化として定着した。AIコーディングコストも同じ軌跡を辿る。今はその最初の可視化フェーズにある。CodeBurnが提供するのはその第一歩だ。

3.2 タグ付けとモデルガバナンス

Datadogのアナリストは、AIコスト管理で最も効果が高い二つの介入としてタグ付けとモデルガバナンスを挙げる。タグ付けはどのプロジェクト、チーム、タスクタイプが支出を生んでいるかを把握することで異常検出を可能にする。モデルガバナンスは、すべての作業に最高性能モデルを使う必要はないという認識だ。単純な反復作業には小型・低コストモデルを、複雑なアーキテクチャ設計にはフロンティアモデルを配置するモデル階層化は、出力品質を落とさずに平均トークン単価を下げられる。CodeBurnのカテゴリー別分析はこの階層化判断の根拠データになる。

3.3 トークン割当制の可能性

一部の先進的なチームでは、クラウドクレジットモデルからヒントを得て、開発者ごとの月次トークン割当制を試験導入している。「これが今月の割当量だ。どう使うかはあなたが決める」という方式だ。自律的な最適化を促すこのアプローチは、上からの統制より自然で持続可能だ。CodeBurnのような可視化ツールがあってこそ、開発者は自分の使用パターンを見ながら自律的に最適化できる。

4. トークンが消える場所 — 主要な浪費パターン

CodeBurnの知見と業界調査を組み合わせると、回避可能なトークン浪費の大部分は以下の4パターンに集約される。

4.1 コンテキストの肥大化

CLAUDE.mdやシステムプロンプトが過大になると、すべてのリクエストにそのオーバーヘッドが付く。100行のCLAUDE.mdを1日100回のプロンプトと合わせて送ると、それだけで1日数万トークンが浪費される。CodeBurnのoptimizeコマンドがこれを検出し、CLAUDE.mdの最適化を提案する最大の理由だ。

4.2 使っていないMCPサーバー

登録されたMCPサーバーはすべて、実際に使われていなくても各リクエストのコンテキストにその説明が含まれる。10個登録していて実際に使うのが3個なら、残り7個が毎リクエストで入力トークンを消費する。不要なMCPサーバーを定期的に整理するだけで、即座にトークン削減につながる。

4.3 低いキャッシュヒット率

プロンプトキャッシングは繰り返されるコンテキストのコストを大幅に削減する。しかしコンテキストプレフィックスの先頭に揮発性の要素があるとキャッシュキーが毎回変わり、キャッシュが効かなくなる。CodeBurnはセッションデータからキャッシュヒット率を計測し、低い場合はコンテキストの順序再構成を提案する。

4.4 リトライループの累積

あるカテゴリーのOne-Shot Rateが低いということは、AIが同じ目標に対して繰り返し失敗しながらトークンを消費しているということだ。根本原因の診断が必要だ。曖昧なプロンプト構造、コードベースの慣習に関するコンテキスト不足、タスクの複雑さとモデル性能のミスマッチのいずれかが多い。One-Shot Rate指標があって初めてこのパターンが定量化できる。

5. CodeBurnとその他のアプローチの比較

AIコーディングコストの可視化ツールはCodeBurnだけではない。各アプローチの特性を整理することで、どこでどのツールが適切かが明確になる。

ツール/アプローチ方式プライバシーコスト適合対象
CodeBurnローカルセッション分析高（外部送信なし）無料（オープンソース）個人・小チーム
Vantage / AmnicクラウドAPI集計中（APIデータ送信）有料SaaS企業・マルチチーム
Datadog AI Costインフラ統合モニタリング中有料SaaS大企業・DevOpsチーム
LLM Gatewayプロキシベース集計低（全トラフィック経由）様々集中管理が必要なチーム
自作ロギングAPIレスポンス解析高構築コスト技術力のあるチーム

CodeBurnの差別化はローカル実行、プライバシー保護、無料の組み合わせにある。コードを外部インフラに送らずに即座の可視性を得たい個人や小チームにとって、この価格帯で代替となるツールはほぼない。20名以上の大チームでは、CodeBurnと専用SaaSツールを組み合わせるのが現実的な選択だ。

6. 主要AIコーディングツールのコスト構造 — 2026年6月基準

参考として、2026年6月時点の主要ツールのコスト構造を整理する。具体的な単価はプロバイダーの方針で変わるため、方向性の参考として受け取ってほしい。

6.1 Claude Code

月20ドル/100ドル/200ドルのプランにクレジットが含まれるが、2026年6月15日の変更でAgent SDKとヘッドレス実行は別のAPIクレジットプールから差し引かれるようになった。エージェント作業が多いパワーユーザーはプランクレジットを早期に消費し、超過分が通常のAPIレートで請求される。エージェントワークフローでは入力トークン（コンテキスト）が出力トークンを大幅に上回ることが多い。

6.2 Cursor

月20ドル/40ドルのプランに含まれるFast Request数に上限があり、超過するとSlow Requestに移行する。使用するバックエンドモデル（Claude、GPT-4など）によって消費Request数が異なる。大きなコンテキストウィンドウを要求するタスクでFast Requestの消費が最も速い。

6.3 Codex (OpenAI)

OpenAIのCodexはGPT-4oクラスのモデルをAPIトークンレートで課金する。大きなコンテキストと長い出力が組み合わさると急速にコストが上がる。Codex CLIのローカル実行モードで一部タスクはAPI呼び出しなしに処理できるが、高品質な作業は結局APIを必要とする。

7. 実践的な推奨事項 — 今すぐできること

この分析を踏まえて、時間軸別に具体的な行動を整理する。

7.1 即座：可視性から始める

今すぐnpx codeburnを実行し、最近のセッションの支出分布を確認しよう。どのタスクカテゴリーが最もトークンを消費しているか、One-Shot Rateが低い領域はどこかを把握することが、すべての最適化の出発点だ。5分もかからない。

7.2 短期：低コストの改善から着手する

CodeBurnのoptimize出力を実行しよう。CLAUDE.mdを必須ルールだけに絞り込み、実際に使っていないMCPサーバーを無効化し、プロンプトキャッシングを有効化する。この3つだけで一般的に20〜40%のトークン削減が報告されている。

7.3 中期：モデル階層化とタグ付け

CodeBurnのカテゴリー別分析を根拠に、シンプルな反復作業（フォーマット、単純リファクタリング、ドキュメント整理）には小型モデルを使い、複雑なアーキテクチャ設計にはフロンティアモデルを残すモデル階層化を実装しよう。チームを管理している場合は、プロジェクト別タグ付け体系を構築して異常アラートを設定することを次のステップとしよう。

7.4 長期：FinOpsルーティンを作る

AIコーディングコストは一度最適化すれば終わりではない。新モデルの登場、チームの拡大、タスク複雑度の上昇で費用構造は常に変化する。月次でCodeBurnレポートを確認し、モデル単価の変化を追跡し、ヘビーユーザーを特定して改善を促すFinOpsルーティンを構築することが、長期的なコスト管理の核心だ。

8. 可視性が最初の一歩

CodeBurnは革新的なツールではない。ログを読んでコストを計算して画面に表示するだけだ。しかし2026年のAIコーディングコスト管理の現状では、その基本的な可視性こそが欠けているものであり、ツールに振り回されずにツールを使いこなすための起点だ。

クラウドコスト管理の初期も同じだった。まず可視化ツールが現れ、タグ付けと予算設定が続き、やがて組織文化として定着した。AIコーディングコストも同じ道を歩む。今はその最初の可視化フェーズにある。CodeBurnを実行することがその第一歩だ。
