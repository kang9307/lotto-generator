1. 생성 AI 시대 사진의 증명력과 provenance 기술의 분기점

생성형 인공지능 도구의 확산으로 사실적인 시각 결과물을 손쉽게 합성하거나 수정할 수 있는 환경이 조성되었다. 배경 요소를 자연스럽게 지우는 일상적 편집을 넘어, 실제 사건의 발생 여부를 증명해야 하는 사진의 핵심적인 사회적 기능이 근본적인 위협에 직면했다. 시각적으로 정교하다는 사실만으로는 해당 이미지가 현실의 물리적 장면을 기록한 진본임을 더 이상 담보할 수 없게 되었다.

과거 본 블로그의 선행 분석에서는 이미지 출처 보증 기술의 일반적 지형을 살펴본 바 있다. 생성 이미지에 붙는 표지에서는 파일 메타데이터, 서명된 C2PA 출처 정보, 비가시 픽셀 워터마크라는 세 가지 계층 구조와 각각의 취약점을 검토했고, 정품 파이프라인의 캡처 갭에서는 정품 서명 체계를 갖춘 카메라일지라도 렌즈 앞에 합성 화면을 들이대는 식의 구조적 한계가 존재함을 짚었다. 반면 2026년 9월 Apple이 공식 보안 블로그를 통해 공개한 Apple Reference Image는 이러한 업계의 기존 표준화 흐름과 명확히 구분되는 새로운 하드웨어·클라우드 결합 아키텍처를 제시한다.

Apple Reference Image는 iPhone 18 Pro와 iPhone 18 Pro Max의 메인 카메라 센서에 처음 도입되는 선택적(opt-in) 촬영 기능이다. 핵심 목표는 사진이 실제 iPhone 카메라 센서에 의해, 특정한 시각 범위 내에 물리적으로 포착된 장면임을 암호학적으로 보증하는 것이다. 이 기술은 단순히 소프트웨어가 이미지에 서명을 추가하는 방식을 탈피하여, 센서 반도체 단계의 암호화부터 Private Cloud Compute(PCC)의 클라우드 검증까지 이어지는 폐쇄적이고 강력한 수직 통합 신뢰 사슬을 구축했다.

2. C2PA 표준 대신 독자적인 수직 통합을 택한 배경

현재 글로벌 콘텐츠 및 카메라 업계의 주요 표준화 흐름은 C2PA(Coalition for Content Provenance and Authenticity) 규격을 중심으로 형성되어 있다. C2PA는 카메라 촬영 이후 단계에서 매니페스트 메타데이터를 첨부하고, 이후 이미지에 가해지는 모든 편집 이력을 서명 형태로 누적 기록하는 개방형 표준이다. 그러나 Apple의 보안 연구팀은 원문에서 C2PA 방식이 지닌 구조적 취약점 두 가지를 직접 지목하며, 이를 대체하는 독자적 해법을 채택했음을 분명히 밝혔다.

첫째는 전송 및 처리 파이프라인의 신뢰 붕괴 위험이다. 현대의 스마트폰 카메라는 렌즈로 들어온 빛을 센서가 아날로그에서 디지털로 변환한 뒤 디모자이킹(demosaicing), 노이즈 제거, 렌즈 왜곡 보정, 톤 매핑 등 광범위한 컴퓨테이셔널 포토그래피 소프트웨어 처리를 거쳐 최종 이미지를 생성한다. C2PA 기반 접근법은 통상 이 소프트웨어 파이프라인이 모두 끝난 종단에서 서명을 부착한다. 이 경우 센서와 이미지 처리 프로세서(ISP) 사이의 하드웨어 전송 버스에 조작된 픽셀을 주입하거나, 운영체제가 탈옥·침해당해 서명 직전의 메모리 데이터를 위조할 경우 사후 서명은 위조된 픽셀에 정품 서명을 붙여주는 결과를 낳는다.

둘째는 사진작가의 프라이버시 침해 문제다. C2PA 체계는 이미지의 출처를 입증하기 위해 특정 기기 식별자나 사진작가의 공개 자격증명(credential)을 파일에 결합한다. 이는 분쟁 지역이나 위험한 취재 현장에서 작업하는 보도 사진기자나 내부 고발자에게 심각한 신원 노출 위험을 초래한다. 특정 기기가 촬영한 여러 사진을 제3자가 교차 추적하는 위험도 발생한다. Apple Reference Image는 사진작가의 공개 신원을 요구하지 않고, 서로 다른 사진이 동일한 기기에서 촬영되었는지를 외부에 노출하지 않으면서도 진위와 폐기 가능성을 동시에 보장하는 설계를 택했다.

3. 신뢰 사슬 1단계 — 센서 내부 서명과 디지털 네거티브 생성

Apple Reference Image의 신뢰는 기기 제조 공장에서 시작된다. 공장에서 iPhone 18 Pro의 메인 카메라 센서가 초기화될 때, 센서는 내부에서 고유한 ECDSA P-256 서명 키 쌍을 자체 생성한다. 이 개인키는 센서 하드웨어 외부로 결코 유출되지 않는다. 공장의 기록 장비는 공개 검증 키만을 읽어 공장 인증기관(CA)의 서명을 거쳐 기기의 하드웨어 매니페스트에 등록한다.

동시에 기기의 격리 보안 프로세서인 Secure Enclave Processor(SEP) 역시 자체 키를 생성하고 Apple의 기본 증명 기관(Basic Attestation Authority, BAA) CA의 인증을 받는다. 제3의 CA는 이 센서 인증서와 SEP 인증서를 하나의 기기 매니페스트로 묶어 서명함으로써, 특정 센서와 특정 Secure Enclave가 동일한 물리적 기기에 속해 있다는 변경 불가능한 결합 관계를 공장 단계에서 확정한다.

사용자가 카메라 앱에서 레퍼런스 모드를 활성화하면, 카메라 센서는 보안 레퍼런스 캡처 모드로 재부팅된다. 이 모드에서 센서는 운영체제로부터 단 하나의 입력만을 받는다. 그것은 기기의 가장 최근 암호학적 타임스탬프, 기기 매니페스트, 시큐어 부트 매니페스트를 조합하여 계산한 SHA-256 다이제스트다. 셔터가 눌리는 순간 센서는 빛을 디지털화하고, 센서 내부의 펌웨어가 픽셀 데이터를 일체 수정하지 못하도록 차단된 상태에서 프레임 내부에 박힌 다이제스트와 원시 픽셀 데이터를 센서의 개인키로 즉각 암호학적으로 서명한다.

센서 외부에서 결정되는 메타데이터는 별도의 경로로 보호된다. 디지털 줌 배율, 노출 시간, 렌즈 파라미터와 같은 시스템 수준의 메타데이터는 센서가 알 수 없다. 카메라는 센서의 서명에 대한 암호학적 커밋먼트(해시)와 이 외부 메타데이터를 결합한 뒤, SEP의 BAA 인증 키로 서명한다. 이로써 센서 수준의 픽셀 데이터와 시스템 수준의 보조 메타데이터가 각각 격리된 하드웨어 영역에서 독립 서명되어 DNG 형식의 보안 디지털 네거티브(secure digital negative)에 패키징된다.

4. 신뢰 사슬 2단계 — 암호학적 타임스탬프와 시간 경계 증명

사진의 신뢰성을 평가할 때 촬영 시각은 위변조 방지의 핵심 요소다. 일반적인 스마트폰 운영체제가 기록하는 EXIF 타임스탬프는 로컬 시스템 시계에 의존하므로 사용자가 설정을 바꾸거나 루팅 권한을 얻으면 임의로 조작할 수 있다. Apple은 단일 시점 기록 대신 암호학적 타임스탬프 서비스(Cryptographic Timestamp Service)를 활용한 상한과 하한의 이중 경계 증명 방식을 도입했다.

기기는 백그라운드에서 주기적인 통신(heartbeat) 프로토콜을 수행한다. Apple Push Notification Service(APNs)의 기존 연결 유지 신호와 연동하여, Apple의 타임스탬프 서비스로부터 SHA-256 기반 ECDSA P-256으로 서명된 RFC 3161 규격의 타임스탬프 토큰을 지속적으로 수신하고 가장 최신 토큰을 기기에 보관한다. 전 세계적으로 이 토큰 수신 주기는 평균 약 15분 간격으로 실행된다. 이 보관된 토큰이 사진 촬영 시점에 센서 프레임 다이제스트에 주입되어 촬영 시각의 엄격한 하한(lower bound)이 된다. 즉, 사진이 해당 토큰 발행 시각 이전에 촬영되었을 가능성을 암호학적으로 배제한다.

촬영 직후 기기는 SEP 서명에 대한 SHA-256 커밋먼트를 생성하여 타임스탬프 서비스로 전송하고, 두 번째 서명 토큰을 받아 상한(upper bound)으로 삼는다. 이를 통해 사진은 공인된 두 시각 경계 사이의 좁은 시간 창 내에 포착되었음이 확정된다. 네트워크 연결이 끊긴 오프라인 상태에서 촬영된 경우 상한 토큰을 즉시 받지 못하지만, 기기는 통신이 복구될 때까지 백그라운드에서 재시도를 이어가 가장 좁은 유효 간격을 획득한다. 이때 타임스탬프 요청은 Oblivious HTTP(RFC 9458)를 경유하므로, Apple의 타임스탬프 서버조차 요청 기기의 IP 주소를 파악할 수 없어 네트워크 수준의 추적이 차단된다.

5. 신뢰 사슬 3단계 — Private Cloud Compute의 5단계 검증 절차

보안 디지털 네거티브는 원시 픽셀과 메타데이터의 암호학적 묶음일 뿐, 일반 사용자가 즉시 볼 수 있는 완성된 이미지가 아니다. 원시 베이어 패턴 데이터를 시각화하려면 디모자이킹, 색상 보정, 톤 매핑이 필수적이다. Apple은 이 현상(development) 작업을 로컬 운영체제에 맡기지 않고, 기밀성과 감사 가능성을 보장하는 Private Cloud Compute(PCC) 환경으로 이전했다. 사용자가 현상을 개시하면 DNG 네거티브가 PCC로 전송되며, PCC 노드는 이미지를 가공하기 전 다음의 엄격한 5단계 검증을 순차적으로 수행한다.

  • 1단계: 프레임 다이제스트 재계산 및 센서 서명 검증 — 수신된 원시 픽셀과 프레임 내에 박힌 SHA-256 다이제스트를 재계산하여, 센서 내부에서 생성된 서명이 단 한 비트의 데이터 왜곡 없이 일치하는지 수학적으로 검증한다.
  • 2단계: 공장 센서 인증서 체인 검증 — 센서 서명에 사용된 공개키가 제조 공장에서 Apple의 센서 CA를 통해 서명·발급된 정품 하드웨어 인증서 체인으로 환원되는지 확인한다.
  • 3단계: 센서와 SEP의 동일 기기 귀속 확인 — SEP 서명 체인(BAA CA)과 센서 인증서 체인을 대조하고, 제조 시 공장 CA가 서명한 하드웨어 매니페스트를 검증하여 센서와 SEP가 원래 동일한 iPhone에서 출하된 조합인지 검사한다. 부품을 떼어내 다른 보드에 이식한 공격을 이 단계에서 걸러낸다.
  • 4단계: 암호학적 타임스탬프 토큰 검증 — 하한 및 상한 RFC 3161 토큰의 유효성을 검증한다. 만약 하한 토큰 검증에 실패하면 기능이 공식적으로 존재하지 않던 시점인 2026년 3월 31일로 대체 처리하고, 상한 토큰이 오프라인 지연 등으로 결손된 경우에는 PCC 현상 시점의 현재 시각을 상한으로 대체하여 시간적 경계를 확정한다.
  • 5단계: 은닉 가중치 신경망 기반 물리적 특성 평가 — 비공개 은닉 가중치를 탑재한 신경망을 구동하여, 입력된 원시 데이터가 실제 iPhone 카메라 센서의 아날로그 신호 변환 과정에서 나타나는 고유한 물리적 노이즈 및 광학적 특성을 유지하고 있는지 분석하고 신뢰도 점수를 산출한다.

PCC 노드는 소프트웨어의 무결성이 공개 투명성 로그(transparency log)에 해시 형태로 영구 기록되는 환경이다. 외부 보안 연구자는 PCC에서 실행되는 바이너리를 공개적으로 다운로드하여 분석할 수 있으며, 기기는 해당 로그에 서명된 정품 빌드를 구동하는 노드에만 데이터를 전송하도록 암호학적으로 강제된다. 이는 이미지 현상 과정에서 데이터가 사적으로 열람되거나 위조되지 않음을 수학적으로 입증한다.

6. 신뢰 사슬 4단계 — 신경망 신뢰도 점수와 센서 단위 폐기 메커니즘

암호학적 서명이 유효하더라도, 렌즈 앞을 정교하게 조작하거나 물리적 공격을 시도할 가능성은 완전히 배제할 수 없다. PCC의 5단계 검증 절차에 포함된 은닉 신경망은 센서가 수집한 원시 출력물이 실제 물리적 센서의 전자적 특성에 부합하는지를 다각도로 평가하여 신뢰도 점수(confidence score)를 매긴다. 이는 순수 수학적 서명 검증과 물리 세계의 신호 특성 검증을 결합하는 핵심 완충 계층이다.

신뢰도 점수가 산출되면, PCC는 현상된 레퍼런스 이미지에 서명하기 전에 사진의 고유 식별자(photo GUID), 원시 해시, 신뢰도 점수, 그리고 센서 ID를 별도의 동반 서비스(companion service)로 전송한다. 이 서비스는 센서별 누적 신뢰도 점수를 업데이트하고, 해당 센서가 사기 의심으로 등록된 폐기(revocation) 목록에 올라 있는지 대조한다. 만약 누적 점수가 임계값 아래로 떨어지거나 의심 정황이 확인되어 센서가 폐기 대상으로 지정되면, PCC는 향후 해당 센서에서 올라오는 모든 이미지의 현상 및 서명 작업을 거부한다.

이 폐기 시스템의 가장 중요한 설계 원칙은 프라이버시의 유지다. 동반 서비스는 사진의 픽셀 데이터를 일체 수신하지 않으며 오직 GUID와 센서 ID, 점수 메타데이터만을 비공개로 유지한다. 최종 사용자의 iPhone은 정기적으로 최신 센서 폐기 목록을 내려받아 로컬 캐시에 저장한다. 기기에서 사진을 감상하거나 진위를 검증할 때는 로컬 폐기 목록과의 대조가 기기 내부에서 완결되므로, 특정 사용자가 지금 어떤 사진을 조회하고 있는지 네트워크 외부에 신호가 노출되지 않는다. 사진작가의 신원을 특정하지 않으면서도 부정 기기에서 생성된 사진 전체를 소급하여 무효화할 수 있는 구조를 확립했다.

7. 신뢰 사슬 5단계 — 포스트 퀀텀 하이브리드 서명과 장기적 무결성

PCC 검증과 신경망 평가를 모두 통과하면, PCC는 원시 베이어 데이터를 디모자이킹 및 톤 매핑하여 표준 JPEG 파일로 압축한다. 이어 압축된 결과물의 해시를 생성하여 커밋먼트로 삼는다. 이 해시는 향후 사진을 고유하게 식별하는 photo GUID의 기반 비트로도 사용된다.

PCC는 이 커밋먼트를 Apple의 중앙 서명 서비스로 전달한다. 여기서 최종 생성되는 서명은 일반적인 고전 암호 체계가 아니라 양자 컴퓨팅 공격에 내성을 지닌 포스트 퀀텀 하이브리드 서명이다. 원문은 이 체계를 RSA-3072와 양자내성 전자서명 표준인 ML-DSA-87을 결합한 복합 서명(hybrid MLDSA87-RSA-3072-PSS-SHA512 scheme)으로 기술한다.

보도 사진이나 역사적 기록물은 촬영 시점뿐만 아니라 수십 년이 흐른 뒤에도 진위 여부가 검증 가능해야 한다. 향후 쇼어 알고리즘을 구동할 수 있는 대규모 양자 컴퓨터가 등장할 경우 고전적 RSA나 타원곡선(ECDSA) 서명은 사후 위조될 수 있다. Apple은 2026년에 촬영된 레퍼런스 이미지가 영구적인 신뢰를 유지할 수 있도록, NIST 표준화가 완료된 ML-DSA-87 격자 기반 서명과 널리 검증된 고전적 RSA-3072를 동시에 결합하는 다중 방어막을 구축했다. 최종 하이브리드 서명은 생성된 JPEG 메타데이터에 내장되어 클라이언트로 반환되며, 원본 DNG 네거티브는 기기의 최근 삭제된 항목(Recently Deleted)으로 자동 이동되어 30일 후 자동 영구 삭제되거나 필요시 보존된다.

8. 위협 모델 대응 분석 — 5단계 사슬이 차단하는 공격 벡터

Apple Reference Image의 진정한 가치는 단순히 기능을 나열하는 데 있지 않고, 하드웨어 센서부터 클라우드까지 촘촘히 엮인 검증 단계가 각각 어떠한 구체적 보안 위협을 무력화하도록 설계되었는지를 이해하는 데 있다. 각 방어선은 서로 다른 공격 벡터를 봉쇄하기 위해 유기적으로 짝지어져 있다.

아래 표는 주요 공격 시나리오와 이에 대응하는 시스템 내부의 기술적 메커니즘을 정리한 것이다. 이는 공식 기술 발표문에 제시된 구성 요소의 입출력 관계를 기반으로 분석한 보안 경계의 대응 구조다.

표 1: 위협 모델과 신뢰 사슬 대응 메커니즘 분석
위협 시나리오 (Threat Vector) 공격자가 시도하는 행위 대응 메커니즘 및 방어 계층
센서 버스 조작 및 픽셀 주입 센서와 AP/ISP 사이의 전송 회로에 가짜 이미지 데이터를 전기적으로 주입 센서 시큐어 부트 전용 모드 및 촬영 직후 센서 내부 서명(ECDSA P-256), 펌웨어 수정 차단
센서 외부 메타데이터 위조 운영체제를 탈옥하여 디지털 줌 배율, 노출값, 초점 거리를 임의 조작 SEP가 센서 서명 커밋먼트와 외부 메타데이터를 결합하여 BAA 인증 키로 격리 서명
촬영 시각 조작 및 소급 위조 로컬 시스템 시계를 조작하여 사진이 과거 또는 미래에 찍힌 것처럼 위장 APNs 주기적 토큰(평균 약 15분) 하한과 촬영 직후 토큰 상한의 이중 타임스탬프 강제
센서 분해 및 기기 이식 정품 센서를 적출하여 임의로 변조된 다른 로직 보드에 연결해 악용 공장 제조 시 제3의 CA가 서명한 기기 매니페스트로 센서 CA와 SEP BAA 키의 동일 기기 귀속 검증
비물리적 합성 이미지 주입 센서 서명 키를 부분 탈취하거나 정교한 그래픽 렌더링 데이터를 직접 주입 PCC 내 은닉 가중치 신경망의 물리적 센서 특성 검사 및 신뢰도 점수 기반 폐기 목록 연동

이 위협 분석이 시사하는 핵심 결론은 다음과 같다:

  • 운영체제 수준의 완전한 침해가 발생하더라도 센서 내부 서명과 SEP 독립 서명이 유지되므로 픽셀 변조가 불가능하다.
  • 공장 인증서 체인과 기기 매니페스트의 3중 서명 구조로 인해 하드웨어 부품 적출 및 스왑 공격이 차단된다.
  • 시간 동기화 공격은 로컬 OS의 권한과 무관하게 독립된 암호학적 타임스탬프 서버의 서명 검증으로 봉쇄된다.
  • 네트워크 전송 경로의 추적은 Oblivious HTTP를 통해 IP 익명성을 확보함으로써 물리적 위협을 상쇄한다.
  • 양자 컴퓨터를 활용한 미래 시점의 서명 위조 공격은 ML-DSA-87 복합 서명을 통해 수십 년간 선제 방어된다.

9. 기술의 유효 범위 — 증명하는 것과 침묵하는 것

Apple Reference Image는 정교한 신뢰 사슬을 자랑하지만, 모든 이미지 위변조 문제를 마법처럼 해결하는 만능열쇠가 아니다. 이 기술이 정확히 무엇을 입증하며, 반대로 무엇을 입증하지 못하고 원문이 침묵하는지를 엄격하게 분리하여 인식해야 불필요한 과신이나 기술적 오판을 피할 수 있다.

가장 중요한 한계는 사후 편집과의 단절이다. 보도나 창작 현장에서 원본 사진을 그대로 사용하는 경우는 드물다. 대다수 사진은 노출 보정, 리사이징, 크롭(자르기), 색조 변경 등의 재가공 과정을 거친다. 그러나 Apple의 기술 문서는 원시 디지털 네거티브가 PCC에서 JPEG 레퍼런스 이미지로 현상되는 단일 파이프라인만을 설명할 뿐, 사용자가 이후 사진 앱이나 포토샵 등 외부 소프트웨어에서 사진을 편집했을 때 서명이 어떻게 유지되거나 갱신되는지에 대해 일절 언급하지 않는다. C2PA가 편집 계보(assertion chain)를 기록하려 했던 것과 달리, Apple의 원문은 촬영 직후 찰나의 순간에 대한 진위 증명에만 집중하고 있다.

표 2: Apple Reference Image의 증명 범위와 기술적 공백 비교
이 기술이 명확히 증명하는 것 (Verified Guarantees) 증명하지 못하는 것 및 원문이 침묵하는 영역 (Silences & Limitations)
iPhone 18 Pro/Pro Max 메인 센서가 실제 촬영했다는 사실 촬영 이후 크롭, 보정, 필터 등 편집 후 서명 유지 여부 (원문 침묵)
타임스탬프 하한과 상한 사이의 특정 시간대에 촬영되었다는 사실 서드파티 앱, 웹 브라우저, 외부 개발자용 API 연동 규격 (원문 침묵)
센서 캡처부터 JPEG 현상까지 픽셀이 조작되지 않았다는 사실 렌즈 앞 고해상도 모니터 재촬영(아날로그 홀)의 완전 차단 여부 (실험치 부재)
사진작가의 신원 노출이나 기기간 사진 연동 추적이 없다는 사실 C2PA 생태계 등 이기종 플랫폼 간의 상호운용성 (독자 폐쇄 노선)
향후 양자 컴퓨터 공격 환경에서도 서명이 유효하다는 사실 인터넷에 떠도는 임의의 AI 합성 이미지를 판별하는 범용 기능 (정품 화이트리스트에 불과)

또한 이 기술은 임의의 이미지가 AI로 생성되었는지를 가려내는 블랙리스트 탐지기가 아니다. 오직 자사의 최신 하드웨어 센서로 적법하게 생성된 레퍼런스 이미지에 한해서만 진본임을 보증하는 화이트리스트 방식이다. 따라서 이 기능이 디지털 생태계 전반의 가짜뉴스나 딥페이크 문제를 즉시 종식시킬 수는 없으며, 수직 통합된 Apple 하드웨어 생태계 내부에서 가장 엄격한 원본 증명 규격을 세운 시도로 평가하는 것이 타당하다.

기술 도입을 평가할 때 고려해야 할 핵심 현실적 요소는 다음과 같다:

  • 지원 기기가 iPhone 18 Pro 및 iPhone 18 Pro Max 메인 카메라로 한정되어 보급 초기 생태계 범위가 좁다.
  • C2PA를 배제한 독자 노선으로 인해 타사 카메라 기기나 타사 클라우드와의 상호 운용에 장벽이 존재한다.
  • PCC 서버와의 통신이 요구되므로 네트워크가 단절된 극단적 환경에서는 현상 및 검증 완료 시점이 지연된다.
  • 디지털 네거티브가 30일 후 자동 삭제되므로 원시 증명 데이터를 장기 보존하려면 사용자의 추가 관리가 필요하다.
  • 사후 가공에 대한 명세가 부재하여 편집이 필수적인 출판·보도 현장 파이프라인에 즉각 도입하기에는 제약이 따른다.

10. 확인하지 못한 것

  • 편집 및 재가공 후 서명 유지 여부: Apple의 공식 기술 문서는 보안 디지털 네거티브를 PCC에서 JPEG 레퍼런스 이미지로 1회 현상하는 과정까지만 기술하고 있으며, 사진 앱의 자체 보정 도구나 서드파티 편집기에서 색조 변경이나 크롭을 수행했을 때 서명이 어떻게 보존·변환되는지 명시하지 않아 확인되지 않았다.
  • 서드파티 개발자용 API 및 플랫폼 연동 규격: 서드파티 앱 개발자나 웹 브라우저 환경에서 Reference Image의 서명 무결성과 로컬 폐기 목록을 직접 검증할 수 있는 공개 SDK나 API 명세가 제공되는지 여부는 원문에 언급되지 않아 확인되지 않았다.
  • 은닉 가중치 신경망의 구체적 판정 임계값: PCC에서 원시 센서의 물리적 특성을 평가하는 신경망의 입력 피처 구성, 허용 노이즈 편차, 신뢰도 점수의 정량적 임계값 수치는 보안성 유지를 위해 비공개로 분류되어 확인되지 않았다.
  • 센서 펌웨어 독립 감사 가능 여부: PCC 실행 바이너리는 공개 투명성 로그를 통해 외부 보안 전문가의 독립 검증이 가능하다고 공개되었으나, 카메라 센서 내부 펌웨어와 서명 모듈의 코드가 서드파티에 감사 가능한 형태로 제공되는지는 확인되지 않았다.
  • 광학적 스크린 재촬영(아날로그 홀)에 대한 신경망 판별 성능: 고해상도 올레드 모니터나 사진 인화물을 정품 카메라로 다시 촬영하는 식의 물리적 기만 시도에 대해 신경망 신뢰도 점수가 어느 정도의 탐지율을 나타내는지에 관한 공식 실험 데이터는 발표문에 포함되어 있지 않다.
