摩擦为什么在做的一方看不见 - 2003年一封内部邮件成为记录的原因

抱怨每天都有，却没有变成文档。记录得以产生的条件，以及把那些条件日常化的装置

2026-09-08 潮流/文化

2003年1月15日星期三上午10点05分发出的一封内部邮件，二十多年后仍在互联网上流传。主题是 Windows Usability Systematic degradation flame，发信人是比尔·盖茨，收件人只有吉姆·奥尔钦一人，抄送栏里还有六个名字。开头一句是「I am quite disappointed at how Windows Usability has been going backwards and the program management groups don't drive usability issues.」，紧接着就转入「Let me give you my experience from yesterday.」。之后的全部内容，是前一天为了下载一个软件而遭遇的事情的时间顺序记述。

这份文件通常被介绍成「最高经营者发火的邮件」。这种介绍恰好挑走了文件里最不重要的那部分。人每天都会发火。那一年那一天在同一条路径上被卡住的人有多少，没有人知道，因为没有人在数。那封邮件的特别之处不在抱怨的大小，而在于那份抱怨获得了文档的形式这一点。

所以这里用的轴既不是人物也不是公司。轴只有一条。摩擦为什么在做的一方看不见，以及如何把看不见的东西变成记录。二十年过去，软件的名字全换了一遍，但人在安装与注册的头五分钟里被卡住的位置类型几乎没有移动。既然留下来的是类型，对策也必须是类型。

下文讨论的2003年文件，被标注为经由2007年美国艾奥瓦州消费者集体诉讼 Comes v. Microsoft 公开的内部文件。引用压到四处，文面以公开该文件的档案库和当时报道所转录的形态为准。它并未与法院提交本逐词比对，这一局限连同其他局限放在后面的小节说明。另外，这里不把二十年前的文件当作对今天产品的评价，全文也不点名当下市场上的任何产品。

那封邮件至今还在的原因

先把文件的身份钉住。一份文件被引用得越广，流传的变形版本就越多，而变形版本几乎总是被打磨成比原文更强的句子。那封邮件常常以「盖茨装不上自家的软件」这一行摘要在流通。文面实际支撑的范围要窄得多。

发送时间是2003年1月15日星期三上午10点05分，收件人一位，抄送六位。主题里的 flame 是当时内部邮件中预告语气激烈的习惯用语。正文写的是前一天的经历，因此事件本身发生在1月14日。公开路径是2007年的艾奥瓦州集体诉讼，该案在庭审中以和解结束，原告方原本公开的证据档案库随后受到访问限制。今天流传的文面，经由那段时间的转录本和2008年的报道保留下来。

这张表的右栏不为空，这一点很要紧。文件越出名，右栏就越会被人们的记忆填满，而被填进去的内容多半不是事实。把引用压短并附上归属，理由就在这里。

不是摩擦被发现，而是记录被产生

正文里被反复引用的段落有两处。一处是搜索的场景：「I typed in moviemaker. Nothing. I typed in movie maker. Nothing.」同一个词只改动空格输入了两遍，两次都没有结果。另一处在后面，转述了向负责人询问后得到的答复：「So they told me that using the download page to download something was not something they anticipated.」

后面这句把本文的整条轴压缩成一行。把下载页面用来下载东西，这种用法不在预想清单里。这不是过失的招认，而是视野的陈述。做的一方在用另一种用途使用那个页面，在那种用途下并没有任何问题。问题不在页面，而在预想清单。

分岔就出现在这里。预想清单上的这个洞不是那天早上才开的。搜索词里一个空格就改变结果这种性质，以及找到东西的页面和领取东西的页面被分开这种结构，都不是一天能造出来的。也就是说，那天并不是摩擦被发现了。那天是摩擦获得了记录的形式。造成这个差别的是三个条件。

  • 撞上它的人握有决策权。那一周在同一条路径上损失同样时间的人想必不少，但他们的时间没有被写到任何地方，因为没有可写的位置。
  • 整条路径被走完而没有被切断。从搜索开始，经下载、安装直到重启，中途没有绕去内部工具，也没有去问熟人。所以它成了一个连贯的叙述。
  • 记录进入了不会被丢弃的通道。内部邮件会被保存，被保存的东西以后会被打开。如果只是口头抱怨，当天傍晚就消失了。

这三个条件是偶然叠在一起的。组织该学的不是那个偶然，而是把同样的三个条件日常化的方法。做到了，就不必等最高决策者偶然坐到用户的位置上。

做的一方的机器不是用户的机器

摩擦看不见的第一个原因不是态度而是状态。做产品的人的机器，已经被整备成能让这个产品跑得很顺的机器。所谓整备好，准确说就是首次启动的条件被抹掉了。

特别难办的是，首次启动这条路径正是做的一方走得最少的路径。开发期间在已经装好的状态下重启，在已经登录的状态下打开页面。就算一天打开一百次，只要这一百次全是第二次以后的访问，首次访问就一次也没被观测到。而且次数越多信心越足，越是没被观测的地方越会被有底气地说没问题。

知道这件事遮住了什么

无法自行复现不知道的状态，这不是意志问题，而是被反复观测到的性质。给它命名的是经济学。卡默勒、勒文斯坦与韦伯1989年发表在 Journal of Political Economy 第97卷第5期的论文用实验表明，信息更充分的一方即使忽略私有信息更符合自身利益也做不到忽略。这篇论文对实务最有用的数值来自市场实验一侧：市场压力把这一偏差削减约一半，但没有消除。也就是说，加了激励仍有残余。

把同一性质表现得更直观的，是1990年斯坦福伊丽莎白·牛顿的博士论文 The rocky road from actions to intentions 里的实验。一方在桌上敲出一首广为人知的歌曲的节奏，另一方听着猜曲名。被广泛引用的数值是，敲出的120首里被猜中的只有2.5个百分点，而敲的一方事先预测的正确率是50个百分点。旋律在敲的人脑子里流淌着，于是传到听的一方的只有节拍这个事实无法被复现。

在产品里，这个结构表现成这样。做的一方脑子里，功能的名字、页面的位置和顺序早已在流淌。到达用户那里的只有页面上实际写着的词。所以「站在用户角度想一想」这条指示不构成方法。那等于让敲的人忘掉旋律。

替代方案不是态度，而是条件的物理复原。新账号、第一次开机的设备或至少一个新的浏览器配置文件、清空的缓存、默认区域设置，以及一个没有参与制作的人。前四项可以准备，最后一项得借。

摩擦在组织里消失的路径

第二个原因不是认知而是组织。撞上摩擦的人和能修它的人之间通常隔着好几级，每一级都会掉信息。

  • 撞上的人大多不说。当提交反馈所花的时间大于干脆放弃所花的时间，人就会放弃。所以被受理的工单不是摩擦的样本，而是耐心的样本。
  • 被受理的工单会被摘要。摘要会丢掉复现步骤。十种不同的卡点进了同一个叫使用方法咨询的格子，这格子在下次会议上就成了低优先级条目。
  • 路径会沿着组织架构被切断。搜索归搜索团队，分发归分发团队，安装归产品团队，支付归支付团队。每个团队的指标在自己的区间里都正常。可是用户并不分区间地走。
  • 修的权限和看的位置在不同的地方。把摩擦看得最清楚的通常是支持与运维，而能修的通常是产品。这种错位与收益漏掉的地方不在工作内部而在边界上是同一个结构。

第三条重新解释了前面那份2003年文件。那封邮件之所以例外，不在语气而在跨度。一个人把搜索、下载、安装和重启写成了一个故事。组织里没有任何一个指标覆盖那个跨度。无论各区间的数字看得多好，把区间接起来之后的总耗时和总流失率，在任何看板上都找不到。

抱怨会挥发，记录不会

摩擦到底有多常见，只有在有人数过的地方才看得见。把这一点展示得最清楚的公开汇总来自电子商务。Baymard 研究所汇集了2006年到2025年间的50项研究，把有文献记载的购物车放弃率平均值定为70.22个百分点。在因为并非单纯浏览的理由而放弃的人当中，「网站要我注册账号」占18个百分点。同一调查里，额外费用占40个百分点，配送太慢占20个，不信任网站处理银行卡信息占19个，结账太长或太复杂占17个。

这里要紧的不是18这个数字的大小，而是它的形式。它不是谁生气了的陈述，而是数出来的值。如果没人数，这18个百分点就不存在。不存在的值在会议上赢不了。并非另有一套机制让不满转化为流失，而是没被数下来的不满被悄悄按流失结算掉了。

左栏全是句子，右栏全是数值。句子只能被另一个句子反驳，数值只能被另一个数值反驳。所以减少摩擦的工作有一半并不是设计工作，而是把左栏搬到右栏的工作。搬完之后，那处摩擦才够格上优先级讨论的桌面。不过数这件事有先后，数什么必须在事情发生之前就定好。事后翻日志拼出来的数值只会显示当时恰好留下的东西，没留下的会被永远记成零。

把摩擦变成记录的四件装置

四件就够。四件都不是要新造的工具，而是把已有的东西换个切法的规则。

首次启动的分步到达率

把安装和注册当成一个完成率来看，就说不出人是在哪里断掉的。要分别统计每一步的进入和完成。切分步骤的依据不是页面跳转，而是用户必须做决定的地方。一个页面里有三个决定，那就是三步。

step_enter  { flow: "signup", step: "email_verify", session, ts, platform, locale, is_first_run }
step_exit   { flow, step, outcome: "done|abandon|error", ms_in_step, retries, error_code }
first_value { flow, ms_since_signup, path_taken }

流失点与它前一刻的行为

只看流失率生不出原因候选。必须把流失前的最后一次操作、当时的报错文案、同一步骤的重试次数、在该步骤停留的时长一并挂上去。其中重试次数尤其便宜而信号强。同一步骤重复三次的会话，说明那一步的文案没能传达它到底在要求什么。

工单的分类体系

把工单二分为「缺陷」和「使用方法咨询」，摩擦就会全被吸进后一格，而那格再也不会被打开。至少要有两条独立的轴：在哪个页面和想做什么。有了两条轴，靠前的条目会自动排出来，这个排序就是首次启动指引文档的目录。重复出现的问题始终没被升格成文档而一直重复的结构，正是缺少这两条轴时产生的。

用新账号和新设备做的定期走查

定好周期，在完全崭新的条件下从头走到尾。这里常见的反驳是样本量，而所需人数比想象中少。尼尔森与兰道尔发表在1993年INTERCHI论文集206页至213页的论文，把可用性问题的发现建模为泊松过程，把n人参与时被发现的比例写成1减去1减L的n次方。L是单个参与者发现某一问题的概率，跨多个项目的典型取值约为31个百分点。代入后五个人得到约85个百分点。不过31来自项目平均，并非对所有产品成立的常数。实务含义偏向定期性比人数更重要这一侧。

记录出现之后会发生什么

记录出现了，摩擦并不会因此消失。前面那份2003年文件有后续。自述当时在该公司负责网站的市场组织工作的蒂姆·贾勒特在2008年的回忆说，此后约18个月里陆续做了搜索索引与算法改进、基于用户行为数据的编辑方针整顿，以及内部分析工具改善。同时他写道，自己的团队没有改变或推翻产品组织决定的权限。

这段回忆是五年后个人留下的自述，不是公司的正式记录。可它描述的结构并不陌生。当观察的组织和修理的组织不是同一个，记录就会堆积，而变更会变成谈判。谈判在优先级竞争里通常是输的一方，因为摩擦不在任何人的目标里。注册完成率是增长组织的目标，安装成功率不是谁的目标。

所以这些装置的最后一个条件不是采集而是归属。每一条摩擦条目都得挂上要修的一方的名字，而那个名字应该是目标而不是团队。没有归属的记录，结局无非三种。

  • 变成报告。每个季度都做得很好也发得很勤，却没有一条被关闭。
  • 变成工具之争。指标不准的意见反复出现，提升准确度的工作替代了修摩擦的工作。
  • 变成人的问题。被翻译成某个团队是否尽责，于是下一轮那个团队只守自己的区间。

二十年后仍然存在的摩擦类型

名字全换了，类型留下了。下面不点名当下市场上的任何产品，只整理公开研究里能取到信号的类型。

关于诱导式设计的规模，有马图尔等人2019年提交给 CSCW 会议的调查。他们扫描了约1.1万个购物网站的约5.3万个商品页，找出1,818个实例，并归入15种类型7个范畴。在同意界面这一侧，有诺文斯等人2020年提交给 CHI 会议的调查。他们采集了英国前1万网站中使用五个最常见同意管理平台的680个站点的设计，其中满足最低法定要求的只有11.8个百分点。同一篇论文还用40人的现场实验，考察八种最常见设计如何改变人们的实际选择。

更新时机在别的事情做到一半时要求重启和等待没有公开汇总，只有个案记录延后点击次数、强制退出发生率
前置条件不可见失败之后才告诉你需要什么没有公开汇总，只有个案记录各失败码的首次出现时点

表的后三行没有公开汇总。这不表示这些类型少见，而是没有人把那些位置当作常规去数。没被数过的位置正是2003年的那个位置。像未经同意就被安装这样从摩擦转向权利的类型，要放在与这张表不同的轴上处理。

在自己产品里找摩擦的流程

三步就够，半天走完一轮。

第一步 复原条件

建一个新账号。把现有账号登出是不够的。用新的浏览器配置文件或重置过的设备，清空缓存，区域设置留在默认值，走非公司内网的线路。清单里放一台低配设备和一块窄屏幕。到这里为止是机器能复原的部分。

第二步 不切断地走完

把目标定在拿到首个价值的那一刻，既非安装完成也非注册完成，而是使用这个产品的理由第一次兑现的地方。在此之前不动内部工具，也不问熟人。卡住了就卡着，把时刻记下来。绕过去的那一瞬间，这一轮的数值就没了。这一步复现的是前面三个条件中的第二个。

第三步 让记录有归属

每条填四栏：在哪个页面、想做什么、花了多久、进入谁的目标。最后一栏空着，这条下一轮还会原样留着。然后把这张表保存下来而不是删掉，因为下一轮的基线就是这张表。没有基线，变好还是变坏就只能停留在印象里。

  • 这套流程抓的是路径上的摩擦。功能缺失或对价格的拒绝，它抓不到。
  • 它抓不到的是长期使用的摩擦。数据积累之后才变慢的问题，在首次启动里看不见。
  • 同一个人反复做，数值会一轮比一轮好。那种改善属于这个人的学习而不是产品。每轮换人更好。

这套方法失效的地方

装置都配齐了却出不来结果的情况是有的。失效大体来自四个方向。

  • 观察改变了条件。做走查的人知道自己在走查，于是比平时更能忍，平时早关掉的页面这次读到底。总耗时会比现实短，流失被低估。
  • 指标只数留下来的人。在第一屏就离开的人，往往在埋点代码运行之前就消失了。所以到达率表的第一行永远比真实情况乐观。
  • 去掉摩擦并不总是对的。在付款、删除、授予权限、对外分享这些难以撤销的行为面前，摩擦是安全装置。区分该删和该留的标准只有一条，就是能不能撤销。
  • 测量本身制造新的摩擦。埋点一多，同意文案和选择页面就跟着多，于是又回到前面类型表的第二行。测量项目最好只保留能被关闭的问题那么多。

归结起来是这样。2003年那封邮件留下的不是对一家公司的评价，而是摩擦成为记录的条件的一个样本。这个样本告诉我们两件事。一是摩擦看不见的原因不是漠不关心，而是状态与结构；二是那种状态与结构是可以复原的。新账号、新设备，还有一张不会被删掉的表。需要的差不多就这些。剩下的工作是给那张表的每一行填上名字。

未能确认的部分

以下条目因为在一手材料里取不到文面，没有写进正文，或者以更窄的说法写了。理由一并列出。

  • 与法院提交本的比对 - 艾奥瓦州诉讼原告方的公开档案库在和解后受限。今天的文面经由当时的转录本与2008年报道而来，未与提交本扫描件逐词对齐，证据编号也取不到。
  • 正文全文的确定文面 - 有多个版本在流通，因此直接引用压到四处，其余只写要旨。常见摘要版有时带着原文没有的强调。
  • 目标软件的版本与分发渠道 - 文件里只有 Moviemaker 这个名字。想领取的是哪一版、从哪里领取，文面无法确定。
  • 回复与后续的内部文件 - 对那封邮件的回复，以及随后应当存在的内部指示文件，在公开材料里都找不到。
  • 卡默勒等1989年论文的样本构成 - 摘要与介绍性文献只支撑个体层面与市场实验的比较，以及市场把偏差削减约一半这个数值。被试人数与构成需打开全文。
  • 牛顿1990年论文的数值 - 120首、2.5个百分点、50个百分点这些数值出自转述该博士论文的二手文献，而非论文本身。原论文的条件与确切样本未作比对。
  • 尼尔森与兰道尔的31这个数字的依据 - 综述文献只支撑跨多个项目的典型取值这一表述，项目数量与种类无法确定。
  • Baymard 汇总的内部构成 - 50项研究的逐项清单与所涉国家、行业构成比，公开摘要页上没有。因此正文数值只作平均值使用。
  • 后续说法的验证 - 第八节的回忆是个人博客上的自述，无公司正式文件佐证。所述期间与成果范围也只在那篇文章内得到说明。
  • 三个类型的公开汇总 - 下载路径分叉、更新时机、前置条件不可见这三类，找不到衡量规模的标准汇总，表里照实写了。
