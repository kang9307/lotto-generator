OpenAI Codex Record & Replay — Turning Observed Workflows into Reusable Skills

A new paradigm for reducing repetitive-prompt fatigue: show the agent once, skip writing the script

2026-06-24 Tech & IT

Introduction: Automation That Learns by Watching

On June 18, 2026, OpenAI shipped Record & Replay for Codex. The core idea is simple: demonstrate a repetitive workflow on your Mac once, and Codex observes the steps to generate a reusable skill. Going forward, a single natural-language prompt is enough to invoke the agent and run that workflow again.

This piece does not restate the press release. Instead, it examines what Record & Replay actually does mechanically, why it matters in the context of AI coding agents, and — most critically — where it falls short. The phrase "agent that learns your workflow" is appealing, but the reality is both more concrete and more constrained than the marketing framing suggests.

First, the hard constraints: this feature is macOS-only, requires Computer Use to be enabled, and was unavailable at launch in the EU, UK, and Switzerland. Understanding these constraints clarifies the feature's scope considerably.

1. The Three-Stage Mechanism

Cross-referencing official documentation and launch coverage, the workflow breaks into three discrete stages.

1.1 Recording

From the Codex app's Plugins menu, select Record a skill. The system requests macOS accessibility permissions in addition to screen recording. Early users noted that it asks for accessibility element access — not just pixel capture — because Codex reads the UI element tree alongside the visual stream. Parsing button IDs and DOM labels rather than coordinates makes the resulting skill more resilient to minor layout changes.

After granting permissions, the user performs the actual workflow: submitting an expense report, opening a correctly templated GitHub issue, downloading a weekly report. When finished, recording stops.

1.2 Skill Generation

Codex analyzes the captured actions and window content, then auto-drafts a SKILL.md file. This file is plain markdown and contains the following sections:

  • When this skill should (and should not) be invoked
  • Required input variables (dates, filenames, amounts, etc.)
  • Step-by-step procedure
  • Verification method to confirm completion

The critical point: SKILL.md is editable. If the auto-generated draft misses intent or includes unwanted steps, you open it in any text editor and fix it. This is what separates Codex skills from coordinate-based macro recorders. The file encodes intent, not screen positions.

1.3 Replay

Once stored, the skill is invokable in two ways. Explicit invocation uses $skill-name or /skills to select it directly. Implicit invocation lets Codex read the natural-language task description and automatically route to the best-matching skill. For example, typing "submit this week's travel expenses" triggers the expense-report skill without naming it explicitly.

Skills are stored in priority-ordered directories: .agents/skills (repository-level, team-shared), $HOME/.agents/skills (user-level, personal), and /etc/codex/skills (system-level, admin-managed).

2. SKILL.md Architecture and Context Management

Record & Replay sits on top of Codex's Agent Skills architecture. The feature's job is to produce a valid SKILL.md through demonstration rather than manual authoring.

2.1 Skill Directory Layout

skill-name/
├── SKILL.md          # Required: instructions + metadata
├── scripts/          # Optional: executable code
├── references/       # Optional: documentation
├── assets/           # Optional: templates and resources
└── agents/
    └── openai.yaml   # Optional: UI configuration

A minimal SKILL.md looks like this:

---
name: expense-report
description: Use when submitting an expense report to the internal portal
---

1. Navigate to expense.company.com
2. Enter the reporting period and total amount
3. Attach the receipt files
4. Confirm the submission success message

2.2 Progressive Disclosure — Keeping Context Lean

As skill libraries grow, context bloat becomes a real concern. Codex addresses this with progressive disclosure: the initial skill listing consumes at most 2% of the model's context window (or 8,000 characters). The full SKILL.md content loads only after a specific skill is selected. If the library is very large, descriptions shorten progressively and a warning appears when skills risk being omitted. The practical implication: keep skill descriptions concise and distinctive to maintain reliable implicit routing as your skill library scales.

3. Why This Feature, Why Now

3.1 Prompt Fatigue — The Hidden Cost of Agent Automation

The biggest friction in agent-based automation is, paradoxically, writing the prompt. To hand a repetitive task to an agent, you first need to describe every step accurately. For many workflows, writing that description takes longer than doing the task manually. "Submit my expense report" is a natural request, but turning it into a reliable multi-step agent prompt requires authoring a ten-step procedure.

Record & Replay sidesteps this friction: show instead of describe. The demonstration becomes the prompt. The underlying idea is not new — macro recorders, RPA tools, and Selenium IDE have explored similar ground for years. What changes in the AI agent context is the shift from deterministic coordinate clicks to intent-based reasoning. If the button moves, the intent "find and click the submit button" can survive the change. Whether it does in practice depends on how much the UI changes, which is addressed below.

3.2 Computer Use as the Enabling Condition

The requirement for Computer Use defines the feature's character. Computer Use is the ability for AI to observe a real screen and manipulate mouse and keyboard directly. It is the automation path of last resort — for web UIs without APIs, legacy internal systems, and GUI-only tools. Record & Replay makes sense only in this context. Conversely, if a workflow is cleanly automatable via API, using Record & Replay is overkill.

4. The Determinism Problem — Where to Be Honest

The most consistently underestimated challenge in agent automation is determinism: will the same skill produce the same correct result every time? For Record & Replay, this question has three layers.

4.1 UI Layout Changes

Skills become brittle when the target application's layout changes significantly between recording and replay. Accessibility-tree parsing reduces coordinate dependence, but if the page structure is substantially redesigned, re-recording is required. Skills targeting stable internal systems with infrequent updates face less exposure here; skills against frequently updated external services carry meaningful maintenance overhead.

4.2 Input Variable Scope

Skills accept variables — dates, filenames, amounts — that are substituted at runtime. If variable format or range differs from what was seen during recording, the agent may misinterpret. Stating explicit input specifications inside SKILL.md (e.g., "date must be in YYYY-MM-DD format") is the most reliable mitigation.

4.3 Unreviewed Skill Distribution

Auto-generated SKILL.md files are the agent's best inference about observed intent. Inference can be wrong. The file is editable precisely because human review is expected before deployment. Distributing an unreviewed skill to a team means distributing unvalidated automation — a quiet source of subtle errors. Human review before sharing is not optional; it is the reliability mechanism.

5. Security and Governance for Teams

5.1 Sensitive Data in Recordings

Recording captures the entire content of visible windows. Passwords, personal data, or API keys on screen during recording can surface in the generated SKILL.md. OpenAI's documentation calls this out as a security concern. In practice: close or obscure sensitive screens before starting a recording, and read the generated SKILL.md before saving it anywhere accessible to others.

5.2 Version Control for Shared Skills

Because SKILL.md is a file, it is Git-versionable. Team-shared skills benefit from change history, code review before updates land, and rollback capability if a new version breaks. High-stakes workflows — payments, external publishing, access management — warrant a review gate before any skill update is deployed.

5.3 Dual Cost Model

Skill creation (recording and analysis) and skill execution (Computer Use, browser actions, model calls) carry different cost structures. In team environments where skills run frequently, usage monitoring and budget guardrails become necessary.

6. What to Use It For — and What Not To

6.1 Good Fits

  • High-frequency administrative tasks: expense submission, time-off requests, weekly report downloads
  • Template-driven workflows: creating issues in a specific format, entering meeting notes in a fixed system
  • API-less internal UIs: legacy internal portals, ERP click sequences
  • Preference-heavy personal workflows: multi-step UI flows faster to show than describe

6.2 Poor Fits

  • Tasks requiring complex judgment each run: creative writing, nuanced decision-making
  • Flows involving security credentials on screen: recording a full login sequence with a visible password
  • Tasks cleanly handled by API: no need for Computer Use overhead
  • Frequently redesigned external services: maintenance cost may exceed automation benefit
  • Windows/Linux environments: macOS-only at launch; cross-platform teams have partial coverage

7. Honest Reading of "Agent That Learns Your Workflow"

The most important reframe: Record & Replay does not fine-tune a model or update weights based on observed behavior. It auto-generates a text instruction file (SKILL.md) from a demonstration. The agent then follows that file during replay. This is automated instruction authoring, not machine learning in the weight-update sense.

Why does the distinction matter? "Learning" implies persistent transfer — what the agent learns this time stays for next time automatically. SKILL.md is a file. If you delete it, the skill is gone. If you do not invoke it, the behavior does not appear. The agent reproduces the workflow only in contexts where the skill file is loaded and triggered.

None of this diminishes the feature's practical value. Lowering the barrier to skill creation from "manually write a multi-step SKILL.md" to "do the task once while Codex watches" is a genuine reduction in friction. If most users cannot write reliable SKILL.md files from scratch, demonstration-based generation removes that barrier. The long-term implication is that teaching agents becomes more about showing and editing than prompt engineering.

8. Competitive Context

Record & Replay addresses a problem that other automation paradigms have approached differently. Traditional macro tools (AutoHotkey, Selenium IDE) use coordinate- or DOM-based deterministic replay — brittle on UI changes. Enterprise RPA (UiPath, Automation Anywhere) implements similar record-and-play at scale, but with heavy setup and maintenance costs. Browser AI agents (Operator, Browser Use) accept natural-language instructions but lack standardized skill-storage systems.

Record & Replay's differentiation is native integration within the Codex ecosystem. A coding agent can handle code tasks and UI automation in the same context window. "Analyze this dataset and then publish the summary to the internal dashboard" becomes a single agent loop rather than two disconnected tools. This integration value is most pronounced for teams where development work and repetitive administrative workflows coexist.

9. Conclusion — Practical Takeaways as of June 2026

What it does: On macOS, with Computer Use enabled, demonstrate a repetitive UI workflow once, get an editable SKILL.md, and call it with natural language going forward. Team sharing is possible via repository-level skill directories.

Real limits: macOS-only. Requires Computer Use. Unavailable in EU/UK/Switzerland at launch. Skill determinism depends on UI stability and input variable clarity. Auto-generated skills need human review before team distribution. Sensitive data may appear in recordings.

Three actions you can take today. First, identify repetitive UI workflows in your work that have no API alternative and involve no sensitive credentials on screen. Second, record one of them, read the generated SKILL.md carefully to verify intent accuracy, and run it a few times in a personal environment. Third, before sharing with a team, check the skill file for sensitive data, add explicit input specifications, and version-control it in a repository.

Record & Replay is an early, constrained implementation of a direction that matters: AI coding agents that can handle not just code but the administrative automation surrounding it. The feature is not finished — platform coverage is narrow, determinism is partial, governance tooling is minimal. But the direction is correct, and the friction reduction for skill creation is real.
