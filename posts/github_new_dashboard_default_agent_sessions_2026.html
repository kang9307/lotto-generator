요점: 변경 기록(2026년 10월 1일자)은 새 대시보드가 이제 모든 사용자의 기본 화면이라고 알린다. 활성 에이전트 세션·이슈·풀 리퀘스트를 한곳에서 보여 주고 목록은 섹션당 최대 12개다. 이전 화면은 「Preview」 옆 드롭다운으로 언제든 되돌릴 수 있다. GitHub Docs 의 두 문서는 같은 홈 대시보드를 아직 public preview 로 서술한다.

계기 — 기능 미리보기에서 기본 화면으로의 전환

GitHub 변경 기록(Changelog)의 2026년 10월 1일자 항목 「New dashboard experience now the default」는 기능 미리보기(feature preview)로 제공되던 새 대시보드 경험이 이제 모든 사용자의 기본 화면이라고 밝힌다. 변경 기록은 이 화면을 생산성 중심(productivity-focused) 대시보드라 부르고, 가장 중요한 작업에 집중하게 하며 다음에 필요한 것을 찾아 바로 처리하기 쉽게 만든다고 설명한다. 항목 분류는 개선(Improvement)이다.

시간 순서는 두 출처를 나란히 놓아야 보인다. 커뮤니티 공지(#208952)는 9월 28일에 올라왔고, 이미 새 대시보드를 모두를 위한 기본 경험으로 만든다고 적었다. 변경 기록은 그 사흘 뒤인 10월 1일자이며 「is now the default」라고 적었다. 변경 기록은 기본 화면이 실제로 바뀐 날짜를 따로 밝히지 않으므로, 10월 1일부터 전환되었다고 단정할 수 없다.

공지에 따르면 GitHub 는 지난해 생산성 중심의 새 대시보드를 기능 미리보기로 소개했고, 그 뒤 많은 사용자가 새 대시보드와 이전 대시보드 양쪽에 대한 피드백을 남겼다. 공지는 그 피드백에 근거해 새 대시보드를 모두의 기본으로 한다고 적는다. 공지가 꼽는 새 대시보드의 기능은 네 가지이며, 변경 기록은 같은 내용을 세 항목으로 묶어 적는다. 각 기능과 GitHub Docs 의 서술은 이어지는 절에서 정리한다. 확인하지 못한 항목은 「확인하지 못한 것」 절에 사유와 함께 모았다.

변경 기록이 명시한 새 대시보드의 주요 구성

커뮤니티 공지는 새 대시보드로 할 수 있는 일을 네 항목으로 나열한다. 변경 기록은 이 중 첫째와 둘째를 한 항목으로 합쳐 세 항목으로 적는다.

  • 한곳에 모으기: 활성 에이전트 세션(active agent sessions), 이슈(issues), 풀 리퀘스트(pull requests)를 한곳에서 본다.
  • 필터와 목록 수 제한: 필터로 각 섹션에 나올 항목을 고르며, 각 목록에는 최대 12개 항목이 표시된다.
  • 별도의 Feed 탭: 저장소와 조직의 활동 업데이트는 별도의 「Feed」 탭에서 따라잡는다. 변경 기록은 이를 피드를 생산성 중심 대시보드와 구분해 두는 것이라고 적는다.
  • 대시보드에서 작업 시작: 이슈를 Copilot 코딩 에이전트에 할당하거나 풀 리퀘스트를 Copilot Chat 에서 여는 것을 예로 든다.

공지는 이 화면을 현재 작업을 집중해서 보여 주고 다음에 무엇을 할지 정하도록 돕는 것으로 설계했다고 적는다. 12개라는 숫자는 두 출처 모두에서 「각 섹션을 필터링하고 목록당 최대 12개를 표시한다」는 한 문장으로만 나온다. 12개를 넘는 항목을 어떻게 보는지는 두 출처가 적지 않으며, GitHub Docs 가 적은 것은 에이전트 세션 목록의 View all 뿐이다(다음 절).

에이전트 세션과 이슈·PR 통합 — 작업 중심 인터페이스

변경 기록은 에이전트 세션·이슈·풀 리퀘스트를 한곳에서 본다고만 적는다. 각 목록에 무엇이 오르는지는 GitHub Docs 의 「Personal dashboard」 문서 중 「Home dashboard view」 항목이 설명한다. 다만 이 항목은 업데이트된 홈 대시보드를 public preview 이며 바뀔 수 있다고 서술하고, 보려면 먼저 feature preview 에서 「New Dashboard Experience」를 켜야 한다고 적는다. 기본 화면이 되었다는 변경 기록과 서술 시점이 다르므로, 아래 Docs 서술은 기본화 이전에 쓰인 문장일 수 있다.

  • 에이전트 세션: 실행 중이거나 지나간 Copilot cloud agent 세션의 목록이다. 「View all」을 누르면 agents 탭이 열린다.
  • 풀 리퀘스트: 본인이 작성했거나, 리뷰했거나, 멘션되었거나, 리뷰어로 요청받은 가장 최근 풀 리퀘스트의 목록이다.
  • 이슈: 본인에게 할당되었거나 본인이 관련된 가장 최근 이슈의 목록이다.
  • 필터와 12개: 변경 기록과 공지의 문구이며, Docs 의 홈 대시보드 항목에는 필터나 12개라는 숫자가 나오지 않는다.

Docs 의 같은 문서는 홈 대시보드와 별개로 「Recent activity」 섹션도 설명한다. 이 섹션은 최근 2주 안에 생긴 업데이트를 최대 4개까지 미리 보여 주며, 열린 이슈나 PR 이 오르는 조건으로 본인이 연 경우, 본인이 연 이슈·PR 에 다른 사람이 댓글을 단 경우, 다시 열린 경우, 리뷰를 요청받은 경우, 담당자로 지정된 경우, 커밋에서 참조한 경우, 본인이 댓글을 단 경우를 든다. 「Top repositories」 목록은 자동으로 만들어지고 직접 편집할 수 없으며, 커밋·이슈·PR 생성이나 댓글 같은 상호작용이 있었던 저장소가 오르고 마지막 상호작용 1년 뒤에 목록에서 빠진다. 이 둘이 새 대시보드에서 어떻게 보이는지는 Docs 가 새 대시보드와 연결해 서술하지 않는다.

이슈와 PR 을 다루는 협업 방식은 이 블로그의 기존 글 Git & GitHub 협업 마스터 4편: Pull Request와 코드 리뷰에서 다룬 바 있다.

Feed 탭의 분리 — 소셜·저장소 업데이트와 업무 영역 분리

변경 기록은 업데이트를 별도의 「Feed」 탭에서 확인하게 하여 피드를 생산성 중심 대시보드와 구분해 둔다고 적는다. 어떤 활동이 피드에 오르는지는 GitHub Docs 의 「Personal dashboard」 문서가 「Feed activity」 항목에 나열한다. 이 항목은 새 피드(new feed)도 public preview 이며 바뀔 수 있다고 적고, 「팔로우하는 누군가가 …할 때」 업데이트가 보인다고 설명한다.

  • Feed 탭의 정의(변경 기록·공지): 변경 기록은 업데이트를 Feed 탭에서 따라잡는다고 적고, 공지는 저장소와 조직의 활동을 따라잡는 곳이라고 적는다.
  • Docs 의 피드 이벤트 (1): 팔로우하는 사람이 저장소에 스타를 누를 때, 다른 사용자를 팔로우할 때, 공개 저장소를 만들 때.
  • Docs 의 피드 이벤트 (2): 팔로우하는 사람이 내가 지켜보는(watch) 저장소에서 help wanted 나 good first issue 라벨이 붙은 이슈·PR 을 열 때, 내가 지켜보는 저장소에 커밋을 푸시할 때.
  • Docs 의 피드 이벤트 (3): 팔로우하는 사람이 공개 저장소를 포크할 때, 새 릴리스를 게시할 때. 「Quickstart」 문서는 피드 오른쪽 위의 Filter 드롭다운으로 볼 이벤트 종류를 고를 수 있다고 적는다.

변경 기록은 Feed 탭에 어떤 이벤트가 오르는지 적지 않으므로, 위 Docs 목록이 Feed 탭의 내용과 같은지는 두 문서가 명시하지 않는다. 확인된 것은 변경 기록이 피드를 별도 탭으로 둔다는 것과, Docs 가 피드 이벤트를 위 종류로 정의한다는 것이다.

대시보드 직결 액션 — Copilot 코딩 에이전트 및 Copilot Chat 연계

변경 기록은 대시보드에서 바로 작업을 시작하는 예로 두 가지를 든다. 공지도 같은 두 예를 적는다. GitHub Docs 는 홈 대시보드의 Copilot 관련 요소를 별도로 설명한다.

  • 이슈를 Copilot 코딩 에이전트에 할당: 변경 기록은 「assigning an issue to Copilot coding agent」를 예로 든다.
  • Copilot Chat 에서 풀 리퀘스트 열기: 변경 기록은 「opening a pull request in Copilot Chat」을 예로 든다.
  • Docs 의 Copilot 프롬프트 상자: 홈 대시보드에는 GitHub Copilot 에 프롬프트를 보내고, Copilot cloud agent 에 작업을 할당하고, Copilot 으로 이슈를 만들고, GitHub Spark 로 빌드를 시작하는 프롬프트 상자가 있다고 적는다.
  • Docs 퀵스타트의 에이전트 추적: 대시보드에서 Copilot 에 직접 프롬프트를 보내고, 직접 시작한 최신 에이전트 세션을 추적하고, 에이전트 로그로 진행 상황을 확인하고, 결과로 나온 풀 리퀘스트와 작업을 관리할 수 있다고 적는다.

변경 기록은 「Copilot coding agent」, Docs 는 「Copilot cloud agent」라고 적어 표기가 다르다. 브라우저 기반 개발 환경의 권한 문제는 github.dev 1-클릭 토큰 탈취 취약점 분석에서, 에이전트에 넘기는 작업 명세는 OpenSpec AI 코딩 에이전트 명세에서 각각 다뤘다.

이전 대시보드로 되돌리는 방법 — Preview 드롭다운

변경 기록은 이전 경험을 유지하려면 「Preview」 옆의 드롭다운을 눌러 언제든 되돌아갈 수 있다고 적는다. 커뮤니티 공지도 이전 대시보드를 선호하면 Preview 옆 드롭다운으로 언제든 되돌아갈 수 있다고 적는다.

  • 전환 경로: 「Preview」 표시 옆의 드롭다운을 누른다.
  • 전환 시기: 변경 기록과 공지 모두 「at any time」, 즉 언제든이라고 적는다.
  • 의견 창구: 변경 기록은 질문과 의견을 Community discussion 에 댓글로 남기라고 안내한다. 공지는 생산성에 도움이 되는 것, 방해가 되는 것, 가장 개선받고 싶은 것을 댓글로 요청한다.
  • 후속 개선: 공지는 지난 몇 주 동안 의견을 많이 받았고, 가장 일관되게 들은 주제를 바탕으로 후속 개선 방향 여러 가지를 탐색 중이라고 적는다.

공지는 그 개선 내용을 향후 수 주 안에(in the next few weeks) 공유하겠다고 적고, 그동안(in the meantime)에는 이전 대시보드를 선호하면 드롭다운으로 전환할 수 있다고 안내한다.

표에서 보듯 변경 기록은 구성 네 가지와 12개 제한, 되돌리는 방법을 짧게 적고, Docs 는 각 목록에 오르는 항목의 기준과 피드 이벤트를 적는다. 다만 Docs 는 홈 대시보드를 아직 public preview 로 서술하고 있어, 기본화 이후에 갱신된 문서인지는 두 문서만으로 가릴 수 없다. 정렬 기준은 Docs 가 PR·이슈를 「가장 최근」 항목이라고 적은 것이 전부이고, 조직 단위의 제어 정책은 어느 문서에도 적혀 있지 않다.

기존 협업 흐름과의 관계와 읽기 전용 점검

대시보드가 기본 화면이 된 뒤 각 항목을 어떤 출처로 대조할 수 있는지를 표로 정리하고, 설정을 바꾸지 않는 점검 절차를 덧붙인다.

작업 영역변경 기록상 제공 기능 및 동작대조할 출처
홈 대시보드 메인에이전트 세션, 이슈, PR 을 한곳에 목록당 최대 12개씩 표시Docs 「Home dashboard view」: Copilot 프롬프트 상자·Agent sessions·Pull requests·Issues 네 요소
목록 필터링각 섹션에 표시될 항목을 필터로 선택필터 조건의 종류는 출처에 없음
Feed 탭저장소 및 조직의 활동 업데이트를 따라잡는 별도 탭Docs 「Feed activity」의 이벤트 목록과 퀵스타트의 Filter 드롭다운
Copilot 작업 실행이슈의 코딩 에이전트 할당, PR 의 Copilot Chat 열기Docs 퀵스타트 「Working with GitHub Copilot from your dashboard」
이전 환경 복원이전 대시보드 경험으로 되돌리기변경 기록과 공지의 「Preview」 옆 드롭다운 문구

점검은 아래 순서로 설정을 건드리지 않고 할 수 있다.

  • 대시보드에서 활성 에이전트 세션, 이슈, 풀 리퀘스트 섹션이 보이는지 확인한다.
  • 자신에게 할당된 이슈나 리뷰를 요청받은 PR 중 목록당 12개 제한으로 목록에 보이지 않는 항목이 있는지 확인한다.
  • Feed 탭을 열어 팔로우하는 사람과 지켜보는 저장소의 활동이 Docs 가 나열한 종류대로 나오는지 확인한다.
  • 이전 화면이 필요하면 「Preview」 옆 드롭다운으로 전환한다.
  • 불편한 점이나 개선 제안은 Community discussion(#208952)에 댓글로 남긴다.

확인하지 못한 것

  • GitHub Docs 두 문서가 기본화 이후에 갱신되었는지. 두 문서는 열려 있으며 홈 대시보드를 public preview 로, 활성화를 feature preview 의 「New Dashboard Experience」로 서술한다. 변경 기록이 기본 화면이라고 적은 시점과 서술이 다르고, Docs 에는 12개 제한·Feed 탭 분리·이전 화면 복귀 서술이 없다.
  • 조직(Organization)이나 엔터프라이즈(Enterprise) 관리자가 구성원의 대시보드 기본값을 이전 화면으로 고정할 수 있는 정책 제어의 존재 여부. 어느 문서에도 적혀 있지 않다.
  • 목록당 12개라는 표시 개수를 사용자 설정에서 바꿀 수 있는지 여부와, 12개를 넘는 이슈·PR 을 보는 방법. Docs 에는 에이전트 세션의 View all 만 있다.
  • 「Preview」 옆 드롭다운으로 이전 화면에 돌아가는 기능이 언제까지 유지되는지. 종료 일정은 적혀 있지 않다.
  • 외부 개발자 커뮤니티의 비공식 반응과 만족도 통계. 이 글은 변경 기록·공지·Docs 의 문구만 확인했고, 공식 문서가 아닌 반응은 확인 대상에서 뺐다.
