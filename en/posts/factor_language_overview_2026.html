The Trigger: A Code-Forward Overview of Factor

A post titled "Factor Overview" appeared on the Re: Factor blog on October 4, 2026, and GeekNews carried it on October 7. The blog's tagline is "Factor: the language, the theory, and the practice", and the copyright notice at the bottom of the page names John Benediktsson. The post first recommends the guided tour in the official documentation, and then gives its own motivation: a wish for more code-forward examples of everyday syntax, control flow, combinators and some of the main libraries. The reader it assumes is someone who has programmed before but has not necessarily used a stack-based language.

What Factor is gets a short answer on the official site. factorcode.org describes Factor as a concatenative, stack-based programming language with high-level features including dynamic types, extensible syntax, macros and garbage collection. The implementation is fully compiled for performance while still supporting interactive development, and the source code is available under a BSD license. The version listed as the stable release is 0.101. The first article of the guided tour, "Concatenative Languages", introduces Factor in its opening sentence as a concatenative programming language in the spirit of Forth.

For a quick start, the overview advises working through the stack, word definitions, quotations, control flow and sequences first. The later sections on objects, metaprogramming and libraries are ones a reader can return to as needed. The sections below follow the same order. The shortest program is the single line "Hello, world!" print, and the post shows four ways to run it.

  • From the listener. Type it at the IN: scratchpad prompt as it is. The listener is Factor's interactive REPL.
  • From the command line. Pass the code as a string after ./factor -e=.
  • As a script. Create a file named hello.factor and run it with ./factor hello.factor. Inside the file, USING: imports vocabularies, IN: selects the vocabulary for definitions, and MAIN: sets an entry point.
  • As a vocabulary. If it is available in the vocabulary roots search path, ./factor -run=hello runs that vocabulary's main word.

The terminal listener is started with ./factor -run=listener, and the development environment also has a graphical listener. Comments in the examples begin with ! and are part of valid Factor source, so the code can be pasted directly. The place interactive execution holds in a language is discussed in Adding Interactive Execution to a Compiled Language, and another tradition of treating code as a value is covered in Why Lisp Still Matters.

Values and the Stack: Literals Push, Words Consume

The first rule in the overview takes three sentences. Literals push values onto the data stack. Words consume inputs from the top of that stack and push their outputs. Code runs from left to right.

USING: math prettyprint ;
                    
                    2 3 + .                         ! 5
                    10 4 - .                        ! 6
                    2 3 + 4 * .                     ! 20

. consumes and prints an object, and print consumes and prints a string. The comments beside the examples show the output. Because printing removes the value, the examples leave the stack empty unless stated otherwise. There are no parentheses around function arguments: the arguments are put on the stack, and then the word is invoked. Following the third line token by token, the stack moves as shown below. The top of the stack is on the right.

CodeStack afterwards
22
32 3
+5
45 4
*20
.(empty)

Spaces matter. 2 3 + is three tokens, while 2+3 is a single token and would therefore need to be the name of a word. This is why number>string, empty? and set-at are ordinary word names. The punctuation characters are part of the name, not separate operators. The conventions article in the official documentation lays out the shapes that names take in a table, noting that these conventions are not hard and fast but are usually a good first step in understanding a word's behavior.

General formMeaningExample in the documentation

foo!A variant of foo which mutates one of its argumentsappend!

The range of literals is broad as well. The examples in the overview include the hexadecimal 0xff, the binary 0b1010, the exact rational 3/4, the complex number C{ 2 3 }, the array { 1 2 3 }, the growable vector V{ 1 2 3 }, the byte array B{ 0 127 255 }, the hashtable H{ } and the quotation [ 1 + ]. { ... } is an array, while [ ... ] is executable code held as a value. Both contain objects without executing them. Spaces also separate the literal openers, their contents and the closing delimiters.

Word Definitions and Stack Effects: What ( inputs -- outputs ) Says

USING: kernel math prettyprint ;
                    IN: scratchpad
                    
                    : square ( n -- n-squared ) dup * ;
                    : neighbors ( n -- below above )
                        dup 1 - swap 1 + ;
                    
                    5 square .                      ! 25
                    5 neighbors . .                 ! Prints 6, then 4
                    
                    CONSTANT: answer 42
                    answer .                        ! 42

: begins a definition and ; ends it. The ( inputs -- outputs ) after the name is the stack effect, and it documents how many values the word consumes and how many it produces. neighbors takes one value and leaves two. The comment says 6 is printed first and then 4 because repeated calls to . print the topmost result first. Gathered together, what the overview and the official documentation say about stack effects is the following.

  • Direction. Inputs and outputs run from left to right, with the topmost value last. swap ( x y -- y x ) therefore changes a stack ending in x y into one ending in y x, and values below those inputs are untouched.
  • Names. The names in an effect describe the values. They do not bind variables or specify types. The documentation lists conventions for them: ? is a boolean, m and n are integers, seq is a sequence, quot is a quotation and obj is an object.
  • Checking. The overview says the compiler checks stack effects, including compatible effects for branches. According to the official documentation, the optimizing compiler checks the declarations of words before they can be run, and words that do not pass the stack checker are rejected and cannot be run. If a word's stack effect cannot be inferred, a compile error is reported.
  • How the documentation characterizes it. The official documentation says this essentially defines a very simple and permissive type system that nevertheless catches some invalid programs and enables compiler optimizations.
  • Returning. A word can return several values simply by leaving them on the stack. There is no explicit return: execution finishes at the end of the word.
  • Other definitions. CONSTANT: defines a constant, and ALIAS: new-name existing-word defines another name for a word.

Rearranging the order of values on the stack is called stack shuffling. The six shuffle words the overview lists together with their stack effects are these.

WordStack effectWhat it does
dup( x -- x x )Duplicates the top item
drop( x -- )Discards the top item
swap( x y -- y x )Exchanges the top two items
over( x y -- x y x )Copies the second item to the top
nip( x y -- y )Discards the second item
rot( x y z -- y z x )Brings the third item to the top

The post adds that most Factor code uses short definitions and combinators to keep explicit shuffling to a minimum. The guided tour points in the same direction. The farther a value is down the stack, the harder it becomes to refer to it, so functions are encouraged to stay small and only refer to the top two or three elements on the stack.

Quotations and Booleans: Code Is a Value and Only f Is False

Square brackets produce a quotation. In the overview's examples, 5 [ 1 + ] call . prints 6 and { 1 2 3 } [ 2 * ] map . prints { 2 4 6 }. Quotations can be passed to words, returned from words and stored in collections. Words that take quotations are called combinators. The terms that have come up so far are defined in the glossary of the official documentation as follows.

TermDefinition in the official glossary
wordThe basic unit of code, analogous to a function or procedure in other programming languages
stack effectA pictorial representation of a word's inputs and outputs, for example + ( x y -- z )
quotationAn anonymous function; an instance of the quotation class
combinatorA word taking a quotation or another word as input; a higher-order function
vocabularyA named set of words
generic wordA word whose behavior depends on the class of one of its inputs

Conditionals sit inside the same framework. In boolean tests, only f is false. Zero, an empty string and an empty array are all true.

USING: kernel math prettyprint ;
                    
                    t f and .                        ! f
                    t f or .                         ! t
                    f not .                          ! t
                    
                    3 2 > [ "yes" ] [ "no" ] if .    ! "yes"
                    0 [ "truthy" ] [ "false" ] if .  ! "truthy"
                    
                    t [ "runs" . ] when              ! "runs"
                    f [ "runs too" . ] unless        ! "runs too"

if consumes a condition and two quotations; it calls the first quotation for a true condition and the second for f. when and unless take one quotation. In the post's words, these are words that operate on code values, just as + operates on numbers. That the second if line produces "truthy" is a direct consequence of the f rule. The official documentation likewise states that any object that is not f has a true value and that t is the canonical true value.

  • Several alternatives. cond tries predicate quotations in order. case compares an input with each key; a matching branch consumes the key automatically, while the default branch receives the unmatched input.
  • and and or. These combine values that have already been computed. The effects given in the documentation are and ( obj1 obj2 -- obj2/f ) and or ( obj1 obj2 -- obj1/obj2 ).
  • Short-circuit evaluation. For this, predicate quotations are passed to 1&& and 1||. Each predicate receives the same input; 1&& stops at the first false result and 1|| stops at the first true result. The leading number is the number of inputs passed to each predicate.
  • Telling f apart from absence. The documentation notes that many words which search collections confuse the case of no element being present with an element being found equal to f, and points to comparing at with at*. at* returns a presence flag as well as a value.

Combinators Take the Place of Shuffling and Control Flow

The official documentation names the combinator as a central concept in Factor, defining it as a word taking code as input. The first ones to appear in the overview are dip and keep, which set a value aside for a moment.

USING: kernel math prettyprint ;
                    
                    10 20 [ 2 * ] dip + .           ! 40: double 10, then restore 20 and add
                    5 [ 1 + ] keep . .              ! Prints 5, then 6

The stack effect the post gives for both words is the same: ( ..a x quot -- ..b x ). The overall shapes look alike, but dip hides x from the quotation and keep passes it in. In the first line, [ 2 * ] doubles 10 while 20 is hidden, and after 20 is restored + produces 40. 2dip hides two values and 2keep preserves two inputs. Next comes the bi family, which distributes inputs across several quotations.

USING: kernel math prettyprint ;
                    
                    ! Apply two quotations to the same input.
                    5 [ 1 + ] [ 2 * ] bi . .        ! Prints 10, then 6
                    
                    ! Apply one quotation to each of two inputs.
                    3 4 [ 2 * ] bi@ . .             ! Prints 8, then 6
                    
                    ! Apply separate quotations to separate inputs.
                    3 4 [ 1 + ] [ 2 * ] bi* . .     ! Prints 8, then 4
CombinatorWhat it does, as the overview describes it
dipTemporarily hides a value while a quotation works on the stack below it
keepGives a quotation a value and also preserves that value
biApplies two quotations to the same input
bi@Applies one quotation to each of two inputs
bi*Applies separate quotations to separate inputs
2biCalculates two results from the same inputs, as in [ + ] [ * ] 2bi
curryBinds a value to the beginning of a quotation. 10 [ + ] curry behaves like [ 10 + ]
composeJoins two quotations so that one runs after the other
each, mapeach is for side effects, and map collects quotation results
reduceThreads an accumulator through the sequence. { 1 2 3 4 } 0 [ + ] reduce is 10

tri, tri@ and tri* extend the same patterns to three quotations or three inputs, and cleave, napply and spread are the generalizations of those patterns. The fry vocabulary provides quotation templates. In '[ _ + ], _ inserts a value and @ inserts a call to a supplied quotation. The placeholders consume their values when the template is constructed, not when the resulting quotation is called.

Defining a combinator is equally ordinary. It is a word with quotation inputs; those inputs are given their own stack effects and the word is declared inline so that the compiler can infer the effects at its call sites. The post's example twice has the effect ( ... quot: ( ... -- ... ) -- ... ) and the body dup dip call. The ... represents the values carried through the combinator, and 3 [ 2 * ] twice . prints 12.

Loops, Recursion and Local Variables

USING: kernel math prettyprint sequences ;
                    
                    3 [ "hello" . ] times           ! Print three times
                    { "Ada" "Grace" } [ . ] each    ! Visit each element
                    5 <iota> [ . ] each             ! Print 0 through 4
                    
                    0 [ dup 3 < ] [ dup . 1 + ] while drop
                    ! Print 0, 1, 2; keep the counter on the stack

while calls its predicate before each iteration. The predicate leaves a condition, and the body updates the loop's values. until reverses the condition. The post adds that each, map or reduce often expresses the loop directly. All four lines above are calls to words that take quotations, and the post refers to while as a looping combinator.

  • Recursion. It uses an ordinary call to the word being defined. The post's factorial places two quotations and if after dup 1 <=, and 5 factorial . prints 120.
  • Order of definitions. Definitions are read in order, so helper words are defined before the words that use them. DEFER: declares a word before its implementation, which allows mutual recursion.
  • Tail calls. The post states that Factor guarantees tail-call optimization, so a final call can continue without growing the call stack.
  • Local variables. When names make an algorithm easier to read, locals is imported and a word is defined with ::. Its inputs become lexical variables. :> binds a computed value, and [| n | ... ] names quotation inputs and can capture enclosing variables.
  • Mutable locals. These have an exclamation point in their declaration and an associated setter. The post's example declares one with 0 :> total! and changes its value with total!. [let ... ] establishes a lexical scope, including in the listener.

Data Structures and Objects: Sequences, Hashtables, Tuples, Generic Words

Arrays, vectors, strings and several other types share the sequence protocol, and most sequence words work across these types. Indexing is zero-based, so 1 { 10 20 30 } nth is 20. push mutates a growable sequence and consumes both the new element and the sequence. Associative collections use the assocs protocol, and set-at takes a value, a key and an assoc, in that order. Sets also have a protocol, so members, in?, union, intersect and diff work on ordinary sequences. For repeated membership checks, the post recommends a hash set, HS{ }, rather than scanning a sequence. The counterpart of a record is the tuple.

USING: accessors kernel prettyprint ;
                    IN: scratchpad
                    
                    TUPLE: person name age ;
                    C: <person> person
                    
                    "Ada" 36 <person>
                    dup name>> .                    ! "Ada"
                    37 >>age
                    age>> .                         ! 37

TUPLE: defines a class with named slots. C: defines a constructor using boa, and boa constructs a tuple from slot values in declaration order. name>> reads a slot, while >>age writes a slot and returns the tuple, which allows chained updates. Names such as <person> conventionally denote constructors, and the angle brackets are part of the word's name. In the order the post presents them, what is built on top of tuples is the following.

  • Slot declarations. A slot can declare a class, an initial value or the read-only attribute. { value integer initial: 0 } is one example. change-value applies a quotation to the current slot value, stores the result and returns the tuple.
  • Generic words. They are declared with GENERIC:, and methods are defined with M:. A method is chosen based on the class of the topmost input. This is how protocols such as sequences and assocs provide common operations for many concrete types.
  • Inheritance. As in TUPLE: employee < person role ;, a subclass inherits its parent's slots and can add its own. An overriding method can reuse the next less-specific method with call-next-method.
  • Predicate classes and unions. PREDICATE: defines a narrower class. UNION: accepts instances of any listed class, and INTERSECTION: requires membership in all listed classes.
  • Mixins. These are open groups of classes. INSTANCE: adds a member, including after the mixin was defined.
  • Singletons and enumerations. SINGLETONS: defines classes that each have one stateless instance, and ENUMERATION: defines named numeric values.
  • Structs. STRUCT: defines a record backed by a C memory layout, and every field declares a C type. PACKED-STRUCT: removes padding between fields and at the end. In the post's example, the heap-size of a packet-header with a uint8_t field and a uint32_t field is 5. The post sums it up as: use tuples for ordinary Factor records, and structs when C-compatible memory or an explicitly specified binary layout is needed.

Tools and Libraries: The Listener, Vocabularies, Error Handling, Calling C

The listener runs in a live image containing loaded definitions and objects. A word can be redefined and tried again in the same session. Code saved in a vocabulary is loaded once with USE:; after its source is edited, "examples.greeting" reload reloads that vocabulary and refresh-all reloads the changed files in loaded vocabularies.

A vocabulary is a namespace and a unit of source organization. A vocabulary named examples.greeting conventionally lives in examples/greeting/greeting.factor under a vocabulary root. <PRIVATE ... PRIVATE> places helper definitions in the vocabulary's private namespace. Source files need explicit imports, and importing a parent does not automatically import its children. For ambiguous names, either a vocabulary prefix is used, as in math:+, or a word is selected with FROM:. The remaining areas for which the overview gives examples are as follows.

  • Errors. ERROR: defines an error class and a word that throws an instance of it. recover calls a handler with the thrown object, and finally runs cleanup on either normal completion or an error.
  • Resource disposal. Ordinary objects are garbage collected, but resources such as open streams also need deterministic disposal. with-disposal disposes of a resource when the quotation finishes or throws. Inside with-destructors, &dispose disposes when the scope finishes, on success or error, and |dispose disposes when the scope exits with an error.
  • Dynamic variables. When a value is bound to a symbol created by SYMBOL: using with-variable, words called inside the quotation see the binding too, and the previous binding is restored on exit.
  • Metaprogramming. Words are objects too. MACRO: computes quotations that the compiler expands at call sites, and parsing words execute while source is being read and so extend the syntax. :, TUPLE: and the literal openers are examples of parsing words.
  • Memoization. MEMO: defines a word whose results are cached by its inputs. The post cautions that cached mutable results are shared objects.
  • Files and output. There is printf from formatting, set-file-contents and file-contents, and with-file-reader and with-file-writer, which close the stream after the quotation finishes.
  • JSON, regular expressions and HTTP. json> and >json convert between JSON text and Factor objects, regular expressions use their own literal syntax such as R/ [0-9]+/, and http-get returns both a response object and the downloaded content.
  • Threads. Factor threads are cooperatively scheduled. yield lets another runnable thread execute, and blocking I/O integrates with the scheduler.
  • Testing and exploring. tools.test expresses expected stack results as an array, as in { 5 } [ 2 3 + ] unit-test. Tests conventionally live alongside the source in a *-tests.factor file. help, see and time open documentation, show a definition and time a quotation.

Calling C takes two lines of declaration. After LIBRARY: libc, writing FUNCTION: size_t strlen ( c-string str ) makes strlen a Factor word, and in the post's example "hello" strlen . prints 5. The c-string argument converts a Factor string for the C call. The post states that the FFI also supports structures, pointers, callbacks and arrays, and that, unlike managed objects, foreign allocations can require explicit lifetime management.

Where Factor Differs From Habits Formed in Other Languages

Collected in one place, the differences the overview points out along the way look like this. The post does not name any particular language; it describes them only as differences from common habits.

AspectIn Factor
Passing argumentsThere are no parentheses. The arguments are put on the stack, then the word is invoked
TokensThey are separated by spaces. 2+3 is a single token
False valuesOnly f. Zero, an empty string and an empty array are true
CharactersThere is no separate character type. CHAR: A is the integer code point 65
Integer division7 2 / is the exact rational 3+1/2. Integer division is /i and the remainder is mod
Size of integersThey grow beyond machine size automatically
Unicode escapes\u is followed by exactly six hexadecimal digits, which differs from languages that use four. There is also a braced form
String lengthIt is the number of code points, not the number of visible glyphs
ReturningThere is no return. Whatever is left on the stack is the result, and there can be several values
Conditionals and loopsThey are not syntax but words that take quotations

The last sentence of the post is advice on the order in which to read code: start with small words, follow their stack effects, and use combinators to make the flow of values clear. As the next stop for more detail it names the Factor handbook, for a project walkthrough the first-program tutorial, and for the libraries as a whole the vocabulary index.

What Could Not Be Verified

  • Attribution of authorship. The overview carries no byline at the top. The name John Benediktsson comes from the copyright notice (2008-2026) at the bottom of the page. His role within the Factor project is not stated in the sources used here.
  • Running the examples. The code blocks and the output values in the comments are exactly as written in the overview. They were not checked by running the code.
  • Reference version. The overview does not say which version of Factor it was written against. The stable release on the official site is 0.101, while the footer of the online documentation says it was generated from a 0.102 build dated October 2, 2026. Whether the examples behave the same in both versions is not in the sources.
  • Performance. The official site says the implementation is fully compiled for performance, and the guided tour speaks of very high performance for a dynamically typed language. Neither document gives numbers or a point of comparison.
  • Relationship to other languages. The only mention of Forth is a single sentence in the guided tour. The designers and history of Factor, and any detailed comparison with other stack languages, are not among the sources used here.
  • Scope of the stack checker. The classes of errors the checker catches and the ways to bypass checking are described in sub-articles of the official documentation, but those articles are not among the sources used here.
