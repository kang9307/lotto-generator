Shortcat - マウスなしでキーボードだけでmacOSを完全操作 2026

UI要素を索引するコマンドパレットで手をキーボードに留める

2026年6月9日 IT・技術

はじめに：マウスへの短い往復が積み重なると

コードに集中している最中、サイドバーのファイルを1つクリックするために右手をキーボードから離してトラックパッドへ移し、クリックして、またキーボードへ戻る。1秒にも満たない動作です。しかしこの短い往復を1日に数百回、1か月に数千回繰り返すと話は変わります。手首に微細な疲労が積もり、作業の流れはそのたびに細かく途切れます。Shortcatはまさにこの「マウスへの短い往復」をなくそうとするmacOSツールです。2026年6月8日のGeekNews（news.hada.io）で1位を獲得し、再び注目を集めました。

中心となる発想はシンプルでありながら強力です。画面上のすべてのUI要素——ボタン、リンク、メニュー項目、テキストフィールド、ウィンドウ——をアクセシビリティ APIで索引し、コマンドパレットで名前やヒントラベルから検索してキーボードだけで実行するのです。マウスカーソルを特定の座標へ引きずる代わりに、目的の要素の名前を入力します。本稿ではShortcatが解く課題、アクセシビリティ APIに基づく仕組み、キーボード優先ワークフローの生産性、Vimium・Homerow・Vimac・Keyboard Maestroといった類似ツールの比較、設定と活用のコツ、そして率直な限界までを落ち着いて整理します。

1. Shortcatが解く課題——マウスの往復、RSI、アクセシビリティ

Shortcatを理解するには、まずそれが「何のための解決策か」を見る必要があります。表面的には生産性ツールですが、その下には3つの異なる課題が横たわっています。

  • マウス往復の非効率：キーボードで入力し、手をマウスへ移し、目標を狙ってクリックし、またキーボードへ戻る「ホーミング」動作は、測定可能な時間の損失です。個別には微々たるものでも、積み重なれば相当な量になります。
  • RSI（反復性緊張障害）：マウスを絶えず使う作業は手首と腕に負担をかけます。RSI予防の資料は一様に、ショートカット・マクロ・ホットキーといったキーボード基盤のツールを、マウス使用を減らす中心的手段として勧めています。
  • アクセシビリティ：Shortcatが依存する技術そのものが、視覚障害のあるユーザーのためのスクリーンリーダー基盤の上に立っています。キーボード優先の操作は本質的に、より包摂的なインターフェースへ向かう方向と接しています。

つまりShortcatは単に「速くなるツール」ではなく、入力効率・健康・アクセシビリティという3つの軸を同時に触れるツールです。この点が単純なショートカット拡張との決定的な違いです。

2. Shortcatとは何か——一文の定義

公式の紹介によれば、Shortcatは「Macのための汎用コマンドパレット（universal command palette）」です。ボタンをクリックし、テキストフィールドにフォーカスを与え、メニューコマンドを実行し、ウィンドウを切り替える——それらを、マウスなしで、キーボードだけで処理します。FinderでもSpotifyでも、ほぼすべてのアプリのUI要素にキーボードでアクセスできるようにするバックグラウンドユーティリティです。

ここで「コマンドパレット」という表現が重要です。VS Codeなどのエディタを使ったことがある人には馴染みがあるでしょう。ショートカットで検索窓を出し、コマンド名を入力して実行するあのパターンをOS全体へ拡張したのがShortcatの本質です。特定アプリのコマンドに限らず、画面に見えるすべてのクリック可能な要素が検索対象になります。

マウスが「どこを指すか」を問うなら、Shortcatは「何を実行するか」を問う。座標ではなく名前でインターフェースを扱う転換である。

3. 仕組み——アクセシビリティ APIでUIを読む

Shortcatの魔法はmacOSのアクセシビリティ（Accessibility）APIにあります。このAPIはもともと、VoiceOverのようなスクリーンリーダーが画面の内容を視覚障害のあるユーザーに読み上げるために作られました。OSはこのAPIを通じて、各アプリのボタン・ラベル・メニュー・ウィンドウといったUI要素を構造化されたツリーとして公開します。

Shortcatはまさにこのツリーを読みます。動作の流れを段階に分けると次のようになります。

1. ホットキー       Shortcatパレットを呼び出す
   │
   ▼
2. 要素の索引       APIで現在の画面のクリック可能な要素を収集
   │
   ▼
3. ヒント/検索      要素にヒントラベルを重ねる＋名前のあいまい検索
   │
   ▼
4. キーボード実行   ラベル入力または名前検索の後Enter → クリック/メニュー実行

要点は、Shortcatが画面を「ピクセル」として見ていないことです。画像認識やOCRではなく、アプリがアクセシビリティ APIに自ら申告した構造的情報を読みます。だから正確で速く、同時に「アプリがAPIに情報をどれだけ公開するか」に精度が左右されるという限界もここから生まれます。よく作られたネイティブアプリほどShortcatはうまく動きます。

4. ヒントモードと検索モード

Shortcatが要素を扱う方法は大きく2つです。状況に応じて使い分けます。

4.1 ヒント（ラベル）モード

パレットを出すと、画面のクリック可能な要素の上に短い文字ラベルが重ねて表示されます。目的の要素のラベル文字を入力すると、その要素がすぐに実行されます。画面に要素が少ないとき、または名前を知らないアイコンボタンを素早く押すときに便利です。Vimiumの「f」ヒントと同じ発想です。

4.2 検索（タイピング）モード

要素の名前やラベルテキストを直接入力すると、あいまい検索で候補が絞られます。たとえば「保存」ボタンを探したいなら、その一部だけ入力してもマッチします。名前を知っているボタン・リンクを押すとき、特に同種の要素が画面に大量にあるときに強力です。Shortcatはヒントとタイピングの両方に対応する点で、ヒント中心の一部の競合ツールと差別化されます。

5. メニューのあいまい検索——隠れた強み

Shortcatの真価はメニューバーのコマンドを扱うときに現れます。macOSのアプリはメニューバーに数十・数百のコマンドを抱えていますが、ショートカットが割り当てられているのは一部だけで、残りはマウスでメニューを掘らないと見つかりません。

Shortcatは現在のアプリのメニュー項目を電光石火のあいまい検索で公開します。より賢いのは同義語（synonym）に対応する点です。紹介によれば「Delete item」というコマンドを「delete」だけでなく「remove」「clear」「destroy」といった語でも見つけられます。コマンドの正確な名前を覚えていなくても、意味さえ分かれば到達できるということです。このメニュー検索だけでも、多くのユーザーがShortcatを常時起動しておく理由を見いだします。

6. キーボード優先ワークフローの生産性

キーボードだけでコンピュータを操ることは本当により生産的なのでしょうか。答えは「場合により、そして時間が経つほど」です。

RSI・生産性関連の資料は核心を一貫して語ります。ショートカットやホットキー、マクロといったキーボード基盤の流れはマウス/トラックパッドの負担を減らし、CLIのようなキーボード中心の作業は1〜3年の習熟を経るとGUI・マウス基盤の流れの生産性に到達するか、それを超えるということです。つまり即効薬ではなく、複利で積み上がる投資です。

キーボード優先ワークフローの利点をまとめると次のとおりです。

  • 文脈切替の減少：手がホームポジションを離れないため、入力の流れが途切れません。
  • 照準負担の除去：小さなボタンをマウスで精密に狙う認知・筋肉の負担が消えます。
  • 一貫したメンタルモデル：「名前で実行する」という1つのパターンがほぼすべてのアプリに同じように適用されます。
  • RSIの緩和：マウス依存を減らし、手首・腕の累積負担を分散します。

もちろんこれらの利点はすべて、学習コストという代償を先に払って初めて得られます。「ツールが流れを変える」似た事例はターミナル性能と開発者の生産性でも扱いました。

7. 類似ツール比較——Vimium、Homerow、Vimac、Keyboard Maestro

Shortcatはキーボード優先操作という広い生態系の一部です。よく比較されるツールを整理すると選択が楽になります。

ツール 範囲 方式 費用/状態
Shortcat macOS全体 ヒント＋タイピング検索、メニューあいまい 無料 / 近年保守は活発でない
Homerow macOS全体 ヒントラベル、キーボードスクロール 有料 / Vimacの後継、活発
Vimac macOS全体 ヒント、HJKLスクロールモード 無料 / 開発終了（Homerowへ移行）
Vimium ブラウザ限定 ヒント、Vimキー操作 無料 / ブラウザ拡張
Keyboard Maestro macOS全体 マクロ/自動化中心 有料 / 性格の異なるツール

解釈を加えると、Vimiumはブラウザ内でのみ動作するため、Shortcatと直接の代替関係にはありません。Vimacは事実上終了し、開発は有料アプリHomerowへ移りました。HomerowはVimacのより高速で洗練された後継で、Shortcatにないキーボードスクロールなどの機能を備えています。Keyboard Maestroは毛色が異なり、UI要素の索引よりマクロ・自動化ワークフローを作るツールなので、Shortcatと補完的に併用されることが多いです。

各まとめ記事に共通する推奨は明確です。初めて使うならShortcatです。無料で、対応アプリも多く、入門の敷居が最も低いからです。その後、キーボードスクロールなどが切実に必要になればHomerowへ移る経路が自然です。

8. インストールと権限設定

Shortcatを使うには2つが必要です。適切なmacOSバージョンとアクセシビリティ権限です。

  • 要件：macOS 13以降が必要で、最新のmacOSで動作が確認されています。公式サイトから無料でダウンロードでき、2025年7月時点でバージョン0.12.2が公開されています。
  • アクセシビリティ権限：ShortcatがUI要素を読み取り操作するには、システム設定＞プライバシーとセキュリティ＞アクセシビリティでShortcatを許可する必要があります。この権限なしでは画面要素を索引できません。

アクセシビリティは強力な権限なので、信頼できる出所（公式サイト）から入手したものか確認してから付与する習慣が大切です。macOSの権限モデル全般は2026年に開発者が実際に使うツールで触れた「ツール衛生」とも通じる文脈です。

9. 活用のコツ——Shortcatを手に馴染ませる

ツールを入れただけで生産性がすぐ上がるわけではありません。次の順序で慣らすことを勧めます。

  1. 1つの動作から：最初は「メニューコマンドの実行」だけをShortcatでやってみてください。最も効果が大きく、マウスに対する優位が明確な領域です。
  2. ヒントより検索を先に：名前を知っているボタンはタイピング検索が速いです。名前を知らないアイコンのときだけヒントモードに切り替えましょう。
  3. 同義語を信頼する：コマンド名がうろ覚えなら意味を入力しましょう（remove、clearなど）。正確な名前を覚えようと苦労する必要はありません。
  4. 意図的にマウスから離れる：1週間だけ意識的にトラックパッド使用を減らすと、手がパターンを覚え始めます。
  5. 補完ツールと組み合わせる：ウィンドウ管理やマクロが必要なら、Keyboard Maestroのようなツールと役割を分けて使いましょう。

10. 限界と率直な短所

バランスのため弱点も明確に挙げます。Shortcatは万能ではありません。

  • アクセシビリティ APIへの依存：アプリがアクセシビリティ情報を公開しなければ索引できません。独自キャンバスで描画するグラフィックアプリ、一部のElectron/Webアプリ、ゲームなどは操作が難しいか不可能です。
  • 学習コスト：最初の数日はむしろ遅いです。手がパターンを覚えるまで、マウスのほうが速く感じる区間が必ずあります。
  • 保守の懸念：Shortcatは数年活発に保守されていないという指摘があります。無料という大きな利点との引き換えであり、最新機能や迅速なバグ修正が必要なら弱点になります。
  • 機能の空白：キーボード基盤のスクロールなど一部機能はShortcatになくHomerowにあります。

これらの限界はほとんど「アクセシビリティ APIベース」という設計選択の影です。正確さと軽さを得る代わりに、APIが届かない領域では無力になります。

11. 誰に勧められるか

では、Shortcatは誰のためのツールでしょうか。整理すると次のとおりです。

  • キーボード中心の開発者：すでにVim・ターミナル・ショートカットに慣れ、手をキーボードに留めたい人。
  • RSIを管理するユーザー：マウス使用を医学的・予防的に減らす必要がある人。
  • アクセシビリティが必要なユーザー：キーボード優先操作が単なる好みではなく必要である人。
  • メニューハンター：ショートカットのない深いメニューコマンドを頻繁に使うデザイナー・パワーユーザー。

逆に、グラフィック中心のアプリやゲームを主に扱う人、新しいツール学習に時間を割けない人なら効用は限られるかもしれません。新しいツールを選ぶとき「自分のワークフローに合うか」をまず問う姿勢は、Claude Codeの隠れた設定で強調したツール選択の原則とも接しています。

12. 結論＋今日すぐ試せる3つ

Shortcatは「マウスへの短い往復」という、小さいが絶えず繰り返される非効率を正面から狙ったツールです。アクセシビリティ APIでUI要素を索引し、キーボードだけでクリック・メニュー・ウィンドウ切替を可能にすることで、入力効率・健康・アクセシビリティの3軸を同時に触れます。無料で敷居が低く、キーボード優先ワークフローを初めて試す人に理想的な出発点です。ただしアクセシビリティ APIに依存するという構造的限界と保守の懸念は明確に理解して使うべきです。

今日すぐ試せる3つで締めくくります。

  1. インストールしてアクセシビリティ権限からオンに。公式サイトから入手・インストールし、システム設定のアクセシビリティで権限を許可するのがすべての出発点です。
  2. メニュー検索だけを1週間使ってみる。ショートカットのないメニューコマンドをShortcatのあいまい検索で実行する習慣からつけると、効用を最も早く実感できます。
  3. Homerowと比べてみる。キーボードスクロールが切実なら、有料のHomerowも試して、無料のShortcatと自分のワークフローに合うほうを選びましょう。
