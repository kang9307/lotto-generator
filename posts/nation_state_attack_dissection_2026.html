실패한 국가배후 추정 사이버 공격 해부 — 방어자가 배우는 것

정교한 APT 공격이 어디서 어떻게 막혔는지, 블루팀이 뽑아낼 수 있는 실전 교훈

2026-06-28 개발/인프라

이 게시물은 쿠팡 파트너스 활동의 일환으로, 이에 따른 일정액의 수수료를 제공받습니다.

교육 목적 안내: 이 글은 방어자(블루팀) 관점에서 공격 메커니즘을 이해하기 위해 작성되었습니다. 공격 재현이나 악용 기법 습득이 목적이 아니며, 탐지·대응·예방에 초점을 맞춥니다.

서론: 공격이 실패할 때 가장 많이 배운다

2026년 6월, 한 캐나다 개발자가 자신이 받은 사이버 공격의 전 과정을 상세히 공개했다. "Lua Ventures"라는 싱가포르 기반 DeFi VC를 사칭한 공격자가 가짜 기술 면접 과제로 접근해 정교한 RAT(원격 접근 트로이목마)을 심으려 했으나, 결정적인 순간에 들통났다. 공격자가 국가 수준인지 여부는 여전히 추정 단계지만, 사용된 기법의 정교함은 상당히 높은 수준이었다.

성공한 공격보다 실패한 공격을 해부하는 것이 블루팀에게 훨씬 유용하다. 이유는 간단하다. 어디서 어떻게 막혔는지가 명확하게 드러나기 때문이다. 이 글은 그 공격 사례를 분석하되, 공격 도구를 복제하는 것이 아니라 방어자가 배울 수 있는 탐지 포인트, 사고 패턴, 그리고 구조적 교훈을 뽑아내는 데 집중한다. 2026년 6월 기준으로 이 유형의 공격은 확산 추세에 있다.

1. 공격 배경: Contagious Interview 캠페인

이 사례는 단독 사건이 아니다. Microsoft 보안팀과 Palo Alto Unit42가 추적하는 Contagious Interview라는 캠페인의 전형적 패턴에 해당한다. 이 캠페인은 북한 연계 위협 행위자와 연관이 있으며, 2024년 말부터 2026년 현재까지 지속 확산되고 있다. 타깃은 암호화폐·DeFi·AI·방산 분야 개발자다.

왜 개발자인가? 개발자 머신에는 소스코드, API 키, 클라우드 자격증명, SSH 키, 내부망 VPN 접근 권한이 집중되어 있다. 단 하나의 개발자 머신을 장악하면 공격자는 프로덕션 환경, 내부 서비스, 동료 계정으로의 횡적이동 발판을 얻는다. 채용 과정은 낯선 사람이 코드를 실행하라고 요청해도 자연스럽게 받아들이는 맥락이라는 점에서 공격 벡터로서 매력적이다.

2. 공격 단계별 해부

2.1 정찰 단계 (MITRE ATT&CK T1591, T1593)

공격자는 단순히 무작위로 접근하지 않았다. "싱가포르 기반 DeFi VC 펀드"를 사칭하며 다음 요소들을 사전에 준비했다.

  • 그럴듯한 LinkedIn 프로필과 실제 회사 이름처럼 보이는 포트폴리오 기업 목록
  • DeFi 투자 맥락에 부합하는 전문 용어 사용
  • 타깃 개발자의 기술 스택(TypeScript) 파악 후 맞춤형 저장소 구성

이 단계에서 이미 여러 경보 신호가 있었다. LinkedIn 프로필을 직접 검색하면 2025년 11월에 이름이 변경된 흔적, LLM이 생성한 듯한 어색한 문장, 전문가치고 구체성이 부족한 이력 등이 노출됐다. 그러나 피해자는 이를 캐치하지 못했다.

MITRE ATT&CK 매핑: T1591 (조직 정보 수집), T1593 (소셜 미디어 정보 수집), T1566.003 (스피어피싱 via 서비스)

2.2 침투 단계 (T1195.002 — 공급망 타협)

공격자는 "Ticket Harbor"라는 페리 티켓 앱으로 위장한 TypeScript 저장소를 제공했다. 핵심 악성 메커니즘은 patch-package를 악용한 것이다.

patch-package는 npm 패키지의 버그를 로컬에서 직접 패치하는 정당한 도구다. 그런데 공격자는 이를 악용해 typescript+5.9.2.patch 파일 안에 Base64와 XOR(키 73) 이중 난독화로 감싼 악성 코드를 숨겼다. 피해자가 "typecheck와 테스트 스위트를 실행해달라"는 지시를 따르는 순간 페이로드가 활성화되는 구조였다.

추가로 공격자는 git update-index --skip-worktree 명령으로 수정된 파일이 git status에 나타나지 않도록 숨겼다. 일반적인 코드 리뷰 습관만으로는 이 숨김 파일을 발견하기 어렵다.

MITRE ATT&CK 매핑: T1195.002 (공급망 타협 - 소프트웨어), T1027 (파일 및 정보 난독화), T1553 (신뢰 통제 우회)

2.3 실행 및 지속성 단계 (T1543, T1053)

페이로드 체인은 3단계로 구성됐다: 패치 파일 내 WASM 스텁 → 1.68MB 2단계 RAT → 최종 PinpinRAT 설치. 최종 악성 코드는 운영체제별 지속성 메커니즘을 갖췄다.

  • Windows: "PinpinWrappedJs" 예약 작업 등록
  • macOS: com.apple.WebKit.Networking을 사칭한 Launch Agent (정상 Apple 프로세스 위장)
  • Linux: cronjob (~/.cache-[randomhex]/mutex.js)

설치 후 PinpinRAT은 RSA-2048로 키를 생성하고 AES-256-CBC로 C2 통신을 암호화한다. 호스트 지문(IP·사용자명·OS), 파일 업로드/다운로드, 임의 프로세스 실행, 자가 제거 기능을 갖췄다. C2 서버는 89.124.107.161:80이었다.

MITRE ATT&CK 매핑: T1543.001 (Launch Agent), T1053.005 (예약 작업), T1071.001 (C2: HTTP), T1041 (C2 채널을 통한 유출)

2.4 횡적이동 — 이 사례에서 막힌 지점

공격자가 의도한 횡적이동 경로는 개발자 머신을 발판으로 내부망 자격증명과 소스코드 저장소에 접근하는 것이었다. 그러나 실행 단계에 이르기 전에 공격이 탐지되어 이 단계에는 도달하지 못했다.

3. 어디서, 어떻게 막혔나

탐지는 예상치 못한 방식으로 일어났다. 피해자는 시간을 아끼려고 받은 TypeScript 저장소를 Claude AI에 입력해 분석을 요청했다. AI가 즉시 patch-package 사용에서 이상 징후를 발견했다: "postinstall 훅 없이 patch-package가 존재한다." 이 단서를 따라 패치 파일을 직접 확인하자 Base64 난독화 스텁이 드러났다.

피해자 본인도 인정했다. 저장소가 Rust로 작성됐다면 build.rs 스크립트를 통한 악성 코드 실행에 함정에 빠질 수 있었을 것이라고. TypeScript였고, AI 도구를 우연히 먼저 사용했기 때문에 막혔다.

"충분한 노란색 신호가 쌓이면 빨간색이 된다" — 개별 지표는 의심스럽지 않지만 누적 패턴 인식이 핵심이다.

사후 검토에서 드러난 초기 신호들: 캘린더 초대 없이 Google Meet 링크만 전달, 통화 중 카메라 미작동, 싱가포르 조직이 CEST 시간대에서 운영, LinkedIn 이름 변경 이력, LLM 흔적의 어색한 문장. 각각은 무시할 수도 있지만 누적은 명확한 패턴이었다.

4. 방어자(블루팀)가 배우는 교훈

4.1 탐지: 코드 실행 전 검토를 워크플로에 강제하라

이 공격의 핵심 벡터는 "낯선 저장소를 받아 npm install을 실행한다"는 자연스러운 개발자 행동이다. 방어는 이 행동 앞에 한 단계를 삽입하는 것이다.

  • 실행 전 patch 파일 확인 의무화: git log --all --oneline, git diff HEAD, 그리고 patches/ 디렉토리를 반드시 검토한다
  • AI 코드 스캔 통합: 외부 저장소를 AI에 먼저 스캔시키는 것은 실제로 효과를 입증했다. 자동화 파이프라인으로 만들 수 있다
  • postinstall 훅 검사: cat package.json | jq '.scripts'로 postinstall 스크립트의 존재와 내용을 먼저 확인한다
  • git skip-worktree 파일 탐지: git ls-files -v | grep '^S'로 숨겨진 파일을 확인한다

4.2 로깅: 개발자 워크스테이션을 사각지대로 두지 마라

대부분의 조직이 서버·네트워크 경계에 집중하고 개발자 워크스테이션 로깅을 소홀히 한다. 그러나 이 사례처럼 공격이 개발자 머신에서 시작된다면 그 사각지대가 치명적이다.

  • EDR 배포: 엔드포인트 탐지·대응 솔루션을 개발자 워크스테이션에도 적용, 비정상 프로세스 생성·네트워크 연결을 로깅한다
  • DNS 로깅: 알려지지 않은 외부 IP에 대한 DNS 조회·TCP 연결을 중앙 집계한다. PinpinRAT의 C2(89.124.107.161)는 이 방식으로 탐지 가능하다
  • 프로세스 실행 로그: node.js 프로세스가 예상치 않은 child process를 생성하는 이벤트를 탐지 규칙으로 설정한다
  • 홈 디렉토리 숨김 파일 감시: ~/.cache-*/ 같은 패턴의 신규 디렉토리 생성을 파일 시스템 모니터링으로 알림 처리한다

4.3 최소권한: 개발자 머신 자격증명의 폭발 반경을 줄여라

가장 구조적인 방어는 개발자 머신이 침해되더라도 공격자가 할 수 있는 일을 최소화하는 것이다. 이것이 최소권한(Least Privilege) 원칙의 핵심이다.

  • 클라우드 자격증명 범위 제한: 개발자의 AWS/GCP IAM 권한을 실제 필요한 리소스로만 제한, 광범위한 관리자 권한 금지
  • 단기 토큰 사용: 장기 API 키 대신 STS 임시 자격증명이나 OIDC 기반 단기 토큰을 사용해 탈취 후 유효 시간을 최소화한다
  • SSH 키 분리: 프로덕션 서버용 SSH 키를 개발용 저장소에서 분리 보관하고, 하드웨어 보안 키(FIDO2) 기반 인증을 도입한다
  • 시크릿 스캔: GitHub Advanced Security나 동등 도구로 저장소 내 API 키·패스워드 노출을 자동 탐지한다

4.4 제로트러스트: 침해를 전제로 설계하라

제로트러스트는 "내부 네트워크는 안전하다"는 전제를 버리는 것이다. APT의 특성상 초기 침투는 막기 어렵다. 중요한 것은 침투 후 공격자가 할 수 있는 것을 제한하는 설계다.

  • 마이크로세그멘테이션: 개발 환경, 스테이징, 프로덕션 간 네트워크를 명시적으로 분리하고 최소 필요 포트만 허용한다
  • 지속적 인증: VPN에 연결됐다고 내부 서비스 전체에 자동 접근을 부여하지 않는다. 서비스별 인증을 추가로 요구한다
  • 이상 행동 탐지: 개발자 계정이 평소와 다른 시간·장소·서비스에 접근하면 즉시 알림을 트리거하는 UEBA(User Entity Behavior Analytics)를 적용한다

5. 국가배후 추정의 의미와 한계

이 공격이 실제로 국가 기관의 작전인지는 결론 내리기 어렵다. 공격의 정교함은 높지만, Lobsters와 Reddit 보안 커뮤니티가 지적했듯이 이 정도 수준은 자원이 풍부한 범죄 조직도 충분히 구현 가능하다. 피해자 본인도 캐나다 사이버보안청(CCCS)에 신고했지만 확실한 귀인(attribution)은 미지수다.

그러나 귀인 여부가 방어자에게 중요한 것은 아니다. 중요한 것은 사용된 기법이다. MITRE ATT&CK 프레임워크로 매핑하면, 이 공격이 T1566.003(소셜 미디어 스피어피싱), T1195.002(소프트웨어 공급망 타협), T1027(난독화), T1543(자동 실행 메커니즘) 등 국가배후 그룹이 자주 쓰는 기법 조합을 활용했다는 사실이 중요하다. 귀인과 무관하게 이 기법들은 방어자가 대비해야 하는 현실적 위협이다.

2026년 기준으로 국가배후 추정 그룹과 금전 동기 범죄 조직의 경계는 더욱 흐려지고 있다. SecurityWeek의 2026년 사이버 전망에 따르면, 국가 프록시가 금전 동기 APT와 혼합되며 스파이, 방해, 수익이 뒤섞인 작전이 증가하고 있다. 방어자는 귀인을 기다리는 대신 기법 기반으로 대비해야 한다.

6. APT 대응 원칙 — 실전 적용 가능한 3가지

이 사례에서 배울 수 있는 가장 실천적인 교훈을 세 가지로 압축한다.

6.1 채용 과정을 보안 위험으로 취급하라

기술 면접 과제로 외부 저장소를 받고 실행하는 것은 사실상 낯선 사람의 코드를 본인 머신에서 돌리는 행위다. 이를 명시적으로 위험 행위로 분류하고, 샌드박스 가상환경(VM·Docker·CI 격리 환경)에서만 실행하는 정책을 팀 또는 개인 차원에서 확립해야 한다. 개발 머신과 실험 머신을 물리적 또는 논리적으로 분리하는 것이 가장 강력한 대응이다.

6.2 누적 신호를 읽는 훈련이 기술보다 먼저다

이 사례에서 가장 인상적인 점은 탐지가 기술적 도구가 아니라 "뭔가 이상하다"는 누적 신호 인식에서 시작됐다는 것이다. 캘린더 초대 없이 링크만, 카메라 미작동, 어색한 문장, 바뀐 LinkedIn 이름. 각각은 무시할 수 있지만 누적은 무시할 수 없다. 보안 인식 교육에서 개별 IoC보다 패턴 누적 사고를 가르치는 것이 실효성이 높다.

6.3 위협 헌팅을 반응적이 아닌 선제적으로 운영하라

이 공격에서 탐지를 가능하게 한 것은 침해지표(IoC)가 시그니처 데이터베이스에 있어서가 아니었다. AI 도구가 맥락 없이 코드를 분석하다 구조적 이상을 발견한 것이었다. 이는 위협 헌팅이 알려진 악성 코드 스캔을 넘어, "이 코드가 왜 이렇게 작성됐나"를 묻는 이상 행동 기반 분석으로 확장되어야 함을 시사한다. 블루팀은 SIEM 알림을 기다리는 것이 아니라 정기적으로 가설을 세우고 로그·코드·설정에서 그 가설을 검증하는 사냥꾼 사고방식을 훈련해야 한다.

결론

이 사례가 귀중한 이유는 공격이 성공하지 못했기 때문이다. 성공한 침해는 피해자가 공개하기 어렵고, 공격 흐름 전체를 이렇게 상세히 볼 기회가 없다. 공격자의 정체가 국가 기관이든 범죄 조직이든, 사용된 기법은 오늘날 블루팀이 대비해야 하는 실제 위협이다.

방어의 핵심은 불침투 신화를 버리는 것에서 시작한다. 정교한 공격자는 언제나 진입 경로를 찾는다. 진짜 방어는 침투 후 공격자가 할 수 있는 것을 최소화하고, 침투를 빠르게 탐지하며, 피해 범위를 제한하는 것이다. 탐지, 로깅, 최소권한, 제로트러스트는 그 구조적 기반이다. 이 사례는 그 원칙들이 왜 실용적인지를 실제 공격 흐름으로 증명한다.
