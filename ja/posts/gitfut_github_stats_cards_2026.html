GitFut - GitHub の活動指標を FIFA 選手カードに変える面白さ

Your Commits, Rated Out of 99 - 開発者指標ゲーミフィケーションを読み解く

2026年7月17日 トレンド・カルチャー

序論: 開発者が急にサッカー選手になった理由

最近、開発者コミュニティやSNSのタイムラインに見慣れない画像が流れ始めた。六本の能力値バー、国旗、ポジション表記、そしてブロンズからアイコンまでの等級がついたサッカー選手カードだ。よく見ると選手名の位置にGitHubのIDが、クラブロゴの位置にオーバーロールレーティングが入っている。このカードを生成するツールがGitFutだ。

GitFutはユーザーのGitHubプロフィール活動を読み取り、ワールドカップゲームおなじみのアルティメットチーム(FUT)カード形式に再構成して見せてくれる。自己紹介でも実績レポートでもなく、ゲームカードという意外なフォーマットを選んだ点がこのツールを興味深くしている。本稿ではGitFutが実際に何をするツールなのか確認済みの事実を中心に整理し、なぜこの種のゲーミフィケーションが開発者に刺さるのか、そして楽しさの裏にどんな落とし穴があるのかをバランスよく見ていく。

1. GitFutとは何か - GitHub統計をFIFAカードに

GitFutは開発者Younes FdjがNext.js・TypeScript・Tailwind・Redisで構築したWebツールだ。重要なのは、自己申告ではなくGitHub GraphQL APIからリアルタイムでプロフィールデータを読み取ってカードを生成する点にある。つまりユーザーが自分でスコアを入力するのではなく、実際のコミット・PR・スターといった公開活動の履歴がそのままカードに反映される。

1.1 六つの指標を、サッカーの能力値に

GitFutはGitHubの活動を六つのサッカー能力値にマッピングする。確認されているマッピングは次の通りだ。Pace(スピード)は直近1年のコミット数、Shooting(シュート)はリポジトリ全体で獲得したスター数、Passing(パス)はPR活動とフォロワー数、Dribbling(ドリブル)は使用言語の多様性、Defending(守備)はコードレビューとイシュー活動、Physical(フィジカル)は生涯累積コントリビューションだ。サッカーゲームに触れたことがある人なら誰でも知っている六マスのステータスレーダーを、そのまま開発者指標に転用した形といえる。

1.2 レーティングシステム - 0〜99、ただし実質の上限は88

カード上部には0から99のオーバーロールレーティングが表示される。ただしGitFutの公式説明によれば、生の統計値(raw stat)は88点で上限が設定されている。90点台は別枠の「レガシーゲート」として扱われ、一年だけ活動を集中させても到達できず、複数年にわたる継続と影響力が積み重なって初めて開くという設計だ。短期集中の活動でアイコン等級を獲得できないようにする仕組みで、これは実際のFIFAアルティメットチームで伝説級カードが簡単には出ないよう設計された希少性の仕組みをそのまま借用した構造といえる。

1.3 ポジション・アーキタイプ・カード等級・国旗

GitFutは六つの能力値の分布パターンを見て、ポジションとプレースタイル(アーキタイプ)まで自動で割り当てる。例えばシューティングの数値が突出していれば得点型ストライカーに、守備とパスが強ければディープライイング・プレーメイカーに分類される。カード自体の等級もブロンズ・シルバー・ゴールド・インフォーム・TOTY・アイコンの六段階で視覚的に表現され、国はプロフィール情報を基本としつつURLパラメータで国旗を変更することもできる。カードは固定画像ではなく生きたURLであり、READMEやポートフォリオに埋め込んでおけば、GitHubの活動が変わるたびに統計も自動で更新される。

2. FIFAカードの比喩がここまで刺さる理由

技術指標を可視化する方法は数え切れないほどある。それでもなぜサッカー選手カードがここまで拡散し話題になったのか。理由は三つに集約できると考える。

2.1 六本のバーに凝縮された直感性

生のダッシュボードやGitHub本家のインサイトページは数字とグラフが並ぶだけで、それ自体はすぐには読み取りにくい。一方でPace・Shooting・Passing・Dribbling・Defending・Physicalという六軸は、サッカーに少しでも触れたことがある人なら説明なしでも直感的に理解できる。複雑な活動履歴を六本のバーとオーバーロール一つの数字に圧縮する凝縮力こそ、このカードが瞬時に読み取れる理由だ。

2.2 収集欲と希少性の設計

ブロンズからアイコンまで続く等級体系、そして生の統計値を88に固定し90点台を「年数と影響力でのみ開く扉」として設計したのは偶然ではない。実際のFIFAアルティメットチームがそうであるように、簡単には届かない上位等級があってこそ、人はスコアを確認し翌年また戻ってきてカードを更新したくなる。hada.ioのディスカッションでも、ユーザーが自分のパーセンタイル順位(0.03%、0.01%といった数値)を示し合って比較する様子が見られたが、これはこの設計が意図した反応に近い。

2.3 拡散のために生まれたフォーマット

GitFutのカードは一つの画像URLとして存在する。X(旧Twitter)やスレッズにスクリーンショットを投稿しやすく、GitHubプロフィールのREADMEにマークダウン画像として貼っておけば、訪問者はその都度更新されたカードを目にする。テキストの要約や表よりもキャラクター化されたカード一枚のほうがはるかに目を引き、「自分のカードを見て」という一言は「自分のコミットログを見て」よりも圧倒的にクリックを誘う。拡散を狙って最初から設計されたフォーマットなのだ。

3. この流行の系譜 - README バッジから3Dスカイラインまで

GitFutはある日突然生まれたアイデアではない。GitHubの活動を視覚的に再構成し、自慢し合い共有しようという試みには、かなり長い系譜がある。

3.1 github-readme-stats - READMEバッジの元祖

Anurag Hazraが作ったgithub-readme-statsは、GitHubプロフィールのREADMEにスター・コミット・PRといった統計を動的にレンダリングして表示するオープンソースプロジェクトだ。統計カード、人気言語カード、リポジトリカード、ストリークカードなど複数の種類をサポートし、今も数多くの開発者プロフィールページの上部を飾っている。GitFutが扱う原材料(コミット・スター・PR・レビュー)の多くは、この系譜ですでに標準的に扱われてきた指標でもある。

3.2 GitHub Skyline - 草グラフを3Dの街に

GitHub公式が作ったgh-skylineは、1年分のコントリビューショングラフを3Dスカイラインモデルに変換するCLI拡張機能だ。コミットが多い週は高いビルになり、このモデルはSTLファイルとして書き出して3Dプリントすることもできる。数字の羅列だった草グラフを目に見える街並みへと変え、一年の活動を「展示できるもの」にした点で、GitFutと志向が重なる。

3.3 Wrapped系 - Spotifyの文法の移植

Spotify Wrappedが年末ごとに巻き起こす話題性に着想を得て、GitHubの活動を要約してくれる「GitHub Wrapped」系のツールも複数登場した。最も活発だったコミット曜日、よく使った言語、年間コミットストリークなどをカード形式で要約し、開発者ペルソナまで導き出すツールもある。GitFutとこうしたWrapped系ツールは同じ心理を狙っている。一年分のデータを自分で見返すのは面倒だが、誰かが代わりに要約してきれいに包んでくれれば、人は喜んで確認し共有するという心理だ。

3.4 なぜ今、開発者アイデンティティ系コンテンツが流行るのか

この流れの背景には、開発者のキャリアがますます公に証明される文化がある。履歴書の一行よりもGitHubプロフィールやポートフォリオサイトが先に見られる採用慣行、X・スレッズ・LinkedInで開発の近況を共有することが当たり前になったSNS文化、そしてオープンソースへの貢献そのものが経歴になるエコシステムが重なり合い、「自分の開発活動を圧縮して見せてくれるコンテンツ」への需要が根強く存在してきた。GitFutはその需要にFIFAカードという新鮮なフォーマットを乗せた最新の事例に過ぎない。

4. GitFutが算出する指標、どう読むべきか

ここからはGitFutが公式に明らかにしたマッピングを根拠にした筆者自身の解釈だ。それぞれの能力値が何を「比喩」しているのか、そしてその比喩がどこまで妥当なのかを一緒に見ていく。

4.1 Pace(直近コミット) - 勤勉さの代理指標?

直近1年のコミット数をスピードに対応させたのは、「どれだけ頻繁に動いたか」を示そうとする意図に読める。コミット頻度は活動の勤勉さをある程度推測させてくれるが、コミット一つひとつの規模と意味は千差万別だ。誤字を一つ直したコミットと複雑なバグを潰したコミットが同じ1点として集計される点は、この指標の明確な限界だ。

4.2 Passing(PR+フォロワー) - 協業の比喩

PRとフォロワー数をパスに対応させた発想は気が利いている。パスがチームメイトにボールをつなぐ行為であるように、PRは他人のコードベースに貢献を「届ける」行為であり、フォロワーはその到達範囲の広さを示す。ただしフォロワー数は実力よりもネットワーキングや偶発的なバイラルに左右されることが多く、協業力の指標とするにはノイズが大きい。

4.3 Shooting(スター) - 影響力であり人気投票でもある

スター数をシューティング(得点力)に対応させたのは、影響力を示そうとする意図だ。実際、スターの多いリポジトリは広く使われているか話題になった可能性が高い。しかしスターは実際の利用とは無関係に押されることも多く、タイミングよくトレンド入りしたリポジトリ一つが生涯コミットよりもスター総数に大きく貢献することもある。人気投票に近い指標であることは覚えておくべきだ。

4.4 Defending・Dribbling・Physical - 残る三軸

守備をレビューとイシュー活動に対応させたのも比喩としては筋が通っている。コードレビューはチームの品質を守る防御的な行為に近く、イシュー対応も問題が大きくなる前に食い止める役割だからだ。ドリブルは使用言語の多様性で多才さを、フィジカルは生涯累積コントリビューションで長く続けた体力を象徴する。六つの指標を一言でまとめるとこうなる。面白い比喩ではあるが、精密な実力測定ではない。

5. 楽しさの裏にある含意 - 活動指標は実力ではない

GitFutを楽しむことと、そのスコアを実力の証拠として受け止めることはまったく別の問題だ。ここからはゲーミフィケーションツール全般にかかる、以前からの警告を取り上げる。

5.1 活動は実力の代理指標であって、実力そのものではない

ソフトウェアエンジニアリング業界では以前から、コミット数・コード行数・PR数といった指標を「虚栄指標(vanity metrics)」と呼んで警戒してきた。500行の洗練されたコードが2,000行の散漫なコードより大きな価値を生むことがあり、コミットを細かく分ければ数字はいくらでも水増しできるという指摘が代表例だ。GitFutの六指標も結局この系列に属する。楽しむことと実力の証明として使うことの間には明確な一線が必要だ。

5.2 ゲーム可能な指標という根本的な限界

エンジニアリング組織を研究してきた資料は、代案としてSPACEフレームワーク(満足度・成果・活動・コミュニケーション・効率)やDORA指標(デプロイ頻度・リードタイム・変更失敗率・復旧時間)のような、結果とチームの文脈まで併せて見る多次元指標を提案している。GitFutの楽しさはちょうど六つの数字に単純化したところから生まれるが、その単純化こそがコード品質・設計判断・チームへの目に見えない貢献のような、数字にうまく落とし込めない部分をまるごと消してしまうという点も併せて知っておく必要がある。

5.3 比較の罠とバーンアウト

hada.ioのコメントに見られるように、人はこうしたカードを手にすると自然にお互いのスコアやパーセンタイルを比較し始める。Spotify WrappedでもGitHub WrappedでもGitFutでも、「要約して見せてくれる」ツール全般が共通して抱える影の部分だ。オープンソースに貢献せず会社の非公開業務中心で働く開発者、非公開リポジトリ中心で仕事をする開発者は、実際の実力とは無関係に低いスコアになってしまう。カードのスコアを上げるために意味のないコミットを細切れにしたり、スターをねだったりする行動につながるなら、楽しさはすでにストレスに変わっている。

6. 気軽に楽しむためのコツ

結論から言えば、GitFutは悪いツールではない。むしろ誠実に作られている。自己申告ではなく実際のGitHub APIデータを読み取り、生の統計値を88に固定して短期の活動集中で等級を水増ししにくく設計し、90点台を「年数で積み上げる区間」と明示している点も、制作者がゲーミフィケーションの落とし穴をある程度意識している証だろう。筆者が勧める使い方はシンプルだ。一年を振り返る楽しいスナップショットとして楽しみ、READMEに貼って笑い話にするのは構わないが、そのスコアを転職・評価・自分の実力判断の根拠には絶対に使わないこと。カードのオーバーロールが低いからといって実力が低いわけではなく、高いからといって実力が高いわけでもない。ただ直近1年間にGitHub上で何をどれだけやったかを、面白く圧縮して見せてくれただけのことだ。

結論

GitFutは開発者活動をゲーミフィケーションで表現した事例の中でも、比喩が特にきれいに噛み合ったツールだ。実際のGitHubデータを根拠にし、希少性の設計で共有欲を刺激し、github-readme-stats・GitHub Skyline・GitHub Wrapped系へと続く開発者アイデンティティ系コンテンツの系譜の上に立っている。ただし楽しさと実力の証明は別物だ。コミット・PR・スターといった活動指標がコード品質や実際の力量を代弁しないという点は、業界内ですでに何度も指摘されてきた事実である。2026年7月時点で、この種のゲーミフィケーションツールは今後も増えていく可能性が高い。楽しみつつも、たった一つの数字に一喜一憂しないバランス感覚が必要だ。
