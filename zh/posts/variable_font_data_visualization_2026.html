用可变字体画图表?2026年数据可视化的新趋势 - Datatype及其超越

不用图表库,只用一行CSS font-variation-settings绘制KPI

2026-05-20 IT/技术

引言:当字体成为图表

2026年5月,GeekNews(hada.io话题)上出现了一篇有趣的文章。Frank Tisellano制作的Datatype可变字体。想法简单却新颖:"别再用柱状图画数据,改用字体粗细来表达"。销售额增长则数字变粗,下降则变细。没有图表库,没有画布,只是文本。

本文不是介绍Datatype本身。而是以Datatype所展示的想法为出发点,从技术角度分析可变字体(Variable Fonts)在2026年数据可视化中具有何种可能性。核心是字体标准本身已经是强大的可视化工具,而我们一直忽视了它的潜力。

1. 可变字体(Variable Fonts)是什么

可变字体起源于2016年OpenType 1.8引入的OpenType Font Variations标准。传统字体每种粗细(Regular、Bold、Light)都需要单独的文件,通常8到16个。可变字体将它们压缩到单一文件中,通过插值(interpolation)生成中间的无限多个值。

使这种插值成为可能的是轴(Axis)的概念。标准定义的五个注册轴如下:

  • wght(Weight):100(Thin)到900(Black)的粗细
  • wdth(Width):窄到宽的字宽
  • slnt(Slant):倾斜(斜体)
  • ital(Italic):斜体开关
  • opsz(Optical Size):正文/标题优化

除此之外字体设计师可以定义自己的自定义轴。Datatype所利用的正是这个领域。

1.1. 与普通字体的区别

实际工作中最能感受到的差异是文件大小和灵活性。

项目普通字体(静态)可变字体

总容量(中日韩)3-6MB(多文件)800KB-1.5MB

1.2. 浏览器兼容性

从2018年起Chrome、Safari、Firefox、Edge全部支持可变字体。2026年除IE11外几乎100%支持,移动端Safari和Android Chrome也稳定运行。核心API是font-variation-settings属性和font-weight: 1 9999范围标记。

2. Datatype的洞见 - "用数据驱动字体轴"

设计师通常将可变字体的wght轴视为预设值(如400、700)。Datatype的洞见是用数据动态控制这个值。一个CSS变量就够了。

.chart-value {
  font-family: "DataTypeVariable", sans-serif;
  font-variation-settings: 'wght' var(--value);
  transition: font-variation-settings 0.3s ease;
}

HTML中可以直接映射数据。

<span class="chart-value" style="--value: 850">1,250</span>  <!-- 大销售 → 粗 -->
<span class="chart-value" style="--value: 320">430</span>     <!-- 小销售 → 细 -->
<span class="chart-value" style="--value: 600">780</span>     <!-- 中间 → 中等 -->

完全没有调用图表库(D3.js、Chart.js、ECharts)。没有canvas,没有SVG。读者却能一眼看出"哪个数字大"。如果可视化的本质是将数据映射到视觉属性,那么字体粗细正是最自然的视觉属性之一。

2.1. 无障碍性(Accessibility)的免费奖励

这种手法的隐藏优势是无障碍性。canvas绘制的图表屏幕阅读器无法读取。SVG需要逐个添加ARIA属性。但可变字体可视化只是文本。NVDA、JAWS、VoiceOver直接读出"850、430、780"。视障用户也能获取数据,这才是真正意义上的通用可视化。

3. 五个实际应用场景

想法再好,没有实际用武之地也没意义。以下是可变字体可视化能立即见效的五个场景。

场景1:仪表盘KPI卡片

月度销售额、新增用户数、转化率等单一数字需要承担巨大视觉权重的位置最适合。数字本身通过粗细展示变化,不需要额外的图表组件。Vue、React中只需通过props传递weight值即可。

场景2:数据表格单元格强调

在1,000行销售表中想要强调高值行时,颜色对色盲用户不友好,柱状图每行需要额外空间。可变字体粗细在同一行内即时呈现差异。

td.amount {
  font-variation-settings: 'wght' calc(300 + (attr(data-value number) / 1000) * 600);
}

(2026年5月当前attr() type仍在部分浏览器中受限,生产环境建议使用JS注入CSS变量。)

场景3:信息图与印刷媒体

可变字体在印刷中也能完整保留粗细。在杂志、年报、演示文稿中用文本替换柱状图,纸面上的数据也能"活"起来。报纸标题粗细自动映射到文章重要性的实验也可行。

场景4:实时监控面板

用可变字体粗细显示服务器CPU使用率、交易品种波动率,比闪烁的仪表组件视线负担更小。加上transition属性的平滑插值,数据会有"呼吸"的感觉。

场景5:中日韩可变字体 - 中文环境应用

中文环境中代表性的可变字体是阿里巴巴普惠体(Alibaba PuHuiTi)Variable和思源黑体(Source Han Sans / Noto Sans SC)Variable。前者商用免费,后者由Adobe与Google联合发布。与韩国环境的Pretendard Variable、日本环境的Noto Sans JP Variable应用模式相同。

@font-face {
  font-family: "Noto Sans SC Variable";
  src: url("/fonts/NotoSansSC-VF.woff2") format("woff2-variations");
  font-weight: 100 900;
}

.kpi-number {
  font-family: "Noto Sans SC Variable", sans-serif;
  font-variation-settings: 'wght' var(--data-weight);
}

4. 与D3.js / Chart.js的定量对比

可变字体可视化并非万能。让我们定量比较它在哪些领域强,哪些领域弱。

标准可变字体方式Chart.js / D3.js
初始加载大小字体文件80-150KB库200-500KB
屏幕阅读器支持原生文本(优秀)需另外做ARIA
交互仅CSS hover/transition缩放、工具提示、下钻丰富
学习曲线非常低(一行CSS)中等到陡峭
图表表现力单值、文本为主散点图、热力图等丰富
印刷兼容性完美(文本原样)需要光栅化
SEO作为正文文本索引canvas不被索引

总结:可变字体可视化在单值强调和文本优先环境中强,在复杂多维图表和交互式仪表盘中弱。两者不是替代关系,而是互补关系才更准确。

5. 中文环境下的现实 - 中日韩字体为何更大

中文可变字体比拉丁可变字体文件更大。原因很简单。拉丁字母约有200-300个字形,而简体中文GB 2312标准为6,763字,扩展到GB 18030则包含27,484字,加上繁体则更多。此外可变字体必须为每个字形单独存储插值数据。

因此实际工作中必须做以下两种优化。

  • 子集化(Subset):仅提取网站实际使用的字符。使用pyftsubset等工具可将1.5MB压缩到约300KB。
  • 分段加载(unicode-range):在CSS的@font-face中明确unicode-range,仅下载需要的块。
@font-face {
  font-family: "Noto Sans SC Variable";
  font-weight: 100 900;
  font-style: normal;
  font-display: swap;
  src: url("/fonts/noto-sans-sc-var.woff2") format("woff2-variations");
  unicode-range: U+4E00-9FFF;  /* 中日韩统一表意文字基本区 */
}

6. 限制与注意事项

在生产环境中采用可变字体可视化之前应检查以下几点。

6.1. 可表达图表形式的局限

本质上可变字体适用于将一维值映射到单个视觉属性。散点图(双轴)、热力图(二维)、折线图(时序趋势)等多维和时间序列表达不适合。这些情况下D3、ECharts、Vega-Lite仍是正解。

6.2. 字体加载前的FOUT处理

可变字体加载前会显示系统字体作为后备,此时weight映射不生效,所有数据看起来粗细相同。配合font-display: swap和<link rel="preload">最小化FOUT时间,或字体加载完成前在可视化区域显示加载指示器更安全。

6.3. 印刷介质中的weight精度

显示器上插值的weight 350与印刷输出的weight 350可能略有差异。这是因为RIP(光栅图像处理器)的插值算法不同。需要精密印刷的媒体建议只使用100、300、500、700、900等整数weight。

6.4. 与设计系统的协调

如果现有设计系统只定义了Regular/Bold两种weight,可变字体可视化会在两者之间自由使用。必须先将设计系统指南更新为"可变友好",否则设计师与开发者之间会产生冲突。

7. 推荐和不适合的对象

综合本文分析,可变字体可视化的适合度划分清晰。

推荐对象不适合对象
数据可视化入门者 - 无学习成本即可开始交互式仪表盘开发者 - 缺少缩放和工具提示
信息设计师 - 适合信息图自动化BI系统运营者 - 需要复杂分析图表
印刷媒体设计师 - 印刷兼容性完美实时交易屏幕开发者 - 毫秒级更新负担大

注重SEO的内容 - 正文可被索引高分辨率图表印刷物 - 需要像素级精度

8. 结论 - 可变字体是可视化范式的静默扩展

Datatype不是宏大的库,只是一位设计师制作的一款小字体。但它所展示的想法是本质性的。它再次提醒我们:图表不是画在画布上的图画,而是将数据映射到视觉属性的所有行为。

2026年的网络正向更轻、更可访问、更适合印刷的方向演化。可变字体与这一趋势恰好契合。在调用200KB图表库之前,也许100KB字体文件中已经有答案。希望本文能成为再次审视这一可能性的契机。
