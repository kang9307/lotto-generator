발표 개요 — 501B 오픈 가중치 모델 Beam과 가중치 공개 예정의 범위

2026년 10월 5일 Reflection은 자사 첫 오픈 가중치 모델 Beam을 발표했다. 가중치는 이달 안에 공개할 예정이며, 발표 시점에는 아직 내려받을 수 없다. Beam은 코딩, 추론, 에이전트 워크로드를 겨냥해 만든 희소 혼합 전문가(Sparse Mixture-of-Experts, 이하 MoE) 모델이다. 총 매개변수는 5,010억 개(501B)이고 토큰당 활성 매개변수는 230억 개(23B)이다.

원문은 Beam의 능력이 사전학습과 강화학습(RL) 양쪽의 큰 투자에서 나왔다고 설명한다. 웹과 독점 라이선스 데이터셋에서 고른 23.8조 토큰으로 사전학습했고, 10.5K개의 NVIDIA GB300 GPU로 4주 동안 1억 회가 넘는 롤아웃을 생성하는 고연산 RL을 돌렸다. 원문은 이를 합쳐 「프런티어급 추론 연산 효율을 갖춘 경쟁력 있는 오픈 가중치 성능」이라고 요약한다.

  • 공개 일정: 가중치, 기술 보고서, 모델 카드, 개발자 산출물을 이달 안에(later this month) 공개한다고 적었다.
  • 라이선스: 이달 중 Apache 2.0 라이선스로 가중치를 내고, 모델을 실행·평가·미세조정하기 위한 문서와 전체 스택도 함께 공개할 계획이라고 한다. 출시 때 배포 파트너 생태계와 여러 오픈소스 라이브러리와의 통합도 함께 내놓겠다고 밝혔다.
  • 현재 접근: 모델은 최종 레드팀과 평가를 거치는 중이며, 원문은 조기 접근 신청 링크를 안내하고 선별된 사용자 그룹에만 이른 버전을 제공하며 대기 명단을 받는다고 적었다.

따라서 지금의 Beam은 이미 배포된 오픈소스가 아니라 사양과 벤치마크가 발표되고 가중치 공개가 예고된 모델이다. 원문이 밝힌 수치와 그 계산 분모는 구분해서 적고, 원문이 말하지 않은 부분은 따로 모아 둔다.

아키텍처 사양 — 총 501B 대비 활성 23B의 희소 MoE

Beam은 총 501B 매개변수 가운데 토큰당 23B가 활성인 희소 MoE 모델이다. 활성 비율은 23÷501로 약 4.6%이다(계산). 원문은 아키텍처와 최적화 레시피가 지속적인 후속 RL의 기반이 되는 수치적으로 건강한 토대를 강조한다고 설명하며, 사전학습 검증은 이렇게 했다고 적는다. 점차 큰 모델 시리즈를 사전학습해 스케일링 레시피를 세우고 검증했으며, 최종 Beam Base는 예측된 성능과 일치하고 접근 가능한 비슷한 크기의 오픈 베이스 모델과 같거나 더 낫다고 한다.

  • 구성 요소: 로컬 어텐션과 글로벌 어텐션의 교차 배치, 세분화된 라우팅 전문가(fine-grained routed experts), 제어된 잔차 스트림, 여러 형태의 부하 균형을 결합했다고 원문은 요약한다.
  • 전문가 부하 균형: 무보조 손실 부하 균형(auxiliary-loss-free load balancing, DeepSeek-AI et al., 2024)을 바탕으로, 학습 후반의 라우팅 교란을 줄이도록 전문가 편향(expert-bias) 갱신에 코사인 감쇠를 도입했다.
  • 시퀀스 수준 균형: 사전학습 분포 밖의 데이터에서도 전문가 활용을 고르게 하도록 시퀀스 수준 균형을 추가했고, 하류 RL의 분포 변화에 대비하는 것이라고 설명한다.
  • 균형의 결과: 사전학습이 끝난 시점의 베이스는 거의 완벽에 가까운 균일한 활용을 보였고, 가장 바쁜 전문가의 부하는 MoE 레이어 평균으로 1.04배였다고 한다(Figure 7).
  • 잔차 스트림: 깊이에 따른 스케일링 방식으로 서브레이어 출력이 쌓일 때의 활성화 증가를 상쇄하고, SandwichNorm, 원소별 어텐션 게이팅, FP32 잔차 누적(작은 갱신을 더할 때의 반올림 오차 감소)과 결합했다.
  • 안정성의 범위: 52개 레이어 전체에서 잔차 스트림 RMS가 사전학습 내내 유한하게 유지되었고(Figure 8), 이 안정성이 사전학습, 강화학습, 정렬 과정에 걸쳐 이어졌다고 적었다.

원문은 모델이 활성 매개변수 기준으로 얼마나 가벼운지를 호스팅 요구량으로 환산해 설명하지 않는다. 총 가중치를 서빙하는 데 필요한 메모리나 GPU 구성은 원문에 없으므로 그 수치는 만들어 내지 않는다.

사전학습과 인프라 — 23.8조 토큰과 6,144개 GB300

원문은 Beam을 웹, 공개 출처, 독점 라이선스 데이터셋에서 모은 다양한 고품질 토큰 23.8조 개로 사전학습했다고 적는다. 데이터 파이프라인은 소스 코드, 기술 설명, 수학·과학 지식을 모든 큐레이션 단계에서 보존해 하류 에이전트 코딩의 토대를 만들도록 설계했다. 웹에서 접근 가능하고 제한 없는 라이선스의 코드와 코드 문서는 거의 모두 학습에 썼다고 한다.

  • 필터링: 파싱, 중복 제거, 큐레이션을 거쳐 원시 인터넷 토큰의 약 95%가 제거된다. 한편 기존 기법이었다면 놓쳤을 약 1.8조 개의 고품질 토큰을 유지했고, 여기에는 큐레이션된 웹 코드 토큰의 87%가 포함된다. 1.8조는 최종 선별 총량이 아니라 기존 필터가 놓쳤을 분량이다.
  • 품질 분류: 웹, 코드, STEM 콘텐츠용 품질 분류기를 직접 학습하고, 데이터를 세분화된 품질 등급으로 나누어 좋은 자료 쪽으로 학습 비중을 기울였다.
  • PDF 처리: 비전-언어 OCR 모델에 자체 품질 분류기와 잘못 복원된 결과물을 잡는 결함 탐지기를 결합한 고처리량 파이프라인을 수천 개 GPU에 분산해 페타바이트 규모의 기술 데이터를 처리했다.
  • 연산 인프라: 6,144개의 NVIDIA GB300 NVL72 GPU 클러스터에서 4주 미만으로 사전학습을 끝냈다. 토폴로지를 인식하는 쿠버네티스 기반 스케줄러, 노드 수명주기 시스템, 반자동 되감기·재시작이 가능한 조용한 데이터 손상(silent data corruption, SDC) 탐지 시스템을 사내에서 구축했다.
  • 학습 안정성: 비결정적 그래디언트 노름 급등 또는 SDC로 의심되는 사건으로 반자동 되감기를 아홉 번 실행했고, 손실 곡선에는 큰 불안정이 관측되지 않았다고 한다(Figure 9).
  • Goodput: 후반에 92.3%에 도달했다. 원문 정의로는 최종 모델에 남은 학습 스텝에 쓴 실시간(wall-clock) 시간의 비율이다.

사전학습 뒤의 중간학습(midtraining)은 고연산 RL의 토대를 만들도록 설계했다. 실제 과제의 구조와 복잡성을 담은 다단계 데이터 큐레이션 파이프라인으로 학습 데이터를 만들었고, 효과적인 컨텍스트 길이를 100만 토큰으로 확장했다. 구조화된 코드 저장소, 장기 과제, 고품질 장문 문서를 조합해 긴 시퀀스에서 관련 정보를 찾아 이어 붙이도록 가르친다고 한다.

고연산 강화학습 — 10.5K GPU와 1억 회 이상의 롤아웃

원문은 고연산 RL을 Beam 스케일링의 중심 축으로 삼았다고 설명한다. 10.5K개의 NVIDIA GB300 GPU를 4주 동안 투입해 최대 컨텍스트 길이 256K 토큰으로 1억 회가 넘는 롤아웃을 생성했고, 학습과 채점에 약 13억 개의 샌드박스를 썼다. 원문은 이것이 지금까지 오픈 랩이 수행한 가장 큰 규모의 RL 가운데 하나라고 믿는다고 적는다. 평가 모음 전체에서 RL 연산을 늘릴수록 역량이 계속 향상되었고 정체 조짐은 없었다고 한다.

  • 환경: 합성 데이터 파이프라인 중심에 독점 벤더 데이터와 오픈소스 출처를 보탠 거의 100만 개의 환경을 만들었다. 도메인은 소프트웨어 엔지니어링, 터미널 사용, 경쟁 코딩, STEM, 웹 검색, 도구 사용, 일반 지식 업무이다.
  • 환경 큐레이션: 과제를 합성하거나 수집하고, 난이도(항상 풀리지도 불가능하지도 않게)와 품질(불명확하거나 추측·해킹이 가능한 과제 제외)로 걸러내며, RL로 시험해 다음 수집과 필터링에 반영하는 반복 과정이다.
  • 샌드박스: 최대 17만 개를 동시에 지원했고, 샌드박스 생성 요청은 10억 건을 넘었으며 20개 넘는 클러스터, 두 클라우드, 네 리전에 걸쳤다. 새 샌드박스의 90%는 10초 안에 준비되었다.
  • 비동기 실행: 학습 중 평균 11만 개의 롤아웃이 동시에 돌았다. 토큰마다 생성한 모델 버전을 태그해 정책 노후화(staleness)를 학습 알고리즘이 반영하게 했고, 현재 정책보다 107개 가중치 버전, 약 하루 뒤처진 샘플로 학습해도 수치가 안정적이었다고 한다(Figure 4).
  • 연산 배분과 가중치 갱신: 추론 대 학습 GPU 비율을 3.9:1에서 5.4:1까지 조정했다. 새 가중치는 추론 플릿에 중앙값 약 12초에 반영되었고, 랙 간 RoCE와 랙 내부 NVLink의 계층 전송으로 랙 간 트래픽을 75% 줄이고 반영 속도를 2.2배로 높였다.
  • 장애 복원과 패킹: 학습 중 추론 장애 71건을 학습 작업 중단 없이 처리했고 용량은 중앙값 8분에 복구되었으며, 손실 용량은 서빙 GPU 분 기준 0.02%였다. 동적 패킹으로 학습 배치는 평균 99.99% 찼다.

보상 설계에서는 성공한 해결을 보상하고 불필요한 토큰을 억제하는 조절 가능한 길이 페널티를 썼다. RL 초반에는 응답 길이가 줄면서도 성능이 향상되었고, 이후 에이전트 역량이 강해지면서 응답 길이가 다시 늘었으나 그 추가 토큰이 성능 향상을 뒷받침했다고 한다. 사용자는 추론 노력(reasoning effort) 파라미터로 이 균형을 조절할 수 있다. Figure 3은 전체 1억 회 이상의 롤아웃 가운데 추론 전문가 학습에 쓰인 8,000만 회를 보여 주며, 비교로 Inkling은 3,000만 회, MiMo는 75만 3천 회로 학습했다고 적는다.

벤치마크 표와 비교 모델 대비 위치

원문은 Beam이 서구권 오픈 가중치 프런티어를 전진시키며, 코딩과 에이전트 작업에서 더 큰 오픈 모델인 GLM 5.2와 경쟁할 만하고 Qwen 3.8 Max에 근접한다고 평가한다. 동시에 Kimi K3 같은 프런티어 오픈 모델이 원성능에서는 여전히 앞서며, Beam의 강점은 추론 시점의 효율이라고 적는다.

  • 코딩: SWE Bench Pro v1에서 65.5로 GLM 5.2(62.1)보다 높고 Qwen 3.8 Max(67.7)보다 낮다. Terminal Bench v2.1은 80.1로 GLM 5.2(81.0)와 거의 같다.
  • 추론과 STEM: AIME 2026은 97.8로 GLM 5.2(99.2)에 못 미치고, GPQA Diamond는 90.5, 도구 없는 HLE는 36.2이다.
  • 도구 호출과 검색: MCP Atlas 78.7, AutomationBench public 37.0으로 GLM 5.2의 77.8과 26.2를 웃돈다.
  • 선도 모델과의 격차: Kimi K3는 SWE Bench Pro v2-Hard 88.2, HLE 46.9이고 DeepSeek V4.1 Flash는 DeepSWE 74.2, Terminal Bench v2.1 90.6으로 표에서 Beam보다 높다.

표의 값은 Reflection이 발표한 것이며, 원문은 NR을 보고되지 않은 점수라고 설명한다. 같은 표에는 Inkling, Nemotron 3 Ultra, GLM 5.3 열도 있으나 아래 표에는 옮기지 않았다. 모델마다 비어 있는 칸이 달라서, 여기 적은 비교는 값이 모두 있는 칸에 한정된다.

「추론 연산량 3~4분의 1」 주장의 산출 공식과 배제된 비용

원문은 고급 추론 벤치마크에서 Beam이 GLM-5.2와 비슷한 점수를 내면서 추론 연산을 3~4배 적게 쓴다고 적는다. 2T+ 매개변수급 모델(예: Qwen 3.8-Max)과 비교하면 토큰당 훨씬 많은 연산이 필요하므로 효율 차이가 더 두드러진다고도 한다. 이 주장의 계산 분모는 Figure 2의 캡션에 있다. 아래는 그 캡션 전문이며, 읽기 쉽도록 문장마다 줄을 바꾼 것 외에는 원문 그대로이다.

캡션을 읽으면 이 비교의 전제가 드러난다.

  • 추정 공식: 생성 연산량은 활성 매개변수 수에 attempt당 평균 생성 토큰 수를 곱하고 2를 곱한 값이며, 곱셈-누산 1회를 2회 연산으로 센다.
  • 생성 토큰의 범위: 생성 토큰에는 추론 과정과 최종 답이 모두 포함된다.
  • MoE 매개변수 기준: MoE 모델은 전체 모델 크기가 아니라 토큰당 활성화되는 매개변수를 썼다.
  • 제외된 비용: 프롬프트 프리필, 문맥에 따라 달라지는 어텐션 연산, 서빙 오버헤드가 빠져서 측정된 추론 비용이 아니라 대략적인 연산 비교이다.

따라서 「3~4분의 1」은 GPU 클러스터의 전력이나 호스팅 비용을 잰 결과가 아니라, 활성 매개변수와 attempt당 평균 생성 토큰 수로 추정한 연산량의 비교이다. 공식상 attempt당 생성 토큰 수가 많은 모델일수록 추정 연산량이 커진다.

에이전트 전이 사례와 가중치 공개 전에 확인할 것

원문은 RL이 훈련 과제를 넘어 일반화되는 역량을 키우도록 설계했다고 설명한다. 추론, 소프트웨어 엔지니어링, 터미널 과제를 학습하는 단계에서 RL 혼합에 브라우징 과제가 없었는데도 브라우징 성능이 꾸준히 향상되었고, 웹 접근이 주어지면 다른 대규모 언어 모델을 검색해 질의하고 OCR API로 문서를 읽는 법을 스스로 익혔다고 한다. 원문은 Beam이 텍스트 전용이지만 텍스트로 표현된 다른 양식의 정보를 다룰 수 있다고 덧붙인다.

  • 시연 사례: p5.js 3D 우주 비행사 게임, 뉴욕 MTA 공개 데이터로 만든 실시간 지하철 지도, Gemma-4 소형 모델의 Text2SQL 미세조정 노트북 작성이 소개되었다. 노트북으로 Gemma를 미세조정해 보류 테스트 세트의 정확도가 66.5% 올랐다고 한다.
  • 육지·바다 실험: 180×90 격자의 16,200개 점 문제에서 95.5%를 맞혀 Opus 5(92.5%)와 Fable 5(97.8%) 사이라고 원문은 적는다. 이 값은 원문 자체의 시연 결과이다.
  • 안전과 정렬: 사전학습 체크포인트에서 별도의 SFT·RL 파이프라인으로 안전·정렬 모델을 하나 더 학습하고, 다중 교사 온폴리시 증류(MOPD)로 두 교사의 역량을 합쳤다. 안전 평가 결과는 모델 기술 보고서에 싣겠다고 한다.
  • 가중치 공개 뒤의 확인: 가중치 공개 때 Apache 2.0 조항이 실제 배포물에 어떻게 적용되는지는 공개된 라이선스 문서로 확인하는 것이 바람직하다.

요약하면 원문이 확인해 주는 것은 사양, 학습 규모, 발표된 벤치마크 값, 연산 추정 방식이다. 가중치를 직접 받아 서빙해 보기 전까지는 원문의 수치를 사실상 Reflection의 보고로 읽어야 한다. 서빙 프레임워크 지원 여부 같은 실무 정보는 원문에 없으므로, 아래 「확인하지 못한 것」으로 남긴다.

확인하지 못한 것

  • 가중치가 실제로 공개되었는지, 공개된 체크포인트의 용량과 양자화본 계획. 원문은 이달 안에 공개한다고만 적었다.
  • 501B 가중치를 호스팅하는 데 필요한 하드웨어 요구량. 원문에는 서빙 요구량이 없다.
  • vLLM, SGLang 같은 오픈소스 추론 엔진의 지원 여부와 시점. 원문은 여러 오픈소스 라이브러리와의 통합을 예고했을 뿐 구체 목록을 적지 않았다.
  • 사전학습 23.8조 토큰 가운데 웹, 공개 출처, 독점 라이선스 데이터의 구성 비율.
  • 벤치마크 표 값의 독립적인 제3자 재현. 표는 Reflection이 발표한 것이다.
  • Figure 2에서 모델별로 쓴 평균 생성 토큰 수의 원자료.
