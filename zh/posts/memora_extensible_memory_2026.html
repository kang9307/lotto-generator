Memora — 面向长期任务的可扩展AI记忆系统

突破上下文遗忘的壁垒，让AI智能体记住数日工作的方法

2026-07-01 IT/技术

引言：AI无法记忆的问题

任何与AI智能体进行多日项目合作的人都会遇到同样的困境：每个新会话都从零开始，昨天的决定今天需要重新解释，上周商定的约束条件凭空消失。即便上下文窗口扩展至128K或200K token，会话一旦结束，记忆便荡然无存。这不是token数量的问题，而是记忆架构的问题。

微软研究院正面应对这一问题，发布了Memora（MIT许可证，提交至ICML 2026）。截至2026年6月，该框架在GeekNews获得11分关注。它使AI智能体能够从对话和文档中自动提取所需信息，并实现长期存储、检索和更新。本文分析其与RAG管道或简单对话摘要方式的本质区别，以及这一设计对智能体生态的意义。

本文基于Memora官方GitHub仓库及相关报道。基准数值引用已公开的实验结果，但需注意这是ICML 2026提交阶段，尚未经过同行评审。

1. 仅扩大上下文窗口为何不够

1.1 上下文窗口的物理局限

上下文窗口如同RAM——可以保存当前运行内容，但程序关闭即消失。研究表明，即便是128K token的窗口，超过约80K后召回率也开始下降，模型倾向于偏重最近的输入而忽视前期上下文。将上下文填满在推理成本上也低效。截至2026年6月，全文本方式每次查询平均消耗超过26,000 token，而设计良好的记忆系统能以不足7,000 token实现同等甚至更高的精度。

1.2 什么是智能体的长期任务

代码智能体用一周时间对代码库进行重构、调研智能体历时数日完成报告、个人助手累积用户偏好实现个性化——这些都无法在单次会话内完成。智能体需要记得昨天如何修改了文件结构、用户一周前设定了什么约束。无论上下文窗口扩展多大，跨会话遗忘问题都无法从根本上解决。外部长期记忆层是架构上的必要组件。

2. Memora的三层记忆结构

Memora与现有方法最显著的区别在于记忆条目的表示方式。每个记忆项被分为三个组成部分。

2.1 Memory Value — 原文原样保存

Memory Value不进行索引，负责无压缩地保存原始信息，是最终传递给智能体的内容。将其排除在索引之外是核心设计决策。嵌入模型在将长文本压缩为向量的过程中会丢失细节信息、平坦化语义。通过将原始值排除在索引对象之外，检索由抽象层负责，传递由原文承担，实现了职责分离。

2.2 Primary Abstraction — 记忆的规范单位

Primary Abstraction被索引，是记忆值核心内容的一对一摘要，作为检索、更新和去重的基准点。新信息进入时，判断是否与现有记忆重叠的轴心就是这个抽象层。「Alice要搬到西雅图」这一Memory Value对应的抽象可能是「Alice的搬家计划」——一种可与检索查询对比的形式。规范单位这一表述很重要：同一事实以不同表述进入系统时，可以在同一抽象下进行合并和更新。

2.3 Cue Anchors — 多重语义入口

Cue Anchors是允许从多个角度访问同一记忆的多重索引，以「实体+核心方面」的组合构成，通过多对多结构让多个查询能找到同一记忆条目。例如，「Alice的工作变动」「西雅图搬家」「新工作」等不同表述的查询都能检索到同一记忆项目。这是对传统向量检索中查询-文档相似度单一轴依赖的突破。

2.4 这一设计的意义

三层分离将「存什么」与「怎么找」完全解耦。嵌入模型的语义压缩损失不影响原始信息，检索精度由抽象层和Cue Anchors负责。这一设计的实际效果体现在基准测试中：LoCoMo多跳问题较现有记忆方式提升+23.1分，时间推理提升+29.6分。

3. 记忆生命周期 — 从采集到检索

3.1 采集（Ingestion）：自动提取

Memora将对话或文档切分为主题性片段，从中自动提取事实性、情节性和程序性知识，形成结构化记忆条目。无需智能体明确发出「保存」指令。采集阶段同步检查与现有记忆的重复，重叠信息会被合并或更新，而非累积为独立副本。

3.2 存储：ChromaDB与Redis

默认存储为ChromaDB，将Primary Abstraction和Cue Anchors以语义嵌入向量进行索引。Redis用作快速结构化检索的Cue索引。本地和远程后端均支持，多个智能体共享同一记忆层的配置也可实现，还可按智能体或角色指定记忆范围以控制访问权限。

3.3 检索：四种策略

策略方式特点
Semantic向量相似度检索快速通用的语义匹配
PromptedLLM多步精化复杂查询精度高
Hybrid向量+BM25关键词语义与关键词平衡
GRPO强化学习驱动（实验性）本地轻量模型替代LLM调用

GRPO（Group Relative Policy Optimization）策略尤为值得关注。通过LoRA微调Qwen 3B/7B等轻量模型来承担检索策略决策，替代昂贵的LLM API调用，在推理成本敏感的环境中是颇具价值的实验方向。

4. Memora相较RAG与其他记忆框架的差异

4.1 与传统RAG的区别

RAG从预构建的外部知识文档（维基、手册、代码库等）中检索信息并注入LLM，存储的是「世界知识」，更新周期缓慢。Memora则聚焦于智能体自身经历的内容——与特定用户的对话历史、项目决策、个性化偏好。两者解决的问题根本不同。RAG与Memora是互补关系，而非竞争关系。但许多系统混淆了二者，试图用文档RAG替代对话记忆，这是错误的设计。

4.2 与平面记忆存储的区别

最简单的记忆实现是将对话累积至数据库并用向量检索提取相似历史。这种方法有两大局限：一是难以去重——同一事实以多种表述重复存储会产生检索噪音；二是难以更新——新信息进入时往往是新增条目而非修正现有条目。Memora基于Primary Abstraction的规范单位管理直接解决了这两个问题。

4.3 与图谱知识库的区别

MemGPT等图谱记忆方案将实体与关系结构化为图。表达能力强，但构建和维护成本高，非结构化情节信息难以映射为图结构。Memora通过内置的三层结构实现类似目标，无需外部图存储依赖。2026年的趋势正从外部图存储转向内嵌实体链接，与Memora的设计方向一致。

5. 智能体跨数日延续工作的意义

5.1 项目连续性

目前与AI智能体进行一周项目时，每次会话开始都需花几分钟重新交代「上次进展到哪里」。长期记忆运作良好后，这一开销将消失。智能体自行读取昨天的决定，延续今天的工作。代码智能体将记住文件结构变更历史、决策原因和待完成任务列表。

5.2 个性化的实质性实现

个性化一直是AI的目标，但会话重置导致实质实现受限。若长期记忆能积累用户的工作风格、偏好模式和反馈历史，智能体的响应将随时间不断优化。Memora的多智能体共享记忆架构还支持多个专业智能体共享同一用户上下文。

5.3 语音与非视觉界面

语音界面中用户无法滚动或复制历史对话，持久化记忆是唯一的连续性机制。2026年AI智能体记忆市场年增长率35%的背后，正是AI向语音、车载、IoT设备扩展的浪潮。

6. 实用评估

6.1 优势真正发挥的场景

Memora价值最直接的场景包括：历时数日至数周的代码项目、需累积用户偏好的个人助手、多智能体分工需共享上下文的系统、文档持续积累的知识管理管道。LoCoMo和LongMemEval中时间推理与多跳问题的显著提升与这些场景直接相关。

6.2 需要注意的局限

需要坦诚指出的局限：一、处于ICML 2026提交阶段，基准数值为作者报告，尚待独立验证；二、10倍规模时时间抽象性能下降25%；三、GRPO策略处于实验阶段，生产环境需谨慎验证；四、ChromaDB默认配置之外的大规模分布式存储集成需额外工作。

6.3 现实的引入路径

建议先确认自己的智能体任务中是否确实存在跨会话遗忘导致的问题。若有，长期记忆层的价值即可验证。Memora设计为插件式接入现有智能体系统，Python 3.10+环境下通过pip install -e .安装。从小型任务开始实验，通过LoCoMo基准脚本直接验证性能，是现实的起步方式。

7. 结论 — 长期记忆开启智能体的下一层能力

Memora提出的核心问题很简单：AI智能体要成为真正的长期协作者，就需要记忆。不是无限扩大上下文窗口，而是选择性地结构化存储所需内容——这才是现实且高效的方向。

Memora的三层结构（Memory Value / Primary Abstraction / Cue Anchors）是对这一问题的具体解答。将原始内容与检索索引分离，设置可更新的规范单位，以多重语义入口提升检索精度——这一设计精准切中了RAG与平面记忆的局限。

目前仍处于初期发布阶段，大规模环境的验证有待完成。但其方向本身——智能体跨数日延续工作——是2026年AI智能体走向实用化的核心条件之一。Memora作为这一方向的具体早期实现，值得深入关注。
