서론 - 정렬했는데 10이 9보다 앞에 온다

JavaScript에서 숫자 배열에 sort()를 비교자 없이 부르면 숫자가 숫자 크기가 아니라 다른 기준으로 줄을 선다. [1, 10, 9, 2]가 [1, 10, 2, 9]로 나오는 것이 가장 유명한 모양이다. 이 동작은 버그가 아니라 정의이며, 정의를 알면 비교자를 어떻게 써야 하는지, 어떤 값이 어디로 가는지, 잘못 쓴 비교자가 어떤 결과를 내는지가 한 줄로 이어진다.

축은 sort의 기본 비교자와 비교자 작성이다. 한글과 로캘이 정렬 순서를 바꾸는 문제는 한글 정렬이 기대와 다른 이유가 도구별로 자세히 다루었고, 배열 메서드 전반과 sort의 숫자 함정 한 줄은 JavaScript 기초 문법에 있다. 여기서는 비교자가 받는 값, 돌려주어야 하는 값, 깨뜨리는 입력을 출력으로 하나씩 확인한다.

다루는 질문은 다음과 같다.

  • 기본 비교자는 숫자를 어떤 기준으로 비교하는가.
  • 문자열 비교의 기준인 UTF-16 코드 유닛 순서는 코드 포인트 순서와 어떻게 다른가.
  • undefined·빈 칸·null·NaN은 어디로 가고 비교자는 그것들을 받는가.
  • 비교자는 무엇을 돌려주어야 하고, 불리언이나 불일치 비교자는 어떤 결과를 내는가.
  • 안정 정렬은 사양이 보장하고, 어떤 비교자가 그것을 깨뜨리는가.
  • toSorted·localeCompare·Intl.Collator는 어떤 자리에서 sort와 비교자를 대신하는가.

기본 비교자는 문자열 비교다

MDN의 Array.prototype.sort 문서는 기본 정렬을 이렇게 정의한다. 「기본 정렬 순서는 오름차순이며, 요소를 문자열로 바꾼 뒤 그 UTF-16 코드 유닛 값의 순서를 비교하는 방식에 기초한다.」 비교자가 없으면 undefined가 아닌 모든 요소가 문자열로 바뀌어 코드 유닛 순서로 비교된다는 문장도 있다. 아래 코드는 이 정의가 [1, 10, 9, 2]에 어떻게 나타나는지, 같은 배열을 문자열로 바꾼 것과 비교자를 준 것까지 나란히 출력한다.

console.log('node ' + process.version);
                    const a = [1, 10, 9, 2];
                    console.log(a.sort());
                    console.log([1, 10, 9, 2].map(String));
                    console.log(['1', '10', '9', '2'].sort());
                    console.log('10' < '9', 10 < 9);
                    console.log([1, 10, 9, 2].sort((x, y) => x - y));
node v22.16.0
                    [ 1, 10, 2, 9 ]
                    [ '1', '10', '9', '2' ]
                    [ '1', '10', '2', '9' ]
                    true false
                    [ 1, 2, 9, 10 ]

첫 정렬은 [1, 10, 2, 9]이다. 같은 배열을 문자열로 바꾸면 '1', '10', '9', '2'이고, 문자열 배열을 정렬한 결과 '1', '10', '2', '9'가 숫자 배열의 결과와 같은 순서이다. 문자열 '10'은 첫 글자 '1'(0x31)이 '9'(0x39)보다 작아서 '9'보다 앞에 온다. 마지막 두 줄의 비교가 이를 직접 보여 준다. 문자열 비교 '10' < '9'는 true이고 숫자 비교 10 < 9는 false이다. 비교자 (x, y) => x - y를 주면 [1, 2, 9, 10]이 된다.

  • 기본 정렬의 대상은 값이 아니라 값의 문자열 표현이다. 숫자 10과 9는 비교되지 않고 '10'과 '9'가 비교된다.
  • 배열이 한 자리 수로만 이루어졌다면 문자열 순서와 숫자 순서가 우연히 같아서 시험에서 통과한다. 두 자리 수가 섞이는 순간 어긋난다.
  • 비교자 (x, y) => x - y는 값 자체를 빼서 부호로 순서를 알린다. 정의 쪽에서 바꾸는 것이 아니라 비교의 기준을 문자열에서 숫자로 바꾸는 것이다.

문자열 비교는 UTF-16 코드 유닛 순이다

문자열을 비교한다는 것은 정의상 코드 유닛 단위의 비교이다. 대부분의 글자는 코드 유닛 하나이지만 U+FFFF를 넘는 문자(이모지 등)는 서로게이트 쌍으로 코드 유닛 둘이다. 이 차이는 기본 정렬과 코드 포인트 순서가 서로 다른 결과를 내는 경우를 만든다. 아래 코드는 이모지 U+1F600과 전각 문자 U+FF21을 일반 글자와 섞어, 기본 정렬과 코드 포인트 기준 비교자의 결과를 비교한다.

const words = ['\u{1F600}', 'Ａ', 'z', 'Z', 'a'];
                    const hex = w => 'U+' + w.codePointAt(0).toString(16).toUpperCase();
                    console.log('default      :', [...words].sort().map(hex).join(' '));
                    console.log('code point   :', [...words].sort((x, y) => x.codePointAt(0) - y.codePointAt(0)).map(hex).join(' '));
                    console.log('first unit of U+1F600 = 0x' + words[0].charCodeAt(0).toString(16).toUpperCase() + ', of U+FF21 = 0x' + words[1].charCodeAt(0).toString(16).toUpperCase());
default      : U+5A U+61 U+7A U+1F600 U+FF21
                    code point   : U+5A U+61 U+7A U+FF21 U+1F600
                    first unit of U+1F600 = 0xD83D, of U+FF21 = 0xFF21

기본 정렬은 Z, a, z, U+1F600, U+FF21 순서이고 코드 포인트 순서는 Z, a, z, U+FF21, U+1F600이다. 이모지의 첫 코드 유닛은 0xD83D이고 전각 A의 코드 유닛은 0xFF21이므로, 코드 유닛 순서에서는 이모지가 앞선다. 코드 포인트로는 0xFF21이 0x1F600보다 작아서 반대다. 대문자 Z(0x5A)가 소문자 a(0x61)보다 앞서는 것도 같은 기준에서 나온다. 일반 영숫자만 다루면 이 차이가 보이지 않으므로, 이모지나 보충 평면 문자가 들어올 때 정렬 순서가 직관과 어긋나는 일이 생긴다.

undefined·빈 칸·null·NaN은 어디로 가는가

MDN은 「모든 undefined 요소는 배열의 끝으로 정렬된다」고 적고, 빈 칸에 대해서는 「sort()는 빈 칸을 보존한다. 원본이 희소 배열이면 빈 칸은 배열 끝으로 옮겨지고 모든 undefined보다 항상 뒤에 온다」고 적는다. 이 두 문장이 비교자와 어떻게 만나는지는 비교자가 받은 인자를 기록하면 보인다.

const calls = [];
                    const r = [3, undefined, 1, , 2].sort((x, y) => { calls.push(x + ',' + y); return x - y; });
                    console.log(r, 'length', r.length, '| index 4 in result:', 4 in r);
                    console.log('comparator calls:', calls.join(' | '));
                    console.log('any call saw undefined:', calls.some(c => c.includes('undefined')));
                    console.log([3, undefined, 'a', null, NaN, 1].sort());
                    console.log([3, undefined, 'a', null, NaN, 1].map(String));
                    console.log([3, undefined, 1].sort((x, y) => y - x));
                    console.log(['z', undefined, 'a'].sort(), '| String(undefined) =', String(undefined));

  • 첫 줄은 [1, 2, 3, undefined, 빈 칸]이다. 길이는 5로 그대로이고 인덱스 4는 빈 칸으로 남았다. undefined가 앞, 빈 칸이 맨 뒤라는 MDN 문장과 같다.
  • 비교자가 기록한 호출은 숫자 쌍뿐이고, undefined가 인자로 들어온 호출은 없다. 비교자는 undefined와 빈 칸을 받지 않는다.
  • 내림차순 비교자 (x, y) => y - x에서도 undefined는 끝에 남았다. 비교자의 부호로 undefined의 위치를 바꿀 수 없다.
  • [z, undefined, a]의 기본 정렬은 a, z, undefined이다. String(undefined)는 문자열 undefined이고 이것은 z보다 작은 글자열인데도 끝에 놓였으므로, undefined는 문자열로 비교되지 않고 별도 규칙으로 맨 뒤에 간다.
  • null과 NaN은 undefined와 달리 문자열 null과 NaN으로 바뀌어 다른 문자열 사이에서 순서가 정해진다. 기본 정렬 결과에서 NaN은 3 뒤, a 앞이고 null은 a 뒤이다.

비교자는 음수·0·양수를 돌려주는 함수다

MDN은 비교자가 숫자를 돌려주어야 한다고 적는다. 음수는 a가 b보다 앞, 양수는 a가 b보다 뒤이고, 0 또는 NaN은 둘이 같다는 뜻이다. 더 형식적으로는 비교자가 순수하고, 같은 쌍에 같은 결과를 내고, 반사적(compareFn(a, a) === 0)이며, 반대칭적(compareFn(a, b)와 compareFn(b, a)가 모두 0이거나 서로 반대 부호)이고, 이행적이어야 한다고 적는다. 아래 코드는 올바른 비교자와 불리언을 돌려주는 비교자, 상수를 돌려주는 비교자를 같은 배열에 적용하고 천 개 난수 배열에서 정렬이 되었는지를 센다.

const nums = [10, 9, 1, 100, 2];
                    console.log('a - b       ', nums.slice().sort((x, y) => x - y));
                    console.log('b - a       ', nums.slice().sort((x, y) => y - x));
                    console.log('a > b       ', nums.slice().sort((x, y) => x > y));
                    console.log('a < b       ', nums.slice().sort((x, y) => x < y));
                    console.log('() => 1     ', nums.slice().sort(() => 1));
                    console.log('() => -1    ', nums.slice().sort(() => -1));
                    console.log('() => 0     ', nums.slice().sort(() => 0));
                    console.log('default     ', nums.slice().sort());

                    console.log('  a - b  ', inversions(big.slice().sort((x, y) => x - y)));
                    console.log('  a > b  ', inversions(big.slice().sort((x, y) => x > y)));

불리언을 돌려주는 a > b는 5개 입력에서 아무것도 바꾸지 못했고 천 개 입력에서는 하락이 496곳이나 남았다. 이 환경에서 Number(true)는 1, Number(false)는 0이다. 불리언 비교자가 돌려준 값은 0 또는 1이었다. 이 비교자는 같은 쌍에서 a, b에 1, b, a에 0을 돌려주어 MDN의 반대칭 성질을 위반한다. MDN은 구현마다 다르게 동작할 수 있어 다섯 가지 조건을 지켜 비교자를 잘 구성하라고 권고한다. 이 Node.js의 불리언 결과는 이 엔진의 값이며 다른 엔진에서 같다고 단정하지 않는다.

a - b 가 깨지는 입력 - 키 누락·문자열·BigInt

비교자 a - b는 숫자 사이에서만 올바른 부호를 낸다. 값이 없거나 숫자가 아닌 경우에는 뺄셈이 NaN이 되고, MDN은 비교자가 돌려준 NaN을 0과 같이 같다는 뜻으로 적는다. MDN은 또 비교자가 일관된 비교 결과를 내야 한다고 규정한다. 다음 코드는 키가 없는 객체, 문자열, BigInt에서 a - b가 내는 결과를 보인다.

const rows = [{ p: 4 }, {}, { p: 3 }, { p: 2 }, { p: 1 }];
                    console.log(rows.slice().sort((x, y) => x.p - y.p).map(r => ('p' in r ? r.p : 'none')));
                    console.log(undefined - 1, Number.isNaN(undefined - 1));
                    console.log(['b', 'c', 'a'].sort((x, y) => x - y));
                    console.log(['b', 'c', 'a'].sort((x, y) => (x < y ? -1 : x > y ? 1 : 0)));
                    try {
                      console.log([3n, 1n, 2n].sort((x, y) => x - y));
                    } catch (e) {
                      console.log(e.constructor.name + ': ' + e.message);
                    }
                    console.log([3n, 1n, 2n].sort((x, y) => (x < y ? -1 : x > y ? 1 : 0)));

                    NaN true
                    [ 'b', 'c', 'a' ]
                    [ 'a', 'b', 'c' ]

                    [ 1n, 2n, 3n ]
  • p 키가 없는 객체가 끼어 있을 때 이 입력의 출력은 [4, none, 1, 2, 3]이다. 위 MDN 문장과 출력을 나란히 둔 것이며 둘 사이의 인과는 이 출력으로 가르지 않는다. 예외도 경고도 없다.
  • undefined - 1은 NaN이다. 두 번째 줄의 NaN true가 그 증거이며, MDN은 비교자의 반환값 NaN을 같다는 뜻으로 적는다.
  • 문자열 [b, c, a]에 a - b를 쓰면 순서가 그대로 [b, c, a]이다. b - c도 NaN이기 때문이다. 문자열에는 a < b ? -1 : a > b ? 1 : 0이 필요하다.
  • BigInt에서는 a - b가 BigInt를 돌려주고 sort가 이를 숫자로 바꾸지 못해 TypeError(Cannot convert a BigInt value to a number)가 난다. 이 경우만은 조용히 틀리지 않고 즉시 드러난다.

안정 정렬과 동점 처리

MDN은 「버전 10(ECMAScript 2019)부터 사양이 Array.prototype.sort를 안정 정렬로 정한다」고 적는다. 안정 정렬은 비교자가 같다고 판정한 요소들이 입력 순서를 유지하는 성질이다. 아래 코드는 키가 0~4인 객체 1000개에서 비교자별로 정렬이 되었는지와 동점의 입력 순서가 유지되었는지를 검사한다. 마지막 줄은 보조 키로 먼저 정렬하고 주 키로 다시 정렬하는 두 번 정렬이다.

const make = () => Array.from({ length: 1000 }, (_, i) => ({ k: (i * 7919) % 5, i }));
                    const isStable = arr => arr.every((v, j) => j === 0 || arr[j - 1].k !== v.k || arr[j - 1].i < v.i);
                    const sorted = arr => arr.every((v, j) => j === 0 || arr[j - 1].k <= v.k);
                    const good = make().sort((x, y) => x.k - y.k);
                    console.log('k-only comparator : sorted', sorted(good), '| ties keep input order', isStable(good));
                    const tie1 = make().sort((x, y) => (x.k < y.k ? -1 : 1));
                    console.log('tie returns 1     : sorted', sorted(tie1), '| ties keep input order', isStable(tie1));
                    const tie2 = make().sort((x, y) => (x.k > y.k ? 1 : -1));
                    console.log('tie returns -1    : sorted', sorted(tie2), '| ties keep input order', isStable(tie2));
                    const two = make().sort((x, y) => x.i - y.i).sort((x, y) => x.k - y.k);
                    console.log('two passes        : sorted', sorted(two), '| ties keep input order', isStable(two));
k-only comparator : sorted true | ties keep input order true
                    tie returns 1     : sorted true | ties keep input order true
                    tie returns -1    : sorted true | ties keep input order false
                    two passes        : sorted true | ties keep input order true
  • 동점에서 0을 돌려주는 정상 비교자(x.k - y.k)는 정렬이 되었고 동점의 입력 순서도 유지됐다. 1000개 규모의 입력에서 얻은 결과이다.
  • 동점에서 -1을 돌려주는 비교자는 이 입력에서 정렬은 되었지만 동점의 입력 순서가 유지되지 않았다(출력의 false). 이 비교자는 같은 쌍에서 양쪽 순서 모두 -1이라 MDN이 적은 반대칭 조건을 충족하지 않는다. 결과가 그 위반 때문인지는 이 실험으로 가를 수 없다. 다음 항목의 동점 1 비교자도 반사성 조건을 충족하지 않는데 순서가 유지됐다.
  • 동점에서 1을 돌려주는 비교자는 이 Node.js에서 동점 순서가 유지됐다. 같은 반사성 위반인데 결과가 달랐다. 이 차이가 엔진의 인자 전달 방식에서 오는지는 이 출력으로 가를 수 없고 보장으로 읽지 않는다.
  • 마지막 줄의 두 번 정렬은 이 입력에서 결과가 정렬되었고 동점 순서도 유지되었음(두 값 모두 true)만 보인다. 입력이 이미 i 순서라 첫 정렬이 바꾸는 것이 없으므로 이 줄을 안정성의 증거로 쓰지 않는다. 안정성을 확인한 실험은 앞의 1000개 입력 실험이다.

sort는 원본을 바꾸고 toSorted는 복사본을 돌려준다

MDN은 sort()가 배열을 제자리에서 정렬하고 같은 배열에 대한 참조를 돌려준다고 적으며, 원본을 바꾸지 않고 정렬하려면 toSorted()를 쓰라고 적는다. 이 Node.js에서 두 메서드의 반환 관계를 출력으로 확인한 코드다.

const a = [3, 1, 2];
                    const b = a.sort();
                    console.log('sort():     same array', b === a, a);
                    const c = [3, 1, 2];
                    const d = c.toSorted();
                    console.log('toSorted(): same array', d === c, 'original', c, 'result', d);
                    console.log(typeof Array.prototype.toSorted);
sort():     same array true [ 1, 2, 3 ]
                    toSorted(): same array false original [ 3, 1, 2 ] result [ 1, 2, 3 ]
                    function

sort()의 반환값은 원본과 같은 배열(true)이고 원본은 [1, 2, 3]으로 바뀌었다. toSorted()의 반환값은 원본과 다른 배열(false)이며 원본은 [3, 1, 2]로 남고 결과가 [1, 2, 3]이다. 마지막 줄은 이 Node.js에서 Array.prototype.toSorted가 함수라는 확인이다. 정렬 결과를 공유 상태(상태 관리 라이브러리의 불변 배열, 이미 화면에 그려진 배열)에 쓰는 자리라면 복사본을 돌려주는 쪽이 의도치 않은 변경을 막는다. 비교자에 대한 규칙은 두 메서드가 같다.

숫자와 문자열이 섞였을 때

실제 데이터에는 숫자와 숫자 모양 문자열이 섞여 들어오는 일이 있다. 기본 정렬은 전부 문자열로 비교하고, a - b는 숫자로 바꿀 수 없는 값에서 NaN이 된다. 형식별 순위를 먼저 비교하는 비교자를 세워 결과를 나란히 두었다. 마지막 줄은 숫자 모양 문자열만 있는 배열에 a - b를 쓴 결과다.

const m = [10, '9', 1, 'a', 2, 'B'];
                    console.log('default      ', m.slice().sort());
                    console.log('a - b        ', m.slice().sort((x, y) => x - y));
                    const rank = v => (typeof v === 'number' ? 0 : 1);
                    const mixedCmp = (x, y) => rank(x) !== rank(y) ? rank(x) - rank(y)
                      : (x < y ? -1 : x > y ? 1 : 0);
                    console.log('typed cmp    ', m.slice().sort(mixedCmp));
                    console.log('numeric strs ', ['10', '9', '1'].sort((x, y) => x - y));
default       [ 1, 10, 2, '9', 'B', 'a' ]
                    a - b         [ 1, 2, '9', 10, 'a', 'B' ]
                    typed cmp     [ 1, 2, 10, '9', 'B', 'a' ]
                    numeric strs  [ '1', '9', '10' ]
  • 기본 정렬은 1, 10, 2, 9, B, a이다. 숫자 10이 숫자 2보다 앞에 오고 숫자 1 다음에 놓이는 문자열 순서가 이어진다.
  • a - b는 숫자 끼리는 정렬하지만 문자열 '9'가 숫자 사이(2와 10 사이)에 끼고 'a'와 'B'는 입력 순서대로 끝에 남는다. 숫자로 바뀌지 않는 값이 섞이면 결과가 부분적으로만 정렬된다.
  • 형식 순위 비교자는 1, 2, 10, 9, B, a로 숫자가 먼저 숫자 순서로, 문자열이 그 뒤에 코드 유닛 순서로 놓인다. 혼합 입력의 규칙을 비교자에 명시한 결과다.
  • 숫자 모양 문자열만 있으면 a - b는 문자열을 숫자로 바꿔 빼므로 '1', '9', '10'으로 정렬된다. 이 경우 정렬은 맞지만 요소는 문자열인 채로 남는다.

한글·로캘 정렬은 비교자로 푼다

문자열 정렬에서 코드 유닛 순서가 사람이 기대하는 순서와 다를 때는 비교자가 localeCompare나 Intl.Collator의 compare를 쓴다. 같은 문자열 목록을 기본 정렬, localeCompare, Intl.Collator, 숫자 옵션 순으로 정렬했다. 콜레이션 규칙의 자세한 도구별 비교는 한글 정렬 글이 다룬다.

const names = ['나', '다', '가', 'Z', 'a', 'B', 'ㄱ'];
                    console.log('default       ', [...names].sort().join(' '));
                    console.log('localeCompare ', [...names].sort((x, y) => x.localeCompare(y, 'ko')).join(' '));
                    const col = new Intl.Collator('ko');
                    console.log('Intl.Collator ', [...names].sort(col.compare).join(' '));
                    const files = ['파일10', '파일2', '파일1'];
                    console.log('default       ', [...files].sort().join(' '));
                    console.log('numeric true  ', [...files].sort(new Intl.Collator('ko', { numeric: true }).compare).join(' '));
default        B Z a ㄱ 가 나 다
                    localeCompare  ㄱ 가 나 다 a B Z
                    Intl.Collator  ㄱ 가 나 다 a B Z
                    default        파일1 파일10 파일2
                    numeric true   파일1 파일2 파일10

기본 정렬은 대문자 B, Z, 소문자 a, 한글 호환 자모 ㄱ, 완성형 음절 가, 나, 다 순서로 코드 유닛 순서를 따른다. localeCompare('ko')와 Intl.Collator('ko')는 이 Node.js에서 같은 결과(ㄱ, 가, 나, 다, a, B, Z)를 냈다. 이 순서에서 한글이 라틴 글자보다 앞서는 것은 이 환경의 ICU 데이터에 따른 값이다. 두 번째 목록에서 기본 정렬은 파일1, 파일10, 파일2이고 Collator의 numeric 옵션을 켜면 파일1, 파일2, 파일10이 된다. 같은 Collator는 한 번 만들어 compare를 재사용한다는 점은 위 한글 정렬 글이 성능 측정과 함께 다루었다.

  • 동점에서는 정확히 0을 돌려준다. 1이나 -1을 돌려주는 비교자는 반사성을 어긴다.
  • 불리언을 돌려주지 않는다. 비교자의 반환값은 숫자이고 true·false는 1과 0이 되어 음수가 없다.
  • undefined와 빈 칸은 비교자가 받지 않으므로 비교자 안에서 위치를 정할 수 없다. 끝에 두지 않으려면 정렬 전에 값을 채우거나 대체 키를 쓴다.
  • 원본을 유지해야 하면 toSorted를 쓰거나 복사본을 만든 뒤 sort한다.
  • 비교자를 바꾸었으면 숫자·문자열 혼합, 키 누락, 동점 순서가 들어 있는 시험 데이터로 확인한다. 5개짜리 입력만으로는 불리언 비교자도 우연히 통과할 수 있다.

확인하지 못한 것

  • ECMAScript 사양 본문의 Array.prototype.sort·SortCompare 알고리즘. 사양 페이지가 목차만 반환되어 MDN 문서의 서술만 인용했다.
  • Node.js 22 이외의 엔진(브라우저, Bun, Deno, 다른 Node.js 버전)에서의 불리언·불일치 비교자 결과와 비교자 호출 순서.
  • 불리언 비교자가 5개 입력에서 아무것도 바꾸지 못한 내부 이유. 정렬 알고리즘의 내부 구현은 이 Node.js에서 확인하지 않았다.
  • 동점에서 1을 돌려주는 비교자의 안정성이 다른 입력 크기·엔진에서도 유지되는지.
  • 대형 배열(수십만 건 이상)에서의 정렬 시간과 비교자 호출 횟수.
  • ICU 데이터 버전에 따른 한글·라틴 혼합 정렬 순서의 차이와 sensitivity·caseFirst 같은 다른 Collator 옵션의 효과.
  • TypedArray.prototype.sort의 기본 비교(숫자 순서라는 문서 서술)와 Array와의 차이.
