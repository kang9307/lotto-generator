契機 — 外部ハーネスによる文脈圧縮の限界とプレプリントの問題提起

大規模言語モデル（LLM）に基づく自律エージェントが長時間にわたる複雑なタスク（long-horizon tasks）を実行する際、真っ先に直面する物理的限界はコンテキストウィンドウの容量と計算コストの急増である。数十回に及ぶツール呼び出し、Web探索、コマンド実行結果が積み重なると、コンテキストは瞬時に数万から数十万トークンに達する。これまでエージェントフレームワークは、モデル外部の実行ハーネス（external harness）にヒューリスティックな制御器を設け、トークン上限に達した段階で過去ログを切り捨てるスライディングウィンドウを適用するか、要約プロンプトを用いて履歴全体を一括圧縮する手法をとってきた。

しかし、外部ハーネス主導のコンテキスト管理には本質的な構造欠陥が存在する。ハーネスの定型ルールは、現在の思考段階においてどの微細な情報が決定的に重要であるかを意味論的に理解できない。一括要約（summarization）の過程で、デバッグに不可欠なスタックトレースや厳密な引数定義が失われ、幻覚（hallucination）によって重要な文脈が歪められる事故が頻発する。逆に、すでに役割を終えた過去の膨大なツール出力がコンテキスト内に残留し続け、モデルのアテンションを分散させ、推論計算量を無駄に肥大化させていた。

2026年9月、Rulin Shao、Shannon Zejiang Shen、Nathan Lambert、Luke Zettlemoyer、Pang Wei Kohら13名の研究チームは、arXivを通じて「Context Language Models」（arXiv:2609.37725）と題したプレプリントを公開した。本研究は、コンテキスト管理の主権を外部フレームワークの静的な規則から、モデル自身の内生的な行動（intrinsic behavior）へと完全に移行させるパラダイムシフトを提唱している。公式アブストラクトに明記された問題意識と目標は以下の通りである。

  • 外部ハーネスによる機械的な切り捨てや一括要約が引き起こす情報喪失と幻覚リスクの克服
  • コンテキストそのものを完全なファイル（file）としてモデルに提示し、自律的な部分編集権限を付与
  • 現在の作業に真に必要な情報のみをモデル自らが判断して選択的に保持する自己調整機構の確立
  • 推論精度の向上と同時に不要なトークン蓄積を抑止し、サーバー側の浮動小数点演算量（FLOPs）を大幅に削減

このアプローチは、リッチ・サットン（Rich Sutton）が提唱した「The Bitter Lesson（苦い教訓）」の哲学と深く共鳴している。人間が考案した硬直的なヒューリスティック規則に頼るのではなく、汎用的な計算と学習を通じて、モデル自身に最適なコンテキスト管理ポリシーを獲得させる道筋を示している。

中核構造 — 文脈をファイルとして扱う無制約更新(Unrestricted Updates)

従来の標準的な言語モデルにおいて、コンテキストの拡張は純粋な追記専用（append-only）であった。新たなユーザー指示、ツール出力、モデル自身の推論ステップは、既存コンテキストの末尾に絶え間なく連結（⊕）される構造をとる。

これに対し、コンテキスト言語モデル（CLM）は、次のステップのコンテキスト全体をモデル自身が制御・変換する一般的な関数として再定義する。対話履歴やツール実行結果の全容を単一のファイルとして構成し、モデルに対してこのファイルに対する**無制約の更新（unrestricted updates）**を許可する。モデルはファイル編集コマンドを通じて、特定行の削除、冗長なログの縮約、過去の状態メモの上書きを自由に行うことができる。

// 従来の言語モデル(LM)の文脈遷移 (追記専用方式)
                    c(t+1) = c(t) ⊕ fLM(c(t))
                    
                    // コンテキスト言語モデル(CLM)の文脈遷移 (自律変換方式)
                    c(t+1) = fCLM(c(t))

この変更可能なファイル指向構造は、追記専用システムと比較して次の4つの運用上の利点をもたらす。

  • 重要情報の原文維持: 決定的な制約指示や特定のエラーコードは、粗い要約に巻き込まれることなくファイル内に原文のまま正確に維持される。
  • 局所的なその場更新: パズル盤面や作業進捗レジスタのような状態管理において、コンテキスト全体を再生成することなく該当行のみを直接上書き更新できる。
  • 不要ノイズの完全排除: Webクエリやコマンド実行で生じた数千行の一時的な出力は、必要な結論を抽出した直後にコンテキストファイルから完全に抹消できる。
  • ツール入出力と長期記憶の分離: ツール実行結果が永続的にコンテキストへ固定化されるのを防ぎ、ワーキングメモリとしての鮮度を維持できる。

これは、事前に定められた領域やタイミングでのみモデルの介入を認めていた従来の部分的アプローチを超え、コンテキストウィンドウ全体に対する完全な主権をモデルに委ねる設計である。

マルチエージェント展開 — ファイル単位の文脈共存と状態共有

コンテキストをファイルとして扱う設計は、システムをマルチエージェント（multi-agent systems）協調環境へと拡張する際に極めて大きな構造的優位性を発揮する。従来のマルチエージェント基盤では、メッセージキューや共有黒板（blackboard）オブジェクトを介して通信を行っていたため、直列化のオーバーヘッドが発生し、対話履歴の混濁によるコンテキスト汚染が頻発していた。

論文アブストラクトによると、CLMのファイルインターフェースは、複数のエージェントのコンテキストが個別のファイル（files）として同一環境内に共存する形態へと自然に拡張される。エージェントごとの作業領域が物理的に分割されることで、明確なアーキテクチャ境界が生まれる。

  • 各エージェントは独立した作業ファイルを保持し、自身のタスク状態とツール実行結果を安全に隔離管理できる。
  • 他エージェントの成果を参照する際は、煩雑なブロードキャスト通信を行わず、指定された共有ファイルを読み出す形態をとる。
  • 特定エージェント内で発生した推論エラーやコンテキスト破壊が、他エージェントのファイルへ波及しない堅牢な障害隔離が成立する。
  • 大規模エージェント群（swarm）において、全エージェント間での無駄なメッセージ複製が根絶され、トークンの浪費が抑制される。

アブストラクトに記された「24時間のマルチリポジトリ・エージェントスウォーム課題において、同一計算量で65%大きな性能改善を達成した」という結果は、このファイル分離による効率的な状態共有機構に裏付けられている。

ベンチマーク実測値 — ゼロショット環境で実証された精度向上と計算量削減

CLMの有効性を客観的に評価するため、論文ではタスク固有の追加ファインチューニングを行わない**ゼロショット（zero-shot）**条件下で、既存の最先端（SOTA）文脈管理手法との性能比較を実施した。アブストラクトで公式に確認された実測データは以下の通りである。

評価ベンチマークタスク特性および評価条件従来SOTA比のCLM実測成果
BrowseComp-Plus長時間のWeb調査および深層推論タスク精度が相対比較で11.4%向上、計算量(FLOPs)が21.5%削減
EdgeBench (12時間)複雑なエッジケースおよび長期作業シミュレーションスコアが5%向上、計算量(FLOPs)が59%削減
Agent-Swarm (24時間)複数コードベースを対象とするマルチエージェント協調同一計算量の投入条件下で65%大きな改善幅を達成
BrowseComp-Plus (Qwen3.5-9B オンラインRL)オンライン強化学習を適用したオープンモデル評価精度が47.6%大幅向上、計算量(FLOPs)が12%追加削減
推論高速化 (Suffix Cache Reuse)標準的なSGLangサービングエンジンとの対照評価同等精度を維持したままサーバー側計算量を35%削減

実測データ全体から導き出される共通した傾向は、以下の3点に整理される。

  • 精度向上と計算量削減の同時達成: 精度を高めながらFLOPsを21.5%から59%削減することに成功した。
  • 長期タスクでの優位性の拡大: 実行時間が12時間へ延びるにつれ、外部要約方式に対する計算量削減幅が59%へと急拡大した。
  • 複数リポジトリ協調での相乗効果: 24時間のコードベース横断スウォーム課題において、同一計算量で65%大きな性能改善を達成した。

これは、モデル自身が不要なテキストを積極的に剪定（pruning）することで、アテンション演算に投入される有効トークン数そのものを劇的に抑制した結果である。特に12時間のEdgeBenchにおいて計算量が59%も削減された事実は、タスクが長期化するほど外部要約方式に対するCLMの優位性が指数関数的に拡大することを示している。

戦略の最適化 — 自然言語指示の進化とオンライン強化学習の成果

コンテキスト管理を外部ハーネスの固定コードからモデルの内生的行動へと移管したことで、コンテキスト管理ポリシーそのものを**インコンテキスト学習やパラメータ強化学習**によって継続的に最適化できる新たな道が切り拓かれた。

研究チームは、標準的なスキル最適化ループ（skill-optimization loop）を通じて、モデルが参照するコンテキスト編集指示（natural-language instructions）を進化させた。どのような形式でログを圧縮し、どの粒度で状態を維持すべきかという指示文を自動洗練させることで、計算量を削減しながら保留評価セットにおける精度を**最大35.9ポイント**向上させた。

さらに著者らは、CLMのためのオンライン強化学習（online reinforcement learning）手法を導入した。オープンモデルであるQwen3.5-9Bに対して強化学習を実施したところ、BrowseComp-Plusにおいて**精度が47.6%急増し、同時に計算量が12%削減**される成果を得た。この最適化プロセスから明らかになった技術的示唆は以下の通りである。

  • 自然言語による指示文の自動洗練のみで、保留評価セットにおける精度が最大35.9ポイント向上する
  • モデルパラメータ自体に編集ポリシーを学習させることで、中規模モデルでも計算量の削減が達成される
  • オープンモデルQwen3.5-9Bで47.6%の大幅向上を確認し、大規模商用モデルに匹敵する安定性を獲得できることを実証
  • プロンプトに基づくインコンテキスト指示とパラメータ強化学習の相互補完的な融合パスを確立

サービング最適化 — Suffix Cache ReuseとKVキャッシュ再利用機構

コンテキストの任意の位置を自由に編集できる仕組みは理論上優れているが、LLMの推論インフラの観点からは極めて深刻な課題を突きつける。現代の高スループット推論エンジン（vLLMやSGLang等）は、コンテキストの前半が静的に不変であることを前提とする**プレフィックスキャッシング（Prefix Caching）**に依存しているためである。

従来のプレフィックスキャッシングでは、コンテキストの途中や前半にあるツール結果が編集されると、位置エンコーディングのずれによってそれ以降のすべてのKey-Value（KV）キャッシュが無効化（invalidation）されてしまう。その結果、わずかな編集を行うたびに後続の全トークンのKVキャッシュをサーバー側で再計算（prefill recomputation）しなければならず、サービング負荷が跳ね上がる。

// 従来の一般的なプレフィックスキャッシング (Prefix Caching)
                    [ システム指示 (キャッシュ適用) ] -> [ 途中編集箇所 (キャッシュ無効化) ] -> [ 後続全体をゼロから再計算 ]
                    
                    // CLMで共同設計された Suffix Cache Reuse 構造
                    [ システム指示 ] -> [ 局所編集箇所 ] -> [ 変更のない後続文脈 (サフィックスキャッシュ適用) ]

このボトルネックを打開するため、著者らは推論サービングと協調設計した**Suffix Cache Reuse（接尾辞キャッシュ再利用）**技術を提案した。コンテキストの中間が書き換えられた場合でも、後方に位置する未変更のテキストブロックを検出し、そのKVキャッシュを再利用する機構である。アブストラクトによると、この設計により標準的なSGLangと比較して**サーバー側計算量を35%追加削減**することに成功した。モデルの自律編集アルゴリズムと推論インフラの協調設計が不可欠であることを物語っている。

固定ハーネス規則に対する設計選択のトレードオフと運用課題

優れたベンチマーク結果が示された一方で、外部ハーネスの保護を排してモデルに文脈編集の全権を委ねるアプローチには、実運用上の無視できないトレードオフが存在する。

  • 基盤指示や安全方針の誤消去リスク: モデルが無制限にコンテキストを編集できる場合、悪意あるプロンプトや推論の混乱により、最上位のシステムプロンプトや安全ガードレールを自ら消去してしまう危険がある。
  • ツールインターフェースの構文破壊: ツールのスキーマ定義や引数規則を自己流に要約・書き換えてしまい、以降のツール呼び出しが文法エラーで失敗する恐れがある。
  • 編集処理自体のトークンオーバーヘッド: 編集コマンドの生成やテキスト置換のためのトークンを消費するため、短時間の単純タスクでは外部ハーネスよりも総コストが高くなる場合がある。
  • 専用サービングインフラへの依存:アブストラクトには、商用マネージドAPIでの計算削減効果に関する記載がない。
  • デバッグと決定論的再現の困難さ: コンテキストがモデルの動的判断で変形し続けるため、過去の異常終了ログから同一の失敗挙動を再現して監査することが難しくなる。
  • モデル能力による編集精度の格差: Qwen3.5-9Bでの成功例が示されたものの、より小型のモデルでは何を消して何を残すべきかの判断を誤り、タスクを早期破綻させるリスクが高まる。
