简短答案 — 约束定了工具基本也定了

选工具看起来像口味问题，但只要把两个约束定下来，候选就会收缩到两三个。第一，编辑器能不能换。第二，是否必须给支出设上限。这两条定了再看模型性能就够了。反过来做，就会选中一款性能不错却过不了内部审批的工具。

  • 编辑器不能换 → GitHub Copilot、JetBrains AI、Amazon Q Developer，它们挂在现有 IDE 上
  • 编辑器可以换 → Cursor、Devin Desktop、Zed，专用编辑器才进入候选
  • 要在终端和 CI 里跑 → Claude Code、OpenAI Codex CLI、Gemini CLI
  • 想自己挑模型提供方 → Cline、Zed、Aider，都是插自己 API 密钥的结构
  • 已经有 AWS 合同、不想再走一遍供应商流程 → Amazon Q Developer，直接并进已有账单
  • 支出上限是硬要求 → GitHub Copilot 的预算与告警、Claude for Teams 与 Enterprise 的席位配额加支出上限、Amazon Q Developer 的席位固定价
  • 想按美元整数读支出 → JetBrains AI，1 积分固定等于 1 美元，不需要换算
  • 想几乎零成本起步 → Gemini CLI 用 Google 账号登录每天 1000 次请求，Copilot Free 每月 2000 次代码补全，Cline 与 Aider 的客户端免费只按模型计费

如果到这里答案已经出来，后面当作证据核对即可。如果还没出来，第 5 节和第 7 节会替你做决定。

2026年5月以后真正变了什么

这篇文章的第一版写于 2026 年 5 月。三个月里计费结构变了，还有一款产品丢掉了名字。

Windsurf 变成了 Devin Desktop

2026 年 6 月 2 日，Cognition 把 Windsurf 改版为 Devin Desktop。老用户以自动更新的方式收到，套餐和设置保持不变。本地智能体 Cascade 只能用到 7 月 1 日，之后要换成用 Rust 重写的 Devin Local。这次改版的实质不是名字，而是用看板管理多个智能体的 Agent Command Center，以及让智能体之间共享上下文的 Spaces。产品性格从单一编辑器挪到了智能体编排器。

实际会咬人的是自动化。如果 CI 流水线或脚本里直接调用 cascade，那条调用已经断了。如果内部文档里钉了 Windsurf 时代的链接，现在会跳到 devin.ai，锚文本也要一并整理。

GitHub Copilot 从高级请求换成了 AI 积分

过去的 Copilot 按请求数计，比如 Pro 每月 300 次高级请求。现在每档套餐带的是以美元标价的 AI 积分。Pro 每月 10 美元含 15 美元，Pro+ 39 美元含 70 美元，Max 100 美元含 200 美元。个人侧新增了 Max，Business 与 Enterprise 则有组织级的积分池。

从请求数换成金额对用户是好事。请求数时代要知道每个模型的倍率才能算出余量，现在剩下的积分就是剩下的钱。要注意的是用贵的模型，同样一次请求会把积分烧得更快。Copilot 代码评审自 2026 年 6 月 1 日起适用倍率 13。

Cursor 的个人套餐分成了三档

在每月 20 美元的 Pro 之上新增了 Pro Plus 每月 60 美元与 Ultra 每月 200 美元，分别包含 20、70、400 美元的第三方模型用量。Ultra 是花 200 美元买 400 美元用量，单价最划算，同时也是最容易白扔 200 美元的一档。

Copilot 免费版与个人版的训练默认值变了

自 2026 年 4 月 24 日起，GitHub 可以把 Free 与 Pro 用户的输入、输出、代码片段及相关上下文用于训练与改进 AI 模型。设置里有一个 Allow GitHub to use my data for AI model training 开关，关掉是用户自己的事。同一份文档写明 Business 与 Enterprise 的客户数据不用于训练。如果公司里存在用个人套餐碰公司代码的做法，这一行会最先卡住上线。

两条路线 — 终端智能体与编辑器内置

十款摆在一起看着复杂，实际的分岔只有一个。是人看着代码去叫 AI，还是 AI 干完活由人来审。这个差别决定了计费形态，也决定了团队怎么运转。

这不是二选一。真实落地会收敛到给所有人配编辑器内置型，只给需要的人配智能体型。全员配智能体，费用分布就管不住；一个都不配，迁移这类大活就永远留在待办里。

Devin Desktop 正在把这条界线弄模糊，这一点值得记住。它从编辑器出发，如今把管理多个智能体的看板放在了最前面。Claude Code 从另一头走向同一个位置：从 CLI 起步，陆续加上 VS Code 扩展、JetBrains 插件、桌面应用和网页，而 CLAUDE.md 与 MCP 配置在所有界面之间共享。

怎么读积分

JetBrains 的做法最好读。1 积分钉死在 1 美元，剩下的积分就是剩下的钱。官方文档还给出了 1 积分能做多少事的大致量：AI 聊天里生成代码约 10 次，编辑器内生成代码约 40 次，代码解释约 25 次，写文档约 280 次，生成提交信息约 140 次。同样 1 美元买得到 140 条提交信息，或者 10 次聊天里的代码生成。这 14 倍的差距就是积分计费的本质。

Copilot 同样把积分标成美元，但另有模型倍率。文档说每个模型都有基于复杂度与资源消耗的高级请求倍率，并且明确代码评审功能自 2026 年 6 月 1 日起适用倍率 13。把代码评审接成每个 PR 自动跑，积分会比谁的预算都干得快。

由此得出的运营原则很简单。贵的功能只在人明确调用时才跑，自动触发只挂在便宜的功能上。不守这条，积分余额曲线会在月初一周内像断崖一样掉下去。

这张表在哪里分出高下

空格越多的一行，上线后在预算会上越难解释。尤其是Cursor 的团队分析偏向活动量指标，支出明细不在同一个屏幕上。聊了多少次、采纳了多少 Tab 补全、AI 写的代码占多少比例都有，唯独没有谁花了多少。活动看得见钱看不见，一旦出现超额账单，就很难把原因落到具体的人。

另一端是 Claude Code。/usage 把会话令牌统计和套餐余量并排放，并把近期消耗按技能、子智能体、插件与 MCP 服务器拆成占比。当长上下文或缓存未命中占到近期用量的 10% 以上时也会单独标出。组织侧可以用 OpenTelemetry 把 claude_code.cost.usage（美元）、claude_code.token.usage、claude_code.lines_of_code.count 等指标送进自建监控栈。这是唯一一条不必等厂商面板、就能在自家 Grafana 上立起按开发者划分的成本面板的路。

官方文档给出的基线也有用：企业部署平均为每位开发者活跃日约 13 美元、每月 150 到 250 美元，90% 的用户活跃日低于 30 美元。这组数字应当用来对照试点结果，而不是用来报预算。自家团队均值到了活跃日 40 美元，说明用法有问题；只有 5 美元，说明工具实际上没人用。

当工具完全不显示金额时，自己测算成本的办法写在AI编程工具里的金额消失了里。

上下文变成费用的区间

在智能体型工具里把账单撑大的是习惯，不是模型。Claude Code 官方文档点出的原因很具体。

  • 长会话。整段对话随每次请求发出，所以在开了一整天的会话里问一行问题，也会按当天全部历史产生用量
  • 缓存未命中。超过缓存寿命后再发的第一条消息会重新处理整个上下文。订阅制下寿命是 1 小时，开始动用 usage credits 后是 5 分钟，用 API 密钥或云厂商时默认 5 分钟
  • MCP 服务器过多。工具定义会吃掉窗口。文档建议 gh、aws、gcloud 这类 CLI 工具，上下文效率优于 MCP 服务器
  • 智能体团队。成员在计划模式下运行时，令牌消耗约为标准会话的 7 倍，这也是该功能默认关闭的原因
  • 压缩大上下文。/compact 需要读完它要总结的对话，本身就是一次大请求。不需要连续性时，费用为零的 /clear 更好

把这份清单原样贴到团队上手文档的第一页，试点费用会明显下降。多数超支不是来自难题，而是来自没清掉的会话。

可以直接交给安全评审的问题

  1. 在我们所用的套餐下，代码与提示词是否会用于训练模型。各套餐答案不同，不要按品牌回答
  2. 关闭训练的开关在组织管理员手里，还是在每个开发者手里
  3. 对话与代码在厂商服务器上留多少天。无留存选项是标准合同的一部分，还是需要另行谈
  4. 能否按用户取出用量与支出。只有界面，还是也有 API
  5. 能否按组织、分组与个人分别设置上限
  6. 是否有过滤器可以挡下与公开代码雷同的建议
  7. 合同里是否有针对生成代码的知识产权赔偿条款
  8. SSO、SCIM 与审计日志能否接上我们的身份提供方
  9. 本机上会留下什么。Claude Code 文档写明会话记录以明文缓存在 ~/.claude/projects/ 下，默认 30 天，保留期可配置
  10. 能否关闭遥测，一个环境变量够不够

第 9 条最常被漏掉。服务器侧签了无留存协议，开发者笔记本上却堆着 30 天的明文会话记录，那份协议只履行了一半。

最后一行经常被误读。工具开源与数据不被用于训练之间没有关系。Cline、Gemini CLI、Aider 的客户端都是开放的，提示词最终仍然会发到某个模型提供方的服务器。安全评审要读的文件是那家提供方的条款。

两周试点的设计

开三次选型会不如做一次两周试点准确。条件只有一个：在开始之前把要测的项目定下来。结束后再定，标准就会被结果牵着走。

测量项怎么测判定标准
人均日支出按天记录工具的用量界面或遥测数据与官方文档的基线对照：活跃日约 13 美元，90% 低于 30 美元
支出分布分别看中位数与前 10%，不要只看均值若一个人占掉团队一半支出，那是用法问题
完成的任务数试点期内合并且由工具参与的 PR与同长度的上一个迭代对比
回退比例工具产出的改动中被 revert 或返工的比例这个值高，速度上的收益会被抵消
评审时长从 PR 创建到批准写得快评审慢，总时长并没有变
会话卫生会话平均长度、压缩发生次数看长会话是否与支出前列的人重合
推行阻力安装后连续三天以上没用的人的比例若一半人没碰过，问题在上手引导而不在工具
安全评审通过情况第 10 节的十个问题是否都有答案只要有一个没答案，扩大铺开就先押后

试点的运行规则

  • 人数 5 到 8 人，其中一半用对工具持怀疑态度的人来填。全是热心用户，结论永远是好的
  • 不要让两款工具做同一件事。时间翻倍而比较信息增加有限，不如给每款工具分配不同类型的活
  • 第一周结束就把用量界面公开给全组。支出被看见的那一刻，习惯就会变
  • 把 /clear、/compact 这类上下文管理命令和选模型的标准写进上手文档的第一页
  • 智能体团队与并行执行等功能放到第二周再开。第一周就开，费用数据会被污染
  • 不要等结束再签合同，要在试点期间真的去点一遍上限设置和支出报表。有界面和好用是两回事
  • 试点仓库要用真实的业务代码。示例项目上下文小，费用和质量都会跟真实情况不一样
  • 最后一天的复盘先读指标再听感受。顺序反过来，印象会盖过数字

费用飙升的位置与止损办法

超预算多半不是一次戏剧性的事故，而是反复出现的小习惯。按症状查原因的表，在实务里比一串建议更有用。

症状原因处理
月初一周积分就去掉一半贵的功能挂在了自动触发上，通常是代码评审关掉自动触发，改为人工调用。Copilot 代码评审倍率是 13
一行的问题也记很大的用量会话没清，整段对话每次都被发出去换任务就 /clear，只有需要连续性时才 /compact
午饭后的第一次请求特别贵缓存寿命已过，整个上下文被重新处理休息后开新会话，或者从摘要恢复
做类似的活，人和人差五倍默认模型设成了最高档且从没改过默认改成中档模型，难题才用高档
刚开始对话上下文就少了一半MCP 服务器太多，或者指令文件太长停用不常用的服务器，把长指令拆成技能
并行作业之后用量猛涨智能体成员各自维持上下文窗口缩小团队规模、成员用中档模型、完事就关掉
只要做日志分析就贵大量输出原样进了上下文用钩子预处理只传需要的行，或交给子智能体
出了超额账单却不知道是谁的没有按用户归属的手段回到选型这一步。这个问题运营解决不了

最后一行就是全文的概括。前七条可以靠运营修好，但选了一款没有归属手段的工具，运营修不好。所以成本可见性要提到和性能同一等级的选型标准上。

锁定与迁出成本

用上一年左右，工具就不好换了。提前知道什么会绊住脚，就能把这些部分做成可迁移的形状。

积累下来的资产能不能迁重建成本
项目指令文件（如 CLAUDE.md）是纯文本，能迁低，只需对齐格式
自定义技能与斜杠命令各家格式不同中等，逻辑还在，只重写外壳
钩子与自动化脚本钩子事件名是各工具专有的中等
MCP 服务器配置支持 MCP 的工具之间可以迁低
CI 流水线集成调用命令是各工具专有的高。Cascade 终止时真正出问题的就是这里
团队的使用习惯迁不走清单里最贵的一项
用量与费用历史基本迁不走基线要重新积累
连编辑器一起换掉的情况扩展、快捷键、配置全都要牵动高

降低迁出成本有两个务实的做法。第一，让自动化去调用 Shell 脚本而不是工具命令。只在脚本里调用工具，换的时候改一个文件就够了。Cascade 停用时慌张的只有直接在流水线里调用它的团队。第二，把指令提交进代码仓库。只存在于厂商账号里的配置，合同一结束就一起消失。

在中国大陆落地时

价格表全是美元，所以在大陆落地时真正左右判断的，往往是表上没有的项目。

付款与报销

  • 价格全部以美元计价，换汇时点与跨境刷卡手续费会每月叠加，表里的美元数字与最终入账金额并不一致
  • 多数厂商只出具 invoice。报销流程最好在付款之前就确认好
  • 部分产品的年付折扣可观。Claude Pro 年付折合每月 17 美元（一次性 200 美元），月付 20 美元；Team Standard 年付每席 20 美元，月付 25 美元
  • 已经有 AWS 合同的团队，Amazon Q Developer 的流程最短，直接并入现有账单，不必新增供应商，也不必新增支付方式

企业落地常见的卡点

  • 让每个人自己买个人版再报销看着省事，但GitHub Copilot Free 与 Pro 的训练默认值决定了它不适合处理公司代码。要以策略强制就必须升到组织套餐
  • 客户端能否连通、厂商是否在你所在区域提供服务，属于各家的区域政策，本文没有逐一核实，落地前需要自行验证
  • 如果合规要求代码不出境，结构上能走的只有自带密钥这条路。Cline、Aider、Zed、Gemini CLI 的客户端是开源的，模型端点可以替换
  • Claude Code 的终端 CLI 与 VS Code 支持第三方模型提供方，也支持 Amazon Bedrock、Google Cloud 的 Agent Platform 与 Microsoft Foundry，数据落点由所选后端决定
  • 需要审计就不能只有界面。能否按用户导出支出，是 CSV 还是 API，要在签约前确认
  • 席位少的团队要看最低签约条件。Zed Business 走订单合同最低 25 席，低于这个数按自助方式处理

实务组合

在这种约束下最容易走通的组合，是把席位固定价的工具铺给全员，智能体型只对少数人单独审批。前者预算固定、好解释，后者人数少、超额可控。反过来把按量计费的工具对全员开放，第二个月的账单就会引出你本想避开的那场对话。

常见问题

只能选一款时看什么

先确定两件事：编辑器能不能换，是否需要支出上限。这两条会把候选压到两三个，然后再比模型性能就够了。从性能开始看，往往会选中一款过不了内部审批的工具。

固定月费为什么还会撞上限

现在的个人套餐大多在固定费里包着用量预算。Copilot Pro 是 10 美元含 15 美元积分，Cursor Pro 是 20 美元含 20 美元模型用量，JetBrains AI Pro 是 10 美元含 10 积分，Zed Pro 是 10 美元含 5 美元代币。预算用完就撞上限或者产生超额账单。

同时用几款是不是浪费

轴不同就不浪费。一款编辑器内置型和一款终端型做的活并不重叠。把同一条轴上的两款工具都留着才是浪费。

用开源工具数据就安全吗

客户端开源与数据不被用于训练是两回事。Cline、Gemini CLI、Aider 的提示词都会发到某个模型提供方的服务器。要读的文件是那家提供方的条款。

脚本里还在调用 Cascade 怎么办

2026 年 7 月 1 日之后已经不能用了，需要改成调用 Devin Local。顺便清理内部文档里的 windsurf.com 链接，它们现在会跳到 devin.ai。

模型价格去哪里看

工具套餐与模型 API 单价是两条轴。每百万令牌的单价以及缓存与批量折扣，都在2026年 AI模型综合对比里。

# AI编程工具选型清单 — 对比表、选择标准、落地检查表

> 出处: braindetox.kr — AI编程工具2026实战比较
> 这份文件不是排行榜，而是一套**选型流程**。可以原样复制进内部文档使用。
> 所有数值的核对日期为 2026-08-04。空格表示厂商未公开该数值。
> ⚠ 模型 API 单价不在这里。工具套餐与模型单价是两条不同的轴。

## 0. 前提 — 只要定下两件事，候选就会收缩

| 先确定的事 | 随之确定的事 |
|---|---|
| 编辑器能不能换 | 挂在现有 IDE 上还是用专用编辑器 |
| 是否必须给支出设上限 | 席位固定价还是积分按量 |
| 是否要在终端与 CI 里跑 | 智能体型是不是必需 |
| 模型提供方是否由自己挑 | 需不需要自带密钥的结构 |

- 从性能开始看，往往会选中一款过不了内部审批的工具
- 同样 20 美元在不同厂商买到的东西不一样，不要只比月费

## 6. 费用飙升的位置 — 从症状查原因

| 症状 | 原因 | 处理 |
|---|---|---|
| 月初一周积分去掉一半 | 贵的功能挂在自动触发上 | 改为人工调用 |
| 一行的问题也记很大用量 | 会话没清 | 换任务就 `/clear` |
| 休息后第一次请求特别贵 | 缓存未命中 | 开新会话或从摘要恢复 |
| 人和人差五倍 | 默认模型停在最高档 | 默认改成中档模型 |
| 刚开始上下文就少一半 | MCP 服务器太多或指令太长 | 停用不用的服务器，指令拆成技能 |
| 并行之后用量猛涨 | 智能体成员各自持有上下文 | 缩小团队、用中档模型、完事就关 |
| 只有日志分析贵 | 大量输出原样进上下文 | 用钩子预处理或交给子智能体 |
| 出了超额账单不知道是谁 | 没有按用户归属的手段 | **运营解决不了，回到选型** |

## 8. 降低锁定的两个做法

1. **让自动化调用 Shell 脚本而不是工具命令。** 换工具时改一个文件就够了。Cascade 停用时真正出问题的就是这里
2. **把指令提交进代码仓库。** 只存在于厂商账号里的配置，合同一结束就会一起消失

复制后可直接粘贴到笔记应用或 AI 工具中。
