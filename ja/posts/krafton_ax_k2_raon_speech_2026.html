はじめに: 書き起こしが崩れる場所はいつも同じだ

録音した会議を自動で書き起こしたことがある人なら、出力に同じ模様を見つける。ふつうの文は驚くほどきれいに出る。ところが英語の技術用語に現地語の語尾が付いた一文に差しかかると、そこだけが急におかしくなる。マージが別の語に化け、ロールバックが消え、運が悪ければ節ごと丸ごと落ちる。

認識器がその言語に弱いわけではない。一つの文のなかで言語が切り替わる地点で崩れているのだ。そして韓国の開発・業務環境の発話は、その地点を一日に何百回も通過する。

KRAFTON が公開した A.X K2 Raon-Speech-21B-A3B が正面から狙ったのがここだ。SK テレコムの A.X K2 Light 20B-A3B というテキストバックボーンの上に、自社で学習させた音声エンコーダと音声コーデックを載せた韓英バイリンガル音声モデルである。全体で約 21.2B、活性で約 3.5B。

判断から書く。この公開の価値はベンチマーク順位ではなく、言語境界の処理を設計目標に据えた音声モデルが開いた形で世に出たという事実そのものだ。そしてその価値は、ライセンスの一行のせいで当面は研究と検証でしか回収できない。CC BY-NC 4.0、非商用である。

この記事はまず境界の問題をほどき、次にモデルが何をどう組み立てたのか、21.2B という規模が音声タスクで実際に何を支払わせるのか、どの仕事ならこれを見て、どの仕事なら既存の商用 API のほうがよいのかまで進む。すでにある音声合成モデル群をどのレンズで測るかは別の話なので、ローカル TTS 55 種を三つのレンズで比較するベンチマークで扱った。ここでは測る話ではなく新しく組み上がった物の設計を見る。

1. 崩れるのは言語ではなく境界だ

韓国語の音声処理は難しい、という言い方は粗すぎて手が動かない。実際に難しいのはいくつかの具体的な境界である。

  • 言語の境界。一つの文のなかで韓国語と英語が行き来する。しかも多くは単語一つの単位で
  • 形態素の境界。膠着語なので語幹に助詞と語尾が連なる。分かち書きの単位と意味の単位がずれる
  • 表記の境界。同じ音をハングルで書くかラテン文字で書くかが文書の慣行に委ねられている
  • 敬体の境界。文末の語尾一つで文全体の格が変わる。二つの丁寧体は音も用法も違う

このうち最も高くつくのが一つ目だ。韓英の混在を測るために作られた HiKE ベンチマークは、混在レベルを単語・句・文の三段階に分けて標識を付ける。わざわざ三段階にしたのは、段階ごとに難度が違うからだ。文単位の混在は前後を切って処理すればよいが、単語単位の混在には切る場所がない。

同論文の結論は冷たい。多くの多言語音声認識モデルは混在発話での初期性能が十分ではなく、その能力は合成した混在データで微調整して初めて生まれる。多言語で学習したからといって、言語が編み込まれた発話を自動でこなせるようにはならないという意味だ。複数の言語を別々に知っていることと、二つの言語を一息で聞き分けることは別の能力である。

1.1 膠着語が境界をさらにぼかす

英語の語幹に現地語の語尾が付いた瞬間、問題はもう一段こじれる。マージして、デプロイしたけれど、ロールバックしなければ、といった形では一語のなかに二つの言語が入っている。ここで言語を切り分けるには語より小さい単位まで下りる必要があり、その粒度では言語識別器が役に立たなくなる。

英語とスペイン語のように系統が近く形態論も似た対であれば、この問題はずっと浅かっただろう。韓国語と英語は語順も形態論も音韻も遠い。データが希少な理由であり、この対のためのモデルが別に必要になる理由でもある。

2. 外来語とコードスイッチングは別の問題

この二つを混ぜると、モデリング以前に評価が壊れる。日本語で言えば「リアクトで書きました」のリアクトは何なのか、という問いに近い。

類型例期待出力が割れる理由
定着した外来語コンピュータ、バス、プロジェクト現地文字の表記が標準。ラテン文字ではむしろ不自然
技術固有名詞React、Kubernetes、PostgreSQL文書の慣行がラテン文字。現地文字では検索できなくなる
揺れている中間Docker、Slack同じ組織のなかでも表記が割れる
本物のコードスイッチングこれ deprecated ですよ英語の語を英語で書くのが唯一の正解に近い
混合した語形マージして、コミットしました一語のなかで表記の基準が衝突する

HiKE が混在レベル標識と外来語標識を別立てにしたのは、この表の一行目と四行目を同じ物差しで測ってはいけないからだ。定着した外来語をラテン文字で書き取ったことと、本物の英語の語を現地文字で潰したことはまったく性質の違う誤りなのに、単語誤り率一本にまとめると両方とも同じ 1 点として引かれる。

ここから実務者が持ち帰る判断が一つ出る。混在環境で音声認識器を選ぶとき、公開された誤り率の数字を一つ見ただけではほとんど何も分からない。自組織の表記慣行を正解とみなす短い評価セットを自分で作ったほうが速い。会議録音 30 分あれば足りるし、そのなかに自分たちが実際に使う用語がすべて入っている。

3. 数詞・単位・敬体 - 正解が一つでない場所

テキスト正規化は、音声の二つの方向で違う痛みを出す。

認識の方向では一つの音が複数の表記に割れる。読み上げられた日付は 2026-08-05 とも 2026 年 8 月 5 日とも仮名書きとも書ける。どれが正しいかはそのテキストがどこへ行くかで決まる。カレンダーに入れるなら数字でなければならず、字幕なら読みどおりのほうがよい場合もある。

合成の方向では逆に一つの表記が複数の音に割れる。韓国語の数詞が固有語系と漢字語系の二系統あり、後ろに来る助数詞がどちらを使うかを決めるからだ。日本語話者には「一日」を「ついたち」と読むか「いちにち」と読むかの分岐が近い感覚になる。

  • 3 時 20 分は、時に固有語系、分に漢字語系を同じ息で使う
  • 3 個は固有語系、3 番は漢字語系。同じ数字なのに読みが割れる
  • 1,200 ウォンは量として読み、電話番号の 1200 は一桁ずつ読む
  • 3.5B は三点五ビーとも億単位の読みとも取れ、文脈がなければ決められない
  • 80GB はギガバイトと読む組織と、文字二つのまま読む組織がある

敬体はさらに別の層だ。認識の方向では文末の一音節を落とすと文の格が変わる。合成の方向では、同じ文をかしこまった体で読むときと柔らかい丁寧体で読むときとで抑揚の曲線そのものが違う。英語の音声合成では丁寧さは主に語彙選択の問題だが、韓国語では文法と韻律の両方に同時に配線されている。

これらの項目が重要なのは、規模では解けない種類の問題だからだ。パラメータを十倍にしても「3.5B をどう読むか」の正解は依然として組織のなかにある。規模が解くのは音から言語を取り出す仕事であり、この種の項目はその後に来る取り決めの層だ。

4. 二つのモデルを束ねたものとの決定的な違い

この記事の核心だ。それぞれの言語で最良のモデルを使い、前に言語識別器を置けばよいのではないか。結論から言えばできないのではなく、切り替わる単位が粗すぎて実際の発話に追いつけない。

比較軸単言語モデル + 言語識別バイリンガル単一モデル
最小の切り替え単位発話または文トークン単位で連続
混合した語形送り先がない一つの表現空間で処理
文脈の連続性モデルを乗り換える時点で切れる一つの文脈でつながる
遅延識別待ちと切り替え費用が乗る切り替え費用なし
運用の複雑さモデル 2 つ + 識別器 + ルーティング規則モデル 1 つ
言語ごとの最高性能言語別の最強モデルをそのまま使える容量を分け合うので交換が生じる
メモリ二つのモデルを同時に載せる一組の重み

最後の二行が正直な代償だ。そして今回の公開は、その代償を自らの発表資料のなかに数字として残した。モデルカードの総合順位表を見ると、A.X K2 Raon-Speech は韓国語 0.72 で 1 位、英語は 0.75 で 3 位である。同じ表に Raon-Speech という名のモデルが別に載っていて、そちらは韓国語 0.70、英語 0.79 で英語 1 位だ。

両者の系譜関係をカードが明示していないので断定はできないが、表が示す対比ははっきりしている。韓国語を 0.02 上げた場所で英語が 0.04 下がった。これがバイリンガル統合の値段であり、多言語モデルを選ぶときに必ず確認すべき行だ。総合 1 位という文言だけ読んで通り過ぎると、自分のワークロードで英語比重が高いときに何を失うのか分からないまま導入することになる。

4.1 パイプラインが失うのは精度だけではない

音声対話を音声区間検出 → 音声認識 → テキスト対話 → 音声合成と並べる構成は長く使われ、今も多くの製品がこれで動いている。Moshi 論文はこの方式の問題を二つに整理する。一つはやり取りのあいだに数秒の遅延が生じること。もう一つはテキストを経由する過程で感情や非言語音のように意味を変える情報が失われることだ。

二つ目が特に重い。相槌の一音節は、抑揚によって承諾にも聞き返しにも諦めにもなる。テキストとして着地した瞬間その情報は復元されない。音声から音声へ直行するモデルが必要な理由は、精度よりここに近い。

5.1 コーデックは何をする部品なのか

音声言語モデルにおけるコーデックは、音をモデルが扱える離散トークンに変える部品だ。テキストでトークナイザがやることを音でやる。参照になった Mimi は 24kHz の音声を毎秒 12.5 個の表現に落としつつ 1.1kbps の帯域で完全ストリーミング動作し、フレームサイズと同じ 80ms の遅延を持つ。

ここで毎秒フレーム数がなぜ重要かが見えてくる。フレーム周期がそのまま応答遅延の下限になる。毎秒 12.5 フレームなら 1 フレームは 80ms であり、どれほど速いハードウェアを付けてもその下には行けない。逆にフレーム数を増やせば遅延は縮むが、言語モデルが処理すべきトークンはその分だけ増える。音声モデル設計でもっとも露骨な交換がこの場所にある。

6. 21.2B で活性 3.5B - 規模と実時間性の交換

数字二つを並べて読まなければならない。全体約 21.2B、活性約 3.5B。専門家混合の構成でトークンごとに点灯する専門家は 128 個のうち 8 個だ。

この構造がくれるものとくれないものは明確に分かれる。

  • くれる。演算量が 3.5B 級だ。トークンあたりの処理時間が密な 21.2B モデルよりはるかに短い
  • くれる。知識容量は 21.2B から来る。専門家ごとに別のものを収められる
  • くれない。メモリは全体規模ぶんかかる。どの専門家が点くか分からないので全部載せておく必要がある
  • くれない。バッチ処理の効率が密なモデルほどきれいではない。要求ごとに点く専門家が違う

モデルカードの実行要件がそれをそのまま示す。BF16 の重みが約 42.4GB なので 80GB GPU 一枚または複数 GPU 構成が必要で、vLLM-Omni 経路では単一 GPU 基準で約 96GB の VRAM を要求すると書かれている。併記された条件はテンソル並列 1、最大文脈 4,096、バッチトークン 4,096 だ。

まとめるとこうなる。品質は 21.2B で買い、速度は 3.5B で買い、代金は 21.2B で払う。個人の機材で回してみる物ではない、という意味でもある。

実時間音声で本当の遅延はどこから来るか。総スループットではなく、最初の音が出るまでの時間が対話の質を決める。Moshi 論文は理論遅延 160ms、実測 200ms を報告した。人間の会話の自然なターン間隔がその近辺にあるため、この数字が基準線のように使われる。遅延をどの断片に割ってモデルを選ぶかは速いモデルが勝つ領域で別に整理した。

8. 重みは開き、ライセンスは閉じている

モデルカードに書かれたライセンスは CC BY-NC 4.0 だ。NC は非商用を意味する。重みをダウンロードできることと製品に載せられることはまったく別の話である。

ここで実際に事故が起きやすい地点を一つ指摘する。同じカードが Apache License 2.0 にも言及しているが、適用範囲は同梱された A.X K2 Light の実装コードに限定されると明記されている。コードが Apache だからといって重みまで商用に使えるわけではない。バックボーンを作った SK テレコム側の公開方針と、この音声モデルの公開方針は別物だ。

  • 重み — CC BY-NC 4.0。非商用条件
  • 同梱のバックボーン実装コード — Apache 2.0。その範囲のなかだけ
  • 話者の同意 — 識別可能な話者が関わる音声条件付けや生成には事前同意を確保する責任が利用者にあるとカードが記している
  • 公式の想定用途 — バイリンガル音声認識・生成、音声理解、音声アシスタント研究。すべて非商用の範囲内だ

三つ目の項目はライセンスとは別に重い。話者条件付き音声合成は短い参照音声から特定人物の声の特徴を移す機能であり、このモデルはその API を明示的に提供する。技術的にできることと、やってよいことのあいだの隔たりがこの機能でもっとも大きい。日本でも声優の音声を無断で学習・合成した事例が繰り返し問題になっており、この隔たりは制度以前に現場の信頼の問題として現れている。

オープンウェイトという言葉が実際にはどれだけ多くの層を指すのかは、Krea 2 オープンウェイト画像モデルを扱ったときに一度整理した。今回も同じ罠だ。ダウンロードボタンがあるという事実は、ライセンスについて何も語らない。

9. これを見る仕事と商用 API が勝つ仕事

基準を一つに圧縮するとこうなる。いま売上が掛かっているなら商用 API、検証して学ぶ段階ならこちらだ。ライセンスがすでにその線を引いているので、実は悩む余地も多くない。

状況選択理由
韓英混在の認識性能を自分で実測したいこのモデル混在を狙って作られた公開モデルが少ない
音声対話エージェントの試作このモデル認識・合成・対話が一つのモデルにある
データ持ち出し禁止環境での事前検証このモデルオンプレで回せる。ただし商用転換は別問題
コーデックやエンコーダ自体の研究このモデル部品別の相対性能が公開されている
顧客向けサービスに載せる商用 API非商用ライセンスなので成立しない
リアルタイム通話字幕商用 APIストリーミング・再接続・部分結果が必要
話者分離とタイムスタンプが要る商用 APIモデルカードに該当機能の言及がない
80GB 級 GPU がない商用 API重みだけで 42.4GB ある

表に入らない話を一つ足す。公開ウェイト音声モデルの本当の費用は GPU ではなくその周辺だ。話者分離、句読点復元、用語辞書の適用、部分結果のストリーミング、切れた接続の再開、長い音声の分割と接合。商用音声 API が売っているものの半分以上はモデルではなくこのリストである。モデルを無料で手に入れてもこのリストは自分で作る必要があり、たいていそちらのほうが長くかかる。

10. 音声 AI の勢力図における位置

この公開から勢力図について確認できる事実は三つだ。

  1. テキストバックボーンは SK テレコムの A.X K2 Light、音声エンコーダとコーデックは KRAFTON の自社学習。韓国の組織が作ったバックボーンの上に別の韓国の組織が音声層を載せた
  2. 比較表にネイバーの HyperCLOVA X 8B Omni が入っていて韓国語総合 0.60 だ。韓国語のオムニモデルどうしを対照できる状態になったという意味である
  3. 同じ表に Qwen3-Omni(韓国語 0.65)が 3 位で載っている。韓国語性能でも中国の公開モデルがすでに直接の比較対象だ

三つ目がもっとも実務的な含意を持つ。韓国語だから国内モデルが当然強い、という仮定はもう表で反証される。0.65 と 0.72 の差は明確だが、その差を得るために非商用ライセンスを飲むかは別の計算だ。日本市場から見ると、日本語を含む多言語オムニモデルにも同じ読み方がそのまま使える。自国語だから自国モデル、という前提は表で確かめるべき仮説になった。

ゲーム会社が音声モデルを出した背景としてキャラクター音声や NPC 対話を思い浮かべるのは自然だが、公開資料で確認できる話ではないのでこの記事では推測のまま残す。モデルカードが明示した用途はバイリンガル音声認識・生成、音声理解、音声アシスタント研究までだ。

モデル名と順位を追いかけることがなぜおおむね損なのかは、AI モデル名を全部覚えるなで扱った。今回も同じで、覚えるべきは名前ではなく部品構成とライセンス二行だ。その二つを掴んでおけば、半年後に出る次のモデルも同じ読み方で読める。

11. 確認できなかったこと

次の項目は一次根拠を特定できなかったため、本文で数値や断定として使っていない。

  • 絶対誤り率。公開された総合点は 0〜1 に正規化した合算値だ。個々のデータセットの単語・音節誤り率はカードにない
  • 46 個のベンチマークの個別構成。韓国語 24 個・英語 22 個という個数だけが確認できる。どのデータセットが入ったのかは照合できなかった
  • 実測遅延とリアルタイム係数。本文の 160ms・200ms・80ms は Moshi と Mimi の値であってこのモデルの値ではない。このモデル自体の遅延数値はカードにない
  • 比較表の Raon-Speech が何か。名前と点数だけが確認できる。このモデルとの系譜関係・規模・学習条件を確認できなかったため、韓国語と英語の点数の対比だけを引用した
  • 韓英コードスイッチング専用の性能。HiKE のような混在専用ベンチマークの結果はカードにない。混在を狙ったという設計意図と、混在性能が測定されたということは別の話だ
  • 商用利用の協議可否。別途の商用ライセンス経路があるかを公開文書で確認できなかった
  • 話者分離・タイムスタンプ・用語辞書。対応タスク一覧にない。ないという意味なのか文書化されていないだけなのか区別できなかった

結論: 名前二行ではなく表二つを見よ

この公開で長く残るのは順位ではない。文の途中で二つの言語が混ざる状況を設計目標に載せた音声モデルが開いた形で出たという事実であり、その試みの代償が同じ文書のなかに数字として残ったことだ。韓国語を 0.02 上げる場所で英語が 0.04 下がった。こういう表をそのまま公開する側は、隠す側より信用できる。

だからこのモデルを見る人に残すのは二つだ。一つはコーデックの表である。PESQ は削られ韓国語認識は上がった、というあの形が、この物の性格をもっとも正確に説明する。音声言語モデル用の部品であってオーディオ圧縮器ではない。もう一つはライセンスの一行だ。CC BY-NC 4.0 を確認せずにロードマップへ載せると、あとで戻る場所がない。

今日やってみる価値のあることも一つ残す。自組織の会議録音 30 分で短い評価セットを作ることだ。自分たちが実際に使う英語の用語がそのなかに全部入っているし、表記の慣行もすでに決まっている。そのセット一つが、他人のベンチマーク 46 個より導入判断に多くを語ってくれる。モデルが変わってもセットは残るのがおまけで、たいていそのおまけのほうが元手より大きい。
