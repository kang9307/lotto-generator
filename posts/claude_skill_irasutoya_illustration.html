1. 서론: 슬라이드와 문서를 만들 때 시각 자료를 찾는 시간

현대 지식 근로자가 문서 작성에 투입하는 시간 중 상당 부분은 텍스트를 집필하는 논리적 사고가 아니라, 보조적인 시각 자료를 검색하고 가공하는 부차적 행위에 소모됩니다. 예를 들어 새로운 클라우드 아키텍처 도입 제안서를 작성할 때, '서버 장애', '데이터베이스 백업', '보안 인증'과 같은 추상적 개념을 한눈에 보여줄 수 있는 가벼운 아이콘이나 일러스트를 찾느라 브라우저 탭을 수십 개씩 열어두는 모습은 사무실에서 흔히 목격됩니다.

유료 스톡 이미지 플랫폼은 품질이 뛰어나지만 정기 구독료 부담이 크고, 대다수의 사진 자료가 지나치게 서구적이거나 사실적이어서 가벼운 내부 기술 발표 자료나 스타트업의 기획서에는 어색한 이질감을 유발합니다. 또한 무료 스톡 사이트들은 저작권 조건이 제각각이어서 상용 이용 가능 여부나 크레딧 표기 의무를 확인하는 데 또 다른 주의력을 요구합니다.

최근에는 DALL-E나 Midjourney 같은 텍스트 기반 이미지 생성 AI를 이용해 삽화를 만들려는 시도도 늘어났습니다. 그러나 생성형 AI는 프롬프트를 입력할 때마다 그림의 스타일과 선의 느낌이 무작위로 바뀌기 때문에 여러 장의 슬라이드에 걸쳐 통일된 톤앤매너를 유지하기가 불가능에 가깝습니다. 더욱이 생성 모델이 출력하는 결과물은 대개 배경이 채워진 사각형 래스터 이미지이므로, 발표용 배경색에 자연스럽게 녹아들도록 하려면 별도의 알파 채널 분리 작업이 필요하다는 한계를 드러냅니다.

결국 많은 실무자들이 다시 いらすとや로 돌아오게 되는 이유는 명확합니다. 수만 장에 달하는 일러스트가 일관된 동글동글하고 따뜻한 화풍으로 그려져 있어 어떤 슬라이드에 배치해도 통일감을 해치지 않으며, 모든 파일이 배경이 완전히 제거된 고해상도 투명 PNG로 제공되기 때문입니다. 그러나 사이트 내 검색창에 키워드를 입력했을 때 원하는 그림이 제때 나오지 않아 페이지를 한참 넘겨야 했던 불편은 여전한 과제로 남아 있었습니다. irasutoya Claude Skill은 바로 이 오랜 탐색 비용 문제를 정면으로 겨냥한 솔루션입니다.

2. いらすとや Claude Skill이란 무엇인가: 개념과 기본 작동 방식

irasutoya Claude Skill은 Anthropic의 에이전트 인터페이스(Claude Code CLI, Claude Desktop, Claude Design 아티팩트 환경 등)에 등록되어 작동하는 자동화 도구입니다. 사용자가 문서 작성 중 "이 부분에 어울리는 회의 일러스트를 넣어줘"라고 명령하면, Claude가 문맥을 파악해 적절한 일본어 단어를 도출하고, 외부 스크립트를 호출하여 최적의 삽화를 실시간으로 가져와 배치합니다.

2.1 검색부터 투명 PNG 삽입까지의 단일 호출 워크플로

과거의 수작업 방식에서는 사용자가 브라우저를 켜고 사이트에 접속한 뒤 일본어 단어를 조합해 검색하고, 수십 개의 썸네일 중 적합한 것을 골라 상세 페이지로 이동한 다음, 원본 다운로드 버튼을 눌러 로컬 저장소에 저장해야 했습니다. 그 후 파일 탐색기에서 이미지를 찾아 슬라이드 소프트웨어나 웹 에디터로 드래그하는 6단계 이상의 물리적 과정이 요구되었습니다.

반면 irasutoya 스킬은 이러한 일련의 과정을 단 한 번의 도구 호출(one call)로 압축했습니다. 사용자의 질의가 전달되면 백그라운드 스크립트가 검색, 순위 매김, 다운로드를 연속으로 처리하며, 이 전체 파이프라인이 완료되는 데 걸리는 시간은 약 1.5초에 불과합니다. 작업자는 편집 화면을 벗어나지 않고도 필요한 시각 자산을 즉시 손에 쥘 수 있게 됩니다.

다운로드되는 파일은 원작자가 배포한 투명 배경 PNG(알파 채널 포함) 원본이므로, 문서나 웹페이지에 삽입되었을 때 뒷배경과 어색한 경계선을 만들지 않고 자연스럽게 융합됩니다. 이는 별도의 그래픽 도구를 다룰 줄 모르는 비디자이너 직장인이나 개발자에게 막대한 작업 시간 절약 효과를 제공합니다.

2.2 CLI와 Claude Design 환경 지원

이 도구는 Claude의 대화형 프롬프트 인터페이스뿐만 아니라 독립적인 터미널 환경에서도 완벽히 동작하도록 듀얼 인터페이스를 제공합니다. 사용자는 터미널 콘솔에서 파이썬 스크립트를 직접 실행하여 일러스트를 검색하거나 특정 라벨 전체를 일괄 조회하는 등의 배치 작업을 수행할 수 있습니다.

또한 웹 기반 프로토타이핑 캔버스인 Claude Design 환경에 대한 대응책이 마련되어 있습니다. 브라우저 기반의 아티팩트 렌더링 샌드박스는 보안 정책(CSP, Content Security Policy)에 따라 외부 호스트(예: 구글 블로거 이미지 CDN)의 이미지를 임의로 로드하지 못하도록 차단하는 경우가 많습니다. 스킬은 이를 감안하여 로컬에 저장된 에셋 파일을 직접 마운트하거나, 이미지를 즉시 base64 형태의 data URI 문자열로 변환하여 아티팩트 코드 내에 인라인으로 주입하는 기능을 갖추고 있습니다.

3. 왜 단순 fetch가 실패하는가: 일본어 표기 변환과 Blogger 검색의 한계

소프트웨어 엔지니어링 관점에서 볼 때, 특정 사이트의 이미지를 가져오는 작업은 대개 REST API나 RSS 피드를 단순히 호출하는 단순한 일로 여겨지기 쉽습니다. 그러나 いらすとや가 구축된 기반 기술과 일본어의 언어적 특성을 고려하지 않고 접근하면 단순 fetch 방식은 십중팔구 빈 결과를 반환하며 실패하게 됩니다.

3.1 일본어 표기의 불일치: 한자와 가타카나의 혼용

いらすとや는 별도의 커스텀 웹 애플리케이션이 아니라 구글이 제공하는 무료 블로그 서비스인 Blogger 플랫폼 위에서 운영되고 있습니다. Blogger에 내장된 검색 시스템은 전문적인 형태소 분석 엔진이나 유의어 사전, 벡터 유사도 검색 기능을 전혀 내장하고 있지 않습니다. 오직 사용자가 입력한 문자열이 포스트의 제목이나 본문에 글자 그대로(literal match) 존재하는지만 검사하는 극히 단순한 텍스트 매칭 엔진입니다.

문제는 일본어라는 언어가 가진 고유의 표기 다양성입니다. 일본어에서는 하나의 개념을 한자(漢字), 히라가나(ひらがな), 가타카나(カタカナ)로 모두 표기할 수 있으며, 실제 언어 생활에서도 이들이 혼용됩니다. いらすとや 사이트에 등록된 수만 개의 포스트 제목 역시 일정한 표기 통일 규칙이 없습니다. 예를 들어 '원숭이'라는 동물은 어떤 포스트에는 한자인 猿으로 적혀 있고, 어떤 포스트에는 가타카나인 サル로 등록되어 있습니다.

실제 테스트 결과에 따르면, サル バナナ(가타카나 원숭이 + 바나나)로 검색하면 일치하는 포스트가 없어 검색 결과가 0건으로 출력됩니다. 반면 원숭이를 한자로 바꾼 猿 バナナ로 검색하면 2건의 정확한 일러스트가 결과로 나타납니다. '안경'이라는 단어 역시 한자 眼鏡과 가타카나 メガネ 중 사이트 운영자가 당시 어떤 단어를 선택해 제목을 붙였느냐에 따라 검색 여부가 갈립니다. 사람이 직관적으로 검색할 때도 겪는 이 문제를 기계적인 AI 에이전트가 단일 키워드로 돌파하기는 불가능합니다.

3.2 조사 결합과 동사 활용이 검색을 무효화하는 이유

더욱 치명적인 장벽은 자연어 문장 질의에서 발생합니다. 인간 사용자가 AI에게 "사과를 먹는 아이 그림을 찾아줘"라고 부탁하면, 통상적인 언어 모델은 이를 일본어 문장으로 번역하여 リンゴを食べる(사과를 먹다)라는 질의를 생성하기 쉽습니다.

그러나 이 문장을 그대로 Blogger 검색창에 질의하면 결과는 예외 없이 0건입니다. Blogger 검색 엔진은 목적격 조사인 を를 독립 어휘로 분리하지 못하고 'リンゴを' 전체를 하나의 단어로 인식하며, 동사의 기본형인 食べる 역시 제목에 적힌 활용형(예: 먹고 있는 모습, 먹는 아이 등)과 완전히 일치하지 않으면 매칭에 실패합니다.

반면 조사 を를 깨끗이 털어내고 단어 사이에 공백을 준 リンゴ 食べる로 검색하면 비로소 사과를 먹는 일러스트들이 화면에 나타납니다. 결국 일본어의 어간 추출, 조사 분리, 동사 활용 꼬리(verb tails) 제거라는 정밀한 언어학적 전처리 없이는 いらすとや의 데이터베이스를 활용할 수 없는 것입니다.

4. 기술적 해결책: 12가지 표기 병렬 확장과 클라이언트 순위화

irasutoya Claude Skill이 오픈소스 커뮤니티에서 기술적 찬사를 받는 이유는 Blogger 검색 엔진의 구조적 결함을 외부에서 우회하기 위해 매우 정교한 질의 확장 및 랭킹 파이프라인을 구축했기 때문입니다.

4.1 12가지 질의 생성과 병렬 호출 메커니즘

사용자나 Claude가 하나의 개념 단어를 입력하면, 스크립트 내부의 변환 엔진이 즉시 가동되어 최대 12가지 형태의 변형 검색어를 자동으로 파생시킵니다. 이 알고리즘에 적용된 핵심 규칙들은 다음과 같습니다.

  • 조사 자동 제거: 문장 구조 내에서 명사와 동사를 연결하는 を, に, で, が 등의 조사를 식별하여 제거합니다.
  • 단어 예외 사전 유지: 단순 정규식 기반 조사 제거의 치명적 부작용을 막기 위한 방어 로직입니다. 예를 들어 '김' 또는 '풀'을 뜻하는 단어 のり의 경우, 첫 글자 の가 소유격 조사로 오인되어 り만 남는 참사를 방지하도록 예외 단어로 등록되어 있습니다.
  • 가나 상호 치환: 히라가나로 작성된 표현을 가타카나로, 가타카나로 작성된 표현을 히라가나로 상호 변환하여 작성자의 표기 습관에 구애받지 않도록 합니다.
  • 한자↔가타카나 대응어 치환: 猿과 サル, 眼鏡과 メガネ처럼 혼용 빈도가 높은 대표 어휘 쌍을 치환하여 질의 풀을 확장합니다.
  • 동사 활용 꼬리 제거: 동사의 어미 변화(活用語尾)를 잘라내어 기본 어간만을 남김으로써 매칭 확률을 극대화합니다.

이렇게 파생된 최대 12개의 검색어는 순차적으로 하나씩 호출되는 것이 아닙니다. 파이썬의 비동기 처리 및 시스템 curl을 결합하여 Blogger 서버로 동시에 병렬 전송(fan out)됩니다. 덕분에 12번의 검색을 수행함에도 불구하고 전체 소요 시간은 단일 호출과 큰 차이 없는 약 1.5초를 유지할 수 있습니다.

4.2 부분일치 강등과 요약 엔드포인트 최적화

병렬 질의를 통해 수신된 결과 데이터는 그대로 사용자에게 전달되지 않고 정교한 클라이언트 측 순위화(ranking) 알고리즘을 거칩니다. 병렬로 여러 단어를 던지다 보면 검색어와 무관한 엉뚱한 결과가 섞여 들어오기 때문입니다.

가장 대표적인 사례가 부분문자열 일치(substring match)의 순위 강등(demotion)입니다. 원문 문서에 소개된 실제 버그 사례에 따르면, サル(원숭이)을 검색했을 때 단순 매칭 알고리즘을 적용하면 アンドリューサルクス(앤드루사르쿠스, 선사시대 멸종 거대 육식 포유류)라는 생소한 동물 일러스트가 1위로 검색되는 어처구니없는 현상이 발생했습니다. 스킬은 입력된 검색어가 긴 복합어의 중간에 부수적으로 끼어 있는 경우 순위를 대폭 깎아내려, 사용자가 진짜로 찾고자 하는 전형적인 '원숭이' 그림이 최상단에 올라오도록 보정합니다.

여기에 더해 네트워크 페이로드를 줄이기 위한 세심한 엔드포인트 튜닝이 적용되었습니다. Blogger의 기본 피드 URL인 /feeds/posts/default 대신 요약 피드인 /feeds/posts/summary를 호출합니다. 공식 문서에 따르면 두 엔드포인트가 제공하는 핵심 메타데이터 필드는 동일하지만, 요약 엔드포인트를 사용할 경우 응답 데이터의 용량이 약 40% 절감됩니다. 1회의 사용자 요청에 최대 12개의 네트워크 요청이 발생하는 구조에서 이 40%의 페이로드 다이어트는 전체 시스템의 지연 시간을 낮추고 대역폭을 보존하는 결정적 요인으로 작용합니다.

5. 설치와 실행: CLI 명령 구성과 환경 설정

이 도구의 또 다른 미덕은 극단적으로 가벼운 아키텍처에 있습니다. 최근 등장하는 많은 인공지능 보조 도구들이 방대한 파이썬 가상환경과 수백 메가바이트에 달하는 pip 패키지 의존성을 요구하는 것과 달리, irasutoya 스킬은 운영체제의 기본 기능만을 활용하도록 정밀하게 설계되었습니다.

5.1 환경 요구 사항과 설치 방법

실행을 위한 시스템 필수 조건은 Python 3와 curl 두 가지뿐입니다. 외부 서드파티 라이브러리나 별도의 pip 패키지 설치가 전혀 필요하지 않으므로, 환경 충돌이나 버전 꼬임 문제 없이 어떤 개발 환경에서도 즉시 구동됩니다. 네트워크 환경에서는 www.irasutoya.com 웹사이트 및 구글의 블로거 콘텐츠 서버인 blogger.googleusercontent.com으로 향하는 아웃바운드 HTTPS 통신만 허용되어 있으면 됩니다.

설치는 Claude의 스킬 전용 디렉터리에 GitHub 저장소를 복제하는 단 한 줄의 명령어로 완료됩니다.

git clone https://github.com/hsol/irasutoya ~/.claude/skills/irasutoya

다운로드된 이미지 파일이 저장되는 기본 경로는 환경변수 IRASUTOYA_OUT으로 제어할 수 있으며, 이 환경변수를 지정하지 않을 경우 시스템 기본값인 ~/Downloads/irasutoya 디렉터리에 자동으로 저장됩니다.

Claude와의 대화창을 거치지 않고 터미널에서 스크립트를 단독으로 실행할 때 사용할 수 있는 CLI 명령어 체계는 매우 직관적으로 구성되어 있습니다.

또한 저장소에는 개발 과정에서 실제로 발견되었던 11건의 결함을 방지하기 위한 단위 테스트 스위트가 마련되어 있습니다.

python3 tests/test_search.py

조사가 포함된 검색어 누락(リンゴを食べる), 멸종 동물 노출(サル 검색 시 앤드루사르쿠스 등장), 복합어 조사 오인(のり의 の 보존) 등 실제 라이브 웹사이트를 대상으로 11개 테스트 케이스를 약 15초에 걸쳐 엄격하게 검증합니다.

6. 가장 중요한 실무 주의점: いらすとや의 20장 상용 라이선스 규칙

이 도구를 업무나 영리 목적의 프로젝트에 도입하려는 기업 및 개인 창작자가 가장 주의 깊게 살펴봐야 할 영역은 기술적 기능이 아니라 바로 저작권 라이선스 조건입니다. いらすとや가 인터넷상에서 "무료 일러스트 사이트"로 널리 알려져 있다 보니, 아무런 제약 없이 무제한으로 가져다 쓸 수 있는 퍼블릭 도메인처럼 오해하는 경우가 빈번합니다. 그러나 원작자가 공지한 공식 이용약관에는 매우 명확하고 엄격한 상용 수량 상한선이 규정되어 있습니다.

6.1 무료 이용 범위와 21장 이상의 과금 조건

いらすとや의 기본 정책은 매우 파격적입니다. 개인적인 비영리 사용은 물론, 영리 기업의 마케팅 자료, 발표 슬라이드, 웹사이트, 유튜브 영상 등에 이르기까지 상용 프로젝트라 할지라도 별도의 출처 표기(크레딧) 의무 없이 무료로 사용할 수 있습니다. 그러나 이 무료 이용 혜택에는 명확한 수량 제한이 붙어 있습니다.

공식 이용약관에 따르면, 하나의 상용 디자인(단일 프로젝트, 1종의 발표 자료, 1권의 책자 등) 내에서 무료로 사용할 수 있는 일러스트는 최대 20장까지입니다. 만약 단일 상용 제작물에 서로 다른 일러스트가 21장 이상 포함될 경우, 원작자(みふねたかし)와 별도의 유료 라이선스 계약을 체결하고 라이선스 비용을 지불해야 합니다. 이때 동일한 일러스트를 한 문서 안에서 여러 번 반복 사용하는 것은 중복 계산되지 않고 1장으로 인정되지만, 서로 다른 일러스트의 종류가 21종을 넘어서는 순간 과금 대상이 됩니다.

구체적으로 공식 이용약관에서 하나의 상용 디자인 단위로 간주하는 대표적인 프로젝트 범위는 다음과 같습니다.

  • 프레젠테이션 슬라이드 1세트: 전체 슬라이드의 매수와 상관없이 단일 발표 자료 1종을 하나의 제작물 단위로 봅니다.
  • 단일 인쇄 홍보물: 팜플렛, 리플릿, 카탈로그, 포스터 등 하나의 인쇄 매체 프로젝트를 1개 단위로 판정합니다.
  • 웹사이트 및 애플리케이션: 단일 도메인의 웹 서비스나 모바일 앱의 UI 구성 에셋 전체를 하나의 디자인으로 계산합니다.
  • 영상 콘텐츠 1편: 유튜브, 홍보 영상, 온라인 강의 등 독립된 단일 영상물 1건을 하나의 단위로 적용합니다.
  • 교육 교재 및 단행본 매뉴얼: 사내 교육용 책자나 단행본 매뉴얼 1권을 단일 제작물 단위로 취급합니다.

실무에서 슬라이드를 제작하다 보면 장표마다 삽화를 1~2개씩 넣다가 30~40장이 훌쩍 넘어가는 경우가 흔합니다. AI 도구가 편리하다고 해서 생각 없이 삽화를 계속 추가하다 보면 자신도 모르는 사이에 21장 기준을 넘겨 저작권 분쟁에 휘말릴 수 있으므로, 20장 규칙은 실무진이 반드시 기억해야 할 마지노선입니다.

6.2 스킬의 안내 방식과 사용자의 라이선스 확인 의무

이 스킬의 개발자 역시 이러한 법적 리스크를 명확히 인지하고 코드에 안전장치를 마련해 두었습니다. 그러나 스킬은 20장을 넘었다고 해서 사용자의 다운로드 요청을 강제로 거부하거나 작업을 차단(gate)하지는 않습니다. 대신 '정보성 고지'의 형태로 작동합니다.

스크립트는 작업 문맥에서 상용 프로젝트로 의심되는 신호가 있을 때 사용된 일러스트 수를 누적 계산하며, 21장의 경계선을 넘어서는 순간 사용자에게 "단일 상용 디자인에 20장을 초과했습니다"라는 주의 메시지를 단 1회 출력합니다. 만약 사용자가 내용을 인지하고 계속 진행하겠다고 확인하면 스크립트는 다운로드를 계속 진행합니다. 도구의 알림은 단순한 편의성 리마인더일 뿐 법률 자문이 아니므로, 라이선스 조건을 확인하고 준수할 최종 책임은 전적으로 사용자 본인에게 있습니다.

7. 한국 직장인과 창작자 관점의 시사점과 실무 활용 팁

irasutoya Claude Skill의 등장은 일본어 자료를 검색하는 데 언어적 피로감을 느끼던 한국의 기획자, 개발자, 1인 창작자들에게 실질적인 업무 효율성을 가져다줍니다.

7.1 검색 피로도의 획기적 단축과 톤 통일

한국 사용자 입장에서 일본어 웹사이트를 검색하는 일은 상당한 언어 장벽을 수반합니다. 적절한 일본어 단어를 찾기 위해 번역기를 거쳐야 하고, 그 단어가 한자로 쓰였는지 가타카나로 쓰였는지 알 수 없어 여러 번 검색창을 두드려야 했습니다. Claude Skill을 사용하면 한국어로 "데이터 분석을 하는 개발자 일러스트를 찾아줘"라고만 입력해도, Claude가 적절한 일본어 개념어를 스스로 추출하고 스크립트의 12가지 표기 변환 로직을 태워 최적의 결과물을 단 1.5초 만에 가져옵니다.

또한 슬라이드의 시각적 완성도를 높이기 위해서는 일러스트의 화풍 통일이 필수적입니다. 여러 사이트에서 제각각 내려받은 이질적인 그림들을 섞어 쓰면 문서가 산만해지기 쉽지만, いらすとや의 일러스트로 전체 문서를 구성하면서 --label 플래그를 활용해 계열을 일치시키면 고도로 정돈된 전문 자료를 빠르게 완성할 수 있습니다.

7.2 인공지능 도구 설계의 교훈

이 프로젝트는 인공지능 보조 도구가 나아가야 할 바람직한 아키텍처 방향성을 잘 보여줍니다. 거대하고 무거운 외부 프레임워크에 의존하지 않고, 운영체제 기본 명령과 가벼운 파이썬 스크립트만으로 레거시 웹 서비스의 검색 알고리즘 한계를 완벽히 우회했습니다.
