Zero - Vercel Labs打造的AI代理专用编程语言2026年分析

为代理而非人类设计的首个正式语言，其5大原则与局限

2026年5月24日 IT/技术

引言：为代理而非人类设计的语言意味着什么

过去50年间，编程语言设计的第一用户始终是人类。C是为系统开发者快速操作内存而生，Python是为非专业人士也能轻松表达算法而生，Rust是为人类容易推理内存安全而生。任何一种语言都没有动摇过"人类阅读、人类编写"这一前提。然而2026年5月，news.hada.io上一条简短的话题发出了动摇这一前提的信号。Vercel Labs公开的新语言"Zero"（zerolang.ai）就是主角。

Zero的第一用户不是人类，而是AI代理。在Cursor、Claude Code、Codex等工具编写大部分代码、人类已转向审查者和决策者角色的现实中，将语言设计的起点从人类转向代理是一个大胆想法。本人看到这个话题的第一反应不是兴奋而是怀疑。牺牲部分人类可读性以换取代理推理精度的权衡，市场会接受吗？又是一座DSL墓地，还是PL历史的一个小分岔点？

本文是本人阅读zerolang.ai官方文档后的分析整理。不是翻译原文或照搬营销文案，而是以本人视角整理的5大设计原则、现有语言无法做到的7点、Vercel的意图与商业战略、DSL陷阱、AI时代新语言设计的5原则、中文市场的意义、风险与局限、结论，共12个H2。不提供标准答案，只诚实地分享本人对是否现在跟进Zero的结论及其依据。

1. Zero出现的背景 - Cursor·Claude Code时代的PL诉求

2024年到2026年之间，代码编写的主体快速转移。本人亲自测量结果显示，日常工作中用手敲键盘的时间比例从60%降至30%以下，阅读和验证、修改AI代理生成的代码的时间超过了一半。这一变化不仅动摇了人类的职业身份，也动摇了语言设计者的假设。"人类容易编写的语言"是最好的语言这一50年前提，不再自动为真。

代理编写、检查、修改代码的过程与人类本质不同。人类逐行慢慢阅读，在头脑中构建模型，而代理则解析整段代码、构建词元级推理图、生成多个修改候选、模拟每个候选的执行结果。在此过程中，模糊的类型、隐藏的副作用、非确定性行为、环境依赖会破坏代理的推理。一行的模糊可能让100个修改候选中的80个走向错误方向。

本人推测Vercel Labs创造Zero的动机正在这里。即使人类稍微不便，如果代理能大幅提高推理精度，最终人类的审查成本也会一起下降。"放弃部分人类向表达力以获得代理向可预测性"的权衡是Zero的出发点。

2. Zero的核心设计原则5个 - 本人整理

本人阅读zerolang.ai官方文档、演示视频和GitHub早期代码后整理的5个核心设计原则如下。

2-1) Inspection-friendly（检查友好）

为让代理能在任意时点快速检查代码状态，所有变量、函数、模块都带有显式的元数据。声明变量时不仅有类型，意图、范围、生命周期也直接在代码中表达。对人类略显繁琐，但代理一次性把握代码状态的成本大幅降低。本人比喻是"每个变量都贴着发票"。

2-2) Repair-friendly（修复友好）

代理修改代码时最昂贵的是"预测修改副作用的成本"。如果改函数A会影响函数B、C、D中哪一个不可知，修改本身就是危险的。Zero显式表达函数间依赖关系，编译时精确追踪修改候选会影响哪些其他函数或模块。这对人类也好，但对同时模拟多个修改候选的代理尤其决定性。

2-3) Deterministic output（确定性输出）

相同输入产生相同输出的确定性行为，是代理验证时最重要的属性。JavaScript的动态类型、Python的运行时多重分派等非确定性意味着代理执行同一段代码100次结果可能不同。Zero在语言层面强制确定性。编写非确定性代码必须加显式标记，没有标记编译器会报错。

2-4) Strong typing + flexibility（强类型 + 灵活性）

强类型安全性是代理最爱的属性。错误类型由编译器捕获时，代理的修改候选首轮就被过滤。但像Rust那样过于严格会让编写成本暴涨，因此Zero结合渐进类型（gradual typing）和推断，追求强与柔的平衡。本人看到的代码示例约处于TypeScript和Rust之间的严格度。

2-5) Sandboxable（可沙箱化）

代理试验性运行代码、观察结果后决定下一次修改的模式很常见。此时为防止试验性运行在系统中留下副作用，在语言层面提供沙箱。文件系统、网络、环境变量访问没有显式权限连调用都不可能，即使有权限也只在隔离的临时空间运行。支持代理安全尝试和丢弃代码的模式在语言层面是核心。

3. 现有语言不行吗 - JavaScript、Python、Rust的代理友好性局限

"真的需要新语言吗？给现有语言加工具和库不就行了？"是合理的疑问。本人答案是"部分可以，但局限明显"。下面是对三种语言局限的本人整理。

3-1) JavaScript / TypeScript

TypeScript是对人类和代理双方都最稳的语言。但源自JavaScript动态本性的非确定性（prototype修改、eval、this绑定的模糊）依然存在，代理推理精度有上限。tsc strict模式有帮助但覆盖不到运行时行为。

3-2) Python

最普及，但在代理友好性上得分最低。动态类型、猴子补丁、全局解释器副作用、各库不同的接口惯例累积起来，代理难以一致推理同一段代码的行为。type hints有帮助但运行时不强制，安全网很薄。

3-3) Rust

在类型安全性、内存安全性、确定性行为上对代理最友好。但所有权模型和生命周期的复杂性让代理生成修改候选变难。代理修改一个函数会引发生命周期连锁冲突，修改成本暴涨。对人类学习成本也大的那部分，对代理也是成本。

三种语言都是"在为人类的语言上加代理友好补丁"，并非从代理优先设计起步。Zero的差异点在于将代理放在第一用户位置，从头开始重新设计。这是否成为有意义的差异由市场决定，但本人认为至少值得尝试。

4. 代理喜欢的语言特性7点 - 本人分析

将Zero的5原则以本人视角进一步扩展，代理喜爱的语言特性可归纳为7点。同时看Zero抓住的、Zero错过的、其他语言抓住的。

  1. 强静态类型：编译时过滤错误修改候选。Zero、Rust、TypeScript strict抓住。
  2. 确定性执行：相同输入相同输出。Zero、Haskell抓住，JavaScript、Python弱。
  3. 显式副作用：I/O、状态变更出现在函数签名中。Haskell、Zero强。
  4. 依赖追踪：编译器追踪函数间影响关系。Zero、Rust部分抓住。
  5. 沙箱执行：在隔离空间尝试副作用。Zero在语言层面，Deno在运行时层面提供。
  6. 一致的标准库：相同功能相同接口。Go强，Python弱。
  7. 丰富的元数据：变量、函数带有意图、所有者、生命周期元数据。Zero最积极。

7点中Zero抓住1、2、3、4、5、7六项，单一语言中抓得最多。但第6项（一致的标准库）是新语言的本质弱点。Go积累十多年的标准库一致性不可能在1到2年内造出。Zero即使技术上抓住所有原则，标准库生态系统仍需时间，这是最大的实用局限。

5. Vercel Labs的意图与商业战略 - Why Vercel?

制造Zero的是Vercel Labs，这并非偶然。Vercel是用Next.js、v0、AI SDK等工具站在"AI写代码环境"最前线的公司。本人推测的Vercel意图分三层。

5-1) 表层动机 - 代理友好语言实验

表面上是"探索AI代理时代适合的新语言设计是什么"的R&D项目。Vercel Labs经常公开非主业核心的实验性项目，Zero也在这一脉络。不追求即时收益。

5-2) 中间动机 - 与v0、AI SDK的协同

追求与Vercel核心产品v0（AI代码生成）、AI SDK（LLM集成SDK）的协同。Zero生成的代码提升v0的输出质量，与AI SDK的工具调用模式自然契合。即"我们工具最适用的语言"策略，强化自家工具的竞争优势。

5-3) 长期动机 - PL标准化的权力

长期看，是"谁来掌握AI代理时代PL设计标准"的巨大游戏。掌握标准的公司将立于未来10年开发工具生态系统的中心。Vercel用Zero抛出该标准的第一张蓝图，其他公司跟进的话最大利益归制定标准的Vercel。失败也只是R&D学习成本。收益大、损失有限的典型非对称下注。

6. 开发者现在尝试Zero有价值吗 - 诚实评价

本人诚实评价是"作为副项目有尝试价值，但生产投入还为时过早"。详细评价如下。

6-1) 值得尝试的情况

  • 新技术学习是本人价值核心的资深开发者
  • 想深入研究与代理协作模式的人
  • 对PL设计本身感兴趣的开发者
  • 喜欢在副项目、黑客松中尝试新工具的人

6-2) 现在不应尝试的情况

  • 生产系统、关乎收益的项目
  • 需要团队协作的环境（团队成员不懂Zero）
  • 必须依赖丰富库和工具链的工作
  • 学习时间已经不足的初级开发者（优先深耕TypeScript、Rust、Python）

本人结论是"观察而非学习"。精读一次zerolang.ai文档，把5个原则记在心里，但直接写代码的时间还是投资在自己熟悉的语言上更合理。

7. DSL陷阱与Zero的不同 - Elm、Wasp等过往失败案例

"又一个酷炫的新语言出现了"的兴奋在PL历史上重复无数次，大部分在1到3年内冷却。本人记得的代表案例两个。

7-1) Elm - 函数式前端的承诺

Elm在React时代初期带着"函数式前端的承诺"登场，赢得忠实粉丝，但最终采用率停滞、活动减少。原因是（1）维护者后方支援不足，（2）与JavaScript生态系统的集成成本，（3）学习曲线相对回报不足。

7-2) Wasp - 全栈DSL的雄心

Wasp是"用DSL声明全栈应用"的雄心工具，但与一般全栈框架（Next.js、Remix）相比学习成本不合理，难以休闲采用。

7-3) Zero可能不同的理由

Zero能避开Elm、Wasp陷阱的差异有两点。（1）第一用户是代理而非人类，学习曲线政治学不同。代理以分钟为单位吸收学习成本。（2）有Vercel作为后盾，维护者离场风险相对低。但这两点差异是否足够由市场决定，本人推测的生存概率在30%以下。

8. AI时代新语言设计的5原则 - 超越Zero

无论Zero生存或消失，Zero抛出的设计原则将在PL历史上留下小印记。本人看Zero后整理的"AI时代新语言设计的5原则"如下。这些原则超越Zero，可应用于其他语言设计。

  1. 代理也是用户：语言设计的用户画像不仅要包括人类，还要包括代理。
  2. 可预测性 > 表达力：以放弃部分表达力获得确定性和可预测性的权衡是合理的。
  3. 元数据作为一等公民：变量、函数、模块的意图、所有者、生命周期元数据应是代码的一部分而非注释。
  4. 依赖追踪自动化：编译器应自动追踪函数修改影响哪些其他函数。
  5. 默认沙箱：副作用应在没有显式权限时不可执行。安全是默认值而非附加选项。

这5点是Zero都试图抓住的，未来5年无论哪种新语言出现，这些原则中的某些必然包含在内，本人这样看。Zero消失原则也生存是本文最重要的信息之一。

9. 中文开发者环境的意义 - 哪些人会感兴趣

以本人视角指出Zero在中文开发者市场的意义。中国的情况可能呈现与硅谷略有不同的模式。

9-1) 大型平台公司（阿里、腾讯、字节、百度）

短期内采用可能性极低。这些公司已经具备庞大的Java、Go、TypeScript生态系统，引入新语言的验证成本和人力成本巨大。但内部R&D团队可能实验性尝试。

9-2) 现代创业公司

有好奇心的工程师可能在副项目、黑客松中尝试。但生产投入难以断言。

9-3) 独立开发者、Indie Hacker

最积极尝试的群体。学习自由度高、失败成本低、与代理协作是日常。本人遇到的中文独立开发者中部分已经在看Zero。

9-4) 学生、新人开发者

不推荐。学习时间有限的新人应先专注于市场采用率高的TypeScript、Python。Zero属于在基础之后好奇心层面观察的对象。

10. 风险与局限 - 也可能成为又一座DSL墓地

本人将Zero面临的风险整理为5个。

  • 采用率风险：新语言若采用率不过临界点自然消亡。Zero1年内未集结1000名活跃用户就危险。
  • 维护者风险：Vercel Labs若将R&D优先级转向他处，Zero活动会迅速减少。
  • 生态系统风险：缺乏库、工具链、LSP、调试器是最大的采用障碍。
  • 竞争风险：Google、Microsoft、Anthropic等巨头可能用更大资源后进入相似尝试。
  • 范式风险：若对"代理处理代码是否必须新语言"的质疑增加，市场可能定论为"现有语言+补丁"更合理。

前面提到本人推测的生存概率在30%以下。但30%绝不是小数字。PL历史上生存下来的语言起初都从30%以下出发，其中一些成了标准。Zero若生存，将成为PL历史的小分岔点；即使消失，抛出的设计原则也会被其他语言吸收。无论哪种，观望价值充足。

11. 结论 - 应该追踪什么

2026年5月23日在hada.io以16分相对平静的分数出现的Zero话题，相对于这个分数在本人头脑中留存得更久。原因不是简单的"又一个新语言"，而是"语言设计的第一用户可能不是人类"的想法本身罕见。本人得到的暂定结论有以下三点。

第一，Zero本身不是学习对象，而是观察对象。本人精读了一遍zerolang.ai文档并浏览了GitHub早期代码，但直接写代码的时间还是投资在TypeScript、Python、Rust上。再观察6到12个月，采用率信号明确后再判断。

第二，Zero提出的5个设计原则生存可能性非常高。检查友好、修复友好、确定性输出、强类型、沙箱化——这五点即使Zero消失，也会被其他语言吸收或以库和工具的形式实现。在本人写的TypeScript代码中有意识地应用这些原则，与代理的协作效率会迅速提升。

第三，本人认为最值得追踪的是Vercel的下一步。Zero如何与v0、AI SDK集成、Vercel是否将Zero提升为自家工具的一等公民、其他公司是否开始相似尝试，都将决定未来PL市场的方向。本人下一个12个月的监控清单中Zero排在上位。

一句话结论是：不要学习Zero，去观察Zero。把5个设计原则吸收到自己的代码中。追踪Vercel未来12个月的动向。答案由本人决定。本文只是诚实地分享了帮助你做决定的5个原则和本人的暂定回答。
