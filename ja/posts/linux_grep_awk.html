Linuxテキスト処理の徹底解説：grepとAWKをマスターする

LinuxおよびUNIX系のシステムでは、テキストデータが運用の中心です。ログファイル、設定ファイル、コマンド出力など、あらゆるものがテキスト形式で存在しており、それを効果的に扱う能力はシステム管理者、開発者、データアナリストいずれにとっても必須のスキルです。本記事では、Linuxで最も強力かつ広く使われているテキスト処理ツールであるgrepとawkについて、基本的な使い方から高度な活用法までを詳しく解説します。この2つのツールを使いこなせれば、複雑なテキスト処理を自動化し、大量のデータから必要な情報を素早く抽出し、システム監視や解析業務を効率的に遂行できるようになります。

grep（Global Regular Expression Print）コマンドの徹底解説

grepは、ファイルや標準入力から特定のパターン（主に正規表現）に一致する行を検索して出力する強力なコマンドラインユーティリティです。単純な文字列検索から複雑なパターンマッチングまで、多彩な機能を提供します。

基本的な使い方

grep [オプション] パターン [ファイル...]
  • [オプション]: 検索方法を制御するさまざまなオプションです。
  • パターン: 検索する文字列または正規表現です。
  • [ファイル...]: 検索対象のファイルです。省略すると標準入力（stdin）が使用されます。

よく使う便利なオプション詳解

オプション 説明 例
-i (--ignore-case) 大文字と小文字を区別せずに検索します。 grep -i "error" log.txt
-n (--line-number) 一致した行の行番号も合わせて表示します。 grep -n "warning" log.txt
-v (--invert-match) パターンに一致しない行のみを検索します。 grep -v "success" log.txt
-c (--count) パターンに一致する行の総数のみを出力します。 grep -c "debug" app.log
-l (--files-with-matches) 一致を含むファイル名のみを出力します（内容は表示しません）。 grep -l "TODO" *.java
-L (--files-without-match) パターンに一致する行がないファイル名のみを出力します。 grep -L "FINAL_VERSION" *.txt
-r または -R (--recursive) 指定したディレクトリとそのサブディレクトリまで再帰的に検索します。 grep -r "config_value" /etc/project/
-w (--word-regexp) パターンが独立した単語として一致する場合のみ検索します（空白や特殊文字で区切られている必要があります）。 grep -w "main" program.c（main_functionは不一致、単独のmainのみ一致）
-x (--line-regexp) パターンが行全体と完全に一致する場合のみ検索します。 grep -x "localhost:8080" access.log
-E (--extended-regexp) 拡張正規表現（ERE）を使用します。egrepコマンドと同等です。 `grep -E "error
-F (--fixed-strings) パターンを正規表現ではなく固定文字列として扱います（特殊文字もそのまま扱います）。 grep -F "*ERROR*" log.txt（*をそのまま文字として検索）
-A NUM (--after-context=NUM) 一致行とその後ろのNUM行も合わせて表示します。 grep -A 2 "Exception" error.log
-B NUM (--before-context=NUM) 一致行とその前のNUM行も合わせて表示します。 grep -B 3 "SEGFAULT" core_dump.txt
-C NUM (--context=NUM) 一致行とその前後NUM行を合わせて表示します（-A NUM -B NUM相当）。 grep -C 1 "critical error" system.log
--color=auto 一致した部分を色付きで強調表示します（多くのシステムで既定）。 grep --color=auto "pattern" file.txt
-o (--only-matching) 行全体ではなくパターンに一致した部分のみを出力します。各マッチは別の行に表示されます。 grep -o -E "[0-9]{1,3}\.[0-9]{1,3}\.[0-9]{1,3}\.[0-9]{1,3}" access.log

grepと正規表現（Regular Expressions）

grepの真価は正規表現と組み合わせて使うときに発揮されます。正規表現は、テキストの特定のパターンを記述するための形式言語です。

  • 基本正規表現（BRE - Basic Regular Expressions）: grepのデフォルトモードです。*、.、^、$、[]、\などのメタ文字を使用します。+、?、|、()のような一部のメタ文字は、特別な意味として使うときに前に\を付ける必要があります（例：\+、\?、\|、\(\)）。
  • 拡張正規表現（ERE - Extended Regular Expressions）: grep -Eまたはegrepを使用します。BREの全機能に加え、+、?、|、()などを\なしで利用でき、表現がシンプルになります。

主な正規表現メタ文字および構成要素：

メタ文字/構成要素 説明 BRE例（必要に応じて\） ERE例（grep -E）
. 任意の1文字に一致（改行を除く） a.c a.c
* 直前の文字が0回以上繰り返されるとき一致 ab*c（ac, abc, abbc...） ab*c
+ 直前の文字が1回以上繰り返されるとき一致（ERE） ab\+c ab+c（abc, abbc...）
? 直前の文字が0回または1回現れるとき一致（ERE） ab\?c ab?c（ac, abc）
^ 行頭に一致 ^start ^start
$ 行末に一致 end$ end$
[abc] 角括弧内の文字のいずれかに一致（aまたはbまたはc） [aeiou] [aeiou]
[^abc] 角括弧内の文字以外のいずれかに一致 [^0-9]（数字以外） [^0-9]
[a-z] aからzまでのいずれかに一致（範囲指定） [A-Za-z0-9] [A-Za-z0-9]
|（BRE）|（ERE） OR条件。前後のパターンのいずれかに一致 apple|orange `apple
\(...\)（BRE）(...)（ERE） グループ化。パターンの一部をまとめて範囲指定したり、後方参照に使用 \(ab\)\+ (ab)+
{n} 直前の文字が正確にn回繰り返される（ERE） a\{3\} a{3}（aaa）
{n,} 直前の文字がn回以上繰り返される（ERE） a\{2,\} a{2,}（aa, aaa...）
{n,m} 直前の文字がn回以上m回以下繰り返される（ERE） a\{2,4\} a{2,4}（aa, aaa, aaaa）
\b 単語境界（word boundary）。単語の先頭または末尾を意味（GNU grep） \bword\b \bword\b
\w 単語文字（英数字とアンダースコア）。[A-Za-z0-9_]に近い（GNU grep） \w+ \w+
\s 空白文字（スペース、タブなど）（GNU grep） \s* \s*

実用例の拡張

  1. ログファイルから特定日のエラーメッセージのみを抽出：

    # 2025年7月20日に発生したERRORメッセージを検索
grep "2025-07-20" /var/log/syslog | grep "ERROR"
# あるいは正規表現で一度に検索（EREを使用）
grep -E "^2025-07-20.*ERROR" /var/log/syslog

  2. 特定ユーザー（例：'nginx'）のプロセスを見つけてCPU/メモリ使用量を確認：

    ps aux | grep "^nginx" # nginxで始まるユーザー名のプロセス
# ps auxの出力で1番目のフィールドが'nginx'である行だけをgrep
ps aux | grep -E "^nginx\s+"

  3. 設定ファイルからコメント（#で始まる行）と空行を除外し、実際の設定値だけを表示：

    grep -v -E "^\s*#|^\s*$" /etc/ssh/sshd_config
# ^\s*# : 空白で始まる可能性のあるコメント行
# ^\s*$ : 空白のみ、または何もない空行
# | : OR条件
# -v : 上記パターンを除外

  4. ソースコードから関数定義を探す（例：'function_name('パターン）：

    grep -E -n -r "my_function\s*\(" ./src_directory/
# -n: 行番号表示、-r: サブディレクトリも検索
# \s*\( : 関数名の後ろに空白があってもなくてもよく、開きカッコが続くパターン

  5. IPアドレスのみを抽出：

    grep -E -o "([0-9]{1,3}\.){3}[0-9]{1,3}" access.log
# -o: 一致した部分のみを出力
# ([0-9]{1,3}\.){3} : 1〜3桁の数字とドット(.)が3回繰り返される（例：192.168.1.）
# [0-9]{1,3} : 最後の1〜3桁の数字（例：100）

  6. 特定の拡張子のファイルのみで検索：

    grep "search_term" --include=\*.{c,h} -r ./project_dir/
# --includeを使って.cまたは.hファイルのみを検索
grep "api_key" --exclude-dir=node_modules -r .
# --exclude-dirを使って特定ディレクトリ(node_modules)を検索対象から除外

AWKコマンドの徹底解説

awkはパターン検索とテキスト／データ操作のための強力なプログラミング言語です。特に列（column）ベースのデータ処理やレポート生成に優れた能力を発揮します。C言語に似た構文を持ち、複雑な条件処理、演算、文字列関数などをサポートします。

AWKプログラムの基本構造

pattern { action }
  • pattern: どの行に対してactionを実行するかを決める条件です。省略するとすべての行に対してactionが実行されます。
    • 正規表現：/regex/
    • 比較式：$1 == "ERROR"、$3 > 100
    • 文字列マッチ：$2 ~ "pattern"（マッチ）、$2 !~ "pattern"（非マッチ）
    • 特別なパターン：BEGIN、END
  • action: 波括弧{}で囲み、セミコロン(;)で区切られた1つ以上のawk文から構成されます。省略した場合のデフォルト動作はprint $0（現在の行全体を出力）です。

特別なパターン：

  • BEGIN { actions }: 入力ファイルを読み込む前に一度だけ実行されます。変数の初期化やヘッダー出力などに使用します。
  • END { actions }: すべての入力処理が終わった後に一度だけ実行されます。合計の計算やサマリーレポート出力などに使用します。

フィールド処理と区切り文字

awkは入力行を自動的にフィールド（field）に分割します。

  • $0: 現在処理中の行全体を表します。
  • $1、$2、$3、...: 1番目、2番目、3番目のフィールドを表します。
  • フィールド区切り文字（Field Separator）:
    • FS（Input Field Separator）: 入力側のフィールド区切り文字です。デフォルトは空白（スペース、タブ）です。
      • コマンドラインで-Fオプション指定：awk -F, '{print $1}' data.csv（カンマ区切りのCSVファイル）
      • BEGINブロックで設定：awk 'BEGIN { FS = ":" } {print $1, $7}' /etc/passwd（コロン区切りのファイル）
    • OFS（Output Field Separator）: 出力側のフィールド区切り文字です。デフォルトは空白です。
      • BEGINブロックで設定：awk 'BEGIN { OFS = "\t" } {print $1, $2}' file.txt（タブ区切りで出力）
# /etc/passwdからユーザー名（1番目のフィールド）とシェル（7番目のフィールド）をコロン区切りで出力
awk -F: '{print "User:", $1, "Shell:", $7}' /etc/passwd

# CSVから1番目と3番目のフィールドをタブ区切りで出力
awk -F, 'BEGIN{OFS="\t"} {print $1, $3}' data.csv

条件文とパターンの詳細

awkはさまざまな条件やパターンを使って、特定の行にのみアクションを実行できます。

  • 正規表現パターン:

    # 'error' または 'fail'（大文字小文字を区別せず）を含む行の全体を出力
/[Ee]rror|[Ff]ail/ {print $0}

    （シェルで実行する場合）

    awk '/[Ee]rror|[Ff]ail/ {print $0}' log.txt

  • 比較式パターン:

    # 3番目のフィールドの値が100より大きい行のみ出力
$3 > 100 {print "Large Value Found:", $0}

    （シェルで実行する場合）

    awk '$3 > 100 {print "Large Value Found:", $0}' data.txt

    # 1番目のフィールドが正確に "user_admin" である行の2番目と4番目のフィールドを出力
$1 == "user_admin" {print $2, $4}

    （シェルで実行する場合）

    awk '$1 == "user_admin" {print $2, $4}' users.txt

  • 範囲パターン: 特定の開始パターンから終了パターンまでのすべての行にアクションを実行します。

    # "START_SECTION" から "END_SECTION" までの行を出力
/START_SECTION/,/END_SECTION/ {print}

    （シェルで実行する場合）

    awk '/START_SECTION/,/END_SECTION/ {print}' config.file

  • 論理演算子: &&（AND）、||（OR）、!（NOT）で複合条件を作れます。

    # 1番目のフィールドが "admin"、かつ4番目のフィールドが0より大きい行を出力
$1 == "admin" && $4 > 0 {print $0}

    （シェルで実行する場合）

    awk '$1 == "admin" && $4 > 0 {print $0}' access_records.txt

  • アクション内の条件文（if-else）:

    {
    if ($3 > 1000) {
        status = "High"
    } else if ($3 > 500) {
        status = "Medium"
    } else {
        status = "Low"
    }
    print $1, $2, $3, status
}

    （シェルで実行する場合）

    awk '{
    if ($3 > 1000) {
        status = "High"
    } else if ($3 > 500) {
        status = "Medium"
    } else {
        status = "Low"
    }
    print $1, $2, $3, status
}' resource_usage.txt

主な組み込み変数

awkはプログラミングを容易にするさまざまな組み込み変数を提供します。

変数名 説明 例（シェルで実行する場合）
NR Number of Records。これまでに処理したレコード（行）の総数。 awk '{print NR, $0}' file.txt（行番号付きで出力）
FNR File Number of Record。現在処理中のファイル内のレコード数。複数ファイル処理時に便利。 awk '{print FILENAME, FNR, $0}' file1.txt file2.txt
NF Number of Fields。現在のレコード（行）のフィールド数。 awk '{print "Line", NR, "has", NF, "fields:", $0}' file.txt
FILENAME 現在処理中の入力ファイル名。 awk '/error/ {print FILENAME, ":", $0}' *.log
FS Input Field Separator。入力フィールド区切り文字（デフォルト：空白）。 awk -F';' '{print $1}' data.csv <br> awk 'BEGIN{FS=";"} {print $1}' data.csv
OFS Output Field Separator。出力フィールド区切り文字（デフォルト：空白）。 awk 'BEGIN{OFS=","} {print $1, $2}' file.txt（カンマ区切りで出力）
RS Record Separator。入力レコード区切り文字（デフォルト：改行\n）。 awk 'BEGIN{RS="\n\n"} {print $1}' paragraphs.txt（空行で区切られた段落を処理）
ORS Output Record Separator。出力レコード区切り文字（デフォルト：改行\n）。 awk 'BEGIN{ORS=";"} {print $1}' items.txt（セミコロンでレコードを区切って出力）
ARGC Argument Count。コマンドライン引数の数。 awk 'BEGIN{print "ARGC:", ARGC}' file.txt
ARGV Argument Vector。コマンドライン引数を格納する配列。ARGV[0]はawk自体。 awk 'BEGIN{for(i=0;i<ARGC;i++) print ARGV[i]}' file.txt
ENVIRON 環境変数にアクセスできる連想配列。 awk 'BEGIN{print "User:", ENVIRON["USER"]}'

AWKスクリプティング：変数、配列、ループ

awkは単なるフィルタリングを超えて、スクリプト言語としての機能も備えています。

  • 変数の使用:

    # 3番目のフィールドの合計を計算
{ sum += $3 } END { print "Total Sum:", sum }

    （シェルで実行する場合）

    awk '{ sum += $3 } END { print "Total Sum:", sum }' numbers.txt

  • 連想配列（Associative Arrays）: awkの配列は数値インデックスだけでなく、文字列インデックスも使用できます。

    # 1番目のフィールド（例：IPアドレス）の出現回数を計算
{ counts[$1]++ } END { for (ip in counts) print ip, "occurred", counts[ip], "times" }

    （シェルで実行する場合）

    awk '{ counts[$1]++ } END { for (ip in counts) print ip, "occurred", counts[ip], "times" }' access.log

  • ループ（Loops）: forループとwhileループが使えます。

    # 各行のすべてのフィールドを逆順に出力
{
    for (i = NF; i >= 1; i--) {
        printf "%s ", $i
    }
    printf "\n" # または print ""
}

    （シェルで実行する場合）

    awk '{
    for (i = NF; i >= 1; i--) {
        printf "%s ", $i
    }
    printf "\n" # または print ""
}' data.txt

    # 1から5までの数字を出力（BEGINブロック）
BEGIN { i=1; while(i<=5) { print i; i++ } }

    （シェルで実行する場合）

    awk 'BEGIN { i=1; while(i<=5) { print i; i++ } }'

  • ユーザー定義関数（User-Defined Functions）:

    function format_size(bytes,    suffix_idx, suffixes) { # ローカル変数は追加パラメータとして宣言
    suffixes = "Bytes KB MB GB TB PB"
    split(suffixes, suffix_array, " ")
    suffix_idx = 1
    while (bytes >= 1024 && suffix_idx < length(suffix_array)) {
        bytes /= 1024
        suffix_idx++
    }
    return sprintf("%.2f %s", bytes, suffix_array[suffix_idx])
}

# ファイルサイズ（ls -lの5番目のフィールド）を読みやすい形式にフォーマット（NR > 1でヘッダーを除外）
# シェルで実行する例
# ls -l | awk '
# function format_size(bytes, suffix_idx, suffixes) {

    （上のls -l例をシェルでそのまま実行できる形で以下に示します）

実務での活用例 徹底解説

システム監視

  1. メモリ使用量が特定のしきい値（例：5.0%）を超えるプロセスを探す（プロセスID、メモリ使用率、コマンドを出力）：

    ps aux | awk 'NR > 1 && $4 > 5.0 {printf "PID: %s, %%MEM: %s, CMD: %s\n", $2, $4, $11}'
# NR > 1 : ヘッダー行を除外
# $4 > 5.0 : 4番目のフィールド（メモリ使用率）が5.0より大きい場合
# printf : 書式付き出力

  2. ディスク使用量が90%以上のパーティションを探す（ファイルシステム、使用率、マウント位置を出力）：

    df -h | awk 'NR > 1 && int($5) > 90 {print "FS:", $1, "| Usage:", $5, "| Mounted on:", $6}'
# int($5) : %記号を取り除き整数に変換（GNU awkでは $5+0 でも可）
# df -P | awk 'NR > 1 && $5+0 > 90 {print $1, $5, $6}' # POSIX互換、%は自動除去

  3. 特定ポート（例：80）を使用しているネットワーク接続状態を確認：

    netstat -tulnp | grep ":80\s" | awk '{print $4, $5, $7}'
# $4: Local Address, $5: Foreign Address, $7: PID/Program name

ログ解析

  1. Webサーバーログ（common log format）から特定時間帯（例：10時〜11時台）の404エラーログを抽出し、リクエストパスを出力：

    # 例：20/Jul/2025:10:00:00 から 20/Jul/2025:10:59:59 まで
grep "20/Jul/2025:10:" access.log | awk '$9 == "404" {print $1, $4, $7, $9}'
# $1: IP, $4: Timestamp, $7: Requested Path, $9: Status Code

  2. IPアドレス別のアクセス回数を計算し、上位10件のIPを出力：

    awk '{print $1}' access.log | sort | uniq -c | sort -nr | head -n 10
# awk '{print $1}' : 1番目のフィールド（IPアドレス）のみ抽出
# sort : IPアドレスをソート
# uniq -c : 重複を除去し出現回数をカウント
# sort -nr : 数値降順ソート（最も多いアクセスから）
# head -n 10 : 上位10件のみ出力

    AWKだけでも可能：

    awk '{ip_counts[$1]++} END {for (ip in ip_counts) print ip_counts[ip], ip}' access.log | sort -nr | head -n 10

  3. SSHログイン失敗ログから試行されたユーザー名とIPアドレスを抽出：

    grep "Failed password" /var/log/auth.log | awk '{print "User:", $(NF-5), "IP:", $(NF-3)}'
# "Failed password for invalid user admin from 1.2.3.4 port 12345 ssh2" のようなログ形式を想定
# $(NF-5) : 末尾から6番目のフィールド（ユーザー名）
# $(NF-3) : 末尾から4番目のフィールド（IPアドレス）
# ログ形式によってフィールド番号は変わります。
# 例: "Failed password for root from 116.37.102.13 port 40940 ssh2"
# この場合は awk '{print "User:", $9, "IP:", $11}'

データ処理と変換

  1. CSVファイルから特定条件（例：3列目の値が "Completed"）を満たす行の1列目と5列目を新しいCSVファイルに保存：

    awk -F, '$3 == "Completed" {print $1 "," $5}' input.csv > output.csv

    あるいはOFSを使う：

    awk -F, 'BEGIN{OFS=","} $3 == "Completed" {print $1, $5}' input.csv > output.csv

  2. テキストファイルからすべてのメールアドレスを抽出し、1行ずつソートして重複を除去：

    grep -E -o "\b[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,6}\b" file.txt | sort | uniq
# grep -o : 一致部分のみ出力
# \b : 単語境界
# [A-Za-z0-9._%+-]+ : ユーザー名部分
# @ : 区切り
# [A-Za-z0-9.-]+ : ドメイン名部分
# \.[A-Za-z]{2,6} : トップレベルドメイン（例：.com、.co.jp）

  3. 数値リストファイルから各数値を2乗して出力：

    # numbers.txt の内容例:
# 1
# 5
# 10

    awk '{print $1, "squared is", $1*$1}' numbers.txt

    出力：

    # 1 squared is 1
# 5 squared is 25
# 10 squared is 100

  4. 複数ファイルの特定列の合計を計算（例：各ファイルの2列目の合計と総合計）：

    # data1.txt:
# itemA 10
# itemB 20
# data2.txt:
# itemC 30
# itemD 40

    GNU Awkの拡張を使う場合：

    awk '
    { current_sum += $2 }
    ENDFILE { # GNU Awkの拡張。各ファイル処理後に実行
        print "Sum for", FILENAME, ":", current_sum
        total_sum += current_sum
        current_sum = 0 # 次のファイルのために初期化
    }
    END {
        print "Grand Total:", total_sum
    }
' data*.txt

    POSIX互換（FNRを利用）：

    awk '
    FNR == 1 && NR != 1 { # 新しいファイルの開始（最初のファイルを除く）
        print "Sum for", prev_filename, ":", current_sum
        total_sum += current_sum
        current_sum = 0
    }
    { current_sum += $2; prev_filename = FILENAME }
    END {
        print "Sum for", prev_filename, ":", current_sum # 最後のファイルの合計
        total_sum += current_sum
        print "Grand Total:", total_sum
    }
' data*.txt

grepとAWKの組み合わせ

grepで1次フィルタリングを行い、その結果をパイプ(|)でawkに渡して2次加工する方法は非常に効果的です。

# /var/log/secure から "Accepted publickey" ログのうちユーザー名とIPアドレスだけを抽出
grep "Accepted publickey" /var/log/secure | awk '{print "User:", $9, "IP:", $11, "Port:", $13}'

# カレントディレクトリのCソースファイル(*.c)で "include" という単語を含む行を見つけ、
# それらの行からファイル名と行番号、そして#includeの後ろのヘッダファイル名だけを抽出
grep -Hn "include" *.c | awk -F'[:<>]' '{print "File: " $1 ", Line: " $2 ", Header: " $4}'
# grep -H: ファイル名出力、-n: 行番号出力
# awk -F'[:<>]': コロン(:), 開きヤマ(<), 閉じヤマ(>) を区切り文字として使用
# 例: main.c:10:#include <stdio.h> -> $1=main.c, $2=10, $3=#include , $4=stdio.h

まとめ

grepとawkは、Linux/UNIX環境でテキストを扱う際のスイスアーミーナイフのような存在です。grepは強力なパターン検索能力で必要な情報を素早く見つけ出し、awkは構造化データの処理やレポート作成に特化しています。この2つのツールの豊富なオプションと正規表現、そしてawkのプログラミング機能を深く理解し、組み合わせて使うことで、複雑で膨大なテキストデータも手軽に望む形に加工・分析できるようになります。

もちろん、非常に複雑なロジックや大規模データ処理にはPythonやPerlといった汎用スクリプト言語の方が適している場合もありますが、日々のシステム管理、ログ解析、簡単なデータ変換作業の大半はgrepとawkだけでも十分に効率よくこなせます。継続的な練習と、実際のさまざまな問題に適用してみることが、これらのツールを習得する最良の方法です。
