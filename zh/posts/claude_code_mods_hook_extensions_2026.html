mod的定义与架构 — 区别于设置钩子的会话常驻结构

原文把mod定义为在Claude Code会话内部运行的小型JavaScript或TypeScript文件。mod可以观察会话中发生的事情，可以改变Claude Code的行为，也可以在终端或桌面应用中绘制自己的界面。无需先学习API：运行claude，用话语描述想要的mod，当Claude Code询问是否允许热重载时点头同意，回合结束时mod就会出现。

Claude Code本来就允许通过设置、权限规则（permission rules）、斜杠命令、技能和状态栏改变许多行为。原文说明，mod更进一步，可以改写或替换Claude Code的行为，还能绘制自定义界面。在内部，mod是随插件一起发布的钩子，每个mod都会在事件发生的当下看到会话里的所有事件。

与设置钩子的区别，原文用一小段话概括：设置钩子对每个事件运行一条shell命令，并通过stdin和stdout传递JSON；mod则只加载一次，常驻在会话中。由这一结构带来的特点可归纳为四点。

  • 一次加载，常驻会话：不必为每个事件启动进程，模块加载后在整个会话期间一直存在。
  • 保持状态：把值放进由宿主保管的$.state而不是模块变量，就能在重载后保留下来。
  • 更新界面：绘制随事件发生而更新的界面。
  • 回调：回调Claude Code，打开窗格、运行进程、注册斜杠命令，或注册模型可调用的工具。

据原文，Claude Code自己也在使用mod。AGENTS.md支持以及对话旁边的/diff窗格等部分功能就是以mod形式构建的，其源码与测试位于公开仓库anthropics/claude-code的mods/目录下，可以读到团队如何编写mod。

钩子链与三大动作模式 — Observe·Rewrite·Answer的运作原理

mod以插件钩子串成的链条运行。模块导出register(on, options)，在其中用on(event, matcher?, hook)添加钩子。每个钩子形状相同，原文的代码用注释说明了这个形状和三个参数的含义。

on("tool.call", { tool: "Bash" }, async ($, e, next) => {
                      // $    the mods API: ui, session, state, store, fs, process, clock, http, tool, command, model, ...
                      // e    this event's input, as plain data
                      // next passes e to the other plugins and then to Claude Code's own behavior
                      return next(e);
                    });

钩子像中间件一样串联：你的钩子先运行，next(e)把事件交给下一个插件，最底层由Claude Code做它本来就要做的事。钩子能做三件事。观察（Observe）是用const r = await next(e);取得结果、查看后原样返回，例如记录每次文件编辑，或在每个回合结束后读取数值。改写（Rewrite）是return next({ ...e, command: safer })，改变链的其余部分所看到的输入。直接应答（Answer）是不调用next而返回{ deny: "…" }，用来拒绝工具调用，或由钩子自己处理命令与工具。

模式区分代码形式原文示例在链中的位置
Observe (观察)const r = await next(e); /* look */ return r记录每次文件编辑、每回合后读取数值调用next之后查看结果
Rewrite (改写)return next({ ...e, command: safer })改变链的其余部分所看到的输入调用next之前修改输入
Answer (直接应答)return { deny: "…" } (不调用next)拒绝工具调用、自行处理命令或工具终止链条，由钩子代为作答

原文所述的事件范围包括工具调用、提交的提示词、回合的开始与结束、会话的开始与结束、斜杠命令，以及代表界面每一块绘制内容的ui.render。从正文和代码中能确认名称的有以下几个。

  • tool.call：工具调用，可用{ tool: "Bash" }这样的匹配器限定到某个工具。
  • prompt.submit：提交的提示词，原文把给每个提示词附加团队规范的钩子列为一个创意。
  • turn.start · turn.complete：回合的开始与结束，子代理的回合用e.agentId区分。
  • session.start：会话开始，原文把会话的开始与结束都列为事件。
  • command.run：已注册的斜杠命令被运行时，用{ command: "replay" }这样的命令名限定。
  • ui.render：界面的某一块被绘制时，用{ component: "AbovePrompt" }这样的组件限定。

模块在自己的沙箱里运行，没有DOM，也没有Node，因此与外部相关的一切都要经过$。原文代码的注释写明，$包含ui、session、state、store、fs、process、clock、http、tool、command、model等。

mod插件的组成要素 — 清单·类型契约·$.state

mod不是单独的格式，而是一个普通的插件文件夹。原文展示的Token Weather目录结构如下。

token-weather/
                    ├── .claude-plugin/
                    │   ├── plugin.json
                    │   └── types/            (written by Claude Code when it loads the mod)
                    ├── hooks/
                    │   ├── hooks.json
                    │   └── token-weather.mjs
                    ├── types/
                    │   └── index.d.ts        (added in step 3)
                    └── tests/
                        └── token-weather.test.ts   (added in step 5)

各部分的职责如下。

  • .claude-plugin/plugin.json：标准的插件清单，记录name、version、description和author。
  • hooks/hooks.json：在modules下准确指向一个模块，原文写的是「A mod has exactly one」。
  • types/index.d.ts：在PluginState接口中声明$.state所存值的类型契约，还需在清单中加上"types": "./types/index.d.ts"。
  • .claude-plugin/types/：Claude Code每次加载mod时把该构建的声明写入的文件夹，编辑器和tsc -p无需额外步骤即可使用。

原文最强调的习惯，是把热重载考虑在内。模块级的let readings = []看似顺手，但热重载是一次全新的加载，register与session.start会再次执行，模块变量从头开始。历史数据应放进$.state，它在宿主中保存具名的值，因此重载后依然存在。值通过plugin和key来指定，如{ plugin: "token-weather", key: "readings" }，用$.state.get和$.state.set读写。

如果漏掉声明，claude plugin validate会以指出修正处的错误拦下你。原文展示的错误是「token-weather.readings is not declared: the manifest's types contract must name it in interface PluginState { … }」。认真声明也有回报：在渲染钩子运行期间执行的$.state.get会订阅那次绘制，此后每次$.state.set都会让色带重绘，不必调用$.ui.invalidate。

示例1：Token Weather — 上下文余量与12回合趋势可视化

原文从空文件夹开始构建的第一个mod是Token Weather。每个回合结束后，它读取上下文窗口已占用多少，并在提示符正上方的色带中画出一行。这一行包含天气图标、占用百分比、窗口中已用的token数、最近回合的小图表，以及上一回合增加的量，整个模块约80行。原文展示了色带从18%的Clear、67%的Showers到81%的Storm逐步填满的过程。

上下文使用率天气标识与文字显示颜色代码中的upTo值
低于25%☀ Clearyellow25
25% ~ 49%☁ Cloudycyan50
50% ~ 74%☂ Showersblue75
75% ~ 89%☇ Stormmagenta90
90%以上↯ Compact soonredInfinity

提示符正上方的色带是名为AbovePrompt的组件。原文指出，Claude Code自己不在这里绘制任何内容，所以适合作为第一个练习对象。给这个组件的ui.render事件挂上钩子并返回元素树即可。原文第二步的代码如下。

// hooks/token-weather.mjs
                    export function register(on) {
                      on("ui.render", { component: "AbovePrompt" }, ($, e, next) => {
                        const { Box, Text } = $.ui.resolve(e);
                        return Box({
                          paddingX: 1,
                          children: [Text({ color: "yellow", bold: true, children: "☀  Clear skies" })],
                        });
                      });
                    }

元素不是全局变量。Claude Code绘制的每种界面（surface）支持的元素集合略有不同，所以由$.ui.resolve(e)返回当前界面的构造函数。用claude --plugin-dir ./token-weather打开会话后，提示符上方会出现「☀ Clear skies」，由于文件夹处于监视状态，每次保存都会就地重新加载模块，无需重启。

数值取自$.session.usage()，它返回与状态栏相同的数字，包含context.tokens、context.window和context.percent。调用本身免费，只有在要求明细时才会发出token计数请求。钩子在session.start与turn.complete中先调用next(e)再进行观察，并用if (!e.agentId)排除子代理的回合，只读取主循环的回合。历史只保留最近12条，用▁▂▃▄▅▆▇█这些字符绘制图表。

原文列出三个值得照搬的细节。组件的props在e.props中：hasSurvey为真时表示问卷要使用这条色带，钩子就用next(e)让出，bodyColumns是色带的实际宽度，窗格停靠在旁边时比终端更窄。这段代码仅在宽度不少于60列时才加上图表和增减量。没有要画的内容时，返回next(e)就把色带交还给Claude Code和其他mod。最后，使用单宽度符号而非emoji，在任何终端字体中都能对齐。

示例2：Blast Radius — 危险命令拦截与演练报告

当Claude用Bash调用下列任何一项时，Blast Radius会拦住该调用。它先算出命令将触及的对象，再打开带有Proceed和Cancel的窗格。按2，Claude会收到附带理由的拒绝；按1，命令按原样执行。

  • rm -rf
  • git reset --hard
  • git clean
  • 强制推送（force push）
  • 数据库迁移（database migration）

这个mod使用三个钩子：针对Bash的tool.call，以及针对Pane和AbovePrompt的ui.render。核心是前面表格中的直接应答（Answer），原文代码如下。

on("tool.call", { tool: "Bash" }, async ($, e, next) => {
                      const risk = classify(String(e.command ?? ""));
                      if (risk === null) return next(e);                 // everything else runs as normal
                      const report = await measure($, risk, await $.session.cwd());  // git status, git clean -n, du, ...
                      held = { command: e.command, risk, report, decision: null };
                      const opened = await $.ui.open({ id: "blast-radius", title: "Blast Radius", focus: true });
                      if (!opened.isPlaced) held.where = "band";         // too narrow for a pane: draw above the prompt
                      while (held.decision === null && !next.signal.aborted) {
                        await $.process.run(["sleep", "0.25"]);          // time inside $ calls doesn't count against the hook's time limit
                      }
                      if (held.decision === "proceed") return next(e);   // let it run
                      return { deny: `Blast Radius held this command: the user pressed Cancel. It would have: ${report.summary}.` };
                    });

原文从这段代码指出四点。第一，演练通过$.process.run进行。报告来自这些工具自己的命令：git status --porcelain、git clean -n、git log HEAD..origin/main和showmigrations，参数以argv数组传入，所以路径中的任何字符都不会被当作shell代码执行。第二，拦住调用的方法：钩子每次分派获得10秒属于自己的时间，但在$调用内部等待的时间不计入。因此循环用短暂的sleep进程等待，直到按钮的onPress设定了决定，并在next.signal中止时（按下Esc）放弃。

第三，按钮可以带快捷键：Button({ label: "Proceed", hotkey: "1", onPress })可以通过点击、Tab加Enter或数字键触发。第四，退回到色带：终端足够宽时窗格停靠在对话旁边，当$.ui.open返回isPlaced: false时，同一份报告就画在提示符上方。

原文也明确写出了局限。这个mod是安全网，而不是权限系统。它读取的是命令文本，所以$(…)、别名（alias）以及调用rm的脚本都能绕过。若要强制拦截，请使用权限规则。

示例3：Replay Theater — 按回合分步回放文件编辑差异

Replay Theater在回合运行期间记录每一次Edit和Write调用，对象是文件以及写入前后的文本。回合结束后，提示符上方会出现提示，按r或输入/replay，窗格就会带着编号步骤条和Prev、Next、Close按钮，逐个diff地走完这些编辑。这个mod从不阻止或改变编辑，只做观察，原文代码如下。

on("tool.call", async ($, e, next) => {
                      if (EDIT_TOOLS.has(e.tool)) state.pending.push(...(await stepsFor($, e)));  // old/new text → diff
                      return next(e);                                                              // the edit runs untouched
                    });
                    on("turn.start", ($, e, next) => { if (!e.agentId) state.pending = []; return next(e); });
                    on("turn.complete", async ($, e, next) => {
                      const r = await next(e);
                      if (!e.agentId && state.pending.length) state.replay = state.pending;       // one replay per turn
                      return r;
                    });
                    on("session.start", async ($, e, next) => {
                      const r = await next(e);
                      await $.command.register({ name: "replay", description: "Step through the last turn's file edits" });
                      return r;
                    });
                    on("command.run", { command: "replay" }, async ($, e) => ({ text: (await openReplay($)) ? "Replaying" : "No edits" }));

原文归纳出四点可学之处。其一是事件配对：turn.start与turn.complete把编辑归入每回合一次的回放，e.agentId把子代理的回合排除在分组之外。其二是注册斜杠命令：在session.start中调用$.command.register，并在command.run中应答。其三是读取文件：对于Write，在写入落盘前用$.fs.read读取旧内容，因此diff是真实的。其四是布局属于界面的职责：全屏时窗格停靠在右侧，80列时在提示符上方内联打开，mod在两种情况下绘制同一棵树。

mod的分发与安全边界 — 本地执行权限与来源核查

原文第五步是验证与测试。claude plugin validate以Claude Code读取的同样方式读取清单和模块源码，并报告模块挂接了哪些事件、调用了哪些$方法。claude plugin test针对真实的Claude Code运行时执行插件的*.test.ts文件。测试中用on注册的钩子在链中排在mod之后运行，并代替Claude Code给出应答，因此可以精确控制$.session.usage()返回的值。

claude plugin validate ./token-weather
                    claude plugin test ./token-weather
                    claude --plugin-dir ./token-weather

mod就是插件，所以分发方式与插件相同。只要有一个带.claude-plugin/marketplace.json的文件夹就可以充当市场，放进GitHub仓库后，该仓库就成为你的市场，用普通的推送即可更新。安装只需在Claude Code中输入三条命令：/plugin marketplace add your-org/my-mods、/plugin install token-weather@my-mods和/reload-plugins。mod在重载时启动，若没有出现则重启Claude Code。包含mod的插件也可以提交到Claude directory（claude.ai/directory/manage）。

关于安全，原文的核心语句只有一句。mod是在你机器上的Claude Code内部、以与Claude Code相同的访问权限运行的代码，作者是发布者而不是Anthropic，所以要「install mods the way you'd install a package: read the repo first and only install from people you trust」。围绕这句话，能从原文确认的事实如下。

  • mod拥有的访问范围与Claude Code拥有的相同。
  • mod的作者是发布者而不是Anthropic，因此要先读仓库，只安装信任的人发布的mod。
  • 在你运行命令之前，不会安装任何东西。
  • 模块在没有DOM和Node的沙箱中运行，与外部的所有接触都要经过$。原文没有把这个沙箱描述为权限隔离。
  • 钩子每次分派获得10秒属于自己的时间，在$调用内部等待的时间不计入。

原文自己的例子也指向同一方向：Blast Radius是安全网而不是权限系统，要强制拦截就应使用权限规则。

未能确认的事项

  • 在Claude Code 2.1.286及以下版本加载mod时的错误信息或回退行为。
  • $.state中的值在结束会话后恢复（resume）时是否会被还原（原文只说明了重载后保留）。
  • 终端和桌面应用之外，如VS Code扩展等界面可用的$.ui组件的完整清单。
  • 向claude.ai/directory/manage提交mod时所采用的审核标准。
  • 钩子内部创建的异步定时器或后台任务在会话结束时如何被清理。
