OpenAI Codex Record & Replay: Show It Once, Reuse It as a Skill

When Programming by Demonstration Meets LLM Agents — PbD Revival, RPA Comparison, and Claude Code Skill Analysis

2026-06-20 Tech & IT

Introduction: "If It's Hard to Explain, Just Show It"

There have always been two fundamental approaches to automation: describe what to do in text, or demonstrate it directly. The latter has a formal name in computer science — Programming by Demonstration (PbD) — and a history stretching back to the 1980s. Early PbD systems powered industrial robot teaching. By the 2000s, tools like CoScripter and Vegemite attempted to apply the concept to web automation. The results were promising in research but brittle in production: systems recorded precise screen coordinates and UI selectors, which broke the moment an interface changed.

As of June 2026, OpenAI has shipped what is arguably the most practically usable PbD implementation yet: Codex Record & Replay. Demonstrate a workflow once on macOS, and Codex converts it into an editable, version-controllable SKILL.md file — a reusable agent Skill that can be triggered at will. This article analyzes what the feature actually does, where it genuinely helps and where it falls short, and how it compares to Claude Code's approach to agent Skills. All factual claims are grounded in OpenAI's official documentation and coverage as of June 2026.

1. How Record & Replay Works — The Three-Stage Flow

1.1 Record: State Your Goal, Then Demonstrate

Before starting a recording, the user briefly explains the goal and any variable inputs to Codex. Something like: "I'm going to record how I file the weekly team expense report in Notion; the date and total amount change each week." Then the user performs the actual workflow on screen, while Codex observes via macOS Computer Use — capturing both user actions and window content. When the workflow is complete, the recording stops. OpenAI explicitly recommends using test data during demonstration, never real credentials or secrets.

1.2 Process: Codex Infers Intent and Drafts a Skill

After recording ends, Codex analyzes the captured action sequence and screen context. The key insight here is that it does not simply log "click at coordinates X, Y." Instead, leveraging its LLM capabilities, it attempts to infer why each action was taken. The resulting SKILL.md draft encodes: when to use this skill, what input variables are required, the procedural steps, and how to verify success. This semantic representation of the workflow — rather than a positional snapshot — is the mechanism that gives LLM-based PbD an advantage over classical RPA.

1.3 Replay: Invoke the Skill Anytime

The generated SKILL.md is a plain-text file the user can freely edit. Preferred naming conventions, default values to always select, exception-handling notes — all can be added in natural language. Once the Skill is ready, invoking it in any new Codex task thread causes Codex to follow the SKILL.md instructions with only the variable inputs swapped. Ask "file this week's expense report" and Codex executes the entire captured workflow substituting current values.

2. The PbD Revival: What LLMs Change About an Old Idea

2.1 The Classic Brittleness Problem

Classical PbD systems and RPA tools recorded the surface of actions: specific pixel coordinates, CSS selectors, element IDs. When a web page redesigned its layout or a button moved, the recorded script broke. The deeper issue was architectural: these systems captured what was done but not why it was done. Without understanding intent, they could not adapt to surface-level changes.

2.2 LLMs as Intent-Inferring Observers

Codex Record & Replay positions an LLM as the observer. Because the model can interpret text and visual context, it can reason about the purpose of each observed action. "The user clicked the dropdown and selected 'Unlisted' rather than 'Private' — this was a deliberate visibility preference, not an arbitrary choice." That inferred intent gets encoded into the SKILL.md. When replaying, Codex navigates toward the same semantic goal even if the UI has changed, rather than blindly repeating a position-based script.

2.3 The Value of an Editable Intermediate Representation

The fact that the output is a plain-text SKILL.md matters independently. Traditional RPA produces visual flow diagrams in proprietary formats that are hard to modify without specialized tools. A SKILL.md file can be committed to git, reviewed in a pull request, and edited by anyone who can write markdown. Automation logic becomes an inspectable, versioned knowledge asset rather than a black box. This adds auditability and explainability to AI-driven automation — properties that matter in enterprise contexts.

3. Comparison with Traditional RPA

3.1 Where RPA Still Wins

RPA retains genuine advantages in high-volume, rule-bound workflows with stable interfaces. A process that runs thousands of identical transactions daily against a fixed ERP screen is actually well-served by RPA's deterministic execution. Mature RPA platforms also come with robust audit logging, exception management, and SLA tooling that AI agent frameworks are still catching up to.

3.2 Where Record & Replay Gains Ground

Codex Record & Replay is better suited when interfaces change frequently, when tasks require linguistic judgment ("select 'Unlisted' unless the content is internal"), or when the workflow is easier to show than describe. Industry estimates for 2026 place AI agent-based automation ROI at approximately 8:1 versus RPA's 2:1 for appropriate workloads — though both figures are highly dependent on workflow selection, not universal claims.

3.3 Real Limitations to State Plainly

Record & Replay is macOS-only as of June 2026, excluded from the EEA, UK, and Switzerland, and requires Computer Use to be enabled. If an organization has disabled Computer Use via requirements.toml, the feature is unavailable. LLM intent inference is not infallible — ambiguous or noisy demonstrations produce poor SKILL.md drafts. Deploying an auto-generated Skill without human review is a significant risk.

4. SKILL.md Open Standard: Codex vs Claude Code

One of the more interesting structural facts about this space: both OpenAI Codex and Anthropic Claude Code have converged on the same SKILL.md file format as their agent skill standard.

4.1 What They Share

Both tools use YAML frontmatter (name, description) plus markdown instructions as the core file format. Skills written for one tool are largely interoperable with the other without modification. Gemini CLI and other emerging agent tools are also adopting the standard, giving Skills genuine portability across vendors.

4.3 Why Claude Code Lacks Record & Replay

Claude Code has no equivalent to Record & Replay as of June 2026. Skill creation requires direct authoring — manually writing the SKILL.md or generating it with AI assistance. This reflects a strategic divergence: Codex is deeply integrated with macOS Computer Use and positions itself for desktop workflow automation, while Claude Code centers on terminal-based development tasks. Neither approach is categorically superior; the right choice depends on the nature of the workflows being automated.

5. Team Knowledge Transfer: When a Skill Becomes Organizational Memory

5.1 Converting Tacit Knowledge to Explicit Form

Every organization has workflows that live only in the heads of specific people. "This report must be opened in this tab order." "This field accepts text, not numbers, even though it looks numeric." Such tacit knowledge is notoriously hard to document and tends to disappear when individuals leave. A SKILL.md generated via Record & Replay is one mechanism for externalizing that knowledge into a structured, shareable artifact.

5.2 Risks of Skill Propagation at Scale

Team-wide deployment of Skills is a double-edged capability. A well-crafted Skill shared with a department scales a single person's workflow efficiency across dozens of colleagues. A flawed Skill scales the errors proportionally. Organizational Skill governance — review processes, approval gates, rollback procedures — is not provided by Codex out of the box. Teams deploying Skills broadly should build those processes themselves.

6. Developer Productivity Impact — Concrete Assessment

6.1 Lowering the Automation Entry Barrier

The most direct productivity effect is democratization. Previously, automating a repetitive workflow required scripting ability or RPA platform training. Record & Replay reduces the requirement to: be able to perform the workflow yourself. Non-developers can participate in agent automation directly. This has genuine organizational productivity implications beyond individual developer efficiency.

6.2 Bypassing the Prompt Articulation Problem

Getting LLM agents to execute complex multi-step workflows via text prompts is harder than it sounds. Describing "click the third item in the left panel, and when a popup appears, select the left option labeled 'Unlisted' rather than 'Private'" in a prompt that reliably produces correct behavior requires careful prompt engineering. Demonstrating the workflow directly encodes those preferences without needing to articulate them in language. This is where PbD's original intuition remains valid: some knowledge transfers more accurately by showing than by telling.

6.3 The Warning About Convenient Blind Spots

Convenience creates a specific failure mode: the more seamless the automation, the easier it is to stop reviewing its outputs. An expense filing Skill that submits the wrong amount, an issue creation Skill that assigns the wrong project code, or a video publishing Skill that defaults to Public when Private was intended — these errors are real possibilities. The scope of automation errors scales with the reach of the automation. Skills must be reviewed before deployment and monitored after.

7. Workload Triage: When to Use and When to Avoid

7.1 Good Fits

Workflows that are repetitive with predictable structure, have clear success criteria, and vary only in a small number of inputs (date, amount, filename) are ideal. Concrete examples: periodic expense filing, templated issue or ticket creation, recurring report downloads and organization, video publishing with consistent metadata patterns, internal system data entry with defined formats.

7.2 Poor Fits

Complex decision-making where the right choice varies widely by context, highly non-linear processes where the next step depends heavily on intermediate results, high-stakes customer-facing operations, and any workflow where real credentials must be entered during demonstration — all of these are unsuitable or require significant risk mitigation before deployment.

8. Conclusion: PbD at Scale via LLM Agents

OpenAI Codex Record & Replay is a practical realization of a 40-year-old computer science idea, made viable for production use by combining LLM intent inference with Computer Use observation. The classical brittleness problem — hard-coded coordinates that break on interface change — is partially addressed by encoding semantic intent rather than positional actions. The output is a human-readable, version-controllable SKILL.md that can be reviewed, edited, and shared.

The two most significant implications in my assessment: first, democratization of automation creation — the barrier drops from scripting ability to workflow familiarity. Second, tacit knowledge externalization — organizational know-how stored in individuals' heads gets a conversion path to documented, shareable Skills. Both are genuine value propositions that go beyond "run a macro faster."

Compared to Claude Code, the shared SKILL.md standard ensures portability while platform-specific features diverge meaningfully. Codex's unique contribution is the demonstration-based creation path; Claude Code's strengths lie in richer slash-command ergonomics and agent composition metadata. As of June 2026, the open standard means teams do not have to choose one exclusively — Skills built for one largely work on the other.

The caveats remain real: macOS-only, EEA excluded, Computer Use dependency, LLM inference errors, and the organizational risk of deploying unreviewed auto-generated Skills. Automation's convenience and automation's failure blast radius scale together. That is not a reason to avoid it — it is a reason to govern it carefully.
