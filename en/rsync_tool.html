🚀 Why Should You Use Rsync?

The key lies in its delta-transfer algorithm, which transfers only the changed portions of files.

Regular Copy (cp / scp)

Even if only 1 KB changes in a 10 MB file,
the entire 10 MB is transferred.

0%

Intelligent Sync (rsync)

Only the changed 1 KB chunk of data
is intelligently identified and transferred.

0%

🖥️ Generated Command

rsync -a [SOURCE] [DESTINATION]

💡 Why the trailing slash matters: source/ copies only the contents, while source copies the directory itself.

🎯 Real-World Scenarios

📁 Scenario 1: Local Directory Backup

Back up all the data in your home directory (~/documents) to an external drive (/mnt/backup). All file attributes are preserved and progress is shown.

rsync -av --progress ~/documents/ /mnt/backup/documents_backup/

🌐 Scenario 2: Back Up to a Remote Server (over SSH)

Transfer a local project folder to a remote server (192.168.0.100) with compression. The example assumes the SSH port is 2222.

rsync -avz -e 'ssh -p 2222' /var/www/my_project/ user@192.168.0.100:/home/user/backups/

🔄 Scenario 3: Mirror a Production Server (with --delete)

Create a perfect replica of the production server's web content on a backup server. Files deleted on the production server are also deleted on the backup. Use --delete with extreme caution.

# 1. First, run --dry-run (-n) to check which files would be deleted! rsync -avzn --delete user@source_server:/var/www/html/ user@backup_server:/var/www/html/ # 2. Once you've verified it's safe, remove -n to execute for real. rsync -avz --delete user@source_server:/var/www/html/ user@backup_server:/var/www/html/

🚫 Scenario 4: Back Up While Excluding Specific Files/Directories

When backing up a project folder, exclude the large node_modules directory and unnecessary log files (*.log).

rsync -av --exclude 'node_modules/' --exclude '*.log' /path/to/project/ /path/to/backup/

💡 If you have many items to exclude, it's cleaner to create an exclude-list.txt file and use --exclude-from='exclude-list.txt'.

⏰ Scenario 5: Automatic Daily Backup with Cron

Configure cron to automatically back up critical data to a remote server every day at 2:00 AM. Output is written to a log file for auditing.

# crontab -e 0 2 * * * rsync -a --delete ~/critical_data/ user@remote_server:/backup/ >> /var/log/rsync_backup.log 2>&1
