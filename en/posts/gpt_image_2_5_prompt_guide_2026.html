1. Paradigm Shift from Generative Creation to Preservation-Centric Editing

The early development of AI visual models centered almost exclusively on single-shot text-to-image synthesis from natural language prompts. Practitioners combined descriptive phrases and stylistic tags to sample outputs from latent spaces. However, when applied to production pipelines such as commercial product design, UI layout prototyping, or catalog production, this approach faces structural limitations. Production workflows require maintaining the composition and subject identity of approved baseline images while making precise localized adjustments to specific clothing or background components.

The issue where edit instructions alter unintended areas becomes a reliability challenge in production pipelines. OpenAI's GPT Image 2.5 prompt guide provides practical guidance for addressing this challenge. The documentation instructs developers to write "change only X" alongside a list of details to preserve when giving edit instructions.

The original documentation instructs separating a single target change from elements to preserve (identity, geometry, layout, lighting, labels). It also notes that repeated edits can change details intended to be preserved (Section 7). Note that the original documentation announces that gpt-image-1.5 is scheduled for shutdown on December 1, 2026, and gpt-image-1 on October 23, 2026.

2. Architectural Characteristics and Selection Criteria for Flare and Sunburst

OpenAI's official API specifications delineate two distinct model offerings within the GPT Image 2.5 family: gpt-image-2.5-flare and gpt-image-2.5-sunburst. Both share identical prompt syntax and parameter specifications, but differ in optimization directions.

  • GPT Image 2.5 Flare: The original text describes it as a "small model, optimized for speed, with image quality comparable to GPT Image 2," and advises choosing it for fast, high-quality everyday image generation.
  • GPT Image 2.5 Sunburst: The original text describes it as the "base model, optimized for quality, with higher image quality than GPT Image 2," and advises choosing it for workflows where editing precision matters most.

The official documentation outlines specific migration and selection rules. If GPT Image 2 already meets quality requirements, start with GPT Image 2.5 Flare and test for latency improvement. If GPT Image 2 falls short on complex use cases, start with GPT Image 2.5 Sunburst. For the first comparison, keep the prompt, references, dimensions, output format, and explicitly selected quality setting unchanged.

The original text states that both models support image generation, editing, and transparent backgrounds.

4. The Four Core Sizing Constraints and Arithmetic Boundaries

In addition to predefined presets, the GPT Image 2.5 API supports arbitrary rectangular outputs. The original text accepts custom sizes as WIDTHxHEIGHT strings and imposes the following conditions:

  • Maximum Edge Bound: Neither edge may exceed 3,840 pixels.
  • Modulo-16 Divisibility: Width and height must both be multiples of 16.
  • Aspect Ratio: Must be between 1:3 and 3:1.
  • Total Pixel Count: Between 655,360 and 8,294,400.

The official documentation classifies resolutions above 2560x1440 (3,686,400 pixels) as experimental. The table below illustrates valid and invalid configurations derived mathematically from these authoritative specifications.

5. Separating Changes from Constraints — Labeled Section Prompt Engineering

To organize complex visual requirements, OpenAI's official documentation instructs structuring prompts using labeled sections rather than monolithic descriptive prose. The recommended foundational architecture decomposes prompts into four distinct structural layers: Scene, Subject, Details, and Constraints.

  • Explicitly Naming Subject and Intent: Name the subject and intended use, such as a product photograph, advertisement, or diagram.
  • Itemizing Concrete Observable Details: Discard subjective mood words in favor of tangible physical properties. Specify materials, lighting, colors, and the visual medium.
  • Quoting Exact Typographic Content: Put required wording in quotes and describe its position and typography. Ask for no extra text, then check spelling and legibility in the output.
  • Isolating Negative Exclusions and Boundaries: Segregate exclusions, such as unwanted text, logos, or watermarks, into a dedicated constraints section to maintain clarity.

The code block below demonstrates an illustrative labeled prompt constructed in accordance with OpenAI's structural recommendations. This example was created specifically for this technical guide to showcase production sectioning principles rather than replicating an existing OpenAI sample.

[Scene]: A bright, modern Nordic kitchen counter with soft morning daylight entering from the left window.
[Subject]: A compact matte-black espresso coffee machine placed on a light oak wood surface.
[Details]: Brushed metal drip tray, visible steam wand texture, warm ambient reflections, shallow depth of field focusing on the portafilter.
[Text Requirement]: The word "AURA" engraved on the front panel in clean minimalist sans-serif capitals, rendered exactly once.
[Constraints]: No human hands or figures, no commercial brand watermarks, no decorative clutter, clean photorealistic finish.

The original text instructs organizing complex requests into labeled sections divided into scene, subject, details, and constraints. The section labels and specific wording in the example block represent this article's formulation.

6. Production Editing Workflows — Defining and Enforcing Preserve Lists

The operational core of the GPT Image 2.5 editing specification (utilized via the client.images.edit API endpoint) centers on a foundational syntactic mandate highlighted in the official documentation:

Say "change only X" and list the details to preserve, such as identity, geometry, layout, lighting, or labels.

This operational directive establishes that every production editing prompt should state what to change and immediately list elements to preserve. The official guide identifies five primary pillars that must be declared whenever existing visual continuity is required:

  • Identity: When working with human subjects, declare facial features, eye contour, skin texture, and expression as constants to preserve.
  • Geometry: Maintain the physical proportions, volumetric contours, and perspective vanishing lines of existing structural assets.
  • Layout: Preserve canvas framing, subject positioning, camera focal length, and spatial relationships between elements.
  • Lighting: Match the directional vector, color temperature, and shadow falloff of the existing scene.
  • Labels and Visual Signifiers: Protect existing text elements, measurement annotations, UI buttons, and infographic arrows from alteration.

In localized modification workflows, engineers should further declare saturation, contrast, arrows, camera angle, and surrounding objects as fixed elements. When using multiple input references, identify each input by number and purpose, such as subject, style, clothing, or background.

The following prompt represents an illustrative production editing instruction engineered to execute a clean garment replacement while enforcing an exhaustive preserve list. This template was formulated based on OpenAI's operational rules to demonstrate real-world implementation.

[Task]: Edit the input image to change only the clothing of the subject.
[Change Target]: Replace the current gray knit sweater with the dark-navy waterproof trench coat provided in reference image 2.
[Preserve List - Critical]:
- Identity: Keep the subject's face, facial features, eyes, smile, skin texture, and hairstyle completely unchanged.
- Geometry: Retain the existing upper body posture, shoulder angle, and arm placement.
- Lighting: Match the soft golden-hour directional sunlight and shadows of the original photo.
- Layout: Do not alter the urban street background, depth of field, or camera framing.
[Constraints]: Coat must drape naturally according to the body geometry, realistic fabric creases, no added accessories, no brand logos.

The original text instructs writing "change only X" alongside a preserve list in edits, and assigning each input image a number and role (subject, style, clothing, background) when using multiple references. The above prompt is an illustrative example following this guidance.

7. The Cost of Constraints and Repetitive Overhead — Residual Drift and Mitigations

While formulating explicit preserve lists is essential for professional editing, engineers must recognize the operational costs and architectural constraints inherent to this methodology.

First, the cost of increasing constraints. This article conjectures that adding numerous preservation items lengthens the prompt, potentially burying key mutation directives. The original documentation does not address this phenomenon.

Second, drift in repeated edits. The original text states that "Repeated edits can still change details you intended to preserve." The official documentation explicitly acknowledges this behavioral reality and outlines the necessary mitigation strategy:

Restate critical constraints if the result drifts. If a region must remain pixel-identical, composite the approved edit into the original image instead of relying on prompting alone.

This guidance establishes an essential boundary: if a region must remain completely identical without variation, teams should not rely purely on prompting, but should composite the approved edited region back into the original image.

8. Verification Procedures — Comparative Evaluation of Preserve Prompts on Identical Inputs

When teams wish to understand the impact of preserve-list prompting in practice, it can be inspected via A/B comparison. The comparative evaluation framework outlined below presents a structured verification approach:

  1. Anchor Baseline Test Assets: Prepare a curated benchmark suite consisting of representative production assets, including portraiture, dense technical infographics, transparent product shots, and banner graphics.
  2. Execute Control Group A (Naive Mutation Prompts): Under identical model and parameters (size, quality), invoke the edit API using naive change directives (e.g., "Change the jacket to a beige leather jacket").
  3. Execute Test Group B (Preserve-First Structured Prompts): In the identical environment, invoke the edit API with labeled sections separating changes from preserve lists (e.g., "Change only the jacket. Preserve face, hairstyle, lighting, and background").
  4. Evaluate Against Four Structural Integrity Metrics:
    • Identity Preservation Index: Measure facial similarity and feature alignment between original and edited outputs.
    • Environmental Consistency: Confirm whether background textures, lighting vectors, and depth-of-field blur remain coherent.
    • Boundary Artifact Density: Audit perimeter seams between modified objects and preserved anatomy for pixel bleeding or haloing.
    • Unintended Mutation Count: Quantify instances of unprompted typographic insertion, accessory hallucination, or color shifting.

The procedure in this section is a proposal of this article rather than from the original text, and this article did not perform this empirical comparison directly. Outcomes must be verified against individual images and configurations.
