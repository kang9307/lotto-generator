JWT는 무엇이고 어디에 사용하나요?

JWT(JSON Web Token)는 두 시스템 사이에서 정보를 안전하게 전달하기 위한 컴팩트한 토큰 포맷입니다. header.payload.signature 세 부분으로 구성되며 각 부분은 Base64URL로 인코딩됩니다. OAuth 액세스 토큰, 세션 대체, API 인증, SSO 등 광범위하게 사용됩니다.

HS256과 HS512는 어떻게 다른가요?

두 알고리즘 모두 HMAC 기반 대칭키 서명이지만 사용하는 해시 함수가 다릅니다. HS256은 SHA-256(256비트), HS512는 SHA-512(512비트)를 사용합니다. HS512가 더 안전하지만 토큰 길이가 길고 약간 더 느립니다. 비밀키는 해시 출력 길이 이상 권장됩니다.

알고리즘 "none"은 왜 비권장인가요?

alg: none은 서명을 검증하지 않는 옵션입니다. 과거 많은 라이브러리에서 이를 악용한 JWT 위변조 취약점이 발견되었으며, 운영 환경에서는 반드시 비활성화해야 합니다. 본 도구는 테스트 목적으로만 지원합니다.

토큰 데이터가 서버로 전송되나요?

아니요. 모든 디코드·생성·검증은 브라우저의 Web Crypto API(window.crypto.subtle)로 수행됩니다. 토큰, 비밀키, payload는 외부 서버로 절대 전송되지 않습니다. 네트워크 탭에서 확인할 수 있습니다.

exp(만료시간) 표시는 어떻게 계산되나요?

JWT의 exp, iat, nbf 클레임은 Unix Epoch 초 단위입니다. 본 도구는 이를 ISO-8601 날짜와 함께 "2시간 후" 또는 "3일 전 만료" 같은 상대 시간으로 변환해서 보여줍니다.

jwt.io와 어떻게 다른가요?

jwt.io와 동일한 핵심 기능(디코드·생성·검증)을 제공하면서도 4개 언어(한국어·영어·일본어·중국어) UI, 만료시간 상대 시간 표시, 인앱 5채널 공유, 모바일 최적화 다크 테마 등을 추가했습니다. 라이브러리 의존성 없이 Web Crypto API만 사용합니다.

RS256(RSA) 같은 비대칭 알고리즘도 지원하나요?

현재 버전은 HMAC 계열(HS256/HS512)만 지원합니다. RS256/ES256 등 비대칭 알고리즘은 디코드는 가능하지만 서명 생성·검증에는 공개키/개인키 페어가 필요해 별도 UI가 요구되며, 향후 버전에서 추가 예정입니다.
