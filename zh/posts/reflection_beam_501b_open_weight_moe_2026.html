发布概览——501B开放权重模型Beam与权重公开计划的范围

2026年10月5日，Reflection发布了公司首个开放权重模型Beam。权重计划在本月内公开，发布时还不能下载。Beam是面向编码、推理和智能体工作负载打造的稀疏混合专家（Sparse Mixture-of-Experts，下称MoE）模型。总参数为5010亿个（501B），每个token的激活参数为230亿个（23B）。

原文说明，Beam的能力来自对预训练和强化学习（RL）两方面的大量投入。模型在从网络和专有授权数据集中挑选的23.8万亿token上进行了预训练，高算力RL则在10.5K块NVIDIA GB300 GPU上运行了四周，生成了超过1亿次rollout。

  • 公开时间表：原文写明，权重、技术报告、模型卡和开发者产物将在本月内（later this month）公开。
  • 许可证：本月内将以Apache 2.0许可证公开权重，并同时公开运行、评估和微调模型所需的文档与完整技术栈。发布时还将推出分发合作伙伴生态以及与众多开源库的集成。
  • 当前访问方式：模型正在进行最终红队测试和评估，原文给出了早期访问的申请链接，向选定的用户群提供早期版本，并接受候补名单。

因此，现在的Beam还不是已经发布的开源软件，而是规格和基准已经公布、权重公开已被预告的模型。

架构规格——总参数501B、激活23B的稀疏MoE

Beam是总参数501B中每个token激活23B的稀疏MoE模型。激活占比为23÷501，约4.6%（计算）。原文说明，架构和优化方案强调为持续的后续RL打下数值上健康的基础，并这样描述预训练的验证：逐步训练了一系列更大的模型来建立并验证扩展方案，最终的Beam Base与预测性能一致，并且与可获取的同等规模开源基础模型持平或更好。

  • 组成要素：原文概括为局部注意力与全局注意力交替排列、细粒度的路由专家（fine-grained routed experts）、受控的残差流，以及多种形式的负载均衡相结合。
  • 专家负载均衡：在无辅助损失负载均衡（auxiliary-loss-free load balancing，DeepSeek-AI et al., 2024）的基础上，为减少训练后期的路由扰动，在专家偏置（expert-bias）更新中引入了余弦衰减。
  • 序列级均衡：加入序列级均衡，以便在预训练分布之外的数据上也能均衡地使用专家，为下游RL的分布变化做准备。
  • 均衡的结果：预训练结束时的基础模型呈现几乎完美的均匀使用，最繁忙专家的负载在各MoE层上的平均值为1.04倍（Figure 7）。
  • 残差流：用基于深度的缩放方式抵消子层输出累积时的激活增长，并与SandwichNorm、逐元素注意力门控、FP32残差累加（减少加上小幅更新时的舍入误差）结合使用。
  • 稳定性的范围：在全部52层中，残差流RMS在整个预训练期间保持有界（Figure 8），原文写道这种稳定性贯穿预训练、强化学习和对齐过程。

原文没有把模型按激活参数计算的轻量程度换算成托管需求。服务完整权重所需的内存或GPU配置在原文中没有，本文也不编造这些数字。

预训练与基础设施——23.8万亿token与6,144块GB300

原文写道，Beam在来自网络、公开来源和专有授权数据集的23.8万亿个多样化高质量token上进行预训练。数据管线的设计目标是为下游智能体式编码打下基础，在每一个策展阶段都保留源代码、技术说明以及数学和科学知识。团队表示，网络上几乎所有可公开获取且许可不受限制的代码与代码文档都用于了训练。

  • 过滤：经过解析、去重和策展，约95%的原始互联网token被剔除。另一方面，团队保留了传统技术会漏掉的约1.8万亿个高质量token，其中包括经过策展的网络代码token的87%。1.8万亿不是最终筛选的总量，而是传统过滤器会漏掉的量。
  • 质量分类：团队自行训练了面向网络、代码和STEM内容的质量分类器，把数据分成细粒度的质量层级，并向更优质的材料倾斜训练权重。
  • PDF处理：把视觉语言OCR模型与自有质量分类器、能捕捉错误重建结果的缺陷检测器结合成高吞吐管线，分布在数千块GPU上处理PB级的技术数据。
  • 算力基础设施：在由6,144块NVIDIA GB300 NVL72 GPU组成的集群上，用不到四周完成预训练。团队自行构建了感知拓扑的、基于Kubernetes的调度器、节点生命周期系统，以及能够半自主回滚与重启的静默数据损坏（silent data corruption，SDC）检测系统。
  • 训练稳定性：执行了九次半自动回滚，原因归于非确定性的梯度范数尖峰或疑似SDC，损失曲线没有观察到不稳定或无法恢复的大尖峰（Figure 9）。
  • Goodput：后期达到92.3%。按原文定义，它是花在最终模型中保留下来的训练步骤上的实际耗时（wall-clock）所占的比例。

预训练之后的中期训练（midtraining）是为高算力RL打基础而设计的。团队用多阶段数据策展管线构造训练数据，反映真实任务的结构与复杂性，并把有效上下文长度扩展到100万token。

高算力强化学习——10.5K块GPU与超过1亿次rollout

原文把高算力RL描述为Beam扩展的核心轴线。团队部署了10.5K块NVIDIA GB300 GPU，运行四周，以最大256K token的上下文长度生成了超过1亿次rollout，训练与评分使用了约13亿个沙箱。在整个评估套件上，随着RL算力的增加，能力持续提升，没有出现停滞的迹象。

  • 环境：以合成数据管线为主，辅以专有供应商数据和开源来源，构建了近100万个环境。领域包括软件工程、终端使用、竞赛编程、STEM、网络搜索、工具使用和一般知识工作。
  • 环境策展：先合成或收集任务，按难度（既不总是可解也不是不可能）和质量（排除表述不清、可猜测、可被利用漏洞的任务）进行过滤，再通过RL测试，并用结果指导下一轮收集与过滤。
  • 沙箱：最多同时支持17万个，处理了超过10亿次沙箱创建请求，跨越20多个集群、两个云和四个区域。新沙箱中有90%在10秒内就绪。
  • 异步执行：训练期间平均有11万个rollout并发运行。每个token都标记了生成它的模型版本，使训练算法能够考虑策略陈旧（staleness）问题，即使样本比当前策略落后107个权重版本、约一天，数值仍然稳定（Figure 4）。
  • 算力分配与权重更新：推理与训练的GPU比例在3.9:1到5.4:1之间调整。新权重以约12秒的中位时间到达推理集群，通过机架间RoCE与机架内NVLink的分层传输，机架间流量减少75%，采用速度提高到2.2倍。
  • 故障恢复与打包：训练期间处理了71起推理故障而未中断训练任务，容量恢复的中位时间为8分钟，损失的容量占已用服务GPU分钟数的0.02%。动态打包使训练批次平均装满99.99%。

在奖励设计上，团队使用了可调节的长度惩罚，奖励成功的解答，抑制不必要的token。RL早期，回答长度缩短而性能提升；后来随着智能体能力增强，回答长度再次增长，而这些额外的token支撑了进一步的性能提升。用户可以通过推理力度（reasoning effort）参数调节这一权衡。Figure 3展示了超过1亿次rollout中用于推理专家训练的8,000万次，作为对比，原文写道Inkling用3,000万次rollout训练，MiMo为75.3万次。

基准表与相对比较模型的位置

原文评价说，Beam推进了西方开放权重的前沿，在编码和智能体任务上可与更大的开源模型GLM 5.2竞争，并接近Qwen 3.8 Max。同时原文写道，Kimi K3这样的前沿开源模型在原始能力上仍然领先，Beam的优势是推理时的效率。

  • 编码：SWE Bench Pro v1为65.5，高于GLM 5.2（62.1），低于Qwen 3.8 Max（67.7）。Terminal Bench v2.1为80.1，接近GLM 5.2（81.0）。
  • 推理与STEM：AIME 2026为97.8，低于GLM 5.2（99.2），GPQA Diamond为90.5，无工具HLE为36.2。
  • 工具调用与搜索：MCP Atlas为78.7，AutomationBench public为37.0，超过GLM 5.2的77.8和26.2。
  • 与领先模型的差距：在表中，Kimi K3的SWE Bench Pro v2-Hard为88.2、HLE为46.9，DeepSeek V4.1 Flash的DeepSWE为74.2、Terminal Bench v2.1为90.6，都高于Beam。

「推理算力三分之一至四分之一」说法的计算公式与被排除的成本

原文写道，在高级推理基准上，Beam取得了与GLM-5.2相当的分数，而推理算力少3到4倍。原文还补充说，与Qwen 3.8-Max这样的2T+参数级模型相比，由于每个token需要多得多的算力，效率优势更为突出。这一说法的计算分母在Figure 2的图注中。下面是图注全文，除了为便于阅读按句换行外，与原文一致。

Figure 2: Beam demonstrates frontier-level inference efficiency, both when measured in terms of FLOPS and token count across DeepSWE, Humanity’s Last Exam (HLE), and Terminal Bench 2.1.
                    We used data from Artificial Analysis and DataCurve, estimating generation forward-pass compute as FLOPs ≈ 2 × active parameter count × mean generated tokens per attempt, counting each multiply-add as two operations.
                    Generated tokens include both reasoning and the final answer.
                    For mixture-of-experts models, we used the parameters activated per token rather than the total model size.
                    These estimates exclude prompt prefill, context-dependent attention operations, and serving overhead, so they represent an approximate compute comparison rather than measured inference cost.
                    We use Artificial Analysis and DataCurve as sources for other model’s evals.

读过图注就能看出这个比较的前提。

  • 估算公式：生成算力是激活参数数乘以每次attempt的平均生成token数再乘以2，并将一次乘加算作两次运算。
  • 生成token的范围：生成token包括推理过程和最终答案两部分。
  • MoE的参数口径：对MoE模型使用的是每个token激活的参数，而不是整个模型的大小。
  • 被排除的成本：提示词预填充、与上下文相关的注意力运算和服务开销都被排除在外，所以这是大致的算力比较，而不是实测的推理成本。

因此「三分之一至四分之一」不是测量GPU集群电力或托管成本的结果，而是用激活参数和每次attempt的平均生成token数估算出的算力之比。按这个公式，每次attempt生成token越多的模型，估算算力越大。

智能体能力迁移案例与权重公开前应确认的事项

原文说明，RL被设计成培养能够泛化到训练任务之外的能力。在训练推理、软件工程和终端任务的阶段，尽管RL混合数据中没有浏览任务，浏览性能仍然持续提升；获得网络访问权限后，模型自发学会了搜索并询问其他大语言模型，以及使用OCR API读取文档。

  • 演示案例：介绍了p5.js的3D宇航员游戏、用纽约MTA公开数据制作的实时地铁地图，以及为小型模型Gemma-4编写Text2SQL微调笔记本。据称用该笔记本微调Gemma后，其在保留测试集上的准确率提高了66.5%。
  • 陆地与水域实验：在180×90网格、16,200个点的题目上，Beam答对了95.5%，介于Opus 5（92.5%）与Fable 5（97.8%）之间，原文如此写道。这个数值是原文自己的演示结果。
  • 安全与对齐：从预训练检查点出发，用独立的SFT和RL管线再训练一个安全与对齐模型，并通过多教师在线策略蒸馏（MOPD）合并两位教师的能力。原文表示安全评估结果将收录在技术报告中。
  • 权重公开后的确认：权重公开后，Apache 2.0条款如何适用于实际分发的产物，最好以随之公布的许可证文本为准确认。

总之，原文能让我们确认的是规格、训练规模、已发布的基准数值和算力估算方式。在能够下载并部署权重之前，这些数字应当当作Reflection自己的报告来读。

  • vLLM、SGLang等开源推理引擎是否支持以及何时支持。原文预告了与众多开源库的集成，但没有给出具体清单。
