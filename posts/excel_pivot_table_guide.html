엑셀 피벗테이블 실무 가이드 - 만드는 법 말고, 막히는 지점을 푸는 법

새로고침이 안 먹고, 합계가 개수로 잡히고, 계산 필드 총합계가 틀리는 이유를 원리부터 짚는다

2026-07-28 IT/기술

서론: 피벗테이블은 만들 때가 아니라 두 번째 날 막힌다

삽입 > 피벗 테이블을 누르는 방법을 설명하는 글은 이미 충분히 많다. 그런데 실무에서 사람들이 검색창을 여는 순간은 피벗테이블을 처음 만들 때가 아니다. 어제 만든 피벗테이블에 오늘 데이터를 붙였는데 숫자가 그대로일 때, 금액 열을 값 영역에 넣었는데 합계가 아니라 개수가 나올 때, 이익률을 계산 필드로 만들었는데 총합계만 말이 안 되는 숫자일 때다.

이런 증상은 대부분 사용자의 실수가 아니라 피벗테이블의 설계상 동작에서 나온다. 피벗테이블은 워크시트 셀을 실시간으로 읽는 수식이 아니다. 원본을 한 번 읽어 피벗 캐시라는 별도의 스냅샷에 담아 두고, 화면에는 그 캐시를 요약해 보여 준다. 이 한 문장을 이해하면 「새로고침해도 안 바뀜」, 「원본을 지웠는데 피벗은 살아 있음」, 「파일 용량이 두 배로 늘어남」이 전부 같은 원인에서 나온 형제 증상이라는 것이 보인다.

이 글은 2026년 7월 기준 Microsoft 공식 지원 문서를 근거로, 피벗테이블에서 실제로 막히는 지점을 증상 → 원인 → 해결 → 왜 그렇게 동작하는가 순서로 정리한다. 마지막에는 버전과 플랫폼별로 되는 것과 안 되는 것을 표로 붙였다. 같은 메뉴 이름이 Excel 2016과 Microsoft 365에서 다른 위치에 있는 경우가 많고, Mac과 웹에서는 아예 없는 기능도 있기 때문이다. 확인하지 못한 항목은 감으로 채우지 않고 「확인되지 않음」으로 남겨 두었다.

이 글의 메뉴 경로는 Windows용 Microsoft 365 기준으로 적었다. Excel 2016 이하에서는 피벗 테이블 분석 탭이 분석 탭으로 표시되는 등 리본 이름이 다르고, Mac과 웹은 위치가 또 다르다. 경로가 맞지 않으면 리본 오른쪽 검색 상자에 기능 이름을 그대로 입력하는 편이 빠르다.

1. 피벗에 넣기 전 - 원본 데이터 점검표

피벗테이블 문제의 절반 이상은 피벗테이블이 아니라 원본 표에서 시작된다. Microsoft는 피벗테이블용 원본 데이터의 요건을 명시하고 있다. 핵심은 세 가지다. 모든 열에 머리글이 있을 것, 그 머리글은 한 줄이고 비어 있지 않으며 중복되지 않을 것, 그리고 한 열에는 한 가지 데이터 형식만 들어 있을 것. Microsoft 문서는 머리글에 대해 이중 머리글 행이나 병합된 셀을 피하라고 못 박고 있으며, 예로 「같은 열에 날짜와 텍스트를 섞지 말라」고 적고 있다.

왜 이렇게 까다로운가. 피벗테이블은 첫 행을 필드 이름으로, 그 아래를 레코드로 해석하는 단순한 규칙으로 캐시를 만든다. 머리글이 두 줄이면 두 번째 줄이 데이터로 흡수되고, 병합 셀이 있으면 병합된 영역의 좌측 상단 한 칸만 값을 갖고 나머지는 빈 칸이 된다. 빈 열이 하나 끼어 있으면 Ctrl+A로 잡히는 연속 범위가 거기서 끊긴다. 즉 사람 눈에 표로 보이는 것과 엑셀이 표로 인식하는 것이 다른 데서 오는 문제다.

1.1 피벗에 넣기 전 5분 점검표

점검 항목왜 문제가 되는가조치
머리글이 두 줄이거나 병합됨두 번째 줄이 데이터로 흡수되고, 병합 시 빈 머리글이 생겨 필드 이름이 깨진다머리글을 한 줄로 합치고 병합 해제. 예: 상반기/1월 → 상반기_1월
중간에 빈 행 또는 빈 열자동 범위 감지가 거기서 끊겨 아래쪽 데이터가 통째로 누락된다빈 행·열 삭제. 삭제가 어려우면 표(Ctrl+T)로 범위를 명시
본문에 섞인 소계 행·합계 행소계가 다시 합산되어 총합계가 두 배 가까이 부풀려진다소계 행 제거. 소계는 피벗테이블이 알아서 만든다
숫자처럼 보이는 텍스트값 필드가 합계가 아니라 개수로 잡힌다오류 표시기의 숫자로 변환, 또는 텍스트 나누기로 일괄 변환
텍스트로 저장된 날짜날짜 그룹화가 되지 않고 자동 시간 그룹도 만들어지지 않는다DATEVALUE 또는 텍스트 나누기로 실제 날짜 값으로 변환
한 열에 형식이 섞임기본 요약 함수 선택과 정렬·필터가 모두 어긋난다열을 분리하거나 형식을 통일
앞뒤 공백·줄바꿈·비인쇄 문자같은 이름이 서로 다른 항목으로 분리되어 행이 두 번 나온다TRIM·CLEAN 적용 후 값으로 붙여넣기
가로형(연도가 열로 펼쳐진) 배치피벗은 세로형 레코드를 전제로 하므로 연도별 비교가 불가능해진다파워 쿼리의 열 피벗 해제로 세로형 전환

이 점검표에서 가장 자주 사고를 내는 항목은 소계 행이다. 사람이 보기에는 「합계」라고 적혀 있으니 구분되지만 피벗테이블에게는 그냥 금액이 큰 레코드 하나일 뿐이다. 원본에 이미 소계가 들어 있는 표를 그대로 피벗에 넣으면 총합계가 정확히 두 배가 되는데, 이 숫자는 언뜻 그럴듯해 보여서 보고서에 그대로 실려 나가기 쉽다.

2. 왜 반드시 표(Ctrl+T)로 만들어야 하는가

피벗테이블을 만들 때 원본으로 지정할 수 있는 것은 두 가지다. 셀 범위(예: Sheet1!$A$1:$F$500)와 표(예: 매출데이터)다. 겉보기에는 같아 보이지만 동작이 완전히 다르다.

셀 범위는 정적 주소다. 501행에 데이터를 추가해도 피벗테이블은 여전히 500행까지만 본다. 새로 고침을 아무리 눌러도 501행은 캐시에 들어오지 않는다. 반면 표는 이름을 가진 동적 객체다. Microsoft는 피벗테이블 만들기 문서에서 표를 원본으로 쓰면 새로 고침할 때 새 행이 자동으로 포함되도록 표가 확장된다고 설명한다. 이것이 「원본에 행을 추가했는데 반영이 안 됨」의 근본 해결책이다.

이미 범위로 만들어 버린 피벗테이블을 표 기반으로 바꾸려면 순서가 중요하다.

  1. 먼저 원본 데이터 안 아무 셀이나 클릭하고 Ctrl+T를 눌러 표로 변환한다. 머리글 포함 여부를 확인한다.
  2. 표 안을 클릭하면 나타나는 표 디자인 탭에서 표 이름을 의미 있게 바꾼다. 예: 표1 → 매출2026.
  3. 피벗테이블을 클릭하고 피벗 테이블 분석 탭 > 데이터 원본 변경을 연다.
  4. 표/범위 칸에 옛 셀 주소 대신 표 이름을 입력한다.
  5. 새로 고침한다.

4번을 빼먹는 사람이 매우 많다. 원본을 표로 만들었다는 사실만으로 기존 피벗테이블이 표를 따라가지는 않는다. 피벗테이블은 생성 시점에 기록된 원본 주소 문자열을 계속 들고 있기 때문이다. 데이터 원본을 표 이름으로 다시 지정해 줘야 그때부터 자동 확장이 적용된다.

왜 표가 자동으로 자라는가. 표는 시트 안에 「여기부터 여기까지가 하나의 데이터셋」이라는 경계를 객체로 등록한다. 표 바로 아래 행에 값을 입력하면 엑셀이 그 행을 표 영역으로 편입시키고, 표를 참조하는 모든 대상(피벗테이블·차트·수식의 구조적 참조)이 새 경계를 함께 따라간다. 범위 참조에는 이런 경계 개념 자체가 없다.

3. 새로고침의 정확한 동작 - 왜 눌러야 하고, 왜 눌러도 안 바뀌나

피벗테이블이 자동으로 갱신되지 않는 이유는 성능 때문이다. 수식은 참조 셀이 바뀌면 즉시 재계산되지만, 피벗테이블은 수십만 행을 다시 집계해야 하므로 매번 자동 실행하면 편집 자체가 느려진다. 그래서 엑셀은 캐시를 명시적으로 다시 채우는 시점을 사용자에게 맡긴다. Microsoft 문서도 기본적으로 피벗테이블은 자동으로 새로 고쳐지지 않는다고 명시한다.

3.1 새로 고침하는 네 가지 방법

  • 단축키: 피벗 안 셀을 선택하고 Alt+F5(Windows). 해당 피벗테이블 하나만 새로 고침된다.
  • 리본: 피벗 테이블 분석 탭 > 데이터 그룹 > 새로 고침.
  • 전부 갱신: 같은 위치에서 새로 고침 아래 화살표 > 모두 새로 고침. 통합 문서의 모든 피벗테이블과 연결이 대상이 된다.
  • 마우스: 피벗 안에서 오른쪽 클릭 > 새로 고침.

3.2 파일을 열 때 자동으로 새로 고치기

매번 누르는 것을 잊는다면 파일 단위로 자동화할 수 있다. 피벗테이블을 선택한 뒤 피벗 테이블 분석 탭 > 옵션 > 데이터 탭에서 파일을 열 때 데이터 새로 고침을 체크한다. 이렇게 하면 통합 문서를 열 때마다 캐시가 다시 채워진다. 다만 원본이 큰 경우 파일 여는 시간이 눈에 띄게 늘어나므로, 원본이 외부 데이터이거나 매일 바뀌는 경우에만 켜는 것이 좋다.

3.3 자동 새로 고침은 아직 모두에게 열려 있지 않다

2025년 이후 Microsoft는 원본이 바뀌면 피벗테이블이 실시간으로 따라오는 피벗테이블 자동 새로 고침 기능을 도입하고 있다. 다만 Microsoft 지원 문서는 이 기능이 Microsoft 365 참가자(Insider) 프로그램 참여자에게 제공된다고 적고 있으며, 설정은 피벗테이블 단위가 아니라 데이터 원본 단위로 적용되어 같은 원본을 쓰는 모든 피벗테이블에 함께 영향을 준다고 안내한다. Microsoft 365 참가자 블로그에는 Windows 버전 2506(빌드 19008.2000) 이상, Mac 버전 16.99(빌드 250616106) 이상이라는 조건이 소개돼 있다. 정리하면 2026년 7월 현재 영구 라이선스 버전(2016~2024)과 일반 채널 사용자 다수는 여전히 수동 새로 고침이 기본이라고 보는 편이 안전하다.

3.4 그래도 안 바뀔 때 확인할 순서

  1. 원본이 표인가 범위인가. 범위라면 데이터 원본 변경에서 실제 주소를 눈으로 확인한다.
  2. 추가한 행이 그 주소 안에 들어 있는가. 500행까지 잡혀 있는데 501행에 입력했다면 원인은 이것이다.
  3. 원본 시트가 다른 통합 문서인가. 외부 원본이면 연결이 끊겼을 수 있다.
  4. 피벗을 복사해서 만든 것인가. 복사본은 원본 피벗과 캐시를 공유하는 경우가 있어 한쪽만 갱신되지 않을 수 있다.
  5. 수식 계산 옵션이 수동으로 바뀌어 있는가. 피벗 자체와는 별개지만 피벗 결과를 참조하는 수식이 멈춰 있을 수 있다.
  6. 필터가 걸려 있어 새 항목이 선택되지 않은 상태인가. 새로 등장한 항목은 기존 필터에서 자동으로 체크되지 않는 경우가 있다.

4. 합계가 아니라 개수로 나오는 이유

이 증상은 원인이 명확하다. Microsoft 문서는 엑셀이 숫자 데이터가 들어 있는 값 필드에는 합계를, 텍스트가 들어 있는 필드에는 개수를 기본 요약 함수로 적용한다고 설명한다. 즉 엑셀이 그 열을 「숫자 열」로 판정하지 못했다는 신호다.

4.1 판정을 뒤집는 흔한 오염원

  • 숫자형 텍스트: 외부 시스템에서 내려받은 CSV, 웹에서 복사한 표, ERP 내보내기에서 흔하다. 셀 왼쪽 위 초록 삼각형이 단서다.
  • 천 단위 구분 기호가 문자로 들어간 값: 1,234가 텍스트로 저장된 경우.
  • 단위가 붙은 값: 1200원, 15%가 문자열인 경우.
  • 오류 값: #N/A, #VALUE!가 한 칸이라도 있으면 숫자 열로 보지 않는다.
  • 겉보기 빈 칸: 공백 문자 하나 또는 =""를 반환하는 수식 결과. 비어 보이지만 텍스트다.
  • 하이픈: 값이 없다는 뜻으로 넣은 -, N/A 같은 표기.

4.2 고치는 순서

  1. 원본 열을 선택하고 홈 탭 > 찾기 및 선택 > 이동 옵션에서 상수를 고른 뒤 숫자 체크를 해제하면 텍스트·오류 값만 선택된다. 어디가 오염됐는지 눈으로 확인할 수 있다.
  2. 숫자형 텍스트는 셀을 선택했을 때 나타나는 오류 표시기에서 숫자로 변환을 고른다. 키보드로는 Alt+Shift+F10으로 메뉴를 연다.
  3. 대량이라면 데이터 탭 > 텍스트 나누기를 열고 아무것도 바꾸지 않은 채 마침을 누른다. 열 전체가 재해석된다.
  4. 수식으로 처리하려면 새 열에 =VALUE(A2)를 쓰고 결과를 값으로 붙여넣는다.
  5. 원본을 고쳤으면 새로 고침한다. 캐시에는 아직 옛 형식이 남아 있다.
  6. 그래도 개수라면 값 영역의 항목을 오른쪽 클릭 > 값 필드 설정에서 요약 함수를 합계로 직접 바꾼다. 한 번 개수로 결정된 필드는 원본을 고쳐도 설정이 유지된다.
왜 새로 고침만으로는 부족한가. 요약 함수는 필드를 값 영역에 처음 놓는 순간 결정되고, 그 뒤에는 피벗테이블의 설정으로 저장된다. 원본을 숫자로 고치고 새로 고침하면 캐시의 데이터 형식은 바뀌지만 이미 저장된 「이 필드는 개수」라는 설정은 그대로다. 그래서 6단계가 필요하다.

5. 날짜가 그룹화되지 않을 때

Excel 2016부터 날짜 필드를 행 영역에 놓으면 연·분기·월이 자동으로 만들어진다. Microsoft는 이를 시간 그룹화라고 부르며, 시간 관련 필드의 관계를 자동으로 감지해 함께 묶는다고 설명한다. 편리하지만 두 방향으로 문제를 만든다. 원할 때 안 되고, 원하지 않을 때 된다.

5.1 그룹화가 안 될 때

오른쪽 클릭 > 그룹을 눌렀는데 「선택한 영역을 그룹화할 수 없습니다」가 나오는 경우다. 원인은 대부분 날짜 열이 순수한 날짜가 아니기 때문이다. Microsoft 문서는 그룹의 모든 항목이 같은 데이터 형식이어야 하며 그렇지 않으면 오류가 난다고 안내한다.

  • 텍스트 날짜: 2026.07.28, 2026-07-28 문자열, 앞에 아포스트로피가 붙은 값. 오른쪽 정렬이 아니라 왼쪽 정렬이면 의심한다.
  • 빈 셀: 날짜 열에 한 칸이라도 비어 있으면 그룹화가 막힌다. 임시로 대표 날짜를 채워 넣고 나중에 필터로 제외하는 방법이 있다.
  • 날짜와 텍스트 혼재: 미정, - 같은 표기가 섞인 경우.
  • 피벗을 만들 때 데이터 모델에 추가한 경우: 데이터 모델 기반 피벗테이블은 OLAP 방식으로 동작해 일반 피벗과 기능 집합이 다르다. 이 제약은 커뮤니티에서 널리 보고되지만 Microsoft 공식 문서에서 명시적 문장을 확인하지 못했다. 확실한 회피책은 같은 원본으로 데이터 모델에 이 데이터 추가를 체크하지 않은 피벗을 하나 더 만드는 것이다.

근본 해결은 원본에서 고치는 것이다. 텍스트 날짜는 텍스트 나누기 마법사 3단계에서 열 데이터 서식을 날짜로 지정하면 한 번에 변환된다. 또는 새 열에 =DATEVALUE(A2)를 쓰고 날짜 서식을 적용한다.

5.2 자동 그룹화가 거슬릴 때

반대로 날짜를 날짜 그대로 보고 싶은데 엑셀이 멋대로 연·분기로 묶어 버리는 경우가 있다. 일별 추이를 볼 때 특히 성가시다. 임시 해제는 만들어진 그룹 필드를 오른쪽 클릭하고 그룹 해제를 누르면 된다. 아예 기능을 끄려면 파일 > 옵션 > 데이터에서 피벗테이블의 날짜·시간 열 자동 그룹화를 해제하는 체크박스를 사용한다.

버전 주의. 자동 시간 그룹화 자체는 Excel 2016에서 도입됐지만, 이를 끄는 엑셀 옵션 체크박스는 그보다 뒤 버전에서 추가됐다고 알려져 있다. Microsoft 공식 문서에서 「Excel 2016에는 이 옵션이 없다」는 문장을 확인하지 못했으므로, 본인 버전의 옵션 > 데이터에 해당 항목이 보이는지 직접 확인하기 바란다. 보이지 않는다면 그룹 해제로 그때그때 처리하는 것이 현실적이다.

7. 계산 필드와 계산 항목 - 그리고 비율·평균을 계산 필드로 만들면 안 되는 경우

여기가 피벗테이블에서 가장 조용하게 틀리는 지점이다. 오류 메시지가 뜨지 않고 그럴듯한 숫자가 나오기 때문에 검토를 통과해 버린다.

7.1 둘의 차이

Microsoft 문서는 두 기능의 차이를 연산 대상으로 구분한다. 계산 필드의 수식은 수식에 등장하는 각 필드의 기초 데이터 합계 위에서 동작하고, 계산 항목의 수식은 개별 레코드 위에서 동작한다. 그리고 다른 필드의 데이터를 써야 하면 계산 필드를, 한 필드 안의 특정 항목들만 써야 하면 계산 항목을 쓰라고 안내한다.

구분계산 필드계산 항목

7.2 곱셈으로 만든 계산 필드가 총합계를 망가뜨리는 이유

Microsoft 지원 문서에는 이 현상을 다룬 별도 문서가 있다. 계산 필드가 곱셈·나눗셈·거듭제곱처럼 고차 산술 연산으로 정의됐을 때 총합계가 잘못 나온다는 내용이다. 문서의 예를 그대로 따라가 보자. 단가와 수량이 다음과 같고, 매출을 단가 * 수량이라는 계산 필드로 만들었다.

행수량단가기대한 매출피벗이 보여 주는 매출
제품 A1101010
제품 B2112222
제품 C3123636
총합계63368198

각 행은 전부 맞는데 총합계만 68이 아니라 198이다. 이유는 단순하다. 피벗테이블이 총합계 칸에서 계산한 식은 10+22+36이 아니라 SUM(수량) * SUM(단가), 즉 6 * 33 = 198이었다. 계산 필드가 합계 위에서 동작한다는 규칙이 그대로 적용된 결과다.

해결은 계산 필드를 포기하는 것이다. 원본 표에 매출 도우미 열을 만들어 행마다 =단가*수량을 계산해 두고, 피벗에서는 그 열을 합계로 요약한다. 이렇게 하면 곱셈이 행 단위로 먼저 끝나고 피벗은 더하기만 하므로 총합계가 68로 맞는다. 도우미 열은 캐시에 한 번 저장되므로 성능에도 유리하다.

7.3 나눗셈은 오히려 맞는다 - 그런데 다른 함정이 있다

같은 규칙 때문에 나눗셈은 반대 결과가 나온다. 이익 / 매출이라는 계산 필드는 총합계에서 SUM(이익) / SUM(매출)이 되는데, 이것은 가중 평균 이익률로서 대개 우리가 원하는 값이다. 그래서 「비율은 계산 필드로 만들면 안 된다」는 말은 절반만 맞다. 정확히 말하면 이렇다.

  • 맞는 방법: 원본에 이익과 매출 두 금액 열을 두고, 피벗에서 계산 필드 =이익/매출을 만든다. 각 행도 총합계도 가중 비율이 된다.
  • 틀리는 방법: 원본에 이미 행마다 계산된 이익률 열이 있고, 그 열을 값 영역에 끌어다 놓는다. 기본 요약 함수가 합계이므로 비율들이 더해진다. 12%와 8%를 더해 20%가 표시되는 상황이 여기서 나온다.
  • 더 교묘하게 틀리는 방법: 위 상황에서 요약 함수를 평균으로 바꾼다. 합계보다는 그럴듯해 보이지만 이것은 가중치 없는 평균이다. 매출 1억 원 지점의 이익률과 매출 100만 원 지점의 이익률이 같은 비중으로 섞인다.

평균도 같은 구조다. 지점별 평균 객단가 열을 만들어 두고 피벗에서 평균을 내면 평균의 평균이 되어 실제 전체 객단가와 다르다. 올바른 방법은 총매출과 거래건수 두 열을 원본에 두고 계산 필드로 =총매출/거래건수를 만드는 것이다.

정리하면 규칙은 하나다. 「합계를 먼저 내고 계산해도 되는가?」를 물어보면 된다. 나눗셈으로 만드는 비율·단가·평균은 대개 합계를 먼저 내는 편이 맞다. 곱셈으로 만드는 금액은 반드시 행에서 먼저 계산해야 한다. 그리고 이미 계산된 비율 열은 값 영역에 넣지 않는다.

7.4 계산 필드로 아예 할 수 없는 것들

Microsoft 문서가 명시한 제약이다. 이걸 모르면 수식을 만들다 왜 안 되는지 한참 헤맨다.

  • 셀 참조나 정의된 이름을 쓸 수 없다. =금액*$B$1 같은 식은 불가능하다.
  • 인수로 셀 참조를 요구하는 워크시트 함수를 쓸 수 없다.
  • 배열 함수를 쓸 수 없다.
  • 총계를 참조할 수 없다. 「3월 합계」나 「총합계」를 수식에 넣을 수 없다.
  • OLAP 데이터 원본에 연결된 피벗테이블에서는 수식 자체를 만들 수 없다.
  • 계산 필드가 있는 필드는 요약 함수를 바꿀 수 없는 경우가 있다.

세율을 곱하고 싶어서 어딘가 셀에 세율을 적어 두고 참조하려던 시도가 막히는 이유가 첫 번째 항목이다. 이 경우 세율을 수식에 상수로 직접 쓰거나, 원본에 세율 열을 만들어 행마다 갖게 하는 편이 낫다.

7.5 계산 필드보다 먼저 검토할 것 - 값 표시 형식

비율을 보고 싶은 목적이라면 계산 필드가 아니라 값 표시 형식으로 해결되는 경우가 많다. 값 영역 항목을 오른쪽 클릭하고 값 표시 형식을 열면 다음 계산이 준비돼 있다.

값 표시 형식은 피벗테이블이 계층 구조를 알고 있는 상태에서 계산하므로, 계산 필드로 흉내 내다 총합계가 틀어지는 사고를 원천적으로 피한다. 같은 필드를 값 영역에 두 번 넣어 하나는 합계, 하나는 총합계 비율로 두면 금액과 구성비를 나란히 볼 수 있다.

8. GETPIVOTDATA는 왜 자동으로 생기는가

피벗테이블 옆 빈 셀에 =를 입력하고 피벗의 숫자를 클릭하면 =D5가 아니라 이런 것이 들어간다.

=GETPIVOTDATA("매출",$A$3,"지점","강남","월",7)

많은 사람이 이것을 버그로 여기고 검색한다. 그러나 이것은 의도된 안전장치다. 이유를 알면 무작정 끄지 않게 된다.

피벗테이블의 셀 위치는 고정이 아니다. 필터를 하나 걸면 행이 줄어들고, 필드 순서를 바꾸면 열이 이동하며, 새로 고침 후 항목이 늘면 표 전체가 아래로 밀린다. 이때 =D5라고 써 둔 참조는 여전히 D5를 가리키지만 D5에 있던 값은 다른 것으로 바뀌어 있다. 숫자가 나오니 오류도 나지 않는다. 잘못된 값이 조용히 보고서에 실린다.

GETPIVOTDATA는 위치가 아니라 의미로 참조한다. 「이 피벗의 매출 필드에서 지점이 강남이고 월이 7인 값」이라고 지정하므로 레이아웃이 바뀌어도 같은 값을 따라간다. 해당 조합이 사라지면 #REF!를 내서 틀린 값 대신 오류를 보여 준다. 침묵하는 오답보다 시끄러운 오류가 낫다는 설계다.

8.1 그래도 끄고 싶을 때

대시보드를 만들면서 수식을 옆으로 채우기 할 때는 GETPIVOTDATA가 불편하다. 상대 참조처럼 밀리지 않고 인수가 고정되기 때문이다. 끄는 방법은 다음과 같다.

  1. 피벗테이블 안 아무 셀이나 선택한다.
  2. 피벗 테이블 분석 탭에서 옵션 버튼 자체가 아니라 그 옆의 작은 화살표를 누른다.
  3. 목록에서 GetPivotData 생성을 눌러 체크를 해제한다.

이 설정은 파일이 아니라 엑셀 프로그램 전체에 적용되는 응용 프로그램 수준 설정이다. 한 번 끄면 그 PC의 모든 통합 문서에서 꺼진다. 팀에서 파일을 공유할 때 상대 PC에서는 여전히 GETPIVOTDATA가 생성될 수 있다는 뜻이기도 하다.

일시적으로만 피하고 싶다면 굳이 설정을 바꾸지 말고 셀 주소를 마우스로 클릭하지 말고 키보드로 직접 입력하면 된다. =D5를 타이핑하면 그대로 들어간다. 다만 앞서 설명한 위험을 감수하는 것이므로, 레이아웃이 자주 바뀌는 피벗이라면 권하지 않는다.

9. 여러 시트 데이터를 하나로 합칠 때의 선택지

월별로 시트가 나뉜 파일, 지점별로 파일이 따로인 폴더는 실무에서 흔하다. 이걸 하나의 피벗으로 만드는 방법은 세 가지이고, 셋의 성격이 꽤 다르다.

방법어떻게장점한계
수동으로 한 시트에 붙여넣기각 시트를 복사해 하나의 표 아래로 이어 붙인 뒤 표로 변환버전·플랫폼 제약이 없다. 누구나 가능매달 반복해야 하고 실수가 누적된다
다중 통합 범위 마법사Alt+D를 누른 뒤 P를 눌러 옛 마법사를 열고 다중 통합 범위 선택리본에 없는 옛 기능이지만 여전히 동작한다필드 구조가 행·열·값 하나씩으로 고정돼 원본 열 이름을 잃는다
파워 쿼리로 추가(Append)데이터 탭 > 데이터 가져오기로 각 표를 불러와 쿼리 추가새로 고침 한 번으로 반복 자동화. 폴더 단위 취합도 가능버전·플랫폼 제약이 있다(아래 11장 참조)

Microsoft도 다중 통합 범위 문서에서 최신 버전에서는 여러 시나리오가 파워 쿼리로 데이터를 먼저 결합한 뒤 피벗테이블을 만드는 방식으로 처리된다고 안내한다. 실제로 다중 통합 범위 마법사는 결과물의 필드 이름이 행, 열, 값으로 뭉개져 나오기 때문에 지금 시점에서 새로 배울 이유는 크지 않다.

파워 쿼리 방식의 실질적 장점은 같은 작업을 다음 달에 반복하지 않아도 된다는 점이다. 한 번 쿼리를 만들어 두면 다음 달 데이터를 같은 폴더에 넣고 새로 고침만 누르면 된다. 다만 시트 이름이나 열 구성이 달마다 바뀌면 쿼리가 깨지므로, 취합 대상 파일의 열 이름과 순서를 통일해 두는 사전 작업이 사실상 필수다.

참고로 여러 표를 이어 붙이는 것(추가)과 옆으로 붙이는 것(병합·조회)은 다른 작업이다. 지점 코드로 지점명을 붙이는 식의 조회 작업은 VLOOKUP·XLOOKUP 가이드에서 다룬 조회 함수나 파워 쿼리의 병합 기능이 맞는 도구다.

10. 피벗테이블이 느려질 때 점검할 것

피벗테이블이 느려지는 원인은 대부분 캐시가 커졌거나, 캐시를 반복해서 다시 만들고 있거나, 화면 갱신이 과도한 세 가지 중 하나다. 순서대로 점검한다.

점검 항목왜 느려지나조치

여기서 피벗 캐시 공유는 알아 둘 가치가 있다. 같은 원본으로 삽입 > 피벗 테이블을 세 번 실행하면 캐시가 세 벌 생겨 파일이 세 배로 커진다. 반면 이미 만든 피벗테이블이 있는 시트를 시트 복사하면 캐시를 공유해 용량이 거의 늘지 않는다. 다만 캐시를 공유하는 피벗들은 새로 고침과 그룹화가 함께 움직인다. 한쪽에서 날짜를 월별로 묶으면 다른 쪽도 월별로 바뀐다. 이 동작을 모르면 「내가 건드리지도 않은 피벗이 바뀌었다」는 상황이 된다.

11.1 파워 피벗이 없는 에디션이 생각보다 많다

Microsoft의 파워 피벗 안내 문서는 에디션별 포함 여부를 구체적으로 나열한다. 포함되는 쪽에는 Windows 데스크톱 엑셀이 들어 있는 Microsoft 365 전 버전, Office Professional 2021, Office Home & Business 2021, Office Home & Student 2021, 2019 계열, Office 2016 Professional Plus(볼륨 라이선스), Office 2013 Professional Plus, Excel 2013·2016 단독 제품이 있다. 반대로 포함되지 않는 쪽에는 Office Professional 2016, Office Home & Student 2013·2016, Office Home & Business 2013·2016, Office for Mac, Office for Android, Office RT 2013, Office Standard 2013, Office Professional 2013이 있다.

여기서 눈여겨볼 것은 2016 세대와 2021 세대의 역전이다. Office Professional 2016에는 파워 피벗이 없지만 Office Home & Student 2021에는 있다. 즉 「전문가용을 샀으니 당연히 되겠지」라는 추정이 통하지 않는다. 회사 PC에서 파워 피벗 탭이 보이지 않는다면 버전 번호가 아니라 에디션 이름을 확인해야 한다.

11.2 Mac 사용자가 먼저 알아야 할 것

Mac에서도 피벗테이블 자체는 정상적으로 만들고 새로 고칠 수 있다. 다만 데이터 모델을 전제로 하는 기능은 기대하지 않는 편이 좋다. 파워 피벗이 Office for Mac에 포함되지 않는다는 것이 Microsoft 문서에 명시돼 있기 때문이다. 데이터 모델을 켜야만 나타나는 고유 개수 요약 함수가 Mac에서 보이지 않는다는 보고가 많은데, Microsoft 공식 문서에서 「Mac은 고유 개수를 지원하지 않는다」는 직접적인 문장은 확인하지 못했다. 다만 파워 피벗 미포함이라는 공식 사실과는 정합적이다. 고유 개수가 필요하면 원본에 중복 표시용 도우미 열을 만드는 우회가 현실적이다.

파워 쿼리는 Mac에서도 쓸 수 있지만 Microsoft 365 구독자 한정이며, 데이터 탭의 데이터 가져오기에서 접근한다. 지원 원본은 텍스트·CSV, 엑셀 통합 문서, XML, JSON, SQL Server, SharePoint, OData, 폴더, 표·범위 등으로 Windows보다 좁다.

11.3 웹 버전에서 자주 걸리는 세 가지

  • 계산 필드를 새로 만들 수 없다. 데스크톱에서 만들어 둔 계산 필드는 표시되지만 브라우저에서 추가·편집하는 경로가 없다. 대안은 원본에 도우미 열을 만드는 것이다.
  • 슬라이서는 로컬 피벗테이블에만 만들 수 있다. 표에 대한 슬라이서, 데이터 모델 피벗의 슬라이서, Power BI 연결 피벗의 슬라이서는 Windows 또는 Mac 데스크톱이 필요하다.
  • 메뉴 이름이 다르다. 데스크톱의 옵션이 웹에서는 설정으로 표시되고, 새로 고침도 모두 새로 고침 드롭다운 안에 들어 있다.

실무적 함의는 분명하다. 파일을 만드는 사람과 보는 사람의 환경이 다르면 기능이 조용히 사라진다. 계산 필드로 만든 지표가 웹에서 열 때는 보이더라도, 웹에서만 작업하는 동료는 그것을 수정할 수 없다. 협업 파일이라면 계산 필드보다 원본 도우미 열이 안전한 선택인 이유다.

결론: 「어떻게」보다 「왜」를 알아야 다음번에도 풀린다

이 글에서 다룬 증상들은 겉보기에는 제각각이지만 뿌리는 몇 개 안 된다. 정리하면 이렇다.

  • 피벗은 캐시를 본다. 그래서 새로 고침이 필요하고, 원본을 지워도 살아 있고, 파일이 커지고, 필터 목록에 유령 항목이 남는다.
  • 범위는 자라지 않고 표는 자란다. 그래서 행을 추가해도 반영되지 않는다.
  • 요약 함수는 데이터 형식으로 결정된다. 그래서 텍스트 한 칸이 합계를 개수로 바꾼다.
  • 계산 필드는 합계 위에서 계산한다. 그래서 곱셈은 틀리고 나눗셈은 맞는다.
  • GETPIVOTDATA는 위치가 아니라 의미로 참조한다. 그래서 자동으로 생기고, 끄면 조용한 오답 위험이 생긴다.
  • 기능은 버전이 아니라 에디션과 플랫폼으로 갈린다. 그래서 같은 2016이라도 되는 사람과 안 되는 사람이 갈린다.

실무에서 바로 적용할 것을 하나만 고르라면 원본을 표로 만드는 것이다. 새로고침 미반영, 범위 재지정, 성능 저하 세 가지를 한 번에 줄인다. 두 번째는 계산 필드를 쓰기 전에 값 표시 형식과 도우미 열을 먼저 검토하는 것이다. 총합계가 조용히 틀리는 사고를 대부분 막을 수 있다.

마지막으로 메뉴 위치는 시간이 지나면 또 바뀐다. 이 글의 경로가 화면과 다르면 리본의 검색 상자에 기능 이름을 그대로 입력하는 편이 빠르고, 기능이 아예 보이지 않는다면 버전이 아니라 에디션과 플랫폼을 먼저 확인하기 바란다. 2026년 7월 기준으로 정리했으며, 자동 새로 고침처럼 아직 참가자 프로그램 단계인 기능은 앞으로 일반 채널로 넓어질 가능성이 있다.
