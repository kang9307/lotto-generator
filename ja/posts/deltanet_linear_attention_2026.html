線形アテンションが安くするものと手放すもの

過去を固定サイズの状態に圧縮すれば計算量は線形になるが、正確な想起は値が上がる

2026-07-30 IT・技術

序論: 「線形」は安いという意味ではなく、別のものを買うという意味だ

「線形アテンション」という名前は誤解を招く。初めて聞く人はたいてい同じことをより安くやる方法として受け取る。ところが実際に起きていることは違う。同じことを安くやるのではなく、別のものを買うのだ。この区別を落とすと、以後の判断がすべてずれる。

出発点は一本の系譜整理記事だ。ソフトマックスアテンションから線形アテンションへ、そこからDeltaNetとGated DeltaNetを経てKimi Delta Attentionまで続く流れを段階ごとに解いた記事が最近、開発者コミュニティに上がった。よい解説であり、その系譜をもう一度要約することがこの記事の目的ではない。

この記事が答えようとする問いは二つだ。第一に、線形アテンションは正確に何を安くするのか。第二に、その代償に何を手放すのか。そして実務者にとって重要な三番目の問いがここから派生する。自分がやっている作業は、その代償を負担できる種類なのか。

あらかじめ結論の方向を打ち込んでおく。標準アテンションが高い金で買っているものは全量再参照権だ。どのトークンでももう一度、正確に見られるという権利である。線形アテンションはその権利を売って要約カード一枚を買う。要約は書き直し続けられるが大きさは増えない。だから要旨だけで足りる仕事はほとんど損失なく回り、原文をそのまま取り出す仕事から先に崩れる。デルタ則系がやったことはその壁を後ろへ押しやったことであってなくしたことではない。

手法の特定は成功した。元記事が扱う三つの手法と論文がすべて確認でき、この記事はその論文の要旨で確認できる範囲だけを根拠に使う。数式は移していない。概念は言葉で解き、必要な箇所にだけごく短い擬似コードを置いた。測定条件が書かれていない数値は、条件がないという事実とともに示し、条件なしで引用していない。確認できなかったことは本文にそのまま残した。キャッシュ最適化の軸はすでにKVキャッシュ共有とAttention圧縮で扱ったので、ここでは繰り返さない。

最後の行を特に強調したい。標準アテンションのコストがシーケンス長の二乗に比例するという記述はあまりに広く使われているので原論文の要旨に書かれているように思えるが、要旨にはない。要旨を直接開いて確認したが、二乗のコストやシーケンス長のコストについての文は出てこない。層ごとの計算量を比較した表は本文にあるが要旨のページでは確認できなかった。そこでこの記事は二乗コストの根拠を線形トランスフォーマー論文の要旨から取る。そちらは入力長に対する二乗の計算量のために非常に長いシーケンスでは遅すぎると最初の文で明記している。

些細に見える確認だが習慣の問題だ。誰もが知っている事実であるほど、出典が見当違いのところに付いている場合が多い。

2. 標準アテンションが買っているもの - 全量再参照権

まずコストから整理する。長さTのシーケンスでクエリとキーの組はTの二乗の規模で生じる。学習段階ではこれがそのまま計算量であり、生成段階では新しいトークンが出るたびにそれまでの履歴全体をもう一度覗かねばならないという意味になる。だから履歴を入れておくキャッシュが長さに比例して育つ。

ここでよくある誤読が一つ生じる。このコストを浪費と読むことだ。ところがそのコストは浪費ではなく購入である。何を買うのか。

  • 全量再参照権 - 三万番目のトークンを生成するとき、17番目のトークンのキーと値を元のままもう一度見られる。圧縮された要約ではなく原本だ。
  • 選択性 - ソフトマックスは関連のある位置に重みを寄せる。何を見るかを毎時点で選び直せる。
  • 正規化 - 重みの和が定まっているので、履歴が長くなっても寄与度の尺度が保たれる。
  • 後からの問い合わせ - 入力を入れる時点で何を問うか分からなくてよい。問いが決まった後に過去を探せる。この性質が実務で最も価値があり、同時に最も失いやすい。

最後の項目がこの記事で何度も戻ってくる地点だ。固定サイズの状態に折り畳んだ瞬間、何を残すかは問いを見る前に決まる。モデルはこれから何を問われるか分からない状態で要約を作らねばならない。これが原理的に難しい問題だという事実が、この系譜全体を説明する。

3. 線形アテンションの着想 - 再帰に折り畳んで状態を固定する

着想そのものは驚くほど単純だ。ソフトマックスをカーネル特徴写像の内積に替えれば掛け算の順序を変えられる。線形トランスフォーマー論文の要旨はこの箇所を行列積の結合法則を利用して計算量をシーケンス長の二乗から線形へ下げると記す。そしてこの形が反復的な実装を許し、再帰型ニューラルネットワークとの関係を明らかにすると付け加える。

言葉で解くとこうだ。過去のキーと値をすべて保管する代わりに、それらを一つの行列に重ね続ける。トークンを一度なぞりながら毎段階同じ大きさの状態を更新する。なぞり終えればその状態一つに過去が入っている。大きさは最初から最後まで同じだ。

# 概念的な擬似コード - 二つの方式が何を抱えて進むかだけを比べる
# 実装ではなく、正規化とマルチヘッド、位置情報は省略した

## 標準アテンション: 過去をすべて抱えて進む
cache = []                            # 長さに比例して育つ
for t in 1..T:
    cache.append( (key[t], value[t]) )
    out[t] = weighted_sum(query[t], cache)   # 毎回 cache 全体を見直す
# 状態の大きさ = 長さに比例      トークンあたりコスト = それまでの長さ分

## 線形アテンション: 固定サイズの状態一つだけを抱えて進む
S = zeros(d_value, d_key)             # 大きさが T と無関係だ
for t in 1..T:
    S = update(S, key[t], value[t])   # 同じ場所に重ね書きし続ける
    out[t] = read(S, query[t])        # cache を見直さない
# 状態の大きさ = 固定             トークンあたりコスト = 長さと無関係

# ★ 下のループには key[1] から key[t-1] までを見直す手立てがない。
#   S に残ったものだけが見える。これが計算量を下げた代償だ。
#   条件として書けばこうなる。
#     if 必要な情報 が S に残っている      -> 正答
#     if 必要な情報 が重ね書きで消えた     -> もっともらしい誤答

ここで得られるものは明確だ。生成段階でトークンあたりのコストが履歴の長さと無関係になる。キャッシュが育たないのでメモリも長さに引きずられない。長い文脈でこの差は程度の問題ではなく可能と不可能の問題になることもある。

ところが一緒に消えるものがある。一次出典の記事が突く表現どおり、線形化はソフトマックスの正規化と選択性を捨てた代償に効率を得たものだ。そしてそれより根本的なことが上の擬似コードの最後のコメントにある。過去を見直す手立て自体がない。状態に残ったものだけが見える。

4000倍という数字をどう読むか

線形トランスフォーマー論文の要旨は非常に長いシーケンスの自己回帰予測で最大4000倍まで速いと記す。印象的な数字であり実際に広く引用される。だからこそ条件を確認しなければならない。

  • 条件として書かれているもの - 自己回帰予測という作業の種類、非常に長いシーケンスという定性的な記述、最大という限定語。
  • 要旨に書かれていないもの - モデルサイズ、正確なシーケンス長、ハードウェア、バッチサイズ、比較対象の実装設定。この五つの欄が空だ。
  • だからこの記事はこの数値を方向の根拠としてのみ使う。つまり非常に長いシーケンスの逐次生成で差が大きく開くという意味に読み、自分たちの状況で4000倍が出るという意味には読まない。
  • 同じ規則を Mamba 論文の処理量5倍にも当てる。要旨は速い推論という文脈とともにこの倍率を記すが、バッチサイズとハードウェアは要旨にない。

この習慣が重要な理由は線形系の利得が条件に特に敏感だからだ。利得の大きさがシーケンス長によって変わる。短い文脈では差がほとんどなく、文脈が長くなるほど開く。長さを書いていない速度主張は、線形系では特に情報が少ない。

4. DeltaNet系が直したもの - 上書きと忘却

ここから系譜の本論だ。そしてこの系譜は同じ問題を三度違うやり方で攻めた記録として読むのが一番よく分かる。問題は一つだ。固定サイズの状態をどう無駄なく使うか。

ア. 加算は代入ではない

一次出典の記事が投げる問題提起が正確だ。加算は代入ではない。どういう意味か。純粋な線形アテンションは新しい情報を状態に足す。ところが互いに異なるキーが完全に直交していなければ足した値が既存の値と混ざる。同じ場所に二度書けば上書きされるのではなく重なる。記事はこの状況について、すでに書いた値をもう一度書くと状態がその値の二倍を出すと説明する。

メモリ更新の比喩で言えばこうだ。我々が望んだのは代入で、実際に起きたのは累積だ。更新が必要なたびに以前の痕跡が残るので、状態は次第に汚れていく。これがいわゆる書き込み干渉の問題である。

イ. デルタ則 - 誤差だけを書く

DeltaNetの着想はこれへの答えだ。値の全体を書くのではなく、現在の状態がすでに出せる値との差だけを書く。つまり状態にそのキーを問い、返ってきた答えと正解の誤差を計算してその分だけを反映する。すでによく保存されていればほとんど何も書かず、ずれていればその分だけ直す。

論文の要旨で確認できる記述は次のとおりだ。線形アテンションのトランスフォーマーと状態空間モデルが線形時間の代替として提示されたが特に文脈内検索を要する課題でトランスフォーマーに及ばないこと、加算的な更新をデルタ則に置き換えたより表現力のある変種が連想想起により効果的だと判明したこと、ところがそうしたモデルを学習させる既存のアルゴリズムがシーケンス長方向に並列化されず現代のハードウェアで非効率だということだ。論文の貢献はその並列化をハードウェア効率のよいアルゴリズムで解いた点にある。

この最後の箇所が実務的に重要だ。着想がよくても学習が並列化されなければ規模を上げられない。この系譜で毎段階の論文がアルゴリズムとカーネルを一緒に出す理由がそれだ。アーキテクチャの発想とハードウェアへの写像は分離しない。

ウ. ゲーティング - 的を絞った修正に全体消去を足す

Gated DeltaNetはここに忘却を足す。要旨の記述が明快だ。最近の研究が適応的な記憶制御のためのゲーティングと精密な記憶修正のためのデルタ更新則という二つの機構をそれぞれ探ってきたが、著者らはこの二つが相補的だと観察する。ゲーティングは素早い記憶消去を可能にし、デルタ則は的を絞った更新を助けるというものだ。

言葉で解くとこうだ。デルタ則は特定の項目を書き直すことには強いが、古くなって丸ごと捨てるべきものをすっかり空けることには弱い。ゲートはどれだけ残すかを調節してその仕事を担う。話題が変わったとき以前の話題を素早く手放す能力と見ればよい。

要旨に具体的な数値はない。言語モデリング、常識推論、文脈内検索、長さの外挿、長文脈理解を含む複数のベンチマークでMamba2 や DeltaNet といった既存モデルを一貫して上回ると記すだけで、スコアやモデルサイズ、学習トークン数は要旨の範囲では確認できない。したがってこの記事は優位の方向だけを引用し、大きさは引用しない。

エ. チャネル別の減衰 - ゲートをより細かく割る

Kimi Delta Attentionはそのゲートをより細分化する。一次出典の記事の説明では、一つの値で状態全体の保存度を定めていたものを次元ごとに異なる比率に変えたものだ。そうするとあるチャネルは空けながら別のチャネルは保つことができる。

論文の要旨で確認できるのはこうだ。KDA はGated DeltaNet をより細かいゲーティング機構へ拡張した表現力のある線形アテンションのモジュールで、その目的は限られた有限状態の再帰メモリをより効果的に使うことである。そして専用のチャンク単位アルゴリズムが対角プラス低ランクの遷移行列の特化した変種を通じてハードウェア効率を得ており、一般的な形より計算を大きく減らしつつ古典的なデルタ則との整合性を保つと記す。

注目すべき表現は限られただ。論文自身がメモリが限られているという事実を前提にその中での効率を語る。この系譜全体が器を大きくする競争ではなく器をうまく使う競争だという事実が、ここで明らかになる。

5. それでも残る壁 - 正確な想起は状態の大きさに閉じ込められる

この節がこの記事の中心だ。先の改善が印象的だが種類が決まっていることを確かめようとするものである。

最も直接的な根拠はRepeat After Me論文だ。要旨の記述はこうだ。著者らはシーケンス長と無関係な固定サイズの潜在状態を使うモデルを一般化状態空間モデルとまとめて呼び、こうしたモデルが推論効率の点では有望だが入力文脈から複写する課題ではトランスフォーマーに比べて制限されると述べる。そして文字列の複写という単純な課題を理論的に分析し、二層のトランスフォーマーは指数的な長さの文字列を複写できる一方、これらのモデルは固定サイズの潜在状態に根本的に制限されることを証明したと記す。

根本的にという表現が重要だ。これは実装が未熟だからでもなく学習が足りないからでもない。入れる器の大きさが決まっていれば入れられる量も決まるという話だ。要旨はさらに、事前学習された大規模言語モデルを評価した結果トランスフォーマーのモデルが文脈から情報を複写し検索する仕事で状態空間モデルを大きく上回ると記し、これらの結果を合わせると実用的に重要な課題で二つの系譜のあいだに根本的な隔たりがあることを示唆すると結ぶ。

興味深いのは同じ診断が複数の場所で独立に出てくるという事実だ。

  • DeltaNet 論文は最初の文から線形時間の系譜が特に文脈内検索を要する課題でいまだトランスフォーマーに及ばないと記す。改善を提案する論文がその弱点を出発点にしている。
  • Mamba 論文は複数の準二乗時間アーキテクチャが言語のような重要なモダリティでアテンションほどうまくいかなかったと記し、その核心的な弱点を内容に基づく推論能力の欠如だと指摘する。そしてそれを直す方法として、状態空間のパラメータを入力の関数にする選択性を導入する。
  • Gated DeltaNet 論文は線形トランスフォーマーが検索と長文脈の課題で性能が限られていたという記述で始まる。
  • Kimi Linear 論文は改善の目的を限られた有限状態メモリのより効果的な使用と明記する。限られているという前提を否定しない。

四本の論文が同じ壁を互いに違う角度から指している。そして各論文の貢献はその壁を後ろへ押すことだ。デルタ則は同じ器をより汚さずに使う。ゲーティングは要らなくなったものを素早く空ける。チャネル別の減衰は空けるものと残すものをより細かく分ける。すべて同じ器をよりうまく使う方法であり、器を大きくする方法は一つもない。

比喩を一つ - キャビネットと要約カード

標準アテンションは原本の書類キャビネット全体を抱えて歩くことに等しい。重くて場所を取るが、後でどの書類でも原本をもう一度取り出せる。

線形アテンションは要約カード一枚を書き直し続けることだ。軽くて速い。デルタ則はカードにすでに書かれた項目を消して直す要領であり、ゲーティングは時代遅れの項目を丸ごと消す要領であり、チャネル別の減衰は項目ごとに違う速さで消す要領だ。要領がよくなるほどカードは充実する。ところがカードの大きさは一度も増えていない。

だからカードに書かれていないことを問えば答えがない。もっと悪いのはモデルが答えがないと言わないことだ。カードにある似た項目でもっともらしい答えを作る。実務でこれが本当の危険だ。失敗が沈黙せず偽装する。

6. ハイブリッドは妥協ではなくこの交換の結論だ

ハイブリッドという語はしばしば決められなくて半分ずつ混ぜたもののように聞こえる。ここではそうではない。前節の交換をそのまま計算すれば出てくる結論だ。そしてその根拠は論文の要旨に直接書かれている。

  • DeltaNet 論文は二種類のハイブリッドを実験したと記す。一つは一層おきにスライディングウィンドウアテンション層を入れたもの、もう一つは大域アテンション層を二つ入れたものだ。そしてこれらのハイブリッドが強いトランスフォーマーの基準線を上回ったと明かす。
  • Gated DeltaNet 論文は自らの層をスライディングウィンドウアテンションまたは Mamba2 層と結合したハイブリッドアーキテクチャを開発し、学習効率と課題性能をともに改善したと記す。
  • Kimi Linear 論文はKDA と Multi-Head Latent Attention の層ごとハイブリッドを基に事前学習したと明かす。そしてハイブリッドの線形アテンションアーキテクチャが公正な比較で完全アテンションを初めて上回ったと主張する。

ここで読むべきは二つという数字だ。大域アテンション層を全部入れずに二つだけ入れたのに強い基準線を上回ったという記述が語ることがある。

  • 正確な想起の能力はすべての層に必要なものではない。数層あれば相当部分が回復される。
  • コストの大部分は線形層が担う。キャッシュが育つ層が少数なので、長さに対するコストの増加が大きく抑えられる。
  • したがってハイブリッドは想起とコストを半分ずつ分けたものではなく、想起が必要な場所にだけ値を払ったものだ。こちらのほうがはるかに正確な理解である。
  • Kimi Linear が報告したKVキャッシュ最大75%削減がまさにこの構造から出てくる。完全アテンションの四分の一ほどという意味であり、ゼロではないという点も併せて読まねばならない。残った四分の一が想起を支える層だ。

そこでハイブリッドという語に出会ったとき問うべき値が定まる。この三つが事実上、想起性能の上限を決める。

  1. 大域アテンションは何層か。二層か八層かで話がまったく変わる。
  2. どの間隔で配置されているか。前方に寄っているか、均等に散っているか、後方にあるか。
  3. 窓を使う層の窓の大きさはどれだけか。スライディングウィンドウは大域ではない。窓の外は見えない。

技術レポートでこれらの値をどう探して読むかは技術レポートの読み方でレポート読解の観点から別に扱った。この記事はその値がなぜ想起性能の上限を決めるのかに集中する。トランスフォーマー自体の基礎が必要なら機械学習独学ロードマップの該当段階へ行くほうが速い。

7. 「1M コンテキスト」の読み方

線形系の広がりはコンテキスト長表記のインフレとともに来た。だからこの表記を読む技術が実務の技能になる。

まず表記の意味を狭めなければならない。コンテキスト長は入力が収まるという意味だ。その長さで精度が保たれるという意味ではない。容量の表記であって性能の表記ではない。

この区別の根拠として最もよい資料がRULER論文だ。要旨の記述を整理するとこうなる。長い妨害文書から一片を探し出す単純な検索試験が広く使われているが、それは長文脈理解の表層的な形しか示さない。そこで著者らはシーケンス長と課題の難度を自由に設定できる合成ベンチマークを作り、探す対象の種類と個数を多様化し、多段の追跡と集約という新しい範疇を入れて17個のモデルを13の課題で評価した。

結果の記述が核心だ。単純な検索試験でほぼ完璧な精度を出しながら、文脈の長さが伸びるとほぼすべてのモデルの性能が大きく落ちたこと、そしていずれも32K以上の文脈サイズを主張するが、そのうち半分だけが32Kの長さで満足できる性能を保ったことだ。200K に対応するあるモデルも入力長と課題の難度を上げると改善の余地が大きいと記す。

この結果を線形系にそのまま当てはめてはならない。RULER の評価対象が特定のアーキテクチャ系譜に限られるという記述は要旨になく、この記事が確認した範囲でもそうした区分は確認できない。つまりこれは線形系の欠陥ではなく長文脈一般の問題だ。ただし固定サイズの状態という構造がその問題を原理的により強く受けるという点は5節の根拠から従う。二つの事実を混ぜないことが正確だ。

同じ規則を Kimi Linear の数値にも当てねばならない。1M文脈でデコード処理量最大6倍は処理量の主張だ。その長さで精度が保たれるという主張ではない。二つの軸は分けて読むべきである。

8. 自分の作業が想起依存かどうかを見分ける手順

ここで観点を変える。ここまではアーキテクチャの話であり、ここからは自分にできることだ。

冷静に言えば、選択はたいてい自分の手にない。ほとんどの実務者はアテンション方式を選ばない。モデルを選ぶか、実のところ会社が契約したモデルを使う。そして提供側がアーキテクチャを乗り換えれば通知なく変わる。バージョン番号は上がるが、内部構成がどう変わったかはレポートを開いてみないと分からず、レポートがない場合も多い。

そうなると実務の行動は一つに狭まる。自分の作業が想起依存かどうかを見分け、それに合った回帰ゲートをあらかじめ掛けておくこと。そうすればアーキテクチャが変わったとき自分が先に気づくようになる。

第1段階 - 想起依存度を点数にする

# 自分の作業が想起依存かを見分ける - 概念的な手順
score = 0

if 出力に原文の文字列がそのまま入る必要がある:        score += 3
if 答えが入力の二か所以上に散っている:                score += 2
if 答えと見た目の似た妨害項目が複数ある:              score += 2
if 間違っても見た目はもっともらしい:                  score += 2
if 入力がおおむね8千トークンを超える:                 score += 1

if score >= 5:
    想起依存だ
    # 位置スイープのゲートが必須。大域アテンション層の有無と数を確認する。
    # 原文と突き合わせられる形に出力形式を強制する。
elif score >= 3:
    境界にある
    # 引用部分だけ人が標本検査する。標本率を文書で定める。
else:
    要旨型だ
    # 線形系のコスト利得をそのまま享受してよい。

# ★ 点数そのものが目的ではない。五つの問いを落とさないことが目的だ。

五つの問いを一つずつ解いておく。順序に意味がある。上のほうがより決定的だ。

  • 原文の文字列がそのまま必要か - 条項番号、金額、日付、識別子、関数シグネチャ、設定キー。一文字違えば使えない値があるなら、その作業は想起依存だ。要約がどれほどよくても代替されない。
  • 答えが何か所に散っているか - 一か所にあるなら探すだけでよい。三か所をつなぎ合わせる必要があるなら検索と追跡が同時に要り、このとき難度が急激に上がる。RULER が多段の追跡を別の範疇に置いた理由がそれだ。
  • 似た妨害項目が複数か - これが最も過小評価される。似た条項が繰り返される契約書、名前だけ違う関数が多いコードベース、書式が同じログ数万行。要約カードではこれらの項目が互いに混ざりやすい。
  • 間違えたときに目に見えるか - 要約はもっともらしく外す。引用は原文と突き合わせれば捕まる。目に見えない失敗のほうが危険だ。だから出力形式を突き合わせ可能な形に強制すること自体が防御策になる。
  • 入力が長いか - 最後に置く理由がある。長さは単独の指標ではない。短くても想起依存であり得るし、長くても要旨型であり得る。長さは他の四つを増幅する変数だ。

第2段階 - 自社の文書で位置スイープのゲートを作る

想起依存と判定されたなら、公開ベンチマークの点数を信じるだけで終わらせてはならない。自社の文書はベンチマークと分布が違う。妨害項目の密度、文書の構造、用語の反復の様相がすべて違う。

# 自社の文書で作る想起の回帰ゲート - 概念的な手順
# 公開ベンチマークの点数ではなく自社のデータで確認する

for length in [8k, 32k, 128k, 256k, 512k]:
    for position in [前 5%, 25%, 50%, 75%, 後 95%]:
        doc = build_haystack(our_corpus, length)
        doc = insert_target(doc, position, target_span)
        ans = ask(doc, question_requiring_verbatim_quote)
        ok  = exact_match(ans, target_span)   # 要約一致ではなく逐語一致
        record(length, position, ok)

# 判定規則は数字を見る前に書いておく
#   pass : すべての位置で精度 >= 0.98
#   warn : どこか一つの位置でも 0.90 <= 精度 < 0.98
#   fail : どこか一つの位置でも 精度 < 0.90
#
# ★ ゲートを信じる前に対象の語句をわざと抜いて一度回す。
#   そのとき fail が出なければ、そのゲートは何も測っていない。
#   それまでの合格はすべて無意味だったという意味だ。

このハーネスで譲ってはならない地点が四つある。

  • 位置をスイープする - 対象の語句を文書の前、中、後にそれぞれ入れる。固定サイズの状態を使う構造では前方の情報が重ね書きされる余地がより大きい。後ろだけ試験すればこの失敗を捕まえられない。
  • 長さをスイープする - 一つの長さでの点数は閾値がどこかを教えてくれない。我々が知りたいのは点数ではなく何万トークンから崩れるかだ。
  • 逐語一致で採点する - 意味の類似度で採点すればもっともらしい誤答が通る。想起を測るなら採点も想起の基準でなければならない。
  • 判定規則を先に書く - 結果を見た後に基準を定めれば、人は必ず合格する値に定める。これは誠実さの問題ではなく認知の問題だ。

第3段階 - アーキテクチャが変わるときに備える

  • モデルのバージョンをログに残す - どのバージョンでどの点数が出たかが残らなければ退行を発見しても原因を突けない。
  • ゲートを定期的に回す - 提供側のモデルは自分たちのリリース周期と無関係に変わる。自分たちが何も変えていない週に結果が変わり得る。
  • 想起依存の作業には検索を前に置く - モデルに長い文書をすべてくわえさせる代わりに、関連する区間だけを切って入れる。状態の大きさの制約をパイプラインの設計で迂回する方法であり、たいてい最も安い。
  • 引用を強制する - 答えとともに根拠の語句をそのまま移させ、その語句が原文に実際にあるかを機械的に突き合わせる。この一枚が想起の失敗を沈黙から音に変える。
  • 要旨型の作業は逆に放っておく - 分類、振り分け、感情判定、会話文脈の維持のように要旨だけで足りる仕事に想起ゲートを掛ければコストだけ増えて得るものがない。ゲートも資源だ。
作業原文の逐語が必要答えの分散想起依存度最も危険な失敗
契約書の条項を探して引用必要しばしば複数箇所非常に高い似た条項を混ぜてもっともらしい条項を作る
コードベースから正確な参照を抽出必要複数ファイル非常に高い存在しないシグネチャを自然に出す

複数文書の事実の統合部分的文書間高い出典を誤って帰属させる
長い報告書の要約不要全域低い細部の数値を落とす。たいてい許容できる
問い合わせの分類と振り分け不要ふつう一か所非常に低い境界事例の誤分類。閾値の調整で対応

9. 判断表 - 作業から結論へ

最後に使える形へ圧縮する。三番目の列より四番目の列が重要だ。系譜を選べない場合がほとんどで、そのとき残る行動は評価で何を確認するかだけだからである。

結論: 選んだのではなく受け継いだ交換

この系譜が実際に示したものから整理する。固定サイズの状態を使う再帰形へ折り畳めばシーケンス長に対する計算量が線形になり、生成時のトークンあたりコストが長さと無関係になる。その状態を使う要領は三つの段階にわたって実質的に改善された。誤差だけを書くデルタ則、要らなくなったものを空けるゲーティング、チャネルごとに違う速さで空ける細分化だ。そして一部の層にのみ大域アテンションを置くハイブリッドが公正な比較で完全アテンションを上回ったという主張まで出た。ここまでは論文の要旨で確認できる。

確認できなかったことも明確に書いておく。一次出典の記事はこの系譜のうち二つが最新の Qwen と Kimi のモデル系列に使われていると記すが、どのバージョンにどの構成で入ったのかは Qwen 側の一次資料を開いて確認できなかった。Kimi 側は論文自体が層ごとハイブリッドの構成を明かすので根拠がある。またGated DeltaNet の優位の幅は要旨に数値がなく大きさを引用できず、この記事が引用した倍率のうちバッチサイズとハードウェアが併記されたものは一つもなかった。元のトランスフォーマー論文の要旨に二乗コストの記述がないという事実もそのまま残しておいた。

実務者が持ち帰るものは三つだ。

  1. 「線形」は安いという意味ではなく要約を買うという意味だ。標準アテンションはすべてのトークンをもう一度見られるが、線形アテンションは要約しか見ない。デルタ則とゲーティングは要約をはるかによく作る方法であり、要約を原本へ戻す方法ではない。
  2. 自分の作業が想起依存かどうかが、唯一自分で決められることだ。アーキテクチャは与えられる。原文の逐語の必要性、答えの分散の程度、見た目の似た妨害項目の存在、失敗の可視性。この四つを先に判定し、それに合ったゲートを掛けておく。
  3. コンテキスト長の表記は容量であって性能ではない。長さ別の精度の推移と位置スイープ、逐語採点のない長さ表記はまだ何も語っていない。そしてその確認は公開ベンチマークではなく自社の文書で行うべきだ。

最後に一行。この交換は我々が選んだのではなく受け継いだものだ。アテンション方式を決める席に座っている実務者はごく少数である。しかし自分の作業がその交換のどちら側に立っているかを判定し、判定が外れたときに気づく装置を掛けておく仕事は誰にでもでき、それが事実上すべてだ。コストは請求書で知らせてくれる。想起は誰も知らせてくれない。
