更新設定画面の全体像 — 何を決められて、何は決められないのか

Windows 11の更新設定はスタート > 設定 > Windows Updateから始まる。MicrosoftのWindows Update FAQは、Windowsがデバイスを安全で最新の状態に保つために更新を自動でダウンロードしインストールすると説明している。同じ文書は、更新を完全に止めることはできず、一時的に一時停止できるだけだとも述べる。この一文が画面全体を読む基準になる。画面のほぼすべての項目は「受け取るかどうか」を決めるスイッチではなく、「いつ、どの方式で、どこまで遅らせられるか」を決める調整つまみである。

項目を役割で分けると三つの系統になる。

  • 時点を決める項目: 更新の一時停止、アクティブ時間、再起動のスケジュール。インストール自体は止めず、インストールや再起動が起きる時刻を調整する。
  • 受け取る範囲を決める項目: 利用可能になり次第最新の更新を入手する、オプションの更新。定期的なセキュリティ更新のほかに何を受け取るかを扱う。
  • 受け取る方法を決める項目: 配信の最適化。同じ更新をどこからダウンロードし、どれだけ外へ送るかを決める。

これに事後の道具が二つ加わる。更新履歴(インストール済みの更新を見て、一部を削除する)とトラブルシューティング(インストールが失敗したとき)である。下の表は、文書が示す場所、項目の働き、文書に書かれた上限を一度に並べたものである。各項目の条件と例外は続く節で解く。

機能更新・品質更新・オプションの更新 — 何がどう違うのか

更新FAQは更新を二種類に分ける。機能更新は年に1回リリースされ、新機能を含む。品質更新はそれより頻繁に提供され、セキュリティ修正とバグ修正を含む。設定画面では、一時停止・アクティブ時間・再起動のスケジュールが両方の種類に適用される。FAQは、機能更新を新機能を含む年1回のリリースとして、品質更新をより頻繁に提供されるセキュリティ修正とバグ修正としてのみ説明しており、両者の大きさやリスクを比べてはいない。

三つ目の区分であるオプションの更新は、月例の累積更新に加えて新機能と非セキュリティの変更を提供する更新として説明される。Microsoft Learnの「Windows Updateクライアントポリシーの構成」(IT管理者向け文書)は、オプションの更新のインストールは、Windows Updateクライアントポリシーを使って更新を受け取るデバイスでは既定で有効になっていないと述べる。個人PCにも同じ既定値が当てはまるかは、その文書には書かれていない。個人PCでこの区分がどの画面にどう表示されるかは確認した文書にないため、その点は末尾の「確認できなかったこと」に別に書いた。

更新の一時停止 — 最大35日が意味すること

一時停止はスタート > 設定 > Windows Updateの更新の一時停止コントロールで日付を選択して行う。文書は、現在の日付から最大35日まで更新を一時停止でき、カレンダーでは対応する一時停止期間内の日付だけを選べると述べる。

動作の規則は四つである。

  • 一時停止の間: 再起動が必要になる可能性のある更新は、一時停止が終わるまでダウンロードもインストールもされない。一時停止した時点で進行中だった更新は取り消されると文書は書いている。
  • 一時停止が終わると: デバイスは利用可能な最新の更新を確認し、ダウンロードしてインストールする。遅らせた分たまった更新が一度に入ってくるということである。
  • 延長: すでに一時停止している状態で新しい終了日を選ぶと、今日から最大35日までになる。以前に一時停止した期間は加算されない。一時停止の上限に達した後で再び一時停止するには、先に最新の更新をインストールする必要があるとFAQは書いている。
  • 何もしなければ: 一時停止の期限が切れた時点で更新が自動的に再開される。文書は、これがデバイスを安全で安定した状態に保つのに役立つと説明する。

計算例を一つ挙げる。2026年10月5日に選択可能な最も遠い日付を選ぶと、終了日は35日後の11月9日である(10月は31日までなので、10月5日に35日を足して11月9日、計算)。一時停止中の10月20日に延長するなら、新しい終了日は今日から35日以内でなければならないので最も遠い日付は11月24日であり(計算)、前の期間は合算されない。これに対して11月9日に上限に達した後は、再び一時停止する前に最新の更新をインストールする必要がある。IT管理者向けのLearn文書(Windows Updateクライアントポリシーの構成)にも似た記述がある。「35日が経過すると一時停止の設定は自動的に期限切れになり … このスキャンの後、デバイスの更新を再び一時停止できます」という文である。ただしこれはポリシーで一時停止を構成する文脈の説明なので、設定画面の一時停止コントロールが同じように動作するかはわからない。一時停止を繰り返して事実上無期限に先送りする用途が文書の意図だと読む根拠もない。

一時停止の文書は、この機能が必要になる場面を自ら挙げている。「旅行中、カンファレンス参加中、休暇中、あるいは重要なプレゼンテーションや締め切りの間の中断を避けたい」とき、時間が必要なら更新を一時停止できるというものである。終了日は自分で選ぶので、カレンダーに書いておけば、期限後の確認・ダウンロード・インストールを見込める。

アクティブ時間 — 自動と手動、既定値と最大の長さ

アクティブ時間は、デバイスが使われていると予想される時間帯である。Learn文書は、更新がアクティブ時間外にインストールされた後に自動で再起動されると説明する。つまりアクティブ時間は再起動の時点を後ろへ押しやる仕組みであり、インストールを止める仕組みではない。

Windows 11での場所は設定 > Windows Update > 詳細オプション > アクティブ時間である。アクティブ時間の調整は自動と手動から選ぶ。自動は使用パターンに応じてWindowsが調整し、手動は開始・終了時刻を自分で決める。

  • 既定値: Learn文書はPCの既定のアクティブ時間を午前8時から午後5時までと書いている。9時間である(計算)。
  • 最大の長さ: 同じ文書は、最大のアクティブ時間の範囲が開始時刻から計算されると書き、「Windows 10バージョン1607およびWindows Server 2016の最大アクティブ時間の長さは12です。それ以降のバージョンは最大18時間をサポートします」と述べる。つまり1607は12時間で、その次のバージョンから18時間である。18時間で数えれば、開始を午前8時にすると理論上は翌日の午前2時まで設定できる(計算)。
  • 数値の限界: この18時間はIT管理者向け文書の中でポリシー設定の文脈で出てくる値である。個人PCの設定画面で同じ値がそのままスライダーの最大として表れるかは、この文書だけではわからない。

Learn文書は、管理者向けの最大アクティブ時間範囲の設定の目的を、更新のインストールに十分な時間を確保しつつ、アクティブ時間中の判断の一部を利用者側に柔軟に残すことだと説明している。この文書が個人設定の推奨の長さを示しているわけではない。個人利用者向けの案内はFAQにある。デバイスを使っていないときだけ更新のために自動で再起動するよう、使用時間を設定できるという文である。

再起動のスケジュールと通知 — 再起動をいつ起こすか選ぶ

更新のインストールが終わっても、再起動して初めて適用される場合がある。FAQは、Windowsがデバイスを使っていないときに再起動を試み、それができない場合は都合のよい時間に再起動するようスケジュールを促すメッセージを表示すると説明している。いつでも自分でスケジュールする方法も同じFAQにある。スタート > 設定 > Windows Updateを選び、再起動のスケジュールを選んで都合のよい時間を選ぶ、というものである。アクティブ時間が「この時間には再起動するな」という側なら、再起動のスケジュールは「この時刻に再起動せよ」という側である。

Learn文書の再起動に関する記述のうち、個人利用者に意味のある部分は次のとおりである。

  • Windowsは更新をインストールした後、アクティブ時間外に自動で再起動しようとする。
  • 既定の期間である7日が過ぎても再起動が成功しないと、再起動が必要であるという通知が利用者に表示される。「約束された再起動」の節は同じ内容を「既定の7日の期間が終わると、Windowsはユーザーがスケジュールする再起動に切り替わります」と書いている。
  • ポリシー「スケジュールされた自動更新のインストールでログオンしているユーザーがいる場合は自動再起動しない」の説明によれば、利用者が更新通知から再起動をスケジュールした場合、利用者が指定した時刻には、利用者がサインインしていてもデバイスは再起動される。

二番目の項目の7日には但し書きがつく。同じ文書で、この期間を変更するポリシー(更新プログラムをインストールするために自動再起動する前の期限の指定)と、約束された再起動の切り替え期間を調整するポリシーは、いずれもレガシーポリシーでありWindows 11には適用されないと示されている。そのため、Windows 11の設定画面が同じ7日を使うのかは文書が直接述べていない。文書から確認できるのは、既定の7日と、その後にユーザーがスケジュールする再起動へ切り替わるところまでである。

三番目の項目は適用範囲が狭い。この文はポリシーの説明の中にあり、文書は、そのポリシーが自動更新の構成がオプション4 - 自動ダウンロードおよびインストールのスケジュールに設定されている場合にのみ適用されると述べている。したがって、すべての個人PCで成り立つ一般的な動作として読んではならない。同じ文書は、このポリシーが説明どおりには正確に動作しないことも書いている。

「利用可能になり次第最新の更新を入手」 — オンにすると何が変わるか

Microsoftは、非セキュリティ更新を制御された機能ロールアウト(CFR)で段階的に配信すると文書で説明している。スタート > 設定 > Windows Updateで利用可能になり次第最新の更新を入手するトグルをオンにすると、この過程を前倒しできる。

  • セキュリティ更新との関係: トグルの状態に関係なく、定期的なセキュリティ更新は引き続き提供される。トグルはセキュリティパッチの受信可否を決めない。
  • アクティブ時間: 文書は、この設定がアクティブな使用時間を尊重すると書いている。
  • 再起動: 再起動が必要な一部の更新は、次の累積更新(LCU)と結合されて再起動の回数を減らすと説明される。
  • 解除: いつでも無効にできる。

文書が述べている違いは、非セキュリティ更新が段階的配信(CFR)の順番を待つのか、トグルでその過程を前倒しするのか、という点である。トグルと一時停止を併用したときにどちらが優先されるかは、確認した文書にない。

配信の最適化 — 他のデバイスから受け取ることと、送り出す量

配信の最適化は、Windows Update、Microsoft Storeのアプリ、その他のMicrosoft製品をダウンロードするクラウドベースのシステムである。「伝達の最適化」のような言い方で探す人もいるが、韓国語版文書の画面名はこの配信の最適化に当たる。場所はスタート > 設定 > Windows Update > 詳細オプション > 配信の最適化である。

ダウンロード元は二つの選択肢から決める。

  • ローカルネットワーク上のデバイスのみ: 同じルーターにつながった他のPCと更新の断片をやり取りする。
  • インターネット上およびローカルネットワーク上のデバイス: インターネット上の他のデバイスも取得元になる。

帯域幅は二つの方式で制限する。一つは絶対帯域幅(Mbps単位)、もう一つは測定された帯域幅に対する割合である。文書は「帯域幅の制限は、自動更新ダウンロードに対する配信の最適化にのみ適用されます」と書き、設定でWindowsを更新したりアプリをダウンロードしたりして手動でダウンロードを始めた場合は、設定した帯域幅の制限が適用されないと付け加えている。月間アップロード上限はこれとは別にアップロードのオプションで1GBから500GBの間で選ぶもので、上の文がこの上限の適用範囲まで述べているかは文書にない。

この節で判断が必要になるのはアップロードの側である。従量制回線やモバイルホットスポットにつながったPCでは、月間アップロード上限を下げるか、取得元をローカルネットワークに限定することで、意図しないデータ使用を減らす方向に設定を組める。ただし、どの組み合わせが実際に何MB減らすかは、文書に数値がないため言えない。

更新履歴と削除 — 元に戻す前に知っておくこと

インストール済みの更新は設定 > Windows Update > 更新履歴で見る。削除の経路は、Microsoftサポート文書にスタート > 設定 > Windows Update > その他のオプション > 更新履歴 > 更新プログラムのアンインストールの順で書かれている(更新プログラムのアンインストールは関連設定にある)。文書は、一覧から削除する更新を選んでアンインストールを選ぶよう案内し、一部の更新は削除できないと明記している。Windowsにアクセスできないときは、回復環境(Windows RE)でトラブルシューティング > 詳細オプションから削除する方法が別に紹介されている。

  1. まず時刻を照合する。更新履歴の一覧で、症状が始まった時点に近い項目があるかを探す。
  2. その項目が削除可能かを確認する。文書が一部の更新は削除できないと述べているので、一覧には削除できない項目がある可能性がある。
  3. セキュリティ更新であれば、削除のリスクを先に理解する。文書はセキュリティ更新を削除する前にリスクを理解するよう案内している。同じ文書は、Windows 11を使っている場合は先にWindowsのバージョンを再インストールしてみることも案内している。
  4. 削除した後は同じ更新が再び自動でインストールされることがあるので、一時停止の日付をどう使うかも併せて判断する。ただし文書は、削除した更新の再インストール時の動作を詳しくは書いていない。

性能の問題が疑われる場合は、タスクマネージャーでボトルネックを先に特定する手順が先であり、設定全般の点検リストはWindows 11最適化ガイドにある。更新の確認を定期タスクにまとめる方法はWindows自動化入門が扱う。更新画面の項目そのものの説明は上の節で完結している。

インストールが失敗したときに確認する順序

Microsoftサポートの更新トラブルシューティング文書は、基本的な解決方法を10個示している。順序は次のとおりである。

順序文書が示した点検補足
1自動トラブルシューティングツールの実行設定 > システム > トラブルシューティングから開く
2デバイスが正しく接続され、インターネットにつながっているかの確認電源とインターネットの接続を確認する。安定したインターネット接続が重要である
3管理者権限の確認一部の更新で必要になる
4外付けハードウェアの取り外し基本機能に不要な外付けストレージ・ドライブ・ドックなどをすべて外し、更新を再実行する
5更新キャッシュの初期化破損したファイルがエラーの原因になりうる
6日付と時刻の設定の確認自動同期をオンにする
7サードパーティ製ドライバーの更新メーカーのWebサイトで確認する
8ディスク容量の確保文書は32ビットで16GB、64ビットで20GB以上と書いている
9更新の再実行追加の更新が残っていることがある
10デバイスの再起動変更を適用する

文書はこの10個を「Windows更新の問題を解決するのに役立つ次の一般的なトラブルシューティング手順を試してください」という文の下に、1段階から番号順に示し、試す前に個人ファイルをバックアップするよう先に念を押している。どの段階の費用が低いか、どの段階が原因になることが多いかは、文書に書かれていない。文書はまた、エラーコード別の対応(たとえば0x8007000d、0x800705b4)、DISMやSFCといったシステムファイル修復ツール、新規インストールツールを詳細オプションとして紹介している。画面にエラーコードが出ている場合は、そのコードを文書の一覧でまず探す。

ディスク容量は、とくに機能更新で問題になる。FAQは、ディスク容量が不足する場合にファイルを整理するか外付けドライブを使うよう勧めている。空き容量が足りないPCでは、一時停止で時間を稼ぐよりも先に記憶域を確保しないと、同じ失敗が繰り返される。

恒久的な遮断を使わない理由 — 設定ではなく時点の問題として扱う

更新が不便なとき、グループポリシーやレジストリで完全に止める方法を探す人は多い。その方法はここでは扱わない。理由は三つある。

  • 文書が定める基本方針は「自動インストール」であり、停止は一時的なものとしてのみ認められている。
  • Learn文書は、Windowsレジストリを直接編集する方法を推奨しないと繰り返し書いている。
  • 問題が再起動ならアクティブ時間と再起動のスケジュールで、時点なら一時停止で大半は解決し、その範囲を超える要求は管理ツールの領域である。

管理対象デバイスでは管理者が定めたポリシーが優先され、設定画面の一部の項目がグレー表示になったり、組織が管理しているという文言が出たりすることがある。この場合は個人が変更するのではなく、管理者に依頼するのが適切である。また、Windows 10のサポートは2025年10月14日に終了したと文書が告知している。まだWindows 10を使っているデバイスは、更新設定に触れる前に、Windows 11へ移行するかどうかを先に決める必要がある。

確認できなかったこと

  • セキュリティ更新を無期限に先送りしないよう求める明示的な勧告の文。一時停止の文書には、期限切れ後の自動再開がデバイスを安全で安定した状態に保つのに役立つという説明しかなく、別個の勧告文は見つからなかった。
  • 一時停止の上限に達した後、再び一時停止する前にインストールが必要な「最新の更新」が正確には何か、そしてIT管理者向けポリシー文書にある35日経過後の再一時停止の文が設定画面にも同じように当てはまるか。
  • 個人PCのアクティブ時間画面で最大の長さが18時間として表れるか(18時間はLearnのIT管理者向け文書の数値)。該当のLearn文書は機械翻訳版である。
  • Windows 11の設定画面で自動再起動が通知に切り替わる期間が、文書の既定の7日と同じかどうか(この期間を変更するポリシーはWindows 11には適用されないレガシーだと示されている)。
  • オプションの更新が個人PCの設定画面のどの項目にどう表示されるか、インストールの順序。
  • 配信の最適化のオプション別の実際のデータ削減量。文書に数値がない。
  • このPCで画面を直接開いて照合することはできなかった。場所と名称はすべて文書の文言に基づき、ビルドによって異なる可能性がある。Windows 10の画面の違い、Insiderチャンネル、グループポリシー・MDMの構成は範囲から除外した。
