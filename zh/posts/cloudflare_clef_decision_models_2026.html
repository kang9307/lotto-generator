决策模型的演进背景 — 从开放文本生成转向结构化概率判断

随着生成式人工智能深入企业生产主链路，传统的自回归（autoregressive）大语言模型在关键系统热路径（hot path）上暴露出显著的架构缺陷。在线工单分类、智能体工具路由（tool calling）、实时网络攻击阻断与行为分支决策等场景，本质上并不需要大段连贯的自然语言文本。工业级系统真正需要的，是具有明确类型约束的离散判定结果（如布尔状态、工单类别、风险分级）以及对应的置信度概率。

通用LLM在处理这类任务时存在严重的计算资源错配。即便是输出一个简短的分类标签，模型也必须启动完整的生成解码管线，每一个输出Token都会累加数十毫秒的自回归延迟。此外，即便是采用结构化输出语法约束（JSON Mode），模型依然面临幻觉、格式损坏以及长尾延迟抖动的风险。在这一背景下，完全剔除Token生成过程、直接接收输入状态并输出离散概率分布的「决策模型（Decision Model）」作为独立技术分支快速崛起。

关于这一技术路线的演进脉络，本站曾在Jev实测评估与类型安全分类解析、探索多模态适配的Jev风格视觉LLM包装层实验，以及在决策前引入推理的PostHog Jeeves决策模型剖析中进行了持续追踪。2026年10月1日，Cloudflare正式推出了全面对标该领域的开源决策模型Clef与Clef-flash。

  • 核心负载失配矛盾： 强行将文本生成模型置于高吞吐实时热路径，造成巨大的延迟与算力开销。
  • 非自回归推理范式： 彻底弃用逐Token自回归解码循环，在单次前向计算中并行计算所有候选选项得分。
  • 概率数值原生输出： 直接输出0.0至1.0之间的浮点概率，为自动化系统提供可量化的决策边界。
  • 边缘运行环境整合： 深度融入Cloudflare cf CLI智能体设计所构建的边缘自动化体系。
  • 全开源权重策略： 采用宽松的Apache-2.0许可证在Hugging Face发布模型权重，同步提供Workers AI托管。

Clef与Clef-flash模型规格及非自回归并行评估机制

Cloudflare本次推出的Clef系列包含两款面向不同应用场景的子模型。旗舰模型Clef基于Qwen3.8-27B构建，专为高精度多标签分类与复杂多工具选择场景设计；轻量模型Clef-flash则基于Qwen3.5-9B构建，专注于边缘端极低延迟的路由与实时自动化。两款模型均保持底层Transformer骨干网络权重冻结，仅对其专有的路由分类头与低秩自适应（LoRA）适配层进行专项训练。

Clef的核心竞争力源于其非自回归（non-autoregressive）并行评估结构。在完成单次输入上下文预填充（prefill）后，模型直接在内部隐藏状态（hidden states）空间内，通过两阶段注意力机制对所有预设选项进行并行评估。第一阶段，各个选项独立读取输入上下文中的关联线索；第二阶段，模型综合不同提问之间的相互依赖关系与整体状态，计算出最终的归一化置信度得分。

{
                      "messages": [
                        { "role": "user", "content": "Payment failed for all customers over the past hour. DB connection pool exhausted." }
                      ],
                      "questions": [
                        { "id": "urgency", "type": "choice", "options": ["low", "medium", "critical"] },
                        { "id": "assignee", "type": "choice", "options": ["billing_team", "infra_team", "support"] },
                        { "id": "customer_impact", "type": "boolean" }
                      ]
                    }

从上述调用格式可以看出，开发者可以在单次请求中针对一段背景信息捆绑多个不同维度的决策问题（单选、布尔、评分）。Clef并不是依次生成各个问题的回答，而是一次性并发返回所有选项的条件概率分布。这种非自回归特性确保了系统整体延迟不会随着决策字段的增多而发生线性膨胀。

  • Clef（27B模型）： 基于Qwen3.8-27B，适用于复杂业务逻辑判定与深度企业级工具调用匹配。
  • Clef-flash（9B模型）： 基于Qwen3.5-9B，专为边缘网络环境下的50毫秒以内极速响应而优化。
  • 两阶段注意力架构： 严格解耦选择项与上下文的线索匹配，以及跨问题字段的全局一致性求解。
  • 冻结骨干网络方案： 在保留基础大模型通用常识的前提下，实现分类头的高效轻量训练。
  • 并发决策吞吐优势： 单一上下文即便挂载数十个评估字段，依然能在固定前向耗时内一次性完成判定。

Cloudflare官方自测基准与响应延迟指标的客观解读

在发布公告中，Cloudflare披露了在其自营边缘GPU集群上运行学术与工业基准测试的结果。在评估工具调用准确度的BFCL基准上，Clef达到98.47%，Clef-flash达到98.76%，高于作为对比基准的Jev（95.75%）。在API-Bank基准测试中，Clef与Clef-flash分别取得91.93%与93.11%的准确率，同样高于Jev的88.19%。

然而，Clef并非在所有任务上均处于领先地位。在评估模型是否能准确克制、不发生多余工具调用的When2Call基准测试中，Jev以80.97%显著高于Clef的72.37%以及Clef-flash的65.58%。Cloudflare在报告中客观承认，在When2Call和BRIGHT测试集上Jev保持了领先优势。这表明在积极调用工具与保守抑制调用之间，不同模型由于训练目标差异存在显著的策略偏向。

在延迟指标方面，Cloudflare汇总了涵盖43项评测的整体响应耗时。Clef-flash的中位数延迟低至38.8毫秒，相比对比组Jev的524.1毫秒展现出显著的速度优势。在反映长尾波动的p95指标上，Clef-flash录得122.4毫秒，呈现出极窄的延迟离散度。技术团队在采纳上述指标时需明确，这些数据完全基于Cloudflare官方在特定边缘硬件上的自测汇总，目前尚未经由第三方独立基准机构复现。

  • 厂商自测数据属性： 文中所涉及的准确率与延迟数据均属于Cloudflare公布的官方实验结果。
  • 38.8毫秒中位数响应： 展现了9B轻量模型与非自回归技术在专用边缘加速环境中的推理速度。
  • 不同维度的精度权衡： Clef在功能执行匹配上表现出色，但在判断何时不调用的审慎度上仍不及Jev。
  • 全链路系统端到端耗时： 在包含Browser Run页面抓取渲染的实际网站安全分类测试中，端到端耗时为2.2秒。
  • 超小型Laya基准参考： 官方报告提到了微型模型Laya达到5.8毫秒中位数，但强调Clef-flash在p95稳定性上更优。

多模态64K上下文与Jev API完全兼容特性

Clef在工程架构上的另一大亮点，是其对多模态输入的原生支持以及高达64K Token的上下文缓冲区。此前的早期决策模型（如Jev）大多仅限于纯文本输入与32K上下文，而Clef能够直接接收高分辨率截图与长篇日志。这使得决策模型可以直接应用于网页欺诈识别、工单附件发票OCR分类以及UI自动化代理等复杂视觉感知场景。

为了降低开发者的迁移门槛，Cloudflare在API协议设计上实现了对Jev API的全面兼容。现存基于TypeSafe Jev SDK构建的应用系统，无需对请求负载的数据结构进行任何修改，仅需将调用端点重定向至Workers AI即可平滑接入。模型返回的负载保持统一的结构化JSON规范，包含了各个字段的判定结果与其对应的概率值。

{
                      "decisions": {
                        "urgency": {
                          "selected": "critical",
                          "probabilities": { "low": 0.012, "medium": 0.045, "critical": 0.943 }
                        },
                        "assignee": {
                          "selected": "infra_team",
                          "probabilities": { "billing_team": 0.021, "infra_team": 0.965, "support": 0.014 }
                        },
                        "customer_impact": {
                          "selected": true,
                          "probability": 0.988
                        }
                      }
                    }

这种确定性的JSON输出结构彻底消除了下游系统维护正则表达式或JSON修复解析器的负担。开发团队可以基于精确的概率值设定自动化门禁阈值，例如在critical置信度大于0.90时直接触发告警，而在置信度处于临界区间时自动回退至人工介入审核。

  • 64K大容量上下文： 支持直接喂入庞大的OpenAPI描述文件、多轮交互状态及详尽的业务规则规范。
  • 原生图像多模态输入： 无需外部LLM预处理即可直接针对网页截屏与监控图表展开结构化判定。
  • Jev协议无缝平替： 对既有采用Jev通信协议的客户端提供即插即用的无缝兼容体验。
  • 确定性格式输出保障： 在物理层面彻底避免了文本生成大模型常见的输出截断与JSON格式错乱。
  • 严格的企业隐私承诺： 承诺除参与微调合作的客户外，绝不记录、保存或将调用数据用于后续训练。

RLCD校准算法、专职微调服务及平台演进路线

在严谨的系统自动化工程中，决策模型输出概率的统计校准（calibration）与分类准确率同等重要。若模型声称某项结论具备80%的发生概率，在现实场景的100次采样中该结论就必须严格对应80次真实命中。通用大语言模型普遍存在严重过度自信（overconfident）的问题，往往以99%的极高置信度输出错误结论。为确保输出概率真实反映现实世界的置信边界，Cloudflare引入了RLCD（Reinforcement Learning for Calibrated Decisions）强化学习算法。

RLCD算法在奖励设计中引入了针对有序选项（如低/中/高）的距离惩罚，对接近正确答案的候选给予部分奖励，并对多字段联合命中的完整性施加高额激励。这种优化使得模型输出的对数几率（logits）严格收敛于统计层面的真实概率，使工程师能够直接将概率值作为自动化执行策略中的可靠判定准绳。

在商业落地方面，Cloudflare目前通过专职的现场工程团队（Forward Deployed Engineering, FDE）为企业设计合作伙伴提供定制化微调服务。与此同时，官方公布了未来的全自动微调平台演进图景，计划将AI Gateway（数据捕获）、Workers AI（推理日志）、Containers（智能体沙箱评测）与新增的Trainer整合为闭环链路。但公告同时明确强调，该自动化平台目前仍在开发当中，企业现阶段可即刻使用的是预训练模型本身与FDE定制支持。

  • RLCD概率校准算法： 采用专门的强化学习目标使模型输出的概率与真实世界的经验正答率严格对齐。
  • 序数距离感知奖励： 在训练阶段考量分类误差的语义距离，并重点奖励多字段联合准确预测。
  • 模型现状与平台规划明确区分： 预训练模型已全面就绪，但全托管的自动化微调平台仍在研发推进中。
  • FDE专属工程定制： 目前针对黑产拦截、安全合规与复杂客服分类提供专业工程师驻场式微调支持。
  • 全栈边缘基座整合蓝图： 展望涵盖网关监控、安全容器隔离与自适应热重训的一体化演进路径。

决策模型技术版图 — 对比Jev、Luna与Jeeves的异同

Clef的发布标志着决策模型正在演进为现代AI基础架构中的核心支柱。该赛道的行业标杆最初由TypeSafe的Jev System One确立，其通过专有的指针头分类器证明了专用决策模型在运行效率上可对通用大模型形成代际碾压，详见本站此前针对Jev实测评估的深度分析。

随后这一技术路线分化为两大流派。一支是以OpenAI Luna Decision API技术分析为代表的闭源云端托管方案，力求以极简的外部API形态统揽业务分发；另一支则是以开源权重为主导的探索，例如PostHog开源的Jeeves决策模型，通过在决策前插入轻量思考Token（reasoning）的方式突破复杂推理瓶颈。

在此格局下，Cloudflare Clef的战略定位是结合「全球边缘基础设施」与「多模态64K长窗口」的开源高性能决策枢纽。与Jeeves为了追求逻辑推理深度而牺牲延迟（通常消耗数秒推理时间）不同，Clef坚定坚守非自回归架构以锁定几十毫秒的极限吞吐。而面对Jev的商业化托管壁垒，Clef凭借Apache-2.0全开放权重以及Workers AI极具竞争力的定价策略（Clef每百万Token 0.24美元，flash仅0.09美元）展开差异化竞争。

  • 针对Jev的演进： 完整继承Jev的接口规范，同时将上下文翻倍至64K并原生接入多模态图像感知能力。
  • 与OpenAI Decision API对比： 摆脱完全黑盒的SaaS服务绑定，赋予企业将模型全量私有化离线部署的自主权。
  • 与PostHog Jeeves的分野： Jeeves侧重于依赖思考Token攻克复杂因果逻辑，Clef则专精于毫秒级极速热路径。
  • 边缘运行环境协同： 与Cloudflare Python Workers GA等既有边缘服务形成紧密的一体化协同链路。
  • 工程分工基本准则： 涉及开放式因果逻辑推荐Jeeves或前沿LLM，高频并发的分支调度则交由Clef系模型接管。
