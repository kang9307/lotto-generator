Ceph Storage 概览与详细指南

Comprehensive Guide to Ceph Storage

2025-06-02 开发/基础设施

Ceph 是一款开源的分布式存储系统,能够在同一统一平台上同时提供对象存储、块存储与文件存储。当大规模数据中心和云环境需要具备高可扩展性、可靠性与高性能的存储方案时,Ceph 无疑是一个出色选择。

English: Ceph is an open-source distributed storage system that provides object, block, and file storage capabilities within a single unified platform. It's an excellent choice for large-scale data centers and cloud environments requiring a storage solution with high scalability, reliability, and performance.

Ceph 存储的核心概念

Ceph 的架构建立在多项核心概念之上,正是这些概念支撑起其强大的性能与稳定性。

RADOS (Reliable Autonomic Distributed Object Store)

RADOS 是 Ceph 最底层的对象存储系统,所有数据都以对象的形式存储,并被分散到整个集群中。

+-------------------+
|     Applications  |
+-------------------+
          |
+-------------------+
|  LIBRADOS (API)   |
+-------------------+
          |
+-------------------+
|   RADOS Cluster   |
| (OSD + Monitor)   |
+-------------------+

主要特性:

  • 自动化的数据分布与复制
  • 节点故障时可自愈,实现自动恢复
  • 集群状态监控与管理

CRUSH 算法

CRUSH(Controlled Replication Under Scalable Hashing)是决定 Ceph 如何分布式存放数据的关键算法。

# 查看 CRUSH Map 的命令
ceph osd crush dump

CRUSH 算法的优势:

  • 无需中心化查找表即可计算数据位置
  • 集群结构变动时数据移动最小化
  • 可定义存储层级与故障域

OSD (Object Storage Daemon)

OSD 是真正负责存储与管理数据的守护进程,通常每块物理磁盘对应一个 OSD。

# 查看 OSD 状态
ceph osd status
ceph osd tree

OSD 的职责:

  • 数据的存储与读取
  • 数据复制与恢复协调
  • 与其他 OSD 间的心跳交换,监控集群状态

Monitor

Monitor 节点负责维护集群的状态地图,并向客户端提供集群信息。

# 查看 Monitor 状态
ceph mon stat

Monitor 的作用:

  • 管理各类集群 Map(Monitor Map、OSD Map、PG Map 等)
  • 负责客户端认证与权限管理
  • 基于仲裁(Quorum)的分布式决策

Placement Group (PG)

PG 是管理对象集合的逻辑单元,是 Ceph 实现可扩展性的关键。

# 查看 PG 状态
ceph pg stat

PG 的重要性:

  • 高效管理数百万级对象
  • 协调 OSD 间的数据复制与分布
  • 支持恢复作业的并行化

Ceph 的主要存储接口

Ceph 提供三大存储接口,可覆盖多样化的使用场景。

1. RADOS Gateway (RGW) — 对象存储

RGW 是兼容 Amazon S3 与 OpenStack Swift 的 RESTful 对象存储接口。

适用场景:

  • 云原生应用
  • 静态网页内容托管
  • 备份与归档方案
  • 大规模数据仓库
# 启动 RGW 服务
systemctl start ceph-radosgw@rgw.`hostname -s`

2. RADOS Block Device (RBD) — 块存储

RBD 是 Ceph 的块存储接口,为虚拟机和容器提供块设备。

适用场景:

  • 虚拟机磁盘(OpenStack、VMware)
  • 数据库存储
  • 容器持久卷(Kubernetes)
# 创建 RBD 镜像示例
rbd create --size 10G --pool rbd my_disk

特点:

  • 精简配置(Thin Provisioning)
  • 支持快照与克隆
  • 自动数据分布与复制

3. CephFS — 文件存储

CephFS 提供 POSIX 兼容的文件系统接口。

适用场景:

  • 共享文件系统
  • 数据分析工作负载
  • 大规模主目录
# CephFS 挂载示例
mount -t ceph mon1:6789:/ /mnt/cephfs -o name=admin,secret=[YOUR_CEPH_SECRET_KEY]

特点:

  • 通过元数据服务器(MDS)实现高性能文件操作
  • 支持动态目录切分,增强可扩展性
  • 支持 POSIX ACL

Ceph 的安装与配置概览

部署和配置 Ceph 集群的基本步骤如下:

1. 前置条件

# 在所有节点安装必需的软件包
apt-get update
apt-get install -y ceph-common python3 ntp

硬件需求:

  • 至少 3 个 OSD 节点(生产环境)
  • 至少 3 个 Monitor 节点(高可用集群)
  • 各节点之间的稳定网络连接

2. 使用 Cephadm 安装(当前推荐方式)

# Cephadm 引导
curl --silent --remote-name --location https://github.com/ceph/ceph/raw/octopus/src/cephadm/cephadm
chmod +x cephadm
./cephadm bootstrap --mon-ip <mon-ip>

3. 存储池配置

# 创建默认的副本型存储池
ceph osd pool create mypool 128 128
ceph osd pool set mypool size 3

# 创建纠删码(Erasure Coding)存储池
ceph osd pool create ecpool 128 erasure
ceph osd pool set ecpool allow_ec_overwrites true

4. 客户端配置

# 分发客户端配置文件
ceph config generate-minimal-conf > /etc/ceph/ceph.conf
ceph auth get client.admin > /etc/ceph/ceph.client.admin.keyring

Ceph 的性能优化

为了充分释放 Ceph 集群的性能,可关注以下要点:

网络优化

# 网络调优参数
net.core.rmem_max = 56623104
net.core.wmem_max = 56623104
net.core.rmem_default = 56623104
net.core.wmem_default = 56623104
net.core.optmem_max = 40960

网络建议:

  • 将公共网络与集群网络分离
  • 至少使用 10GbE 网卡
  • 启用巨型帧(Jumbo Frame)

OSD 优化

# OSD 调优参数
osd_memory_target = 4294967296  # 4GB
bluestore_cache_size_ssd = 3221225472  # SSD 使用 3GB

OSD 建议:

  • 使用高性能磁盘(SSD 或 NVMe)
  • 配置专用日志设备
  • 元数据与数据分离存放

监控与故障排查

# 集群状态监控
ceph health detail
ceph -s

# 查看性能计数器
ceph daemon osd.0 perf dump

重点监控指标:

  • IOPS 与吞吐量
  • 延迟
  • 恢复作业状态
  • 集群使用率

Ceph 与其他存储方案的对比

Ceph vs GlusterFS

功能 Ceph GlusterFS
架构 基于对象 基于文件
存储类型 对象、块、文件 主要为文件
可扩展性 EB(Exabyte)级 PB(Petabyte)级
复杂度 相对较高 相对较低
适用场景 大规模云平台 文件共享 / NAS

Ceph vs Swift

功能 Ceph Swift
适用范围 统一存储 仅对象存储
一致性 强一致性 最终一致性
块存储 原生支持 不支持
文件系统 支持 CephFS 不支持

Ceph vs HDFS

功能 Ceph HDFS
主要用途 通用存储 大数据分析
数据模型 基于对象 基于块
访问模式 多样化工作负载 针对顺序访问优化
API S3/Swift/POSIX HDFS API

Ceph 的未来展望

Ceph 仍在持续演进,并在以下关键领域不断突破:

性能改进

  • BlueStore 存储引擎的持续优化
  • 针对 NVMe 与持久内存的优化
  • 网络协议的优化

云原生集成

  • 与 Kubernetes 的深度整合
  • 容器化部署的简化
  • 更好地支持微服务架构

管理简化

  • 引入新的 Cephadm 与 Rook 管理工具
  • 实现自动化的集群管理
  • 采用声明式配置方式

结论

Ceph 是一款兼具可扩展性、可靠性与灵活性的强大分布式存储方案。在同一系统中同时提供对象、块与文件存储的能力,为现代数据中心和云环境带来了明显优势。

无需停机即可完成集群扩容、节点新增或替换等操作,再加上硬件故障下仍可自动恢复的自愈机制,使 Ceph 跻身企业级存储系统之列。

凭借开源属性与活跃的社区支持,Ceph 将持续进行创新与进化,并在云原生环境和现代化数据中心中占据核心地位。
