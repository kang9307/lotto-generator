引言 - 排序之后10排在9前面

在JavaScript中，对数字数组不带比较函数调用sort()时，数字不是按数值大小而是按另一种标准排列。[1, 10, 9, 2]变成[1, 10, 2, 9]是最广为人知的形态。这种行为不是缺陷而是定义，了解定义之后，比较函数该怎么写、各类值会排到哪里、写错的比较函数会产生什么结果，就能一线贯通。

本文的主线是sort的默认比较器与比较函数的写法。韩文与区域设置改变排序顺序的问题，由韩文排序为何与预期不同按工具详细讨论，数组方法总览以及sort数字陷阱的一行说明在JavaScript基础语法中。这里则通过输出逐一验证比较函数接收的值、应返回的值以及会使其失效的输入。

涉及的问题如下。

  • 默认比较器按什么标准比较数字？
  • 字符串比较所依据的UTF-16码元顺序与码点顺序有何不同？
  • undefined、空槽、null与NaN会排到哪里，比较函数是否会接收到它们？
  • 比较函数应返回什么，布尔值或不一致的比较函数会产生什么结果？
  • 稳定排序是否由规范保证，哪种比较函数会破坏它？
  • toSorted、localeCompare与Intl.Collator在哪些场合可以替代sort加手写比较函数？

默认比较器是字符串比较

MDN的Array.prototype.sort文档对默认排序给出如下定义：默认排序顺序为升序，基于把元素转成字符串、再比较其UTF-16码元值序列。另一句话说明，若未提供compareFn，所有非undefined的数组元素都会被转成字符串，并按UTF-16码元顺序比较。下面的代码并列输出该定义在[1, 10, 9, 2]上的表现，以及把同一数组转成字符串、提供比较函数之后的结果。

console.log('node ' + process.version);
                    const a = [1, 10, 9, 2];
                    console.log(a.sort());
                    console.log([1, 10, 9, 2].map(String));
                    console.log(['1', '10', '9', '2'].sort());
                    console.log('10' < '9', 10 < 9);
                    console.log([1, 10, 9, 2].sort((x, y) => x - y));
node v22.16.0
                    [ 1, 10, 2, 9 ]
                    [ '1', '10', '9', '2' ]
                    [ '1', '10', '2', '9' ]
                    true false
                    [ 1, 2, 9, 10 ]

第一次排序的结果是[1, 10, 2, 9]。把同一数组转成字符串后是'1'、'10'、'9'、'2'，对字符串数组排序得到'1'、'10'、'2'、'9'，顺序与数字数组的结果相同。字符串'10'的首字符'1'(0x31)小于'9'(0x39)，所以排在'9'之前。倒数第二行的比较直接说明了这一点：字符串比较'10' < '9'为true，数值比较10 < 9为false。传入比较函数(x, y) => x - y后结果是[1, 2, 9, 10]。

  • 默认排序的对象不是值本身，而是值的字符串表示。数字10与9不会被比较，被比较的是'10'与'9'。
  • 如果数组只含一位数，字符串顺序与数值顺序碰巧一致，测试会通过；一旦混入两位数，两者就会产生偏差。
  • 比较函数(x, y) => x - y直接把两个值相减，用符号表示顺序。它并没有改变定义，而是把比较的依据从字符串换成了数字。

字符串比较按UTF-16码元顺序

按定义，比较字符串就是以码元为单位的比较。大多数字符只占一个码元，但超过U+FFFF的字符(表情符号等)是由两个码元组成的代理对。这一差异会造成默认排序与码点顺序结果不同的情形。下面的代码把表情符号U+1F600和全角字符U+FF21与普通字母混在一起，比较默认排序与基于码点的比较函数的结果。

const words = ['\u{1F600}', 'Ａ', 'z', 'Z', 'a'];
                    const hex = w => 'U+' + w.codePointAt(0).toString(16).toUpperCase();
                    console.log('default      :', [...words].sort().map(hex).join(' '));
                    console.log('code point   :', [...words].sort((x, y) => x.codePointAt(0) - y.codePointAt(0)).map(hex).join(' '));
                    console.log('first unit of U+1F600 = 0x' + words[0].charCodeAt(0).toString(16).toUpperCase() + ', of U+FF21 = 0x' + words[1].charCodeAt(0).toString(16).toUpperCase());
default      : U+5A U+61 U+7A U+1F600 U+FF21
                    code point   : U+5A U+61 U+7A U+FF21 U+1F600
                    first unit of U+1F600 = 0xD83D, of U+FF21 = 0xFF21

默认排序的顺序是Z、a、z、U+1F600、U+FF21，码点顺序则是Z、a、z、U+FF21、U+1F600。表情符号的第一个码元是0xD83D，全角A的码元是0xFF21，所以按码元顺序表情符号在前；按码点则0xFF21小于0x1F600，顺序相反。大写Z(0x5A)排在小写a(0x61)之前，也出自同一标准。只处理普通字母数字时看不出这一差异，因此当表情符号或增补平面字符出现时，排序顺序就可能与直觉不符。

undefined、空槽、null与NaN会去哪里

MDN写明所有undefined元素都会排到数组末尾，并就空槽说明：sort()会保留空槽，若源数组是稀疏数组，空槽会被移到数组末尾，且始终排在所有undefined之后。这两句话与比较函数如何衔接，记录比较函数收到的参数后便能看到。

const calls = [];

                    console.log('comparator calls:', calls.join(' | '));
                    console.log('any call saw undefined:', calls.some(c => c.includes('undefined')));
                    console.log([3, undefined, 'a', null, NaN, 1].sort());
                    console.log([3, undefined, 'a', null, NaN, 1].map(String));
                    console.log([3, undefined, 1].sort((x, y) => y - x));

  • 第一行是[1, 2, 3, undefined, 空槽]。长度仍为5，索引4仍是空槽，与MDN所述一致：undefined在前，空槽在最后。
  • 比较函数记录到的调用只有数字对，没有任何一次调用把undefined作为参数。比较函数不会收到undefined与空槽。
  • 使用降序比较函数(x, y) => y - x时，undefined同样留在末尾。无法通过比较函数的符号改变undefined的位置。
  • [z, undefined, a]的默认排序结果是a, z, undefined。String(undefined)是字符串undefined，它比z小，却被放在了最后，可见undefined并不是按字符串比较，而是依另一条规则排到末尾。
  • null与NaN不同于undefined，它们被转成字符串null和NaN，并在其他字符串之间确定顺序。默认排序结果中NaN在3之后、a之前，null在a之后。

比较函数是返回负数、0或正数的函数

MDN写明比较函数应返回数字：负数表示a应排在b之前，正数表示a应排在b之后，0或NaN表示二者视为相等。更形式化地，比较函数应当是纯函数，对同一对输入返回相同结果，具有自反性(compareFn(a, a) === 0)，具有反对称性(compareFn(a, b)与compareFn(b, a)要么都是0，要么符号相反)，并具有传递性。下面的代码把正确的比较函数、返回布尔值的比较函数和返回常量的比较函数应用于同一数组，并在一千个伪随机数的数组上统计是否完成了排序。

const nums = [10, 9, 1, 100, 2];
                    console.log('a - b       ', nums.slice().sort((x, y) => x - y));
                    console.log('b - a       ', nums.slice().sort((x, y) => y - x));
                    console.log('a > b       ', nums.slice().sort((x, y) => x > y));
                    console.log('a < b       ', nums.slice().sort((x, y) => x < y));
                    console.log('() => 1     ', nums.slice().sort(() => 1));
                    console.log('() => -1    ', nums.slice().sort(() => -1));
                    console.log('() => 0     ', nums.slice().sort(() => 0));
                    console.log('default     ', nums.slice().sort());

返回布尔值的a > b在五个输入上没有改变任何东西，在一千个输入上仍残留多达496处下降。在这个环境中Number(true)为1，Number(false)为0。返回布尔值的比较函数所返回的值是0或1。这个比较函数对同一对输入，(a, b)返回1而(b, a)返回0，违反了MDN所述的反对称性。MDN建议遵守五项约束来构造良好的比较函数，因为不同实现的行为可能不同。这个Node.js的布尔结果只是该引擎的数值，不断言其他引擎相同。

a - b失效的输入 - 缺失键、字符串与BigInt

比较函数a - b只有在数字之间才能给出正确的符号。当值缺失或不是数字时，减法的结果为NaN，MDN写明比较函数返回的NaN与0一样表示相等。MDN还规定比较函数必须给出一致的比较结果。下面的代码展示了a - b对缺失键的对象、字符串与BigInt的结果。

const rows = [{ p: 4 }, {}, { p: 3 }, { p: 2 }, { p: 1 }];

                    console.log(['b', 'c', 'a'].sort((x, y) => x - y));
                    console.log(['b', 'c', 'a'].sort((x, y) => (x < y ? -1 : x > y ? 1 : 0)));

                      console.log([3n, 1n, 2n].sort((x, y) => x - y));

  • undefined - 1的结果是NaN，第二行的NaN true就是证据，MDN写明比较函数的返回值NaN表示相等。
  • 对字符串[b, c, a]使用a - b，顺序仍为[b, c, a]，因为b - c同样是NaN。字符串需要使用a < b ? -1 : a > b ? 1 : 0。
  • 对于BigInt，a - b返回BigInt，sort无法把它转成数字，于是抛出TypeError(Cannot convert a BigInt value to a number)。只有这种情况不会悄悄出错，而是立即暴露。

稳定排序与相等元素的处理

MDN写明，自版本10(ECMAScript 2019)起，规范规定Array.prototype.sort是稳定排序。稳定排序指比较函数判为相等的元素保持输入顺序。下面的代码针对键为0至4的1000个对象，按不同比较函数检查是否完成排序以及相等元素的输入顺序是否保留。最后一行是两遍排序：先按次要键排序，再按主要键排序。

const make = () => Array.from({ length: 1000 }, (_, i) => ({ k: (i * 7919) % 5, i }));
                    const isStable = arr => arr.every((v, j) => j === 0 || arr[j - 1].k !== v.k || arr[j - 1].i < v.i);
                    const sorted = arr => arr.every((v, j) => j === 0 || arr[j - 1].k <= v.k);
                    const good = make().sort((x, y) => x.k - y.k);
                    console.log('k-only comparator : sorted', sorted(good), '| ties keep input order', isStable(good));
                    const tie1 = make().sort((x, y) => (x.k < y.k ? -1 : 1));
                    console.log('tie returns 1     : sorted', sorted(tie1), '| ties keep input order', isStable(tie1));
                    const tie2 = make().sort((x, y) => (x.k > y.k ? 1 : -1));
                    console.log('tie returns -1    : sorted', sorted(tie2), '| ties keep input order', isStable(tie2));
                    const two = make().sort((x, y) => x.i - y.i).sort((x, y) => x.k - y.k);
                    console.log('two passes        : sorted', sorted(two), '| ties keep input order', isStable(two));
k-only comparator : sorted true | ties keep input order true
                    tie returns 1     : sorted true | ties keep input order true
                    tie returns -1    : sorted true | ties keep input order false
                    two passes        : sorted true | ties keep input order true
  • 在相等时返回0的正常比较函数(x.k - y.k)完成了排序，相等元素的输入顺序也得以保留。这是在1000个元素的输入上得到的结果。
  • 在相等时返回-1的比较函数在这个输入上完成了排序，但相等元素的输入顺序没有保留（输出中的false）。对同一对元素，两个方向都返回-1，不满足MDN列出的反对称条件。结果是否由这一违反造成，无法由这个实验判定。下一项中相等时返回1的比较函数同样不满足自反条件，顺序却保留了。
  • 在相等时返回1的比较函数，在这个Node.js中相等元素的顺序得以保留。同样违反自反性，结果却不同。这一差异是否来自引擎传递参数的方式，无法由这份输出判定，也不作为保证来理解。
  • 最后一行的两次排序只显示：在这个输入上结果已排序且相等元素的顺序保留（两个值均为true）。输入本来就是i的顺序，第一次排序没有改变任何东西，因此这一行不作为稳定性的证据。确认稳定性的实验是前面的1000个元素的实验。

sort修改原数组，toSorted返回副本

MDN写明sort()会就地排序并返回同一数组的引用，并指出若要在不改变原数组的情况下排序应使用toSorted()。下面的代码在这个Node.js上用输出验证这两个方法返回值之间的关系。

const a = [3, 1, 2];
                    const b = a.sort();
                    console.log('sort():     same array', b === a, a);
                    const c = [3, 1, 2];
                    const d = c.toSorted();
                    console.log('toSorted(): same array', d === c, 'original', c, 'result', d);
                    console.log(typeof Array.prototype.toSorted);
sort():     same array true [ 1, 2, 3 ]
                    toSorted(): same array false original [ 3, 1, 2 ] result [ 1, 2, 3 ]
                    function

sort()的返回值与原数组是同一个数组(true)，原数组变成了[1, 2, 3]。toSorted()的返回值是另一个数组(false)，原数组仍为[3, 1, 2]，结果是[1, 2, 3]。最后一行确认在这个Node.js中Array.prototype.toSorted是函数。当排序结果要写入共享状态(状态管理库中的不可变数组、已经渲染到界面的数组)时，返回副本的方法能防止意外修改。两个方法对比较函数的规则相同。

数字与字符串混合时

真实数据中有时会混入数字与形似数字的字符串。默认排序把一切都当作字符串比较，而a - b对无法转成数字的值得到NaN。这里建立了先按类型排名比较的比较函数，并把结果并排列出。最后一行是对只含形似数字的字符串的数组使用a - b的结果。

const m = [10, '9', 1, 'a', 2, 'B'];
                    console.log('default      ', m.slice().sort());
                    console.log('a - b        ', m.slice().sort((x, y) => x - y));
                    const rank = v => (typeof v === 'number' ? 0 : 1);
                    const mixedCmp = (x, y) => rank(x) !== rank(y) ? rank(x) - rank(y)
                      : (x < y ? -1 : x > y ? 1 : 0);
                    console.log('typed cmp    ', m.slice().sort(mixedCmp));
                    console.log('numeric strs ', ['10', '9', '1'].sort((x, y) => x - y));
default       [ 1, 10, 2, '9', 'B', 'a' ]
                    a - b         [ 1, 2, '9', 10, 'a', 'B' ]
                    typed cmp     [ 1, 2, 10, '9', 'B', 'a' ]
                    numeric strs  [ '1', '9', '10' ]
  • 默认排序为1、10、2、9、B、a，延续了数字10排在数字2之前、紧跟在数字1之后的字符串顺序。
  • a - b会让数字之间排好序，但字符串'9'夹在数字之间(2与10之间)，而'a'和'B'按输入顺序留在末尾。混入无法转成数字的值时，结果只是部分有序。
  • 按类型排名的比较函数得到1、2、10、9、B、a：数字先按数值顺序排列，字符串随后按码元顺序排列，这是把混合输入的规则写进比较函数的结果。
  • 如果只有形似数字的字符串，a - b会把字符串转成数字再相减，因此排成'1'、'9'、'10'。这种情况下排序正确，但元素仍是字符串。

韩文与区域排序用比较函数解决

在字符串排序中，当码元顺序与人们期望的顺序不同时，比较函数使用localeCompare或Intl.Collator的compare。同一个字符串列表依次用默认排序、localeCompare、Intl.Collator与数字选项排序。各工具排序规则的详细比较由韩文排序一文讨论。

const names = ['나', '다', '가', 'Z', 'a', 'B', 'ㄱ'];
                    console.log('default       ', [...names].sort().join(' '));
                    console.log('localeCompare ', [...names].sort((x, y) => x.localeCompare(y, 'ko')).join(' '));
                    const col = new Intl.Collator('ko');
                    console.log('Intl.Collator ', [...names].sort(col.compare).join(' '));
                    const files = ['파일10', '파일2', '파일1'];
                    console.log('default       ', [...files].sort().join(' '));
                    console.log('numeric true  ', [...files].sort(new Intl.Collator('ko', { numeric: true }).compare).join(' '));
default        B Z a ㄱ 가 나 다
                    localeCompare  ㄱ 가 나 다 a B Z
                    Intl.Collator  ㄱ 가 나 다 a B Z
                    default        파일1 파일10 파일2
                    numeric true   파일1 파일2 파일10

默认排序遵循码元顺序：大写B、Z，小写a，韩文兼容字母ㄱ，然后是预组合音节가、나、다。localeCompare('ko')与Intl.Collator('ko')在这个Node.js中给出相同的结果(ㄱ、가、나、다、a、B、Z)。在这个顺序里韩文排在拉丁字母之前，是由这个环境的ICU数据决定的数值。在第二个列表中，默认排序得到파일1、파일10、파일2，启用Collator的numeric选项后得到파일1、파일2、파일10。同一个Collator只创建一次并复用其compare这一点，上面的韩文排序文章已连同性能测量一起讨论。

  • 相等时恰好返回0。返回1或-1的比较函数违反自反性。
  • 不要返回布尔值。比较函数的返回值是数字，true与false变成1与0，没有负数。
  • 比较函数收不到undefined与空槽，因此无法在比较函数内部决定它们的位置。若不想让它们排在末尾，应在排序前填充值或使用替代键。
  • 若需要保留原数组，使用toSorted，或先复制再sort。
  • 修改比较函数后，用包含数字字符串混合、缺失键与相等元素的测试数据来验证。仅用五个元素的输入，布尔比较函数也可能碰巧通过。
