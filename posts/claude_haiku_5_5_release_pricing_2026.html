발표 개요 — Anthropic이 소개한 Haiku 5.5의 자리

Anthropic은 2026년 10월 7일 「Introducing Claude Haiku 5.5」를 게시하고, 이 모델을 자사가 출시한 소형 모델 가운데 가장 저렴하고 가장 빠르며 가장 능력이 높다고 소개했다. 이는 Anthropic 자신의 표현이다. 모델 ID는 claude-haiku-5-5이다.

Claude Platform의 모델 문서는 이 모델의 용도를 분류, 추출, 라우팅 같은 대량·저지연 작업으로 소개하고 서브에이전트 작업을 함께 든다. 발표문은 용도를 대량 반복 작업과 비용에 민감한 작업으로 규정한다. 요약, 컴팩션, 데이터베이스 질의, 분류 요청이 예로 나온다. 같은 문서는 코딩 작업에서 Opus 5.5·Sonnet 5.5와 짝을 이루는 서브에이전트로도 어울리고, 지금까지의 모델 중 가장 빠르다는 점에서 실시간 고객 지원과 브라우저 사용 같은 속도 민감 작업에 특히 맞는다고 설명한다. 상위 모델의 발표는 Claude Opus 5.5 발표 정리에서 다루었고, 같은 시기 다른 회사 모델의 가격표 읽는 법은 GPT-6.1 Sol 가격 정리에 있다.

  • 발표일과 ID. 게시일은 2026년 10월 7일이고, 모델 ID는 claude-haiku-5-5이다.
  • 용도. 요약·컴팩션·데이터베이스 질의·분류 같은 빠르고 반복적인 작업이 예로 제시된다.
  • 서브에이전트. 코딩 작업에서 Opus 5.5·Sonnet 5.5와 함께 서브에이전트로 쓰기에 어울린다고 발표문이 적는다.
  • 속도 단서. 각주 1은 각 모델의 표준 속도 기준으로 가장 빠르지만, Opus 모델의 Fast Mode보다는 느리다고 적는다.

가격표 — 10만 토큰 이하와 초과를 나누어 읽기

발표문의 가격표는 100만 토큰당 단가이며, Haiku 5.5 열만 「prompts up to / over 100k」로 두 구간을 슬래시로 붙여 적는다. 아래 표는 이를 두 열로 풀어 쓴 것이다. Haiku 4.5와 Sonnet 5.5는 원문 표에 구간 구분이 없어 한 칸씩이다.

100만 토큰당 Haiku 5.5 (10만 이하) Haiku 5.5 (10만 초과) Haiku 4.5 Sonnet 5.5
Cache reads $0.01 $0.05 $0.10 $0.10
Cache writes $0.125 $0.625 $1.25 $2.50
Input tokens $0.10 $0.50 $1.00 $2.00
Output tokens $0.50 $2.50 $5.00 $10.00

발표문은 Haiku 5.5가 프롬프트 10만 토큰 이하 작업에서 특히 가성비가 좋고, 이 구간이 이전 Haiku 모델 요청의 약 90%를 차지했다고 적는다. 모델 문서의 가격 절은 같은 값을 입력·출력·캐시 쓰기·캐시 읽기별로 풀어 쓰며, 입력 단가 앞에 「From」이 붙는다.

  • 구간 배수(계산). 표의 네 행 모두 10만 토큰 초과 단가가 이하 단가의 5배이다. 0.10달러 대 0.50달러, 0.50달러 대 2.50달러, 0.01달러 대 0.05달러, 0.125달러 대 0.625달러이다.
  • Haiku 4.5 대비(계산). 10만 토큰 이하의 네 행은 모두 Haiku 4.5의 10분의 1이고, 초과 구간의 네 행은 모두 2분의 1이다. 발표문 각주 2의 90%·50% 인하와 일치한다.
  • Sonnet 5.5 대비(계산). 10만 토큰 이하에서 Haiku 5.5의 입력·출력·캐시 쓰기는 Sonnet 5.5의 20분의 1이고, 캐시 읽기는 10분의 1이다.

「75%」「90%」「50%」「20%」는 각각 무엇의 변화인가

발표문에는 비율이 네 가지 나오며 기준이 서로 다르다. 아래 표는 각 문장을 원문 그대로 옮기고 적용 범위를 붙인 것이다.

수치 원문 문장 적용 범위와 기준
평균 약 75% On average, it now costs around 75% less to run. Haiku 4.5와 비교한 평균 실행 비용. 각주 2가 산정 근거를 적는다
90% 인하 Claude Haiku 5.5 is priced 90% lower than Claude Haiku 4.5 for requests up to 100,000 tokens 10만 토큰 이하 요청의 가격
50% 인하 and 50% lower for requests over 100,000 tokens. 10만 토큰 초과 요청의 가격
요청의 90% On Haiku 4.5, 90% of requests fell into the former category. Haiku 4.5의 요청 중 10만 토큰 이하 비중. 문장의 단위는 요청이다
약 20% this reduces the cost of Sonnet 5.5 on most agentic tasks by around 20%. Sonnet 5.5 캐시 읽기를 0.20달러에서 0.10달러로 내린 효과. 대부분의 에이전트 작업이 대상이다

각주 2는 75%를 산정할 때 Haiku 4.5와 Haiku 5.5 사이에 같은 작업을 끝내는 데 쓰는 토큰 수가 달라지는 점도 반영했다고 적는다. Haiku 5.5의 토크나이저가 Sonnet 5.5·Opus 5.5의 것과 비슷하게 갱신되어 작업당 토큰이 조금 더 쓰인다는 설명이다.

  • 토큰 수 증가의 크기. 모델 문서와 마이그레이션 가이드는 같은 텍스트가 Haiku 4.5보다 약 30% 더 많은 토큰으로 세어진다고 적는다. 정확한 증가폭은 내용에 따라 다르다고 덧붙인다.
  • 같은 텍스트 기준 단가(계산). 토큰이 30% 늘면 10만 토큰 이하의 실효 단가는 Haiku 4.5의 0.10달러 곱하기 1.3, 즉 13%이다. 같은 텍스트라면 87% 낮은 셈이다.
  • 요청 수 가중 평균(계산). 요청의 90%가 10% 단가, 10%가 50% 단가라면 평균은 약 14%로 86% 낮고, 토큰 증가 1.3배를 곱하면 약 18%로 82% 낮다. 발표문의 75%는 이보다 작다.
  • 발표문이 적지 않은 것. 75%를 낸 가중 방식, 입력과 출력의 비중, 요청당 토큰 규모는 발표문에 없어 위 계산으로 75%를 재현할 수 없다.

발표문에는 컨텍스트 길이와 최대 출력이 없고, Claude Platform의 모델 문서에 있다. 아래 표는 Haiku 5.5 문서의 사양 값이다.

effort 단계별 정확도와 시도당 비용

벤치마크 요약 — 설정과 형제 모델 대비

아래 표는 발표문의 성능 표이다. Sonnet 5.5 열에는 원문이 「For reference」라고 적었다. 발표문은 평가 실행 방식이 Haiku 5.5 시스템 카드에 있다고 안내한다.

  • 표의 값과 effort 차트의 관계(대조). OSWorld 72.4%, GDPval-AA 1620, Humanity’s Last Exam 45.9%, Terminal-Bench 39.2%는 각각 차트의 Haiku 5.5 Max 값과 같다. Sonnet 5.5의 83.9%·1840·56.9%·70.6%도 각 차트의 Max 값과 같다. 표 자체는 effort를 적지 않고 FrontierCode의 Sonnet 5.5에만 Xhigh를 적는다.
  • Terminal-Bench 4.0의 비용 곡선. Haiku 5.5는 Low 12.7%($0.42), Med 20.3%($0.68), High 24.8%($1.04), Xhigh 31.5%($1.75), Max 39.2%($2.64)이고 Haiku 4.5는 0.0%($0.79)이다. Sonnet 5.5는 캐시 읽기 0.10달러 기준으로 Low 20.0%($0.62), Med 28.8%($0.68), High 43.0%($1.46), Xhigh 61.5%($4.34), Max 70.6%($10.44)이다.
  • Sonnet 5.5 인하 효과(계산). 같은 차트의 캐시 읽기 0.20달러 기준 Max 비용은 14.15달러이고 0.10달러 기준은 10.44달러로 약 26% 낮다. 다섯 단계 모두 21%에서 26% 사이이다.

Anthropic은 이 차트가 Haiku 5.5와 큰 모델의 차이를 보여 준다고 설명한다. Terminal-Bench 4.0 같은 복잡한 에이전트 코딩에는 Sonnet 5.5와 Opus 5.5가 계속 더 나은 선택이고, Haiku 5.5는 컴팩션·요약·서브에이전트 작업처럼 범위가 좁은 작업에 가장 알맞다는 설명이다. 위 수치는 모두 Anthropic의 자체 발표이다. 발표문 차트 주석은 벤치마크를 이렇게 설명한다. OSWorld 2.1은 에이전트가 실제 컴퓨터를 조작해 길고 여러 단계인 과업을 끝내는 능력을, Terminal-Bench 4.0은 명령줄 환경에서 복잡하고 여러 단계인 전문 과업을 해내는 능력을, Humanity’s Last Exam은 전문가 수준의 학술 지식과 추론을 잰다. GDPval-AA는 Artificial Analysis의 평가이며 44개 직업의 실무를 다룬다.

초기 고객사 평가 6건

발표문은 초기 테스트에서 고객사들이 위 성능·비용 개선과 일치하는 결과를 보고했다고 적고, 여섯 곳의 인용을 싣는다. 아래는 각 인용의 요지이며 모두 해당 회사의 발언을 Anthropic이 게재한 것이다.

  • Asana(Staff Software Engineer Aaron Vinh). AI 에이전트 제품 AI Teammates의 평가 세트에서 현재 쓰는 모델과 비교해 작업 완료 지연이 30% 넘게 줄고 에이전트 턴당 추론이 최대 2.5배 빨랐다고 밝혔다.
  • HubSpot(Distinguished Software Engineer Ze’ev Klapow). 시뮬레이션 포털 기반 CRM 작업 평가에서 지금까지 본 최고 점수인 92.8%(세 번 실행 평균)를 얻었다고 밝혔다. 별도로, 낡았지만 모호한 레코드를 찾는 감사 작업에서 시험한 모든 모델 가운데 가장 빨리 끝냈고 적중률은 가장 높고 오탐률은 가장 낮았다고 적었다.

Sonnet 5.5 캐시 읽기 인하와 Max·Team API 크레딧

Anthropic은 같은 날 모델 라인업의 가치를 높이는 두 가지를 더 발표했다. 첫째, 이날부터 Sonnet 5.5의 캐시 읽기 가격이 50% 내려 100만 토큰당 0.20달러에서 0.10달러가 되었다. 캐시 읽기가 모델 토큰 소비에서 큰 비중을 차지하므로 대부분의 에이전트 작업에서 Sonnet 5.5 비용이 약 20% 줄어든다는 것이 Anthropic의 설명이다. 둘째, 이번 주 안에 모든 Max·Team 구독자에게 Claude Platform용 월간 API 크레딧을 순차 제공한다. 금액은 발표문과 Help Center 문서의 값이며, 아래 표는 Help Center 기준이다.

요금제 월간 크레딧 비고
Max 5x $100 발표문과 같음
Max 20x $200 발표문과 같음

  • 대상. Max와 Team(할인 Team 포함)이 대상이고, Free·Pro·Enterprise는 대상이 아니라고 문서가 적는다. 해당 요금제에 7일 있어야 신청할 수 있다.
  • 신청 절차. Claude Console 조직 하나를 요금제에 연결하는 방식이며, 한 조직만 연결할 수 있고 직접 바꿀 수 없다고 안내한다.
  • 적용 범위. 발표문은 모든 모델에 쓸 수 있다고 적고, 문서는 Claude API(Messages·Message Batches), Console Playground, Claude Managed Agents, Claude Agent SDK를 든다.
  • 적용되지 않는 곳. 터미널·IDE·데스크톱·웹의 대화형 Claude Code, Claude 계열 제품의 추가 사용량, Amazon Bedrock·Google Cloud Vertex AI·Microsoft Foundry의 Claude에는 쓰이지 않는다.
  • 갱신 방식. 결제 주기마다 갱신되고 쓰지 않은 크레딧은 주기 말에 소멸한다. 구매한 크레딧보다 먼저 소진되며, 요금제의 사용 한도와는 별개이다.

잔액이 소진되면 구매한 크레딧이나 자동 충전이 있을 때만 사용이 이어지고, 없으면 다음 월간 크레딧이 들어올 때까지 API 요청이 멈춘다. 사용분이 요금제에 청구되는 일은 없다고 문서가 적는다. Max 5x에서 Max 20x로 올리면 비례 배분된 크레딧이 즉시 지급되고, 해지하거나 대상이 아닌 요금제로 내리면 새 크레딧은 멈추지만 이미 받은 크레딧은 만료 전까지 쓸 수 있다. Max에서 Team으로 옮기면 Max 연결은 끝나며, Team이 7일 이상 유지된 뒤 소유자가 팀 크레딧을 신청할 수 있다.

마이그레이션 가이드가 적은 변경점

Claude Platform의 Haiku 5.5 마이그레이션 가이드는 Haiku 4.5에서 옮길 때 코드에 영향을 주는 항목을 차례로 적는다. 아래는 그 가운데 요청 형식과 과금에 직접 닿는 여덟 가지이다.

  • 모델 ID. Haiku 4.5의 claude-haiku-4-5-20251001 또는 claude-haiku-4-5를 claude-haiku-5-5로 바꾼다. Bedrock은 anthropic.claude-haiku-4-5에서 anthropic.claude-haiku-5-5로, Google Cloud는 claude-haiku-4-5@20251001에서 claude-haiku-5-5로 바뀐다.
  • 토큰 재계산. 같은 텍스트가 약 30% 더 많은 토큰이 되므로 max_tokens 한도와 비용 추정을 다시 계산하라고 안내한다.
  • 사고 설정. {"type": "enabled", "budget_tokens": N}를 보내면 400 오류가 난다. {"type": "adaptive"}와 output_config.effort를 쓰며, adaptive thinking은 기본으로 켜져 있다.
  • 사고 블록 표시. 기본값에서 사고 블록은 thinking 필드가 비어 있고 서명만 담긴다. 요약을 받으려면 display를 summarized로 지정한다.
  • 샘플링 파라미터. temperature·top_p·top_k는 빼야 한다. temperature를 보내면 1이어야 하고 top_p는 0.99여야 하며, 다른 값과 top_k는 400 오류이다.
  • 프리필. 마지막 어시스턴트 턴으로 응답을 이어 쓰게 하는 방식은 사고를 꺼도 400 오류이며, 사용자 턴으로 끝내야 한다.
  • 컴퓨터 사용 도구. Claude API와 Google Cloud에서는 computer_toolset_20260801만 지원하고 computer_20250124 선언은 400 오류이다. 브라우저 사용 도구 browser_toolset_20260801도 지원하며 Haiku 4.5는 지원하지 않는다.
  • 거절과 용량. 안전 분류기가 요청을 거절할 수 있어 stop_reason refusal을 처리해야 하고 서버 측 대체 경로는 없다. Priority Tier는 Haiku 5.5에서 지원되지 않는다. 사고 블록은 만든 계정에서만 유효하고, 앞선 턴이 바뀌면 400 오류가 난다.

가이드는 Messages API 코드의 이전을 다루며, Claude Managed Agents를 쓴다면 모델 이름 변경 외에 필요한 수정이 없다고 적는다. Claude Code에서 /claude-api migrate를 실행하면 번들된 Claude API 스킬이 모델 ID 교체와 필요한 파라미터 수정을 코드베이스에 적용하고, 직접 확인할 항목의 목록을 만든다고 안내한다. 강제 tool_choice(any 또는 도구 이름 지정)는 허용되지만 응답이 도구 호출로 시작하고 사고 블록이 없으며, 도구 호출 전에 사고하게 하려면 tool_choice를 auto로 두고 프롬프트에서 도구 사용 시점을 말하라는 설명이 있다. 발표문은 Claude Python·TypeScript SDK에 컴퓨터 사용과 브라우저 사용 지원을 베타로 추가한다고 밝힌다. 가용성은 모든 플랫폼이며 AWS, Google Cloud, Microsoft Azure가 예로 나온다.

프리필을 대체하는 방법으로 가이드는 출력 형식에는 구조화 출력이나 enum 필드가 있는 도구를, 서두 제거에는 시스템 프롬프트의 직접 답변 요청을, 이어쓰기에는 사용자 메시지로 옮긴 이어쓰기 지시를 제시한다. 이전 모델 쪽으로는 Haiku 3.5가 Claude API와 Amazon Bedrock에서, Haiku 3가 Claude API에서 종료되었고 종료된 모델로 보낸 요청은 실패한다고 적는다.

안전성 평가와 보호 장치

발표문의 안전 절은 정렬 평가와 보호 장치 두 항목으로 이루어진다. 세부 평가 과정은 시스템 카드에 있다고 안내한다.

  • 정렬. Anthropic은 Haiku 4.5와 비교해 거의 모든 정렬 평가에서 큰 개선이 있었고, 정렬을 벗어난 행동이 훨씬 적었으며 오용에 협조하려는 정도가 낮아졌다고 밝혔다.
  • 사이버 보안 보호 장치. Haiku 4.5보다는 엄격하고 최근의 다른 모델보다는 다소 덜 엄격하다고 적는다. Sonnet 5.5의 보호 장치보다 방어 작업을 넓게 허용하지만, 침투 테스트와 공격자가 쓸 가능성이 큰 기법은 여전히 막는다.
  • 생물학 보호 장치. Sonnet 5, Sonnet 5.5, Opus 5와 같다. 연구 목적의 생물학 질문은 허용하되 해를 끼칠 가능성이 크다고 판단하는 요청은 제한한다.

더 넓은 생물학·사이버 활동을 하는 조직은 Life Sciences Verification Program과 Cyber Verification Program에 신청할 수 있다고 발표문이 안내한다.

확인하지 못한 것

  • 시스템 카드의 평가 설정. 발표문이 평가 실행 방식을 안내하는 시스템 카드는 PDF로 제공되어 본문을 읽지 못했고, 성능 표의 effort·시도 횟수는 차트 값과의 일치로만 추정했다.
  • 75% 산정의 가중 방식. 발표문과 각주에 요청별 토큰 규모와 입력·출력 비중이 없어 산술로 재현하지 못했다.
  • GPT-6 Luna의 공식 사양과 가격. 발표문 표의 비교 값만 옮겼고 해당 회사 자료는 다루지 않았다.
  • Amazon Bedrock·Google Cloud·Microsoft Foundry에서의 실제 청구 단가와 지역별 제공 시점. 이들 플랫폼의 가격 문서는 열지 못했다.
