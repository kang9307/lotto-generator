2026년의 디지털 한국은 표면적으로는 매우 진보적입니다. 키오스크가 거리마다 자리 잡고, 정부 서류는 모두 PDF로 발급되며, 학교 교과서마저 태블릿으로 옮겨갔습니다. 그러나 이 화려한 디지털 전환의 그늘에는 약 25만 명의 시각 장애인이 있습니다. 그들에게 PDF는 그림이고, 키오스크는 평평한 유리이며, 태블릿은 음성 안내가 없는 한 그저 검은 액자입니다.

점자는 200년 가까이 시각 장애인의 문자 시스템으로 기능해 왔습니다. 그러나 디지털 콘텐츠가 폭증하는 속도에 비해, 한글 점자 변환은 줄곧 뒤처져 있었습니다. 인쇄 점자 도서 한 권을 만드는 데 수개월이 걸리고, 자동 변환 도구는 약어·외래어·숫자에서 자주 오류를 냈습니다. 2024년 한국 점자 규정 개정이 이루어진 배경이 바로 이것입니다. 그리고 2026년 5월, GeekNews(hada.io 토픽)에 등장한 braillify는 이 규정 개정을 디지털 도구로 구현해 낸 최초의 오픈소스 사례 중 하나입니다.

본 글은 braillify의 단순 소개를 넘어, 점자 시스템의 기본부터 한국 점자의 특수성, 2024 규정 개정의 핵심, 그리고 개발자가 즉시 활용할 수 있는 통합 가이드까지를 5,000자 분량으로 정리합니다. 접근성을 단순한 ‘의무’가 아니라 ‘새로운 시장’으로 바라보는 시각을 함께 제시합니다.

1. braillify란 - 짧은 도구 소개

braillify는 한국어 텍스트를 점자(Unicode Braille Patterns, U+2800~U+28FF)로 변환해 주는 오픈소스 JavaScript 라이브러리입니다. 한국 개발자 커뮤니티에서 만들어진 이 도구는 다음과 같은 정체성을 가집니다.

  • 라이센스: MIT - 상업적 이용 자유
  • 지원 규정: 2024년 개정 한국 점자 규정 전면 반영
  • 검증 수준: 2,419개 테스트 케이스 통과 (단위 테스트 기준)
  • 런타임: 브라우저(ES Module) + Node.js 동시 지원
  • 의존성: 외부 패키지 0개 (zero-dependency)

한 줄로 요약하면, braillify는 ‘설치 즉시 한글을 점자로 바꿔주는 가장 가벼운 라이브러리’입니다. 기존 점자 변환 도구는 대개 윈도우용 데스크톱 프로그램이거나 서버에 설치해야 하는 무거운 솔루션이었습니다. braillify는 이 흐름을 깨고, 정적 HTML 파일 안에서도 동작할 수 있는 수준까지 단순화했습니다.

2. 점자(Braille)의 기본 - 점자 시스템 이해

점자를 한 번도 본 적 없는 독자를 위해, 먼저 점자의 구조를 짚고 가겠습니다. 점자는 가로 2점 × 세로 3점 = 6점 셀을 한 단위로 사용합니다. 점이 도드라지면 1, 평평하면 0이므로, 셀 하나가 표현할 수 있는 조합은 2의 6승 = 64가지입니다.

유니코드는 1999년 U+2800~U+28FF에 점자 패턴 256개를 등록했습니다. 이는 8점 셀(컴퓨터 점자) 전체를 포함하기 위함입니다. 6점 셀 모드만 쓴다면 U+2800~U+283F의 64개 코드포인트만 사용됩니다.

요소설명
셀(Cell)점자 한 글자 단위 (가로 2 × 세로 3)
점(Dot)1~6번까지 번호로 식별 (왼쪽 위부터 세로 방향)
약자(Contraction)자주 쓰는 단어를 한두 셀로 줄인 표기
약어(Abbreviation)긴 단어의 정해진 짧은 점자 표기
수표(Number Sign)이어 나오는 셀이 숫자임을 표시
대문자표(Capital Sign)이어 나오는 셀이 대문자임을 표시

2.1. 왜 6점이고 왜 두 개 단으로 늘어나는가

1825년 루이 브라유가 점자를 고안할 때, 손가락 끝의 촉각 해상도를 기준으로 6점 셀을 선택했습니다. 검지 끝으로 한 번에 인식 가능한 영역이 대략 가로 6mm × 세로 9mm이고, 그 안에 6점이 들어가야 정확한 식별이 가능합니다. 셀이 더 크면 손가락을 들었다 놓는 동작이 늘고, 더 작으면 점을 구분하지 못합니다. 이 인체공학적 제약이 200년이 지난 지금도 6점 셀의 표준을 유지시키고 있습니다.

3. 한글 점자의 특수성 - 자모 분리, 약자, 약어 규정

영어 점자는 알파벳 한 글자가 점자 한 셀에 대응합니다. 매우 직관적입니다. 그러나 한글은 다릅니다. 한글은 초성·중성·종성의 조합 문자이기 때문입니다. ‘안녕’이라는 두 글자는 자모로 풀면 ‘ㅇ + ㅏ + ㄴ + ㄴ + ㅕ + ㅇ’의 6개 자모가 됩니다. 점자는 이 자모 하나하나에 셀을 할당합니다.

여기에 한국어 특유의 규칙이 더해집니다.

  • 초성·종성 구분: 같은 ‘ㄱ’이라도 초성 위치와 종성 위치에서 점자 패턴이 다릅니다.
  • 약자(Contraction): ‘그러나’, ‘그리고’ 같은 자주 쓰는 단어는 별도 점자 한 셀로 줄여 씁니다.
  • 약어(Abbreviation): ‘대한민국’처럼 긴 단어는 미리 정해진 약어 점자로 대체합니다.
  • 외래어 처리: 영어 단어가 섞이면 영어 점자 모드로 전환 표시를 삽입해야 합니다.
  • 띄어쓰기 규칙: 점자는 일반 텍스트보다 더 많은 띄어쓰기를 요구합니다.

이 모든 규칙을 정확히 구현하려면 단순 매핑 테이블로는 부족합니다. 형태소 분석에 가까운 전처리 단계가 필요합니다. 자동화 도구가 정확도 면에서 어려움을 겪었던 이유가 바로 여기에 있습니다.

4. 2024년 한국 점자 규정 개정 - 무엇이 바뀌었나

2024년에 개정된 한국 점자 규정은 디지털 시대를 정조준한 첫 번째 개정입니다. 그 이전 규정은 인쇄 점자 도서 제작을 전제로 설계되어, 자동화 변환에는 모호한 지점이 많았습니다. 신규정의 주요 변경은 다음과 같습니다.

영역구 규정2024 신규정
외래어 표기영문 점자 전환 표시 모호전환 시점·범위 명확화
숫자 처리수표 적용 범위 해석 다름연속 숫자·소수점·콤마 일원화

디지털 출력인쇄만 가정유니코드 출력 가이드 명시

특히 마지막 항목인 유니코드 출력 가이드는 의미가 큽니다. 그 이전까지 점자 도구는 출판사가 쓰는 BRF 파일(.brf)을 만들어 점자 프린터에 보내는 것이 일반적이었습니다. 신규정은 유니코드 점자 패턴(U+2800~U+28FF)으로 직접 출력하는 방식을 공식화함으로써, 웹 화면에서 점자를 그대로 보여주거나, 점자 디스플레이 장치에 바로 전송하는 길을 열어 주었습니다. braillify가 이 흐름을 정확히 따릅니다.

5. braillify의 5가지 강점

본 글에서는 braillify를 다음 5가지 관점에서 평가합니다.

5.1. 2024 신규정 완전 지원

2024년 신규정에 등장한 외래어 전환 표시, 수표 일원화, 약자 충돌 해결 규칙이 모두 코드로 구현되어 있습니다. 기존 한국 시각 장애인 협회의 인쇄용 도구가 신규정 반영에 시간을 들이는 사이, braillify는 GitHub 커밋 로그에서 2024년 개정 발표 직후 빠르게 대응한 흔적이 보입니다. 표준 변경에 민첩하게 반응하는 것은 오픈소스 프로젝트의 큰 미덕입니다.

5.2. 2,419개 테스트 케이스 검증

한글 점자 변환은 자모 분리, 약자, 외래어, 숫자가 얽혀 ‘악마는 디테일에 있다’는 말이 가장 잘 맞는 분야입니다. braillify는 단위 테스트로만 2,419개 케이스를 보유합니다. 일반 단어, 약자 적용 단어, 영문 혼용, 숫자 혼용, 문장 부호, 약어, 다중 약자 충돌 등 모든 경계 조건이 회귀 테스트로 포함되어 있습니다. 이는 ‘오픈소스이지만 신뢰할 수 있다’의 객관적 증거입니다.

5.3. JavaScript 라이브러리 통합 용이

설치는 한 줄입니다. npm install braillify. CDN 사용자는 ESM 형태로 직접 import 할 수 있습니다. API는 단 하나의 함수 호출에 가깝습니다. 입력은 한국어 문자열, 출력은 유니코드 점자 문자열입니다. 옵션으로 약자 모드, 외래어 모드, 출력 형식을 조절합니다. 학습 곡선이 거의 없는 수준입니다.

5.4. 오픈소스 + MIT 라이센스

접근성 도구를 상업 라이센스로 보호하는 것은 사실 모순입니다. 시각 장애인이 사용하는 도구가 비싸다면 접근성 자체가 깎입니다. MIT 라이센스는 누구나 자유롭게 가져다 쓰고, 수정하고, 재배포할 수 있게 합니다. 기업이 자사 키오스크에 통합해도 라이센스료가 발생하지 않으며, 학교가 교육용 앱에 넣어도 무료입니다. 이 결정은 작지만 묵직합니다.

5.5. 브라우저·Node 동시 지원

같은 코드가 클라이언트와 서버 모두에서 동작합니다. 즉, 정적 사이트의 자바스크립트에서도, Next.js의 서버 컴포넌트에서도, AWS Lambda 위에서도 변환 결과는 동일합니다. 이는 점자 변환의 정확성이 환경에 따라 흔들리지 않는다는 의미이기도 합니다. 인쇄용·웹용·키오스크용 등 다양한 출력처에 단일 코드베이스로 대응할 수 있습니다.

7. 개발자 통합 방법 - 5분 시작 가이드

이론은 충분합니다. 이제 실제 코드로 들어가겠습니다.

7.1. 설치

npm install braillify
# 또는 CDN 사용
# <script type="module">import { toBraille } from 'https://cdn.jsdelivr.net/npm/braillify/+esm';</script>

7.2. 기본 사용

import { toBraille } from 'braillify';

const text = '안녕하세요. 점자 변환 테스트입니다.';
const braille = toBraille(text);
console.log(braille);
// 출력: 점자 유니코드 문자열 (U+2800~U+28FF 영역)

7.3. 옵션 활용

const result = toBraille(text, {
  contraction: true,       // 약자 적용
  abbreviation: true,      // 약어 적용
  foreignMode: 'auto',     // 외래어 자동 전환
  format: 'unicode',       // 'unicode' | 'brf' | 'numeric'
});

7.4. React 컴포넌트 예시

import { useState } from 'react';
import { toBraille } from 'braillify';

export function BrailleConverter() {
  const [input, setInput] = useState('');
  const braille = input ? toBraille(input, { contraction: true }) : '';
  return (
    <div>
      <textarea value={input} onChange={(e) => setInput(e.target.value)} />
      <div className="braille-output" aria-label="점자 출력">{braille}</div>
    </div>
  );
}

7.5. 서버 사이드 (Node.js / Next.js API)

// app/api/braille/route.ts (Next.js App Router)
import { toBraille } from 'braillify';

export async function POST(req) {
  const { text } = await req.json();
  const braille = toBraille(text, { contraction: true });
  return Response.json({ braille });
}

5분이라는 표현이 과장이 아닙니다. 위 다섯 단계만 거치면 어떤 환경에서든 한글 점자 변환이 작동합니다.

8. 활용 시나리오 5가지

도구가 매력적이어도 적용처가 떠오르지 않으면 의미가 없습니다. braillify가 즉시 효과를 내는 다섯 가지 시나리오를 정리합니다.

시나리오 1: 시각 장애인용 학습 자료 자동 변환

교과서 PDF, 교사가 만든 학습지, 학원 문제집을 텍스트 추출 후 braillify로 점자 변환합니다. 점자 프린터로 종이 출력하거나, 점자 디스플레이에 직접 표시할 수 있습니다. 기존에는 출판사에 의뢰해 수개월을 기다렸지만, 이제는 분 단위로 처리됩니다. 특수교육 현장의 시간 비용이 극적으로 줄어듭니다.

시나리오 2: 점자 학습 앱

시각 장애 아동이 점자를 배우거나, 비장애인이 점자를 학습할 때 braillify는 즉석 변환 카드를 만들어 줍니다. ‘오늘 단어’ 모드, ‘퀴즈’ 모드, ‘약자 시험’ 모드 등을 React Native로 구현하면 모바일 점자 학습 앱이 됩니다. 교육부의 디지털 교과서 사업과 연결될 가능성도 있습니다.

시나리오 3: 공공 기관 문서 접근성 자동화

구청, 시청, 동주민센터의 안내문이 PDF로 발급될 때, 같은 내용의 점자 PDF를 자동 병행 생성합니다. 정부 디지털 접근성 평가에서 점자 제공 여부가 점점 더 큰 항목으로 자리 잡고 있어, 이 자동화는 평가 점수와 직접 연결됩니다. braillify의 BRF 출력 모드가 여기서 활용됩니다.

시나리오 4: 점자 키오스크

지하철 매표 키오스크, 병원 접수 키오스크, 공항 체크인 키오스크에 점자 디스플레이를 결합합니다. 키오스크 화면의 텍스트를 실시간으로 braillify에 통과시켜 점자 디스플레이로 출력하면, 시각 장애 사용자는 직원의 도움 없이 키오스크를 사용할 수 있습니다. 2026년 이후 키오스크 접근성이 의무화되는 흐름과도 정확히 맞물립니다.

시나리오 5: 다국어 점자 (영어·일본어·중국어와의 차이)

braillify 자체는 한국어 전용이지만, 같은 페이지에 영어·일본어·중국어 점자 변환기를 함께 두면 다국어 점자 서비스가 만들어집니다. 영어는 liblouis, 일본어는 BES, 중국어는 핀인 변환 후 liblouis를 사용하는 방식으로 조합 가능합니다. 글로벌 관광지의 안내 키오스크가 자연스러운 적용처입니다.

9. 글로벌 시각 - 영어 점자 vs 한글 점자 vs 일본어 점자 vs 중국어 점자

한글 점자가 얼마나 정교한 시스템인지 보려면 다른 언어와 비교하는 것이 도움이 됩니다.

언어변환 방식약자 체계글자당 평균 셀대표 도구
영어알파벳 1:1 매핑Grade 1 / Grade 21.0~1.2셀liblouis
한국어자모 분리 후 매핑약자·약어 다층2.5~3.0셀braillify
일본어가나 1:1 매핑제한적 약자1.5~2.0셀BES
중국어한자 → 핀인 → 점자병음 약자3.0~4.0셀libbraille

한글 점자는 ‘평균 셀 수’ 측면에서 영어보다 약 2.5배 더 많은 공간을 차지합니다. 자모 분리 때문입니다. 이는 점자 도서의 분량이 인쇄본보다 훨씬 두꺼워지는 이유이며, 디지털 점자 디스플레이의 화면 폭이 80셀 이상 권장되는 이유이기도 합니다. 중국어는 더 까다롭습니다. 한자를 직접 점자로 매핑할 수 없어 핀인 변환이 선행되어야 하고, 그 과정에서 동음이의어가 정보 손실로 이어지기 때문입니다. 한국어가 그나마 자모 단위로 1:1 매핑이 가능하다는 점은 점자 변환 알고리즘 설계자 입장에서 큰 행운입니다.

10. 접근성 분야의 미래 - AI와 점자

점자는 200년이 된 시스템입니다. 그러나 디지털·AI 시대에 점자가 처한 환경은 급변하고 있습니다. 다음 세 가지 흐름이 향후 5년간 접근성 분야를 재편할 것입니다.

  • 실시간 음성 → 점자 변환: STT(음성 인식)로 즉시 텍스트화하고 braillify 같은 변환기로 점자 디스플레이에 흘려보내면, 시각·청각 동시 장애 사용자도 실시간 대화를 ‘읽을’ 수 있습니다.
  • OCR + 점자 자동 발행: 종이 책의 사진을 찍으면 OCR로 추출 → braillify로 변환 → 점자 PDF로 저장하는 워크플로우가 모바일 앱 하나로 완결됩니다.
  • 대형 언어 모델과 결합: LLM이 요약·번역한 결과를 그대로 점자로 흘려보낼 수 있으면, 시각 장애 학습자가 일반 학습자와 같은 정보 접근성을 가집니다. 단, 환각(hallucination) 검증이 점자에서도 별도 검증 절차로 들어가야 합니다.

AI 시대의 접근성은 ‘덤’이 아니라 ‘기본 기능’이 됩니다. 그리고 그 기본 기능을 가능하게 하는 것은 braillify처럼 작고 빠르며 정확한 도구들입니다.

11. 한국 개발자가 즉시 적용 가능한 3가지

본 글을 읽은 후 한국 개발자가 즉시 실행에 옮길 수 있는 액션 3가지를 제시합니다.

  1. 회사 공지사항·뉴스레터에 점자 출력 추가: HTML 페이지에 braillify 한 줄을 추가해 점자 토글 버튼을 만듭니다. 시각 장애 직원·고객이 있다면 즉시 가치를 줍니다. ESG·DEI 평가에서 가산점이 됩니다.
  2. 오픈소스 프로젝트 README에 점자 버전 병행: GitHub 프로젝트 README의 핵심 문장을 점자로 함께 표시합니다. 작은 시도지만 접근성 친화 프로젝트라는 메시지를 전달합니다. 후원·기여 유입이 늘어날 수 있습니다.
  3. braillify에 기여(Contribute): 한국어 점자에 익숙한 개발자라면 단위 테스트 케이스를 추가하거나, 디지털 점자 디스플레이 출력 모드를 보완하는 PR을 보냅니다. 한국에서 시작된 오픈소스가 글로벌 표준이 되는 길은 한국 개발자들의 작은 기여에서 시작됩니다.

12. 결론 - 가장 작은 라이브러리, 가장 큰 사회적 가치

braillify는 거대한 프로젝트가 아닙니다. 의존성 0개, MIT 라이센스, 단위 테스트 2,419개. 그 자체로는 한 명의 개발자가 만든 도구처럼 보입니다. 그러나 이 작은 라이브러리가 다루는 영역은 한국의 25만 시각 장애인, 그리고 그들의 가족·교사·동료들이 만나는 모든 디지털 콘텐츠입니다. 사회적 가치의 밀도가 가장 높은 라이브러리 중 하나라 할 수 있습니다.

2026년의 한국은 접근성을 ‘부가 기능’으로 두는 시대를 지나, 그것을 ‘기본 기능’으로 끌어올리는 시기에 있습니다. 그 전환에 필요한 것은 거창한 정부 정책이 아니라, braillify 같은 작고 단단한 오픈소스 도구들과, 그것을 즉시 자신의 서비스에 도입하는 개발자들의 결정입니다. 본 글이 그 결정의 무게를 조금이라도 가볍게 만들어 주기를 바랍니다.
