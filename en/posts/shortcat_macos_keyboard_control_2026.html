Shortcat - Control Your Entire Mac With the Keyboard 2026

A UI-indexing command palette that keeps your hands on the keys

Jun 9, 2026 Tech

Introduction: The Tiny Round Trip to the Mouse Adds Up

You are deep in a coding session, then you lift your right hand off the keyboard, reach for the trackpad to click a file in the sidebar, and return to the keys. It takes less than a second. But repeat that little round trip a few hundred times a day, a few thousand times a month, and the picture changes. Micro-fatigue accumulates in the wrist, and your flow breaks into tiny fragments each time. Shortcat is a macOS tool built to eliminate exactly that "short round trip to the mouse." It returned to attention by topping GeekNews (news.hada.io) on June 8, 2026.

The core idea is simple yet powerful: index every on-screen UI element - buttons, links, menu items, text fields, windows - through the Accessibility API, then search them by name or hint label in a command palette and action them with the keyboard alone. Instead of dragging a cursor to a coordinate, you type the name of the thing you want. This article covers the problem Shortcat solves, how it works on top of the Accessibility API, the productivity of a keyboard-first workflow, a comparison with Vimium, Homerow, Vimac, and Keyboard Maestro, setup and usage tips, and the honest limits.

1. The Problem Shortcat Solves - Mouse Round Trips, RSI, Accessibility

To understand Shortcat, look first at what it is a solution for. On the surface it is a productivity tool, but underneath sit three distinct problems.

  • The inefficiency of the mouse round trip: Typing, then moving a hand to the mouse, aiming at a target, clicking, and homing back to the keyboard is a measurable loss of time. Trivial individually, substantial in aggregate.
  • RSI (repetitive strain injury): Constant mouse use strains the wrist and arm. RSI-prevention material consistently recommends keyboard-based tools - shortcuts, macros, hotkeys - as a key way to reduce mouse usage.
  • Accessibility: The very technology Shortcat depends on stands on screen-reader foundations built for users with visual impairments. Keyboard-first control is inherently aligned with making interfaces more inclusive.

So Shortcat is not merely a "make it faster" tool; it touches three axes at once - input efficiency, health, and accessibility. That is the decisive difference from a plain shortcut-extension utility.

2. What Shortcat Is - A One-Sentence Definition

According to the official introduction, Shortcat is a "universal command palette for your Mac." Clicking buttons, focusing text fields, invoking menu commands, switching windows - all of it, with no mouse required. It is a background utility that lets you reach almost any UI element of your Mac with the keyboard, whether you are in Finder, Spotify, or any other app.

The phrase "command palette" matters. If you have used VS Code or another editor, you know the pattern: a hotkey opens a search box, you type a command name, and it runs. Shortcat extends that pattern to the whole operating system. It is not limited to one app's commands; every clickable element on screen becomes searchable.

If the mouse asks "where do I point," Shortcat asks "what do I run." It is a shift from addressing the interface by coordinates to addressing it by name.

3. How It Works - Reading the UI Through the Accessibility API

Shortcat's magic lives in the macOS Accessibility API. That API was originally built so screen readers like VoiceOver could read screen contents aloud to users with visual impairments. Through it, the operating system exposes each app's buttons, labels, menus, and windows as a structured tree.

Shortcat reads that tree. Broken into steps, the flow looks like this:

1. Hotkey            Trigger the Shortcat palette
   │
   ▼
2. Index elements    Collect clickable elements on the current screen via the API
   │
   ▼
3. Hint / search     Overlay hint labels + fuzzy-search element names
   │
   ▼
4. Keyboard action   Type a label or search a name, then Enter to click / run

The key point is that Shortcat does not see the screen as "pixels." It is not image recognition or OCR; it reads the structural information apps report to the Accessibility API. That makes it accurate and fast - and it also means accuracy hinges on how well an app exposes information. The better-behaved a native app is, the better Shortcat works.

4. Hint Mode and Search Mode

Shortcat handles elements in two main ways. Pick whichever fits the moment.

4.1 Hint (Label) Mode

When the palette opens, short character labels are overlaid on clickable elements. Type the label of the one you want and it fires immediately. This is handy when there are few elements on screen, or for quickly hitting an icon button whose name you do not know. It is the same idea as Vimium's "f" hints.

4.2 Search (Typing) Mode

Type an element's name or label text and fuzzy search narrows the candidates. To find a "Save" button, typing part of it is enough. This shines when you know the name of a button or link, especially when the screen is crowded with similar elements. Notably, Shortcat supports both hints and typing, which sets it apart from some competitors that lean on hints alone.

5. Menu Fuzzy Search - A Hidden Strength

Shortcat's real value emerges when dealing with menu-bar commands. A macOS app can hold dozens or hundreds of commands in its menu bar, yet only some have shortcuts; the rest require digging through menus with the mouse.

Shortcat exposes the current app's menu items with lightning-fast fuzzy search. Smarter still, it supports synonyms. Per its introduction, a command like "Delete item" can be matched not only by "delete" but also by "remove," "clear," or "destroy." In other words, you can reach a command by meaning even if you cannot recall its exact name. Menu search alone is reason enough for many users to keep Shortcat running all the time.

6. The Productivity of a Keyboard-First Workflow

Is driving a computer with the keyboard alone really more productive? The answer is "sometimes, and increasingly over time."

RSI and productivity literature is consistent on the core point: keyboard-based flows - shortcuts, hotkeys, macros - reduce mouse and trackpad strain, and keyboard-centric work such as the CLI can, after one to three years of dedicated effort, reach or exceed the productivity of a mouse-and-GUI workflow. It is not a quick fix but an investment that compounds.

The benefits of a keyboard-first workflow can be summarized as:

  • Fewer context switches: Hands never leave the home position, so the input flow stays unbroken.
  • No aiming overhead: The cognitive and muscular cost of precisely aiming at a small button with the mouse disappears.
  • A consistent mental model: The single pattern of "run by name" applies the same way across nearly all apps.
  • RSI relief: Reducing mouse dependence distributes the cumulative load on the wrist and arm.

Of course, all of these come only after paying the upfront cost of a learning curve. The theme of "a tool reshaping your flow" also appears in terminal performance and developer productivity.

7. Comparing the Field - Vimium, Homerow, Vimac, Keyboard Maestro

Shortcat is part of a broader ecosystem of keyboard-first control. Laying out the tools it is often compared to makes the choice easier.

Tool Scope Approach Cost / Status
Shortcat All of macOS Hints + typed search, menu fuzzy Free / not actively maintained lately
Homerow All of macOS Hint labels, keyboard scrolling Paid / successor to Vimac, active
Vimac All of macOS Hints, HJKL scroll mode Free / deprecated (moved to Homerow)
Vimium Browser only Hints, Vim-key navigation Free / browser extension
Keyboard Maestro All of macOS Macro / automation focused Paid / a different kind of tool

To interpret: Vimium only works inside the browser, so it is not a direct replacement for Shortcat. Vimac is effectively discontinued, with development moved to the paid app Homerow. Homerow is the faster, sleeker successor to Vimac and has features Shortcat lacks, such as keyboard-driven scrolling. Keyboard Maestro is a different animal - it builds macro and automation workflows rather than indexing UI elements, so it is often used alongside Shortcat as a complement.

The common recommendation across roundups is clear: if you are just getting started, start with Shortcat. It is free, works with more apps, and has the lowest barrier to entry. Later, if you find you desperately need keyboard scrolling, moving to Homerow is a natural path.

8. Installation and Permission Setup

Using Shortcat requires two things: a suitable macOS version and Accessibility permission.

  • Requirements: macOS 13 or later, tested on recent macOS. It is a free download from the official site, and version 0.12.2 was released in July 2025.
  • Accessibility permission: For Shortcat to read and control UI elements, you must allow it under System Settings > Privacy & Security > Accessibility. Without this permission it cannot index screen elements.

Accessibility is a powerful permission, so it is worth confirming the app came from a trusted source (the official site) before granting it. The broader macOS permission model echoes the "tool hygiene" theme covered in developer tools 2026 - what devs actually use.

9. Usage Tips - Making Shortcat Second Nature

Installing a tool does not instantly raise productivity. Break it in in this order.

  1. Start with one action: At first, do only "run a menu command" through Shortcat. It is the highest-impact area and where the advantage over the mouse is clearest.
  2. Search before hints: For buttons whose names you know, typed search is faster. Switch to hint mode only for icons whose names you do not know.
  3. Trust the synonyms: If a command name is fuzzy in your memory, type the meaning (remove, clear, and so on). No need to memorize exact names.
  4. Deliberately keep away from the mouse: Consciously cut trackpad use for a week and your hands start to remember the pattern.
  5. Combine with complements: For window management or macros, split duties with a tool like Keyboard Maestro.

9.5 A Concrete Day With Shortcat

Abstract benefits are easy to nod along to and hard to feel. So picture a concrete morning. You open your mail client; instead of reaching for the trackpad to click "Reply," you trigger Shortcat, type "rep," and the reply field is focused before your hand has left the home row. You switch to a browser, need to click a small "Submit" button buried among form fields, fire the palette, type a few letters of its label, and it activates without a single pixel of aiming. You jump into a design tool whose most-used command lives three levels deep in a menu with no shortcut; you summon Shortcat, type the meaning rather than the exact name, and the command runs.

None of these individual moments is dramatic. That is precisely the point. The value of Shortcat is not a single heroic shortcut but the quiet removal of thousands of tiny frictions across a day. By the afternoon you notice your hands have barely left the keyboard, your wrist feels less worked, and your attention stayed on the task instead of repeatedly re-acquiring a cursor. The compounding nature of that relief is exactly what the productivity literature predicts: small, repeated savings that only become visible in aggregate.

10. Limits and Honest Downsides

For balance, let us name the weaknesses plainly. Shortcat is not a cure-all.

  • Tied to the Accessibility API: If an app does not expose accessibility information, it cannot be indexed. Graphics apps that draw on a custom canvas, some Electron/web apps, and games are hard or impossible to control.
  • Learning curve: The first few days are actually slower. There is always a stretch where the mouse feels faster until your hands learn the pattern.
  • Maintenance concern: Shortcat has reportedly not been actively maintained for a couple of years. It is the trade-off for being free - a weakness if you need new features or fast bug fixes.
  • Feature gaps: Some features, such as keyboard-based scrolling, are absent in Shortcat but present in Homerow.

Most of these limits are the shadow of one design choice: building on the Accessibility API. In exchange for accuracy and lightness, it is powerless where the API cannot reach.

11. Who Should Use It

So who is Shortcat for? In short:

  • Keyboard-centric developers: People already comfortable with Vim, the terminal, and shortcuts who want to keep their hands on the keys.
  • Users managing RSI: People who need to reduce mouse use medically or preventively.
  • Users who need accessibility: People for whom keyboard-first control is a necessity, not just a preference.
  • Menu hunters: Designers and power users who frequently use deep menu commands without shortcuts.

Conversely, if you mostly work in graphics-heavy apps or games, or cannot spare time to learn a new tool, the payoff may be limited. The discipline of asking "does this fit my workflow" before adopting a tool echoes the tool-selection principle stressed in Claude Code hidden settings.

12. Conclusion + 3 Things to Try Today

Shortcat targets a small but endlessly repeated inefficiency: the short round trip to the mouse. By indexing UI elements through the Accessibility API and enabling keyboard-only clicks, menus, and window switching, it touches three axes at once - input efficiency, health, and accessibility. Being free and low-barrier, it is an ideal starting point for anyone trying a keyboard-first workflow for the first time. Just go in clear-eyed about the structural limit of depending on the Accessibility API and the maintenance concern.

Three things you can try today:

  1. Install it and turn on Accessibility first. Download from the official site, install, and allow the permission under System Settings - that is the starting point for everything.
  2. Use menu search alone for a week. Build the habit of running shortcut-less menu commands through Shortcat's fuzzy search, and you will feel the payoff fastest.
  3. Compare with Homerow. If keyboard scrolling is essential, trial paid Homerow alongside and pick whichever fits your workflow against free Shortcat.
