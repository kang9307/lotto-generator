1. 계기와 배경 — 버전 2.1.277에서 전해진 AGENTS.md 지원의 실체

일반적으로 코딩 어시스턴트 환경에서 프로젝트 전반의 개발 지침을 표준 마크다운 파일로 전달하여 모델의 일관된 응답을 유도하는 방식이 활용된다.

Claude Code 생태계에서는 오랫동안 CLAUDE.md 파일이 프로젝트 지침의 표준 명칭으로 기능해 왔다. 2026년 9월 버전 2.1.277 공개와 함께 소식이 전달되었다. X 게시물로 전해진 문장에 따르면 Thariq은 「We're adding support for AGENTS.md to Claude Code. Starting today in version 2.1.277, if there is no CLAUDE.md in a folder, Claude will check for and use AGENTS.md. You can toggle this behavior in /config.」라고 밝혔다.

GeekNews의 2차 요약에 따르면, 이 기능은 Claude Code의 새 커스터마이징 시스템인 Mods 위의 built-in mod로 구현되었으며 해당 소스 코드가 저장소에 공개되었다. 요약문은 이를 두고 「별도의 CLAUDE.md 를 복제하거나 심볼릭 링크로 연결할 필요가 없어짐」이라고 정리했다. 온라인 커뮤니티 반응에서는 「마침내!」와 같은 환영 의견이 확인되었다.

공식 1차 출처인 저장소의 README 문서는 이 모듈의 역할을 간결하게 명시한다. README는 「The agents-md mod allows Claude Code to read AGENTS.md files as instruction files, similar to how it reads CLAUDE.md files.」라고 설명한다. 이 글의 해석으로는 기본 설정에서 CLAUDE.md가 부재할 때만 AGENTS.md가 로드되므로, 기존 프로젝트 파일 구성에 따라 모델에 전달되는 지침이 달라진다.

2. 기본 동작 원리 — 병합이 아닌 폴백(claude-md-or-agents-md)의 작동 경계

공식 README에 명시된 기본 옵션값은 claude-md-or-agents-md이다. README에 기술된 실제 규칙에 따르면, 자체 지침 파일이 없는 프로젝트에 한해서만 CLAUDE.md가 있을 자리에 AGENTS.md를 대신 로드한다.

README는 여기서 말하는 「자체 지침 파일(of its own)」의 판별 기준을 다음과 같이 구체적으로 규정한다:

  • 프로젝트 루트 디렉터리부터 현재 작업 디렉터리까지 내려오는 경로 상의 어느 디렉터리에서든 CLAUDE.md, .claude/CLAUDE.md, 또는 CLAUDE.local.md 중 하나라도 엔진에 의해 로드된 경우
  • 위의 세 가지 파일 중 단 하나라도 감지되면 엔진이 프로젝트 전체의 지침 처리를 전담하며 플러그인은 컨텍스트에 일체 개입하지 않고 대기 상태를 유지함(leaves the whole project to the engine, and the plugin stays out)
  • 반면 조직의 관리형 파일(managed file), 사용자의 홈 디렉터리에 위치한 ~/.claude/CLAUDE.md, .claude/rules 파일, 그리고 --add-dir 플래그로 추가된 디렉터리의 CLAUDE.md는 중첩 탐색 경로에서 확인되지 않으므로 프로젝트 자체 파일로 계산하지 않음
  • 경로 상에 자체 지침 파일이 전혀 없는 경우에만 경로 상의 모든 AGENTS.md 및 .claude/AGENTS.md가 엔진이 렌더링하는 지침 파일 목록에 결합됨

우선순위 측면에서도 단일 디렉터리 내 경합 규칙이 확고하다. 만약 동일한 디렉터리에 CLAUDE.md와 AGENTS.md가 나란히 존재하는 경우, CLAUDE.md가 해당 디렉터리를 차지하며 AGENTS.md는 완전히 무시된다. 기본 설정 상태에서는 기존 프로젝트에 CLAUDE.md가 남아 있다면 새로 작성한 AGENTS.md는 모델에게 전달되지 않는다.

이 글의 해석으로는 기본값에서는 CLAUDE.md가 하나라도 있으면 AGENTS.md가 로드되지 않으므로, 두 파일을 함께 쓰려면 병합 모드를 선택해야 한다.

3. 네 가지 instructionFiles 옵션과 로드 정책의 비교

README에 따르면 이 내장 플러그인은 instructionFiles라는 단일 옵션을 통해 제어되며, 네 가지 상호 배타적인 모드를 지원한다. 각 모드는 엔진이 기본 제공하는 지침 처리 루틴과 플러그인이 주입하는 파일의 상호작용 방식을 변경한다.

README에 기술된 네 가지 옵션의 상세 정의는 다음과 같다:

  • claude-md: 엔진이 기존 방식 그대로 CLAUDE.md 계열 파일만 로드하며, 플러그인은 컨텍스트에 아무것도 추가하지 않는다.
  • claude-md-or-agents-md: 플러그인의 기본값이다. 프로젝트 자체에 CLAUDE.md 지침이 전혀 없는 경우에만 AGENTS.md 파일을 대신 주입한다.
  • claude-md-and-agents-md: 트리 상하위의 모든 AGENTS.md 파일을 CLAUDE.md 파일과 나란히 함께 로드한다. 이미 @ 구문으로 임포트되었거나 링크로 연결된 파일은 중복 로드되지 않는다.
  • managed-only: 프로젝트의 체크인된 지침 파일, 로컬 비공개 지침 파일, 사용자 개인 지침 파일이 모두 컨텍스트에서 제외되며 조직 관리 CLAUDE.md와 엔진 메모리만 보존된다.

다음 표는 README 문서를 바탕으로 네 가지 모드의 로드 대상과 적용 조건을 비교 정리한 것이다.

옵션 값 컨텍스트에 로드되는 파일 기본값 여부 및 작동 조건
claude-md 엔진의 기존 CLAUDE.md 탐색 파일만 단독 로드 비기본값. 플러그인이 아무런 작업도 수행하지 않음
claude-md-or-agents-md 자체 CLAUDE.md 부재 시에만 AGENTS.md 로드 기본값(default). 프로젝트 자체 지침이 하나라도 있으면 플러그인이 개입하지 않음
claude-md-and-agents-md 디렉터리 트리의 CLAUDE.md와 AGENTS.md 전체 병합 비기본값. 두 지침을 공존시키며 중복 파일은 경로와 내용 비교를 거쳐 제외함
managed-only 조직 관리 CLAUDE.md 및 엔진 메모리만 유지 비기본값. 프로젝트 저장소와 사용자 개인의 지침 파일을 컨텍스트에서 배제함

README는 이 파일들이 모델에 도달하는 내부 경로에 관해서도 설명한다. 파일 전달은 플러그인이 독자적으로 수행하는 것이 아니라 엔진의 책임이다. prompt.context 훅이 claudeMd 항목 뒤에 위치한 지침 파일 목록(객체 구조 { path, kind, content, parent? }, kind는 managed, user, project, local, memory 순서)을 플러그인에 전달하면, 훅이 변경된 목록을 반환하는 구조다. 엔진은 반환된 파일들을 바탕으로 자체 서문과 프레이밍을 붙여 렌더링하며, 각 파일명을 콘솔에 공지한다.

이 글의 해석으로는 4가지 옵션에 따라 프로젝트 지침의 포함 여부와 로드 범위가 결정론적으로 분기된다.

4. 상황별 탐색 규칙 — 동일 디렉터리, 하위 디렉터리 Read, 심볼릭 링크

프로젝트 구조가 복잡해질수록 지침 파일이 어떤 디렉터리에 위치하고 어떤 순서로 모델에 주입되는지가 중요하다. README는 중첩된 디렉터리와 다양한 파일 시스템 상태에서의 탐색 메커니즘을 명시하고 있다.

하위 디렉터리에 위치한 AGENTS.md 파일의 로드 시점에 대해 README는 다음과 같이 명시한다: 「Nested AGENTS.md files attach on text Read operations only」. 에이전트가 텍스트 Read 도구를 실행하는 순간에 프로젝트 루트와 대상 파일 사이에 위치한 디렉터리들을 거슬러 올라가며 해당 경로의 AGENTS.md가 컨텍스트에 첨부된다. 이때도 해당 하위 디렉터리에 CLAUDE.md가 존재한다면 그 파일이 우선권을 가져가며 AGENTS.md는 첨부되지 않는다.

다음 표는 실무에서 마주칠 수 있는 대표적인 파일 시스템 구성 상황과 각 모드별 처리 결과를 정리한 것이다.

상황 및 디렉터리 파일 구성 적용 모드 실제 로드 결과 및 동작
루트에 CLAUDE.md와 AGENTS.md 동시 존재 claude-md-or-agents-md (기본값) CLAUDE.md가 해당 위치를 차지하며 AGENTS.md는 완전히 무시됨
저장소에 CLAUDE.md가 일체 없고 AGENTS.md만 존재 claude-md-or-agents-md (기본값) CLAUDE.md가 로드될 위치에 AGENTS.md가 정상적으로 대체 주입됨
루트에 CLAUDE.md, 하위 디렉터리에 AGENTS.md 존재 claude-md-or-agents-md (기본값) 루트에 자체 지침이 있으므로 하위 디렉터리의 AGENTS.md도 일체 로드되지 않음
루트에 CLAUDE.md, 하위 디렉터리에 AGENTS.md 존재 claude-md-and-agents-md (병합 모드) 하위 파일에 대한 텍스트 Read 발생 시 해당 경로의 AGENTS.md가 첨부됨
심볼릭 링크로 AGENTS.md를 CLAUDE.md에 연결 claude-md-and-agents-md (병합 모드) 경로 철자와 파일 내용을 순차 비교하여 중복인 경우 2회 로드를 방지함

심볼릭 링크와 관련된 처리 규격도 명시되어 있다. README에 따르면 플러그인은 심볼릭 별칭(symlink alias)을 엔진 자체처럼 실제 경로로 해석하지 않고, 경로의 문자열 철자(spelling)를 기준으로 비교한다. 파일 시스템에서 경로 표기가 상이하게 전달되는 경우 엔진 자체의 탐색 동작과 플러그인의 판정 사이에 차이가 발생할 수 있다.

이 글의 해석으로는 하위 디렉터리의 AGENTS.md는 텍스트 Read 작업 이전의 일반 대화 단계에서는 컨텍스트에 포함되지 않는다.

5. @ 임포트 승인과 중복 방지 — claude-md-and-agents-md 병합의 동작

두 지침 파일을 동시에 로드하는 claude-md-and-agents-md 모드를 활성화할 경우 @ 구문을 통한 외부 지침 임포트 처리가 중요하다.

README는 중복 제거 메커니즘을 다음과 같이 규정한다:

  • CLAUDE.md가 이미 @ 구문으로 임포트했거나 링크로 연결한 파일은 두 번째로 로드되지 않는다.
  • 중복 여부를 판정할 때 시스템은 먼저 파일 경로(path)를 비교하고, 경로가 다르면 파일 내용(content)을 비교하는 2단계 검증을 수행한다.
  • AGENTS.md 내부에서 사용된 @ 임포트 구문은 CLAUDE.md의 외부 임포트와 동일한 외부 임포트 승인(approval) 절차를 거친 뒤에만 컨텍스트에 반영된다.
  • 승인되지 않은 외부 임포트 구문은 모델의 지침 파일 프레임에 포함되지 않고 배제된다.

이 글의 해석으로는 경로가 다르더라도 내용이 같으면 중복 로드가 방지되며, 외부 파일 임포트는 승인 절차를 거친 것만 반영된다.

6. 조직 거버넌스와 managed-only 모드의 컨텍스트 격리

조직 환경에서는 개별 저장소 지침을 통제해야 하는 요구가 발생한다. managed-only 옵션은 이러한 거버넌스를 위해 설계된 격리 모드이다.

README에 따르면 managed-only 모드가 활성화되었을 때의 동작 특성은 다음과 같다:

  • 프로젝트에 체크인된 지침 파일(CLAUDE.md, AGENTS.md)과 개인 로컬 파일(CLAUDE.local.md), 그리고 사용자 개인의 지침 파일(~/.claude/CLAUDE.md)이 컨텍스트에서 제거된다.
  • 조직 단위에서 중앙 관리하는 CLAUDE.md와 엔진 자체의 내부 메모리만 컨텍스트에 보존된다.
  • 엔진 레벨의 claudeMdExcludes 설정(사용자, 프로젝트, 로컬 지침 제외 규칙)도 유효하게 존재하며, 이 플러그인이 읽는 AGENTS.md 파일들에도 동일하게 적용된다.
  • 조직 차원에서 prompt.context에 사전에 배치한 플러그인은 본 플러그인보다 상위에 위치하므로 최종 파일 목록에 대한 결정권을 유지한다.

다만 README는 세부 동작을 명시한다. 텍스트 Read 시점에 발생하는 엔진의 중첩 CLAUDE.md 첨부는 아직 이벤트 기반으로 제어되지 않기 때문에 managed-only 모드에서도 도달할 수 있다(still arrive). 소스 코드인 register.ts에서도 managed-only 모드에서는 Files.DROPPED_KINDS에 해당하는 지침 파일들을 Files.isKeptWithoutInstructions 필터를 통해 걸러내는 훅을 등록한다.

이 글의 해석으로는 managed-only 모드에서는 저장소 내부의 지침 파일이 제외되고 조직 관리 파일과 엔진 메모리만 남게 된다.

7. 설정 방식과 하위 호환성 — /config 와 JSON 설정, legacy 키

이 플러그인의 설정을 변경하는 인터페이스는 대화형 명령과 정적 설정 파일의 두 가지 방식으로 제공된다. README는 두 방식의 구체적인 설정 경로와 값의 규격을 기술하고 있다.

대화형 환경에서 사용자는 /config 명령을 실행하여 나타나는 화면 중 「Project instructions」 행을 통해 네 가지 값 중 하나를 선택할 수 있다. README는 이 행이 네 가지 선택지를 제공하는 선택기(picker)로 동작한다고 설명한다.

직접 설정 파일을 편집하는 경우, 사용자 설정 파일(~/.claude/settings.json), CLI 실행 시 --settings 플래그로 지정한 파일, 또는 관리형 설정 파일에 다음 JSON 블록을 구성할 수 있다. README에 명시된 설정 JSON 예시는 다음과 같다:

{
  "pluginConfigs": {
    "agents-md@builtin": {
      "options": { "instructionFiles": "claude-md-and-agents-md" }
    }
  }
}

개별 프로젝트 루트의 .claude/settings.json 파일은 플러그인 옵션으로 읽히지 않는다. README는 사용자 전역 설정이나 관리형 설정에서만 이 옵션을 인식한다고 적는다. 설정을 변경하면 모듈이 즉시 다시 로드되며, 재로드 후 다음 턴, 새로운 대화 세션 시작, /clear 명령 실행, 또는 컨텍스트 압축(compaction) 시점부터 새로 지정된 모드의 지침 파일들이 반영된다.

사용자가 네 가지 유효 값 이외의 임의의 문자열을 수동으로 입력한 경우, 해당 사실이 트랜스크립트에 1회 출력되며 기본값인 claude-md-or-agents-md로 처리된다. /plugin 목록에서도 내장 플러그인 항목으로 표시되어 사용자가 직접 비활성화할 수 있다. 플러그인을 완전히 끄면 엔진은 기존처럼 CLAUDE.md만 단독으로 읽는다.

설정 키의 마이그레이션 이력도 문서에 기술되어 있다. 과거에는 옵션 키로 projectInstructions가 사용되었으며, 지원 값은 claude, agents-fallback, both, none이었다. README와 register.ts에 따르면 레거시 키가 아직 저장되어 있는 경우 instructionFiles가 기본값인 상태에서 다음과 같이 매핑되어 존중된다:

  • none → managed-only
  • claude → claude-md
  • agents-fallback → claude-md-or-agents-md
  • both → claude-md-and-agents-md

그 밖의 임의 값은 아무것도 추가하지 않는 claude-md로 매핑된다. 세션이 처음 시작될 때 레거시 키가 어떤 값으로 해석되었는지가 트랜스크립트에 표시된다. 일단 instructionFiles가 기본값 이외의 새로운 값으로 지정되면 레거시 키는 더 이상 읽히지 않으며 레거시 키를 설정에서 제거하라는 안내문이 출력된다.

8. 실무 검증 절차와 주의점 — 테스트 명령과 트레이드오프

공식 저장소의 디렉터리 구조를 확인해 보면, 해당 모듈은 .claude-plugin, 훅 구현체인 hooks/(진입점 register.ts 포함), tests/, 그리고 README.md로 구성되어 있다. 모듈 동작을 검증할 수 있는 테스트 스위트가 포함되어 있으며, README에 명시된 테스트 실행 명령은 다음과 같다:

claude plugin test mods/agents-md

실무 엔지니어링 관점에서 이 기능을 적용할 때 점검해야 할 사항은 다음과 같다:

  • 단일 저장소에서의 침묵하는 무시 현상: 기본값인 claude-md-or-agents-md 환경에서는 루트에 CLAUDE.md가 남아 있는 한 하위 디렉터리의 AGENTS.md가 읽히지 않는다. AGENTS.md를 반영하려면 설정 모드를 claude-md-and-agents-md로 전환해야 한다 (이 글의 해석).
  • 모노레포의 동적 첨부 타이밍: 하위 패키지의 지침은 대상 파일을 텍스트 Read로 읽는 시점에만 첨부된다. 따라서 파일 열람 전의 일반 계획 단계에서는 하위 규칙이 모델에 아직 전달되지 않는다 (이 글의 해석).
  • 심볼릭 링크의 문자열 경로 비교: 심볼릭 링크 별칭이 실제 경로로 해석되지 않고 문자열 철자로 중복 여부가 비교된다. 따라서 상대 경로 표기가 다르면 중복 방지 로직이 적용되지 않을 수 있다 (이 글의 해석).
  • 팀 내 로컬 설정 불일치: 플러그인 옵션은 프로젝트 루트의 .claude/settings.json이 아니라 개인 전역 설정에 저장된다. 따라서 팀원마다 설정값이 다르면 동일 저장소에서도 로드되는 지침 파일이 달라질 수 있다 (이 글의 해석).

이 글의 해석으로는 기본 동작이 단순 병합이 아니라 조건부 대체이므로, 프로젝트 파일 구성에 맞추어 instructionFiles 모드를 명시적으로 설정해야 한다.
