mq - jq风格的Markdown查询语言 2026

jq为JSON做的事，这次轮到Markdown

2026-06-10 IT/技术

引言：Markdown到处都是，趁手的工具却很贫乏

想想开发者的一天，Markdown几乎无处不在：README、Wiki、Issue、设计文档、博客草稿，到了2026年还包括LLM的提示词和回复。它已成为文本结构化文档事实上的标准。可一旦你想把这些Markdown当成程序对象来处理，工具就显得贫乏了。用grep找标题，连代码块里的#注释也会被一并抓出；用sed替换链接，又会和表格里的竖线符号打架。Markdown对人友好，但让机器从结构层面处理，却意外地棘手。

精准瞄准这处空白、并在GeekNews上引发热议的工具，正是mq。一句话概括，mq就是面向Markdown的jq。它把处理JSON的标准工具jq的哲学——用点号选择元素、用管道串联转换、组合过滤器——原封不动地搬到了Markdown上。本文会先简单复习jq是什么，再看mq解决了什么问题、它的工作原理、实战中如何使用，以及它与pandoc、remark、mdq等邻近工具有何不同。

1. 先复习jq - 面向JSON的查询工具

要理解mq，得先从它的原型jq说起。jq是命令行下处理JSON的轻量处理器，常被称为面向JSON的sed/awk，或JSON版的SQL。其核心概念是过滤器（filter）。一段jq程序就是一个接收输入、产生输出的过滤器，而最简单的过滤器.是恒等运算符，把输入原样传出。

jq的强大来自用管道（|）串联小过滤器。和shell管道一样，前一个过滤器的输出会成为下一个过滤器的输入。

# 从对象中只提取name字段
echo '{"name":"Ada","age":36}' | jq '.name'
# => "Ada"

# 遍历数组，只选择age大于30的项
echo '[{"n":"A","age":36},{"n":"B","age":20}]' \
  | jq '.[] | select(.age > 30)'
# => {"n":"A","age":36}

有三点值得记住。其一，用点号表示法（.name）深入结构。其二，用管道串联各阶段。其三，用select()这类函数做筛选。在别的语言里要用循环和条件分支完成的事，jq只用把过滤器像胶水一样拼接就能解决。这套思路几乎被原样移植到了mq中。

2. 可Markdown不是JSON - 问题的本质

jq之所以这么顺手，是因为JSON从一开始就具备便于机器解析的结构。键与值、对象与数组清晰嵌套，点号表示法可以精确指向任何位置。

Markdown不同。它是为方便人读写而设计的纯文本。看似简单，里面却藏着标题、段落、列表、引用、表格、链接、代码块这些隐含结构。问题在于，这种结构在按行划分时并不容易显现。

  • grep的盲区： 用grep '^#'找标题时，会把代码块里的shell注释#也一起抓出来。grep只看文本行，并不知道某一行是否在代码块内部。
  • sed的盲区： 想批量替换链接时，单凭正则常常和嵌套括号或表格里的竖线（|）发生冲突。
  • 对结构无知： 归根结底，grep、sed、awk对Markdown的结构是看不见的。对它们而言，文档不过是一串行。

另一端则是pandoc。pandoc是把整篇文档转换成其他格式的强大工具，但对于只取h2标题、或只取Rust代码块这样的外科式提取来说太重了。正是这处按行工具与整篇转换工具之间的空白，是mq瞄准的位置。

3. mq是什么 - 面向Markdown的jq

据官方介绍，mq是用类似jq的语法处理Markdown的命令行工具，由Rust编写。它对Markdown进行切片、过滤、映射和转换。jq处理的是JSON对象和数组，而mq处理的是标题、段落、代码块这样的文档节点。

mq的身份可以用一句话概括。

grep和sed对Markdown的结构视而不见，pandoc则把整篇文档转换。mq居于其间，对Markdown内部的元素做外科式查询与改写。

介绍资料中强调的mq主要用途如下。

  • LLM工作流： 高效加工、整理用于LLM提示词与输出的Markdown。这是2026年最受关注的用途。
  • 文档管理： 跨多个文档文件提取、转换和整理内容。
  • 内容分析： 快速从Markdown文档中取出特定章节或模式。
  • 批量处理： 对多个Markdown文件应用一致的转换。

工具支持也介绍得相当丰富。它具备用于交互式试验的REPL、带LSP（语言服务器协议）支持的VSCode扩展，以及可逐步查看查询的调试器。把以mq-开头的可执行文件放进~/.local/bin/，还能扩展出自定义子命令。

4. 工作原理 - 把Markdown看成AST

mq与grep的根本不同就在这里。mq不是把Markdown当作一串行，而是解析成结构化的树，即AST（抽象语法树，Abstract Syntax Tree）。

比如有这样一段简短的Markdown。

# 安装

用以下命令进行安装。

```bash
cargo install mq-run
```

## 用法

详情请参见[文档](https://mqlang.org/)。

在人眼里只是文本，mq却把它理解为如下结构。

Document
├─ Heading(level=1)  "安装"
├─ Paragraph         "用以下命令进行安装。"
├─ CodeBlock(lang=bash)  "cargo install mq-run"
├─ Heading(level=2)  "用法"
└─ Paragraph
   └─ Link(url="https://mqlang.org/")  "文档"

结构一旦显式呈现，只取标题、只取二级标题、只取bash代码块、只取全部链接这类选择就变得精确。代码块里的#不会再被误认成标题。mq之所以能像jq一样工作，秘密正是这种在AST之上的查询。jq的输入是JSON树，mq的输入则是Markdown的AST。

5. 基本选择器 - 标题、代码块、链接

现在来看实际语法。mq的选择器像jq的点号表示法，只是对象换成了Markdown元素。下面的示例整理自官方文档和介绍资料中给出的模式。

5.1 标题提取（.h）

# 提取所有标题
mq '.h' README.md

# 只取h1标题
mq '.h(1)' README.md

# 只取h1和h2标题
mq '.h(1, 2)' README.md

# 级别1到3的标题（区间）
mq '.h(1..3)' README.md

5.2 代码块提取（.code）

# 所有代码块
mq '.code' example.md

# 只取rust代码块
mq '.code("rust")' example.md

# 只取javascript代码块
mq '.code("javascript")' example.md

把它和在jq里见过的select()与contains()组合，就得到条件过滤。

# 只取包含"install"的标题
mq '.h | select(contains("install"))' README.md

# 只取包含"name"的代码块
mq '.code | select(contains("name"))' example.md

点号表示法、管道、select——用过jq的人会立刻感到熟悉。用拼接过滤器代替循环的jq思路在这里完整保留。

6. 转换与组合 - 展开为文本

mq不止于提取，还能转换。它可以把提取出的节点展开成纯文本、改变大小写，或包装成链接。

# 把所有标题转换为文本
mq '.h | to_text()' README.md

# 把代码块转换为文本
mq '.code | to_text()' example.md

# 用管道连接工具（提取后转小写）
cat README.md | mq '.h' | mq 'downcase()'

和jq一样，mq真正的威力在于把小部件组合起来。把shell管道和mq内部的管道一起用，像取出标题→转小写→交给下一个工具这样的流程就能一行写完。

7. 实战应用场景

那么这到底能做什么？比起抽象的语法，具体场景更能体现工具的价值。

7.1 自动生成目录（TOC）

把文档的h1、h2标题收集起来，生成带锚点链接的目录。官方介绍中也给出了收集标题并用to_link()转成链接的目录生成示例。在自动整理长README或Wiki文档时很有用。

7.2 从README抽取代码示例进行验证

用mq '.code("bash")'只提取README里的shell示例，放进CI跑一遍看是否真能运行。这是防止文档里命令与现实脱节、即文档腐化（rot）的好办法。

7.3 精简LLM提示词与回复

从LLM长篇输出的Markdown回复中只取标题结构和链接，用作摘要上下文；或过滤掉多余代码块以节省token。提取标题与链接来精简LLM输入，在介绍资料中也被列为核心用途。

7.4 文档批量转换与校验

对数十个Markdown文件应用同一查询，找出失效链接或检查某章节是否存在，构建文档检查（linting）流水线。这些都是grep因为不懂结构而难以胜任的工作。

8. CLI使用示例一览

把前面的模式汇成实战命令。

# 安装（依据官方说明）
cargo install mq-run

# 1) 把文档所有h2标题输出为文本
mq '.h(2) | to_text()' docs/guide.md

# 2) 只提取python代码块
mq '.code("python")' docs/guide.md

# 3) 查找包含"deprecated"的段落
mq 'select(contains("deprecated"))' CHANGELOG.md

# 4) 管道：提取标题 → 转小写
cat README.md | mq '.h' | mq 'downcase()'

看出规律了吗？选择 → 过滤 → 转换这套jq的三段结构，在Markdown上原样重复。一旦学会，写新查询的成本就极低。若你对用Rust实现压缩与系统工具感兴趣，用Rust实现Zstandard一文也值得一并参考。

9. Python绑定与MCP

mq并非只能当CLI用。介绍称PyPI上以markdown-query包提供了Python绑定，可以在Python脚本中用相同语法查询Markdown。对于用Python编写数据流水线或文档处理自动化的团队很方便。

在2026年的语境下，尤其有意思的是MCP（模型上下文协议，Model Context Protocol）集成。据介绍资料，可以把mq作为MCP服务器暴露，让AI应用以结构化方式加工Markdown。LLM不必囫囵吞下整篇文档，而是用mq精确切出所需部分再传入。关于AI工具生态更宏观的脉络，我们在2026年开发者真正在用的工具中做了梳理。

10. 同类工具对比 - mq vs mdq vs pandoc vs remark

处理Markdown的工具不止mq，各自瞄准的位置不同。依据介绍与对比资料整理如下。

工具 性质 擅长 局限/特点
mq jq风格查询CLI（Rust） 元素提取与转换，REPL、LSP、调试器，MCP与Python绑定 功能丰富，需要学的表达也更多
mdq jq风格查询CLI（Rust） 从文档中简单、聚焦地选取特定元素 被介绍为比mq更轻量、更简单的选取工具
pandoc 通用文档转换器 格式间整篇转换（MD↔HTML↔PDF等） 用于外科式元素提取过重
remark JS的Markdown处理框架 基于插件的转换与检查，构建集成 比CLI一行查询更偏编程

概括来说，mq和mdq是同一谱系的jq风格查询工具。mq偏向工具支持（REPL、LSP、调试器）与集成（MCP、Python）更丰富的一侧，mdq则被介绍为更简单、更聚焦的选取工具。pandoc重在转换，remark是JS生态的框架，两者气质不同。也就是说，是否用mq，取决于你是要转换文档，还是要在文档内部做挑选。

11. 采用mq时的考量

好工具也要契合场景才能发光。在采用mq前，有些现实问题值得权衡。

  • 学习曲线： 有jq经验上手很快；若对jq本身陌生，就要先掌握点号表示法、管道、过滤器组合这套思路。
  • 安装依赖： 基于Rust，cargo install被指引为最便捷的途径。是否提供预编译二进制要看你所在平台，需要确认。
  • 成熟度： 这是一个仍在活跃开发的较新工具，部分表达或功能可能随版本变化。对于未经确认的行为，以官方文档为准更稳妥。
  • 适用场景： 对一次性提取可能过重。在反复的文档自动化、校验、LLM预处理这类需要把同一查询跑很多遍的场景中，价值才更大。

12. 对开发者与文档工作者的意义

mq的出现，意义不止于多了一个趁手的CLI。它代表着把Markdown当作数据来对待这一思路的扩散。长期以来Markdown是供人阅读的文档，而非供机器查询的数据。正如jq让JSON成为一等数据，mq把Markdown提升为可查询的结构。

这一变化对两类人尤其有感。对开发者而言，文档成了代码流水线的一部分：测试README的代码示例、校验变更日志、把文档检查纳入CI都变得自然。对文档工作者而言，过去手工修改几十个文档的重复劳动，缩成了一行查询。

而2026年的决定性语境，依然是LLM。在AI大量生产和消费Markdown的时代，能精确切分、过滤这些Markdown的工具，需求只会越来越大。mq把LLM工作流与MCP摆在台前并非偶然。Markdown越是成为AI与人类之间的通用语言，处理这门通用语言的jq式工具，其位置就越清晰。

13. 结论 + 现在就能试的三件事

mq用一句jq的Markdown版就能概括，但这一句所指相当宽广。在grep、sed看不见结构、pandoc又过重的那处空白里，mq把Markdown解析成AST，做外科式查询与转换。用过jq的人，凭点号表示法、管道、过滤器这套熟悉语法就能立刻起步。

以现在就能试的三件事收尾。

  1. 先拿你最长的README抽标题。 一行mq '.h' README.md就能让文档骨架一目了然，是最快体会到价值的起点。
  2. 提取代码块并接入验证流水线。 用mq '.code("bash")'把文档里的命令抽出来在CI里跑，就能自动捕捉文档与现实的脱节。
  3. 把它嵌入LLM预处理。 从长篇Markdown回复中只切出需要的元素再传入，既省token又能保持上下文整洁。

工具反复印证的真理始终如一：把人原本要反复做的结构化工作越多地交给机器，我们就越能专注于真正重要的判断。mq正是把Markdown这门熟悉的文本，提升到这一层面的小巧而聪明的工具。
