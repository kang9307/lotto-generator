Ceph RBD vs CephFS 完全比較: どちらをいつ選ぶべきか?

Complete Comparison of Ceph RBD vs CephFS: When to Choose Which?

2025-07-10 開発・インフラ

Ceph はブロックストレージ (RBD) とファイルシステム (CephFS) の 2 種類の主要なストレージインターフェースを提供します。それぞれ異なる用途と特性を持っており、プロジェクトの要件に応じた適切な選択が必要です。

English: Ceph provides two major storage interfaces: block storage (RBD) and file system (CephFS). Each has different purposes and characteristics, and appropriate selection based on project requirements is essential.

🎯 RBD vs CephFS 比較の概要

🔷 Ceph RBD (RADOS Block Device)

  • ブロックレベルのストレージ
  • 仮想マシンイメージに最適化
  • 高い IOPS 性能
  • 単一クライアントアクセス

🔷 CephFS (Ceph File System)

  • POSIX 互換ファイルシステム
  • マルチクライアントでの共有が可能
  • 階層的なディレクトリ構造
  • 柔軟な権限管理

🎯 ユースケース比較

🔷 RBD が最適なユースケース

  • 仮想マシンのディスクイメージ
  • データベースのストレージ
  • コンテナのボリューム
  • 高性能アプリケーション
  • ブートディスク

🔷 CephFS が最適なユースケース

  • 共有ファイルシステム
  • ホームディレクトリ
  • ログファイルの保存
  • メディアストレージ
  • コラボレーション用ワークスペース

🔍 実際の性能テスト結果

テスト項目 RBD CephFS 差分

💡 性能分析: RBD はブロックへの直接アクセスにより、ほとんどのワークロードで優れた性能を発揮しますが、CephFS はメタデータ管理のオーバーヘッドによりわずかな性能低下が発生します。

🛠️ 設定と管理

🔧 RBD 設定の例

# RBD プールの作成
ceph osd pool create rbd-pool 128 128
ceph osd pool application enable rbd-pool rbd
rbd pool init rbd-pool

# RBD イメージの作成
rbd create --size 10240 rbd-pool/my-image

# イメージのマッピング
sudo rbd map rbd-pool/my-image

# ファイルシステムの作成とマウント
sudo mkfs.ext4 /dev/rbd0
sudo mount /dev/rbd0 /mnt/rbd-mount

🔧 CephFS 設定の例

# CephFS プールの作成
ceph osd pool create cephfs-data 128 128
ceph osd pool create cephfs-metadata 32 32

# ファイルシステムの作成
ceph fs new cephfs cephfs-metadata cephfs-data

# MDS のデプロイ
ceph orch apply mds cephfs --placement="2"

# クライアント側のマウント
sudo mount -t ceph mon1:6789,mon2:6789,mon3:6789:/ /mnt/cephfs -o name=admin,secret=AQC...

🔐 セキュリティと権限管理

🛡️ RBD のセキュリティ特性

  • アクセス制御: クライアントごとのキーに基づく認証
  • 暗号化: クライアントサイド暗号化をサポート
  • スナップショット: 読み取り専用スナップショットの作成
  • クローン: 効率的なイメージ複製

🛡️ CephFS のセキュリティ特性

  • POSIX 権限: 標準的なファイルシステム権限
  • ディレクトリ権限: ディレクトリ単位での細かな制御
  • クライアント制限: パスベースのアクセス制限
  • 暗号化: 通信経路上の暗号化をサポート

🔄 バックアップとリストア

🔷 RBD のバックアップ方法

# スナップショットの作成
rbd snap create rbd-pool/my-image@snap1

# スナップショットのエクスポート
rbd export rbd-pool/my-image@snap1 backup.img

# スナップショットからの復元
rbd import backup.img rbd-pool/restored-image

🔷 CephFS のバックアップ方法

# スナップショットの作成
mkdir /mnt/cephfs/.snap/snap1

# rsync でバックアップ
rsync -av /mnt/cephfs/ /backup/cephfs/

# tar でバックアップ
tar -czf backup.tar.gz /mnt/cephfs/

💰 コストとリソース

💸 運用コスト比較

  • RBD:
    • MDS が不要なため、運用コストが低い
    • シンプルなアーキテクチャで管理が容易
    • 高い性能によってハードウェア効率が向上
  • CephFS:
    • MDS 運用のための追加リソースが必要
    • 複雑なメタデータ管理
    • マルチクライアント環境ではコスト効率が高い

🎯 選定ガイド

✅ RBD を選ぶべきケース

  • 仮想マシンのストレージが必要な場合
  • データベース用ストレージとして利用する場合
  • 高い IOPS が求められるアプリケーション
  • 単一クライアントのみがアクセスする場合
  • コンテナのボリュームとして利用する場合

✅ CephFS を選ぶべきケース

  • 複数クライアントが同時にアクセスする必要がある場合
  • 既存アプリケーションで POSIX 互換性が必要な場合
  • 共有ファイルシステムが必要な場合
  • 複雑なディレクトリ構造が必要な場合
  • ログファイルやメディアの保管庫として利用する場合

⚡ 性能最適化 Tips

🔧 RBD の最適化

# クライアントの最適化
echo mq-deadline > /sys/block/rbd0/queue/scheduler
echo 4096 > /sys/block/rbd0/queue/nr_requests

# キャッシュ設定
rbd_cache = true
rbd_cache_size = 33554432  # 32MB

# マルチスレッド設定
rbd_concurrent_management_ops = 20

🔧 CephFS の最適化

# クライアントキャッシュ設定
client_cache_size = 268435456  # 256MB
client_readahead_min = 131072   # 128KB

# MDS の最適化
mds_cache_size = 1000000
mds_cache_memory_limit = 1073741824  # 1GB

# クライアントマウントオプション
mount -t ceph mon:/ /mnt/cephfs -o name=admin,rsize=4194304,wsize=4194304

🚨 注意事項と制限事項

⚠️ RBD の制限事項:
  • 複数クライアントから同時に書き込みができない
  • ファイルシステム機能の制限
  • 複雑な権限管理が困難
⚠️ CephFS の制限事項:
  • MDS 障害時にファイルシステム全体に影響
  • メタデータ性能のボトルネック
  • RBD と比較して性能が低い

🎯 まとめ

RBD と CephFS はそれぞれ固有の長所と用途を持っています。RBD は高性能が求められるブロックストレージに、CephFS は共有ファイルシステムが必要な環境に適しています。プロジェクトの要件を正確に分析し、適切な選択を行うことが重要です。

🔑 選定まとめ:
  • 高性能 + 単一クライアント → RBD を選択
  • 共有アクセス + マルチクライアント → CephFS を選択
  • データベース + 仮想マシン → RBD を選択
  • ファイル共有 + コラボレーション → CephFS を選択
