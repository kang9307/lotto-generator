서론: 왜 6개월 단위의 정리가 2026년에 맞는 해상도인가

6개월 전인 2025년 11월의 LLM 풍경은 안정적으로 보였습니다. OpenAI는 GPT-5 계열이 기본 모델이었고, Anthropic은 2025년 9월 29일에 Claude Sonnet 4.5를 내놓은 뒤였으며, Google은 Gemini 2.x 계열의 Flash 모델이 저가 영역의 일꾼이었습니다. 시장은 "스케일링 법칙이 약해지고 곡선이 평탄해졌다"고 이야기했습니다. 그 후 6개월이 지난 지금, 그 문단의 거의 모든 가정이 깨졌습니다. 11월부터 5월까지의 윈도우는 초대 GPT-4 출시 이래 가장 바쁜 LLM 릴리즈 사이클이었고, 그 속도는 AI 풀타임 빌더들조차 따라가지 못할 정도였습니다. 많은 팀의 스택에는 여전히 2025년 가정이 박혀 있고, 그만큼 가용 품질·비용·속도를 손해 보며 쓰고 있을 가능성이 큽니다.

여기 정리한 것은 이 기간의 6개월 회고입니다. 주요 랩과 오픈 웨이트 패밀리를 빠짐없이 훑고, 변화를 매트릭스와 표로 압축하며, 마지막에는 다섯 개의 구체적 실무 시사점과 하반기 전망으로 마무리합니다. 구조는 의도된 것입니다. 회사별 정리, 다음에 트렌드, 다음에 벤치마크, 다음에 조언. 매트릭스만 필요하면 큰 표만 보면 됩니다. 맥락을 알고 싶다면 처음부터 끝까지 읽어주세요. 본문은 어떤 랩의 마케팅 어조도 따르지 않고, 실무자의 의사결정에 무엇이 바뀌었는가를 기준으로 썼습니다.

2026년 9월 29일 갱신에서는 본문에 나오는 모델 이름과 출시일을 각 회사의 공식 발표·문서로 다시 확인했습니다. 발행 당시 본문에는 날짜가 틀렸거나 공식 발표에서 확인되지 않는 이름(예: GPT-4.5o, Claude 4.7 Sonnet, Llama 4 7B·30B·200B)이 섞여 있었고, 이를 정정하거나 확인 불가로 표시했습니다. 이 기간의 기록이라는 성격은 그대로 두었으므로, 발행 뒤의 출시는 끝부분의 이후 경과 절에 따로 모았습니다.

본격적인 정리에 앞서 세 가지 프레임을 짚습니다. 첫째, 모델 번호는 진보 측정 단위가 아닙니다. 어떤 랩의 "0.1"은 다른 랩의 "2.0"보다 큰 점프일 수 있습니다. 본문은 "무엇이 실제로 바뀌었는가"를 중심에 둡니다. 둘째, 폐쇄 모델과 오픈 웨이트의 진행 곡선이 이제는 평행으로 달리고 있습니다. 일부 축에서는 격차가 몇 주 단위로 좁혀집니다. 셋째, 가장 결정적인 변화는 어떤 단일 모델 릴리즈가 아니라 주변 스택입니다. 에이전트 하네스, 코딩 에이전트, 메모리 원시 기능, 그리고 사실상 표준으로 자리 잡은 Model Context Protocol이 그것입니다. 본문 전반에서 이 점으로 계속 돌아옵니다.

OpenAI: GPT-5.x, Codex Goals, Operator 트랙

OpenAI의 이 기간은 두 가지 큰 움직임으로 요약됩니다. 첫 번째는 GPT-5 계열의 연속 업데이트입니다. GPT-5는 이 기간이 시작되기 전에 이미 출시돼 있었고, 기간 중에는 2025년 12월 GPT-5.2, 2026년 4월 24일 GPT-5.5(API·Codex·ChatGPT 제공)처럼 GPT-5.x 버전이 이어졌습니다. 발행 당시 본문은 「1월 말 GPT-5 출시」라고 적었으나 공식 발표와 맞지 않아 정정했습니다. 그동안 o 시리즈로 갈라져 있던 추론 트랙이 하나의 제품 안에서 사고량을 조절하는 형태로 합쳐진 것이 개발자에게는 가장 큰 단순화였습니다. 두 번째는 Codex Goals입니다. Codex 서브 제품을 단순 챗 완성에서 "고수준 목표를 받아 저장소에 몇 시간 동안 작업하는" 자율 코딩 에이전트에 가까운 무언가로 변모시켰습니다.

조용한 변화가 실무에서는 더 중요합니다. 발행 당시 본문은 3월 Operator 스택의 일반 출시로 컴퓨터 사용 API가 안정화되었고, Realtime API에 네이티브 도구 사용이 추가되었으며, 메모리 영속성이 명시적 저장·검색·망각 원시 기능을 가진 문서화된 표면으로 승격되었다고 정리했습니다. "어시스턴트가 세션을 넘어 나를 기억한다"를 만들기가 1분기 프로젝트에서 1주 프로젝트로 바뀐 셈입니다. 이 문단과 Codex Goals의 단계별 일정(2월 말~4월)은 2026-09-29에 OpenAI 공식 문서로 다시 확인하지 못한 당시 서술입니다.

가격 금액은 이번 갱신에서 공식 가격표로 다시 확인하지 못해 싣지 않습니다. 발행 당시 본문은 4o 패밀리가 Q3 2026에 끝나는 일정으로 단계적 폐기 중이라고 적었는데, 이것 역시 당시 전망으로 읽어야 합니다. Codex Goals 변화 자체와 일상 루프에 어떻게 엮을지에 대한 별도 정리는 본 블로그의 OpenAI Codex Goals 실전 활용 가이드 2026에서 더 깊이 다룹니다.

Anthropic: Claude Opus 4.5·4.6·4.7 그리고 Claude Code의 해

Anthropic은 6개월 동안 Opus 라인을 세 번 올렸습니다. 2025년 11월 24일 Claude Opus 4.5, 2026년 2월 5일 Claude Opus 4.6(2월 17일에는 Claude Sonnet 4.6), 그리고 2026년 4월 16일 Claude Opus 4.7입니다. 발행 당시 본문은 「2025년 12월 말 Claude 4.6」「2026년 3월 Claude 4.7 Sonnet」「2026년 5월 Claude 4.7 Opus」로 적었으나 공식 발표 날짜와 달라 정정했습니다. Anthropic의 Sonnet 발표 목록에는 4.7 버전이 없습니다(4.5 → 4.6 → 5 → 5.5). 공식 발표에서 Opus 4.7은 가장 어려운 소프트웨어 엔지니어링 작업에서 Opus 4.6보다 눈에 띄게 나아졌고, 추론량과 지연 사이를 더 세밀하게 고르는 xhigh 노력 수준이 새로 들어왔습니다. 각 릴리즈는 이름상 점진적이지만, 누적적으로 "에이전트를 두 시간 보내놓고 신뢰할 수 있는가" 카테고리에서 Anthropic의 입지를 굳혔습니다.

모델 주변에서 Claude Code는 완성된 제품으로 진화했습니다. Skills, Hooks, Sub-agents, 안정화된 settings.json 스키마가 CLI를 파워 유저 장난감에서 팀이 코드베이스 전체에 배포하는 도구로 바꿔놓았습니다. 2024년 후반 Anthropic이 시작한 Model Context Protocol은 이 기간에 사실상 업계 표준처럼 쓰이기 시작했고, 발행 당시 본문은 OpenAI, Google, 주요 IDE 벤더 대부분이 MCP를 지원한다고 정리했습니다. 프로토콜 레이어를 조용히 점유하면서 Anthropic은 어떤 모델을 호출하든 개발자 도구 스택의 중심에 자리 잡았습니다.

발행 당시 본문은 2026년 2월 Andrej Karpathy의 Anthropic 합류를 이 기간의 화제로 적었습니다. 2026-09-29에 Anthropic 뉴스룸에서 이를 알리는 공식 발표를 찾지 못했으므로 이를 사실로 단정하지 않으며, 매트릭스에서도 뺐습니다. Claude Code 자체의 일상 활용에 대해서는 Claude Code Skills 완벽 가이드가 4.6과 4.7 전환 이후에도 살아남은 패턴들을 다룹니다.

Google: Gemini 3, 3.5 Flash 그리고 가격 전쟁

Google의 이 기간 전략은 최고 품질과 함께 가격 대비 성능에서의 압박이었습니다. Gemini 2.5 계열은 이미 2025년 중에 나와 있었고, 2025년 11월 18일 Gemini 3 Pro 프리뷰가 Google을 다시 프론티어 대화의 중심에 올려놓았습니다. 이어 12월 17일 Gemini 3 Flash 프리뷰, 2026년 2월 19일 Gemini 3.1 Pro 프리뷰가 나왔습니다. 이 기간의 헤드라인은 2026년 5월 19일 정식(GA) 출시된 Gemini 3.5 Flash로, Google은 이를 에이전트·코딩 작업에서 지속적인 프론티어 성능을 내는 가장 지능적인 모델로 소개했습니다. 발행 당시 본문의 「12월 Gemini 2.5」「2월 Gemini 3.0」「4월 Gemini 3.5 Flash」는 Gemini API 공식 변경 기록과 달라 정정했고, 확인되지 않는 「200만 토큰 컨텍스트」「2.0 Flash 대비 출력 비용 약 60% 절감」 수치는 뺐습니다.

Google 검색의 AI Overviews는 "좋은 아이디어인지 다투던 단계"에서 검색 경험의 상시 요소로 자리를 옮겼습니다. 이는 모델 자체를 넘어선 의미를 가집니다. AI가 생성한 답변이 사용자와 대부분의 오픈 웹 사이에 끼어 있는 레이어가 되었고, 2026년 콘텐츠 전략은 이 레이어를 먼저 겨냥해 작성되어야 합니다. Google의 개발자 표면 안에서는 5월 중순 I/O 2026 발표가 Gemini의 Workspace, Android, 그리고 새로운 Code Assist 에이전트 티어 통합을 미리 보여주었습니다. 개별로는 충격적이지 않지만, 누적 효과는 Google이 다시 기본 선택지로 돌아왔다는 것입니다.

가격 포인트는 무거운 자동화를 굴리는 팀에 가장 중요합니다. LLM을 월 100만 회 이상 호출하는 무언가를 만든다면, 트래픽 하위 대부분은 Flash급 모델로 보내고 프론티어 모델은 마진 품질 차이가 비용을 정당화하는 상위 일부에만 남기는 편이 맞다는 것이 이 글의 판단입니다. 이 2티어 패턴이 진지한 LLM 제품의 기본 아키텍처가 되었고, 본문 후반 트렌드 섹션에서 다시 다룹니다.

Meta: Llama 4와 오픈 전략

Meta의 Llama 4는 이 기간보다 앞선 2025년 4월 5일에 발표됐습니다. 공개된 모델은 Llama 4 Scout(활성 17B·전체 109B 파라미터, 전문가 16개, 컨텍스트 1,000만 토큰)와 Llama 4 Maverick(활성 17B·전체 400B 파라미터, 전문가 128개)이고, 활성 288B·전체 약 2조 파라미터의 Llama 4 Behemoth는 발표 당시 학습 중인 미리보기로 소개됐습니다. 발행 당시 본문의 「12월부터 4월에 걸친 Llama 4 7B, 30B, 200B 릴리즈」와 「256K까지 안정적」은 Meta 공식 발표에서 확인되지 않는 구성이라 정정했습니다.

발행 당시 본문은 Meta가 절대 프론티어를 정면으로 쫓기보다 "공통 사이즈에서 충분히 좋은" 오픈 웨이트와 자가 호스팅 비용 하락을 결합해 추론 워크로드 점유를 노린다고 해석했습니다. 이는 이 글의 해석이며, 이 기간 Meta의 공식 전략 발표로 뒷받침되는 것은 아닙니다. 그 베팅이 통할지는 6분기 질문이지 6개월 질문이 아닙니다.

실무 관점의 교훈도 고쳐 적습니다. 발행 당시 본문은 「Llama 4 30B」를 알아야 할 사이즈로 꼽았지만 그런 모델은 공식 구성에 없습니다. Llama 4의 두 공개 모델은 모두 MoE라 토큰당 활성 파라미터(17B)는 작아도 전체 가중치(109B·400B)를 메모리에 올려야 하므로, 단일 GPU 배포가 가능한지는 양자화 방식과 메모리 용량으로 따로 계산해야 합니다. 30B급 밀집 모델이 필요하다면 아래 중국 절의 Qwen3-32B가 공식적으로 확인되는 선택지입니다.

중국 빅3: DeepSeek, Qwen, Doubao

이 기간의 중국 이야기는 외부 관찰자에게 가장 놀라운 것입니다. 2025년 11월에는 V4 이전 세대가 DeepSeek의 주력이었고, 2026년 4월 24일 DeepSeek-V4 프리뷰가 나왔습니다. V4-Pro(전체 1.6T·활성 49B 파라미터)와 V4-Flash(전체 284B·활성 13B 파라미터) 두 모델이며, 둘 다 100만 토큰 컨텍스트를 지원합니다. 발행 당시 본문의 「2026년 2월 V4」「671B MoE·토큰당 약 37B 활성」「Q1 2026 가장 많이 배포된 단일 오픈 모델」은 DeepSeek 공식 발표와 맞지 않아 정정했습니다(V4는 2분기에 나왔습니다). V4의 라이선스 조건은 이번 갱신에서 다루지 않았습니다.

알리바바의 Qwen3는 2025년 4월 29일에 이미 공개돼 있었습니다. MoE 모델 Qwen3-235B-A22B와 Qwen3-30B-A3B, 밀집 모델 Qwen3-32B부터 Qwen3-0.6B까지로 구성됩니다. 발행 당시 본문의 「2026년 3월 Qwen 3 패밀리」는 날짜가 맞지 않아 정정했고, 「Qwen 3 Coder 32B」라는 모델명과 「현존 최강 소형 오픈 코더」라는 평가, 알리바바의 오픈 웨이트 추론 서비스량 추정은 이번에 공식 자료로 확인하지 못해 뺐습니다. ByteDance의 Doubao는 네이티브 크로스 모달 능력으로 중국어권 시장에서 중요하다는 것이 발행 당시의 평가였으나, 본문이 적은 「2026년 4월 Doubao 1.6」 출시 시점은 공식 발표로 뒷받침되지 않아 당시 서술로만 남깁니다. 이 모델들을 쓸지 말지는 데이터 처리 입장에 크게 좌우되지만, 존재하지 않는 척하는 것은 더 이상 방어 가능한 입장이 아닙니다. 전체 지형은 본 블로그의 DeepSeek vs Qwen vs Doubao 중국 LLM 비교 2026에서 다룹니다.

기술적 곁다리 하나만 짚자면, DeepSeek V4를 대상으로 한 스티어링 벡터 연구가 작지만 의미 있는 해석 가능성의 문을 열었다는 것이 발행 당시의 평가입니다. 실무적 함의는 LLM 스티어링 벡터와 DeepSeek V4 글에서 다룹니다.

xAI: Grok 4, 언더독 서사

xAI의 Grok 4는 이 기간보다 앞선 2025년 7월 9일에 발표됐습니다. 발행 당시 본문의 「2025년 11월 말 Grok 3가 처음으로 프론티어 권 진입」「2026년 4월 Grok 4」는 공식 발표와 맞지 않아 정정했고, 이 기간 중 Grok 4 후속 버전의 공식 발표는 이번 갱신 범위에 넣지 않았습니다. 발행 당시 이 글의 평가는 xAI가 밈에서 벗어났지만 여전히 주로 X와 독립 컨슈머 앱을 통해 배포되어 개발자의 기본 선택지가 되기 어렵다는 것이었고, 학습 클러스터 Colossus의 규모가 모델에 반영되고 있다는 것이었습니다.

실무자 관점에서 Grok 계열은 자체 검색 레이어를 만들지 않고도 실시간 웹 그라운딩이 필요할 때의 선택지이자 백업 모델로 볼 만합니다. 제약은 주로 문화적인 것입니다. 많은 엔터프라이즈가 조달 이유로 여전히 xAI를 X와 너무 가까운 것으로 취급합니다. 스택이 이미 프로바이더 사이를 로드 밸런싱하는 라우터를 호출한다면, Grok을 옵션으로 추가하는 데 몇 시간이면 되고, 다음 프로바이더 장애에 대한 회복력을 얻습니다.

Mistral, Cohere 그리고 2티어 통합

2티어 프론티어 랩들도 이 기간에 움직였습니다. Mistral Large 3는 2025년 12월 2일 Mistral 3 발표와 함께 나왔습니다. 활성 41B·전체 675B 파라미터의 희소 MoE이며 Apache 2.0 라이선스로 공개됐고, 3B·8B·14B 밀집 모델인 Ministral 3 시리즈가 함께 나왔습니다. 발행 당시 본문의 「1월 Mistral Large 3」는 날짜를 정정했습니다. 본문이 함께 적은 Codestral 2·Pixtral 2와 Cohere의 Command R-Plus 2026 업데이트는 공식 발표로 뒷받침되지 않은 당시 서술입니다. 유럽 거주 인프라와 규제 대응이 Mistral의 강점이고, Cohere는 엔터프라이즈 RAG에 집중한다는 것이 발행 당시의 평가입니다.

2025년 말까지 대화에 있던 몇몇 작은 행위자들은 사실상 빠졌다는 것이 발행 당시의 관찰이었습니다. AI21의 Jamba 패밀리는 매우 긴 컨텍스트만 필요한 니치 선택지가 되었고, Inflection은 프론티어 컨슈머 모델에서 피벗했으며, Reka 외 몇몇은 기술적으로 흥미로운 작업을 계속 출시하지만 벤치마크 상위에서 경쟁하지 않습니다. 시장은 OpenAI, Anthropic, Google, Meta(오픈), DeepSeek, Alibaba/Qwen, xAI 정도로 좁혀지고, Mistral과 Cohere는 강한 지역 또는 버티컬 옵션으로 남는다는 것이 이 글의 판단입니다.

로컬 LLM: Llama.cpp, Ollama, vLLM, MLX

로컬과 자가 호스팅 생태계는 빠르게 움직였습니다. Llama.cpp가 Vulkan과 ROCm 경로를 강화하면서 NVIDIA 전용 가정이 약해졌습니다. Strix Halo PC(AMD의 고메모리 APU 플랫폼)에서 큰 모델을 실용 속도로 돌리는 것이 하나의 제품 카테고리가 되었습니다. Ollama가 주류 개발자 도구로 진입해 안정적인 모델 레지스트리와 IDE 통합을 갖췄습니다. vLLM은 배칭과 투기적 디코딩 개선으로 프로덕션 배포의 추론 비용을 낮췄고, Apple의 MLX는 M 시리즈 Mac을 30B에서 70B 파라미터 대역의 메모리 대비 가격이 좋은 로컬 추론 옵션으로 만들었습니다. 통합 메모리가 넉넉한 최신 Mac이면 Qwen3-32B 같은 30B급 모델을 무리 없이 올릴 수 있다는 것이 발행 당시의 평가입니다. 이 절에 나오는 vLLM·MLX의 버전 번호와 기기 사양은 공식 문서로 재검증하지 않은 당시 서술입니다.

결합된 효과는 저관여 LLM 트래픽의 실질적 점유가 API를 떠나고 있다는 것입니다. 개인 노트 어시스턴트, IDE 자동 완성, 팀 문서 요약 등 데이터 민감도, 지연, 비용이 절대 프론티어보다 더 중요한 작업이 로컬 추론으로 옮겨 가는 중입니다. 하드웨어 전체 지형은 본 블로그의 로컬 LLM 하드웨어 선택 가이드 2026에서 다룹니다.

AI 코딩 도구: Cursor, Claude Code, Codex, Aider, Cline

AI 코딩 도구는 반기의 가장 빨리 움직인 하위 카테고리였습니다. Cursor의 에이전트 모드가 멀티 파일 리팩토링을 안정적으로 처리하는 무언가로 성숙했습니다. Claude Code는 진지한 자율 코딩 워크플로의 지배적 CLI 도구가 되었습니다. 발행 당시 기준으로 30분 이상 걸리는 작업을 굴린다면 Claude Opus 4.7을 쓰는 Claude Code가 기본값이었습니다. OpenAI Codex 서브 제품의 Codex Goals는 가장 강한 원샷 생성 표면입니다. 모델 출력을 보고 빠르게 조정하는 타이트한 반복 루프에는 이기기 어렵습니다.

Aider는 오픈소스 베이스라인으로 강력함을 유지했고, Cline은 IDE를 떠나지 않고 인에디터 경험을 원하는 개발자를 위한 VS Code 통합 에이전트 니치를 채웠습니다. 이 글의 평가는 어떤 단일 도구도 모든 워크플로를 지배하지 않는다는 것입니다. 인에디터 페어 프로그래밍은 Cursor, 긴 자율 작업은 Claude Code, 원샷 생성은 Codex, 그리고 완전 검사가 가능한 도구가 필요할 때는 Aider를 오픈 폴백으로. 3개월 비교는 본 블로그의 Claude Code vs Codex 3개월 사용 후기 2026에서 로테이션 패턴을 상세히 다룹니다.

6개월 핵심 트렌드

개별 랩에서 한 발 물러서면, 네 가지 트렌드가 이 기간을 정의합니다.

에이전트 AI가 데모에서 프로덕션으로 이동했습니다. 반기 동안 프론티어 모델 릴리즈의 공통 기능은 더 길고 더 안정적인 자율 체인이었습니다. Claude Opus 4.7로 긴 자율 코딩 세션이 현실적이 되었고, GPT-5.x와 Gemini 3 계열로 모델이 스스로 계획을 제안, 브라우징, 요약, 반복하는 멀티스텝 리서치가 동작합니다. 남은 실패 양상들은 진짜이지만 프로덕션 사용을 막지는 않습니다.

추론 모델이 별도 제품 카테고리에서 사라졌습니다. o 시리즈는 GPT-5 계열의 사고량 조절 안으로 들어갔고, Claude는 모델이 스스로 사고량을 정하는 방식으로 옮겨 갔으며, Gemini 3 계열도 내부 추론을 기본으로 씁니다. 지난 1년 사용자를 혼란시킨 "사고 모델" 토글은 대부분 사라졌고, 그 단순화 자체가 품질 개선입니다.

멀티모달이 기본 사양이 되었습니다. 비전은 프론티어 모델에서 동작하고, 오디오 입출력은 표준이며, 비디오 이해는 상위 랩 전반에서 유능합니다. 차별화 요소는 더 이상 "멀티모달이 있나"가 아니라 "멀티모달 입력과 도구 사용을 얼마나 잘 엮느냐"입니다.

30B급에서 더 작은 게 더 좋다가 진짜입니다. Qwen3-32B와 Qwen3-30B-A3B, 그리고 더 작은 DeepSeek 디스틸들이 이 범위에 있고, 실제로 프론티어 IQ가 필요하지 않은 작업의 상당수를 처리합니다. 이 대역이 배포 빈도 기준 최대 수혜라는 것은 이 글의 관찰이며 측정 자료는 아닙니다.

벤치마크 변화: MMLU 포화, SWE-bench 폭증

벤치마크 지형도 실질적으로 바뀌었습니다. 발행 당시 본문은 MMLU가 사실상 포화되어 프론티어 모델이 88~91 사이에 몰려 있고, SWE-bench 상위 점수는 6개월 동안 약 2배(2025년 11월 49%에서 2026년 5월 Verified 90% 초과)로 뛰었으며, GPQA 상위 점수는 60대 초반에서 70대 후반으로 이동했다고 적었습니다. 이 수치들은 2026-09-29에 공식 리더보드로 다시 확인하지 못한 당시 서술이므로, 인용하려면 SWE-bench 등 원 리더보드의 최신 값을 쓰십시오. ARC-AGI 계열은 여전히 가장 어려운 공개 벤치마크로 꼽히며, 랩들이 가장 가시적으로 경쟁하는 곳입니다.

벤치마크를 읽는 엔지니어를 위한 교훈은 SWE-bench가 "이 모델이 코딩에 좋은가"를 묻는 가장 유용한 단일 숫자에 가깝고, MMLU 성능과 실세계 효용성 사이의 격차가 크다는 것입니다. 어떤 모델이 MMLU에서 높은 점수를 받고도 프로덕션 디버깅에서 실패할 수 있습니다. 벤치마크 숫자는 항상 자신의 워크로드에 대한 작업별 평가와 함께 봐야 합니다.

개발자가 내재화해야 할 5가지 시사점

6개월 그림에서 압축된 조언입니다.

  1. 코딩 도구를 최소 두 개 로테이션하십시오. Claude Code + Codex, 또는 Claude Code + Cursor가 가장 회복력 있는 패턴입니다. 실패 양상이 서로 다르고, 한 프로바이더가 장애일 때도 작업이 계속됩니다.
  2. 2티어 라우팅 레이어를 세우십시오. 트래픽의 60~80%를 Gemini Flash 또는 Claude Haiku급으로 보내고, 프론티어 모델은 정말 필요한 호출에만 예약합니다. 비율은 이 글의 권고이며, 자신의 호출 분포로 조정하십시오.
  3. 모델 하나는 로컬로 굴려보십시오. M 시리즈 Mac 또는 고성능 GPU를 단 워크스테이션에서 30B급 모델은 오프라인 작업, 민감 데이터를 커버하고, "이 작업이 API 없이 가능한가"의 기준점을 줍니다.
  4. MCP를 기본값으로 취급하십시오. Model Context Protocol은 새로운 "AI를 위한 REST"에 가깝습니다. ChatGPT, Claude, Gemini에 각각 자체 통합을 만들기 전에 MCP 서버 하나로 연결할 수 있는지부터 확인하십시오.
  5. 벤치마크를 분기마다 재평가하십시오. 11월 평가에서 이긴 모델이 오늘은 2티어일 가능성이 큽니다. 최소 분기마다 평가 스위트를 돌리고, 눈을 뜬 채로 새 기본값을 고르십시오.

2026년 하반기 전망(작성 당시)

아래는 2026년 5월 작성 당시의 전망입니다. 검증된 예측이 아니라 당시 전망이며, 실제로 확인된 하반기 출시는 이후 경과 절에 정리했습니다.

첫째, 에이전트 시스템이 파워 유저의 기본 UI가 됩니다(당시 전망). UI 진화는 챗봇이 2023년 거친 것과 비슷합니다. 1분기 실험적, 4분기 주류. 연말까지 주요 랩이 옵트인 베타가 아닌 기본 제품 일부로 에이전트 표면을 출시할 것으로 예상했습니다.

둘째, 모델 차별화 축이 순수 IQ에서 메모리, 도구 사용, 작업당 가격으로 이동합니다(당시 전망). 경쟁은 주변 스택으로 옮겨가고, 메모리를 먼저 제대로 푸는 랩이 컨슈머 마인드셰어의 의미 있는 점유를 가져갈 가능성이 크다고 보았습니다.

셋째, 온디바이스와 랩탑급 추론이 저관여 트래픽의 큰 점유를 조용히 가져갑니다(당시 전망). M 시리즈 Mac과 Strix Halo PC가 30~70B 모델을 실용 속도로 굴리면서, 컨슈머 사용의 상당 부분이 API에서 이탈한다고 보았습니다. 저가 티어 API 수익에는 나쁘고, 사용자 프라이버시에는 좋습니다.

하반기 로드맵을 세운다면 이 셋을 염두에 두되, "다음 모델을 기다리자" 함정을 피하십시오. 필요한 능력은 이미 오늘 굴릴 수 있는 스택에 들어 있습니다.

결론: 6개월의 구조적 시프트

11월부터 5월까지의 윈도우는 또 하나의 업그레이드 사이클이 아니었습니다. 에이전트 시스템이 진짜가 된 시점, 오픈 웨이트가 의미 있는 축에서 프론티어 격차를 좁힌 시점, 가격이 아키텍처 패턴을 바꿀 만큼 떨어진 시점, 그리고 MCP가 도구가 세워질 표준 레이어로 자리 잡은 시점이었습니다. 그중 어느 하나라도 평년 1년치 진보입니다. 네 가지가 동시에 일어났다는 사실이 이 기간을 구조적 시프트로 만듭니다.

빌더의 실용적 자세는 사이클 초기부터 변하지 않았습니다. 도구에 가까이 머물고, 최소 두 개를 로테이션하고, 분기마다 스택을 평가하고, 완벽한 기본값이 출현하기를 기다리려는 유혹에 저항하십시오. 프론티어는 그게 가능할 만큼 천천히 움직이지 않습니다. 빌더의 경쟁 우위는 사용 가능한 조각들을 진짜 문제를 푸는 무언가로 얼마나 빨리 조합하느냐에 있지, 어느 랩 로고가 API 호출에 박혀 있는지에 있지 않습니다. 매트릭스를 읽고, 셈을 돌리고, 다음 것을 출하하십시오.
