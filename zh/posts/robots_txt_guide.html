什么是 robots.txt？

robots.txt 是位于网站根目录下的一个文本文件，用于告诉搜索引擎爬虫（机器人）网站的哪些部分可以抓取、哪些部分不应访问。该文件遵循名为 Robots Exclusion Protocol（机器人排除协议） 的网页标准，所有主流搜索引擎（谷歌、Bing、Naver 等）都会遵循这一标准。

robots.txt 的重要性

  • 抓取控制：区分爬虫应访问与不应访问的页面
  • 节省服务器资源：避免不必要的抓取，降低服务器负载
  • 内容保护：防止敏感信息或重复内容出现在搜索结果中
  • 优化抓取预算：通过调节抓取频率与深度，让重要页面获得优先

robots.txt 文件的基本结构

robots.txt 文件格式非常简单，基本结构如下：

User-agent: [爬虫名称]
Disallow: [禁止访问的路径]
Allow: [允许访问的路径]
Sitemap: [站点地图 URL]

主要指令（directives）说明

  • User-agent：指定规则适用于哪个搜索引擎爬虫
    • User-agent: * - 适用于所有爬虫
    • User-agent: Googlebot - 仅适用于谷歌爬虫
  • Disallow：指定禁止抓取的路径
    • Disallow: /private/ - 禁止抓取 /private/ 目录
    • Disallow: / - 禁止抓取整站
    • Disallow: - 不做任何禁止（全部允许）
  • Allow：为 Disallow 规则设置例外，允许访问特定路径
    • Disallow: /private/
    • Allow: /private/public.html - 仅允许 private 目录下的 public.html
  • Sitemap：指定站点地图文件的位置
    • Sitemap: https://example.com/sitemap.xml

编写 robots.txt 时的注意事项

1. 把文件放在正确的位置

robots.txt 文件必须放在网站的根目录下。如果放在其他位置，爬虫是识别不到的。

正确位置：https://example.com/robots.txt
错误位置：https://example.com/public/robots.txt

2. 大小写敏感

部分指令与路径是区分大小写的。尤其是 URL 路径必须完全匹配大小写。

User-agent: Googlebot (O)
user-agent: Googlebot (X - 部分爬虫能识别，但不推荐)

Disallow: /Private/ (仅屏蔽 Private 目录)
Disallow: /private/ (仅屏蔽 private 目录，与上一条是不同目录)

3. 通配符的用法

部分爬虫（谷歌、Bing 等）支持用于模式匹配的通配符：

  • *：匹配 0 个或多个字符
  • $：表示 URL 的结尾
Disallow: /*.pdf$ (屏蔽所有 PDF 文件)
Disallow: /private* (屏蔽所有以 private 开头的 URL)

4. 安全相关注意事项

重要：robots.txt 不是安全手段！不能用来保护敏感信息或机密页面。

  • robots.txt 文件任何人都可以查看（可通过 https://example.com/robots.txt 访问）
  • 恶意爬虫可能会无视 robots.txt 的规则
  • 敏感信息应使用密码保护、IP 限制等安全手段进行保护

有效的 robots.txt 示例

1. 基础版 robots.txt（适合大多数小型网站）

User-agent: *
Disallow:
Sitemap: https://example.com/sitemap.xml

上述示例允许所有爬虫抓取整站，并告知爬虫站点地图的位置。

2. 屏蔽管理页面与重复内容

User-agent: *
Disallow: /admin/
Disallow: /temp/
Disallow: /duplicate-content/
Disallow: /*?sort=
Disallow: /*?filter=
Allow: /admin/public-stats.php
Sitemap: https://example.com/sitemap.xml

此示例屏蔽管理页面、临时文件以及因排序/过滤产生的重复页面，但允许公开的统计页面。

3. 针对不同搜索引擎应用不同规则

User-agent: Googlebot
Disallow: /google-excluded/

User-agent: Bingbot
Disallow: /bing-excluded/

User-agent: *
Disallow: /private/
Disallow: /temp/
Sitemap: https://example.com/sitemap.xml

此示例为谷歌和 Bing 分别指定不同规则，其余爬虫则套用通用规则。

4. 面向资源优化的 robots.txt

User-agent: *
Disallow: /api/
Disallow: /large-images/
Disallow: /*.zip$
Disallow: /*.pdf$
Disallow: /*?*
Crawl-delay: 10
Sitemap: https://example.com/sitemap.xml

此示例限制对 API 调用、大图片、压缩包、PDF 等消耗服务器资源较多内容的抓取，并将抓取间隔设置为 10 秒（仅部分搜索引擎支持 Crawl-delay）。

robots.txt 与站点地图的关系

在搜索引擎优化（SEO）中，robots.txt 与 sitemap.xml 扮演着互补的角色：

  • robots.txt：告知爬虫不应访问的页面
  • sitemap.xml：告知爬虫重要页面及其元数据（最后修改时间等）

两者配合使用，搜索引擎可以更高效地对网站进行索引。在 robots.txt 中明确指出 sitemap.xml 的位置，是值得推荐的做法：

User-agent: *
Disallow: /private/
Sitemap: https://example.com/sitemap.xml

robots.txt 的测试方法

在正式应用 robots.txt 之前，确认其书写正确非常重要：

1. 使用 Google Search Console

Google Search Console 提供的 robots.txt 测试工具可以检查语法错误，并测试特定 URL 是否被允许或屏蔽抓取。

  1. 登录 Google Search Console
  2. 选择 “设置” > “robots.txt 测试工具” 菜单
  3. 输入 robots.txt 内容或载入当前文件
  4. 输入要测试的 URL，然后点击 “测试” 按钮

2. 手动测试

部署 robots.txt 文件后，直接访问以下 URL，确认能否正确显示： 

https://your-domain.com/robots.txt

常见错误与解决方案

1. 屏蔽了所有爬虫

User-agent: *
Disallow: /

上述规则会屏蔽所有爬虫的访问。对测试环境或开发中的站点可能合适，但在正式公开的网站上会导致其无法出现在搜索引擎中。

2. 不合适的文件路径

Disallow: admin

路径必须始终以斜杠（/）开头。正确写法：

Disallow: /admin

3. robots.txt 中未包含站点地图

在 robots.txt 中包含 Sitemap URL，可帮助搜索引擎更容易地找到站点地图：

Sitemap: https://example.com/sitemap.xml

4. 不同 User-agent 组之间没有空行

User-agent: Googlebot
Disallow: /google-only/
User-agent: *
Disallow: /private/

不同的 User-agent 组之间建议加入空行：

User-agent: Googlebot
Disallow: /google-only/

User-agent: *
Disallow: /private/

robots.txt 文件的更新周期

每次爬虫访问网站时都会检查 robots.txt 文件，因此修改会较快生效。但仍有几点需要注意：

  • 大多数搜索引擎会对 robots.txt 文件进行缓存，在一段时间内可能不会重新获取
  • 谷歌通常每天会重新抓取一次 robots.txt
  • 如遇重要变更，可在 Google Search Console 中重新提交 robots.txt，请求立即生效

实战技巧：通过 robots.txt 进行 SEO 优化

1. 解决重复内容问题

屏蔽带有 URL 参数的页面，避免搜索引擎对重复内容进行索引：

User-agent: *
Disallow: /*?sort=
Disallow: /*?filter=
Disallow: /*?page=
Disallow: /*?session=

2. 优化抓取预算

搜索引擎会为每个站点分配有限的“抓取预算”。屏蔽不重要的页面，可以让重要页面获得更多抓取资源：

User-agent: *
Disallow: /old-content/
Disallow: /print-versions/
Disallow: /tags/

3. 允许抓取但不在搜索结果中显示

如果希望某个页面能被抓取但不显示在搜索结果中，应在该页面上使用 noindex meta 标签，而不是借助 robots.txt：

<meta name="robots" content="noindex, follow">

该方式允许爬虫跟踪页面上的链接，同时让该页面本身不出现在搜索结果中。

4. 分阶段调整

对于大型网站来说，一次性大幅修改 robots.txt 可能带来意外后果。建议分阶段应用变更，并持续监控搜索流量。

结语

robots.txt 看似简单，却是能显著影响网站搜索引擎可见度与性能的强大工具。配置得当的 robots.txt 能带来以下益处：

  • 引导搜索引擎聚焦于重要内容
  • 减少不必要抓取带来的服务器压力
  • 帮助解决重复内容问题
  • 与站点地图配合使用，最大化索引效率

每个网站都有独特的需求，robots.txt 应根据网站结构与目标进行定制化配置。定期审查与更新，能让搜索引擎更高效地抓取与索引你的网站。

最后请记住，robots.txt 只是 SEO 策略的一部分，必须与 meta 标签、站点地图、结构化数据、优质内容等其他要素一起综合考虑。
