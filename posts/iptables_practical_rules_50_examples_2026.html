iptables 실전 룰셋 50선 - 시나리오별 방화벽 규칙 모음

10대 시나리오 카테고리 × 5선 = 즉시 적용 가능한 50개 룰

2026-05-18 IT/기술

이 게시물은 쿠팡 파트너스 활동의 일환으로, 이에 따른 일정액의 수수료를 제공받습니다.

서론: 왜 iptables 50선인가

iptables는 Linux 서버 보안의 가장 오래되고 견고한 도구입니다. 2026년 현재 nftables가 표준으로 자리잡았지만 여전히 RHEL 7/8 계열, 임베디드 장비, 다수의 컨테이너 호스트에서 iptables 또는 iptables-translate가 활발하게 사용됩니다. 문제는 명령어 자체가 직관적이지 않다는 점입니다. 한 번 잘못 입력하면 SSH 세션이 끊겨 콘솔로 가야 하는 사고가 비일비재합니다.

본 글은 그런 시행착오를 줄이기 위해 10대 시나리오 카테고리 × 5개씩 = 총 50가지 실전 룰셋을 정리합니다. 각 룰셋은 즉시 복사해서 적용할 수 있는 명령어, 의미 해석, 적용 시나리오 3요소로 구성됩니다. 단순한 문법 나열이 아닌 "언제 무엇을 써야 하는가"에 초점을 맞췄습니다.

본 사이트의 iptables 생성기와 함께 사용하면 효과가 배가됩니다. 글에서 개념을 익히고, 도구에서 실제 룰을 시각적으로 조합한 뒤 그대로 서버에 적용하는 흐름이 가장 빠릅니다.

1. 기본 정책 설정 (5선)

모든 방화벽의 출발점입니다. 정책(POLICY)을 명시적으로 정의해야 의도하지 않은 트래픽 차단·허용을 막을 수 있습니다.

[#1] 기본 정책 DROP + 명시적 허용 방식
sudo iptables -P INPUT DROP
sudo iptables -P FORWARD DROP
sudo iptables -P OUTPUT ACCEPT
의미: INPUT/FORWARD는 기본 차단, 명시적으로 허용한 것만 통과. OUTPUT은 자유.
적용: 일반 서버 보안 표준. 가장 안전한 출발점.
[#2] ESTABLISHED·RELATED 연결 허용
sudo iptables -A INPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT
의미: 이미 수립된 연결과 그 부속 연결(FTP-data 등)을 자동 허용.
적용: 거의 모든 INPUT 체인의 첫 번째 규칙으로 들어가야 함.
[#3] 루프백 인터페이스 허용
sudo iptables -A INPUT -i lo -j ACCEPT
sudo iptables -A OUTPUT -o lo -j ACCEPT
의미: 127.0.0.1 통신 허용. 다수 데몬이 IPC로 사용하므로 필수.
적용: 정책 DROP 직후 가장 먼저 등록.
[#4] INVALID 패킷 차단
sudo iptables -A INPUT -m conntrack --ctstate INVALID -j DROP
의미: 잘못된 시퀀스 번호·플래그 등 비정상 패킷 차단.
적용: 기본 위생 룰. 포트 스캐너 회피에도 도움.
[#5] ICMP 핑 허용 (운영 모니터링용)
sudo iptables -A INPUT -p icmp --icmp-type echo-request -m limit --limit 10/sec -j ACCEPT
의미: 초당 10회까지 ping 응답. 핑 플러드 방지.
적용: 모니터링·NMS가 핑으로 헬스체크할 때 필수.
즉시 생성: iptables 생성기에서 INPUT 체인 + ESTABLISHED·loopback 체크박스 한 번에 출력.

2. SSH 보안 강화 (5선)

서버 침해의 절반은 22번 포트로 들어옵니다. SSH는 가장 우선적으로 보호해야 할 서비스입니다.

[#6] SSH 포트 변경 후 허용
sudo iptables -A INPUT -p tcp --dport 2222 -j ACCEPT
의미: 22 대신 2222 포트로 SSH 접근. 자동 봇 스캔 95% 회피.
적용: sshd_config의 Port 2222와 함께 적용.
[#7] SSH 화이트리스트 (특정 IP만)
sudo iptables -A INPUT -p tcp -s 203.0.113.0/24 --dport 22 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 22 -j DROP
의미: 사무실 대역에서만 SSH 접속, 나머지 전 차단.
적용: 고정 IP 환경(VPN·사무실)에서 가장 강력한 SSH 방어.
[#8] SSH 브루트포스 Rate Limit
sudo iptables -A INPUT -p tcp --dport 22 -m conntrack --ctstate NEW \
    -m recent --set --name SSH
sudo iptables -A INPUT -p tcp --dport 22 -m conntrack --ctstate NEW \
    -m recent --update --seconds 60 --hitcount 4 --name SSH -j DROP
의미: 60초 안에 4번 이상 신규 접속 시 자동 차단.
적용: fail2ban 대신 커널 레벨에서 처리.
[#9] 국가 단위 SSH 차단 (xtables-addons geoip)
sudo iptables -A INPUT -p tcp --dport 22 -m geoip --src-cc CN,RU,KP -j DROP
의미: 특정 국가 IP에서 들어오는 SSH 전부 차단.
적용: 글로벌 트래픽 불필요한 내부망 서버. xtables-addons 패키지 필요.
[#10] 포트 노킹 (knock 시퀀스)
sudo iptables -N SSH_PHASE2
sudo iptables -A INPUT -p tcp --dport 7000 -m recent --name PH1 --set -j DROP
sudo iptables -A INPUT -p tcp --dport 8000 -m recent --name PH1 --rcheck \
    -m recent --name PH2 --set -j DROP
sudo iptables -A INPUT -p tcp --dport 22 -m recent --name PH2 --rcheck -j ACCEPT
의미: 7000 → 8000 순서로 노킹해야 SSH 열림.
적용: 정적 IP가 없고 노출 최소화가 필요한 경우.

3. 웹서버 보안 (HTTP/HTTPS) (5선)

80/443은 외부에 열어야 하므로 가장 공격이 빈번한 표면입니다. Rate limit과 SYN flood 방어가 핵심.

[#11] 80/443 일반 허용
sudo iptables -A INPUT -p tcp -m multiport --dports 80,443 -j ACCEPT
의미: HTTP·HTTPS 두 포트 동시 허용.
적용: 모든 공개 웹서버 기본.
[#12] Cloudflare IP만 80/443 허용
for ip in $(curl -s https://www.cloudflare.com/ips-v4); do
    sudo iptables -A INPUT -p tcp -s $ip -m multiport --dports 80,443 -j ACCEPT
done
sudo iptables -A INPUT -p tcp -m multiport --dports 80,443 -j DROP
의미: CDN 우회 직접 공격 차단. CF를 거치지 않으면 무조건 DROP.
적용: Cloudflare 프록시 사용 시 origin 보호 필수.
[#13] 동시 연결 수 제한 (DDoS 기본)
sudo iptables -A INPUT -p tcp --dport 80 -m connlimit --connlimit-above 50 -j REJECT
의미: 같은 IP에서 80번 포트에 50개 이상 동시 연결 거부.
적용: 봇·HTTP flood 1차 완화.
[#14] Slowloris 방어 (느린 HTTP 연결)
sudo iptables -A INPUT -p tcp --dport 80 -m hashlimit \
    --hashlimit-name http_slow --hashlimit-mode srcip \
    --hashlimit-above 30/min --hashlimit-burst 20 -j DROP
의미: IP당 분당 30개 초과 연결 차단. 느린 다중 연결로 자원 고갈 방지.
적용: Apache·Nginx 앞단에 무료 Slowloris 보호.
[#15] SYN flood 방어
sudo iptables -A INPUT -p tcp --syn -m limit --limit 1/sec --limit-burst 3 -j ACCEPT
sudo iptables -A INPUT -p tcp --syn -j DROP
의미: SYN 패킷 초당 1개로 제한, 버스트 3.
적용: 커널 tcp_syncookies와 병행 권장.
웹 룰셋 자동 생성: iptables 생성기에서 "웹서버" 프리셋 선택.

4. 데이터베이스 보안 (5선)

DB는 절대 외부에 열면 안 됩니다. 다층 방어가 원칙이며 iptables는 그 중 가장 강력한 외곽선입니다.

[#16] MySQL 외부 접근 차단 + 앱서버 허용
sudo iptables -A INPUT -p tcp -s 10.0.1.10 --dport 3306 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 3306 -j DROP
의미: 특정 앱서버(10.0.1.10)만 MySQL 접근.
적용: 모든 운영 DB의 기본 형태.
[#17] PostgreSQL 5432 내부망 한정
sudo iptables -A INPUT -p tcp -s 10.0.0.0/16 --dport 5432 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 5432 -j DROP
의미: 사설 대역만 PG 접근 허용.
적용: VPC·VPN으로 격리된 환경.
[#18] Redis 6379 (bind 127.0.0.1 + 방화벽 이중)
sudo iptables -A INPUT -p tcp ! -s 127.0.0.1 --dport 6379 -j DROP
의미: redis.conf bind와 별개로 iptables에서도 외부 차단.
적용: Redis 인증 미설정 환경에서 필수.
[#19] MongoDB 27017 외부 전면 차단
sudo iptables -A INPUT -p tcp --dport 27017 -i ! lo -j DROP
의미: 루프백 외 모든 인터페이스에서 27017 차단.
적용: 단일 서버 MongoDB 사고 방지 최후 보루.
[#20] Memcached 11211 화이트리스트
sudo iptables -A INPUT -p tcp -s 10.0.1.0/24 --dport 11211 -j ACCEPT
sudo iptables -A INPUT -p udp -s 10.0.1.0/24 --dport 11211 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 11211 -j DROP
sudo iptables -A INPUT -p udp --dport 11211 -j DROP
의미: Memcached UDP 증폭 공격 방지. TCP·UDP 둘 다 화이트리스트.
적용: 인증 없는 Memcached 노출 시 DDoS 반사 우려.

5. Docker 컨테이너 환경 (5선)

Docker는 자체적으로 iptables 룰을 다수 생성하므로 충돌이 빈번합니다. DOCKER-USER 체인을 활용해야 합니다.

[#21] Docker 데몬 포트 (2375/2376) 보안
sudo iptables -A INPUT -p tcp -m multiport --dports 2375,2376 -j DROP
의미: Docker API 원격 노출 전면 차단. 노출 시 즉시 컨테이너 탈취 위험.
적용: 모든 Docker 호스트 필수.
[#22] DOCKER-USER 체인으로 컨테이너 외부 접근 제어
sudo iptables -I DOCKER-USER -s 203.0.113.0/24 -j ACCEPT
sudo iptables -I DOCKER-USER -j DROP
의미: 특정 대역만 컨테이너로 들어가는 트래픽 허용. -p 옵션과 무관하게 동작.
적용: Docker가 자동 생성하는 룰 위에 안전하게 정책 추가.
[#23] 컨테이너 간 통신 격리
sudo iptables -I DOCKER-USER -i docker0 -o docker0 -j DROP
의미: 같은 bridge 안의 컨테이너 간 직접 통신 차단.
적용: 멀티테넌트 컨테이너 호스트. --icc=false 대안.
[#24] Swarm 노드 간 통신 (2377/7946/4789)
sudo iptables -A INPUT -p tcp -s 10.0.0.0/24 --dport 2377 -j ACCEPT
sudo iptables -A INPUT -p tcp -s 10.0.0.0/24 --dport 7946 -j ACCEPT
sudo iptables -A INPUT -p udp -s 10.0.0.0/24 --dport 7946 -j ACCEPT
sudo iptables -A INPUT -p udp -s 10.0.0.0/24 --dport 4789 -j ACCEPT
의미: Swarm 클러스터 노드 간 관리·gossip·overlay 통신.
적용: Swarm 클러스터 자체에는 열고 외부엔 닫는다.
[#25] 컨테이너 egress 제한
sudo iptables -I DOCKER-USER -s 172.17.0.0/16 -d 169.254.169.254 -j DROP
의미: 컨테이너가 EC2 메타데이터 엔드포인트 접근 차단. SSRF 방어.
적용: AWS·GCP 클라우드 호스트에서 컨테이너 탈취 피해 최소화.

6. Kubernetes 노드 (5선)

K8s 컨트롤플레인과 워커 노드는 각각 열어야 할 포트가 정해져 있습니다. 내부 통신용 포트는 외부에 절대 노출 금지.

[#26] API Server 6443 화이트리스트
sudo iptables -A INPUT -p tcp -s 10.0.0.0/16 --dport 6443 -j ACCEPT
sudo iptables -A INPUT -p tcp -s 203.0.113.5 --dport 6443 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 6443 -j DROP
의미: 클러스터 내부망과 관리자 IP만 kube-apiserver 접근.
적용: 마스터 노드 표준 정책.
[#27] Kubelet 10250 내부 노드에서만
sudo iptables -A INPUT -p tcp -s 10.0.0.0/16 --dport 10250 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 10250 -j DROP
의미: kubelet API는 컨트롤플레인에서만 호출. 외부 노출 시 권한 우회 위험.
적용: 모든 워커 노드.
[#28] NodePort 범위 (30000-32767) 제한
sudo iptables -A INPUT -p tcp -s 10.0.0.0/16 --dport 30000:32767 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 30000:32767 -j DROP
의미: NodePort는 LB/Ingress 내부망에서만 접근. 직접 외부 노출 금지.
적용: LoadBalancer 앞단을 거치는 표준 구성.
[#29] etcd 2379-2380 클러스터 내부 한정
sudo iptables -A INPUT -p tcp -s 10.0.1.0/24 --dport 2379:2380 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 2379:2380 -j DROP
의미: etcd는 컨트롤플레인 노드 간에만 통신. 외부 노출 시 클러스터 키 노출.
적용: 마스터 노드 (HA etcd 포함).
[#30] CNI 플러그인 통신 (VXLAN 4789, Wireguard 51820)
sudo iptables -A INPUT -p udp -s 10.0.0.0/16 --dport 4789 -j ACCEPT
sudo iptables -A INPUT -p udp -s 10.0.0.0/16 --dport 51820 -j ACCEPT
의미: Flannel·Calico VXLAN, Cilium Wireguard 노드 간 터널.
적용: 사용 중인 CNI에 맞춰 1개만 열면 됨.

7. 메일 서버 (5선)

메일 포트는 스팸 봇이 끊임없이 두드립니다. 적절한 rate limit과 TLS 강제가 핵심.

[#31] SMTP 25/587/465 허용
sudo iptables -A INPUT -p tcp -m multiport --dports 25,465,587 -j ACCEPT
의미: 표준 메일 송수신 포트 모두 허용.
적용: Postfix·Exim 등 메일 서버 기본.
[#32] IMAPS·POP3S만 허용 (평문 차단)
sudo iptables -A INPUT -p tcp -m multiport --dports 993,995 -j ACCEPT
sudo iptables -A INPUT -p tcp -m multiport --dports 143,110 -j DROP
의미: TLS 포트만 열고 평문 IMAP/POP3 전면 차단.
적용: 모던 메일 서버는 평문 비활성화 필수.
[#33] SMTP rate limit (스팸 봇 방어)
sudo iptables -A INPUT -p tcp --dport 25 -m connlimit --connlimit-above 10 -j REJECT
sudo iptables -A INPUT -p tcp --dport 25 -m hashlimit \
    --hashlimit-name smtp --hashlimit-mode srcip \
    --hashlimit-above 5/min --hashlimit-burst 3 -j DROP
의미: IP당 동시 10개, 분당 5개 초과 SMTP 연결 차단.
적용: 정상 메일 흐름은 영향 없고 봇만 차단.
[#34] 의심 IP 차단 (RBL 연동 대신 iptables ipset)
sudo ipset create spamips hash:ip
sudo iptables -A INPUT -p tcp --dport 25 -m set --match-set spamips src -j DROP
의미: ipset에 추가만 하면 즉시 차단. 동적 차단에 효과적.
적용: rspamd·SpamAssassin이 ipset에 추가하도록 연동.
[#35] 메일 서버 outbound 25 제한 (오픈 릴레이 방지)
sudo iptables -A OUTPUT -p tcp -m owner --uid-owner postfix --dport 25 -j ACCEPT
sudo iptables -A OUTPUT -p tcp --dport 25 -j DROP
의미: postfix 사용자만 외부 25번 접근. 일반 사용자·웹 셸 스팸 발송 차단.
적용: 공유 호스팅·다중 사용자 서버에서 필수.

8. NAT 및 포트 포워딩 (5선)

iptables NAT 테이블은 라우터·게이트웨이 역할에 필수. PREROUTING·POSTROUTING 차이를 명확히 이해해야 합니다.

[#36] 외부 80 → 내부 8080 포워딩
sudo iptables -t nat -A PREROUTING -p tcp --dport 80 -j REDIRECT --to-port 8080
의미: 외부에서 들어오는 80번 패킷을 로컬 8080으로 리다이렉트.
적용: root 권한 없이 80번에 바인딩하기 위한 표준 트릭.
[#37] 다른 호스트로 DNAT
sudo iptables -t nat -A PREROUTING -p tcp --dport 80 -j DNAT --to-destination 10.0.1.50:80
sudo iptables -t nat -A POSTROUTING -p tcp -d 10.0.1.50 --dport 80 -j MASQUERADE
의미: 게이트웨이로 들어온 80번 트래픽을 백엔드 10.0.1.50:80으로 전달.
적용: 간단한 L4 로드밸런서, 리버스 프록시 대용.
[#38] MASQUERADE (홈 라우터 기본 NAT)
sudo iptables -t nat -A POSTROUTING -o eth0 -s 192.168.0.0/24 -j MASQUERADE
의미: 내부망 패킷이 eth0(WAN) 나갈 때 게이트웨이 IP로 변환.
적용: Linux 라우터·홈서버 게이트웨이.
[#39] SNAT (고정 IP 변환)
sudo iptables -t nat -A POSTROUTING -o eth0 -s 10.0.0.0/8 -j SNAT --to-source 203.0.113.10
의미: MASQUERADE와 달리 명시적 출발지 IP 지정. 성능 약간 우위.
적용: WAN IP가 고정된 환경에서 권장.
[#40] 1:1 NAT (외부 IP ↔ 내부 IP 매핑)
sudo iptables -t nat -A PREROUTING -d 203.0.113.20 -j DNAT --to-destination 10.0.1.20
sudo iptables -t nat -A POSTROUTING -s 10.0.1.20 -j SNAT --to-source 203.0.113.20
의미: 외부 IP 하나를 내부 서버 하나에 완전 매핑. 양방향 NAT.
적용: DMZ 서버에 공인 IP 직접 부여 효과.
NAT 룰 생성: iptables 생성기에서 PREROUTING/POSTROUTING 체인 + DNAT/SNAT 옵션 선택.

9. 로깅 및 모니터링 (5선)

차단만큼 중요한 것이 가시성입니다. LOG 타깃을 적절히 활용하면 침입 흔적을 사후 추적할 수 있습니다.

[#41] DROP 직전 LOG 로깅
sudo iptables -A INPUT -m limit --limit 5/min -j LOG --log-prefix "iptables-drop: " --log-level 7
sudo iptables -A INPUT -j DROP
의미: DROP 전 분당 5회까지 로그. /var/log/kern.log 또는 /var/log/messages에 기록.
적용: 사후 분석용. 로그 폭주 방지 위해 limit 필수.
[#42] 신규 SSH 연결 모두 로그
sudo iptables -A INPUT -p tcp --dport 22 -m conntrack --ctstate NEW \
    -j LOG --log-prefix "ssh-new: "
의미: 신규 SSH 시도를 모두 기록. 브루트포스·정상 접속 둘 다 확인.
적용: 보안 감사가 필요한 환경.
[#43] Rate limit 트리거 로그
sudo iptables -A INPUT -p tcp --dport 80 -m connlimit --connlimit-above 50 \
    -j LOG --log-prefix "http-flood: "
sudo iptables -A INPUT -p tcp --dport 80 -m connlimit --connlimit-above 50 -j REJECT
의미: 플러드 임계 도달 시 로그 + 거부. 사고 시점 확인 용이.
적용: 모니터링 시스템과 grok 패턴 연동.
[#44] 의심 패턴 알람용 prefix
sudo iptables -A INPUT -p tcp --dport 22 -m recent --rcheck --seconds 60 --hitcount 4 \
    --name SSH -j LOG --log-prefix "SSHBRUTE-ALERT: "
의미: 특정 prefix로 로그 → rsyslog·Loki에서 알람 트리거.
적용: SIEM·중앙 로깅 환경.
[#45] ULOG/NFLOG (커널 사용자 공간 로깅)
sudo iptables -A INPUT -p tcp --dport 80 -j NFLOG --nflog-group 1 --nflog-prefix "http-in: "
의미: ulogd2가 그룹 1을 받아 PostgreSQL·MySQL·JSON 등으로 적재.
적용: 대용량 패킷 로깅. dmesg 폭주 회피.

10. 응급·일시적 차단 (5선)

공격 진행 중이거나 사고 의심 시 빠르게 적용해야 할 룰들입니다. 일시적이므로 시간 기반 자동 해제와 함께 사용하면 좋습니다.

[#46] 특정 IP 즉시 차단
sudo iptables -I INPUT 1 -s 198.51.100.45 -j DROP
의미: 가장 앞 자리(-I 1)에 삽입. 다른 ACCEPT 룰보다 먼저 평가.
적용: 공격 IP 확인 즉시 1초 안에 차단 가능.
[#47] CIDR 단위 차단 (소규모 봇넷)
sudo iptables -I INPUT 1 -s 192.0.2.0/24 -j DROP
의미: 같은 대역에서 다수 IP가 공격할 때 한 번에 차단.
적용: 호스팅·VPS에서 시작된 봇넷 대응.
[#48] 국가 단위 차단 (전체 INPUT)
sudo iptables -I INPUT 1 -m geoip --src-cc CN,RU,KP -j DROP
의미: 특정 국가 IP 전면 차단. SSH뿐 아니라 모든 포트에 적용.
적용: 글로벌 트래픽 불필요한 내부 서비스. xtables-addons 필요.
[#49] 시간 제한 차단 (1시간 후 자동 해제)
sudo iptables -I INPUT 1 -s 198.51.100.45 -j DROP
echo "sudo iptables -D INPUT -s 198.51.100.45 -j DROP" | at now + 1 hour
의미: at 명령으로 1시간 후 자동 해제. 영구 차단 누적 방지.
적용: 일시적 의심 IP에 적합. at 데몬 활성화 필요.
[#50] DOS 의심 시 자동 ipset 추가
sudo ipset create blacklist hash:ip timeout 3600
sudo iptables -I INPUT -m set --match-set blacklist src -j DROP
# 공격 IP 발견 시
sudo ipset add blacklist 198.51.100.99 timeout 3600
의미: ipset에 추가만 하면 즉시 차단되고 3600초 후 자동 해제.
적용: 스크립트·CrowdSec·fail2ban과 통합.

적용 시 주의사항

50개 룰을 한 번에 쏟아붓는 것은 위험합니다. 다음 순서를 지키는 것이 가장 안전합니다.

  • SSH 연결 끊김 방지: 정책을 DROP으로 바꾸기 전에 반드시 iptables -I INPUT 1 -p tcp --dport 22 -s 본인IP -j ACCEPT를 먼저 등록. 그래야 사고 시에도 본인 접속은 유지됨.
  • 영구화: 룰은 메모리에만 존재하므로 재부팅 시 사라짐. iptables-save > /etc/iptables/rules.v4로 저장하고 iptables-persistent 패키지로 부팅 시 복원.
  • ufw·firewalld 충돌: 같은 서버에 두 가지 도구를 동시에 쓰면 룰이 덮어쓰임. 하나만 선택하거나 ufw/firewalld가 내부적으로 iptables를 어떻게 다루는지 이해 후 사용.
  • 롤백 계획: 작업 전 iptables-save > /root/iptables.backup.$(date +%F)로 백업. 사고 시 iptables-restore < /root/iptables.backup.YYYY-MM-DD로 즉시 복구.
  • 시각적 검증: 본 사이트 iptables 생성기로 룰을 GUI에서 조합하고 미리보기 후 적용하면 실수가 크게 줄어듭니다.

결론: 50개는 시작점이다

본 글의 50개 룰셋은 일반적 환경의 표준 출발점입니다. 실제 운영 환경은 워크로드·트래픽 패턴·규제 요건에 따라 룰이 달라져야 합니다. 예를 들어 PCI-DSS 환경은 모든 차단·허용에 로그가 의무화되고, 의료 데이터 서버는 ePHI 접근 IP의 강력한 화이트리스트가 필요합니다.

iptables를 익히는 가장 빠른 방법은 한 번에 한 카테고리씩, 실험 서버에서 직접 적용해보고 깨뜨려보는 것입니다. 시스템을 부수지 않고 학습할 수 있는 환경(예: Vagrant·LXC·Docker)을 마련하고, 본 글의 50선을 카테고리별로 하나씩 손에 익히세요.
