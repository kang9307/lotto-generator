はじめに - 置換文字列はパターンとは別の文法である

正規表現パターンの移植性はよく話題になるが、置換文字列（replacement）はパターンとは別の文法で、特殊表記もツールごとに違う。同じ & が sed ではマッチした文字列全体を表し、Python・JS・PowerShell では普通のアンパサンドである。同じ $1 が perl・JS・PowerShell ではグループ1を表し、sed・Python では文字どおりの $1 である。

問題は2か所で起きる。1つは、別のツールの表記をそのまま持ち込むときである。エラーなしで静かに誤った結果になることもあれば、エラーで止まることもある。もう1つは、変数の値を置換文字列の位置にそのまま入れるときである。値の中の $・\・& が特殊表記として読まれ、値が変形する。前者は表記の対照表で整理でき、後者は置換部を文字列ではなく関数で渡す方法で閉じられる。

  • 対象は、シェルツールの sed（GNU sed 4.9）、awk（GNU Awk 5.0.0）、perl 5.38.2 と、Python 3.13.3 の re.sub である。
  • 残る2つは、node v22.16.0 の String.replace と、Windows PowerShell 5.1 の -replace である。
  • 入力はすべて短い固定文字列で、意図は同じである。マッチ全体の再利用、グループの入れ替え、リテラル値の挿入である。
  • パターン側の方言は正規表現の移植性の記事が、sed の & と区切り文字の衝突は sed の記事が扱うので、ここではツール間の対照と値の入れ方に絞る。
  • 出力はエラーメッセージも含めてそのまま貼り付けてあり、Python の repr と JS の JSON 形式で出した行は引用符も出力に含まれる。

全体一致の参照 - &、$&、\g<0>

マッチした文字列全体を置換文字列の中で再び使う表記は、ツールごとに違う。以下は、Tom を [Tom] にする同じ意図を3つのシェルツールに入れた結果である。

echo 'Tom' | sed 's/Tom/[&]/'
                    echo 'Tom' | sed 's/Tom/[\0]/'
                    echo 'Tom' | awk '{ sub(/Tom/, "[&]"); print }'
                    echo 'Tom' | awk '{ print gensub(/Tom/, "[\\0]", "g") }'
                    echo 'Tom' | perl -pe 's/Tom/[$&]/'
                    echo 'Tom' | perl -pe 's/Tom/[&]/'
[Tom]
                    [Tom]
                    [Tom]
                    [Tom]
                    [Tom]
                    [&]

sed の & と \0、awk の sub の & と gensub の \\0、perl の $& は、いずれも全体一致を指した。最後の行のとおり、perl の & は文字どおりのアンパサンドである。sed と同じ期待で perl に & を使うと、置換は起きるが全体一致は入らない。

import re
                    print(repr(re.sub('Tom', '[&]', 'Tom')))
                    print(repr(re.sub('Tom', r'[\g<0>]', 'Tom')))
                    print(repr(re.sub('Tom', r'[\0]', 'Tom')))
'[&]'
                    '[Tom]'
                    '[\x00]'

Python では & は文字どおりで、全体一致は \g<0> である。\0 は全体一致ではなく NUL 文字（\x00）になった。Python の文書は、repl 文字列の中のバックスラッシュエスケープが処理されると書き、マッチした部分文字列全体を入れる参照として \g<0> を挙げている。

console.log(JSON.stringify('Tom'.replace(/Tom/, '[&]')));
                    console.log(JSON.stringify('Tom'.replace(/Tom/, '[$&]')));
                    console.log(JSON.stringify('Tom'.replace(/Tom/, '[$0]')));
"[&]"
                    "[Tom]"
                    "[$0]"
'Tom' -replace 'Tom','[&]'
                    'Tom' -replace 'Tom','[$&]'
                    'Tom' -replace 'Tom','[$0]'
[&]
                    [Tom]
                    [Tom]

JS と PowerShell では全体一致は $& である。MDN の表は $& を「Inserts the matched substring.」と書き、Microsoft Learn は $& を全体一致のコピーを入れる置換として挙げる。違いは $0 に出る。JS は $0 を特殊表記と見ず文字どおり返し、PowerShell 5.1 は $0 を全体一致として読んだ。

  • この出力で & が全体一致を意味したのは sed と awk だった。
  • $& は perl・JS・PowerShell で同じ意味である。
  • \0 は sed では全体一致、Python では NUL 文字である。
  • $0 は PowerShell では全体一致、JS では文字どおりである。

グループ参照 - \1 系と $1 系

括弧グループを参照する表記は2つの系統に分かれる。sed・awk（gensub）・Python はバックスラッシュ系（\1）で、perl・JS・PowerShell はドル系（$1）である。2つの表記を取り違えるとどうなるかを、ab を ba にする置換で見る。

echo 'ab' | sed -E 's/(a)(b)/\2\1/'
                    echo 'ab' | sed -E 's/(a)(b)/$2$1/'
                    echo 'ab' | awk '{ print gensub(/(a)(b)/, "\\2\\1", "g") }'
                    echo 'ab' | awk '{ sub(/(a)(b)/, "\\2\\1"); print }'
                    echo 'ab' | perl -pe 's/(a)(b)/$2$1/'
                    echo 'ab' | perl -pe 's/(a)(b)/\2\1/'
ba
                    $2$1
                    ba
                    \2\1
                    ba
                    ba

1行目で sed の \2\1 は ba を返し、2行目の $2$1 はグループではなく文字どおり出力された。awk でグループを参照できるのは gensub だけで、sub に同じ \\2\\1 を入れると \2\1 がそのまま出た。perl は $2$1 が ba で、 \2\1 も ba になった。

import re
                    print(repr(re.sub(r'(a)(b)', r'\2\1', 'ab')))
                    print(repr(re.sub(r'(a)(b)', '$2$1', 'ab')))
                    print(repr(re.sub(r'(a)(b)', r'\g<2>\g<1>', 'ab')))
'ba'
                    '$2$1'
                    'ba'

Python では \2\1 と \g<2>\g<1> が同じ結果で、$2$1 は文字どおりである。ドル系のツールでは逆になる。

console.log(JSON.stringify('ab'.replace(/(a)(b)/, '$2$1')));
                    console.log(JSON.stringify('ab'.replace(/(a)(b)/, '\\2\\1')));
"ba"
                    "\\2\\1"
'ab' -replace '(a)(b)','$2$1'
                    'ab' -replace '(a)(b)','\2\1'
ba
                    \2\1

JS と PowerShell では $2$1 がグループ参照で、\2\1 は文字どおり出力された。JS の出力の "\\2\\1" は JSON のエスケープで、実際の文字は \2\1 である。バックスラッシュ系の表記をドル系のツールに持ち込むとエラーなしでリテラルが出るので、誤った結果が静かに通る。

グループ番号の後ろに数字が続くとき

グループ1の値の後ろにリテラルの 0 を付ける置換（a を a0 に）は、番号の後ろの数字が番号の一部として読まれるかどうかでツールが分かれる。

echo 'a' | sed -E 's/(a)/\10/'
                    echo 'a' | awk '{ print gensub(/(a)/, "\\10", "g") }'
                    echo 'a' | perl -pe 's/(a)/${1}0/'
                    echo 'a' | perl -pe 's/(a)/[$10]/'
a0
                    a0
                    a0

sed と awk は \10 をグループ1の後ろの 0 と読んだ。perl は ${1}0 と書けば a0 になり、$10 は角括弧の中が空文字列になった。

import re

                    except re.error as e:
                        print(type(e).__name__ + ': ' + str(e))
                    print(repr(re.sub(r'(a)', r'\g<1>0', 'a')))
                    print(repr(re.sub(r'(?P<x>a)', r'\g<x>0', 'a')))

console.log(JSON.stringify('a'.replace(/(a)/, '$10')));
                    console.log(JSON.stringify('a'.replace(/(?<x>a)/, '$<x>0')));
                    console.log(JSON.stringify('a'.replace(/(a)/, '$2')));

JS はグループが1つのパターンで $10 をグループ1の後ろの 0 と読み、a0 を返した。MDN は $n を、n が100未満の正の整数のときの n 番目のグループと書き、グループが無ければリテラルとして置換されると書く。最終行の $2 がそのリテラルである。PowerShell は $10 を文字どおり残した。Microsoft Learn は、$ の後ろの数字はすべて番号に属し、その番号のグループが無ければリテラルになると書き、${1}1 の形を代替として挙げる。

リテラルの $ を含む値が壊れる箇所

変数の値を置換文字列にそのまま入れるコードは、値に特殊表記があると壊れる。価格の文字列 $5.00 が典型である。パターンにグループが無ければ $5 は文字どおりなので偶然合うが、グループが5つあると結果が変わる。JS で6種類の値を入れ、最後の行でグループ5つのパターンに $5.00 を入れた。

for (const v of ['A&B', '$5.00', 'C:\\dir', 'US$', '$$', '$&$&']) {
                      console.log(v.padEnd(8) + JSON.stringify('x=OLD'.replace('OLD', v)));

最初の行では $5.00 と US$ はそのままで、$$ は $ 1文字に縮み、$&$& は OLDOLD になった。値が置換表記として読まれた結果である。最終行は、グループ5つのパターンで $5.00 が e.00 になったものである。MDN の表は $$ を「Inserts a "$".」と書く。

PowerShell 5.1 も同じ結果である。$$5.00 と書けばリテラルの $5.00 が入る。Microsoft Learn は $$ を、単一のリテラル $ を入れる表記として書く。

perl でソースに s/OLD/$5.00/ と書くと、グループの無いパターンでも $5.00 が .00 になる。perl がソースの $5 を変数として補間した結果であり、値が置換表記として解釈されたのではない。この出力は次の節に出る。

  • 値に $ があり、パターンにグループがあると、JS と PowerShell は値の一部をグループに置き換える。
  • $$ は値ではなく置換表記なので $ 1文字に縮む。
  • $&$& のように表記と同じ形の値は全体一致に展開される。
  • グループの無いパターンで偶然合っていても、パターンが変わると壊れる。

リテラルのバックスラッシュと & を含む値

パス C:\dir と A&B も同じ方法で入れる。以下は、x=OLD の OLD を各値に置き換えた sed・awk・perl の出力である。perl の最後の行は A@B である。各行の値はスクリプトのソースに直接書いたものである。

echo 'x=OLD' | sed 's/OLD/A&B/'
                    echo 'x=OLD' | sed 's/OLD/$5.00/'
                    echo 'x=OLD' | sed 's/OLD/C:\dir/'
                    echo 'x=OLD' | awk '{ sub(/OLD/, "A&B"); print }'
                    echo 'x=OLD' | awk '{ sub(/OLD/, "$5.00"); print }'
                    echo 'x=OLD' | awk '{ sub(/OLD/, "C:\\dir"); print }'
                    echo 'x=OLD' | perl -pe 's/OLD/A&B/'
                    echo 'x=OLD' | perl -pe 's/OLD/$5.00/'
                    echo 'x=OLD' | perl -pe 's/OLD/C:\dir/'
                    echo 'x=OLD' | perl -pe 's/OLD/A@B/'

                    x=$5.00

sed では A&B の & が OLD に展開されて AOLDB になり、C:\dir ではバックスラッシュが消えて C:dir になった。スクリプトに書いた置換部を sed が読んだ結果である。awk でも & が OLD に展開され、awk ソースの "C:\\dir" は C:\dir として入った。perl は A&B がそのままだが、$5.00 は .00、C:\dir は C:dir、A@B は A になり、@B の部分が消えた。この3つは、ソースに書いた置換部の中の $5・\d・@B を perl がソースの段階で読んだ結果であり、値が置換表記として解釈されたのではなくコードの問題である。同じ3つの値を環境変数で渡して読むと、下の出力のようにそのまま入る。

値を文字列ではなく関数で渡す

値を置換文字列として解釈させない方法は、置換部を文字列ではなく関数の戻り値として渡すことである。値には、C:\dir\1 & $1 \n のようにあらゆる表記を含めて試す。まず Python である。

import re
                    v = r'C:\dir\1 & $1 \n'
                    print('v = ' + v)
                    try:
                        print(re.sub('OLD', v, 'x=OLD'))
                    except re.error as e:
                        print(type(e).__name__ + ': ' + str(e))
                    print(re.sub('OLD', lambda m: v, 'x=OLD'))
                    print(re.sub('OLD', v.replace('\\', '\\\\'), 'x=OLD'))
                    print('x=OLD'.replace('OLD', v))
                    print(re.sub(r'(a)(b)', lambda m: m[2] + m[1], 'ab'))

                    x= $v

PowerShell 5.1 で -replace の置換は文字列である。[regex]::Replace に MatchEvaluator を渡すか、正規表現ではない .Replace() メソッドを使うと値がそのまま入った。最後の行のように -replace にスクリプトブロックを渡すと、5.1 では関数として呼ばれず、周りの空白を含むブロックの文字列が入った。

  • Python は lambda m: v、JS は () => v で値を返せば解釈は起きない。
  • PowerShell は MatchEvaluator か .Replace() 文字列メソッドを使う。
  • 正規表現が要らなければ、str.replace・split/join・.Replace() が最も単純である。
  • -replace に値を直接入れる必要があるなら $ を $$ に置き換える方法があり、5.1 のスクリプトブロックは関数ではない。

ツールの外側の層 - シェルの引用と awk -v

値がツールに届く前に、シェルとツール自身の引用の層が値をもう一度変える。awk の -v オプションがその例である。以下で tr は TAB を > に変えて見えるようにしている。

echo 'x=OLD' | awk -v v='a\tb' '{ sub(/OLD/, v); print }' | tr '\t' '>'
                    V='a\tb' awk 'BEGIN { print ENVIRON["V"] }'
x=a>b
                    a\tb

-v v='a\tb' で渡した値は awk がエスケープを処理して TAB になった（x=a>b）。環境変数で渡して ENVIRON で読んだ値は、a\tb が文字どおりだった。この違いは出力が直接示している。

'[' + ('ab' -replace '(a)(b)','$2$1') + ']'
                    '[' + ('ab' -replace '(a)(b)',"$2$1") + ']'
[ba]
                    []

PowerShell では引用符の種類が層を作る。同じ置換文字列を単一引用符で書くとグループ参照になり、二重引用符で書くと PowerShell が先に $2 と $1 を変数として展開し、空文字列になった。出力の2行目 [] がその結果である。

安全に入れる方法 - ツール別の選択表

sed では値の中の &・\・区切り文字をエスケープしてから入れる。awk は index と substr でつなぐか、ENVIRON で値を受け取り、perl は値を環境変数から読む。値は A&B\C/D である。

V='A&B\C/D'
                    ESC=$(printf '%s' "$V" | sed 's/[&\/\\]/\\&/g')
                    echo "ESC=$ESC"
                    echo 'x=OLD' | sed "s/OLD/$ESC/"
                    echo 'x=OLD' | V="$V" awk '{ i = index($0, "OLD"); print substr($0, 1, i-1) ENVIRON["V"] substr($0, i+3) }'
                    echo 'x=OLD' | V="$V" awk '{ sub(/OLD/, ENVIRON["V"]); print }'
                    echo 'x=OLD' | V="$V" perl -pe 's/OLD/$ENV{V}/'
ESC=A\&B\\C\/D
                    x=A&B\C/D
                    x=A&B\C/D
                    x=AOLDB\C/D
                    x=A&B\C/D

sed の変換は A\&B\\C\/D を作り、置換結果は値そのものである。awk は index と substr の方式で値のままになり、同じ値を sub に入れると & が OLD に展開されて AOLDB\C/D になった。perl は $ENV{V} で読んだ値がそのまま入った。ツール別の選択は表のとおりである。

gawk 5.0.0index と substr でつなぐか、ENVIRON で値を受け取る。sub の置換部に入れると & が展開されるx=A&B\C/D · x=AOLDB\C/D

  • sed は値をエスケープしてから挿入し、区切り文字を値に無い文字に変える必要がある場合もある。
  • awk は sub の置換部に値を入れず、index と substr でつなぐ。
  • Python・JS・PowerShell は、関数か文字列メソッドで解釈そのものを避ける。
  • perl は値を変数や環境変数から読み、置換部のリテラルに $ や @ を書かない。

パターン側の方言は正規表現の方言の記事が、sed の & のエスケープと区切り文字の衝突はsed -i の記事が扱う。ハングルの正規表現とシェルのエスケープが重なる箇所はハングル正規表現の記事にある。

確認できなかったこと

  • GNU sed のマニュアルと GNU awk のマニュアルは接続が拒否されて開けなかった。sed と awk の動作は GNU sed 4.9 と gawk 5.0.0 の出力だけを根拠にしており、GNU sed 4.9 に関数置換にあたる形があるかは示せなかった。mawk・BSD awk での動作と、表の「—」のセル（名前付きグループの表記）の sed・awk・perl の結果は、出力がない。
  • perl の文書は開いていない。perl の $ と @ の補間と \2 の挙動は出力だけを根拠にしており、ソースリテラルの段階での解釈という説明は、$ENV{V} で受け取った値がそのまま入った出力から導いたものである。
  • Python の \0 が NUL 文字になる規則と、JS の $10 でグループ数に応じた処理の細部は、文書の文言では確認できなかった。
  • PowerShell 7 での -replace の動作（スクリプトブロックを含む）は、この PC に pwsh が無いため実行できなかった。
  • BSD sed・mawk などの他の実装と、Linux・macOS での結果は実行していない。
