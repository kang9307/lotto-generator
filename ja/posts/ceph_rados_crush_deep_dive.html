Ceph 徹底解説：RADOSの概念とCRUSH Ruleを完全に理解する

2025-06-02 開発・インフラ

Cephは最新の分散ストレージシステムであり、優れた拡張性と安定性を兼ね備え、多くの企業や組織から注目を集めています。Cephの中核には、RADOSという強力なオブジェクトストレージと、データの配置先を決定するCRUSHアルゴリズムが存在します。本稿では、Cephの心臓部ともいえるRADOSの概念とCRUSH Ruleについて詳しく解説します。

English Summary: This document provides an in-depth analysis of Ceph's core components: RADOS (Reliable Autonomic Distributed Object Store) and the CRUSH (Controlled Replication Under Scalable Hashing) algorithm. It covers their fundamental concepts, key features, and how they work together to deliver a scalable and reliable distributed storage solution.

1. RADOS (Reliable Autonomic Distributed Object Store) とは

RADOSは、Cephストレージクラスタの基盤となる中核コンポーネントです。その名称が示すとおり、信頼性が高く（Reliable）、自律的で（Autonomic）、分散型の（Distributed）オブジェクトストア（Object Store）です。

主な特徴と構成要素：

  • オブジェクトベースストレージ：RADOSはすべてのデータをオブジェクト（Object）形式で保存します。ファイルシステムのファイルやブロックデバイスのブロックとは異なり、オブジェクトはデータとメタデータを一体的に含む柔軟な単位です。
  • 分散性と拡張性：データはクラスタ内の複数のOSD（Object Storage Daemon）に分散して保存されます。OSDは実際の物理ストレージデバイス（HDD、SSDなど）を管理するデーモンです。新しいOSDを追加することで、クラスタの容量と性能をリニアに拡張できます。
  • 高可用性とデータの安全性：データはレプリケーション（Replication）またはイレイジャーコーディング（Erasure Coding）により複数のOSDに冗長保存されるため、障害発生時もデータ損失を防ぎ、サービスの継続性を確保します。
  • 自律的な管理：RADOSはOSDの状態を常時監視し、障害発生時には自動的にデータの復旧とリバランシング（Rebalancing）を実行します。これにより、運用管理の負担が大幅に軽減されます。
  • 中核コンポーネント：
    • OSD (Object Storage Daemon)：実際のデータを保存し、データのレプリケーション、復旧、リバランシングなどの処理を実行します。
    • MON (Monitor)：クラスタマップ（Cluster Map）のマスターコピーを保持し、クラスタ全体の状態を管理するとともに、OSD間の合意形成を仲介します。高可用性のため、通常3台以上の奇数台で構成されます。
    • MGR (Manager)：クラスタのステータス情報（使用量、パフォーマンス、システム負荷など）を追跡し、Ceph Dashboardなどの管理インターフェースを提供します。
    • MDS (Metadata Server)：CephFS（Ceph File System）を利用する場合に、ファイルシステムのメタデータを保存・管理します。

RADOSアクセスインターフェース：

Cephは、RADOS上にさまざまなインターフェースを提供し、複数の方法でストレージにアクセスできるようにしています。

  • librados：C、C++、Java、Python、PHPなど多様なプログラミング言語からRADOSクラスタに直接アクセスできるライブラリです。RBD、RGW、CephFSの基盤となっています。
  • RADOS Gateway (RGW)：Amazon S3およびOpenStack Swiftと互換性のあるRESTful APIを提供するオブジェクトストレージゲートウェイです。
  • RBD (RADOS Block Device)：スナップショットやシンプロビジョニングなどの機能を備えたブロックストレージサービスです。仮想マシンのディスクイメージなどに活用されます。
  • CephFS (Ceph File System)：POSIX準拠の分散ファイルシステムです。

2. CRUSH (Controlled Replication Under Scalable Hashing) アルゴリズム

CRUSHは、Cephにおいてデータの配置先を決定する中核アルゴリズムです。従来の中央集約型メタデータサーバに依存することなく、クライアントが直接データの保存先OSDを算出できる仕組みです。これがCephの拡張性とパフォーマンスに大きく貢献しています。

主要な概念：

  • CRUSH Map：クラスタの物理的なトポロジ（ラック、ホスト、OSDなど）とデータ配置ポリシーを定義するマップです。CRUSHアルゴリズムはこのマップに基づいてデータの配置先を決定します。
  • Bucket：CRUSH Map内でOSDをグループ化する論理的な単位です。host、rack、row、datacenterなど、さまざまなタイプのバケットを定義することで、物理的な障害ドメイン（Failure Domain）やパフォーマンスドメイン（Performance Domain）を設定できます。
  • CRUSH Rule：特定のプール（Pool）のデータがどのように保存されるかを定義するルールです。たとえば、「データのレプリカ3個を、それぞれ異なるラックに属するOSDに保存する」といったルールを設定できます。
  • Placement Group (PG)：OSD内でオブジェクトをグループ化する単位です。オブジェクトはまずPGにマッピングされ、その後PGがCRUSH Ruleに従ってOSDにマッピングされます。PGはデータ管理の効率を高めるとともに、OSD障害時のデータ移動単位を最小化します。

CRUSHアルゴリズムの動作の仕組み：

  1. クライアントが特定のオブジェクトに対する操作をリクエストすると、オブジェクトIDとプールIDに基づいて、そのオブジェクトが属するPGが算出されます。
  2. 算出されたPG IDとCRUSH MapのCRUSH Ruleを用いて、そのPGが保存されるOSDのリストが決定されます。この過程でCRUSHアルゴリズムは、障害ドメインやOSDの重み（容量など）を考慮し、データを均等に分散させようとします。
  3. クライアントは、算出されたOSDリストのうちPrimary OSDに直接アクセスし、データの読み書きを行います。

CRUSH Ruleの重要性：

CRUSH Ruleは、データの安全性、可用性、パフォーマンスに直接影響を与えます。管理者はクラスタの物理環境と要件に合わせて、CRUSH Ruleを慎重に設計する必要があります。

  • 障害ドメイン（Failure Domain）：CRUSH Ruleを通じて、データのレプリカがそれぞれ異なる障害ドメイン（例：別のサーバ、別のラック）に保存されるよう強制できます。これにより、特定のサーバやラック全体に障害が発生しても、データ損失なくサービスを継続できます。
  • パフォーマンスドメイン（Performance Domain）：SSDとHDDを混在させる構成では、CRUSH Ruleを使って特定のタイプのデータ（例：高いパフォーマンスが求められるメタデータ）をSSD OSDのみに保存するよう設定できます。
  • 重み（Weight）：OSDの容量やパフォーマンスに応じて重みを設定し、データがバランスよく分散されるよう調整できます。

3. RADOSとCRUSH Ruleの関係

RADOSはデータをオブジェクト形式で保存・管理するシステムであり、CRUSHはこれらのオブジェクトがクラスタ内のどのOSDに保存されるかを決定するアルゴリズムです。

  • クライアントがデータを保存または読み取ろうとする際、CRUSHアルゴリズムが動作して対象のOSDを決定します。
  • RADOSは、CRUSHが決定したOSD群と通信し、実際のデータI/O処理を実行します。
  • OSD障害が発生すると、MONがクラスタマップを更新し、CRUSHが新たなデータ配置計画を算出します。
  • RADOSはこの新しい計画に従い、データを自動的に復旧・再配置します。

このように、RADOSとCRUSHは緊密に連携し、Cephストレージの中核機能であるデータの保存、管理、分散、高可用性などを実現しています。

まとめ

CephのRADOSとCRUSHアルゴリズムは、分散ストレージシステムの複雑さを効果的に管理し、優れた拡張性と安定性を提供する中核技術です。RADOSはインテリジェントなオブジェクトストレージバックエンドを提供し、CRUSHはデータ配置に対する柔軟かつ強力な制御機能を提供します。これらのコンポーネントを深く理解することは、Cephクラスタを効果的に設計・構築・運用するうえで不可欠です。
