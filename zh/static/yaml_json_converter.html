为何经常需要 YAML 与 JSON 互转?

在 DevOps 和 SRE 流程中,YAML 与 JSON 表达同一份数据模型,但应用场景不同。Kubernetes manifest、docker-compose.yml、GitHub Actions、Helm chart、Ansible playbook 都采用 YAML,而 API 响应、环境变量、CI 变量注入、jq 管道则以 JSON 为标准。本工具让两种格式即刻互转,并立即定位缩进错误与引号问题。

  • 实时转换 · 边输入边转换,同时标注出错行(仅在浏览器中处理,不会上传到服务器)。
  • 输入格式自动识别 · 首字符为 { 或 [ 时按 JSON 处理,否则按 YAML 处理。
  • 按字母排序键 · 将对象键排序,使 diff 与代码评审更整洁。
  • YAML 1.2 strict 模式 · 不再把 yes/no/on/off 自动解析为 boolean,确保 k8s 安全。
  • 缩进选项 · 可选 2 或 4 空格(YAML 官方推荐为 2)。

常见问题

转换数据会上传到外部服务器吗?

不会。所有转换都通过 js-yaml 库在浏览器中完成,不发起任何网络请求,因此可以安全地处理内部 manifest 与敏感的 secret key。

能处理大文件吗?

一般几 MB 的文件都能秒级转换。如果文件超过 10MB,浏览器可能短暂卡顿,建议先关闭实时转换并手动触发。

YAML 1.1 与 YAML 1.2 有什么区别?

YAML 1.1 将 yes/no/on/off/y/n 解析为 boolean,并接受六十进制数字(60:00=3600);YAML 1.2 起仅识别 true/false。Kubernetes 集群中曾出现 version: yes 被静默转换为 true 导致故障的案例,因此推荐启用 strict 模式。

支持多文档 YAML(以 --- 分隔)吗?

支持。以 --- 分隔的多文档 YAML 会被转换为 JSON 数组;反之,顶层是数组的 JSON 在转换回 YAML 时会自动变为多文档格式。

支持 YAML anchor 与 alias 吗?

支持。使用 &ref 定义、*ref 引用的 anchor/alias 可以正确解析,并在转换为 JSON 时被自动展开。

可以把转换结果下载为文件吗?

可以。点击输出面板中的 💾 按钮,即可保存为 .json 或 .yaml 文件。
