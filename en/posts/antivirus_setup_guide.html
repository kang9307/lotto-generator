The Windows Security App and Microsoft Defender Antivirus - Names and Scope

The antivirus that runs by default on Windows goes by two names. The screen a user opens is the Windows Security app, and the engine that scans files and handles threats is Microsoft Defender Antivirus. The overview article states that Microsoft Defender Antivirus is available on Windows 10, Windows 11, and Windows Server versions, and that it is built into Windows. The same article introduces the product as the next-generation protection component of Microsoft Defender for Endpoint, one that combines machine learning, big-data analysis, in-depth threat-resistance research, and the Microsoft cloud infrastructure to protect devices.

Turning off the Windows Security app is not the same as turning off the engine. The documentation states that disabling the Windows Security app does not disable Microsoft Defender Antivirus or Windows Firewall. It adds a warning, though: if the app is turned off, or if related Group Policy settings stop it from starting or running, the app can show stale or inaccurate information about the antivirus and firewall products installed on the device, and Microsoft Defender Antivirus might not turn itself back on when a non-Microsoft antivirus is uninstalled. The article cautions that disabling the app significantly lowers the protection level of the device and can lead to malware infection.

  • Supported operating systems: The compatibility article lists Windows 11, Windows 10, Windows Server 2016 or later, Windows Server version 1803 or later, and Azure Stack HCI OS version 23H2 or later. In the Windows Security app, the features for running scans, checking updates, adding exclusions, and configuring ransomware protection are available on Windows 10 version 1703 or later. The Offline scan does not apply to Windows Server.
  • Processes and services: If MsMpEng.exe (service name WinDefend) appears on the Details tab of Task Manager, the engine is running. Other components are the Microsoft Defender Core Service MdCoreSvc (MpDefenderCoreService.exe), the network real-time inspection service WdNisSvc (NisSrv.exe), and the command-line utility MpCmdRun.exe.
  • Do not modify the services: The compatibility article advises against disabling, stopping, or modifying the wscsvc, SecurityHealthService, MsSense, Sense, WinDefend, and MsMpEng services and processes. It says that modifying them manually can cause severe instability on the device.
  • Policy-managed devices: When settings are configured and deployed through Group Policy, the Virus & threat protection settings in the Windows Security app appear dimmed and cannot be changed on the individual endpoint. Changes made through the Group Policy object must be deployed to the device before the Windows settings reflect them.

Background on antivirus and malware response is covered separately in the complete personal cybersecurity basics guide and malware and ransomware response.

Opening the Windows Security App and the Virus & Threat Protection Screen

Search for Windows Security on the Start menu, open the app, and select Virus & threat protection. The documentation also gives the Virus & threat protection tile (or the shield icon on the left menu bar) as a way to reach the same screen. Running scans, checking security intelligence updates, verifying real-time protection, adding exclusions, reviewing threat detection history, and configuring ransomware protection all happen on this screen.

  • Quick scan and Scan options: Selecting Quick scan starts a scan, and other types such as Full scan are chosen under Scan options.
  • Virus & threat protection updates: The version of the installed security intelligence (formerly called the definition version) and its download date are displayed. Selecting Check for updates downloads any new protection updates.
  • Virus & threat protection settings: Open Manage settings to work with the real-time protection switch and the exclusions.
  • Protection history: All recent items are listed. The result of an Offline scan is also checked here.
  • Ransomware protection: Under Manage ransomware protection, controlled folder access is configured, and under Ransomware data recovery, a OneDrive account is connected or set up.
  • Manage providers: Under Who's protecting me?, select Manage providers. On the Security providers page, the Antivirus entry should show that Microsoft Defender Antivirus is turned on.
  • Task Manager check: Looking for MsMpEng.exe on the Details tab is another way to see whether the engine is running.

The update check has one condition. If the device points to WSUS or a software update point and the Windows Update policy is set to 3 - Auto download and notify for install, selecting Check for updates installs all available Microsoft Defender Antivirus updates, meaning security intelligence, engine, and platform.

Protection Settings - Real-Time Protection, Cloud-Delivered Protection, Automatic Sample Submission, and Tamper Protection

Opening Manage settings under Virus & threat protection settings shows the switches for the core protection features. Four items are backed by the documentation.

Real-time protection is the always-on protection that reviews files as they are opened and closed and whenever a user browses to a folder. It is verified by turning the Real-time protection switch to On in Virus & threat protection settings. If the switch is turned off, it turns itself back on after a short delay, and the documentation explains that this automatic re-enabling is meant to keep the device protected from malware and threats.

Cloud-delivered protection is the cloud protection service, also called Microsoft Advanced Protection Service (MAPS), which enhances standard real-time protection. Thanks to this service, new threats can be identified quickly, sometimes before a single endpoint is infected, as the documentation puts it. The cloud service is not simply protection for files stored in the cloud; it uses distributed resources and machine learning to deliver protection far faster than traditional security intelligence updates. Cloud protection is enabled by default, and the documentation recommends keeping it turned on, because some security features of Microsoft Defender for Endpoint work only when cloud protection is enabled. On an unmanaged device, Cloud-delivered protection and Automatic sample submission are turned on under Manage settings. The Windows Security app has no setting for the cloud protection level.

Automatic sample submission sends files and executables to the Microsoft Defender Antivirus cloud service for analysis. It relies on cloud protection, although it can also be configured as a standalone setting. In management tools, the sample submission consent is chosen between Send safe samples automatically (the default) and Send all samples automatically. According to the Group Policy description, the safe-samples option sends most samples automatically but asks the user for additional confirmation for files that are likely to contain personal information.

Tamper protection helps prevent important security settings from being disabled or changed. The article explains the background: during a cyberattack, attackers often disable security features on a device so they can reach data and install malware. When tamper protection is on, the article lists the items that cannot be changed: virus and threat protection, real-time protection, behavior monitoring, antivirus protection including IOfficeAntivirus (IOAV), cloud protection, security intelligence updates, automatic actions on detected threats, and scanning of archived files. Exclusions cannot be modified or added, and attempts to change Microsoft Defender Antivirus settings through the registry are blocked. Changes made through management tools such as Group Policy can appear to succeed, but tamper protection blocks them. When a change is truly needed, troubleshooting mode temporarily disables tamper protection. Tamper protection does not interfere with how a non-Microsoft antivirus app registers in the Windows Security app.

Among these, the item the documentation directly recommends keeping on is cloud protection. The compatibility article adds a separate recommendation: when Microsoft Defender Antivirus runs in passive mode, or when EDR in block mode is used, do not turn off capabilities such as real-time protection, cloud-delivered protection, or limited periodic scanning.

Scan Types - Quick Scan, Full Scan, Custom Scan, and Offline Scan

The on-demand scan article distinguishes three types: quick scan, full scan, and custom scan. A scan starts immediately, and parameters such as location or type can be defined. Separately, the Scan options in the Windows Security app include the Microsoft Defender Offline scan.

A quick scan checks all the locations where malware could be registered to start with the system, such as registry keys and known Windows startup folders. The scheduled-scan article says it checks the processes, memory, profiles, and specific locations of the device, and adds that it also runs on mounted removable devices such as USB drives. Combined with always-on real-time protection, it provides strong protection against malware that starts at the system and kernel level. Both articles say a quick scan is enough in most cases and is the recommended option for scheduled and on-demand scans. A malicious file can be stored in a location that a quick scan does not include, but real-time protection scans every file that is opened or closed and the files in folders the user accesses.

A full scan starts with a quick scan and then scans all mounted fixed disks and removable or network drives. Depending on the amount and type of data to scan, it can take hours or even days. It uses the security intelligence installed when the scan starts, so if a new update is released during the scan, another full scan is needed to pick up the new threats it contains. Because of the time and resources involved, the documentation says scheduling full scans is generally not recommended. If a device is unplugged and runs on battery during a scheduled full scan, the scan stops with event 1002 and runs again at the next scheduled time.

A custom scan runs on the files and folders that are specified. The documentation's examples are a USB drive or a specific folder on a local drive. It is the type the documentation suggests for confirming that a portable device does not contain malware.

Microsoft Defender Offline scan is an antimalware scanning tool that boots and runs a scan from a trusted environment. Because the scan runs outside the normal Windows kernel, it can target malware that tries to bypass the Windows shell, such as viruses and rootkits that infect or overwrite the master boot record (MBR). It is used when a malware infection is suspected or when a thorough check that the endpoint is clean after an outbreak is wanted. The path is Virus & threat protection, then Scan options in the Windows Security app, then selecting Microsoft Defender Offline scan and Scan now. After selecting Scan in the prompt that asks to save work, and Yes in the prompt that asks for permission to make changes to the device, a message says the user will be signed out and Windows will shut down in under a minute. Files must be saved and running programs closed before the scan, and the scan takes about 15 minutes. When it finishes, the endpoint restarts and Windows loads normally. The result is viewed in Protection history, and Event ID 2030 in the Microsoft-Windows-Windows Defender/Operational log in Event Viewer shows that the Offline scan was configured.

The Offline scan has five prerequisites.

  • Hardware: It can be used on x64 Windows 11 and x64/x86 Windows 10. It does not apply to ARM Windows 11, ARM Windows 10, or Windows Server stock-keeping units (SKUs).
  • Account and mode: The user must sign in with local administrator rights, and Microsoft Defender Antivirus must be the primary antivirus, not in passive mode.
  • WinRE: Windows Recovery Environment (WinRE) must be enabled. If it is disabled, the Offline scan does not run and no error message appears; even restarting the computer manually does nothing. The status is checked with reagentc /info, and if it is disabled, reagentc /enable turns it on.
  • BitLocker: If BitLocker is used on the system drive, suspend BitLocker protection before the Offline scan. Otherwise the system might ask for the BitLocker recovery key when it restarts into the offline environment.
  • Updates: Keep receiving platform, engine, and security intelligence updates the usual way. The latest protection updates can also be downloaded and installed manually from the Microsoft Malware Protection Center.

The Three Modes When a Third-Party Antivirus Is Installed

The compatibility article explains that Microsoft Defender Antivirus runs in one of three states: active mode, passive mode, or disabled. In active mode, Defender is the primary antivirus of the device, files are scanned, threats are remediated, and detections are listed in security reports and in the Windows Security app. In passive mode, Defender is not the primary antivirus; it scans files and reports detected threats but does not remove them. In the disabled or uninstalled state, files are not scanned and threats are not remediated, and the article generally recommends against disabling or uninstalling Defender.

Passive mode can generally be set only on endpoints onboarded to Defender for Endpoint. To run in passive mode, another antivirus must be installed and used as the primary antivirus, the endpoint must be onboarded, and the Windows Security Center Service must be enabled. The table below is the scenario summary from the article.

Primary antivirus Onboarded to Defender for Endpoint Smart App Control Microsoft Defender Antivirus state
Microsoft Defender Antivirus Yes On, Evaluation, or Off Active mode
Microsoft Defender Antivirus No Off or Evaluation Active mode
Microsoft Defender Antivirus No On Hybrid model
Non-Microsoft antivirus Yes or No Evaluation or On Passive mode
Non-Microsoft antivirus No Off Disabled
  • Default behavior: On Windows 10 and 11, when a non-Microsoft antivirus is the primary antivirus, Defender goes into disabled mode, and this transition happens automatically. Turning on Smart App Control puts it in passive mode instead of disabled, but the article distinguishes this from the passive mode of a device onboarded to Defender for Endpoint.
  • Limited periodic scanning: When another antivirus is installed, Microsoft Defender Antivirus automatically disables itself and shows that in the Windows Security app. A setting then appears that allows limited periodic scanning to be turned on.
  • When it turns back on: If the non-Microsoft antivirus expires, is uninstalled, or stops providing real-time protection, Microsoft Defender Antivirus can automatically be enabled again.
  • Conflict between two engines: If the Windows Security Center Service is disabled on a Windows client, Defender cannot detect the third-party antivirus installation and stays active. Both then try to provide real-time protection, which affects performance and is an unsupported configuration, according to the article.

Windows Server is different. On Windows Server 2016 or later, version 1803 or later, and Azure Stack HCI OS 23H2 or later, installing a non-Microsoft antivirus does not put Defender in passive mode automatically, and the table lists the state as Disabled (set manually). On a server running a non-Microsoft antivirus, Defender can be removed by running Uninstall-WindowsFeature Windows-Defender in an elevated PowerShell (with Windows-Defender-Gui as well on Windows Server 2016), and the server must be restarted to finish the removal. To keep an onboarded server in passive mode, set the ForceDefenderPassiveMode value to DWORD 1 under the registry key HKLM\SOFTWARE\Policies\Microsoft\Windows Advanced Threat Protection, and set it before onboarding.

Exclusions and Ransomware Protection - Controlled Folder Access

Exclusions start from Manage settings under Virus & threat protection settings. Select Add or remove exclusions in the Exclusions section and choose + Add an exclusion, and the following choices appear.

  • File or folder: Also called a path exclusion.
  • File type: An exclusion by file type extension, applied to any file with that extension regardless of location.
  • Process: An exclusion for files opened by the specified process. The process itself is not excluded, so to exclude a process, use a file or folder exclusion.

The mode description in the tamper protection article includes the point that, while tamper protection is on, exclusions cannot be modified or added. Because an exclusion narrows what is scanned, it is safer to specify only the paths that are really needed.

Controlled folder access (CFA) is a Microsoft Defender Antivirus feature that helps protect files from ransomware, and it is one of the attack surface reduction capabilities of Defender for Endpoint. It is turned on under Manage ransomware protection in Ransomware protection.

  • Components: CFA consists of protected folders (folders in which untrusted apps cannot modify or delete files), trusted apps (apps that can change files in protected folders), and disk sectors (low-level sectors that store the boot record). When an untrusted app tries, CFA blocks the attempt and can show a notification, and an entry appears in Protection history in the Windows Security app.
  • Default and modes: CFA is off by default. The Windows Security app supports only On (the same as the enabled or block mode) and Off; audit mode and the disk-modification-only modes are set with other methods such as PowerShell, Group Policy, or Intune. Microsoft recommends assessing the impact in audit mode before moving to enabled (block) mode.
  • Default protected locations: The hard drive boot sector, plus the Documents, Favorites, Music, Pictures, and Videos folders of user accounts and system accounts, and the Documents, Music, Pictures, and Videos folders under C:\Users\Public. When a folder is redirected, CFA protects the redirected location, and the article's example is OneDrive folder redirection moving the Documents, Pictures, or Desktop folders into the OneDrive folder. The default list cannot be modified, but more folders can be added.
  • Conditions to work: Microsoft Defender Antivirus must be the primary antivirus in active mode, and real-time protection must be on. CFA does not work in passive mode, passive mode with EDR in block mode, limited periodic scanning, or off.

For trusted apps, Microsoft Defender Antivirus evaluates every type of executable, such as .exe, .scr, and .dll files, and automatically trusts most apps based on their prevalence and reputation. The list of automatically trusted apps is not shown in the Windows Security app or the related cmdlets, and an app needs to be added to the allowed list only when it is blocked and known to be trustworthy. An allowed app must be given with its location, and the folder part of the path can use environment variables and wildcards (*). When folders are added for protection, network shares, mapped drives, and environment variables are supported but wildcards are not, and a local share path (loopback) should not be added; the local path should be used instead. The article warns that protecting shared network folders can significantly degrade network performance when untrusted processes access them.

Checking Status and Running Scans with PowerShell

Status can also be checked without opening the screen. The compatibility article tells the reader to check the AMRunningMode value for the mode of Defender, and the controlled folder access article gives commands, run in an elevated PowerShell, that show the current CFA mode and the default protected folders.

Get-MpComputerStatus | select AMRunningMode
                    Get-MpPreference | Format-Table EnableControlledFolderAccess
                    (Get-MpPreference).ControlledFolderAccessDefaultProtectedFolders
  • AMRunningMode: Normal means Microsoft Defender Antivirus is running in active mode. Passive means it is running but is not the primary antivirus, and EDR Block Mode means EDR in block mode is in use. SxS Passive Mode means it runs alongside another antivirus and limited periodic scanning is used.
  • EnableControlledFolderAccess: 0 or Disabled is the default, followed by 1 Enabled, 2 AuditMode, 3 BlockDiskModificationOnly, and 4 AuditDiskModificationOnly. The list of default protected folders is returned only when CFA is on.

A scan starts with Start-MpScan, and an Offline scan starts with Start-MpWDOScan. The latter reboots the device into an isolated environment to look for persistent malware.

Start-MpScan
                    Start-MpWDOScan

To turn on CFA in audit mode first, use Set-MpPreference -EnableControlledFolderAccess AuditMode. To add protected folders to the existing list, use Add-MpPreference -ControlledFolderAccessProtectedFolders rather than Set-MpPreference, because Set-MpPreference overwrites the existing values with the ones specified. The WMI call for the Offline scan (MSFT_MpWDOScan) restarts the endpoint immediately when it runs, so files must be saved first.

What Could Not Be Confirmed

  • Whether the on-screen wording of the Windows Security app matches the articles, which can differ by Windows build and display language.
  • The specific procedure for what happens when an exclusion is added through the Windows Security app on a device where tamper protection is on.
  • The screen layout and menu locations on Windows 10 versions earlier than 1703.
  • Whether the Automatic sample submission switch in the Windows Security app is on from the start. What the documentation states as defaults are the cloud protection enablement and the sample submission consent setting in management tools.
  • The period and scope with which limited periodic scanning runs.
  • Conflict cases and resource usage specific to particular third-party antivirus products.
