掌握 Rsync 命令

超越简单复制，体验智能文件同步的世界。这份交互式指南将彻底改变您的数据管理工作方式。

🚀 为什么要使用 Rsync？

核心在于只传输变更部分的 **增量传输算法**。

普通复制 (cp / scp)

10MB 文件中即使只改动了 1KB，
也会传输全部 10MB。

0%

智能同步 (rsync)

只智能识别并传输
变更过的 1KB 数据片段。

0%

🖥️ 生成的命令

rsync -a [SOURCE] [DESTINATION]

💡 路径末尾斜杠（/）的重要性：source/ 仅复制目录内容，source 复制目录本身。

🎯 实战应用场景

📁 场景 1：本地目录备份

将我的家目录（~/documents）中所有数据备份到外置硬盘（/mnt/backup）。保留所有文件属性并显示进度。

rsync -av --progress ~/documents/ /mnt/backup/documents_backup/

🌐 场景 2：备份到远程服务器（使用 SSH）

将本地项目目录压缩后传输到远程服务器（192.168.0.100），假设 SSH 端口为 2222。

rsync -avz -e 'ssh -p 2222' /var/www/my_project/ user@192.168.0.100:/home/user/backups/

🔄 场景 3：生产服务器镜像（删除选项）

将生产服务器的网页内容完整复制到备份服务器。生产端被删除的文件，备份端也会同步删除。--delete 选项必须非常谨慎使用。

# 1. 先用 --dry-run (-n) 测试，确认哪些文件会被删除！ rsync -avzn --delete user@source_server:/var/www/html/ user@backup_server:/var/www/html/ # 2. 确认安全后，去掉 -n 选项实际执行 rsync -avz --delete user@source_server:/var/www/html/ user@backup_server:/var/www/html/

🚫 场景 4：备份时排除特定文件/目录

备份项目目录时，排除体积庞大的 node_modules 目录和不必要的日志文件（*.log）。

rsync -av --exclude 'node_modules/' --exclude '*.log' /path/to/project/ /path/to/backup/

💡 如果排除项较多，建议创建 exclude-list.txt 文件并使用 --exclude-from='exclude-list.txt' 选项，这样会更整洁。

⏰ 场景 5：使用 Cron 每天凌晨自动备份

设置 cron，让重要数据每天凌晨 2 点自动备份到远程服务器。执行结果记录到日志文件中以便追踪。

# crontab -e 0 2 * * * rsync -a --delete ~/critical_data/ user@remote_server:/backup/ >> /var/log/rsync_backup.log 2>&1
