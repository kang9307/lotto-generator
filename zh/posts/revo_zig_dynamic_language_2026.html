revo - 为编程乐趣而生的Zig动态语言 2026

everything is something - 用Zig重写动态语言的乐趣

2026-06-13 IT/技术

引言：一门把乐趣放在首位的语言登场

新的编程语言问世时，多数都打出更快、更安全、更可扩展的旗号。然而2026年6月在开发者社区引发热议的revo却打出了另一句话：为编程乐趣而生的动态语言（a dynamic language for the joy of programming）。不是性能指标，也不是基准测试，而是把乐趣放在第一行。更有趣的是，这门语言竟用Zig实现。一门追求乐趣的动态语言，偏偏建立在直接操作内存的低层系统语言之上。

本文将围绕新兴语言revo的理念、语法，以及用Zig做动态语言这一选择的含义展开分析。我们将拆解其核心概念everything is something（一切皆为某物）究竟意味着什么，基于spawn的并发模型如何运作，它与Ruby、Lua等既有动态语言有何不同，以及它适合哪些用途、又有哪些局限。先说明一点：revo仍是0.0.0阶段的极早期项目。因此部分语法基于公开的介绍资料，未确定的部分则以通用的语言设计原理加以补充说明。

1. revo是什么 - 一句话定义

先打好基础。revo是用Zig编写的动态类型语言。动态类型意味着变量的类型在运行时而非编译时确定，Python、Ruby、JavaScript、Lua都属于这一系。revo的官方介绍把自己定义为表现力强、动态类型、为编程乐趣而生的语言。

这里有两个关键词格外醒目：一个是表现力（expressive），另一个是乐趣（joy）。二者其实相连。当代码能写得简短而自然地流动时，开发者更容易感到乐趣，而revo的语法设计正是聚焦于营造这种流动。管道运算符、以表达式为中心的结构、简洁的函数定义，都指向同一方向。

revo并非简单的树遍历解释器，而是把源码编译为字节码再执行。其CLI除脚本执行外，还提供字节码编译（-b）、反汇编（--dis）、测试（--test）、基准测试（--bench）和交互式REPL等选项。对一门小语言而言，工具配置相当认真。

2. 核心理念 - everything is something

理解revo最重要的钥匙就是everything is something，即一切皆为某物（值）的原则。这是语言设计中所谓表达式导向（expression-oriented）思想的一种体现。通俗地说，代码中几乎所有结构都作为表达式而非语句运作，并返回结果值。

例如在许多语言中，if只是分流控制的语句，并不产生值。但在表达式导向语言中，if会返回值，因此可将其结果直接赋给变量。revo介绍资料中的块表达式示例如下。

let x = do
    let y = 5 + 10
    y
end

这里整个do ... end块就是一个表达式，块的最后一个值（y）直接成为块的值并落入x。这一思想与Ruby几乎一切皆为表达式以及Rust的块表达式同属一脉。效果很明确：减少临时变量与单独赋值，让代码自上而下地读作一条连续的流。

表达式导向设计的本质，是抹去计算的代码与产生值的代码之间的界线。当一切都产生值，代码便从命令的罗列变成值的流动。

3. 管道运算符 - 直接书写值的流动

everything is something理念最直观的体现，是管道运算符（|>）。借用Unix shell管道的思路，把前一个表达式的结果送入下一个函数。revo介绍中的示例是这样的。

let x = "hello"
  |> _:upper()
  |> _:sub(1, 2)
  |> assert_eq("el")

这里_看起来是指代上一步流入之值的占位符。"hello"被转为大写，截取结果的一部分，最后与期望值比较——整个过程自上而下逐行读出。原本要写成嵌套括号assert_eq(sub(upper("hello"), 1, 2), "el")、需从里向外阅读的代码，被按处理顺序铺展开来。这是Elixir、F#及近年多门语言采用的范式，尤其适合表达数据变换的管线。

4. 函数与模式匹配 - 用结果类型处理错误

revo的函数定义十分精简。在错误处理上，它顺应现代语言的潮流，使用结果类型（result type）与模式匹配。不抛出异常，而是把成功与失败作为值返回，再对该值进行分支。看看介绍资料的示例。

fn safe_div(a, b)
  if b == 0 (:err, :DivByZero)
  else (:ok, a / b)

match safe_div(10, 2)
  | (:ok, v)  => print(v)
  | (:err, e) => print(e)

这里以冒号开头的值:ok、:err、:DivByZero看起来是符号（symbol／atom），与Ruby的符号或Elixir的原子是同一概念，即本身即为名字的轻量常量。safe_div在除以零时返回元组(:err, :DivByZero)，正常时返回(:ok, 结果)。调用方用match查看该元组的形状并分支。

这种方式的好处是，错误成为显式的值而非隐藏的异常。函数可能失败这一事实直接刻在返回值的形状上，调用者便很难漏掉失败分支。这与Rust的Result、Go的多返回值、Elixir的{:ok, ...} / {:error, ...}惯用法属于同一设计脉络。

5. 并发模型 - 一个spawn点亮异步

revo最有趣的部分是它的并发（concurrency）模型。核心被压缩进介绍资料的这一句：先写阻塞代码，再在前面加上spawn使其变为非阻塞。也就是说，不在一开始就把并发塞进设计，而是先写普通代码，再在需要之处补上spawn一词转为异步的渐进式方法。

const h = spawn fn() add(20, 22)
join(h)

spawn把后续的函数调用作为独立任务（task）启动，并返回指向该任务的句柄（h）。join(h)等待该任务结束后取回结果。几乎原样保留同步代码的形状，只在一行调用前加上spawn，便成了并发执行。

任务之间的通信通过通道（channel）完成：用chan()创建通道，用send()发送值，用recv()接收。介绍资料中的worker示例如下。

let ch = chan()
fn worker(n) do
  if n == 6 do
    send(ch, :done)
    return n
  end
  sleep(n * 100)
  send(ch, n * 10)
end

这种基于通道的消息传递模型，与Go的goroutine和通道、Erlang/Elixir的actor模型同属一脉。它不对共享内存加锁，而是奉行通过传递值来通信（communicate by sharing）的理念，被视为能在结构上减少数据竞争（data race）的模型。

6. 为何偏偏是Zig - 实现语言的意义

这里再深入一层。revo用Zig实现这一事实，并非单纯的技术花絮，而是决定语言性格的重要选择。动态语言不由用户直接编译机器码，而是由预先做好的解释器／字节码虚拟机执行代码。因此用什么来实现这个解释器，便左右着语言的性能与可移植性。

Zig是2026年现在临近1.0的系统编程语言，具有以下特性。

Zig特性 含义 对解释器的益处
无运行时 像C一样没有隐藏的运行时与GC 执行环境轻量且可预测
手动内存管理 显式处理分配器 精细控制虚拟机内存
comptime 编译期代码执行与泛型 预生成分派表等以提速
便捷交叉编译 一次构建面向多平台 提升解释器分发的可移植性
C互操作 直接对接既有C代码与库 嵌入与绑定更容易

概而言之，Zig在给出接近C的速度的同时，构建简单、交叉编译容易，很好地满足了动态语言解释器所需的快、轻、随处可运行的条件。事实上revo提供了C嵌入API，可将解释器嵌入其他程序，这同样得益于Zig的C亲和性。另一方面，Zig尚在1.0之前、标准库与异步模型仍在变动，这对revo这类早期项目而言本身也是风险因素。

7. 动态语言的设计趋势 - revo站在何处

revo的语法并非凭空而来，更像是把动态语言数十年来打磨出的好点子汇集而成。与主要语言对照，revo的坐标便清晰起来。

  • Ruby：几乎一切皆为表达式、把开发者幸福作为明确目标，这两点使Ruby与revo最为相像。revo的乐趣宣言直接承接了Ruby的精神。
  • Lua：小巧轻量、便于嵌入其他程序的解释器，与revo的C嵌入取向相通。
  • Elixir/Erlang：原子、模式匹配、消息传递并发，直接对应revo的符号、match与通道。
  • Go：spawn-join与通道，可读作把goroutine与通道的思路移植到动态语言语境。
  • Rust：基于结果类型的错误处理、块表达式，可见Rust的影响。

有趣的是这一组合的方向性。自2010年代后期以来，新兴语言几乎把表达式导向＋模式匹配＋基于消息的并发当作标准套件采用。revo可以读作：在带垃圾回收的动态语言的舒适之上，以Zig这一快速基座来实现这套现代组合的尝试。编译器实现趋势这一更广的脉络，我在Perry - 用TypeScript打造的LLVM编译器中也有探讨。

8. 适合哪些问题与用途

那么revo实际适合用在哪里？综合其当前阶段与设计取向，以下领域较为自然。

  • 脚本与自动化：动态类型与简洁语法很适合短脚本、工具和粘合代码（glue code）。
  • 嵌入式脚本引擎：C嵌入API与小巧的解释器，适合像Lua那样作为其他应用的扩展语言嵌入。
  • 并发实验：spawn-join与通道模型，是轻松学习与试验并发概念的好场地。
  • 语言设计学习：用Zig写成的字节码虚拟机结构本身，对想钻研解释器实现的人来说是极佳的读物。

反之，对大型生产服务、必须依赖丰富库的数据分析与Web后端、以及长期维护至关重要的系统而言，现在还为时尚早。那片领域属于Python、Ruby、Node.js等生态深厚的语言。

9. 局限与生态 - 冷静审视

为求均衡，也要把阴影讲清楚。revo很有吸引力，但截至2026年仍背负着明显的约束。

  • 早期阶段（0.0.0）：语法与标准库随时可能变动。这意味着今天能运行的代码，下一个版本可能就坏掉。
  • 生态很小：几乎没有包仓库、第三方库，也几乎搜不到现成的示例与答案。遇到问题只能自己解决。
  • 平台差异：据介绍，部分平台（如Windows）尚未具备异步后端或功能完整的行编辑器。功能体验会因操作系统而异。
  • 性能未经验证：抛开基于Zig的潜力不谈，由真实基准测试验证的成熟优化仍为时尚早。
  • 贡献者稀少：由少数人主导的早期项目，其持续性与方向对外部变量较为敏感。

这些局限与其说是缺陷，不如说是年龄问题。所有成熟语言都曾是0.0.0。但站在评估采用的立场，把revo看作今日有趣的实验、而非明日的主力语言候选，才是准确的视角。

10. 开发者会感兴趣的地方

尽管如此，revo能勾起开发者好奇心，自有其明确理由。归纳为三点。

第一，理念的真诚。把乐趣当作设计原则而非口号去贯彻的痕迹，遍布于语法各处。管道、表达式块、简洁函数，都指向写代码之人的心情。对厌倦了性能竞赛的人来说，这个方向本身就很新鲜。

第二，好点子的组合。把Ruby的表现力、Elixir的并发、Rust的结果类型、Lua的可嵌入性汇于一门语言的尝试，本身就极具学习价值。你能用很小的代码体会到每个点子为何出色，以及把它们放在一起时如何彼此相融。

第三，Zig生态的成长。revo是用Zig能做什么的鲜活案例。在Zig迈向1.0的当下，这类语言实现项目是衡量Zig潜力的好标尺。用系统语言去造另一门语言，也与用Rust重写工具的潮流相通，这一脉络在从Go到Rust - 迁移指南与用Rust实现的Zstandard中有更广的讨论。

11. 想亲自上手的话 - 入门指南

为想轻量上手revo的开发者整理一条务实路径，前提是仅用于学习与实验。

  1. 先备好Zig：revo由Zig构建，需先安装较新的Zig工具链。用zig build做调试构建，发布版则加上优化标志。
  2. 用REPL找感觉：在交互式REPL里直接输入表达式块与管道。everything is something的手感，靠一行执行最快上手。
  3. 一个小并发示例：用spawn-join与通道启动两三个worker。在同步代码上加一个词spawn的体验，正是关键。
  4. 体验内置测试：把test块与源码写在一起，用--test运行，感受代码与验证同居一文件的结构。
  5. 窥探反汇编：用--dis输出字节码，观察动态语言在内部如何表示代码。
面对新兴语言，最健康的态度不是问我能用它做什么，而是问这个设计为何如此。revo正是一门对后一个问题有许多答案的语言。

12. 结论 + 立即可用的3点

用一句话总结revo便是：在Zig这一快速基座之上，以乐趣为标尺，将表达式导向、模式匹配、基于消息的并发这些现代动态语言理念编织而成的早期实验。它还不是生产级语言，却小而清晰地展示了语言设计的好潮流正流向何方。最后，留下三点即便你从不碰revo、今天也能带走的东西。

  1. 把思维切换到表达式导向。无论你用什么语言，把if和块视为产生值之物的习惯，都能让代码更短、更易读。从减少临时变量的小重构开始。
  2. 把错误当作值而非异常来处理。用返回值的形状呈现成功与失败，就很难漏掉失败处理。哪怕只对一个函数，也试着套用Result或元组返回的惯用法。
  3. 并发以稍后再spawn的方式切入。不要一开始就按异步设计，先把同步代码写清楚，再只把瓶颈处拆成任务——这个顺序对调试与理解更有利。
