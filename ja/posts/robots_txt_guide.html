robots.txt 완벽 가이드: 検索엔진 크롤링 최적화 전략 (Complete Guide to robots.txt: Search Engine Crawling Optimization Strategies)

robots.txt란 무엇인가?

robots.txt는 ウェブ사이트의 루트 디렉토리에 위치한 テキスト 파日로, 検索엔진 크롤러(봇)에게 사이트의 어떤 부分을 크롤링해도 되고 어떤 부分은 접근하지 말아야 하는지 지시하는 규칙을 담고 있습니다. 이 파日은 로봇 배제 표준(Robots Exclusion Protocol)이라는 ウェブ 표준을 따르며, 모든 週요 検索엔진(구글, 빙, 네이버 등)이 이 표준을 준수합니다.

robots.txt의 중요성

  • 크롤링 제어: 크롤러가 접근해야 할 페이지와 접근하지 말아야 할 페이지를 구分
  • 서버 자원 절약: 불필요한 크롤링을 방지하여 서버 부하 감소
  • 콘텐츠 보호: 민감한 情報나 중복 콘텐츠가 検索結果에 노출되는 것 방지
  • 크롤링 はい산 최적화: 크롤링 빈도와 깊이를 조절하여 중요 페이지에 우선순위 부여

robots.txt 파日의 기본 구조

robots.txt 파日은 매우 간단한 テキスト 형식을 가지고 있으며, 기본 구조는 次へ과 같습니다:

User-agent: [크롤러 이름]
Disallow: [접근 금지 경로]
Allow: [접근 허용 경로]
Sitemap: [사이트맵 URL]

週요 지시문(directives) 説明

  • User-agent: 규칙이 적용될 検索엔진 크롤러 지정
    • User-agent: * - 모든 크롤러에 적용
    • User-agent: Googlebot - 구글 크롤러에만 적용
  • Disallow: 크롤링을 금지할 경로 지정
    • Disallow: /private/ - /private/ 디렉토리 크롤링 금지
    • Disallow: / - 全体 사이트 크롤링 금지
    • Disallow: - 아무것도 금지하지 않음(すべて 허용)
  • Allow: Disallow 규칙에 はい외를 두어 특정 경로 허용
    • Disallow: /private/
    • Allow: /private/public.html - private 디렉토리 내 public.html만 허용
  • Sitemap: 사이트맵 파日 위치 지정
    • Sitemap: https://example.com/sitemap.xml

robots.txt 작성 시 注意사항

1. 올바른 위치에 파日 生成

robots.txt 파日은 반드시 ウェブ사이트의 루트 디렉토리에 위치해야 합니다. 다른 위치에 있으면 크롤러가 인식하지 못합니다.

올바른 위치: https://example.com/robots.txt
잘못된 위치: https://example.com/public/robots.txt

2. 대小文字 구分

一部 지시문과 경로는 대小文字를 구分합니다. 특히 URL 경로는 대小文字를 정확히 日치시켜야 합니다.

User-agent: Googlebot (O)
user-agent: Googlebot (X - 一部 크롤러는 인식할 수 있지만 권장하지 않음)

Disallow: /Private/ (Private 디렉토리만 차단)
Disallow: /private/ (private 디렉토리만 차단, 위와 다른 디렉토리)

3. 와日드카드 使用법

一部 크롤러(구글, 빙 등)는 패턴 매칭을 ための 와日드카드를 サポート합니다:

  • *: 0개 이상의 文字와 日치
  • $: URL의 끝을 의미
Disallow: /*.pdf$ (모든 PDF 파日 차단)
Disallow: /private* (private로 開始하는 모든 URL 차단)

4. セキュリティ 관련 注意사항

중요: robots.txt는 セキュリティ 수단이 아닙니다! 민감한 情報나 비밀 페이지를 보호하는 용도로 使用해서는 안 됩니다.

  • robots.txt 파日은 누구나 볼 수 있습니다 (https://example.com/robots.txt로 접근 可能)
  • 악의적인 크롤러는 robots.txt 규칙을 무시할 수 있습니다
  • 민감한 情報는 パスワード 보호, IP 제한 등 セキュリティ 機能으로 보호해야 합니다

효과적인 robots.txt はい제

1. 기본적인 robots.txt (대부分의 소규모 ウェブ사이트에 적합)

User-agent: *
Disallow:
Sitemap: https://example.com/sitemap.xml

위 はい제는 모든 크롤러에게 사이트 全体 크롤링을 허용하고, 사이트맵 위치를 알려줍니다.

2. 관리자 페이지 및 중복 콘텐츠 차단

User-agent: *
Disallow: /admin/
Disallow: /temp/
Disallow: /duplicate-content/
Disallow: /*?sort=
Disallow: /*?filter=
Allow: /admin/public-stats.php
Sitemap: https://example.com/sitemap.xml

이 はい제는 관리자 페이지와 임시 파日, 그리고 整列/フィルタリング된 중복 페이지를 차단하지만, 공개 통계 페이지는 허용합니다.

3. 検索엔진별 다른 규칙 적용

User-agent: Googlebot
Disallow: /google-excluded/

User-agent: Bingbot
Disallow: /bing-excluded/

User-agent: *
Disallow: /private/
Disallow: /temp/
Sitemap: https://example.com/sitemap.xml

이 はい제는 구글과 빙에 서로 다른 규칙을 적용하고, 나머지 모든 크롤러에게는 공통 규칙을 적용합니다.

4. 리소스 최적화를 ための robots.txt

User-agent: *
Disallow: /api/
Disallow: /large-images/
Disallow: /*.zip$
Disallow: /*.pdf$
Disallow: /*?*
Crawl-delay: 10
Sitemap: https://example.com/sitemap.xml

이 はい제는 API 호출, 대용량 이미지, 압축 파日, PDF 파日 등 서버 리소스를 많이 使用하는 콘텐츠의 크롤링을 제한하고, 크롤링 간격을 10秒로 設定합니다 (一部 検索엔진만 Crawl-delay サポート).

週요 検索엔진 크롤러 목록

検索엔진 週요 크롤러 이름
구글 Googlebot, Googlebot-Image, Googlebot-Mobile
빙/MSN Bingbot, MSNBot
네이버 Yeti
야후 Slurp
바이두 Baiduspider

robots.txt와 사이트맵의 관계

robots.txt와 sitemap.xml은 検索엔진 최적화(SEO)에서 상호보완적 역할을 합니다:

  • robots.txt: 크롤러에게 접근하면 안 되는 페이지를 알려줍니다
  • sitemap.xml: 크롤러에게 중요한 페이지와 그 메타데이터(최종 修正日 등)를 알려줍니다

두 파日을 함께 使用하면 検索엔진이 ウェブ사이트를 더 효율적으로 색인화할 수 있습니다. robots.txt에서 sitemap.xml 위치를 명시하는 것이 좋은 관행입니다:

User-agent: *
Disallow: /private/
Sitemap: https://example.com/sitemap.xml

robots.txt 테스트 방법

robots.txt 파日을 적용하기 전에 올바르게 작성되었는지 確認하는 것이 중요합니다:

1. 구글 서치 콘솔 使用

구글 서치 콘솔(Search Console)에서 제공하는 robots.txt 테스터를 使用하면 구문 エラー를 確認하고 특정 URL이 크롤링 허용/차단되는지 테스트할 수 있습니다.

  1. 구글 서치 콘솔에 로그인
  2. '設定' > 'robots.txt 테스터' メニュー 選択
  3. robots.txt 内容 入力 또는 현재 파日 読み込む
  4. 테스트할 URL 入力 후 '테스트' 버튼 클릭

2. 수동 테스트

robots.txt 파日을 배포한 후 次へ URL로 직접 접근하여 올바르게 표시되는지 確認합니다: 

https://your-domain.com/robots.txt

日반적인 실수와 해결책

1. 모든 크롤러 차단

User-agent: *
Disallow: /

위 규칙은 모든 크롤러의 접근을 차단합니다. 이는 테스트 환경이나 개발 중인 사이트에는 적합할 수 있지만, 공개 ウェブ사이트에서는 検索엔진에 표시되지 않게 됩니다.

2. 부적절한 파日 경로

Disallow: admin

경로는 항상 슬래시(/)로 開始해야 합니다. 올바른 방법:

Disallow: /admin

3. robots.txt에 사이트맵을 含む하지 않음

사이트맵 URL을 robots.txt에 含む하면 検索엔진이 사이트맵을 簡単に 찾을 수 있습니다:

Sitemap: https://example.com/sitemap.xml

4. User-agent 그룹 사이에 빈 줄 なし

User-agent: Googlebot
Disallow: /google-only/
User-agent: *
Disallow: /private/

다른 User-agent 그룹 사이에는 빈 줄을 넣는 것이 좋습니다:

User-agent: Googlebot
Disallow: /google-only/

User-agent: *
Disallow: /private/

robots.txt 파日 アップデート 週기

robots.txt 파日은 크롤러가 사이트를 방문할 때마다 確認하므로, 변경사항은 速く 적용됩니다. 그러나 몇 가지 고려할 점이 있습니다:

  • 대부分의 検索엔진은 robots.txt 파日을 캐싱하여 日정 期間 동안 다시 確認하지 않을 수 있습니다
  • 구글은 日반적으로 하루에 한 번 정도 robots.txt 파日을 다시 確認합니다
  • 중요한 변경사항이 있을 경우, 구글 서치 콘솔에서 robots.txt 파日을 재제출하여 즉시 적용되도록 요청할 수 있습니다

실전 팁: robots.txt를 통한 SEO 최적화

1. 중복 콘텐츠 문제 해결

検索엔진이 중복 콘텐츠를 색인화하지 않도록 URL 매개변수가 있는 페이지를 차단합니다:

User-agent: *
Disallow: /*?sort=
Disallow: /*?filter=
Disallow: /*?page=
Disallow: /*?session=

2. 크롤링 はい산 최적화

検索엔진은 각 사이트에 제한된 '크롤링 はい산'을 할당합니다. 중요하지 않은 페이지를 차단하여 중요한 페이지에 더 많은 크롤링 리소스가 배分되도록 합니다:

User-agent: *
Disallow: /old-content/
Disallow: /print-versions/
Disallow: /tags/

3. 検索結果에 표시하지 않으면서 크롤링은 허용

특정 페이지를 크롤링은 허용하되 検索結果에 표시하지 않으려면, robots.txt 대신 페이지에 noindex 메타タグ를 使用합니다:

<meta name="robots" content="noindex, follow">

이 방법은 페이지의 링크를 따라가도록 허용하면서도 해당 페이지 자체는 検索結果에 표시되지 않게 합니다.

4. 단계적 변경

대규모 사이트의 경우, robots.txt 파日을 한 번에 크게 변경하면 はい상치 못한 結果가 발생할 수 있습니다. 변경사항을 단계적으로 적용하고 検索 트래픽을 모니터링하는 것이 좋습니다.

결론

robots.txt 파日은 간단하지만 ウェブ사이트의 検索엔진 가시성과 성능에 큰 영향을 미칠 수 있는 강력한 ツール입니다. 올바르게 구성된 robots.txt 파日은 次へ과 같은 이점을 提供します:

  • 検索엔진이 중요한 콘텐츠에 集中하도록 유도
  • 불필요한 크롤링으로 인한 서버 부하 감소
  • 중복 콘텐츠 문제 해결 도움
  • 사이트맵과 함께 使用하여 색인화 효율성 극대화

모든 ウェブ사이트는 고유한 요구 사항이 있으므로, robots.txt 파日은 사이트의 구조와 목표에 맞게 맞춤 設定해야 합니다. 정기적으로 검토하고 アップデート하면 検索엔진이 ウェブ사이트를 더 효율적으로 크롤링하고 색인화하는 데 도움이 될 것입니다.

最後으로, robots.txt는 SEO 전략의 一部日 뿐이며, 메타 タグ, 사이트맵, 구조화된 데이터, 품질 콘텐츠 등 다른 요소들과 함께 종합적으로 접근해야 한다는 점을 기억하세요.
