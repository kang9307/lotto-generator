线性注意力换来了什么，又放弃了什么

把过去压缩进固定大小的状态，成本会变成线性，但精确回忆的价格会上涨

2026-07-30 IT/技术

引言：线性不是更便宜，而是买了别的东西

线性注意力这个名字容易引起误读。第一次听到的人大多把它理解成把同一件事做得更便宜的办法。可实际发生的事情不是这样。不是把同一件事做便宜了，而是改买了另一件东西。漏掉这个区分，后面所有的判断都会跑偏。

起点是一篇梳理谱系的文章。从softmax注意力到线性注意力，再经DeltaNet与Gated DeltaNet一路走到Kimi Delta Attention，逐级拆解的文章最近出现在开发者社区。这是一篇不错的讲解，而本文的目的并不是把那条谱系再总结一遍。

本文要回答的问题有两个。第一，线性注意力到底把什么变便宜了。第二，它拿什么作为交换。由此又派生出对从业者最重要的第三个问题：我做的工作，是承担得起这份代价的那一类吗。

先把结论的方向钉住。标准注意力用高价买到的是全量重查权，也就是可以把任意词元原样再看一遍的权利。线性注意力卖掉这项权利，换来一张摘要卡。摘要可以一直改写，但大小不会增长。所以只要要点就够的活儿几乎没有损失，而必须原样取出原文的活儿会最先崩掉。delta规则系做的事情是把那道墙往后推，而不是把它拆掉。

手法的定位成功了。原文所涉的三种手法与论文全部得到确认，本文只把那些论文摘要中可确认的范围当作依据。公式没有搬运。概念用文字讲清，只在必要处放了极短的伪代码。凡是没有写明测量条件的数字，都连同「缺少条件」这一事实一起标出，绝不脱离条件引用。没能确认的内容原样留在正文里。缓存优化这条线已经在KV缓存共享与注意力压缩里讲过，这里不再重复。

最后一行特别值得强调。标准注意力的成本与序列长度的平方成正比这个说法用得太广，以至于让人觉得它一定写在原论文的摘要里，可摘要里没有。摘要是直接打开确认的，其中并没有关于平方成本或序列长度成本的句子。逐层计算复杂度的对比表在正文中，但在摘要页上无法确认。因此本文把平方成本的依据取自线性Transformer论文的摘要。那边在第一句就明确写着，由于关于输入长度的平方复杂度，Transformer 在很长的序列上慢得不可接受。

看起来是件小事，但这是习惯问题。越是人人皆知的事实，其引用越常被挂到不相干的地方。

2. 标准注意力买到的东西 - 全量重查权

先把成本讲清。在长度为T的序列里，查询与键的配对会以T的平方的量级出现。训练阶段这直接就是计算量，生成阶段则意味着每出一个新词元都要把此前的全部历史重新看一遍。因此存放历史的缓存会随长度成比例增长。

这里常出现一种误读：把这份成本读成浪费。然而那份成本不是浪费，而是购买。买的是什么？

  • 全量重查权 - 在生成第三万个词元时，可以把第17个词元的键和值按原样再看一遍。不是压缩过的摘要，而是原件。
  • 选择性 - softmax 会把权重集中到相关的位置上。看什么，可以在每个时刻重新选。
  • 归一化 - 权重之和是固定的，所以历史变长后贡献度的尺度仍然成立。
  • 事后提问 - 输入进去的时候不必知道之后会问什么。问题定下来之后还能回去翻过去。这一性质在实务中最有价值，同时也最容易丢掉。

最后一条是本文会反复回到的地方。一旦折叠成固定大小的状态，留什么就在看到问题之前已经定了。模型必须在不知道接下来会被问什么的情况下做出摘要。这件事在原理上就很难，而这正解释了整条谱系。

3. 线性化的思路 - 折成递推，把状态钉住

思路本身简单得令人意外。把softmax换成核特征映射的内积，乘法的顺序就可以调换。线性Transformer论文的摘要把这一处写作利用矩阵乘法的结合律，把复杂度从序列长度的平方降到线性，并补充说这种形式允许一种迭代式实现，并揭示了它与循环神经网络的关系。

用文字来讲是这样。不再保存过去所有的键和值，而是把它们不断叠加到同一个矩阵里。把词元扫一遍，每一步更新同样大小的状态。扫完之后，过去就装在那一个状态里。大小从头到尾都一样。

# 概念伪代码 - 只比较两种方式各自带着什么
# 不是实现，归一化、多头与位置信息都省略了

## 标准注意力：把过去全部带着走
cache = []                            # 随长度成比例增长
for t in 1..T:
    cache.append( (key[t], value[t]) )
    out[t] = weighted_sum(query[t], cache)   # 每一步都重看整个 cache
# 状态大小 = 与长度成正比      每词元成本 = 此前读过的长度

## 线性注意力：只带一个固定大小的状态
S = zeros(d_value, d_key)             # 大小与 T 无关
for t in 1..T:
    S = update(S, key[t], value[t])   # 一直往同一个位置覆写
    out[t] = read(S, query[t])        # 不再回看 cache
# 状态大小 = 固定              每词元成本 = 与长度无关

# ★ 下面这个循环里没有任何办法回看 key[1] 到 key[t-1]。
#   只能看到 S 里剩下的东西。这就是压低成本所付的代价。
#   写成条件就是这样。
#     if 需要的信息 还留在 S 里        -> 正确答案
#     if 需要的信息 已被覆写掉         -> 看起来合理的错误答案

得到的东西很清楚。生成阶段每个词元的成本不再依赖历史长度。缓存不增长，内存也就不被长度拖着走。在长上下文下，这个差别有时会不再是程度问题，而变成可行与不可行的问题。

但也有东西一起消失了。用一手来源那篇文章的说法，线性化是以丢掉softmax的归一化与选择性为代价换来了效率。而比这更根本的东西写在上面伪代码的最后一段注释里：回看过去的手段本身就不存在。只能看到状态里剩下的部分。

4000倍这个数字该怎么读

线性Transformer论文的摘要写道，在很长序列的自回归预测上最高快4000倍。这是个抓人的数字，实际上也被广泛引用。正因如此才必须核对条件。

  • 写明的条件 - 自回归预测这一任务类型、很长的序列这一定性描述，以及最高这个限定词。
  • 摘要里没有写的 - 模型规模、确切的序列长度、硬件、批大小、对照实现的配置。这五栏是空的。
  • 所以本文只把这个数字当作方向的依据。也就是读成在很长序列的逐步生成上差距会大幅拉开，而不读成我们这边也能出4000倍。
  • 同样的规则也用在 Mamba 论文的吞吐5倍上。摘要是在快速推理的语境里写下这个倍数的，但批大小与硬件不在摘要里。

这个习惯之所以重要，是因为线性系的收益对条件格外敏感。收益的大小会随序列长度变化。短上下文下差距几乎没有，上下文越长差距越大。没有写长度的速度主张，在线性系里信息量尤其低。

4. DeltaNet系修好的东西 - 覆写与遗忘

下面进入谱系的正题。而这条谱系读作用三种不同方式攻同一个问题的记录最容易理解。问题只有一个：如何把固定大小的状态用得不浪费。

甲、加法不等于赋值

一手来源那篇文章提出的问题很准确：加法不等于赋值。什么意思？纯粹的线性注意力是把新信息加进状态。可如果不同的键不完全正交，加进去的值就会与原有的值混在一起。同一个位置写两次，不是被覆盖，而是被叠加。文章把这种情形描述为：把已经写过的值再写一次，状态会给出那个值的两倍。

用内存更新来打比方：我们想要的是赋值，实际发生的是累加。每次需要更新时都留下上一次的痕迹，状态于是越来越脏。这就是所谓的写入干扰问题。

乙、delta规则 - 只写误差

DeltaNet的思路正是对此的回答：不写整个值，只写它与当前状态已能给出的值之间的差。也就是拿那个键去问状态，算出返回值与正确值之间的误差，只反映这部分。已经存得好就几乎什么都不写，偏了就只改那么多。

摘要中可确认的表述如下。线性注意力的Transformer与状态空间模型被提出作为线性时间的替代方案，但在需要上下文内检索的任务上仍不及Transformer；把加法式更新替换为delta规则的更具表达力的变体已被发现对联想回忆更有效；然而训练这类模型的既有算法不能沿序列长度并行，因此在现代硬件上效率低下。论文的贡献就在于用硬件高效的算法解决了这一并行化问题。

最后这一处在实务上很重要。思路再好，训练不能并行就没法放大规模。这条谱系上每一步的论文都要连同算法与核函数一起给出，原因就在此。架构上的想法与到硬件的映射是分不开的。

丙、门控 - 在定点修补之外加上整体擦除

Gated DeltaNet在此之上加了遗忘。摘要的表述很清楚：近期研究分别探索了用于自适应记忆控制的门控与用于精确记忆修改的delta更新规则这两种机制，而作者观察到这两者是互补的，即门控能实现快速的记忆擦除，delta规则则有助于有针对性的更新。

用文字讲是这样。delta规则擅长改写某个具体条目，但对于已经过时、该整块丢掉的东西，它不擅长一次清空。门控通过调节保留多少来承担这件事。可以理解为话题切换时迅速放掉上一个话题的能力。

摘要里没有具体数字。它只写道，在包含语言建模、常识推理、上下文内检索、长度外推与长上下文理解的多个基准上持续超过 Mamba2 与 DeltaNet 这类既有模型，而分数、模型规模与训练词元数在摘要范围内无法确认。因此本文只引用优势的方向，不引用其幅度。

丁、按通道衰减 - 把门控切得更细

Kimi Delta Attention把那个门控进一步细分。按一手来源的说明，原先由一个数值决定整个状态保留程度的做法，被改成按维度取不同的比率。这样就能清空某个通道，同时保住另一个通道。

论文摘要中可确认的是：KDA 是把 Gated DeltaNet 扩展到更细粒度门控机制的、具表达力的线性注意力模块，其目的是更有效地使用有限的有限状态循环记忆。其定制的分块算法通过对角加低秩转移矩阵的一种特化变体获得硬件效率，在大幅减少计算的同时保持与经典delta规则的一致性。

值得注意的表述是有限。论文自身是以记忆有限这一事实为前提来谈其中的效率。整条谱系是把容器用好的竞赛，而不是把容器做大的竞赛，这一点在此变得清楚。

5. 仍然留着的那道墙 - 精确回忆被状态大小锁住

这一节是本文的中心，目的是确认前面那些改善虽然可观，但种类是定死的。

最直接的依据是Repeat After Me论文。摘要的表述是：作者把使用与序列长度无关的固定大小潜在状态的模型统称为广义状态空间模型，并指出这类模型在推理效率上有前景，但在需要从输入上下文中复制的任务上相比Transformer受到限制。随后他们对字符串复制这一简单任务作了理论分析，并写道其证明了两层Transformer可以复制指数长度的字符串，而这些模型则从根本上受其固定大小潜在状态的限制。

从根本上这个说法是关键。这不是因为实现不成熟，也不是因为训练不够，而是在说容器的大小定了，能装的量也就定了。摘要进一步报告，评测预训练大语言模型的结果显示Transformer模型在从上下文中复制与检索信息这件事上大幅领先状态空间模型，并总结说这些结果合起来提示两个谱系在具有实际重要性的任务上存在根本性的差距。

有意思的是，同一个诊断在多个地方独立出现。

  • DeltaNet 论文开篇就写道，线性时间的谱系尤其在需要上下文内检索的任务上仍不及Transformer。一篇提出改进的论文把这个弱点当作出发点。
  • Mamba 论文指出多种次平方时间架构在语言这类重要模态上不如注意力，并把其核心弱点指为缺乏基于内容的推理能力。其修法是引入选择性，让状态空间的参数成为输入的函数。
  • Gated DeltaNet 论文以线性Transformer在检索与长上下文任务上表现有限这一表述开篇。
  • Kimi Linear 论文把改进的目的明确写为更有效地使用有限的有限状态记忆，并不否认记忆是有限的这一前提。

四篇论文从不同角度指向同一道墙。而每篇的贡献都是把那道墙往后推。delta规则把同一个容器用得更不脏。门控迅速清出不再需要的东西。按通道衰减把该清的与该留的分得更细。全都是把同一个容器用得更好的办法，没有一个是把容器做大的办法。

一个比喻 - 档案柜与摘要卡

标准注意力像把整个原件档案柜背着走。又重又占地方，但日后任何一份文件都能把原件再取出来。

线性注意力是一张摘要卡不断改写。又轻又快。delta规则是把卡上已写条目擦掉改正的手法，门控是把过时条目整块擦掉的手法，按通道衰减是按条目以不同速度擦掉的手法。手法越好，卡片越充实。可是卡片的大小一次都没有变大。

所以问卡上没写的东西，就没有答案。更糟的是模型不会说没有答案。它会拿卡上相似的条目拼出一个看起来合理的答案。在实务中这才是真正的危险：失败不沉默，而是伪装。

表里最有实务意义的一行是最后一行。成本问题会通过账单告知你，回忆问题不会告知任何人。所以回忆这一侧必须由人来加上闸门。第8节讲的就是这件事。

6. 混合不是妥协，而是这笔交换的结论

混合这个词常听起来像决定不下来于是各掺一半。这里不是。它是把上一节那笔交换如实算一遍就会得到的结论，而依据直接写在论文摘要里。

  • DeltaNet 论文写道试了两种混合结构：一种是每隔一层插入滑动窗口注意力层，另一种是加入两层全局注意力层，并且这些混合结构超过了强Transformer基线。
  • Gated DeltaNet 论文写道，开发了把自身层与滑动窗口注意力或 Mamba2 层结合的混合架构，同时改善了训练效率与任务表现。
  • Kimi Linear 论文说明其基于KDA 与 Multi-Head Latent Attention 的逐层混合进行预训练，并主张混合的线性注意力架构在公平比较下首次超过了全注意力。

这里该读的是两这个数字。全局注意力层没有全放，只放两层却超过了强基线，这一表述说明了一些事。

  • 精确回忆的能力并非每一层都需要。少数几层就能恢复相当一部分。
  • 成本的大头由线性层承担。会增长缓存的层只是少数，因此成本随长度的增长被大幅抑制。
  • 所以混合不是把回忆与成本各分一半，而是只在需要回忆的地方付了钱。这样理解要准确得多。
  • Kimi Linear 报告的KV缓存最多减少75%正是从这个结构里来的。意思是大约是全注意力的四分之一，而它不是零这一点也要一并读到。剩下的那四分之一就是支撑回忆的层。

于是遇到混合这个词时该问的值就定下来了。这三个值实际上决定了回忆性能的上限。

  1. 全局注意力有几层。两层和八层是完全不同的故事。
  2. 按什么间隔分布。是挤在前部、均匀散开，还是放在后部。
  3. 使用窗口的层，窗口有多大。滑动窗口不是全局，窗口之外看不见。

在技术报告里怎么找到并读懂这些值，已经在技术报告怎么读里从报告解读的角度另行处理。本文专注于那些值为什么决定了回忆性能的上限。如果缺的是Transformer本身的基础，去机器学习自学路线图的相应阶段会更快。

7. 怎么读1M上下文这类标注

线性系的扩散是与上下文长度标注的通胀一起来的。所以读这类标注的能力成了实务技能。

先把标注的含义收窄。上下文长度的意思是输入放得进去，不是在那个长度上准确率仍然保持。它是容量标注，不是性能标注。

作为这一区分的依据，最好的材料是RULER论文。整理其摘要是这样。从大量干扰文本中找出一段信息的简单检索测试被广泛采用，但它只能反映长上下文理解的表层形态。于是作者构建了可自由设定序列长度与任务难度的合成基准，让待查内容的种类与数量多样化，加入多跳追踪与聚合这样的新类别，对17个模型做了13类任务的评测。

结果的表述才是关键。在简单检索测试上几乎能拿到满分，但随着上下文长度增加，几乎所有模型的表现都大幅下滑；而且它们都声称支持32K以上的上下文，其中只有一半能在32K的长度上维持令人满意的表现。一个支持200K的模型在输入长度与任务难度提高后同样还有很大改进空间。

这个结果不能原样套到线性系上。摘要里没有把 RULER 的评测对象限定在某个架构谱系的表述，本文确认的范围内也看不到这样的划分。也就是说这不是线性系的缺陷，而是长上下文的普遍问题。不过固定大小状态这一结构在原理上会更重地承受这个问题，这一点由第5节的依据推出。把两件事不混在一起才准确。

同样的规则也要用在 Kimi Linear 的数字上。1M上下文解码吞吐最高6倍是吞吐主张，不是在主张那个长度上准确率仍然保持。两条轴要分开读。

8. 判断自己的任务是否依赖回忆的流程

这里转换视角。此前讲的是架构，从这里开始讲自己能做的事。

冷静地说，选择通常不在自己手上。大多数从业者不挑注意力机制。他们挑模型，或者其实是用公司签了合同的那个模型。而供应方一换架构，是不会通知的。版本号会往上走，但内部构成怎么变了得打开报告才知道，而很多时候没有报告。

那么实务上的行动就收窄成一件事：判断自己的任务是否依赖回忆，并预先架好相应的回归闸门。这样架构变了的时候，你会先知道。

第1步 - 把回忆依赖度打成分

# 判断自己的任务是否依赖回忆 - 概念流程
score = 0

if 输出里必须原样包含原文字符串:            score += 3
if 答案散落在输入的两处以上:                score += 2
if 有多个外观与答案相似的干扰项:            score += 2
if 答错时看起来依然合理:                    score += 2
if 输入通常超过八千词元:                    score += 1

if score >= 5:
    依赖回忆
    # 位置扫描闸门是必需的。确认是否有全局注意力层及其数量。
    # 强制输出格式，使其能与原文比对。
elif score >= 3:
    处在边界上
    # 只对引用部分做人工抽检。抽检比例要写进文档。
else:
    属于要点型
    # 可以直接享受线性系带来的成本收益。

# ★ 分数本身不是目的，不漏掉这五个问题才是目的。

把五个问题逐一展开。顺序是有意义的，越靠上越决定性。

  • 是否需要原文字符串原样出现 - 条款编号、金额、日期、标识符、函数签名、配置键。只要存在错一个字符就不能用的值，这个任务就依赖回忆。摘要做得再好也替代不了。
  • 答案散落在几处 - 在一处就只需找到。需要把三处拼起来就同时需要检索与追踪，此时难度会陡然上升。RULER 把多跳追踪单独列为一类，原因就在这里。
  • 相似的干扰项是否有多个 - 这一点最被低估。相似条款反复出现的合同、只有名字不同的函数遍布的代码库、格式相同的数万行日志。在摘要卡上，这些条目很容易互相混起来。
  • 答错时是否看得出来 - 摘要会以看起来合理的方式出错，引用则一比对原文就会被抓住。看不见的失败更危险。所以把输出格式强制成可比对的形状本身就是一道防线。
  • 输入是否长 - 放在最后是有原因的。长度不是单独的指标。短的也可能依赖回忆，长的也可能属于要点型。长度是放大其余四项的变量。

第2步 - 用自家文档搭位置扫描闸门

若判定为依赖回忆，就不能只靠相信公开基准的分数了事。自家文档与基准的分布不同。干扰项的密度、文档结构、术语重复的样态全都不一样。

# 用自家文档搭的回忆回归闸门 - 概念流程
# 不看公开基准的分数，在自家数据上确认

for length in [8k, 32k, 128k, 256k, 512k]:
    for position in [前 5%, 25%, 50%, 75%, 后 95%]:
        doc = build_haystack(our_corpus, length)
        doc = insert_target(doc, position, target_span)
        ans = ask(doc, question_requiring_verbatim_quote)
        ok  = exact_match(ans, target_span)   # 逐字匹配，不是摘要匹配
        record(length, position, ok)

# 判定规则要在看到任何数字之前写下来
#   pass : 所有位置上准确率 >= 0.98
#   warn : 任一位置上 0.90 <= 准确率 < 0.98
#   fail : 任一位置上 准确率 < 0.90
#
# ★ 相信这个闸门之前，先故意抽掉目标语句跑一遍。
#   那时若不报 fail，说明这个闸门什么也没在测。
#   此前所有的通过都毫无意义。

这套测试装置里有四个不能让步的点。

  • 扫描位置 - 把目标语句分别放到文档的前、中、后。在使用固定大小状态的结构里，前部的信息被覆写的余地更大。只测后部就抓不到这类失败。
  • 扫描长度 - 单一长度上的分数不会告诉你阈值在哪。我们想知道的不是分数，而是从几万词元开始崩。
  • 按逐字匹配评分 - 用语义相似度评分，看起来合理的错答就会通过。要测回忆，评分也必须按回忆的标准。
  • 先写判定规则 - 看到结果之后再定标准，人一定会定在能通过的那个值上。这不是诚信问题，而是认知问题。

第3步 - 为架构变动做好准备

  • 把模型版本记进日志 - 不留下哪个版本出了哪个分数的记录，就算发现退化也定不了原因。
  • 定期跑闸门 - 供应方的模型与自家发布周期无关地在变。自己什么都没改的那一周，结果也可能变。
  • 依赖回忆的任务把检索放到前面 - 不要让模型把长文档整个吞下去，而是只切出相关区间再喂进去。这是用流水线设计绕开状态大小限制的办法，通常也最便宜。
  • 强制引用 - 要求在答案之外原样搬出作为依据的语句，再机械地比对该语句是否真的存在于原文。这一层能把回忆失败从沉默变成有声。
  • 要点型任务反过来放它一马 - 对分类、路由、情感判定、对话上下文维持这类只要要点就够的活儿加回忆闸门，只会增加成本而毫无所得。闸门也是资源。

结语：不是选来的，而是继承来的交换

先从这条谱系实际展示出来的东西说起。折成使用固定大小状态的递推形式后，关于序列长度的成本变成线性，生成时每词元的成本与长度无关。使用那个状态的手法经三个阶段得到了实质性的改善：只写误差的delta规则、清出不再需要之物的门控、按通道以不同速度清除的细分化。而且已经出现了只在部分层放全局注意力的混合结构在公平比较下超过全注意力的主张。到这里都能在论文摘要中得到确认。

没能确认的部分也明确写下来。一手来源写道这一谱系中有两种被用在最新的 Qwen 与 Kimi 模型系列里，但究竟哪个版本以何种构成采用了它，在 Qwen 一侧没能打开一手资料确认。Kimi 一侧有依据，因为论文本身说明了逐层混合的构成。另外Gated DeltaNet 优势的幅度因摘要里没有数字而无法引用，而本文引用的倍数中没有任何一个是连同批大小与硬件一起写明的。原始Transformer论文摘要里没有平方成本表述这一事实也原样留下。

从业者要带走的有三点。

  1. 线性不是便宜的意思，而是买了摘要的意思。标准注意力可以把每个词元再看一遍，线性注意力只看得到摘要。delta规则与门控是把摘要做得好得多的办法，而不是把摘要还原成原件的办法。
  2. 自己的任务是否依赖回忆，是唯一能由自己决定的事。架构是给定的。是否需要原文逐字、答案分散的程度、是否存在外观相似的干扰项、失败是否可见。先判定这四项，再架上相应的闸门。
  3. 上下文长度标注是容量，不是性能。没有按长度的准确率走势、没有位置扫描、没有逐字评分的长度标注，等于还什么都没说。而且这份确认要在自家文档上做，不是在公开基准上。

最后一句。这笔交换不是我们选来的，而是继承来的。坐在决定注意力方式那个位置上的从业者极少。但判定自己的工作站在这笔交换的哪一侧，并架好在判定出错时能让自己察觉的装置，是任何人都能做的，而且这基本上就是全部。成本会通过账单告知你。回忆不会有人告知你。
