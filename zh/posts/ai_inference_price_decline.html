单价降了20%，这个月的账单却更高了

成本究竟被削在哪里，以及这份节省为什么落不到自己的支出上

2026年8月23日 IT/技术

引言：降价公告与账单为何对不上

降价公告发出来了。输入降了20%，输出降得更多。可是打开这个月的用量页面，金额比上个月还高。既没有配置失误，流量也没有暴涨。

这种错位不是故障，而是算术。账单不由单价决定，而是由单价 × 令牌数决定。公告只动了前一项，后一项这段时间一直在悄悄长大：上下文稍微加长了、思考强度上调了一档、智能体原来一个任务调三次，现在调五次。

这里要谈两件事：推理单价为什么下降，以及这份节省为什么到不了自己的支出上。后者是正文。顺带还会看怎样按项目读价格表，以及成本实际在哪些地方被决定。

关于价格的前提。文中出现的所有单价都是2026年8月23日在官方价格页面上确认的数值，并附有模型名、单位与币种。推理价格变动频繁。促销结束、档位改版、新模型发布都可能让它此后发生变化，因此实际测算必须重新核对当时的官方页面。本文不推荐任何特定供应商，也不用价格排优劣。

1. 这次确认到的内容——数字与条件

先简短交代起因。OpenAI 在2026年8月21日下调了旗舰模型 GPT-5.6 Sol 的 API 单价。2026年8月23日在官方价格页面上读到的数值如下，单位一律是每100万令牌的美元。

项目标准批处理已确认的条件
输入$4.00$2.00每100万令牌
缓存过的输入$0.40$0.20缓存读取按未缓存输入单价的0.1倍计费
输出$20.00$10.00思考令牌也按输出计费
缓存写入未缓存输入单价的1.25倍GPT-5.6 系列
长文加价输入2倍 · 输出1.5倍输入超过272K令牌时对整个请求生效
上下文窗口1,050,000 令牌最大输出128,000令牌
价格性质促销标注为至少维持到2026年11月21日

降价前的单价据报道为输入$5、输出$30、缓存过的输入$0.50。不过官方页面只显示当前价格，因此降价前的数值依据的是新闻报道，这一点如实写明。按报道口径计算，输入降了20%，输出降了约33%。

这张表里最值得琢磨的一行不是单价本身，而是降幅在输入和输出上并不一致这个事实。若成本是均匀下降的，两个数值本该同步移动。它们走势不同，说明要么输入与输出消耗的是不同资源，要么价格并非只由成本决定。实际上两者都是。

把同一页面上的低档位并排看，差距更明显。GPT-5.6 Terra 是 $2.00 / $0.20 / $12.00，GPT-5.6 Luna 是 $0.20 / $0.02 / $1.20（输入 / 缓存过的输入 / 输出）。即使在同一家供应商内部，最高档与最低档的输入单价也差20倍。这个差距后面还会再出现。

2. 单价下降的四条线——成本被削在哪里

把推理成本写成一行就是：把加速器运行一小时的费用 ÷ 这一小时处理的令牌数。能往下走的路只有缩小分子或扩大分母，实际发生的一切都落在这两者之一。

2.1 硬件——缩小分子

推理和训练的瓶颈不同。每生成一个令牌都要把模型权重从显存里读出来，所以在解码阶段决定速度的往往是显存带宽而非算力。换代时值得盯的数字，是带宽和容量而不是峰值算力。

  • 带宽提升——同样时间里更快读出权重，每秒令牌数就上去了。分母变大
  • 低精度运算单元——硬件直接支持窄位宽，同样功耗就能跑更多运算
  • 显存容量——一张卡上能装下更多请求的状态，并发数就上去了
  • 互联——模型切分到多张卡上时，卡间通信若成为瓶颈，就会产生相应的空转

不过硬件改进是反映到价格上最慢的一项。设备跟着合同与折旧周期走，已经铺开的那一代会一直留在成本里，直到寿命结束。这也是发布会上的倍数与实际服务成本不同步的原因。这部分在推理硬件的瓶颈里单独讲过。

2.2 服务化优化——扩大分母

从同一台机器上榨出更多令牌，这条线其实动得更快，因为它是软件。

  • 连续批处理——读一次权重的开销，不管这一批里装了几个请求都差不多。凑得越多，单个令牌摊到的份额越小。批越大时延越长、成本越低，所以这是一次交换而不是白得的性能
  • KV缓存管理——对话变长后，之前令牌的键与值会在显存里堆积。若一次性预留一大块连续空间，剩下的空隙就碎成了没法用的零头。提出按页管理的那篇论文报告说，减少碎片与冗余复制之后在同等时延下把吞吐提高到2〜4倍
  • 预填充与解码分离——一次性读完提示的阶段，和一个一个吐令牌的阶段，性格正好相反。混在同一份资源上就会互相干扰
  • 量化——把权重与KV缓存存成更窄的位宽，显存占用和带宽需求会同时下降。代价是精度，能压到哪一步取决于具体任务
  • 前缀缓存——多个请求共享开头部分时，这一段计算就能复用。这是成本节省直接作为价格表项目露出来的少见例子

2.3 模型效率化——同样质量，更少计算

第三条线的幅度最大。用更小的模型达到同一条性能线，买这条性能线的价格就整体塌下来。

斯坦福 HAI 的 AI Index 用一句话概括了这个走势：在 MMLU 上达到 GPT-3.5 水平（准确率64.8%）的模型，查询成本从2022年11月的每100万令牌$20降到2024年10月的$0.07，超过280倍。同一份报告还写明，按任务不同，年降幅在9倍到900倍之间。

读这个数字必须带上一个条件：它是买一条固定质量线的价格，不是前沿质量的价格。去年的最高档变成今年的中档，而不是今年的最高档变成去年价格的二百八十分之一。两条曲线走法不同。这就是为什么「AI便宜了280倍」这句话听起来总和实务感受对不上。

2.4 竞争与策略性定价——与成本无关的调整

最后一条线不是技术。价格并不总是成本加毛利，存在由定位决定的区间。这次公告里有两处痕迹。

  • 促销这个标注——带截止日期，意味着这是限期调整而非成本结构的改变。「至少维持到2026年11月21日」这句话不承诺此后的任何事
  • 输入与输出的降幅不同——若成本是均匀下降的，没有理由降得不一样。降得不一样，可能说明考虑了哪个数字在比较中被引用得更频繁

这不是要指责什么，而是怎么读的问题。价格下降和成本下降是两件事，不加区分的话，促销一结束预算计划就会整个动摇。看到降价公告，先要确认的不是降幅，而是这个价格是否带着期限。

3. 便宜了就用得更多——支出不降的真正原因

这里是正文。就算前面四条线全部属实，就算单价真的腰斩，很多团队的支出也不会减少。它和工业革命时期在煤炭上观察到的老现象结构相同：蒸汽机效率提高后，煤炭消耗不但没减，反而增加了。因为变便宜的东西又多出了那么多可以用的地方。

在推理上，这体现为四条路径。

  • 上下文变长——窗口有105万令牌，就没理由再把文档切块塞进去。整份丢进去开发更省事、效果通常也更好，于是就整份丢进去。单个请求的输入令牌悄悄涨了十倍
  • 思考步骤增加——思考强度上调一档，答案会变好。可思考令牌是按输出计费的，而输出通常比输入贵好几倍。买质量最贵的那条路，恰好藏在最顺手的那个旋钮后面
  • 智能体反复调用——一个任务不等于一次调用。在调用工具、拿回结果、再做判断的循环里，每一轮都会把之前的全部上下文重新当作输入送出去。轮次变多的同时每轮输入也在变多，所以累计输入令牌不是与轮次成正比，而是涨得更快
  • 实验门槛降低——便宜就开着跑。每次部署都跑评测集、一次比较十个提示变体、输出可疑就再换个模型问一遍。每一件都合理，加起来就是账单

用算术看很直白。单价降20%是系数0.8倍；同一时期每个任务的调用从3次变成5次是1.67倍；相乘是1.33倍。单价降了，支出涨了33%。两个数字都为真，不把它们分开看就没法解释眼前的局面。

如果这篇文章只能留一句话，就是这句：降价只有在使用方式不变时才是节省，而单价一降，使用方式就不会保持原样。这不是因为团队松懈，而是因为东西变便宜时，合理的选择本身就变了。上下文用得长，以前是浪费，现在是妥当的设计。

4. 价格表怎么读——它不止一行

只拿输入那一行做单价比较，结论会和实际账单对不上。把价格表上真实存在的项目种类记住，看哪家供应商都能用同一套方法读。

项目计的是什么在哪里出偏差
输入单价送进模型的令牌通常摆在最显眼处，却只是实际单价的一部分
输出单价模型生成的令牌比输入贵好几倍。输出偏长的负载，金额就在这里定下
缓存过的输入被复用的前缀命中条件苛刻，最小长度、前缀完全一致、保持时间都要满足，否则没有折扣
缓存写入把内容放进缓存的开销有时是加价而非折扣。没有复用就是亏
批处理以时延换来的处理能降到半价左右，但拿不到完成时刻的承诺
上下文长度区间过长的提示倍率只作用于超出部分，还是作用于整个请求，金额差别很大
思考令牌回复里看不到的内部生成按输出计费却不显示在屏幕上，因此与体感相悖
模态图像、音频输入换算成令牌的规则与文本不同
内置工具搜索、代码执行等有时在令牌之外还按调用次数另行收费

具体怎么出偏差，这次的价格页面上就能直接看到。缓存读取是未缓存输入的0.1倍，折扣很大；但缓存写入是1.25倍。缓存默认在1,024令牌以上的提示上自动生效，前缀哪怕差一个字符也不会命中。在系统提示最前面放一个时间戳，结果就是命中率每次都是0，只剩下写入的加价。GPT-5.6 系列的缓存保持时间标注为30分钟。

长文加价同理。输入超过272K令牌后，输入2倍、输出1.5倍会作用于整个请求。若按只对超出部分加价来估算，结果会与真实金额差很多：272,001令牌的请求，价格约为271,999令牌请求的两倍。

思考令牌在文档里写得很清楚：内容不通过 API 暴露，但会占用上下文窗口，并按输出令牌计费。数量会单独出现在回复的用量对象里，所以计量是可行的。文档还建议为思考和输出至少预留2万5千令牌。想看把多家供应商单价并排的表，可以去API价格比较整理，只是那张表在它自己的确认时点之后也需要重看。

5. 决定账单的是设计，不是单价

单价不是能谈判的东西，对多数团队来说就是给定值。令牌数则完全是设计的产物。同一个模型、同一个单价，账单也能差出好几倍。

设计判断在账单上的表现该问的问题
提示前半部分的构成直接决定缓存命中率会变的值是不是混在了前面
对话历史的保留方式轮次越多，每轮输入也跟着变多摘要与截断的时点是否定好了
工具输出的体积搜索结果与文件转储原样变成输入送进模型之前有没有裁剪
重试策略失败的调用也按已生成的量计费是否设了重试上限与退避
校验调用用另一次调用给输出打分，调用量翻倍是全量校验还是抽样校验
中断流式输出中途掐断，已生成的令牌仍然算数中断条件是否在靠前的位置生效
思考强度的默认值最贵的项目由一个默认值定死是否按任务分别设定

最常漏的是第三行。一旦挂上工具，送进模型的文本就不再由人来写。二十条搜索结果、整个文件、报错的调用栈原样变成输入，下一轮还会再送一遍。提示打磨得再好，不动这一块，总量也降不下来。

思考强度的默认值影响也大。质量变好看得见，所以容易把默认值调高，而代价从最贵的项目即输出令牌里出去。分类、抽取这类答案很短的任务是不是也在同一强度上跑，值得看一眼。把路由与缓存放到架构层面来谈的内容在AI编码的成本管理里，组织层面的限额与归属设计在令牌成本的FinOps里，硬塞上下文为何对质量也不好则在令牌过载的反效果里。

6. 换成便宜档位，总成本会下降吗

只看单价似乎不言自明——如前所述，同一系列里输入单价差20倍。可总成本不只是 API 费用这一项。

  • 重试——失败率上升，达成同样结果所需的调用次数就增加，单价差的一部分在这里被抵消
  • 人工确认时间——如果输出需要人来核对，需要核对的比例只要略微上升，人力成本很快就会盖过 API 费用
  • 下游善后——错误输出没被拦住就流走时的代价。难以计入模型，实际上往往最大
  • 路由本身的开销——判断该送到哪一档，本身又是一次调用或一段时延。路由不是免费的

所以标准最好定在失败的性质上，而不是单价。失败能被自动拦下、重跑一次就了结的任务——格式转换、分类、生成初稿——便宜档位占优。失败会占用人的时间或难以回退的任务——改代码、对外文档、最终判断——贵档位在总成本上反而可能更便宜。

拿捏大致感觉的办法只有一个：把一个人一小时的价值和100万令牌的价格放在同一杆秤上。100万令牌相当于几十件寻常任务，如果这个价钱低于一个人一小时，那么「少一次人工核对，换一档更好的模型」这个选择就成立。反过来，如果流程里人反正要看全量，升档能拿到的好处就有限。

7. 该计量什么才谈得上管理

没有计量就想降成本，往往止步于把提示写短。真正的大项其实在别处。该测的东西整理如下。

  • 金额和令牌分开记录——这条最重要。只留金额，单价变动和用量增长就混在一起，原因拆不开。令牌序列在单价变动后仍然可比
  • 每个请求的输入、输出、缓存命中令牌——要拆开而不是合计。合计只有在已经晚了之后才会动
  • 缓存命中率与命中失效的原因——是前缀变了、没到最小长度，还是超过了保持时间
  • 每完成一件任务的调用次数——这是智能体里的暴涨点。请求数常有人盯，每个任务的调用次数却往往没人看
  • 思考令牌在输出中所占比例——用量对象里单列，可以直接汇总
  • 落入长文加价区间的请求比例——若有请求在边界附近来回，这本身就是设计信号
  • 按功能、按团队的归属标签——不知道哪个功能花了多少，就选不出该削哪里

单位建议用每完成一件任务而不是每个请求。每个请求的成本，光靠把提示切碎就能降下来，总额却纹丝不动甚至上升。用户真正拿到的一个结果花了多少钱，才是唯一不会晃动的单位。

供应商界面上的拆解正在消失，所以把观测点只放一处会很被动。这件事在成本显示消失后还剩下的观测点里单独谈过。

8. 价格下跌真正打开的东西

只读到这里，降价好像没什么意义。这个结论是错的。单价下跌是朝着拓宽可做之事的范围、而不是压缩支出的方向起作用的，那一侧的效果是实打实的。

  • 实验的成本——把提示改二十遍、每遍都跑一次评测集，如今不需要开预算会。提升质量最可靠的办法是反复，而反复的价钱降了
  • 小团队的可及性——碰一碰顶级模型，不再需要合同和最低用量。个人用前沿模型做个原型再丢掉，已经成为正常的开发动作
  • 批量作业的经济性——固定质量线的价钱下来后，大批量分类、翻译、摘要这类单件价值低而件数多的活儿第一次算得过账。AI Index 说的280倍，在实务里就是以这种形态被感知的
  • 新的架构选项——批处理与缓存作为项目存在，意味着「拿时延换成本」可以在产品层面被选择。夜间批量处理重新成为合理选项

归结起来，价格下跌的成果体现在范围上而不是账单上。是用同样的钱做了更多事，而不是把同样的事做得更便宜。把这两件事分开，「看到降价公告，费用怎么没变」这个问题本身立错了，也就看得出来了。

9. 接下来看什么——已确定的与未确定的

不预测未来价格。但把已确定的事实和未确定的部分分开，读下一次公告时能省不少时间。

  • 已确定——2026年8月23日时点的展示单价、促销这一性质与最低维持期限、长文加价的基准线与倍率、缓存读取与写入的倍率、思考令牌按输出计费这一事实
  • 未确定——促销结束之后的价格、这次降价究竟出自成本下降还是竞争应对、其他供应商会怎么动

下一次降价公告来了，按这个顺序确认。

  • 价格上是否带着期限标注——带着的话，预算按原价来做
  • 降的是输入还是输出——自己的负载若偏输出，输入降价几乎没有体感
  • 缓存条件是否一并改了——最小长度、保持时间、写入倍率都是会悄悄变的项目
  • 加价区间的位置是否挪了——一条边界线的影响可能大过单价降幅
  • 思考强度的默认值是否变了——这是没改代码而输出令牌变多的典型路径

未能确认的部分

把本文中没有下断言的内容集中放在一处。

  • 降价之前的单价——官方页面只显示当前价格。正文中的 $5 / $30 / $0.50 依据的是新闻报道
  • 这次降价的动机——是成本下降还是竞争应对，没有找到官方说明
  • 各供应商实际的推理成本与毛利——属于不公开的范围。正文对成本结构的说明是基于公开技术文献的一般性论述
  • 把档位间质量差按任务定量化的独立测量值——单价的倍数和质量的倍数是两回事
  • 货币换算与税务处理——随币种和计费方式而变，因此文中的美元标价与实际结算金额可能并不一致

结论：留下的三条判断标准

第一，看令牌数而不是单价。公告只动一个系数，真正推动账单的通常是它旁边那一项。不把金额和令牌分开记录，这两者就永远分不开。

第二，价格表不止一行。输出倍数、缓存的读取与写入、批处理、长度区间、思考令牌合在一起才构成实际单价。只比输入那一行，比较本身就不成立。

第三，节省来自设计而不是谈判。把提示前半固定住让缓存活下来、在送进去之前裁掉工具输出、按任务区分思考强度——这些对金额的作用比一纸降价公告更大。而且这一侧不必等谁发布。

最后补一句：支出没降本身未必是坏信号。如果同样的钱正在做以前做不了的事，那就是按计划走。真正的问题是说不清多出来的支出买到了什么。让这份说明成为可能的是计量，而计量必须在账单送到之前就装好。
