AI 写出来的韩语到底哪里不对

在1058万字上量出的翻译腔、缓冲表达与文体漂移，以及检查器永远够不到的那一层

2026年8月11日 IT/技术

开头：拼写检查全过，读起来却一眼看穿

初稿拿到手，第一眼就有什么东西卡住。没有错别字，助词也对。可是读到第三段，你就知道这不是人写的。别人问你哪里不对，你答不上来。

那种感觉的真身多半是句法结构。词是本地语言，但组织小句的顺序和搭建谓语的方式来自英语文档。拼写检查器会放行这类句子，因为它们并不违反规范。于是意见提出来了，可以照着改的清单却没有。

要造出这份清单，就得能给出错的位置起名字。下面是把19条检查规则跑在1260篇韩语文档、约1058万字上得到的分布。样本全部由大语言模型写成、再由人修订，统计时排除了代码块。

本文范围 — 出错位置的清单、把它写成规约的格式，以及在生成时和输出后两个位置上强制执行的方法。引入分词与词性分析器、训练文体迁移模型不在讨论之内。中文读者可以把全文当作欧化表达治理来读，结构完全对得上。

1. 翻译腔是句法，不是词汇

把翻译腔当成敏感词表来治，是治不住的。禁掉一个被动标记，同样的结构会换个助词继续出现。真正的问题是英语句子的骨架穿上了本地语言的词。骨架在五个位置露出来。

1.1 无生命主语占据了本该属于人的位置

英语让事物做主语再用主动语态陈述，几乎没有限制。韩语和汉语的这个位置都窄得多。把 This tool allows you to deploy automatically 逐词搬过来，就得到一个以工具作主语、谓语意为使之成为可能的句子。自然的排法是把人或动作放回主语位置，结果还短一截。中文里的这个工具允许你自动部署是同一回事。

1.2 施事被塞进状语，谓语改成被动

这是英语 by 短语的落点。施事清楚时用主动是常态，被动留给需要隐去施事的场合。사용자에 의해 호출된다 应当还原为 사용자가 호출한다。中文的被用户调用属于同一位置的被字句滥用。

1.3 动词被压成名词，再用助词串起来

名词化是五者中分布最广的。review of performance 变成 성능에 대한 검토，本来以动词收尾的句子变成了实施一次检讨。句子变长，信息没变。中文里对性能进行检讨、作出评估这类说法就是它。

1.4 have 一族固化成一个动词

译者看到 have 时顺手抓的那个动词，本义更接近用手握住。描述属性时该用存在动词或形容词谓语。캐시를 가지고 있다 应当写成 캐시가 있다，拥有很高的准确率应当写成准确率高。

1.5 为了造副词而加后缀

basically、generally、effectively 被自动转成汉字词副词形式，粘在每句话前面。绝大多数删掉都不影响意思。只留下删不掉的那些。

Passive + by-agent사용자에 의해 호출된다사용자가 호출한다

3. 教科书警告的位置和真正塌下去的位置不是同一个

翻译腔纠错资料最先举的例子是双重被动和 by 短语被动。样本里双重被动在1058万字中出现6次。by 短语一族141次，每万字0.1次。最常被点名的拼写混淆是0次，数词与单位之间的分写也一次都没有乱过。

占据前列的是另外三类。

  • 缓冲表达 — 表示可能的说法每万字14.1次，折算下来十万字的稿子里出现140次。
  • 排版惯例 — 引号形状、冒号、破折号这些从英文排版带过来的习惯，分别是每万字31.0次、13.0次、8.3次。
  • 名词化 — 名词化连接每万字3.1次，是翻译腔一类里唯一进入上半区的。

归结起来就是违反规范的错误几乎没有，规范管不着的选择一直在偏。这同时也是好消息：拼写检查器覆盖的那一层已经干净了。剩下的问题在检查器之上，处理那一层的工具正是文体规约。

4. 缓冲表达 - 每万字十四次的可以

当表示可能、推测、应当的标记贴在每一句话上，文章就不再主张任何东西。可以修改设置这句话，本来应该以修改设置或请修改设置收尾。可能是错误这句话，往往贴在条件缺失的位置上。

并不是要把缓冲全部清掉。当判断确实是有条件的，缓冲是诚实的表达。写进规约的标准三行足够。

  • 已确认的事实直接断言。有依据就把依据附上，缓冲拿掉。
  • 随条件变化时写条件而不是写缓冲。不写可能会变慢，写并发超过200时会变慢。
  • 只在确实需要表达可能性的地方保留，并把上限定为每段一次。

第三条最容易搬进检查器，因为它不判断单句的对错，而是量密度。应当类说法每万字3.4次，可以用同样的方式设上限。

5. 文体漂移 - 五篇里有一篇在混用句末

韩语靠句末决定整份文档的正式程度。英语通过词汇选择来调节语域，韩语和日语却在每一句话最后两三个音节上重新宣布一次。所以句末一混就立刻显眼。

句末  敬体 47,096 · 常体 105,496 · 口语体 4,095
少数派句末超过10%的文档: 237 / 1260 = 18.8%
前5篇的少数派比例: 49%, 46%, 42%, 40%, 38%

排在前五的文档，两种文体基本各占一半。一段以敬体收尾、下一段以常体收尾的文章，会逼着读者重新计算自己和叙述者的距离。内容正确却仍然读着像草稿，最大的原因就在这里。

文体代表性句末样本频次适用场合
敬体합니다 · 입니다 · 하십시오47,096告知文、面向用户的文档、公文
常体한다 · 이다 · 아니다105,496报告、分析文档、技术说明
口语体해요 · 이에요4,095对话式引导、营销文案
名词性结尾확인 · 미측정 · 필요-表格单元格、列表项、摘要行

写进规约的项目四行就够。

  • 按文档类型指定一种句末。报告用常体，面向用户的说明用敬体，钉死。
  • 表格单元格和列表项一律用名词性结尾收尾。这是让它们不与正文句末打架的最便宜的办法。
  • 引文内部的句末随原文，排除在检查之外。
  • 标题不带句末形式。

如果是公文，这就不是选择而是遵从事项。韩国国立国语院公开了公共语言写作指引(2022年修订版)，除了拟稿、新闻稿、报告的分类原则，附录还列出了100个需要改进的行政用语和50个应当避免的日语来源词。

6. 助词与分写 - 表层字符串终究判定不了的那一层

做检查器时烧伤最重的就是这里。韩语正词法第42条要求依存名词分写，第43条要求单位名词分写，规范毫不含糊。问题在于同一个音节既是依存名词，也是词尾的一部分。

只看前一个音节的收尾辅音加后一个音节来写规则，结果是这样。

修正前 339 处 → 修正后 38 处 (每万字 0.04)
· 소득이 높을수록 유리                    ← 比较连接词尾，正确
· 다른 조건이 같다면 추출수 온도가 높을수록  ← 比较连接词尾，正确
· 이 숫자를 어떻게 읽을지가 중요하다        ← 疑问连接词尾，正确
· 승인을 누구에게 물을지가 정해지고         ← 疑问连接词尾，正确
· 어떤 공정에 예산을 넣을지가 저절로 정해진다 ← 疑问连接词尾，正确

339处全部是比较连接词尾，没有一处是依存名词。把它加进例外后降到38处，剩下的又全是疑问连接词尾。真错误一处都没有。在1058万字上刷一遍，正确率是零。

这条规则离开分词与词性分析就立不住。而如果不打算引入分析器，正确的做法是把规则删掉。一条只产生误报的规则，代价比漏检更大。

6.1 写规则的人会滑倒两次的地方

韩文把初声、中声、终声存成预先合成的一个字符。所以只写词干的规则抓不到活用形。想抓双重被动而写下词干 보여지，보여진다 就会溜过去，因为终声融进音节后变成了另一个字。

更安静的失败是冠形词形词尾。想抓表示可能的说法而写 /[을ㄹ]\s*수/，一处都命中不了，因为那些音节里的终声并不是独立字符。要读它必须拆码点。

// 音节 = 0xAC00 + (初声*21 + 中声)*28 + 终声。流音终声的索引是 8。
function jong(ch) {
  const c = ch.codePointAt(0);
  if (c < 0xAC00 || c > 0xD7A3) return -1;
  return (c - 0xAC00) % 28;
}

// 实际输出
终声陷阱 - /[을ㄹ]\s*수/ 命中 0 处，码点判定命中 2 处
音节陷阱 - /아니/ 命中 0 处，/아[니닙]/ 命中 1 处

把同一个陷阱扩展到各类词尾的安全模式、规范化与 shell 边界的讨论，放在韩文正则表达式的陷阱里。写第一个本地语言检查器之前值得先看那篇。

7. 列表、表格、标题 - 英文文档习惯直接流进来的地方

这一节的数字最贴近实操。它们属于惯例而不是规范，而惯例只要在一篇文档内部保持一致就行，偏偏塌掉的就是这个一致性。

列表项以句号结尾41,901 个中 13,179 个 (31.5%)可选项，各文档自己定

第三行是关键。列表项要不要句号，是文档自己的选择。可是同一篇里两种混着来的占十分之四。这个缺陷不是因为不知道规则，而是因为前面的选择没有被保持下来，人一读就觉得潦草。

7.1 引号问题规范早已理顺

2014年12月发布、2015年1月起施行的标点修订，把原本只用于竖排的角括号改为横排也可使用。书名和报刊名用双角括号或双书名号，也可以用双引号代替；小标题、作品名、商号、法规名用单书名号。规约里写一行就够：无论选哪种，全文统一。

8. 把规约写进提示词的方法，以及它的边界

强制规约的位置有两个：生成时和输出后。提示词负责前者。

8.1 写进提示词时的形态

  • 写替换对，不要写禁用表。不要用这个形式远不如 A 被 B 处理改成 B 处理 A 有效。不给替代形式，结构只会换个标记继续存在。
  • 用可判定的句子钉死句末。所有句子以常体收尾，表格单元格和列表项以名词性结尾收尾。
  • 附上三到五个例句。一个错句配一个改好的句子，效率高过一整段规则说明。
  • 把数字定下来。缓冲表达每段不超过一次是可以数的，酌情使用是数不了的。
  • 规则数量控制在20条以内。规则越多，靠后的越被稀释。

8.2 提示词够不到的部分

  • 文档级一致性。列表项句号混用40.9%就是证据。不是不知道规则，是前面的选择没被保持。
  • 长输出的后半段。输出越长，开头守住的句末在后面越会漂。
  • 规则之间的冲突。写得简洁和附上依据经常打架，提示词里没写哪一条优先。
  • 验证。提示词不会告诉你它有没有被遵守。唯一的办法是量输出。

靠不断增加规则来管控会在哪里触顶，另写在长篇方针文档管不住智能体里。

9. 用输出后检查来强制 - 拦截、警告、报告三分

做检查器最常见的失败是把所有规则设成同一个等级。只要挂上一条噪音大的规则，人很快就会无视整份报告。把等级分成三档，这个事故就不会发生。

给警告等级设阈值需要基准值。直接拿本样本的数字来用，等于把现状定成标准，没有意义。挑十篇你认为写得好的文档，用同一套规则量一遍，把那个值当上限更合适。

把检查分成语法层、运行时层、语义层的通用做法以及误报管理，整理在给 AI 产出搭一套验收体系里。这里要补的只有一条：本地语言检查器必须按规则分别测误报率。正如上面所见，一条规则正确率为零而其余规则完好，是真会发生的事。

10. 规约文档的格式 - 写成替换表而不是禁用表

把规约写成文档，一张表基本就够了。五列。

  • 对象 — 会被命中的形式。用检查器将要搜索的同一种写法记录。
  • 替换 — 改成什么。留空规则就不会被遵守。
  • 例外 — 命中也放行的情形。这一栏为空的规则一定会产生误报。
  • 等级 — 拦截、警告、报告三选一。
  • 基准 — 若为警告等级，写明每万字多少次。

再加上几条覆盖全文的项目。

  • 句末指定，以及表格和列表的名词性结尾规则。
  • 术语统一 — 以本地语言写法为正本，只在首次出现时用括号附上英文。样本里这种对照每万字8.0次，同一个术语标注两三遍，从第二次起就是赘余。
  • 数字格式 — 千分位位置、是否使用万位表述、小数位数。
  • 给每个数值加状态标记 — 实测、估算还是未测。写进规约后，无出处的数字会明显减少。
  • 句长上限 — 超过60个字就拆开，这样一条机械标准就够。

公共部门的文档再补上规范依据即可。国立国语院在正词法正文之外还公开了易懂公文写作指引，并运营着公共语言综合支援窗口。

11. 这套方法够不到的部分与未能核实的部分

  • 没有分词与词性分析，助词和分写的规则立不住。如上所示正确率会归零。真要压住这一层必须上分析器，那超出本文范围。
  • 密度基准值没有依据。没有找到任何公开标准说明每万字多少次算正常。上表数字描述的是一个样本的分布，不是推荐值。
  • 样本有偏。1260篇全部是韩语技术与生活资讯类文章。小说、法律文书、合同的分布应当不同，但未做核实。
  • 没有对比提示词规约与输出后检查效果的数字。要在同等条件下对照，需要一次受控的生成实验，而那个实验没有做。
  • 成因未经核实。用训练语料或对齐方式来解释双重被动稀少而缓冲表达密集，这类说法很常见，但没有找到可作依据的资料，所以这里只记录分布。
  • 国立国语院的资料只核实到介绍页面。没有逐条比对指引全文的PDF，因此不引用其中的具体例句。
  • D 系规则里混着误报。括号内英文对照每万字8.0次在技术文档中大多正当，标题内冒号6.8%在本地写作中也很普遍。所以这些项目被放在报告等级而不是拦截。

结论：文体规约不是审美，是接口

机器写出来的文字里该改的不是拼写，那一层已经干净了。剩下的是英语文档的骨架和文档级一致性两样，两样都属于规约而非规范。

定个顺序的话是这样。

  • 先把句末钉死。每种文档一种句末，表格和列表用名词性结尾。五篇里出现一篇的文体漂移，靠这一行就消失。
  • 接着把一致性项目挂进检查器。列表项句号混用判定时不需要解释，而且十篇里出现四篇，投入产出比最高。
  • 翻译腔用替换对写进提示词，再用密度来量。禁用词表抓不住它。
  • 分写规则在分析器就位之前不要加。加了会先赔掉整个检查器的可信度。

把规约落成文档，目的不是让句子好看，而是让人和机器能用同一把尺子判定同一份文档。标准没有写成句子，读着像 AI 这句评价每次都只能停在观感上，下一版初稿还是原样。
