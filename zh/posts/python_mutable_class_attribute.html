引言 - 同一个名称指向的位置

在类体中写下items = []，所有实例看到的是同一个列表。Python官方教程中「Class and Instance Variables」一节把这种写法作为「mistaken use of a class variable」（类变量的误用）的示例（Dog.tricks），并区分两种用途：实例变量用于每个实例独有的数据，类变量用于所有实例共享的属性和方法。症状本身的复现已见于默认参数里放空列表，每次调用都会累积值的第7节，以及打乱测试顺序会暴露什么的4.2节。

混乱的根源在于同一个名称既可能存在于实例，也可能存在于类。类属性是在类体中赋值的名称，保存在类的__dict__中；实例属性是保存在实例的__dict__中的名称。同一个名称在哪一处，决定了读取、写入、删除的结果。下面直接查看这个位置，并逐个操作分清它触及哪一处。

涉及的问题如下。

  • 值在实例还是类中，如何查明？
  • 读取、写入、删除看的是同一个位置吗？
  • 改动类一侧的值后，已经创建的实例会怎样？
  • +=对整数和列表分别留下什么？
  • 子类是否共享父类的可变属性，用type(self)写入时值落在哪里？
  • dataclass、ClassVar、__slots__如何处理这一区分？
  • 有意共享时，哪种形式对读者最清楚？

值所在的位置 - 用__dict__和vars查看

本节的输出是此前文章第7节已做过的实验，这里用来通过vars()和type(obj).__dict__查看值的位置。数据模型文档写道：类属性引用被翻译为对类字典的查找（C.x变为C.__dict__["x"]）；对类实例而言，实例字典是最先搜索属性引用的位置，找不到且类中有同名属性时，搜索继续到类属性。这两个字典的输出如下。

class Cart:
                        items = []
                        label = 'cart'
                    
                    a = Cart()
                    b = Cart()
                    print('a.__dict__            :', a.__dict__)
                    print('vars(a)               :', vars(a))
                    print('Cart.__dict__ keys    :', [k for k in vars(Cart) if not k.startswith('__')])
                    print('type(a) is Cart       :', type(a) is Cart)
                    print('type(Cart.__dict__)   :', type(vars(Cart)).__name__)
                    print('a.items is Cart.items :', a.items is Cart.items)
                    a.items.append('x')
                    print('b.items               :', b.items)
a.__dict__            : {}
                    vars(a)               : {}
                    Cart.__dict__ keys    : ['items', 'label']
                    type(a) is Cart       : True
                    type(Cart.__dict__)   : mappingproxy
                    a.items is Cart.items : True
                    b.items               : ['x']

实例a的字典是空的。items和label只存在于Cart的字典中。a.items is Cart.items为True，通过a向列表追加值后，b.items里也能看到。两个实例上都没有列表，读取的却是类上的同一个列表。类的字典以mappingproxy形式输出，查看值的位置只需vars(obj)和vars(type(obj))两个调用。

  • vars(obj)返回实例字典，为空说明没有实例属性。
  • vars(type(obj))返回类字典，名称只出现在这里就是类属性。
  • 当obj.name is type(obj).name为True且名称不在实例字典中时，即可确定共享。
  • 这里is只用于列表这类可变对象。小整数和字符串上is的结果随运行方式而不同，这一点在为什么测试通过而线上条件却不成立中讨论。

读取向上查找，写入止于实例

同一个名称的读取与写入看的是不同的位置。数据模型文档的原句是：Attribute assignments and deletions update the instance's dictionary, never a class's dictionary。读取从实例上溯到类，而对实例的赋值和删除只修改实例字典。用字符串属性得到的输出如下，可见这种不对称。

class Cart:
                        label = 'cart'
                    
                    a = Cart()
                    b = Cart()
                    a.label = 'mine'
                    print('a.__dict__ after set  :', a.__dict__)
                    print('a.label, b.label, Cart.label:', a.label, b.label, Cart.label)
                    del a.label
                    print('after del a.label     :', a.label, a.__dict__)
                    Cart.label = 'changed'
                    print('after Cart.label=...  :', a.label, b.label)
                    b.label = 'shadow'
                    Cart.label = 'again'
                    print('b shadowed, a not     :', b.label, a.label)
a.__dict__ after set  : {'label': 'mine'}
                    a.label, b.label, Cart.label: mine cart cart
                    after del a.label     : cart {}
                    after Cart.label=...  : changed changed
                    b shadowed, a not     : shadow again

执行a.label = 'mine'后，a的字典里出现了条目，Cart.label没有变化。del a.label之后字典又变空，a.label回到类上的值。在类一侧修改Cart.label时，没有自有值的a随之改变，而最后两行中有自有值的b不受类上新值的影响。下表汇总了每个操作改变的位置。

操作改变的位置结果（依据上面的输出）
a.label = va.__dict__只有a改变，类和b保持原样
del a.label从a.__dict__删除条目a重新读取类上的值
Cart.label = vCart.__dict__所有没有自有值的实例读取新值
b.label = v之后Cart.label = wb.__dict__中已存在b保持v，其他实例读到w
a.items.append(x)挂在类上的列表对象本身凡是看到该对象的地方都能看到变化

表中最后一行就是共享症状的本质。a.items.append(x)先读取a.items，再调用该对象的方法，因此不发生对实例字典的赋值。写入规则只在给名称赋值时适用，对原地修改对象的调用不适用。

改动类一侧：哪些实例跟随，哪些不跟随

给类属性赋一个新对象，与修改已有对象，对实例的影响范围不同。先在类一侧重新绑定名称，再让部分实例拥有自有值，然后再次绑定。

class Box:
                        items = []
                        n = 0
                    
                    a = Box()
                    b = Box()
                    Box.items = ['new']
                    print('class rebinding        :', a.items, b.items)
                    a.items = ['mine']
                    Box.items = ['newer']
                    print('after a has its own    :', a.items, b.items)
                    Box.n = 5
                    a.n += 1
                    Box.n = 9
                    print('a.n, b.n, Box.n        :', a.n, b.n, Box.n)
class rebinding        : ['new'] ['new']
                    after a has its own    : ['mine'] ['newer']
                    a.n, b.n, Box.n        : 6 9 9

Box.items = ['new']之后，两个实例都读到了新列表，因为类字典中的名称所指的对象变了，而实例没有自有值。接着用a.items = ['mine']让a拥有自有值，再次改动类时，只有a没有跟随。数值也一样。Box.n = 5之后，a.n += 1读到5，加1得到6并放入a的字典；之后Box.n = 9时，b.n跟随变为9，而a.n停留在6。

  • 类属性的重新绑定只扩散到没有自有值的实例。
  • 实例一旦拥有某名称的自有值，类一侧对该名称的改动就不再到达它。
  • 因此，同一个类中只有部分实例读到新设置的现象，取决于哪些实例已经拥有了自有值。

+=留下什么 - 整数与列表的差别

整数部分是此前文章第7节已做过的实验，这里用来通过vars()查看实例字典中是否出现名称。self.count += 1把读取和写入叠在一行。右侧的读取上溯到类，左侧的写入止于实例。对整数和列表应用了同一个运算。

class Counter:
                        hits = 0
                        log = []
                    
                    p = Counter()
                    q = Counter()
                    p.hits += 1
                    p.hits += 1
                    q.hits += 1
                    print('p.hits q.hits Counter.hits:', p.hits, q.hits, Counter.hits)
                    print('p.__dict__ :', p.__dict__)
                    p.log += ['p']
                    q.log += ['q']
                    print('p.log      :', p.log, ' Counter.log:', Counter.log)
                    print('p.log is Counter.log:', p.log is Counter.log)
                    print('p.__dict__ :', p.__dict__)
                    p.log = p.log + ['new']
                    print('after p.log = p.log + [...]:', p.log, Counter.log, p.log is Counter.log)
p.hits q.hits Counter.hits: 2 1 0
                    p.__dict__ : {'hits': 2}
                    p.log      : ['p', 'q']  Counter.log: ['p', 'q']
                    p.log is Counter.log: True
                    p.__dict__ : {'hits': 2, 'log': ['p', 'q']}
                    after p.log = p.log + [...]: ['p', 'q', 'new'] ['p', 'q'] False

整数一侧如预期分开：p.hits为2，q.hits为1，类上的值为0，因为名称hits出现在p的字典中。列表一侧则不同。p.log += ['p']和q.log += ['q']之后，类上的列表里有两个值，p.log is Counter.log为True。但p的字典里确实出现了log。输出与下面的解释相符：列表的+=在原地扩展挂在类上的列表，并把结果（同一个列表）赋给实例名称。名称出现在实例字典里，并不意味着实例拥有该对象。

最后一行的p.log = p.log + ['new']会新建列表并赋值，所以p.log脱离了类上的列表。类上的列表里没有'new'，is为False。

  • 整数的+=创建新对象并绑定到实例，共享因此解除。
  • 列表的+=扩展同一个对象并重新绑定，共享依然保留。
  • x = x + [...]新建列表并绑定，共享解除。两个看似等价的式子表现不同。
  • 不要只看名称是否在实例字典中，还要检查obj.name is type(obj).name。

子类原样使用父类的列表

同样的规则在子类中延续。数据模型文档写明，名称不在类字典中时，搜索继续到基类。一个父类和两个子类中列表位置的输出如下。

class Base:
                        tags = []
                    
                    class Child(Base):
                        pass
                    
                    class Other(Base):
                        tags = ['own']
                    
                    c = Child()
                    o = Other()
                    bs = Base()
                    print('Child.tags is Base.tags :', Child.tags is Base.tags)
                    print('Other.tags is Base.tags :', Other.tags is Base.tags)
                    c.tags.append('from child instance')
                    print('Base.tags               :', Base.tags)
                    print('bs.tags                 :', bs.tags)
                    print('o.tags                  :', o.tags)
                    print("'tags' in vars(Child)   :", 'tags' in vars(Child))
                    print('MRO of Child            :', [k.__name__ for k in Child.__mro__])
Child.tags is Base.tags : True
                    Other.tags is Base.tags : False
                    Base.tags               : ['from child instance']
                    bs.tags                 : ['from child instance']
                    o.tags                  : ['own']
                    'tags' in vars(Child)   : False
                    MRO of Child            : ['Child', 'Base', 'object']

Child自己的字典里没有tags，Child.tags与Base.tags是同一个对象。通过子类实例追加值后，父类和父类实例上也能看到。创建类时重新声明了tags的Other拥有自己的列表，不与父类的值混在一起。查找顺序按MRO输出（Child, Base, object）从子类上溯到父类。

  • 仅仅创建子类并不会复制类属性的列表。
  • 在子类体中重新声明同名属性，该子类就拥有自己的对象。
  • 要让每个子类各自持有父类属性的一份拷贝，必须在子类创建的时刻赋一个新对象。方法见第10节。

计数器的两种写法 - type(self)与类名

增加类一侧计数器的代码有两种写法：用指向实例所属类的type(self)，或直接写类名。一旦牵涉子类，结果就分开了。

class Reg:
                        count = 0
                        def __init__(self):
                            type(self).count += 1
                    
                    class RegChild(Reg):
                        pass
                    
                    Reg(); Reg(); RegChild()
                    print('Reg.count, RegChild.count   :', Reg.count, RegChild.count)
                    print("'count' in vars(RegChild)   :", 'count' in vars(RegChild))
                    
                    class Reg2:
                        count = 0
                        def __init__(self):
                            Reg2.count += 1
                    
                    class Reg2Child(Reg2):
                        pass
                    
                    Reg2(); Reg2Child(); Reg2Child()
                    print('Reg2.count, Reg2Child.count :', Reg2.count, Reg2Child.count)
                    print("'count' in vars(Reg2Child)  :", 'count' in vars(Reg2Child))
Reg.count, RegChild.count   : 2 3
                    'count' in vars(RegChild)   : True
                    Reg2.count, Reg2Child.count : 3 3
                    'count' in vars(Reg2Child)  : False

type(self).count += 1读取时拿到父类的值2，写入则进入RegChild自己的字典。结果RegChild.count变成3，Reg.count仍是2。直接写类名的Reg2.count += 1即使创建子类实例也只改父类的字典，汇总成3这一个值，Reg2Child的字典里没有出现该名称。

  • 想用一个值统计全部实例，直接写类名能汇总到一处。
  • 想按子类分别计数，就用type(self)，同时要知道第一次写入从父类当前的值开始。
  • 两种写法混在同一个类层次中，同名的值会在父类和子类之间错开。

dataclass看什么 - 字段、ClassVar与可变默认值

list的ValueError是此前文章第7节已做过的实验，这里与字段、ClassVar的判定放在一起看。dataclass在声明阶段处理这个问题。官方文档指出默认值保存为类属性，并写明遇到不可哈希的默认值会抛出ValueError，其假设是不可哈希就是可变，同时自称只是部分解决办法。文档还写明，类型为typing.ClassVar的字段会被排除在字段之外，fields()不会返回它。下面是在一个类中放入字段、ClassVar和无注解的属性，以及给出四种默认值时的输出。

from typing import ClassVar
                    from dataclasses import dataclass, field, fields
                    
                    @dataclass
                    class Plain:
                        name: str
                        tags: list = field(default_factory=list)
                        registry: ClassVar[dict] = {}
                        note = 'no annotation'
                    
                    p1 = Plain('a'); p2 = Plain('b')
                    print('fields          :', [f.name for f in fields(Plain)])
                    print('annotations     :', list(Plain.__annotations__))
                    print('registry shared :', p1.registry is p2.registry is Plain.registry)
                    print('tags shared     :', p1.tags is p2.tags)
                    print('p1.__dict__     :', p1.__dict__)
                    print('note is a field :', 'note' in [f.name for f in fields(Plain)], '/ Plain.note =', Plain.note)
                    try:
                        Plain('x', ['q'], {}, 'extra')
                    except TypeError as e:
                        print('TypeError       :', e)
                    
                    for kind, default in [('list', []), ('dict', {}), ('set', set()), ('tuple', ())]:
                        try:
                            @dataclass
                            class Probe:
                                x: object = default
                            print(kind, '-> accepted')
                        except ValueError as e:
                            print(kind, '-> ValueError:', e)

                    annotations     : ['name', 'tags', 'registry']
                    registry shared : True
                    tags shared     : False
                    p1.__dict__     : {'name': 'a', 'tags': []}
                    note is a field : False / Plain.note = no annotation
                    TypeError       : Plain.__init__() takes from 2 to 3 positional arguments but 5 were given
                    list -> ValueError: mutable default <class 'list'> for field x is not allowed: use default_factory
                    dict -> ValueError: mutable default <class 'dict'> for field x is not allowed: use default_factory
                    set -> ValueError: mutable default <class 'set'> for field x is not allowed: use default_factory

__slots__与类属性的冲突

在使用__slots__的类中，同名的类属性不被允许。数据模型文档的__slots__一节（3.3.2.4）写道：「class attributes cannot be used to set default values for slot variables; otherwise, the class attribute would overwrite the descriptor」。

try:
                        class WithSlots:
                            __slots__ = ('x',)
                            x = 1
                    except ValueError as e:
                        print('ValueError:', e)
                    
                    class Ok:
                        __slots__ = ('x',)
                    o = Ok()
                    o.x = 1
                    print('slots instance has __dict__:', hasattr(o, '__dict__'))
ValueError: 'x' in __slots__ conflicts with class variable
                    slots instance has __dict__: False

类一创建就抛出ValueError，消息说明槽位名称与类变量冲突。只声明了槽位的类，其实例没有__dict__。文档这句话的范围是类属性不能用来给槽位变量设置默认值，本输出显示的也只是这一冲突和__dict__的缺失。槽位变量的默认值在__init__中赋值。

有意共享 - 按子类划分的注册表与默认值拷贝

有时共享正是意图，比如注册表和默认配置。此时问题不在共享本身，而在于子类是否也用了同一个对象，以及读者能否看出意图。三种形式的输出如下。前两种使用子类定义时被调用的__init_subclass__，一种为每个子类赋一个新列表，另一种把名称汇集到父类的列表中。第三种是实例拷贝类字典中默认值的形式。

class Plugin:
                        registry = []
                        def __init_subclass__(cls, **kw):
                            super().__init_subclass__(**kw)
                            cls.registry = []          # each subclass gets its own list
                            Plugin.registry.append(cls.__name__)
                    
                    class A(Plugin): pass
                    class B(Plugin): pass
                    print('Plugin.registry :', Plugin.registry)
                    print('A.registry      :', A.registry, ' B.registry:', B.registry)
                    
                    class Shared:
                        registry = []
                        def __init_subclass__(cls, **kw):
                            super().__init_subclass__(**kw)
                            cls.registry.append(cls.__name__)
                    class C(Shared): pass
                    class D(Shared): pass
                    print('Shared.registry :', Shared.registry, C.registry is D.registry)
                    
                    # per-instance copy of a class-level default
                    class Config:
                        defaults = {'retries': 3}
                        def __init__(self, **over):
                            self.opts = {**type(self).defaults, **over}
                    c1 = Config(retries=5); c2 = Config()
                    print('c1.opts, c2.opts, defaults:', c1.opts, c2.opts, Config.defaults)
Plugin.registry : ['A', 'B']
                    A.registry      : []  B.registry: []
                    Shared.registry : ['C', 'D'] True
                    c1.opts, c2.opts, defaults: {'retries': 5} {'retries': 3} {'retries': 3}

Plugin每当定义一个子类，就给该子类赋一个新的空列表。A.registry和B.registry是各自的列表，父类的列表里汇集了两个子类名称。Shared向cls.registry追加名称，C和D指向同一个列表。两者都是依意图而定的正确设计，但具体是哪一种，应当能从代码中看出。最后的Config把类字典中的默认值当作只读原件，并为每个实例新建字典，只放入要覆盖的值。在c1上修改的值没有扩散到c2和Config.defaults。

  • 想汇集到一个父类中，就向父类的列表添加；想让每个子类各有一份，就赋新对象。
  • 若只把类属性当作默认值的原件来读，由实例制作拷贝，共享事故会在结构上减少。
  • 有意的共享应加上typing.ClassVar注解，标明它不是实例属性。typing文档写明这不改变运行时行为，可供静态类型检查器使用。

从症状到原因 - 判别表

把上面的运行按症状归类。每一行的检查代码就是前面各节输出中用过的代码。

症状检查什么输出所指示的处理办法
