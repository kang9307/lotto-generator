Building an Automated Ceph Storage Bucket Monitoring Script

Enterprise Storage Monitoring with Slack Integration

2025-06-29 Dev & Infra

In modern IT infrastructure, storage monitoring is an essential operational element. This is especially true for distributed storage systems such as Ceph, where you need to track per-bucket capacity and object counts in real time to support capacity planning and performance optimization.

Today we will take a detailed look at how to build an automation script that monitors a specific bucket in Ceph Object Storage, analyzes its change trends, and sends notifications to Slack.

📋 System Requirements

To run the script, the following environment must be in place:

  • Ceph Cluster: Access to the radosgw-admin command
  • jq: Tool for parsing JSON
  • curl: For sending HTTP requests
  • Slack Webhook URL: Notification channel configured

🔧 Core Script Breakdown

Let's walk through the key components of the bucket monitoring script:

1. Base Configuration and Variable Definitions

#!/bin/bash

# Slack webhook URL (example)
SLACK_WEBHOOK_URL="https://hooks.slack.com/services/EXAMPLE/WEBHOOK/URL"

# Current date and time
EXECUTION_TIME=$(date)

# Path to the previous statistics file

BUCKET_NAME="my-data-bucket"

2. Collecting Bucket Information

# Get bucket capacity and object count
BUCKET_INFO=$(radosgw-admin bucket stats --bucket=${BUCKET_NAME})

BUCKET_SIZE=$(echo "$BUCKET_INFO" | jq -r '.usage."rgw.main".size')
BUCKET_NUM_OBJECTS=$(echo "$BUCKET_INFO" | jq -r '.usage."rgw.main".num_objects')

💡 Pro Tip

The radosgw-admin command is the management tool for the Ceph Object Gateway, and it exposes detailed bucket statistics in JSON format. You can use jq to extract just the fields you need.

3. Data Formatting Function

# Convert to a human-readable unit
function human_readable_size() {
  local size=$1

  if ! [[ "$size" =~ ^[0-9]+$ ]]; then
    echo "0 Bytes"
    return
  fi

  local result=$(awk -v size="$size" '
  BEGIN {
    units[0] = "Bytes"; units[1] = "KB"; units[2] = "MB"
    units[3] = "GB"; units[4] = "TB"; units[5] = "PB"

    i = 0
    while (size >= 1000 && i < 5) {
      size = size / 1000
      i++
    }

    if (i == 0) {
      printf "%.0f %s", size, units[i]
    } else {
      printf "%.2f %s", size, units[i]
    }
  }')

  echo "$result"
}

4. Change Calculation

# Statistics calculation function
function calculate_change() {
  local current=$1
  local previous=$2

  if ! [[ "$current" =~ ^[0-9]+$ ]] || ! [[ "$previous" =~ ^[0-9]+$ ]] || [ "$previous" -eq 0 ]; then
    echo "N/A"
    return
  fi

  local change=$((current - previous))
  local percentage=$(awk -v curr="$current" -v prev="$previous" 'BEGIN { printf "%.2f", ((curr - prev) / prev) * 100 }')

  if [ "$change" -gt 0 ]; then
    echo "+$(add_commas $change) (+${percentage}%)"
  elif [ "$change" -lt 0 ]; then
    echo "$(add_commas $change) (${percentage}%)"
  else
    echo "No change (0%)"
  fi
}

✅ Benefits

  • Automatically computes the rate of change compared to prior data
  • Shows both percentage and absolute values at the same time
  • Adds commas to numbers for readability
  • Handles edge cases (prevents division by zero)

📊 Implementing Slack Notifications

This part of the script sends the collected data to Slack:

# Prepare message text
MESSAGE_TEXT="🕒 Execution time: ${EXECUTION_TIME}

=========== Bucket Info ===========
- Bucket name: ${BUCKET_NAME}
- Capacity: ${BUCKET_SIZE_HUMAN} (${BUCKET_SIZE_COMMA} Bytes)
- Object count: ${BUCKET_NUM_OBJECTS_COMMA}"

# Append statistics info
if [ -n "$SIZE_CHANGE" ] && [ -n "$OBJECTS_CHANGE" ]; then
    MESSAGE_TEXT="${MESSAGE_TEXT}

========== Change vs. Previous ==========
- Previous measurement: ${PREV_TIME}
- Capacity change: ${SIZE_CHANGE}
- Object count change: ${OBJECTS_CHANGE}"
fi

# Generate JSON payload
PAYLOAD="{
  \"text\": \"\`\`\`${MESSAGE_TEXT_ESCAPED}\`\`\`\"
}"

# Send the Slack message
curl -X POST -H 'Content-type: application/json' --data "$PAYLOAD" $SLACK_WEBHOOK_URL

⚙️ Execution and Automation Setup

1. Granting Execute Permission to the Script

chmod +x bucket_monitoring.sh

2. Scheduling Periodic Runs with Cron

# Run every hour
0 * * * * /path/to/bucket_monitoring.sh

# Run every day at 9 AM
0 9 * * * /path/to/bucket_monitoring.sh

# Run every 5 minutes (high-frequency monitoring)
*/5 * * * * /path/to/bucket_monitoring.sh

⚠️ Cautions

  • Verify permissions to execute the radosgw-admin command
  • Keep the Slack Webhook URL secure
  • Choose a run interval that accounts for storage I/O load
  • Manage log file size and rotate logs
