JavaScript Basic Syntax

2025-06-01 開発・インフラ

JavaScript はウェブ開発で最も広く使われているプログラミング言語です。本記事では JavaScript の基本文法と主要な概念について解説します。

English: JavaScript is the most widely used programming language in web development. This article explains the basic syntax and key concepts of JavaScript.

本記事は ES2015(ES6)以降のモダンな標準を前提にまとめています。2015 年に標準化された ES6 は let・const・アロー関数・テンプレートリテラル・クラス・モジュールを一度に導入し、JavaScript を事実上別の言語へと変えました。ネット上には今も var や == を使う古いサンプルが数多く残っていますが、これから学ぶ人がその慣習をわざわざ真似る理由はありません。本記事では「何を使うか」だけでなく「なぜ古い書き方を避けるのか」まで併せて解説します。

サンプルコードはすべて、ブラウザの開発者ツールのコンソール(F12)や Node.js にそのまま貼り付けて実行できるように書き、コメントに実際の出力値を記載しています。読むだけで終わらせず、自分で実行して出力を確認することが基礎を身につける最短ルートです。特に結果が予想と違うサンプルは、その場で値を変えながら試してみてください。

  • データ型: プリミティブ型 7 種と typeof が返す値
  • 型変換: 明示的変換と暗黙的変換、truthy と falsy
  • 演算子と比較: == を避けて === を使う理由
  • 条件分岐とループ: if・switch・for...of・for...in の使い分け
  • 関数: 宣言・式・アロー関数と this の違い
  • 配列とオブジェクト: よく使うメソッド、分割代入、浅いコピーの落とし穴

変数の宣言 (Variable Declaration)

JavaScript では var、let、const というキーワードを使って変数を宣言できます。

English: In JavaScript, you can declare variables using the keywords var, let, and const.

// var (関数スコープ - function scope)
var x = 5;

// let (ブロックスコープ - block scope)
let y = 10;

// const (定数、再代入不可 - constant, cannot be reassigned)
const PI = 3.14;

この 3 つのキーワードは名前が違うだけではありません。スコープ(有効範囲)、再宣言・再代入の可否、宣言前にアクセスしたときの挙動がすべて異なります。下の表で一覧にして比較してみましょう。

項目varletconst
スコープ関数スコープブロックスコープ { }ブロックスコープ { }
再代入可能可能不可 (TypeError)
同名の再宣言可能(黙って上書き)不可 (SyntaxError)不可 (SyntaxError)
宣言前のアクセスundefined を返すReferenceError (TDZ)ReferenceError (TDZ)
宣言と同時の初期化省略可省略可必須
トップレベル宣言時のグローバルオブジェクト登録登録される登録されない登録されない
新規コードでの推奨度使わない値が変わるときだけ既定(まず選ぶ)

実務のルールは非常にシンプルです。基本は const で宣言し、値を入れ直す必要があるときだけ let に切り替え、var は新規に使わない。こうすると「この変数はこの先変わらない」という情報がコードにそのまま現れ、後から読む人が追跡すべき状態の数が減ります。再代入が必要になった瞬間にだけ let へ下げれば十分です。

スコープ: 変数が生きている範囲

var は関数スコープなので、if や for のブロック内で宣言してもブロックを抜けて関数全体からアクセスできてしまいます。一方 let と const はブロックスコープで、波括弧を抜ければ存在しません。ブロック内だけで使うつもりの一時変数が関数の最後まで生き残るのは、バグのよくある出発点です。

// var: 関数スコープ + 宣言だけが巻き上げられる(値は undefined)
function varScope() {
  console.log(typeof value); // "undefined" - エラーにはならない
  if (true) {
    var value = 1;
  }
  return value;              // 1 - if ブロックの外からもアクセスできる
}

// let: ブロックスコープ
function letScope() {
  if (true) {
    let value = 1;
    console.log(value);      // 1
  }
  // console.log(value);     // ReferenceError: value is not defined
}

console.log(varScope());     // 1
letScope();

スコープを理解するうえで押さえておきたい点をまとめます。

  • 波括弧 { } で囲まれたすべてのブロック(if、for、while、単独ブロック)が let・const の境界になります。
  • 内側のスコープからは外側の変数を読めますが、その逆はできません。
  • 内側で同じ名前を再宣言すると外側の変数を隠すシャドーイングが起きます。意図的でなければ名前を変えたほうが安全です。
  • キーワードを省いて x = 1 と書くと、非厳格モードではグローバル変数が作られます。ファイル先頭に 'use strict' を置くか ES モジュール(type="module")を使えば、このミスはエラーとして検出されます。

ホイスティングと TDZ(一時的死角)

JavaScript エンジンはコードを実行する前に宣言を先に処理します。このとき var は宣言と同時に undefined で初期化されるため、宣言行より上で読んでもエラーにならず undefined が返ります。値がまだ無いのにプログラムが黙って動き続けるので、原因を突き止めにくいバグになります。

let と const も巻き上げられますが、初期化されないまま残ります。ブロックの先頭から宣言行に到達するまでの区間を TDZ(Temporal Dead Zone、一時的死角) と呼び、この区間でアクセスすると ReferenceError が発生します。黙って誤った値を使うより、その場でエラーとして知らせてくれるほうがずっと安全です。

// var: ループ全体で 1 つの変数を共有する → 3, 3, 3
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log('var:', i), 0);
}

// let: 反復ごとに新しいバインディングが作られる → 0, 1, 2
for (let j = 0; j < 3; j++) {
  setTimeout(() => console.log('let:', j), 0);
}

このサンプルは var と let の違いが実際にどんな結果の差を生むかを最もはっきり示しています。var i はループ全体で変数を 1 つ共有するため、コールバックが実行される時点ではすでに 3 になっています。let j は反復ごとに別のバインディングを作るので、各コールバックが自分の順番の値を覚えています。以前はこの問題を即時実行関数で回避していましたが、今は let を使うだけで自然に解決します。

const が守るものと守らないもの

const は「値が変わらない」ではなく、「その変数名に別の値を再代入できない」という意味です。オブジェクトや配列を const で宣言しても、内部のプロパティや要素はいくらでも変更できます。中身まで固めたい場合は Object.freeze() が必要ですが、これも一段だけの浅い凍結です。

const config = { retry: 3 };
config.retry = 5;             // OK - オブジェクト内部の値は変更できる
console.log(config.retry);    // 5

// config = { retry: 5 };     // TypeError: Assignment to constant variable.

const frozen = Object.freeze({ retry: 3 });
frozen.retry = 5;             // 非厳格モードでは黙って無視される
console.log(frozen.retry);    // 3

まとめると、const はバインディングを固定し、Object.freeze() はオブジェクトの表面を固定します。両者を混同して「const で宣言したから安全だ」と決めつけると、共有オブジェクトが別の関数で変更される状況を見落とすことになります。

データ型 (Data Types)

JavaScript の基本データ型は以下のとおりです。

English: JavaScript has the following basic data types:

  • String: 文字列 (text)
  • Number: 数値 (numbers)
  • Boolean: 真偽値 (true/false)
  • null: 値がない状態 (no value)
  • undefined: 値が代入されていない状態 (unassigned value)
  • Object: オブジェクト (objects)
  • Symbol: 一意で変更不可能なデータ型 (unique and immutable data type)
let name = "홍길동";  // String
let age = 25;         // Number
let isActive = true;  // Boolean
let user = {          // Object
  name: "홍길동",
  age: 25
};

もう少し正確に整理すると、JavaScript の値はプリミティブ型 7 種とオブジェクトに分かれます。プリミティブ型はメソッドやプロパティを持たない単純な値で、変更できません(immutable)。値を「変える」ように感じる操作は、実際には新しい値を作って代入し直しているだけです。一方オブジェクトは複数の値をまとめる構造で、変数にはそのオブジェクトを指す参照が入ります。

typeof で型を確認する

console.log(typeof "hi");         // "string"
console.log(typeof 42);           // "number"
console.log(typeof 10n);          // "bigint"
console.log(typeof true);         // "boolean"
console.log(typeof undefined);    // "undefined"
console.log(typeof Symbol("id")); // "symbol"
console.log(typeof null);         // "object" ← 初期実装のバグ。互換性のため残っている
console.log(typeof [1, 2]);       // "object" ← 配列もオブジェクト
console.log(typeof function(){}); // "function"

// そのため配列と null は typeof ではなく専用の方法で判定する
console.log(Array.isArray([1, 2])); // true
const v = null;
console.log(v === null);            // true

typeof null が "object" になるのは、JavaScript 最初の実装に残っていたバグです。修正案は出されましたが既存の Web を壊すという理由で却下され、今もそのまま残っています。したがってnull かどうかは必ず === null で、配列かどうかは Array.isArray() で判定してください。

型変換: 明示的な変換を習慣にする

JavaScript は異なる型どうしを演算すると自動的に型を揃えてくれます。便利に見えますが規則が直感的でないため、初心者が最もつまずく箇所です。値を扱うときは Number()・String()・Boolean() で意図をコードに明示するほうが安全です。

// 文字列 → 数値
console.log(Number("42"));                 // 42
console.log(Number(""));                   // 0    ← 空文字列は 0 になる(注意)
console.log(Number("42px"));               // NaN
console.log(parseInt("42px", 10));         // 42   ← 先頭から読める分だけ
console.log(Number.parseFloat("3.14abc")); // 3.14

// 数値 → 文字列
console.log(String(42));       // "42"
console.log((42).toString(2)); // "101010"  ← 2 進数の文字列

// 暗黙的な型変換の落とし穴
console.log(1 + "2");  // "12"  + は片方が文字列なら連結として動く
console.log("3" - 1);  // 2     - は文字列を数値に変換してから計算する
console.log([] + {});  // "[object Object]"
  • parseInt() は第 2 引数に基数を明示する習慣をつけましょう。parseInt("08", 10) と書けば意図が明確になります。
  • ユーザー入力値(input.value)は常に文字列です。数値計算の前に必ず Number() で変換してください。
  • 文字列連結として働くのは + だけで、-・*・/ は数値変換を試みます。この非対称性が "3" - 1 === 2 なのに 1 + "2" === "12" になる理由です。
  • 数値かどうかの確認には Number.isNaN() と Number.isFinite() を使ってください。グローバルの isNaN() は引数を数値に変換してから判定するため、isNaN("abc") が true になります。

truthy と falsy、そして ?? 演算子

条件式に入れると false のように振る舞う値を falsy、それ以外のすべての値を truthy と呼びます。falsy な値はちょうど 8 個しかないので、まとめて覚えておくと便利です。

falsy な値意味間違えやすい truthy な値
false真偽値の偽"false"(中身のある文字列)
0数値のゼロ"0"(中身のある文字列)
-0負のゼロ[](空の配列)
0nBigInt のゼロ{}(空のオブジェクト)
""空文字列" "(スペース 1 個)
null値が無い(意図的)function(){}(関数)
undefined値が未代入Infinity
NaN数値ではないnew Boolean(false)(オブジェクト)
 
const falsyValues = [false, 0, -0, 0n, "", null, undefined, NaN];
console.log(falsyValues.every(v => !v)); // true - 8 個すべてが falsy

// || は falsy をすべて弾くので 0 や "" まで置き換えてしまう
const count1 = 0 || 10;  // 10 ← たいてい意図した結果ではない

// ?? は null または undefined のときだけ置き換える (ES2020)
const count2 = 0 ?? 10;  // 0  ← 意図した結果

console.log(count1, count2); // 10 0

「値が無ければ既定値を使う」というコードを || で書くと、数値の 0 や空文字列のような正常なのに falsy な値まで既定値で上書きされてしまいます。Null 合体演算子 ?? は null と undefined だけを対象にするので、この種の事故を防げます。

演算子と比較: == ではなく ===

等価比較 == は両辺の型が異なると片方を変換してから比較します。この変換規則が複雑で結果を予測しにくく、JavaScript コードで最も多い論理バグの原因になっています。厳密等価 === は型が違えば即座に false を返すので、覚えるべき規則は 1 つだけです。特別な理由がない限り、常に === と !== を使ってください。

比較式== の結果=== の結果理由
1 vs "1"truefalse文字列が数値に変換される
0 vs ""truefalse空文字列が 0 に変換される
0 vs falsetruefalse真偽値が数値 0 に変換される
[] vs falsetruefalse[] → "" → 0 の順に変換される
null vs undefinedtruefalse== はこの 2 つだけを等しいとみなす
null vs 0falsefalsenull は undefined 以外とは等しくない
NaN vs NaNfalsefalseNaN は自分自身とも等しくない
{a:1} vs {a:1}falsefalseオブジェクトは中身ではなく参照で比較される
 
console.log(1 == "1");            // true  - 文字列が数値に変換される
console.log(1 === "1");           // false - 型が違えば必ず false
console.log(null == undefined);   // true
console.log(null === undefined);  // false
console.log([] == false);         // true  - [] → "" → 0
console.log(0 == "");             // true

console.log(NaN == NaN);          // false - NaN は自分自身とも違う
console.log(Number.isNaN(NaN));   // true  - 正しい判定方法
console.log(Object.is(NaN, NaN)); // true  - Object.is は NaN を等しいとみなす

比較演算子を使うときに併せて覚えておきたい点です。

  • == が有用な唯一のケースは value == null です。null と undefined をまとめて検査する短い書き方として広く使われます。それ以外では === を使ってください。
  • オブジェクトと配列は === で比較しても参照が同じかどうかしか確認しません。中身の比較が必要なら各プロパティを直接比べるか、専用の関数を書きます。
  • NaN の判定には Number.isNaN() または Object.is() を使ってください。x === NaN は常に false です。
  • <、> のような大小比較は === と違って今も型変換を行います。比較前に Number() で揃えておくほうが安全です。

条件分岐とループ (Conditionals and Loops)

条件分岐はプログラムの流れを分け、ループは同じ処理を複数の値に適用します。条件が二択なら if...else、1 つの値が複数の候補のどれかを判定するなら switch、値だけが変わるなら三項演算子が読みやすくなります。

const score = 87;

// if / else if / else
if (score >= 90) {
  console.log("A");
} else if (score >= 80) {
  console.log("B");   // ← ここが実行される
} else {
  console.log("C");
}

// 三項演算子: 値を選ぶときに簡潔
const grade = score >= 80 ? "合格" : "不合格";

// switch: 各 case の break を忘れると下に流れ落ちる
switch (grade) {
  case "合格":
    console.log("おめでとうございます");
    break;
  default:
    console.log("再受験");
}

ループの選び方

ループは種類が多いものの、実際によく使うのは数えるほどです。配列の値を巡回するなら for...of、オブジェクトのキーを巡回するなら for...in を使うのが基本原則です。名前が似ていて紛らわしいので、用途をしっかり区別しておきましょう。

const scores = [90, 75, 88];

// for...of : 値を巡回(配列に推奨)
for (const s of scores) {
  console.log(s);        // 90, 75, 88
}

// for...in : キーを巡回(オブジェクト用。配列には非推奨)
const user = { name: "山田太郎", age: 25 };
for (const key in user) {
  console.log(key, user[key]);  // name 山田太郎 / age 25
}

// インデックスと値を一緒に使いたいなら entries()
for (const [i, s] of scores.entries()) {
  console.log(i, s);     // 0 90 / 1 75 / 2 88
}

// while: 繰り返し回数が事前にわからないとき
let n = 3;
while (n > 0) {
  n--;
}
  • for...in は配列に使うとインデックスを文字列で返し、プロトタイプチェーンのプロパティまで走査するため、配列には使いません。
  • ループ変数は const で宣言するのが基本です。for...of は反復ごとに新しいバインディングを作るので、再代入しない限り const で十分です。
  • break はループを完全に中断し、continue は現在の回だけをスキップします。
  • forEach() の中では break が動きません。途中で止めたい場合は for...of を使うか、some()・every() を活用してください。
  • 配列を「変換」または「絞り込む」目的なら、ループより map()・filter() を使うほうが意図がずっと明確に伝わります。

関数 (Functions)

関数はコードの再利用性を高める重要な概念です。

English: Functions are important concepts that enhance code reusability.

// 関数宣言 (Function Declaration)
function add(a, b) {
  return a + b;
}

// 関数式 (Function Expression)
const multiply = function(a, b) {
  return a * b;
};

// アロー関数 (Arrow Function)
const divide = (a, b) => a / b;

3 つの書き方は文法が違うだけでなく、ホイスティングの挙動と this の決まり方が異なります。どれを選ぶか迷ったら下の表を基準にしてください。

デフォルト引数・残余引数とアロー関数の this

ES2015 は関数の記述をぐっと簡潔にする文法をいくつも追加しました。デフォルト引数、残余引数、テンプレートリテラルはほぼすべてのコードに登場するので、今のうちに身につけておくとよいでしょう。

// デフォルト引数 (ES2015)
function greet(name, greeting = "こんにちは") {
  return `${greeting}、${name}さん`;   // テンプレートリテラル
}
console.log(greet("山田"));            // "こんにちは、山田さん"

// 残余引数: 個数が決まっていない引数を配列で受け取る
function sum(...numbers) {
  return numbers.reduce((acc, n) => acc + n, 0);
}
console.log(sum(1, 2, 3, 4));        // 10

// アロー関数は自分の this を持たず、外側の this をそのまま使う
const timer = {
  label: "タイマー",
  startArrow() {
    setTimeout(() => console.log(this.label), 0);            // "タイマー"
  },
  startFunc() {
    setTimeout(function () { console.log(this.label); }, 0);  // undefined
  }
};
timer.startArrow();
timer.startFunc();
  • コールバックの中で外側オブジェクトの this をそのまま使いたいならアロー関数を選びます。かつて使われていた const self = this や .bind(this) が不要になります。
  • 逆にオブジェクトのメソッドを定義するときにアロー関数を使ってはいけません。this がそのオブジェクトを指さないためです。短縮メソッド構文(startArrow() { })が定石です。
  • アロー関数の本体が 1 つの式なら波括弧と return を省略できます。波括弧を書いた場合は return が必須になります。
  • オブジェクトリテラルをそのまま返すには括弧で包みます。() => ({ id: 1 }) と書かないと、波括弧が関数本体として解釈されます。

配列とループ (Arrays and Loops)

配列とループを使うと、データを効率的に処理できます。

// 配列の宣言
const fruits = ["사과", "바나나", "오렌지"];

// for ループ
for (let i = 0; i < fruits.length; i++) {
  console.log(fruits[i]);
}

// forEach メソッド
fruits.forEach(fruit => {
  console.log(fruit);
});

// map メソッド (新しい配列を返す)
const fruitLengths = fruits.map(fruit => fruit.length);

実務で配列を扱うときは for ループより配列メソッドをはるかに多く使います。「何をしようとしているか」がメソッド名にそのまま表れ、コードを読む速度が上がるからです。よく使うものから整理すると次のとおりです。

メソッドする事戻り値元の配列の変更
map(fn)各要素を変換する同じ長さの新しい配列しない
filter(fn)条件を満たす要素だけ残す新しい配列しない
reduce(fn, init)1 つの値に集約する集約結果の値しない
find(fn) / findIndex(fn)条件に合う最初の要素 / その位置要素または undefined / インデックスまたは -1しない
some(fn) / every(fn)1 つでも満たす / すべて満たすtrue または falseしない
includes(v)特定の値を含むかtrue または falseしない
slice(a, b)一部の区間を切り出して複製新しい配列しない
push() / pop()末尾に追加 / 末尾から削除新しい長さ / 削除された要素する
splice(i, n, ...)途中で削除・挿入する削除された要素の配列する
sort(fn) / reverse()並べ替え / 順序の反転並べ替え・反転された元の配列する
toSorted(fn) / toReversed()並べ替え / 反転(複製)新しい配列 (ES2023)しない
 
const products = [
  { name: "キーボード", price: 45000 },
  { name: "マウス", price: 25000 },
  { name: "モニター", price: 300000 }
];

// filter: 条件に合う要素だけを新しい配列に
const cheap = products.filter(p => p.price < 100000);
console.log(cheap.length);   // 2

// map: 各要素を変換する
console.log(products.map(p => p.name));  // ["キーボード", "マウス", "モニター"]

// reduce: 1 つの値に集約する(第 2 引数が初期値)
const total = products.reduce((acc, p) => acc + p.price, 0);
console.log(total);          // 370000

// find / some / every
console.log(products.find(p => p.price > 100000).name); // "モニター"
console.log(products.some(p => p.price > 100000));      // true
console.log(products.every(p => p.price > 10000));      // true

元の配列を変えるメソッドと変えないメソッド

配列メソッドで最も事故が起きやすいのは、どのメソッドが元の配列を直接書き換えるかという点です。sort()・reverse()・splice()・push() は元を変え、map()・filter()・slice()・concat() は新しい配列を作ります。ES2023 で追加された toSorted()・toReversed()・toSpliced()・with() は、同じ処理を元に触れずに行う複製版です。

const nums = [3, 1, 2];
const sorted = nums.sort((a, b) => a - b);
console.log(nums, sorted === nums);  // [1,2,3] true ← 元が変わった

// toSorted は元を残して新しい配列を返す (ES2023)
const base = [3, 1, 2];
const copy = base.toSorted((a, b) => a - b);
console.log(base, copy);             // [3,1,2] [1,2,3]

// 数値の並べ替えで比較関数を省くと文字列基準で並ぶ
console.log([10, 9, 100].sort());               // [10, 100, 9]  ← 落とし穴
console.log([10, 9, 100].sort((a, b) => a - b)); // [9, 10, 100]

既定の sort() は各要素を文字列に変換してから辞書順に並べます。そのため [10, 9, 100] が [10, 100, 9] になります。数値を並べ替えるときは比較関数 (a, b) => a - b を必ず渡してください。

オブジェクトを扱う (Objects)

オブジェクトは キー: 値 のペアの集まりで、1 つの対象が持つ複数の属性をまとめて表現します。ES2015 以降に追加された分割代入とスプレッド構文を知ると、オブジェクトを扱うコードが目に見えて短くなります。

const user = { name: "山田太郎", age: 25, address: { city: "東京" } };

// 分割代入 (ES2015)
const { name, age } = user;
console.log(name, age);            // 山田太郎 25

// スプレッド構文でコピー + 一部だけ上書き(元はそのまま)
const updated = { ...user, age: 26 };
console.log(updated.age, user.age); // 26 25

// オプショナルチェーン (ES2020): 途中が無くてもエラーではなく undefined
console.log(user.address?.city);    // "東京"
console.log(user.company?.name);    // undefined

// キー / 値の巡回
console.log(Object.keys(user));     // ["name", "age", "address"]
Object.entries({ a: 1, b: 2 }).forEach(([k, v]) => console.log(k, v));
  • 分割代入は関数の引数でも使えます。function f({ name, age }) { } のように書けば、引数の順番を覚える必要がなくなります。
  • スプレッド構文 ... はオブジェクトと配列の両方でコピー・結合に使えます。後にある値が前の値を上書きします。
  • オプショナルチェーン ?. は、API レスポンスのように存在するか分からないネストしたデータを読むときに特に便利です。
  • Object.keys()・Object.values()・Object.entries() はオブジェクトを配列に変換するので、そのまま配列メソッドにつなげられます。
  • キーに変数を使うには角括弧記法を使います。obj[key] は変数の値で、obj.key は文字どおり "key" でアクセスします。

浅いコピーと深いコピー

スプレッド構文と Object.assign() は浅いコピーです。一段だけ新しく作り、その中のオブジェクトや配列は元と同じものを指します。ネストしたデータをコピーした後で内側を変更すると元まで変わるのは、これが理由です。

const original = { name: "山田太郎", tags: ["a", "b"] };

const shallow = { ...original };
shallow.tags.push("c");
console.log(original.tags);   // ["a","b","c"] ← 元も一緒に変わる

const deep = structuredClone(original);  // 深いコピー(最新ブラウザ、Node 17+)
deep.tags.push("d");
console.log(original.tags.length, deep.tags.length); // 3 4

深いコピーが必要なら、標準の組み込み関数 structuredClone() を使うのが最も簡単です。かつてよく使われた JSON.parse(JSON.stringify(obj)) は Date が文字列になり、undefined・関数・Map・Set が消えるため推奨されません。

非同期の基礎: Promise と async/await

JavaScript は一度に 1 つのことだけを処理するシングルスレッドで動きます。サーバーへのリクエストのように時間のかかる処理を待つ間に画面が止まらないよう、そうした処理は「終わったら知らせて」という方式で扱われます。その結果を表すオブジェクトが Promise であり、Promise を同期コードのように読ませる文法が async/await です。

function delay(ms, value) {
  return new Promise(resolve => setTimeout(() => resolve(value), ms));
}

// 前の結果が必要なとき → 順次処理(約 100ms)
async function runSequential() {
  const a = await delay(50, "A");
  const b = await delay(50, "B");
  return a + b;
}

// 互いに独立しているとき → 並列処理(約 50ms)
async function runParallel() {
  const [a, b] = await Promise.all([delay(50, "A"), delay(50, "B")]);
  return a + b;
}

// エラーは try/catch で捕まえる
async function safeRun() {
  try {
    return await delay(10, "ok");
  } catch (err) {
    console.error("失敗:", err);
    return null;
  }
}

runSequential().then(r => console.log("sequential:", r)); // "AB"
runParallel().then(r => console.log("parallel:", r));     // "AB"
safeRun().then(r => console.log("safeRun:", r));          // "ok"
  • await は async 関数の中でしか使えません(ES モジュールのトップレベルは例外)。通常の関数内で使うと構文エラーになります。
  • async 関数は常に Promise を返します。値を return しても、呼び出し側では await か .then() で取り出す必要があります。
  • 互いに依存しないリクエストを await で 1 行ずつ並べると不必要に遅くなります。その場合は Promise.all() でまとめてください。
  • 非同期関数のエラーは try/catch で捕まえます。.then() チェーンを使うなら、最後に必ず .catch() を付けてください。

初心者がよくするミス 12 選

以下の項目は、初めて JavaScript を学ぶ人ならほぼ必ず一度は遭遇する問題です。事前に知っておくとデバッグに費やす時間を大きく減らせます。

  1. NaN を === で比較する。 NaN === NaN は false です。Number.isNaN(x) または Object.is(x, NaN) を使いましょう。
  2. 0.1 + 0.2 === 0.3 が true だと期待する。 浮動小数点方式のため実際の値は 0.30000000000000004 です。許容誤差を設けて比較するか、整数単位で計算してください。
  3. == を習慣的に使う。 0 == "" や [] == false がすべて true になるなど予測が困難です。=== を基本にしましょう。
  4. メソッドをアロー関数で定義する。 アロー関数は自分の this を持たないため、オブジェクトのメソッドにすると欲しい値を読めません。逆にコールバックにはアロー関数が正解です。
  5. 非同期の結果を同期のように読もうとする。 fetch() のすぐ次の行では、まだ値がありません。await で待つか .then() の中で処理してください。
  6. async 関数の戻り値をそのまま使う。 コンソールに Promise { <pending> } と表示されたら await を書き忘れています。
  7. 数値の配列を比較関数なしで sort() する。 文字列基準で並び、[10, 100, 9] になります。(a, b) => a - b を渡しましょう。
  8. map() のコールバックで return を書き忘れる。 波括弧付きのアロー関数は明示的な return がないと undefined で埋まった配列になります。
  9. オブジェクト・配列を === で中身比較する。 参照が違えば中身が同じでも false です。プロパティを直接比べてください。
  10. 浅いコピーを深いコピーと勘違いする。 { ...obj } は一段だけコピーします。ネスト構造には structuredClone() を使いましょう。
  11. 入力値を文字列のまま計算する。 "5" + 3 は "53" です。Number() で変換してから計算してください。
  12. || で既定値を指定する。 値が 0 や空文字列のときも既定値で上書きされます。?? を使いましょう。
// ミス 2: 浮動小数点
console.log(0.1 + 0.2);          // 0.30000000000000004
console.log(0.1 + 0.2 === 0.3);  // false

const almostEqual = (a, b) => Math.abs(a - b) < Number.EPSILON;
console.log(almostEqual(0.1 + 0.2, 0.3)); // true

// 金額は最小単位の整数で計算してから割ると安全
console.log((0.1 * 10 + 0.2 * 10) / 10);  // 0.3

// ミス 8: map のコールバックに return が無い
console.log([1, 2, 3].map(n => { n * 2; }));      // [undefined, undefined, undefined]
console.log([1, 2, 3].map(n => n * 2));          // [2, 4, 6]

これらのミスの多くは「JavaScript が自動的に合わせてくれる挙動」を信頼したことから生じます。型変換と参照のコピーをコードに明示的に書く習慣をつければ、半分以上は消えてなくなります。

よくある質問 (FAQ)

JavaScriptで変数を宣言する方法は何ですか?

var、let、const というキーワードを使って変数を宣言できます。この 3 つはそれぞれ異なる特性を持つため、状況に応じて選んで使います。実務の基準では const を既定とし、値を入れ直す必要があるときだけ let を使い、var は関数スコープとホイスティングの問題から新規コードでは使いません。

JavaScriptの基本データ型にはどんなものがありますか?

文字列(String)、数値(Number)、真偽値(Boolean)、null(値がない)、undefined(値が代入されていない)、オブジェクト(Object)、そして一意で変更不可能なデータ型である Symbol があります。さらに大きな整数を扱う BigInt を加えると、プリミティブ型は全部で 7 種類となり、参照として扱われるのはオブジェクトだけです。typeof null が "object" になるのは言語初期のバグなので、=== null で判定してください。

JavaScriptにおいて関数はなぜ重要な概念なのですか?

関数はコードの再利用性を高める重要な概念です。繰り返し登場するロジックを関数にしておけば、必要なときにいつでも呼び出して使えます。また JavaScript では関数を値として変数に入れたり引数として渡したりできるため、map()・filter() のような高階関数やイベントコールバックの基盤にもなっています。

配列と反復文はどんな役割を果たしますか?

配列とループを使うと、複数のデータを効率的に処理できます。1 つずつ扱うのが面倒なデータのまとまりを配列に入れ、ループで巡回しながら処理する方式です。ただし値を変換したり絞り込んだりする目的なら、for ループより map()・filter()・reduce() といった配列メソッドのほうが意図を明確に表現できます。

JavaScriptの基本文法を身につけると何ができますか?

記事のとおり、JavaScript の基本文法を身につければさまざまなウェブアプリケーションを開発できます。変数・データ型・関数・配列・ループはその出発点となる中核的な概念です。その後 DOM 操作と fetch を覚えれば実際に動作する Web ページを作れますし、モジュールとクラスまで進めばフレームワークの学習へ自然につながります。

JavaScript の基本文法を身につければ、さまざまなウェブアプリケーションを開発できるようになります。
