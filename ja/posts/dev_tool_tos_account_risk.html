2026-09-05 開発・インフラ

新しい開発ツールを入れるとき、開発者が測るのはたいてい三つである。どれだけよく動くか、いくらかかるか、どれだけ早くつなげるか。無料で配られるツールなら二つ目の項目が丸ごと消えるので、判断はさらに速くなる。ダウンロードして、手持ちのアカウントでログインして、その日のうちにパイプラインへ入れる。

ところが、そのログイン一回で静かに決まるものがある。そのツールをどのアカウントで使い始めたのか、そしてそのアカウントにすでに何がぶら下がっているのかである。ツールを一つ差し込んだだけなのに、そのツールの利用規約が規律する範囲の内側に、メールも文書も認証もクラウドストレージも一緒に入ってしまうことがある。

ここで扱うのは特定の会社の是非ではない。無料の開発ツールを業務の流れに入れるとき、アカウント一つに何がぶら下がることになるのか、そしてその答えが約款のどの条項の型で分かれるのかである。条項の型を知っていれば、新しいツールに出会うたびに同じ順序で読めるし、読み落とした部分がどんな危険を開けたままにしているのかも一緒に見える。

以下は法的助言ではない。公開されている原文の文言に基づいて、約款の条項の型がそれぞれ何を決めるのかを整理した情報提供の文書である。個別契約の効力、特定条項の有効性、実際の紛争の結論は、法域と契約形態と当事者の地位によって変わり、その判断は所管機関と有資格の専門家に属する。引用した文言には閲覧時点を併記した。

きっかけ - 一文から分かれた二つの話

2026年9月初め、韓国の開発者コミュニティにGoogle Antigravity のサードパーティ使用禁止とアカウント停止約款をめぐる論争という題の投稿が上がった。元リンクは X、かつての Twitter の投稿を指している。

コミュニティの要約が伝える論点は四筋ある。第一に、当該サービスの約款がサードパーティのツールを通じた接続を禁じ、Antigravity と Gemini CLI へのアクセス停止を許容しているということ。第二に、初期の文言がyour accountという曖昧な表現を使ったため、Google アカウント全体が永久に停止されるのではないかという懸念が広がったということ。第三に、Antigravity 側の責任者が停止の対象は Antigravity アカウントを指すと整理し、アカウント全体の解除は起きていないと述べたということ。第四に、それでも上位の約款には重大または反復的な違反についてアカウント全体を扱いうる規定が別に存在するということである。

ここでは三つの層が混ざっている。コミュニティが要約した論点、会社の関係者が述べたと伝えられる発言、そして約款のページに実際に書かれている文である。この三つは同じ出来事を指すが、重さがまるで違う。発言は運用を教えるが契約を変えない。要約は方向を教えるが、文に付いていた条件を落としやすい。契約上何が可能なのかを決めるのは条文だけである。

したがって以下では論争を移さない。条文を移し、その条文が作る構造的な帰結だけを追う。

条文と主張を分けて置く

Google Antigravity Additional Terms of Service は2026年9月5日の閲覧時点で八項からなる。問題の第6項は四つの文であり、それぞれの文がする仕事が違う。

You must not abuse, harm, interfere with, or disrupt the Service. This includes, but is not limited to, using the Service in connection with products not provided by us. Using third party software, tools, or services to access the Service (e.g. using OpenClaw with Antigravity OAuth) is a breach of this Agreement. Such actions may be grounds for suspension or termination of your Antigravity and/or Gemini CLI accounts.
  • 第一文は上位の範疇を立てる。濫用、加害、妨害、混乱である。この四つは互いに別の行為であり、それぞれが独立した禁止として立っている
  • 第二文はその範疇の内側に、提供元が提供していない製品と結び付けて使用することを入れる。そしてこれに限られないという表現を付ける。列挙は上限ではなく下限だという意味である
  • 第三文が最も断定的である。サードパーティのソフトウェアとツールとサービスでサービスに接続することは本契約の違反だと言い切り、括弧の中に具体的な例まで入れている
  • 第四文は結果を述べるが確定形ではない。そうした行為が停止または解除の根拠となりうると書き、対象はAntigravity および Gemini CLI アカウントと範囲が付いている

見出しのアカウント停止と条文の第四文は二つの地点で違う。一つは確定性である。根拠となりうるという言い方は裁量の記述であって自動執行の記述ではない。もう一つは範囲である。条文に書かれた対象はサービスアカウント二つである。

ただしここで止めれば半分しか読んでいないことになる。同じ文書の第1項が上位の約款を一緒に引き込む。だからこの追加規約の範囲限定が、そのまま契約全体の範囲限定になるわけではない。その重なりが、以下で六番目の条項の型として別に扱う内容である。

整理するとこうなる。条文はサードパーティ経由の接続を違反と規定するという点で要約と一致する。停止が自動だという点、そして Google アカウント全体が対象だという点は、この条文から出てこない。その二つは別の文書と別の条項で改めて確かめるべき事項である。

型その一 - 許容用途と禁止用途

最初に見る条項の型は何をしてよく何をしてはいけないかを定める部分である。この型が決めるのは単純だ。いま自分がしようとしている使い方が契約の内側なのか外側なのか。

読むときに分けるべきなのは目録の性格である。列挙型なら目録にない行為は原則として禁止の外にある。例示型なら目録は例にすぎず、判断基準はその上にある抽象的な範疇のほうにある。二つの形を分ける標識がこれに限られないという文言であり、先に見た第6項がまさにその形である。

他の文書と並べると形の違いが浮かぶ。Gemini API Additional Terms of Service は2026年3月23日発効、ページ表記上2026年4月28日最終更新の文言で、サービスと競合するモデルを開発するためにサービスを使用できないと述べ、サービスの構成要素をリバースエンジニアリングしたり抽出したり複製しようとする試みを禁じ、利用可能な地域の中でのみサービスに接続し API クライアントを提供できると述べる。Anthropic Commercial Terms of Service は2025年6月17日発効の文言で、競合する製品やサービスを作るための接続、競合モデルの訓練、再販を禁じ、リバースエンジニアリングと複製を禁じ、第三者がそうした行為をするのを支援することまで併せて塞いでいる。

  • 抽象範疇型 — 濫用、妨害、混乱のような広い語で範疇を立て、例を下にぶら下げる。予測可能性は低い代わりに適用範囲が広い
  • 行為列挙型 — リバースエンジニアリング、再販、競合モデルの訓練のような具体的行為を名指しで並べる。目録の外の行為は別の条項へ移る
  • 条件付加型 — 地域制限のように、行為そのものではなく条件を掛ける。同じ使い方でも条件がずれれば違反になる

開発ツールを選ぶときこの型で実際に確かめるべきなのは、禁止目録の長さではなく自分の使い方がその範疇の内側として読まれうるかである。社内のバッチ処理が自動化なのか、CI からの呼び出しがサードパーティクライアントなのか、社内プロキシを経由することが接続方法の変更なのかは、ここで分かれる。

型その二 - 自動化とサードパーティクライアント

二番目の型は開発ツールにおいて特に重い。開発者の基本反射がつなげて使うことだからである。CLI があればスクリプトで包み、トークンが出れば別のエージェントに渡し、呼び出しが増えればキャッシュやプロキシを前に立てる。この三つはすべて公式クライアントではない経路で同じ資源に届く行為である。

Antigravity 追加規約の第6項が括弧の中に例を入れたのもその地点である。特定のサードパーティエージェントを当該サービスの OAuth と一緒に使う組み合わせを名指しした。単一の製品ではなく組み合わせを例に挙げたということは、認証資格がどこへ流れるのかを基準に見ているという読みにつながる。

この型で分けて問うべき質問は三つである。

  • 禁じられているのは自動化なのか、非公式クライアントなのか。 自動化そのものが禁止なら社内スケジューラも掛かる。非公式クライアントが対象なら、公式 CLI を包んだスクリプトは別に読まれる余地がある
  • 公式 API が別の約款で開かれているか。 同じ会社でも対話型の製品と API は別の文書で規律されることが多い。API 経路があるなら自動化をそちらへ移すのが契約上安全な選択肢になる
  • 無料ティアと有料ティアで扱いが違うか。 データの利用、割り当て、停止の裁量がティアごとに分かれる文書がある

三番目の質問は実際に文書へ現れている。Gemini API 追加規約は無料提供分について、利用者が提出したコンテンツと生成された応答を製品とサービスの提供、改善、開発に使用すると述べ、有料サービスについてはプロンプトと応答を製品の改善に使用しないと述べる。Antigravity 追加規約も同じ構造である。第3項は利用者データ、サービス利用に関するインタラクションデータ、関連するメタデータ、提供されたフィードバックを記録し保存すると述べ、第5項はそれを研究、製品、サービス、機械学習技術の評価と開発と改善に使用すると述べ、従業員と請負業者がアクセスし閲覧し検討しうると付け加える。同じ第5項に、設定で利用方法についての選好を変えられるという文が付いている。

トークン単位の課金がツール選択をどう変えるのかは AIコーディングツールから金額が消えた で別に扱った。ここで見るのは費用ではなく接続経路が契約上どう分類されるかだけである。

型その三 - 停止・解除の権限と事前通知

三番目の型がこの記事の軸である。停止条項は三つを定める。どんな事由で停止できるのか、どんな手続きで行うのか、そして事前に知らせるのかである。

Antigravity 追加規約の第6項には事由の記述はあるが手続きの記述がない。停止または解除の根拠となりうるという一文で終わる。手続きは上位の文書へ移る。

Google 利用規約 は2026年7月30日発効の文言で事由を分けて書く。規約またはサービス別ポリシーを重大にまたは反復して違反する場合、法律または裁判所の命令によって要求される場合、そして利用者と第三者と提供元に害や責任をもたらす行為をする場合である。最後の項目にはハッキング、フィッシング、嫌がらせ、スパム、他者を誤導する行為、コンテンツのスクレイピングが例として付いている。

通知に関する文はこうである。以下に記述する措置を取る前に合理的に可能な場合には事前通知を提供するというものだ。そして例外が続く。通知が害をもたらす場合、法に違反することになる場合、調査を妨げる場合、サービスのセキュリティや完全性を損なう場合である。

この文が実務で持つ重みは条件節にある。事前通知は原則であって保証ではない。 しかも例外事由のうち調査の妨害とセキュリティの毀損は、判断の余地が広い項目である。計画を立てるときは通知がない場合を既定値に置くほうが安全である。

対照として Anthropic の商用利用規約を置くと形の違いが見える。この文書は停止事由を項目記号まで付けて列挙する。サービスに対する危険や攻撃があると合理的に判断する場合、利用者が遵守条項とポリシー条項と使用制限条項に違反してサービスを使用する場合、法律上提供が禁じられるか提供費用が実質的に増加する場合、そしてサービスの提供に必要な第三者のサービスが停止または終了する場合である。最後の項目は利用者の落ち度でない事由でも停止が起こりうることを文書に書いておいた例である。

型その四 - 持ち出し経路と停止後のアクセス権

四番目の型は、先の三つの型が現実になったときの被害の大きさを決める。データをいつどんな形式で取り出せるのか、そしてアカウントが止まった後もその経路が生きているのかである。

Antigravity 追加規約には削除の経路だけがある。第3項はインタラクションデータを削除する選択肢があると述べ、削除を望むなら指定された支援用のメールアドレスへ依頼するよう案内する。持ち出しに関する文はこの文書にない。

Google 利用規約で持ち出しの話が出てくる場所には条件が付いている。提供元がサービスの提供を中止する場合、関連する法律とポリシーに従って Google Takeout でコンテンツを書き出す機会を与えるという文である。つまりその文はサービス終了のシナリオにぶら下がっているのであって、アカウント停止のシナリオにぶら下がっているのではない。

停止のシナリオはサポート文書のほうに書かれている。アカウントが無効化されると当該サービスにログインできず、そのアカウントでのログイン機能も使えない。データについては条件付きの表現を使う。アカウントに入れない場合、一部のサービスからアカウントデータをダウンロードして保存できる可能性があるというものだ。アカウントの乗っ取りや児童の性的搾取のような特定の違反類型ではそれすら遮断されると記されている。異議申立てはログイン後に手続きを開始して行い、一部の違反類型については最大二回まで審査し、その後の申立ては自動的に終結する。措置を取らなければアカウントは永久に無効化され削除の検討対象になる。欧州連合の居住者には追加の解決手段がありうるという案内が付いている。

型その五 - 準拠法と紛争解決

五番目の型は争いが起きたときどの国の法でどの裁判所で争うのかを定める。平時には何もしないが、問題が起きた瞬間に現実的な対応可能性の全体を決めてしまう。

Antigravity 追加規約には準拠法と紛争解決の条項がない。この席は上位の約款が埋める。Google 利用規約は、この規約およびこの規約に関連して生じるすべての紛争にカリフォルニア法が適用され、紛争は米国カリフォルニア州サンタクララ郡の連邦または州の裁判所でのみ解決されると述べる。ただし二つの緩和が続く。現地法がその裁判所への提訴を妨げる場合には現地の裁判所へ提起でき、カリフォルニア法を適用できない場合には現地法が適用されうるというものである。

韓国でこうした条項がどう扱われるのかは法域の問題である。約款の規制に関する法律の第6条は、信義誠実の原則に反して公正を失った約款条項を無効とし、顧客に不当に不利な条項、取引形態など関連するすべての事情に照らして予想しがたい条項、契約の目的を達成できない程度に契約に伴う本質的権利を制限する条項を、公正を失ったものと推定する。無効事由のなかには、契約の解除権と解約権を顧客に対して不当に排除または制限し、事業者に対しては不当に広く認める内容が入る。第3条は事業者に約款の明示と写しの交付、重要な内容の説明義務を課し、これに違反した場合その約款を契約の内容として主張できないと定める。

  • 一般論と個別判断は別の層である。 ある条項が実際の事件で無効になるかどうかは、契約形態、当事者が消費者か事業者か、交渉の余地があったかなどによって分かれる
  • 法域が違えば結論も違う。 同じ文言でも、どの国の消費者保護規範のもとで争うかによって扱いが変わる
  • 準拠法の合意があるからといって現地の強行規定がすべて排除されるわけではない。 その境界もまた法域ごとに定まる

不公正な約款の一般論と無効主張の経路は 不公正な約款の無効主張・紛争解決完全ガイド に別途まとめてある。ここではツール選択の観点だけを見る。すなわち争えるかどうかより争っている間に業務が止まっているかどうかが実務では先に来る。

型その六 - 約款が何枚に重なっているか

六番目の型は、先の五つの型をどこで読むべきかを定める。ほとんどのツールの約款は単独の文書ではなく、参照で他の文書を引き込む薄い文書である。

Antigravity 追加規約の第1項は、三つの文書がサービスの利用を規律すると述べる。Google 利用規約、この追加規約、そしてプライバシーポリシーである。第2項はこの三つを束ねて一つの契約と呼び、上位の約款から読むよう案内する。第8項がもう一枚を重ねる。主たるエージェントモデルとしてサードパーティまたはオープンソースのモデルを選ぶとそのモデルの規約に拘束されると述べ、Anthropic の場合は商用利用規約の所在を明示する。文書の冒頭には逆向きの例外がある。特定の企業向け製品ラインや、特定の条件下の Workspace 契約、あるいは企業向けエージェントプラットフォームの API キーで接続する場合、管理者が承諾または署名した規約が適用され、この文書は適用されないというものである。

  • 最少で三本 — 上位の約款、追加規約、プライバシーポリシー
  • モデルを変えれば四本 — 選んだモデル提供者の規約が加わる
  • 組織経路なら別の束 — 管理者が締結した契約がこの文書を丸ごと置き換える
  • サービス別ポリシーがさらにある — 上位の約款が停止事由として挙げるものにサービス別ポリシーの違反が含まれる

この型が作る構造的な帰結は明確である。約款を読んだという言葉が成立するには、何本読んだのかを数えられなければならない。 しかもそのうちどの文書が停止の手続きを持ち、どの文書が持ち出しを持つのかが互いに違うので、一つの文書だけを見て下した結論はたいてい半分である。

爆発半径 - アカウント一つにぶら下がっているもの

ここまでが文書の話なら、ここからは被害の大きさの話である。同じ条項でも、そのアカウントに何がぶら下がっているかによって結果はまったく変わる。

範囲を示す文はすでに出てきた。アカウントが無効化されると当該サービスにログインできず、そのアカウントでのログイン機能も使えないという文である。後半が決定的だ。そのアカウントでログインしておいた別の会社のサービスまで一緒に塞がるという意味だからである。

認証がぶら下がっている場所

  • ソーシャルログインでつないでおいた外部サービスのすべて — 配布ダッシュボード、決済コンソール、エラー追跡、ドキュメントツール
  • 二段階認証のアプリと復旧コードが、そのアカウントのメールやクラウドに保存されている場合
  • 別のアカウントの復旧用メールとして指定しておいた場合。このとき停止は別アカウントの復旧経路まで断つ
  • ドメイン登録、証明書の更新通知、請求書の受信先のような自動化された流れの終着点

成果物がぶら下がっている場所

  • ツールが作ったコード、ログ、対話履歴のうちサービス側にしかないもの
  • メールボックス、文書、カレンダーのように業務の文脈を抱えている保管場所
  • クラウドドライブにしかない設計資料と資格情報のメモ
  • 持ち出しアーカイブの配信先として指定しておいたストレージが同じアカウントに結び付いている場合

OAuth トークンが一度漏れるとどこまで広がるのかは github.dev 1クリック・トークン窃取の脆弱性 で扱った。停止の爆発半径も形は同じである。違うのは一つだけだ。トークンの流出は攻撃者が入ってくる出来事であり、アカウントの停止は自分が入れない出来事である。備えの向きが逆になる。

個人アカウントと組織アカウントで分かれる地点

Antigravity 追加規約の冒頭にある例外が、この違いを文書の次元で作る。組織経路で接続すると管理者が承諾または署名した規約が適用され、個人向けの文書は適用されない。すなわち契約の相手方が変わる。

項目個人アカウントで業務ツールを使うとき組織が発行したアカウントで使うとき
契約当事者個人とサービス提供者組織と提供者、個人は利用者
適用される文書公開された消費者向けの約款の束管理者が承諾または署名した契約、別の条件が付く場合がある
停止が起きたときの対応主体個人が直接異議を申し立て、審査回数の制限を個人が使い切る管理者チャネルと契約上の支援経路が別にある場合がある
成果物の所在個人アカウントの中。組織が届く経路がない組織のテナントの中。管理者が移管と持ち出しを行える
退職・不在のとき引き継ぎが個人の協力に依存するアカウント移管の手続きで処理される
私的な利用制約が少ない組織のポリシーの適用を受ける

責任の配分に関する条項もここに掛かる。Antigravity 追加規約の第4項は、サービスの中で作成し調整し開始するエージェントについて利用者が全面的に責任を負うと述べる。エージェントが行った動作と作業、用途への適合性の判断、データとアプリケーションとシステムへのアクセス権限の付与、そして本番環境で使用するときの判断と監督が目録に入っている。第7項は補助ファイルの形の機能について同じ形の文を繰り返す。無保証であり、用途適合性の判断と監督は利用者の責任だというものである。

個人アカウントで業務をすれば、この全面的に利用者がそのまま個人を指す。組織アカウントならそれが誰を指すのかは管理者が締結した契約が定める。ツールを個人アカウントで始めておいて後から組織へ移す順序は、この一文のせいで移す前の区間の責任の所在を曖昧に残す。

日付のない約款を引用する方法

約款は改定される。だから引用には時点が付いていなければならない。ところがその時点を提供する方法が文書ごとに違う。

  • Google 利用規約 — 文書の上部に発効日が書かれている。ここで扱ったのは2026年7月30日発効の文言である
  • Gemini API 追加規約 — 発効日が2026年3月23日で、ページの下部に2026年4月28日最終更新の表記が別にある。二つの日付は別のものを指している
  • Anthropic 商用利用規約 — 2025年6月17日発効で、旧版へのリンクが併記されている。改定前の文言を突き合わせられるという意味である
  • Google Antigravity 追加規約 — 発効日も最終更新日も文書に表記されていない

最後の場合に残る方法は一つだ。読む側が時点を作る。 閲覧の時刻を記し、その時点の文言を複製として残し、複製のハッシュを記録しておく。導入の決定を下した根拠が何だったのかを後から再構成できなければならないからである。

# 導入時点の約款の文言を複製として残す
mkdir -p terms
D=$(date +%F)
curl -sSL https://antigravity.google/terms/ -o terms/antigravity_$D.html
curl -sSL https://policies.google.com/terms -o terms/google_universal_$D.html
sha256sum terms/*_$D.html | tee -a terms/HASHES.txt

この習慣が必要なのは、きっかけになった論争そのものが文言が変わったという主張を含んでいるからである。コミュニティの要約は、初期の文言が範囲を特定しない表現であり、その後に対象が整理されたと伝える。2026年9月5日時点の原文では対象が Antigravity および Gemini CLI アカウントと書かれている。二つの文のうちどちらがいつ存在したのかを言えるのは、その時点の複製を持っている側だけである。

ツールを作って配る側が約款とポリシー文書をどう準備するのかは サービスを公開する前に確認する五つの質問 にまとめてある。ここで見るのは反対側、すなわち他人が書いた約款を読んで採用の可否を決める側の視線である。

無料という言葉が契約で意味するもの

無料のツールが有料のツールより契約上不利になる経路は、感情の問題ではなく構造の問題である。三つが重なる。

  • データの扱いが違う。 Gemini API 追加規約は無料提供分について、提出したコンテンツと生成された応答を製品とサービスの提供、改善、開発に使用すると述べ、有料サービスについてはプロンプトと応答を製品の改善に使用しないと述べる
  • 切る費用が低い。 料金関係がなければ停止の判断において考慮すべき契約上の給付が少ない。逆に有料の契約には返金、サービス水準、通知といった仕組みが付く余地が生じる
  • 支援の経路が違う。 無料利用者の窓口はたいてい公開のフォーラムか指定のメールであり、契約上の応答期限が付かない

Antigravity 追加規約も問い合わせを公開の掲示板へ案内して終わる。削除の依頼だけを支援用のメールアドレスで受ける。これは設計の誤りではなく無料提供物の一般的な形である。ただし業務の流れに入れた瞬間、その形がそのまま復旧時間の上限になるという点が変わる。

だから判断はツールの品質ではなく代替可能性で下すべきである。同じ仕事を別の経路でできるなら停止は不便であり、できないなら停止は中断である。

ツールを入れる前に終わらせておくもの

ここまでの内容を導入の手順に移すと次のようになる。項目ごとに導入の後へ回せるかを基準に二つの束へ分けた。

導入前に終わっているべきもの

  • アカウントの分離 — ツール用のアカウントを、メールと文書と認証がぶら下がった主アカウントから分離する。分離が不可能なツールなら、その事実自体が危険項目である
  • 復旧経路の分離 — ツール用アカウントの復旧メールと二段階認証の手段をそのアカウントの外に置く。同じアカウントの中に置けば、停止が復旧経路まで一緒に断つ
  • 持ち出し経路の確認 — 成果物が持ち出しの対象目録に入っているか、持ち出しがログインを前提とするかを確かめる。予約持ち出しが可能なら導入と同時に掛ける
  • 約款の複製と閲覧時点の記録 — 規律する文書を全部数え、各文書の版の表記と閲覧時点を併せて残す
  • 代替手段の指定 — このツールが明日止まったら何で同じ仕事をするのかを名前まで書いておく。書けないならそのツールはまだ業務の経路ではなく実験である

導入後に維持するもの

  • 成果物のローカル複製 — ツールが作ったコードとログをサービスの外へ定期的に複製する。複製の古さがそのまま最悪の損失の大きさである
  • 資格情報の分離保管 — 複製の中にトークンや鍵が混ざり込まないよう除外目録を管理する
  • 接続経路の目録化 — どのラッパーとスクリプトがそのサービスに届くのかを目録として維持する。約款が変われば、この目録がそのまま影響範囲である
  • 約款の改定監視 — 複製のハッシュを定期的に比較する。更新日の表記がない文書ほど、この方法以外に変化をつかむ手段がない
# ツールが作った成果物とログを毎日ローカルへ複製する
printf '%s\n' '.env' '*.token' 'credentials.json' | tee /backup/EXCLUDE
rsync -a --delete --exclude-from=/backup/EXCLUDE ~/work/agent-out/ /backup/agent-out/
git -C ~/work/repo bundle create /backup/repo-$(date +%F).bundle --all

この目録で最も頻繁に抜け落ちるのが二つ目の束の最初の項目である。ツールがうまく回っている間は複製が無駄に見え、役に立つ瞬間には作れないからである。アカウントが乗っ取られたら完全復旧ガイド で整理した復旧の順序も同じ前提の上に立っている。閉じられた後にできることは、閉じられる前にしておいたことの関数である。

確認できなかったこと

  • きっかけになった X の投稿の原文 — コミュニティの投稿が指すリンクは当該プラットフォームの投稿であり、ログインなしに本文を開ける形ではなかった。したがって投稿そのものの文は引用せず、上で移したものはコミュニティの要約が伝える内容だという表示を付けてある
  • 関係者の発言の原文と時点 — 停止の対象がサービスアカウントに限られるという趣旨の発言は、コミュニティの要約を通じて伝えられたものである。発言の原文、正確な表現、時点は確定できなかったため、契約上の効力を持つ文言としては扱っていない
  • Antigravity 追加規約の改定履歴 — この文書には発効日も最終更新日も旧版へのリンクもない。したがって以前の文言が何であり、いつ変わったのかは、ここでは断定しない
  • Gemini CLI 専用の約款文書の有無 — 追加規約は Gemini CLI アカウントを停止の対象として併記するが、そのサービスだけを規律する別の文書があるのかどうかは、この記事の範囲では扱っていない
  • 個別の停止事例の事実関係 — 公開の掲示板に異議申立ての投稿があるが、各事例で実際にどんな行為があり、どんな手続きが適用されたのかは当事者と事業者だけが知る領域である。事例を根拠に条項の運用方法を一般化することはしていない
あらためて記す。以上の内容は特定の事案についての法的助言に代わるものではない。引用した条文は表示された閲覧時点の文言であり、約款は予告なく改定される。ある条項が実際に有効なのか、特定の行為が違反に当たるのか、どんな救済手段が開いているのかは、法域と契約形態と当事者の地位によって分かれる。契約上の地位や損害が掛かっている状況なら、所管機関または有資格の専門家の判断を受けるのが正しい。
