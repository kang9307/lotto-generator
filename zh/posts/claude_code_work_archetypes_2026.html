AI时代的五种工作者原型 — Claude Code创始人的洞见

Prototyper · Builder · Sweeper · Grower · Maintainer — 用工作方式而非职称来理解人，是AI时代的新语言

2026-07-01 潮流/文化

引言：职称无法描述工作方式的时代

截至2026年6月，AI工具已将工程师编写代码的速度提升了数倍。随之而来的是一个奇特的现象：工程、产品管理、设计和数据科学之间的边界正在消融，传统职称越来越难以解释一个人实际的工作方式。说"我是后端工程师"几乎无法告诉别人这个人每天在做什么。

在这一背景下，Claude Code的创始人Boris Cherny提出了一个有意思的框架。通过观察自己的团队，他发现了五种反复出现的工作模式：Prototyper（原型师）、Builder（构建者）、Sweeper（清理者）、Grower（成长者）、Maintainer（维护者）。这不是职称，而是工作方式的模式。设计师可能是Prototyper，工程师可能是Maintainer，产品经理可能是Sweeper。

本文不仅介绍这个框架，还将深入分析为什么这种区分在2026年更具价值、各原型的真正优势与陷阱是什么，以及AI工具时代如何改变每种原型所能提供的价值。

1. 五种原型 — 各自做什么

先回到Boris Cherny的原始定义。他有一个重要前提："这些角色与职能并无绑定——在Anthropic，一些设计师符合类型1，一些符合类型2，一些符合类型3；工程师、PM、DS同理。"这是工作方式的模式，而非职称。

1.1 Prototyper — 探索可能性的人

Prototyper是"产生全新想法的人，快速尝试许多想法，但其中大多数不会最终发布"。他们将精力投入探索本身，而非完成。AI工具的出现极大提升了Prototyper的产出。过去验证一个想法需要几天，现在几小时内就能做出可运行的原型。

优势：快速覆盖可能性空间。不惧失败，因此能看到他人不敢尝试的方向。在产品早期探索阶段，能为团队注入能量。

陷阱：容易陷入"好想法没能坚持到底"的模式。AI加速原型制作反而加深了这个陷阱——想法来得太容易，专注于一个想法的能力反而会减弱。Prototyper过多的团队会创造出一个"想法的墓地"。

1.2 Builder — 将想法变成产品的人

Builder是"将原型或想法快速转化为生产级产品和基础设施的人"。他们在构建时考虑可扩展性、稳定性和可维护性。Builder知道什么是"完成"——不只是能运行，而是经得起他人接手而不崩溃的东西。

优势：最能高效利用AI编码工具的原型。代码生成速度由AI提升，但构建什么、如何构建的判断仍是Builder的领域。AI越快，Builder完成的东西就越多。

陷阱：可能沉迷于构建本身而忘记问"现在应该构建这个吗"。若不仔细审查AI生成的代码就堆砌，Builder反而会成为技术债务的生产者。

1.3 Sweeper — 驾驭复杂性的人

Sweeper是"整理UI、简化代码和系统、移除不必要功能（unship）、优化性能的人"。他们通过删减而非增加来创造价值。这是Boris Cherny框架中最独特的原型，"主动下架功能"的概念尤为引人注目。

优势：AI加速代码生成，复杂性债务随之快速积累，Sweeper正是管理这种债务的人。有优秀Sweeper的团队，即使随着时间推移，代码库也能保持可理解的状态，这直接关系到团队整体速度。

陷阱：Sweeper的价值在组织中不可见。"添加了新功能"的PR显眼，"删除了500行代码同时保持相同功能"的贡献却被低估。在AI生成代码泛滥的时代，Sweeper更加重要，但认可度反而更难获得。

1.4 Grower — 寻找市场匹配的人

Grower是"通过反复迭代已构建的产品来提升产品市场匹配度（Product-Market Fit）的人"。他们对用户数据、市场信号和竞争动向高度敏感。他们关注的不是产品技术上有多出色，而是产品在市场上的接受程度。

优势：让团队远离"技术上很优秀但没人用"的陷阱。能以用户的语言与团队沟通，并根据市场信号排列优先级。AI让实验速度加快，Grower的判断力能引导实验走向更有意义的方向。

陷阱：过于响应短期市场信号可能迷失产品的根本方向。Grower强势的团队有时因"用户喜欢"就持续添加功能，反而堆积复杂性。

1.5 Maintainer — 守护稳定的人

Maintainer是"随着成熟系统扩展，负责让其保持安全、可靠、快速和高效的人"。变化不是价值，稳定才是。系统不宕机就是成功。往往是团队中最安静的人，但出了问题第一个被找到的也是他。

优势：成熟系统中没有Maintainer，技术债务和安全漏洞会悄然积累。无论AI工具如何进化，深度了解遗留系统的上下文和依赖关系的人都难以替代。对Maintainer来说，知识本身就是价值。

陷阱：容易滑向回避变化的方向。"现在运行得好，别动它"的态度有时会阻碍技术演进。导入AI工具、改善架构等变化需要Maintainer主导，而接受这种不适感可能并不容易。

2. AI工具如何改变各原型

Boris Cherny提出这个框架的背景不是简单的角色分类。其核心是：在工程、产品、设计、数据科学融合为新型角色的时代，如何捕捉人们实际的工作方式。

AI工具对各原型的影响各不相同。Prototyper的探索速度借助AI提升了数倍；Builder可以将实现的重复工作交给AI，更专注于设计决策；Sweeper面临AI生成代码带来的新复杂性整理负担；Grower借助AI快速完成数据分析，运行更多实验；Maintainer可通过AI自动化减轻运维负担，但需更仔细审查AI生成代码中的隐藏漏洞。

关键变化是：一个人能够胜任的原型数量增加了。以前同时出色地扮演Prototyper和Builder需要极端的能力，现在AI减轻了实现的重量，Prototyper在一定程度上也能担任Builder的角色。但随着工具加速执行，各原型的判断力变得更加重要。在工具快速构建的时代，决定构建什么的能力才是核心技能。

3. 产品生命周期与原型配比

Boris Cherny的另一个重要洞见是：原型的最优配比随产品生命周期变化。早期探索阶段需要Prototyper、Builder和Sweeper的能量——快速实验是首要任务。市场信号出现后，Builder、Sweeper和Grower的比重上升。产品成熟后，Sweeper、Grower和Maintainer成为核心，稳定增长优先于快速变化。

这一视角的重要性在于：许多团队会犯"在错误阶段配置错误原型能量"的错误。成熟产品中只有Prototyper的团队会持续添加不必要的功能，同时让系统陷入混乱。早期探索阶段只有Maintainer则什么都造不出来。构建团队时，首先要问的是："我们的产品现在处于哪个阶段？"

4. 认识并发展自己的原型

最实用的问题：你属于哪种原型，如何发展自己薄弱的那些？

最诚实的诊断方式是观察能量最高的时刻。尝试新想法时感到兴奋，说明你偏Prototyper；将想法打磨成高完成度产品时感到满足，则偏Builder；整理混乱代码后感到充实，则是Sweeper；看用户反应并持续改进时动力充沛，则是Grower；系统稳定运行时感到安心，则接近Maintainer。

如Boris Cherny所承认的，大多数人横跨两三种原型，这并非弱点，而是优势——能在不同原型所需的时机灵活切换本身就很有价值。但了解自己的主导原型仍有意义：你能更清楚地知道何时能做出最大贡献，也能更好地看到团队需要补充什么。

4.1 发展薄弱原型的方法

Builder想培养Grower能力，可以从有意识地花时间做用户访谈和数据分析开始。Prototyper想培养Builder习惯，核心在于反复将一个想法坚持到"完成"标准。Maintainer想培养Sweeper感觉，可以养成定期提交简化常触碰代码的PR的习惯。AI工具也能加速这种发展——Prototyper用AI更快验证想法，Builder用AI减少样板代码，Sweeper用AI快速分析代码。但方向始终由人来判断：构建什么、简化什么、保留什么，这些判断至今仍属于人类领域。

5. 这个框架为何在当下重要

Boris Cherny的框架不只是角色分类，其背后有更大的问题：在AI工具瓦解职能边界的时代，组织如何理解和配置人才？

传统职称式组织以"后端工程师2人、产品经理1人"的职能方式构建团队。但当AI工具模糊这些边界，同是"工程师"也可能有完全不同的工作方式。这个框架为这种多样性提供了新语言。

对招聘而言，"我们现在需要的是具有Sweeper能量的人"这样的诊断，比"招募高级工程师"更能引导精准招聘。对团队诊断而言，明确"我们团队缺少Sweeper"，就能在复杂性债务积累之前提前应对。对职业规划而言，了解自己的原型，能更清楚地看到应该在什么样的团队和产品阶段中工作。

结论 — 用模式而非职称来认识自己

2026年，AI工具正在快速改变工作方式。在这一变化中，Boris Cherny的框架提供了一个实用视角：重要的不是你持有什么职称，而是以何种方式工作时你的能量最高。

五种原型之间没有高下之分。Maintainer并不比Prototyper次要。只是不同的产品阶段和团队情况需要不同的原型。重要的是认识到团队拥有哪些原型、缺少什么，以及自己在哪种原型中贡献最强。

AI工具提升了各原型的速度，但决定方向的判断力依然属于人类。Prototyper探索哪些想法、Builder构建什么和如何构建、Sweeper删减什么、Grower追随市场哪些信号、Maintainer接受哪些变化并稳定保持什么——这些判断，正是AI时代人类创造的价值。
