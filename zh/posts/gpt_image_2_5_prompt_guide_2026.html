1. 从自由生成转向约束保持的图像编辑范式变革

在视觉生成式人工智能技术的演进初期，核心焦点主要集中于纯粹的单次文本生成图像（Text-to-Image）能力。创作者通过堆叠描述词与艺术风格指定，引导模型在潜在空间中采样出单幅作品。然而，当这种生成范式被引入商业产品设计、UI布局原型设计、电商商品图制作等实际生产管线时，其固有的结构性局限立刻显现。生产实践所要求的并非任意变形，而是在维持已确认基准图像构图与人物身份特征的前提下，对局部服饰或单一背景要素进行精确替换与控制。

编辑指令改动了非预期区域的问题，在生产管线中构成了系统可靠性挑战。OpenAI的GPT Image 2.5提示词指南恰在此时提供了切实的技术指导。该指南指导在编辑指令中写明「change only X」并附上需要保留的细节清单。

原文指导在编辑时将单一变更目标与保留要素（身份特征、几何结构、排版布局、环境光照、标牌文字）拆解分述。原文同时指出，重复编辑可能会改变原本试图保留的细节（第7节）。顺便提及，原文指明gpt-image-1.5计划于2026年12月1日终止支持，gpt-image-1计划于2026年10月23日终止支持。

2. Flare与Sunburst的架构特性与模型选型准则

OpenAI在官方技术文档中明确界定了GPT Image 2.5体系下的两款核心衍生模型：gpt-image-2.5-flare与gpt-image-2.5-sunburst。二者共享完全一致的提示词语法与参数规范，但优化方向各异。

  • GPT Image 2.5 Flare: 原文描述其为「small model, optimized for speed, with image quality comparable to GPT Image 2」，指导开发者在日常快速、高质量生成任务中选用。
  • GPT Image 2.5 Sunburst: 原文描述其为「base model, optimized for quality, with higher image quality than GPT Image 2」，指导开发者在编辑精度最为核心的工作流中选用。

官方技术文档提出了具体的模型迁移与选型规则。若GPT Image 2已能满足质量要求，建议先从Flare开始以测试延迟改善；若在复杂场景中GPT Image 2无法达标，则建议从Sunburst开始。在初次对照测试中，应保持提示词、参考图、尺寸、导出格式以及显式选取的quality数值完全不变。

原文指出两款模型均支持图像生成、编辑以及透明背景输出。

4. 分辨率四大约束法则与像素算术边界

除了常规的预设画幅外，GPT Image 2.5 API全面允许开发者提交自定义矩形分辨率。原文以WIDTHxHEIGHT字符串形式接收自定义尺寸，并设定了以下条件：

  • 单边绝对极值: 两条边缘均不得超过3840像素。
  • 16像素整除模数: 宽度与高度必须均为16的倍数。
  • 长宽比限制: 必须介于1:3至3:1之间。
  • 总像素容量区间: 介于655,360至8,294,400之间。

5. 变更与约束的清晰解耦 — 标签分段提示词工程

针对复杂工业场景下的视觉指令组织，OpenAI官方文档指导采用带有显式标签的分段结构（labeled sections）。官方倡导的核心骨架由四大标签板块构成：场景（Scene）、主体（Subject）、细节（Details）、约束（Constraints）。

  • 明确命名主体与最终用途: 明确命名主体与预期用途，例如商品照片、广告宣传图或图表。
  • 描述可直接观测的细节: 避免模糊情绪词汇，直接描述材质、光照、色彩以及视觉媒介。
  • 准确引用所有需呈现的文字: 将必须呈现的文字置于引号内，并阐明其位置与字体样式。避免多余文字，并在输出中检查拼写与清晰度。
  • 独立隔离排除项与保护边界: 将排除事项（如不需要的文字、商标或水印）作为独立的约束条件分离开来。

[Scene]: A bright, modern Nordic kitchen counter with soft morning daylight entering from the left window.
[Subject]: A compact matte-black espresso coffee machine placed on a light oak wood surface.
[Details]: Brushed metal drip tray, visible steam wand texture, warm ambient reflections, shallow depth of field focusing on the portafilter.
[Text Requirement]: The word "AURA" engraved on the front panel in clean minimalist sans-serif capitals, rendered exactly once.

6. 生产级编辑工作流 — 保持清单的建立与严苛执行

在GPT Image 2.5的局部编辑功能模块（通过client.images.edit端点调用）中，官方文档总结出了一条核心语法定律：

Say "change only X" and list the details to preserve, such as identity, geometry, layout, lighting, or labels.

这一原则确立了专业编辑提示词的固定起手式：首先指明「仅更改X」，随后紧接着列出必须保留的细节清单。官方推荐的五大核心保持维度包含：

  • 身份特征（Identity）: 当主体涉及具体人物时，将面部特征、眼神、肤色质感及表情锁定为保留项。
  • 几何空间结构（Geometry）: 维持既有结构体、工业产品及器具的物理比例与外轮廓线条。
  • 全局排版布局（Layout）: 严格维持构图画面中的主体占位、镜头取景焦距以及各元素间的相对空间位置。
  • 环境光照物理（Lighting）: 确保新增要素与原画面中的主光源照射方向、色温以及阴影走势保持一致。
  • 标牌文字与图符（Labels）: 保护原图中的说明文字、品牌标识以及指示箭头等元素不被破坏。

对于精准的局部微调，还应进一步指明饱和度、对比度、指示箭头、镜头角度及周边物体的相对位置保持不变。在组合多个输入参考图时，需为每个输入图像分配数字编号及其特定职能角色（如主体、风格、服装或背景）。

[Task]: Edit the input image to change only the clothing of the subject.
[Change Target]: Replace the current gray knit sweater with the dark-navy waterproof trench coat provided in reference image 2.

7. 显式约束的代价与迭代成本 — 残留漂移与应对

尽管建立保留清单是确保编辑稳定性的有效路径，但在实际工程架构中，严密的约束同样伴随着技术代价与边界。

第一，约束增加的成本。据本文推想，罗列的保留项越多，提示词越冗长，可能掩盖核心变更指令。原文并未探讨该现象。

第二，反复编辑引发的漂移。原文指明「Repeated edits can still change details you intended to preserve」。官方文档在确认这一现象的同时，给出了明确的应对建议：

Restate critical constraints if the result drifts. If a region must remain pixel-identical, composite the approved edit into the original image instead of relying on prompting alone.

若在多轮编辑中结果出现偏离，必须重新强调关键约束。而若特定区域要求完全一致无任何像素差异，团队不应单纯依赖提示词，而应将审核通过的编辑区域直接蒙版拼贴回原始图像。

8. 验证程序 — 基于相同基准图的保持提示词对比评估

团队若欲在实际业务中考察保留清单提示词的实际效用，可通过A/B比对予以检验。推荐的对照验证步骤如下：

  1. 锁定标准基准测试素材库: 准备涵盖人像特写、图表、透明背景商品照以及海报在内的标准原图各一张，作为固定的对照基准。
  2. 执行对照组A（单纯变更指令）: 在相同模型与参数（size、quality）环境下，仅传入单纯修改要求（例如「将模特的夹克改为米色皮夹克」）发起编辑调用。
  3. 执行实验组B（保持清单结构化指令）: 在相同环境下，使用划分了标签区块与保留清单的提示词（例如「仅修改夹克为米色皮夹克，主体面部、发型、光照及背景严格与原图保持一致」）发起编辑调用。
  4. 按照四大视觉一致性维度打分:
    • 主体身份保真度: 对比修改前后人物五官特征的空间重合度与视觉一致性。
    • 环境抗扰度: 检查背景区域的纹理平滑度、光线投射角与景深是否产生偏移。
    • 接缝边缘伪影度: 审查修改构件与原始肌体交界处的像素边缘是否存在模糊羽化。
    • 非预期突变发生率: 统计画面中是否意外增生了未指定的装饰或异常色彩漂移。

本节流程系本文建议而非源自原文，且本文并未亲身执行该项比对。具体结论须在各自的具体图像与配置中加以检验。
