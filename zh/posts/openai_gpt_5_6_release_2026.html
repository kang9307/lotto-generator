OpenAI 正式发布 GPT-5.6 - Sol·Terra·Luna 三层变体战略解读

从政府审查到正式发布 - 分析已确认的规格、价格、变体战略与竞争格局

2026年7月10日 IT/技术

引言:为什么现在要关注 OpenAI GPT-5.6

2026年7月9日,OpenAI 正式发布了新一代模型 GPT-5.6。这次发布的特别之处在于,它不是单一模型,而是一次性推出了 Sol、Terra、Luna 三个变体。而且这些模型早在6月26日就经历了美国政府的安全审查,仅向少数机构限量开放,大约两周后审查解除,才转为面向大众的正式发布。模型越强大、政府越先介入审查这一流程本身,就足以说明 GPT-5.6 所处的时点氛围。

本文是笔者交叉核实 OpenAI 官方公告与多家媒体报道后整理的自主分析。由于发布时间尚短,不少规格和基准测试数据目前仍依赖 OpenAI 自身公开的资料,独立验证才刚刚开始。本文会区分已确认事实与厂商说法,并梳理变体战略的含义,以及这对一线开发者和中文读者意味着什么。(截至2026年7月)

1. GPT-5.6 是什么 - Sol·Terra·Luna 三层发布

1.1 从预览到正式发布

据 OpenAI 公告,GPT-5.6 系列于2026年6月26日首次以限量预览形式亮相。当时只有约20家可信合作机构可通过 API 和 Codex 访问,多家媒体报道称美国政府的安全审查充当了限制发布范围的关卡。约12天后的7月8日至9日,OpenAI 宣布解除政府限制,让 Sol、Terra、Luna 三个模型全部通过 API 与 ChatGPT 广泛开放,即正式发布(GA)。同一天,GitHub 官方更新日志也宣布三个模型已集成进 GitHub Copilot。

1.2 规格与价格摘要

据报道,三个模型都共享约 105万 Token 的上下文窗口与 最多12.8万 Token 的输出上限,知识截止日期为2026年2月16日。推理强度被细分为 none、low、medium、high、xhigh、max 六个等级,其中 max 推理强度以及所谓的 ultra 模式据报道仅 Sol 可以开启。价格方面,每百万 Token(输入/输出)Sol 为5美元/30美元,Terra 为2.5美元/15美元,Luna 为1美元/6美元。也就是说三个模型共享同样的上下文与输出上限,差异体现在推理强度、速度与成本上。

2. 相比上一代究竟变了什么 - 只谈已确认的事实

"比上一代更强"这种宣传语几乎每次发布都会出现。这里只挑出有据可查的变化。

2.1 成本效率 - Terra 的胜负手

最具体、最能确认的变化是成本。多家报道称,Terra 在保持与上一代 GPT-5.5 相当的性能的同时,价格约便宜一半。与其说这一代主打绝对性能的飞跃,不如说重点放在了以更低价格提供同等性能上。据报道,萨姆·奥特曼在接受 CNBC 采访时提到,新模型在智能体式编程任务中使用的 Token 减少了约54%,但这属于官方说法,目前尚未见独立复现验证。

2.2 Programmatic Tool Calling - Responses API 专属新功能

真正意义上的新功能是 Responses API 中的 Programmatic Tool Calling。据报道,模型现在可以自行编写并运行 JavaScript 代码来编排多个工具调用,支持循环和条件语句,可并行调用多个工具,并能把中间结果保留在托管运行环境中以过滤掉不必要的数据。但报道明确指出该功能不支持旧版 Chat Completions 接口,只能在 Responses API 中使用。对于需要编排大量工具的智能体开发者而言,这是实质性的变化;但对仍停留在 Chat Completions 的团队来说,不迁移就无法使用这项新功能。

2.3 基准测试说法与独立验证之间的差距

据 OpenAI 公布的自有基准测试,在评估55个领域长周期专业工作表现的 Agents' Last Exam 中,Sol 得分53.6,据称比 Claude Fable 5 高出13.1分。需要明确指出的是,这一数字目前来自 OpenAI 自己,尚未见独立机构复现验证。

3. 变体阵容战略的含义 - 为何不是一个而是三个

3.1 按用途分化的逻辑

在笔者看来,这次发布最值得玩味的不是规格表,而是拆分成三个模型这一决定本身。Sol 面向最难的问题,是唯一开放 max 推理强度与 ultra 模式的旗舰;Terra 定位日常工作的平衡点,事实上充当默认选项;Luna 则主打速度与成本优先的大批量、轻量级任务。这似乎释放出一个信号:竞争重心正从"打造一个最聪明的模型"转向"让用户按任务难度挑选模型"。

3.2 全行业在分层策略上的趋同

这种三层结构并不陌生。Anthropic 早就以 Opus、Sonnet、Haiku 运营类似的用途分化,谷歌则有 Pro、Flash。OpenAI 这次以 Sol、Terra、Luna 明确采用相同逻辑,可以理解为整个行业正在就"与其打造单一最强模型,不如用价格、速度、性能三个维度管理产品阵容"达成共识。在实务中,现在更重要的问题不再是哪个模型最强,而是该把哪个任务交给哪一层模型的路由设计问题。

4. 竞争格局 - 对比 Claude、Gemini 的中立视角

4.1 2026年7月初的局势

截至2026年7月初,竞争格局非常不稳定。Anthropic 于7月1日推出了新的 Claude Sonnet 5,同期因出口管制相关措施而一度暂停服务的 Claude Fable 5 也宣告回归,据报道重新夺回了自家智能指数排名第一的位置。据悉 Claude Opus 4.8 在 SWE-bench Pro 等编程基准测试中仍保持领先地位,谷歌 Gemini 3.5 Pro 则据报道凭借超大上下文窗口进入企业级预览阶段。在这样的格局下,GPT-5.6 与其说是宣称"绝对第一",不如说更多是以成本效率和自有智能体基准测试上的优势作为主要卖点。

4.2 基准测试与实际体验之间的差距

这里需要一个平衡的视角。知名独立评测者 Simon Willison 分享了早期使用 Sol 的感受:确实是一款能力不俗的模型,但在他一直用 Claude Fable 5 处理的复杂编程任务中,尚未给他留下明显优于 Fable 5 的印象。也就是说,OpenAI 所强调的基准测试优势,与用户实际感受到的优势之间,可能仍存在差距。与其把单一基准测试的分差当作绝对优劣的定论,不如等更多独立评测和自己工作负载上的直接对比出现后再下判断,这样更为稳妥。

5. 一线开发者视角 - 该把什么用在哪里

5.1 给 API、智能体开发者的实务建议

眼下可以立刻落地的是路由策略。将难度高、预算充裕的任务(复杂架构设计、高难度调试)交给开启 max 推理强度的 Sol,日常的代码生成、评审、文档工作交给 Terra,分类、摘要、聊天机器人回复等大批量、低延迟优先的任务交给 Luna,这种三层路由方案比较合理。不过要提前确认,像 Programmatic Tool Calling 这样的新功能需要迁移到 Responses API 才能使用——如果你的管线还停留在 Chat Completions,这项功能暂时用不上。

5.2 GitHub Copilot 集成的意义

三个模型在发布当天就集成进 GitHub Copilot,这一点在实务上也很重要。不需要单独签订 API 合约或做迁移,已经在用 Copilot 的开发者可以直接在 IDE 中来回切换三个模型,对比实际体验。这等于提前打通了一条成本最低的路径:在决定是否采用新模型之前,先用内部的黄金测试集做验证。

6. 对中文用户意味着什么

GPT-5.6 的限量预览与政府审查话题在国际媒体上获得了大量报道,可见开发者与企业对此已经高度关注。不过截至本文撰写时,尚未确认针对中文用户群体的具体开放顺序或本地资费政策的官方公告。参考以往新模型发布的模式,通常会先向 ChatGPT Plus、Pro 订阅用户开放,再逐步扩展到 Free、Go 等级别,初期阶段价格往往维持不变。对预算敏感的创业团队和中小开发团队而言,Terra 价格较上一代降低约一半这一点,可能是最直接、最能感受到的成本节省。如果业务需要大量调用 API,Luna 的低成本结构也值得一并评估。

7. 局限性与警惕夸大宣传

有几点局限需要明确指出。第一,Agents' Last Exam 等核心基准测试数字目前仍依赖 OpenAI 自身发布,后续需要独立验证。第二,奥特曼提到的 Token 效率提升幅度等数字也属于官方说法,需要谨慎看待。第三,通过政府安全审查这一事实本身并不能证明模型绝对优秀,反而更准确的理解是:这恰恰说明高风险用途、网络安全滥用等方面的担忧同样不小。第四,变体名称(Sol、Terra、Luna)及其角色划分虽已通过 OpenAI 官方公告与媒体报道交叉确认,但实际性能排序目前仍处于发布初期的厂商说法阶段,在用自己的实际任务验证之前,不宜当作定论接受。

8. 结论 - 本周可以做的三件事

GPT-5.6 并非只是一个更聪明的模型,而是一次性推出了按难度分层的三个模型、成本效率提升,以及用于工具编排的新 API 功能的综合发布。从政府审查到正式发布这一过程本身表明,截至2026年,前沿模型的部署已经不只是技术问题,而是与政策、安全议题紧密交织在一起。

本周值得做的三件事:第一,按难度拆分自己的工作负载,估算 Sol、Terra、Luna 三层路由能节省多少成本。第二,如果计划迁移到 Responses API,检查现有的编排代码中是否有可以用 Programmatic Tool Calling 替代的部分。第三,不要照单全收 OpenAI 的基准测试说法,用自己任务构建的黄金测试集,直接与 Claude、Gemini 做对比。
