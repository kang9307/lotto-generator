引言 - 替换字符串是与模式不同的另一套语法

正则模式的可移植性常被讨论，但替换字符串（replacement）是与模式分开的另一套语法，特殊写法因工具而异。同一个 & 在 sed 中表示匹配到的整段文本，在 Python、JS 和 PowerShell 中只是普通的 & 符号。同一个 $1 在 perl、JS 和 PowerShell 中是分组 1，在 sed 和 Python 中则是字面的 $1。

问题出在两处。一处是把别的工具的写法直接搬过来：可能没有任何报错却悄悄得到错误结果，也可能因报错而停止。另一处是把变量的值直接放进替换位置：值里的 $、\、& 被当成特殊写法，值就被改变。前一个问题靠一张写法对照表即可理清，后一个问题通过把替换部分作为函数而不是字符串来解决。

  • 对象是三个 shell 工具 sed（GNU sed 4.9）、awk（GNU Awk 5.0.0）、perl 5.38.2，以及 Python 3.13.3 的 re.sub。
  • 另外两个是 node v22.16.0 的 String.replace 和 Windows PowerShell 5.1 的 -replace。
  • 输入都是简短的固定字符串，意图相同：重用整体匹配、交换分组、放入字面量值。
  • 模式一侧的方言由正则可移植性文章讲述，sed 的 & 与分隔符冲突由 sed 文章讲述，因此这里集中于工具之间的对照和值的放入方法。
  • 输出连同错误信息都是原样粘贴的；用 Python 的 repr 和 JS 的 JSON 形式打印的行，其引号也属于输出。

整体匹配的引用 - &、$&、\g<0>

在替换字符串中重新使用整段匹配文本的写法因工具而异。下面把 Tom 变成 [Tom] 的同一意图交给三个 shell 工具。

echo 'Tom' | sed 's/Tom/[&]/'
                    echo 'Tom' | sed 's/Tom/[\0]/'
                    echo 'Tom' | awk '{ sub(/Tom/, "[&]"); print }'
                    echo 'Tom' | awk '{ print gensub(/Tom/, "[\\0]", "g") }'
                    echo 'Tom' | perl -pe 's/Tom/[$&]/'
                    echo 'Tom' | perl -pe 's/Tom/[&]/'
[Tom]
                    [Tom]
                    [Tom]
                    [Tom]
                    [Tom]
                    [&]

sed 的 & 和 \0、awk 中 sub 的 & 和 gensub 的 \\0、perl 的 $& 都指向整体匹配。如最后一行所示，perl 中的 & 是字面的 & 符号。以 sed 的预期在 perl 里用 &，替换会发生，但整体匹配不会被放入。

import re
                    print(repr(re.sub('Tom', '[&]', 'Tom')))
                    print(repr(re.sub('Tom', r'[\g<0>]', 'Tom')))
                    print(repr(re.sub('Tom', r'[\0]', 'Tom')))
'[&]'
                    '[Tom]'
                    '[\x00]'

在 Python 中 & 是字面量，整体匹配是 \g<0>。\0 没有得到整体匹配，而是变成了 NUL 字符（\x00）。Python 文档写明 repl 字符串中的反斜杠转义会被处理，并把 \g<0> 列为代入整段匹配子串的引用。

                    console.log(JSON.stringify('Tom'.replace(/Tom/, '[$0]')));

                    "[Tom]"
                    "[$0]"
'Tom' -replace 'Tom','[&]'
                    'Tom' -replace 'Tom','[$&]'
                    'Tom' -replace 'Tom','[$0]'
[&]
                    [Tom]
                    [Tom]

在 JS 和 PowerShell 中整体匹配是 $&。MDN 的表把 $& 写作「Inserts the matched substring.」，Microsoft Learn 把 $& 列为放入整体匹配副本的替换。区别出现在 $0：JS 不把 $0 当作特殊写法，按字面返回；PowerShell 5.1 则把 $0 读成整体匹配。

  • 在这些输出中，& 表示整体匹配的工具是 sed 和 awk。
  • $& 在 perl、JS、PowerShell 中含义相同。
  • \0 在 sed 中是整体匹配，在 Python 中是 NUL 字符。
  • $0 在 PowerShell 中是整体匹配，在 JS 中是字面量。

分组引用 - \1 系列与 $1 系列

引用括号分组的写法分成两个系列。sed、awk（gensub）、Python 属于反斜杠系列（\1），perl、JS、PowerShell 属于美元系列（$1）。把两种写法互换会怎样，用把 ab 变成 ba 的替换来看。

echo 'ab' | sed -E 's/(a)(b)/\2\1/'
                    echo 'ab' | sed -E 's/(a)(b)/$2$1/'
                    echo 'ab' | awk '{ print gensub(/(a)(b)/, "\\2\\1", "g") }'
                    echo 'ab' | awk '{ sub(/(a)(b)/, "\\2\\1"); print }'
                    echo 'ab' | perl -pe 's/(a)(b)/$2$1/'
                    echo 'ab' | perl -pe 's/(a)(b)/\2\1/'
ba
                    $2$1
                    ba
                    \2\1
                    ba
                    ba

第一行 sed 的 \2\1 得到 ba，第二行的 $2$1 没有被当作分组而是按字面输出。awk 中只有 gensub 能引用分组；把同样的 \\2\\1 放进 sub，输出仍是 \2\1。perl 中 $2$1 得到 ba， \2\1 也得到了 ba。

import re
                    print(repr(re.sub(r'(a)(b)', r'\2\1', 'ab')))
                    print(repr(re.sub(r'(a)(b)', '$2$1', 'ab')))
                    print(repr(re.sub(r'(a)(b)', r'\g<2>\g<1>', 'ab')))
'ba'
                    '$2$1'
                    'ba'

在 Python 中，\2\1 与 \g<2>\g<1> 结果相同，$2$1 保持字面。在美元系列工具中则相反。

console.log(JSON.stringify('ab'.replace(/(a)(b)/, '$2$1')));
                    console.log(JSON.stringify('ab'.replace(/(a)(b)/, '\\2\\1')));
"ba"
                    "\\2\\1"
'ab' -replace '(a)(b)','$2$1'
                    'ab' -replace '(a)(b)','\2\1'
ba
                    \2\1

在 JS 和 PowerShell 中，$2$1 是分组引用，\2\1 按字面输出。JS 输出中的 "\\2\\1" 是 JSON 转义，实际字符是 \2\1。把反斜杠系列的写法带进美元系列工具，不会报错而是得到字面量，错误结果悄悄通过。

分组编号后面接数字时

把 a 变成 a0，也就是在分组 1 的值后面追加字面量 0，各工具的区别在于编号后面的数字是否被当作编号的一部分。

echo 'a' | sed -E 's/(a)/\10/'
                    echo 'a' | awk '{ print gensub(/(a)/, "\\10", "g") }'
                    echo 'a' | perl -pe 's/(a)/${1}0/'
                    echo 'a' | perl -pe 's/(a)/[$10]/'
a0
                    a0

sed 和 awk 把 \10 读成分组 1 后面的 0。perl 写成 ${1}0 得到 a0，而 $10 使方括号内成为空字符串。

import re
                    try:
                        print(repr(re.sub(r'(a)', r'\10', 'a')))
                    except re.error as e:
                        print(type(e).__name__ + ': ' + str(e))
                    print(repr(re.sub(r'(a)', r'\g<1>0', 'a')))
                    print(repr(re.sub(r'(?P<x>a)', r'\g<x>0', 'a')))

Python 文档写明 \g<2> 与 \2 等价，但在 \g<2>0 中没有歧义，并写明 \20 会被解释为对分组 20 的引用。输出中的 PatternError 是分组 10 不存在的提示。因报错而停下好过悄悄出错。

在只有一个分组的模式下，JS 把 $10 读成分组 1 后面加 0，得到 a0。MDN 把 $n 写作 n 为小于 100 的正整数时的第 n 个分组，并写明分组不存在时按字面替换；最后一行的 $2 就是那个字面量。PowerShell 把 $10 按字面保留。Microsoft Learn 写明 $ 后面的数字都属于编号，该编号的分组不存在时是字面量，并给出 ${1}1 的形式作为替代。

含有字面量 $ 的值被破坏的位置

把变量的值直接放进替换字符串的代码，一旦值里有特殊写法就会出错。价格字符串 $5.00 是典型例子。模式没有分组时 $5 是字面量，结果碰巧正确；有 5 个分组时结果就变了。下面在 JS 中放入六种值，最后一行把 $5.00 放进有 5 个分组的模式。

for (const v of ['A&B', '$5.00', 'C:\\dir', 'US$', '$$', '$&$&']) {
                      console.log(v.padEnd(8) + JSON.stringify('x=OLD'.replace('OLD', v)));
                    }
                    console.log(JSON.stringify('abcde'.replace(/(a)(b)(c)(d)(e)/, '$5.00')));

                    $5.00   "x=$5.00"

                    $&$&    "x=OLDOLD"
                    "e.00"

前几行中，$5.00 和 US$ 保持原样，$$ 缩成一个 $，$&$& 变成 OLDOLD。这是值被读成替换写法的结果。最后一行是在 5 个分组的模式下 $5.00 变成 e.00。MDN 的表把 $$ 写作插入一个 "$"。

                      $v.PadRight(8) + ('x=OLD' -replace 'OLD',$v)

                    $5.00

PowerShell 5.1 的结果相同。写成 $$5.00 就会放入字面的 $5.00。Microsoft Learn 把 $$ 写作放入单个字面 "$" 的写法。

在 perl 源码里写 s/OLD/$5.00/，即使模式没有分组，$5.00 也会变成 .00。这是 perl 把源码中的 $5 当作变量插值的结果，而不是值被读成了替换表记。该输出见下一节。

  • 值里有 $ 且模式有分组时，JS 和 PowerShell 会把值的一部分换成分组。
  • $$ 是替换写法而不是值，所以缩成一个 $。
  • 像 $&$& 这样形状与写法相同的值会展开为整体匹配。
  • 在没有分组的模式下碰巧正确，模式一变就会出错。

路径 C:\dir 和 A&B 也用同样的方式放入。下面是 sed、awk、perl 把 x=OLD 中的 OLD 换成各个值的输出。perl 的最后一行是 A@B。每一行的值都是直接写在脚本源码里的。

把值作为函数而不是字符串传入

不让值被当作替换字符串解释的办法，是把替换部分作为函数的返回值而不是字符串传入。测试值包含各种写法：C:\dir\1 & $1 \n。先看 Python。

import re
                    v = r'C:\dir\1 & $1 \n'
                    print('v = ' + v)
                    try:
                        print(re.sub('OLD', v, 'x=OLD'))
                    except re.error as e:
                        print(type(e).__name__ + ': ' + str(e))
                    print(re.sub('OLD', lambda m: v, 'x=OLD'))
                    print(re.sub('OLD', v.replace('\\', '\\\\'), 'x=OLD'))
                    print('x=OLD'.replace('OLD', v))
                    print(re.sub(r'(a)(b)', lambda m: m[2] + m[1], 'ab'))
v = C:\dir\1 & $1 \n
                    PatternError: bad escape \d at position 2
                    x=C:\dir\1 & $1 \n
                    x=C:\dir\1 & $1 \n
                    x=C:\dir\1 & $1 \n
                    ba

作为字符串传入会引发 PatternError，作为 lambda m: v 传入则值原样放入。把反斜杠写成两个的做法和 str.replace 得到同样的值。Python 文档写明当 repl 是函数时，对每个不重叠的匹配调用它，并返回替换字符串。最后一行是在函数内取出分组并交换。

const v = 'C:\\dir $1 $& $$ \\1';

                    console.log('x=OLD'.replace('OLD', v));
                    console.log('x=OLD'.replace('OLD', () => v));
                    console.log('x=OLD'.replace('OLD', v.replaceAll('$', '$$$$')));
                    console.log('x=OLD'.split('OLD').join(v));
                    console.log('ab'.replace(/(a)(b)/, (m, p1, p2) => p2 + p1));
v = C:\dir $1 $& $$ \1
                    x=C:\dir $1 OLD $ \1
                    x=C:\dir $1 $& $$ \1
                    x=C:\dir $1 $& $$ \1
                    x=C:\dir $1 $& $$ \1

在 JS 中，字符串替换会解释 $1、$&、$$。作为函数传入时全部保持原样。MDN 写道：「The above-mentioned special replacement patterns do not apply for strings returned from the replacer function.」把值里的每个 $ 写成 $$$$ 的做法和 split/join 也都原样放入。

                    'v = ' + $v

在 PowerShell 5.1 中，-replace 的替换是字符串。把 MatchEvaluator 传给 [regex]::Replace，或使用非正则的 .Replace() 方法，值都原样放入。如最后一行所示，给 -replace 传脚本块时，5.1 并不把它当函数调用，而是放入了带前后空格的块文本。

  • Python 用 lambda m: v、JS 用 () => v 返回值，就不会发生解释。
  • PowerShell 使用 MatchEvaluator 或 .Replace() 字符串方法。
  • 不需要正则时，str.replace、split/join 和 .Replace() 最简单。
  • 如果必须直接给 -replace 传值，可以把 $ 换成 $$；5.1 中的脚本块不是函数。

工具之外的层 - shell 引用与 awk -v

值到达工具之前，shell 和工具自身的引用层会再改变它一次。awk 的 -v 选项就是例子。下面用 tr 把 TAB 换成 > 以便看见。

echo 'x=OLD' | awk -v v='a\tb' '{ sub(/OLD/, v); print }' | tr '\t' '>'
                    V='a\tb' awk 'BEGIN { print ENVIRON["V"] }'
x=a>b
                    a\tb

用 -v v='a\tb' 传入的值被 awk 处理了转义，变成 TAB（x=a>b）。通过环境变量传入并用 ENVIRON 读取的值，a\tb 保持字面。这个区别由输出直接显示。

'[' + ('ab' -replace '(a)(b)','$2$1') + ']'
                    '[' + ('ab' -replace '(a)(b)',"$2$1") + ']'
[ba]
                    []

在 PowerShell 中，引号的种类构成一个层。同一个替换字符串用单引号写就是分组引用，用双引号写则 PowerShell 先把 $2 和 $1 当作变量展开，结果是空字符串。输出的第二行 [] 就是这个结果。

安全放入的方法 - 各工具的选择表

sed 先对值里的 &、\、分隔符做转义再放入。awk 用 index 和 substr 拼接，或用 ENVIRON 接收值，perl 从环境变量读取值。值是 A&B\C/D。

V='A&B\C/D'
                    ESC=$(printf '%s' "$V" | sed 's/[&\/\\]/\\&/g')
                    echo "ESC=$ESC"
                    echo 'x=OLD' | sed "s/OLD/$ESC/"
                    echo 'x=OLD' | V="$V" awk '{ i = index($0, "OLD"); print substr($0, 1, i-1) ENVIRON["V"] substr($0, i+3) }'
                    echo 'x=OLD' | V="$V" awk '{ sub(/OLD/, ENVIRON["V"]); print }'
                    echo 'x=OLD' | V="$V" perl -pe 's/OLD/$ENV{V}/'
ESC=A\&B\\C\/D
                    x=A&B\C/D
                    x=A&B\C/D
                    x=AOLDB\C/D
                    x=A&B\C/D

sed 的转换生成 A\&B\\C\/D，替换结果就是值本身。awk 用 index 和 substr 的方式得到原值，把同一个值放进 sub 则 & 展开成 OLD，得到 AOLDB\C/D。perl 通过 $ENV{V} 读取的值原样放入。各工具的选择见表。
