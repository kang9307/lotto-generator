GitFut - Turning Your GitHub Stats Into a FIFA Player Card

Your Commits, Rated Out of 99 - Unpacking Developer-Metric Gamification

Jul 17, 2026 Trends & Culture

Intro: Why Developers Suddenly Turned Into Football Players

A strange image has been making the rounds on developer timelines lately: six attribute bars, a flag, a position label, and a card tier ranging from Bronze to Icon. Look closer and a GitHub handle sits where a player's name would go, and an overall rating sits where a club crest would be. The tool stamping out these cards is GitFut.

GitFut reads a user's GitHub activity and reformats it as a World-Cup-style Ultimate Team (FUT) player card. It is not a resume, not a performance report - it is a game card, and that unusual choice of format is exactly what makes the tool worth unpacking. This post sticks to verified facts about what GitFut actually does, then digs into why this kind of gamification lands so well with developers, and where the fun quietly runs into limits.

1. What Is GitFut? Turning GitHub Stats Into a FIFA Card

GitFut is a web tool built by developer Younes Fdj on Next.js, TypeScript, Tailwind, and Redis. The key detail is that it does not rely on self-reported input - it reads profile data live from the GitHub GraphQL API. Your card is not something you fill out yourself; it reflects your actual public commit, PR, and star history.

1.1 Six Metrics, Mapped to Football Attributes

GitFut maps GitHub activity onto six football attributes. The confirmed mapping is: Pace comes from commits over the last year, Shooting from stars earned across repositories, Passing from pull request activity plus follower count, Dribbling from language diversity, Defending from reviews and issue activity, and Physical from lifetime cumulative contributions. Anyone who has ever touched a football video game recognizes this six-slot stat radar instantly - it has simply been repurposed for developer activity.

1.2 The Rating System - 0 to 99, but the Real Ceiling Is 88

Every card carries an overall rating between 0 and 99. But per GitFut's own description, raw stats are capped at 88. The 90s are treated as a separate "legacy gate" - a tier that a single burst of activity in one year cannot reach; it only opens up through sustained years of consistency and influence. The design deliberately blocks a short activity spike from buying you an Icon-tier card, borrowing the same scarcity mechanism real FIFA Ultimate Team uses to keep legendary cards rare.

1.3 Position, Archetype, Card Tier, and Flag

GitFut also auto-assigns a position and playstyle (archetype) based on the shape of your six stats - a pronounced Shooting spike reads as a poacher-style striker, while strong Defending and Passing reads as a deep-lying playmaker. The card itself is rendered across six visual tiers - Bronze, Silver, Gold, In-Form, TOTY, and Icon - and country defaults to your profile info but can be overridden via a URL parameter. Crucially, a card is not a static image but a living URL: embed it in a README or portfolio and your stats refresh automatically as your GitHub activity changes.

2. Why the FIFA Card Metaphor Works So Well

There are countless ways to visualize technical activity. So why did a football player card specifically catch on and get shared this widely? I think it comes down to three things.

2.1 Intuition Compressed Into Six Bars

A raw dashboard or GitHub's own insights page is just numbers and charts laid out flat - it does not read itself. Pace, Shooting, Passing, Dribbling, Defending, and Physical, on the other hand, are instantly legible to anyone with even passing familiarity with football. Compressing a messy activity history into six bars and a single overall number is exactly what makes a card readable at a glance.

2.2 A Collection Instinct Built on Scarcity

The Bronze-to-Icon tier ladder, and capping raw stats at 88 while framing the 90s as a door opened only by years and influence, is not an accident. Just like real FIFA Ultimate Team, you need an upper tier that is genuinely hard to reach if you want people to keep checking their score and coming back next year to refresh their card. On the hada.io discussion thread, users compared their percentile rankings (figures like 0.03% and 0.01%) - exactly the kind of reaction this design seems built to provoke.

2.3 A Format Built to Be Shared

A GitFut card exists as a single image URL. It is easy to screenshot into a post on X or Threads, and pasting it into a GitHub profile README means every visitor sees a freshly updated card. A character-styled card is simply more eye-catching than a text summary or a table, and "check out my card" pulls far more clicks than "check out my commit log." This is a format engineered from the start to spread.

3. The Lineage - From README Badges to 3D Skylines

GitFut did not appear out of nowhere. Repackaging GitHub activity into something visual and shareable has a fairly long history.

3.1 github-readme-stats - The Original README Badge

github-readme-stats, built by Anurag Hazra, is an open-source project that dynamically renders stats like stars, commits, and PRs into a GitHub profile README. It supports several card types - a stats card, a top-languages card, a repo card, a streak card - and still tops countless developer profile pages today. Much of the raw material GitFut works with (commits, stars, PRs, reviews) is already treated as standard signal in this same lineage.

3.2 GitHub Skyline - Turning the Grass Into a 3D City

GitHub's own official gh-skyline CLI extension converts a year's contribution graph into a 3D skyline model. Weeks with more commits become taller buildings, and the model exports as an STL file you can 3D print. It turns what was once a flat list of numbers into a viewable, printable cityscape - "something you can put on display" for a year of activity - which shares its core aim with GitFut.

3.3 Wrapped-Style Tools - Borrowing Spotify's Grammar

Inspired by the annual buzz around Spotify Wrapped, a family of "GitHub Wrapped" tools has appeared, summarizing a year of activity: your most active day of the week, your top languages, your commit streaks, sometimes even a "developer persona." GitFut and these Wrapped-style tools target the same psychology: reviewing a year of your own data yourself is tedious, but if someone packages and summarizes it into something pretty, you will happily check it out and share it.

3.4 Why Developer-Identity Content Is Having a Moment

Behind this trend is a culture where developer careers are increasingly proven in public. Hiring practices now often check a GitHub profile or portfolio site before a resume line ever gets read; sharing dev updates on X, Threads, or LinkedIn has become normal; and open-source contributions themselves double as a career record. Together, these create a steady appetite for "content that compresses my dev activity into something I can show." GitFut is simply the latest entry to put a fresh FIFA-card format on top of that appetite.

4. What GitFut's Metrics Actually Measure - and How to Read Them

From here on, this is my own reading built on GitFut's stated mapping - what each attribute is metaphorically standing in for, and where that metaphor holds up or breaks down.

4.1 Pace (Recent Commits) - A Proxy for Diligence?

Mapping last-year commit count to Pace reads as an attempt to show "how often you moved." Commit frequency does give some sense of consistent activity, but the size and significance of any given commit varies wildly. A typo fix and a gnarly bug fix both count as exactly one commit - a clear limit of this metric.

4.2 Passing (PRs + Followers) - A Metaphor for Collaboration

Mapping PRs and follower count to Passing is a clever idea. Just as a pass moves the ball to a teammate, a PR "delivers" a contribution into someone else's codebase, and follower count reflects how far that delivery reached. But follower count is often driven more by networking or an occasional viral moment than by skill, which adds a lot of noise if you try to read it as collaboration ability.

4.3 Shooting (Stars) - Influence, or a Popularity Contest

Mapping star count to Shooting (scoring power) tries to capture reach. A well-starred repo probably is widely used or was talked about at some point. But stars also get clicked regardless of actual usage, and one well-timed trending repo can outweigh a lifetime of commits in total star count. It is worth remembering this is closer to a popularity contest than a precision instrument.

4.4 Defending, Dribbling, and Physical - the Remaining Three

Mapping Defending to reviews and issue activity is also a reasonable metaphor - code review protects a team's quality much like defending protects a goal, and responding to issues heads off bigger problems. Dribbling maps to language diversity, symbolizing versatility. Physical maps to lifetime cumulative contributions, symbolizing staying power. In one line: these are fun metaphors, not precise skill measurements.

5. What the Fun Doesn't Show - Activity Is Not Skill

Enjoying GitFut and treating its score as proof of skill are two very different things. This section covers a warning that gamified developer tools in general have long carried.

5.1 Activity Is a Proxy for Skill, Not Skill Itself

The software engineering field has long flagged metrics like commit count, lines of code, and PR count as vanity metrics - numbers that look impressive but don't map cleanly to value. Five hundred lines of clean, well-considered code can deliver more value than two thousand lines of sprawling code, and commit counts are trivially inflated by splitting work into smaller pieces. GitFut's six stats ultimately belong to this same family. There is a real line between enjoying a card and treating it as proof of ability.

5.2 A Fundamental Limit - These Metrics Can Be Gamed

Research on engineering organizations tends to point toward multidimensional alternatives such as the SPACE framework (Satisfaction, Performance, Activity, Communication, Efficiency) or DORA metrics (deployment frequency, lead time, change failure rate, recovery time), which weigh outcomes and team context rather than raw activity counts. GitFut's fun comes precisely from boiling everything down to six numbers - but that same simplification erases the parts that don't reduce to numbers well: code quality, design judgment, and quieter contributions to a team.

5.3 The Comparison Trap and Burnout

As the hada.io comments show, once people hold a card like this, comparing scores and percentiles becomes almost automatic. This is a shadow shared by every "summarize and show me" tool, whether it's Spotify Wrapped, GitHub Wrapped, or GitFut. A developer who mostly works on private, closed-source repos at a day job will score low here regardless of actual skill. And if chasing a higher card score starts driving people to split commits meaninglessly or beg for stars, the fun has already curdled into stress.

6. How to Enjoy It Without Falling Into the Trap

To be clear, GitFut is not a bad tool - if anything, it was built with a fair amount of honesty. It reads real GitHub API data instead of self-reported input, it caps raw scores at 88 to resist a short burst inflating your tier, and explicitly framing the 90s as a "years-earned" zone suggests its creator was already aware of gamification's usual traps. My advice is simple: treat it as a fun snapshot of your year, drop it in a README and smile about it, but never use the score as evidence in a hiring decision, a performance review, or your own sense of how skilled you are. A low overall does not mean you're a weak engineer, and a high one does not mean you're a great one. It just compressed a year of GitHub activity into something entertaining to look at.

Conclusion

GitFut stands out among developer-activity gamification tools for how cleanly its metaphor lands. It is grounded in real GitHub data, its scarcity design taps directly into the urge to share, and it sits on a lineage that runs through github-readme-stats, GitHub Skyline, and GitHub-Wrapped-style tools building developer-identity content. But fun and proof-of-skill are different things. That activity metrics like commits, PRs, and stars fail to represent code quality or real ability is a point the industry has made repeatedly. As of July 2026, tools in this gamification genre are likely to keep multiplying. Enjoy them - just don't let a single number swing your mood.
