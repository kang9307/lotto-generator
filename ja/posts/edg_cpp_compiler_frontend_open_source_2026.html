背景 — 数十年にわたり非公開だったコンパイラ基盤の公開

C++言語は構文が極めて複雑であり、テンプレートメタプログラミング、精緻な型推論、文脈依存の構文規則が存在するため、ゼロから完全なパーサーとフロントエンドを構築することは困難を極める。そのため、多くのツールベンダーや組み込み向け開発企業は、自社でフロントエンドを独自開発する代わりに、実績のある商用フロントエンドエンジンをライセンス導入してきた。その代表例がEdison Design Group（EDG）のC/C++フロントエンドである。

EDGは長年にわたり商用ライセンスのみでソフトウェアを提供してきた。独自のソースコード管理と年間契約を前提としていたため、一般の開発者がその内部実装を検証したり直接改修したりすることは不可能であった。しかし2026年9月30日、EDGのJohn Spicerは公式声明を通じて、EDG C/C++フロントエンドの全ソースコードをGitHub上でオープンソースとして無償公開すると発表した。同時にEDG法人は営利活動を終了し、プロジェクトの継続的な維持・運営を非営利団体The C++ Allianceへ移管することを宣言した。

この出来事はC++コミュニティにとって重要な転換点となる。かつて商用独占技術の象徴であったパーサーエンジンがLLVMライセンスで利用可能になったことで、独自のコード解析器、ソース間変換ツール、LSPサーバーなどを開発するエンジニアにとってClangに並ぶ強力な選択肢が誕生したためである。本稿では公開されたコードの範囲、ライセンス形態、運営体制、および実務的な論点を整理する。

フロントエンドの本質 — 構文解析・型検査と中間表現の生成

コンパイラ工学における「フロントエンド」とは、UI画面を指すものではない。ソースコードの文字列を読み込み、字句解析、構文解析、名前解決、型検査、テンプレート実体化を経て意味的エラーを検証し、抽象構文木（AST）や中間言語（Intermediate Language, IL）へと変換する一連の前段処理エンジンを意味する。

公式資料に記載されたフロントエンドの役割は以下の通り規定されている。

  • 意味解析の独立性: 特定のCPUアーキテクチャの機械語生成に依存せず、ソースコードの文法および意味的な正当性を検証して中間言語を構築することに特化する。
  • バックエンドとの明確な分離: 中間表現を受け取ってレジスタ割り当てや最適化を行い、機械語バイナリを出力する後段のバックエンドと厳密に分離されている。
  • 開発支援ツールの基盤: 完全なコンパイラだけでなく、コード構造を深く理解する必要があるIDE、リファクタリング支援ツール、静的セキュリティ解析器などの頭脳として機能する。
  • 厳密な言語標準適合性: 複雑なISO C++仕様の難解なエッジケースを忠実に実装し、構文解釈のあいまいさを排除する高い信頼性を提供する。

公式発表で確認された代表的な採用例として、Microsoft Visual StudioのC++ IntelliSenseにおけるリアルタイム構文解析エンジンや、VeracodeによるC++セキュリティ脆弱性の静的解析基盤が挙げられる。長年にわたり最も過酷な実環境コードを支えてきた技術がオープンソース化されたことになる。

公開リポジトリの構成範囲 — フロントエンドと変換バックエンド

コンパイラのオープンソース化と聞くと即座に実行バイナリを出力できる完成品を連想しがちだが、GitHub（github.com/edgcpp/compiler）に公開されたコードベースには明確な境界が存在する。READMEに記載された構成要素は以下の通りである。

  • EDG C/C++フロントエンド中核部: 最新C++規格の構文および型を網羅的に解析し、中間言語（IL）を生成するパーサー本体。
  • C言語生成バックエンド（C-generating back end）: C++プログラムを標準Cコードへ変換して出力するトランスパイラ。ネイティブC++コンパイラが存在しない組み込み環境等で利用される。
  • C++再生成バックエンド（C++-generating back end）: 中間表現から再構成されたC++コードを出力するバックエンド。リファクタリングやコード変換ツールの構築に利用される。
  • 自動テンプレート実体化プリリンカー（Prelinker）: 分割コンパイル環境下でのテンプレート実体化の重複を防ぎ、リンクを調整するユーティリティ。
  • 中間言語（IL）診断ツールおよび名前復元器（Demangler）: 中間言語のファイル保存・読み込み・テキスト表示を行うツール群、およびマングルされたシンボルを復元するデマングラー。

一方で、含まれていない要素についても明記されている。x86やARMなどの機械語を直接出力するターゲット固有のバックエンドは含まれず、標準I/Oストリームなどの完全なC++標準ライブラリを除外した最小限のランタイム支援ライブラリのみが同梱される。つまり、本作はバイナリコンパイラそのものではなく、解析器や変換器を構築するための高精度フロントエンド基盤である。

# EDGフロントエンドによる構文解析と中間言語（IL）ファイルの出力例
                    edgcpfe --c++20 --dump-il my_program.cpp -o my_program.il
                    
                    # C++コードを標準Cコードへ変換出力するコマンド例
                    edgcpfe --gen-c my_program.cpp -o transformed_program.c

ライセンスと組織移行 — LLVMライセンスとThe C++ Alliance

オープンソース化において最も重要な法的要件は適用ライセンスである。本プロジェクトにはLLVMライセンス（Apache License v2.0 with LLVM Exceptions）が適用された。これは現代のコンパイラ基盤において標準的なパーミッシブ（寛容）ライセンスである。

このライセンスの採用は商用ツールベンダーに大きな利点をもたらす。GPLのようなコピーレフト条項とは異なり、EDGのソースコードを商用製品（クローズドソースのIDE、独自セキュリティツール、特殊ハードウェア用コンパイラ）に組み込んだ場合でも、製品全体のソースコード公開義務が生じない。さらにLLVM例外条項により、コンパイラが出力した中間コードや生成物にライセンス制約が伝播しない。

同時に、運営体制についても大きな移行が行われた。

  • 営利法人の終了: Edison Design Group法人はソフトウェアのライセンス販売事業を終了した。
  • The C++ Allianceへの移管: 非営利組織であるThe C++ Allianceが公式なホスティング先および財政支援組織（Fiscal Sponsor）となった。同団体は2024年よりBoost C++ Librariesの財政支援を担っており、エンジニアと資金管理の体制を整えている。
  • 開発の継続性確保: 企業としてのEDGは終了するが、長年開発に携わってきた中心技術者がC++ Allianceの支援のもとで維持管理や新規格対応を継続する。
  • 既存顧客契約の保護: オープンソース化以前にEDGと商用ライセンス契約を結んでいた既存顧客の権利やサポート契約は維持される。

これにより、特定企業の年間契約料に依存していた構造から、コミュニティと産業界の支援によって持続する公開基盤へと転換した。

他コンパイラとの互換性 — Clang・GCC・MSVCの挙動再現

開発支援ツールにフロントエンドを組み込む際、最大の障壁となるのは実社会のコードが規格に厳密に従っていないという現実である。多くの現場コードはGCCの拡張構文、Clang特有の構文解釈、あるいはMicrosoft Visual C++の非標準的な挙動や古いバグに依存して書かれている。

もし解析エンジンが標準仕様のみを厳格に適用した場合、GCCやMSVCでは正常に通るコードがツール上では構文エラーとして誤検知されてしまう。EDGが長年にわたり選ばれてきた強みは、この高い互換性エミュレーションにある。

  • 高い解析互換性: Clang、GCC、MSVCで正常にビルドできるコードであれば、EDGでもエラーなく解析できるよう徹底的な互換モードを備えている。
  • バグ・独自挙動のエミュレーション: 各コンパイラの拡張構文だけでなく、過去バージョンから引き継がれた構文解釈のバグや特異な振る舞いまで忠実に再現するオプションを持つ。
  • 動作モードの切り替え: フラグ指定によりGNUモード、Clangモード、MSVCモードを切り替え、対象コンパイラに合わせたマクロ定義や構文解釈を適用できる。
  • 充実した技術文書: エンジン内部の構造や構文規則の改変方法が詳細に文書化されており、ツールの設計者が自社環境に合わせて柔軟に派生させることが可能である。

John Spicerは発表の中で「この成果物をC++コミュニティが引き継ぎ、g++やclangと並ぶC++世界の基礎ツールとして発展することを期待する」と述べている。これはClang/LLVMが主流を占めていた領域に、強力なオープンソースの第3の選択肢が加わったことを意味する。

開発の継続性 — 3つの貢献経路と財政支援委員会

巨大な商用コードベースがオープンソース化された後に保守が停滞するリスクを回避するため、プロジェクトは持続可能な開発体制を明文化している。

開発と資金調達は以下の3つの経路で推進される。

  • コミュニティ直接貢献: 一般ユーザーや外部エンジニアはGitHubのPull Requestを通じてバグ修正や機能追加を提出できる。初期段階ではEDGのベテラン技術者がレビューを担当する。
  • 常時保守体制: The C++ Allianceに所属する専任開発者が、日常的なパッチ適用、性能向上、および最新C++言語規格の実装を継続してリポジトリに反映する。
  • 共同後援機能開発（Co-sponsored Features）: 特定の企業や組織が大規模機能の開発を望む場合、自社技術者を直接投入する代わりに開発資金を共同拠出できる。
  • 公開コードベースの厳守: 資金を提供した企業のみに機能を先行提供するような非公開ブランチは作らず、すべての機能は同一の公開リポジトリへ公平に反映される。

これらの方針や機能の優先順位付けは、John Spicerが委員長を務めコミュニティ有志が参加する財政支援委員会（Fiscal Sponsorship Committee, FSC）によって監督される。

                    cd compiler
                    mkdir build && cd build
                    cmake .. -DCMAKE_BUILD_TYPE=Release
                    cmake --build .
