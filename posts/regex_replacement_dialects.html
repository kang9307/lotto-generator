출력은 Windows 10 의 Git Bash(GNU sed 4.9, GNU Awk 5.0.0, perl 5.38.2), Python 3.13.3, node v22.16.0, Windows PowerShell 5.1.19041.6456 의 것이다. 근거는 그 출력과 MDN·Python 문서·Microsoft Learn 의 문구이며, 문서를 인용한 곳은 문서 문장임을 밝힌다. 이 글의 결과는 위 환경에서의 값이다.

서론 - 치환 문자열은 패턴과 다른 문법이다

정규식 패턴의 이식성은 자주 논의되지만, 치환 문자열(replacement)은 패턴과 별도의 문법이고 특수 표기가 도구마다 다르다. 같은 &가 sed 에서는 일치한 문자열 전체이고 Python·JS·PowerShell 에서는 평범한 앰퍼샌드이다. 같은 $1이 perl·JS·PowerShell 에서는 그룹 1이고 sed·Python 에서는 글자 그대로의 $1이다.

문제는 두 곳에서 생긴다. 하나는 표기를 다른 도구에서 옮겨 올 때이다. 오류 없이 조용히 틀린 결과가 나오기도 하고 오류로 멈추기도 한다. 다른 하나는 변수의 값을 치환 문자열 자리에 그대로 넣을 때이다. 값 안의 $·\·&가 특수 표기로 읽혀 값이 변형된다. 앞의 문제는 표기 대조표 하나로 정리되고, 뒤의 문제는 치환부를 문자열이 아닌 함수로 주는 방법으로 닫힌다.

  • 대상은 sed(GNU sed 4.9), awk(GNU Awk 5.0.0), perl 5.38.2 세 셸 도구와 Python 3.13.3 의 re.sub 이다.
  • 나머지 둘은 node v22.16.0 의 String.replace 와 Windows PowerShell 5.1 의 -replace 이다.
  • 입력은 모두 짧은 고정 문자열이고 의도는 같다. 일치 전체를 다시 쓰기, 그룹을 교환하기, 리터럴 값을 넣기이다.
  • 패턴 쪽 방언은 정규식 이식성 글이, sed 의 &·구분자 충돌은 sed 글이 다루므로 여기서는 도구 사이의 대조와 값을 넣는 방법에 둔다.
  • 출력은 오류 메시지까지 그대로 붙였으며, Python 의 repr 과 JS 의 JSON 형태로 찍은 줄은 따옴표가 출력에 포함된다.

전체 일치 참조 - &, $&, \g<0>

일치한 문자열 전체를 치환 문자열에서 다시 쓰는 표기는 도구마다 다르다. 아래는 Tom 을 [Tom] 으로 바꾸려는 같은 의도를 세 셸 도구에 넣은 결과이다.

echo 'Tom' | sed 's/Tom/[&]/'
                    echo 'Tom' | sed 's/Tom/[\0]/'
                    echo 'Tom' | awk '{ sub(/Tom/, "[&]"); print }'
                    echo 'Tom' | awk '{ print gensub(/Tom/, "[\\0]", "g") }'
                    echo 'Tom' | perl -pe 's/Tom/[$&]/'
                    echo 'Tom' | perl -pe 's/Tom/[&]/'
[Tom]
                    [Tom]
                    [Tom]
                    [Tom]
                    [Tom]
                    [&]

sed 의 &와 \0, awk 의 sub에서 &와 gensub에서 \\0, perl 의 $&가 모두 일치 전체를 가리켰다. 마지막 줄이 보이듯 perl 에서 &는 글자 그대로의 &이다. sed 와 같은 기대로 perl 에 &를 쓰면 치환은 일어나지만 일치 전체가 들어가지 않는다.

import re
                    print(repr(re.sub('Tom', '[&]', 'Tom')))
                    print(repr(re.sub('Tom', r'[\g<0>]', 'Tom')))
                    print(repr(re.sub('Tom', r'[\0]', 'Tom')))
'[&]'
                    '[Tom]'
                    '[\x00]'

Python 에서 &는 글자 그대로이고 전체 일치는 \g<0>이다. \0은 일치 전체가 아니라 NUL 문자(\x00)가 되었다. Python 문서는 repl 문자열 안의 백슬래시 이스케이프가 처리된다고 적고, 전체 일치 참조로는 \g<0>을 든다.

console.log(JSON.stringify('Tom'.replace(/Tom/, '[&]')));
                    console.log(JSON.stringify('Tom'.replace(/Tom/, '[$&]')));
                    console.log(JSON.stringify('Tom'.replace(/Tom/, '[$0]')));
"[&]"
                    "[Tom]"
                    "[$0]"
'Tom' -replace 'Tom','[&]'
                    'Tom' -replace 'Tom','[$&]'
                    'Tom' -replace 'Tom','[$0]'
[&]
                    [Tom]
                    [Tom]

JS 와 PowerShell 에서 전체 일치는 $&이다. MDN 의 표는 $&를 「Inserts the matched substring.」 으로 적고, Microsoft Learn 은 $&를 「entire match」 를 넣는 치환으로 적는다. 차이는 $0에서 난다. JS 는 $0을 특수 표기로 읽지 않아 글자 그대로 내놓았고, PowerShell 5.1 은 $0을 일치 전체로 읽었다.

  • &가 일치 전체를 뜻하는 도구는 이 글의 출력에서 sed 와 awk 였다.
  • $&는 perl·JS·PowerShell 에서 같은 뜻이다.
  • \0은 sed 에서 일치 전체, Python 에서 NUL 문자이다.
  • $0은 PowerShell 에서 일치 전체, JS 에서 글자 그대로이다.

그룹 참조 - \1 계열과 $1 계열

괄호 그룹을 참조하는 표기는 두 계열로 갈린다. sed·awk(gensub)·Python 은 백슬래시 계열(\1)이고, perl·JS·PowerShell 은 달러 계열($1)이다. 두 표기를 서로 바꿔 쓰면 어떻게 되는지, ab 를 ba 로 바꾸는 치환으로 본다.

echo 'ab' | sed -E 's/(a)(b)/\2\1/'
                    echo 'ab' | sed -E 's/(a)(b)/$2$1/'
                    echo 'ab' | awk '{ print gensub(/(a)(b)/, "\\2\\1", "g") }'
                    echo 'ab' | awk '{ sub(/(a)(b)/, "\\2\\1"); print }'
                    echo 'ab' | perl -pe 's/(a)(b)/$2$1/'
                    echo 'ab' | perl -pe 's/(a)(b)/\2\1/'
ba
                    $2$1
                    ba
                    \2\1
                    ba
                    ba

첫 줄에서 sed 의 \2\1은 ba 를 냈고, 둘째 줄의 $2$1은 그룹이 아니라 글자 그대로 출력되었다. awk 는 gensub만 그룹을 참조한다. sub에 같은 \\2\\1을 넣으면 \2\1이 그대로 나왔다. perl 은 $2$1이 ba 이고, \2\1도 ba 가 되었다.

import re
                    print(repr(re.sub(r'(a)(b)', r'\2\1', 'ab')))
                    print(repr(re.sub(r'(a)(b)', '$2$1', 'ab')))
                    print(repr(re.sub(r'(a)(b)', r'\g<2>\g<1>', 'ab')))
'ba'
                    '$2$1'
                    'ba'

Python 은 \2\1과 \g<2>\g<1>이 같은 결과이고 $2$1은 글자 그대로이다. 달러 계열 도구에서는 거꾸로이다.

console.log(JSON.stringify('ab'.replace(/(a)(b)/, '$2$1')));
                    console.log(JSON.stringify('ab'.replace(/(a)(b)/, '\\2\\1')));
"ba"
                    "\\2\\1"
'ab' -replace '(a)(b)','$2$1'
                    'ab' -replace '(a)(b)','\2\1'
ba
                    \2\1

JS 와 PowerShell 에서는 $2$1이 그룹 참조이고 \2\1이 글자 그대로 출력되었다. JS 출력의 "\\2\\1"은 JSON 이스케이프이며 실제 문자는 \2\1이다. 백슬래시 계열 표기를 달러 계열 도구에 가져가면 오류 없이 리터럴이 나오므로 틀린 결과가 조용히 통과한다.

그룹 번호 뒤에 숫자가 붙을 때

그룹 1 의 값 뒤에 글자 0 을 붙이는 치환(a 를 a0 으로)은 번호 뒤의 숫자가 번호의 일부로 읽히는지에서 도구가 갈린다.

echo 'a' | sed -E 's/(a)/\10/'
                    echo 'a' | awk '{ print gensub(/(a)/, "\\10", "g") }'
                    echo 'a' | perl -pe 's/(a)/${1}0/'
                    echo 'a' | perl -pe 's/(a)/[$10]/'
a0
                    a0
                    a0
                    []

sed 와 awk 는 \10을 그룹 1 다음의 0으로 읽었다. perl 은 ${1}0으로 쓰면 a0 이고, $10은 대괄호 안이 빈 문자열이 되었다.

import re
                    try:
                        print(repr(re.sub(r'(a)', r'\10', 'a')))
                    except re.error as e:
                        print(type(e).__name__ + ': ' + str(e))
                    print(repr(re.sub(r'(a)', r'\g<1>0', 'a')))
                    print(repr(re.sub(r'(?P<x>a)', r'\g<x>0', 'a')))
PatternError: invalid group reference 10 at position 1
                    'a0'
                    'a0'

Python 문서는 \g<2>가 \2와 같되 \g<2>0처럼 모호하지 않다고 적고, \20은 그룹 20 의 참조로 해석된다고 적는다. 출력의 PatternError 는 그룹 10 이 없다는 메시지이다. 조용히 틀리는 쪽보다 오류로 멈추는 쪽이 낫다.

console.log(JSON.stringify('a'.replace(/(a)/, '$10')));
                    console.log(JSON.stringify('a'.replace(/(?<x>a)/, '$<x>0')));
                    console.log(JSON.stringify('a'.replace(/(a)/, '$2')));
"a0"
                    "a0"
                    "$2"
'a' -replace '(a)','$10'
                    'a' -replace '(a)','${1}0'
                    'a' -replace '(?<x>a)','$<x>0'
$10
                    a0
                    $<x>0

JS 는 그룹이 하나인 패턴에서 $10을 그룹 1 뒤의 0 으로 읽어 a0 을 냈다. MDN 은 $n을 n 이 100 미만의 양의 정수일 때의 n번째 그룹으로 적고, 그룹이 없으면 리터럴이 된다고 적는다. 마지막 줄의 $2가 그 리터럴이다. PowerShell 은 $10을 글자 그대로 두었다. Microsoft Learn 은 $ 뒤의 숫자가 모두 번호에 속하고, 그 번호의 그룹이 없으면 리터럴이 된다고 적으며 ${1}1 형태를 대안으로 든다.

지금까지의 대조를 한 표로 묶는다. 칸의 「—」는 이 글에 출력이 없는 칸이다. 이 표는 GNU sed 4.9·gawk 5.0.0 에서의 결과이다.

의미GNU sed 4.9gawk 5.0.0perlPythonJSPowerShell 5.1

  • 번호 뒤에 숫자를 붙이려면 번호의 끝을 명시하는 표기를 쓴다. perl 과 PowerShell 은 ${1}, Python 은 \g<1>이다.
  • JS 는 이름 그룹 $<x>0이 a0 을 냈다. PowerShell 의 $<x>0은 글자 그대로였다.
  • 같은 $10이 JS 에서 a0, PowerShell 에서 $10, perl 에서 빈 문자열이다.
  • 그룹이 없는 $2는 JS 에서 리터럴이고 Python 의 \1은 오류이다.

리터럴 $ 가 든 값이 깨지는 자리

변수의 값을 치환 문자열에 그대로 넣는 코드는 값 안에 특수 표기가 있으면 깨진다. 가격 문자열 $5.00이 전형이다. 패턴에 그룹이 없으면 $5가 글자 그대로라 우연히 맞지만, 그룹이 5개이면 결과가 달라진다. JS 에서 여섯 가지 값을 넣고, 마지막 줄에서 그룹 5개 패턴에 $5.00을 넣었다.

for (const v of ['A&B', '$5.00', 'C:\\dir', 'US$', '$$', '$&$&']) {
                      console.log(v.padEnd(8) + JSON.stringify('x=OLD'.replace('OLD', v)));
                    }
                    console.log(JSON.stringify('abcde'.replace(/(a)(b)(c)(d)(e)/, '$5.00')));
A&B     "x=A&B"
                    $5.00   "x=$5.00"
                    C:\dir  "x=C:\\dir"
                    US$     "x=US$"
                    $$      "x=$"
                    $&$&    "x=OLDOLD"
                    "e.00"

첫 줄들에서 $5.00과 US$는 그대로이고, $$는 $ 한 글자로 줄었으며, $&$&는 OLDOLD 가 되었다. 값이 치환 문자열 표기로 읽힌 결과이다. 마지막 줄은 그룹 5개 패턴에서 $5.00이 e.00 이 된 것이다. MDN 의 표는 $$를 「Inserts a "$".」 로 적는다.

foreach ($v in 'A&B','$5.00','C:\dir','US$','$$','$&$&') {
                      $v.PadRight(8) + ('x=OLD' -replace 'OLD',$v)

                    'abcde' -replace '(a)(b)(c)(d)(e)','$$5.00'

PowerShell 5.1 도 같은 결과이다. $$5.00으로 쓰면 리터럴 $5.00이 들어간다. Microsoft Learn 은 $$를 단일 $ 리터럴을 넣는 표기로 적는다.

perl 에서 소스에 s/OLD/$5.00/로 쓰면 그룹이 없는 패턴인데도 .00이 된다. perl 이 소스의 $5를 변수로 보간한 결과이며, 값이 치환 표기로 해석된 것이 아니다. 이 출력은 다음 절에 나온다.

  • 값에 $가 들어 있고 패턴에 그룹이 있으면 JS·PowerShell 은 값 일부를 그룹으로 바꾼다.
  • $$는 값이 아니라 치환 표기이므로 $ 한 글자로 줄어든다.
  • $&$&처럼 표기와 같은 모양의 값은 일치 전체로 확장된다.
  • 그룹이 없는 패턴에서 우연히 맞았다면 패턴이 바뀔 때 깨진다.

리터럴 백슬래시와 &가 든 값

경로 C:\dir과 A&B도 같은 방식으로 넣는다. 아래는 x=OLD에서 OLD 를 각 값으로 바꾼 sed·awk·perl 의 출력이다. perl 의 마지막 줄은 A@B이다. 각 줄의 값은 스크립트 소스에 직접 쓴 것이다.

echo 'x=OLD' | sed 's/OLD/A&B/'
                    echo 'x=OLD' | sed 's/OLD/$5.00/'
                    echo 'x=OLD' | sed 's/OLD/C:\dir/'
                    echo 'x=OLD' | awk '{ sub(/OLD/, "A&B"); print }'
                    echo 'x=OLD' | awk '{ sub(/OLD/, "$5.00"); print }'
                    echo 'x=OLD' | awk '{ sub(/OLD/, "C:\\dir"); print }'
                    echo 'x=OLD' | perl -pe 's/OLD/A&B/'
                    echo 'x=OLD' | perl -pe 's/OLD/$5.00/'
                    echo 'x=OLD' | perl -pe 's/OLD/C:\dir/'
                    echo 'x=OLD' | perl -pe 's/OLD/A@B/'
x=AOLDB
                    x=$5.00
                    x=C:dir
                    x=AOLDB
                    x=$5.00
                    x=C:\dir
                    x=A&B
                    x=.00
                    x=C:dir

sed 는 A&B에서 &가 OLD 로 확장돼 AOLDB 가 되었고, C:\dir에서는 백슬래시가 사라져 C:dir 이 되었다. 스크립트에 쓴 치환부를 sed 가 읽은 결과이다. awk 도 &가 OLD 로 확장되었고, awk 소스의 "C:\\dir"는 C:\dir로 들어갔다. perl 은 A&B가 그대로이지만 $5.00은 .00, C:\dir은 C:dir, A@B는 A가 되어 @B 부분이 사라졌다. 이 세 경우는 소스에 쓴 치환부 안의 $5·\d·@B를 perl 이 소스 단계에서 읽은 결과이며, 값이 치환 표기로 해석된 것이 아니라 코드의 문제이다. 같은 세 값을 환경 변수로 넘겨 읽으면 아래 출력처럼 그대로 들어간다.

같은 세 값을 소스에 쓰지 않고 환경 변수로 넘겨 $ENV{V}로 읽으면 다음과 같다.

for v in '$5.00' 'C:\dir' 'A@B'; do
                      echo 'x=OLD' | V="$v" perl -pe 's/OLD/$ENV{V}/'
                    done
x=$5.00
                    x=C:\dir
                    x=A@B
import re
                    for v in ['A&B', '$5.00', r'C:\dir']:
                        try:
                            print(repr(re.sub('OLD', v, 'x=OLD')))
                        except re.error as e:
                            print(type(e).__name__ + ': ' + str(e))
'x=A&B'
                    'x=$5.00'
                    PatternError: bad escape \d at position 2

Python 은 C:\dir을 bad escape \d로 거부했다. Python 문서는 알 수 없는 ASCII 문자 이스케이프를 오류로 처리하고 \&처럼 그 밖의 알 수 없는 이스케이프는 그대로 둔다고 적는다.

같은 세 값의 결과를 여섯 도구로 모으면 다음과 같다. 표의 JS·PowerShell 칸은 패턴에 그룹이 없는 경우이다. perl 칸은 소스에 쓴 치환부의 결과이고, 값으로 받은 경우는 위 출력처럼 그대로 들어간다.

gawk 5.0.0 (sub)x=AOLDBx=$5.00x=C:\dir (awk 소스는 "C:\\dir")
perlx=A&Bx=.00 (소스의 $5 보간)x=C:dir (소스의 \d)
Pythonx=A&Bx=$5.00PatternError: bad escape \d
JSx=A&Bx=$5.00 (그룹 5개면 e.00)x=C:\dir
PowerShell 5.1x=A&Bx=$5.00 (그룹 5개면 e.00)x=C:\dir
  • &가 값 안에 있으면 sed 와 awk 에서 일치 전체로 확장된다.
  • \가 sed 스크립트·perl 소스의 치환부에 있으면 백슬래시가 지워지고, 값으로 받은 문자열에 있으면 Python 은 오류를 낸다.
  • $가 perl 소스의 치환부에 있으면 변수로 보간되고, 값으로 받은 문자열 안에 있으면 JS·PowerShell 은 그룹이 있을 때 읽는다. perl 이 값으로 받은 문자열은 그대로 들어간다.
  • JS 와 PowerShell 은 백슬래시를 건드리지 않아 경로가 그대로 들어간다.

값을 문자열이 아니라 함수로 넘긴다

값을 치환 문자열로 해석시키지 않는 방법은 치환부를 문자열이 아니라 함수가 돌려주는 값으로 주는 것이다. 값이 C:\dir\1 & $1 \n처럼 특수 표기를 모두 가진 경우로 시험한다. 먼저 Python 이다.

import re
                    v = r'C:\dir\1 & $1 \n'
                    print('v = ' + v)
                    try:
                        print(re.sub('OLD', v, 'x=OLD'))
                    except re.error as e:
                        print(type(e).__name__ + ': ' + str(e))
                    print(re.sub('OLD', lambda m: v, 'x=OLD'))
                    print(re.sub('OLD', v.replace('\\', '\\\\'), 'x=OLD'))
                    print('x=OLD'.replace('OLD', v))
                    print(re.sub(r'(a)(b)', lambda m: m[2] + m[1], 'ab'))

                    PatternError: bad escape \d at position 2

문자열로 넘기면 PatternError 이고, lambda m: v로 넘기면 값이 그대로 들어갔다. 백슬래시를 두 배로 만드는 방법과 str.replace도 같은 값이 나왔다. Python 문서는 repl 이 함수이면 겹치지 않는 일치마다 호출되어 치환 문자열을 돌려준다고 적는다. 마지막 줄은 함수 안에서 그룹을 직접 꺼내 두 그룹을 교환한 것이다.

JS 에서 문자열 치환은 $1·$&·$$가 해석되었다. 함수로 넘기면 모두 그대로이다. MDN 은 「The above-mentioned special replacement patterns do not apply for strings returned from the replacer function.」 이라고 적는다. 값 안의 $를 $$$$로 두 배 하는 방법과 split/join 도 그대로 들어갔다.

                    'v = ' + $v

PowerShell 5.1 에서 -replace의 치환은 문자열이다. [regex]::Replace에 MatchEvaluator 를 넘기거나 정규식이 아닌 .Replace() 메서드를 쓰면 값이 그대로 들어갔다. 마지막 줄처럼 -replace에 스크립트 블록을 주면 5.1 에서는 함수로 호출되지 않고 문자열 $v 주변의 공백과 함께 들어갔다.

  • Python 은 lambda m: v, JS 는 () => v로 값을 돌려주면 해석이 없다.
  • PowerShell 은 MatchEvaluator 또는 .Replace() 문자열 메서드를 쓴다.
  • 정규식이 필요 없으면 str.replace·split/join·.Replace()가 가장 단순하다.
  • -replace에서 값을 직접 넣어야 하면 $를 $$로 바꾸는 방법이 있고, 5.1 의 스크립트 블록은 함수가 아니다.

도구 바깥의 층 - 셸 인용과 awk -v

도구에 닿기 전에 셸과 도구 자체의 인용 층이 값을 한 번 더 바꾼다. awk 의 -v 옵션이 그 예이다. 아래에서 tr은 TAB 을 >로 바꿔 보이게 한 것이다.

echo 'x=OLD' | awk -v v='a\tb' '{ sub(/OLD/, v); print }' | tr '\t' '>'
                    V='a\tb' awk 'BEGIN { print ENVIRON["V"] }'
x=a>b
                    a\tb

-v v='a\tb'로 넘긴 값은 awk 가 이스케이프를 처리해 TAB 이 되었다(x=a>b). 환경 변수로 넘겨 ENVIRON으로 읽은 값은 a\tb가 글자 그대로였다. 이 차이는 출력이 직접 보여 준다.

'[' + ('ab' -replace '(a)(b)','$2$1') + ']'
                    '[' + ('ab' -replace '(a)(b)',"$2$1") + ']'

                    []

PowerShell 에서는 따옴표 종류가 층을 만든다. 같은 치환 문자열을 단일 따옴표로 쓰면 그룹 참조가 되고 큰따옴표로 쓰면 PowerShell 이 먼저 $2와 $1을 변수로 확장해 빈 문자열이 되었다. 출력의 두 번째 줄 []가 그 결과이다.

안전하게 넣는 방법 - 도구별 선택표

sed 는 값 안의 &·\·구분자를 이스케이프한 뒤 넣는다. awk 는 index·substr로 이어 붙이거나 ENVIRON으로 값을 받고, perl 은 값을 환경 변수에서 읽어 넣는다. 값은 A&B\C/D이다.

V='A&B\C/D'
                    ESC=$(printf '%s' "$V" | sed 's/[&\/\\]/\\&/g')
                    echo "ESC=$ESC"
                    echo 'x=OLD' | sed "s/OLD/$ESC/"
                    echo 'x=OLD' | V="$V" awk '{ i = index($0, "OLD"); print substr($0, 1, i-1) ENVIRON["V"] substr($0, i+3) }'
                    echo 'x=OLD' | V="$V" awk '{ sub(/OLD/, ENVIRON["V"]); print }'
                    echo 'x=OLD' | V="$V" perl -pe 's/OLD/$ENV{V}/'
ESC=A\&B\\C\/D
                    x=A&B\C/D
                    x=A&B\C/D
                    x=AOLDB\C/D
                    x=A&B\C/D

sed 의 변환은 A\&B\\C\/D를 만들고 치환 결과는 값 그대로이다. awk 는 index·substr 방식이 값 그대로이고 같은 값을 sub에 넣으면 &가 OLD 로 확장된 AOLDB\C/D가 나왔다. perl 은 $ENV{V}로 읽은 값이 그대로 들어갔다. 도구별 선택은 표와 같다.

gawk 5.0.0index·substr로 이어 붙이거나 ENVIRON으로 값을 받는다. sub의 치환부에 넣으면 &가 확장된다x=A&B\C/D · x=AOLDB\C/D

  • awk 는 sub의 치환부에 값을 넣지 말고 index·substr로 이어 붙인다.
  • Python·JS·PowerShell 은 함수 또는 문자열 메서드로 해석 자체를 피한다.
  • perl 은 값을 변수·환경 변수에서 읽어 넣고 치환부 리터럴에는 $·@를 쓰지 않는다.

패턴 쪽 방언은 정규식 방언 글이, sed 의 & 이스케이프와 구분자 충돌은 sed -i 글이 다룬다. 한글 정규식과 셸 이스케이프가 겹치는 자리는 한글 정규식 글에 있다.

확인하지 못한 것

  • GNU sed 매뉴얼과 GNU awk 매뉴얼은 접속이 거부되어 열지 못했다. sed·awk 의 동작은 GNU sed 4.9·gawk 5.0.0 의 출력만을 근거로 하며, GNU sed 4.9 에서 함수 치환에 해당하는 형태가 있는지는 보이지 못했다. mawk·BSD awk 에서의 동작과, 표의 「—」 칸(이름 그룹 표기)의 sed·awk·perl 결과는 출력이 없다.
  • perl 문서는 열지 않았다. perl 의 $·@ 보간과 \2 동작은 출력만을 근거로 하며, 소스 리터럴 단계의 해석이라는 설명은 $ENV{V}로 받은 값이 그대로 들어간 출력에서 이끌어 낸 것이다.
  • Python 의 \0이 NUL 문자가 되는 규칙과 JS 의 $10 에서 그룹 수에 따른 처리 세부는 문서 문구로 확인하지 못했다.
  • PowerShell 7 에서의 -replace 동작(스크립트 블록 포함)과 pwsh 는 이 PC 에 없어 실행하지 못했다.
  • BSD sed·mawk 등 다른 구현과 리눅스·macOS 의 결과는 실행하지 못했다.
