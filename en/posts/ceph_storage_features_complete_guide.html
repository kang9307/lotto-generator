Complete Guide to Ceph Storage: Object, Block, and FileSystem Features

2025-07-09 Dev & Infra

Ceph is a truly unique distributed storage solution that delivers object, block, and filesystem storage all from a single platform. In this guide, we take a detailed look at Ceph's three core storage capabilities, along with their strengths and real-world deployment examples.

By consolidating all three storage paradigms, Ceph lets teams manage a single system instead of operating parallel stacks for each storage type.

Ceph Storage Architecture Overview

Ceph's power comes from its unified architecture built on RADOS (Reliable Autonomic Distributed Object Store). Every storage type runs on the same cluster, dramatically reducing management complexity.

+-----------------------------------------+
|         Ceph Storage Platform           |
+-----------------------------------------+
|  Object Storage | Block Storage | FS    |
|  (RGW/S3)       | (RBD)         |(CephFS)|
+-----------------------------------------+
|             LIBRADOS Layer              |
+-----------------------------------------+
|              RADOS Cluster              |
|  (Monitors + OSDs + Managers + MDSs)    |
+-----------------------------------------+

Object Storage: RADOS Gateway (RGW)

Key Features and Benefits

Ceph's object storage fully supports both the Amazon S3 and OpenStack Swift APIs, ensuring compatibility with existing applications.

  • Full S3 API compatibility: Migrate existing S3-based applications without code changes
  • Unlimited scalability: Scales linearly up to petabyte-class storage
  • Multi-tenancy: Isolated namespaces per tenant
  • Geo-replication: Automatic replication across multiple data centers

Real Deployment Example

# Install and configure RADOS Gateway
sudo ceph-deploy install --rgw ceph-rgw01

# Create an RGW instance
sudo ceph-deploy rgw create ceph-rgw01

# Create an S3 user
radosgw-admin user create \
  --uid=testuser \
  --display-name="Test User" \
  --email=test@example.com

# Create a bucket (using the AWS CLI)
aws s3 mb s3://my-test-bucket --endpoint-url=http://rgw-server:7480

Block Storage: RADOS Block Device (RBD)

Key Features and Benefits

RBD provides high-performance block storage optimized for virtualization and container orchestration environments.

  • Thin provisioning: Only allocates space for what is actually used
  • Snapshots and clones: Instant backups and fast cloning
  • Encryption support: Transparent encryption for data security
  • QoS controls: IOPS and bandwidth limiting

Real-World Use Cases

# Create an RBD image (100GB)
rbd create --size 100G mypool/vm-disk01

# Create a snapshot
rbd snap create mypool/vm-disk01@backup-$(date +%Y%m%d)

# Create a clone (instant VM duplication)
rbd snap protect mypool/vm-disk01@backup-20250709
rbd clone mypool/vm-disk01@backup-20250709 mypool/vm-disk01-clone

# Mount via kernel module
rbd map mypool/vm-disk01
mkfs.ext4 /dev/rbd0
mount /dev/rbd0 /mnt/ceph-volume

FileSystem Storage: CephFS

Key Features and Benefits

CephFS is a POSIX-compliant distributed filesystem that excels at large-scale file sharing and parallel processing.

  • Full POSIX compatibility: 100% compatible with existing Linux applications
  • Dynamic metadata distribution: Automatic load balancing across metadata servers
  • Multi-active MDS: Metadata server redundancy for high availability
  • Subvolume support: Logical directory isolation and quota management

Deployment Walkthrough

# Deploy MDS servers
ceph-deploy mds create ceph-mds01 ceph-mds02

# Create the CephFS file system
ceph osd pool create cephfs_data 128
ceph osd pool create cephfs_metadata 64
ceph fs new cephfs cephfs_metadata cephfs_data

# Client mount (kernel driver)
mount -t ceph 192.168.1.10:6789:/ /mnt/cephfs \
  -o name=admin,secret=AQD4...

# FUSE mount (user space)
ceph-fuse /mnt/cephfs-fuse \
  --name client.admin \
  --keyring /etc/ceph/ceph.client.admin.keyring

Subvolume Management

# Create a subvolume group
ceph fs subvolumegroup create cephfs group1

# Create a subvolume (100GB quota)
ceph fs subvolume create cephfs vol1 --group_name group1 --size 100G

# Configure per-user access
ceph fs authorize cephfs client.user1 \
  /volumes/group1/vol1 rw

Best-Fit Scenarios for Each Storage Type

Recommended Uses for Object Storage (RGW)

  • Web applications: Storing images, videos, and static content
  • Backup and archive: Data that needs long-term retention
  • Big data analytics: Building data lakes
  • Cloud-native apps: Data sharing between microservices

Recommended Uses for Block Storage (RBD)

  • Virtual machines: VM disks and boot volumes
  • Databases: Transactional workloads that need high performance
  • Containers: Kubernetes Persistent Volumes
  • HPC: Storage for high-performance computing applications

Recommended Uses for File System (CephFS)

  • Shared workspaces: Collaboration environments for development teams
  • Media processing: Video editing and rendering
  • Log collection: Centralized log storage
  • Home directories: Per-user file services

Security and Access Control

Unified Authentication System

# Create a Ceph user (access to all storage types)
ceph auth get-or-create client.myapp \
  mon 'allow r' \
  osd 'allow rw pool=mypool' \
  mds 'allow rw path=/myapp-data'

# Create S3 keys for Object Storage
radosgw-admin user create \
  --uid=myapp \
  --display-name="MyApp User" \

Operational Best Practices

Capacity Planning

Pro Tip: When you plan capacity for a Ceph cluster, don't forget to account for replicas and metadata overhead. In general, only about 60-70% of raw capacity ends up being usable.

# Monitor capacity utilization
ceph df
ceph osd df tree

# Check per-pool utilization
ceph osd pool stats
rados df

Sample Automation Script

#!/bin/bash
# Ceph cluster health-check script

HEALTH=$(ceph health -f json | jq -r '.status')
DATE=$(date '+%Y-%m-%d %H:%M:%S')

if [ "$HEALTH" != "HEALTH_OK" ]; then
    echo "[$DATE] Ceph cluster abnormal state: $HEALTH"
    ceph health detail

    # Send a Slack notification
    curl -X POST -H 'Content-type: application/json' \
        --data '{"text":"Ceph cluster warning: '$HEALTH'"}' \
        $SLACK_WEBHOOK_URL
fi

Closing Thoughts: The Future of Ceph

Ceph Storage has established itself as the most powerful unified storage platform in cloud-native environments. By providing three storage interfaces -- Object, Block, and FileSystem -- from a single cluster, it delivers:

  • Dramatically reduced operational complexity
  • Optimized infrastructure costs
  • Scalability and availability at the same time
  • Freedom from vendor lock-in

Ceph's value stands out even more in hybrid cloud and edge computing scenarios, where a single, flexible storage platform can serve many different workloads at once.

As cloud-native and edge computing continue to grow, Ceph's ability to unify object, block, and file storage in one cluster will remain one of its most compelling differentiators.
