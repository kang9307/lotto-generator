Background of Decision Models — Shifting from Text Generation to Structured Probabilities

As enterprise engineering teams integrate generative artificial intelligence into production backbones, the architectural mismatch of autoregressive large language models (LLMs) has become increasingly apparent along critical system hot paths. Real-world automation tasks—such as triage of incoming support tickets, tool routing in agentic loops, real-time fraud mitigation, and traffic classification—rarely require prose synthesis. What software systems fundamentally demand are strongly typed discrete decisions: boolean flags, categorical buckets, and continuous confidence scores.

Standard generative models fulfill these requirements inefficiently. Generating even a single categorical token forces the runtime through full decoding pipelines, introducing dozens or hundreds of milliseconds in per-token inference overhead. Even when constrained by structured JSON grammars, generative models risk schema drift, syntax validation failures, and hallucinations. These structural bottlenecks catalyzed the emergence of dedicated 「Decision Models」—an independent model class engineered to bypass text generation entirely and output calibrated probability distributions over discrete options.

The progression of this paradigm has been analyzed previously in studies such as Jev Evaluation and Type-Safe Classification, multimodal wrapper architectures in Jev-Style Vision LLM Wrapper Experiments, and reasoning-augmented approaches in PostHog Jeeves Decision Model Analysis. On October 1, 2026, Cloudflare formally entered this arena with the release of Clef and Clef-flash, their open-weight decision model family.

  • Hot-Path Workload Mismatch: Generative autoregressive loops impose excessive latency and compute waste on straightforward classification tasks.
  • Non-Autoregressive Execution: Parallel evaluation of all candidate choices in a single forward pass without sequential token decoding.
  • Direct Probability Outputs: Normalized floating-point confidence values (0.0 to 1.0) returned directly for programmatic threshold gating.
  • Edge Infrastructure Synergy: Native alignment with edge execution runtimes such as Cloudflare cf CLI for Agents.
  • Open Weights Distribution: Released under the permissive Apache-2.0 license on Hugging Face alongside hosted Workers AI endpoints.

Clef and Clef-flash Architecture and Non-Autoregressive Parallel Evaluation

The Clef family comprises two distinct models optimized for different operational envelopes. The flagship Clef model, built on Qwen3.8-27B, targets high-accuracy multi-label categorization and complex tool-calling environments. The compact Clef-flash model, built on Qwen3.5-9B, is engineered for ultra-low latency, making it suitable for edge routing and live bot mitigation. Both models leave the base transformer backbone frozen, training specialized routing heads and low-rank adapter (LoRA) layers on synthetic and operational decision datasets.

In contrast to standard LLM generation, Clef operates via a non-autoregressive parallel evaluation mechanism. Following a single prompt prefill phase, the model maps input tokens into hidden representations and evaluates candidate options across a two-stage attention architecture. In the first stage, each choice independently attends to relevant segments of the prompt context. In the second stage, the model cross-references inter-question relationships and input states to compute joint calibrated scores.

{
                      "messages": [
                        { "role": "user", "content": "Payment failed for all customers over the past hour. DB connection pool exhausted." }
                      ],
                      "questions": [
                        { "id": "urgency", "type": "choice", "options": ["low", "medium", "critical"] },
                        { "id": "assignee", "type": "choice", "options": ["billing_team", "infra_team", "support"] },
                        { "id": "customer_impact", "type": "boolean" }
                      ]
                    }

As illustrated in this request schema, applications can bundle multiple disparate questions—categorical, boolean, or scored—into a single network request. Clef processes all candidate options simultaneously rather than streaming tokens sequentially. This non-autoregressive property guarantees that inference execution time does not scale with the length of the generated output, eliminating tail latency spikes inherent in autoregressive decoding.

  • Clef (27B Parameter Model): Powered by Qwen3.8-27B, tailored for deep domain classification and complex multi-tool selection.
  • Clef-flash (9B Parameter Model): Powered by Qwen3.5-9B, optimized for edge deployment where sub-50ms execution is paramount.
  • Two-Stage Attention Routing: Separates choice-to-context attention from inter-question dependency resolution.
  • Frozen Backbone Architecture: Retains foundational world knowledge while tuning task-specific classification heads.
  • Parallel Query Processing: Enables batch evaluation of dozens of decision fields without incurring linear latency penalties.

Interpretation of Cloudflare Self-Reported Benchmarks and Latency Metrics

In their announcement, Cloudflare presented comparative performance figures evaluated across standard academic and synthetic benchmarks. On the Berkeley Function-Calling Leaderboard (BFCL), which measures tool selection exact match rates, Clef scored 98.47% and Clef-flash achieved 98.76%, compared to 95.75% reported for Jev. Similarly, in the API-Bank benchmark, Clef attained 91.93% and Clef-flash reached 93.11%, exceeding Jev's 88.19%.

However, performance was not uniformly superior across all evaluated tasks. On the When2Call benchmark—which evaluates a model's restraint in determining whether a tool should be invoked at all—Jev outperformed both Cloudflare models, achieving 80.97% against Clef's 72.37% and Clef-flash's 65.58%. Cloudflare openly acknowledged that Jev demonstrated stronger performance on When2Call and the BRIGHT benchmark. This divergence illustrates the inherent trade-off between aggressive tool invocation precision and conservative withholding policies.

Regarding latency, Cloudflare reported aggregated runtime metrics across 43 diverse benchmarks. Clef-flash achieved a median latency of 38.8ms, compared to 524.1ms reported for Jev. For 95th percentile (p95) tail latency, Clef-flash recorded 122.4ms, representing the tightest distribution among compared systems. Engineers must bear in mind that these benchmarks represent vendor-reported numbers executed on Cloudflare's proprietary edge hardware and have not yet been replicated by independent third-party audit labs.

  • Vendor Self-Reported Metrics: All benchmark accuracies and latency figures reflect Cloudflare's published evaluations.
  • 38.8ms Median Latency: Demonstrates the speed advantages of non-autoregressive 9B architectures on managed edge GPUs.
  • Benchmark Divergence: Clef led on BFCL tool execution, while Jev retained superiority on When2Call invocation restraint.
  • End-to-End Pipeline Evaluation: In a real-world web classification workflow using Browser Run, total pipeline execution took 2.2s.
  • Laya Baseline Reference: The report noted ultra-small model Laya reached a 5.8ms median, though Clef-flash held better p95 stability.

Multimodal 64K Context Window and Jev API Compatibility

A notable architectural expansion in Clef is its native multimodal processing and 64K token context window. In contrast to legacy decision models like Jev, which operated strictly over text inputs within a 32K context window, Clef accommodates high-resolution images alongside extensive textual state. This capability unlocks decision workflows for visual use cases, such as automated website security classification from browser screenshots, multimodal receipt processing, and visual agent state triage.

Furthermore, Cloudflare designed Clef to be wire-compatible with the established Jev API specification. Engineering teams already utilizing TypeSafe Jev clients or REST connectors can redirect their traffic to Workers AI endpoints without altering client-side schemas. The model responds with standardized JSON structures containing discrete selection identifiers and normalized probability vectors.

{
                      "decisions": {
                        "urgency": {
                          "selected": "critical",
                          "probabilities": { "low": 0.012, "medium": 0.045, "critical": 0.943 }
                        },
                        "assignee": {
                          "selected": "infra_team",
                          "probabilities": { "billing_team": 0.021, "infra_team": 0.965, "support": 0.014 }
                        },
                        "customer_impact": {
                          "selected": true,
                          "probability": 0.988
                        }
                      }
                    }

This deterministic JSON payload eliminates the parsing fragilities that plague conventional LLM JSON-mode implementations. Downstream systems can inspect raw probability fields directly, enabling engineers to set strict certainty thresholds—for instance, escalating to on-call engineers only when critical probability exceeds 0.90, while routing borderline cases to human operators.

  • 64K Context Capacity: Accommodates large OpenAPI schemas, extended support histories, and multi-turn agent execution traces.
  • Native Multimodal Ingestion: Evaluates images and screenshots directly alongside text prompts for visual classification.
  • Drop-In Jev API Compatibility: Enables immediate migration from existing Jev client libraries by switching base URLs.
  • Deterministic Structured Payloads: Eliminates parsing failures by guaranteeing strict key-value JSON schema compliance.
  • Enterprise Data Privacy Policy: Cloudflare commits to not logging, storing, or training on customer payloads outside custom fine-tuning contracts.

RLCD Calibration and Enterprise Fine-Tuning Platform Roadmap

In production decision systems, raw classification accuracy is insufficient without statistical calibration. If a model assigns an 80% confidence probability to a hypothesis, that outcome must prove true in exactly 80 out of 100 historical instances. Conventional LLMs are notoriously miscalibrated, often expressing 99% confidence on incorrect assertions. To enforce mathematical alignment between output probabilities and true empirical likelihoods, Cloudflare employed Reinforcement Learning for Calibrated Decisions (RLCD).

RLCD utilizes a shaped reward function that accounts for the ordinal distance between options (e.g., granting partial credit if the model selects "medium" when the true answer is "high") and rewards correct joint predictions across multi-field queries. This reinforcement regimen aligns the model's logits with real-world probabilities, allowing developers to treat the returned float values as dependable operational metrics rather than arbitrary heuristics.

From an enterprise deployment perspective, Cloudflare currently provides customized fine-tuning through dedicated Forward Deployed Engineering (FDE) teams for design partners. Looking forward, the company outlined an integrated self-service RL platform combining AI Gateway for dataset capture, Workers AI for execution logging, Sandboxed Containers for agent policy evaluation, and a dedicated Trainer for automated retraining. However, the release explicitly clarified that this automated self-service platform is still in active development, distinguishing current model availability from future platform capabilities.

  • RLCD Objective: Mathematical reinforcement training designed to align model logits with empirical ground truth likelihoods.
  • Ordinal Distance Reward Shaping: Grants partial credit to semantically close answers while penalizing severe misclassifications.
  • Model vs. Platform Availability: Pretrained Clef weights are live today; the self-service fine-tuning platform remains in development.
  • FDE Enterprise Engagement: Fine-tuning currently delivered via high-touch engineering partnerships for specialized workloads.
  • Integrated Cloudflare Infrastructure: Planned integration spanning AI Gateway, Containers sandbox evaluation, and edge retraining.

Landscape of Decision Models — Contrasting Clef with Jev, Luna, and Jeeves

The rise of Clef underscores a broader architectural transition across AI engineering. The foundational benchmark for this category was established by TypeSafe's Jev System One, which demonstrated that dedicated pointer-head classifiers could outpace generative LLMs by orders of magnitude, as chronicled in Jev Evaluation and Type-Safe Classification.

Subsequently, the landscape split along architectural lines. One trajectory pursued closed-source cloud APIs, exemplified by OpenAI Luna Decision API Analysis. The other trajectory embraced open-weight customization, highlighted by PostHog's release of PostHog Jeeves Decision Model, which integrated chain-of-thought reasoning tokens immediately prior to probability emission to tackle complex analytical reasoning.

Within this ecosystem, Cloudflare Clef stakes its claim on edge distribution, non-autoregressive speed, and multimodal capabilities. Unlike Jeeves, which sacrifices latency (often requiring multiple seconds of reasoning time) to maximize analytical accuracy, Clef prioritizes strict sub-second responsiveness. Against Jev's proprietary hosted model, Clef provides open weights under Apache-2.0 and highly competitive Workers AI inference pricing ($0.24 per million tokens for Clef, $0.09 for Clef-flash).

  • Relationship to Jev: Full schema compatibility while extending context from 32K to 64K and adding native multimodal vision support.
  • Contrast with OpenAI Decision API: Delivers open-weight inspectability and local self-hosting rather than proprietary cloud lock-in.
  • Trade-Off Against Jeeves: Jeeves excels at deep multi-step deduction via reasoning tokens; Clef dominates high-throughput millisecond hot paths.
  • Ecosystem Integration: Complements edge compute stacks including Cloudflare Python Workers GA.
  • Strategic Fit: Pure non-autoregressive architectures deliver predictable latency profiles indispensable for infrastructure-level routing.

Before deploying decision models into production pipelines, engineering teams must evaluate whether target tasks genuinely demand free-form prose. By delegating discrete categorization and routing to Clef while reserving generative LLMs for conversational synthesis, organizations can achieve substantial cost reductions and latency improvements.

  • Decouple Classification from Generation: Restrict generative LLMs to user-facing prose; route discrete decisions to Clef.
  • Calibrated Threshold Gating: Leverage RLCD-calibrated floating-point probabilities to build robust automated circuit breakers.
  • Prototyping via Workers AI: Validate accuracy using @cf/cloudflare/clef before committing to on-premise serving.
  • Evaluate Local Serving Viability: Test Hugging Face weights under internal GPU clusters for ultra-low intranet latency.
  • Acknowledge Platform Maturity: Treat fine-tuning as an enterprise partnership engagement while self-service tools mature.
