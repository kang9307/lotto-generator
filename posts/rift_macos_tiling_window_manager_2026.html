본 분석은 오픈소스 프로젝트 Rift의 공식 깃허브 저장소(acsandmann/rift)와 공개 기술 문서에 명시된 내용을 바탕으로 작성되었다. Rift는 성능과 사용성을 목표로 설계된 macOS용 타일링 창 관리자이며, 시스템 무결성 보호(SIP)를 유지한 채 동작하는 구조적 특성을 지닌다.

1. 성능과 사용성에 초점을 맞춘 macOS 타일링 창 관리자

일반적으로 데스크톱 운영체제에서 다수의 애플리케이션 창을 효율적으로 배치하고 제어하는 일은 개발자와 시스템 엔지니어의 일상적인 생산성에 큰 영향을 미친다. 전통적인 겹침형 윈도우 인터페이스에서는 마우스를 이용해 창의 테두리를 끌어 크기를 조절하거나 원하는 모니터 위치로 직접 이동시키는 반복 작업이 불가피하다. 이러한 수동 배치의 비효율성을 줄이기 위해 화면을 규칙적인 격자나 분할 영역으로 빈틈없이 채워 넣는 타일링 창 관리 방식이 널리 활용되어 왔다.

리눅스 환경에서는 i3, bspwm, dwm, sway 등 다양한 독립 창 관리자가 독자적인 분할 알고리즘과 인터페이스 철학을 발전시키며 두터운 사용자층을 확보해 왔다. 반면 macOS 환경에서는 그래픽 합성 엔진과 창 서버가 운영체제 프레임워크와 긴밀하게 결합되어 있어, 리눅스 스타일의 창 관리 메커니즘을 외부 도구 형태로 안정적으로 구현하기가 상대적으로 까다로웠다. 일부 선행 도구들은 시스템 내부 비공개 인터페이스 접근을 위해 보안 메커니즘을 변경하도록 요구하거나, 화면 분할 조작 시 눈에 띄는 입력 지연과 프레임 드롭을 유발하기도 했다.

Rift는 원문 공식 설명에 명시되어 있듯이 「성능과 사용성에 초점을 맞춘 macOS용 타일링 창 관리자(a tiling window manager for macOS that focuses on performance and usability)」로 개발되었다. 원문 프로젝트를 관리하는 개발자 acsandmann은 기존 도구들이 지녔던 한계를 보완하면서, 사용자가 시스템 보안 기능을 끄지 않고도 높은 반응 속도와 네이티브에 가까운 조작 편의성을 누릴 수 있도록 아키텍처를 설계했다고 밝힌다.

이 글의 해석으로는, Rift가 내세우는 핵심 가치는 단일한 분할 철학을 강제하지 않는 유연성에 있다. 사용자의 작업 성격에 따라 서로 다른 리눅스 창 관리자의 배치 스타일을 선택할 수 있게 허용하면서도, 메뉴바 제어와 트랙패드 제스처 같은 macOS 고유의 상호작용 체계를 유기적으로 결합한 점이 주목할 만한 부분이다. 성능 최적화와 사용성 개선을 양대 축으로 삼아 데스크톱 환경의 전환 비용을 낮추는 구조를 취하고 있다.

개발자 환경에서 화면 분할 도구는 단순한 시각적 배치를 넘어 키보드 워크플로의 핵심 허브로 작동한다. 소스 코드 에디터, 컴파일러 터미널, 디버거 콘솔, API 문서 브라우저를 동시에 띄워 두고 작업할 때 창의 위치를 마우스로 일일이 정렬하는 시간 소모는 집중력을 흐트러뜨리는 주요 원인이 된다. Rift는 이러한 반복적인 수동 조작을 알고리즘 기반 자동 배치로 전환함으로써 개발자가 코드와 터미널 작업에 온전히 몰입할 수 있는 작업 환경을 지향한다.

2. 6가지 레이아웃 스타일과 리눅스 창 관리자 참조 모델

Rift의 가장 두드러진 기능적 특징 중 하나는 단일 창 관리자 안에서 6가지의 서로 다른 레이아웃 스타일을 기본 지원한다는 점이다. 대다수의 타일링 창 관리자가 특정한 하나의 배치 알고리즘을 중심으로 전체 인터페이스를 구성하는 것과 달리, Rift는 리눅스 진영에서 검증된 대표적인 창 배치 모델들을 수용하여 작업 환경에 맞춰 전환할 수 있도록 구현했다.

레이아웃 명칭 원문 참조 모델 창 배치 및 분할 방식 작업 영역 적합성
Tiling i3 / sway 유사 스타일 화면 분할 방향에 따라 컨테이너를 가로 또는 세로로 나누는 격자형 배치 고정된 비율의 터미널과 에디터를 병렬 배치하는 표준 개발 작업

타일링 및 파티셔닝 계열 레이아웃

원문 설명에 따르면 Rift는 전통적인 리눅스 타일러들의 대표적 분할 체계를 포괄한다. Tiling 레이아웃은 i3나 sway에서 친숙한 컨테이너 기반 분할 방식을 취하여 사용자가 직관적으로 가로 및 세로 분할을 제어할 수 있게 돕는다. 사용자가 새로운 창을 열 때 수평 또는 수직 분할 방향을 지정하면, 기존 컨테이너 내부가 쪼개지며 규칙적인 타일 격자가 형성된다. 이러한 방식은 2분할이나 4분할과 같이 정형화된 화면 구성을 장시간 유지하며 터미널과 편집기를 나란히 띄워 놓는 작업에 최적화되어 있다.

반면 Binary Space Partitioning(BSP)은 bspwm처럼 이진 트리 구조로 화면 공간을 재귀적으로 나누어 화면 공간을 균등하고 정밀하게 채워 나간다. 각 창은 트리의 리프 노드로 표현되며, 새로운 창이 추가될 때마다 현재 선택된 노드가 반으로 나뉘며 잎사귀를 형성한다. 창을 닫으면 형제 노드가 부모 영역을 흡수하며 자동으로 공간을 재분배하므로, 창의 개수가 수시로 변하는 동적인 멀티태스킹 작업에서 수동 배치 부담을 덜어준다.

Master-stack 방식은 dwm의 전형적인 화면 구성 방식을 차용하여 주 작업 창을 좌측이나 중앙에 크게 두고 나머지 도구 창들을 우측 보조 스택에 차곡차곡 적재하는 구조를 취한다. 메인 개발 에디터나 브라우저를 주 화면에 크게 고정해 두고, 참고용 로그 창이나 서브 셸들을 스택 영역에 자동으로 누적시킬 수 있어 주요 작업 대상에 시선을 집중하기에 알맞다.

동적 공간 활용 및 부유형 레이아웃

정통 타일링 외에도 현대적인 데스크톱 실험을 수용한 점이 눈에 띈다. Scrolling columns 레이아웃은 웨이랜드(Wayland) 기반의 niri 창 관리자 스타일을 본뜬 것으로, 창들이 무한한 수평 띠 형태의 컬럼으로 나열되어 화면을 가로로 스크롤하며 창을 전환할 수 있도록 지원한다. 단일 화면의 물리적인 해상도 한계에 구애받지 않고 가로 방향으로 여러 작업 창을 끝없이 펼쳐 두고 좌우로 미끄러지듯 이동할 수 있으므로, 다수의 소스 코드나 긴 로그를 동시에 열어 두고 추적해야 하는 대규모 프로젝트 디버깅에 탁월한 유연성을 발휘한다.

Stack 레이아웃은 아코디언 방식으로 창 목록을 접어 두었다가 활성화된 대상만 펼쳐 보여주며 공간 효율을 극대화한다. 화면 해상도가 제한된 맥북 단일 디스플레이 환경에서 창들을 수직으로 겹쳐 배치하고, 현재 작업 중인 창만 전체 높이로 늘려 보여줌으로써 작은 화면에서도 시각적 혼란 없이 다중 작업을 순차 처리할 수 있도록 돕는다. 마지막으로 Floating 레이아웃은 엄격한 타일링을 해제하고 독립적인 창 프레임과 선택적 스택을 허용하여 자유 배치가 필요한 예외적 작업 상황에 유연하게 대응한다. 그래픽 편집 도구나 다이얼로그 형태의 비정형 윈도우를 다룰 때 타일 격자를 강제하지 않고 자연스럽게 부유 창으로 다룰 수 있다.

원문에 명시된 6가지 레이아웃 세부 목록은 다음과 같다.

  • Tiling: i3 및 sway 스타일을 계승한 격자형 컨테이너 자동 분할 구조
  • Binary Space Partitioning: bspwm 스타일의 이진 공간 분할 트리 기반 레이아웃
  • Floating: 고정 그리드에서 벗어난 독립 창 프레임 및 선택적 스택 배치
  • Master-stack: dwm 스타일의 주 창(Master)과 보조 창 적재(Stack) 영역 2분할
  • Scrolling columns: niri 스타일의 수평 스크롤 기반 연속 창 컬럼 탐색
  • Stack: 아코디언 방식으로 창을 접어 두고 포커스에 따라 펼치는 고밀도 구조

3. 시스템 무결성 보호(SIP) 유지와 네이티브 디스플레이 통합

macOS에서 창 관리 도구를 도입할 때 사용자들이 가장 먼저 마주하는 심리적·기술적 장벽 중 하나는 시스템 무결성 보호(System Integrity Protection, 이하 SIP)의 비활성화 여부다. 과거 yabai 등 일부 도구는 Dock이나 WindowServer 프로세스에 코드를 주입하거나 윈도우 애니메이션을 강제로 제거하기 위해 복구 모드로 부팅하여 SIP를 끄도록 권장했다. 그러나 업무용 장비나 엄격한 보안 컴플라이언스가 적용된 환경에서는 SIP를 비활성화하는 행위 자체가 금지되어 도구 도입이 차단되는 경우가 빈번했다.

Rift의 README 문서는 이와 관련하여 「SIP 비활성화를 요구하지 않는다(Does not require disabling SIP)」는 점을 명확한 장점으로 내세운다. 복구 모드 진입이나 시스템 커널 수준의 보안 해제 절차 없이, 운영체제가 제공하는 표준 사용자 공간에서 즉시 구동될 수 있는 안전성을 보장한다. 시스템 관리자의 보안 정책을 위배하지 않으면서도 온전한 타일링 경험을 구축할 수 있다는 점은 기업 및 상용 개발 환경에서 결정적인 채택 요인이 된다.

또한 Rift는 다중 모니터 환경에서 애플이 제공하는 네이티브 가상 데스크톱 설정과 유연하게 결합된다. 원문에서는 Rift가 「디스플레이마다 별도의 Spaces 사용(Displays have separate Spaces)」 옵션이 켜진 상태에서도 완전하게 호환되어 동작한다고 강조한다. 다른 주요 타일링 창 관리자들의 경우 모니터별 Spaces 분리 설정과 충돌을 일으키거나 화면 간 창 이동 시 좌표 계산이 어긋나는 문제가 보고되곤 했으나, Rift는 macOS 네이티브 멀티 디스플레이 동작 방식을 온전히 수용하도록 설계되었다.

설정 런타임 Hot reloadable configuration 환경 설정 파일 변경 시 프로세스를 재시작하지 않고 실시간 런타임 적용
외부 확장 통신 Mach port based IPC Mach 포트 기반 프로세스 간 통신을 통해 sketchybar 등 서드파티 상태 바 연동

다중 디스플레이 환경에서 각 모니터가 독립된 가상 데스크톱을 가지는 설정은 맥북 프로와 외장 4K 모니터를 함께 사용하는 개발자들에게 필수적인 환경이다. 한쪽 화면에서 전체 화면으로 문서를 검토하면서 다른 쪽 화면에서는 분할 터미널 작업을 지속할 수 있어야 하기 때문이다. 기존의 서드파티 창 관리자들은 이러한 모니터별 독립성을 보장하지 못해 외장 모니터의 작업영역을 변경할 때 노트북 화면까지 함께 전환되거나 창 배치 좌표가 어긋나는 불편을 낳았다. Rift는 이러한 네이티브 특성을 그대로 살려 이질감 없는 다중 모니터 작업 환경을 제공한다.

이와 같은 시스템 통합 설계는 업무용 데스크톱 환경에서 다음과 같은 실질적인 운영상의 이점을 제공한다.

  • 운영체제 보안 규정을 훼손하지 않고 순수 사용자 공간에서 실행 가능
  • 다중 모니터 간 독립 Spaces 전환 시 발생하는 화면 깜빡임 및 위치 오차 최소화
  • 마우스 포커스 추적(Focus follows mouse)과 자동 창 부상(Auto raise)을 통한 입력 흐름 단축
  • 운영체제 메이저 업데이트 시 SIP 관련 코드 주입 실패로 인한 오작동 위험 차단

4. 제스처 기반 작업영역 전환과 애니메이션 연출

기존의 리눅스 지향 타일링 창 관리자들은 성능 극대화와 즉각적인 화면 갱신을 목표로 애니메이션 연출을 완전히 배제하고 창 위치를 순간 이동시키듯 전환하는 경우가 흔했다. 이러한 즉각적인 화면 전환은 키보드 중심의 빠른 조작에는 적합할 수 있지만, 창이 이동하거나 크기가 바뀌는 시각적 맥락이 생략되어 사용자가 순간적으로 작업 위치를 놓치는 인지적 피로를 유발하기도 한다.

Rift 개발자는 동기(Motivation) 절을 통해, Aerospace 등 기존 도구들이 훌륭하게 작동했음에도 불구하고 유려한 애니메이션의 부재와 한쪽 디스플레이에서 전체 화면을 띄우면서 다른 디스플레이 작업을 병행하는 데서 오는 아쉬움이 Rift 개발의 계기가 되었다고 밝힌다. 이에 따라 Rift는 「부드럽고 빠른 애니메이션(Performant animations)」을 기본 탑재하여 창 배치 및 크기 조절 과정에서 자연스러운 시각적 전환을 제공한다.

창이 분할되거나 다른 컨테이너로 이동할 때 부드럽게 크기가 늘어나고 줄어드는 보간 연출은 사용자가 창의 이동 경로와 상태 변화를 직관적으로 인지할 수 있도록 돕는다. 이러한 애니메이션은 반응 속도를 저해하지 않는 고성능 렌더링 방식으로 구동되어, 조작 반응성과 시각적 미려함을 동시에 달성하도록 튜닝되어 있다.

더불어 macOS 사용자의 기본 입력 장치인 트랙패드와의 네이티브 수준 연동을 지원한다. 트랙패드 제스처를 사용하여 macOS 순정 환경과 완전히 동일한 감각으로 이전 및 다음 작업영역(Workspace)을 부드럽게 오갈 수 있다. 손가락 스와이프 제스처를 감지하여 작업 공간을 좌우로 넘기는 조작은 맥북의 하드웨어 특성을 극대화한 기능이다. 키보드 단축키에 전적으로 의존하는 하드코어 타일러의 장점을 취하면서도, 맥북 내장 트랙패드의 제스처 감각을 그대로 살려 사용자가 느끼는 조작 이질감을 최소화했다.

5. 메뉴바 제어 인터페이스와 레이아웃 상태 관리

타일링 창 관리자의 가장 큰 진입 장벽 중 하나는 수십 개에 달하는 키보드 단축키를 외우지 않으면 사소한 창 배치 변경조차 어렵다는 점이다. 복잡한 모디파이어 키 조합을 기억해야 하는 부담감은 입문자들에게 큰 심리적 저항선을 형성한다. Rift는 터미널 기반의 CLI 조작과 단축키 환경을 완비하면서도, macOS 상단 메뉴바(Menubar)에 전용 아이콘을 배치하여 시각적인 빠른 제어 인터페이스를 함께 제공한다.

사용자는 메뉴바 아이콘을 클릭하여 드롭다운 메뉴를 열고, 현재 작업영역(Workspace)을 전환하거나 레이아웃 스타일(Tiling, BSP, Floating, dwm 스타일 등)을 마우스 클릭 한 번으로 즉시 변경할 수 있다. 키 바인딩을 잊어버렸거나 일시적으로 마우스 조작이 편리한 상황에서도 손쉽게 창 관리자 설정을 제어할 수 있도록 돕는 실용적인 장치다. 메뉴바를 통해 현재 어떤 레이아웃이 적용되어 있는지 시각적으로 즉시 확인 가능한 상태 표시기 역할도 겸한다.

또한 Rift는 레이아웃의 저장 및 복원(Save and restore layouts) 기능을 갖추고 있다. 메뉴바 인터페이스나 CLI 명령어를 통해 현재 화면의 창 배치 상태를 저장할 수 있으며, 사용자가 설정한 구성 폴더에 저장된 재사용 가능한 레이아웃 템플릿 목록을 불러와 작업 상황에 맞춰 화면 배치를 즉각적으로 재현할 수 있다. 예를 들어 프론트엔드 개발 시에는 브라우저와 에디터가 반반 나뉜 레이아웃을 불러오고, 데이터 분석 시에는 다중 로그 뷰어가 배치된 레이아웃을 불러오는 식의 작업 전환이 손쉽게 이루어진다.

메뉴바 제어와 레이아웃 관리 기능이 제공하는 주요 특징은 다음과 같다.

  • 메뉴바 아이콘 클릭을 통한 작업영역 전환 및 레이아웃 모드 즉시 변경
  • 단축키 암기 없이 마우스 조작만으로 접근 가능한 빠른 제어 메뉴 제공
  • 현재 화면 구성 상태를 파일로 저장하고 필요할 때 원클릭으로 복원하는 상태 영속성
  • 사용자 지정 설정 폴더에 저장된 템플릿 레이아웃 목록의 유연한 재사용

6. 핫 리로드 설정 체계와 Mach 포트 기반 프로세스 간 통신

창 관리 도구를 자신의 작업 스타일에 맞추어 미세 조정하는 과정에서는 설정 파일 수정과 테스트가 쉼 없이 반복된다. 여백의 크기, 창 간격(Gap), 외곽선 테두리 색상, 특정 앱의 타일링 제외 규칙 등을 다듬을 때마다 창 관리자를 껐다 켜야 한다면 작업 흐름이 심각하게 단절된다. Rift는 사용자의 생산성을 저해하지 않도록 핫 리로드 가능한 설정(Hot reloadable configuration) 체계를 지원한다.

런타임 구성 변경과 핫 리로드 동작

설정 파일을 편집기에 열고 옵션 값을 변경한 뒤 저장하면, 백그라운드에서 동작 중인 Rift 프로세스가 파일 시스템 변경 이벤트를 감지하여 실시간으로 런타임 상태에 반영한다. 창 관리자 프로세스를 수동으로 재시작하거나 열려 있는 작업 창들이 닫히는 번거로움 없이, 테두리 두께, 패딩 간격, 단축키 매핑, 기본 레이아웃 등의 변경 사항을 즉각적으로 확인할 수 있다. 실시간 피드백을 통해 데스크톱 테마와 타일링 규칙을 빠르고 직관적으로 튜닝할 수 있는 개발 환경을 선사한다.

Mach 포트 IPC 기반 외부 상태 바 연동

Rift는 외부 서드파티 프로그램과의 연동을 위해 macOS의 고유한 IPC 메커니즘인 Mach 포트 기반 통신(Mach port based IPC)을 제공한다. 유닉스 도메인 소켓이나 임시 파이프에 의존하는 방식 대신 커널 수준의 Mach 메시징 인터페이스를 활용함으로써 전송 지연을 낮추고 안정성을 확보했다.

이 Mach 포트 통신 인터페이스를 통해 사용자는 macOS 커스터마이징 진영에서 널리 쓰이는 sketchybar와 같은 서드파티 상태 바 위젯에 현재 활성 작업영역 번호, 선택된 레이아웃 모드, 창 포커스 상태 등의 실시간 메타데이터를 연동하여 시각화할 수 있다. 창 관리자의 내부 상태가 실시간으로 외부 프로세스에 발행되므로, 사용자는 자신만의 맞춤형 데스크톱 대시보드와 정보 바를 유연하게 구축할 수 있다.

7. Rust 기반 구현과 glide-wm 포크로부터의 진화

창 관리자는 운영체제의 이벤트 루프와 끊임없이 상호작용하며 창 생성, 소멸, 크기 변경 이벤트를 실시간으로 처리해야 하므로 실행 바이너리의 메모리 안전성과 연산 성능이 극히 중요하다. 가비지 컬렉션의 일시 정지 지연이 발생하거나 댕글링 포인터로 인한 메모리 손상이 일어날 경우 데스크톱 환경 전체가 멈추거나 충돌할 위험이 있다. Rift는 현대적인 시스템 프로그래밍 언어인 Rust로 개발되어 메모리 결함 위험을 컴파일 타임에 차단하면서도 C 언어에 필적하는 높은 실행 효율을 달성했다.

프로젝트의 계보를 살펴보면, Rift는 glide-wm 프로젝트의 포크(fork)로 처음 출발했다. 그러나 개발 과정에서 내부 구조와 기능 설계가 대대적으로 개편되며 현재는 glide-wm과 크게 분기(diverged significantly)되어 독자적인 코드베이스로 발전했다. 라이선스 측면에서는 원문의 명시적 서술에 따라 glide-wm과 동일한 라이선스로 배포되고 있다.

또한 Rift는 yabai 및 여타 선행 오픈소스 프로젝트들이 리버스 엔지니어링을 통해 규명한 비공개 API(private APIs)를 일부 활용한다. 원문 문서에서는 비공개 API를 활용하는 이유에 대해, macOS 전체 시스템이 바로 그 내부 API들을 바탕으로 구축되어 있기 때문에 오히려 공개 API보다 더 신뢰성 있고 높은 성능을 보이기 때문이라고 설명한다. 운영체제 내부 컴포넌트들이 사용하는 경로를 직접 활용함으로써 우회 레이어를 줄이고 실행 속도를 끌어올렸다는 분석이다. 단, 공식 프로젝트는 glide-wm이나 yabai와 공식적으로 제휴(affiliated)되어 있지 않은 독립 프로젝트임을 분명히 밝히고 있다.

프로젝트 구현 및 오픈소스 생태계 지표는 다음과 같이 요약할 수 있다.

  • Rust 언어 기반 개발을 통한 메모리 안전성 및 저지연 창 연산 성능 확보
  • 깃허브 저장소 기준 2,400개 이상의 스타(2.4k stars)와 95개의 포크(forks) 기록
  • glide-wm의 포크로 시작되었으나 광범위하게 진화한 독자 코드베이스 유지
  • glide-wm과 동일한 오픈소스 라이선스 정책을 준수하여 배포

8. 오픈소스 커뮤니티와 후원 생태계

Rift는 전 세계 개발자들과 소통하고 프로젝트를 개선하기 위해 개방형 커뮤니티 채널을 운영하고 있다. 기술적인 논의와 질의응답, 기능 제안 및 버그 보고는 분산형 오픈 프로토콜인 매트릭스(Matrix) 네트워크의 공식 채널(#rift:matrix.org)을 통해 활발히 이루어진다. 중앙 집중식 상용 메신저 대신 개방형 표준 프로토콜을 커뮤니티 채널로 선택한 점은 오픈소스 생태계의 독립성과 연속성을 중시하는 개발 철학을 잘 보여준다.

프로젝트 메인테이너인 acsandmann은 Rift를 일상 업무 워크플로에 도입하여 유용하게 활용하는 사용자들을 위해 GitHub Sponsors를 통한 개발 후원(sponsorship) 옵션을 제공하고 있다. 사용자의 자발적인 후원은 개인 개발자가 지속적으로 macOS 버전 변경에 대응하고 새로운 레이아웃과 성능 최적화 패치를 유지보수할 수 있는 중요한 원동력이 된다. 오픈소스 지속 가능성을 담보하기 위한 후원 모델이 자연스럽게 결합되어 있다.

Rift 커뮤니티 및 지원 참여 경로는 다음과 같다.

  • Matrix 분산 채팅 네트워크의 공식 채널(#rift:matrix.org)을 통한 실시간 기술 질의 및 피드백
  • GitHub 이슈 트래커를 통한 버그 보고 및 기술 토론 참여
  • GitHub Sponsors 플랫폼을 통한 메인테이너 개발 후원 참여

9. 확인하지 못한 것

본 글을 작성하며 1차 출처 문서와 기술적 세부 사항을 확인하는 과정에서 아래 항목들은 명확한 수치나 추가 자료를 확인하지 못하여 단정적으로 서술하지 않고 본 절에 남긴다.

  • Rift가 glide-wm의 포크로 시작되어 동일한 라이선스로 배포된다는 점은 확인되었으나, 해당 라이선스의 구체적인 정식 명칭(예: MIT, GPL, Apache 등)은 원문 README 본문 및 저장소 메타데이터에서 특정되지 않아 확인하지 못했다.
  • 공식 설치 명령어(예: Homebrew 탭이나 패키지 명칭, 또는 소스 빌드 파라미터)의 상세 구문은 README에 직접 기재되지 않고 공식 문서의 빠른 시작(quick start) 서브페이지로 안내되어 있어 본문 표에 싣지 못했다.
  • Rift가 화면 제어를 위해 활용하는 구체적인 비공개 API 함수명 목록 및 yabai로부터 차용한 리버스 엔지니어링 함수의 세부 시그니처는 공식 README에 명시되지 않아 기술하지 못했다.
  • Mach 포트 IPC를 통한 sketchybar 연동 외에 다른 서드파티 데스크톱 유틸리티들과의 공식 플러그인 호환성 목록의 전체 범위는 공식 문서의 추가 갱신 사항을 확인하지 못했다.
