Complete A-to-Z Guide to Claude Code Skills

2025-11-15 IT/技术

Claude Code Skills 是一项将 Anthropic 的 Claude AI 集成到开发工作流中的强大功能，能够自动化重复性任务、提升代码质量并最大化开发生产力。它不仅仅是简单的代码自动补全，更是一位能够理解开发者意图并提供贴合上下文解决方案的智能开发助手。

English: Claude Code Skills is a powerful feature that integrates Anthropic's Claude AI into development workflows to automate repetitive tasks, improve code quality, and maximize development productivity. It's an intelligent development assistant that goes beyond simple code completion to understand developer intent and provide context-appropriate solutions.

🎯 什么是 Claude Code Skills？

Claude Code Skills 主要由以下三个核心组成部分构成：

  • Skill 定义文件：用于定义任务目的、输入参数和执行逻辑。
  • Claude AI 引擎：负责理解自然语言指令、生成并执行代码。
  • 集成环境：与 VS Code、CLI 等各种开发环境实现无缝集成。

核心特点

  • 上下文理解：分析项目的整体结构和编码风格，生成具有一致性的代码。
  • 工作流自动化：将重复性的开发任务定义为 Skills 并自动执行，节省时间。
  • 可扩展性：可无限创建自定义 Skills，满足团队的特定需求。
  • 协作支持：在团队成员之间共享 Skills，统一开发标准并提升协作效率。

📋 基本概念与结构

Skill 的结构

一个 Claude Code Skill 的基本结构如下：

name: skill-name
description: 该 Skill 所执行任务的描述
version: 1.0.0

parameters:
  - name: param1
    type: string
    required: true
    description: 第一个参数的说明

  - name: param2
    type: array
    required: false
    default: []
    description: 第二个参数的说明

instructions: |
  在这里编写该 Skill 需要执行的具体指令。
  Claude 将根据这些指令完成任务。

  可以使用 ${param1}、${param2} 的形式引用变量。

output:
  format: markdown
  location: ./output/

主要组成部分说明

  • name：Skill 的唯一标识符，使用 kebab-case 命名。
  • description：简要描述 Skill 的目的和功能。
  • parameters：定义 Skill 运行时所需的输入值。
  • instructions：Claude 将要执行的具体任务指令。
  • output：指定输出产物的格式与保存位置。

🛠️ 创建 Skills

第一个 Skill：API 端点生成器

我们来动手创建一个在实际工作中最常用的 RESTful API 端点生成 Skill。

Step 1：创建 Skill 文件

在 .claude/skills/ 目录下创建 create-api-endpoint.yaml 文件：

name: create-api-endpoint
description: 自动生成 RESTful API 端点
version: 1.0.0

parameters:
  - name: resource_name
    type: string
    required: true
    description: 资源名称（例如：user、product、order）

  - name: methods
    type: array
    required: false
    default: ["GET", "POST", "PUT", "DELETE"]
    description: 要生成的 HTTP 方法列表

  - name: database
    type: string
    required: false
    default: "postgresql"
    description: 使用的数据库（postgresql、mysql、mongodb）

instructions: |
  请按顺序执行以下任务：

  1. 为 ${resource_name} 生成数据模型。
     - 定义 TypeScript interface
     - 定义 ${database} 架构
     - 包含校验逻辑

  2. 为 ${methods} 中指定的每个 HTTP 方法生成控制器。
     - GET：列表查询与单项查询
     - POST：创建新项
     - PUT：修改现有项
     - DELETE：删除项

  3. 为每个端点生成单元测试。
     - 正常用例
     - 错误用例
     - 边界用例

  4. 以 OpenAPI 3.0 格式生成 API 文档。

  5. 按合理的目录结构生成并整理所有文件。

output:
  format: files
  structure: |
    src/
      models/${resource_name}.model.ts
      controllers/${resource_name}.controller.ts
      routes/${resource_name}.routes.ts
      services/${resource_name}.service.ts
    tests/
      ${resource_name}.test.ts
    docs/
      api/${resource_name}.openapi.yaml

Step 2：运行 Skill

在 Claude Code CLI 或 VS Code 扩展中按如下方式运行 Skill：

# 在 CLI 中执行
claude skill run create-api-endpoint \
  --resource_name=product \
  --methods=GET,POST,PUT,DELETE \
  --database=postgresql

# 或以交互模式运行
claude skill run create-api-endpoint
📘 运行结果
执行上述命令后，Claude 将自动为 Product 资源生成完整的 API 端点，包括模型、控制器、路由、服务层、测试代码和 API 文档。这些通常需要手动耗费数小时的工作，几分钟即可完成。

高级 Skill 示例：自动重构

name: auto-refactor
description: 检测代码坏味道并自动进行重构
version: 2.0.0

parameters:
  - name: target_files
    type: array
    required: true
    description: 要重构的文件路径列表

  - name: refactor_types
    type: array
    required: false
    default: ["all"]
    description: |
      要应用的重构类型：
      - extract_method：将过长的方法拆分为小方法
      - remove_duplication：去除重复代码
      - simplify_conditional：简化复杂的条件判断
      - rename_variable：使用更清晰的变量名
      - all：应用所有重构

instructions: |
  1. 分析 ${target_files} 中的每个文件，找出以下代码坏味道：
     - 过长的方法（超过 50 行）
     - 重复代码（重复 3 次以上）
     - 复杂的条件判断（嵌套深度 3 层以上）
     - 不清晰的变量名（如 a、b、temp 等）
     - 过大的类（超过 300 行）

  2. 应用 ${refactor_types} 中指定类型的重构。

  3. 生成重构前后的对比报告：
     - 变更摘要
     - 代码质量指标改善情况
     - 潜在问题警告

  4. 确认重构后的代码仍能通过既有测试。

output:
  format: report
  include:
    - refactored_files
    - comparison_report
    - test_results

示例 2：自动生成 E2E 测试

只要描述用户场景，即可自动生成 Playwright 或 Cypress 测试代码。

// Skill 生成的 E2E 测试示例
import { test, expect } from '@playwright/test';

test.describe('Product Purchase Flow', () => {
    test.beforeEach(async ({ page }) => {
        await page.goto('https://example.com');
    });

    test('用户可以搜索并购买商品', async ({ page }) => {
        // 1. 登录
        await page.click('[data-testid="login-button"]');
        await page.fill('[name="email"]', 'test@example.com');
        await page.fill('[name="password"]', 'password123');
        await page.click('[type="submit"]');
        await expect(page.locator('[data-testid="user-menu"]')).toBeVisible();

        // 2. 搜索商品
        await page.fill('[data-testid="search-input"]', 'MacBook Pro');
        await page.press('[data-testid="search-input"]', 'Enter');
        await expect(page.locator('[data-testid="search-results"]')).toBeVisible();

        // 3. 选择商品
        await page.click('[data-testid="product-card"]:first-child');
        await expect(page.locator('[data-testid="product-title"]'))
            .toContainText('MacBook Pro');

        // 4. 加入购物车
        await page.click('[data-testid="add-to-cart"]');
        await expect(page.locator('[data-testid="cart-badge"]'))
            .toContainText('1');

        // 5. 结账流程
        await page.click('[data-testid="go-to-cart"]');
        await page.click('[data-testid="checkout-button"]');
        await page.fill('[name="card-number"]', '4111111111111111');
        await page.fill('[name="expiry"]', '12/25');
        await page.fill('[name="cvc"]', '123');
        await page.click('[data-testid="pay-button"]');

        // 6. 确认支付完成
        await expect(page.locator('[data-testid="order-confirmation"]'))
            .toBeVisible();
        await expect(page.locator('[data-testid="order-number"]'))
            .toHaveText(/ORD-\d{8}/);
    });
});

🎓 进阶使用技巧

Skills 链式调用

可以将多个 Skills 串联起来，实现复杂的工作流自动化：

name: full-feature-pipeline
description: 从功能开发到部署的全流程自动化
version: 1.0.0

steps:
  - skill: create-api-endpoint
    params:
      resource_name: ${feature_name}
      methods: ${http_methods}

  - skill: generate-tests
    params:
      target: ${previous_output.files}
      coverage_threshold: 80

  - skill: generate-documentation
    params:
      files: ${previous_output.files}
      format: openapi

  - skill: code-review
    params:
      files: ${previous_output.files}
      strict_mode: true

  - skill: create-pr
    params:
      title: "feat: Add ${feature_name} API endpoint"
      description: ${previous_output.summary}
      reviewers: ${team_members}

✅ 最佳实践与技巧

高效编写 Skill 的指南

  1. 明确目的：每个 Skill 都应只承担一个明确的目标。
  2. 指令具体：相比模糊的指令，具体的分步骤描述能带来更好的结果。
  3. 包含验证环节：在 Skill 中加入验证生成代码是否正确的步骤。
  4. 错误处理：明确列出可能的错误情况及处理方式。
  5. 文档说明：为 Skill 本身提供说明文档和使用示例。

🔧 问题排查指南

常见问题与解决方案

问题 1：Skill 生成的结果不符合预期

原因：指令含糊或上下文信息不足

解决方案：

  • 在指令中加入更具体的示例
  • 明确要求参考项目既有的代码风格
  • 按步骤添加验证检查点

问题 2：Skill 运行超时

原因：一次性处理的任务过多

解决方案：

  • 将大 Skill 拆分为多个小 Skills
  • 减小批量大小或按块处理
  • 可并行的任务拆分为独立 Skill
