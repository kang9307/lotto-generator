序論: なぜ6ヶ月単位の整理が2026年に合う解像度なのか

6ヶ月前の2025年11月、LLMの風景は安定して見えました。OpenAIはGPT-5系列が既定で、Anthropicは2025年9月29日にClaude Sonnet 4.5を出した後で、GoogleはGemini 2.x系列のFlashモデルが低価格帯の働き者でした。市場は「スケーリング則が緩み、曲線が平坦化した」と語っていました。その後の6ヶ月で、その段落のほぼすべての前提が崩れています。11月から5月までのウィンドウは初代GPT-4以降で最も忙しいLLMリリースサイクルであり、その速度はAIフルタイムビルダーですら追いつけないほどでした。多くのチームのスタックにはまだ2025年の前提が刺さっており、その分だけ利用可能な品質・コスト・速度を失っている可能性が高いです。

本稿はこの期間の6ヶ月レビューです。主要ラボとオープンウェイトファミリーを漏れなく回し、変化をマトリクスと表で圧縮し、最後に5つの具体的な実務示唆と下半期の展望で締めます。構造は意図的です。企業別 → トレンド → ベンチマーク → アドバイス。マトリクスだけ要るなら大きな表を見てください。背景まで知りたければ通読をどうぞ。本文はどのラボのマーケトーンにも従わず、実務者の意思決定に何が変わったかを基準に書いています。

2026年9月29日の更新では、本文に出てくるモデル名とリリース日を各社の公式発表・ドキュメントで確認し直しました。公開当時の本文には日付の誤りや公式発表で確認できない名前(例: GPT-4.5o、Claude 4.7 Sonnet、Llama 4 7B・30B・200B)が混ざっており、訂正するか確認不可と明記しました。この期間の記録という性格はそのまま残したため、公開後のリリースは末尾の「その後の経過」節にまとめています。

本格的な整理の前に3つのフレームを置きます。第一に、モデル番号は進歩の測定単位ではありません。あるラボの「0.1」は別ラボの「2.0」より大きい跳躍であり得ます。本稿は「実際に何が変わったか」を中心に据えます。第二に、クローズドとオープンウェイトの進歩曲線は今や並行して走っています。一部の軸では差が数週単位に縮まっています。第三に、最も決定的な変化は単一モデルのリリースではなく、周辺スタックです。エージェントハーネス、コーディングエージェント、メモリプリミティブ、そして事実上の標準として定着したModel Context Protocolがそれです。本文全体でこの点に繰り返し戻ります。

OpenAI: GPT-5.x、Codex Goals、Operatorトラック

OpenAIのこの期間は2つの大きな動きに集約されます。第一はGPT-5系列の連続アップデートです。GPT-5はこの期間が始まる前にすでにリリースされており、期間中は2025年12月のGPT-5.2、2026年4月24日のGPT-5.5(API・Codex・ChatGPTで提供)のようにGPT-5.xのバージョンが続きました。公開当時の本文は「1月末のGPT-5リリース」と書いていましたが、公式発表と合わないため訂正しました。これまでoシリーズに分かれていた推論トラックが、1つの製品の中で思考量を調整する形に統合されたことが、開発者にとって最大の単純化でした。第二はCodex Goalsです。Codexサブ製品を単純なチャット補完から、「高レベル目標を受け取ってリポジトリ上で数時間作業する」自律コーディングエージェントに近いものへ変貌させました。

静かな変化が現場ではより効きます。公開当時、本稿は3月のOperatorスタックの一般公開でコンピュータ使用APIが安定し、Realtime APIにネイティブのツール使用が追加され、メモリ永続性が明示的な保存・取得・忘却プリミティブを持つドキュメント化された表面へ昇格したと整理しました。「アシスタントがセッションを越えて私を覚えている」を作るのが1四半期プロジェクトから1週間プロジェクトに変わったわけです。この段落とCodex Goalsの段階的日程(2月末〜4月)は、2026-09-29にOpenAIの公式ドキュメントで確認し直せなかった当時の記述です。

価格の金額は今回の更新で公式価格表により確認し直せなかったため掲載しません。公開当時の本文は4oファミリーがQ3 2026に終わる予定で段階的に廃止中と書いていましたが、これも当時の見通しとして読むべきです。Codex Goalsの変化自体と日常ループへの組み込み方は、本ブログのOpenAI Codex Goals実践ガイド 2026でより深く扱っています。

Anthropic: Claude Opus 4.5・4.6・4.7とClaude Codeの年

Anthropicは6ヶ月でOpusラインを3回更新しました。2025年11月24日のClaude Opus 4.5、2026年2月5日のClaude Opus 4.6(2月17日にはClaude Sonnet 4.6)、そして2026年4月16日のClaude Opus 4.7です。公開当時の本文は「2025年12月末のClaude 4.6」「2026年3月のClaude 4.7 Sonnet」「2026年5月のClaude 4.7 Opus」と書いていましたが、公式発表の日付と異なるため訂正しました。AnthropicのSonnet発表一覧に4.7のバージョンはありません(4.5 → 4.6 → 5 → 5.5)。公式発表でOpus 4.7は、最も難しいソフトウェアエンジニアリング作業でOpus 4.6より目立って改善し、推論量と遅延のあいだをより細かく選べるxhighの努力レベルが新たに加わりました。各リリースは名前上は漸進的ですが、累積として「エージェントを2時間放っておいて信頼できるか」のカテゴリーでAnthropicの位置を固めました。

モデル周辺でClaude Codeは完成された製品に進化しました。Skills、Hooks、Sub-agents、安定したsettings.jsonスキーマがCLIをパワーユーザーのおもちゃから、チームがコードベース全体に展開するツールに変えました。2024年後半にAnthropicが始めたModel Context Protocolはこの期間に事実上の業界標準のように使われ始め、公開当時、本稿はOpenAI、Google、主要IDEベンダーの大半がMCPをサポートしていると整理しました。プロトコルレイヤを静かに押さえることで、Anthropicはどのモデルを呼ぶかに関係なく開発者ツールスタックの中心に陣取りました。

公開当時の本文は、2026年2月のAndrej KarpathyのAnthropic合流をこの期間の話題として書いていました。2026-09-29にAnthropicのニュースルームでこれを告げる公式発表を見つけられなかったため、本稿はこれを事実と断定せず、マトリクスからも外しました。Claude Code自体の日常活用についてはClaude Code Skills完全ガイドで、4.6と4.7の移行後にも生き残ったパターンを扱っています。

Google: Gemini 3、3.5 Flashと価格戦争

Googleのこの期間の戦略は、最高品質とともに価格対性能での圧力でした。Gemini 2.5系列はすでに2025年中に出ており、2025年11月18日のGemini 3 ProプレビューがGoogleを再びフロンティアの議論の中心に置きました。続いて12月17日のGemini 3 Flashプレビュー、2026年2月19日のGemini 3.1 Proプレビューが出ました。期間のヘッドラインは2026年5月19日に一般提供(GA)されたGemini 3.5 Flashで、Googleはこれをエージェント・コーディング作業で持続的なフロンティア性能を出す最も賢いモデルとして紹介しました。公開当時の本文の「12月のGemini 2.5」「2月のGemini 3.0」「4月のGemini 3.5 Flash」はGemini APIの公式変更履歴と異なるため訂正し、確認できない「200万トークンのコンテキスト」「2.0 Flash比で出力コスト約60%カット」の数値は削除しました。

Google検索のAI Overviewsは「良いアイデアかどうかを議論する段階」から検索体験の恒常的な要素へと位置を移しました。これはモデル自体を超えた含意があります。AIが生成した回答がユーザーと大半のオープンウェブの間に挟まるレイヤになり、2026年のコンテンツ戦略はこのレイヤを先に狙って書かれなければなりません。Googleの開発者表面では5月中旬のI/O 2026発表がGeminiのWorkspace、Android、新Code Assistエージェント階層への統合を予告しました。個別では衝撃的ではありませんが、累積効果はGoogleが再び既定の選択肢に戻ったということです。

価格ポイントは重い自動化を回すチームに最も重要です。LLMを月100万回以上呼ぶ何かを作っているなら、低関与トラフィックの大半はFlashクラスのモデルに送り、フロンティアモデルはマージン品質差がコストを正当化する上位の一部にだけ残すのが妥当、というのが本稿の判断です。この2層パターンが真剣なLLM製品の既定アーキテクチャになり、トレンド節で再び触れます。

Meta: Llama 4とオープン戦略

MetaのLlama 4はこの期間より前の2025年4月5日に発表されました。公開されたモデルはLlama 4 Scout(アクティブ17B・総計109Bパラメータ、エキスパート16、コンテキスト1,000万トークン)とLlama 4 Maverick(アクティブ17B・総計400Bパラメータ、エキスパート128)で、アクティブ288B・総計約2兆パラメータのLlama 4 Behemothは発表当時まだ学習中のプレビューとして紹介されました。公開当時の本文の「12月から4月にわたるLlama 4 7B、30B、200Bのリリース」と「256Kまで安定」はMetaの公式発表で確認できない構成のため訂正しました。

公開当時、本稿はMetaが絶対フロンティアを正面から追うより、「共通サイズで十分に良い」オープンウェイトと自家ホスティングコストの低下を組み合わせて推論ワークロードのシェアを狙っていると解釈しました。これは本稿の解釈であり、この期間のMetaの公式な戦略発表に裏付けられたものではありません。その賭けが効くかは6ヶ月の問題でなく6四半期の問題です。

実務上の教訓も書き直します。公開当時の本文は「Llama 4 30B」を知っておくべきサイズに挙げましたが、そのようなモデルは公式構成にありません。Llama 4の2つの公開モデルはいずれもMoEで、トークンあたりのアクティブパラメータ(17B)は小さくても総重み(109B・400B)をメモリに載せる必要があるため、単一GPUで配備できるかは量子化方式とメモリ容量から別途計算する必要があります。30B級の密モデルが必要なら、下の中国節のQwen3-32Bが公式に確認できる選択肢です。

中国ビッグ3: DeepSeek、Qwen、Doubao

この期間の中国の物語は外部観察者にとって最も驚くべきものです。2025年11月はV4より前の世代がDeepSeekの主力で、2026年4月24日にDeepSeek-V4プレビューが出ました。V4-Pro(総計1.6T・アクティブ49Bパラメータ)とV4-Flash(総計284B・アクティブ13Bパラメータ)の2モデルで、どちらも100万トークンのコンテキストに対応します。公開当時の本文の「2026年2月のV4」「671B MoE・トークンあたり約37B活性」「Q1 2026最多に配備された単一オープンモデル」はDeepSeekの公式発表と合わないため訂正しました(V4は第2四半期に出ました)。V4のライセンス条件は今回確認できませんでした。

AlibabaのQwen3は2025年4月29日にすでに公開されていました。MoEモデルのQwen3-235B-A22BとQwen3-30B-A3B、密モデルのQwen3-32BからQwen3-0.6Bまでで構成されます。公開当時の本文の「2026年3月のQwen 3ファミリー」は日付が合わないため訂正し、「Qwen 3 Coder 32B」というモデル名と「現存最強の小型オープンコーダー」という評価、Alibabaのオープンウェイト推論サービス量の推計は、今回公式資料で確認できなかったため削除しました。ByteDanceのDoubaoはネイティブのクロスモーダル能力で中国語圏市場において重要というのが公開当時の評価でしたが、本文が書いた「2026年4月のDoubao 1.6」のリリース時期は今回公式発表で確認できませんでした。これらのモデルを使うかどうかはデータ扱いの立場に大きく依存しますが、存在しないふりはもはや守れる立場ではありません。全体地形は本ブログのDeepSeek vs Qwen vs Doubao 中国LLM比較 2026で扱っています。

技術的な余談として、DeepSeek V4を対象にしたステアリングベクトル研究が小さくとも意味のある解釈可能性の扉を開いた、というのが公開当時の評価です。実務的含意はLLMステアリングベクトルとDeepSeek V4で扱っています。

xAI: Grok 4、アンダードッグ叙事

xAIのGrok 4はこの期間より前の2025年7月9日に発表されました。公開当時の本文の「2025年11月末のGrok 3が初めてフロンティア圏入り」「2026年4月のGrok 4」は公式発表と合わないため訂正し、期間中のGrok 4後継バージョンの公式発表は今回確認できませんでした。公開当時の本稿の評価は、xAIはミームから抜け出したものの依然として主にXとスタンドアロンの消費者向けアプリで配布され、開発者の既定選択肢になりにくいこと、そして訓練クラスタColossusの規模がモデルに反映されつつあることでした。

実務者の観点で、Grok系列は自前の取得レイヤを作らずにリアルタイムのウェブグラウンディングが要るときの選択肢であり、バックアップモデルとして検討に値します。制約は主に文化的なものです。多くのエンタープライズが調達上の理由でいまだにxAIをXに近すぎるとして扱っています。スタックが既にプロバイダー間でロードバランスするルーターを呼んでいるなら、Grokをオプションに加えるのは数時間で、次のプロバイダー障害に対するレジリエンスを得ます。

Mistral、Cohereと2層の統合

2層のフロンティアラボもこの期間に動きました。Mistral Large 3は2025年12月2日、Mistral 3の発表とともに出ました。アクティブ41B・総計675Bパラメータの疎なMoEで、Apache 2.0ライセンスで公開され、3B・8B・14Bの密モデルであるMinistral 3シリーズが同時に出ました。公開当時の本文の「1月のMistral Large 3」は日付を訂正しました。本文が併せて書いたCodestral 2・Pixtral 2とCohereのCommand R-Plus 2026アップデートは、今回公式発表で確認できませんでした。EU居住インフラと規制対応がMistralの強みで、CohereはエンタープライズRAGに集中しているというのが公開当時の評価です。

2025年末まで対話にあったいくつかの小さな主体は実質的に退いた、というのが公開当時の観察でした。AI21のJambaファミリーは非常に長いコンテキストだけが必要なニッチ選択肢になり、Inflectionはフロンティア消費者向けモデルからピボットし、Rekaほか数社は技術的に興味深い仕事を出し続けているもののベンチマーク上位では競っていません。市場はOpenAI、Anthropic、Google、Meta(オープン)、DeepSeek、Alibaba/Qwen、xAI程度に絞られ、MistralとCohereは強い地域・垂直オプションとして残る、というのが本稿の判断です。

ローカルLLM: Llama.cpp、Ollama、vLLM、MLX

ローカルと自家ホスティングの生態系は速く動きました。Llama.cppがVulkanとROCm経路を強化し、NVIDIA専用の前提が弱まりました。Strix Halo PC(AMDの高メモリAPUプラットフォーム)で大きなモデルを実用速度で動かすことが1つの製品カテゴリになりました。Ollamaが主流の開発者ツールに進入し、安定したモデルレジストリとIDE統合を備えました。vLLMはバッチングと投機的デコーディングの改善で本番配備の推論コストを下げ、AppleのMLXはM系列Macを30B〜70Bパラメータ帯のメモリ対価格が良いローカル推論オプションにしました。統合メモリに余裕のある最新のMacならQwen3-32Bのような30B級モデルを無理なく載せられる、というのが公開当時の評価です。この節に出てくるvLLM・MLXのバージョン番号と機器仕様は、今回公式ドキュメントで確認し直せませんでした。

組み合わせ効果は低関与LLMトラフィックの実質シェアがAPIから離れていることです。個人ノートアシスタント、IDEのオートコンプリート、チーム文書の要約など、データ感度、レイテンシ、コストが絶対フロンティアより重要な作業がローカル推論へ移りつつあります。ハードウェア全体地形は本ブログのローカルLLMハードウェア選択ガイド 2026で扱っています。

AIコーディングツール: Cursor、Claude Code、Codex、Aider、Cline

AIコーディングツールは半期で最も速く動いたサブカテゴリでした。Cursorのエージェントモードがマルチファイルリファクタリングを安定処理する何かに成熟しました。Claude Codeは本格的な自律コーディングワークフローの支配的CLIツールになりました。公開当時の基準では、30分以上かかるタスクを回すならClaude Opus 4.7を使うClaude Codeが既定でした。OpenAI Codexサブ製品のCodex Goalsは最強のワンショット生成表面です。モデルの出力を見て素早く調整するタイトな反復ループでは勝ちにくい相手です。

Aiderはオープンソースのベースラインとして強さを維持し、ClineはIDEを離れずインエディタ体験を望む開発者向けにVS Code統合エージェントのニッチを埋めました。本稿の評価はどの単一ツールもすべてのワークフローを支配しないです。インエディタのペアプログラミングはCursor、長い自律タスクはClaude Code、ワンショット生成はCodex、完全検査が要るときはAiderをオープンフォールバックに。3ヶ月比較は本ブログのClaude Code vs Codex 3ヶ月レビュー 2026でローテーションパターンを詳細に扱っています。

6ヶ月の核心トレンド

個別ラボから一歩引くと、4つのトレンドがこの期間を定義します。

エージェントAIがデモから本番へ移りました。半期中のフロンティアモデルリリースに共通する特徴は、より長く、より安定した自律チェーンでした。Claude Opus 4.7で長い自律コーディングセッションが現実的になり、GPT-5.xとGemini 3系列でモデルが自分で計画を提案・ブラウジング・要約・反復するマルチステップ研究が動きます。残った失敗モードは本物ですが本番使用を妨げません。

推論モデルが別製品カテゴリから消えました。oシリーズはGPT-5系列の思考量調整の中に入り、Claudeはモデル自身が思考量を決める方式へ移り、Gemini 3系列も内部推論を既定で使います。過去1年ユーザーを混乱させた「思考モデル」トグルはほぼ消え、その単純化自体が品質改善です。

マルチモーダルが標準装備になりました。ビジョンはフロンティアモデルで動き、音声入出力は標準、ビデオ理解は上位ラボ全般で有能です。差別化要素はもう「マルチモーダルがあるか」ではなく「マルチモーダル入力とツール使用をどれだけ良く編むか」です。

30B級で「より小さくてより良い」が本物です。Qwen3-32BとQwen3-30B-A3B、より小さなDeepSeek蒸留がこの範囲にあり、実際にフロンティアIQが要らないタスクの相当部分を処理します。この帯域が配備頻度ベースで最大の受益者だというのは本稿の観察であり、測定資料ではありません。

ベンチマークの変化: MMLU飽和、SWE-bench急増

ベンチマーク地形も実質的に変わりました。公開当時、本稿はMMLUが事実上飽和してフロンティアモデルが88〜91の間に集まり、SWE-benchの上位スコアは6ヶ月で約2倍(2025年11月の49%から2026年5月のVerified 90%超)に跳ね、GPQAの上位スコアは60台前半から70台後半に移動したと書きました。これらの数値は2026-09-29に公式リーダーボードで確認し直せなかった当時の記述なので、引用するならSWE-benchなど元のリーダーボードを直接確認してください。ARC-AGI系列は依然として最も難しい公開ベンチマークとされ、ラボが最も可視的に競う場所です。

ベンチマークを読むエンジニアへの教訓は、SWE-benchが「このモデルはコーディングに良いか」を問う最も有用な単一の数字に近く、MMLU性能と実世界の有用性の差が大きいということです。あるモデルがMMLUで高得点を取りつつ本番デバッグで失敗することがあります。ベンチマーク数値は常に自分のワークロードに対するタスク別評価とともに見るべきです。

開発者が内在化すべき5つの示唆

6ヶ月の絵から圧縮された助言です。

  1. コーディングツールを最低2つローテーションしてください。Claude Code + Codex、またはClaude Code + Cursorが最もレジリエントなパターンです。失敗モードが違い、1つのプロバイダーが障害でも作業が続きます。
  2. 2層ルーティングレイヤを立ててください。トラフィックの60〜80%をGemini FlashまたはClaude Haikuクラスに送り、本当に必要な呼び出しにだけフロンティアモデルを予約します。比率は本稿の推奨なので、自分の呼び出し分布に合わせて調整してください。
  3. モデルを1つはローカルで回してみてください。M系列Macまたは高性能GPUを積んだワークステーションで30B級モデルはオフライン作業、機微データをカバーし、「このタスクはAPIなしで可能か」の基準を与えます。
  4. MCPを既定として扱ってください。Model Context Protocolは新しい「AIのためのREST」に近い存在です。ChatGPT、Claude、Geminiにそれぞれ独自統合を作る前に、MCPサーバ1つでつなげられるかをまず確認してください。
  5. ベンチマークを四半期ごとに再評価してください。11月の評価で勝ったモデルは今日2層の可能性が高いです。最低四半期ごとに評価スイートを回し、目を開けたまま新しい既定を選んでください。

2026年下半期の展望(執筆当時)

以下は2026年5月の執筆当時の展望です。検証済みの予測ではなく当時の見通しであり、実際に確認された下半期のリリースは「その後の経過」節にまとめました。

第一に、エージェントシステムがパワーユーザーの既定UIになります(当時の見通し)。UI進化はチャットボットが2023年に経たものと似ています。Q1で実験的、Q4で主流。年末までに主要ラボがオプトインベータではなく既定製品の一部としてエージェント表面を出すと予想していました。

第二に、モデル差別化の軸が純粋IQからメモリ、ツール使用、タスク単価へ移ります(当時の見通し)。競争は周辺スタックへ移り、メモリを最初にうまく解くラボが消費者マインドシェアの意味あるシェアを取る可能性が高いと見ていました。

第三に、オンデバイスとラップトップクラスの推論が低関与トラフィックの大きなシェアを静かに取ります(当時の見通し)。M系列MacとStrix Halo PCが30〜70Bモデルを実用速度で回すことで、消費者使用の相当部分がAPIから離脱すると見ていました。低価格ティアAPI収益には悪く、ユーザープライバシーには良い話です。

下半期のロードマップを立てるなら、この3つを念頭に置きつつ「次のモデルを待とう」の罠を避けてください。必要な能力はすでに今日回せるスタックに入っています。

結論: 6ヶ月の構造的シフト

11月から5月までのウィンドウはもう1つのアップグレードサイクルではありませんでした。エージェントシステムが本物になった時点、オープンウェイトが意味ある軸でフロンティアの差を縮めた時点、価格がアーキテクチャパターンを変えるほど落ちた時点、そしてMCPがツールの建つ標準レイヤとして定着した時点でした。そのいずれか1つでも平年1年分の進歩です。4つが同時に起こったことが本期間を構造的シフトにします。

ビルダーの実用的姿勢はサイクル初期から変わりません。ツールに近くいて、最低2つをローテーションし、四半期ごとにスタックを評価し、完璧な既定が出てくるのを待つ誘惑に抵抗してください。フロンティアはそれが可能なほどゆっくりは動きません。ビルダーの競争優位は使えるピースを本物の問題を解く何かにどれだけ速く組み合わせるかにあり、どのラボのロゴがAPI呼び出しに刻まれているかにはありません。マトリクスを読み、算盤を回し、次のものを出荷してください。
