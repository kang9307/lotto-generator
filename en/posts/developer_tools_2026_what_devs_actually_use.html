Introduction: The 2026 Developer Tooling Landscape

Asking a developer "what tools do you use?" is never just idle curiosity. The answer is a window into their workflow, their values, and how they spend their day. When a thread titled "What are your favorite developer tools?" climbed to 38 points and sparked a lively discussion on the Korean tech community news.hada.io in late May 2026, it was for exactly this reason. Engineers love to show off their setup, and they are endlessly curious about what everyone else is running.

But the 2026 tooling landscape is decisively different from just two or three years ago. The biggest change is that AI is no longer a separate category; it has soaked into almost every category. Editors now carry AI autocomplete and agents, terminals suggest commands, and AI features are arriving in database clients too. "Do you use AI tools?" is now about as meaningful a question as "do you use an editor?" The real question has shifted to "which tools, at what depth, combined how?"

This article is a category-by-category guide built to answer that question. We will walk through ten tool categories in turn -- code editors, AI coding, terminals, version control, API/HTTP, containers, databases, notes, monitoring, and utilities -- then cover what is distinctive about the Korean development environment, five principles for choosing tools, and finally which category of tool fits which situation. The goal is not to rank popularity but to explain why each tool earns its place, so that you can reason about your own choices rather than copy someone else's.

Usage figures appear only where a source could be confirmed. As of 2026-09-29, the most recent large public survey with published results is the Stack Overflow 2025 Developer Survey (collected in 2025, about 49,000 respondents). The official Stack Overflow blog announced that the 2026 survey opened for responses on June 23, 2026, but its results could not be found during this check. All figures below are shares of all respondents to multiple-answer questions.

1. Code Editors - VS Code, Cursor, Zed, Neovim, JetBrains

Every workflow centers on an editor. The 2026 editor landscape resolves into a clean shape: VS Code as the default, surrounded by AI-era challengers.

VS Code is still the default. In the IDE question of the Stack Overflow 2025 survey, 75.9% of all respondents said they use VS Code. Its enormous extension ecosystem, stability, and the ability to bolt on AI extensions (Copilot, Claude Code integration) keep it a safe option for organizations that need a team standard.

Cursor, built as a VS Code fork, keeps extension compatibility while treating AI as a first-class citizen of the editor itself. In the same survey Cursor stood at 17.9%. At publication this article said Cursor had gained share faster than anyone, but no primary source showing the growth rate could be confirmed, so that claim was removed. One name needs care. At publication this article introduced Composer as the name of a multi-file editing feature; on October 29, 2025, the official Cursor blog announced its own agent model under the name Composer. When reading about it, check whether a source means the feature or the model.

Zed is an open-source editor written in Rust; its official site calls it "a minimal code editor crafted for speed and collaboration with humans and AI." It now offers downloads for macOS, Linux, and Windows, and says external agents such as Claude Agent, Codex, and OpenCode can run inside the editor through the Agent Client Protocol (ACP). In the same survey Zed was at 7.3%, Neovim at 14%, and IntelliJ IDEA at 27.1%. Neovim remains the pick of terminal-first developers, and distributions like LazyVim have dramatically lowered the barrier to entry. JetBrains (IntelliJ, PyCharm, GoLand, and the rest) is used for large enterprise Java/Kotlin and for work that depends on precise refactoring and debugging.

2. AI Coding - Claude Code, Codex, Cursor, Copilot, Aider

This is the fastest-changing category of 2026. The key insight is not "which one is best" but that the right category differs by task type. There are three broad branches: agentic tools that take instructions and change many files across a repository, editor-integrated tools where you edit while watching changes inside the editor, and autocomplete tools that suggest the next piece of code as you type. As the paragraphs below show, the lines have blurred because single products now cover several branches.

Claude Code is an agentic tool that started in the terminal and is used for large multi-file refactors, codebase exploration, and automating repetitive work. Its official documentation now lists the terminal CLI, IDE extensions (VS Code and JetBrains), a desktop app, and the web, and says most surfaces require a Claude subscription or an Anthropic Console account. OpenAI Codex has moved the same way: OpenAI documentation lists a desktop app, the web, a CLI, an IDE extension, a cloud environment, and GitHub integration. The two tools this article filed under "terminal agents" at publication now span several surfaces. Moving existing prompts and settings to a new model is covered separately in What Happens When You Carry Over Opus 5 Settings, and letting an agent do the planning in Is Plan Mode Dead?

Cursor fits cases where you want to keep context inside the editor and watch changes apply visually. GitHub Copilot has a free plan (Copilot Free) and several paid plans, and GitHub documentation states that agent mode is included starting from the free plan. Describing it only as a "lightweight, autocomplete-first assistant," as this article did at publication, is now too narrow. Aider is a minimal, Git diff-based CLI tool that records changes as commits. However, the latest release on its GitHub releases page is v0.86.0 from August 9, 2025, and no later release had appeared as of the 2026-09-29 check. If you are adopting it now, checking the repository's recent activity first is the safer move.

Practical tip: AI coding rarely ends with one tool. Split your work by category -- agentic tools for large jobs that touch the whole repository, editor-integrated tools for edits you want to watch, autocomplete for typing assistance -- and the gaps become visible. If you run several agent tasks at once in one repository, the Practical Guide to git worktree, which covers splitting work into separate folders, helps.

3. Terminals - Warp, Ghostty, iTerm2, Alacritty

Terminals were a stagnant category for a long time, but the last few years have brought big changes. Warp drew attention as the tool that "redesigned the terminal" with a block-based UI and AI command suggestions, and its official site now describes it as "the agentic development environment." It started as a terminal and has shifted its weight toward being a place to run agents. Ghostty, a GPU-accelerated terminal that emerged in 2024 and 2025, is described in its official docs as a terminal emulator that is "fast, feature-rich, and native," and currently supports macOS and Linux.

iTerm2 is the long-standing standard among macOS users, prized for its deep feature set and stability, and Alacritty is the Rust-based minimal GPU terminal chosen by people who want fast and simple, nothing more. Terminal choice ultimately comes down to speed, customization freedom, and how well it pairs with your tmux and shell configuration.

4. Version Control - Git, GitHub, GitLab, Jujutsu (jj)

The foundation is unchanged: Git. In the code documentation and collaboration tools question of the Stack Overflow 2025 survey, GitHub was at 81.1% and GitLab at 35.6% (the question is not about hosting alone). Organizations that need self-hosting and integrated CI/CD sometimes choose GitLab. The tool worth watching is Jujutsu (jj); its official repository calls it "a Git-compatible version control system that is both simple and powerful." As of 2026-09-29 the latest version on its GitHub releases page is 0.45.1, still before 1.0.

The appeal of jj is that every change is committed automatically, and conflict resolution and history rewriting are far more intuitive. Because it is still pre-1.0, it needs a trial before becoming a team standard, but if you are worn down by Git's tangled command surface, it is worth a try.

5. API/HTTP - curl, Postman, Insomnia, Bruno

API testing and HTTP requests are daily bread for backend and full-stack developers. The lightest tool is still curl. A one-line curl command is the most efficient way to fire a quick request, but as the flags pile up, writing the command becomes error-prone. At that point a free online tool like the BrainDetox curl Builder lets you assemble headers, method, and body options visually and copy the command directly, cutting down on mistakes.

When you need a GUI, Postman offers broad team collaboration and collection-sharing features, but after its plans changed to Free, Solo, Team, and Enterprise in March 2026, its documentation states that the Free plan is limited to one user and cannot create a team. Two or more people sharing collections for free now requires a paid plan. The open-source, local-first Bruno has an open-source edition and paid editions (Pro and Ultimate), and its pricing table lists in-app Git integration (Native Git Integration) under the paid editions. Insomnia has a free plan (Essentials) and offers a local-only Scratch Pad that works without logging in.

6. Containers / Orchestration - Docker, Podman, k9s, Lens

Containers are now a baseline, not a choice. In the Stack Overflow 2025 survey, 71.1% of all respondents said they use Docker. Some environments use Podman for its daemonless, rootless architecture and licensing terms. At publication this article said there was a clear drift toward Podman with adoption rising in enterprises, but no primary source showing that could be confirmed, so the claim was removed.

If you work with Kubernetes, the terminal-based cluster manager k9s is widely used. Navigating pods, logs, and resources entirely by keyboard suits terminal-centric operations. If you prefer a GUI, Lens is convenient for multi-cluster management.

7. Database Tools - DBeaver, TablePlus, DataGrip

Database clients are a strongly opinionated space. DBeaver is free, open-source, and supports nearly every DBMS, making it the general-purpose client. TablePlus draws macOS users with a fast, clean UI that is especially pleasant for light work. DataGrip is the natural choice inside the JetBrains ecosystem, with precise SQL autocomplete and refactoring as its strengths. On October 1, 2025, JetBrains announced on its official blog that DataGrip is free for non-commercial use such as learning, hobby or open-source projects, and content creation. Commercial use still requires a paid license.

As the DataGrip announcement lists AI-powered code completion among its features, AI capabilities such as natural-language query generation and schema explanation are arriving in database tools. The scope of support per tool was not checked this time. The shift underway is that time spent hand-writing SQL is shrinking, while time spent reviewing and refining grows.

8. Notes / Docs - Obsidian, Notion, Logseq

Knowledge management is the hidden axis of productivity. Obsidian, built on local Markdown files plus powerful linking and graph features, is used by developers who value data ownership. Since February 20, 2025, its commercial license has been optional, so anyone can use it for work for free (official Obsidian blog). Its vast plugin ecosystem lets you customize almost any workflow.

Notion is the all-in-one that gathers team collaboration, databases, and wikis in one place, strong for teams that want to unify docs and project management. Logseq is an outliner-based open-source tool specialized in daily notes and bidirectional-link thinking. The deciding factors come down to "who holds my data" and "solo versus team."

9. Monitoring / Debugging - Sentry, Datadog, Grafana

If you run anything in production, observability tools are essential. Sentry is a widely used tool for error tracking and performance monitoring, collecting exceptions and stack traces quickly with minimal setup. Datadog is the integrated platform spanning infrastructure, APM, logs, and security, serving as the comprehensive observability hub for larger organizations.

Grafana is the heart of open-source visualization, paired with Prometheus, Loki, and friends. It is the core tool for infrastructure and SRE engineers who want to build their own metric dashboards. If you want to avoid cost and lock-in while keeping direct control, an open-source stack such as Grafana plus Prometheus fits; if you want fast SaaS integration, an integrated platform such as Datadog fits.

10. Utilities - JWT Decoder, JSON/YAML Conversion

There are small tools you do not use every day but sorely miss when they are gone: cracking open a JWT payload, converting JSON to YAML and back, or quickly checking what an HTTP status code means. Firing up a heavy IDE or a separately installed tool for these is inefficient.

As lightweight, free online alternatives, BrainDetox offers a JWT Decoder, a YAML/JSON Converter, an HTTP Status Codes reference, and a JSON Formatter that handle these tasks instantly in the browser. Choosing tools that run client-side -- no install, no sending your data to a server -- is also the safer choice from a security standpoint.

11. Tools Korean Developers Favor

Separate from global trends, the Korean developer ecosystem has its own environment. First, for collaboration messaging, alongside Slack, domestic tools like KakaoWork and JANDI are used in corporate settings. Second, for issue tracking, Jira has long been in use (46.4% of worldwide respondents in the Stack Overflow 2025 survey), and some startups use Linear or Notion. No public survey showing tool shares for Korea alone could be confirmed this time.

Third, Korean developer communities (news.hada.io, OKKY, Inflearn) are central channels for sharing tool information and a route by which new tools become known domestically. Fourth, because many environments restrict cloud SaaS for security reasons, local, open-source, and on-premises alternatives (self-hosted GitLab, local LLMs, and so on) often make the shortlist. At publication this article said this interest was higher than the global average, but no comparison figure could be confirmed, so that was removed. The importance of asking "where does my data go" when choosing tools remains.

12. Five Principles for Choosing Tools in 2026

You do not choose tools by popularity ranking. Here are five principles that start from your own bottlenecks.

  1. Respect the inertia of familiarity, but re-evaluate once a year. A tool you know by hand is a powerful asset, but without a periodic review of your core tools you will permanently miss better alternatives.
  2. Count the integration cost. Before adding a tool, check whether your existing tools already solve the problem. More tools mean more context-switching overhead.
  3. Guard against lock-in. Prefer data export and open formats. Once your data is tied to a single vendor, you lose the freedom to switch.
  4. Separate team standards from personal preference. Tools that affect collaboration (VCS, CI, issue trackers) should follow the team standard; personal productivity tools (editor, terminal, notes) can follow taste.
  5. Try free and open-source alternatives first. Validating your requirements on a free option before paying means you only spend money on the features you truly need. Free-plan limits on seats and features can change (as with Postman in March 2026), so check the current terms before adopting.

13. Conclusion: Which Category Fits Which Situation

In the end, a good stack is not the sum of trendy tools but the combination that removes the most friction from your own workflow. The moment the tool itself becomes the goal, you fall into the trap of spending all your time configuring tools instead of building the thing you set out to build. You do not need to fill all ten categories above. Optimize, one at a time, starting from where you most often get stuck.

Instead of picking specific products, here is which category of tool is used in which situation. Names in parentheses are examples from this article, not a ranking.

  • Editor: a general-purpose editor when team standards and the extension ecosystem matter (VS Code), an AI-integrated editor when AI-driven editing is a large share of work (Cursor, Zed), a full IDE for large Java/Kotlin projects (JetBrains)
  • AI coding: agentic tools for repository-wide work, editor-integrated tools for edits you watch on screen, autocomplete for typing assistance; first check which branches your product already covers
  • Terminal: a lightweight GPU-accelerated terminal when speed and simplicity come first, an agentic development environment when you want agent runs on the same screen, and a multiplexer such as tmux for session persistence
  • Version control: Git plus hosting (GitHub, GitLab); a Git-compatible VCS for experimenting with new workflows (jj, pre-1.0)
  • API: curl for one-off requests (plus an online curl Builder); if several people need a GUI, check the seat limits of free plans first
  • Containers: a container runtime for local development (Docker, Podman), a terminal UI (k9s) or GUI (Lens) for Kubernetes operations
  • DB: a general-purpose client when one tool must cover many DBMSs; for IDE-grade features in non-commercial use, check DataGrip's free terms
  • Notes: local-file-based tools when data ownership comes first (Obsidian), an all-in-one when team wikis and project management come first (Notion)
  • Monitoring: error tracking (Sentry) plus a self-controlled metrics stack (Grafana/Prometheus) or an integrated SaaS platform (Datadog)
  • Utilities: browser-based tools that do not send your data to a server (JWT decoder, JSON/YAML conversion, and the like)

This is not a list to copy verbatim. The point is the mindset of starting from "what do I get stuck on" rather than "what is everyone else using." The 2026 toolbox is richer than ever, and thanks to AI the boundaries between categories have blurred. That means more freedom of choice, which is exactly why it matters more than ever that you can explain to yourself why each tool earns its place.

## 2. Pre-adoption checklist

- [ ] Checked seat limits on the free plan (Postman Free: one user and no team creation since the March 2026 plan change)
- [ ] Checked which AI features the free plan includes (GitHub docs: agent mode is included in Copilot Free)
- [ ] Checked commercial vs non-commercial terms (DataGrip free for non-commercial use since 2025-10-01; work use needs a paid license)
- [ ] Checked the license for work use (Obsidian's commercial license optional since 2025-02-20)
- [ ] Checked supported OSes (Ghostty: macOS, Linux / Zed: macOS, Linux, Windows)
- [ ] Checked whether an account or subscription is required (most Claude Code surfaces need a Claude subscription or Anthropic Console account / Insomnia Scratch Pad needs no login)
- [ ] Checked which edition includes an in-app feature (Bruno pricing: Native Git Integration listed under Pro and Ultimate)
- [ ] Checked the repository's latest release (Aider latest release v0.86.0, 2025-08-09, none after it as of the check)
- [ ] Checked version maturity (jj latest 0.45.1, pre-1.0)
- [ ] Distinguished a feature name from a model name (Cursor's Composer is the name of its own agent model, announced 2025-10-29)
- [ ] Checked whether data leaves for an external server
- [ ] Collaboration tools (VCS, CI, issue tracker) follow the team standard; only personal tools follow taste
