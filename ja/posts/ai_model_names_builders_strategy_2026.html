序論: 半年で登場したAIモデル一覧を見てため息が出たら

2025年から2026年春までの間だけでも、GPT-5（既定スナップショットgpt-5-2025-08-07）、Llama 4（2025年4月5日発表）、Qwen3（2025年4月29日）、Mistral Large 3（v25.12）、DeepSeek-V4（2026年4月24日）が次々に登場し、ClaudeはOpus 4.x世代、Geminiは3.x世代へと進みました。ここにmini、flash、lite、instructといった派生ラベルを足すと、追うべきモデル名はすぐに数十に達します。毎週X(Twitter)のタイムラインは「今週のモデルがこれまでの最高モデルを超えた」という投稿とベンチマーク棒グラフで埋め尽くされます。ビルダーがこの流れに普通についていけるのか、という問いを真剣に投げかけるべき時です。

本記事の出発点は一文です。「モデル名を覚えるのが本業ではない」。ビルダーの本業は何かを作ることであり、モデルはその道具です。ところが道具のスペック表を覚えるのに時間を吸い取られて、作る時間が消えているなら本末転倒です。本記事ではその問題意識を整理し、ビルダーがモデル爆発時代を生き抜くための5つの学習戦略、5つのアンチパターン、そして実務での時間配分ガイドを提示します。

2026年9月29日の更新では、本文のモデル名を各ベンダーの公式ドキュメントで確認し直しました。公開当時の本文には公式ドキュメントで確認できない名前（例: Llama 4 7B・70B）が混じっており、これ自体が名前の追跡がいかに間違えやすいかを示す例になっています。

1. AIモデル名を全部覚えるのが罠である3つの理由

1-1. 毎月変わる - 持続不可能

各ベンダーはほぼ四半期ごとに新しい名前を出します。OpenAIだけ見てもGPT-4 Turbo、GPT-4o、GPT-4o mini、o1-preview、o1-mini、o1、o3-mini、o3が続いたあとGPT-5ファミリーで再編され、2026年9月現在の公式モデルドキュメントの主力はGPT-6 Astra・Sol・Lunaに変わりました。AnthropicはClaude Opus 4.5 → 4.6 → 4.7 → 4.8 → 5 → 5.5とバージョンを上げながらFableという新しい等級まで加え、GoogleはGemini 3.1 Pro・3.5 Flash・3.8 Flashのように等級ごとにバージョン番号が別々に動いています。全モデル名を覚えるのは砂浜に絵を描くようなものです。次の波がすべてを消します。

1-2. 名前は能力のシグナルではない

「Llama 4」という名前だけ見て、前の世代よりすべてのタスクで強いと推定するのは危険です。名前は構成すら教えてくれません。Llama 4として公開されたScoutとMaverickはアクティブパラメータがともに170億ですが、エキスパート数は16と128、総パラメータは1,090億と4,000億で異なります（Meta発表、2025年4月5日）。同じ世代名の下でもサイズと構造はこれほど分かれ、日本語や韓国語のような非英語タスクでは英語ベンチマークの順位がそのまま当てはまる保証はありません。名前・バージョン・パラメータ数が自分のタスクでの順位と一致する保証はありません。結局、自分のタスクで直接比較しないと分かりません。

1-3. 時間ROIが低すぎる

正直に時間を換算してみましょう。毎日30分、新モデルの話題とリリースノートをざっと見るとして月15時間。同じ時間を実プロジェクトに使えば、RAGパイプラインを一つ完成させ、自前の評価スクリプトを二つ書けます。ビルダーの時間は本業に投資してこそ複利で積み上がります。モデル名を覚える時間はそうではありません。

2. ビルダーが本当に学ぶべきもの - 名前ではなく5つの能力軸

本記事が勧める最も実用的な抽象化は5つの能力軸です。名前を覚える代わりにこの5軸で考えます。

能力軸 代表的なベンチマーク 実務上の意味
推論(Reasoning) MMLU, GPQA, ARC-AGI 複雑な思考・多段階問題解決
コード(Code) SWE-bench, HumanEval, LiveCodeBench 実コード作成・デバッグ・リファクタの品質
マルチモーダル MMMU, ChartQA, VideoMME 画像・音声・動画入力の処理
コンテキスト長 RULER, Needle-in-Haystack 長文書・コードベース丸ごとの入力
レイテンシ&コスト tok/s, $ / 1Mトークン リアルタイム応答・大量バッチ処理コスト

新モデルが発表されたとき、最初に問うべきは「名前は?」ではなく「この5軸のどこが強いか?」です。これだけで比較作業が1時間から1分に縮みます。

3. 戦略1: モデル名でなく「ベンチマークカテゴリ」で学ぶ

具体的なスコアでなくベンチマークカテゴリだけ覚える方がずっと長持ちします。スコアはすぐ変わりますが、カテゴリは何年も持ちます。

  • MMLU: 一般知識と幅広い学問領域。「このモデルは賢いか」の基本指標。
  • GPQA Diamond: 博士級推論。フロンティアモデル選別用。
  • SWE-bench Verified: 実GitHubイシュー解決。コーディングアシスタントの本当の実力。2026年9月29日時点でswebench.comにはVerifiedのほかLite・Full・Multimodal・Multilingual・Bash Onlyの各版が掲載されています。
  • ARC-AGI: 抽象推論。新規パターンの一般化能力。現在はARC-AGI-1・2・3に版が分かれ、ARC Prize 2026はARC-AGI-3とARC-AGI-2の競技を並行して開催します。カテゴリ名はそのままで版だけが変わる好例です。
  • HumanEval / MBPP: 単一関数生成。入門コード能力。
  • MMMU: マルチモーダル総合。
  • MT-Bench / Arenaの順位: 人手評価。実ユーザー満足度に最も近い。LMSYS Chatbot ArenaはLMArenaを経て、2026年9月現在Arena（arena.ai）という名前とアドレスを使っています。

この7カテゴリさえ頭にあれば、どんなモデルが出ても「ああ、これはSWE-benchが強いコーディング寄りだな」と数秒で位置付けられます。

4. 戦略2: モデルを「Tier」で抽象化する (Frontier / Production / Local / Edge)

本記事が最もよく勧める抽象化は4-Tierです。新モデルは必ずこの4つのどれかに割り振ります。

Tier 特徴 代表例（2026-09-29 公式ドキュメントで確認） 主用途
Frontier 最高性能・高コスト・高レイテンシ Claude Fable 5.1・Claude Opus 5.5, GPT-6 Astra, Gemini 3.1 Pro（プレビュー） 難推論・研究・重要意思決定
Production バランス型・中コスト・適度な速度 Claude Sonnet 5.5・Claude Haiku 4.5, GPT-6 Luna, Gemini 3.8 Flash 大量APIワークロード・チャットボット・RAG
Local オープン重み・自社ホスト・中品質 Llama 4 Scout・Maverick, Qwen3-32B, DeepSeek-V4-Flash, Mistral Large 3 プライバシー・オフライン・大量バッチ
Edge 小型・高速・オンデバイス Gemini Nano（Android AICore）, Ministral 3 3B, Qwen3-0.6B〜4B モバイル・組込・リアルタイム音声

表の例は、各ベンダーが公式ドキュメントでそのモデルに付けた説明（最も高性能、速度と知能のバランス、最も効率的、オープン重みなど）に従って入れたもので、ベンダー間の優劣を意味しません。公開当時の表にあったClaude 4.7 Sonnet、Gemini 3.5 Ultra・3.5 Pro、Llama 4 70B・3Bは、2026年9月29日に公式ドキュメントで確認できなかったため削除しました。

モデル名が50個でもTierは4つだけ。名前は忘れていいですが、Tierは忘れてはいけません。「Llama 4が出た」だけでは判断できませんが、「Local Tierに新候補追加」と分類しておけば、次にRAGバックエンド入れ替えを検討するときの一行メモで十分です。

5. 戦略3: 自分のユースケース1〜2件に絞ってベンチマークする

全モデルを比較しようとしないでください。自分が実際に作っているものに対してのみ自前ベンチマークするのが最大ROIです。たとえば「日本語の法務文書要約を100件まとめて処理」がユースケースなら、その入力で5モデルを回せば終わりです。

最小限の自前ベンチマーク構成

1) 実入力30〜50件をJSONで用意 → 2) 同一プロンプトで5候補モデルに順次呼出 → 3) 出力を盲検でA vs Bペア比較 → 4) Eloスコア累積 → 5) 結果を表に整理。土曜午後の3時間で十分です。

この結果はSNSで誰かが自慢するスコアよりはるかに、自分の意思決定に役立ちます。公開ベンチマークは日本語性能、自分のドメイン語彙、自分のプロンプトスタイルを反映しません。

6. 戦略4: 絶対価格でなく「価格変化のトレンド」を追う

モデル別のトークン単価を覚えても意味がありません。頻繁に変わるからです。代わりに追うのはトレンドです。数字は覚えず、次の問いへの答えを方向だけ覚えておけば十分です。

  • 「直近半年でFrontier Tierの入力トークン単価は下がったか、上がったか、横ばいか」
  • 「自社ホストしたLocal Tierモデルの単位コスト（GPU償却込み）は、いま使っているクラウドAPIより安いか高いか」
  • 「画像1枚の入力はテキスト何トークン分として課金されるか - ベンダーの料金ページで計算方法だけ確認」

公開当時ここにあった数値（Frontier単価35%下落、自社ホストでクラウドの約1/8、画像1枚1〜5Kトークン相当）は出典を確認できなかったため、2026年9月29日の更新で削除しました。方向単位の記憶は長く有効です。具体額は忘れて勾配だけ覚えておけば、次にどんなモデルが出てもコスト感覚は狂いません。

7. 戦略5: 信頼できる1〜2ソースだけフォローし、残りは切る

ビルダーが陥りやすい試行錯誤は「Twitter、Discord、Subreddit、ニュースレター、ブログを全部見ようとすること」です。S/Nが最も高い1〜2ソースに絞る方がうまくいきます。

  • Simon Willisonのブログ (simonwillison.net) - 深い分析、実機テスト、継続的なまとめ。
  • Arenaリーダーボード (arena.ai/leaderboard、旧LMSYS Chatbot Arena) - ユーザー評価ベースの順位。Text・WebDev・Visionなど分野別の板があるので、自分の仕事に近い板だけ見れば足ります。
  • news.hada.io - 韓国語GeekNewsキュレーション。コメントに実務的な意見が豊富。
  • Anthropic / OpenAI / Google公式ブログ・モデルドキュメント - 新モデル発表のみRSSで受ける。ツイートは見ない。

それ以外のインフルエンサー、匿名フォーラム、Discordの大半は意図的に切ることを勧めます。その時間が本業に戻ってきます。

8. ビルダー向け推奨時間配分

本記事が勧める配分です。計測値ではなく推奨であり、100% = AI関連の学習・実験・情報消費に使う時間全体と仮定します。

項目 推奨比率 具体行動
自分のユースケースを深掘り 60% 実プロジェクトでのモデル直接テスト、評価スクリプト作成、プロンプト調整
新モデルリリースノートをざっと見る 20% 公式ブログ・モデルドキュメントを週1で5分、Tierに割り振るだけ
ベンチマークカテゴリの追跡 10% Arena順位を週1確認、MMLU・SWE-benchトレンドをチェック
コミュニティ議論 10% Simon Willisonブログ、news.hada.ioを週1で整理

1番目が60%なのは、ビルダーの本業が道具を覚えることでなく道具で何かを作ることだからです。60%を下回ったら危険信号です。

9. ビルダーが捨てるべき5つのアンチパターン

アンチパターン1: 全新製品に手を出すFOMO

新モデルが出るたびAPIキーを発行して1時間だけ触って次へ移るパターン。表面だけなめて深さが残らない。推奨基準: 新モデルは四半期に1〜2個だけ本気で評価します。

アンチパターン2: Twitterの無限スクロール

Xのタイムラインを30分以上スクロールするのは学習ではなくドーパミン消費です。公式ブログはRSSだけで受け取り、Xは検索モードでのみ使う方法があります(特定キーワード調査後即終了)。

アンチパターン3: ベンチマーク数値の暗記

「モデルAのSWE-bench Verifiedが67.2%、モデルBが70.1%」（仮の例）という数字を覚えても無駄です。次の四半期にどちらも変わります。覚えず、「BがSWE-benchで少しリード」程度の順位感覚で十分です。

アンチパターン4: モデル別プロンプト技法を全部覚える

「GPTはシステムプロンプトをこう、ClaudeはXMLタグでこう、Geminiはまた別...」全モデルの全テクニックを覚えるのは時間の無駄。主力1〜2モデルの推奨パターンだけ深く学び、残りは必要時に公式ドキュメントを引けばいい。

アンチパターン5: 毎週ツールを乗り換える

「今週はCursor、来週はCline、その次はContinue」というように毎週ツールを変えるビルダーがいます。ショートカットとワークフローの学習コストがモデル改善の恩恵を超えます。四半期に1回の見直しで十分です。

10. 日本市場で信頼できる情報源

英語ソースだけだと日本語性能、国内事例、法務環境を見落とします。組み合わせの例:

  • news.hada.io - 韓国GeekNewsだが日本のビルダーにも有用。
  • 日本語LLM評価 - Nejumi LLMリーダーボード（参考資料のリンク先）やJGLUEなどの日本語ベンチ。
  • 各ベンダー日本法人の事例発表 - 国内コンプライアンス・調達文脈に直結。
  • Qiita・Zennの上位記事 - 一次ソースの和訳・要約として有用。元記事のリンクも必ず確認。
  • 英語2 + 日本語2の組合せが時間対効果のバランスが取れます。

11. モデル疲れは結局なくなるのか

公開当時（2026年5月）の本記事の見通しは次のとおりでした。検証済みの予測ではなく当時の見通しです。

  • 2026〜2027年（当時の見通し）: モデル発表頻度がピーク。年60〜80モデル。疲れも最大。
  • 2028年（当時の見通し）: 統合・整理期。Frontier Tierは3〜4社に収束、Local TierもLlama・Qwen・DeepSeek程度に集約。
  • 2029年以降（当時の見通し）: 名前追跡の負荷が大幅減。能力軸の理解だけで十分に。

2026年9月29日に確認した事実だけを付け加えると、公開後の4か月の間にも公式ドキュメントの主力名は変わりました。Anthropicのモデルドキュメントの現行一覧はClaude Fable 5.1・Opus 5.5・Sonnet 5.5・Haiku 4.5、OpenAIのモデルドキュメントの主力はGPT-6 Astra・Sol・Lunaで、DeepSeekはV4-Proの正式リリース（2026年8月13日）とV4.1-Flash（2026年9月10日）を告知しました。リリース頻度がピークを越えたかどうかは、これらの事実だけでは判断できません。それでも今後2〜3年は、意図的に「追跡を減らし抽象度を上げる」戦略を維持するのが安全だというのが本記事の推奨です。

12. 結論: ビルダーの本質はモデルでなく「問題解決」

本記事の核心メッセージは一行に集約されます。「モデルは道具であり、ビルダーの本業は問題解決である」。名前の暗記に時間を使うほど本業の時間が消えます。能力軸5、Tier 4、ベンチマークカテゴリ7、信頼ソース1〜2。本記事の4つの抽象化さえ持っていれば、どんな新モデルが出ても1分で位置付けて本業に戻れます。

2026年のビルダーに最も重要な能力は「最新モデルを全部知っていること」ではなく、「自分が作っているものを深く知っていること」です。モデルは問題を解いてくれる協力者であって、追いかけ続ける主人ではありません。

# 新しいAIモデルを1分で分類するチェック表 - 名前ではなく能力軸とTierで見る

基準日: 2026-09-29。
モデル名と等級の説明はAnthropic・OpenAI・Google・Meta・Qwen・Mistral・DeepSeekの公式ドキュメントで確認したものです。時間配分の比率と四半期1〜2個の評価基準は計測値ではなく本文の推奨です。

---

## 1. 新しいモデル名を見たら最初に確認すること

- [ ] その名前がベンダーの公式モデルドキュメントや公式発表に実在する（SNSや要約記事の名前はよく間違っている）
- [ ] 公式の日付（スナップショットID・変更履歴の日付・発表日）を確認した
- [ ] 同じ世代名の下にサイズや構成が複数あるか確認した（例: Llama 4 ScoutとMaverickはアクティブ170億で同じだが、エキスパートは16対128）
- [ ] オープン重みかAPI専用かを確認した
- [ ] ベンダーがそのモデルに付けた説明（最も高性能、バランス型、最も効率的など）を読んだ

---

## 2. 5つの能力軸 - どこが強いか

| 能力軸 | 代表的な指標 | 自分の仕事で重要か |
|---|---|---|
| 推論 | MMLU, GPQA, ARC-AGI | [ ] |
| コード | SWE-bench, HumanEval, LiveCodeBench | [ ] |
| マルチモーダル | MMMU, ChartQA, VideoMME | [ ] |
| コンテキスト長 | RULER, Needle-in-Haystack | [ ] |
| レイテンシ・コスト | tok/s, $ / 1Mトークン | [ ] |

---

## 3. Tierへの割り振り（2026-09-29 公式ドキュメントの例）

| Tier | 特徴 | 例 | 主用途 |
|---|---|---|---|
| Frontier | 最高性能・高コスト・高レイテンシ | Claude Fable 5.1・Opus 5.5, GPT-6 Astra, Gemini 3.1 Pro（プレビュー） | 難推論・研究・重要意思決定 |
| Production | バランス型 | Claude Sonnet 5.5・Haiku 4.5, GPT-6 Luna, Gemini 3.8 Flash | 大量API・チャットボット・RAG |
| Local | オープン重み・自社ホスト | Llama 4 Scout・Maverick, Qwen3-32B, DeepSeek-V4-Flash, Mistral Large 3 | プライバシー・オフライン・大量バッチ |
| Edge | 小型・オンデバイス | Gemini Nano, Ministral 3 3B, Qwen3-0.6B〜4B | モバイル・組込・リアルタイム音声 |

例は各ベンダーの説明に基づく分類であり、ベンダー間の優劣ではありません。

## 4. ベンチマークカテゴリ（スコアではなくカテゴリだけ）

| カテゴリ | 何を見るか | 2026-09-29 メモ |
|---|---|---|
| MMLU | 一般知識 | - |

---

## 5. 自前ベンチマークの確認

- [ ] 実入力30〜50件をJSONで保存した
- [ ] 同一プロンプトで候補モデルを順に呼び出した
- [ ] 出力を人がA対Bで盲検比較した
- [ ] 結果にモデルIDと日付を付けてリポジトリに保管した
- [ ] 四半期ごとに回し直せる程度に小さく保った

---

## 6. 価格は数字ではなく方向で

- [ ] 直近半年のFrontier入力単価: 下がった / 上がった / 横ばい
- [ ] 自社ホストの単位コスト（GPU償却込み）は使っているクラウドAPIより: 安い / 高い
- [ ] 画像入力の課金方法をベンダーの料金ページで確認した

---

## 7. 時間配分の確認（推奨比率）

| 項目 | 推奨 | 今月の実績 |
|---|---|---|
| 自分のユースケースを深掘り | 60% | |
| リリースノートをざっと見る | 20% | |
| ベンチマークカテゴリの追跡 | 10% | |
| コミュニティ議論 | 10% | |

1行目が60%を下回ったら危険信号です。

---

## 8. アンチパターンの自己点検

- [ ] 今四半期に本気で評価した新モデルは1〜2個以内
- [ ] Xのタイムラインを30分以上スクロールした日がない
- [ ] ベンチマークのスコア数値を暗記していない（順位だけ覚える）
- [ ] プロンプトのパターンを深く学んだのは主力1〜2モデルだけ
- [ ] コーディングツールを毎週乗り換えていない

コピーしてメモアプリやAIツールにそのまま貼り付けてください。
