1. 600B MoE 아키텍처와 27B 활성 파라미터의 계산 구조

2차 출처인 OrcaRouter 분석 블로그에 따르면 인공지능 연구 기업 StepFun은 2026년 9월 20일 차세대 플래그십 파운데이션 모델인 Step 5 Preview를 공식 발표했다. 공개된 사양 정보에 따르면 이 모델은 총 600B(6,000억) 파라미터 규모의 희소 전문가 혼합(sparse Mixture-of-Experts, MoE) 구조를 기반으로 설계되었다. 그러나 전체 600B 가중치가 매 토큰 추론마다 모두 연산에 참여하는 것은 아니다. 원문은 개별 토큰을 생성할 때 실제로 활성화되는 파라미터가 전체의 약 4.5%에 해당하는 27B(270억) 파라미터에 불과하다고 명시한다.

일반적으로 전문가 혼합 아키텍처는 전체 가중치를 메모리에 유지하면서도 각 토큰의 맥락에 따라 최적화된 소수의 하위 네트워크만을 동적으로 선택해 활성화하는 방식으로 구동된다. 2차 분석 블로그는 전체 600B 파라미터 대비 27B 활성 파라미터라는 비율을 두고 통상적인 MoE 모델들과 비교할 때 매우 높은 수준의 희소성(unusually sparse ratio)을 가진 구조라고 평가한다. 이러한 극단적인 희소 설계는 연산 효율성과 인프라 비용 사이에서 명확한 기술적 트레이드오프를 형성한다.

이 글의 해석으로는 토큰당 활성 파라미터를 27B 수준으로 제한한 것은 서빙 과정에서 요구되는 부동소수점 연산량(FLOPs)을 소형 모델 수준으로 낮추어 토큰당 단가를 억제하기 위한 구조적 선택으로 볼 수 있다. 반면 총 600B에 달하는 비활성 가중치까지 모두 추론 서버의 고대역폭 메모리에 상주시켜야 하므로, GPU 클러스터가 감당해야 하는 정적 메모리 풋프린트(VRAM) 요구량은 여전히 초대형 모델의 체급에 머무르게 된다.

2차 출처에 따르면 StepFun은 이번 발표에서 Step-3.5-Flash 및 Step-3.7-Flash에 이어 계산 단위당 성능을 극대화하는 파레토 프론티어(Pareto frontier)를 3세대에 걸쳐 일관되게 추구해 왔다고 설명했다. 특히 이번 공개에서는 중간 단계인 Step 4.x 라인업을 완전히 건너뛰고 Step-3.7-Flash에서 곧바로 Step 5 Preview로 판올림을 단행했다. 이러한 버전 명명은 연구팀이 이번 아키텍처 개편을 단순한 점진적 개선이 아닌 대규모 도약으로 규정하고 있음을 드러낸다.

  • 총 파라미터 600B 중 토큰당 연산에 사용되는 활성 파라미터는 27B로 약 4.5% 수준이다.
  • 서빙 시 토큰당 연산 비용은 20B급 소형 모델 수준으로 억제되지만 메모리 적재 공간은 대형 모델 규모를 요구한다.
  • 단위 연산 비용 대비 모델 역량을 끌어올리는 파레토 프론티어 접근법을 설계 기조로 삼았다.
  • Step-3.7-Flash에서 Step 4 제품군을 생략하고 곧바로 Step 5로 판올림을 진행했다.

2. 백만 토큰 컨텍스트와 네이티브 멀티모달 입력 사양

2차 분석 블로그가 인용한 공식 자료에 따르면 Step 5 Preview는 최대 100만(1M) 토큰에 이르는 방대한 컨텍스트 윈도우를 지원한다. 입력 모달리티는 텍스트와 이미지를 네이티브 환경에서 동시에 처리할 수 있도록 구성되었다. 반면 출력 모달리티는 텍스트 생성 전용으로 엄격히 한정된다. 시각 데이터를 입력받아 분석할 수는 있지만 직접 새로운 이미지를 생성해 반환하는 기능은 지원하지 않는다.

일반적으로 네이티브 멀티모달 아키텍처는 별도의 외부 변환기 없이 시각적 토큰을 텍스트 토큰과 동일한 임베딩 공간 안에서 정렬하여 연속적으로 연산한다. 원문은 Step 5 Preview가 일상적인 대화 품질을 다듬는 챗봇용 모델이 아니라, 소프트웨어 엔지니어링, 전문 지식 분석, 금융 데이터 처리 등 장시간 지속되는 실제 에이전트 업무를 수행하기 위한 베이스 모델로 포지셔닝되었다고 기술한다. 긴 문맥 창과 다중 턴 도구 호출 환경에서 작업의 일관성을 유지하는 능력이 핵심 가치로 제시되었다.

이 글의 해석으로는 거대한 저장소 전체의 소스 코드를 단일 세션에 적재하거나 수십 장의 기술 사양서 및 아키텍처 다이어그램을 한 번에 검토해야 하는 소프트웨어 개발 파이프라인을 정조준한 구성으로 판단된다. 복잡한 도구 체인을 순차적으로 호출하며 결과를 피드백받아야 하는 자율 에이전트 워크플로에서는 긴 문맥 유지력이 곧 작업 완결성과 직결되기 때문이다.

그러나 2차 분석 블로그는 발표에 앞서 비공식적으로 유출되어 개발자 도구 설정에 회자되었던 정보와 공식 발표 내용 사이에 해소되지 않은 괴리가 존재한다는 사실을 함께 지적한다. 사전에 유포된 일부 서드파티 설정 파일에는 본 모델의 컨텍스트가 350,000 토큰으로 제한되어 있었고, 최대 출력 토큰 상한선이 64,000 토큰으로 명시되어 있었다. 공식 발표문은 1M 컨텍스트 지원을 명시하면서도 최대 출력 상한선에 대해서는 별도의 세부 수치를 언급하지 않았다.

이 글의 추측으로는 인프라 제공사의 서빙 환경이나 라우팅 정책에 따라 실제 호출 가능한 단일 세션의 출력 한도가 내부적으로 조절될 여지가 있으므로, 장기 에이전트 루프를 구축하는 엔지니어링 팀은 공식 기술 문서의 추가 릴리스를 확인해야 할 필요가 있다.

  • 공식 컨텍스트 윈도우는 100만(1M) 토큰을 지원하여 장기 에이전트 작업에 대응한다.
  • 텍스트와 이미지를 네이티브로 수용하는 멀티모달 입력을 지원하지만 출력은 텍스트 전용이다.
  • 사전 유출된 개발자 도구 설정의 350k 컨텍스트 및 64k 출력 상한선과의 차이가 존재한다.
  • 공식 발표문에는 최대 출력 토큰 상한선에 대한 구체적 제한 수치가 명시되지 않았다.

3. 토큰당 가격 책정과 캐시 95% 할인이 시사하는 경제성

2차 분석 블로그가 정리한 공식 요금 정책에 따르면 Step 5 Preview의 API 호출 비용은 입력 백만 토큰당 1.00달러, 출력 백만 토큰당 2.70달러로 책정되었다. 이에 더해 프롬프트 캐싱을 적용할 경우 최대 95%의 캐시 할인이 제공된다는 점이 함께 공개되었다. 프롬프트 캐싱이 유효하게 작동하는 반복 질의 환경에서는 입력 백만 토큰당 실질 비용이 0.05달러 수준까지 낮아질 수 있음을 시사한다.

일반적으로 프롬프트 캐싱은 다중 턴 상호작용 과정에서 누적되는 고정 시스템 프롬프트나 정적 참조 문서의 키-값(KV) 캐시를 GPU 메모리에 재사용함으로써 반복 연산 오버헤드를 줄이는 메커니즘이다. 100만 토큰에 달하는 대용량 컨텍스트를 유지해야 하는 에이전트 파이프라인에서 매 턴마다 기본 입력 요금을 전액 지불하는 구조는 심각한 비용 폭증을 초래하기 마련이다.

이 글의 해석으로는 95% 캐시 할인 정책은 방대한 코드베이스나 참조 문서를 컨텍스트에 고정해 두고 장시간 작업을 위임하는 에이전트 아키텍처를 도입할 때 실질적인 비용 타당성을 확보해 주는 핵심 장치로 평가된다. 2차 블로그는 StepFun이 자체 평가 자료를 통해 자사 모델의 단일 과업 수행 비용이 Claude Opus 5 대비 약 8분의 1 수준에 불과하다고 주장했음을 전한다.

참고로 비교 대상인 Claude Opus 5의 API 단가는 입력 백만 토큰당 5.00달러, 출력 백만 토큰당 25.00달러 선에 형성되어 있다. 표면적인 단가 수치만 비교하면 Step 5 Preview는 입력에서 5배, 출력에서 9배 이상 저렴한 가격표를 내세운 셈이다. 그러나 표면 단가가 낮다고 해서 전체 워크로드의 총소유비용(TCO)이 무조건 절감된다고 단정할 수는 없다.

이 글의 추측으로는 에이전트가 동일한 문제를 해결하기 위해 생성해 내는 출력 토큰의 총량이 모델의 서술 습관에 따라 크게 좌우될 수 있으므로, 저렴한 단가가 과도한 토큰 소모로 인해 상쇄되는 지점을 실측 데이터로 검증해야 한다.

  • 기본 API 단가는 입력 백만 토큰당 1.00달러, 출력 백만 토큰당 2.70달러로 책정되었다.
  • 프롬프트 캐싱 적용 시 95% 할인이 언급되어 캐시 적중 입력은 백만 토큰당 0.05달러 수준이다.
  • StepFun은 자체 자료에서 단일 과업 수행 비용이 Claude Opus 5의 8분의 1 수준이라고 주장했다.
  • 실제 청구 비용은 단순 토큰 단가뿐만 아니라 과업당 생성되는 총 출력 토큰량에 의해 결정된다.

4. 허깅페이스 저장소 현황과 10월 15일 가중치 공개 일정

오픈소스 생태계 관점에서 Step 5 Preview의 공개 방식을 바라볼 때 가장 명확히 인식해야 하는 지점은 바로 가중치 파일의 부재다. 2차 분석 블로그에 따르면 2026년 9월 20일 발표 당일 허깅페이스 플랫폼에 stepfun-ai/Step-5-Preview-BF16 저장소가 개설된 것은 사실이다. 그러나 해당 저장소에는 실제 인공지능 모델을 구동하기 위한 바이너리 가중치가 일절 존재하지 않는다.

원문은 허깅페이스 API 메타데이터를 직접 확인한 결과를 인용하며, 해당 저장소가 생성 시점 이후 단 하나의 파일인 .gitattributes만을 담고 있는 플레이스홀더 상태라고 적는다. 다운로드 가능한 safetensors 분할 파일은 물론이고, 모델 카드(README), 아키텍처 상세 매개변수를 담은 구성 파일(config.json), 그리고 모델의 상업적 사용 권한을 규정하는 라이선스 파일조차 전혀 등록되지 않았다.

2차 분석 블로그의 저자는 이러한 현실을 명확히 짚으며 "the model is callable today and downloadable in about three and a half weeks, and those are two different things"라고 서술했다. 즉, 오늘 시점에서 모델을 API 엔드포인트로 호출하는 것은 가능하지만 이를 직접 내려받아 자체 인프라에 올릴 수 있는 시점은 약 3주 반 뒤이며, 이 두 가지는 엔지니어링 관점에서 완전히 다른 사안이라는 지적이다.

StepFun이 공식 발표 자료를 통해 제시한 오픈 가중치 배포 예정일은 2026년 10월 15일이다. 2차 블로그는 저장소 명칭에 명시된 `BF16` 접미사를 통해 벤더가 우선 미세조정과 양자화의 기반이 되는 bfloat16 원본 체크포인트를 배포하고, 추후 FP8이나 NVFP4 서빙용 빌드를 순차 제공할 것으로 해석한다. 지난 6월 Step-3.7-Flash 릴리스 당시 다양한 양자화 변형이 함께 제공되었던 것과 달리, 현재 Step 5 계열에서는 오직 단 하나의 빈 저장소만이 예약되어 있다.

이 글의 해석으로는 가중치가 실제로 업로드되기 전까지는 허깅페이스 저장소의 존재 자체가 단지 네임스페이스를 선점해 둔 선언적 단계에 불과함을 의미한다. 따라서 10월 중순 이전에 자체 호스팅을 전제로 도입 계획을 수립하는 것은 실체 없는 파일에 기대는 위험한 접근이 될 수 있다.

  • 공식 허깅페이스 저장소 stepfun-ai/Step-5-Preview-BF16에는 .gitattributes 단일 파일만 존재한다.
  • 가중치 바이너리, config.json, 모델 카드, 오픈소스 라이선스가 모두 누락된 플레이스홀더다.
  • 공식 오픈 가중치 배포 예정일은 2026년 10월 15일로 발표되었다.
  • BF16 접미사로 미루어 볼 때 초기 배포는 bfloat16 포맷을 중심으로 진행될 것으로 관측된다.

5. 제3자 벤치마크와 160M 출력 토큰 장황성 분석

모델의 실제 성능과 신뢰성을 파악하기 위해서는 벤더가 자체적으로 제작한 마케팅 평가 지표와 독립적인 제3자 기관이 측정한 객관적 데이터를 분리해서 검토해야 한다. 2차 분석 블로그에 따르면 인공지능 평가 전문 플랫폼인 Artificial Analysis는 Step 5 Preview에 대한 독립 측정 결과를 발표했다. 해당 벤치마크에서 Step 5 Preview는 Intelligence Index v4.3.2 점수 44점을 기록하여 평가 대상 200개 모델 중 종합 24위에 랭크되었다.

원문은 이 44점이라는 점수가 경쟁 모델인 Kimi K3와 정확히 동률이며, Z.ai의 GLM-5.3(45점)보다 1점 낮은 수준이라고 적는다. 또한 Anthropic의 Claude Opus 5를 중간 추론 노력(medium reasoning effort) 설정으로 구동했을 때의 인덱스 점수와 일치하는 수치다. 시스템 엔지니어링 수행 능력을 가늠하는 Terminal-Bench 4.0 평가에서 Step 5 Preview는 33.3%의 성공률을 기록했다. 이는 DeepSeek V4.1 Flash의 26.8%나 Kimi K3의 약 12.6%를 확실히 앞서는 결과다.

응답 지연과 처리량 측면에서도 독립 측정 수치가 확보되었다. 초당 토큰 생성 속도는 99.8 토큰(tokens/sec)으로 기록되었으며, 사용자의 요청이 전달된 후 첫 번째 토큰이 출력되기까지 걸리는 시간(Time to First Token, TTFT)은 2.96초로 측정되었다. 이러한 속도 지표는 대화형 인터페이스뿐만 아니라 다중 턴 에이전트 루프에서 체감 지연을 크게 줄여줄 수 있는 성능치다.

그러나 2차 분석 블로그는 저렴한 API 단가 이면에 숨겨진 중대한 비용 리스크로 출력 토큰의 과도한 장황성(verbosity) 문제를 함께 제기한다. Artificial Analysis의 인덱스 평가 전체를 수행하는 동안 Step 5 Preview는 무려 160M(1억 6,000만) 개의 출력 토큰을 소모했다. 이는 동일한 평가를 거친 모델들의 중앙값인 92M 토큰과 비교할 때 약 74%나 많은 토큰을 생성해 낸 셈이다.

백만 출력 토큰당 2.70달러의 단가를 대입하면 이 평가에서 발생한 총비용 922.84달러 중 약 432달러가 순수하게 출력 토큰 비용으로 지출되었다. 그 결과 인덱스 태스크당 실질 비용은 0.71달러로 집계되었다. 이 글의 해석으로는 표면적인 API 단가가 아무리 저렴하더라도 모델이 불필요하게 장황한 사고 과정이나 긴 답변을 생성하도록 방치할 경우 실제 운영 청구서의 최종 금액은 기대만큼 낮아지지 않을 수 있음을 시사한다.

6. 커뮤니티에 공유된 추가 벤치마크(출처: GeekNews 요약)

공식 발표문과 2차 기술 블로그 외에도 국내 개발자 커뮤니티인 GeekNews 기술 토픽 요약(hada id: 34006)을 통해 모델의 다양한 세부 성능치와 응용 사례가 공유되었다. 본 절에서 다루는 수치들은 독립 벤치마크 기관의 교차 검증을 거치지 않은 커뮤니티 요약 정보이므로, 데이터의 출처 한계를 엄격히 전제하고 검토해야 한다.

GeekNews 요약에 따르면 StepFun은 사내 평가 벤치마크인 StepCodeBench에서 49.0%의 점수를 획득했다고 밝혔다. 이 벤치마크는 553개 코드 저장소, 9가지 과업 유형, 20개 도메인, 33개 프로그래밍 언어로 구성된 자체 테스트 도구다. 해당 요약은 Step 5 Preview가 "Claude Opus 5와 낮은/중간 난이도에서 비슷하고 가장 긴 태스크에서 격차 크다"고 전했다. 장기적이고 복잡한 엔지니어링 과업에서 최상위 프론티어 모델과의 성능 격차가 여전히 존재함을 시사하는 대목이다.

하드웨어 연산 효율성 측면에서는 24시간 동안 진행된 GPU 커널 최적화 실험에서 MLA(Multi-Head Latent Attention) 커널 피크 성능 508 TFLOPS를 기록했다고 보고되었다. 이는 동일 조건에서 측정된 Claude Opus 5의 493 TFLOPS를 소폭 상회하는 수치다. 또한 DeepSWE v1.1 벤치마크에서는 67.7%를 기록한 것으로 정리되었다.

한편 GeekNews 요약에는 Qwen3-30B-A3B의 AIME24 정확도가 53.3%에서 60%로 향상되었다는 서술이 포함되어 있다. 그러나 이 수치와 관련해서는 StepFun이 자사의 사후 학습 기술을 타사 베이스 모델에 적용한 실험인지, 혹은 무엇을 어떻게 개선한 것인지 구체적인 주체와 대상이 불명확하다. 따라서 본 지표는 벤더의 일반적인 훈련 역량 주장의 일환으로 해석할 뿐 Step 5 Preview 자체의 고유 성능으로 단정해서는 안 된다.

실제 응용 사례로는 게임 및 리서치 에이전트 과업이 소개되었다. 포켓몬 레드 게임 환경에서는 게임 특화 미세조정이나 전용 최적화 없이도 3,082턴 동안 600만 상호작용 토큰을 소모하며 안정적인 플레이를 유지했다는 사례가 수록되었다. 기후 연구 과업에서는 950건의 웹 요청을 자율적으로 조율하여 25년 치 기상 데이터와 1,000개 지역의 복합 정보를 성공적으로 분석했다고 보고되었다.

금융 벤치마크 영역에서는 FrontierFinance에서 66.4%(Claude Opus 5는 69.7%), LiveSearch 74.5%, CorporateValuation 60.6%, DeepResearch 55.8%를 기록한 것으로 집계되었다. 멀티모달 공간 처리 예시로는 침실 사진 여러 장을 입력받아 Blender 및 Three.js 기반의 편집 가능한 3D 가상 공간으로 재구성하는 Room Planner 데모가 공유되었다. 해커뉴스(HN) 댓글에서는 모델의 사고 과정(thought traces)이 기존 오픈 모델들의 추론 패턴에 상당 부분 의존하는 것으로 보인다는 관찰과 함께 "저렴한 모델 중 최고"라는 평가가 오갔다.

7. 자율 에이전트 작업 도입 시의 운영상 고려 사항

실제 서비스 인프라에 Step 5 Preview를 결합하고자 하는 엔지니어링 조직은 모델의 장점뿐만 아니라 현실적인 운영 리스크를 입체적으로 고려해야 한다. 일반적으로 프리뷰 단계의 최신 모델을 단일 공급자의 API 엔드포인트에 전적으로 의존하여 프로덕션에 투입하는 구성은 심각한 가용성 위험을 초래한다.

2차 분석 블로그는 발표 당일 오픈된 신규 API 엔드포인트의 경우 전용 서빙 인프라가 완전히 확충되지 않아 사용량 폭증 시 처리 용량 제약(capacity constraint)에 직면할 위험이 높다고 경고한다. 심야 시간대나 피크 타임에 프리뷰 API 엔드포인트의 응답 지연이나 서비스 장애가 발생하면, 지속적인 다중 턴 상호작용을 이어가던 에이전트 루프 전체가 중간 단계에서 실패로 이어질 수 있다.

이 글의 해석으로는 Step 5 Preview를 주력 모델로 테스트하더라도 DeepSeek V4.1 Flash, GLM-5.3, Claude Opus 5 등 기성 상용 모델을 예비 경로로 지정하는 자동 장애 조치(failover) 라우팅 레이어를 전면에 배치하는 구성이 필수적이다. 이렇게 하면 비정상적인 지연이나 429 요청 거부 상황이 발생하더라도 워크플로의 중단 없이 안정적인 에이전트 실행을 보장받을 수 있다.

비용 측면에서는 Artificial Analysis 독립 평가에서 확인된 160M 출력 토큰의 장황성을 억제하기 위한 프롬프트 엔지니어링이 선행되어야 한다. 시스템 프롬프트 수준에서 불필요한 중간 서술을 억제하고 정형화된 JSON이나 간결한 실행 명령만을 출력하도록 엄격히 유도하지 않으면 저렴한 토큰 단가가 무색해질 정도로 청구 요금이 불어날 수 있다. 더불어 95% 캐시 할인을 최대한 누리기 위해서는 에이전트 프롬프트 템플릿의 앞단에 고정된 시스템 프롬프트와 정적 도구 정의를 배치하고, 가변적인 사용자 입력과 실행 로그는 뒷단에 결합하는 구조적 최적화가 필수적이다.

이 글의 추측으로는 10월 15일 가중치 파일이 정식으로 공개되더라도 600B MoE 모델을 사내 데이터센터에 직접 배포하기 위해서는 방대한 VRAM 용량과 복잡한 텐서 병렬화 인프라 투자가 선행되어야 한다. 따라서 단기적으로는 API 기반의 샌드박스에서 성능과 비용을 선별 검증하고, 자체 호스팅으로의 전환은 공식 가중치 파일과 라이선스 규격이 완전히 확정된 이후에 결정하는 단계적 접근이 바람직하다.

  • 초기 API 인프라의 처리 용량 제약에 대비하여 상용 모델 기반의 자동 장애 조치(failover) 경로를 구성해야 한다.
  • 출력 토큰 장황성을 통제하기 위해 시스템 프롬프트에서 간결한 출력 구조를 엄격히 지정해야 한다.
  • 프롬프트 캐싱 95% 할인을 극대화할 수 있도록 고정 지침을 템플릿 앞단에 배치하는 최적화가 필요하다.
  • 600B MoE의 막대한 메모리 풋프린트를 감안하여 10월 15일 가중치 공개 전까지는 자체 호스팅 결정을 유보해야 한다.

8. 확인하지 못한 것

본 기술 분석을 작성하는 과정에서 원문의 상세 내용과 출처를 대조하였으나, 아래의 항목들은 명확한 기술적 근거를 확인하지 못하여 단정하지 않고 본 절에 사유와 함께 기록한다.

  • StepFun 공식 웹사이트(stepfun.com)의 직접 접근 시 자바스크립트 렌더링 셸만 반환되고 정적 텍스트가 수집되지 않아, 1차 공식 발표 원문의 문언을 직접 대조하지 못하고 2차 기술 블로그 및 커뮤니티 요약 자료에 의존했다.
  • GeekNews 요약에 언급된 Qwen3-30B-A3B 모델의 AIME24 정확도 향상(53.3%→60%)과 관련하여, 이것이 StepFun 자체 모델의 기여인지 혹은 사후 학습 방법론의 일반적 실험 결과인지 그 구체적 개선 대상과 실험 주체를 확인하지 못했다.
  • 사전에 유출된 개발자 도구 설정 파일의 350,000 토큰 컨텍스트 및 64,000 토큰 출력 상한선과 공식 1M 사양 사이의 관계, 그리고 실제 API 엔드포인트에 적용된 최대 출력 제한 수치를 확인하지 못했다.
  • 2026년 10월 15일 공개 예정인 가중치 파일의 공식 라이선스(상업적 제한이 없는 완전한 오픈소스인지, 자체 커스텀 라이선스인지)가 저장소에 아직 고지되지 않아 법적 배포 조건을 확인하지 못했다.
  • GeekNews 요약에 수록된 포켓몬 레드 3,082턴 완주, 기후 연구 950건 웹 요청 조율 등의 자율 에이전트 과업 수치에 대해 제3자 독립 기관의 객관적인 재현 검증 데이터를 확인하지 못했다.
