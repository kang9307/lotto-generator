Ceph Storage の概要と詳細ガイド

Comprehensive Guide to Ceph Storage

2025-06-02 開発・インフラ

Ceph はオープンソースの分散ストレージシステムで、単一プラットフォーム上でオブジェクト、ブロック、ファイルストレージの機能をすべて提供します。大規模データセンターやクラウド環境で、高いスケーラビリティ、信頼性、パフォーマンスを備えたストレージソリューションが必要な場合、Ceph は優れた選択肢となります。

English: Ceph is an open-source distributed storage system that provides object, block, and file storage capabilities within a single unified platform. It's an excellent choice for large-scale data centers and cloud environments requiring a storage solution with high scalability, reliability, and performance.

Ceph ストレージの中核となる概念

Ceph のアーキテクチャはいくつかの中核概念に基づいて設計されており、それらが Ceph の強力なパフォーマンスと信頼性を支えています。

RADOS (Reliable Autonomic Distributed Object Store)

RADOS は Ceph の基盤となるオブジェクトストレージシステムです。すべてのデータはオブジェクトとして保存され、これらのオブジェクトはクラスタ全体に分散されます。

+-------------------+
|     Applications  |
+-------------------+
          |
+-------------------+
|  LIBRADOS (API)   |
+-------------------+
          |
+-------------------+
|   RADOS Cluster   |
| (OSD + Monitor)   |
+-------------------+

主な特徴は次のとおりです。

  • 自動化されたデータ分散とレプリケーション
  • 自己修復機能によりノード障害時に自動復旧
  • クラスタ状態のモニタリングと管理

CRUSH アルゴリズム

CRUSH(Controlled Replication Under Scalable Hashing) は、Ceph がデータをどのように分散保存するかを決定するアルゴリズムです。

# CRUSH マップの確認コマンド
ceph osd crush dump

CRUSH アルゴリズムの利点:

  • 中央のルックアップテーブルなしでデータの配置位置を計算
  • クラスタ構成変更時のデータ移動を最小化
  • ストレージ階層と障害ドメインを柔軟に定義可能

OSD (Object Storage Daemon)

OSD は実際にデータを保存・管理するデーモンプロセスです。一般的には物理ディスク 1 台につき 1 つの OSD を動作させます。

# OSD の状態確認
ceph osd status
ceph osd tree

OSD の役割:

  • データの保存と取得
  • データレプリケーションとリカバリの調整
  • 他の OSD とのハートビートによるクラスタ状態の監視

Monitor

モニターノードはクラスタの状態マップを保持し、クライアントに対してクラスタ情報を提供します。

# モニターの状態確認
ceph mon stat

モニターの役割:

  • クラスタマップの管理(Monitor Map、OSD Map、PG Map など)
  • クライアントの認証と権限管理
  • クォーラムに基づく分散意思決定

Placement Group (PG)

PG はオブジェクトの集合を管理する論理単位で、Ceph のスケーラビリティを担保します。

# PG の状態確認
ceph pg stat

PG の重要性:

  • 数百万のオブジェクトを効率的に管理
  • OSD 間のデータレプリケーションと分散管理
  • リカバリ処理の並列化を支援

Ceph の主要ストレージインターフェース

Ceph は 3 種類の主要ストレージインターフェースを提供し、さまざまなユースケースに対応します。

1. RADOS Gateway (RGW) - オブジェクトストレージ

RGW は Amazon S3 および OpenStack Swift と互換性を持つ RESTful API を提供するオブジェクトストレージインターフェースです。

ユースケース:

  • クラウドネイティブアプリケーション
  • 静的 Web コンテンツのホスティング
  • バックアップおよびアーカイブソリューション
  • 大規模データストア
# RGW サービスの起動
systemctl start ceph-radosgw@rgw.`hostname -s`

2. RADOS Block Device (RBD) - ブロックストレージ

RBD は Ceph のブロックストレージインターフェースで、仮想マシンやコンテナ向けのブロックデバイスを提供します。

ユースケース:

  • 仮想マシンのディスク(OpenStack、VMware)
  • データベースストレージ
  • コンテナのパーシステントボリューム(Kubernetes)
# RBD イメージ作成の例
rbd create --size 10G --pool rbd my_disk

特徴:

  • シンプロビジョニング
  • スナップショットおよびクローンのサポート
  • 自動的なデータ分散とレプリケーション

3. CephFS - ファイルストレージ

CephFS は POSIX 互換のファイルシステムインターフェースを提供します。

ユースケース:

  • 共有ファイルシステム
  • データ分析ワークロード
  • 大規模なホームディレクトリ
# CephFS マウントの例
mount -t ceph mon1:6789:/ /mnt/cephfs -o name=admin,secret=[YOUR_CEPH_SECRET_KEY]

特徴:

  • メタデータサーバー(MDS) による高性能なファイル操作
  • 動的ディレクトリ分割によるスケーラビリティの向上
  • POSIX ACL のサポート

Ceph のインストールと構成の概要

Ceph クラスタをインストール・構成するための基本的な手順は次のとおりです。

1. 事前要件

# すべてのノードに必要なパッケージをインストール
apt-get update
apt-get install -y ceph-common python3 ntp

必要なハードウェア:

  • 本番環境では最低 3 台の OSD ノード
  • 高可用性クラスタのためには最低 3 台のモニターノード
  • 各ノード間のネットワーク接続

2. Cephadm を用いたインストール(最新推奨方式)

# Cephadm のブートストラップ
curl --silent --remote-name --location https://github.com/ceph/ceph/raw/octopus/src/cephadm/cephadm
chmod +x cephadm
./cephadm bootstrap --mon-ip <mon-ip>

3. ストレージプールの構成

# デフォルトのレプリケーションプールを作成
ceph osd pool create mypool 128 128
ceph osd pool set mypool size 3

# イレイジャーコーディングプールを作成
ceph osd pool create ecpool 128 erasure
ceph osd pool set ecpool allow_ec_overwrites true

4. クライアントの設定

# クライアント設定ファイルの配布
ceph config generate-minimal-conf > /etc/ceph/ceph.conf
ceph auth get client.admin > /etc/ceph/ceph.client.admin.keyring

Ceph のパフォーマンス最適化

Ceph クラスタの性能を最大限に引き出すための重要なポイントをいくつか紹介します。

ネットワークの最適化

# ネットワークチューニングパラメータ
net.core.rmem_max = 56623104
net.core.wmem_max = 56623104
net.core.rmem_default = 56623104
net.core.wmem_default = 56623104
net.core.optmem_max = 40960

ネットワークに関する推奨事項:

  • パブリックネットワークとクラスタネットワークを分離する
  • 最低でも 10GbE のネットワークインターフェースを使用する
  • ジャンボフレームを有効化する

OSD の最適化

# OSD のチューニングパラメータ
osd_memory_target = 4294967296  # 4GB
bluestore_cache_size_ssd = 3221225472  # 3GB for SSD

OSD の推奨事項:

  • 高性能ディスク(SSD や NVMe) の利用
  • 専用のジャーナルデバイス
  • メタデータとデータの分離

モニタリングとトラブルシューティング

# クラスタ状態のモニタリング
ceph health detail
ceph -s

# パフォーマンスカウンタの確認
ceph daemon osd.0 perf dump

主要な監視指標:

  • IOPS およびスループット
  • レイテンシ
  • リカバリ処理の状態
  • クラスタの使用量

Ceph と他のストレージソリューションの比較

Ceph vs GlusterFS

機能 Ceph GlusterFS
アーキテクチャ オブジェクトベース ファイルベース
ストレージタイプ オブジェクト、ブロック、ファイル 主にファイル
スケーラビリティ エクサバイト規模 ペタバイト規模
複雑さ 比較的高い 比較的低い
ユースケース 大規模クラウド ファイル共有 / NAS

Ceph vs Swift

機能 Ceph Swift
対応範囲 統合ストレージ オブジェクトストレージのみ
整合性 強整合性 結果整合性
ブロックストレージ ネイティブ対応 非対応
ファイルシステム CephFS 対応 非対応

Ceph vs HDFS

機能 Ceph HDFS
主な用途 汎用ストレージ ビッグデータ分析
データモデル オブジェクトベース ブロックベース
アクセスパターン 多様なワークロード シーケンシャルアクセスに最適化
API S3 / Swift / POSIX HDFS API

Ceph の今後の展望

Ceph は継続的に進化を続けており、次のような主要領域でイノベーションを推進しています。

パフォーマンスの改善

  • NVMe および永続メモリの最適化
  • ネットワークプロトコルの最適化

運用管理の簡素化

  • Cephadm や Rook といった新しい管理ツール
  • クラスタの自動管理
  • 宣言的な構成方式の導入

まとめ

Ceph は、スケーラビリティ、信頼性、柔軟性を兼ね備えた強力な分散ストレージソリューションです。単一のシステムでオブジェクト、ブロック、ファイルストレージのすべてを提供できる点は、現代のデータセンターやクラウド環境において大きな利点となります。

クラスタ拡張、ノードの追加や交換といった作業をサービス停止なしで実施できる機能と、ハードウェア障害に自動対応する自己修復メカニズムが、Ceph をエンタープライズ級のストレージシステムたらしめています。

オープンソースという性質と活発なコミュニティサポートにより、Ceph は今後も革新を続け、クラウドネイティブ環境や現代的なデータセンターの中核コンポーネントとしての地位を確立していくでしょう。
