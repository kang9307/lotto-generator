서론: 2026년 개발자 도구 지형

개발자에게 "어떤 도구를 쓰세요?"라는 질문은 단순한 호기심이 아니다. 그 사람의 워크플로, 가치관, 그리고 하루를 어떻게 보내는지가 도구 목록에 고스란히 담긴다. 2026년 5월 말, 한국 기술 커뮤니티 news.hada.io에 올라온 "좋아하는 개발자 도구는 무엇인가요?"라는 토픽이 38점을 받으며 활발한 토론을 만들어낸 것도 같은 이유다. 사람들은 자기 도구를 자랑하고 싶어 하고, 동시에 남이 무엇을 쓰는지 끊임없이 궁금해한다.

그런데 2026년의 도구 지형은 불과 2~3년 전과 결정적으로 다르다. 가장 큰 변화는 AI가 별도 카테고리가 아니라 거의 모든 카테고리에 스며들었다는 점이다. 에디터에는 AI 자동완성과 에이전트가 들어왔고, 터미널은 AI 명령 추천을 품었으며, 데이터베이스 도구에도 AI 기능이 붙고 있다. "AI 도구를 쓰느냐"는 질문은 이제 "에디터를 쓰느냐"만큼이나 무의미해졌다. 진짜 질문은 "어떤 도구를, 어떤 깊이로, 어떻게 조합해서 쓰느냐"로 바뀌었다.

이 글은 그 질문에 대한 범주별 정리다. 코드 에디터부터 AI 코딩, 터미널, 버전 관리, API/HTTP, 컨테이너, 데이터베이스, 노트, 모니터링, 유틸리티까지 10개 도구 범주를 차례로 훑고, 한국 개발 환경의 특징과 도구 선택의 5가지 원칙, 마지막으로 어떤 상황에 어떤 범주의 도구가 쓰이는지를 정리한다. 인기 순위 나열이 아니라 '왜 이 도구가 이 자리에 있는가'를 함께 설명하는 것이 목표다.

이용률 수치는 출처가 확인되는 것만 적었다. 2026-09-29 기준으로 결과를 확인할 수 있는 가장 최근의 대규모 공개 설문은 Stack Overflow 2025 Developer Survey(2025년 수집, 응답 약 49,000명)다. 2026년 설문은 2026년 6월 23일 응답 접수를 시작했다고 Stack Overflow 공식 블로그가 알렸으나, 결과는 이번 확인에서 찾지 못했다. 아래 수치는 모두 복수 응답 문항의 전체 응답자 기준이다.

1. 코드 에디터 - VS Code, Cursor, Zed, Neovim, JetBrains

모든 워크플로의 중심에는 에디터가 있다. 2026년 에디터 지형은 'VS Code 기본값 + AI 시대의 새 도전자들' 구도로 정리된다.

VS Code는 여전히 기본값이다. Stack Overflow 2025 설문의 개발 환경(IDE) 문항에서 전체 응답자의 75.9%가 VS Code를 쓴다고 답했다. 방대한 확장 생태계와 안정성, 그리고 Copilot·Claude Code 연동 같은 AI 확장을 얹을 수 있다는 점 때문에 팀 표준이 필요한 조직에서 무난한 선택지로 남아 있다.

Cursor는 VS Code 포크 기반이라 확장 호환성을 유지하면서도, 에디터 자체가 AI를 1급 시민으로 다룬다. 같은 설문에서 Cursor는 17.9%였다. 발행 당시에는 '가장 빠르게 점유율을 끌어올렸다'고 썼지만, 증가 속도를 보여 주는 1차 자료는 확인하지 못해 그 표현은 뺐다. 이름 하나는 주의해야 한다. 발행 당시 이 글은 Composer를 멀티파일 편집 기능 이름으로 소개했는데, Cursor 공식 블로그는 2025년 10월 29일 자체 에이전트 모델을 Composer라는 이름으로 발표했다. 자료를 읽을 때 기능과 모델 중 어느 쪽을 말하는지 구분해야 한다.

Zed는 Rust로 작성된 오픈소스 에디터로, 공식 사이트는 스스로를 '속도와, 사람 및 AI와의 협업을 위해 만든 미니멀 코드 에디터'라고 소개한다. 현재 macOS·Linux·Windows용 내려받기를 제공하고, Agent Client Protocol(ACP)을 통해 Claude Agent·Codex·OpenCode 같은 외부 에이전트를 에디터 안에서 쓸 수 있다고 밝힌다. 같은 설문에서 Zed는 7.3%, Neovim은 14%, IntelliJ IDEA는 27.1%였다. Neovim은 터미널 중심 워크플로를 지키는 개발자들의 선택이며, LazyVim 같은 배포판으로 진입장벽이 크게 낮아졌다. JetBrains(IntelliJ, PyCharm, GoLand 등)는 대규모 엔터프라이즈 자바/코틀린, 정교한 리팩터링·디버깅이 필요한 영역에서 쓰인다.

2. AI 코딩 - Claude Code, Codex, Cursor, Copilot, Aider

2026년 가장 빠르게 바뀌는 범주다. 중요한 것은 "어떤 게 최고냐"가 아니라 작업 유형별로 맞는 범주가 다르다는 사실이다. 크게 세 갈래다. 저장소 전체를 대상으로 명령을 받아 여러 파일을 고치는 에이전트형, 에디터 안에서 변경을 보며 편집하는 에디터 통합형, 입력 중에 다음 코드를 제안하는 자동완성형이다. 다만 아래에서 보듯 한 제품이 여러 갈래를 함께 갖추면서 경계는 흐려졌다.

Claude Code는 터미널에서 시작한 에이전트형 도구로, 대규모 멀티파일 리팩터링·코드베이스 탐색·반복 작업 자동화에 쓰인다. 공식 문서는 현재 터미널 CLI, IDE 확장(VS Code·JetBrains), 데스크톱 앱, 웹에서 쓸 수 있다고 안내하며, 대부분의 사용 환경에 Claude 구독이나 Anthropic Console 계정이 필요하다고 밝힌다. OpenAI Codex도 같은 방향이다. OpenAI 문서는 Codex를 데스크톱 앱, 웹, CLI, IDE 확장, 클라우드 환경, GitHub 연동에서 쓸 수 있다고 안내한다. 발행 당시 '터미널 에이전트'로 묶었던 두 도구가 이제는 여러 화면에 걸쳐 있다. 모델을 바꿀 때 기존 프롬프트와 설정을 옮기는 문제는 설정을 그대로 옮기면 생기는 일에서, 에이전트에게 계획을 맡기는 방식은 계획 모드는 죽었는가에서 따로 다뤘다.

Cursor는 에디터 안에서 컨텍스트를 유지하며 변경 사항을 눈으로 확인하고 작업하려는 경우에 쓰인다. GitHub Copilot은 무료 요금제(Copilot Free)와 여러 유료 요금제가 있고, GitHub 문서는 에이전트 모드가 무료 요금제부터 포함된다고 적고 있다. 발행 당시 '자동완성 중심의 가벼운 보조'로만 소개한 것은 지금 기준으로 좁은 설명이다. Aider는 Git diff 기반의 미니멀 CLI 도구로, 변경 이력을 커밋 단위로 남긴다. 다만 GitHub 릴리스 목록의 최신 릴리스는 2025년 8월 9일의 v0.86.0이며, 2026-09-29 확인 시점까지 그 뒤 릴리스는 올라오지 않았다. 새로 도입한다면 저장소의 최근 활동부터 확인하는 편이 안전하다.

실무 팁: AI 코딩 도구는 하나로 끝나지 않는 경우가 많다. 저장소 전체를 건드리는 큰 작업은 에이전트형, 화면을 보며 고치는 편집은 에디터 통합형, 타이핑 보조는 자동완성형처럼 작업 단위로 범주를 나눠 보면 무엇이 비어 있는지 보인다. 한 저장소에서 여러 에이전트 작업을 동시에 돌린다면 작업 폴더를 나누는 방법을 다룬 git worktree 실무 가이드가 도움이 된다.

3. 터미널 - Warp, Ghostty, iTerm2, Alacritty

터미널은 오랫동안 정체된 카테고리였지만 최근 몇 년 사이 변화가 컸다. Warp는 블록 기반 UI와 AI 명령 추천으로 "터미널을 다시 디자인한" 도구로 주목받았고, 현재 공식 사이트에서는 스스로를 '에이전트형 개발 환경(the agentic development environment)'이라고 소개한다. 터미널에서 출발해 에이전트 실행 환경으로 무게를 옮긴 것이다. Ghostty는 2024~2025년 등장한 GPU 가속 터미널로, 공식 문서는 '빠르고, 기능이 풍부하고, 네이티브한' 터미널 에뮬레이터라고 설명하며 현재 macOS와 Linux를 지원한다.

iTerm2는 macOS 사용자들의 오랜 표준으로 풍부한 기능과 안정성을 자랑하고, Alacritty는 Rust 기반 미니멀 GPU 터미널로 "빠르고 단순한 것"을 원하는 사람들의 선택이다. 터미널 선택의 핵심은 결국 속도, 커스터마이징 자유도, 그리고 tmux·셸 설정과의 궁합이다.

4. 버전 관리 - Git, GitHub, GitLab, Jujutsu(jj)

버전 관리의 토대는 변함없이 Git이다. Stack Overflow 2025 설문의 코드 문서화·협업 도구 문항에서 GitHub는 81.1%, GitLab은 35.6%였다(호스팅만 따로 묻는 문항은 아니다). 엔터프라이즈 자체 호스팅·통합 CI/CD가 필요한 조직은 GitLab을 택하기도 한다. 눈여겨볼 도구는 Jujutsu(jj)다. 공식 저장소는 jj를 'Git과 호환되면서 단순하고 강력한 버전 관리 시스템'이라고 소개한다. 2026-09-29 기준 GitHub 릴리스 목록의 최신 버전은 0.45.1로, 아직 1.0 이전이다.

jj의 매력은 "모든 변경이 자동으로 커밋되고, 충돌 해결과 히스토리 재작성이 훨씬 직관적"이라는 점이다. 아직 1.0 이전이라 팀 표준으로 삼기 전에 시험이 필요하지만, Git의 복잡한 명령 체계에 지친 개발자라면 한 번쯤 시험해 볼 가치가 있다.

5. API/HTTP - curl, Postman, Insomnia, Bruno

API 테스트와 HTTP 요청은 백엔드·풀스택 개발자의 일상이다. 가장 가벼운 도구는 여전히 curl이다. 빠른 단발 요청은 curl 한 줄이 가장 효율적이지만, 옵션이 많아질수록 명령어 작성이 번거로워진다. 이때 BrainDetox의 curl Builder 같은 무료 온라인 도구로 헤더·메서드·바디 옵션을 시각적으로 조합해 명령어를 바로 복사하면 실수를 줄일 수 있다.

GUI가 필요할 때 Postman은 팀 협업·컬렉션 공유 기능을 폭넓게 갖췄지만, 2026년 3월 요금제가 Free·Solo·Team·Enterprise로 바뀌면서 공식 문서 기준 무료 요금제는 사용자 1명으로 제한되고 팀을 만들 수 없게 됐다. 두 명 이상이 무료로 컬렉션을 공유하던 방식은 이제 유료 요금제가 필요하다. 오픈소스·로컬 우선의 Bruno는 오픈소스 판과 유료 판(Pro·Ultimate)이 있고, 가격표상 앱 안의 Git 연동(Native Git Integration)은 유료 판 항목이다. Insomnia는 무료 요금제(Essentials)가 있으며, 로그인 없이 쓰는 로컬 전용 Scratch Pad를 제공한다.

6. 컨테이너/오케스트레이션 - Docker, Podman, k9s, Lens

컨테이너는 이제 선택이 아닌 기본이다. Stack Overflow 2025 설문에서 Docker를 쓴다는 응답은 전체의 71.1%였다. 데몬리스(daemonless)·루트리스(rootless) 구조와 라이선스 조건을 이유로 Podman을 쓰는 환경도 있다. 발행 당시에는 'Podman으로 옮겨가는 흐름이 뚜렷하고 기업 환경에서 채택이 늘었다'고 썼지만, 이를 보여 주는 1차 자료는 확인하지 못해 그 표현은 뺐다.

쿠버네티스를 다룬다면 터미널 기반 클러스터 관리 도구 k9s가 자주 쓰인다. 키보드만으로 파드·로그·리소스를 빠르게 탐색할 수 있어 터미널 중심 운영에 맞는다. GUI를 선호한다면 Lens가 멀티 클러스터 관리에 편리하다.

7. 데이터베이스 도구 - DBeaver, TablePlus, DataGrip

데이터베이스 클라이언트는 취향이 강하게 갈리는 영역이다. DBeaver는 무료·오픈소스이면서 거의 모든 DBMS를 지원해 범용 클라이언트로 통한다. TablePlus는 빠르고 깔끔한 UI로 macOS 사용자들이 많이 찾으며, 가벼운 작업에 특히 쾌적하다. DataGrip은 JetBrains 생태계 사용자에게 자연스러운 선택으로, 정교한 SQL 자동완성과 리팩터링이 강점이다. JetBrains는 2025년 10월 1일 공식 블로그에서 DataGrip을 학습·취미·오픈소스·콘텐츠 제작 같은 비상업적 용도에 무료로 제공한다고 발표했다. 업무(상업적) 사용은 여전히 유료 라이선스 대상이다.

DataGrip 발표문이 AI 기반 코드 완성을 기능으로 소개하듯, 데이터베이스 도구에도 자연어 쿼리 생성·스키마 설명 같은 AI 기능이 들어오고 있다. 도구별 지원 범위는 이번에 확인하지 않았다. SQL을 직접 쓰는 시간이 줄고, 검토하고 다듬는 시간이 늘어나는 변화가 진행 중이다.

8. 노트/문서 - Obsidian, Notion, Logseq

지식 관리는 생산성의 숨은 축이다. Obsidian은 로컬 마크다운 파일 기반에 강력한 링크·그래프 기능을 더해, 데이터 소유권을 중시하는 개발자들이 쓴다. 2025년 2월 20일부터 상업용 라이선스가 선택 사항이 되어, 회사 업무에도 무료로 쓸 수 있다(Obsidian 공식 블로그). 플러그인 생태계가 방대해 거의 모든 워크플로를 커스터마이징할 수 있다.

Notion은 팀 협업·데이터베이스·위키가 한곳에 모인 올인원으로, 문서와 프로젝트 관리를 통합하고 싶은 팀에 강하다. Logseq는 아웃라이너 기반의 오픈소스 도구로, 일일 노트와 양방향 링크 중심의 사고 정리에 특화돼 있다. 선택의 기준은 결국 "내 데이터를 누가 쥐고 있는가"와 "혼자 vs 팀"이다.

9. 모니터링/디버깅 - Sentry, Datadog, Grafana

프로덕션을 운영한다면 관측성(observability) 도구는 필수다. Sentry는 에러 추적·성능 모니터링에 널리 쓰이는 도구로, 적은 설정으로 빠르게 예외와 스택트레이스를 수집한다. Datadog은 인프라·APM·로그·보안을 아우르는 통합 플랫폼으로, 규모 있는 조직의 종합 관측성 허브 역할을 한다.

Grafana는 Prometheus·Loki 등과 결합한 오픈소스 시각화의 중심이다. 메트릭 대시보드를 직접 구성하고 싶은 인프라·SRE 엔지니어에게 핵심 도구다. 비용·잠금을 피하면서 직접 통제하고 싶다면 Grafana + Prometheus 같은 오픈소스 스택이, 빠른 SaaS 통합을 원한다면 Datadog 같은 통합 플랫폼이 맞는다.

10. 유틸리티 - JWT 디코더, JSON/YAML 변환

매일 쓰지는 않지만 막상 필요할 때 없으면 답답한 작은 도구들이 있다. JWT 토큰의 페이로드를 까보거나, JSON과 YAML을 서로 변환하거나, HTTP 상태 코드의 의미를 빠르게 확인하는 일들이다. 이런 작업에 무거운 IDE나 별도 설치 도구를 켜는 것은 비효율적이다.

가벼운 무료 온라인 대안으로 BrainDetox의 JWT Decoder, YAML/JSON 변환기, HTTP 상태 코드 참조, JSON 포매터 등을 활용하면 브라우저에서 즉시 처리할 수 있다. 설치 없이, 데이터를 서버로 보내지 않고 클라이언트에서 처리되는 도구를 고르는 것이 보안상으로도 안전하다.

11. 한국 개발자가 선호하는 도구

글로벌 흐름과 별개로 한국 개발 생태계에는 특유의 환경이 있다. 첫째, 협업 메신저는 Slack과 함께 카카오워크·잔디 등 국산 도구가 기업 환경에서 쓰인다. 둘째, 이슈 트래킹은 Jira가 오래 쓰여 왔고(Stack Overflow 2025 설문 전 세계 응답 46.4%), 스타트업에서는 Linear·Notion을 쓰는 경우도 있다. 한국만의 도구별 비율을 보여 주는 공개 설문은 이번에 확인하지 못했다.

셋째, 한국 개발자 커뮤니티(news.hada.io, OKKY, 인프런 등)는 도구 정보 공유의 핵심 채널로, 새 도구가 국내에 알려지는 통로가 된다. 넷째, 사내 보안 정책상 클라우드 SaaS 사용이 제한되는 환경이 많아 로컬·오픈소스·온프레미스 대안(GitLab 자체 호스팅, 로컬 LLM 등)이 검토 대상에 자주 오른다. 발행 당시에는 이 관심이 '글로벌 평균보다 높다'고 썼지만 비교 수치는 확인하지 못해 뺐다. 도구 선택에서 "데이터가 어디로 가는가"를 따지는 것이 중요하다는 점은 그대로다.

12. 2026 도구 선택의 5가지 원칙

도구는 인기 순위로 고르는 것이 아니다. 본인의 병목에서 출발하는 다섯 가지 원칙을 권한다.

  1. 익숙함의 관성을 인정하되 1년에 한 번은 재평가하라. 손에 익은 도구는 강력한 자산이지만, 정기적으로 핵심 도구를 점검하지 않으면 더 나은 대안을 영영 놓친다.
  2. 통합 비용을 따져라. 도구 수를 늘리기 전에 기존 도구로 해결 가능한지 먼저 확인하라. 도구가 많아질수록 컨텍스트 전환 비용이 커진다.
  3. 잠금(lock-in)을 경계하라. 데이터 내보내기와 오픈 포맷을 우선하라. 특정 벤더에 데이터가 묶이면 전환 자유를 잃는다.
  4. 팀 표준과 개인 취향을 분리하라. 협업에 영향을 주는 도구(VCS, CI, 이슈 트래커)는 팀 표준을, 개인 생산성 도구(에디터, 터미널, 노트)는 취향을 따라도 된다.
  5. 무료/오픈소스 대안을 먼저 시험하라. 유료로 올라가기 전에 무료 대안으로 요구사항을 검증하면, 정말 필요한 기능에만 돈을 쓰게 된다. 무료 요금제의 인원·기능 조건은 바뀔 수 있으니(2026년 3월 Postman 사례) 도입 전에 현재 조건을 확인하라.

13. 결론: 상황별로 쓰이는 도구 범주

결국 좋은 스택은 유행하는 도구의 합이 아니라 본인 워크플로의 마찰을 가장 많이 줄이는 조합이다. 도구 자체가 목적이 되는 순간, 도구를 세팅하느라 정작 만들어야 할 것을 못 만드는 함정에 빠진다. 위 10개 범주를 모두 채울 필요도 없다. 본인이 자주 막히는 지점부터 하나씩 최적화하면 된다.

특정 제품을 고르는 대신, 어떤 상황에서 어떤 범주의 도구가 쓰이는지로 정리하면 다음과 같다. 괄호 안 이름은 본문에 나온 예시일 뿐 순위가 아니다.

  • 에디터: 팀 표준·확장 생태계가 중요하면 범용 에디터(VS Code), AI 편집 비중이 크면 AI 통합 에디터(Cursor, Zed), 대형 자바/코틀린 프로젝트는 통합 IDE(JetBrains)
  • AI 코딩: 저장소 전체 작업은 에이전트형, 화면을 보며 고치는 편집은 에디터 통합형, 타이핑 보조는 자동완성형. 쓰는 제품이 어느 갈래까지 겸하는지 먼저 확인
  • 터미널: 속도·단순함이 우선이면 GPU 가속 경량 터미널, 에이전트 실행까지 한 화면에서 원하면 에이전트형 개발 환경, 세션 유지는 tmux 같은 멀티플렉서
  • 버전 관리: Git + 호스팅(GitHub·GitLab), 새 워크플로 실험은 Git 호환 VCS(jj, 1.0 이전)
  • API: 단발 요청은 curl(+ 온라인 curl Builder), GUI를 여럿이 쓰려면 무료 요금제의 인원 조건부터 확인
  • 컨테이너: 로컬 개발은 컨테이너 런타임(Docker·Podman), 쿠버네티스 운영은 터미널 UI(k9s) 또는 GUI(Lens)
  • DB: 여러 DBMS를 한 도구로 다루면 범용 클라이언트, 비상업 용도로 IDE급 기능이 필요하면 DataGrip의 무료 조건 확인
  • 노트: 데이터 소유권이 우선이면 로컬 파일 기반(Obsidian), 팀 위키·프로젝트 관리가 우선이면 올인원(Notion)
  • 모니터링: 에러 추적(Sentry) + 직접 통제하는 메트릭 스택(Grafana/Prometheus) 또는 SaaS 통합 플랫폼(Datadog)
  • 유틸리티: 데이터를 서버로 보내지 않는 브라우저 기반 도구(JWT 디코더, JSON/YAML 변환 등)

이 목록을 그대로 따르라는 뜻은 아니다. 핵심은 "남이 쓰는 것"이 아니라 "내가 무엇에 막히는가"에서 출발하는 사고방식이다. 2026년의 도구는 그 어느 때보다 풍부하고, AI 덕분에 도구 간 경계도 흐려졌다. 그만큼 선택의 자유가 커졌고, 그래서 더더욱 '왜 이 도구인가'를 스스로 설명할 수 있어야 한다.

## 1. 상황별 도구 범주 결정표

괄호 안 이름은 본문에 나온 예시일 뿐 순위가 아니다.

|---|---|---|
| 에디터 | 팀 표준·확장 생태계가 중요하다 | 범용 에디터 (VS Code) |
| 에디터 | AI 편집 비중이 크다 | AI 통합 에디터 (Cursor, Zed) |

| 노트 | 팀 위키·프로젝트 관리가 우선 | 올인원 (Notion) |
| 모니터링 | 직접 통제하고 싶다 | 오픈소스 메트릭 스택 (Grafana/Prometheus) |
| 모니터링 | 빠른 SaaS 통합 | 통합 플랫폼 (Datadog) |
| 유틸리티 | 데이터를 서버로 보내면 안 된다 | 브라우저에서 처리하는 도구 |

---

## 2. 도입 전 확인 체크리스트

- [ ] 무료 요금제의 인원 제한을 확인했다 (Postman 무료 요금제는 2026년 3월 개편 후 1명, 팀 생성 불가)
- [ ] 무료 요금제에 들어 있는 AI 기능 범위를 확인했다 (GitHub 문서: Copilot Free에 에이전트 모드 포함)
- [ ] 상업·비상업 사용 조건을 확인했다 (DataGrip은 2025-10-01부터 비상업 무료, 업무 사용은 유료 라이선스)
- [ ] 업무 사용 라이선스를 확인했다 (Obsidian 상업용 라이선스는 2025-02-20부터 선택 사항)
- [ ] 지원 OS를 확인했다 (Ghostty: macOS·Linux / Zed: macOS·Linux·Windows)
- [ ] 계정·구독이 필요한지 확인했다 (Claude Code 대부분의 사용 환경은 Claude 구독 또는 Anthropic Console 계정 / Insomnia Scratch Pad는 로그인 불필요)
- [ ] 앱 안의 기능이 어느 판에 들어 있는지 확인했다 (Bruno 가격표: Native Git Integration은 Pro·Ultimate 항목)
- [ ] 저장소의 최근 릴리스를 확인했다 (Aider 최신 릴리스 v0.86.0, 2025-08-09 — 확인 시점까지 그 뒤 릴리스 없음)
- [ ] 버전 성숙도를 확인했다 (jj 최신 0.45.1, 1.0 이전)
- [ ] 이름이 기능인지 모델인지 구분했다 (Cursor의 Composer는 2025-10-29 발표된 자체 에이전트 모델 이름)
- [ ] 데이터가 외부 서버로 나가는지 확인했다
- [ ] 협업 도구(VCS·CI·이슈 트래커)는 팀 표준을 따르고, 개인 도구만 취향대로 골랐다
