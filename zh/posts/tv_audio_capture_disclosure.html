「关掉电源」到底关掉了什么 - 电视在待机状态下仍在继续做的事

待机状态的定义，指纹、声音与转写的区分，以及设置能够到的范围

2026-09-07 IT/技术

按下遥控器上的电源键，画面就灭了。那一刻大多数人脑中浮现的画面只有一个：机器停住了。可是翻开产品说明书会发现，这个词在那里并不是这么用的。

「关」不是一种状态。只有画面熄灭的状态、画面和声音都熄灭但电路仍在等信号的状态、为了下次开机更快而特意保持清醒的状态，这三者各自独立存在，厂商文档给它们起的是不同的名字。这个区分就是本文的心脏。

本文写下的内容，来自厂商的官方支持文档与产品手册、广播标准规格、公开专利与学术论文、监管机构的起诉书与和解令，以及韩国国家法令信息中心的法条原文。只出现在某一篇调查报道、无法与一手资料对上的说法，没有当作正文的事实，而是按归属写出；未能分辨的部分连同理由集中放在后面一节。

起因 - 公开了什么，依据又开放到哪一步

2026年9月初，一家硬件媒体把针对某厂商智能电视的调查结果做成约135分钟的影片公开。协作方是另一个硬件频道和几位独立研究者。这件事被转到韩国时，标题写的是在屏幕熄灭的状态下录制音频、并探测周边设备的行为被抓到了。

先要钉住资料本身的性质。同一份调查没有出文章版，一手产出物就是那段影片。不过有一位协作者在影片公开前一天另外贴了一篇技术文档性质的文字，把测试对象写成了一行：OLED65G5WUA 机型上的 webOS 10.2.1，并附了一句只在唯一一台设备上做过测试的保留。

那份文档里有两句会改变这件事方向的话。一句是测试机上的内容识别守护进程处于未启用状态，文中写着库是空的、数据库被填成 0。另一句是语音处理链路在设备内部运行，向远端出去的只有自然语言处理和搜索后端，连唤醒词的名字都写了出来。

厂商到目前为止没有就这次调查表态。按报道时点是无回应，这和拒绝回应不是同一种状态。被广泛引用的那句不收集也不录制周围对话的厂商表述，是针对2026年7月另一件事说的，把它搬过来当作对这次的解释，写出来就是错的。

一篇里装着性质不同的四样东西

这次调查被当成一整块来读，是因为四样性质不同的东西装在了一篇里。它们的依据种类不同，用户能采取的措施也不同。不分开的话，听起来最重的那个词会把其余的全盖住。

类别报道写的一手资料能对上的部分
内容识别把画面的影像和声音做成指纹，记录收视内容技术文档写的是测试机上对应的守护进程未启用
麦克风与语音在屏幕熄灭的待机状态下录到了清晰的麦克风语音唤醒词待机本身在厂商文档里是作为功能写明的
网络探测扫描同一网络里的手机和手表，收集周边无线信息同一类收集在2017年监管机构起诉书里被逐项列出
软件漏洞发现了远程代码执行缺陷公开流程尚在进行中，还没有已分配的编号

另外还有一个经常被搞错的数字。一起被引用的 2 亿 1,600 万这个值，是广告业务部门写在自家宣传资料里的全球装机量，既不是调查对象的台数，也不是被观测到的设备数。

关掉所指的状态不止一种

只要电源线插着，电视就不会彻底死掉。要接收遥控器信号，接收部就得活着；要做预约录制或软件更新，时钟和通信部就得活着。所以产品文档把「关」分成了好几层。

状态画面仍在运转的部分用户怎么叫它
拔掉插头熄灭无彻底关了
普通待机熄灭遥控接收部、电源电路关了
快速开机类功能开启熄灭在上面再加系统的一部分保持待机关了
待机模式开启背景画面或熄灭再加背景画面、音乐播放、唤醒词待机关了
仅关闭画面熄灭主机整体都在工作只听声音

表里的五种状态，用户大多用同一个词来叫，就是关了。报道写屏幕熄灭的状态时，如果不指明那是上面哪一行，同一个句子就会指向完全不同的两件事。

厂商文档里已经写下的东西

有意思的是，这个区分的相当一部分早就写在厂商面向韩国市场的支持文档里。关于快速开机类功能的说明是：关闭电视电源时不完全终止，而是转入待机模式，让下次开机画面更快亮起的便利功能。同一份文档还补了一句，设定后需要维持待机状态，因此待机功率可能比平时增加。

同一份文档也用表格写下这个功能的名称与路径每次版本升级都在变。下面是韩国市场机型的菜单原文与对照译名，其他销售地区并不相同。

webOS 26.0 以后   설정 → 전체 설정 → 시스템 → 기타 설정 → TV 빨리 켜기
webOS 23 以后     설정 → 전체 설정 → 일반 → 시스템 → 기타 설정 → TV 빨리 켜기
webOS 6.0 以后    설정 → 전체 설정 → 일반 → TV와 외부 기기 관리 → TV 관리 → TV 빨리 켜기
webOS 5.0         설정 → 전체 설정 → 일반 → 추가 설정 → Q 스타트+
webOS 4.0 以前    설정 → 전체 설정 → 일반 → Q 스타트+

对照译名  设置 → 全部设置 → 通用 → 系统 → 其他设置 → 电视快速开机 / Q Start+
※ 以上为韩国市场机型的菜单名称，其他国家和地区的名称与层级不同

2022年机型系列另有一个叫做待机模式的独立功能，说明里写着电视关掉之后背景画面和蓝牙音乐播放仍会继续，同时还写着即使背景画面熄灭，唤醒词识别依然工作。

而决定性的一句在语音识别的支持文档里：电视处于关闭状态时，若识别到 Hi LG 这句语音，会发出一声提示音。同一份文档列出了这个功能不工作的条件，分别是语音识别被关掉、没有连接互联网，或者2022年机型的待机模式与更早机型的快速开机、Q Start+ 功能被关掉。

把这份清单反过来读，因果就直接露了出来。把快速开机类功能开着，本身就是让关掉的电视维持唤醒词待机的条件。这不是推测，把厂商的两页文档叠起来读就会得到，也意味着便利功能和常时待机被绑在同一个开关上。

ACR - 认出屏幕上正在放什么的技术

让设备自己认出此刻屏幕上在放什么的技术叫自动内容识别，简称 ACR。放进去的理由很简单：不分广播、外部输入还是应用都能把收视记录收齐，那就是广告投放和推荐的原料。

先要分清规格定了什么、又没定什么。下一代广播标准的相关文档写的是，接收机从影像或音频帧里提取指纹送到远端服务器，服务器再拿它去和数据库比对。可是同一节后面附了一句保留：提取并发送指纹的过程，可以由指纹技术提供方、广播方与接收机厂商三方商定的专有技术来完成，标准并不作规范性规定。所以写成标准规定了指纹方式，那就是错的。

另一个常被搞错的地方是走哪条路。装进电视的 ACR 不是用麦克风去听房间里的声音。同一份标准文档的适用范围一节设想的是机顶盒经 HDMI 连接、只收到未压缩影像与音频的情形，即从画面与解码链路上取。某家专利写得更具体：每 0.1 秒醒来一次，从画面上取 13 个像素的色值，按 1 秒打包送到服务器。1080p 一帧超过 207 万像素，所以这不是截屏，而是极小的抽样。

用麦克风做内容识别而出问题的案例，发生在手机应用那一侧，不是电视。把这两者混在一起，叙述就会走偏。

指纹里留下什么，又丢掉什么

音频指纹方式同样不发送原声。跟着被广泛引用的2002年算法的处理流程走一遍，就能看清什么被丢掉了。

  • 把进来的声音降到 5 kHz 单声道。人声的相当一部分在这一步就已经消失
  • 只看 300 到 2000 Hz 之间。再往上的频段等于根本不存在
  • 把这一段切成 33 个频带
  • 沿时间轴与频率轴只留下能量差分的符号，大小全部丢弃
  • 结果是每 11.6 毫秒生成 32 比特

换成数字，规模就抓得住了。CD 音质每秒约 1,411 千比特，这份指纹每秒约 2.8 千比特，大约五百分之一，留下的只有低频一部分的符号位。另一个体系里那个有名的算法方向也一样。那篇论文写着把频谱图缩成稀疏的坐标集合，并在这一步明确写出幅度分量已被去除，还补了一句每个哈希装进一个 32 位整数。

广告业务部门的公开文档写的方向也相同：从播放设备的音频里取约 10 毫秒、也就是百分之一秒长度的短样本，在设备上做成哈希生成签名，该签名会与 IP 地址或设备标识符相连，但不与姓名、地址、电子邮件相连。

无法还原和里面是空的，是两回事

这里必须把两句话摆在一起才准确。只取其中一句，往哪边都会歪。

第一，从指纹还原原声，就压缩率而言不成立。经营方的说明也写着自家软件不传输也不保存人的话语或原始音频、签名无法还原，并补充说不分析话语、词汇或语言。

第二，这不等于指纹里什么都不剩。2024年发表的一项研究正面处理了音频指纹在隐私层面是安全的这个通念，并写道，仅凭指纹就识别说话人和词汇是可行的，这一点由他们首次给出。报告的数字是 40 名说话人最高 90%、10 个数字最高 82% 的识别准确率。同一篇论文也明确写下，他们的攻击并不是把强压缩本身还原回去。

整理起来就是这样：还原做不到，推断做得到。两句里只引用一句，叙述在那一刻就歪了。

路径出去的是什么原声还原这个说法从哪里来
影像指纹画面上部分像素的色值样本不适用公开专利与监管机构起诉书
音频指纹低频段能量差分的符号位不成立学术论文与经营方公开文档
语音助手转写会话期间的语音与转换后的文本原声本身就是对象厂商隐私政策的收集项目
周边声音常时收集被主张的对象若属实则成立未能与一手资料对上

麦克风打开的那一刻 - 唤醒词与会话

指纹和转写是两条不同的路。上一节表格里的第三行，才更接近这次事件真正的争点。

厂商的隐私政策里有语音信息与语音转换文本信息两个收集项目，写明在具备语音识别功能的设备上、用户使用该功能时收集，保存期限自收集日起一年。不过作为示例列出的设备是冰箱、净水器、空调和扫地机器人，电视并不在那个括号里。

技术文档那一侧的说法前面已经看过：语音处理链路在设备内运行，向远端出去的是自然语言处理和搜索后端。韩国的支持文档里也有唤醒词可以在两个之间选择的说明。

看过影片的用户之间解读是分裂的。一方连时间戳都标了出来提出反驳，大意是被记录的语音全都是在设备上语音输入被明确开始之后才处理的，而那个开始要么是开着的唤醒词，要么是用户在搜索界面按下的语音输入。同一份反驳把影片展示的异常现象总结成这样：静默到来后语音输入会话并没有立刻结束，而是继续把后面的话写了下来，其间画面下方一直显示着输入框。

另一方写的是，把看上去几乎无声的流放大之后，有能听见对话的片段。两份证言彼此并不矛盾。会话在静默之后没有断开的话，周围的话就会照样进去。另一方面，追查语音命令以明文形式被记录这个说法的出处，会走到一条匿名论坛留言上，而同一处马上就跟了反驳。

所以是录音还是指纹这个问法，在这件事上漏掉了一个选项。到目前为止最精确的说法，指向三者中的语音助手会话的转写。

周边设备探测 - 同一个网络里看得见的东西

网络探测是和前面几样不同层次的问题。收视记录是关于看了什么的信息，而同一网络里的设备清单，更接近关于这是一个什么样的家的信息。

在家用路由器底下，设备为了互相找到对方会广播自己的名字。这种广播里常常带着设备种类、厂商，以及用户自己起的名字。所以从一份清单里能读出下面这些。

  • 家庭构成 — 从个人设备的数量和种类，能把住着几个人这件事收窄
  • 持有的装备 — 被绑在某个厂商生态里的程度会显现出来
  • 作息时段 — 哪台设备什么时候出现、什么时候消失，能读出是否在家
  • 年龄层的线索 — 学习用设备或玩具类设备的存在会成为信号

重要的是，这不是设备的过错，而是规格本来就这么设计的结果。服务发现规格规定设备名要放成人能读懂的友好名称，并在附录里以看见的就是得到的为题解释理由，还写着对用户可见的那个名字就是该服务的主要标识符。承载设备描述的另一份规格把厂商名和型号名列为必需项、序列号列为建议项，并规定设备的唯一名称必须跨越重启保持不变。

这些规格制定的当时，隐私并不在考虑项里。服务发现规格的安全考虑一节只写了除既有命名体系的要求之外不需要额外的东西。这个认识改变得晚得多：同一个标准化组织7年后的文档写着这种方式会暴露设备信息，那些信息不只对参与发现的设备可见，对安静听着这个网络的一方也同样可见。

屏幕共享类规格里有一处显眼的不对称。从外部试图启动应用时，规定必须放一个由用户批准的界面；而对于查询装了哪些应用、此刻在跑哪个，没有对应条款。开电视要问许可，往里看一眼不问。同一份规格还规定，远程开机功能开启时响应里要带上 MAC 地址。

这些信息的共同点是，用户在那台电视上什么都不做，它们也照样汇集。收视记录要有收视这个行为才产生，设备清单只要通着电、挂在网上就产生。关于观测本身的话题写在「看见」网络流量意味着什么那篇里，家庭内设备设置的一般做法则由智能家居·IoT设备安全完全指南 — 威胁·设置·管理处理。

周边无线接入点清单变成位置的路径

这里还有一层。设备如果把自己周围的无线接入点清单也一并收集，那份清单就成了把位置收窄的原料。接入点大多长期待在同一处，所以哪些标识符会一起出现，本身就接近一组坐标。

这个转换有多容易，公开的定位服务规格给出了答案。某项服务的官方文档规定请求体里要放物理上可区分的两个以上接入点，每一项的必需字段是 MAC 地址，响应则是纬度、经度和用米表示的精度半径。实现同一接口的另一项服务说明，要求至少两个是强制性的隐私限制。整理下来就是：没有卫星信号，也没有 IP 地址，仅凭周围两个接入点的标识符就能得出坐标。

这不是假设，依据在2017年美国监管机构对另一家厂商提起的起诉书里。内容识别软件在收视数据之外还一并收集了什么，被列在了同一段里。

Defendants' ACR software also periodically collects other
information about the television, including IP address,
wired and wireless MAC addresses, WiFi signal strength,
nearby WiFi access points, and other items.

  IP 地址、有线与无线 MAC 地址、无线信号强度、周边无线接入点

同一份起诉书写着该软件每天最多从超过 1,000 万台电视收集 1,000 亿个数据点并无限期保存，后面还写着性别、年龄、收入、婚姻状况、家庭人数、学历、住房拥有与否及房产价值这类人口统计项目被结合到收视数据上。随后的和解令另行定义了收视数据，要求告知与隐私政策和使用条款分开，并写明在软件更新这类存在交互的媒介上告知必须无法回避。关于位置信号的一般讨论在智能手机位置追踪拦截完全指南里，不需要保存就能认出设备的那一类信号则在清掉 Cookie 之后，为什么还是被当成同一个人里。

这在电视类设备上也有学界记录。2019年的一项调查扫过两个播放平台各 1,000 个频道，与已知追踪商通信的频道分别是 69% 和 89%。同一项研究写着设备标识符、序列号、无线 MAC 地址和所连无线网络的名称时而经由未加密的连接传输；其中一个平台的外部控制接口会返回所连无线网络的名称，而跨源限制开着，任意网页都能读到。把那个值和公开的无线网络数据库对上，就能把用户的位置收窄。该研究的结论之一是，设备提供的广告追踪限制之类的应对手段实质上没有效果。

断网这个选择与它的代价

要确实消掉向外出去的路径，办法是把它从网络上摘下来。参与调查的一方据传也建议了这个选择。不过它带着代价，不把代价一起写出来就只说了一半。

  • 安全更新会停下 — 软件缺陷即使被修好，也到不了那台设备。在漏洞正被讨论的局面下，这是方向相反的措施
  • 应用与广播附加功能会停下 — 买智能电视付出的价钱里，相当一部分就是这些功能
  • 功能可能只是换了个地方 — 接上外部播放设备，那台设备厂商的政策就会替代生效。路径变了，不是消失了
  • 有些功能以同意条款为前提 — 韩国的说明里写着语音识别在同意使用条款之后才启用

所以实际的判断不是二选一。买这台设备原本想用什么，决定了网络连接、单项设置与外部设备之间怎么组合。想把待机功率这根轴也一起看，可以参考节能家电选购完全指南 - 能效等级·电费·省电。

韩国的规制 - 停在法条层面

下面只搬了法条上写着的内容，而且全部是韩国法律。特定产品或特定经营者的处理是否违反这些条文，本文不作判断，那需要经过事实认定与有权机关的程序。其他国家和地区适用各自的法律，条文并不相同。

法律条文写着的内容
个人信息保护法（개인정보 보호법）第15条第1款第1项取得信息主体同意时可以收集，并在其目的范围内使用
同法第16条第2款、第3款对最小限度信息以外的收集，必须具体告知可以不同意；不得以未作该同意为由拒绝提供商品或服务
同法第22条第1款各项同意事项必须区分开、以能够明确认知的方式告知并取得；所列举的情形必须分别取得
同法第23条第1款列举敏感信息：思想信念、工会与政党的加入退出、政治见解、健康、性生活等，语音不在这份列举里
同法第30条第1款第7项自动收集个人信息的装置的安装运营及其拒绝事项，应写入隐私政策
同法第4条第6项把拒绝完全自动化处理所作决定、或要求说明的权利，列为信息主体的权利
位置信息法（위치정보법）第2条第1项把位置信息定义为利用电气通信设备测定的场所信息
同法第15条第1款未经个人位置信息主体同意，不得收集、利用、提供个人位置信息
通信秘密保护法（통신비밀보호법）第3条第1款、第14条第1款不得录制未公开的他人之间的对话，也不得以电子装置或机械手段窃听

有几点需要补充。个人信息保护法的现行版本2025年10月2日施行，后面还跟着预定2026年9月11日施行的版本。另外，旧第6章的信息通信服务提供者特例已在2023年修订中删除，现行第39条之3是关于诉讼程序的条文，所以拿旧特例当依据的引用现在并不成立。

待机功率那一侧也值得写一行。韩国待机功率节减项目的指定产品清单里没有电视机。电视的待机功率在能效管理器材的告示中作为试验成绩书的测量项目处理，并不包含在卖场标签的标示项目里。也就是说，这是一个测了但不出现在标签上的值。

本文写下的设置路径与法条全部以韩国为准。菜单名称、机型的供应情况与适用法律在其他国家和地区都不相同，上述路径不能原样套用到韩国以外销售的机型，法条部分也只是对韩国法律的介绍。界面构成还会随版本升级、机型与销售地区变化。本文不包含对特定产品的动作或特定经营者的处理是否违法的判断，也不能替代法律咨询或产品诊断。自己设备的实际设置请以对应版本的厂商说明为准。

未能确认的部分

下面这些项目因为无法在一手资料里确认文面，没有作为事实写进正文。理由一并记下。

  • 原始音频是否真的从线路或存储设备上被取到 — 一手产出物只有一段135分钟的影片，无法做文面对照，也没有任何资料写出载荷的格式。所以正文把它归属为报道的说法
  • 屏幕熄灭的状态到底是哪一种状态 — 报道原文自己就用括号加了至少看上去是这样的保留。快速开机类当时是否开着，分辨不出
  • 测试当时同意项目是怎么设置的 — 反倒有唤醒词开着的迹象。内容识别守护进程未启用是否因为没有给出同意，文档也没写
  • 断网期间保存、重新连接时上传的说法 — 只出现在二手报道里，技术文档里没有对应的提及。那篇报道的措辞也不是周围声音，而是语音输入
  • 语音命令的明文记录 — 出处是一条匿名留言，并且在同一处就被反驳。不是一手资料
  • 韩国界面上是否有叫做收视信息的单独项目 — 韩文手册目录里没有该项目。是韩国未搭载还是换了名字，分辨不出，所以没有断定为韩国的路径
  • 条款界面里各个同意项目的名称 — 把它们逐项列出的厂商文档没有在网上公开。不看实机界面就分辨不出的项目
  • 近期机型是否内置麦克风 — 厂商公开的支持机型清单只更新到2022年系列，此外只写着请查看各机型规格
  • 漏洞的细节与编号 — 公开流程正在进行中，查不到已分配的编号。过去公开过的同类缺陷是2024年已修复的另一件事
  • 厂商对这次调查的立场 — 官方渠道上没有相关帖子。被广泛引用的那句是针对2026年7月另一件事的
  • 指纹方式不发送原声这一点的验证程度 — 依据是算法设计、标准文句与经营方公开文档，还没有解密实际通信内容来独立确认的研究。2024年的一项测量研究只看流量模式，把内容解读留作后续课题。所以正文只写到设计与文档的层面
  • 韩国销售机型上内容识别是否实际工作 — 广告部门公开的适用国家清单里没有韩国。是未适用还是清单没更新，分辨不出，所以没有以在韩国工作为前提
  • 韩国销售的电视在探测过程中实际发出的值 — 规格允许的范围能从文档上分辨，但特定产品在其中填了什么发出去是规格之外的问题，需要实测
