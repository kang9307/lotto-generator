引言：能下载和能使用是两回事

如果你正在找一个能在内部跑的小模型，候选名单又多了一个。2026年7月28日，Kakao 把 Kanana-2 四款轻量模型的权重推到了 Hugging Face 上。3B 和 1.3B，各有基座版与指令版。文件现在就能下载。

但首先要读的不是规格表，而是许可证第四条。开发并运营自家服务无需另行约定，可一旦卖给第三方，情况就变了。通过 API 出售、作为系统集成项目交付、或者装进你出售的设备，都需要单独的商用许可，合同对每一种情形都点了名。找轻量模型的人第一个想到的落地位置就是端侧，而这个位置被明确写进了例外条款。

这不是缺陷，是条件。而什么时候确认这个条件，才真正决定了落地进度。与其把性能验证全部做完再被法务拦下，不如在下载之前读完第四条，先确认自家公司处在第四条第二款的里面还是外面，这要便宜得多。

本文不会用分数把 Kanana-2 和别的模型排队。它讲的是究竟公开了什么、许可证划下的那条线、模型卡数字说了什么又没说什么，以及哪些组织现在该评估、哪些该等待。需要各模型的单价与上下文详细对比，可以看AI 模型综合对比。小模型在推理上超过大模型这一现象本身，另见小模型如何超越大模型的推理。

1. 公开了什么 - 四款模型的真实规格

公开对象是四个。名字相近容易混，先并排列出来。

仓库参数量类型如何构建
kanana-2-3b-base约 3B预训练基座在 TPU 集群上从零预训练
kanana-2-3b-instruct约 3B指令微调监督微调加强化学习
kanana-2-1.3b-base约 1.3B预训练基座由 3B 经级联剪枝与蒸馏压缩
kanana-2-1.3b-instruct约 1.3B指令微调在上述基座上做后训练

四款模型的共同规格如下。

  • 32,768 token 上下文 — 模型卡称为原生支持
  • 注意力三比一布局 — 三层滑动窗口配一层全注意力，窗口大小 1024
  • KV 缓存约减少 72.7% — 模型卡以 32K 长度为基准给出的数值
  • 韩语分词改进 30% — 相对上一代，模型卡的表述
  • 未使用 Kakao 用户数据 — 模型卡明确说明预训练与后训练均未使用
  • 许可证统一 — 四款均为 Kanana Open License Agreement

1.1 名称带来的两处混淆

第一处是 0.9B。模型卡提到系列中有 0.9B，但它不在本次公开范围内。查资料时 0.9B 的说法会混进来，而现在能下载的只有 3B 和 1.3B。

第二处更麻烦。另有一条 30B-A3B 产品线同样使用 Kanana-2 这个名字，放在各自的仓库里。那是压缩激活参数的专家混合结构，规模和用途都与本文的四款轻量模型完全不同。搜索时两者会混在一起，所以下载前要确认仓库名里带着 1.3b 或 3b。

1.2 KV 缓存减少 72.7% 在生产中意味着什么

这个数字来自架构而非基准测试。全注意力必须把此前所有 token 留在缓存里，而滑动窗口层只看最近的 1024 个 token。四层里有三层如此工作，长输入下的内存就会大幅下降。

关键不在这个百分比本身，而在于推理服务的成本通常由并发会话数决定。一张 GPU 上能放多少会话就是你的单价，而这个上限由 KV 缓存决定。文档越长，这套架构越有利。不过实际节省幅度会随量化方案、批大小和推理运行时实现而变化。模型卡的数值是一个标注了条件的测点，不是到处都能复现的数字。

2. 许可证 - 免费到哪里，从哪里开始协商

权重附带的是 Kanana Open License Agreement，文档标注的发布日期为 2025年7月17日。这份合同定了三件事：你可以做什么，再分发时要附上什么，从哪里开始需要单独协商。

2.1 可以做的

  • 使用、复制、分发 — 第二条第一款授予非独占、全球、不可转让、免版税的有限许可
  • 创建衍生作品并修改 — 同一条款明示，意味着允许微调
  • 开发并运营自家服务 — 第四条第二款。只要不落入下面的第四条第一款，无需单独商用许可
  • 用输出训练或改进其他模型 — 允许，但结果模型的名称须以 Kanana 为前缀

2.2 需要单独商用许可的三种情形

这是第四条第一款划出的区间，共同点是向第三方提供或转售。

  1. 通过 API、云平台或其他远程访问服务向第三方提供或转售对该材料及其衍生作品的访问
  2. 作为系统集成或本地部署方案的全部或一部分，向第三方提供或转售
  3. 嵌入端侧场景后向第三方提供或转售

第三种最能说明这次公开的性质。做轻量模型的理由就是要在设备上跑，而如果那台设备是你出售的产品，就落在条款之内。在自家应用里为自家服务运行，和把内含模型的产品卖给客户，在这份合同下是两种行为。

边界并不总是清晰。如果你做了自家服务，而这个服务对外有 API 供客户调用，那算运营自家服务，还是转售模型访问？仅凭条文并不能把每种形态都切干净。如果你的形态接近这一类，最好在商业结构定型之前就开始沟通。协商所需的时间是落地排期里的真实变量，拖得越久代价越大。

2.3 再分发时必须附上的

第三条第一款给出的条件。无论原样分发权重，还是分发微调后的衍生物，都适用。

  • 在与接收方的协议中纳入同样的合规义务
  • 随附本协议的副本
  • 对修改过的文件标注变更
  • 包含版权声明 — Kanana is licensed in accordance with the Kanana Open License Agreement. Copyright (c) KAKAO Corp. All Rights Reserved.
  • 在网站、界面和文档上醒目展示 Powered by Kanana
  • 基于该材料或其输出构建并分发的 AI 模型，名称须加 Kanana 前缀

展示义务会直接影响面向消费者的界面设计。如果你的构成属于再分发，就在设计评审阶段把位置留出来，而不是最后仓促塞一个徽标进去。

第六条和第七条不出所料：材料按现状提供并免除各项保证，除法律另有要求外不承担损害赔偿责任。这在开放权重里很常见，但也意味着这些句子会原样进入你们的内部风险文档。

你想做的事是否需要另行协商依据
接入内部文档处理流水线不需要第四条第二款
作为自家网络服务的功能不需要第四条第二款
用自家数据做微调不需要第二条第一款
公开发布微调后的模型不需要，但有声明与命名义务第三条第一款
以付费方式提供模型 API需要第四条第一款 (i)
交付到客户的本地环境需要第四条第一款 (ii)
装进设备作为产品出售需要第四条第一款 (iii)

2.4 那么这算开源吗

报道和公告都用了开源这个词。更准确的说法是带使用领域限制的开放权重。开源定义第六条规定许可证不得限制任何人在特定领域使用该程序，第一条要求不得限制再分发。第四条第一款同时触及这两点。

不必把这个区分读成挑刺。对多数企业用户来说，第四条第二款已经够用。但如果贵司的内部规程或采购标准里写着只接受开源许可证，那么这款模型按字面并不符合。这项确认属于文档工作而非工程工作，半天就能完成。开放权重与开源为何不是同义词，在2026 年开源 AI 现状里拆得更细。

这个形状基本决定了它适合什么活。按固定格式抽取、分类、摘要的任务很合适；以解方程为核心的任务则不合适。把文档字段抽成 JSON 的流水线是好搭配，核对财务计算则不是。

引用数值时必须一并附上 — 上述数值全部来自发布方自己的模型卡，并非独立复现，对照组也是同一张卡挑选的。搬进内部报告时，出处和这个限定条件要一起带上。落地决策最终仍要用自家的 100 条数据重新测一遍。

4. 轻量模型真正划算的三处

3B 级模型不是大模型的缩小版，而是干另一种活的工具。它划算的位置是固定的。

4.1 端侧

网络往返消失，数据不离开设备。在飞机上和地下车库里跑得一样快。涉及个人数据的功能，没有把数据发到服务器这件事本身就是架构上的答案。

但要把前面的第四条第一款第三项再想一遍。在自家应用里为自家服务运行，和卖一台装了模型的设备，是两回事。前者属于第四条第二款，后者需要协商。用端侧这一个词笼统带过，这个区分就消失了。

4.2 内网与隔离网络

数据不能外发时，外部 API 不是更差的选项，而是根本不在选项里。这时你的对照基线不是大模型，而是眼下由人手工在做的事。基线不同，够用的门槛也就不同。

规模感也随之改变。3B 级在单张 GPU 上能跑出可观吞吐，1.3B 视配置还能把 CPU 推理纳入考虑。本地运行时真正吃掉性能的地方，整理在本地大模型跑得慢的真正原因里。多数团队的实际体感是，下载权重容易，把推理服务跑起来难。

4.3 单价主导的大批量处理

分类、打标、归一化、初筛。单条判断简单但条数以百万计的活都在这里。这类工作中每次调用的价格远比几个百分点的准确率重要。先由小模型过一遍、只把命中的送到大模型，总花费降到原来的几分之一并不罕见。

以延迟为标准挑模型是另一条线，拆在更快的模型在哪一段胜出里。要点是大批量交给小模型，只有难例才升级，这套路由是生产里能站住的形态。

4.4 不适合的位置

  • 前沿推理 — 需要自行搭出多个步骤才能解的问题。上表的数学行就是信号
  • 长智能体链条 — 每一步的小误差会相乘。十步下来，95% 会变成六成左右
  • 稀有专业知识 — 参数少，能记住的就少。挂上检索来补才是正解
  • 语言覆盖面广的任务 — 语言广度是大模型保持优势的领域

5. 选本国模型的理由与不选的理由

两边同等对待。只看一边做不出判断。

5.1 选它的理由

  • 分词器效率。同一份韩语文档变成更少的 token，上下文余量、吞吐和成本会一起改善。模型卡称较上一代改进 30%。这一点在生产中的体感频率高于基准分数
  • 韩语知识基准领先。KMMLU 的数值高于对照组
  • 本地特有的表述与文书格式。行政表单、营业主体标注、地址体系这类内容在公开基准里几乎看不出来。可能有优势，但验证必须用自家数据
  • 签约对象在同一个国家。对落入第四条第一款的公司而言，这不是加分项而是关键。协商能否实际推进，决定了能否落地

5.2 不选它的理由

  • 全球轻量模型也能处理韩语。带着几年前的差距预期进场，实测时会失望
  • 生态厚度的差距。量化版本、推理运行时支持、微调配方、积累的问题记录，这些决定了交付速度。出问题时有没有人先踩过同一个坑，能差出好几天
  • 存在许可证更简单的替代。如果法务审查时间在贵司就是成本，这条维度可能排在性能之前
  • 后续版本节奏不确定。现在好用，半年后没有更新，迁移成本还得再付一次

分界线是这样的。任务中韩语占比高且格式合规要紧，就放进候选。以英语为主，或以数学与推理为核心，就把优先级往下调。无论哪一边，在进入候选和作出决定之间一定要插进一次实测。

6. 引入开放权重前要确认的七项

这不是只针对 Kanana-2 的清单，而是首次引入开放权重的团队通常会漏掉的项目。

确认项看什么漏掉的代价
许可证类型标准开源还是自订协议被采购规程卡住，临门一脚推翻
使用领域限制哪些业务形态被划为例外产品上线前才开始协商
微调范围是否明示允许衍生作品训练跑完了却不能用
再分发条件协议副本、声明文字、变更标注发布后再补漏掉的声明
命名义务衍生模型的命名规则品牌方案重做
输出使用限制输出能否用于训练其他模型合成数据计划落空
保证与责任条款免责范围、责任上限风险文档重写

用 Kanana-2 填这张表，结果是：自订协议；有使用领域限制（第四条第一款的三种情形）；允许微调；再分发时有声明与展示义务；衍生模型加 Kanana 前缀；输出可用于训练其他模型但同样受命名义务约束；按现状提供且免除责任。

顺序很重要 — 这项确认应放在落地决策之前，而不是概念验证之后。顺序颠倒，你会在确认一切都跑得通之后收到不能用的答复。到那时沉没成本已经在扰乱判断。

6.1 模型卡上还要看什么

  • 训练数据的描述程度。Kanana-2 明确说明未使用 Kakao 用户数据，但语料构成没有写在卡上
  • 评测条件。写清 shot 数和指标，复现才有可能。这张卡写了
  • 对照组的选择。和谁比、把谁排除在外，反映了这张卡的姿态
  • 安全与局限的说明。有没有独立的局限章节，如果有，承认了什么

7. 与全球轻量模型该在哪些维度比较

不建议做一张与 Qwen、Gemma、Llama 系列的分数对照表。各家卡片的评测条件不同，搬别人的表格时条件不会跟着搬过来。更快的做法是定好维度，用自己的任务去测。

比较维度怎么测为什么重要
许可证自由度把业务形态套进条文最先决定淘汰的维度
韩语 token 效率把自家 100 份文档过一遍各分词器同时作用于成本、上下文与吞吐
任务契合度把格式合规型与解题型分开实测经常与基准排名相左
推理服务实测每并发会话内存、首 token 延迟、每秒 token真正决定单价的数值
生态厚度量化版本、运行时支持、可用配方左右问题解决的时间
长文稳定性在真实最大输入长度上测准确率支持与表现是两句话
更新节奏上一代的发布间隔与支持周期迁移成本会重复发生

其中最便宜的维度是 token 效率。把自家 100 份文档送进各候选分词器数一数，半天就完事，结果直接换算成成本差。粗略感受用Token 计算器就够，差额折成月度金额可以放进 LLM API 价格计算器。各模型的单价与上下文细节，整理在AI 模型综合对比里。

8. 现在该评估的组织与该等待的组织

8.1 现在就评估

  • 大批量处理韩语文档，且大厂 API 单价吃紧。主要工作是分类、摘要、抽取的话，与上面的基准形状对得上
  • 数据不能外发，外部 API 本来就不可行。这里它不是备选，而是唯一路径
  • 只在自家服务内部使用的构成。属于第四条第二款范围，不必协商就能开始
  • 已经跑过推理服务的团队。开放权重真正的成本是运维不是权重。有这份经验，验证几天就能收尾
  • 格式合规决定成败的流水线。按既定 schema 输出的活正落在这里

8.2 先等一等

  • 把模型装进产品出售的公司。可以评估，但在协商有结果之前不要排上线日期。第四条第一款第三项正面命中
  • 以推理和数学为核心任务的组织。表格已经给出答案
  • 没有推理服务人手的组织。租 GPU 的花费比不上找到能把它跑起来的人
  • 以英语或多语言为主的服务。选本国模型的理由消失一半
  • 采购规程只接受开源许可证的组织。在技术验证之前先查文档，半天就有结论

这类模型上最远的距离，就在免费先下来看看和我们要落地之间。下载花五分钟，做到可运维状态要几周。能不能承担这几周，才是这个决定的实质。

9. 未能确认的内容

以下项目因无法锁定一手依据，未作为数值或断言写进正文。

  • 与 Gemma、Llama 系列的直接对比数值。模型卡的对照组是 Qwen 系列，卡上没有跨系列的对照表
  • 第三方复现评测。文中数值均以发布方模型卡为准，未找到独立复现结果
  • 0.9B 的公开时间。系列中有提及，时间点未说明
  • 真实的端侧实测。手机上的每秒 token、内存占用与发热没有公开数值
  • 商用许可的条件、费用与所需周期。落入第四条第一款时谈什么、多少钱、多久，均未公开
  • 训练语料构成。未使用 Kakao 用户数据有明示，其余构成卡上没有
  • 韩语分词改进 30% 的测定基准。用哪份语料、与什么对照，未能确认
  • KV 缓存减少 72.7% 的测定条件。该值随批大小与量化设置变化，因此未作一般化

结论：先读条文，再数 token

本国企业以开放权重放出轻量模型，给一线带来的改变不是选项数量，而是审阅顺序。以前是先测性能再算成本，现在是先读许可证再测性能。因为某些业务形态会被直接排除，而作出这个判定所需的时间远少于性能实测。

Kanana-2 的四款轻量模型在指令遵循与代码上领先对照组，在数学上落后，在韩语知识上占优，在长文上大致相当。有明确适合这个形状的任务，也有明确不适合的。属于适合那一边就值得现在评估；把模型装进产品出售的公司，则协商在先。

今天能做的只留两件。一是把许可证第四条先发给法务，自家业务形态处在第四条第二款里还是外，这一行答案是之后所有工作的前提。二是把自家 100 份文档过一遍分词器数 token。这个数字对月度账单的预测，比任何基准分数都准。
