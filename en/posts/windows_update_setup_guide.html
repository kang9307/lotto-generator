This article follows the wording of Microsoft's support documentation and the Microsoft Learn documentation as read in October 2026, in the Korean-language editions. Its focus is the Windows 11 settings screen, but the Microsoft documents it quotes are marked as applying to "Windows 11 and Windows 10". One of them, the Learn document on managing device restarts (waas-restart), is largely a Windows 10 document: its policy table shows which policies apply to Windows 10, and some policies in it carry a mark saying they are legacy policies that do not apply to Windows 11. Screen names and locations vary with the build and with later updates, so every menu path below is carried over in the words the documentation uses rather than rephrased. On a managed device, such as a work or school PC, the administrator's policies take precedence, and this article does not cover how those policies (Group Policy, MDM or the registry) are configured. Putting off security updates for a long time lengthens the period in which a device is exposed to known vulnerabilities, so the settings below are assumed to be used only for the purpose of delaying an update by the time that is actually needed.

The big picture of the update settings screen: what you can decide and what you cannot

The update settings in Windows 11 start at Start > Settings > Windows Update. Microsoft's Windows Update FAQ explains that Windows automatically downloads and installs updates in order to keep the device secure and up to date. The same document also states that updates cannot be stopped completely, only paused for a limited time. That single sentence is the key to reading the whole screen. Almost every item on it is not a switch that decides whether to receive updates; it is a control that decides when, in what way, and for how long a delay is possible.

If the items are grouped by what they do, they fall into three families.

  • Items that set timing: pause updates, active hours and schedule a restart. They do not block installation; they adjust when installation and restarts take place.
  • Items that set what is received: get the latest updates as soon as they are available, and optional updates. They deal with what is received in addition to the regular security updates.
  • Items that set how it is received: Delivery Optimization. It decides where the same update is downloaded from and how much is sent back out.

Two after-the-fact tools complete the picture. Update history shows what has been installed and lets some updates be removed, and troubleshooting applies when an installation fails. The table below puts the location the documentation gives, what the item does, and the limit the documentation states side by side. The conditions and exceptions of each item are worked through in the sections that follow.

On stopping updates completely, the FAQ says that updates cannot be stopped entirely and that, regardless of the update settings, updates will eventually need to be downloaded and installed.

Feature updates, quality updates and optional updates: how they differ

The update FAQ divides updates into two kinds. A feature update is released once a year and carries new features. A quality update arrives more often and carries security and bug fixes. On the settings screen, pausing, active hours and scheduling a restart apply to both kinds. The FAQ describes a feature update only as a once-a-year release with new features and a quality update only as the more frequent security and bug fixes, and it does not compare the two in size or in risk.

A third category, the optional update, is described as an update that delivers new features and non-security changes in addition to the monthly cumulative update. Microsoft Learn's "Configure Windows Update client policies" (a document for IT administrators) states that installation of optional updates is not enabled by default for devices that receive updates using Windows Update client policies. Whether the same default applies to a personal PC is not stated there. How this category is displayed on a personal PC, and in which part of the screen, is not in the documents that were read, so that point is listed separately under "What could not be confirmed" at the end of this article.

Pause updates: what the 35-day maximum actually means

Pausing is done at Start > Settings > Windows Update, using Select date in the Pause updates control. The documentation says updates can be paused for up to 35 days from the current date, and that the calendar only allows dates within the supported pause period to be chosen.

The behavior comes down to four rules.

  • While paused: updates that may require a restart are neither downloaded nor installed until the pause ends. The documentation adds that updates in progress at the moment of pausing are canceled.
  • When the pause ends: the device checks for the latest available updates, then downloads and installs them. In other words, everything that piled up during the delay arrives at once.
  • Extending: while updates are already paused, choosing a new end date allows up to 35 days from today. The time that was paused earlier is not added on. After the pause limit is reached, the FAQ says the latest updates must be installed before updates can be paused again.
  • If nothing is done: updates resume automatically when the pause expires. The documentation explains that this helps keep the device secure and stable.

Here is a calculation example. If the furthest selectable date is chosen on October 5, 2026, the end date is 35 days later, November 9 (October has 31 days, so October 5 plus 35 days is November 9; a calculation). If the pause is extended on October 20 while it is still running, the new end date has to fall within 35 days of that day, so the furthest date is November 24 (a calculation), and the earlier period is not added up. After the limit is reached on November 9, by contrast, the latest updates must be installed before pausing again. The Learn document for IT administrators (Configure Windows Update client policies) has a similar passage: "After 35 days have passed, the pause setting will automatically expire ... Following this scan, you can then pause ... updates for the device again." But that is written in the context of configuring a pause by policy, so it is unknown whether the Pause updates control on the settings screen behaves the same way. There is also no basis for reading the documentation as intending repeated pauses to postpone updates indefinitely.

The pause documentation itself names the occasions: if you are "traveling, attending a conference, on vacation, or you want to avoid interruptions during an important presentation or deadline" and need more time, you can pause updates. Because the end date is chosen by the user, writing it in a calendar makes it possible to anticipate the checking, downloading and installing that follow once the pause ends.

Active hours: automatic and manual, the default and the maximum length

Active hours are the hours of the day when the device is expected to be in use. The Learn documentation explains that after an update has been installed outside active hours, the device restarts automatically. So active hours are a mechanism for pushing the restart time back, not a mechanism for blocking installation.

In Windows 11 the location is Settings > Windows Update > Advanced options > Active hours. Adjusting active hours is a choice between Automatically and Manually. With automatic, Windows adjusts them according to usage patterns; with manual, the user sets the start and end times.

  • Default: the Learn documentation gives the default active hours of a PC as 8 AM to 5 PM. That is nine hours (a calculation).
  • Maximum length: the same document says the maximum active-hours range is counted from the start time, and states: "The max active hours length for Windows 10, version 1607 and Windows Server 2016 is 12. Later versions support max active hours length of 18 hours." So 1607 has 12 hours, and 18 hours starts with the next version. Counting 18 hours, a start of 8 AM could in theory run to 2 AM the next day (a calculation).
  • Limit of that figure: the 18 hours appears in a document for IT administrators, in the context of a policy setting. Whether the same value appears as the slider maximum on the settings screen of a personal PC cannot be known from this document alone.

The Learn documentation describes the purpose of the administrator's maximum active-hours range setting as allowing enough time to install updates while leaving users some of the decision during active hours. That document does not give a recommended length for personal settings. The guidance for individual users is in the FAQ: active hours can be set so that the device restarts automatically for updates only when it is not in use.

Schedule a restart and notifications: choosing when the restart happens

Even after an update has been installed, some updates only take effect after a restart. The FAQ explains that Windows tries to restart the device when it is not in use, and that if it cannot, it shows a message asking the user to schedule the restart for a convenient time. The same FAQ also gives a way to schedule it at any time: select Start > Settings > Windows Update, select Schedule a restart, and choose a time that is convenient. If active hours are the side that says "do not restart during these hours", scheduling a restart is the side that says "restart at this time".

The parts of the Learn documentation on restarts that matter to an individual user are as follows.

  • After installing an update, Windows tries to restart automatically outside active hours.
  • If the restart does not succeed after the default period of 7 days, a notification that a restart is needed is shown to the user. The "Engaged restart" section says the same thing as: "Once the default seven day period ends, Windows transitions to user scheduled restarts."
  • According to the description of the policy "No auto-restart with logged on users for scheduled automatic updates installations", if the user schedules the restart in the update notification, the device restarts at the time the user specifies even if a user is signed in at the time.

The 7 days in the second item comes with a qualification. In the same document, the policy that changes this period (specify the deadline before auto-restart for update installation) and the policies that adjust the transition period for engaged restart are all marked as legacy policies that do not apply to Windows 11. So the document does not directly say whether the Windows 11 settings screen uses the same 7 days. What the document does confirm is the default of 7 days and the transition to user scheduled restarts after it.

The third item has a narrow scope. The sentence sits inside the description of a policy, and the document says that policy applies only when Configure Automatic Updates is set to option 4 - Auto download and schedule the install. It should therefore not be read as general behavior on every personal PC. The same document also notes that this policy does not work exactly as described.

"Get the latest updates as soon as they are available": what changes when it is on

Microsoft explains in its documentation that non-security updates are rolled out gradually through controlled feature rollout (CFR). Turning on the Get the latest updates as soon as they are available toggle at Start > Settings > Windows Update speeds up this process.

  • Relationship to security updates: regardless of the state of the toggle, regular security updates continue to be delivered. The toggle does not decide whether security patches are received.
  • Active hours: the documentation says this setting respects active hours of use.
  • Restarts: some updates that need a restart are described as being combined with the next cumulative update (LCU), which reduces the number of restarts.
  • Turning it off: it can be disabled at any time.

The difference the documentation describes is whether non-security updates wait their turn in the gradual rollout (CFR) or are brought forward by the toggle. Which of the two takes priority when the toggle and a pause are used together is not in the documents that were read.

Delivery Optimization: downloading from other devices and how much is sent out

Delivery Optimization is a cloud-based system for downloading Windows updates, apps from the Microsoft Store and other Microsoft products. People also search for it as transfer optimization or distribution optimization, but the screen name in the Korean edition of the documentation corresponds to Delivery Optimization. The location is Start > Settings > Windows Update > Advanced options > Delivery Optimization.

The source of downloads is chosen between two options.

  • Devices on my local network only: pieces of the update are exchanged with other PCs connected to the same router.
  • Devices on the Internet and on my local network: devices on the Internet can also be a source.

Bandwidth is limited in two ways. One is absolute bandwidth (in Mbps) and the other is a percentage of the measured bandwidth. The documentation states: "Bandwidth limits only apply to Delivery Optimization for automatic updates downloads", and adds that if a download is started manually, for example by updating Windows in Settings or downloading apps, the bandwidth limit that was set does not apply. The monthly upload limit is a separate choice in the upload options, between 1 GB and 500 GB, and whether the sentence above also speaks to the scope of that limit is not in the documentation.

The side of this section that calls for a judgment is uploading. A PC connected to a metered line or a mobile hotspot can have its settings arranged to reduce unintended data use, by lowering the monthly upload limit or by restricting the source to the local network. How many megabytes a particular combination actually saves cannot be said, because the documentation gives no figures.

Update history and uninstalling: what to know before rolling back

Installed updates are viewed at Settings > Windows Update > Update history. The uninstall path is given in Microsoft's support documentation in this order: Start > Settings > Windows Update > More options > Update history > Uninstall updates (Uninstall updates is under Related settings). The documentation says to select the update to remove from the list and then select Uninstall, and it states explicitly that some updates cannot be uninstalled. When Windows cannot be accessed, a separate method is introduced that uses the recovery environment (Windows RE), through Troubleshoot > Advanced options.

  1. First, compare the time. Look in the update history list for an entry close to the moment the symptom started.
  2. Check whether the entry can be uninstalled. Because the documentation says some updates cannot be removed, there may be entries in the list that cannot be uninstalled.
  3. If it is a security update, understand the risk of removing it first. The documentation advises understanding the risk before uninstalling a security update. The same document also advises that, on Windows 11, reinstalling your version of Windows should be tried first.
  4. After uninstalling, the same update may be installed automatically again, so decide together how the pause date will be used. The documentation, however, does not describe in detail what happens to an uninstalled update afterwards.

If a performance problem is suspected, the procedure for identifying the bottleneck with Task Manager first comes before it, and a checklist of settings as a whole is in the Windows 11 optimization guide. Tying update checks to a recurring task is covered by the introduction to Windows automation. The explanation of the update screen items themselves is complete in the sections above.

The order of checks when an installation fails

Microsoft's update troubleshooting documentation presents ten basic fixes. The order is as follows.

OrderCheck presented in the documentationNote
1Run the automated troubleshooterOpened from Settings > System > Troubleshoot
2Verify that the device is properly plugged in and connected to the InternetCheck the power and Internet connections. A stable Internet connection is crucial
3Check administrator permissionsNeeded for some updates
4Disconnect external hardwareRemove external storage devices, drives, docks and other hardware not needed for basic functionality, then run the update again
5Reset the update cacheDamaged files can cause errors
6Check the date and time settingsTurn on automatic synchronization
7Update third-party driversCheck on the manufacturer's website
8Free up disk spaceThe documentation gives 16 GB for 32-bit and at least 20 GB for 64-bit
9Run the update againAdditional updates may remain
10Restart the deviceApplies the changes

The documentation presents these ten under the line "Please try the following general troubleshooting steps to help solve the Windows update problem", from step 1 in numbered order, and first asks the reader to back up personal files before trying them. It does not say which step costs least or which step is most often the cause. The documentation also introduces, as advanced options, responses by error code (for example 0x8007000d and 0x800705b4), system file repair tools such as DISM and SFC, and a fresh installation tool. If an error code appears on the screen, look it up in the documentation's list first.

Disk space is a particular problem for feature updates. The FAQ recommends cleaning up files or using an external drive when disk space is short. On a PC with too little free space, securing storage first, rather than buying time with a pause, is what keeps the same failure from repeating.

Why permanent blocking is not used: treating it as a question of timing, not of settings

When updates are inconvenient, many people look for ways to block them entirely through Group Policy or the registry. Those methods are not covered here, for three reasons.

  • The default policy set by the documentation is automatic installation, and stopping is permitted only as something temporary.
  • The Learn documentation repeatedly states that editing the Windows registry directly is not recommended.
  • If the problem is restarts, active hours and scheduling a restart solve most of it, and if the problem is timing, pausing does; demands beyond that range belong to management tools.

On a managed device, the administrator's policy takes precedence, and some items on the settings screen may appear greyed out or show text saying the organization manages them. In that case the right step is to ask the administrator, not to change it individually. In addition, the documentation notes that support for Windows 10 ended on October 14, 2025. A device still on Windows 10 must first decide whether to move to Windows 11 before touching update settings.

What could not be confirmed

  • An explicit sentence of advice not to postpone security updates indefinitely. The pause documentation only had the explanation that automatic resumption after expiry helps keep the device secure and stable, and no separate sentence of advice was found.
  • What exactly the "latest updates" are that must be installed before pausing again after the pause limit is reached, and whether the passage about pausing again after 35 days in the policy document for IT administrators applies equally to the settings screen.
  • Whether the active hours screen on a personal PC shows 18 hours as the maximum length (the 18 hours is a figure from Learn's document for IT administrators). That Learn document is a machine translation.
  • Whether the period before automatic restarts turn into notifications on the Windows 11 settings screen is the same as the documented default of 7 days (the policies that change this period are marked as legacy policies that do not apply to Windows 11).
  • Where optional updates appear on the settings screen of a personal PC, and in what order they are installed.
  • The actual data savings of each Delivery Optimization option. The documentation gives no figures.
  • The screens could not be opened and compared on this PC. All locations and names follow the wording of the documentation and may differ by build. Differences in the Windows 10 screens, the Insider channels and Group Policy or MDM configuration were left out of scope.
