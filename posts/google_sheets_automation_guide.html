구글 시트 자동화 완전 가이드 - 수식부터 Apps Script, 폼 연동, 알림까지

반복 작업을 줄이는 구글 시트 자동화를 수식 단계부터 스크립트 단계까지 실전 예제로 정리한다

2026-07-24 IT/기술

이 게시물은 쿠팡 파트너스 활동의 일환으로, 이에 따른 일정액의 수수료를 제공받습니다.

서론: 반복 작업을 시트에게 맡기는 법

매주 같은 수식을 새 행마다 다시 복사하고, 다른 시트에서 값을 손으로 옮기고, 응답이 올 때마다 사람이 확인하고 메일을 보내는 작업. 이런 반복은 구글 시트 안에서 상당 부분 자동화할 수 있다. 수식만으로 되는 자동화가 있고, 트리거와 스크립트가 필요한 자동화가 있다.

이 글은 2026년 7월 기준으로 수식 자동화(ARRAYFORMULA·QUERY·IMPORTRANGE·FILTER)부터 데이터 유효성과 조건부 서식, Apps Script 입문(트리거와 간단한 스크립트), 폼과 시트 연동, 웹훅·API 같은 외부 연동, 자동 메일 알림, 협업 시 주의점, 그리고 대용량 데이터에서의 한계와 대안까지 실전 순서로 정리한다.

1. 수식 자동화 - ARRAYFORMULA·QUERY·IMPORTRANGE·FILTER

1.1 ARRAYFORMULA - 한 번 입력해 전체 열에 적용

보통 수식은 셀 하나에만 적용되고, 아래로 자동 확장하려면 드래그해서 복사해야 한다. ARRAYFORMULA는 이 수식을 지정한 범위 전체에 한 번에 적용해, 새로운 행이 추가돼도 자동으로 계산되게 만든다.

=ARRAYFORMULA(IF(A2:A="", "", B2:B*C2:C))

이 수식은 A열이 비어 있지 않은 모든 행에 대해 B열과 C열을 곱한다. 새 주문이 A열에 추가되기만 하면 결과 열이 자동으로 채워진다. 단, QUERY·FILTER·SORT·IMPORTRANGE처럼 원래부터 배열을 반환하는 함수는 ARRAYFORMULA로 감쌀 필요가 없다.

1.2 QUERY - SQL과 비슷한 문법으로 집계

QUERY는 구글 시각화 API 쿼리 언어라는 SQL과 유사한 문법을 쓴다.

=QUERY(주문!A:E, "SELECT A, SUM(D) WHERE C = '완료' GROUP BY A ORDER BY A", 1)

이 수식은 주문 시트에서 상태가 완료인 행만 골라 담당자별 합계를 계산한다. SELECT로 열을 고르고, WHERE로 조건을 걸고, GROUP BY로 집계 기준을 잡고, ORDER BY로 정렬한다. 여러 열을 선택하거나 집계가 필요할 때는 QUERY가 FILTER보다 강력하다.

1.3 IMPORTRANGE - 다른 스프레드시트 데이터 가져오기

IMPORTRANGE는 완전히 별개의 스프레드시트 파일에서 데이터를 가져온다.

=IMPORTRANGE("https://docs.google.com/spreadsheets/d/문서ID/edit", "원본시트!A:D")

처음 사용할 때는 접근 권한을 허용해야 하며, 이후에는 원본이 바뀌면 가져온 데이터도 자동으로 갱신된다. QUERY와 결합하면 다른 파일의 데이터를 가져오면서 동시에 필터링할 수 있다.

=QUERY(IMPORTRANGE("문서URL", "원본시트!A:D"), "SELECT Col1, Col2 WHERE Col3 = '완료'")

1.4 FILTER - 조건에 맞는 행만 간단히 추출

FILTER는 조건에 맞는 행만 골라내는 간단한 함수다.

=FILTER(A2:D, C2:C="완료", D2:D>=10000)

이 수식은 상태가 완료이면서 금액이 만원 이상인 행만 반환한다. 조건이 단순할 때는 QUERY보다 FILTER가 더 읽기 쉽다. IMPORTRANGE와 함께 쓰면 외부 시트 데이터를 가져오면서 조건에 맞는 행만 걸러낼 수도 있다.

2. 데이터 유효성·조건부 서식

데이터 유효성(데이터 → 데이터 확인)은 셀에 입력 가능한 값을 제한한다. 목록에서 선택, 숫자 범위 제한, 날짜 형식 강제 같은 규칙을 걸 수 있고, 규칙을 어기면 입력을 거부하거나 경고만 표시하도록 선택할 수 있다. 여러 사람이 함께 입력하는 시트에서 오타나 형식 불일치를 원천 차단하는 데 유용하다.

조건부 서식(서식 → 조건부 서식)은 값에 따라 셀 배경색이나 글자색을 자동으로 바꾼다. 예를 들어 마감일이 오늘보다 이전이면 빨간색, 완료 상태면 회색으로 표시하는 규칙을 만들 수 있다. 커스텀 수식 조건을 쓰면 다른 열의 값을 참조해 훨씬 복잡한 조건도 표현할 수 있다.

=AND($C2="진행중", $D2 < TODAY())

이 수식을 조건부 서식의 커스텀 수식으로 넣으면, 상태가 진행중이면서 마감일이 지난 행 전체에 서식을 적용할 수 있다.

3. Apps Script 입문 - 트리거와 간단한 스크립트

3.1 트리거 종류

Apps Script의 트리거는 크게 두 가지다. 단순 트리거는 onOpen(e), onEdit(e)처럼 정해진 이름의 함수를 만들어 두기만 하면 자동으로 동작하지만, 외부 메일 발송이나 URL 요청처럼 권한이 필요한 서비스는 쓸 수 없고 실행 시간도 짧게 제한된다. 설치형 트리거는 스크립트 편집기의 트리거 메뉴에서 직접 등록해야 하지만, 권한이 필요한 서비스도 쓸 수 있고 시간 기반(매일 특정 시각, 매주 특정 요일 등)으로도 실행할 수 있다. 폼 제출을 감지하는 onFormSubmit도 설치형 트리거로 등록해야 안정적으로 동작한다.

3.2 제한 사항

스크립트 하나에 만들 수 있는 시간 기반 트리거는 최대 20개이고, 트리거 1회 실행은 최대 6분까지 허용된다. 하루 전체 트리거 실행 시간 합계는 개인 계정 기준 90분, 워크스페이스 계정 기준 6시간으로 제한된다. 이 한도를 넘으면 스크립트가 조용히 실패하므로, 매우 짧은 주기(예: 1분마다)로 무거운 작업을 돌리는 설계는 피해야 한다.

3.3 간단한 스크립트 예시 - 새 행에 타임스탬프 추가

function onFormSubmit(e) {
  const sheet = SpreadsheetApp.getActiveSpreadsheet().getActiveSheet();
  const lastRow = sheet.getLastRow();
  sheet.getRange(lastRow, 6).setValue(new Date());
}

이 함수를 onFormSubmit 설치형 트리거로 등록하면, 폼 응답이 새 행으로 들어올 때마다 6번째 열에 처리 시각을 자동으로 기록한다.

4. 폼 → 시트 연동

구글 폼 편집 화면에서 응답 탭을 열고 스프레드시트 아이콘을 누르면, 응답을 저장할 시트를 새로 만들거나 기존 시트에 연결할 수 있다. 연결 이후에는 응답이 제출될 때마다 자동으로 새 행이 추가된다. 여기에 앞서 본 onFormSubmit 트리거를 붙이면, 응답이 들어올 때마다 값을 검증하거나, 특정 조건을 만족하는 응답만 다른 시트로 옮기거나, 담당자에게 자동으로 알림 메일을 보내는 등의 후속 처리를 실시간으로 자동화할 수 있다.

5. 외부 연동 - 웹훅과 API 개념

Apps Script의 UrlFetchApp 서비스를 쓰면 시트에서 외부 웹 서비스로 HTTP 요청을 보낼 수 있다. 이를 이용해 시트에 새 행이 추가되거나 특정 값이 바뀔 때 웹훅(webhook)으로 슬랙·디스코드 채널에 알림을 보내거나, 사내 시스템 API를 호출해 데이터를 주고받을 수 있다.

function notifySlack(message) {
  const url = "https://hooks.slack.com/services/여기에웹훅주소";
  const payload = { text: message };
  UrlFetchApp.fetch(url, {
    method: "post",
    contentType: "application/json",
    payload: JSON.stringify(payload)
  });
}

반대로 시트를 API처럼 노출하고 싶다면, Apps Script를 웹 앱으로 배포해 doGet(e)·doPost(e) 함수로 외부 요청을 받아 시트 데이터를 읽거나 쓰게 만들 수 있다. 다만 인증·트래픽이 중요한 서비스라면 이 방식보다 전용 백엔드 API가 안정적이다.

6. 자동 알림 - 메일 발송

Apps Script의 MailApp 또는 GmailApp 서비스로 조건에 맞는 행이 생기면 자동으로 메일을 보낼 수 있다.

function sendDailyReport() {
  const sheet = SpreadsheetApp.getActiveSpreadsheet().getSheetByName("주문");
  const data = sheet.getDataRange().getValues();
  const pending = data.filter(row => row[2] === "대기");
  if (pending.length > 0) {
    MailApp.sendEmail("담당자@example.com", "대기 중인 주문 " + pending.length + "건", "확인이 필요합니다.");
  }
}

이 함수를 시간 기반 설치형 트리거로 매일 오전 9시에 실행되도록 등록하면, 대기 중인 주문이 있을 때만 자동으로 메일이 발송되는 일일 알림 시스템이 완성된다. MailApp은 개인 계정 기준 하루 발송량 한도가 있으므로, 대량 발송이 필요하면 워크스페이스 계정이나 전용 이메일 서비스를 검토해야 한다.

7. 협업 시 주의 - 권한과 버전

여러 사람이 같은 시트를 동시에 편집할 때는 공유 권한을 명확히 나눠야 한다. 뷰어(읽기 전용), 댓글 작성자, 편집자 세 단계로 권한을 지정할 수 있고, 수식이 들어간 핵심 열은 편집자에게도 실수로 지워지지 않도록 범위 보호(데이터 → 시트 및 범위 보호)를 걸어두는 것이 안전하다. 또한 파일 → 버전 기록에서 과거 시점으로 되돌리거나 특정 시점에 이름을 붙여 보관할 수 있는데, Apps Script로 자동화를 걸어 둔 시트는 실수로 트리거가 중복 등록되거나 스크립트가 참조하는 시트 이름·열 위치가 바뀌면 자동화 전체가 깨질 수 있으므로, 구조를 변경하기 전 트리거 목록과 스크립트 코드를 먼저 확인하는 습관이 필요하다.

8. 성능 한계와 대안 - 대용량이라면 DB 고려

구글 시트는 파일당 최대 셀 개수 제한(대략 천만 셀 안팎)이 있고, 이 한도 안에 있더라도 데이터가 많아질수록 수식 재계산과 화면 렌더링이 눈에 띄게 느려진다. 특히 QUERY나 배열 수식을 매우 큰 범위에 걸어 두면 시트를 열거나 값을 편집할 때마다 지연이 발생한다. Apps Script 트리거도 앞서 본 실행 시간·횟수 한도 안에서만 동작하므로, 무거운 일괄 처리를 촘촘한 주기로 돌리는 설계는 한계에 부딪힌다.

수만 행을 넘어 계속 늘어나는 데이터, 여러 사용자의 동시 대량 쓰기, 엄격한 정합성이 필요한 트랜잭션 처리라면 구글 시트보다 관계형 데이터베이스나 전용 백엔드로 옮기는 것이 안정적이다. 이 경우 시트는 원천 데이터 저장소가 아니라, DB 위에 QUERY나 API 연동으로 만든 보고서·대시보드 레이어로 역할을 좁히는 구조가 실무적으로 오래간다.

결론

구글 시트 자동화는 계단식으로 접근하는 것이 합리적이다. 먼저 ARRAYFORMULA·QUERY·FILTER·IMPORTRANGE 같은 수식만으로 해결되는지 확인하고, 데이터 유효성과 조건부 서식으로 입력 오류를 줄인 다음, 정말 스크립트가 필요한 지점(폼 연동 후처리, 정기 알림, 외부 시스템 연동)에서만 Apps Script 트리거를 도입하는 순서다. 그리고 데이터 규모가 시트의 한계에 다가서고 있다면, 무리하게 시트 안에서 버티기보다 DB로 옮기고 시트는 보고서 역할로 좁히는 결정을 미루지 않는 것이 좋다.
