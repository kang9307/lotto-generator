1. braillify是什么 - 工具简介

braillify是一个将韩语文本转换为Unicode盲文模式(U+2800至U+28FF)的开源JavaScript库。它由韩国开发者社区围绕2024规范修订而构建,其身份卡如下:

  • 许可证:MIT - 商业用途自由
  • 规范支持:2024修订韩国盲文规范,完整实现
  • 验证强度:2,419项单元测试在CI中持续通过
  • 运行时:浏览器(ES模块)与Node.js同源
  • 依赖:零 - 无运行时第三方包

一句话总结:braillify是当今可安装的最轻量韩语文本转盲文库。传统韩语盲文工具大多是Windows桌面程序或重量级服务器栈,braillify将这一栈压缩到可在静态HTML文件中直接运行的级别。便携性是它的最大标签。

2. 盲文基础 - 六点格的结构

面向从未仔细观察过盲文的读者,先做结构入门。盲文格是2列×3行=6点的方阵。点凸起为1、平整为0,因此一格可以表达2的6次方=64种组合,足以覆盖拉丁字母、数字、标点和大量缩写。

Unicode于1999年为盲文分配了256个码点(U+2800至U+28FF),以同时覆盖六点格和八点电脑盲文。仅用六点模式时仅占U+2800至U+283F共64个码点。braillify默认输出六点,可按需切换八点输出。

概念说明
格(Cell)盲文1字单位(2列×3行)
点(Dot)1〜6号位,左上至右下
缩写(Contraction)常用词压缩为1〜2格
略语(Abbreviation)长词映射为预定义的短格序列
数符(Number Sign)表示后续格为数字
大写符(Capital Sign)表示下一格为大写

2.1. 为什么是六点、两列?

1825年路易·布莱叶设计盲文时,基准是指尖的触觉分辨率。食指腹一次可识别的范围约为6毫米×9毫米,在该范围内6个点能稳定区分。格再大,手指就要更频繁地抬起重置;再小,点与点融合无法分辨。这一人体工学约束经过两百年依然支配着今天每一台数字盲文显示器。

3. 谚文盲文的特殊性

英语盲文几乎是一一对应:一个字母对应一格。但韩语在结构上完全不同。谚文是由初声、中声、终声构成的组合文字,所以盲文需要将每个音节拆解为字母,并为每个字母分配一格。"안녕"两个音节展开后是"ㅇ + ㅏ + ㄴ + ㄴ + ㅕ + ㅇ"共6个字母,6格盲文。

除了拆解,韩语还叠加了以下规则:

  • 位置敏感的辅音:同一个"ㄱ"在初声与终声位置的盲文模式不同。
  • 缩写(Contraction):像"그러나"、"그리고"这样的高频词被压缩为单独的1格。
  • 略语(Abbreviation):"대한민국"等长词映射为预定义的略语序列。
  • 外来词处理:嵌入英语时需要在子串前后插入显式的模式切换标记。
  • 更严格的分词:盲文要求比印刷韩语更多的空格,以避免歧义。

把这些规则全部实现,不再是简单的查表问题,而是接近形态分析的预处理工程。这就是为什么早期自动转换工具在孤立名词上得分尚可,但在真实语料上崩溃。braillify的2,419项回归测试,正是为锁死这些冲突而存在。

4. 2024韩国盲文规范修订

2024修订是首次以数字化流程为前提的韩国盲文规范升级。此前的规则默认使用凸点纸张,允许人工誊抄时的灵活解读,自动化工具难以处理。新规范的关键变化如下:

领域旧规则2024新规范
外来词切换标记模糊切换时点与范围明确
数字数符范围解释不一连续数字、小数、逗号统一
缩写存在冲突新增冲突解决规则
标点引号、括号变体繁多统一为五种规范模式
数字输出仅考虑印刷明确认可Unicode输出

最后一项尤其关键:此前主流流程是生成BRF文件并送往凸版打印机,新规范则正式认可Unicode盲文作为一等输出目标。这一变更打开了在网页上直接渲染盲文、把盲文经网络流式发送到刷新式盲文显示器,以及在无障碍API中以数据形式承载盲文的可能。braillify正是顺着这条新道路构建的。

5. braillify的五大优势

本节以五个维度评价braillify。

5.1. 完整支持2024新规范

2024修订引入的所有新条目——外来词切换、数符统一、缩写冲突解决、标点五种模式、Unicode输出——在代码中全部实现。GitHub提交历史显示,作者在新规范公告后数周内就完成跟进。规范变更的敏捷响应是开源相对官方工具最大的结构性优势。

5.2. 2,419项测试用例

韩语盲文是"魔鬼藏在细节里"的教科书级例子。字母拆解、缩写、外来词、数字与标点的交叉产生庞大的边界用例空间。braillify用2,419项单元测试守住了普通词、缩写词、英文混排、数字混排、标点变体、略语、多重缩写冲突等所有曾经修复过的回归点。这一数字是"开源也可信赖"的最有力证据。

5.3. JavaScript集成轻量

安装一行:npm install braillify。CDN用户可直接import ES模块。公开API近似单一函数:输入韩语字符串,输出Unicode盲文字符串。可选项目控制缩写、略语、外来词模式与输出格式。学习曲线以分钟计。

5.4. 开源与MIT许可证

对无障碍工具收商业版税本身是矛盾的:如果库本身有价格,最需要它的群体反而买不起含有它的产品。MIT允许任何企业把braillify集成进收费的自助终端,也允许学校在教学应用里使用,任何个人都能fork并改进。这是package.json里小小的一行,但是最重要的政治抉择。

5.5. 浏览器与Node同代码

同一份编译产物在Chrome、Safari、Firefox、Node.js、Bun、Deno与AWS Lambda上字节一致。当盲文内容服务器侧生成后由客户端再渲染时,任何一个格的偏差都会破坏规范一致性。所以braillify的可移植性既是便利,更是正确性保证。

7. 开发者集成 - 五分钟上手

理论已经够了,我们直接看代码。

7.1. 安装

npm install braillify
# 或使用CDN
# <script type="module">import { toBraille } from 'https://cdn.jsdelivr.net/npm/braillify/+esm';</script>

7.2. 基本用法

import { toBraille } from 'braillify';

const text = '안녕하세요. 점자 변환 테스트입니다.';
const braille = toBraille(text);
console.log(braille);
// 输出:U+2800-U+28FF范围的Unicode盲文字符串

7.3. 选项

const result = toBraille(text, {
  contraction: true,       // 启用缩写
  abbreviation: true,      // 启用略语
  foreignMode: 'auto',     // 外来词自动切换
  format: 'unicode',       // 'unicode' | 'brf' | 'numeric'
});

7.4. React组件示例

import { useState } from 'react';
import { toBraille } from 'braillify';

export function BrailleConverter() {
  const [input, setInput] = useState('');
  const braille = input ? toBraille(input, { contraction: true }) : '';
  return (
    <div>
      <textarea value={input} onChange={(e) => setInput(e.target.value)} />
      <div className="braille-output" aria-label="盲文输出">{braille}</div>
    </div>
  );
}

7.5. 服务端(Node.js / Next.js API)

// app/api/braille/route.ts
import { toBraille } from 'braillify';

export async function POST(req) {
  const { text } = await req.json();
  const braille = toBraille(text, { contraction: true });
  return Response.json({ braille });
}

"五分钟"并非营销语。完成上述五步,任何环境下的韩语文本到盲文转换都会立刻可用。

8. 五个实战场景

工具再好,没有落地场景也是空中楼阁。以下是braillify即刻产生价值的五个场景。

场景1:视障学生学习资料自动转换

把教材PDF、教师讲义、习题集做文本提取,再通过braillify转盲文,送入凸版打印机或刷新式盲文显示器。传统流程往往要委托出版社耗时数月,如今变成分钟级。特殊教育现场的时间成本极大下降。

场景2:盲文学习应用

面向视障儿童学习盲文、或面向健视者作为通识教育,braillify可即时生成单词卡。"每日一词"、"小测验"、"缩写练习"等模式以React Native封装即可成为移动端盲文学习应用,也能与教育部数字教科书项目对接。

场景3:公共部门文档无障碍自动化

区办、市府、社区中心发布PDF公告时,自动并行生成同内容的盲文PDF。韩国政府的数字无障碍评估越来越看重盲文供给,这种自动化直接转化为评分。braillify的BRF输出模式正是接入既有打印工作流的关键。

场景4:无障碍自助终端

地铁售票机、医院挂号台、机场值机终端配合刷新式盲文显示器,把屏幕文本实时经braillify转为盲文,视障者无需工作人员协助即可完成全部操作。2026年以后陆续生效的自助终端无障碍义务规定与该架构高度契合。

场景5:多语言盲文(与英语·日语·中文的差异)

braillify本身专注韩语,但可以与英语的liblouis、日语的BES、中文的"拼音+liblouis"组合,在同一页面下提供多语言盲文服务。旅游景点的多语种无障碍自助终端是天然落点。

9. 全球视角 - 英语 vs 韩语 vs 日语 vs 中文盲文

把韩语盲文放在全球语境中比较,更能看清其工艺密度。

语言映射方式缩写体系每字平均格数代表工具
英语字母一一对应Grade 1 / Grade 21.0〜1.2格liblouis
韩语字母拆解后映射多层缩写与略语2.5〜3.0格braillify
日语假名一一对应有限缩写1.5〜2.0格BES
中文汉字→拼音→盲文拼音缩写3.0〜4.0格libbraille

韩语盲文每字平均占用格数约为英语的2.5倍——正因字母拆解。这也是为何韩语盲文图书厚度远超印刷版,以及为何刷新式盲文显示器对韩国用户推荐80格以上宽度。中文更复杂,汉字无法直接映射到盲文,必须先转写为拼音,过程中会遇到同音异义的信息损失。相对而言,韩语能保持字母级一一对应,是变换算法设计者的幸运。

10. 无障碍的未来 - AI与盲文

盲文已有两百年,但它所处的环境正在剧变。未来五年将重塑无障碍工具栈的三个趋势:

  • 语音到盲文管道:实时语音识别接入braillify,流式推送至刷新式盲文显示器,聋盲用户也能"读"到现场对话。
  • OCR+盲文一体化应用:用手机拍下印刷页面,OCR提取文本,braillify转换,盲文PDF保存,全部在一款移动应用内完成。
  • 大语言模型结合:LLM摘要、翻译的产物可直接输出盲文,视障学习者获得与一般学习者相当的信息可及性。前提是LLM内容侧需要单独的事实校验,盲文映射本身则保持确定性。

AI时代的无障碍不再是"附加",而是"基础设施"。支撑这一基础设施的,正是braillify这种小而快且准确的工具。
