引言 - 复制是一层一层发生的

有时复制了一份设置字典，想按用户修改数值，结果默认设置也跟着变了。复制的代码运行正常，新字典也确实创建了，但内层的列表与原来是同一个对象。复制发生的层数因方法而异。每种方法新建到第几层、在哪里停下，由对象同一性(is)体现，越过停下位置的方法及其开销则由下面的输出展示。

本文的角度与相邻主题的文章不同。默认参数文章讲默认值对象在执行def语句时只创建一次并在多次调用之间共享的问题，小整数文章讲用is比较整数和字符串时因优化而结果不同的问题。这里只限定于：复制一个已经存在的容器时，到哪一层才会成为新对象。与前两篇相连的地方，在正文中以链接交接。

涉及的问题如下。

  • 赋值(=)会创建几个对象？
  • copy()、list()、切片、dict.copy()、copy.copy、copy.deepcopy各自的外层和内层中，哪一部分是新对象？
  • 嵌套列表和字典中，原对象在什么条件下会改变？
  • 元组中的列表、数据类和用户自定义类在复制中如何处理？
  • deepcopy如何处理同一对象被引用两次的结构和循环引用？
  • deepcopy的时间开销在这台电脑上是多少？

赋值不是复制

最先遇到的情形是把赋值当成了复制。官方文档copy模块的第一句是："Assignment statements in Python do not copy objects, they create bindings between a target and an object."赋值语句不复制对象，只在目标与对象之间建立绑定。下面的输出与这句话一致。

a = [1, 2]
                    b = a
                    print(a is b, id(a) == id(b))
                    b.append(3)
                    print(a)
                    c = list(a)
                    print(c is a, c == a)
                    c.append(4)
                    print(a, c)
True True
                    [1, 2, 3]
                    False True
                    [1, 2, 3] [1, 2, 3, 4]

第一行中，a is b与id(a) == id(b)都是True。数据模型文档写明is比较两个对象的同一性(identity)，id()返回表示该同一性的整数，并补充说在CPython中id(x)是x所存储的内存地址。也就是说，a和b是挂在同一个对象上的两个名字。b.append(3)之后，a也变成了[1, 2, 3]。相比之下，用list(a)生成的c是c is a为False的新列表，c == a为True只表示内容相等，并不表示是同一个对象。c.append(4)没有影响a。

  • ==询问值是否相等，is询问是否为同一个对象。是否发生了复制，要用is来看。
  • 这里的is用来观察容器对象的同一性。用is比较整数、字符串这类值时因优化而结果不同的问题，在小整数文章中介绍。
  • 复制调用方传入的列表这一写法的运行输出，见默认参数文章的第5节。

各复制方法新建的层级

下面的代码对一个嵌套列表和一个字典运行多种复制表达式，并用is not输出结果的外层容器是否与原对象不同(new outer)、内层列表是否与原对象不同(new inner)。

import copy
                    orig = [[1, 2], [3, 4]]
                    cases = [
                        ('b = orig', lambda: orig),
                        ('orig.copy()', lambda: orig.copy()),
                        ('list(orig)', lambda: list(orig)),
                        ('orig[:]', lambda: orig[:]),
                        ('[*orig]', lambda: [*orig]),
                        ('copy.copy(orig)', lambda: copy.copy(orig)),
                        ('copy.deepcopy(orig)', lambda: copy.deepcopy(orig)),
                    ]
                    print('%-22s %-10s %s' % ('expression', 'new outer', 'new inner'))
                    for name, make in cases:
                        b = make()
                        print('%-22s %-10s %s' % (name, b is not orig, b[0] is not orig[0]))
                    d = {'name': 'x', 'tags': ['a']}
                    cases = [
                        ('d.copy()', lambda: d.copy()),
                        ('dict(d)', lambda: dict(d)),
                        ('{**d}', lambda: {**d}),
                        ('copy.copy(d)', lambda: copy.copy(d)),
                        ('copy.deepcopy(d)', lambda: copy.deepcopy(d)),
                    ]
                    print()
                    for name, make in cases:
                        b = make()
                        print('%-22s %-10s %s' % (name, b is not d, b['tags'] is not d['tags']))

copy模块文档这样定义两种复制："A shallow copy constructs a new compound object and then (to the extent possible) inserts references into it to the objects found in the original."浅拷贝新建一个复合对象，并把原对象中所含对象的引用放进去。"A deep copy constructs a new compound object and then, recursively, inserts copies into it of the objects found in the original."深拷贝新建一个复合对象，并递归地把原对象中所含对象的副本放进去。输出与这些定义一致。

表达式外层容器内层对象
b = orig同一对象同一对象
orig.copy()、list(orig)、orig[:]、[*orig]、copy.copy(orig)新对象与原对象共享
d.copy()、dict(d)、{**d}、copy.copy(d)新对象与原对象共享
copy.deepcopy(orig)、copy.deepcopy(d)新对象新对象

从表中可以读出以下几点。

  • 只有赋值连外层也是同一对象。除赋值外的其余十一种表达式都新建了外层容器。
  • 列表的copy()、list()、切片、[*x]，字典的copy()、dict()、{**d}，以及copy.copy，在这个环境中深度相同，都是一层。
  • 官方文档的内置序列条目把可变序列的copy()描述为"Create a shallow copy of sequence. This is equivalent to writing sequence[:]."这与输出中切片和copy()深度相同相符。
  • copy模块文档说，集合的浅拷贝可以用list.copy()、dict.copy()、set.copy()以及整个序列的切片来完成。copy文档把这些方法列为浅拷贝，输出中的is表格显示了这一点。
  • 只有deepcopy把内层对象也新建了。

在嵌套结构中重现原对象被改变

对只重建了一层的副本做修改时，原对象是否改变取决于修改的是哪一层。下面的代码依次对副本做三种修改，每次都输出原对象。后半部分是复制默认设置字典来生成用户设置的场景。

orig = [[1, 2], [3, 4]]
                    dup = orig.copy()
                    dup.append([5, 6])
                    print('after append to the copy   :', orig)
                    dup[0].append(99)
                    print('after changing an inner list:', orig)
                    dup[1] = 'replaced'
                    print('after replacing an element  :', orig)
                    
                    defaults = {'name': 'base', 'tags': ['a']}
                    user = defaults.copy()
                    user['name'] = 'mine'
                    user['tags'].append('b')
                    print(defaults)
                    print(user)
after append to the copy   : [[1, 2], [3, 4]]
                    after changing an inner list: [[1, 2, 99], [3, 4]]
                    after replacing an element  : [[1, 2, 99], [3, 4]]
                    {'name': 'base', 'tags': ['a', 'b']}
                    {'name': 'mine', 'tags': ['a', 'b']}

向副本append新项(修改外层容器)，以及把副本的元素替换为别的值(dup[1] = 'replaced')，对原对象没有影响。但对副本的内层列表dup[0]执行append(99)后，原对象的orig[0]也变成了[1, 2, 99]。副本与原对象指向同一个内层列表，上一节的new inner False输出已经预示了这个结果。

字典也是如此。user['name'] = 'mine'只改变了user，defaults['name']仍是'base'。但user['tags'].append('b')同时把'b'放进了defaults['tags']。本想生成用户设置的代码，污染了默认设置。

  • 修改副本外层容器的操作(添加、替换、删除项)不会影响原对象。
  • 就地修改副本所共享的内层可变对象的操作(append、[k] = v等)，在原对象中也能看到。
  • 即使是同一个副本，结果也取决于改动了哪个字段，所以测试中只检查一个字段可能发现不了问题。

重复运算不是复制，而是同一引用的重复

用[[0] * 2] * 3创建二维列表，是同一问题的另一种表现。官方文档对s * n写道"items in the sequence s are not copied; they are referenced multiple times"，并举例说lists = [[]] * 3之后lists[0].append(3)会得到[[3], [3], [3]]。下面的输出来自类似的代码。

grid = [[0] * 2] * 3
                    print(grid[0] is grid[1] is grid[2])
                    grid[0][0] = 1
                    print(grid)
                    fresh = [[0] * 2 for _ in range(3)]
                    print(fresh[0] is fresh[1])
                    fresh[0][0] = 1
                    print(fresh)
True
                    [[1, 0], [1, 0], [1, 0]]
                    False
                    [[1, 0], [0, 0], [0, 0]]

第一行是True。三行都是同一个列表对象，grid[0][0] = 1在三行中都出现了。用列表推导式为每一行新建列表的fresh，各行是互不相同的对象(False)，只有一行改变。没有使用任何复制函数却出现同样的现象，原因在于问题不在复制方法，而在于同一个对象上挂了多个名字或位置。

元组中的列表 - 不可变容器的陷阱

数据模型文档写道："The value of an immutable container object that contains a reference to a mutable object can change when the latter's value is changed; however the container is still considered immutable, because the collection of objects it contains cannot be changed."意思是，不可变容器如果包含可变对象，当该可变对象变化时，容器的值也可能随之变化。它与复制相遇时的结果见下面的输出。

import copy
                    t = ([1, 2], 3)
                    print(copy.copy(t) is t)
                    deep = copy.deepcopy(t)
                    print(deep is t, deep[0] is t[0], deep == t)
                    t[0].append(99)
                    print(t)
                    try:
                        t[0] += [4]
                    except TypeError as e:
                        print(type(e).__name__, e)
                    print(t)
                    print(deep)
                    u = (1, 'a')
                    print(copy.deepcopy(u) is u)
True
                    False False True
                    ([1, 2, 99], 3)
                    TypeError 'tuple' object does not support item assignment
                    ([1, 2, 99, 4], 3)
                    ([1, 2], 3)
                    True

第一行中，copy.copy(t) is t为True。元组的浅拷贝没有新建元组，而是返回了同一个对象。第二行中，deepcopy(t)是新元组(deep is t为False)，里面的列表也是新对象(deep[0] is t[0]为False)，值相等(deep == t)。对原来t中的列表执行append(99)后，尽管元组不可变，也变成了([1, 2, 99], 3)。

下一行就是陷阱显现的场景。t[0] += [4]抛出了TypeError: 'tuple' object does not support item assignment，但紧接着输出t，得到([1, 2, 99, 4], 3)。虽然抛了异常，列表里却已经加上了4。这份输出确认的是异常与修改两者都发生了。最后两行中，用deepcopy分离出来的deep仍是([1, 2], 3)，而不含可变对象的元组u = (1, 'a')的deepcopy(u) is u为True。

  • 元组的copy.copy返回同一个对象，所以与「复制了」的感觉相反，什么都没有创建。里面如果有列表，该列表当然是共享的。
  • 元组不可变，指的是元组的元素位置不会改变，并不固定元素所指向的列表的内容。
  • 如果把元组用作字典的键或设置值，并在里面放了列表，那么副本之间会共享这个列表。
  • deepcopy对含有可变对象的元组会新建，对只含不可变对象的元组则返回同一个对象。这两行输出是CPython上的观察结果。

类与数据类的复制

用户自定义类的实例遵循同样的规则。代码用数据类创建带列表字段的对象，用四种方法得到新对象，并输出各自是否共享列表字段。最后一行是向原对象的列表追加一项后，四个副本的列表。

import copy
                    import dataclasses
                    from dataclasses import dataclass, field
                    
                    @dataclass
                    class Box:
                        name: str
                        items: list = field(default_factory=list)
                    
                    a = Box('a', [1, 2])
                    b = copy.copy(a)
                    c = copy.deepcopy(a)
                    d = dataclasses.replace(a, name='d')
                    e = copy.replace(a, name='e')
                    for label, x in [('copy.copy', b), ('copy.deepcopy', c), ('dataclasses.replace', d), ('copy.replace', e)]:
                        print('%-20s new object: %-5s shares items: %s' % (label, x is not a, x.items is a.items))
                    a.items.append(3)
                    print(b.items, c.items, d.items, e.items)
copy.copy            new object: True  shares items: True
                    copy.deepcopy        new object: True  shares items: False
                    dataclasses.replace  new object: True  shares items: True
                    copy.replace         new object: True  shares items: True
                    [1, 2, 3] [1, 2] [1, 2, 3] [1, 2, 3]

四种方法都新建了对象，但只有deepcopy分离了列表。copy.copy、dataclasses.replace以及3.13新增的copy.replace与原对象共享列表，最后一行中向原对象放入3后，这三个副本的列表里也能看到3。copy模块文档写明，copy.replace()在3.13中新增，比copy()和deepcopy()的限制更多，只支持具名元组、数据类以及定义了__replace__()的类。修改部分字段来新建对象的replace系列，会原样带过没有改动的字段，所以可变字段是共享的。

deepcopy并不能复制所有对象。对属性中带有锁(threading.Lock)的对象应用copy.copy与copy.deepcopy，也对定义了__deepcopy__的子类应用。

import copy
                    import threading
                    
                    class Job:
                        def __init__(self, name):
                            self.name = name
                            self.lock = threading.Lock()
                            self.log = []
                    
                    job = Job('j1')
                    try:
                        copy.deepcopy(job)
                    except TypeError as e:
                        print(type(e).__name__, e)
                    print(copy.copy(job).lock is job.lock)
                    
                    class SafeJob(Job):
                        def __deepcopy__(self, memo):
                            new = SafeJob(self.name)
                            new.log = copy.deepcopy(self.log, memo)
                            return new
                    
                    s = SafeJob('j2')
                    s.log.append('start')
                    t = copy.deepcopy(s)
                    print(t.log, t.log is s.log, t.lock is s.lock)
TypeError cannot pickle '_thread.lock' object
                    True
                    ['start'] False False

copy.deepcopy(job)以TypeError: cannot pickle '_thread.lock' object失败，而copy.copy(job).lock is job.lock为True。浅拷贝不碰锁对象，直接共享。定义了__deepcopy__(self, memo)的SafeJob生成了带新锁的新对象(t.lock is s.lock为False)，日志列表被单独复制并分离(t.log is s.log为False，内容为['start'])。copy模块文档说，deepcopy允许用户自定义类重写复制操作或所复制的组成部分的集合，并说明object.__deepcopy__(self, memo)实现深拷贝，且接收memo字典作为参数。该说明与输出一致。

  • 浅拷贝(copy.copy)无论属性是什么，只复制引用，所以即使有锁也成功了。
  • deepcopy遇到无法复制的属性时会以TypeError失败。这份输出中的例子就是锁。
  • 对于带有必须共享的资源(锁、连接等)的类，用__deepcopy__指定复制方式。

deepcopy解决了什么 - memo与循环引用

copy模块文档指出深拷贝有两个问题。第一，递归对象(直接或间接包含对自身引用的复合对象)可能引起递归循环。第二，因为深拷贝会复制一切，可能连本应在副本之间共享的数据也一并复制。文档接着说，deepcopy()用两种方式避免这些问题：保留当前复制过程中已复制对象的memo字典，以及允许用户自定义类重写复制操作或所复制的组成部分。下面的输出涉及第一种机制，包括同一列表出现两次的结构、循环结构以及预先填入的memo。

import copy
                    a = [1]
                    orig = [a, a]
                    deep = copy.deepcopy(orig)
                    print('deepcopy keeps sharing :', deep[0] is deep[1], '| detached from original:', deep[0] is not orig[0])
                    naive = [copy.deepcopy(x) for x in orig]
                    print('per-element deepcopy   :', naive[0] is naive[1])
                    shallow = copy.copy(orig)
                    print('shallow copy           :', shallow[0] is shallow[1], shallow[0] is orig[0])
                    
                    memo = {}
                    copy.deepcopy(orig, memo)
                    print('memo entries           :', len(memo))
                    
                    loop = []
                    loop.append(loop)
                    print('cyclic shallow         :', copy.copy(loop)[0] is loop)
                    dup = copy.deepcopy(loop)
                    print('cyclic deepcopy        :', dup is not loop, dup[0] is dup)
                    
                    keep = {id(a): a}
                    part = copy.deepcopy(orig, keep)
                    print('pre-filled memo        :', part[0] is a, part[0] is part[1])
deepcopy keeps sharing : True | detached from original: True
                    per-element deepcopy   : False
                    shallow copy           : True True
                    memo entries           : 3
                    cyclic shallow         : True
                    cyclic deepcopy        : True True
                    pre-filled memo        : True True
  • 对包含同一个列表a两次的orig = [a, a]做deepcopy，副本中的两个位置也是同一个对象(deep[0] is deep[1]为True)，同时与原对象分离(deep[0] is not orig[0]为True)。结构得到了保持。
  • 对每个元素分别做deepcopy的naive，两个位置变成了不同的对象(False)。原先共享同一对象的结构丢失了。memo只在一次deepcopy调用期间保留，所以把调用拆开就无法保持。
  • 浅拷贝中，内层的两个位置直接指向原来的a(shallow[0] is orig[0]为True)。
  • deepcopy填充的memo中有3个条目。
  • 对包含自身的列表loop，浅拷贝的第一个元素指向原来的loop(True)。deepcopy没有无限递归就结束了，副本是与原对象不同的对象，同时又包含自身(dup[0] is dup为True)。循环结构也得到了保持。
  • 预先把{id(a): a}放入memo再调用deepcopy，part[0] is a为True。已在memo中的对象不会被复制，而是原样使用。

最后一项可以作为把必须共享的对象排除在复制之外的方法。对于文档所说的「可能连本应在副本之间共享的数据也一并复制」这个问题，这份输出表明，预先填充memo可以让一个对象保持共享。不过这是利用memo行为得到的观察，文档给出的正式方法是定义__deepcopy__。

deepcopy的开销 - 这台电脑上的测量值

deepcopy要遍历并复制所有内部对象，所以比浅拷贝更耗时。具体多耗时，由timeit的值给出。对含一万个内层列表的嵌套列表(nested)和含一万个整数的扁平列表(flat)，每个表达式重复5次，输出最快的值，单位为每次调用的微秒。下面两份输出来自同一个脚本运行两次，每次在这台电脑上耗时2到3秒。

import copy
                    import timeit
                    
                    def best_us(stmt, glb, number):
                        runs = timeit.repeat(stmt, globals=glb, number=number, repeat=5)
                        return min(runs) / number * 1e6
                    
                    for n in (100, 10000):
                        nested = [[i, i + 1, i + 2] for i in range(n)]
                        flat = list(range(n))
                        fast, slow = (2000, 200) if n == 100 else (200, 5)
                        g = {'copy': copy, 'nested': nested, 'flat': flat}
                        print('n =', n)
                        print('  nested.copy()             %10.1f us' % best_us('nested.copy()', g, fast))
                        print('  copy.copy(nested)         %10.1f us' % best_us('copy.copy(nested)', g, fast))
                        print('  copy.deepcopy(nested)     %10.1f us' % best_us('copy.deepcopy(nested)', g, slow))
                        print('  flat.copy()               %10.1f us' % best_us('flat.copy()', g, fast))
                        print('  copy.deepcopy(flat)       %10.1f us' % best_us('copy.deepcopy(flat)', g, slow))

同样的代码，两份输出的数值相差不小。同一表达式在两份输出中的值不同，所以应当看数量级的差异，而不是绝对数值。对于一万个元素的嵌套列表，copy.deepcopy(nested)耗时约为copy.copy(nested)的624~641倍(两份输出的计算值)，对于一万个整数的copy.deepcopy(flat)，也约为flat.copy()的167~173倍(计算值)。即使是内部不含可变对象的整数列表，deepcopy的值也比浅拷贝大。上面的倍数是这台电脑上的值，重新运行会有变化。

  • 在这个规模下，浅拷贝的值是几十微秒，deepcopy的值是几千到几万微秒(毫秒级)。
  • 当在副本中修改内层可变对象时才需要deepcopy。只读的副本或不改动内部的副本，如第4节的结果所示，用浅拷贝就不会影响原对象。
  • 在循环内调用deepcopy的代码，开销会乘以循环次数。
  • 这次测量是在一台电脑上运行两次的结果。这些数值不是对改进或减少的承诺，数据形状不同可能得到不同结果。

如何选择 - 选择标准

把前面输出得到的标准整理成表。选择性复制与deepcopy两行以下面代码的输出为依据。第一个代码块只复制要修改的字段，第二个代码块用deepcopy整体复制。两种情况都修改副本的limits，然后输出原对象。

import copy
                    
                    def make():
                        return {'name': 'base', 'tags': ['a'], 'limits': {'cpu': 1}}
                    
                    defaults = make()
                    one = {**defaults, 'tags': defaults['tags'].copy()}
                    one['tags'].append('b')
                    one['limits']['cpu'] = 8
                    print('selective copy:', defaults)
                    
                    defaults = make()
                    two = copy.deepcopy(defaults)
                    two['tags'].append('b')
                    two['limits']['cpu'] = 8
                    print('deepcopy      :', defaults)
selective copy: {'name': 'base', 'tags': ['a'], 'limits': {'cpu': 8}}
                    deepcopy      : {'name': 'base', 'tags': ['a'], 'limits': {'cpu': 1}}

选择性复制复制了tags，所以原对象的tags得到保护，但没有复制的limits被共享，原对象的limits变成了{'cpu': 8}。用deepcopy时，重新生成的原对象的tags和limits都保持原样。选择性复制可能漏掉应复制的字段，而deepcopy有开销。

情形方法输出中看到的依据
内部没有可变对象(整数、字符串列表)list.copy()、切片第3节，新的外层容器就够了
只改外层，内层只读浅拷贝第4节，外层改动不影响原对象
只改内层的一部分只复制要修改的字段本节，漏掉的字段会被共享
嵌套深度未知，或必须全部分离copy.deepcopy本节，原对象保持不变
复制时保持同一对象在多处共享的结构一次deepcopy调用第8节，memo保持了结构
有无法复制或必须共享的属性定义__deepcopy__第7节，带锁的对象出现TypeError
修改数据类的部分字段后新建dataclasses.replace(列表会被共享)第7节
创建二维列表用推导式为每行新建列表第5节
