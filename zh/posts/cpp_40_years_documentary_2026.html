C++ 四十年史 - 从贝尔实验室到今天，一部纪录片回顾的旅程

一门语言如何拒绝消亡并再度成长

2026年6月7日 IT/技术

引言：一门坚持四十年的语言，以及一部纪录片

2026年6月，一部纪录片发布，让开发者社区为之一振。片名很朴素：「C++: The Documentary」。它记录了一门语言四十年的历程——从1979年贝尔实验室的一个小实验起步，扩散到游戏引擎、金融交易系统、CERN的粒子物理实验，乃至全球数百万开发者的指尖。这部纪录片中出现了创造该语言的Bjarne Stroustrup(本贾尼·斯特劳斯特鲁普)、领导标准化的Herb Sutter、设计STL的Alexander Stepanov，甚至还有创作了Doom与Quake的John Romero。

有意思的是，这部纪录片并非「怀旧回顾」。据发布时引用的统计，截至2025年第三季度，C++是前四大编程语言中增长最快的，过去3.5年用户增长超过90%。一门曾被视为「遗留」的语言，正再次画出成长曲线。本文将沿着纪录片梳理的脉络，平静地理一理：C++诞生于何处，如何成为标准，为何至今仍被使用，现代C++改变了什么，以及在Rust时代它意味着什么。

1. 诞生：贝尔实验室与「C with Classes」(1979)

故事始于1979年，丹麦出身的年轻计算机科学家Bjarne Stroustrup加入AT&T贝尔实验室。他在博士阶段研究分布式系统时遇到一个两难：擅长仿真的Simula(模拟语言)提供了类这样强大的抽象，但实际使用太慢；反之BCPL虽快，却过于底层，难以构建大型软件。

Stroustrup的结论很干脆：把Simula的抽象架在C的速度之上。1979年10月，他做出了一个为C代码加入Simula式类的预处理器Cpre，这便是「C with Classes」的开端。这一时期加入的特性——类、派生类、强类型检查、内联函数、默认参数——直接奠定了今日C++的骨架。一项关键哲学此时便已确立：「不在运行期为抽象付出代价(零开销抽象)」。即不用的特性不产生开销，用到的特性也不应比手写代码更昂贵。

2. 改名：C++的诞生(1982至1985)

1982年，Stroustrup开始研发「C with Classes」的继任者，并为新名字斟酌。在众多候选中胜出的是C++，取自C语言的自增运算符++，寓意「把C向上推进一步」。命名本身就透着程序员的机智。

1983年，一款名为Cfront的编译器登场。Cfront的精髓在于：先把C++代码转换为C代码，再用既有的C编译器编译。正是这一巧妙策略，让C++得以搭载在当时几乎每个平台都具备的C工具生态之上。1985年，C++随首次商业发布正式问世，同年Stroustrup的著作《The C++ Programming Language》第一版出版。在尚无官方标准的年代，这本书本身扮演了事实标准的角色。

C++的设计哲学可凝练为一句话：信任程序员，但让抽象的代价付在编译期，而非运行期。

3. 标准化时代：通往C++98之路

1980年代后期，C++迅速普及，但风险也随之上升。各家编译器行为略有差异，仅靠一本书支撑的非正式标准难以承载大规模产业采用。于是1990年代初，ISO与ANSI委员会成立，正式的标准化工作开始。

其成果便是1998年的C++98(ISO/IEC 14882:1998)，这是C++首个官方国际标准。该过程中最重要的事件，是整合了由Alexander Stepanov设计的STL(标准模板库)。vector、map、set、list等容器与算法，以基于模板的泛型编程进入标准库。STL不仅是数据结构的集合，更把「容器—迭代器—算法」相分离、自由组合的思维方式镌刻进了C++。2003年，修正了C++98缺陷与歧义的小幅版本C++03问世。

4. 停滞与「C++的寒冬」

C++98之后，C++一度进入停滞期。纪录片也用「2000年代初的C++寒冬」来形容这段时期。带垃圾回收的Java、C#等语言崛起，「C++太复杂、太危险」的批评铺天盖地。由指针误用导致的内存泄漏与崩溃，被点名为C++的标志性弱点。

2003年之后整整八年没有新标准问世，这一事实象征性地展现了那段停滞。许多人认为C++的鼎盛已成过去。然而这段沉默期，实则是下一次飞跃的准备。委员会正在绘制一幅从根本上现代化语言的宏图。

5. 复兴：C++11与「现代C++」的开端

2011年，打破八年沉默的C++11是一个改变格局之作。变化太多，以至于人们开始把这一时点之后称为「现代C++(Modern C++)」。Stroustrup本人也表示「C++11感觉像一门新语言」。其主要新增特性如下：

  • 智能指针(unique_ptr、shared_ptr)：无需手动new/delete即可自动管理资源寿命，从结构上消除内存泄漏的主因。
  • 移动语义：以「移动」资源所有权取代无谓的复制，提升性能，极大降低了返回与传递大型对象的开销。
  • auto类型推导：让编译器推断冗长的类型声明，使代码更简洁。
  • lambda表达式：可在代码流中直接编写匿名函数。
  • constexpr：显式支持编译期计算。

这些变化的共同方向十分明确：「减少危险的手工操作，让编译器做更多事」。尤其是智能指针与移动语义，在很大程度上缓解了C++顽固的内存问题，同时又避开了垃圾回收器的运行期开销。

6. 三年周期的演进：C++14 / 17 / 20

C++11之后，委员会确立了以三年为周期发布标准的规律节奏。这种可预测性本身，就为重建产业信心立下大功。

  • C++14 (2014)：填补C++11缝隙的小幅扩展，通过泛型lambda、变量模板等打磨易用性。
  • C++17 (2017)：以标准文件系统库(<filesystem>)与并行STL为代表特性，还加入了结构化绑定、std::optional、std::string_view、if constexpr等实用工具。
  • C++20 (2020)：堪比C++11的大变革，核心是常被称为「四大件」的四项功能——概念(Concepts)、范围(Ranges)、协程(Coroutines)、模块(Modules)。

尤其是C++20的四大件，改变了语言的表达方式本身。概念为模板显式施加约束，把晦涩的错误信息变得可读；范围让集合处理得以声明式地串联；协程让异步与惰性求值的代码写起来更自然；模块则为根本改善数十年来头文件方式的慢编译与宏污染开辟了道路。

7. 用代码看变化：旧C++ vs 现代C++

只用语言描述显得抽象，下面用两个时代的风格来对比同一任务：直接操作内存的旧方式，与使用智能指针、标准算法的现代方式之别。

// 旧风格 (C++98) - 手动内存管理，泄漏风险
#include <iostream>

void old_style() {
    int* arr = new int[3];          // 手动分配
    arr[0] = 1; arr[1] = 2; arr[2] = 3;

    int sum = 0;
    for (int i = 0; i < 3; ++i) {    // 基于索引的循环
        sum += arr[i];
    }
    std::cout << sum << std::endl;

    delete[] arr;                    // 一旦忘记便内存泄漏
}
// 现代风格 (C++20) - RAII、标准算法、安全推导
#include <vector>
#include <numeric>
#include <iostream>

void modern_style() {
    // 栈上自动管理的容器 - 无需 delete
    std::vector<int> nums{1, 2, 3};

    // 用标准算法声明式地表达意图
    auto sum = std::accumulate(nums.begin(), nums.end(), 0);

    std::cout << sum << std::endl;
}   // nums 离开作用域时自动释放 (RAII)

核心区别在于delete消失了。现代C++的RAII(Resource Acquisition Is Initialization，资源获取即初始化)原则，把资源的生命周期绑定到对象的生命周期。对象离开作用域时资源会自动归还，于是「忘记delete导致的泄漏」这一经典缺陷便从结构上消失了。智能指针正是把RAII应用于指针的实例。

8. 为何仍是C++：性能即身份

2026年C++依旧稳健的原因，可归结为一个词：性能。更准确地说，是它那独特的定位——「在没有垃圾回收器的情况下提供接近硬件的控制，同时又能使用高层抽象」。这一特性大放异彩的领域十分清晰。

领域 为何选C++ 代表案例
游戏引擎 逐帧的毫秒级控制、可预测的延迟 Unreal Engine、主流3A大作
操作系统与浏览器 底层硬件访问、极致优化 Windows核心、Chrome/V8
金融交易 纳秒级延迟直接等于利润 高频交易(HFT)系统
嵌入式与汽车 资源受限、实时控制 车辆控制、航空航天
科学计算 大规模数值运算的吞吐量 CERN粒子物理分析(ROOT)

据一份基准测试报告，在某些以延迟为核心的应用中，C++比Rust快15至20%，原因是它没有Rust为安全而加入的部分运行期检查。在每一周期都重要的游戏引擎与嵌入式中，这类细微差距便成了选型依据。一项研究甚至发现，73%的嵌入式开发者在实时系统中使用C++。

9. 挑战者Rust：不是竞争，而是共存

谈现代C++，绕不开Rust。Rust通过所有权(ownership)与借用检查(borrow checker)，在编译期拦截悬垂指针、释放后使用(use-after-free)与数据竞争，在以内存安全为命脉的汽车、嵌入式领域极具吸引力。一度，「Rust将取代C++」的预言颇为流行。

然而2026年的现实更接近「共存」而非「取代」，原因如下：

  • 庞大的既有代码库：游戏引擎、操作系统、金融系统中积累了数十年的C++代码，无法一夜重写。
  • 生态与工具的成熟度：C++在库、调试器、性能分析器等方面的生态深度具压倒性优势。
  • C++自身的演进：C++26以强化了std::vector、std::string边界检查的「加固标准库」，正在缩小安全差距。

产业的实际选择很明确：需要既有资产与极致性能的领域由C++守住，新启动的、以安全为先的项目则越来越多地交给Rust。在同一系统中混用两种语言的案例也在增多。若对渐进迁移到Rust感兴趣，可参阅从Go迁移到Rust指南；关于内存安全与性能的平衡，可一并阅读用Rust实现的Zstandard分析，这一脉络会更清晰。

10. 纪录片抛出的讯息

「C++: The Documentary」由CultRepo制作，并获得金融领域的赞助。它超越了单纯的技术介绍，探讨一个更大的问题：一门语言如何在四十年间存活并再度成长。纪录片传递的讯息可归纳为三点。

第一，坚持的力量。C++从未是「最时髦的语言」，却默默地持续演进，始终未曾消失。第二，向后兼容的分量。数十年前的代码今天仍须能编译，这一约束让语言变得复杂，但同时也成为庞大产业可以安心倚靠的基石。第三，社区与委员会的奉献。围绕标准的无尽争论与妥协，正是让C++保持鲜活的动力。

11. 给想学C++的人

这段历史再有趣，最终仍会留下一个务实的问题：「现在该学C++吗？若要学，又该怎么学？」结合纪录片的脉络与现代C++的方向，建议如下。

  1. 从现代C++入手。不要照着以new/delete为中心的旧教材，而要从一开始就掌握C++17/20之后的智能指针与RAII。同一门语言，安全性与生产力却截然不同。
  2. 熟悉STL与算法。vector、map以及标准算法是现代C++的日常用语。在自己动手实现之前，先去标准库里找的习惯很重要。
  3. 对「为何用C++」要目标明确。以游戏、嵌入式、高性能系统这类C++大放异彩的领域为目标，学习动机便会清晰。若只是普通的Web后端，别的选择或许更合适。
  4. 把工具一起学。把编译器警告开到最大，养成使用静态分析器与sanitizer(地址、内存检查工具)的习惯，能大幅降低C++的风险。

12. 结语 + 三件可立即实践的事

C++的四十年，可凝练为一句话：「在不放弃性能的前提下，不断朝更安全、更具表达力演进的语言」。从贝尔实验室的一个小预处理器起步，越过标准化之路与「寒冬」，历经C++11的复兴与C++20的大变革，如今在C++26前夕，再度成为增长最快的语言。就连Rust的挑战，也更多是刺激C++更安全地演进，而非终结它。

以三件可立即实践的事作结。

  1. 以现代C++重新审视它。若你早年接触过C++后又疏远，花30分钟看看C++17/20的智能指针、范围与概念。你或许会惊呼：「这真的是那个C++吗？」
  2. 把手动内存管理换成RAII。把既有代码中残留的new/delete逐步换成unique_ptr、vector等RAII工具，最常见的内存缺陷便会消失。
  3. 亲自看一看这部纪录片。「C++: The Documentary」超越技术本身，带来「一项技术如何长久存活」的洞见。无论你用什么语言，只要你是创造者，它都值得一看。
