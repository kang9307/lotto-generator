10년 된 Xeon으로 Gemma 4 돌리기 - 구형 하드웨어로 로컬 LLM 운영하는 법 2026

You Don't Need a GPU - Running Gemma 4 on Decade-Old Xeon Hardware in 2026

2026-06-03 IT/기술

서론: GPU 없이도 로컬 LLM이 가능하다

로컬 LLM 이야기가 나오면 거의 반사적으로 "GPU가 있어야지"라는 말이 따라붙습니다. 수백만 원짜리 그래픽카드가 없으면 시작도 못 한다는 인식이 강합니다. 그런데 2026년 현재, 이 전제는 생각보다 쉽게 무너집니다. 창고에 처박혀 있던 10년 된 Xeon 서버, 회사에서 폐기 직전인 구형 워크스테이션, 중고 시장에서 몇십만 원에 굴러다니는 듀얼 소켓 보드. 이런 하드웨어로도 Gemma 4 같은 경량 오픈 모델을 충분히 돌릴 수 있습니다.

이 글은 GeekNews(hada.io)에서 화제가 된 "10년 된 Xeon으로 Gemma 4 운영 가능"이라는 주제를, 단순 소개가 아니라 직접 운영하는 사람의 관점에서 재구성한 분석입니다. 어떤 글의 번역이나 요약이 아니라, 왜 구형 CPU로도 가능한지, 어디까지가 현실적이고 어디부터가 무리인지, 한국의 중고 서버 시장과 전기료 환경에서 이 전략이 말이 되는지를 직접 따져 봅니다.

핵심 질문은 단순합니다. "GPU에 큰돈을 들이는 대신, 이미 가지고 있거나 헐값에 구할 수 있는 구형 Xeon으로 로컬 LLM을 굴리면 정말 쓸 만한가?" 결론부터 말하면, 작업의 성격을 제대로 분류한다면 상당히 많은 용도에서 답은 "그렇다"입니다. 다만 모든 것을 구형 CPU에 떠넘기려 하면 느린 속도와 전력이라는 벽에 부딪힙니다.

1. Gemma 4란 - Google의 오픈 경량 모델 개요

Gemma는 Google이 공개한 오픈 가중치(open-weight) 경량 LLM 계열입니다. 거대 폐쇄형 모델과 달리 가중치가 공개되어 누구나 내려받아 자기 하드웨어에서 돌릴 수 있고, 무엇보다 여러 크기의 변형을 함께 제공한다는 점이 구형 하드웨어 활용에 결정적입니다.

1.1 크기 선택의 자유

Gemma 4 계열은 작은 변형부터 큰 변형까지 라인업이 나뉩니다. 작은 변형은 수십억 파라미터 규모로, 양자화하면 구형 CPU에서도 무리 없이 돌아갑니다. 여기서 핵심은 "가장 큰 모델"이 아니라 "내 하드웨어가 감당하는 가장 작은 충분한 모델"을 고르는 사고방식입니다.

1.2 왜 경량 모델이 충분한가

요약, 분류, 태깅, 1차 초안 생성 같은 비핵심 반복 작업에서는 소형 모델의 품질이 이미 충분히 쓸 만합니다. 최고 품질이 필요한 작업과 "그럭저럭 괜찮으면 되는" 작업을 구분하면, 후자의 비중이 생각보다 크다는 것을 금방 알게 됩니다. 바로 그 영역이 구형 Xeon + 경량 Gemma 조합이 빛나는 자리입니다.

2. 구형 Xeon으로 가능한 이유 - 양자화·메모리·CPU 추론

10년 전 서버 CPU가 어떻게 최신 LLM을 돌릴까요. 세 가지 기술적 사실이 이를 가능하게 합니다.

2.1 양자화가 모델을 작게 만든다

원본 모델은 보통 16비트 부동소수점으로 저장되지만, 4비트나 8비트로 양자화하면 메모리 사용량이 절반에서 4분의 1로 줄어듭니다. 품질 손실은 비핵심 작업에서 거의 체감되지 않는 수준입니다. 양자화 덕분에 예전이라면 고가 GPU에서나 돌던 모델이 평범한 서버 RAM에 들어맞게 됩니다.

2.2 메모리가 GPU VRAM을 대신한다

GPU 추론의 핵심은 빠른 VRAM입니다. CPU 추론은 그 자리를 시스템 RAM이 대신합니다. 구형 Xeon 서버의 장점은 RAM을 매우 저렴하게 대량으로 꽂을 수 있다는 것입니다. 중고 DDR4 ECC 메모리는 헐값이라, 64GB, 128GB도 부담 없이 확보할 수 있습니다.

2.3 AVX 명령어와 다수 코어

2010년대 중반 이후 Xeon은 AVX2 같은 벡터 명령어를 지원하고, 코어 수도 많습니다. llama.cpp 같은 추론 엔진은 이 명령어와 멀티코어를 활용해 행렬 연산을 병렬화합니다. 덕분에 한 세대 지난 CPU에서도 의미 있는 추론 속도가 나옵니다.

3. 필요한 하드웨어 - 최소 사양과 권장 사양

실제로 무엇을 갖춰야 하는지 표로 정리했습니다. 절대 수치는 모델 크기에 따라 달라지므로 상대적 관계에 집중하세요.

구분최소 사양권장 사양
CPUAVX2 지원 멀티코어 Xeon듀얼 소켓, 메모리 채널 다수
RAM16GB32~128GB (채널 모두 채움)
저장장치SATA SSDNVMe SSD
모델4비트 소형 변형5~8비트 중형 변형

가장 중요한 포인트는 메모리 대역폭입니다. CPU 추론에서 속도를 결정하는 진짜 병목은 코어 수가 아니라, 메모리에서 가중치를 얼마나 빨리 읽어 오느냐입니다. 그래서 메모리 채널을 전부 채우는 것이 단순히 용량을 늘리는 것보다 체감 속도에 더 큰 영향을 줍니다.

4. CPU 추론의 현실 - 속도 vs 비용 트레이드오프

솔직해질 시간입니다. 구형 Xeon에서의 CPU 추론은 느립니다. 양자화된 소형 모델 기준 초당 한 자리에서 낮은 두 자리 토큰이 일반적입니다. 사람이 글을 읽는 속도와 비슷하거나 약간 느린 정도라, 짧은 답변은 견딜 만하지만 긴 문서를 통째로 생성하면 답답함이 분명히 느껴집니다.

하지만 속도만 보면 절반의 그림만 보는 것입니다. 반대편에는 비용이 있습니다. 이미 보유한 서버라면 진입 비용은 사실상 0이고, 중고로 사도 GPU 한 장 값에 한참 못 미칩니다. 토큰을 아무리 생성해도 추가 과금이 없다는 점은 API 종량제와 결정적으로 다릅니다. 즉, 속도를 비용으로 맞바꾸는 구조입니다. 시간에 여유가 있고 돈을 아껴야 하는 작업이라면 이 교환은 충분히 합리적입니다.

5. 양자화의 마법 - Q4·Q5·Q8

구형 하드웨어 활용의 핵심 기술이 바로 양자화입니다. 같은 모델이라도 어떤 양자화를 고르느냐에 따라 메모리와 속도, 품질이 크게 달라집니다.

  • Q4 (4비트): 메모리를 가장 적게 쓰고 가장 빠릅니다. 비핵심 반복 작업에 적합하며, 구형 Xeon의 첫 선택지로 권합니다.
  • Q5 (5비트): Q4와 Q8 사이의 균형점. 약간의 메모리를 더 쓰는 대신 품질이 안정적입니다.
  • Q8 (8비트): 원본에 가장 가까운 품질. RAM이 넉넉하고 품질이 중요할 때 선택합니다.

실무에서는 Q4로 시작해 품질이 부족하면 Q5, Q8로 한 단계씩 올리는 방식을 권합니다. 양자화의 더 깊은 원리와 모델 선택 기준은 로컬 LLM 하드웨어 선택 가이드에서 이어집니다.

6. 실전 셋업 가이드 - llama.cpp와 Ollama

이제 실제로 돌려 봅니다. 가장 널리 쓰이는 두 가지 경로를 소개합니다.

6.1 Ollama로 가장 빠르게 시작하기

Ollama는 CPU 추론을 기본 지원하며, 설치와 실행이 가장 단순합니다.

# Ollama 설치 (Linux)
curl -fsSL https://ollama.com/install.sh | sh

# 경량 Gemma 모델 받아서 실행 (CPU 자동 사용)
ollama run gemma:2b

# 백그라운드 서비스로 API 띄우기
ollama serve

GPU가 없으면 Ollama가 자동으로 CPU 추론으로 동작합니다. 별도 설정 없이 바로 대화를 시작할 수 있어 첫 검증에 이상적입니다.

6.2 llama.cpp로 세밀하게 제어하기

속도와 메모리를 직접 튜닝하려면 llama.cpp가 정답입니다. GGUF 양자화 모델을 직접 지정하고 스레드 수를 조절할 수 있습니다.

# 빌드 (AVX2 자동 감지)
git clone https://github.com/ggerganov/llama.cpp
cd llama.cpp && make

# 4비트 양자화 모델로 추론, 물리 코어 수에 맞춰 스레드 지정
./llama-cli -m gemma-4-q4.gguf -p "로컬 LLM의 장점 세 가지" -t 16

# OpenAI 호환 API 서버로 띄우기
./llama-server -m gemma-4-q4.gguf -t 16 --port 8080

여기서 -t 값은 물리 코어 수에 맞추는 것이 보통 가장 빠릅니다. 하이퍼스레딩을 포함한 논리 코어 전부를 쓰면 오히려 느려지는 경우가 많으니 직접 측정해 보세요.

7. 어떤 작업에 적합한가 vs 부적합한가

7.1 적합한 작업

  • 대량 문서 요약: 시간 여유가 있는 배치 처리에 최적입니다.
  • 분류·태깅: 카테고리 분류, 감정 분석은 소형 모델로도 충분합니다.
  • 1차 초안 생성: 사람이 최종 검토하므로 속도가 덜 중요합니다.
  • 내부 RAG 검색: 외부 노출 없는 사내 지식 검색은 프라이버시 측면에서도 유리합니다.
  • 학습·실험: LLM 동작을 직접 뜯어보며 배우기에 비용 부담이 없습니다.

7.2 부적합한 작업

  • 실시간 대화형 서비스: 느린 토큰 속도가 사용자 경험을 해칩니다.
  • 대규모 동시 처리: 단일 구형 서버로 높은 동시성을 감당하기 어렵습니다.
  • 복잡한 다단계 추론: 소형 모델의 한계가 가장 잘 드러나는 영역입니다.
  • 저지연 SLA 보장 서비스: 응답 시간 보장이 어렵습니다.

8. 구형 하드웨어 활용의 5가지 시나리오

  1. 홈랩 실험실: 폐기 직전 서버를 LLM 놀이터로 재활용. 클라우드 비용 걱정 없이 마음껏 실험합니다.
  2. 프라이버시 우선 처리: 민감한 사내 문서를 외부 API에 보내지 않고 로컬에서만 처리합니다.
  3. 학습 플랫폼: 양자화, 추론 엔진, 프롬프트를 직접 만지며 배우는 비용 0의 학습 환경.
  4. 백업 추론 노드: 메인 GPU 서버 장애 시 비핵심 작업을 떠받치는 보조 노드.
  5. 비용 절감 배치 파이프라인: 야간에 대량 요약·분류를 돌려 API 종량제를 대체합니다.

9. 한국 환경 적용 - 중고 서버 시장, 전기료, 홈서버

한국에서 이 전략은 특히 매력적인 조건을 갖췄습니다. 첫째, 중고 서버 시장이 활발합니다. 데이터센터 교체 물량이 풀리면서 듀얼 Xeon 보드, ECC 메모리, 서버 케이스를 합리적인 가격에 구할 수 있습니다.

둘째, 다만 전기료는 신중히 따져야 합니다. 구형 서버는 전성비가 떨어져 24시간 가동 시 전기료가 누적됩니다. 가정용 누진제 구간에 걸리면 비용이 빠르게 올라가므로, 상시 가동보다는 필요할 때만 켜는 배치 운영이 현실적입니다. 발열과 소음 때문에 거주 공간과 분리된 곳에 두는 것도 고려해야 합니다.

셋째, 홈서버 문화와 잘 맞습니다. 이미 NAS나 홈서버를 운영하는 사용자라면 거기에 LLM 추론을 얹는 진입 장벽이 낮습니다. 더 넓은 맥락은 저렴한 외주 인력 + LocalAI 비용 전략 글에서 다룹니다.

10. 위험과 한계 - 느린 속도, 전력, 발열

장밋빛만 칠하면 정직하지 않습니다. 구형 Xeon LLM 운영에는 분명한 한계가 있습니다.

  • 느린 속도: 가장 큰 제약. 실시간성이 필요한 어떤 용도에도 부적합합니다.
  • 전력 소비: 구형 서버의 낮은 전성비는 장기 운영 시 전기료로 돌아옵니다.
  • 발열·소음: 서버 팬 소음과 발열은 가정 환경에서 무시할 수 없습니다.
  • 유지보수 부담: 노후 하드웨어는 고장 가능성이 높고 부품 수급이 까다로울 수 있습니다.

이런 한계를 인정하고 "배치·비핵심·학습용"이라는 제자리에 두면, 구형 하드웨어 LLM은 훌륭한 도구가 됩니다. 메모리 할당이나 추론 성능을 더 깊이 파고들고 싶다면 mimalloc 고성능 메모리 할당자 글도 참고할 만합니다.

11. 결론 + 즉시 시도 가능한 3가지

결론은 명확합니다. 로컬 LLM에 GPU는 필수가 아닙니다. 작업을 제대로 분류하고 양자화된 경량 Gemma 4를 구형 Xeon에 올리면, 비핵심 작업의 상당 부분을 사실상 무료에 가까운 비용으로 처리할 수 있습니다. 핵심은 "모든 걸 돌리겠다"가 아니라 "돌려도 되는 것만 돌린다"입니다.

지금 바로 시도할 수 있는 세 가지를 권합니다.

  • Ollama로 5분 검증: 보유한 구형 서버에 Ollama를 깔고 경량 Gemma를 띄워 토큰 속도를 직접 측정하세요.
  • 배치 작업 하나 이전: 야간 문서 요약 같은 비핵심 작업 하나를 구형 서버로 옮겨 6주간 품질·속도·비용을 기록하세요.
  • 전기료 손익 계산: 24시간 가동 시 월 전기료를 계산해, 상시 운영과 필요 시 운영 중 무엇이 합리적인지 판단하세요.
