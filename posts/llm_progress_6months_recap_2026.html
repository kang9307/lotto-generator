2025년 11월부터 2026년 5월까지 AI 지형을 바꾼 6개월을 매트릭스 한 장으로

이 게시물은 쿠팡 파트너스 활동의 일환으로, 이에 따른 일정액의 수수료를 제공받습니다.

서론: 왜 6개월 단위의 정리가 2026년에 맞는 해상도인가

6개월 전인 2025년 11월의 LLM 풍경은 안정적으로 보였습니다. GPT-4.5o가 기본 모델이었고, Claude 4.5 Sonnet이 막 출시되었으며, Gemini 2.0 Flash가 저가 영역의 일꾼이었습니다. 시장은 "스케일링 법칙이 약해지고 곡선이 평탄해졌다"고 이야기했습니다. 그 후 6개월이 지난 지금, 그 문단의 거의 모든 가정이 깨졌습니다. 11월부터 5월까지의 윈도우는 초대 GPT-4 출시 이래 가장 바쁜 LLM 릴리즈 사이클이었고, 그 속도는 AI 풀타임 빌더들조차 따라가지 못할 정도였습니다. 주변의 시니어 개발자들과 이야기해 보면, 자기 스택에는 여전히 2025년 가정이 박혀 있고 가용 품질, 비용, 속도의 30~50%를 손해 보면서 쓰고 있는 경우가 대부분입니다.

이 글은 본인이 본인 작업을 위해 정리해 둔 6개월 회고입니다. 주요 랩과 오픈 웨이트 패밀리를 빠짐없이 훑고, 변화를 매트릭스와 표로 압축하며, 마지막에는 다섯 개의 구체적 실무 시사점과 H1 2026 전망으로 마무리합니다. 구조는 의도된 것입니다. 회사별 정리, 다음에 트렌드, 다음에 벤치마크, 다음에 조언. 매트릭스만 필요하면 두 개의 큰 표만 보면 됩니다. 맥락을 알고 싶다면 처음부터 끝까지 읽어주세요. 본문은 어떤 랩의 마케팅 어조도 아닌, 본인이 직접 굴려 본 감각에 기반해 작성했습니다.

본격적인 정리에 들어가기 전에 세 가지 프레임을 짚습니다. 첫째, 모델 번호는 진보 측정 단위가 아닙니다. 어떤 랩의 "0.1"은 다른 랩의 "2.0"보다 큰 점프일 수 있습니다. 본문은 "무엇이 실제로 바뀌었는가"를 중심에 둡니다. 둘째, 폐쇄 모델과 오픈 웨이트의 진행 곡선이 이제는 평행으로 달리고 있습니다. 일부 축에서는 격차가 몇 주 단위로 좁혀집니다. 셋째, 가장 결정적인 변화는 어떤 단일 모델 릴리즈가 아니라 주변 스택입니다. 에이전트 하네스, 코딩 에이전트, 메모리 원시 기능, 그리고 사실상 표준으로 자리 잡은 Model Context Protocol이 그것입니다. 본문 전반에서 이 점으로 계속 돌아옵니다.

OpenAI: GPT-5, Codex Goals, Operator 트랙

OpenAI의 H1 2026은 두 가지 큰 움직임으로 요약됩니다. 첫 번째는 1월 말 GPT-5 출시입니다. 그동안 o 시리즈로 갈라져 있던 추론 트랙을 통합했고, "추론 모델 따로 토글" 구조 대신 하나의 제품 안에서 적응형 사고 예산을 자동으로 조정하는 형태가 되었습니다. 이 단순화만으로도 개발자 입장에서 거대한 혼란이 사라졌습니다. 두 번째는 2월 말부터 4월에 걸쳐 단계적으로 풀린 Codex Goals입니다. Codex 서브 제품을 단순 챗 완성에서 "고수준 목표를 받아 저장소에 몇 시간 동안 작업하는" 자율 코딩 에이전트에 가까운 무언가로 변모시켰습니다.

조용한 변화가 실무에서는 더 중요합니다. 3월 Operator 스택의 일반 출시로 컴퓨터 사용 API가 안정화되었고, 깨진 페이지 상태에서의 회복력이 눈에 띄게 좋아졌습니다. Realtime API에 네이티브 도구 사용이 추가되면서 음성 워크플로에서 Anthropic과의 격차가 좁혀졌습니다. 메모리 영속성은 실험 기능에서 명시적 저장, 검색, 망각 원시 기능을 가진 문서화된 표면으로 승격되었습니다. "어시스턴트가 세션을 넘어 나를 기억한다"를 만들기가 1분기 프로젝트에서 1주 프로젝트로 바뀐 셈입니다. 이 모두는 보도 사이클을 지배하지는 않았지만, 실제 프로덕션 스택은 이 위에 세워집니다.

가격 측면에서는 GPT-5가 2025년 후반 GPT-4.5o 대비 입력은 거의 동일하게, 출력은 캐시 윈도우 연장 덕분에 의미 있게 저렴해진 상태로 출시되었습니다. 4o 패밀리는 Q3 2026에 끝나는 일정으로 단계적 폐기 중이며, 아직 4o에 머물러 있는 팀은 지금 마이그레이션 윈도우를 잡아야 합니다. Codex Goals 변화 자체와 일상 루프에 어떻게 엮을지에 대한 별도 정리는 본 블로그의 OpenAI Codex Goals 실전 활용 가이드 2026에서 더 깊이 다룹니다.

Anthropic: Claude 4.5, 4.6, 4.7 그리고 Claude Code의 해

Anthropic은 6개월 동안 의미 있는 세 번의 릴리즈를 진행했습니다. 2025년 12월 말 Claude 4.6는 도구 사용을 정밀화하고 긴 문서 처리에 네이티브 대응을 추가했습니다. 2026년 3월 Claude 4.7 Sonnet는 컴퓨터 사용을 기본 제품에 편입시키고 코딩 벤치마크를 사실상 다른 모델들과 격차를 두면서 끌어올렸습니다. 2026년 5월 Claude 4.7 Opus는 에이전트와 긴 컨텍스트 대부분의 작업에서 현재 프론티어 모델이며, 본인도 멀티시간 자율 코딩 세션에서 이 모델을 기본으로 씁니다. 각 릴리즈는 이름상 점진적이지만, 누적적으로 "에이전트를 두 시간 보내놓고 신뢰할 수 있는가" 카테고리에서 Anthropic의 격차를 벌렸습니다.

모델 주변에서 Claude Code는 완성된 제품으로 진화했습니다. Skills, Hooks, Sub-agents, 안정화된 settings.json 스키마가 CLI를 파워 유저 장난감에서 팀이 코드베이스 전체에 배포하는 도구로 바꿔놓았습니다. 2024년 후반 Anthropic이 시작한 Model Context Protocol은 H1 2026에 사실상 업계 표준이 되었습니다. OpenAI, Google, 그리고 주요 IDE 벤더 대부분이 MCP를 네이티브 지원합니다. 이는 이 기간 가장 의미 있는 단일 표준 변화입니다. 프로토콜 레이어를 조용히 점유하면서 Anthropic은 어떤 모델을 호출하든 개발자 도구 스택의 중심에 자리 잡았습니다.

Anthropic의 또 다른 화제는 사람 쪽입니다. 2월 Andrej Karpathy의 Anthropic 합류는 그해 가장 회자된 AI 영입이었습니다. 장기 연구 임팩트와 별개로, 시니어 연구자 영입력에 미친 단기 효과는 즉각적이고 가시적이었습니다. Claude Code 자체의 일상 활용에 대해서는 Claude Code Skills 완벽 가이드가 4.6과 4.7 전환 이후에도 살아남은 패턴들을 다룹니다.

Google: Gemini 3.0, 3.5 Flash 그리고 가격 전쟁

Google의 H1 2026 전략은 최고 품질보다는 가격 대비 성능에서의 급진적 압박이었습니다. 12월 Gemini 2.5는 2.0 대비 조용한 품질 향상이었습니다. 2월 Gemini 3.0는 Google을 다시 프론티어 대화의 중심에 올려놓은 첫 릴리즈로, 강력한 멀티모달 성능과 실용적인 200만 토큰 컨텍스트 윈도우를 제공했습니다. 그러나 이 기간 헤드라인 릴리즈는 4월 Gemini 3.5 Flash였습니다. 2.0 Flash 대비 출력 비용을 약 60% 절감하면서 품질도 충분히 올려, 고볼륨 저관여 트래픽에는 명백한 기본값이 되었습니다.

Google 검색의 AI Overviews는 "좋은 아이디어인지 다투던 단계"에서 "10억 명 이상이 검색하는 방식의 영구 기본 요소"로 자리를 옮겼습니다. 이는 모델 자체를 넘어선 의미를 가집니다. AI가 생성한 답변이 사용자와 대부분의 오픈 웹 사이에 끼어 있는 레이어가 되었고, 2026년 콘텐츠 전략은 이 레이어를 먼저 겨냥해 작성되어야 합니다. Google의 개발자 표면 안에서는 5월 중순 I/O 2026 발표가 Gemini의 Workspace, Android, 그리고 새로운 Code Assist 에이전트 티어 통합을 미리 보여주었습니다. 개별로는 충격적이지 않지만, 누적 효과는 Google이 다시 기본 선택지로 돌아왔다는 것입니다.

가격 포인트는 무거운 자동화를 굴리는 팀에 가장 중요합니다. LLM을 월 100만 회 이상 호출하는 무언가를 만든다면, 트래픽 하위 70%에서는 셈이 Gemini 쪽으로 기울었습니다. 프론티어 모델은 마진 품질 차이가 비용을 정당화하는 상위 30%에만 남기십시오. 이 2티어 패턴이 진지한 LLM 제품의 기본 아키텍처가 되었고, 본문 후반 트렌드 섹션에서 다시 다룹니다.

Meta: Llama 4 시리즈와 오픈 전략의 규모화

Meta의 H1 2026은 Llama 4 패밀리였습니다. 12월부터 4월에 걸친 Llama 4 7B, 30B, 200B 릴리즈는 개별적으로는 프론티어를 흔들지 않았지만, 일관된 드롭으로서 오픈 웨이트를 세 가지 축에서 의미 있게 끌어올렸습니다. 더 긴 컨텍스트(256K까지 안정적), 30B 사이즈에서 폐쇄 모델과 동등한 도구 사용, 그리고 200B에서 많은 작업에 대해 Claude 4.5 Sonnet과 같은 대화에 들어갈 만큼의 품질 상승. Meta는 또한 이전 Llama 3.x 약관이 만족시키지 못했던 엔터프라이즈 법무팀을 더 많이 만족시키는 명확한 라이선스 체제를 열었습니다.

Meta가 하지 않은 일도 중요합니다. 500B 이상 규모에서 정면으로 프론티어 폐쇄 모델을 타겟팅한 Llama 4 릴리즈는 없었고, 2026년 초 공개 메시지에서 회사는 이를 무능이 아니라 의도된 전략적 선택으로 규정했습니다. "공통 사이즈에서 충분히 좋은" 오픈 웨이트와 자가 호스팅 비용 하락이 결합되면, 절대 프론티어를 추격하는 것보다 훨씬 큰 추론 워크로드 점유를 결국 끌어올 것이라는 베팅입니다. 그 베팅이 통할지는 6분기 질문이지 6개월 질문이 아니지만, 엔터프라이즈 자가 호스팅 배포의 초기 신호는 우호적입니다.

실무자 관점에서 행동 가능한 교훈은 Llama 4 30B가 알아야 할 사이즈라는 것입니다. 단일 H100 또는 Blackwell B200에서 프로덕션 속도로 편안히 동작하고, 도구 사용을 잘 처리하며, 벤더 락인 없이 호스팅 API급 경험을 줍니다. vLLM 0.7의 배칭 개선과 결합하면, 자가 호스팅 Llama 4 30B의 토큰당 비용은 순수 추론에서 Gemini 3.5 Flash와 경쟁할 수준이며, 스택을 직접 소유하는 전략적 가치는 별도입니다.

중국 빅3: DeepSeek, Qwen, Doubao

H1 2026의 중국 이야기는 외부 관찰자에게 가장 놀라운 것입니다. 2025년 11월 말 DeepSeek V3가 이미 강력했고, 2026년 2월 V4는 프론티어 폐쇄 모델과 진짜로 경쟁합니다. 671B MoE 구조는 토큰당 약 37B 파라미터를 활성화해 추론 비용을 합리적으로 유지하면서 작업 단위 기준 최상위로 품질을 밀어 올렸습니다. 오픈 웨이트, MIT 스타일 라이선스, 그리고 학습 레시피를 보기 드물게 상세히 문서화한 논문 덕분에 DeepSeek V4는 Q1 2026 가장 많이 배포된 단일 오픈 모델이 되었습니다.

알리바바의 2026년 3월 Qwen 3 패밀리는 코딩을 정조준했습니다. Qwen 3 Coder 32B 변형은 본인의 자체 벤치마크에서 현존 최강 소형 오픈 코더입니다. 범용용 Qwen 3 235B와 함께, 알리바바는 글로벌로 가장 많은 오픈 웨이트 추론을 서비스하는 주체가 되었다는 추정도 있습니다. ByteDance의 2026년 4월 Doubao 1.6은 중국 밖에서는 덜 알려져 있지만, 네이티브 크로스 모달 능력과 TikTok 통합을 가지고 출시되어 중국어권 시장에서 중요합니다. 이 모델들을 쓸지 말지는 데이터 처리 입장에 크게 좌우되지만, 존재하지 않는 척하는 것은 더 이상 방어 가능한 입장이 아닙니다. 전체 지형은 본 블로그의 DeepSeek vs Qwen vs Doubao 중국 LLM 비교 2026에서 다룹니다.

기술적 곁다리 하나만 짚자면, 최근 DeepSeek V4의 스티어링 벡터 연구가 작지만 의미 있는 해석 가능성의 문을 열었고, 외부 팀들이 코딩 평가에서 재현 가능한 행동 시프트를 이미 보였습니다. 이는 반기의 더 흥미로운 연구 이야기 중 하나이며, LLM 스티어링 벡터와 DeepSeek V4 글에서 실무적 함의를 다룹니다.

xAI: Grok 3에서 Grok 4로, 언더독 서사

xAI는 조용히 밈에서 벗어났습니다. 2025년 11월 말 Grok 3는 추론 벤치마크에서 처음으로 프론티어 권에 진입한 버전이었고, 2026년 4월 Grok 4는 남은 격차를 좁혔습니다. 여전히 주로 X와 독립 컨슈머 앱을 통해 배포되고, 그 배포 격차가 개발자의 기본 선택지가 되는 것을 막고 있습니다. 그러나 기술적 작업은 진짜입니다. 회사의 학습 클러스터 Colossus는 마이크로소프트-OpenAI급의 새로운 딜이 없으면 경쟁자가 매칭하기 어려운 수준으로 확장되었고, 그 하드웨어 베이스가 이제 모델에 반영되어 있습니다.

실무자 관점에서 Grok 4는 자체 검색 레이어를 만들지 않고도 실시간 웹 그라운딩이 필요할 때 의외로 강한 선택지이자, 백업 모델로 유효합니다. 가격은 중간 티어고 API는 안정화되었습니다. 제약은 주로 문화적인 것입니다. 많은 엔터프라이즈가 조달 이유로 여전히 xAI를 X와 너무 가까운 것으로 취급하고, 그 인식 변화는 기반 기술적 위치가 정당화하는 것보다 느립니다. 스택이 이미 프로바이더 사이를 로드 밸런싱하는 라우터를 호출한다면, Grok 4를 옵션으로 추가하는 데 몇 시간이면 되고, 다음 프로바이더 장애에 대한 측정 가능한 회복력을 얻습니다.

Mistral, Cohere 그리고 2티어 통합

2티어 프론티어 랩들은 H1 2026에 진짜 통합을 거쳤습니다. 1월 Mistral Large 3는 EU 거주 인프라와 US 랩들이 여전히 어려워하는 방식으로 규제를 만족시키는 라이선스 조건으로, Mistral의 가장 강한 유럽 프론티어 선택지로서의 입지를 재확인했습니다. Mistral의 더 작은 오픈 릴리즈(Codestral 2, Pixtral 2)는 개발자 인지도를 유지시켰습니다. Cohere의 Command R-Plus 2026 업데이트는 엔터프라이즈 RAG 워크플로에 두 배로 집중했고, 그라운디드 검색 작업에서 헤드라인 프론티어 모델을 계속 능가합니다.

2025년 말까지 대화에 있던 몇몇 작은 행위자들은 사실상 빠졌습니다. AI21의 Jamba 패밀리는 이제 매우 긴 컨텍스트만 필요한 니치 선택지입니다. Inflection은 프론티어 컨슈머 모델에서 완전히 피벗했습니다. Reka 외 몇몇은 기술적으로 흥미로운 작업을 계속 출시하지만 누구도 신경 쓰는 벤치마크 상위에서 더 이상 경쟁하지 않습니다. 시장은 글로벌로 진지한 LLM 프로바이더 약 7곳으로 통합되고 있습니다. OpenAI, Anthropic, Google, Meta(오픈), DeepSeek, Alibaba/Qwen, xAI. Mistral과 Cohere는 강한 지역 또는 버티컬 옵션으로 남습니다. 2024년 말 12개 이상에서 의미 있게 좁혀진 셈입니다.

로컬 LLM: Llama.cpp, Ollama, vLLM, MLX

로컬과 자가 호스팅 생태계는 빠르게 움직였습니다. Llama.cpp가 안정적인 Vulkan과 ROCm 경로를 추가하면서 1년 전까지 사실이었던 NVIDIA 전용 가정이 깨졌습니다. Strix Halo PC(AMD의 고메모리 APU 랩탑 플랫폼)에서 70B 모델을 실용 속도로 돌리는 것이 Q1 2026에 진짜 제품 카테고리가 되었습니다. Ollama가 주류 개발자 도구로 진입해 안정적인 모델 레지스트리, 예측 가능한 업데이트 채널, VS Code 및 JetBrains IDE와의 긴밀한 통합을 갖췄습니다. vLLM 0.7과 0.8은 페이지드 어텐션 v3와 투기적 디코딩 개선으로 프로덕션 배포의 추론 비용을 절감했습니다. Apple의 MLX 0.20 릴리즈는 M 시리즈 Mac을 30B에서 70B 파라미터 대역의 메모리 대비 가격 최강 로컬 추론 옵션으로 만들었고, M5 Max 기기는 오늘 Llama 4 30B와 Qwen 3 32B를 타협 없이 호스팅하기에 충분한 통합 메모리를 가지고 출하됩니다.

결합된 효과는 저관여 LLM 트래픽의 실질적 점유가 API를 떠나고 있다는 것입니다. 개인 노트 어시스턴트, IDE 자동 완성, 내부 문서 요약 등 데이터 민감도, 지연, 비용이 절대 프론티어보다 더 중요한 모든 작업이 로컬 추론으로 이주하는 중입니다. 하드웨어 전체 지형은 본 블로그의 로컬 LLM 하드웨어 선택 가이드 2026이 이 트렌드에 대해 분기마다 갱신됩니다.

AI 코딩 도구: Cursor, Claude Code, Codex, Aider, Cline

AI 코딩 도구는 반기의 가장 빨리 움직인 하위 카테고리였습니다. Cursor의 에이전트 모드가 11월과 12월에 걸쳐 멀티 파일 리팩토링을 안정적으로 처리하는 무언가로 성숙했고, 경쟁이 강해지는 와중에도 가격을 유지했습니다. Claude Code는 진지한 자율 코딩 워크플로의 지배적 CLI 도구가 되었습니다. 30분 이상 걸리는 작업을 굴린다면, Claude 4.7 Opus를 통한 Claude Code가 현재 기본값입니다. OpenAI Codex 서브 제품의 Codex Goals는 가장 강한 원샷 생성 표면입니다. 모델 출력을 보고 빠르게 조정하는 타이트한 반복 루프에는 이기기 어렵습니다.

Aider는 오픈소스 베이스라인으로 강력함을 유지했고, Cline은 IDE를 떠나지 않고 인에디터 경험을 원하는 개발자를 위한 VS Code 통합 에이전트 니치를 채웠습니다. 세 달 동안 섞어 써 본 솔직한 평가는 어떤 단일 도구도 모든 워크플로를 지배하지 않는다는 것입니다. 인에디터 페어 프로그래밍은 Cursor, 긴 자율 작업은 Claude Code, 원샷 생성은 Codex, 그리고 완전 검사가 가능한 도구가 필요할 때는 Aider를 오픈 폴백으로. 3개월 비교는 본 블로그의 Claude Code vs Codex 3개월 사용 후기 2026에서 로테이션 패턴을 상세히 다룹니다.

6개월 핵심 트렌드

개별 랩에서 한 발 물러서면, 네 가지 트렌드가 이 기간을 정의합니다.

에이전트 AI가 데모에서 프로덕션으로 이동했습니다. 반기 동안 모든 프론티어 모델 릴리즈의 정의적 기능은 더 길고 더 안정적인 자율 체인이었습니다. Claude 4.7 Opus로 2시간 자율 코딩 세션이 현실적이 되었고, GPT-5와 Gemini 3.0로 모델이 스스로 계획을 제안, 브라우징, 요약, 반복하는 멀티스텝 리서치가 동작합니다. 남은 실패 양상들은 진짜이지만 프로덕션 사용을 막지는 않습니다.

추론 모델이 별도 제품 카테고리에서 사라졌습니다. o 시리즈는 GPT-5의 적응형 사고 예산의 일부가 되었고, Claude의 확장 사고는 기본 켜짐이며, Gemini 3.0는 내부 체인을 투명하게 씁니다. 지난 1년 사용자를 혼란시킨 "사고 모델" 토글은 대부분 사라졌고, 그 단순화 자체가 품질 개선입니다.

멀티모달이 기본 사양이 되었습니다. 비전은 모든 프론티어 모델에서 동작하고, 오디오 입출력은 표준이며, 비디오 이해는 상위 3개 랩 전반에서 유능합니다. 차별화 요소는 더 이상 "멀티모달이 있나"가 아니라 "멀티모달 입력과 도구 사용을 얼마나 잘 엮느냐"입니다.

30B급에서 더 작은 게 더 좋다가 진짜입니다. 반기 동안 배포 빈도 기준 단일 최대 수혜는 30B 파라미터 대역입니다. Qwen 3 32B Coder, Llama 4 30B, 그리고 더 작은 DeepSeek 디스틸들이 모두 이 범위에 있고, 실제로 프론티어 IQ가 필요하지 않은 작업의 70~80%를 처리합니다.

벤치마크 변화: MMLU 포화, SWE-bench 폭증

벤치마크 지형도 실질적으로 바뀌었습니다. MMLU는 사실상 포화되었습니다. 모든 프론티어 모델이 88~91 사이에 있고, 벤치마크 자체의 노이즈 플로어가 그 범위에 있습니다. SWE-bench는 6개월 동안 상위 점수가 약 2배로 뛰었습니다. 2025년 11월 49%에서 2026년 5월 Verified 부분 90% 초과로, 이는 이 기간 가장 결정적인 단일 벤치마크 시프트입니다. GPQA 상위 점수는 60대 초반에서 70대 후반으로 이동했습니다. ARC-AGI v2는 여전히 현존 가장 어려운 공개 벤치마크이며, 이제 랩들이 가장 가시적으로 경쟁하는 곳입니다.

벤치마크를 읽는 엔지니어를 위한 교훈은 SWE-bench가 이제 "이 모델이 코딩에 좋은가"를 묻는 가장 유용한 단일 숫자이고, MMLU 성능과 실세계 효용성 사이의 격차가 그 어느 때보다 크다는 것입니다. 어떤 모델이 MMLU 90을 받고도 Claude 4.7이 단일 패스로 처리하는 프로덕션 디버깅에서 실패할 수 있습니다. 벤치마크 숫자는 항상 본인 워크로드에 대한 작업별 평가와 함께 봐야 합니다.

가격 변화 추이 (백만 토큰 기준)

가격 그림은 인쇄해 둘 가치가 있는 또 다른 매트릭스입니다. 숫자는 각 플랫폼의 가장 가까운 비교 가능한 티어에 대한 백만 토큰당 USD 기준 공시 가격의 근삿값입니다.

프론티어 폐쇄 (GPT-5 / Claude 4.7 Opus) 15 / 60~75 15 / 30~50 출력 -40~50%

가격 표에서 가장 중요한 한 가지 시사점은 저가 티어가 충분히 싸져서, 대부분 제품에 올바른 아키텍처가 이제 2모델이 되었다는 것입니다. Flash급이 호출의 60~80%를 처리하고, 어려운 호출에만 프론티어 모델을 예약합니다. 단일 프론티어 모델로 모든 것을 라우팅하는 스택이라면, 필요 비용의 3~5배를 내고 있을 가능성이 큽니다.

개발자가 내재화해야 할 5가지 시사점

6개월 그림에서 압축된 조언입니다.

  1. 코딩 도구를 최소 두 개 로테이션하십시오. Claude Code + Codex, 또는 Claude Code + Cursor가 가장 회복력 있는 패턴입니다. 실패 양상이 서로 다르고, 한 프로바이더가 장애일 때도 작업이 계속됩니다.
  2. 2티어 라우팅 레이어를 세우십시오. 트래픽의 60~80%를 Gemini 3.5 Flash 또는 Claude Haiku급으로 보내고, 프론티어 모델은 정말 필요한 호출에만 예약합니다. 비용 절감이 일주일이면 엔지니어링 비용을 회수합니다.
  3. 모델 하나는 로컬로 굴려보십시오. M 시리즈 Mac 또는 Blackwell 카드를 단 워크스테이션에서 30B 모델은 오프라인 작업, 민감 데이터를 커버하고, "이 작업이 API 없이 가능한가"의 기준점을 줍니다. 로컬 경험 없는 빌더는 점점 질문 방식으로 구분됩니다.
  4. MCP를 기본값으로 취급하십시오. Model Context Protocol은 새로운 "AI를 위한 REST"입니다. ChatGPT, Claude, Gemini에 각각 자체 통합을 만드는 것은 이제 낭비입니다. MCP 서버 하나가 셋 다와 연결됩니다.
  5. 벤치마크를 분기마다 재평가하십시오. 11월에 본인의 평가에서 이긴 모델이 오늘은 2티어일 가능성이 큽니다. 최소 분기마다 평가 스위트를 돌리고, 눈을 뜬 채로 새 기본값을 고르십시오.

2026년 하반기 전망

예측은 어렵고 대부분의 예언은 빠르게 빛이 바래지만, 지난 6개월의 궤적은 합리적 확신으로 세 가지를 부를 만합니다.

첫째, 에이전트 시스템이 파워 유저의 기본 UI가 됩니다. UI 진화는 챗봇이 2023년 거친 것과 동일합니다. 1분기 실험적, 4분기 주류. 연말까지 모든 주요 랩이 옵트인 베타가 아닌 기본 제품 일부로 에이전트 표면을 출시할 것을 예상합니다.

둘째, 모델 차별화 축이 순수 IQ에서 메모리, 도구 사용, 작업당 가격으로 이동합니다. 폐쇄 모델의 순수 벤치마크 경쟁은 평탄해지고 있고, 경쟁은 주변 스택으로 옮겨갑니다. 메모리를 먼저 제대로 푸는 랩(섬뜩하지 않고 유용하게 느껴지는 방식으로 세션을 넘어 기억하는)이 컨슈머 마인드셰어의 의미 있는 점유를 가져갈 가능성이 큽니다.

셋째, 온디바이스와 랩탑급 추론이 저관여 트래픽의 큰 점유를 조용히 가져갑니다. M 시리즈 Mac과 Strix Halo PC가 30~70B 모델을 실용 속도로 굴리면서, 컨슈머 사용의 상당 부분이 API에서 완전히 이탈합니다. 저가 티어 API 수익에는 나쁘고, 사용자 프라이버시에는 매우 좋습니다.

H2 2026 로드맵을 세운다면, 이 셋을 위해 만드십시오. "다음 모델을 기다리자" 함정을 피하십시오. 필요한 능력은 이미 오늘 굴릴 수 있는 스택에 들어 있습니다.

결론: 6개월의 구조적 시프트

11월부터 5월까지의 윈도우는 또 하나의 업그레이드 사이클이 아니었습니다. 에이전트 시스템이 진짜가 된 시점, 오픈 웨이트가 의미 있는 축에서 프론티어 격차를 좁힌 시점, 가격이 아키텍처 패턴을 바꿀 만큼 떨어진 시점, 그리고 MCP가 다음 2년의 도구가 세워질 표준 레이어로 락인된 시점이었습니다. 그중 어느 하나라도 평년 1년치 진보입니다. 네 가지가 동시에 일어났다는 사실이 이 기간을 구조적 시프트로 만듭니다.

빌더의 실용적 자세는 사이클 초기부터 변하지 않았습니다. 도구에 가까이 머물고, 최소 두 개를 로테이션하고, 분기마다 스택을 평가하고, 완벽한 기본값이 출현하기를 기다리려는 유혹에 저항하십시오. 프론티어는 그게 가능할 만큼 천천히 움직이지 않습니다. 본인의 경쟁 우위는 사용 가능한 조각들을 진짜 문제를 푸는 무언가로 얼마나 빨리 조합하느냐에 있지, 어느 랩 로고가 API 호출에 박혀 있는지에 있지 않습니다. 매트릭스를 읽고, 셈을 돌리고, 다음 것을 출하하십시오.
