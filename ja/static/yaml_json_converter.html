YAML と JSON、なぜ頻繁に変換するのか?

DevOps・SRE のワークフローでは、YAML と JSON は本質的に同じデータモデルを扱いますが用途が異なります。Kubernetes manifest、docker-compose.yml、GitHub Actions、Helm チャート、Ansible playbook は YAML で書かれる一方、API レスポンス、環境変数、CI 変数注入、jq パイプラインは JSON が標準です。本ツールは 2 つのフォーマットを瞬時に往復し、インデントや引用符の問題を即座に可視化します。

  • リアルタイム変換 · 入力と同時に変換し、エラー行を表示します(ブラウザ内処理のみで、サーバには送信されません)。
  • 入力形式の自動判定 · 先頭が { または [ なら JSON、それ以外は YAML として処理。
  • キーのアルファベット整列 · オブジェクトキーを並べ替え、diff やコードレビューが綺麗になります。
  • YAML 1.2 strict モード · yes/no/on/off を boolean に自動変換せず、k8s 向けに安全。
  • インデントオプション · 2 または 4 スペース選択可能(YAML 公式推奨は 2)。

よくある質問

変換データは外部サーバに送信されますか?

いいえ。すべての変換は js-yaml ライブラリでブラウザ内で完結します。ネットワーク通信が発生しないため、社内 manifest や機密 secret キーも安全に扱えます。

大きいファイルも処理できますか?

数 MB 程度までは即時処理されます。10MB を超えるファイルではブラウザが一時的に固まる場合があるため、リアルタイム変換をオフにして手動で変換することを推奨します。

YAML 1.1 と YAML 1.2 の違いは?

YAML 1.1 は yes/no/on/off/y/n を boolean と解釈し、sexagesimal 数値(60:00=3600)を許容します。YAML 1.2 では true/false のみが boolean として認識されます。Kubernetes クラスタで version: yes が true に変換されて障害となった事例が多く、strict モードの使用を推奨します。

マルチドキュメント YAML(--- で区切られた複数文書)に対応していますか?

はい。--- で区切られたマルチドキュメント YAML は JSON 配列に変換されます。逆に JSON の最上位が配列の場合、YAML 変換時に自動でマルチドキュメント形式になります。

YAML の anchor と alias もサポートしていますか?

はい。&ref で定義し *ref で参照する anchor/alias は正しく解釈され、JSON 変換時に自動で展開されます。

変換結果をファイルとしてダウンロードできますか?

はい。出力パネルの 💾 ボタンで .json または .yaml として保存できます。
