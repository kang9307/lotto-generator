Cut Codex and Claude Code Token Costs 99% with a Gemma4 Local Router

Using a small local model as a gatekeeper to dramatically reduce AI coding API costs — the real principle, conditions, and limits

2026-06-18 Dev & Infra

Introduction: Is a 99% Token Reduction Even Real?

In June 2026, a project called token-router surfaced on GeekNews. It uses a Gemma4 2B local model as a router to slash Claude Code and Codex token usage by up to 99%. The headline figure — a 41,711-token infrastructure log compressed to 131 tokens — reads like marketing copy at first glance.

But when you look at how it actually works, the number makes sense under the right conditions. The key insight is that the small model does not perform any analysis. It simply answers: which lines in this file are relevant? The actual reasoning stays with the cloud frontier model. Instead of sending the entire file, you send only the relevant excerpt. As of June 2026, this analysis covers why this approach emerged, how it works technically, and where it breaks down.

A disclosure upfront: figures cited here are based on public materials from the token-router project (GitHub: sleeplesshan/token-router) and published research on hybrid LLM routing. The 99% figure is a best-case outcome for specific scenarios, not a universal result. I will make this distinction explicit throughout.

1. Why AI Coding Costs Have Become a Problem

Claude Code and Codex route all inference through cloud APIs billed by the token. At June 2026 pricing, Claude Sonnet-class input runs approximately $3 per million tokens. A single query sounds cheap, but AI agents repeatedly processing large codebases or long log files accumulate costs quickly. Individual developers can see monthly bills in the tens of dollars; team-scale use pushes this into budget line-item territory.

1.1 The Structural Inefficiency

Most AI coding tasks do not require entire files. Analyzing a stack trace needs a few dozen lines around the failure point. Fixing a bug needs the relevant function and its immediate context. Yet AI tools frequently receive entire files as context. A 2,000-line file where only 30 lines matter still costs 2,000 lines worth of tokens. This structural inefficiency is the problem token-router targets.

1.2 Existing Solutions and Their Limits

Two common responses exist. First, replace the cloud API entirely with a local model (redirect Claude Code to an Ollama endpoint). The problem: smaller local models do not match Claude or GPT-4o quality for complex reasoning tasks, and coding quality suffers. Second, manually trim context before sending. The problem: this requires human intervention and does not scale to automated pipelines. Token-router proposes a third path: automated lossless context compression without sacrificing quality.

2. How token-router Works — A Three-Stage Pipeline

The design principle is clear: use the local model as an indexer, not an analyst. The cloud model performs all reasoning but receives only pre-filtered, essential text.

2.1 The Three Stages

StageEngineRoleOutput
1Local Ollama (Gemma4 2B)Scan file for relevant line rangesJSON coordinates (start line ~ end line)
2Python router scriptExtract exact lines from original fileUnmodified original text excerpt
3Cloud LLM (Claude/Codex)Reason over the compressed contextHigh-quality analysis or fix

In stage 1, Gemma4 2B reads the full file and returns a JSON specifying which line ranges are relevant to the query. This is not complex reasoning — it is a location identification task, which a 2B model can handle adequately. In stage 2, a Python script takes those coordinates and extracts the lines verbatim from the original file. In stage 3, Claude or Codex receives only this compressed excerpt rather than the full file.

2.2 What "Lossless" Actually Means

The "lossless" claim requires careful reading. This is not lossless compression in the audio or image sense. It means the extraction step does not modify or summarize the text — it cuts the original verbatim. Stack frame formatting, indentation, config key casing, and variable names are all preserved exactly.

What is not guaranteed is routing accuracy. If the local model identifies the wrong line range, the cloud model receives incomplete context and may produce incorrect analysis. Lossless describes the extraction step, not the correctness of the routing decision. This distinction is essential to understanding both the value and the risk of this tool.

2.3 Three Routing Modes

Token-router provides three modes tuned to different scenarios. error_log is optimized for deployment logs, stack traces, and CI output. heavy_code targets long source files and bug investigations. agent_context handles lengthy agent instruction documents or reference files. Each mode applies a different prompting strategy to the local model to improve line range extraction accuracy.

3. The 99% Reduction — Numbers, Conditions, and Caveats

The project's reported figures are specific. But the conditions that produce them matter just as much.

3.1 Reported Numbers

  • 2,000-line infrastructure log: 41,711 tokens → 131 tokens (99.69% reduction)
  • 2,155-line source file: 7,520 tokens → 70 tokens (99.06% reduction)

The log case shows higher reduction because log files contain repetitive patterns across thousands of lines with the actual error concentrated in a few dozen. Source code is more uniformly relevant, so the relevant fraction is larger.

3.2 What Drives the Savings

The reduction formula is simple: savings = 1 − (extracted lines / total lines). The larger the file and the smaller the relevant section, the higher the savings. Conversely, if the entire file is relevant or the file is small, savings are minimal. The 99% figure is a best-case scenario. Realistic average savings across a mixed workload will be substantially lower. Tasks requiring whole-file context — architecture-level refactoring, cross-file dependency analysis — gain nothing from this tool and may actively suffer from incomplete context.

3.3 Cost Impact in Real Terms

At $3 per million input tokens, sending 41,711 tokens costs roughly $0.125 per query. With token-router reducing it to 131 tokens, that drops to about $0.0004. Individually trivial. At scale — an AI agent automatically analyzing CI logs dozens of times daily — monthly savings compound meaningfully. Teams integrating AI into CI/CD log analysis pipelines are the clearest beneficiaries.

4. Hybrid Routing in Context — Is This a Known Pattern?

Token-router is not entirely novel. Hybrid LLM routing is an active research and engineering area. Understanding how it fits within the broader landscape clarifies both its value and its positioning.

4.1 The General Routing Principle

Hybrid cloud-edge LLM architectures rest on a core observation: 70–80% of production queries do not need a frontier model. A lightweight classifier routes each request to the cheapest tier that handles it adequately. Published research reports 60–80% cost reductions from well-implemented routing layers.

Token-router differs in a critical way: it does not route requests to different models. It routes the content sent to the same model. This is context compression routing rather than model selection routing. Existing model routers reduce the number of frontier model calls; token-router reduces the token count of each call to the frontier model. Both are valid strategies, and they compose.

4.2 Comparable Tools in 2026

Similar approaches appeared around the same period. 9Router applies lossless compression to git diffs, grep outputs, directory listings, and log dumps, targeting 20–40% token reduction. The ypollak2/llm-router project uses a free-first fallback chain targeting 70–85% cost reduction through model routing. OpenRouter's free model tier enables gatekeeper patterns using Llama, Gemma, and Qwen models at zero token cost. Token-router's differentiator is its narrow focus on large-file scenarios where 99% reduction is achievable, versus the more modest 20–40% compression typical of general-purpose tools.

4.3 Why Gemma4 2B?

Gemma4 was released by Google DeepMind on April 2, 2026, under Apache 2.0 license. The E2B (2B effective parameter) variant runs locally via Ollama and handles 4K–8K token contexts sufficient for most files. For the router task — returning a JSON line range — 2B models are fast and cheap. The tradeoff: real-world users reported JSON format errors with Gemma4 2B, particularly on complex or irregular files. The project author suggested Qwen 2.5 Coder 7B as a more reliable alternative. For production use, testing model accuracy on representative file samples before committing is essential.

5. Setup and Workflow

5.1 Requirements

Python 3.10+ and a running Ollama instance are required. Pull the quantized model with ollama pull gemma4:e2b-it-q4_K_M. The Q4_K_M quantization significantly reduces memory requirements, making this feasible on most developer machines with 8GB+ RAM (16GB recommended for comfortable operation).

5.2 Running the Router

OLLAMA_NUM_CTX=4096 OLLAMA_KEEP_ALIVE=0s \
python3 scripts/router.py error_log /path/to/logfile --query "error cause"

OLLAMA_KEEP_ALIVE=0s unloads the model immediately after routing completes, reclaiming memory. OLLAMA_NUM_CTX=4096 caps the local model's context pressure. For Codex integration, copying the tool directory to ~/.codex/skills/ allows the Codex agent to invoke the router directly.

5.3 The Iterative Negotiation Pattern

An important operational detail: when the local model selects too narrow a line range, the cloud model signals it needs more context. The workflow then re-runs the router with an expanded range. This iterative negotiation pattern can in principle be automated, but current implementations require some manual oversight. How automated this becomes depends on the AI agent tool and integration depth.

6. Honest Limitations

6.1 Routing Errors Are the Core Risk

The biggest risk is stage 1 misidentification. Unstructured logs, deeply nested code, multilingual files, and edge-case formatting can cause the local model to return incorrect line ranges. When that happens, the cloud model reasons from incomplete context and produces incorrect results. For production-critical incident analysis or security-sensitive code changes, validate router outputs before trusting them.

6.2 Already-Loaded Context Cannot Be Recovered

If an agent tool has already auto-loaded an entire file as context, token-router cannot remove those tokens retroactively. The tool reduces future input size, not past spending. Effective use requires disabling or limiting agent auto-loading of large files as a prerequisite.

6.3 Configuration Overhead

Mode selection, context size tuning, and output line limits require adjustment per workflow. Incorrect configuration either reduces savings or hurts accuracy. For small projects where token costs are modest, this configuration burden may exceed the financial benefit.

6.4 Counterproductive for Full-Context Tasks

Architecture-level refactoring, cross-file dependency tracing, and holistic code review require full-file context. Forcing token reduction on these tasks degrades AI output quality. The tool's scope must be applied selectively based on task type.

7. What This Means for Cost-Sensitive Developers

7.1 The Cost Problem Is Real

As of June 2026, AI coding tool costs have moved from negligible to a genuine budget consideration for teams running agents continuously on large codebases. Token-router represents one of the more aggressive responses to this pressure, targeting the inefficiency of sending entire large files when only small sections are needed.

7.2 A Different Role for Small Models

The most conceptually interesting aspect of this approach is repositioning small models as precise indexers rather than weak reasoners. A 2B model cannot replace Claude for complex coding tasks. But it can locate the relevant lines in a 2,000-line log file — and that is all it needs to do to enable dramatic cost reduction. Proper role separation turns a small model's limitations into irrelevance for the task at hand.

7.3 Who Should Try This

The tool is worth evaluating if: you repeatedly send large files (thousands of lines) to AI tools; your machine has 16GB+ RAM for running Ollama; you are comfortable adjusting Python script configurations; and you can invest time to validate routing accuracy on your specific file types. If all four conditions hold, monthly token cost reduction will be meaningful. If any are missing, the overhead likely exceeds the benefit.

8. Conclusion — A Conditionally Powerful Tool

The token-router approach is smart in its role separation. Rather than claiming small models can reason like Claude, it assigns them the narrower task of locating relevant lines — a task they can handle adequately — and preserves all reasoning quality by keeping the frontier model in the loop. This makes the 99% reduction figure honest rather than misleading, within its defined conditions.

The honest framing: 99% is a best case for large-file, small-relevant-section scenarios. Average savings across mixed workloads will be lower. Routing errors introduce a new quality risk that must be managed. Full-context tasks are out of scope. And configuration complexity is real.

As of June 2026, three paths exist for reducing AI coding costs: replace cloud models with local ones (quality trade-off), reduce tokens sent to cloud models (token-router's approach), or use free/cheap routing layers as gatekeepers. These strategies compose. Token-router occupies the second path most aggressively. Before adopting it, analyze your actual file size distribution and query repeat frequency to verify that the savings are real for your specific workload.
