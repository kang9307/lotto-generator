Introduction - the replacement string is a different syntax from the pattern

The portability of regular expression patterns is discussed often, but the replacement string is a separate syntax from the pattern, and its special notation differs from tool to tool. The same & means the entire matched text in sed and is a plain ampersand in Python, JS and PowerShell. The same $1 is capture group 1 in perl, JS and PowerShell and is the literal text $1 in sed and Python.

Trouble arises in two places. One is carrying a notation over from another tool: the result may be silently wrong with no error, or the command may stop with one. The other is inserting a variable value straight into the replacement position, where a $, \ or & inside the value is read as special notation and the value is altered. The first problem is settled by one notation table, and the second is closed by giving the replacement as a function rather than a string.

  • The targets are three shell tools, sed (GNU sed 4.9), awk (GNU Awk 5.0.0) and perl 5.38.2, plus re.sub in Python 3.13.3.
  • The remaining two are String.replace in node v22.16.0 and -replace in Windows PowerShell 5.1.
  • Every input is a short fixed string and the intent is the same: reuse the whole match, swap groups, or insert a literal value.
  • Pattern-side dialects belong to the regex portability article and the sed ampersand and delimiter collision belongs to the sed article, so the focus here is cross-tool comparison and on how to insert values.
  • Output is pasted unchanged, error messages included; lines printed through Python repr and JS JSON include the quotation marks in the output.

Whole-match references - &, $& and \g<0>

The notation for reusing the entire matched text inside the replacement differs by tool. Below, the same intent, turning Tom into [Tom], is given to three shell tools.

                    echo 'Tom' | awk '{ sub(/Tom/, "[&]"); print }'
                    echo 'Tom' | awk '{ print gensub(/Tom/, "[\\0]", "g") }'
                    echo 'Tom' | perl -pe 's/Tom/[$&]/'
                    echo 'Tom' | perl -pe 's/Tom/[&]/'

sed with & and \0, awk with & in sub and \\0 in gensub, and perl with $& all referred to the whole match. As the last line shows, & in perl is a literal ampersand. Using & in perl with the sed expectation still performs the substitution, but the whole match does not get inserted.

import re

                    print(repr(re.sub('Tom', r'[\g<0>]', 'Tom')))

In Python, & is literal and the whole match is \g<0>. \0 did not give the whole match; it became a NUL character (\x00). The Python documentation says backslash escapes in the repl string are processed, and names \g<0> as the reference that substitutes the entire matched substring.

In JS and PowerShell the whole match is $&. The MDN table describes $& as "Inserts the matched substring." and Microsoft Learn lists $& as a substitution that includes a copy of the entire match. The difference shows up at $0. JS does not treat $0 as special and returned it as literal text, while PowerShell 5.1 read $0 as the whole match.

  • In the output the tools where & means the whole match were sed and awk.
  • $& has the same meaning in perl, JS and PowerShell.
  • \0 is the whole match in sed and a NUL character in Python.
  • $0 is the whole match in PowerShell and literal text in JS.

Group references - the \1 family and the $1 family

The notation for referring to a parenthesized group splits into two families. sed, awk (gensub) and Python use the backslash family (\1), while perl, JS and PowerShell use the dollar family ($1). What happens when the two notations are swapped is shown with a substitution that turns ab into ba.

echo 'ab' | sed -E 's/(a)(b)/\2\1/'
                    echo 'ab' | sed -E 's/(a)(b)/$2$1/'
                    echo 'ab' | awk '{ print gensub(/(a)(b)/, "\\2\\1", "g") }'
                    echo 'ab' | awk '{ sub(/(a)(b)/, "\\2\\1"); print }'
                    echo 'ab' | perl -pe 's/(a)(b)/$2$1/'
                    echo 'ab' | perl -pe 's/(a)(b)/\2\1/'
ba
                    $2$1
                    ba
                    \2\1
                    ba
                    ba

On the first line sed \2\1 produced ba, and on the second line $2$1 was printed as literal text rather than as groups. In awk only gensub refers to groups; putting the same \\2\\1 into sub printed \2\1 unchanged. In perl $2$1 gives ba, and \2\1 also became ba.

import re
                    print(repr(re.sub(r'(a)(b)', r'\2\1', 'ab')))
                    print(repr(re.sub(r'(a)(b)', '$2$1', 'ab')))
                    print(repr(re.sub(r'(a)(b)', r'\g<2>\g<1>', 'ab')))
'ba'
                    '$2$1'
                    'ba'

In Python, \2\1 and \g<2>\g<1> give the same result and $2$1 stays literal. In the dollar-family tools it is the other way round.

console.log(JSON.stringify('ab'.replace(/(a)(b)/, '$2$1')));
                    console.log(JSON.stringify('ab'.replace(/(a)(b)/, '\\2\\1')));
"ba"
                    "\\2\\1"
'ab' -replace '(a)(b)','$2$1'
                    'ab' -replace '(a)(b)','\2\1'
ba
                    \2\1

In JS and PowerShell, $2$1 is the group reference and \2\1 was printed literally. The "\\2\\1" in the JS output is JSON escaping; the actual characters are \2\1. Carrying a backslash-family notation into a dollar-family tool yields a literal with no error, so the wrong result passes silently.

When a digit follows the group number

Turning a into a0, which appends a literal 0 after the value of group 1, separates the tools by whether a digit after the number is read as part of the number.

echo 'a' | sed -E 's/(a)/\10/'
                    echo 'a' | awk '{ print gensub(/(a)/, "\\10", "g") }'
                    echo 'a' | perl -pe 's/(a)/${1}0/'
                    echo 'a' | perl -pe 's/(a)/[$10]/'
a0
                    a0
                    a0
                    []

sed and awk read \10 as group 1 followed by 0. In perl, ${1}0 gives a0, while $10 produced an empty string between the brackets.

import re
                    try:
                        print(repr(re.sub(r'(a)', r'\10', 'a')))
                    except re.error as e:
                        print(type(e).__name__ + ': ' + str(e))
                    print(repr(re.sub(r'(a)', r'\g<1>0', 'a')))
                    print(repr(re.sub(r'(?P<x>a)', r'\g<x>0', 'a')))

The Python documentation says \g<2> is equivalent to \2 but is not ambiguous in \g<2>0, and that \20 is interpreted as a reference to group 20. The PatternError in the output is the message that group 10 does not exist. Stopping with an error is better than being silently wrong.

console.log(JSON.stringify('a'.replace(/(a)/, '$10')));
                    console.log(JSON.stringify('a'.replace(/(?<x>a)/, '$<x>0')));
                    console.log(JSON.stringify('a'.replace(/(a)/, '$2')));
"a0"
                    "a0"

                    'a' -replace '(a)','${1}0'

With a one-group pattern, JS read $10 as group 1 followed by a 0 and produced a0. MDN describes $n as the nth capture group where n is a positive integer less than 100, and says that if the group is not present the pattern is replaced as a literal; the $2 on the last line is that literal. PowerShell left $10 as literal text. Microsoft Learn says all digits after $ belong to the number, that a number without a matching group is a literal, and offers the ${1}1 form as the alternative.

  • In JS, the named-group form $<x>0 produced a0, while $<x>0 in PowerShell stayed literal.
  • The same $10 gives a0 in JS, literal $10 in PowerShell and an empty string in perl.
  • $2 with no such group is a literal in JS, and \1 with no such group is an error in Python.

Where a value containing a literal $ breaks

Code that inserts a variable value straight into the replacement string breaks when the value contains special notation. A price string such as $5.00 is the classic case. With a pattern that has no groups, $5 is literal and the result happens to be right, but with five groups the result changes. Below, six values go through JS, and the last line puts $5.00 into a five-group pattern.

for (const v of ['A&B', '$5.00', 'C:\\dir', 'US$', '$$', '$&$&']) {
                      console.log(v.padEnd(8) + JSON.stringify('x=OLD'.replace('OLD', v)));
                    }
                    console.log(JSON.stringify('abcde'.replace(/(a)(b)(c)(d)(e)/, '$5.00')));
A&B     "x=A&B"
                    $5.00   "x=$5.00"
                    C:\dir  "x=C:\\dir"
                    US$     "x=US$"
                    $$      "x=$"
                    $&$&    "x=OLDOLD"
                    "e.00"

In the first lines, $5.00 and US$ stayed intact, $$ shrank to a single $, and $&$& became OLDOLD. These are values read as replacement notation. The last line shows $5.00 becoming e.00 under a five-group pattern. The MDN table describes $$ as inserting a "$".

foreach ($v in 'A&B','$5.00','C:\dir','US$','$$','$&$&') {
                      $v.PadRight(8) + ('x=OLD' -replace 'OLD',$v)

PowerShell 5.1 gives the same results. Writing $$5.00 inserts the literal $5.00. Microsoft Learn describes $$ as the substitution that includes a single literal "$".

When perl's source says s/OLD/$5.00/, $5.00 becomes .00 even though the pattern has no groups. That is perl interpolating $5 in the source as a variable, not a value being read as replacement notation. The output appears in the next section.

  • When the value contains $ and the pattern has groups, JS and PowerShell replace part of the value with a group.
  • $$ is replacement notation rather than a value, so it shrinks to one $.
  • A value shaped like notation, such as $&$&, expands to the whole match.
  • Getting lucky with a groupless pattern stops working when the pattern changes.

In sed, the & in A&B expanded to OLD and gave AOLDB, and in C:\dir the backslash disappeared, giving C:dir. That is sed reading the replacement written in the script.   • JS and PowerShell leave backslashes alone, so the path goes in as it is.

Passing the value as a function, not a string

The way to stop a value from being interpreted as a replacement string is to give the replacement as the return value of a function rather than as a string. The test value contains every kind of notation: C:\dir\1 & $1 \n. Python comes first.

import re
                    v = r'C:\dir\1 & $1 \n'
                    print('v = ' + v)
                    try:
                        print(re.sub('OLD', v, 'x=OLD'))
                    except re.error as e:
                        print(type(e).__name__ + ': ' + str(e))
                    print(re.sub('OLD', lambda m: v, 'x=OLD'))
                    print(re.sub('OLD', v.replace('\\', '\\\\'), 'x=OLD'))
                    print('x=OLD'.replace('OLD', v))
                    print(re.sub(r'(a)(b)', lambda m: m[2] + m[1], 'ab'))
v = C:\dir\1 & $1 \n
                    PatternError: bad escape \d at position 2
                    x=C:\dir\1 & $1 \n
                    x=C:\dir\1 & $1 \n
                    x=C:\dir\1 & $1 \n
                    ba

Passed as a string it raised PatternError, and passed as lambda m: v the value went in unchanged. Doubling the backslashes and str.replace produced the same value. The Python documentation says that when repl is a function it is called for every non-overlapping occurrence and returns the replacement string. The last line takes the groups inside the function and swaps them.

const v = 'C:\\dir $1 $& $$ \\1';
                    console.log('v = ' + v);
                    console.log('x=OLD'.replace('OLD', v));
                    console.log('x=OLD'.replace('OLD', () => v));
                    console.log('x=OLD'.replace('OLD', v.replaceAll('$', '$$$$')));
                    console.log('x=OLD'.split('OLD').join(v));
                    console.log('ab'.replace(/(a)(b)/, (m, p1, p2) => p2 + p1));

                    x=C:\dir $1 OLD $ \1

                    x=C:\dir $1 $& $$ \1

                    ba

In JS the string replacement interpreted $1, $& and $$. Passed as a function, all of them stayed intact. MDN says: "The above-mentioned special replacement patterns do not apply for strings returned from the replacer function." Doubling each $ into $$$$ and split/join also inserted the value unchanged.

                    'v = ' + $v

In PowerShell 5.1 the replacement of -replace is a string. Passing a MatchEvaluator to [regex]::Replace, or using the non-regex .Replace() method, inserted the value unchanged. As the last line shows, giving -replace a script block did not call it as a function in 5.1; the text of the block went in, with its surrounding spaces.

  • Python with lambda m: v and JS with () => v return the value with no interpretation.
  • PowerShell uses a MatchEvaluator or the .Replace() string method.
  • When no regular expression is needed, str.replace, split/join and .Replace() are the simplest.
  • If -replace must take the value directly, replacing $ with $$ works, and a script block is not a function in 5.1.

Layers outside the tool - shell quoting and awk -v

Before the value reaches the tool, quoting layers in the shell and in the tool itself change it once more. The awk -v option is an example. Below, tr turns a TAB into > so that it is visible.

echo 'x=OLD' | awk -v v='a\tb' '{ sub(/OLD/, v); print }' | tr '\t' '>'
                    V='a\tb' awk 'BEGIN { print ENVIRON["V"] }'
x=a>b
                    a\tb

A value passed with -v v='a\tb' had its escape processed by awk and became a TAB (x=a>b). A value passed through an environment variable and read with ENVIRON stayed as the literal a\tb. The output shows this difference directly.

'[' + ('ab' -replace '(a)(b)','$2$1') + ']'
                    '[' + ('ab' -replace '(a)(b)',"$2$1") + ']'
[ba]
                    []

In PowerShell the kind of quotation mark creates a layer. The same replacement string in single quotes becomes group references, while in double quotes PowerShell expands $2 and $1 as variables first and the result was an empty string. The second output line, [], is that result.

Inserting values safely - a per-tool choice table

For sed, the &, backslashes and delimiter in the value are escaped before insertion. awk joins the pieces with index and substr or receives the value through ENVIRON, and perl reads the value from an environment variable. The value is A&B\C/D.

V='A&B\C/D'
                    ESC=$(printf '%s' "$V" | sed 's/[&\/\\]/\\&/g')
                    echo "ESC=$ESC"
                    echo 'x=OLD' | sed "s/OLD/$ESC/"
                    echo 'x=OLD' | V="$V" awk '{ i = index($0, "OLD"); print substr($0, 1, i-1) ENVIRON["V"] substr($0, i+3) }'
                    echo 'x=OLD' | V="$V" awk '{ sub(/OLD/, ENVIRON["V"]); print }'
                    echo 'x=OLD' | V="$V" perl -pe 's/OLD/$ENV{V}/'
ESC=A\&B\\C\/D
                    x=A&B\C/D
                    x=A&B\C/D
                    x=AOLDB\C/D
                    x=A&B\C/D

The sed conversion builds A\&B\\C\/D, and the substitution result is the value itself. In awk the index and substr approach returned the value as it was, while putting the same value into sub expanded the & into OLD and gave AOLDB\C/D. In perl the value read through $ENV{V} went in unchanged. The choice per tool is in the table.

  • sed escapes the value before inserting it, and sometimes the delimiter has to be changed to a character that is not in the value.
  • awk should not put the value into the replacement of sub; join the pieces with index and substr.
  • Python, JS and PowerShell avoid interpretation altogether with a function or a string method.
  • perl reads the value from a variable or an environment variable and keeps $ and @ out of the replacement literal.
