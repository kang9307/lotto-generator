更新设置界面的整体图景 — 能决定什么，不能决定什么

Windows 11的更新设置从开始 > 设置 > Windows 更新进入。Microsoft的Windows更新FAQ说明，为了让设备保持安全和最新，Windows会自动下载并安装更新。同一文档还指出，更新无法完全停止，只能暂时暂停。这句话是读懂整个界面的基准。界面上几乎所有项目都不是决定「收不收更新」的开关，而是决定「何时、以什么方式、最多能推迟多久」的调节钮。

按作用划分，这些项目属于三类。

  • 决定时间点的项目：暂停更新、活动时间、安排重启。它们不阻止安装，只调整安装和重启发生的时刻。
  • 决定接收范围的项目：一有更新可用就立即获取、可选更新。涉及在定期安全更新之外还接收什么。
  • 决定接收方式的项目：传递优化。决定同一个更新从哪里下载、向外发送多少。

此外还有两个事后工具：更新历史记录(查看已安装的更新并卸载其中一部分)和疑难解答(安装失败时使用)。下表把文档给出的位置、项目的作用和文档写明的限制并排列出。各项目的条件与例外在后面的章节中展开。

功能更新、质量更新与可选更新 — 区别在哪里

更新FAQ把更新分为两类。功能更新每年发布一次，包含新功能。质量更新更频繁地提供，包含安全修复和错误修复。在设置界面中，暂停、活动时间和安排重启对两类更新都适用。FAQ只把功能更新描述为每年发布一次、包含新功能的更新，把质量更新描述为更频繁提供的安全修复和错误修复，并没有比较两者的大小或风险。

第三类可选更新被描述为在每月累积更新之外提供新功能和非安全变更的更新。Microsoft Learn的「配置Windows更新客户端策略」(面向IT管理员的文档)指出，对于使用Windows更新客户端策略接收更新的设备，可选更新的安装默认不启用。个人电脑是否适用同样的默认值，该文档没有说明。这一类在个人电脑的哪个界面、以何种方式显示，在已阅读的文档中没有，因此该点单独列在文末的「未能确认的内容」中。

暂停更新 — 最长35天意味着什么

暂停在开始 > 设置 > Windows 更新的暂停更新控件中通过选择日期完成。文档写明，自当前日期起最多可暂停更新35天，日历中只能选择受支持的暂停期限之内的日期。

其行为规则有四条。

  • 暂停期间：可能需要重启的更新，在暂停结束之前不会被下载或安装。文档还写明，暂停时正在进行的更新会被取消。
  • 暂停结束后：设备会检查可用的最新更新，然后下载并安装。也就是说，推迟期间积压的更新会一次性到来。
  • 延长：在已经暂停的状态下选择新的结束日期，则最多从今天起35天。此前暂停的时间不会累加。FAQ写明，达到暂停上限后，要再次暂停更新，必须先安装最新更新。
  • 什么都不做：暂停到期时更新会自动恢复。文档说明，这有助于让设备保持安全和稳定。

举一个计算示例。2026年10月5日选择最远的可选日期，结束日期就是35天后的11月9日(10月有31天，10月5日加35天为11月9日，计算值)。如果在暂停仍在进行的10月20日延长，新的结束日期必须在从今天起35天之内，所以最远的日期是11月24日(计算值)，之前的期限不会累加。相反，在11月9日达到上限之后，再次暂停之前必须先安装最新更新。面向IT管理员的Learn文档(配置Windows更新客户端策略)里也有类似的段落：「35天过后，暂停设置会自动到期 … 此次扫描之后，可以再次暂停该设备的更新」。但这是通过策略配置暂停时的说明，设置界面中的暂停控件是否同样运作，无从得知。也没有依据把文档理解为旨在通过反复暂停来无限期推迟更新。暂停文档还写明，可以随时手动恢复更新，恢复后设备会检查更新，并下载安装最新可用的更新。

暂停文档自己点出了适用的场合：如果你正在旅行、参加会议、休假，或想避免在重要的演示或截止日期期间被打扰，需要更多时间，就可以暂停更新。结束日期由用户自己选择，把它记在日历上，就能预见暂停结束后的检查、下载和安装。

活动时间 — 自动与手动，默认值与最大长度

活动时间是预期设备正在使用的时间段。Learn文档说明，更新在活动时间之外安装后，设备会自动重启。因此活动时间是把重启时间往后推的机制，而不是阻止安装的机制。

在Windows 11中，位置是设置 > Windows 更新 > 高级选项 > 活动时间。调整活动时间时在自动和手动之间选择。自动由Windows根据使用模式调整，手动则自己设定开始和结束时刻。

  • 默认值：Learn文档写明，电脑的默认活动时间是上午8点到下午5点，共9小时(计算值)。
  • 最大长度：同一文档写明，最大活动时间范围从开始时刻起计算，并指出：「Windows 10版本1607和Windows Server 2016的最大活动时间长度为12。之后的版本支持最长18小时的活动时间」。也就是说1607为12小时，从下一个版本起才是18小时。按18小时计算，若开始时间设为上午8点，理论上可以设到次日凌晨2点(计算值)。
  • 该数值的局限：这18小时出现在面向IT管理员的文档中，是策略设置语境下的数值。个人电脑的设置界面中，滑块最大值是否同样显示为这个数，仅凭此文档无法得知。

Learn文档把面向管理员的最大活动时间范围设置的目的描述为：在为安装更新留足时间的同时，让用户一侧在活动时间内保留一部分决定的灵活性。该文档并没有给出个人设置的推荐长度。面向个人用户的说明在FAQ中：可以设置活动时间，使设备只在不使用时才为更新自动重启。

安排重启与通知 — 选择何时发生重启

更新安装完成后，有些更新需要重启才会生效。FAQ说明，Windows会在设备未被使用时尝试重启；做不到时，会显示消息，提示在方便的时间安排重启。同一FAQ还给出了随时自行安排的方法：选择开始 > 设置 > Windows 更新，选择安排重启，再选择方便的时间。如果说活动时间是「这段时间不要重启」的一侧，那么安排重启就是「在这个时刻重启」的一侧。

Learn文档中关于重启的叙述里，对个人用户有意义的部分如下。

  • Windows在安装更新后，会尝试在活动时间之外自动重启。
  • 如果过了默认的7天期限重启仍未成功，会向用户显示需要重启的通知。「约定的重启」一节对同一内容的表述是：「默认的7天期限结束后，Windows会转为用户安排的重启」。
  • 按策略「在计划的自动更新安装中有已登录用户时不自动重启」的说明，如果用户通过更新通知安排了重启，那么在用户指定的时间，即使用户已登录，设备也会重启。

第二项的7天带有限定。同一文档中，更改这一期限的策略(指定在为安装更新而自动重启之前的期限)以及调整约定重启转换期限的策略，都被标注为旧版策略，不适用于Windows 11。因此Windows 11的设置界面是否使用同样的7天，文档没有直接说明。文档能确认的是默认的7天，以及此后转为用户安排的重启。

第三项的适用范围很窄。这句话出现在一项策略的说明中，文档写明该策略只有在自动更新配置设为选项4 - 自动下载并计划安装时才适用。因此不能把它当作所有个人电脑上都成立的一般行为。同一文档还指出，这项策略并不完全按说明运作。

「一有更新可用就立即获取」 — 打开后有什么变化

Microsoft在文档中说明，非安全更新通过受控功能推出(CFR)逐步分发。在开始 > 设置 > Windows 更新中打开一有更新可用就立即获取最新更新开关，可以加快这一过程。

  • 与安全更新的关系：无论开关处于什么状态，定期安全更新都会继续提供。开关并不决定是否接收安全补丁。
  • 活动时间：文档写明，这一设置会尊重活动使用时间。
  • 重启：需要重启的部分更新，据说会与下一个累积更新(LCU)合并，从而减少重启次数。
  • 关闭：可以随时停用。

文档说明的差别在于：非安全更新是等待逐步推送(CFR)的顺序，还是通过开关把这一过程提前。开关与暂停同时使用时哪一方优先，已阅读的文档中没有说明。

传递优化 — 从其他设备下载与向外发送的量

传递优化是用于下载Windows更新、Microsoft Store应用和其他Microsoft产品的云端系统。也有人把它称作「传输优化」，但韩语版文档中的界面名称对应的就是传递优化。位置是开始 > 设置 > Windows 更新 > 高级选项 > 传递优化。

下载来源在两个选项中选择。

  • 仅本地网络上的设备：与连接到同一路由器的其他电脑互相交换更新片段。
  • 互联网和本地网络上的设备：互联网上的其他设备也可以成为来源。

带宽有两种限制方式。一种是绝对带宽(以Mbps为单位)，另一种是实测带宽的百分比。文档写明：「带宽限制仅适用于自动更新下载的传递优化」，并补充说，如果在设置中更新Windows或下载应用等手动发起下载，则所设的带宽限制不适用。每月上传限额是上传选项中另行选择的设置，范围在1GB至500GB之间，上面这句话是否也涉及该限额的适用范围，文档中没有说明。

本节需要判断的是上传一侧。连接按流量计费线路或手机热点的电脑，可以通过调低每月上传限额，或把来源限定为本地网络，把设置调整到减少非预期流量使用的方向，这是出于控制流量的目的，而不是文档给出的固定建议。不过，具体哪种组合实际能节省多少MB，文档没有数值，无法说明。

更新历史记录与卸载 — 回退之前需要了解的事

已安装的更新在设置 > Windows 更新 > 更新历史记录中查看。卸载路径在Microsoft支持文档中按开始 > 设置 > Windows 更新 > 更多选项 > 更新历史记录 > 卸载更新的顺序给出(卸载更新位于相关设置下)。文档介绍的是从列表中选择要移除的更新，再选择卸载，并明确指出部分更新无法卸载。无法进入Windows时，也可以在Windows RE中按疑难解答 > 高级选项 > 卸载更新的顺序操作，并选择卸载最新质量更新。无法进入Windows时，另有一种通过恢复环境(Windows RE)、经疑难解答 > 高级选项来卸载的方法。

  1. 先核对时间。在更新历史记录列表中，找找有没有接近症状开始时间的条目。
  2. 确认该条目能否卸载。文档说部分更新无法卸载，所以列表中可能存在无法卸载的条目。
  3. 如果是安全更新，先弄清卸载的风险。文档提示，卸载安全更新之前要先了解风险。同一文档还提示，使用Windows 11时，应先尝试重新安装Windows版本。
  4. 卸载之后，同一更新可能再次被自动安装，因此要一并考虑暂停日期怎么用。不过文档没有详细说明已卸载更新之后的行为。

如果怀疑是性能问题，应先看用任务管理器先定位瓶颈的步骤，整体设置的检查清单在Windows 11优化指南中。把更新检查纳入定期任务的方法见Windows自动化入门。更新界面各项目本身的说明，在上面的章节中已经完整。

安装失败时检查的顺序

Microsoft支持的更新疑难解答文档给出了10种基本解决方法。顺序如下。

顺序文档给出的检查补充
1运行自动疑难解答从设置 > 系统 > 疑难解答打开
2确认设备已正确连接电源并连上互联网检查电源连接和互联网连接。稳定的互联网连接至关重要
3检查管理员权限部分更新需要
4拔掉外接硬件移除基本功能不需要的外置存储设备、驱动器、扩展坞等，然后重新运行更新
5重置更新缓存损坏的文件可能引发错误
6检查日期和时间设置开启自动同步
7更新第三方驱动程序到制造商网站确认
8腾出磁盘空间文档写明32位需16GB，64位需20GB以上
9重新运行更新可能还有其他更新
10重启设备使更改生效

文档把这十项放在「请尝试以下常规疑难解答步骤，帮助解决Windows更新问题」一句之下，从第1步起按编号给出，并先提醒在尝试之前备份个人文件。哪一步成本最低、哪一步最常是原因，文档没有写。文档还把按错误代码给出的应对(例如0x8007000d、0x800705b4)、DISM和SFC等系统文件修复工具，以及全新安装工具，作为高级选项介绍。如果屏幕上出现错误代码，先在文档的列表中查找该代码。

磁盘空间对功能更新尤其是个问题。疑难解答文档的第8步写明，升级32位系统需要16GB以上、升级64位系统需要20GB以上的可用空间，并提到存储空间不足时可使用Windows中增加驱动器空间的方法。FAQ建议磁盘空间不足时清理文件或使用外置驱动器。在可用空间不足的电脑上，先腾出存储空间，比用暂停来争取时间更能避免同样的失败反复发生。

为什么不使用永久屏蔽 — 当作时间点问题而不是设置问题

更新带来不便时，很多人会去找通过组策略或注册表彻底阻止更新的方法。这里不涉及这些方法，理由有三。

  • 文档确定的基本方针是「自动安装」，停止只被允许作为暂时的措施。
  • Learn文档反复写明，不建议直接编辑Windows注册表。
  • 如果问题出在重启，活动时间和安排重启就能解决大半；如果出在时间点，暂停就能解决；超出这个范围的需求属于管理工具的领域。

在受管理的设备上，管理员制定的策略优先，设置界面的部分项目可能显示为灰色，或出现由组织管理的提示。这种情况下，正确的做法是向管理员提出请求，而不是自行更改。另外，文档告知Windows 10的支持已于2025年10月14日结束。仍在使用Windows 10的设备，在调整更新设置之前，要先决定是否迁移到Windows 11。暂停文档指出，2025年10月14日之后Microsoft不再通过Windows更新提供免费的软件更新、技术支持或Windows 10的安全修复；电脑仍可继续运行，但建议迁移到Windows 11。
