人赢了AI这句话要成为命题需要什么 - 让两子对局里被丢掉的条件

让子这把刻度尺、访问数这份预算，以及读懂超人系统崩掉那个位置的方法

2026-09-05 潮流/文化

胜负被压缩成一句话时传得最远。而在压缩的过程中最先掉下去的，就是条件。缺了条件的胜负句子不是信息，而是气氛。

本文以一次围棋对局为素材，把那些条件一条一条重新立起来。要谈的不是一个感人的故事。真正的关注点是：一个系统被称作超人，究竟只在哪些条件之内才成立；当这些条件被丢掉之后，读者又该怎么读那句话。这套读法不只用于围棋，看模型对比表和基准测试分数时可以原样搬过去。

本文只以公开的对局条件和公开的学术论文为依据，不讨论对人的评价或推测。无法确认的项目在正文中明确标注，并连同理由集中放在倒数第二节。

起因 - 一句话传开了，条件全留在原地

2026年7月，隔一天下一局，一共下了三局。一方是职业棋手，另一方是名为 KataGo 的开源围棋引擎。结果是人这一方两胜一负。这个结果很快被压缩成一句话开始流传：人赢了AI。

单看这句话，能确定的东西几乎没有。加上让两子这个说法也帮不上多少忙，因为它省掉了两子是谁摆的。人摆的，就是人接受了让子；机器摆的，就是机器接受了让子。前一种情况下，这个结果是建立在人仍处于下风这一前提之上的成绩；后一种情况下，那就是完全不同、而且大得多的一个主张。

在这之后还有更大的空白。KataGo 不是一个固定的对手。加载了哪个网络文件、每手允许搜索多少次，会让同一个名字下的棋力拉开很大差距。缺了这两个值，赢了KataGo 这句话就停在既非真也非假的状态里，因为被赢的到底是什么还没有被确定下来。

先只把公开资料能确定的部分列成表。下面这些值在对局报道和引擎仓库里原样转录条件的那份记录之间是一致的。

让子方向是这张表里最重要的一行，而且有两条互相独立的证据指向同一处。一条是报道写明棋手每局都先摆下两枚黑子开局；另一条是他本人留下的公开发言。大意是等到能以两子稳定取胜，就想通过贴目或者下分先把条件调得更难。说要把条件调得更难，意味着现在的条件比那更容易，而这只与接受让子的是人这个事实对得上。

各家资料互相打架的地方

即便是描述同一场比赛的资料，有些数值也对不上。把分歧抹掉、直接挑一个当然更省事，但在没有依据判断谁对的时候，把分歧本身如实记下来反而更好。

  • 人方用时既有记作5小时加30秒读秒的记录，也有被概括成5小时30分的叙述。原始记法是 5h+30s，前者更接近原文，但读秒次数在两种版本里都没有写
  • 主办和承办的名称各家写法不同。一处写作某经济类媒体与赞助方的联合主办，另一处则给出一个独立的赛事名称。哪一个才是正式名称未能确认
  • 究竟算正式对局还是表演赛，措辞也不统一。多家报道用了正式这个词，但它是否符合赛事规程中正式对局的定义，未能确认
  • 还有记录把让子方向压缩成让AI两子这样的说法，这种省略读起来像是AI被让了两子。与报道正文以及本人发言对照后，方向与上一节的结论一致

最后一条尤其值得注意。仅仅是同一个事实的缩写方式变了，方向就可能被读反。性能主张里方向被颠倒的事故，大多就是这样发生的。它出自省略，而不是出自谎言。

让子棋的子究竟是量什么的刻度

一子等于一级这个惯例

让子是在棋盘上补偿实力差的装置。弱的一方先摆若干子再开局，在这份便宜之上继续对弈。按惯例，一个等级的差距算作一子。差三级就三子，差五级就五子。只差一级时不摆子，改由强的一方执白但不收贴目。

这里值得留意的是，这把刻度尺是离散的。一子和两子之间没有中间值。所以让子数与其说是一把精确的尺子，不如说更像刻度很粗的台阶。写作两子，并不是断言实力差恰好是两级，而是说有人把条件设在两级附近，希望胜负能够胶着。

两子摆在哪里

摆两子时，黑棋落在右上和左下的星位，也就是斜对角相望的两处。这个摆法是为了让优势均匀地铺开在整张棋盘上，摆的位置一变，同样的两子在实战里的利害也会变。让子棋的贴目通常取0或0.5目，这次的0.5目符合惯例。

子数惯例上的含义摆放位置
0子且有贴目同级。分先定好黑白后开局
0子且无贴目相差一级弱方执黑，不出贴目
2子相差两级上下右上和左下星位
3子相差三级上下三处星位
9子常用的最大让子九处星位全部

把这把刻度尺放到人与机器之间会怎样

让子的刻度是以人与人之间的实力分布为前提造出来的。有段级体系，每一级之间大致有相近的差距，而且积累了用几颗子能补上这段差距的经验。问题在于，把这把尺子原样放到人和引擎之间时，这些前提会一条条失效。

  • 机器那一侧没有段级。引擎的强弱不是用段位表示的，而是用设置表示的。同一个文件只改搜索量，实力就会明显移动
  • 实力差并不均匀。人与人之间的一级差通常在各个领域都拉开相近的幅度，而人与引擎的差距会随局面类型剧烈变化，在某些领域压倒性，在另一些领域则未必
  • 让子局是引擎训练分布之外的局面。自我对弈的训练绝大部分是分先棋。开局就摆着两子的局面处在那个分布的边缘
  • 只有人这一方能研究对手。引擎是公开的，赛前想跑多少局都行。反方向的准备并不存在
  • 时间分配是不对称的。人方用五个小时，机器方每手用20秒。这同样属于测量实力差的条件的一部分

所以两子这个数字并不是把人与机器的实力差确定为两级的结论。它更接近一个为了让胜负看起来胶着而选定的设置。实际上三局里第一局由引擎取胜，另外两局由人取胜。三局这样的样本出现这种组合，只说明两子大致落在均衡点附近，并不能把我们带到实力差恰好是两子的结论上去。

同一个网络，访问数不同就是不同的棋力

现代围棋引擎的一手由两部分构成。一部分是神经网络看到盘面后立刻给出的输出，相当于直觉；另一部分是以这个输出为种子往下延伸并加以验证的搜索。搜索扩展一次的单位叫作访问。访问数就是分配给这一手的计算预算。

这份预算对实力的支配有多大，对抗策略的研究几乎是顺带地把它展示得异常清晰。这项研究先针对 KataGo 训练出攻击用的策略，然后固定攻击方，只改变被攻击方的访问数来测量胜率。

改变访问数就会改变结果的实测

被攻击方的搜索量攻击方胜率样本
不搜索100%1,000局
4,096访问97.3%1,000局
10的6次方访问82%50局
10的7次方访问72%50局

神经网络自始至终是同一个。变的只是每一手多验证几次。可结果却从100%一路移动到72%。这张表说明两件事。第一，增加搜索确实有效。第二，把搜索放大一万倍也不能让弱点消失。访问数是决定实力的一个轴，但某一类缺陷在这个轴上只会缓慢地减少。

带着这一点回到这次对局，问题就清楚了。公开的条件里只有每手20秒这个时间，没有实际的访问数。要从时间反推访问数，需要知道用的是多大的网络、批大小和线程数如何配置，而这些值同样没有。结果就是，谁也无法指出这次对局的对手落在上表的哪一行。

20秒和四块显卡究竟定下了什么

每手20秒加四块显卡，比什么都没有要好，但代替不了访问数，因为中间还夹着下面这些变量。

  • 网络规模。块数和通道数大，单次评估就慢，同样20秒里跑到的访问数就少，代价是单次评估更准。这笔交换并非事先就定好的
  • 精度与批处理。是否以半精度运行、是否把多次评估打包处理，会让每秒吞吐相差数倍
  • 线程与显卡利用。有四块卡，和配置上真的把四块卡都用满，是两回事
  • 是否预读。对方思考时提前搜索的功能被关闭，这一点是公开的。若这个功能开着，实际搜索量会远大于20秒所暗示的水平
  • 局面难度。同样是20秒，不同局面能跑到的访问数也不一样

把延迟和吞吐按条件分开来读，这件事在选模型时会以完全相同的形态重复。同一套系统因为测的区间不同而给出截然不同的数字，这一层情况在把延迟拆成四段再选模型的那篇里另有整理。

最后这两行，就是现有依据所能立起的最强的句子。它依然包含相当分量的内容，只是比人赢了AI窄得多，而正因为窄，它才可以被检验。

KataGo 不是一个固定的对象

KataGo 是开源引擎，神经网络在公开的训练服务器上持续产出。那台服务器的网络列表里不断有新文件上传，到2026年9月初，最新的文件仍以数日为单位更新。也就是说，KataGo 这个名字离开版本就无法指定对象。

而且那台服务器给出的等级分数值上，还挂着制作方自己写下的附注：这些等级分是近似值，不一定能与任何其他机器人或其他训练轮次的等级分相比较。等于是在同一个项目内部就已经钉上了一句不要跨着比数字的告诫。

  • 引擎仓库同时分发多个不同规模的网络。较小的那些被描述为弱得多但依然超过职业水平。弱和超过职业水平这两个说法同处一句
  • 因此用了哪个文件，会让同样20秒下的对手完全不同。写下文件名不是形式主义，而是指定对象的动作
  • 引擎版本又是另一个变量。搜索实现与默认值会随版本发布而变化
  • 这些若都不被记录，日后就无法在相同条件下重下一遍。无法复现的对局只能作为记录留下，无法作为依据留下
# 要写成可复现，至少需要这些
engine        : KataGo v1.x.y
network       : kata1-....bin.gz        # 文件名原样照抄
maxVisits     : N                       # 或实测的平均访问数
maxTime       : 20s
ponder        : false
gpu           : RTX 3090 x4 / 96GB
rules         : 数目法，贴0.5目，让两子
handicap opt  : playoutDoublingAdvantage = ?
per-game log  : 三局是否为同一套设置

让子棋在引擎那一侧也是单独的问题

在让子棋里，让子的那一方引擎从一开始就拿着一盘不利的棋。只以最大化胜率为目标的搜索，在这种局面下会出特有的毛病。当已经落后的局面里所有候选着的胜率都很低时，选哪一手看起来差别都不大，引擎于是陷入无法区分减少损失的一手与能翻盘的一手的状态。

这个问题在引擎那一侧也是已知的，KataGo 仓库在自己的说明里写明了应对。大意是它不只看胜率，还关心目数的最大化，因此在大幅落后的让子棋里也能下得强硬；以及它支持包括整数贴目在内的多种贴目值，并支持高让子局的良好对弈。

也就是说，让子棋里怎么下是由设置调节的领域。有一个单独的参数用来调整让子一方要下得多进取。这次对局里这个参数如何设定，并没有被公开，而它会直接影响结果。即便网络相同、访问数相同，这个设置一变，就成了另一种性格的对手。

超人系统真正崩掉的那个位置

从这里开始谈的不是对局，而是学术上的记录。它与这次结果是两回事，但它是支撑超人这个评价是有条件的这一命题最坚实的依据，值得准确地摆出来。

2022年公开的论文Adversarial Policies Beat Superhuman Go AIs针对 KataGo 训练了攻击用策略，报告说面对以超人设置运行的 KataGo 取得了超过97%的胜率。按作者写在论文里的说法，这些攻击方并不是因为棋下得好才赢，而是诱导对手走出严重的错着。

崩掉的究竟是什么

核心攻击利用的是环形。它诱使对方做出像一个大圈一样连起来的一大块棋，然后攻击这块棋死活判断失灵的那个位置。研究同时报告的一项观察，很能说明这个缺陷的性质：被攻击方在对局的大部分区间里预测损失都偏高，而且在被吃掉之前还把胜率看在99%以上，随后突然崩盘。它不是被一点点压垮的，而是直到最后一刻仍然相信自己在赢。

人可以照着做出来

这个缺陷之所以特别，在于人能够理解并执行它。论文写道，这个攻击清晰到人类专家可以在没有算法辅助的情况下实现，并持续战胜超人级AI，并报告人用这个策略对上顶尖机器人时取得了超过90%的胜率。此后也有报道称，一位业余高段水平的人在网络服务器上对 KataGo 系机器人下了15局赢了14局。

  • 训练攻击方所耗的算力，是训练被攻击方所耗算力的14.0%。需要的不是压倒对手的资源，只是足够找到破绽的资源
  • 更简单形态的攻击，成本还要低得多。对不做搜索的对手取得99.9%胜率的例子也被一并报告
  • 攻击还部分迁移到了别的引擎。不做任何再训练，面对其他超人级引擎取得了6.1%和3.5%的胜率。迁移率本身很低，但不是零
  • 暴露出缺陷的不是平均实力，而是最坏情况。平均性能和最坏性能是两个不同的轴，超人这个评价只挂在前一个轴上

加上防御就挡得住吗

紧接着自然要问：那修一修不就行了。2024年的后续论文Can Go AIs be adversarially robust?处理的正是这个问题。作者们把围棋设定为检验稳健性的有利领域，因为平均能力极高、问题域很窄，而且本来就是对抗性的设定。

论文测试了三种防御：针对手工构造局面的对抗训练、迭代式对抗训练，以及改变网络结构。结果如下。其中一些防御挡住了已知的攻击，但面对新训练出来的攻击方，没有一种撑得住。而且新发现的有效攻击，大多数仍是同一类循环攻击的不同实现。

被攻击方被攻击方搜索量攻击方胜率样本
无防御不搜索100%1,000局
无防御4,096访问97.3%1,000局
经对抗训练防御不搜索100.0%1,048局
经对抗训练防御4,096访问95.7%1,052局

还有一行让加了防御的一方看上去反而略差。样本与攻击方都不同，这些格子不能直接对比，但已经足以支撑一个结论：仅仅因为加了防御就放心是不成立的。论文指出的两处空白是防御泛化的效率和训练的多样性。评估体系会在哪里制造盲区，在讲评估盲区的那篇里从另一个角度做了整理。

这次对局和循环攻击是同一回事吗

这里必须把界线划清楚。没有依据把这次让子棋的结果看作与循环攻击相同的现象。两者在好几个轴上都不同。

轴2026年7月的让子棋对抗策略研究

样本三局数百到上千局的量级
可复现性设置日志未公开，无法复现代码与条件均已公开

公开的棋谱里是否出现过循环形死活崩溃并决定胜负，并未得到确认。所以两件事有可能彼此无关，而且按现有依据把它们看作无关更为忠实。一旦把其中一件当作另一件的证据，两边都会被削弱。

尽管如此还把两者放进同一篇文章，是因为它们共享一个结构。超人这个评价是架在条件之上的。条件一变，评价随之改变。在前一件事里条件是让子和用时，在后一项研究里条件是对方策略的种类和搜索量。抹掉条件、只留下超人这个词，两件事都会被读错。

读性能主张时先问的六件事

下面是本文实用的部分。碰到A赢了B这种句子时该先问的事，压缩成六条就是这些。

六个问题一页看完

问题套到这次对局套到模型对比
1. 方向是哪一边两子是谁摆的哪一边跑在有利的配置上
2. 对手到底是什么哪个网络文件、哪个版本哪个模型的哪个快照
3. 预算是多少每手访问数是多少推理预算、尝试次数、上下文长度
4. 样本有多大三局还是一千局多少道题、重复了几次
5. 测的是什么胜负还是目数差平均还是最坏，用哪个指标
6. 能不能重来一次设置日志是否公开提示词、随机种子、版本是否公开

六个问题里只要有一个是空白，那句话就还不是命题。这不等于说它是假的，而是说它的真假目前无法判定。这个区分在实务里尤其重要：把无法判定当成假，会漏掉好结果；当成真，则会把决策堆在并不存在的依据上。

  • 只空一项时，问那一项就够了。多数情况是原文里写着，只是在摘要里掉了
  • 空了好几项时，就把这个主张当作可供参考的案例，而不作为依据
  • 方向那一项是空白时，其余的不必看。方向一反，结论整个反过来
  • 样本只有个位数时，复现条件是否公开比样本量更重要。只要能重来，样本就能加

把同一套读法搬到基准测试和模型对比上

围棋里的访问数，在别的领域会换个名字出现。换的只是名字，位置是同一个。那个位置就是这次测量给这个模型配了多少计算。

  • 生成多个答案再从中挑选的方式里，尝试次数就是预算。试几次里中一次就算过，会让分数变化很大
  • 让模型写出长推理的设置里，输出长度就是预算。改一改长度上限，同一个模型的分数就会移动
  • 接上工具的设置里，允许调用的次数就是预算。不带工具测的分数和带工具测的分数是两个不同的指标
  • 放进上下文的示例数量同样是预算。零示例测出的分数和放了若干示例测出的分数，是同名的两个数字
  • 评分者本身是模型时，评分者一侧的设置也是条件。量的人换了，刻度也就换了

所以看模型对比表时，最先要核对的不是分数，而是写在分数旁边的条件在两边是否对称。如果只有一边试了很多次，或者只有一边接了工具，那张表比的就不是两个模型，而是两套配置。同样的问题意识从基准测试设计那一侧挖下去的讨论，分别放在拆解基准测试的那篇和讲编码基准测试条件的那篇里。

游戏本身变成评估舞台这股潮流，在人与智能体站在同一套规则之下的实验那篇里另有整理。规则相同才谈得上比较，这条原则在那边占据的也是同一个位置。

没能确认的部分

  • 引擎使用的网络文件与版本未能确认。涉及这次对局的资料里，哪一处都没有写下文件名或发布号。缺了这个值，对手就没有被指定
  • 每手实际的访问数未能确认。公开的只有每手20秒这个时间，而从时间反推访问数需要网络规模与运行配置
  • 与让子相关的引擎设置如何设定未能确认。仓库说明里能确认存在一个调整让子方进取程度的参数，但这次用的值没有公开
  • 三局是否以同一套设置进行未能确认，因为没有公开逐局的设置日志。网上就此有过多种说法，但各方都未出示依据材料，无从判断
  • 第一局的手数与目数差未能确认。第二局和第三局的棋谱是公开的，第一局则不是
  • 规则细节未能确认。数目法与贴0.5目可以确认，但依据的是哪一国规则、细部裁定条款如何，均未写明
  • 世界第一这一修饰的基准时点与等级分体系未能确认。排名会随时点与计算方式而变，因此本文正文没有把这个修饰当作依据使用
  • 正式一词的确切范围未能确认。多家报道用了正式这个词，但没有找到能区分赛事规程上的正式对局与赞助表演赛的材料
  • 访问数与等级分的对应曲线就本次所用网络而言未能确认。正文中与访问数有关的数值，是对抗策略研究就其自身实验对象报告的值，不能原样搬到别的网络上
  • 公开棋谱中是否出现过与环形有关的局面未能确认。因此本文没有写下任何把这次对局与对抗弱点连起来的句子
