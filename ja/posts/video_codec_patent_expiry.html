映像1つが開かなかった時代が残したもの

Linux を入れて手元の動画を開いたら コーデックが見つかりません と出た、という体験は世代を問わず共有されています。解決法もいつも似た形でした。リポジトリをもう1つ足し、名前になじみのないパッケージ群を入れ、そこでようやく再生できる。ブラウザでは普通に流れる映像がローカルプレイヤーだけで止まることもあり、同じファイルがあるディストリでは開いて別のディストリでは開かないこともありました。

この症状の原因は技術ではありません。デコーダのコードはとうに書かれていて、ソースも公開されていて、性能も十分でした。塞いでいたのは特許です。正確には特許そのものというより、そのコードを何百万人に配布する主体が負う責任でした。

2026年7月、その構造の一片が満了で閉じました。25年もちこたえた特許1件が終わり、古い標準1つが世界で特許負担を脱したという知らせが流れました。歓迎すべき話ですが、ここで何が終わり何がそのままなのかは簡単に混ざります。この記事はその境界線を引きます。

コーデックに特許が掛かるということ - 著作権とは別の層

オープンソースを長く扱ってきた人ほど、ここで一度つまずきます。ソースが公開されていてライセンスが自由なら終わりではないのか、と思うところですが、特許は別の層にあります。

  • 著作権は表現を守ります。誰かが書いたそのコードを複製し、改変し、配布する行為を制御します。
  • 特許は方法を守ります。コードをゼロから書き直しても、その方法を使えば掛かります。
  • だからフリーソフトウェアライセンスは特許実施の許諾と同じものではありません。著作権側の許諾を得たからといって特許側が一緒に片づくわけではないのです。
  • 一部のライセンスは貢献者の特許について明示的な許諾条項を置きますが、それは貢献者が持つ特許に限られます。無関係な第三者の特許はその条項の外です。

コーデックがとりわけ厄介なのは、標準の成り立ちのせいです。映像圧縮標準は1つの発明ではなく数百の技法の組み合わせです。動き予測、変換、量子化、エントロピー符号化、ループフィルタといった段階ごとに細かな技法があり、その技法1つ1つに別々の会社の特許が付きます。

ここから標準必須特許という性格が生まれます。標準に従う以上その技法を使わない方法がないので、設計で避けて通ることができません。標準を実装したという事実が、そのまま特許を実施したという意味になります。回避可能な通常の特許とは根本的に性格が異なり、これがコーデックの世界に専用のライセンス窓口ができた理由です。

パテントプールとロイヤリティ - 窓口を1つに束ねる装置

1つの標準に数百件の特許が数十社に散らばっているとしましょう。実装者がその各社と個別交渉するなら、交渉だけで製品寿命が尽きます。そこで生まれた装置がパテントプールです。

  • 権利者が自社の特許を1つの管理者に預け、管理者は1枚のライセンスに束ねて販売します。
  • 実装者は窓口1つと契約し、集められたロイヤリティは管理者が権利者に分配します。
  • 料率はおおむね機器の台数基準か、ストリーミングのようにサービス規模基準か、その両方を置きます。
  • 年間上限を設ける例が多くあります。大量販売する事業者が青天井で課金されないようにする仕組みです。

映像コーデックでよく名前が出る管理者はいくつかあります。MPEG LA は長く MPEG 系のプールを運営し、その流れは Via Licensing Alliance に引き継がれました。HEVC 側では Access Advance が HEVC Advance プールを、新しい標準向けに VVC Advance プールを運営していると述べています。Sisvel は VP9 と AV1 を対象とするプログラムを別に置いています。

ここに実務でよく見落とされる点が1つあります。プールライセンスを受けたからといって、その標準に関するすべての権利が片づくわけではありません。プールに入っていない権利者は常に存在し、同じ標準に対してプールが複数ある場合もあります。プールは取引コストを下げる装置であって、免責証書ではないのです。

料率も固定ではありません。Streaming Media の報道によれば、Via LA は AVC のストリーミング料率構造を改め、2010年8月に定められた年間10万ドルの単一上限に代えて階層構造を導入しました。最上位階層は年450万ドル、その次が337万5千ドルと225万ドルと整理され、小規模・新興サービスは10万ドルが維持されると報じられています。ただしこの改定は2026年以降に新たにライセンスを受ける事業者に適用され、2025年末時点で有効なライセンスを保有する企業は従来の条件を維持すると説明されました。

なぜブラジルだけ25年もったのか

同じ発明なのに欧州では2021年に終わり、ブラジルでは2026年まで生きていました。特許期間の数え方が違ったからです。

  • 多くの国は出願日から20年で数えます。審査が長引けば、実際に権利を行使できる期間はその分だけ減ります。
  • ブラジル産業財産法(法律9.279/96)第40条ただし書はここに下限を置きました。発明特許は登録日から最低10年を保障する構造だったのです。
  • この件は出願2001年、登録2016年。登録まで15年かかり、下限規定が適用されて満期が2026年にずれ込みました。

ところがこの条項はすでに違憲判断を受けています。ブラジル連邦最高裁判所は2016年に提起された違憲訴訟 ADI 5529 において、2021年5月6日に当該ただし書を違憲と判断しました。特許の一時性を定めた憲法条項に反すること、そして審査遅延によって存続期間がまちまちになると法的安定性と競争に問題が生じるという趣旨です。

ではこの特許も当時短縮されるべきではなかったのか、というとそうはなりませんでした。報道によれば遡及効は医薬・保健分野の特許に限定され、ブラジル特許庁が存続期間を短縮したのもその範囲の3,341件でした。コーデック特許はその範囲の外にあり、古い計算法のまま2026年7月まで走ったわけです。

この点が今回の件で最も実務的な教訓です。特許の地理は均一ではありません。米国と欧州で終わったという事実は世界で終わったという意味ではなく、ある法域の制度的な特異点1つが、標準全体を自由に使える時点を5年遅らせることがあります。

ディストリが標準搭載できなかった本当の理由 - 再配布責任

ここで利用者が体験していた症状とディストリビューションの事情がつながります。要は使うことと配布することが違うという点です。

  • 個人が自分のマシンで映像を再生する行為は、ロイヤリティ体系が狙っている地点ではありません。
  • 一方でディストリビューションはソフトウェアを作って広く配布する主体です。特許の掛かった実装を載せて送り出す行為そのものが問題になりえます。
  • 配布主体の性格も分かれます。米国に法人と売上がある組織は標的になりやすく、そうでない組織は実務上のリスクが低くなります。
  • LWN の記事はこの差をはっきり書きました。訴訟リスクの低い配布元は同じコーデックを載せ続けたのです。

そこでディストリビューションはそれぞれ違う妥協点を見つけました。

  • 別リポジトリへ押し出す。本体には入れず、別主体が運営するリポジトリから利用者が自分で取ってくる形にする。利用者が繰り返していたリポジトリ追加の儀式の正体です。
  • 第三者がロイヤリティを肩代わりするバイナリ。Cisco は OpenH264 という特定の H.264 実装の特許費用を負担し無償で配布してきました。ただしCisco が配布するそのバイナリという条件が付きます。
  • ランタイム単位で分ける。アプリ配布ランタイム側にコーデックを置き、ディストリ本体と責任を分離した例もあります。

興味深い例外が今回の知らせと一緒に出てきました。Fedora はブラジル特許がまだ有効だった2023年の時点で、すでに xvidcore を配布していたというのです。個々のディストリビューションが法域と実際のリスクを見て判断を違えてきたということであり、ポリシーは特許の満了日に自動連動しないという事実も同時に示しています。

ハードウェアアクセラレーションが切られた2022年の変更

この構造が最もはっきり表れた出来事が2022年にありました。Fedora はその年の9月、グラフィックスライブラリ Mesa のビルド方法を変え、H.264 と H.265、VC-1 のハードウェアアクセラレーション経路を切りました。openSUSE もほどなく同じ方向を取りました。

当時の論理はこうでした。

  • Mesa は映像アクセラレーション API の一部としてデコード・エンコードのソフトウェア部分を実装していました。
  • ハードウェア単体では侵害が成立しないが、ハードウェアとソフトウェアの組み合わせが実際の作業を行うため、そのかたちで届けられた実装が侵害を構成しうるという判断がありました。
  • ハードウェアベンダーは自社製品を売るにあたりエンドユーザー向けソフトウェアまでライセンスしていませんでした。顧客が別途ライセンスを得ることを前提にしていた、というのです。
  • そこでコードを取り除き、故意侵害の主張が成り立つ余地をなくしました。

利用者にとってこの変更は、突然ハードウェアデコードが消えた出来事として現れました。代替はありました。別リポジトリがコーデックを戻した Mesa と FFmpeg のビルドを提供し、アプリ配布ランタイム経由のアプリケーションはランタイム側でコーデックを維持していました。

ここから得るべきは特定ディストリへの評価ではなく、構造の理解です。特許リスクはコードの1かたまりではなく組み合わせに掛かります。自分たちのコードにエンコーダがないという事実だけで安心はできず、自分たちが載せて出したソフトウェアがどのハードウェアと出会って何を行うのかまでが判断範囲に入ってきます。

コーデック別の現状 - ひとまとめにすると外れる

今回の知らせをもってコーデックが自由になったとひとまとめにすると、ほぼ確実に外れます。標準ごとにライセンス構造が違うからです。以下は2026年8月時点で公開された発表と報道で確認できた範囲だけを整理したものです。

ロイヤリティフリーが生まれた背景と、静かでない理由

ウェブはコーデックを必要としましたが、機器台数基準のロイヤリティはウェブの事業モデルとかみ合いませんでした。ブラウザは数億本が無料で配られ、映像はどこにでも入ります。この隙間がロイヤリティフリーコーデックという方向を作りました。

  • Google は買収した技術をもとに VP8 と VP9 を開放フォーマットとして出しました。
  • 2015年には AOMedia が結成されました。Google、Netflix、Apple、Microsoft、Amazon、Meta、Nvidia、Intel、ARM、Samsung、Cisco、Mozilla などが参加したと整理されています。
  • その成果が AV1 であり、会員が自社の特許を無償で開放するロイヤリティフリー特許ライセンスが併せて付きました。

ただしここで正確に読むべきものがあります。ロイヤリティフリーは標準を作った人たちの約束であって、第三者の特許がないという保証ではありません。この区別が実務で最も頻繁につぶれます。

  • Sisvel は2019年3月から VP9 と AV1 のそれぞれを対象とするライセンスプログラムを運営してきたと述べています。
  • 公開された説明では、VP9 プログラムに12社、AV1 プログラムに14社の権利者が参加していると紹介されました。
  • 標準料率としては VP9 がディスプレイ機器0.24ユーロ・非ディスプレイ0.08ユーロ、AV1 が0.32ユーロ・0.11ユーロと案内されました。
  • 2026年3月24日、Access Advance は自社プールの参加社であるドルビーが AV1 と HEVC に関する特許侵害を理由に Snap を米国とブラジルで提訴したと発表しました。
  • 同発表はこれを、自社ライセンサーによるAV1 実装への初の特許主張であり、ストリーミングプラットフォームを相手取った初の AV1 主張だと説明しています。

この件の当否は裁判所が分ける事柄であり、ここでその判断を代わりに下す理由はありません。実務が持ち帰るべきものは1つです。ロイヤリティフリーの標準を選んだという事実が、ライセンス検討を省いてよいという意味にはなりません。判断の根拠をなくすというより、検討の性格を変えるものと見るのが正確です。

今回の満了が変えることと変えないこと

整理するとこうなります。

区分内容
変わることMPEG-4 Part 2 の実装をめぐって残っていた最後の法域の不確実性が整理されたと報じられた
変わること2000年代の映像資料を扱うデジタル保存の作業で、古い形式のサポート負担が減る
変わることディストリが古いコーデック構成要素を制限する根拠が減る。ただし実際の方針変更は各プロジェクトの判断

変わらないこと再生ツールの多くはすでにこの形式に対応してきた。利用者の体感変化は小さい
変わらないことAAC などの音声系、そのほかの MPEG 技術の状態

体感変化が小さいというのは拍子抜けに聞こえるかもしれませんが、この出来事の値打ちは別のところにあります。2001年に出した出願1件が2026年まで、ある標準の自由な配布を押さえておけるという事実が具体的な数字として残りました。いま設計中のシステムがどの標準に依存するのかを見るとき、この期間感覚はそのまま使えます。

実務で見る4つの判断軸

結論から言えば、何をしているかによって見るべきものが完全に変わります。同じコーデックでも露出する位置が違うからです。

  • 第一に、どの標準か。MP4 コンテナに入っているという事実は何も教えてくれません。コンテナとコーデックは別の層です。実際のストリームが H.264 なのか HEVC なのか AV1 なのかをまず確定します。
  • 第二に、エンコードかデコードか。料率体系はおおむね両者を区別し、どちらを製品機能として売るかによって検討対象が変わります。
  • 第三に、どの法域へ配布するのか。今回の件が示した通りです。ある国で片づいたからといって世界で片づいたわけではありません。
  • 第四に、その機能はどこから来るのか。すでにライセンス済みの OS や部品が提供する機能を使うのと、自分たちがデコーダを直接載せて出すのとでは位置が違います。

この4軸に自分の状況を置いてみると、おおむねこういう絵になります。

  • 個人利用者は事実上気にすることがありません。ディストリが標準提供しないならリポジトリを足す程度の問題として残ります。
  • 社内向けツールを作る場合は配布範囲が狭く販売もないので相対的に単純ですが、社内方針上の確認を要する組織はあります。
  • オープンソースを公開配布する場合は配布主体と法域が争点になります。コーデック実装を本体に入れるか選択構成要素として外すかが、実際の設計判断になります。
  • 機器を販売する場合は台数基準の料率が直接掛かります。部品供給元がどこまでライセンスを確保しているかを契約書で確認する話です。
  • ストリーミングサービスを運営する場合はサービス規模基準の料率と契約時点が同時に効きます。先に見た AVC 料率の改定が新規ライセンシー基準だったのがその例です。

結論 - 今日持ち帰る3つ

第一に、終わったのは1つの標準です。MPEG-4 Part 2 を覆っていたプールの最後の権利が整理されたと報じられ、今日実際に使っている H.264 と HEVC、VVC はそれぞれ別の構造の上にそのまま残っています。1つの知らせをコーデック全般に広げて読むと、その瞬間に外れます。

第二に、特許の地理と時間は均一ではありません。同じ発明が欧州では2021年に終わり、ブラジルでは2026年まで走りました。存続期間を数える規則1つ、違憲判断の遡及範囲1つが5年を作りました。標準依存を見るときは、いつ終わるかだけでなくどこで終わるかを併せて見る必要があります。

第三に、ロイヤリティフリーはリスクがないという意味ではありません。標準を作った人たちの無償開放の約束と、その標準を実装するときに世の中のすべての特許が片づいているという保証は別の言葉です。その差が実際の紛争として表れた事例が2026年に公になりました。

コーデックを選ぶ作業は長らく圧縮率とハードウェア対応の問題として扱われてきました。ここにもう1つ置くなら、その標準のライセンス構造が自分たちの配布方式と合うかです。25年もちこたえた特許1件が残したものがあるとすれば、その軸が思ったより長く有効だという事実です。
