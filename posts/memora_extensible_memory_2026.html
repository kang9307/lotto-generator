Memora — 장기 작업을 위한 확장형 AI 메모리 시스템

컨텍스트 망각의 벽을 넘어, AI 에이전트가 며칠에 걸친 작업을 기억하는 방법

2026-07-01 IT/기술

이 게시물은 쿠팡 파트너스 활동의 일환으로, 이에 따른 일정액의 수수료를 제공받습니다.

서론: AI가 기억하지 못한다는 문제

AI 에이전트와 며칠에 걸친 프로젝트를 진행해 본 사람이라면 공통적으로 겪는 불편이 있다. 어제 나눈 결정을 오늘 다시 설명해야 하고, 지난 대화에서 정했던 제약 조건이 새 세션에서는 없던 일이 된다. 컨텍스트 윈도우가 128K, 200K로 늘어도 세션이 끊기면 기억은 사라진다. 이것은 토큰 수의 문제가 아니라 메모리 아키텍처의 문제다.

Microsoft Research는 이 문제를 정면으로 다루는 Memora를 공개했다(MIT 라이선스, ICML 2026 제출). 2026년 6월 기준 GeekNews에서 11포인트를 받으며 관심을 끈 이 프레임워크는, AI 에이전트가 대화와 문서에서 필요한 정보를 자동으로 추출하고 장기적으로 저장·검색·갱신할 수 있게 설계됐다. 단순한 RAG 파이프라인이나 대화 요약을 붙이는 방식과 무엇이 다른지, 그리고 이 설계가 에이전트 생태계에 어떤 의미인지를 분석한다.

이 글은 Memora 공식 GitHub 저장소와 관련 보도를 바탕으로 한다. 벤치마크 수치는 공개된 실험 결과를 인용하되, 아직 동료 심사(peer review)를 거치지 않은 ICML 제출 단계임을 전제로 읽어야 한다.

1. 왜 컨텍스트 윈도우를 늘리는 것만으로는 부족한가

먼저 근본 문제를 짚고 넘어가자. LLM의 컨텍스트 윈도우는 컴퓨터의 RAM과 비슷하다. 현재 실행 중인 것은 담을 수 있지만, 프로그램이 꺼지면 사라진다. 세션이 끝나면 이전 대화는 없어지고, 다음 세션은 처음부터 시작한다.

1.1 컨텍스트 윈도우의 물리적 한계

128K 토큰 윈도우도 실제로는 약 80K 이후부터 회수율이 떨어지기 시작한다는 연구가 있다. 장기 대화에서 초반 맥락일수록 모델이 집중하지 못하고, 최신 입력에 편향된다. 게다가 컨텍스트를 꽉 채우는 것은 추론 비용 측면에서도 비효율적이다. 2026년 6월 기준 풀 컨텍스트 방식은 쿼리당 평균 26,000토큰 이상을 소비하는 반면, 잘 설계된 메모리 시스템은 7,000토큰 미만으로 동등하거나 더 높은 정밀도를 달성할 수 있다는 수치가 나왔다.

1.2 에이전트의 장기 작업이란

코딩 에이전트가 리포지토리를 리팩토링하는 작업, 조사 에이전트가 며칠에 걸쳐 보고서를 완성하는 작업, 개인 비서가 사용자의 선호와 결정을 누적해 개인화하는 작업. 이 모두는 단일 세션에서 끝나지 않는다. 에이전트가 어제 파일 구조를 어떻게 바꿨는지, 사용자가 일주일 전 어떤 제약을 정했는지를 기억해야 다음 스텝이 의미 있다. 컨텍스트 윈도우는 이 문제를 기술적으로 해결하지 못한다. 세션 경계가 있는 한, 외부 장기 메모리 레이어는 필수다.

2. Memora의 세 계층 메모리 구조

Memora가 기존 접근법과 가장 뚜렷하게 구별되는 것은 메모리 항목의 표현 방식이다. 각 메모리는 세 가지 구성 요소로 분리된다.

2.1 Memory Value — 원본을 있는 그대로

Memory Value는 인덱싱되지 않는다. 원본 정보를 압축 없이 보존하는 역할로, 실제로 에이전트에게 전달될 내용이다. 인덱싱 대상에서 제외한다는 설계 결정이 핵심이다. 임베딩 모델은 긴 텍스트를 벡터로 압축하는 과정에서 세부 정보를 잃고 의미를 평탄화한다. 원본 값을 인덱싱 대상에서 빼면, 검색은 추상화 계층이 담당하고 전달은 원본이 담당하는 역할 분리가 생긴다.

2.2 Primary Abstraction — 메모리의 정준 단위

Primary Abstraction은 인덱싱된다. 메모리 값의 핵심을 요약한 일대일 표현으로, 검색·갱신·중복 제거의 기준점이다. 새 정보가 들어올 때 기존 메모리와 겹치는지 판단하는 축이 바로 이 추상화다. "Alice가 시애틀로 이사한다"는 Memory Value에서 추상화는 "Alice의 이사 계획"처럼 검색 쿼리와 대조 가능한 형태가 된다. 정준 단위라는 표현이 중요한데, 동일 사실이 여러 표현으로 들어와도 하나의 추상화 아래 병합·갱신할 수 있다.

2.3 Cue Anchors — 다중 의미 진입점

Cue Anchors는 하나의 메모리에 여러 각도에서 접근할 수 있게 해주는 다중 인덱스다. "엔티티 + 핵심 측면" 조합으로 구성되며, 다대다 구조로 여러 쿼리가 같은 메모리를 찾아올 수 있다. 예를 들어 "Alice의 직업 변경", "시애틀 이사", "새 직장" 같은 다른 표현의 쿼리가 동일한 메모리 항목을 회수할 수 있다. 이는 전통적 벡터 검색의 쿼리-문서 유사도 단일 축 의존에서 벗어난 다층 접근이다.

2.4 이 설계가 의미하는 것

세 계층 분리는 "무엇을 저장하느냐"와 "어떻게 찾느냐"를 완전히 분리한다. 임베딩 모델의 의미 압축 손실이 원본 정보에 영향을 주지 않으며, 검색 정밀도는 추상화와 큐 앵커가 담당한다. 이 설계의 실질적 효과는 벤치마크로 확인된다. LoCoMo에서 다중 홉 질문 유형 +23.1점, 시간적 추론 +29.6점 향상이 기존 메모리 방식 대비 보고됐다.

3. 메모리 수명 주기 — 수집부터 검색까지

3.1 수집(Ingestion): 대화와 문서에서 자동 추출

Memora는 대화나 문서를 주제별 에피소드로 분할하고, 각 에피소드에서 사실적·에피소드적·절차적 지식을 구조화된 메모리 항목으로 추출한다. 이 과정은 에이전트가 명시적으로 "저장해"라고 지시하지 않아도 자동으로 진행된다. 수집 단계에서 기존 메모리와의 중복 여부를 확인하고, 겹치는 정보는 병합하거나 갱신한다. 별도의 중복 항목을 쌓는 것이 아니라 살아 있는 지식 베이스처럼 관리한다는 뜻이다.

3.2 저장: ChromaDB와 Redis

기본 저장소는 ChromaDB로, Primary Abstraction과 Cue Anchors를 벡터 임베딩으로 인덱싱한다. Redis는 빠른 구조화 조회를 위한 큐 인덱스로 활용된다. 저장소는 로컬 또는 원격 백엔드 모두 지원하며, 다중 에이전트가 하나의 메모리 레이어를 공유하는 구성도 가능하다. 에이전트별·역할별로 메모리 범위를 지정해 접근을 제어하는 것도 설계에 포함돼 있다.

3.3 검색: 네 가지 전략

Memora는 작업 성격에 따라 선택할 수 있는 네 가지 검색 전략을 제공한다.

전략방식특징
Semantic벡터 유사도 검색빠르고 일반적인 의미 매칭
PromptedLLM 기반 다단계 정제복잡한 쿼리에 정밀도 높음
Hybrid벡터 + BM25 키워드 결합의미+키워드 균형
GRPO강화학습 기반(실험적)로컬 경량 모델로 LLM 호출 대체

GRPO(Group Relative Policy Optimization) 전략은 특히 주목할 만하다. Qwen 3B/7B 같은 경량 모델을 LoRA로 파인튜닝해 검색 정책 결정을 로컬에서 수행함으로써 API 호출 비용을 줄이는 실험적 접근이다. 아직 실험 단계지만, 비용 민감 환경에서 흥미로운 방향이다.

4. RAG, 메모리 프레임워크 대비 Memora의 차별점

Memora가 기존 접근법과 어떻게 다른지 정직하게 비교할 필요가 있다. 세 가지 주요 범주를 짚는다.

4.1 전통적 RAG와의 차이

RAG는 미리 구축된 외부 지식 문서(위키, 매뉴얼, 코드베이스 등)를 쿼리에 따라 검색해 LLM에 주입하는 구조다. 여기서 저장되는 것은 "세상 지식"이며, 갱신 주기가 느리다. Memora는 이와 달리 에이전트가 직접 경험한 것 — 특정 사용자와의 대화 이력, 해당 프로젝트에서 내린 결정, 개인화된 선호 — 을 저장·갱신한다. 둘은 해결하는 문제가 다르다. RAG와 Memora는 경쟁 관계가 아니라 보완 관계다. 그런데 많은 시스템이 이 둘을 혼동하거나, 문서 RAG로 대화 메모리를 대체하려는 잘못된 설계를 한다.

4.2 평면 메모리 저장소와의 차이

가장 단순한 메모리 구현은 대화를 텍스트 파일이나 DB에 누적하고, 벡터 검색으로 유사 과거 대화를 끄집어내는 방식이다. 이 방법의 한계는 두 가지다. 첫째, 중복 없이 관리하기 어렵다. 같은 사실이 여러 표현으로 반복 저장되면 검색 노이즈가 생긴다. 둘째, 갱신이 어렵다. "Alice의 직업이 바뀌었다"는 정보가 들어왔을 때, 기존 항목을 찾아 수정하는 것이 아니라 새 항목이 추가된다. Memora의 Primary Abstraction 기반 정준 단위 관리는 이 문제를 직접 해결한다.

4.3 그래프 기반 지식베이스와의 차이

MemGPT 계열이나 그래프 메모리 접근법은 엔티티와 관계를 그래프로 구조화한다. 표현력은 높지만 구축·유지보수 비용이 크고, 비정형 에피소드 정보를 그래프에 매핑하기 어렵다. Memora는 그래프 외부 저장소 대신 내장된 구조화 표현(세 계층)으로 비슷한 목표를 달성하려는 설계다. 2026년 트렌드가 외부 그래프 저장소에서 내장 엔티티 링킹으로 이동하고 있다는 점과 일치한다.

5. 에이전트가 며칠에 걸친 작업을 이어간다는 것의 의미

기술 스펙을 넘어, 이 설계가 실제로 무엇을 바꾸는지를 생각해 본다.

5.1 프로젝트 연속성

현재 AI 에이전트와 함께 일주일짜리 프로젝트를 하면, 매 세션 첫 몇 분을 "지난번에 어디까지 했는지" 재설명하는 데 쓴다. 장기 메모리가 잘 작동하면 이 overhead가 사라진다. 에이전트가 스스로 어제의 결정을 읽고, 오늘의 작업을 이어간다. 코딩 에이전트라면 파일 구조 변경 이력, 결정의 이유, 보류 중인 작업 목록을 기억한다. 조사 에이전트라면 수집한 자료의 출처와 신뢰도 판단을 누적한다.

5.2 개인화의 실질적 구현

개인화는 오랫동안 AI의 목표였지만, 실질적 구현은 제한적이었다. 세션이 끝나면 사용자 선호가 사라지기 때문이다. 장기 메모리가 사용자의 작업 스타일, 반복되는 선택 패턴, 피드백 이력을 누적하면 에이전트의 응답은 시간이 지날수록 그 사람에게 최적화된다. Memora의 다중 에이전트 메모리 공유 설계는 여러 에이전트가 같은 사용자 컨텍스트를 공유할 수 있게도 한다.

5.3 음성 에이전트와 비시각적 인터페이스

음성 인터페이스에서 사용자는 이전 대화 기록을 스크롤하거나 복사할 수 없다. 장기 메모리는 이런 환경에서 특히 필수적이다. 사용자가 어제 설정한 습관 트래커, 오늘 아침에 물어봤던 일정을 에이전트가 자연스럽게 참조할 수 있어야 실용적 비서가 된다. 2026년 에이전트 메모리 시장이 연 35% 성장을 기록하는 배경에는 음성·차량·IoT 디바이스로 AI가 확산되는 흐름이 있다.

6. 실용적 평가 — 무엇을 기대할 수 있고 무엇을 조심해야 하나

6.1 강점이 실제로 작동하는 곳

Memora가 가장 직접적 가치를 내는 시나리오는 명확하다. 며칠~수 주에 걸친 코딩 프로젝트, 사용자 선호와 이력을 누적해야 하는 개인 비서, 여러 에이전트가 공유 컨텍스트로 분업해야 하는 다중 에이전트 시스템, 문서가 누적되는 지식 관리 파이프라인이 대표 사례다. LoCoMo·LongMemEval 벤치마크에서 시간적 추론과 다중 홉 질문이 크게 향상된 것은 이 시나리오와 직결된다.

6.2 아직 주의해야 할 지점

솔직하게 써야 할 주의점도 있다. 첫째, ICML 2026 제출 단계로 아직 동료 심사를 거치지 않았다. 공개된 벤치마크 수치는 저자 측 결과이며 독립 검증이 필요하다. 둘째, 10배 스케일에서 시간 추상화 성능이 25% 저하된다는 점이 보고됐다. 장기 기억이 수백만 항목으로 늘어날 때의 거동은 아직 불확실하다. 셋째, GRPO 전략은 실험적 단계로, 프로덕션 환경에서는 신중한 검증이 필요하다. 넷째, ChromaDB 기본 설정 외 대규모 분산 저장소와의 통합은 별도 작업이 필요하다.

6.3 도입 시 현실적 접근

Memora를 도입하려는 팀에게 권하는 경로는 간단하다. 본인의 에이전트 작업에서 "어제 결정한 X를 오늘 기억하지 못해 문제가 생긴 적이 있는가"를 먼저 확인하라. 그런 사례가 있다면, 장기 메모리 레이어의 가치가 실증된다. Memora는 기존 에이전트 시스템에 플러그인처럼 추가할 수 있도록 설계됐고, Python 3.10 이상에서 pip install -e .로 설치된다. 작은 작업부터 실험하고, LoCoMo 벤치마크 스크립트로 직접 성능을 검증해 보는 것이 현실적인 시작점이다.

7. 결론 — 장기 기억이 에이전트의 다음 층위를 연다

Memora가 던지는 핵심 질문은 단순하다. AI 에이전트가 진정한 장기 협업자가 되려면, 기억이 필요하다. 컨텍스트 윈도우를 무한정 늘리는 방향이 아니라, 무엇을 기억할지 선택하고 구조화하는 방향이 현실적이고 비용 효율적이다.

Memora의 세 계층 구조(Memory Value / Primary Abstraction / Cue Anchors)는 이 문제에 대한 하나의 명확한 답이다. 원본 정보와 검색 인덱스를 분리하고, 갱신 가능한 정준 단위를 두고, 다중 의미 진입점으로 회수 정밀도를 높이는 설계는 기존 RAG와 평면 메모리의 한계를 잘 짚고 있다.

아직 초기 공개 단계이며 대규모 환경의 검증이 남아 있다. 그러나 이 방향 자체 — 에이전트가 며칠에 걸친 작업을 이어가는 것 — 는 2026년 AI 에이전트가 생산성 도구로 실용화되는 핵심 조건이다. Memora는 그 방향의 구체적인 첫 번째 구현 중 하나로 살펴볼 가치가 있다.
