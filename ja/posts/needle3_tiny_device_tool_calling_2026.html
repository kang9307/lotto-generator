1. 小型機器特化型ファウンデーションモデルの登場背景と設計目的

一般的に、言語モデルを組み込みマイコンや小型ハードウェアに直接搭載して稼働させる処理は、利用可能なメモリや計算資源の物理的制約に直面します。

Cactus Computeはこの小型機器環境を対象として「Needle 3」モデルを公開しました。公式GitHubリポジトリ（https://github.com/cactus-compute/needle）の説明によると、Needle 3は「スマートフォン、ウェアラブル、スマートホーム、ロボット、車載、マイコンにおいてツール呼び出し、構造化抽出、埋め込みを実行する2ビット、8〜29MBの自動化基底モデル（Automation foundation model for tiny devices: 2-bit, 8-29 MB, tool calls, structured extraction and embeddings on phones, wearables, smart homes, robots, cars and microcontrollers）」と記述され、Apache-2.0ライセンスで配布されています。製品ページ（https://cactuscompute.com/needle）においてCactusは、「The whole model is a single 8-29 MB binary built on our Simple Attention Network, and we trade general chat capacity to beat models 10x its size on mobile tool calls and match 2-3x bigger models on extraction」と記しています。

この記述の解釈としては、原文はモデルの役割を一般的な対話文の作成ではなく機器ツールの選定と引数充足に絞り込むことで、極小バイナリを維持する設計をとっています。製品ページ（https://cactuscompute.com/needle）に記載された具体的な適用対象と英語原文は以下の通りです。

  • スマートホーム: 「"Dim the bedroom and lock up" becomes two calls, executed offline, with no hub round trip.」
  • ロボット: 「"clean the kitchen but leave the bedroom", "go back to the dock when you are done". Each becomes a sequence of moves it can execute.」
  • スマートフォン: 「make an album from last weekend's photos, open a site, dim the screen, find the lease in your files.」
  • ウェアラブル: 「a card charge into merchant, amount and date; a message into a reply; a complaint into a sentiment flag.」
  • 車載（Automotive）: 「Climate, media, navigation and calls from requests in the cabin, with the tool set pinned so it survives a long drive's worth of conversation.」
  • 検索とマッチング: 「semantic search over notes, messages and documents; a query matched to the closest of hundreds of tools; near-duplicate alerts merged on a watch.」

2. 主要機能3種と入出力仕様 — ツール呼び出し・構造化抽出・埋め込み

Needle 3の機能範囲は、README（https://github.com/cactus-compute/needle）においてツール呼び出し（Tool calls）、構造化抽出（Structured extraction）、テキスト埋め込み（Text embedding）の3種として明記されています。

ツール呼び出しと文法制約下の抽出

ツール呼び出しについて、READMEには次のように記載されています。「given the functions your app exposes, Needle picks the right ones and fills every argument from what the user said. Ask for two things and you get two calls in order; ask for something no tool covers and you get an empty list, not a guess.」すなわち、対応ツールが存在しない要求に対しては推測を行わず空リストを返却すると説明されています。

構造化抽出について、原文は「declare a shape, hand over messy text, get typed fields back: an invoice, a booking, a notification, a form. The decode grammar guarantees the output parses, and extraction generalises to classification」と記しています。デコード文法が出力の構文解析成功を保証する仕様です。

単一モデルによるオンデバイスベクトル埋め込み

テキスト埋め込みについて、原文は「the same model returns a vector for a sentence, so an app can search, match and route locally: find the note you mean, pick the tool closest to a request, collapse duplicate alerts」と説明しています。同一のバイナリから文ベクトルを算出し、ローカル環境での検索やルーティングに充当する仕組みです。

この記述の解釈としては、原文が説明する3つの機能は、機器制御、データ構文解析、ローカル意味検索というエッジ作業を単一のバイナリパッケージ内で処理できるように統合した構成です。

機能分類 入力形式 出力形式 原文記載の挙動および制約仕様
ツール呼び出し（Tool calls） ユーザプロンプト + Python関数デコレータ / スキーマ定義 構造化JSONオブジェクト（選択関数、引数マップ、推論根拠、信頼度） 順次複数呼び出しを支援、対象外の要求に対しては当て推量を排除し空リスト（[]）を返却

製品ページ（https://cactuscompute.com/needle）のツール記述（Writing tools）項目に記載された原則は以下の通りです。

  • ツール範囲: 「a narrow tool with a plain description beats a broad one. One tool per action, described by the actions it covers ("Turn a room's lights on or off") rather than a category.」
  • 列挙型定義: 「Name enum options after what a user says (action: ["increase", "decrease"]) and keep synonyms in the description.」
  • 引数処理: 「Give a required argument a default when a request may leave it out; a required argument with no default and no evidence in the request is withheld rather than guessed.」
  • 値の書式: 「Put value formats in descriptions ("City, ST", "e.g. T-1042"). Add triggers to intents that must always reach a tool, and keep the toolset per turn small.」

3. ラダー型シンプルアテンション（Laddered Simple Attention）アーキテクチャ

Needle 3の内部構造について、README（https://github.com/cactus-compute/needle）は次のように記しています。「Needle 3 is a Laddered Simple Attention Network: a Monarch Hadamard MLP in place of the FFN, GQA attention with causal conv taps, engram n-gram memory read by gather, and multi-lane hyper-connections, trained so that every depth from 2 to 20 layers is a deployable model.」

FFNを代替するモナーク・アダマールとmHC構造

製品ページ（https://cactuscompute.com/needle）の構造図（Figure 1）に記載された仕様は以下の通りです。モデルは20層、隠れ層次元768、総計121Mパラメータを有します。トークナイザには語彙数8,192のSentencePiece BPEが用いられ、重み共有（8,192 × 768）のtied unembed構成をとります。残差結合は4レーンを読み書きするmHCであり、sandwich ZCRMSNormが適用されます。アテンション機構は12q : 2kvのGQA比率、各チャンネル3タップの因果畳み込み、局所窓1,024トークン、RoPE、QK正規化を備え、第4、9、14、19層にグローバルアテンションが配置されています。

FFNを代替するMonarch Hadamardブロックは32 × 32の演算を用います。図のキャプションにおいてCactusは、「Figure 1. The architecture spends over 2x fewer MFLOPs per token than a transformer of the same configuration」と述べています。

エングラム（Engram）メモリとパラメータ構造

構造図は、121Mパラメータのうち70.8Mがエングラムテーブル（第3、7、11、15、19層に位置する18,432スロット、gather演算で読み出されるハッシュ化2-gramおよび3-gramメモリ）に存在することを示しています。READMEはこれについて、「Most of its parameters sit in the engram, so the 121M model does the arithmetic of a 50M one」と説明しています。

学習に関して製品ページは、「360B tokens of proprietary structured dataset」を使用し、訓練時のみ適用されるt+2補助ヘッド（mtp t+2 aux head）を備えていたと記載しています。配布形式はCQ2 2ビット量子化バイナリであり、選択層数に応じて8MBから29MB（製品ページ本文では9 to 29 MB）のバイナリを生成します。要点は以下の通りです。

  • 階層型サブモデル: 2層から20層までのすべての深さが独立して配備可能なモデルとして訓練されている
  • バイナリ規模: 選択した深さに応じて8MBから29MBまでの単一CQ2 2-bitバイナリとして生成される
  • 文法制約: スキーマから構築されたバイトレベル文法が各トークンの生成空間を制限する
  • 校正ヘッド: 学習済みヘッドからターンごとに校正された信頼度スコアを出力する

4. インストール手順とPythonによるツール定義コード

Needle 3の導入手順は、README（https://github.com/cactus-compute/needle）において以下のコマンドを実行することと案内されています。推論エンジンはHugging Face（https://huggingface.co/Cactus-Compute/needle3）から初回に自動取得されキャッシュされます。

pip install cactus-needle

ツールの定義と実行に関してREADMEは、関数シグネチャが引数型を与え、docstringがツールの説明となり、run()メソッドが実行と結果返却のサイクルを完結させると説明しています。掲載されたコードは以下の通りです。

import needle

@needle.tool
def get_weather(city: str):
    "Get the current weather for a city."
    return {"city": city, "temp_c": 27, "sky": "clear"}

agent = needle.Needle(tools=[get_weather])
print(agent.run("what's it like in Lagos right now?")["results"])
# [{'city': 'Lagos', 'temp_c': 27, 'sky': 'clear'}]

原文は、各ターンがfunction_calls、reasoning、校正済みconfidenceを含む単一のJSONオブジェクトを返却し、対象外の要求に対しては空リストを返却すると記載しています。既存の配備環境を維持するため、needle.Needle(tools=[...], generation=2)によって旧世代のNeedle 2を動作させることも可能です。

5. ベンダー公表のベンチマーク性能と測定条件の詳細

Needle 3の性能評価値は、Cactus Computeが製品ページ（https://cactuscompute.com/needle）および評価プロット上で公表した独自計測値です。

Raspberry Pi 5における公表トークン処理速度

CactusはRaspberry Pi 5実機において、秒間400〜4,000トークンのデコード速度（400-4k tokens/s decode）および秒間1,000〜10,000トークンのプリフィル速度（1-10k tokens/s prefill）を記録したと公表しました。また製品ページのサンプルJSON応答では、peak_ram_mbの値が28.5と表記されています。

ファインチューニングによるサブネットワーク性能推移

評価基準についてREADMEは、「Tool calling is exact-match accuracy on the full test splits, extraction is field micro-F1 on the full test splits」と明記しています。Figure 2キャプションは、Needle 3サブネットワーク（20、16、8、4層）が出荷CQ2 2-bitバイナリで動作し、ベースライン群はvLLM f16で、DeepSeek V4 FlashはクラウドAPIで測定されたと説明しています。

CactusはDroidCallによる微調整時に各サブネットワークのスコアが18〜36ポイント向上し、4層（29Mパラメータ）以上でDeepSeek V4 Flashを上回ると主張しました（「fine-tuning on DroidCall lifts every subnetwork by 18 to 36 points, and from 4 layers up the tuned subnetwork passes DeepSeek V4 Flash, starting at 29M parameters (Figure 3)」）。製品ページに列挙された6つの評価スイートの行数と測定基準は以下の通りです。

  • Mobile Actions: 961行、電話コマンドをAndroidインテントに変換、完全一致（exact call）で評価
  • DroidCall: 200行、2回の呼び出しを要する項目を含む、順序保証完全一致（exact calls in order）で評価
  • BFCL v4: 3,641行、Berkeley単一ターン関数呼び出し、AST一致および無関係要求時の非呼び出しを評価
  • DSTC8: 1,813ターン、対話スロットのスキーマ抽出、フィールドF1で評価
  • SNIPS gold: 700行、スキーマ既知でのスロット充填、フィールドF1で評価
  • SNIPS 7-way: 700行、7つのスキーマ候補から選択してスロット充填、フィールドF1で評価

6. 信頼度ゲーティングと正規表現トリガーによるオンデバイス実行制御

Needle 3は実行の制御のため、信頼度（confidence）スコアと正規表現（triggers）オプションを提供しています。

信頼度フロア0.1と拒絶ロジック

原文によると、モデルの応答JSONには校正済みヘッドから出力されたconfidenceスコアが含まれます。推論エンジンは0.1のフロア（下限値）を適用しており、算出値が0.1を下回ると呼び出しはsuppressed_callsへ退避され、function_callsは空リストとして返されます。

Cactusが示した制御コードは、confidenceが0.7以上の場合はツールを実行（execute）し、0.1〜0.7の範囲あるいはsuppressed_callsが存在する場合は利用者に確認（confirm）を行い、呼び出しが存在しない場合は拒絶メッセージを出力するパターンをとります。また、triggersが設定されたツールは入力文と合致した際にデコードが該当ツールへ限定され、0.1のフロア未満であっても呼び出しが生成されます。

コミュニティ検証で報告された現実の限界と注意点

GeekNews（https://news.hada.io/topic?id=33923）などの初期報告では、ベンダー公表値と区別される以下の限界点が指摘されています。

  • 語彙の曖昧性に対する脆弱性: 多義語や短縮表現が入力された際に意図しないツールが呼び出される現象（浴室の照明を意図した「wee」が音楽ジャンル検索ツールとして解釈される誤作動事例など）
  • 体感性能に関する評価: 大規模モデルのような汎用推論を想定した場合に期待と異なる動作をし、宣伝に対して体感性能が誇大に感じられるという反応
  • スキーマ記述への依存: docstringやパラメータ命名、スキーマ定義の精緻さがシステム結果を左右する点
  • 極小サブモデルの限界: 2〜4層に圧縮した際、下流タスクへの微調整を行わなければ基本精度が低下する懸念
  • ツール数の制限: 1ターンに公開されるツール数が増えるほど誤判定率が高まるため、ターンあたりのツール数を少数に保つ必要がある点

7. 確認できなかった事項

公開資料およびリポジトリから客観的に確認できなかった事項は以下の通りです。

  • 正式なリリース日時の特定: 公式READMEおよび製品ページには「Today we release Needle 3」とのみ記されており、日付の記述がないため正確なリリース日を原文から確認できず
  • 独立ベンチマークの再現データ: Raspberry Pi 5での速度やDroidCall微調整時のDeepSeek V4 Flash超過数値はCactus独自の発表であり、中立的な第三者機関による検証データを確認できず
  • 事前学習データセットの詳細構成: 360Bトークンの独自構造化データセットについて、具体的な収集元比率やライセンス条件が公開資料に記載されていない
  • 独自量子化形式（.cact）の仕様: 出荷バイナリに適用されたCQ2 2ビット量子化アルゴリズムの厳密な数学的定義や誤差プロファイルが技術文書に詳述されていない
