引言 - 只改了一个字段，其他值也一起消失

为了只修改资料中的bio，用PATCH发送了{"bio":"new"}，响应里却没有了name和nickname。服务器代码只是普通的body.get(...)。事故的根源是服务器把「键不存在」和「值为null」读成了同一种状态。在JSON文档中这两种状态的文字不同：一个写着"x":null，另一个根本没有x这个名字。但许多语言的读取API默认对两者返回相同的值。

先约定术语。「null」是JSON字面量null。「键不存在」是对象中没有该名字的成员。undefined是JavaScript的值，JSON语法里没有它。三种表达是{"x":null}、{}，以及JavaScript序列化{x: undefined}得到的结果。下面用输出展示Python、Node、PowerShell如何读写这三者，并向本地服务器实际发送请求，观察PATCH中各自引起的状态变化。

涉及的问题如下。

  • JSON语法和RFC 7396分别如何定义null与键不存在？
  • Python的dict.get、Node的d.x、PowerShell的$o.x能区分这两种状态吗？
  • 无法区分的get写法在PATCH中删除值的过程如何复现？
  • 能够区分的安全写法是什么，输出有何不同？
  • 序列化阶段键会消失的是哪些工具的哪些值？

文档的规定 - JSON语法、Merge Patch、语言文档

先汇集作为依据的语句。下面列表中的英文是原文。

  • RFC 8259第3节：A JSON value MUST be an object, array, number, or string, or one of the following three literal names: false, null, true. 值的列表中没有undefined。
  • RFC 8259第4节：The names within an object SHOULD be unique. 对象由名字与值的对组成，没有名字的成员不在对象之中。
  • RFC 7396概述：Null values in the merge patch are given special meaning to indicate the removal of existing values in the target. 补丁中的null不是值，而是删除指令。
  • RFC 7396第1节：...do not make use of explicit null values. The merge patch format is not appropriate for all JSON syntaxes. RFC自己写明，文档把null当作值使用时这种格式并不合适。
  • Python文档中的dict.get：If default is not given, it defaults to None, so that this method never raises a KeyError. 仅凭返回值无法区分键不存在与值为None的键。
  • MDN的in运算符：A property may be present in an object but have value undefined. Therefore, "x" in obj is not the same as obj.x !== undefined.

RFC 7396的伪代码（第2节）可以概括为一句话：补丁中成员的值为null时，若目标中存在该名字就删除，否则递归合并该值。补丁里没有名字的成员不会被处理，因此在目标中原样保留。「null表示删除，键不存在表示不变」就是这种格式的全部，因此服务器若不能区分两种状态，这种格式就无法成立。

Python - get的默认值只在键不存在时生效

import json
                    
                    for text in ['{"x": null}', '{}']:
                        d = json.loads(text)
                        print(text.ljust(11), '| repr:', repr(d), '| get("x"):', repr(d.get('x')),
                              '| get("x", 0):', repr(d.get('x', 0)), '| "x" in d:', 'x' in d)
                    
                    # Python has no undefined; None is serialized as null and the key stays
                    print(json.dumps({'x': None}), json.dumps({}))
                    
                    MISSING = object()  # sentinel: a value no JSON document can contain
                    
                    def classify(d, key):
                        v = d.get(key, MISSING)
                        if v is MISSING:
                            return 'missing'
                        return 'null' if v is None else 'value'
                    
                    for text in ['{"x": null}', '{}', '{"x": 0}', '{"x": ""}']:
                        print(text.ljust(11), '->', classify(json.loads(text), 'x'))

输出如下。

{"x": null} | repr: {'x': None} | get("x"): None | get("x", 0): None | "x" in d: True
                    {}          | repr: {} | get("x"): None | get("x", 0): 0 | "x" in d: False
                    {"x": null} {}
                    {"x": null} -> null
                    {}          -> missing
                    {"x": 0}    -> value
                    {"x": ""}   -> value

d.get("x")对两个文档都是None。区别体现在默认值参数上：d.get("x", 0)只在键不存在时返回0，对值为null的键则原样返回None。默认值是「键不存在时」的值，不是「值为空时」的值。"x" in d只回答键是否存在，所以对两个文档分别是True和False。

json.dumps({"x": None})生成{"x": null}。Python没有undefined，所以「为空」总是None，序列化后键仍以null保留。要得到键不存在，必须不放入该键或把它从字典中删除。以哨兵MISSING = object()为默认值的classify把四个输入分为null、missing、value、value。空字符串和0是值，不是null。

Node - undefined在读取时可区分，在序列化时消失

for (const text of ['{"x": null}', '{}']) {

                    {}          | d.x: undefined | d.x === undefined: true | "x" in d: false | Object.hasOwn: false
                    default {}           -> DEFAULT
                    default {x: null}    -> null
                    default {x: undefined} -> DEFAULT

在JSON.parse生成的对象中，{"x": null}的d.x是null，{}的d.x是undefined。也就是说Node在读取时就按值区分了两种状态：d.x === undefined表示键不存在，d.x === null表示null。in和Object.hasOwn回答键本身是否存在，对两个文档分别是true和false。

区分消失在默认值语法中。解构的默认值{ x = "DEFAULT" }只对undefined生效，因此对{}和{x: undefined}返回DEFAULT，对{x: null}返回null。相反，??会把null和undefined都换成默认值，把两种状态合并为一。同样叫「默认值」的两种语法，一个区分，一个合并。

  • 直接比较值的读取方式（get、$o.x -eq $null）无法区分两种状态。
  • 询问键是否存在的读取方式（in、Object.hasOwn、属性列表）在三种工具中都能区分两种状态。
  • Node也能按值区分，但一旦把undefined当作值处理，序列化时键就会消失。

PATCH端点 - 实现RFC 7396语义的127.0.0.1服务器

一台服务器上放三个处理器。/naive在body.get为None时删除字段，/skipnull在为None时跳过，/merge使用把RFC 7396伪代码原样转写的merge_patch。状态是内存中的字典，用POST /reset恢复。所有文件只在临时文件夹内创建，套接字只在回环地址（127.0.0.1）上打开，并设置了180秒后自行退出的保护。

import json, os, sys, threading
                    from http.server import BaseHTTPRequestHandler, HTTPServer
                    
                    INITIAL = {'name': 'kim', 'nickname': 'kk', 'bio': 'hello'}
                    FIELDS = ['name', 'nickname', 'bio']
                    STATE = {'naive': dict(INITIAL), 'skipnull': dict(INITIAL), 'merge': dict(INITIAL)}
                    
                    
                    def apply_naive(user, body):
                        # get() returns None for a missing key and for an explicit null alike
                        for k in FIELDS:
                            v = body.get(k)
                            if v is None:
                                user.pop(k, None)
                            else:
                                user[k] = v
                    
                    
                    def apply_skipnull(user, body):
                        for k in FIELDS:
                            v = body.get(k)
                            if v is not None:
                                user[k] = v
                    
                    
                    def merge_patch(target, patch):
                        # the MergePatch pseudo-code of RFC 7396 section 2
                        if isinstance(patch, dict):
                            if not isinstance(target, dict):
                                target = {}
                            for name, value in patch.items():
                                if value is None:
                                    if name in target:
                                        del target[name]
                                else:
                                    target[name] = merge_patch(target.get(name), value)
                            return target
                        return patch
                    
                    
                    class H(BaseHTTPRequestHandler):
                        def log_message(self, *a):
                            pass
                    
                        def _send(self, code, obj):
                            raw = json.dumps(obj, sort_keys=True).encode()
                            self.send_response(code)
                            self.send_header('Content-Type', 'application/json')
                            self.send_header('Content-Length', str(len(raw)))
                            self.end_headers()
                            self.wfile.write(raw)
                    
                        def _which(self):
                            first = self.path.strip('/').split('/')[0]
                            return first if first in STATE else None
                    
                        def do_GET(self):
                            w = self._which()
                            self._send(200, STATE[w]) if w else self._send(404, {'error': 'unknown path'})
                    
                        def do_POST(self):
                            if self.path != '/reset':
                                return self._send(404, {'error': 'unknown path'})
                            for k in STATE:
                                STATE[k] = dict(INITIAL)
                            self._send(200, {'reset': True})
                    
                        def do_PATCH(self):
                            w = self._which()
                            if w is None:
                                return self._send(404, {'error': 'unknown path'})
                            body = json.loads(self.rfile.read(int(self.headers.get('Content-Length', 0))))
                            if w == 'naive':
                                apply_naive(STATE[w], body)
                            elif w == 'skipnull':
                                apply_skipnull(STATE[w], body)
                            else:
                                STATE[w] = merge_patch(STATE[w], body)
                            self._send(200, STATE[w])
                    
                    
                    if __name__ == '__main__':
                        srv = HTTPServer(('127.0.0.1', int(sys.argv[1])), H)  # loopback only
                        print('pid', os.getpid(), 'listening on 127.0.0.1:' + sys.argv[1], flush=True)
                        t = threading.Timer(180, lambda: os._exit(0))  # safety: exit by itself after 180 s
                        t.daemon = True
                        t.start()
                        srv.serve_forever()

客户端是curl。把同样的三个请求依次发给三个处理器：只改一个字段的{"bio":"new"}、删除一个字段的{"nickname":null}、什么都不改的{}。每次请求前都把状态恢复为初始值（name=kim、nickname=kk、bio=hello）。

B=http://127.0.0.1:18765
                    patch() {
                      printf 'PATCH /%s %-24s -> ' "$1" "$2"
                      curl -s -X PATCH -H 'Content-Type: application/merge-patch+json' -d "$2" "$B/$1"
                      echo
                    }
                    reset() { curl -s -X POST "$B/reset" > /dev/null; }
                    
                    echo "initial: $(curl -s $B/merge)"
                    for h in naive skipnull merge; do
                      echo "== $h"
                      reset; patch $h '{"bio":"new"}'
                      reset; patch $h '{"nickname":null}'
                      reset; patch $h '{}'
                    done
                    echo "== nested object (merge)"
                    reset; patch merge '{"bio":"new","extra":{"a":1}}'
                    patch merge '{"extra":{"a":null,"b":2}}'

get写法删除值的复现 - 三个处理器的结果

initial: {"bio": "hello", "name": "kim", "nickname": "kk"}
                    == naive
                    PATCH /naive {"bio":"new"}            -> {"bio": "new"}
                    PATCH /naive {"nickname":null}        -> {}
                    PATCH /naive {}                       -> {}
                    == skipnull
                    PATCH /skipnull {"bio":"new"}            -> {"bio": "new", "name": "kim", "nickname": "kk"}
                    PATCH /skipnull {"nickname":null}        -> {"bio": "hello", "name": "kim", "nickname": "kk"}
                    PATCH /skipnull {}                       -> {"bio": "hello", "name": "kim", "nickname": "kk"}
                    == merge
                    PATCH /merge {"bio":"new"}            -> {"bio": "new", "name": "kim", "nickname": "kk"}
                    PATCH /merge {"nickname":null}        -> {"bio": "hello", "name": "kim"}
                    PATCH /merge {}                       -> {"bio": "hello", "name": "kim", "nickname": "kk"}
                    == nested object (merge)
                    PATCH /merge {"bio":"new","extra":{"a":1}} -> {"bio": "new", "extra": {"a": 1}, "name": "kim", "nickname": "kk"}
                    PATCH /merge {"extra":{"a":null,"b":2}} -> {"bio": "new", "extra": {"b": 2}, "name": "kim", "nickname": "kk"}

向/naive发送{"bio":"new"}，响应只剩{"bio": "new"}。请求中没有的name和nickname被删除了。处理器遍历字段列表并读取body.get(k)，请求中没有的名字变成None，而None被当作删除处理。上面的代码与输出直接显示了这一点。发送{}时响应同样是{}：什么都不改的请求删除了所有字段。

/skipnull表现出相反的错误。它对键不存在是安全的，但发送{"nickname":null}后nickname仍保持kk，删除请求被悄悄忽略。只有/merge对三个请求都按预期工作：只有bio改变，只有nickname消失，{}什么都不改。对嵌套对象，{"extra":{"a":null,"b":2}}也只删除extra里的a。

请求/naive（None则删除）/skipnull（None则跳过）/merge（RFC 7396）
{"bio":"new"}name和nickname被删除只改bio只改bio
{"nickname":null}所有字段被删除nickname保留（被忽略）只删除nickname
{}所有字段被删除无变化无变化

能区分的安全写法 - 哨兵、in、对象展开

上一节的merge_patch用name in target和for name, value in patch.items()来区分。按名字遍历补丁对象只会访问请求中有的键，所以不存在的键碰不到。规则只有一条：键是否存在用in（或遍历）来问，之后再问值是否为null，不要由值去推断存在。

哨兵是在默认值位置放一个JSON无法产生的值。Python的object()不可能出现在任何JSON文档中，所以d.get(key, MISSING)返回MISSING就表示键不存在。对象默认值体现在展开语法中。下面是把请求体叠加到默认值对象上的代码与输出，Python的{**defaults, **body}方式相同。

const defaults = { name: 'kim', nickname: 'kk' };
                    console.log(JSON.stringify({ ...defaults, ...JSON.parse('{}') }));
                    console.log(JSON.stringify({ ...defaults, ...JSON.parse('{"nickname": null}') }));
                    const undef = { ...defaults, ...{ nickname: undefined } };
                    console.log(undef, 'nickname' in undef, JSON.stringify(undef));
{"name":"kim","nickname":"kk"}
                    {"name":"kim","nickname":null}
                    { name: 'kim', nickname: undefined } true {"name":"kim"}
import json
                    defaults = {'name': 'kim', 'nickname': 'kk'}
                    print({**defaults, **json.loads('{}')})
                    print({**defaults, **json.loads('{"nickname": null}')})
                    print(json.dumps({**defaults, **{'nickname': None}}))
{'name': 'kim', 'nickname': 'kk'}
                    {'name': 'kim', 'nickname': None}
                    {"name": "kim", "nickname": null}

叠加{}时默认值保持不变，叠加{"nickname": null}时nickname变为null，区别得以保留。但在JavaScript中叠加{nickname: undefined}时，默认值kk会被undefined覆盖，序列化后nickname整个消失，只剩{"name":"kim"}。展开是以键是否存在为基准来覆盖的，in输出true的那一行正说明了这一点。

  • 哨兵：像get(key, MISSING)那样，把JSON无法产生的值放在默认值位置。
  • in、Object.hasOwn、属性列表：读取值之前先问键是否存在。
  • 遍历补丁对象：只访问请求中有的名字，不存在的名字不会成为修改对象。
  • 对象默认值加展开：键不存在则保留默认值，但JavaScript的undefined值会被当作存在的键而覆盖。

序列化阶段键消失的情况 - 按工具对照

即使读取时保持了区分，如果客户端在发送时丢失了区分，同样的事故也会发生。先看Node的JSON.stringify。

                    console.log(JSON.stringify({ x: null }));
                    console.log(JSON.stringify({ a: 1, x: undefined, b: 2 }));
                    console.log(JSON.stringify([undefined, null, function () {}]));
                    console.log(JSON.stringify(undefined));
                    const merged = Object.assign({ x: 1 }, { x: undefined });
                    console.log(merged, Object.keys(merged), JSON.stringify(merged));
{}
                    {"x":null}
                    {"a":1,"b":2}
                    [null,null,null]
                    undefined
                    { x: undefined } [ 'x' ] {}

MDN关于JSON.stringify的文档写道：undefined, Function, and Symbol values are not valid JSON values. If any such values are encountered during conversion, they are either omitted (when found in an object) or changed to null (when found in an array). 输出正是如此。对象中的x: undefined连同键一起消失，数组中的undefined和函数变成null。顶层的undefined返回值undefined而不是JSON文本。最后一行Object.assign的结果是键仍存在的{ x: undefined }，但它的序列化结果是{}。

这一差异在PATCH中会变成怎样的状态变化，通过把三种工具生成的请求体原样发给同一服务器的/merge来确认。三种工具都是出于「清空nickname」的同一意图编写的。

B=http://127.0.0.1:18765
                    send() {
                      printf '%-10s body=%-20s -> ' "$1" "$2"
                      curl -s -X PATCH -H 'Content-Type: application/merge-patch+json' -d "$2" "$B/merge"
                      echo
                    }
                    reset() { curl -s -X POST "$B/reset" > /dev/null; }
                    
                    js=$(node -e "console.log(JSON.stringify({nickname: undefined}))")
                    py=$(python -c "import json; print(json.dumps({'nickname': None}))")
                    ps=$(powershell -NoProfile -Command "[pscustomobject]@{ nickname = \$null } | ConvertTo-Json -Compress")
                    reset; send node "$js"
                    reset; send python "$py"
                    reset; send powershell "$ps"

从症状到原因 - 检查顺序与相邻文章

前面的输出给出了症状与原因的对应关系。检查按症状逐步缩小范围。

  • 只改一个字段却删除了其他字段：检查服务器处理器是否把get的None当作删除（/naive的症状）。
  • 清空值的请求被忽略：检查null是否被当作跳过处理（/skipnull的症状）。
  • JavaScript客户端的删除请求在服务器上没有任何效果：检查请求体中是否有undefined，以及JSON.stringify的结果中是否有该键。
  • 有字段需要把null作为值保存：在RFC 7396的伪代码中null始终表示删除，因此该字段无法用Merge Patch表达，需要使用其他格式或按字段使用明确的值。
  • 想只改数组的一部分：在伪代码中，非对象的补丁会替换整个目标，所以数组要整体发送。
