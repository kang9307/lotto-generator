1. 1.58비트 장벽이라는 상식과 그 뒤에 숨은 가정

거대 언어 모델(LLM)의 양자화와 가중치 압축 연구에서 3진(ternary) 신경망은 효율성의 극단을 상징하는 중요한 기준점으로 다루어져 왔다. 부동소수점 16비트나 8비트, 4비트 정밀도에서 내려와 가중치를 단 세 가지 상태인 {-1, 0, +1} 중 하나로만 제한하는 3진 모델은, 행렬 곱셈 연산에서 고비용의 부동소수점 곱셈기를 제거하고 단순 덧셈과 뺄셈, 부호 반전만으로 추론을 완결할 수 있게 돕는다. 이러한 특성은 메모리 대역폭과 연산 에너지가 극도로 제한된 모바일 및 엣지 장치에서 거대 모델을 직접 구동하기 위한 핵심 기술로 주목받아 왔다.

이 과정에서 컴퓨터 아키텍처 학계와 인공지능 엔지니어링 실무 전반에 걸쳐 일종의 불문율처럼 통용되던 이론적 기준선이 존재했다. 바로 정보이론(Information Theory)에 근거한 가중치당 log₂3 ≈ 1.585비트라는 하한선이다. 세 가지 상태를 수학적으로 구별하여 표현하기 위해 요구되는 엔트로피 하한이 1.585비트이므로, 3진 모델의 저장 용량은 어떠한 무손실 압축 기법을 적용하더라도 가중치당 1.58비트 밑으로 내려갈 수 없다는 인식이 오랜 기간 확고한 장벽으로 자리 잡았다.

그러나 정보이론의 하한선은 언제나 특정한 수학적 전제 조건 위에서만 성립한다. 클로드 섀넌의 정보 엔트로피 공식에서 세 기호가 정확히 1.585비트의 평균 정보량을 갖는 유일한 조건은, 각 기호가 출현할 확률이 각각 3분의 1(p = 1/3)로 완벽히 동일한 균등 분포(equiprobable distribution)를 이룰 때뿐이다. 만약 가중치 행렬 내부에서 세 기호의 출현 빈도가 특정 값으로 심하게 쏠려 있다면, 실제 정보 엔트로피는 1.585비트보다 훨씬 낮아질 수밖에 없다.

모델의 비트 폭 축소와 양자화 정밀도 한계에 관해서는 앞서 붕괴 지점 분석에서 지표별 성능 파괴 양상을 다룬 바 있으며, 실제 연산 요구량과 가중치 크기의 관계는 소형 모델의 실무적 효용성 및 모델 크기와 메모리 추정 방법에서도 구조적으로 짚은 바 있다. 2026년 공개된 최신 연구는 3진 가중치라는 좁고 구체적인 영역에서, 오랜 시간 의심 없이 받아들여지던 1.58비트라는 장벽이 실전 모델에서 어떻게 무너졌는지를 수학적 분포 분석과 시스템 엔지니어링 구현으로 입증한다.

2. 51.5%의 0 — 실전 3진 LLM에서 발견된 비대칭 분포

Evangelos Georganas, Alexander Heinecke, Pradeep Dubey가 발표한 논문 「Breaking the 1.58-bit Barrier for Ternary LLMs」(arXiv:2609.16338)는 바로 이 근본적인 전제에 의문을 제기하는 것에서 출발한다. 연구팀은 이론적 추정에 머무르지 않고, 실제로 학습 및 배포된 29개의 3진 LLM 모델을 수집하여 가중치 행렬 내부의 기호 출현 빈도를 정밀하게 전수 조사했다.

그 측정 결과는 기존의 관례적 가정을 정면으로 뒤흔들었다. 29개 모델 전반에서 가중치 기호 {-1, 0, +1}은 결코 균등하게 분포하지 않았다. 특히 영(0) 값의 가중치가 차지하는 비중이 압도적으로 높았으며, 조사 대상 모델 가운데 0의 비율이 가장 높게 나타난 모델에서는 전체 가중치의 무려 51.5%가 0으로 채워져 있었다.

가중치의 절반 이상이 0이라는 사실은 정보이론적 관점에서 지대한 함의를 갖는다. 세 상태의 출현 확률을 각각 p₀, p₊, p₋라 할 때, 섀넌 엔트로피는 H = -(p₀ log₂ p₀ + p₊ log₂ p₊ + p₋ log₂ p₋)로 정의된다. 만약 0의 출현 확률 p₀가 0.515에 도달하고 나머지 0.485가 +1과 -1에 대칭적으로 양분된다고 가정하면, 이 시스템의 진정한 이론적 정보 엔트로피는 1.48비트 안팎으로 급격히 낮아진다.

즉, 1.585비트라는 수치는 '가장 무질서한 상태(완전 균등 분포)'를 가정한 가상의 천장이었을 뿐, 실제 기계학습 최적화 과정을 거쳐 수렴한 3진 신경망 가중치는 이미 고도의 구조적 편향과 0 중심의 희소성(sparsity)을 강하게 내포하고 있었던 셈이다. 신경망이 학습 과정에서 불필요한 가중치 연결을 0으로 억제하면서 생겨난 자연스러운 불균등 분포가, 이론적 장벽이라는 착시를 깨뜨릴 수 있는 결정적인 열쇠가 되었다. 실전 3진 LLM의 가중치 분포가 보여주는 핵심 특성은 다음과 같이 요약된다.

  • 가중치 공간의 절반 이상을 0이 점유하는 극단적인 희소성 편향
  • +1과 -1로 대표되는 활성 가중치 부호의 상대적 분산과 대칭성
  • 레이어 및 어텐션 헤드별로 불균일하게 나타나는 0 밀도의 편차
  • 기존의 균등 분포 기반 고정 패킹 알고리즘과의 구조적 미스매치

3. 기존 5-트릿 패킹의 한계와 1.625비트의 반올림 손실

그동안 3진 LLM을 메모리에 적재하고 연산 가속기로 전송할 때 사실상의 산업 표준 배포 포맷으로 군림해 온 방식은 5-트릿 패킹(five-trit packing)이다. 3진수 한 자리(트릿, trit)는 3가지 상태를 가지므로, 5개의 트릿을 하나로 묶으면 가능한 상태 조합의 수는 3⁵ = 243가지가 된다. 1바이트는 8비트이므로 2⁸ = 256가지의 상태를 표현할 수 있어, 5개의 3진 가중치를 1바이트 안에 온전히 담아낼 수 있다.

순수 산술적으로 1바이트(8비트)에 5개 가중치를 저장하므로 이론적 저장 폭은 8 ÷ 5 = 1.60비트/가중치가 된다. 이는 균등 엔트로피 한계인 1.585비트에 상당히 근접한 수치로 여겨졌기에 널리 채택되었다. 하지만 이 방식에는 실무 하드웨어 구현 단계에서 치러야 하는 두 가지 결정적인 비용과 낭비가 숨어 있었다.

첫째는 현대 프로세서의 벡터 연산 구조로 인한 정렬 오버헤드다. CPU의 SIMD 레지스터나 GPU의 워프(warp) 단위 연산 장치는 2의 거듭제곱(16, 32, 64, 128개 등) 크기의 벡터 그룹을 기본 처리 단위로 요구한다. 5개 단위로 가중치를 묶는 5-트릿 패킹은 2의 거듭제곱 블록 크기와 깔끔하게 나누어떨어지지 않는다. 이를 정렬하고 패딩을 맞추는 실무적 제약 때문에, 실제 배포 시스템에서 측정되는 실효 저장 비트 폭은 1.60비트가 아니라 1.625비트/가중치로 반올림되어 증가하게 된다.

둘째는 가중치 복원(언패킹) 시의 연산 부하와 무차별성이다. 1바이트 안에 뭉쳐진 5개 값을 분리해 내려면 3으로 나누는 나눗셈 연산과 나머지 연산(divmod by 3)을 반복하거나 복잡한 룩업 테이블(LUT) 조회를 거쳐야 한다. 벡터 실행 유닛에서 정수 나눗셈은 극도로 무거운 연산이며, 룩업 테이블 조회는 캐시 라인 충돌을 유발하기 쉽다. 무엇보다 이 방식은 앞서 살펴본 '51.5%의 0'이라는 분포적 편향을 전혀 고려하지 않고, 0이든 1이든 똑같은 고정 비트 폭을 소모하는 비효율을 고스란히 방치했다. 기존 5-트릿 패킹의 구조적 병목은 아래 4가지로 요약된다.

  • 3⁵ = 243 상태 저장 후 1바이트 내 13개 표현 공간의 영구적 유휴화
  • 2의 거듭제곱 그룹 정렬 제약으로 인한 1.625비트 실효 비트 폭 증가
  • 벡터 레지스터 내 분리 과정에서 발생하는 나눗셈 및 비트 마스킹 연산 부하
  • 0이 절반 이상을 차지하는 실제 모델 가중치 희소성의 완전한 무시

4. BITCOS의 작동 원리 — 밀집 존재 비트맵과 압축 부호 벡터

BITCOS는 이러한 고정 패킹의 한계를 극복하기 위해 설계된 분포 적응형(distribution-adaptive) 저장 레이아웃이다. 제안된 아키텍처의 발상은 단순하면서도 하드웨어 친화적이다. 가중치 행렬을 단일 스트림으로 다루는 대신, 가중치가 0인지 아닌지를 판별하는 구조와 0이 아닌 값의 부호를 담는 구조를 완전히 분리하여 이원화했다.

BITCOS의 저장 공간은 정확히 두 개의 상호 보완적인 벡터로 나뉜다. 첫 번째는 밀집 존재 비트맵(dense presence bitmap)이다. 가중치 하나당 정확히 1비트를 할당하여, 해당 위치의 가중치가 0이면 0, 0이 아니면(+1 또는 -1) 1을 기록한다. 이 비트맵은 가중치 배열과 동일한 길이를 가지며 요소당 정확히 1비트의 고정 비용을 발생시킨다.

두 번째는 압축 부호 벡터(compacted sign vector)다. 0인 가중치는 완전히 건너뛰고, 비트맵에서 1로 표시된 '0이 아닌 유효 가중치'에 대해서만 부호를 1비트로 기록하여 빈틈없이 이어 붙인다. +1은 1, -1은 0(혹은 그 반대)으로 인코딩된다.

이 레이아웃의 저장 효율을 수학적으로 모델링하면 극도로 명쾌한 수식이 도출된다. 모델 전체 가중치에서 0이 차지하는 비율(zero density)을 z(0 <= z <= 1)라고 정의하자. 비트맵은 모든 가중치에 대해 1비트를 소모하므로 가중치당 1비트다. 반면 부호 벡터는 0이 아닌 가중치, 즉 (1 - z) 비율의 가중치에 대해서만 1비트를 소모하므로 가중치당 (1 - z)비트가 든다. 따라서 BITCOS 레이아웃이 요구하는 총 저장 비용은 요소당 정확히 1 + (1 - z) = 2 - z 비트/가중치가 된다. BITCOS 레이아웃이 갖는 핵심 설계상의 특징은 다음과 같다.

  • 가중치 존재 유무와 부호 정보를 독립된 비트 스트림으로 완전 분리
  • 0인 가중치에 대해 부호 비트 할당을 100% 생략하는 공간 압축성
  • 나눗셈 연산 없이 비트맵 기반 마스킹과 시프트만으로 복원 가능한 선형성
  • 모델 고유의 희소성에 비례하여 비트 폭이 자동으로 줄어드는 분포 적응성

5. 29개 모델 중 26개의 승리 — 2 - z 공식과 1.485비트 실측

BITCOS 공식인 2 - z 비트가 기존 5-트릿 패킹의 실효 비트 폭인 1.625비트보다 공간 효율에서 앞서기 위한 분기점(break-even point)은 매우 직관적으로 계산된다. 2 - z < 1.625를 풀면 z > 0.375, 즉 가중치 행렬 내에서 0의 비율이 37.5%를 초과하기만 하면 BITCOS가 무조건 5-트릿 패킹보다 작은 크기를 달성한다.

29개의 실제 3진 LLM 모델을 대상으로 실측한 결과, 29개 중 무려 26개의 모델에서 0의 비율이 37.5%를 훌쩍 넘어선 것으로 나타났다. 즉 실전에 배포되는 대다수의 3진 모델에서 BITCOS는 별도의 손실이나 양자화 오차 없이 순수한 저장 레이아웃 전환만으로 5-트릿 패킹의 압축률을 가볍게 앞질렀다.

특히 0의 비율이 51.5%에 달했던 가장 희소한 모델의 경우, 공식에 따라 2 - 0.515 = 1.485비트/가중치라는 압축률이 실측되었다. 이는 지난 수년간 3진 신경망의 넘을 수 없는 절대 한계선으로 여겨졌던 log₂3 ≈ 1.585비트 장벽을 산술적으로 0.1비트 밑도는 수치다. 정보이론의 하한선을 깬 것이 아니라, 잘못된 전제(균등 확률)가 만들어낸 인위적인 한계를 실전 데이터의 비대칭 분포를 통해 자연스럽게 극복한 결과다.

압축 및 저장 방식 가중치당 비트 폭 (Bits/Weight) 가정 분포 및 전제 조건 29개 모델 대상 적용 결과
이론적 하한 (log₂3) 약 1.585 비트 {-1, 0, +1} 세 기호가 동일 확률(각 33.3%)로 출현 실제 3진 LLM 가중치 분포와 불일치
기존 5-트릿 패킹 (Five-trit) 1.625 비트 (실효치) 1바이트당 5개 가중치 패킹 및 2의 거듭제곱 정렬 오버헤드 균등 분포 기준 배포 표준 포맷
BITCOS 레이아웃 (제안 기법) 2 − z 비트 (z = 0 밀도) 밀집 존재 비트맵(1비트) + 압축 부호 벡터(1 − z 비트) 29개 중 26개 모델에서 5-트릿보다 우수
BITCOS 최적 달성치 최소 1.485 비트 0 비율이 최대치(51.5%)에 달한 희소 3진 LLM 모델 1.585비트 이론적 장벽 하회 돌파

표에서 확인되듯, 1.585비트는 균등 분포의 상한이었을 뿐 실제 모델의 0 밀도가 37.5%를 넘는 순간 5-트릿 패킹은 경쟁력을 잃는다. 51.5%의 0 밀도 모델에서 달성된 1.485비트는 저장 장치 공간 절약뿐 아니라 DRAM 대역폭 병목을 뚫어내는 핵심 동력으로 작용한다.

6. 하드웨어 가속과 커널 성능 — AVX-512·AVX2·Xe2 GPU

아무리 저장 공간을 획기적으로 줄이는 레이아웃이라 하더라도, 행렬 곱셈을 수행하기 위해 가중치를 복원(언패킹)하는 과정이 느리다면 실무 추론 환경에서는 결코 채택될 수 없다. 압축률을 위해 디코딩 지연을 희생하는 것은 처리량이 생명인 LLM 서비스에서 치명적인 결함이 되기 때문이다. 연구진은 BITCOS 레이아웃이 최신 SIMD 명령어 세트와 GPU 하드웨어에서 초고속으로 언패킹될 수 있도록 최적화된 마이크로 커널 시퀀스를 직접 구현했다.

지원 대상 하드웨어는 현대 x86 프로세서의 대표 주자인 AVX-512 및 AVX2와, 인텔의 최신 아키텍처인 Intel Xe2 GPU(내장형 및 외장형 그래픽 카드 모두 포함)다. AVX-512 환경에서는 비트맵 마스크를 벡터 마스크 레지스터로 직접 로드한 뒤, 전용 벡터 확장 명령을 활용하여 분기문 없이 레지스터 내부에서 즉각적으로 부호 벡터를 확장한다. AVX2 환경에서는 전용 마스크 레지스터 부재를 극복하기 위해 바이트 단위 셔플과 비트 논리 연산 조합으로 고속 병렬 언패킹을 수행한다. Intel Xe2 GPU 환경에서는 서브그룹(subgroup) 단위 셔플과 SIMD 비트 조작 명령어로 수천 개의 실행 유닛에 가중치를 지연 없이 공급한다.

상용 최신(Production SOTA) 2비트 커널과 비교하여 측정된 3진 행렬-벡터 곱(GEMV / MVM) 커널 성능에서, BITCOS는 가중치 0 밀도에 비례하는 메모리 로드 감소에 힘입어 최대 1.28배의 속도 향상을 기록했다. 나아가 실제 LLM 서빙 환경을 모사한 5개 플랫폼(클라이언트 CPU, 서버 CPU, 내장 Xe2 GPU, 외장 Xe2 GPU 등) 대상 종단 간(end-to-end) 추론 벤치마크에서도, 토큰 생성의 병목인 디코드 처리량(decode throughput)이 CPU에서 최대 1.18배, GPU에서 최대 1.27배 향상되는 결과를 입증했다.

하드웨어 플랫폼 및 아키텍처 연산 커널 및 평가 시나리오 비교 대조군 기준 실측 성능 향상 폭 (배율)
AVX-512 / AVX2 지원 CPU 3진 행렬-벡터 곱 (MVM) 마이크로 커널 상용 최신(Production SOTA) 2비트 커널 최대 1.28배 속도 향상
Intel Xe2 GPU (내장 및 외장) 3진 행렬-벡터 곱 (MVM) 마이크로 커널 상용 최신(Production SOTA) 2비트 커널 최대 1.28배 속도 향상
클라이언트 및 서버 CPU (2종) 종단 간(End-to-End) LLM 디코드 추론 기존 2비트 가중치 기반 파이프라인 디코드 처리량 최대 1.18배 향상
통합 및 개별 Intel Xe2 GPU (2종) 종단 간(End-to-End) LLM 디코드 추론 기존 2비트 가중치 기반 파이프라인 디코드 처리량 최대 1.27배 향상

성능 평가 결과가 증명하는 핵심 사실은 다음과 같이 정리할 수 있다.

  • 비트맵과 부호 벡터의 언패킹 오버헤드가 메모리 트래픽 절감 이득에 완전히 흡수됨
  • 정수 나눗셈을 배제하고 비트 단위 논리 연산만으로 레지스터 내 확장을 달성
  • 서버급 제온 프로세서뿐 아니라 클라이언트 모바일 CPU에서도 일관된 속도 개선
  • 내장 그래픽과 외장 그래픽 카드 모두에서 메모리 대역폭 한계를 정직하게 돌파

7. 값을 하는 자리와 못 하는 자리 — 메모리 대역폭과 추론 환경

모든 시스템 아키텍처 기술이 그렇듯, BITCOS 역시 모든 추론 환경에서 마법 같은 성능 향상을 보장하는 만병통치약은 아니다. 이 기법이 정확히 어떤 병목을 해결하는 구조인지 이해해야 실무 파이프라인에서 낭비 없는 결정을 내릴 수 있다.

BITCOS가 절대적인 가치를 발휘하는 자리는 메모리 대역폭에 묶여 있는(Memory Bandwidth Bound) 워크로드다. LLM의 추론은 크게 프롬프트를 한 번에 입력받아 병렬 계산하는 프리필(prefill) 단계와, 토큰을 하나씩 순차적으로 뱉어내는 디코드(decode) 단계로 나뉜다. 단일 배치(batch size = 1) 환경의 엣지 기기나 온디바이스 AI, 소규모 로컬 서버에서 토큰을 생성할 때, 하드웨어는 연산 코어의 연산력(FLOPS)이 아니라 가중치를 DRAM에서 캐시로 읽어오는 메모리 버스 대역폭의 한계에 가로막힌다. 가중치를 1.625비트 혹은 2비트에서 1.485비트로 줄이는 것은 메모리 버스를 타고 넘어오는 데이터 바이트 자체를 줄이므로, 디코드 처리량이 정직하게 빨라진다.

반면 BITCOS가 제값을 하지 못하거나 오히려 오버헤드가 될 수 있는 자리는 연산력에 묶여 있는(Compute Bound) 대규모 배치 환경이다. 수십에서 수백 개의 요청을 묶어 처리하는 대규모 데이터센터 서빙 환경이나 긴 프롬프트를 처리하는 프리필 단계에서는 행렬-행렬 곱(GEMM) 연산 밀도가 극도로 높아진다. 이 자리에서는 메모리 대역폭보다 텐서 코어나 행렬 연산 가속기의 순수 처리량이 병목이 되며, 가중치를 풀기 위해 레지스터에서 비트맵을 펼치는 부가 연산이 오히려 파이프라인 지연을 유발할 여지가 있다. 또한 모델의 0 밀도가 37.5% 미만인 예외적인 3개 모델과 같은 환경에서는 구조적 이득이 사라진다. BITCOS 도입 전 검토해야 할 실무 조건은 아래와 같다.

  • 추론 대상 모델의 실제 가중치 0 밀도(z)가 37.5% 이상인지에 대한 사전 프로파일링
  • 서빙 환경의 배치 크기와 프리필 대 디코드 비율에 따른 대역폭 의존도 분석
  • 실행 대상 칩셋이 AVX-512, AVX2, Xe2 수준의 빠른 비트 조작 명령을 지원하는지 여부
  • DRAM 용량 제한으로 인해 모델 적재 자체가 불가능했던 엣지 디바이스 메모리 한계선

8. 이론적 한계를 다시 정의하는 엔지니어링의 관점

BITCOS의 성과가 컴퓨터 공학과 기계학습 시스템 분야에 던지는 메시지는 단순한 압축 알고리즘의 개선을 넘어선다. 그것은 '이론적 하한선'이라는 권위에 갇혀 있던 문제 해결의 지평을 다시 넓혀 준 엔지니어링적 통찰이다.

정보이론이 제시하는 수학적 하한선은 명백한 진리이지만, 그 진리는 모델이 '동일한 확률로 무작위하게 흩뿌려져 있다'는 가정 하에서만 유효했다. 딥러닝 최적화 알고리즘이 손실 함수를 줄여 나가는 과정은 본질적으로 엔트로피를 낮추고 가중치 공간에 구조적 패턴을 아로새기는 작업이다. 그 결과 필연적으로 생성된 51.5%라는 거대한 0의 편향을 포착하고, 이를 위해 맞춤형 저장 레이아웃을 고안한 것은 이론과 실전의 간극을 파고든 훌륭한 시스템 설계의 전형이다.

더불어 균등 분포를 전제로 짠 복잡한 5-트릿 패킹 대신, 비트맵과 부호 벡터라는 가장 단순하고 분리된 원시 자료구조로 돌아감으로써 하드웨어 레지스터에서의 언패킹 복잡도를 획기적으로 낮추었다는 점 역시 주목할 만하다. 가장 효율적인 시스템은 종종 가장 정교한 수학적 트릭이 아니라, 실제 하드웨어의 벡터 명령어와 데이터의 실측 분포가 정확히 맞물리는 지점에서 탄생한다. 본 연구가 시사하는 핵심 교훈은 다음과 같다.

  • 이론적 수학적 한계가 지닌 조건부 전제에 대한 실증적 재검토
  • 하드웨어 벡터 연산 장치의 특성에 부합하는 원시 비트맵 분리 설계
  • 기계학습 모델의 최적화 수렴 과정에서 발생하는 자연적 희소성 활용
  • 초저전력 온디바이스 AI 환경에서의 가중치 전송 대역폭 극대화

9. 확인하지 못한 것

본 분석을 정리하며 1차 출처인 arXiv 공개 논문 초록과 관련 기술 사양을 검토하는 과정에서, 명확한 수치나 추가 자료가 공개되지 않아 단정적으로 기술하지 않고 본 절에 유보하는 항목들은 다음과 같다.

  • 저자 3인(Evangelos Georganas, Alexander Heinecke, Pradeep Dubey)의 구체적인 소속 연구소나 기업명은 arXiv 초록 페이지 메타데이터에 명기되어 있지 않아, 논문 본문 확인 전까지 특정 기관으로 단정하지 않고 인물명으로만 기술했다.
  • 검증 대상이 된 29개 모델 중 BITCOS 레이아웃이 5-트릿 패킹 대비 우위를 점하지 못한 나머지 3개 모델의 구체적인 명칭과 파라미터 크기, 해당 모델들의 개별 제로 밀도 수치는 초록에 공개되지 않았다.
  • 비트맵 마스크와 부호 벡터를 레지스터로 확장하는 과정에서 발생하는 하드웨어 클록 사이클 수나 정밀한 명령어 캐시 오버헤드의 절대적인 정량 수치는 초록에 기재되지 않아 포함하지 않았다.
  • 종단 간 디코드 처리량 평가에 투입된 5개 플랫폼(클라이언트 및 서버 CPU, 내장 및 외장 Xe2 GPU)의 세부 프로세서 모델 번호와 사용된 메모리 세부 사양(DDR5 대역폭 등)은 초록 본문에 명시되지 않았다.
