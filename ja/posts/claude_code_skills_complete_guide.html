Complete A-to-Z Guide to Claude Code Skills

2025-11-15 IT・技術

Claude Code Skillsは、AnthropicのClaude AIを開発ワークフローに統合し、反復的な作業を自動化しコード品質を向上させ、開発生産性を最大化する強力な機能です。単純なコード自動補完を超えて、開発者の意図を理解し、文脈に即したソリューションを提供するインテリジェントな開発アシスタントです。

English: Claude Code Skills is a powerful feature that integrates Anthropic's Claude AI into development workflows to automate repetitive tasks, improve code quality, and maximize development productivity. It's an intelligent development assistant that goes beyond simple code completion to understand developer intent and provide context-appropriate solutions.

🎯 Claude Code Skillsとは何か?

Claude Code Skillsは大きく分けて3つの構成要素で成り立っています。

  • Skill定義ファイル: 作業の目的、入力パラメータ、実行ロジックを定義します。
  • Claude AIエンジン: 自然言語による指示を理解し、コードを生成して実行します。
  • 統合環境: VS Code、CLIなど様々な開発環境とシームレスに統合されます。

主要な特徴

  • 文脈理解: プロジェクト全体の構造とコーディングパターンを分析し、一貫性のあるコードを生成します。
  • ワークフロー自動化: 反復的な開発作業をSkillsとして定義し、自動化して時間を節約します。
  • 高い拡張性: ユーザー定義のSkillsを無制限に作成でき、チーム固有の要件に合わせられます。
  • コラボレーション支援: チームメンバー間でSkillsを共有し、開発標準を統一して協業効率を高めます。

🚀 なぜSkillsを使うべきか?

現代のソフトウェア開発はますます複雑化しています。開発者はコーディングだけでなく、テスト、ドキュメント作成、レビュー、デプロイなど様々な作業を行う必要があります。Claude Code Skillsは、このような反復的で時間のかかる作業を自動化し、開発者が中核ロジックに集中できるよう支援します。

📋 基本概念と構造

Skillの構造

Claude Code Skillは基本的に次のような構造を持ちます。

name: skill-name
description: このSkillが実行する作業の説明
version: 1.0.0

parameters:
  - name: param1
    type: string
    required: true
    description: 第1パラメータの説明

  - name: param2
    type: array
    required: false
    default: []
    description: 第2パラメータの説明

instructions: |
  このSkillが実行すべき具体的な指示事項を記述します。
  Claudeはこの指示に基づいて作業を実行します。

  変数は ${param1}、${param2} の形式で参照できます。

output:
  format: markdown
  location: ./output/

主要構成要素の説明

  • name: Skillの一意識別子で、kebab-caseを使用します。
  • description: Skillの目的と機能を簡潔に説明します。
  • parameters: Skill実行時に必要な入力値を定義します。
  • instructions: Claudeが実行する具体的な作業指示です。
  • output: 成果物の形式と保存場所を指定します。

🛠️ Skillsの作成

最初のSkillを作る: APIエンドポイント生成器

実務で最も頻繁に使われる、RESTful APIエンドポイントを生成するSkillを作成してみましょう。

Step 1: Skillファイルの作成

.claude/skills/ ディレクトリに create-api-endpoint.yaml ファイルを作成します。

name: create-api-endpoint
description: RESTful APIエンドポイントを自動で生成します
version: 1.0.0

parameters:
  - name: resource_name
    type: string
    required: true
    description: リソース名 (例: user、product、order)

  - name: methods
    type: array
    required: false
    default: ["GET", "POST", "PUT", "DELETE"]
    description: 生成するHTTPメソッドのリスト

  - name: database
    type: string
    required: false
    default: "postgresql"
    description: 使用するデータベース (postgresql、mysql、mongodb)

instructions: |
  次の作業を順番に実行してください。

  1. ${resource_name} のデータモデルを生成してください。
     - TypeScriptインターフェースの定義
     - ${database} スキーマの定義
     - バリデーションロジックを含む

  2. ${methods} に指定された各HTTPメソッドのコントローラを生成してください。
     - GET: 一覧取得および単一項目取得
     - POST: 新規項目の作成
     - PUT: 既存項目の更新
     - DELETE: 項目の削除

  3. 各エンドポイントのユニットテストを生成してください。
     - 正常系ケース
     - エラーケース
     - エッジケース

  4. APIドキュメントをOpenAPI 3.0形式で生成してください。

  5. すべてのファイルを適切なディレクトリ構造で作成・整理してください。

output:
  format: files
  structure: |
    src/
      models/${resource_name}.model.ts
      controllers/${resource_name}.controller.ts
      routes/${resource_name}.routes.ts
      services/${resource_name}.service.ts
    tests/
      ${resource_name}.test.ts
    docs/
      api/${resource_name}.openapi.yaml

Step 2: Skillの実行

Claude Code CLIまたはVS Code拡張機能から次のようにSkillを実行します。

# CLIで実行
claude skill run create-api-endpoint \
  --resource_name=product \
  --methods=GET,POST,PUT,DELETE \
  --database=postgresql

# あるいは対話型で実行
claude skill run create-api-endpoint
📘 実行結果
上記コマンドを実行すると、ClaudeはProductリソースに対する完全なAPIエンドポイントを自動生成します。モデル、コントローラ、ルート、サービスレイヤー、テストコード、APIドキュメントまで含まれ、手作業なら数時間かかる作業を数分で完了できます。

高度なSkillの例: 自動リファクタリング

name: auto-refactor
description: コードの匂いを検知して自動でリファクタリングします
version: 2.0.0

parameters:
  - name: target_files
    type: array
    required: true
    description: リファクタリング対象のファイルパス一覧

  - name: refactor_types
    type: array
    required: false
    default: ["all"]
    description: |
      適用するリファクタリングの種類:
      - extract_method: 長いメソッドを小さなメソッドに分割
      - remove_duplication: 重複コードの除去
      - simplify_conditional: 複雑な条件文の単純化
      - rename_variable: わかりやすい変数名への変更
      - all: すべてのリファクタリングを適用

instructions: |
  1. ${target_files} の各ファイルを分析し、以下のコードの匂いを見つけてください。
     - 長いメソッド (50行以上)
     - 重複コード (3回以上の繰り返し)
     - 複雑な条件文 (ネスト深さ3以上)
     - 不明瞭な変数名 (a、b、temp など)
     - 巨大クラス (300行以上)

  2. ${refactor_types} に指定された種類のリファクタリングを適用してください。

  3. リファクタリング前後の比較レポートを生成してください。
     - 変更内容の要約
     - コード品質指標の改善度
     - 潜在的な問題の警告

  4. リファクタリングされたコードが既存テストをパスすることを確認してください。

output:
  format: report
  include:
    - refactored_files
    - comparison_report
    - test_results

例2: E2Eテストの自動生成

ユーザーシナリオを説明すると、自動でPlaywrightまたはCypressのテストコードを生成します。

// Skillが生成したE2Eテストの例
import { test, expect } from '@playwright/test';

test.describe('Product Purchase Flow', () => {
    test.beforeEach(async ({ page }) => {
        await page.goto('https://example.com');
    });

    test('ユーザーが商品を検索して購入できる', async ({ page }) => {
        // 1. ログイン
        await page.click('[data-testid="login-button"]');
        await page.fill('[name="email"]', 'test@example.com');
        await page.fill('[name="password"]', 'password123');
        await page.click('[type="submit"]');
        await expect(page.locator('[data-testid="user-menu"]')).toBeVisible();

        // 2. 商品検索
        await page.fill('[data-testid="search-input"]', 'MacBook Pro');
        await page.press('[data-testid="search-input"]', 'Enter');
        await expect(page.locator('[data-testid="search-results"]')).toBeVisible();

        // 3. 商品選択
        await page.click('[data-testid="product-card"]:first-child');
        await expect(page.locator('[data-testid="product-title"]'))
            .toContainText('MacBook Pro');

        // 4. カートに追加
        await page.click('[data-testid="add-to-cart"]');
        await expect(page.locator('[data-testid="cart-badge"]'))
            .toContainText('1');

        // 5. 決済手続き
        await page.click('[data-testid="go-to-cart"]');
        await page.click('[data-testid="checkout-button"]');
        await page.fill('[name="card-number"]', '4111111111111111');
        await page.fill('[name="expiry"]', '12/25');
        await page.fill('[name="cvc"]', '123');
        await page.click('[data-testid="pay-button"]');

        // 6. 決済完了の確認
        await expect(page.locator('[data-testid="order-confirmation"]'))
            .toBeVisible();
        await expect(page.locator('[data-testid="order-number"]'))
            .toHaveText(/ORD-\d{8}/);
    });
});
⚠️ 注意事項
自動生成されたドキュメントは必ずレビューが必要です。特にビジネスロジックやセキュリティに関する内容は、開発者が直接確認し補完しなければなりません。Skillsは下書きを素早く作成してくれるツールであり、人間の判断を代替するものではありません。

Skillsのチェイニング

複数のSkillsを連結して、複雑なワークフローを自動化できます。

name: full-feature-pipeline
description: 機能開発からデプロイまで全パイプラインを自動化
version: 1.0.0

steps:
  - skill: create-api-endpoint
    params:
      resource_name: ${feature_name}
      methods: ${http_methods}

  - skill: generate-tests
    params:
      target: ${previous_output.files}
      coverage_threshold: 80

  - skill: generate-documentation
    params:
      files: ${previous_output.files}
      format: openapi

  - skill: code-review
    params:
      files: ${previous_output.files}
      strict_mode: true

  - skill: create-pr
    params:
      title: "feat: Add ${feature_name} API endpoint"
      description: ${previous_output.summary}
      reviewers: ${team_members}

Claude Code Skillsの差別化ポイント

  • 真のワークフロー自動化: 単純なコード補完を超え、複雑な開発プロセス全体を自動化

✅ ベストプラクティスとヒント

効果的なSkill作成ガイド

  1. 明確な目的の定義: 各Skillは1つの明確な目的を持つべきです。
  2. 具体的な指示: 曖昧な指示より、具体的で段階的に分かれた指示のほうがより良い結果を生みます。
  3. 検証ステップを含める: Skillが生成したコードが正しいか検証するステップを含めてください。
  4. エラー処理: 想定されるエラー状況と処理方法を明示してください。
  5. ドキュメント化: Skill自体の説明と使用例を含めてください。
💡 プロのヒント
最初から完璧なSkillを作ろうとしないでください。基本バージョンを作って使ってみて、フィードバックを基に段階的に改善するほうが効果的です。

🔧 トラブルシューティングガイド

よくある問題と解決策

問題1: Skillが想定と異なる結果を生成する

原因: 指示が曖昧であったり、文脈情報が不足している

解決策:

  • より具体的な例を指示に含める
  • プロジェクトの既存コードスタイルを参照するよう明示する
  • 段階ごとに検証ポイントを追加する

問題2: Skill実行時にタイムアウトが発生する

原因: 一度に多くの作業を実行しようとしている

解決策:

  • 大きなSkillを複数の小さなSkillsに分割する
  • バッチサイズを減らしたりチャンク単位で処理する
  • 並列処理可能な作業は別のSkillに分離する
