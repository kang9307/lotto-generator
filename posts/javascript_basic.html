JavaScript Basic Syntax

이 게시물은 쿠팡 파트너스 활동의 일환으로, 이에 따른 일정액의 수수료를 제공받습니다.

JavaScript는 웹 개발에서 가장 널리 사용되는 프로그래밍 언어입니다. 이 글에서는 JavaScript의 기본 문법과 주요 개념에 대해 설명합니다.

English: JavaScript is the most widely used programming language in web development. This article explains the basic syntax and key concepts of JavaScript.

이 글은 ES2015(ES6) 이후의 현대 표준을 기준으로 정리했습니다. 2015년에 표준화된 ES6는 let·const·화살표 함수·템플릿 리터럴·클래스·모듈을 한꺼번에 도입하면서 자바스크립트를 사실상 다른 언어로 바꿔 놓았습니다. 인터넷에는 아직도 var와 ==를 쓰는 오래된 예제가 많이 남아 있지만, 지금 처음 배우는 사람이라면 그 관행을 굳이 따라 할 이유가 없습니다. 이 글에서는 "무엇을 쓰는가"뿐 아니라 "왜 옛 방식을 피하는가"까지 함께 설명합니다.

모든 예제는 브라우저 개발자 도구 콘솔(F12)이나 Node.js에 그대로 붙여 넣어 실행할 수 있게 작성했고, 주석에 실제 출력값을 적어 두었습니다. 눈으로만 읽지 말고 직접 실행해서 출력값을 확인하는 것이 기초를 몸에 붙이는 가장 빠른 방법입니다. 특히 결과가 예상과 다른 예제는 그 자리에서 값을 바꿔 가며 실험해 보길 권합니다.

이 글에서 다루는 내용은 다음과 같습니다.

  • 변수 선언: var·let·const의 차이와 선택 기준
  • 스코프와 호이스팅: 변수가 어디까지 살아 있고, 선언 전에 접근하면 어떻게 되는가
  • 자료형: 원시 타입 7종과 typeof가 돌려주는 값
  • 형변환: 명시적 변환과 암묵적 변환, truthy와 falsy
  • 연산자와 비교: ==를 피하고 ===를 쓰는 이유
  • 조건문과 반복문: if·switch·for...of·for...in의 쓰임새
  • 함수: 선언식·표현식·화살표 함수와 this의 차이
  • 배열과 객체: 자주 쓰는 메서드, 구조 분해, 얕은 복사의 함정
  • 비동기 기초: 프로미스와 async/await
  • 자주 하는 실수: 초보자가 반드시 한 번은 겪는 12가지

변수 선언 (Variable Declaration)

JavaScript에서는 var, let, const 키워드를 사용하여 변수를 선언할 수 있습니다.

English: In JavaScript, you can declare variables using the keywords var, let, and const.

// var (함수 스코프 - function scope)
var x = 5;

// let (블록 스코프 - block scope)
let y = 10;

// const (상수, 재할당 불가 - constant, cannot be reassigned)
const PI = 3.14;

세 키워드는 이름만 다른 것이 아닙니다. 스코프(유효 범위), 재선언·재할당 허용 여부, 선언 전에 접근했을 때의 동작이 모두 다릅니다. 아래 표로 한눈에 비교해 보겠습니다.

실무 규칙은 아주 단순합니다. 기본은 const로 선언하고, 값을 다시 넣어야 하는 경우에만 let으로 바꾸며, var는 새로 쓰지 않습니다. 이렇게 하면 "이 변수는 앞으로 바뀌지 않는다"는 정보가 코드에 그대로 드러나서, 나중에 읽는 사람이 추적해야 할 상태의 수가 줄어듭니다. 재할당이 필요해지는 순간에만 let으로 내려 쓰면 됩니다.

스코프: 변수가 살아 있는 범위

var는 함수 스코프라서 if나 for 블록 안에서 선언해도 그 블록을 벗어나 함수 전체에서 접근됩니다. 반면 let과 const는 블록 스코프라서 중괄호를 벗어나면 존재하지 않습니다. 블록 안에서만 쓰려고 만든 임시 변수가 함수 끝까지 살아 있는 것은 버그의 흔한 출발점입니다.

// var: 함수 스코프 + 선언만 끌어올려짐(값은 undefined)
function varScope() {
  console.log(typeof value); // "undefined" - 에러가 아니다
  if (true) {
    var value = 1;
  }
  return value;              // 1 - if 블록 밖에서도 접근된다
}

// let: 블록 스코프
function letScope() {
  if (true) {
    let value = 1;
    console.log(value);      // 1
  }
  // console.log(value);     // ReferenceError: value is not defined
}

console.log(varScope());     // 1
letScope();

스코프를 이해할 때 기억해 둘 점을 정리하면 다음과 같습니다.

  • 중괄호 { }로 감싼 모든 블록(if, for, while, 단독 블록)이 let·const의 경계가 됩니다.
  • 안쪽 스코프에서는 바깥 스코프의 변수를 읽을 수 있지만, 그 반대는 불가능합니다.
  • 안쪽에서 같은 이름으로 다시 선언하면 바깥 변수를 가리는 섀도잉(shadowing)이 일어납니다. 의도한 것이 아니라면 이름을 바꾸는 편이 낫습니다.
  • 선언 키워드를 아예 빼고 x = 1처럼 쓰면 비엄격 모드에서 전역 변수가 만들어집니다. 파일 맨 위에 'use strict'를 두거나 ES 모듈(type="module")을 쓰면 이 실수가 에러로 잡힙니다.

호이스팅과 TDZ(일시적 사각지대)

자바스크립트 엔진은 코드를 실행하기 전에 선언을 먼저 처리합니다. 이때 var는 선언과 함께 undefined로 초기화되기 때문에, 선언 줄보다 위에서 읽어도 에러 없이 undefined가 나옵니다. 값이 아직 없는데도 프로그램이 조용히 굴러가므로 원인을 찾기 어려운 버그가 됩니다.

let과 const도 끌어올려지기는 하지만 초기화되지 않은 상태로 남습니다. 블록 시작부터 선언 줄에 도달하기 전까지의 구간을 TDZ(Temporal Dead Zone, 일시적 사각지대)라고 부르며, 이 구간에서 접근하면 ReferenceError가 발생합니다. 조용히 잘못된 값을 쓰는 대신 즉시 에러로 알려주는 쪽이 훨씬 안전합니다.

// var: 반복이 끝난 뒤의 값 하나를 공유한다 → 3, 3, 3
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log('var:', i), 0);
}

// let: 반복마다 새로운 바인딩이 생긴다 → 0, 1, 2
for (let j = 0; j < 3; j++) {
  setTimeout(() => console.log('let:', j), 0);
}

이 예제는 var와 let의 차이가 실제로 어떤 결과 차이를 만드는지 가장 극명하게 보여 줍니다. var i는 반복문 전체에서 변수 하나를 공유하므로 콜백이 실행될 시점에는 이미 3이 되어 있습니다. let j는 반복 회차마다 별도의 바인딩을 만들어 주기 때문에 각 콜백이 자기 차례의 값을 기억합니다. 예전에는 이 문제를 즉시 실행 함수로 우회했지만, 이제는 let만 쓰면 자연스럽게 해결됩니다.

const가 막아주는 것과 막지 못하는 것

const는 "값이 변하지 않는다"가 아니라 "그 변수 이름에 다른 값을 다시 대입할 수 없다"는 뜻입니다. 객체나 배열을 const로 선언해도 내부 속성이나 요소는 얼마든지 바뀝니다. 내부까지 얼리려면 Object.freeze()가 필요하며, 이마저도 한 겹만 얼리는 얕은 동결입니다.

const config = { retry: 3 };
config.retry = 5;             // OK - 객체 내부 값은 바꿀 수 있다
console.log(config.retry);    // 5

// config = { retry: 5 };     // TypeError: Assignment to constant variable.

const frozen = Object.freeze({ retry: 3 });
frozen.retry = 5;             // 비엄격 모드에서는 조용히 무시된다
console.log(frozen.retry);    // 3

정리하면 const는 바인딩을 고정하고, Object.freeze()는 객체의 겉면을 고정합니다. 둘을 혼동해서 "const로 선언했으니 안전하다"고 넘겨짚으면, 공유된 객체가 다른 함수에서 변경되는 상황을 놓치게 됩니다.

데이터 타입 (Data Types)

JavaScript의 기본 데이터 타입은 다음과 같습니다:

English: JavaScript has the following basic data types:

  • String: 문자열 (text)
  • Number: 숫자 (numbers)
  • Boolean: 논리값 (true/false)
  • null: 값이 없음 (no value)
  • undefined: 값이 할당되지 않음 (unassigned value)
  • Object: 객체 (objects)
  • Symbol: 고유하고 변경 불가능한 데이터 타입 (unique and immutable data type)
let name = "홍길동";  // String
let age = 25;         // Number
let isActive = true;  // Boolean
let user = {          // Object
  name: "홍길동",
  age: 25
};

조금 더 정확하게 정리하면, 자바스크립트의 값은 원시 타입(primitive) 7종과 객체(object)로 나뉩니다. 원시 타입은 메서드나 속성을 가지지 않는 단순한 값이고 변경할 수 없습니다(immutable). 값을 "바꾼다"고 느껴지는 동작은 실제로는 새 값을 만들어 다시 대입하는 것입니다. 반면 객체는 여러 값을 담는 구조이고, 변수에는 그 객체를 가리키는 참조가 저장됩니다.

typeof로 타입 확인하기

console.log(typeof "hi");         // "string"
console.log(typeof 42);           // "number"
console.log(typeof 10n);          // "bigint"
console.log(typeof true);         // "boolean"
console.log(typeof undefined);    // "undefined"
console.log(typeof Symbol("id")); // "symbol"
console.log(typeof null);         // "object" ← 초기 구현의 버그. 호환성 때문에 유지된다
console.log(typeof [1, 2]);       // "object" ← 배열도 객체다
console.log(typeof function(){}); // "function"

// 그래서 배열과 null은 typeof 대신 전용 방법으로 판별한다
console.log(Array.isArray([1, 2])); // true
const v = null;
console.log(v === null);            // true

typeof null이 "object"인 것은 자바스크립트 최초 구현에 남아 있던 버그입니다. 고치자는 제안이 있었지만 기존 웹을 깨뜨린다는 이유로 거부되어 지금까지 그대로 남아 있습니다. 따라서 null 여부는 반드시 === null로, 배열 여부는 Array.isArray()로 판별해야 합니다.

형변환: 명시적 변환을 습관화한다

자바스크립트는 서로 다른 타입끼리 연산하면 알아서 타입을 맞춰 줍니다. 편해 보이지만 규칙이 직관적이지 않아서 초보자가 가장 많이 걸려 넘어지는 지점입니다. 값을 다룰 때는 Number()·String()·Boolean()으로 의도를 코드에 명시하는 편이 안전합니다.

// 문자열 → 숫자
console.log(Number("42"));                 // 42
console.log(Number(""));                   // 0    ← 빈 문자열은 0이 된다(주의)
console.log(Number("42px"));               // NaN
console.log(parseInt("42px", 10));         // 42   ← 앞에서부터 읽을 수 있는 만큼
console.log(Number.parseFloat("3.14abc")); // 3.14

// 숫자 → 문자열
console.log(String(42));       // "42"
console.log((42).toString(2)); // "101010"  ← 2진수 문자열

// 암묵적 형변환의 함정
console.log(1 + "2");  // "12"  + 는 한쪽이 문자열이면 연결로 동작
console.log("3" - 1);  // 2     - 는 문자열을 숫자로 바꾼 뒤 계산
console.log([] + {});  // "[object Object]"
  • parseInt()는 두 번째 인자로 진법을 명시하는 습관을 들이세요. parseInt("08", 10)처럼 써야 의도가 분명합니다.
  • 사용자 입력값(input.value)은 항상 문자열입니다. 숫자 계산 전에 반드시 Number()로 변환하세요.
  • +만 문자열 연결로 동작하고 -, *, /는 숫자 변환을 시도합니다. 이 비대칭이 "3" - 1 === 2인데 1 + "2" === "12"인 이유입니다.
  • 숫자 여부를 확인할 때는 Number.isNaN()과 Number.isFinite()를 쓰세요. 전역 isNaN()은 인자를 숫자로 변환한 뒤 판단하기 때문에 isNaN("abc")가 true로 나옵니다.

truthy와 falsy, 그리고 ?? 연산자

조건문에 넣으면 false처럼 동작하는 값을 falsy, 그 밖의 모든 값을 truthy라고 부릅니다. falsy 값은 딱 여덟 개뿐이므로 통째로 외워 두면 편합니다.

falsy 값의미흔히 헷갈리는 truthy 값
false불리언 거짓"false" (내용 있는 문자열)
0숫자 0"0" (내용 있는 문자열)
-0음의 0[] (빈 배열)
0nBigInt 0{} (빈 객체)
""빈 문자열" " (공백 한 칸)
null값 없음(의도적)function(){} (함수)
undefined값 미할당Infinity
NaN숫자가 아님new Boolean(false) (객체)
 
const falsyValues = [false, 0, -0, 0n, "", null, undefined, NaN];
console.log(falsyValues.every(v => !v)); // true - 여덟 개 모두 falsy

// || 는 falsy 전부를 걸러내므로 0과 ""까지 대체해 버린다
const count1 = 0 || 10;  // 10 ← 대개 의도한 결과가 아니다

// ?? 는 null 또는 undefined 일 때만 대체한다 (ES2020)
const count2 = 0 ?? 10;  // 0  ← 의도한 결과

console.log(count1, count2); // 10 0

"값이 없으면 기본값을 쓰겠다"는 코드를 ||로 작성하면, 숫자 0이나 빈 문자열처럼 정상적이지만 falsy한 값까지 기본값으로 덮여 버립니다. 널 병합 연산자 ??는 null과 undefined만 걸러내므로 이런 사고를 막아 줍니다.

연산자와 비교: == 대신 ===

동등 비교 ==는 양쪽 타입이 다르면 한쪽을 변환한 뒤 비교합니다. 이 변환 규칙이 복잡해서 결과를 예측하기 어렵고, 자바스크립트 코드에서 가장 흔한 논리 버그의 원인이 됩니다. 일치 비교 ===는 타입이 다르면 곧바로 false를 돌려주므로 규칙이 단 하나뿐입니다. 특별한 이유가 없다면 항상 ===와 !==를 쓰세요.

비교식== 결과=== 결과이유
1 vs "1"truefalse문자열이 숫자로 변환된다
0 vs ""truefalse빈 문자열이 0으로 변환된다
0 vs falsetruefalse불리언이 숫자 0으로 변환된다
[] vs falsetruefalse[] → "" → 0 순으로 변환된다

null vs 0falsefalsenull은 undefined 외에는 모두 다르다

console.log(1 == "1");            // true  - 문자열이 숫자로 변환됨
console.log(1 === "1");           // false - 타입이 다르면 무조건 false
console.log(null == undefined);   // true
console.log(null === undefined);  // false
console.log([] == false);         // true  - [] → "" → 0
console.log(0 == "");             // true

console.log(NaN == NaN);          // false - NaN은 자기 자신과도 다르다
console.log(Number.isNaN(NaN));   // true  - 올바른 판별법
console.log(Object.is(NaN, NaN)); // true  - Object.is 는 NaN을 같다고 본다

비교 연산자를 쓸 때 함께 기억해 둘 점들입니다.

  • ==가 유용한 유일한 경우는 value == null입니다. null과 undefined를 한 번에 검사하는 짧은 표현으로 널리 쓰입니다. 그 외에는 ===를 쓰세요.
  • 객체와 배열은 ===로 비교해도 참조가 같은지만 확인합니다. 내용 비교가 필요하면 각 속성을 직접 비교하거나 별도 함수를 써야 합니다.
  • NaN 판별에는 Number.isNaN() 또는 Object.is()를 쓰세요. x === NaN은 언제나 false입니다.
  • <, > 같은 크기 비교는 ===와 달리 여전히 타입 변환을 수행합니다. 비교 전에 Number()로 맞춰 두는 편이 안전합니다.

조건문과 반복문 (Conditionals and Loops)

조건문은 프로그램의 흐름을 나누고, 반복문은 같은 처리를 여러 값에 적용합니다. 조건이 두 갈래일 때는 if...else, 하나의 값이 여러 후보 중 무엇인지 가릴 때는 switch, 값에 따라 결과만 달라질 때는 삼항 연산자가 읽기 좋습니다.

const score = 87;

// if / else if / else
if (score >= 90) {
  console.log("A");
} else if (score >= 80) {
  console.log("B");   // ← 실행된다
} else {
  console.log("C");
}

// 삼항 연산자: 값을 고를 때 간결하다
const grade = score >= 80 ? "합격" : "불합격";

// switch: 각 case 끝의 break를 빠뜨리면 아래로 흘러내린다
switch (grade) {
  case "합격":
    console.log("축하합니다");
    break;
  default:
    console.log("재응시");
}

반복문 고르기

반복문은 종류가 많지만 실제로 자주 쓰는 것은 몇 개뿐입니다. 배열의 값을 순회할 때는 for...of, 객체의 키를 순회할 때는 for...in을 쓰는 것이 기본 원칙입니다. 이름이 비슷해서 헷갈리기 쉬우니 용도를 확실히 구분해 두세요.

const scores = [90, 75, 88];

// for...of : 값을 순회 (배열에 권장)
for (const s of scores) {
  console.log(s);        // 90, 75, 88
}

// for...in : 키를 순회 (객체용, 배열에는 비권장)
const user = { name: "홍길동", age: 25 };
for (const key in user) {
  console.log(key, user[key]);  // name 홍길동 / age 25
}

// 인덱스와 값을 함께 쓰고 싶다면 entries()
for (const [i, s] of scores.entries()) {
  console.log(i, s);     // 0 90 / 1 75 / 2 88
}

// while: 반복 횟수를 미리 알 수 없을 때
let n = 3;
while (n > 0) {
  n--;
}
  • for...in은 배열에 쓰면 인덱스를 문자열로 돌려주고 프로토타입 체인의 속성까지 훑기 때문에 배열에는 쓰지 않습니다.
  • 반복 변수는 const로 선언하는 것이 기본입니다. for...of는 회차마다 새 바인딩을 만들기 때문에 재할당하지 않는 한 const로 충분합니다.
  • break는 반복을 완전히 중단하고, continue는 현재 회차만 건너뜁니다.
  • forEach() 안에서는 break가 동작하지 않습니다. 중간에 멈춰야 한다면 for...of를 쓰거나 some()·every()를 활용하세요.
  • 배열을 "변환"하거나 "걸러내는" 목적이라면 반복문 대신 map()·filter()를 쓰는 편이 의도가 훨씬 잘 드러납니다.

함수 (Functions)

함수는 코드의 재사용성을 높이는 중요한 개념입니다.

English: Functions are important concepts that enhance code reusability.

// 함수 선언식 (Function Declaration)
function add(a, b) {
  return a + b;
}

// 함수 표현식 (Function Expression)
const multiply = function(a, b) {
  return a * b;
};

// 화살표 함수 (Arrow Function)
const divide = (a, b) => a / b;

세 가지 작성법은 문법만 다른 것이 아니라 호이스팅 동작과 this의 결정 방식이 다릅니다. 어떤 것을 골라야 할지 헷갈린다면 아래 표를 기준으로 삼으세요.

기본값·나머지 매개변수와 화살표 함수의 this

ES2015는 함수 작성을 훨씬 간결하게 만드는 문법을 여럿 추가했습니다. 매개변수 기본값, 나머지 매개변수, 템플릿 리터럴은 거의 모든 코드에 등장하므로 지금 익혀 두는 것이 좋습니다.

// 기본 매개변수 (ES2015)
function greet(name, greeting = "안녕하세요") {
  return `${greeting}, ${name}님`;   // 템플릿 리터럴
}
console.log(greet("홍길동"));         // "안녕하세요, 홍길동님"

// 나머지 매개변수: 개수가 정해지지 않은 인자를 배열로 받는다
function sum(...numbers) {
  return numbers.reduce((acc, n) => acc + n, 0);
}
console.log(sum(1, 2, 3, 4));        // 10

// 화살표 함수는 자신의 this를 갖지 않고 바깥의 this를 그대로 쓴다
const timer = {
  label: "타이머",
  startArrow() {
    setTimeout(() => console.log(this.label), 0);            // "타이머"
  },
  startFunc() {
    setTimeout(function () { console.log(this.label); }, 0);  // undefined
  }
};
timer.startArrow();
timer.startFunc();
  • 콜백 안에서 바깥 객체의 this를 그대로 쓰고 싶다면 화살표 함수를 고르세요. 예전에 쓰던 const self = this나 .bind(this)가 필요 없어집니다.
  • 반대로 객체의 메서드를 정의할 때는 화살표 함수를 쓰지 마세요. this가 그 객체를 가리키지 않습니다. 축약 메서드 문법(startArrow() { })을 쓰는 것이 정석입니다.
  • 화살표 함수 본문이 한 줄 표현식이면 중괄호와 return을 생략할 수 있습니다. 중괄호를 쓰면 return을 반드시 적어야 합니다.
  • 객체 리터럴을 그대로 반환하려면 괄호로 감싸세요. () => ({ id: 1 })처럼 쓰지 않으면 중괄호가 함수 본문으로 해석됩니다.

배열과 반복문 (Arrays and Loops)

배열과 반복문을 사용하여 데이터를 효율적으로 처리할 수 있습니다.

// 배열 선언
const fruits = ["사과", "바나나", "오렌지"];

// for 반복문
for (let i = 0; i < fruits.length; i++) {
  console.log(fruits[i]);
}

// forEach 메서드
fruits.forEach(fruit => {
  console.log(fruit);
});

// map 메서드 (새로운 배열 반환)
const fruitLengths = fruits.map(fruit => fruit.length);

실무에서 배열을 다룰 때는 for 반복문보다 배열 메서드를 훨씬 자주 씁니다. "무엇을 하려는가"가 메서드 이름에 그대로 드러나서 코드를 읽는 속도가 빨라지기 때문입니다. 자주 쓰는 것부터 정리하면 다음과 같습니다.

메서드하는 일반환값원본 변경
map(fn)각 요소를 변환같은 길이의 새 배열안 함
filter(fn)조건을 만족하는 요소만 남김새 배열안 함
reduce(fn, init)하나의 값으로 누적·축약누적 결과 값안 함

const products = [
  { name: "키보드", price: 45000 },
  { name: "마우스", price: 25000 },
  { name: "모니터", price: 300000 }
];

// filter: 조건에 맞는 요소만 새 배열로
const cheap = products.filter(p => p.price < 100000);
console.log(cheap.length);   // 2

// map: 각 요소를 변환
console.log(products.map(p => p.name));  // ["키보드", "마우스", "모니터"]

// reduce: 하나의 값으로 축약 (두 번째 인자가 초기값)
const total = products.reduce((acc, p) => acc + p.price, 0);
console.log(total);          // 370000

// find / some / every
console.log(products.find(p => p.price > 100000).name); // "모니터"
console.log(products.some(p => p.price > 100000));      // true
console.log(products.every(p => p.price > 10000));      // true

원본을 바꾸는 메서드와 바꾸지 않는 메서드

배열 메서드에서 가장 자주 사고가 나는 지점은 어떤 메서드가 원본을 직접 수정하는가입니다. sort()·reverse()·splice()·push()는 원본을 바꾸고, map()·filter()·slice()·concat()은 새 배열을 만듭니다. ES2023에 추가된 toSorted()·toReversed()·toSpliced()·with()는 같은 일을 하면서 원본을 건드리지 않는 복사판입니다.

const nums = [3, 1, 2];
const sorted = nums.sort((a, b) => a - b);
console.log(nums, sorted === nums);  // [1,2,3] true ← 원본이 바뀌었다

// toSorted 는 원본을 두고 새 배열을 돌려준다 (ES2023)
const base = [3, 1, 2];
const copy = base.toSorted((a, b) => a - b);
console.log(base, copy);             // [3,1,2] [1,2,3]

// 숫자 정렬에 비교 함수를 빼면 문자열 기준으로 정렬된다
console.log([10, 9, 100].sort());               // [10, 100, 9]  ← 함정
console.log([10, 9, 100].sort((a, b) => a - b)); // [9, 10, 100]

기본 sort()는 각 요소를 문자열로 바꾼 뒤 사전순으로 정렬합니다. 그래서 [10, 9, 100]이 [10, 100, 9]가 됩니다. 숫자를 정렬할 때는 비교 함수 (a, b) => a - b를 반드시 넘겨야 합니다.

객체 다루기 (Objects)

객체는 키: 값 쌍의 모음으로, 하나의 대상이 가진 여러 속성을 묶어서 표현합니다. ES2015 이후 추가된 구조 분해 할당과 전개 연산자를 알면 객체를 다루는 코드가 눈에 띄게 짧아집니다.

const user = { name: "홍길동", age: 25, address: { city: "서울" } };

// 구조 분해 할당 (ES2015)
const { name, age } = user;
console.log(name, age);            // 홍길동 25

// 전개 연산자로 복사 + 일부만 덮어쓰기 (원본은 그대로)
const updated = { ...user, age: 26 };
console.log(updated.age, user.age); // 26 25

// 옵셔널 체이닝 (ES2020): 중간이 없어도 에러 대신 undefined
console.log(user.address?.city);    // "서울"
console.log(user.company?.name);    // undefined

// 키/값 순회
console.log(Object.keys(user));     // ["name", "age", "address"]
Object.entries({ a: 1, b: 2 }).forEach(([k, v]) => console.log(k, v));
  • 구조 분해 할당은 함수 매개변수에서도 쓸 수 있습니다. function f({ name, age }) { }처럼 쓰면 인자 순서를 외울 필요가 없습니다.
  • 전개 연산자 ...는 객체와 배열 모두에서 복사·병합에 쓰입니다. 뒤에 오는 값이 앞의 값을 덮어씁니다.
  • 옵셔널 체이닝 ?.은 API 응답처럼 있을 수도 없을 수도 있는 중첩 데이터를 읽을 때 특히 유용합니다.
  • Object.keys()·Object.values()·Object.entries()는 객체를 배열로 바꿔 주므로 배열 메서드를 그대로 이어 쓸 수 있습니다.
  • 키에 변수를 쓰려면 대괄호 표기법을 씁니다. obj[key]는 변수 값으로, obj.key는 문자 그대로 "key"로 접근합니다.

얕은 복사와 깊은 복사

전개 연산자와 Object.assign()은 얕은 복사입니다. 한 겹만 새로 만들고 그 안의 객체·배열은 원본과 같은 것을 가리킵니다. 중첩된 데이터를 복사한 뒤 안쪽을 수정하면 원본까지 바뀌는 이유가 여기 있습니다.

const original = { name: "홍길동", tags: ["a", "b"] };

const shallow = { ...original };
shallow.tags.push("c");
console.log(original.tags);   // ["a","b","c"] ← 원본도 함께 바뀐다

const deep = structuredClone(original);  // 깊은 복사 (최신 브라우저, Node 17+)
deep.tags.push("d");
console.log(original.tags.length, deep.tags.length); // 3 4

깊은 복사가 필요하면 표준 내장 함수 structuredClone()을 쓰는 것이 가장 간단합니다. 예전에 많이 쓰던 JSON.parse(JSON.stringify(obj))는 Date가 문자열로 바뀌고 undefined·함수·Map·Set이 사라지므로 권장하지 않습니다.

비동기 기초: 프로미스와 async/await

자바스크립트는 한 번에 한 가지 일만 처리하는 싱글 스레드로 동작합니다. 서버 요청처럼 시간이 걸리는 작업을 기다리는 동안 화면이 멈추지 않도록, 그런 작업은 "끝나면 알려 달라"는 방식으로 처리합니다. 그 결과를 표현하는 객체가 프로미스(Promise)이고, 프로미스를 동기 코드처럼 읽히게 만들어 주는 문법이 async/await입니다.

function delay(ms, value) {
  return new Promise(resolve => setTimeout(() => resolve(value), ms));
}

// 앞의 결과가 필요할 때 → 순차 처리 (약 100ms)
async function runSequential() {
  const a = await delay(50, "A");
  const b = await delay(50, "B");
  return a + b;
}

// 서로 독립적일 때 → 병렬 처리 (약 50ms)
async function runParallel() {
  const [a, b] = await Promise.all([delay(50, "A"), delay(50, "B")]);
  return a + b;
}

// 오류는 try/catch로 잡는다
async function safeRun() {
  try {
    return await delay(10, "ok");
  } catch (err) {
    console.error("실패:", err);
    return null;
  }
}

runSequential().then(r => console.log("sequential:", r)); // "AB"
runParallel().then(r => console.log("parallel:", r));     // "AB"
safeRun().then(r => console.log("safeRun:", r));          // "ok"
  • await는 async 함수 안에서만 쓸 수 있습니다(ES 모듈 최상위는 예외). 일반 함수 안에서 쓰면 문법 에러가 납니다.
  • async 함수는 언제나 프로미스를 반환합니다. 값을 return해도 호출한 쪽에서는 await나 .then()으로 꺼내야 합니다.
  • 서로 의존하지 않는 요청을 await로 한 줄씩 늘어놓으면 불필요하게 느려집니다. 이럴 때는 Promise.all()로 묶으세요.
  • 비동기 함수의 오류는 try/catch로 잡습니다. .then() 체인을 쓴다면 마지막에 .catch()를 반드시 붙이세요.

초보자가 자주 하는 실수 12가지

아래 항목들은 처음 자바스크립트를 배우는 사람이라면 거의 반드시 한 번은 겪는 문제들입니다. 미리 알아 두면 디버깅에 쓰는 시간을 크게 줄일 수 있습니다.

  1. NaN을 ===로 비교한다. NaN === NaN은 false입니다. Number.isNaN(x) 또는 Object.is(x, NaN)을 쓰세요.
  2. 0.1 + 0.2 === 0.3이 true일 거라 기대한다. 부동소수점 방식 때문에 실제 값은 0.30000000000000004입니다. 허용 오차를 두고 비교하거나 정수 단위로 계산하세요.
  3. ==를 습관적으로 쓴다. 0 == "", [] == false가 모두 true가 되는 등 예측이 어렵습니다. ===를 기본으로 하세요.
  4. 메서드를 화살표 함수로 정의한다. 화살표 함수는 자기 this가 없어서 객체 메서드로 쓰면 원하는 값을 못 읽습니다. 반대로 콜백에는 화살표 함수가 정답입니다.
  5. 비동기 결과를 동기처럼 읽으려 한다. fetch() 바로 다음 줄에서 결과를 쓰면 아직 값이 없습니다. await로 기다리거나 .then() 안에서 처리하세요.
  6. async 함수의 반환값을 그냥 쓴다. 콘솔에 Promise { <pending> }가 찍힌다면 await를 빠뜨린 것입니다.
  7. 숫자 배열을 비교 함수 없이 sort()한다. 문자열 기준으로 정렬되어 [10, 100, 9]가 나옵니다. (a, b) => a - b를 넘기세요.
  8. map() 콜백에서 return을 빠뜨린다. 중괄호를 쓴 화살표 함수는 명시적 return이 없으면 undefined로 채워진 배열이 됩니다.
  9. 객체·배열을 ===로 내용 비교한다. 참조가 다르면 내용이 같아도 false입니다. 속성을 직접 비교하세요.
  10. 얕은 복사를 깊은 복사로 착각한다. { ...obj }는 한 겹만 복사합니다. 중첩 구조는 structuredClone()을 쓰세요.
  11. 입력값을 문자열인 채로 계산한다. "5" + 3은 "53"입니다. Number()로 변환한 뒤 계산하세요.
  12. ||로 기본값을 지정한다. 값이 0이거나 빈 문자열일 때도 기본값으로 덮입니다. ??를 쓰세요.
// 2번 실수: 부동소수점
console.log(0.1 + 0.2);          // 0.30000000000000004
console.log(0.1 + 0.2 === 0.3);  // false

const almostEqual = (a, b) => Math.abs(a - b) < Number.EPSILON;
console.log(almostEqual(0.1 + 0.2, 0.3)); // true

// 금액은 최소 단위 정수로 계산한 뒤 나누면 안전하다
console.log((0.1 * 10 + 0.2 * 10) / 10);  // 0.3

// 8번 실수: map 콜백에 return 이 없다
console.log([1, 2, 3].map(n => { n * 2; }));      // [undefined, undefined, undefined]
console.log([1, 2, 3].map(n => n * 2));          // [2, 4, 6]

이 실수들은 대부분 "자바스크립트가 알아서 맞춰 주는 동작"을 신뢰했다가 생깁니다. 타입 변환과 참조 복사를 코드에 명시적으로 적는 습관을 들이면 절반 이상이 사라집니다.

자주 묻는 질문 (FAQ)

JavaScript에서 변수를 선언하는 방법은 무엇인가요?

var, let, const 키워드를 사용해 변수를 선언할 수 있습니다. 이 세 가지는 각각 다른 특성을 가지고 있어 상황에 맞게 선택해서 사용합니다. 실무 기준으로는 const를 기본으로 쓰고, 값을 다시 대입해야 할 때만 let을 쓰며, var는 함수 스코프와 호이스팅 때문에 새 코드에서는 사용하지 않습니다.

JavaScript의 기본 데이터 타입에는 어떤 것들이 있나요?

문자열(String), 숫자(Number), 논리값(Boolean), null(값이 없음), undefined(값이 할당되지 않음), 객체(Object), 그리고 고유하고 변경 불가능한 데이터 타입인 Symbol이 있습니다. 여기에 큰 정수를 다루는 BigInt까지 더하면 원시 타입은 모두 7종이며, 객체만 참조로 다뤄집니다. typeof null이 "object"로 나오는 것은 언어 초기의 버그이므로 === null로 판별해야 합니다.

JavaScript에서 함수는 왜 중요한 개념인가요?

함수는 코드의 재사용성을 높이는 중요한 개념입니다. 반복되는 로직을 함수로 만들어두면 필요할 때마다 호출해서 사용할 수 있습니다. 또한 자바스크립트에서 함수는 값처럼 변수에 담고 인자로 넘길 수 있어서, map()·filter() 같은 고차 함수와 이벤트 콜백의 기반이 됩니다.

배열과 반복문은 어떤 역할을 하나요?

배열과 반복문을 사용하면 여러 개의 데이터를 효율적으로 처리할 수 있습니다. 하나씩 다루기 번거로운 데이터 묶음을 배열에 담고 반복문으로 순회하며 처리하는 방식입니다. 다만 값을 변환하거나 걸러내는 목적이라면 for 반복문보다 map()·filter()·reduce() 같은 배열 메서드가 의도를 더 분명하게 드러냅니다.

JavaScript 기본 문법을 익히면 무엇을 할 수 있나요?

글에 따르면 JavaScript의 기본 문법을 익히면 다양한 웹 애플리케이션을 개발할 수 있습니다. 변수·데이터 타입·함수·배열·반복문은 그 출발점이 되는 핵심 개념들입니다. 이후 DOM 조작과 fetch를 익히면 실제로 동작하는 웹 페이지를 만들 수 있고, 모듈과 클래스까지 나아가면 프레임워크 학습으로 자연스럽게 이어집니다.
