引言:为什么要50条iptables规则

iptables是Linux服务器安全领域历史最久、最经得起考验的工具。虽然2026年nftables已成为多数发行版的默认,但RHEL 7/8系、嵌入式设备、大量容器主机上,iptables(或iptables-translate)仍在大规模使用。痛点很明显:语法不直观,一旦输错就可能断掉SSH会话,只能去机房接控制台。

本文正是为减少这种事故而写:10大场景类别 × 每类5条 = 共50个实战iptables规则。每条规则都包含命令、含义解释、应用场景三要素,可直接复制使用。重点不在"语法怎么写",而在"什么时候该写什么"。

本站iptables生成器与本文搭配效果最佳:文章里学概念,工具里可视化组合规则,然后放心粘贴到服务器。

1. 基础策略设定 (5条)

所有防火墙的起点。必须明确定义策略(POLICY),才能避免意外的流量放行或误拦截。

[#1] 默认DROP + 显式允许
sudo iptables -P INPUT DROP
sudo iptables -P FORWARD DROP
sudo iptables -P OUTPUT ACCEPT
含义:INPUT/FORWARD默认拒绝,仅显式ACCEPT通过。OUTPUT保持开放。
场景:服务器安全标准底座,最安全的起点。
[#2] 放行ESTABLISHED与RELATED
sudo iptables -A INPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT
含义:自动允许已建立连接及其衍生流量(如FTP-data)。
场景:几乎所有INPUT链都应把它放在第一条。
[#3] 放行loopback接口
sudo iptables -A INPUT -i lo -j ACCEPT
sudo iptables -A OUTPUT -o lo -j ACCEPT
含义:允许127.0.0.1通信。许多守护进程依赖此IPC。
场景:策略切换为DROP后第一个补的规则。
[#4] 丢弃INVALID包
sudo iptables -A INPUT -m conntrack --ctstate INVALID -j DROP
含义:丢弃序号或标志位异常的非法包。
场景:基础卫生规则,也能对抗部分端口扫描器。
[#5] 放行ICMP echo(限速)
sudo iptables -A INPUT -p icmp --icmp-type echo-request -m limit --limit 10/sec -j ACCEPT
含义:每秒最多响应10次ping,防止ping flood。
场景:NMS或健康检查用ICMP时必备。
即时生成:在iptables生成器勾选INPUT链 + ESTABLISHED + loopback,一键输出。

2. SSH安全加固 (5条)

服务器入侵案例约一半经22端口而来。SSH是最优先要保护的服务。

[#6] 修改SSH端口后放行
sudo iptables -A INPUT -p tcp --dport 2222 -j ACCEPT
含义:用2222代替22,自动扫描约95%失效。
场景:配合sshd_config中Port 2222使用。
[#7] SSH白名单(仅特定IP)
sudo iptables -A INPUT -p tcp -s 203.0.113.0/24 --dport 22 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 22 -j DROP
含义:仅办公段可SSH接入,其余全部拒绝。
场景:VPN/办公室固定IP环境下最强SSH防护。
[#8] SSH暴力破解限速
sudo iptables -A INPUT -p tcp --dport 22 -m conntrack --ctstate NEW \
    -m recent --set --name SSH
sudo iptables -A INPUT -p tcp --dport 22 -m conntrack --ctstate NEW \
    -m recent --update --seconds 60 --hitcount 4 --name SSH -j DROP
含义:60秒内新建4次以上SSH连接的源IP自动封锁。
场景:无需fail2ban,在内核级完成。
[#9] 按国家拦截SSH (xtables-addons geoip)
sudo iptables -A INPUT -p tcp --dport 22 -m geoip --src-cc CN,RU,KP -j DROP
含义:特定国家来源的SSH全部丢弃。
场景:无需全球访问的内网服务器。需要xtables-addons包。
[#10] 端口敲门(knock序列)
sudo iptables -N SSH_PHASE2
sudo iptables -A INPUT -p tcp --dport 7000 -m recent --name PH1 --set -j DROP
sudo iptables -A INPUT -p tcp --dport 8000 -m recent --name PH1 --rcheck \
    -m recent --name PH2 --set -j DROP
sudo iptables -A INPUT -p tcp --dport 22 -m recent --name PH2 --rcheck -j ACCEPT
含义:先敲7000再敲8000,SSH才开放。
场景:客户端无固定IP且需要最小暴露面时。

3. Web服务器安全 (HTTP/HTTPS) (5条)

80/443必须对外开放,因此攻击面最大。限速和SYN flood防御是核心。

[#11] 放行80/443
sudo iptables -A INPUT -p tcp -m multiport --dports 80,443 -j ACCEPT
含义:同时放行HTTP与HTTPS。
场景:任何公共Web服务器的基础规则。
[#12] 仅Cloudflare IP可访问80/443
for ip in $(curl -s https://www.cloudflare.com/ips-v4); do
    sudo iptables -A INPUT -p tcp -s $ip -m multiport --dports 80,443 -j ACCEPT
done
sudo iptables -A INPUT -p tcp -m multiport --dports 80,443 -j DROP
含义:绕过CDN直接打源站的流量一律丢弃。
场景:使用Cloudflare代理时保护源站的标准做法。
[#13] 单IP并发连接上限(基础DDoS缓解)
sudo iptables -A INPUT -p tcp --dport 80 -m connlimit --connlimit-above 50 -j REJECT
含义:同一IP对80端口并发超过50即拒绝。
场景:HTTP flood与爬虫的一级缓解。
[#14] Slowloris防御
sudo iptables -A INPUT -p tcp --dport 80 -m hashlimit \
    --hashlimit-name http_slow --hashlimit-mode srcip \
    --hashlimit-above 30/min --hashlimit-burst 20 -j DROP
含义:单IP每分钟超过30个新连接即丢弃,缓解慢连接耗尽资源。
场景:在Apache/Nginx前免费部署Slowloris盾。
[#15] SYN flood防御
sudo iptables -A INPUT -p tcp --syn -m limit --limit 1/sec --limit-burst 3 -j ACCEPT
sudo iptables -A INPUT -p tcp --syn -j DROP
含义:SYN包每秒1个,突发3,其余丢弃。
场景:与内核tcp_syncookies一起开启效果更佳。
Web预设一键生成:在iptables生成器选择"Web服务器"模板。

4. 数据库安全 (5条)

数据库绝对不能直接暴露到互联网。多层防御是原则,iptables是最外侧最强的一道墙。

[#16] MySQL外部禁入 + 仅放行应用服务器
sudo iptables -A INPUT -p tcp -s 10.0.1.10 --dport 3306 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 3306 -j DROP
含义:仅应用服务器(10.0.1.10)可访问MySQL。
场景:任何生产数据库主机的基础规则。
[#17] PostgreSQL 5432仅内网
sudo iptables -A INPUT -p tcp -s 10.0.0.0/16 --dport 5432 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 5432 -j DROP
含义:仅私有子网可访问PostgreSQL。
场景:VPC/VPN隔离环境的标准做法。
[#18] Redis 6379 双重防护(bind + iptables)
sudo iptables -A INPUT -p tcp ! -s 127.0.0.1 --dport 6379 -j DROP
含义:在iptables再补一道,即便redis.conf bind错误也不暴露。
场景:无认证Redis环境必备。
[#19] MongoDB 27017 全面禁外
sudo iptables -A INPUT -p tcp --dport 27017 -i ! lo -j DROP
含义:除loopback以外的所有接口都禁止27017。
场景:防止经典"MongoDB公网暴露"事故的最后一道防线。
[#20] Memcached 11211 白名单
sudo iptables -A INPUT -p tcp -s 10.0.1.0/24 --dport 11211 -j ACCEPT
sudo iptables -A INPUT -p udp -s 10.0.1.0/24 --dport 11211 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 11211 -j DROP
sudo iptables -A INPUT -p udp --dport 11211 -j DROP
含义:同时白名单TCP/UDP,封堵UDP反射放大攻击向量。
场景:无认证Memcached需防DDoS放大滥用。

5. Docker容器主机 (5条)

Docker自己会写入大量iptables规则,容易冲突。务必通过DOCKER-USER链来挂自定义策略。

[#21] 屏蔽Docker守护端口(2375/2376)
sudo iptables -A INPUT -p tcp -m multiport --dports 2375,2376 -j DROP
含义:全面禁止远程Docker API。暴露=瞬间被接管容器。
场景:所有Docker主机必备。
[#22] 通过DOCKER-USER限制容器入站
sudo iptables -I DOCKER-USER -s 203.0.113.0/24 -j ACCEPT
sudo iptables -I DOCKER-USER -j DROP
含义:只有白名单段可访问容器发布的端口。
场景:在Docker自动生成规则之上安全地附加策略。
[#23] 容器之间互相隔离
sudo iptables -I DOCKER-USER -i docker0 -o docker0 -j DROP
含义:禁止默认bridge内的容器直接互通。
场景:多租户容器主机。--icc=false的替代方案。
[#24] Swarm节点间通信 (2377/7946/4789)
sudo iptables -A INPUT -p tcp -s 10.0.0.0/24 --dport 2377 -j ACCEPT
sudo iptables -A INPUT -p tcp -s 10.0.0.0/24 --dport 7946 -j ACCEPT
sudo iptables -A INPUT -p udp -s 10.0.0.0/24 --dport 7946 -j ACCEPT
sudo iptables -A INPUT -p udp -s 10.0.0.0/24 --dport 4789 -j ACCEPT
含义:Swarm的管理、gossip、VXLAN overlay流量。
场景:Swarm子网内放开,外部全部封禁。
[#25] 容器出站限制(SSRF防御)
sudo iptables -I DOCKER-USER -s 172.17.0.0/16 -d 169.254.169.254 -j DROP
含义:禁止容器访问云元数据端点。
场景:AWS/GCP主机,降低容器被攻破后窃取IAM凭据的风险。

6. Kubernetes节点 (5条)

K8s控制平面与工作节点各有需开放的端口。内部通信端口绝不允许暴露到公网。

[#26] kube-apiserver 6443 白名单
sudo iptables -A INPUT -p tcp -s 10.0.0.0/16 --dport 6443 -j ACCEPT
sudo iptables -A INPUT -p tcp -s 203.0.113.5 --dport 6443 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 6443 -j DROP
含义:仅集群子网与管理员IP可访问。
场景:每台控制平面节点的标准策略。
[#27] Kubelet 10250 仅内部节点
sudo iptables -A INPUT -p tcp -s 10.0.0.0/16 --dport 10250 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 10250 -j DROP
含义:仅控制平面可调用kubelet API。暴露会导致权限提升。
场景:所有工作节点。
[#28] NodePort范围 (30000-32767) 限制
sudo iptables -A INPUT -p tcp -s 10.0.0.0/16 --dport 30000:32767 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 30000:32767 -j DROP
含义:NodePort仅供内部LB/Ingress访问,严禁直接暴露公网。
场景:LoadBalancer前置的标准架构。
[#29] etcd 2379-2380 仅集群内
sudo iptables -A INPUT -p tcp -s 10.0.1.0/24 --dport 2379:2380 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 2379:2380 -j DROP
含义:etcd仅在控制平面节点之间通信,泄露=集群密钥外泄。
场景:主节点(含HA etcd部署)。
[#30] CNI overlay通信 (VXLAN 4789, Wireguard 51820)
sudo iptables -A INPUT -p udp -s 10.0.0.0/16 --dport 4789 -j ACCEPT
sudo iptables -A INPUT -p udp -s 10.0.0.0/16 --dport 51820 -j ACCEPT
含义:Flannel/Calico VXLAN或Cilium Wireguard节点间隧道。
场景:仅开放实际使用的CNI对应端口。

7. 邮件服务器 (5条)

邮件端口被垃圾机器人持续敲打。合理的限速与强制TLS是关键。

[#31] 放行SMTP 25/587/465
sudo iptables -A INPUT -p tcp -m multiport --dports 25,465,587 -j ACCEPT
含义:同时放行三个标准邮件投递与传输端口。
场景:Postfix/Exim等邮件服务器的基础规则。
[#32] 仅放行IMAPS/POP3S(拒绝明文)
sudo iptables -A INPUT -p tcp -m multiport --dports 993,995 -j ACCEPT
sudo iptables -A INPUT -p tcp -m multiport --dports 143,110 -j DROP
含义:仅开放TLS端口,明文IMAP/POP3全面拒绝。
场景:现代邮件服务器应强制禁明文。
[#33] SMTP限速(反垃圾机器人)
sudo iptables -A INPUT -p tcp --dport 25 -m connlimit --connlimit-above 10 -j REJECT
sudo iptables -A INPUT -p tcp --dport 25 -m hashlimit \
    --hashlimit-name smtp --hashlimit-mode srcip \
    --hashlimit-above 5/min --hashlimit-burst 3 -j DROP
含义:单IP并发10、每分钟5的上限。
场景:正常邮件不受影响,机器人被压制。
[#34] 可疑IP动态拦截 (ipset)
sudo ipset create spamips hash:ip
sudo iptables -A INPUT -p tcp --dport 25 -m set --match-set spamips src -j DROP
含义:加入ipset即可瞬时生效,适合动态封锁。
场景:rspamd/SpamAssassin等检测器自动写入ipset。
[#35] 限制出站25端口(防开放中继)
sudo iptables -A OUTPUT -p tcp -m owner --uid-owner postfix --dport 25 -j ACCEPT
sudo iptables -A OUTPUT -p tcp --dport 25 -j DROP
含义:仅postfix用户可外发25端口,Web shell与普通用户被禁。
场景:共享主机/多用户服务器必备。

8. NAT与端口转发 (5条)

iptables的nat表是路由器/网关角色的核心。务必厘清PREROUTING与POSTROUTING的差异。

[#36] 外部80转内部8080
sudo iptables -t nat -A PREROUTING -p tcp --dport 80 -j REDIRECT --to-port 8080
含义:把外部进来的80包重定向到本机8080。
场景:无需root也能"绑定"特权端口的经典技巧。
[#37] DNAT到另一台后端
sudo iptables -t nat -A PREROUTING -p tcp --dport 80 -j DNAT --to-destination 10.0.1.50:80
sudo iptables -t nat -A POSTROUTING -p tcp -d 10.0.1.50 --dport 80 -j MASQUERADE
含义:网关上80端口的流量转发到后端10.0.1.50:80。
场景:轻量级L4负载/反向代理替代。
[#38] MASQUERADE(家用路由器默认NAT)
sudo iptables -t nat -A POSTROUTING -o eth0 -s 192.168.0.0/24 -j MASQUERADE
含义:内网包出eth0时改写为网关IP。
场景:作WAN网关的Linux路由器/家庭服务器。
[#39] SNAT(固定源IP转换)
sudo iptables -t nat -A POSTROUTING -o eth0 -s 10.0.0.0/8 -j SNAT --to-source 203.0.113.10
含义:与MASQUERADE不同,显式指定出口IP,性能略优。
场景:WAN IP固定时建议优先使用。
[#40] 1:1 NAT(公网IP ↔ 内网IP映射)
sudo iptables -t nat -A PREROUTING -d 203.0.113.20 -j DNAT --to-destination 10.0.1.20
sudo iptables -t nat -A POSTROUTING -s 10.0.1.20 -j SNAT --to-source 203.0.113.20
含义:将一个公网IP完整映射到一台内网主机,双向NAT。
场景:让DMZ主机以独立公网IP出现的等效方案。
NAT规则生成:在iptables生成器选PREROUTING/POSTROUTING链与DNAT/SNAT选项。

9. 日志与监控 (5条)

可见性与封堵同等重要。合理使用LOG既能事后追溯又不会刷爆syslog。

[#41] DROP前记录日志
sudo iptables -A INPUT -m limit --limit 5/min -j LOG --log-prefix "iptables-drop: " --log-level 7
sudo iptables -A INPUT -j DROP
含义:每分钟最多5条进入kern.log/messages,再丢弃。
场景:取证基线,limit是防止日志风暴的关键。
[#42] 记录每一次新SSH连接
sudo iptables -A INPUT -p tcp --dport 22 -m conntrack --ctstate NEW \
    -j LOG --log-prefix "ssh-new: "
含义:不论暴力破解或正常登录,新SSH连接全部记录。
场景:有安全审计要求的环境。
[#43] 触发限速时记录
sudo iptables -A INPUT -p tcp --dport 80 -m connlimit --connlimit-above 50 \
    -j LOG --log-prefix "http-flood: "
sudo iptables -A INPUT -p tcp --dport 80 -m connlimit --connlimit-above 50 -j REJECT
含义:达到flood阈值时同时记录与拒绝,便于事故时间线复盘。
场景:对接Loki/grok管线。
[#44] 告警友好的prefix
sudo iptables -A INPUT -p tcp --dport 22 -m recent --rcheck --seconds 60 --hitcount 4 \
    --name SSH -j LOG --log-prefix "SSHBRUTE-ALERT: "
含义:专用prefix → rsyslog/Loki模式匹配触发告警。
场景:集中日志/SIEM场景。
[#45] NFLOG(用户态高吞吐日志)
sudo iptables -A INPUT -p tcp --dport 80 -j NFLOG --nflog-group 1 --nflog-prefix "http-in: "
含义:ulogd2接收group 1,可入库到PostgreSQL/JSON文件等。
场景:高吞吐包日志,避免dmesg被刷爆。

10. 应急·临时封禁 (5条)

正在被攻击或怀疑事故时立刻要用的规则。配合自动过期机制才不会越攒越多。

[#46] 立刻封禁单个IP
sudo iptables -I INPUT 1 -s 198.51.100.45 -j DROP
含义:插入到第1位(-I 1),早于其它ACCEPT规则评估。
场景:发现攻击IP后秒级封锁。
[#47] CIDR范围封禁(小型僵尸网络)
sudo iptables -I INPUT 1 -s 192.0.2.0/24 -j DROP
含义:同一段内大量IP攻击时一次性封禁。
场景:某个托管/VPS段的爆发性攻击。
[#48] 按国家整体封禁(全INPUT)
sudo iptables -I INPUT 1 -m geoip --src-cc CN,RU,KP -j DROP
含义:指定国家来源的所有端口全部丢弃,不只是SSH。
场景:无需全球访问的内部服务。需要xtables-addons。
[#49] 限时封禁(1小时后自动解除)
sudo iptables -I INPUT 1 -s 198.51.100.45 -j DROP
echo "sudo iptables -D INPUT -s 198.51.100.45 -j DROP" | at now + 1 hour
含义:借助at命令1小时后自动撤销,避免长期堆积。
场景:对软怀疑IP做临时封禁。需要at守护进程。
[#50] 自动黑名单(ipset超时)
sudo ipset create blacklist hash:ip timeout 3600
sudo iptables -I INPUT -m set --match-set blacklist src -j DROP
# 发现攻击IP时
sudo ipset add blacklist 198.51.100.99 timeout 3600
含义:加入即封锁,3600秒后自动失效。
场景:与CrowdSec、fail2ban或自研脚本一同使用。

应用时的注意事项

不要一次性把50条规则全贴上。请按以下顺序操作。

  • 避免自锁SSH:切策略为DROP之前,务必先执行iptables -I INPUT 1 -p tcp --dport 22 -s 你的IP -j ACCEPT,出错也能继续登录。
  • 规则持久化:规则只在内存中,重启会丢。用iptables-save > /etc/iptables/rules.v4保存,再用iptables-persistent在开机时恢复。
  • 勿与ufw/firewalld冲突:不要同机叠两套前端。要么二选一,要么完全理解封装层如何写底层iptables规则。
  • 预备回滚方案:动手前先iptables-save > /root/iptables.backup.$(date +%F)备份。出事用iptables-restore < /root/iptables.backup.YYYY-MM-DD立即恢复。
  • 可视化校验:用本站iptables生成器在GUI中拼装并预览规则,再贴到服务器,可大幅减少失误。

结论:50条只是起点

本文50条规则是典型Linux服务器的稳健底座。真实环境仍需按工作负载、流量形态和合规要求微调。例如PCI-DSS环境必须记录所有放行与拒绝;医疗数据服务器需要严格的ePHI访问白名单。

掌握iptables最快的方式是动手:开一台一次性虚拟机,按类别逐条应用,并故意去打破。Vagrant、LXC、Docker都可以。按本文10个类别一项项练成肌肉记忆。

想要更完整的安全背景,请结合本站Linux服务器安全指南、网络安全 - 防火墙、家庭服务器安全系列一起阅读。
