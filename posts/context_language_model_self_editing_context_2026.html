계기 — 외부 하네스의 컨텍스트 압축 한계와 프리프린트의 문제 제기

대규모 언어 모델(LLM)을 활용한 자율 에이전트가 장기 작업(long-horizon task)을 수행할 때, 가장 먼저 맞닥뜨리는 물리적 한계는 컨텍스트 윈도우의 용량과 토큰 비용이다. 수십 번의 도구 호출, 웹 탐색, 코드 실행 출력이 누적되면 컨텍스트는 순식간에 수만~수십만 토큰에 도달한다. 지금까지 에이전트 프레임워크들은 이 문제를 해결하기 위해 모델 외부의 실행 하네스(external harness)에 규칙 기반 제어기를 두는 방식을 취해 왔다. 특정 토큰 임계치에 도달하거나 작업 턴이 바뀔 때 대화 기록을 과거부터 잘라내는 슬라이딩 윈도우(sliding window)를 적용하거나, 이전 턴 전체를 서머라이저 프롬프트로 요약해 압축하는 방식이 대표적이다.

그러나 외부 하네스 주도의 컨텍스트 관리는 본질적인 결함을 내포한다. 하네스는 현재 작업에서 어떤 세부 정보가 결정적으로 중요한지 의미론적으로 완전히 이해하지 못한다. 일괄 요약(summarization) 과정에서 디버깅에 필수적인 에러 로그의 특정 스택 트레이스나 정밀한 파라미터 값이 유실되기 일쑤이며, 중요한 세부 단서가 지워지거나 환각(hallucination)으로 왜곡되는 현상이 빈번하게 일어난다. 반대로 작업이 이미 완료된 과거의 방대한 도구 반환값은 쓸데없이 자리를 차지하며 모델의 주의력(attention)을 분산시키고 추론 연산 비용을 기하급수적으로 폭증시킨다.

2026년 9월, Rulin Shao, Shannon Zejiang Shen, Nathan Lambert, Luke Zettlemoyer, Pang Wei Koh 등 13명의 연구진은 arXiv를 통해 「Context Language Models」(arXiv:2609.37725)라는 제목의 프리프린트를 공개했다. 이 논문은 컨텍스트 관리의 권한을 외부 프레임워크의 고정된 휴리스틱 규칙에서 모델 고유의 내부 행동(intrinsic behavior)으로 완전히 넘기는 패러다임 전환을 제안한다. 공식 초록에 제시된 문제의식과 핵심 목표는 다음과 같다.

  • 외부 하네스의 인위적인 컨텍스트 절단 및 일괄 요약이 초래하는 정보 손실과 환각 위험 극복
  • 컨텍스트 자체를 하나의 온전한 파일(file)로 모델에 제공하여 자율적인 부분 편집 권한 부여
  • 작업 맥락에 가장 중요한 정보만을 모델이 스스로 학습하고 선별 유지하는 자기 조율 메커니즘 수립
  • 추론 정확도 향상과 동시에 불필요한 토큰 누적을 억제하여 서버 측 부동소수점 연산량(FLOPs) 대폭 감축

이 접근법은 서튼(Rich Sutton)의 유명한 에세이 「The Bitter Lesson」(쓰디쓴 교훈)의 철학과 직접적으로 맞닿아 있다. 사람이 고안한 복잡하고 경직된 컨텍스트 관리 파이프라인 대신, 모델이 범용 연산과 학습을 통해 스스로 최적의 컨텍스트 유지 전략을 찾도록 만드는 구조다.

핵심 메커니즘 — 컨텍스트를 파일로 다루는 비제약 갱신(Unrestricted Updates)

기존 언어 모델(LM)의 컨텍스트 확장 방식은 순수하게 덧붙이기 전용(append-only)이었다. 새로운 사용자 입력이나 도구 실행 결과, 모델의 이전 추론 토큰은 기존 컨텍스트의 꼬리 부분에 끊임없이 이어 붙는 구조였다. 이를 수식으로 표현하면 시점 t의 컨텍스트 c(t) 뒤에 모델의 새로운 출력 토큰들이 결합(concatenation, ⊕)되는 형태다.

반면, 컨텍스트 언어 모델(CLM)은 다음 단계의 컨텍스트 전체를 모델 자신이 직접 변환하고 결정하는 일반 함수로 재정의한다. 대화 기록, 이전 추론, 도구 호출 결과 전체를 단일 파일로 구성하고, 모델에게 이 파일에 대한 **비제약 갱신(unrestricted updates)** 권한을 부여한다. 모델은 파일 편집 도구나 명령어를 통해 텍스트의 특정 부분을 삭제하거나, 지나치게 긴 결과를 간략히 압축하거나, 이전 단계의 작업 상태 스케치패드를 제자리에서 덮어쓸 수 있다.

// 일반적인 표준 언어 모델(LM)의 컨텍스트 전이 (단순 추가 방식)
                    c(t+1) = c(t) ⊕ fLM(c(t))
                    
                    // 컨텍스트 언어 모델(CLM)의 컨텍스트 전이 (전체 자율 변환 방식)
                    c(t+1) = fCLM(c(t))

이러한 비제약 파일 갱신 구조가 실현하는 운영상의 기술적 특성은 다음과 같이 정리된다.

  • 선택적 원문 보존: 핵심적인 지침, 특정 고유 식별자, 정밀한 에러 코드는 일괄 요약에 의해 뭉개지지 않고 원본 텍스트 그대로 파일 내에 온전히 보존된다.
  • 국소적 제자리 갱신: 예를 들어 상태 추적기나 스도쿠 판과 같은 작업 보드의 경우, 전체 컨텍스트를 재작성할 필요 없이 변경된 특정 행과 열만 제자리에서 부분 덮어쓰기(in-place update)할 수 있다.
  • 불필요한 쓰레기 데이터 폐기: 웹 크롤링이나 시스템 로그 조회에서 발생한 수천 줄의 무의미한 HTML 마크업이나 디버그 출력은 핵심 정보를 추출한 즉시 컨텍스트 파일에서 완전히 삭제된다.
  • 도구 실행과 컨텍스트의 분리: 도구를 실행했다고 해서 그 장황한 반환값이 영구적으로 컨텍스트에 박제되는 것이 아니라, 모델이 필요에 따라 즉각 압축하거나 폐기할 수 있는 작업 버퍼로 취급된다.

이 방식은 기존의 Context-as-a-Tool이나 AutoCompact처럼 사전에 정의된 특정 영역이나 특정 시점에만 모델의 개입을 허용하던 부분적 시도들을 뛰어넘어, 컨텍스트 윈도우 전체에 대한 완전한 읽기·쓰기 주권을 모델에 부여하는 형태다.

다중 에이전트 확장 — 파일 기반 컨텍스트 공존과 상태 공유

단일 에이전트 환경에서 컨텍스트를 파일로 다루는 설계는, 시스템이 다중 에이전트(multi-agent systems) 협업 환경으로 확장될 때 매우 강력한 구조적 이점을 발휘한다. 기존의 멀티 에이전트 프레임워크들은 에이전트 간 메시지 전달을 위해 복잡한 통신 프로토콜, 공유 칠판(blackboard) 객체, 혹은 별도의 메모리 서버를 구축해야 했다. 이 과정에서 메시지 직렬화와 역직렬화 오버헤드가 발생하고, 서로 다른 에이전트의 대화 기록이 뒤섞이면서 컨텍스트 오염이 빈번하게 일어났다.

논문 초록에 따르면, CLM의 파일 기반 컨텍스트는 여러 에이전트의 컨텍스트가 각각 독립된 파일(files)로 시스템 내에 공존하는 형태로 자연스럽게 확장된다. 에이전트 A의 컨텍스트와 에이전트 B의 컨텍스트가 파일 시스템 상의 별도 파일로 관리되므로 구조적 경계가 명확해진다.

  • 각 에이전트는 독립된 작업 상태 파일을 소유하여 자신의 고유한 작업 기억과 도구 호출 내역을 격리 관리할 수 있다.
  • 다른 에이전트의 작업 결과를 참조해야 할 때, 복잡한 RPC 호출 대신 공유된 상태 파일을 읽거나 명시적으로 참조하는 방식을 취한다.
  • 한 에이전트의 컨텍스트가 실패나 오류로 오염되더라도 다른 에이전트의 파일로 오염이 전파되지 않는 안전한 결함 격리(fault isolation)가 가능하다.
  • 대규모 에이전트 스웜(agent swarm) 환경에서 불필요한 전체 대화 브로드캐스팅을 방지하여 집합적 토큰 낭비를 차단할 수 있다.

초록에서 언급된 24시간 멀티 리포지토리 에이전트 스웜 과제에서 동일 연산량 대비 65% 더 큰 성능 향상을 기록한 배경에는, 바로 이러한 파일 기반의 깔끔한 컨텍스트 분리와 효율적인 상태 공유 구조가 작동했음을 알 수 있다.

벤치마크 실측치 — 제로샷 환경에서 검증된 정확도와 연산량 절감

새로운 아키텍처의 실효성을 입증하기 위해, 논문은 모델에 대한 별도의 추가 미세조정(fine-tuning) 없이 기존 파운데이션 모델을 그대로 활용한 **제로샷(zero-shot)** 환경에서 기존의 최신(SOTA) 컨텍스트 관리 기법들과 성능을 직접 비교했다. 공식 초록에 명시된 벤치마크 결과는 다음과 같다.

평가 벤치마크과제 특성 및 조건기존 SOTA 대비 CLM 실측 결과
BrowseComp-Plus장시간 심층 웹 조사 및 추론 과제정확도 11.4% 향상 (상대 비교), 연산량(FLOPs) 21.5% 절감
EdgeBench (12시간)극단적 엣지 케이스 및 장기 작업 시뮬레이션점수(scores) 5% 향상, 연산량(FLOPs) 59% 절감
Agent-Swarm (24시간)다중 저장소(multi-repo) 대상 다중 에이전트 협업동일 연산량 투입 시 65% 더 큰 성능 개선 달성
BrowseComp-Plus (Qwen3.5-9B 온라인 RL)온라인 강화학습(RL) 적용 모델 평가정확도 47.6% 대폭 향상, 연산량(FLOPs) 12% 추가 절감
서빙 가속 (Suffix Cache Reuse)표준 SGLang 서빙 엔진 대비 비교동일 정확도 유지 조건에서 서버 측 연산량 35% 절감

초록에서 입증된 실측 데이터는 세 가지 뚜렷한 공통적 특성을 보여준다.

  • 정확도와 연산량의 역 상관관계 증명: 정확도를 높이면서도 연산량을 21.5%에서 최대 59%까지 동시에 절감하는 데 성공했다.
  • 장기 작업에서의 누적 효율 격차: 작업 기간이 12시간으로 길어질수록 외부 일괄 요약보다 모델 자체 편집의 연산 절감 폭이 59%로 크게 확대되었다.
  • 다중 코드 저장소 환경에서의 협업 성능 증폭: 24시간 동안 여러 저장소를 넘나드는 고난도 에이전트 스웜 과제에서 동일 연산량 투입 시 65%의 큰 성능 개선을 기록했다.

이는 모델이 직접 불필요한 데이터를 가지치기(pruning)함으로써, 매 턴마다 어텐션 연산에 투입되는 유효 토큰 수 자체가 대폭 감소했기 때문이다. 특히 12시간 동안 실행되는 EdgeBench에서 연산량이 59%나 줄어들었다는 점은, 작업 시간이 길어질수록 외부 하네스의 누적 요약 방식보다 모델의 자체 편집 방식이 기하급수적으로 더 높은 비용 효율성을 발휘함을 명백히 보여준다.

전략 최적화 — 자연어 지시 진화와 온라인 강화학습의 성과

컨텍스트 관리를 외부 하네스의 고정된 하드코딩 코드에서 모델의 내재적 행동으로 전환함에 따라, 또 다른 결정적인 지평이 열렸다. 바로 컨텍스트 관리 전략 자체를 **인컨텍스트(in-context) 학습과 파라메트릭(parametric) 강화학습**을 통해 지속적으로 진화시키고 최적화할 수 있게 되었다는 점이다.

연구진은 표준적인 스킬 최적화 루프(skill-optimization loop)를 적용하여 모델이 컨텍스트를 편집할 때 참조하는 자연어 지시문(natural-language instructions)을 진화시켰다. 어떤 시점에 어떤 패턴으로 로그를 압축하고, 어떤 형식으로 요약본을 유지해야 하는지에 대한 프롬프트 지침이 반복적 평가를 통해 고도화되었다. 초록에 따르면, 이러한 자연어 지시 유도만으로도 연산량을 줄이면서 보류 평가셋(held-out set) 기준 정확도를 **최대 35.9포인트(points)**까지 끌어올렸다.

더 나아가 연구진은 CLM을 위한 온라인 강화학습(online reinforcement learning) 방법론을 도입했다. 오픈소스 모델인 Qwen3.5-9B를 대상으로 온라인 강화학습을 수행한 결과, 심층 조사 벤치마크인 BrowseComp-Plus에서 **성능이 무려 47.6% 향상되면서도 연산량은 12% 더 적게 사용**하는 결과를 입증했다. 이 학습 최적화 과정이 입증한 핵심 원리는 다음과 같다.

  • 프롬프트 진화만으로도 보류 평가셋에서 최대 35.9포인트의 큰 폭의 정확도 개선 달성
  • 모델 파라미터가 효율적인 편집 정책을 직접 체화하여 소형 모델에서도 연산량 절감 달성
  • 오픈 가중치 모델 Qwen3.5-9B에서 47.6% 개선이 초록에 보고됨
  • 자연어 기반 프롬프트 스킬과 가중치 기반 강화학습의 상호 보완적 결합 경로 제시

서빙 최적화 — Suffix Cache Reuse와 KV 캐시 재사용 구조

컨텍스트를 중간에서 자유롭게 편집하는 방식은 이론적으로 매우 매력적이지만, 실제 LLM 추론 서빙 인프라 관점에서는 심각한 기술적 병목을 유발한다. 현대의 vLLM이나 SGLang 같은 고성능 서빙 엔진은 컨텍스트의 앞부분이 고정되어 있다는 전제하에 작동하는 **접두사 캐싱(Prefix Caching, RadixAttention)**에 전적으로 의존하기 때문이다.

기존 서빙 체계에서는 컨텍스트의 시작점부터 일치하는 토큰 시퀀스에 대해서만 미리 계산된 Key-Value(KV) 캐시를 재활용한다. 만약 모델이 컨텍스트의 중간 텍스트나 앞부분의 도구 반환값을 삭제하거나 수정하면, 그 변경 지점 뒤에 오는 모든 후속 토큰들의 위치 인코딩(positional encoding)과 캐시가 무효화(invalidation)된다. 결국 편집이 일어날 때마다 뒤따라오는 방대한 텍스트의 KV 캐시를 서버가 처음부터 다시 계산(prefill recomputation)해야 하므로, 서버 연산량이 폭증하게 된다.

// 기존의 표준적인 접두사 캐싱 (Prefix Caching)
                    [ 공통 시스템 프롬프트 (캐시 재사용) ] -> [ 변경 지점 (캐시 무효화) ] -> [ 후속 전체 재계산 ]
                    
                    // CLM이 공동 설계한 Suffix Cache Reuse 구조
                    [ 공통 프롬프트 ] -> [ 중간 편집 영역 ] -> [ 변하지 않은 후속 컨텍스트 (접미사 캐시 재사용) ]

연구진은 이 인프라 레벨의 병목을 해결하기 위해 서빙 엔진과 공동 설계한 **Suffix Cache Reuse(접미사 캐시 재사용)** 기술을 제안했다. 비록 컨텍스트 중간이나 상태 파일의 일부 라인이 편집되더라도, 변경되지 않은 채 그대로 유지되는 후속 텍스트 블록의 KV 캐시를 식별하여 연산 없이 재사용하는 메커니즘이다. 초록에 명시된 바에 따르면, Suffix Cache Reuse는 표준 SGLang 엔진과 동일한 작업 성능을 유지하면서도 **서버 측 연산량을 35% 추가로 절감**했다. 이는 모델 수준의 편집 기능과 추론 런타임 최적화가 유기적으로 맞물려야만 실용성을 얻을 수 있음을 방증한다.

하네스 고정 규칙 대비 설계 선택의 트레이드오프

컨텍스트 언어 모델이 보여준 인상적인 벤치마크 결과에도 불구하고, 외부 하네스의 통제를 벗어나 모델에게 컨텍스트 편집의 전권을 위임하는 설계는 실무 운영 관점에서 결코 무시할 수 없는 트레이드오프와 리스크를 동반한다.

  • 시스템 지침 및 안전 프롬프트의 자체 삭제 위험: 모델이 컨텍스트를 자유롭게 편집할 수 있다면, 탈옥(jailbreak) 시도나 추론 오류로 인해 시스템 프롬프트나 핵심 보안 정책 가드레일을 실수로 삭제해 버릴 위험이 상존한다.
  • 도구 스키마 및 인터페이스 파손: 모델이 도구의 JSON 스키마나 API 명세를 요약한답시고 문법을 변형하면, 이후의 도구 호출이 연쇄적으로 실패(crash)할 수 있다.
  • 편집 루프 자체의 연산 오버헤드: 컨텍스트를 편집하기 위해 별도의 도구를 호출하거나 편집 텍스트를 생성하는 토큰 비용이 발생하므로, 단순하고 짧은 작업에서는 오히려 배보다 배꼽이 더 커질 수 있다.
  • 서빙 인프라의 복잡도 급증: Suffix Cache Reuse와 같은 특화된 캐시 재사용 엔진을 직접 패치하거나 호스팅해야 하므로, 범용 클라우드 API(예: OpenAI나 Anthropic의 관리형 엔드포인트) 환경에서는 즉각적인 인프라 이점을 온전히 누리기 어렵다.
  • 디버깅 및 재현성의 어려움: 컨텍스트가 모델의 동적 판단에 따라 매 순간 다르게 변형되므로, 과거 세션에서 왜 특정 오류가 발생했는지 동일한 프롬프트로 재현하고 감사(audit)하기가 훨씬 까다롭다.
  • 소형 모델의 편집 능력 편차: 초록에서는 Qwen3.5-9B의 성공적인 강화학습 사례를 보고했으나, 지능이 상대적으로 낮은 경량 모델의 경우 컨텍스트를 직접 편집하려다 필요한 단서를 엉뚱하게 지워버리는 실수를 저지를 확률이 높다.

종합적으로 볼 때, Context Language Models는 에이전트 인프라가 나아가야 할 방향에 대해 중요한 화두를 던진다. 컨텍스트를 더 크게 늘리는 것(Context Maxxing)만이 능사가 아니며, 모델이 스스로 지적인 가지치기와 상태 관리를 수행할 수 있을 때 비로소 장기 작업의 비용과 신뢰성이 확보될 수 있음을 실측 수치로 보여주었다.

  • 본 논문은 2026년 9월 arXiv에 제출된 프리프린트(arXiv:2609.37725v1)이며, 학술대회나 저널의 동료 검토(peer review) 통과 여부는 확인되지 않았다.
  • 초록에 기술된 수치 외에, PDF 본문에 수록된 상세 실험 표나 개별 벤치마크 하위 태스크별 절대 점수. 초록 밖의 세부 수치는 이 글의 범위가 아니다.
  • Qwen3.5-9B 온라인 강화학습에 사용된 보상 모델(reward model)의 구조와 손실 함수(loss function)의 수학적 정식화.
  • 모델이 컨텍스트 파일 내부의 시스템 프롬프트나 민감한 지침을 임의로 훼손하는 것을 방지하기 위한 권한 분리(permission boundary) 계층의 존재 유무.

  • 클로즈드 소스 상용 모델의 API 환경에서 Suffix Cache Reuse 없이 CLM을 구현했을 때의 실제 토큰 과금 비용 변동치.
