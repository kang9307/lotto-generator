从外部测量模型规模的尝试

什么能成为信号，什么成不了 - 以及推定值该信到哪一步

2026年8月29日 开发/基础设施

引言: 报价单上有一格填不出来

写引入评估文档时，总有一格没人填得出来。这个模型到底有多大。要判断能否自建托管，得知道权重占多少 GB；要给出性能预期，得知道它属于哪个量级。可供应方公开的只有价目表和上下文长度。于是团队里有人复述一个在别处看到的数字，那个数字进了会议纪要，两个月后就在出处消失的情况下被当成前提使用。

不公开本身不是什么坏事。权重规模会把训练开销与基础设施形态直接暴露出来，因此选择不公开是常见的商业决定。只是这个决定让外面的人只能靠可观测的信号去推测内部，并且得自己判断这份推测有多牢靠。

最近有一种正面处理这个题目的方法公开了。Trillion Labs 博客提出的 IKP(Incompressible Knowledge Probes) 通过测量模型记住了多少稀有事实来反推量级。前提是推理能力可以靠训练方法提升，而需要被记住的事实本身是压不掉的。

这里不打算搬运那篇文章，而是退后一步来看。只凭外部可见之物去推断内部，原理上是一件什么样的工作，又会在哪里塌掉。先说结论：从外部得到的信号全部是多种原因的合成，所以给出的答案永远不是数值，而是范围。

1. 为什么想知道规模

这个问题常被当成好奇心，但实际上问起规模的场合，多半是决定即将做出的场合。

  • 为了定出成本下限 — 权重整体必须驻留在内存里，因此规模决定了自建托管所需的加速卡数量与最低配置。只有这一处，规模几乎就是直接的答案
  • 为了预先校准性能预期 — 知道量级，就大致清楚它能顺利跨过多难的任务，从哪里开始需要靠提示词去补
  • 为了保住可复现性 — 要复核论文或内部实验的结论，就需要对照条件。不知道规模，比较本身就不成立
  • 为了读懂市场坐标 — 判断开放权重模型追赶闭源模型追到了哪一步，不能只看分数，还要看拿出这份分数所动用的规模
  • 为了判断能否往下降 — 能不能换成更便宜的档位，终归要先知道现在用的是什么量级；在讨论单价是否合理的谈判桌上，需要的也是同一个数字

这几条里只有第一条与规模一一对应。其余的即便把数字交到手上，答案也不会自动出现。这个事实在文章后半还会再出现一次，因为估计规模所花的力气里，相当一部分其实是把别的问题错译成了规模。

2. 规模这个词指着的四样东西

动手估计之前得先定下一件事：要测的是什么。没有这个共识，两个人就会用同一个词说着不同的数字互相争论。

是什么决定什么从外部如何显现
总参数内存常驻量、存储容量、部署难度几乎看不见。只有与知识量相关的观测结论
激活参数处理单个词元所需的运算量与每词元生成时间、单价反应得比较接近
非嵌入参数主体的表达力，不受词表大小影响的比较看不见。只有词表大小能从分词器确认
训练词元量在同样规模下把性能拉开看不见。只能从知识覆盖面间接推测

实务中最常错开的就是前两行。说某个模型大的时候，这句话是在讲内存还是在讲运算，会导向完全不同的结论。自混合专家结构普及以来，这两者可以拉开十倍以上。

第四行同样常被忘掉。参数量相同，投入训练的词元量不同，结果就不同。想只凭规模预测性能的尝试之所以一再落空，有一半原因就在这里。

3. 这次的提案选中的信号 — 压不掉的知识

IKP 的想法很简单。去问那些推理导不出来的事实，也就是不存在某处就答不上来的信息，再从答对的数量反推存储容量。某个活动是哪一年开始的这类问题，再聪明也推不出来。

它靠两个前提。一是被存下的事实量与模型规模之间存在很强的关系。二是推理能力会随时间在同样规模下变好，而记忆量不会以同样的速度变好。解题的方法可以变得高效，但要背下来的东西本身仍然占地方。

该提案说明的测量条件如下。搬运数值时，必须把测的是什么、在什么条件下测的一并写上。

  • 基线用93 个开放权重模型建立。先在规模公开的模型上把记忆量与规模的关系拟合出来，再把闭源模型放到那条线上
  • 题目分成七个难度档。简单的事实小模型也答得出来，不分档的话高端区间就没有区分度了
  • 用逐个抽掉一个模型、再用其余模型去预测它的方式验证，报告的一般误差约为 1.48 倍
  • 随时间的走势另外在100 个模型上检查，混合专家结构的处理方式则通过41 个 MoE 模型的比较来确认
  • MoE 按总参数口径换算。依据是记忆量与总参数的关联强于与激活参数的关联这一观测

作者自己讲明的局限同样清楚。精确参数量查不出来；一万亿以上的区间只有两个可作参照的公开模型，不确定性很大；经常拒答的模型，其数值应当读作下限而不是真实的知识容量。

这条路子相对其他信号有一个好处。它较少被部署方式扰动。价格与延迟会被服务基础设施改写，而记住了什么则在权重里面。代价是它引入了训练数据构成这个新变量。大量灌入事实训练出的小模型，与偏重代码和推理的大模型，并不会落在同一条线上。

4. 从外部可见的其他信号

除了记忆量，可观测的值还有好几个。麻烦在于它们个个都是多种原因的合成。把每个信号暗示什么、无法暗示什么分开摆好，就能判断哪些主张可以当依据用。

信号它暗示什么它无法暗示什么
首个词元的等待时间队列状态、预填充余量、路由结构参数量。输入长度与服务器拥塞的影响更大
每词元生成时间解码路径的宽度、内存带宽的余裕总参数。若是 MoE，只照亮激活那一侧
并发吞吐量批处理余量与基础设施规模模型规模。大集群跑大模型同样很快
词元单价供应方的市场策略与目标客群成本。价格与成本之间还隔着一层策略
上下文长度关于注意力设计与缓存预算的决定参数量。这是设计选择，不是规模的结果
分词器词表大小嵌入矩阵的规模、模型的谱系主体大小。词表大而层数浅是可能的
知识覆盖面存储容量与训练数据的结合两者的分离。数据构成不同，同样规模看起来也不同

表格右列最接近本文的核心。没有任何单一信号能独自指向规模。反推要成立就得把其余变量固定住，而站在外面的人没有可以握住它们的把手。

5. 价格是策略，不是成本

看上去最省事的信号，偏得也最厉害。单价是公开的，落成一个干净的数字，看着好比较，可在这个数字被造出来的过程里，成本只是若干输入之一。

  • 引流价 — 新入场的供应方为买份额，可能把价格定在成本之下；到了面向开发者的免费额度，与成本的联系干脆断掉。在这个区间用价格读规模，读出来会偏小
  • 打包销售 — 含在高阶订阅里的用量并不换算成单价。同一个模型在不同渠道有不同的面孔
  • 分档定价 — 批处理、夜间时段、缓存命中部分各有各的单价。一组权重身上挂着三四个价格
  • 利用率 — 同样的硬件，闲置时间一长，实际成本就上去了。把需求填得满的供应方卖得更便宜也仍有余
  • 硬件世代与电力 — 成本本身就随合同条款和当地电价而变。从外面甚至看不出它跑在哪一代硬件上

归拢起来，从价格通向规模的箭头要跨过两次未知数：一次从价格到成本，一次从成本到规模。把经过两次跳跃的值当依据，实际上就是读了对方公司的销售策略，然后管它叫模型规模。单价为什么降了而账单不动，另有一篇推理单价一直在降，账单却没变专门谈过。

6. 延迟与输出分布 — 两扇窗各自看见什么

比起价格，时间与概率更靠近物理。只是各自都带着特有的模糊。

6.1 首个词元与每个词元测的是两回事

把响应延迟看成一个数字，什么也看不出来。至少要拆成两截。首个词元出现之前的时间，是请求在队列里等待的时间加上把输入整体过一遍的预填充时间；后续词元之间的间隔，则是单个生成步的开销。前者随输入长度增长，后者大体恒定。

与规模有关的是后者。生成步通常被内存带宽卡住，所以造一个词元要读的权重越多就越慢。可一旦想从实测中把这层关系取出来，就会撞上好几重雾。

  • 动态批处理 — 请求会与其他用户的流量捆在一起处理，同一个请求在不同时段会呈现不同速度
  • 前缀缓存 — 前半部分若已算过，预填充会被整段跳过。同一段提示词发两次，第二次更快就是这个缘故
  • 投机解码 — 若采用小模型先提出若干词元、大模型一次性校验的方式，每词元时间就与主体规模对不上了
  • 路由与调度 — 查询可能被送往不同的后端，落在哪个数据中心的哪块加速卡上也会改变数值。被测的对象本身随请求而变

这四项改变延迟的理由都与规模无关。所以基于延迟的估计，要凑齐同一时刻、同样输入长度、足够多的重复才勉强得到可比的值，而这样得到的值也只照亮激活参数那一侧。硬件这条轴上究竟什么会成为瓶颈，整理在选推理硬件时真正拉开差距的是什么里。

6.2 输出分布这扇窄窗

只要能看到模型对下一个词元赋予的概率哪怕一部分，得到的信息就远多于只看文本：词表的大小、输出层的结构、同一谱系分出的模型之间的相似度。学术界之所以出现这个方向的方法，原因也在这里。输出层维度上限这类结构性质，只要收集到足够多样的输出，原理上就会浮现出来。

只是这扇窗在实务中大多是关着的。商用 API 要么根本不返回概率值，要么限制在前若干个候选，而且那也是经过安全过滤与采样设置之后的值。何况这类结构估计需要大量查询，这里连着费用问题与服务条款问题。商用服务的使用条件中，限制试图查明模型内部结构之行为的条款相当常见。所以本文不写方法。研究会用到这类思路，到此为止就是这一节要谈的范围。

7. 混合专家打碎的直觉

在混合专家结构普及之前，规模、成本与能力大体朝同一个方向走。大就聪明、就慢、就贵。现在不是了。

  • 内存要装下总量。所以自建托管的开销由总参数决定
  • 单个词元的运算只用到激活那部分。所以响应速度与单价跟着激活参数走
  • 有观测显示，记住的事实量更贴着总量一侧。这也是这次的提案把 MoE 按总参数口径换算的依据
  • 于是又快又便宜却知道得多的组合成为可能，这是旧直觉解释不了的位置。何况从外部连密集型还是混合型都分不出来，这次的方法也明确写着无法作此区分

正因如此，用多少 B 这样一个数字去说的那一刻，就已经把其中一侧说错了。说总量，就在速度与单价上给出错误预期；说激活量，就在部署成本与知识广度上给出错误预期。至少写上两个数字，句子才立得住。架构为什么朝这个方向走，在LLM架构最新动向2026里谈过。

8. 估计常常出错的四条路

测量方法再精细，被测的对象不肯待着不动，结果就会偏。真正把估计打垮的，多半不是方法论，而是下面这四样。

  • 蒸馏 — 用大模型的输出去教小模型，小模型就会显出与自身规模不相称的能力。从能力通向规模的回归线在这一点上被掰弯
  • 量化与服务优化 — 同样的权重以更低精度运行，内存占用与速度都会变。想从延迟读规模的尝试，会在这里拾到系统性误差
  • 路由 — 一个名字后面可能站着好几个模型。短而简单的查询走轻量后端、困难查询走重型后端时，究竟测到了什么，取决于查询的构成
  • 版本更替 — 端点名保持不变而里面的东西被更新，这是会发生的。上个月的测量值属于上个月的模型，没有任何东西保证它今天仍然成立

上面还要再压一条。我们通过 API 遇到的，通常不是模型本身，而是叠了系统提示词、工具调用与检索增强的产品。答对了某个事实，不等于那个事实原本就在权重里。对基于知识的估计来说，这个区分是致命的。

所以从外部得到的测量值必须带上日期、端点与配置。缺了这三样就没法复核，而无法复核的数字不是依据。

9. 该怎样拿捏推定值

那么该信到哪一步。准则可以缩成一句：没有范围与前提的数字不用。

先对误差倍数究竟意味着什么建立感觉，判断就容易了。假设某方法的一般误差在 1.5 倍上下，那么三千亿量级这个推定，意思是大约在两千亿到四千五百亿之间。这个宽度用来划量级绰绰有余，用来比较供应商则完全不够。同一方法给出的两个推定若相差 1.3 倍，那不是差异，是噪声。

遇到推定值时该问的若没有答案
说的是总参数还是激活参数不拿它与其他推定值作比较
什么时候测的当作没有保质期的值处理，也就是不引用
作为基线的模型集合是什么该集合之外属于外推，可信度大幅下调
报告的误差是多少不当作点估计来读，只用于判断量级
是否对拒答与安全过滤做了校正只当作下限来读
中间是否夹着检索或工具调用不解释为模型自身的性质

就算是通过了这张表的推定值，能说的话也有限。这个模型大致处在某个量级是上限；这个模型有多少 B 则不论出自何处都已越界。引用时把原作者附上的条件摘掉、只搬走数字，那一刻，谨慎做出的推定就变成了没有依据的事实。实际上大部分污染并非发生在方法论，而是发生在引用这一步。

10. 该用什么代替规模去测

回到前面搁下的话。问规模的问题里，相当一部分其实是别的问题。而那些别的问题，多半可以直接测量，甚至更容易。

  • 自己工作里的准确率 — 几十条规模的自建评测集就足以起步。它比任何公开排行榜都更直接地回答引入决策
  • 失败的类型与频率 — 比起错得多不多，怎么错更要紧。悄无声息地错与直接拒答，应对方式完全不同；而触发安全过滤的比例随业务性质差得很远，却与规模无关地左右着产品质量
  • 每项任务的成本 — 看的是完成一项工作的总花费，而不是词元单价。这个数字要把重试与冗长的思考过程都算进去才有意义
  • 延迟的分布 — 不看平均，拆成 p50 与 p95 来看。用户感受到的是尾部
  • 有效上下文 — 看的不是标称长度，而是在那个长度上质量是否撑得住。两者常常不同
  • 对替换的耐受度 — 模型被悄悄更新之后还撑得住吗。手里攥着一套回归用例，至少能在事后察觉更新发生过

这份清单上的值有个共同点。可以自己动手重新测，对象一变，值也跟着变。从外部估出来的参数量两条都不满足。评测集要怎么起步，另写在没有定义失败的评估只会产出数字里。

那规模估计是没用的吗。并非如此。要把握整个市场的格局、要给开放权重阵营走到了哪一步定位、要分辨某项能力是靠规模还是靠数据与训练方法，这类估计是唯一的材料。只是那个位置是理解产业的位置，不是设计自己系统的位置。设计上的决定，用自己测出来的值。

未能确认的部分

  • IKP 所用题目集合的具体构成与题量，未能从公开文章中确认。已公开的只到难度分为七档这一步
  • 报告中约 1.48 倍这个误差出自何种分布假设、是否随规模区间而不同，未能确认
  • 把该方法应用于商用模型所得的数值，本文没有搬运。既无从验证，搬来也等于把带条件的推定当作事实去流通
  • 其他研究团队的复现结果，以及服务条款如何界定结构估计，均未能确认。前者发布时间尚近、后续验证还没有出现；后者各供应方条款不一，本文未逐条比对

结论: 留下的三件事

从外部测量内部，原理上是从多种原因的合成信号中把其中一个拣出来的工作。只要其余变量固定不住，答案就以区间而非点的形式出现。接受这一点，对待推定值的态度也就理顺了。

  • 先定下说的是哪一种规模。自从总量与激活量分家之后，没有这个共识，任何比较都不成立
  • 不引用缺少范围与前提的数字。摘掉条件的引用制造了绝大部分污染
  • 决定要用自己测出来的值。准确率、每任务成本、尾部延迟不知道规模也测得出来，而知道了规模它们也不会因此得到回答

用记忆量去读量级之所以有意思，不是因为它准，而是因为它在价格与延迟晃动得最厉害的地方，挑了一个相对不那么晃的信号。好的估计不来自猜中答案，而来自知道哪块地面更稳。而知道这一点的人，不会因为给自己的推定值加上范围而觉得难为情。
