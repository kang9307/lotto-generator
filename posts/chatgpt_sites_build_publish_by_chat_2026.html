계기 — 대화 인터페이스에서 배포까지 이어지는 ChatGPT Sites

OpenAI는 대화창에서 웹사이트, 경량 웹 애플리케이션, 인터랙티브 도구를 직접 생성하고 호스팅과 배포까지 완결할 수 있는 ChatGPT Sites 기능을 공개 베타 형태로 선보였다. 기존에 다루었던 OpenAI Codex Sites 플러그인이 개발자 중심의 프롬프트 배포 파이프라인에 초점을 맞추었다면, 이번 ChatGPT Sites는 일반 ChatGPT 인터페이스 안에서 대화와 프리뷰, 인앱 테스트, 그리고 최종 게시까지 한 번에 처리하도록 통합된 환경을 지향한다.

사용자는 대화창에서 원하는 웹사이트의 형태와 목적을 설명하거나 @Sites를 호출하여 작업을 시작할 수 있다. 텍스트 지시 외에도 로컬 파일이나 디자인 시안, 기존 프로젝트 코드를 참조 자료로 업로드할 수 있으며, 내장된 브라우저 환경에서 동작을 즉시 검증하면서 레이아웃이나 인터랙션을 대화형으로 수정해 나갈 수 있다.

그러나 사이트를 생성하는 과정이 간소화될수록 게시자가 반드시 주의해야 하는 보안 및 운영상의 책임은 오히려 무거워진다. 사이트가 어떤 도메인으로 외부에 노출되는지, 방문자가 입력한 데이터가 어디에 어떻게 저장되는지, 그리고 조직 내부의 워크스페이스에서 구성원 간 권한이 어떻게 분리되는지를 정확히 인지하지 못하면 의도치 않은 정보 유출이 발생할 수 있다.

기본 비공개 상태와 워크스페이스 공유 범위

OpenAI 공식 도움말 문서에 따르면 ChatGPT Sites를 통해 생성된 모든 새 사이트는 생성 즉시 외부에 열리지 않고 기본 비공개(Private by default) 상태로 보호된다. 이는 작업 중인 미완성 페이지나 실험용 코드가 의도치 않게 검색 엔진이나 제3자에게 노출되는 사고를 원천적으로 방지하기 위한 설계다.

공식 문서가 규정하는 초기 접근 제어와 워크스페이스 공유 규칙은 다음과 같다.

  • 새 사이트의 초기 접근 권한은 사이트를 직접 생성한 소유자와 소속 워크스페이스 관리자에게만 제한된다.
  • 사이트가 생성된 직후에는 외부 방문자뿐만 아니라 워크스페이스 내의 일반 팀원도 해당 페이지를 열람할 수 없다.
  • 소유자는 워크스페이스 정책과 구독 요금제 설정에 따라 선택된 특정 구성원만 개별 초대할 수 있다.
  • 조직 전체가 활용해야 하는 대시보드나 내부 포털의 경우 워크스페이스 전체 공유 모드로 전환할 수 있다.
  • 외부 열람자를 초대하는 기능은 지원 요금제에 순차적으로 적용 중이며 조직 관리자의 사전 승인이 필요할 수 있다.
  • 전체 공개(Public)로 전환하기 전에는 인증 요구 여부와 공유 링크의 활성화 범위를 반드시 재검토해야 한다.

이러한 단계적 공개 구조는 엔터프라이즈 환경에서 매우 중요한 의미를 지닌다. 사내 전용 도구나 고객 응대 포털을 제작할 때, 작성자가 실수로 게시 버튼을 누르더라도 즉각적인 대외 공개로 이어지지 않도록 다중 안전장치가 적용되어 있음을 의미한다.

공동 편집과 권한 분리 — 소유자, 편집자, 외부 열람자

ChatGPT Sites는 단독 제작 도구에 머무르지 않고 팀 단위의 협업을 지원하기 위해 편집자(Editor) 초대 기능을 갖추고 있다. 소유자는 자신이 소속된 워크스페이스의 활성 멤버를 사이트의 공동 편집자로 지정할 수 있다.

공식 문서에 따른 역할별 권한 경계는 다음과 같이 구별된다.

  • 소유자(Owner): 사이트를 최초로 생성하고 최초 1회 게시를 실행할 수 있는 유일한 권한을 가지며, 편집자 초대 및 도메인 설정을 총괄한다.
  • 편집자(Editor): 소유자가 사이트를 최소 1회 이상 게시한 이후부터 레이아웃, 텍스트, 로직을 수정하고 업데이트 버전을 직접 게시할 수 있다.
  • 편집자의 데이터 접근: 편집자는 사이트 수정 권한뿐만 아니라, 사이트에 누적 저장된 데이터베이스 레코드와 업로드 파일에도 열람 접근권을 갖는다.
  • 외부 열람자(Viewer): 사이트의 결과 화면만을 탐색하고 이용할 수 있으며, 프롬프트 수정, 코드 변경, 관리자 데이터베이스 접근은 전면 차단된다.
  • 워크스페이스 관리자: 보안 거버넌스 차원에서 조직 내에서 생성된 모든 사이트의 메타데이터와 접근 통제 상태를 감시할 수 있다.
  • 권한 회수 및 변경: 구성원이 워크스페이스에서 비활성화되거나 소유자가 초대를 취소할 경우 편집 권한과 저장 데이터 접근권은 즉시 중단된다.

여기서 특히 주목해야 할 지점은 편집자가 사이트에 저장된 데이터에 접근할 수 있다는 사실이다. 방문자의 설문 응답이나 고객 문의 데이터가 축적되는 사이트라면, 편집자를 추가할 때 해당 구성원이 사내 개인정보 취급 규정을 충족하는지 사전에 점검해야 한다.

방문자 로그인과 데이터 저장소 구조

단순한 정적 페이지를 넘어 사용자와 상호작용하는 웹 애플리케이션을 구현하기 위해 ChatGPT Sites는 자체적인 인증 체계와 영속적 저장 공간을 제공한다. 핵심 요소는 Sign in with ChatGPT(ChatGPT로 로그인) 기능과 내장 데이터베이스 및 파일 스토리지의 결합이다.

공식 안내와 기술 문서를 통해 확인된 데이터 처리 및 인증 특성은 다음과 같다.

  • 방문자가 자신의 ChatGPT 계정으로 로그인하면 세션이 유지되어 작업을 중단했다가 나중에 돌아와도 이전 상태를 이어갈 수 있다.
  • 게임 점수, 개인별 환경 설정, 양식 입력값 등의 정형 데이터는 내장 관계형 데이터베이스(D1 기반)에 안전하게 기록된다.
  • 방문자가 업로드한 이미지, PDF 문서 등의 비정형 미디어 파일은 객체 저장소(R2 기반)를 통해 격리 관리된다.
  • Business 및 Enterprise 워크스페이스에서는 방문자가 자신이 사전에 연결해 둔 업무 도구에 대해 읽기 전용 접근을 승인할 수 있다.
  • 도구 연동 시 사이트는 방문자 본인에게 이미 열람 권한이 있는 정보만 조회하며, 제작자의 계정 권한을 빌려 쓰거나 데이터를 변조하지 않는다.

이러한 구조는 백엔드 서버를 별도로 구축하거나 외부 인증 공급자(OAuth)를 복잡하게 연동하지 않고도 회원제 서비스나 맞춤형 포털을 빠르게 구축할 수 있게 돕는다. 반면 방문자의 개인정보와 파일이 OpenAI의 인프라 내부에 저장되므로, 서비스 약관 및 개인정보 처리방침에 부합하는 데이터만 수집하도록 입력 양식을 설계해야 한다.

호스팅 식별 체계와 맞춤 도메인 연결 시 고려 사항

ChatGPT Sites에서 사이트를 게시하면 별도의 인프라 구성 없이 OpenAI가 호스팅을 즉시 처리한다. 기본적으로 사이트는 서브도메인 형식의 고유 웹 주소를 부여받으며, 필요에 따라 사용자가 보유한 독립 도메인을 연동할 수 있다.

호스팅 주소 체계와 도메인 설정 시 검토해야 할 사항은 다음과 같다.

  • 기본 호스팅 주소는 *.chatgpt.site와 같은 구조의 서브도메인 형태로 발급된다.
  • 소유자는 기본 제공되는 사이트 주소의 이름을 원하는 명칭으로 변경할 수 있다.
  • 기존 호스팅 URL의 이름을 변경할 경우, 이전 주소로 접속한 방문자는 시스템에 의해 새 주소로 자동 리다이렉트된다.
  • 기업 브랜드나 개인 브랜딩을 위해 자체 도메인(Custom Domain)을 소유하고 있다면 이를 사이트에 연결할 수 있다.
  • 도메인 연결을 위해서는 도메인 등록기관(DNS 관리자)에서 지정된 레코드를 올바르게 구성해야 한다.
  • 맞춤 도메인을 활성화한 후에도 기본 호스팅 경로와의 연결 상태가 정상 유지되는지 접속 검증이 필요하다.

주소 이름을 바꿀 때 이전 주소가 새 주소로 자동 연결되는 메커니즘은 공유 링크의 단절을 막아주는 유용한 장치다. 다만 공식 업무용으로 사이트를 외부에 공개할 때는 조직의 공식 도메인을 연결하여 피싱이나 비인가 사이트로 오인받지 않도록 브랜딩 신뢰성을 확보하는 것이 바람직하다.

기본 비공개 (Private) 사이트 소유자 및 워크스페이스 관리자 전용 ChatGPT 워크스페이스 로그인 필수 소유자만 수정 가능, 데이터 열람 제한
초대된 구성원 (Invited) 소유자가 명시적으로 이메일 초대한 팀원 초대받은 계정으로 로그인 후 접근 초대 시 부여된 역할(편집자 또는 뷰어)에 따라 분기
워크스페이스 공유 (Workspace) 동일 워크스페이스 내의 모든 활성 구성원 조직 워크스페이스 계정 인증 필수 구성원은 뷰어로 접근, 지정된 편집자만 수정 가능
전체 공개 (Public) URL을 알고 있는 인터넷 상의 모든 사용자 로그인 없이 접근 가능 (선택적 로그인 연동) 외부 사용자는 전면 읽기 전용, 편집 권한 절대 불가

이와 같이 명확히 분리된 권한 체계를 이해하고 사이트의 성격에 맞춰 적절한 단계를 설정해야 한다. 내부 지식 공유용 도구는 워크스페이스 단계에 머물러야 하며, 마케팅 랜딩 페이지나 대외 공개 포트폴리오만 전체 공개 단계를 적용하는 것이 안전하다.

확인하지 못한 것

  • 요금제별 구체적인 사이트 생성 개수 상한 및 월간 트래픽 대역폭 수치. 공식 문서는 플랜과 지역에 따라 다르다고만 명시했다.
  • 공개 베타 기간의 구체적인 종료 시점 및 정식 상용화(GA) 일정. OpenAI 공지에는 베타 기간에 대한 날짜 정보가 없다.
  • 자체 맞춤 도메인 연결 시 SSL/TLS 인증서의 갱신 주기와 자동 발급 메커니즘에 대한 세부 기술 사양.
  • 향후 무료 요금제(ChatGPT Free) 사용자에게 읽기 전용 또는 제한적 생성 기능이 제공될 계획이 있는지 여부.
  • 사이트에 저장된 D1/R2 데이터베이스의 외부 백업 덤프 다운로드 기능이나 타 클라우드로의 데이터 마이그레이션 도구 지원 여부.
  • 사이트 내에 삽입될 수 있는 외부 자바스크립트 라이브러리나 서드파티 분석 스크립트에 대한 샌드박스 보안 제약 수준.
