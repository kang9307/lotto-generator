YAML과 JSON, 왜 자주 변환할까?

DevOps·SRE 워크플로에서 YAML과 JSON은 본질적으로 동일한 데이터 모델을 다루지만, 사용처가 다릅니다. Kubernetes manifest, docker-compose.yml, GitHub Actions, Helm chart, Ansible playbook은 대부분 YAML이지만, API 응답·환경 변수·CI 변수 주입·jq 파이프라인은 JSON이 표준입니다. 이 도구는 두 포맷 사이를 한 번에 오가며 들여쓰기 오류와 따옴표 누락을 즉시 잡아냅니다.

  • 실시간 변환 · 타이핑하는 즉시 변환되며 에러 라인을 표시합니다 (브라우저에서만 처리, 서버 전송 없음).
  • 입력 형식 자동 감지 · 첫 글자가 { 또는 [면 JSON, 그 외는 YAML로 처리합니다.
  • 키 알파벳 정렬 · 객체 키를 정렬하여 diff와 코드 리뷰가 깔끔해집니다.
  • YAML 1.2 strict 모드 · yes/no/on/off를 boolean으로 자동 해석하지 않아 k8s에 안전합니다.
  • 들여쓰기 옵션 · 2 또는 4 스페이스 선택 (YAML 공식 권장은 2).

자주 묻는 질문

변환된 데이터가 외부 서버로 전송되나요?

아니요. 모든 변환은 브라우저 안에서 js-yaml 라이브러리로 처리됩니다. 네트워크 요청 없이 로컬에서만 동작하므로 사내 manifest나 민감한 secret 키를 안전하게 다룰 수 있습니다.

큰 파일도 처리되나요?

일반적으로 수 MB까지는 즉시 처리됩니다. 다만 너무 큰 파일(10MB 이상)은 브라우저가 잠시 멈출 수 있으므로, 그런 경우에는 실시간 변환을 끄고 수동으로 변환 버튼을 누르는 것을 권장합니다.

YAML 1.1과 YAML 1.2의 차이는 무엇인가요?

YAML 1.1은 yes/no/on/off/y/n을 boolean으로 해석하고 sexagesimal 숫자(60:00=3600)를 허용하지만, YAML 1.2부터는 true/false만 boolean으로 인식합니다. Kubernetes 클러스터에서 version: yes로 적은 값이 true로 변환되어 장애가 발생한 사례가 많아, strict 모드 사용을 권장합니다.

Multi-document YAML (---로 분리된 여러 문서)은 처리되나요?

네. ---로 구분된 multi-document YAML을 입력하면 JSON 배열로 변환됩니다. 반대로 JSON 최상위가 배열이면 YAML 변환 시 자동으로 multi-document 형식이 됩니다.

YAML anchor와 alias도 지원하나요?

네. &ref로 정의하고 *ref로 참조하는 anchor/alias가 정상 해석되며, JSON 변환 시 자동으로 확장됩니다.

변환된 결과를 파일로 다운로드할 수 있나요?

네. 출력 패널의 💾 버튼을 누르면 .json 또는 .yaml 확장자로 저장됩니다.
