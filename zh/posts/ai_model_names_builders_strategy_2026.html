序言: 看完过去半年的AI模型清单,你是不是叹了口气?

仅在2025年到2026年春之间,就先后出现了GPT-5(默认快照gpt-5-2025-08-07)、Llama 4(2025年4月5日发布)、Qwen3(2025年4月29日)、Mistral Large 3(v25.12)和DeepSeek-V4(2026年4月24日),Claude进入Opus 4.x一代,Gemini进入3.x一代。再加上mini、flash、lite、instruct各种变体,需要追踪的名字很快就达到几十个。每周一早上,X(推特)时间线被"本周新模型又超越了此前最强模型"和各种排行榜柱状图刷屏。对一个构建者(builder)而言,是否还能用正常节奏跟上这股洪流,已经是必须正视的问题了。

本文的出发点只有一句话:"背模型名不是本职。" 构建者的本职是做出有用的东西,模型只是工具。当查规格表的时间已经多过用工具的时间时,优先级就颠倒了。本文整理的是一套裁剪过的学习习惯:5个值得保留的策略、5个应当淘汰的反模式,以及一份能够持续执行的时间分配指南。

2026年9月29日更新时,本文依据各厂商官方文档重新核对了所有模型名称。发布时的正文里混有官方文档中查不到的名称(例如Llama 4 7B、70B),这本身就说明追踪名字有多容易出错。

1. 把AI模型名全部背下来,是个陷阱的3个原因

1-1. 每月都在变 - 不可持续

厂商基本每个季度都推出新名字。仅OpenAI就先后有GPT-4 Turbo、GPT-4o、GPT-4o mini、o1-preview、o1-mini、o1、o3-mini、o3,之后用GPT-5家族重新整合,而截至2026年9月,其官方模型文档的主力又换成了GPT-6 Astra、Sol、Luna。Anthropic沿着Claude Opus 4.5 → 4.6 → 4.7 → 4.8 → 5 → 5.5一路升级,途中还新增了Fable这一档;Google则像Gemini 3.1 Pro、3.5 Flash、3.8 Flash这样,每一档的版本号各自变动。把所有模型名都背下来,就像在沙滩上画画,下一个浪头会把它们都抹掉。

1-2. 名字不是能力的可靠信号

仅凭"Llama 4"这个名字就断定它在所有任务上都强于上一代,是很危险的。名字甚至不会告诉你架构。以Llama 4名义发布的Scout和Maverick激活参数同为170亿,但专家数分别是16个和128个,总参数分别是1090亿和4000亿(Meta发布,2025年4月5日)。同一代名字下,规模与结构就能差这么多;在中文等非英文任务里,英文基准的排名也不保证能直接套用。名字、版本号和参数量,并不保证与你自己任务上的排名一致。最终结论必须靠你自己的输入去测。

1-3. 时间ROI太低

诚实地算一笔账。每天花30分钟刷新模型的消息和发布说明,一个月就是15小时。同样的时间投入到真实项目里,够你完成一条RAG流水线,再写两个评估脚本。构建者的时间投在本业上才会复利累积,投在"背名字"上不会。

还有一个少被讨论的二阶效应:你花在模型新闻上的每一小时,本质上是在替别人的叙事打工——他们的炒作周期、他们的基准、他们的关键词。摄入过多此类内容的构建者,最后会用与自己用户毫无关系的外部指标来评价自己的项目。控制信息入口不仅是在保护日历,更是在保护判断力。

2. 构建者真正应该学的 - 不是名字,而是5个能力轴

本文推荐的最实用的抽象是5个能力轴。别再追名字了,换成追这5个轴。

能力轴 代表基准 实战含义
推理(Reasoning) MMLU, GPQA, ARC-AGI 复杂思考与多步问题求解
代码(Code) SWE-bench, HumanEval, LiveCodeBench 真实代码编写、调试、重构质量
多模态 MMMU, ChartQA, VideoMME 图像、音频、视频输入理解
上下文长度 RULER, Needle-in-Haystack 长文档、整库代码作为输入
延迟与成本 tokens/s, $ / 1M tokens 实时响应、大批量任务的成本

新模型发布时,第一个问题不该是"叫什么",而是"在5个轴里哪个轴强?"——这一句话就能把一小时的比对压缩到一分钟以内。

3. 策略1: 记基准类别,而不是具体分数

具体分数很快就会过期,基准类别却能稳定好几年。记类别,别记数字。

  • MMLU: 通识与多学科覆盖,"这模型聪不聪明"的基础标尺。
  • GPQA Diamond: 博士级推理,用于区分前沿模型。
  • SWE-bench Verified: 解决真实GitHub Issue,代码助手的真本事。截至2026年9月29日,swebench.com上除Verified外还列有Lite、Full、Multimodal、Multilingual、Bash Only等榜单。
  • ARC-AGI: 抽象推理,对全新模式的泛化能力。现已分为ARC-AGI-1、2、3三版,ARC Prize 2026同时举办ARC-AGI-3和ARC-AGI-2竞赛——类别名不变、版本在变的好例子。
  • HumanEval / MBPP: 单函数生成,入门代码能力。
  • MMMU: 多模态综合理解。
  • MT-Bench / Arena排名: 人类评分,最接近用户真实满意度。LMSYS Chatbot Arena经过LMArena阶段,截至2026年9月使用Arena(arena.ai)这一名称和地址。

把这7个类别放进脑子,任何新模型都能秒级定位:"哦,这是个SWE-bench偏强的代码模型"或"这是多模态侧重的新版本"。

4. 策略2: 把模型抽象成"Tier"(Frontier / Production / Local / Edge)

本文最常推荐的抽象是4-Tier。每个新模型必入其中一档。

Tier 特征 代表示例(2026-09-29 官方文档核对) 典型用途
Frontier 最高性能、高成本、高延迟 Claude Fable 5.1、Claude Opus 5.5, GPT-6 Astra, Gemini 3.1 Pro(预览) 复杂推理、研究、核心决策
Production 均衡、中等成本、合理速度 Claude Sonnet 5.5、Claude Haiku 4.5, GPT-6 Luna, Gemini 3.8 Flash 大量API、聊天机器人、RAG
Local 开放权重、自托管、中等品质 Llama 4 Scout、Maverick, Qwen3-32B, DeepSeek-V4-Flash, Mistral Large 3 隐私、内网、批量任务
Edge 小型、高速、设备端 Gemini Nano(Android AICore), Ministral 3 3B, Qwen3-0.6B~4B 移动端、嵌入式、实时语音

表中示例依据各厂商在官方文档中对该模型的描述(能力最强、速度与智能的平衡、最高效、开放权重等)归类,并不代表厂商之间的优劣。发布时表中的Claude 4.7 Sonnet、Gemini 3.5 Ultra与3.5 Pro、Llama 4 70B与3B,在2026年9月29日的官方文档中无法确认,因此已删除。

名字可以有50个,Tier永远只有4个。可以忘记名字,但绝不能忘Tier。听到"Llama 4发布了"本身做不了任何决定,但在备忘录里写一行"Local Tier多了一个候选",就足以让你下次评估RAG后端时拿来比较。

5. 策略3: 只对自己1~2个用例做亲手基准测试

不要试图比较所有模型。只对你真正在做的东西做基准——这才是ROI最高的事。比如用例是"中文法律文书摘要,一次100份",就拿这100份输入跑5个候选模型,完事。

最小化的自建基准结构

1) 准备30~50份真实输入(JSON) → 2) 用同一段提示词顺序调用5个候选模型 → 3) 盲评做A vs B两两比较 → 4) 累积Elo分数 → 5) 一页纸总结。一个周六下午就够。

这份结果比社交媒体上任何人晒的分数都更有助于你的决定。公开基准无法反映你的语言偏好、领域术语、提示风格。

建议把基准本身做得极小并加版本控制。30条案例胜过300条,因为30条你才真的愿意每季度跑一次而不感到负担。把JSON与评估脚本一起放在你的仓库里,每次跑都打上"模型ID + 日期"标签——你就得到了一个对产品本身远比全球排行榜更有意义的私有Leaderboard。

6. 策略4: 追"价格趋势",而不是绝对价格

把单家厂商的token单价背下来没有意义,它们变得很频繁。要追的是趋势。不用记数字,只要记住下面这些问题答案的方向即可。

  • "过去半年里,Frontier Tier的输入token单价是降了、涨了,还是持平?"
  • "自托管Local Tier模型的单位成本(含GPU折旧),比你现在用的云API便宜还是更贵?"
  • "一张图片输入按多少文本token计费?——只需在厂商价格页确认计算方式。"

发布时此处的数字(Frontier单价下跌约35%、自托管约为云API的1/8、每张图片约合1~5K token)未能找到出处,已在2026年9月29日更新中删除。"方向单位"的记忆有效期很长。具体价格忘掉,记住斜率就好,下一次价格变动都不会让你的成本直觉失准。

7. 策略5: 只关注1~2个可信信息源,其余坚决砍掉

构建者常踩的坑是"X、Discord、Subreddit、邮件订阅、博客全都想看"。收窄到信噪比最高的一两个来源效果更好:

  • Simon Willison 博客 (simonwillison.net) - 深度分析、实测、持续整理。
  • Arena排行榜 (arena.ai/leaderboard,原LMSYS Chatbot Arena) - 基于用户评价的排名,按Text、WebDev、Vision等领域分榜,只看与自己工作最接近的榜即可。
  • news.hada.io - 韩文极客新闻,评论区有大量实战意见。
  • Anthropic / OpenAI / Google 官方博客与模型文档 - 只用RSS收新模型发布,不看推文。

建议有意切断其他KOL、匿名论坛和绝大多数Discord。腾出来的时间会回到项目本身。

这条规则真正难的不是信息层面,而是心理层面——砍订阅会让你产生"在落后"的错觉。可实际效果恰恰相反:你会发现同一个信号迟一两天就通过你保留的可信源传到你手里,而且经过了更好的过滤和上下文补充。"接十个源所以更早知道"的优势,绝大多数时候只是错觉,因为等信号变得真正可执行时,它早已落到精选源里。

8. 构建者的时间分配建议

这是本文建议的分配。它是建议而非测量值。100% = 你在AI相关学习、实验、信息消费上花的全部时间。

项目 推荐比例 具体动作
深耕自己的用例 60% 在真实项目里测模型、写评估脚本、调提示词
浏览新模型发布说明 20% 官方博客/模型文档,每周一次5分钟,做Tier归类
跟踪基准类别 10% 每周一次Arena排行,关注MMLU、SWE-bench趋势
社区讨论 10% 每周整理Simon Willison和news.hada.io

第一项之所以高达60%,是因为构建者的本业是"用工具做东西",不是"记住工具"。一旦低于60%,就是危险信号。

9. 构建者应该砍掉的5个反模式

反模式1: 因FOMO试遍每个新品

每发布一个新模型就申请API Key,试用一小时再换下一个。永远停留在表面。建议规则:每季度只挑1~2个认真评估,其余只归类。

反模式2: 无止境刷推特

X时间线刷30分钟以上不是学习,是多巴胺消费。一个可行的办法是:官方博客只用RSS接收,X只在搜索模式下查关键字,看完即关。

反模式3: 背基准分数

"模型A的SWE-bench Verified是67.2%,模型B是70.1%"(假设的例子)——背这些没用,下个季度都会变。记住"B在SWE-bench上略领先"这样的相对顺序就够。

反模式4: 学齐每个模型的提示技巧

"GPT用这种system prompt,Claude用XML标签,Gemini又是另一套..."把所有家的所有技巧都学一遍是浪费。只深入掌握主力1~2个模型的推荐用法,其他模型用到再翻官方文档。

反模式5: 每周换工具

"这周Cursor、下周Cline、再下周Continue"——快捷键和工作流的重学成本会超过模型微小提升带来的收益。每季度做一次工具评审已经足够。

10. 中文环境下值得信赖的信息源

只看英文源会错过中文性能、本地案例和监管语境。一个可参考的组合是:

  • news.hada.io - 虽然以韩文为主,但对国际AI事件的汇总质量高。
  • 知乎与微信公众号头部技术作者 - 一手英文资料的中文转译与评论,务必同时核对原文链接。
  • OpenCompass / CLUE / SuperCLUE - 中文LLM评测榜单。
  • 阿里 / DeepSeek / 智谱 / Moonshot 官方博客 - 国内厂商发布说明。
  • 英文源2个 + 中文源2个的组合,在时间投入上最平衡。

11. 这种"模型疲劳"最终会消失吗?

发布时(2026年5月)本文的展望如下。这是当时的展望,并非经过验证的预测。

  • 2026~2027年(当时展望): 模型发布频率达到顶峰,一年60~80款新模型,疲劳值最高。
  • 2028年(当时展望): 进入整合期。Frontier Tier收敛到3~4家厂商,Local Tier收敛到Llama / Qwen / DeepSeek这几家。
  • 2029年以后(当时展望): 名字追踪的负担大幅下降,只靠能力轴思考就够用。

只补充2026年9月29日核实的事实:发布后的四个月里,官方文档中的主力名称又变了。Anthropic模型文档的现行列表是Claude Fable 5.1、Opus 5.5、Sonnet 5.5、Haiku 4.5;OpenAI模型文档的主力是GPT-6 Astra、Sol、Luna;DeepSeek公布了V4-Pro正式发布(2026年8月13日)和V4.1-Flash(2026年9月10日)。仅凭这些事实无法判断发布频率是否已过顶峰。尽管如此,本文的建议仍是未来2~3年主动维持"少追多抽象"的策略。

12. 结语: 构建者的本质是"解决问题",不是熟悉所有规格表

整篇文章可以浓缩成一句:"模型是工具,构建者的本职是解决问题。" 花在背名字上的时间,就是从本职里抠走的时间。5个能力轴、4个Tier、7个基准类别、1~2个可信源——只要你脑子里有这4层抽象,任何新模型在一分钟内都能定位完毕,然后立刻回到本业。

对2026年的构建者来说,最重要的能力不是"知道所有新模型",而是"对自己正在做的事知道得很深"。模型是替你解决问题的协作者,不是你必须追着跑的主人。

建议配合阅读AI时代开发者的复利成长策略、本地LLM硬件选择指南与AI编程工具2026对比,模型选择与学习策略的全貌会更清晰。

## 1. 看到新模型名时先确认的事

- [ ] 这个名字确实出现在厂商官方模型文档或官方发布中(社交媒体和摘要文章里的名字经常出错)
- [ ] 已确认官方日期(快照ID、更新日志日期或发布日期)
- [ ] 已确认同一代名称下是否有多种规模或配置(例如Llama 4 Scout与Maverick激活参数同为170亿,但专家数为16对128)
- [ ] 已确认是开放权重还是仅限API
- [ ] 已阅读厂商对该模型的描述(能力最强、均衡型、最高效等)

## 3. Tier归类(2026-09-29 官方文档示例)

| Tier | 特征 | 示例 | 典型用途 |
|---|---|---|---|
| Frontier | 最高性能、高成本、高延迟 | Claude Fable 5.1、Opus 5.5, GPT-6 Astra, Gemini 3.1 Pro(预览) | 复杂推理、研究、核心决策 |
| Production | 均衡型 | Claude Sonnet 5.5、Haiku 4.5, GPT-6 Luna, Gemini 3.8 Flash | 大量API、聊天机器人、RAG |
| Local | 开放权重、自托管 | Llama 4 Scout、Maverick, Qwen3-32B, DeepSeek-V4-Flash, Mistral Large 3 | 隐私、内网、批量任务 |
| Edge | 小型、设备端 | Gemini Nano, Ministral 3 3B, Qwen3-0.6B~4B | 移动端、嵌入式、实时语音 |

示例依据各厂商自己的描述归类,不代表厂商之间的优劣。

## 5. 自建基准检查

- [ ] 已把30~50份真实输入保存为JSON
- [ ] 已用同一段提示词依次调用各候选模型
- [ ] 已由人工对输出做A对B盲评
- [ ] 已把结果连同模型ID和日期存进仓库
- [ ] 规模小到每季度都愿意重跑

---

## 6. 价格只记方向,不记数字

- [ ] 过去半年Frontier输入单价: 下降 / 上涨 / 持平
- [ ] 自托管单位成本(含GPU折旧)相比正在用的云API: 更便宜 / 更贵
- [ ] 已在厂商价格页确认图片输入的计费方式
