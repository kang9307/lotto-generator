前言：安全不是选择而是必须

服务器安全需要纵深防御（Defense in Depth）策略，而不是单一解决方案。在这最后一篇中，我们讲解Linux服务器安全加固的核心内容。

本文的命令与配置已对照 OpenSSH、Linux-PAM、UFW、DNF Automatic、Greenbone 的官方文档重新确认（2026-09-29）。因发行版而异的部分（软件包名、服务名、日志位置）已在正文中标注。在远程服务器上修改 SSH、防火墙或 PAM 时，所有步骤的前提都是不关闭当前会话，并在新终端中测试。这些命令只应在自己拥有或有管理权限的服务器上使用。

1. 系统加固基础

1.1 禁用不必要的服务

# 检查运行中的服务
systemctl list-units --type=service --state=running

# 禁用不必要的服务（未安装时报错属正常）
sudo systemctl disable --now cups
sudo systemctl disable --now avahi-daemon
sudo systemctl disable --now bluetooth

# 查看开机自启动的服务
systemctl list-unit-files --type=service --state=enabled

在生产服务器上，关闭服务之前先用 systemctl list-dependencies --reverse 服务名 等命令确认有无其他组件依赖它。

1.2 安全更新

# Ubuntu/Debian
sudo apt update && sudo apt upgrade -y
sudo apt install unattended-upgrades
sudo dpkg-reconfigure unattended-upgrades

# RHEL 系（RHEL、Rocky Linux、AlmaLinux）
sudo dnf update -y
sudo dnf install dnf-automatic
# dnf-automatic.timer 遵循 automatic.conf，apply_updates 默认为 False，因此不会安装更新
sudo systemctl enable --now dnf-automatic-install.timer

在 RHEL 系中，dnf-automatic.timer 完全遵循 automatic.conf 的设置，而 apply_updates 的默认值是 False。因此只启用这个定时器，只会下载或通知更新，并不会安装。若要自动安装，应使用 dnf-automatic-install.timer（DNF Automatic 文档）。本文旧版让读者启用前者，实际上不会安装任何更新。

1.3 GRUB安全

# 以 Debian/Ubuntu 为例。编辑前先备份，并确保有控制台访问手段
sudo cp -a /etc/grub.d/40_custom /root/40_custom.bak

# 生成 GRUB 密码哈希
sudo grub-mkpasswd-pbkdf2
# 复制哈希值

# 编辑 /etc/grub.d/40_custom
set superusers="admin"
password_pbkdf2 admin grub.pbkdf2.sha512...

# 应用配置（Debian/Ubuntu）
sudo update-grub

GRUB 密码用于防止编辑启动菜单，设置不当可能导致无法使用启动菜单。请先备份 40_custom，并确保有控制台访问手段（虚拟机控制台、IPMI 等）。RHEL 系的命令不同，本文不涉及。

2. 用户安全

2.1 密码策略

# /etc/login.defs
PASS_MAX_DAYS   90    # 最长使用期限
PASS_MIN_DAYS   7     # 最短使用期限
PASS_WARN_AGE   14    # 到期提醒

# PAM 密码复杂度（Debian/Ubuntu：/etc/pam.d/common-password）
password requisite pam_pwquality.so retry=3 minlen=12 dcredit=-1 ucredit=-1 ocredit=-1 lcredit=-1

# 应用到已有用户
sudo chage -M 90 -m 7 -W 14 username

RHEL 系没有 /etc/pam.d/common-password。相同的选项（如 minlen）放在 pwquality 配置中，具体位置请以发行版文档为准。修改 PAM 文件时，不要关闭已打开的 root 会话，并在另一个终端用 passwd 测试。

2.2 sudo配置

# /etc/sudoers（务必用 sudo visudo 编辑 - 语法错误会导致 sudo 本身无法使用）
# 日志记录
Defaults logfile=/var/log/sudo.log
Defaults log_input, log_output

# 超时设置
Defaults timestamp_timeout=5

# 仅允许特定命令
username ALL=(ALL) NOPASSWD: /usr/bin/systemctl restart nginx

NOPASSWD 示例仅适用于限定为单个命令的情况。范围一旦扩大，该账户被攻破时就等于直接获得 root 权限。

2.3 账户锁定

# RHEL 系：通过 authselect 启用 faillock 功能（取代 pam_tally2）
sudo authselect current
sudo authselect enable-feature with-faillock

# /etc/security/faillock.conf
deny = 5
unlock_time = 900

# 查看失败次数 / 解除锁定
sudo faillock --user username
sudo faillock --user username --reset

pam_tally2 已在 Linux-PAM 1.5.0 中被移除（1.5.0 发布说明："Removed deprecated pam_tally and pam_tally2 modules, use pam_faillock instead"）。本文旧版使用的 pam_tally2.so deny=5 unlock_time=900 在之后的发行版上已无法工作，其后继者是 pam_faillock。配置文件为 /etc/security/faillock.conf，默认值为 deny 3 次、fail_interval 900 秒、unlock_time 600 秒（faillock.conf(5)）。为防止拒绝服务，root 默认不会被锁定（pam_faillock(8)），但可通过 even_deny_root 改变。远程 root 被锁后，没有控制台很难恢复，启用前请先确认能访问控制台。

在 Debian/Ubuntu 上需要自己在 common-auth 和 common-account 中加入 pam_faillock 行，顺序遵循 man pam_faillock 示例（auth 中的 preauth、pam_unix、authfail，然后是 account）。编辑前先备份，并在保留 root 会话的同时用另一个账户登录测试。

3. SSH安全加固

# 0) 编辑前先备份。当前的 SSH 会话直到验证完成前不要关闭
sudo cp -a /etc/ssh/sshd_config /etc/ssh/sshd_config.bak

# /etc/ssh/sshd_config

# 修改默认端口（可选）。须先准备好防火墙（第4节），RHEL 系还要先加 SELinux 端口标签（6.1 节）
Port 2222

# 禁止 root 登录
PermitRootLogin no

# 禁用密码认证 - 须先在新会话中确认密钥登录成功
PasswordAuthentication no

# 允许密钥认证
PubkeyAuthentication yes

# 禁止空密码
PermitEmptyPasswords no

# 限制登录尝试
MaxAuthTries 3
LoginGraceTime 30

# 仅允许特定用户（同时使用 AllowGroups 时的组合规则请先查 sshd_config(5) 并测试）
AllowUsers admin deploy
#AllowGroups sshusers

# （不再需要 Protocol 2：OpenSSH 7.4 已移除 SSH v1 服务端支持）

# 1) 语法检查 - 无输出即为正常
sudo sshd -t
# 2) 查看实际生效的配置
sudo sshd -T | grep -Ei '^(port|permitrootlogin|passwordauthentication|maxauthtries) '

# 3) 应用（服务名：Debian/Ubuntu 为 ssh，RHEL 系为 sshd）
sudo systemctl restart ssh
sudo ss -tlnp | grep sshd

# 4) 保留旧会话，在新终端中测试登录
ssh -p 2222 admin@server

# 5) 若失败，在保留的旧会话中回滚
sudo cp -a /etc/ssh/sshd_config.bak /etc/ssh/sshd_config
sudo systemctl restart ssh

OpenSSH 的默认值为 PermitRootLogin prohibit-password、MaxAuthTries 6、LoginGraceTime 120 秒（sshd_config(5)）。自 OpenSSH 7.4 移除 SSH v1 服务端支持后，Protocol 2 一行已无意义，因此删除（7.4 发布说明）。sshd -t 检查配置文件与密钥的有效性，sshd -T 输出实际生效的配置（sshd(8)）。Ubuntu 文档要求在重启前用 sudo sshd -t 检查配置，并警告一旦出错可能被锁在服务器之外（Ubuntu Server 文档）。因此请遵循上面的顺序（备份、语法检查、重启、新终端测试、失败回滚），测试结束前不要关闭已有会话。

在 Ubuntu 使用套接字激活（ssh.socket）的环境中，修改 Port 是否仅重启即可生效，尚未确认。重启后请用 ss -tlnp | grep sshd 检查实际监听的端口。修改端口只能减少自动扫描造成的日志噪音，真正的防线是密钥认证和访问限制。同时使用 AllowUsers 与 AllowGroups 前，请先阅读 sshd_config(5) 并测试。

4. 防火墙配置

4.1 UFW (Ubuntu)

# 默认策略
sudo ufw default deny incoming
sudo ufw default allow outgoing

# ★ 先放行 SSH，再执行 ufw enable。端口必须与 sshd 实际监听的端口一致
sudo ss -tlnp | grep sshd
sudo ufw allow 2222/tcp comment 'SSH'
sudo ufw allow 80/tcp comment 'HTTP'
sudo ufw allow 443/tcp comment 'HTTPS'

# 基于 IP 的限制（SSH 端口与上面相同，为 2222）
sudo ufw allow from 192.168.1.0/24 to any port 2222 proto tcp

# 启用。若被锁在外面，在控制台执行 sudo ufw disable
sudo ufw enable
sudo ufw status verbose

手册指出，ufw enable 会清空链，可能断开 SSH 等现有连接（ufw(8)）。因此要在 enable 之前先加入 SSH 放行规则，并使其端口与 sshd 实际监听的端口一致。本文旧版把 SSH 改为 2222，却把 IP 限制规则写成 22 端口，前后矛盾。ufw limit 规则会拒绝在 30 秒内尝试 6 次以上连接的 IP。

4.2 firewalld (RHEL/CentOS)

# 查看默认区域
sudo firewall-cmd --get-default-zone

# 放行服务
sudo firewall-cmd --permanent --add-service=http
sudo firewall-cmd --permanent --add-service=https

# 放行端口 - 在 sshd 使用新端口重启之前先开放
sudo firewall-cmd --permanent --add-port=2222/tcp

# 应用规则并确认
sudo firewall-cmd --reload
sudo firewall-cmd --list-all

修改 sshd 的 Port 时，应先完成防火墙的 --permanent 规则与 --reload，以及 SELinux 端口标签（6.1 节），再重启 sshd。顺序颠倒会导致无法通过新端口连接，或 sshd 无法启动。

5. 入侵检测系统

5.1 Fail2Ban

# 安装（RHEL 系使用 dnf，提供该软件包的仓库因发行版而异）
sudo apt install fail2ban

# /etc/fail2ban/jail.local
[DEFAULT]
bantime = 3600
findtime = 600
maxretry = 3
# 添加管理员 IP，避免把自己封禁
ignoreip = 127.0.0.1/8 ::1

[sshd]
enabled = true
port = 2222
# 仅使用 journald 的系统（没有 /var/log/auth.log）改为读取日志
backend = systemd
# 使用文件日志时：logpath = /var/log/auth.log

[nginx-http-auth]
enabled = true

# 启动并查看状态
sudo systemctl enable --now fail2ban
sudo fail2ban-client status
sudo fail2ban-client status sshd
# 解除误封的 IP
sudo fail2ban-client unban 203.0.113.10

像 Debian 12 这样只使用日志（journald）的系统没有 /var/log/auth.log，只写 logpath 会让 sshd jail 无日志可读。这类系统应使用 backend = systemd。这一部分以及 ignoreip、unban 选项，未能直接对照 fail2ban 官方文档，而是通过二手资料确认的。应用后请用 fail2ban-client status sshd 确认 jail 确实在工作。

5.2 AIDE（完整性检查）

# 安装（Debian/Ubuntu）
sudo apt install aide

# 初始化数据库
sudo aideinit

# 执行检查
sudo aide --check

# 更新数据库
sudo aide --update

6. SELinux / AppArmor

6.1 SELinux (RHEL/CentOS)

# 查看状态
getenforce
sestatus

# 切换模式（重启前有效）。Permissive 仅用于排查原因
sudo setenforce 0  # Permissive
sudo setenforce 1  # Enforcing

# 永久设置（/etc/selinux/config）
SELINUX=enforcing

# 若修改了 SSH 端口，须在重启 sshd 之前添加标签（否则 bind 会报 Permission denied）
sudo semanage port -a -t ssh_port_t -p tcp 2222
sudo semanage port -l | grep ssh_port_t

# 故障排查
sudo ausearch -m avc -ts recent
sudo sealert -a /var/log/audit/audit.log

在 RHEL 系上修改 SSH 端口后，SELinux 只允许 sshd 绑定带有 ssh_port_t 标签的端口。不加标签就重启，sshd 会因 Permission denied 无法启动。semanage 包含在 policycoreutils-python-utils 软件包中。该步骤是通过二手资料而非官方文档确认的。sealert 可能需要另外安装软件包。setenforce 0 只是用于隔离原因的诊断手段，确认完毕后应立即用 setenforce 1 切回。

6.2 AppArmor (Ubuntu)

# 查看状态
sudo aa-status

# 管理配置文件
sudo aa-enforce /etc/apparmor.d/usr.sbin.nginx
sudo aa-complain /etc/apparmor.d/usr.sbin.nginx

# 查看日志
sudo journalctl -fx | grep apparmor

8. 日志监控

# 监控可疑活动
# 登录失败（Debian/Ubuntu）
sudo grep "Failed password" /var/log/auth.log | tail -20
# 登录失败（RHEL 系）
sudo grep "Failed password" /var/log/secure | tail -20
# 仅使用 journald 的系统（RHEL 系使用 -u sshd）
sudo journalctl -u ssh --since today | grep "Failed password" | tail -20

# sudo 使用记录
sudo grep "sudo" /var/log/auth.log

# 系统启动/关机
last reboot
last shutdown

# 当前登录用户
who
w

# 网络连接
ss -tuln

日志位置因发行版而异：Debian/Ubuntu 为 /var/log/auth.log，RHEL 系为 /var/log/secure，仅使用日志（journal）的系统则用 journalctl 查看。旧版中的 netstat 一行与 ss 作用相同，因此删除。

9. 安全检查清单

#!/bin/bash
# security_audit.sh (只读检查)

echo "=== Linux 安全审计 ==="

echo -e "\n[1] 检查系统更新"
apt list --upgradable 2>/dev/null | head -10

echo -e "\n[2] root 是否可登录（生效配置）"
sudo sshd -T 2>/dev/null | grep -i "^permitrootlogin"

echo -e "\n[3] 是否允许密码认证（生效配置）"
sudo sshd -T 2>/dev/null | grep -i "^passwordauthentication"

echo -e "\n[4] 开放端口"
ss -tuln | grep LISTEN

echo -e "\n[5] SUID 文件（仅同一文件系统）"
find / -xdev -perm -4000 -type f 2>/dev/null | head -10

echo -e "\n[6] 空密码账户（需要 root 权限）"
sudo awk -F: '($2 == "") {print $1}' /etc/shadow

echo -e "\n[7] 最近的登录失败"
sudo grep "Failed password" /var/log/auth.log /var/log/secure 2>/dev/null | tail -5

echo -e "\n[8] 防火墙状态"
sudo ufw status 2>/dev/null || sudo firewall-cmd --state 2>/dev/null

echo -e "\n审计完成"

# 远程服务器安全变更检查清单 - SSH、防火墙、PAM

基准日：2026-09-29
出处：OpenSSH 7.4 发布说明、sshd(8)、sshd_config(5)、ufw(8)、Linux-PAM 1.5.0 发布说明、faillock.conf(5)、DNF Automatic 文档、Greenbone Community Containers 文档

---

## 1. 变更之前（SSH、防火墙、PAM 通用）

- [ ] 当前已连接的会话，在测试结束前不要关闭
- [ ] 已确认有控制台访问手段（虚拟机控制台、IPMI）
- [ ] 已备份要编辑的文件（`cp -a 文件 文件.bak`）

## 2. SSH 配置变更的顺序

| 顺序 | 操作 | 命令 |
|---|---|---|
| 1 | 备份 | `sudo cp -a /etc/ssh/sshd_config /etc/ssh/sshd_config.bak` |
| 2 | 语法检查（无输出即正常） | `sudo sshd -t` |
| 3 | 查看生效配置 | `sudo sshd -T` |
| 4 | 重启（Debian/Ubuntu 为 ssh，RHEL 系为 sshd） | `sudo systemctl restart ssh` |
| 5 | 检查实际监听的端口 | `sudo ss -tlnp` |
| 6 | 在新终端中测试登录 | `ssh -p 端口 用户@服务器` |
| 7 | 失败则在旧会话中回滚 | 恢复 `.bak` 后重启 |

- [ ] 关闭密码认证之前，已在新会话中确认密钥登录成功
- [ ] 不要加入 `Protocol 2` 这一行（OpenSSH 7.4 已移除 SSH v1 服务端支持）

## 3. 如果修改 SSH 端口（顺序很重要）

- [ ] 先在防火墙中开放新端口（UFW：`ufw allow`；firewalld：先 `--permanent` 再 `--reload`）
- [ ] RHEL 系需添加 SELinux 端口标签（`semanage port -a -t ssh_port_t -p tcp 端口`）
- [ ] 然后才重启 sshd
- [ ] 使用 UFW 时，先加入 SSH 放行规则再执行 `ufw enable`（enable 可能断开现有连接）

## 4. 登录失败锁定

| 项目 | 值 |
|---|---|
| `pam_tally2` | 已在 Linux-PAM 1.5.0 中移除 - 不要使用 |
| 替代 | `pam_faillock`（配置 `/etc/security/faillock.conf`） |
| 默认值 | deny 3 次 / fail_interval 900 秒 / unlock_time 600 秒 |
| root | 默认不会被锁定（用 `even_deny_root` 改变） |

- [ ] 锁定远程 root 之前，已确认可访问控制台
- [ ] 修改 PAM 文件后，已用另一个账户登录测试

## 5. 自动更新（RHEL 系）

- [ ] 若要自动安装，请启用 `dnf-automatic-install.timer`
- [ ] 只启用 `dnf-automatic.timer` 时，因 `apply_updates` 默认为 False，不会安装更新

## 6. 各发行版的差异

| 项目 | Debian/Ubuntu | RHEL 系 |
|---|---|---|
| SSH 服务名 | `ssh` | `sshd` |
| 认证日志 | `/var/log/auth.log` | `/var/log/secure` |
| 仅使用 journal 的系统 | `journalctl -u ssh` | `journalctl -u sshd` |
| fail2ban 使用 journal | `backend = systemd` | 相同 |
