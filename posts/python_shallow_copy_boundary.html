출처는 Python 공식 문서(copy, 내장 시퀀스 연산, 데이터 모델)와 각 설명 바로 앞의 출력이고, 범위는 Windows 10 Git Bash 의 Python 3.13.3(CPython)이며 객체 동일성은 id() 값(실행마다 달라짐)이 아니라 is 연산자의 참·거짓으로, 시간 값은 이 PC 값(재실행하면 달라짐)으로 나타낸다.

서론 - 복사는 한 겹씩 일어난다

설정 딕셔너리를 복사해 사용자별로 값을 바꿨는데 기본 설정까지 바뀌어 있는 경우가 있다. 복사 코드는 문제없이 실행되었고 새 딕셔너리도 분명히 만들어졌다. 그런데 안쪽 리스트는 원본과 같은 객체였다. 복사가 일어나는 층의 수가 방법마다 다르기 때문이다. 어느 방법이 몇 겹까지 새로 만들고 어디서 멈추는지는 객체 동일성(is)으로 드러나고, 멈추는 지점을 넘는 방법과 그 비용은 아래 출력이 보여 준다.

이웃 주제의 글과는 축이 다르다. 기본 인자 글은 기본값 객체가 def 문이 실행될 때 한 번만 만들어져 호출 사이에 공유되는 문제를, 작은 정수 글은 is로 정수·문자열을 비교할 때 최적화 때문에 결과가 달라지는 문제를 다룬다. 여기서는 이미 존재하는 컨테이너를 복사할 때 어느 층까지 새 객체가 되는지에 한정한다. 앞의 두 글과 이어지는 지점은 본문에서 링크로 넘긴다.

다루는 질문은 다음과 같다.

  • 대입(=)은 객체를 몇 개 만드는가.
  • copy()·list()·슬라이스·dict.copy()·copy.copy·copy.deepcopy는 각각 바깥과 안쪽 중 어디까지 새 객체인가.
  • 중첩 리스트와 딕셔너리에서 원본이 바뀌는 조건은 무엇인가.
  • 튜플 안의 리스트, 데이터클래스, 사용자 정의 클래스는 복사에서 어떻게 다루어지는가.
  • deepcopy는 같은 객체를 두 번 참조한 구조와 순환 참조를 어떻게 처리하는가.
  • deepcopy의 시간 비용은 이 PC에서 얼마인가.

대입은 복사가 아니다

가장 먼저 부딪히는 경우는 복사라고 생각한 것이 대입인 경우이다. 공식 문서 copy 모듈의 첫 문장은 이렇다. "Assignment statements in Python do not copy objects, they create bindings between a target and an object." 대입문은 객체를 복사하지 않고 대상과 객체 사이의 바인딩을 만든다. 아래 출력은 이 문장과 일치한다.

a = [1, 2]
                    b = a
                    print(a is b, id(a) == id(b))
                    b.append(3)
                    print(a)
                    c = list(a)
                    print(c is a, c == a)
                    c.append(4)
                    print(a, c)
True True
                    [1, 2, 3]
                    False True
                    [1, 2, 3] [1, 2, 3, 4]

첫 줄에서 a is b와 id(a) == id(b)가 모두 True이다. 데이터 모델 문서는 is가 두 객체의 동일성(identity)을 비교하고 id()가 그 동일성을 나타내는 정수를 돌려준다고 적으며, CPython에서 id(x)는 x가 저장된 메모리 주소라고 덧붙인다. 즉 a와 b는 한 객체에 붙은 이름 두 개이다. b.append(3) 뒤에 a도 [1, 2, 3]이 되었다. 반면 list(a)로 만든 c는 c is a가 False인 새 리스트이고, c == a가 True인 것은 내용이 같다는 뜻일 뿐 같은 객체라는 뜻이 아니다. c.append(4)는 a에 영향을 주지 않았다.

  • ==는 값이 같은지, is는 같은 객체인지를 묻는다. 복사 여부는 is로 본다.
  • 여기서 쓰는 is는 컨테이너 객체의 동일성을 보는 데 쓴다. 정수·문자열 같은 값을 is로 비교하면 최적화 때문에 결과가 달라지는 문제는 작은 정수 글이 다룬다.
  • 호출자가 넘긴 리스트를 복사해 두는 패턴의 실행 출력은 기본 인자 글의 5절에 있다.

복사 방법별로 새로 만들어지는 층

다음 코드는 중첩 리스트 하나와 딕셔너리 하나에 대해 여러 복사 표현을 실행하고, 결과의 바깥 컨테이너가 원본과 다른 객체인지(new outer), 안쪽 리스트가 원본과 다른 객체인지(new inner)를 is not으로 출력한다.

import copy
                    orig = [[1, 2], [3, 4]]
                    cases = [
                        ('b = orig', lambda: orig),
                        ('orig.copy()', lambda: orig.copy()),
                        ('list(orig)', lambda: list(orig)),
                        ('orig[:]', lambda: orig[:]),
                        ('[*orig]', lambda: [*orig]),
                        ('copy.copy(orig)', lambda: copy.copy(orig)),
                        ('copy.deepcopy(orig)', lambda: copy.deepcopy(orig)),
                    ]
                    print('%-22s %-10s %s' % ('expression', 'new outer', 'new inner'))
                    for name, make in cases:
                        b = make()
                        print('%-22s %-10s %s' % (name, b is not orig, b[0] is not orig[0]))
                    d = {'name': 'x', 'tags': ['a']}
                    cases = [
                        ('d.copy()', lambda: d.copy()),
                        ('dict(d)', lambda: dict(d)),
                        ('{**d}', lambda: {**d}),
                        ('copy.copy(d)', lambda: copy.copy(d)),
                        ('copy.deepcopy(d)', lambda: copy.deepcopy(d)),
                    ]
                    print()
                    for name, make in cases:
                        b = make()
                        print('%-22s %-10s %s' % (name, b is not d, b['tags'] is not d['tags']))
expression             new outer  new inner
                    b = orig               False      False
                    orig.copy()            True       False
                    list(orig)             True       False
                    orig[:]                True       False
                    [*orig]                True       False
                    copy.copy(orig)        True       False
                    copy.deepcopy(orig)    True       True
                    
                    d.copy()               True       False
                    dict(d)                True       False
                    {**d}                  True       False
                    copy.copy(d)           True       False
                    copy.deepcopy(d)       True       True

copy 모듈 문서는 두 복사를 이렇게 정의한다. "A shallow copy constructs a new compound object and then (to the extent possible) inserts references into it to the objects found in the original." 얕은 복사는 새 복합 객체를 만들고 원본 안의 객체에 대한 참조를 거기에 넣는다. "A deep copy constructs a new compound object and then, recursively, inserts copies into it of the objects found in the original." 깊은 복사는 새 복합 객체를 만들고 원본 안의 객체의 사본을 재귀적으로 넣는다. 출력은 이 정의와 일치한다.

표현바깥 컨테이너안쪽 객체
b = orig같은 객체같은 객체
orig.copy(), list(orig), orig[:], [*orig], copy.copy(orig)새 객체원본과 공유
d.copy(), dict(d), {**d}, copy.copy(d)새 객체원본과 공유
copy.deepcopy(orig), copy.deepcopy(d)새 객체새 객체

표에서 읽을 수 있는 것은 다음과 같다.

  • 대입만 바깥까지 같은 객체이다. 대입을 뺀 나머지 열한 가지 표현은 모두 바깥 컨테이너를 새로 만들었다.
  • 리스트의 copy()·list()·슬라이스·[*x]와 딕셔너리의 copy()·dict()·{**d}, 그리고 copy.copy까지 이 환경에서는 같은 깊이(한 겹)였다.
  • 공식 문서 내장 시퀀스 항목은 가변 시퀀스의 copy()를 「Create a shallow copy of sequence. This is equivalent to writing sequence[:].」라고 적는다. 슬라이스와 copy()가 같은 깊이라는 출력과 맞는다.
  • copy 모듈 문서는 컬렉션의 얕은 복사를 list.copy()·dict.copy()·set.copy()와 전체 슬라이스로 만들 수 있다고 적는다. copy 문서는 이 방법들을 얕은 복사로 열거한다. 출력의 is 표가 이를 보여 준다.
  • deepcopy만 안쪽 객체까지 새로 만들었다.

중첩 구조에서 원본이 바뀌는 재현

한 겹만 새로 만들어진 사본에 변경을 가하면, 어느 층의 변경인지에 따라 원본이 바뀌기도 하고 바뀌지 않기도 한다. 아래 코드는 사본에 세 종류의 변경을 차례로 가하고, 그때마다 원본을 출력한다. 뒷부분은 기본 설정 딕셔너리를 copy()해 사용자 설정을 만드는 상황이다.

orig = [[1, 2], [3, 4]]
                    dup = orig.copy()
                    dup.append([5, 6])
                    print('after append to the copy   :', orig)
                    dup[0].append(99)
                    print('after changing an inner list:', orig)
                    dup[1] = 'replaced'
                    print('after replacing an element  :', orig)
                    
                    defaults = {'name': 'base', 'tags': ['a']}
                    user = defaults.copy()
                    user['name'] = 'mine'
                    user['tags'].append('b')
                    print(defaults)
                    print(user)
after append to the copy   : [[1, 2], [3, 4]]
                    after changing an inner list: [[1, 2, 99], [3, 4]]
                    after replacing an element  : [[1, 2, 99], [3, 4]]
                    {'name': 'base', 'tags': ['a', 'b']}
                    {'name': 'mine', 'tags': ['a', 'b']}

사본에 새 항목을 append하는 것(바깥 컨테이너의 변경)과 사본의 원소를 다른 값으로 교체하는 것(dup[1] = 'replaced')은 원본에 영향이 없었다. 반면 사본의 안쪽 리스트 dup[0]에 append(99)를 하자 원본의 orig[0]도 [1, 2, 99]가 되었다. 사본과 원본이 같은 안쪽 리스트를 가리키기 때문이며, 앞 절의 new inner False 출력이 이 결과를 예고한다.

딕셔너리도 같다. user['name'] = 'mine'은 user만 바꿨고 defaults['name']은 'base'로 남았다. 하지만 user['tags'].append('b')는 defaults['tags']에도 'b'를 넣었다. 사용자 설정을 만들려던 코드가 기본 설정을 오염시킨 것이다.

  • 사본의 바깥 컨테이너를 바꾸는 연산(항목 추가·교체·삭제)은 원본에 영향이 없다.
  • 사본이 공유하는 안쪽 가변 객체를 제자리에서 바꾸는 연산(append, [k] = v 등)은 원본에도 보인다.
  • 같은 사본에서도 어느 필드를 건드렸는지에 따라 결과가 갈리므로, 테스트에서 한 가지 필드만 확인하면 문제가 드러나지 않을 수 있다.

반복 연산은 복사가 아니라 같은 참조의 반복이다

2차원 리스트를 [[0] * 2] * 3으로 만드는 것도 같은 문제의 다른 얼굴이다. 공식 문서는 s * n에 대해 「items in the sequence s are not copied; they are referenced multiple times」라고 적고, lists = [[]] * 3 뒤 lists[0].append(3)이 [[3], [3], [3]]이 되는 예를 든다. 아래 출력은 비슷한 코드의 결과이다.

grid = [[0] * 2] * 3
                    print(grid[0] is grid[1] is grid[2])
                    grid[0][0] = 1
                    print(grid)
                    fresh = [[0] * 2 for _ in range(3)]
                    print(fresh[0] is fresh[1])
                    fresh[0][0] = 1
                    print(fresh)
True
                    [[1, 0], [1, 0], [1, 0]]
                    False
                    [[1, 0], [0, 0], [0, 0]]

첫 줄이 True이다. 세 행이 모두 같은 리스트 객체이고, grid[0][0] = 1이 세 행 모두에 나타났다. 리스트 컴프리헨션으로 행마다 새 리스트를 만든 fresh는 행이 서로 다른 객체이고(False) 한 행만 바뀌었다. 복사 함수를 쓰지 않았는데도 같은 현상이 나는 이유는, 문제가 복사 방법이 아니라 「같은 객체에 이름이나 위치가 여러 개 붙었다」는 점에 있기 때문이다.

튜플 안의 리스트 - 바꿀 수 없는 컨테이너의 함정

데이터 모델 문서는 이렇게 적는다. "The value of an immutable container object that contains a reference to a mutable object can change when the latter's value is changed; however the container is still considered immutable, because the collection of objects it contains cannot be changed." 불변 컨테이너가 가변 객체를 담고 있으면 그 가변 객체가 바뀔 때 컨테이너의 값도 바뀔 수 있다는 문장이다. 복사와 만났을 때의 결과는 아래 출력과 같다.

import copy
                    t = ([1, 2], 3)
                    print(copy.copy(t) is t)
                    deep = copy.deepcopy(t)
                    print(deep is t, deep[0] is t[0], deep == t)
                    t[0].append(99)
                    print(t)
                    try:
                        t[0] += [4]
                    except TypeError as e:
                        print(type(e).__name__, e)
                    print(t)
                    print(deep)
                    u = (1, 'a')
                    print(copy.deepcopy(u) is u)
True
                    False False True
                    ([1, 2, 99], 3)
                    TypeError 'tuple' object does not support item assignment
                    ([1, 2, 99, 4], 3)
                    ([1, 2], 3)
                    True

첫 줄에서 copy.copy(t) is t가 True이다. 튜플의 얕은 복사는 새 튜플을 만들지 않고 같은 객체를 돌려줬다. 둘째 줄에서 deepcopy(t)는 새 튜플(deep is t가 False)이고 안의 리스트도 새 객체이며(deep[0] is t[0]가 False) 값은 같다(deep == t). 원본 t의 리스트에 append(99)를 하면 튜플이 불변인데도 ([1, 2, 99], 3)이 되었다.

그다음 줄이 이 함정이 드러나는 장면이다. t[0] += [4]는 TypeError: 'tuple' object does not support item assignment를 냈는데, 곧이어 t를 출력하면 ([1, 2, 99, 4], 3)이다. 예외가 났는데도 리스트에 4가 이미 추가되어 있었다. 이 출력에서 확인되는 것은 예외와 변경이 둘 다 일어났다는 사실이다. 마지막 두 줄에서 deepcopy로 분리해 둔 deep은 ([1, 2], 3) 그대로이고, 안에 가변 객체가 없는 튜플 u = (1, 'a')의 deepcopy(u) is u는 True였다.

  • 튜플의 copy.copy는 같은 객체를 돌려주므로 「복사했다」는 느낌과 달리 아무것도 만들어지지 않는다. 안에 리스트가 있으면 그 리스트도 당연히 공유한다.
  • 튜플이 불변이라는 것은 튜플의 원소 자리가 바뀌지 않는다는 뜻이고, 원소가 가리키는 리스트의 내용까지 고정하지는 않는다.
  • 튜플을 딕셔너리 키나 설정 값으로 쓰면서 안에 리스트를 넣었다면 복사본 사이에서 그 리스트가 공유된다.
  • deepcopy는 가변 객체가 든 튜플은 새로 만들고, 불변 객체만 든 튜플은 같은 객체로 돌려줬다. 이 출력 두 줄은 CPython에서 나온 관찰이다.

클래스와 데이터클래스의 복사

사용자 정의 클래스의 인스턴스도 같은 규칙을 따른다. 데이터클래스로 리스트 필드를 가진 객체를 만들고 네 가지 방법으로 새 객체를 얻은 뒤, 각각이 리스트 필드를 공유하는지 출력한다. 마지막 줄은 원본의 리스트에 항목을 추가한 뒤 네 사본의 리스트이다.

import copy
                    import dataclasses
                    from dataclasses import dataclass, field
                    
                    @dataclass
                    class Box:
                        name: str
                        items: list = field(default_factory=list)
                    
                    a = Box('a', [1, 2])
                    b = copy.copy(a)
                    c = copy.deepcopy(a)
                    d = dataclasses.replace(a, name='d')
                    e = copy.replace(a, name='e')
                    for label, x in [('copy.copy', b), ('copy.deepcopy', c), ('dataclasses.replace', d), ('copy.replace', e)]:
                        print('%-20s new object: %-5s shares items: %s' % (label, x is not a, x.items is a.items))
                    a.items.append(3)
                    print(b.items, c.items, d.items, e.items)
copy.copy            new object: True  shares items: True
                    copy.deepcopy        new object: True  shares items: False
                    dataclasses.replace  new object: True  shares items: True
                    copy.replace         new object: True  shares items: True
                    [1, 2, 3] [1, 2] [1, 2, 3] [1, 2, 3]

네 방법 모두 새 객체를 만들었지만 deepcopy만 리스트를 분리했다. copy.copy와 dataclasses.replace, 그리고 3.13에 추가된 copy.replace는 리스트를 원본과 공유했고, 마지막 줄에서 원본에 3을 넣자 이 셋의 리스트에도 3이 보였다. copy 모듈 문서는 copy.replace()가 3.13에서 추가되었고 copy()·deepcopy()보다 제한적이며 namedtuple, 데이터클래스, __replace__()를 정의한 클래스만 지원한다고 적는다. 필드 일부를 바꿔 새 객체를 만드는 replace 계열은 바꾸지 않은 필드를 그대로 가져오므로, 가변 필드는 공유된다.

deepcopy가 모든 객체를 복사할 수 있는 것은 아니다. 락(threading.Lock)을 속성으로 가진 객체에 copy.copy와 copy.deepcopy를 적용하고, __deepcopy__를 정의한 하위 클래스에도 적용한다.

import copy
                    import threading
                    
                    class Job:
                        def __init__(self, name):
                            self.name = name
                            self.lock = threading.Lock()
                            self.log = []
                    
                    job = Job('j1')
                    try:
                        copy.deepcopy(job)
                    except TypeError as e:
                        print(type(e).__name__, e)
                    print(copy.copy(job).lock is job.lock)
                    
                    class SafeJob(Job):
                        def __deepcopy__(self, memo):
                            new = SafeJob(self.name)
                            new.log = copy.deepcopy(self.log, memo)
                            return new
                    
                    s = SafeJob('j2')
                    s.log.append('start')
                    t = copy.deepcopy(s)
                    print(t.log, t.log is s.log, t.lock is s.lock)
TypeError cannot pickle '_thread.lock' object
                    True
                    ['start'] False False

copy.deepcopy(job)은 TypeError: cannot pickle '_thread.lock' object로 실패했고, copy.copy(job).lock is job.lock은 True였다. 얕은 복사는 락 객체를 건드리지 않고 공유한다. __deepcopy__(self, memo)를 정의한 SafeJob은 새 락을 가진 새 객체를 만들었고(t.lock is s.lock이 False), 로그 리스트는 따로 복사되어 분리되었다(t.log is s.log가 False, 내용은 ['start']). copy 모듈 문서는 deepcopy가 사용자 정의 클래스가 복사 동작이나 복사할 구성 요소의 집합을 재정의하게 해 준다고 적고, object.__deepcopy__(self, memo)가 깊은 복사를 구현하며 memo 딕셔너리를 인자로 받는다고 설명한다. 이 설명과 출력이 일치한다.

  • 얕은 복사(copy.copy)는 객체의 속성이 무엇이든 참조만 복사하므로 락이 있어도 성공했다.
  • deepcopy는 복사할 수 없는 속성을 만나면 TypeError로 실패한다. 이 출력에서 그 예가 락이다.
  • 공유해야 하는 자원(락, 연결 등)이 있는 클래스에는 __deepcopy__로 복사 방식을 지정한다.

deepcopy가 해결하는 것 - memo와 순환 참조

copy 모듈 문서는 깊은 복사에 두 가지 문제가 있다고 적는다. 첫째, 재귀적 객체(직접 또는 간접으로 자기 자신에 대한 참조를 담은 복합 객체)가 재귀 루프를 일으킬 수 있다. 둘째, 모든 것을 복사하므로 복사본 사이에 공유되도록 의도된 데이터까지 복사할 수 있다. 그리고 deepcopy()는 이를 두 가지로 피한다고 적는다. 현재 복사 과정에서 이미 복사한 객체의 memo 딕셔너리를 유지하는 것, 사용자 정의 클래스가 복사 동작이나 복사 구성 요소를 재정의하게 하는 것이다. 첫 번째 장치는 아래 출력으로 확인된다. 출력은 같은 리스트가 두 번 들어간 구조, 순환 구조, 미리 채운 memo를 다룬다.

import copy
                    a = [1]
                    orig = [a, a]
                    deep = copy.deepcopy(orig)
                    print('deepcopy keeps sharing :', deep[0] is deep[1], '| detached from original:', deep[0] is not orig[0])
                    naive = [copy.deepcopy(x) for x in orig]
                    print('per-element deepcopy   :', naive[0] is naive[1])
                    shallow = copy.copy(orig)
                    print('shallow copy           :', shallow[0] is shallow[1], shallow[0] is orig[0])
                    
                    memo = {}
                    copy.deepcopy(orig, memo)
                    print('memo entries           :', len(memo))
                    
                    loop = []
                    loop.append(loop)
                    print('cyclic shallow         :', copy.copy(loop)[0] is loop)
                    dup = copy.deepcopy(loop)
                    print('cyclic deepcopy        :', dup is not loop, dup[0] is dup)
                    
                    keep = {id(a): a}
                    part = copy.deepcopy(orig, keep)
                    print('pre-filled memo        :', part[0] is a, part[0] is part[1])
deepcopy keeps sharing : True | detached from original: True
                    per-element deepcopy   : False
                    shallow copy           : True True
                    memo entries           : 3
                    cyclic shallow         : True
                    cyclic deepcopy        : True True
                    pre-filled memo        : True True
  • 같은 리스트 a를 두 번 담은 orig = [a, a]를 deepcopy하면, 사본에서도 두 자리가 같은 하나의 객체이다(deep[0] is deep[1]가 True). 그러면서 원본과는 분리되어 있다(deep[0] is not orig[0]가 True). 구조가 보존된 것이다.
  • 원소마다 따로 deepcopy한 naive는 두 자리가 서로 다른 객체가 되었다(False). 같은 객체를 공유하던 구조가 사라진다. memo는 한 번의 deepcopy 호출 동안만 유지되므로, 호출을 쪼개면 보존되지 않는다.
  • 얕은 복사는 안쪽 두 자리가 원본의 a를 그대로 가리킨다(shallow[0] is orig[0]가 True).
  • deepcopy가 채운 memo에는 3개 항목이 들어 있었다.
  • 자기 자신을 담은 리스트 loop에서 얕은 복사의 첫 원소는 원본 loop를 가리킨다(True). deepcopy는 무한 재귀 없이 끝났고, 사본은 원본과 다른 객체이면서 자기 자신을 담는다(dup[0] is dup가 True). 순환 구조까지 보존한 것이다.
  • memo에 {id(a): a}를 미리 넣고 deepcopy를 호출하면 part[0] is a가 True였다. 이미 memo에 있는 객체는 복사되지 않고 그대로 쓰인다.

마지막 항목은 공유해야 하는 객체를 복사 대상에서 빼는 방법이 된다. 문서가 말한 「복사본 사이에 공유되도록 의도된 데이터까지 복사할 수 있다」는 문제에 대해, 이 출력은 memo를 미리 채우는 것으로 한 객체를 공유로 남길 수 있음을 보여 준다. 다만 이는 memo의 동작을 이용한 관찰이고, 문서가 제시하는 정식 방법은 __deepcopy__를 정의하는 것이다.

deepcopy의 비용 - 이 PC의 측정값

deepcopy는 안쪽 객체를 모두 순회하며 복사하므로 얕은 복사보다 오래 걸린다. 얼마나 걸리는지는 timeit 값으로 나타낸다. 안쪽 리스트 1만 개를 가진 중첩 리스트(nested)와 정수 1만 개의 평평한 리스트(flat)에 대해, 표현마다 5회 반복해 가장 빠른 값을 1회 호출당 마이크로초로 출력한다. 아래 두 출력은 같은 스크립트를 두 번 돌린 결과이며, 한 번에 이 PC에서 2~3초가 걸린다.

import copy
                    import timeit
                    
                    def best_us(stmt, glb, number):
                        runs = timeit.repeat(stmt, globals=glb, number=number, repeat=5)
                        return min(runs) / number * 1e6
                    
                    for n in (100, 10000):
                        nested = [[i, i + 1, i + 2] for i in range(n)]
                        flat = list(range(n))
                        fast, slow = (2000, 200) if n == 100 else (200, 5)
                        g = {'copy': copy, 'nested': nested, 'flat': flat}
                        print('n =', n)
                        print('  nested.copy()             %10.1f us' % best_us('nested.copy()', g, fast))
                        print('  copy.copy(nested)         %10.1f us' % best_us('copy.copy(nested)', g, fast))
                        print('  copy.deepcopy(nested)     %10.1f us' % best_us('copy.deepcopy(nested)', g, slow))
                        print('  flat.copy()               %10.1f us' % best_us('flat.copy()', g, fast))
                        print('  copy.deepcopy(flat)       %10.1f us' % best_us('copy.deepcopy(flat)', g, slow))

두 출력에서 같은 코드의 값이 달랐다. 같은 표현의 값이 두 출력에서 다르므로 개별 수치보다는 크기의 차이를 읽어야 한다. 1만 개짜리 중첩 리스트에서 copy.deepcopy(nested)는 copy.copy(nested)보다 약 624~641배(두 출력의 계산값) 걸렸고, 정수 1만 개의 copy.deepcopy(flat)도 flat.copy()보다 약 167~173배(계산값) 걸렸다. 안쪽에 가변 객체가 없는 정수 리스트에서도 deepcopy의 값은 얕은 복사보다 컸다. 위 배수는 이 PC의 값이며 재실행하면 달라진다.

  • 이 크기에서 얕은 복사의 값은 수십 마이크로초였고, deepcopy의 값은 수천~수만 마이크로초(밀리초 단위)였다.
  • deepcopy는 사본에서 안쪽 가변 객체를 바꾸는 경우에 필요하다. 읽기만 하는 사본이나 안쪽을 바꾸지 않는 사본은 4절의 결과처럼 얕은 복사로 원본에 영향이 없다.
  • 반복문 안에서 deepcopy를 호출하는 코드는 비용이 반복 횟수만큼 곱해진다.
  • 이 측정은 한 PC의 두 번 실행이다. 개선이나 감소를 약속하는 값이 아니며, 다른 데이터 모양에서는 다른 결과가 나올 수 있다.

무엇을 고를까 - 선택 기준

앞의 출력에서 얻은 기준을 표로 묶는다. 마지막 두 줄의 선택적 복사와 deepcopy는 아래 코드의 출력을 근거로 한다. 첫 블록은 바꿀 필드만 골라 복사한 경우이고, 둘째 블록은 deepcopy로 통째로 복사한 경우이다. 두 경우 모두 사본의 limits를 바꾸고 원본을 출력한다.

import copy
                    
                    def make():
                        return {'name': 'base', 'tags': ['a'], 'limits': {'cpu': 1}}
                    
                    defaults = make()
                    one = {**defaults, 'tags': defaults['tags'].copy()}
                    one['tags'].append('b')
                    one['limits']['cpu'] = 8
                    print('selective copy:', defaults)
                    
                    defaults = make()
                    two = copy.deepcopy(defaults)
                    two['tags'].append('b')
                    two['limits']['cpu'] = 8
                    print('deepcopy      :', defaults)
selective copy: {'name': 'base', 'tags': ['a'], 'limits': {'cpu': 8}}
                    deepcopy      : {'name': 'base', 'tags': ['a'], 'limits': {'cpu': 1}}

선택적 복사는 tags를 복사해 두었으므로 tags는 원본이 지켜졌지만, 복사하지 않은 limits가 공유되어 원본의 limits가 {'cpu': 8}이 되었다. deepcopy는 새로 만든 원본에서 tags와 limits 모두 그대로였다. 선택적 복사는 복사할 필드를 빠뜨릴 수 있고, deepcopy는 비용이 든다.

점검 질문으로 줄이면 다음과 같다.

  • 복사한 뒤 안쪽 가변 객체를 제자리에서 바꾸는가.
  • 사본의 안쪽 객체가 원본과 같은 객체인지 is로 확인했는가.
  • deepcopy를 쓴다면 복사할 수 없는 속성이나 공유해야 하는 속성이 없는가.
  • 반복문 안의 deepcopy가 시간에 영향을 주는가.
  • [[0] * n] * m 같은 반복 표현을 쓰고 있지 않은가.

확인하지 못한 것

  • deepcopy가 느린 내부 이유. 이 PC의 측정값만 있고, 어떤 단계에서 시간이 드는지는 프로파일링하지 않았다.
  • deepcopy가 채운 memo의 3개 항목이 각각 무엇인지. 개수만 출력했고 항목 하나하나의 정체는 따로 보지 않았다.
  • set·bytearray·사용자 정의 컨테이너 등 리스트·딕셔너리 이외 컨테이너에서의 복사 깊이.
  • PyPy 같은 다른 구현이나 다른 Python 버전에서의 동작. 튜플의 얕은 복사가 같은 객체를 돌려주는 것도 이 환경(CPython 3.13.3)의 관찰이다.
  • NumPy 배열·pandas 데이터프레임 등 외부 라이브러리 객체의 복사 의미.
  • __copy__·__reduce__·copyreg를 통한 복사 확장과 이것이 deepcopy의 TypeError와 맺는 관계.
  • 슬롯(__slots__)을 쓰는 클래스, 상속 구조가 복잡한 객체의 deepcopy 결과.
  • 멀티스레드에서 복사 중 원본이 변경될 때의 동작.
