모드(mod)의 정의와 아키텍처 — 설정 훅과 다른 세션 상주 구조

원문은 모드를 Claude Code 세션 안에서 도는 작은 JavaScript 또는 TypeScript 파일이라고 정의한다. 모드는 세션에서 일어나는 일을 지켜볼 수 있고, Claude Code가 하는 일을 바꿀 수 있으며, 터미널이든 데스크톱 앱이든 자기 UI를 직접 그릴 수 있다. API를 배울 필요도 없다. claude를 실행해 원하는 모드를 말로 설명하고, 핫 리로드를 허용하겠느냐는 질문에 허락하면 턴이 끝날 때 모드가 나타난다고 한다.

Claude Code는 이미 설정, 권한 규칙(permission rules), 슬래시 명령, 스킬, 상태 표시줄로 동작을 많이 바꿀 수 있게 해 준다. 원문은 모드가 한 걸음 더 나아가 Claude Code가 하는 일을 다시 쓰거나 대체하고 맞춤 UI까지 그린다고 설명한다. 내부적으로 모드는 플러그인에 실려 배포되는 훅이며, 각 모드는 세션에서 일어나는 모든 이벤트를 그때그때 본다.

설정 훅과의 차이는 원문이 한 단락으로 요약한다. 설정 훅은 이벤트마다 셸 명령을 실행하고 stdin·stdout으로 JSON을 주고받는다. 반면 모드는 한 번 로드되어 세션에 머문다. 이 구조에서 모드가 하는 일은 네 가지로 정리된다.

  • 한 번 로드, 세션 유지: 이벤트마다 프로세스를 띄우지 않고 로드된 상태로 세션 내내 머문다.
  • 상태 유지: 값을 모듈 변수가 아니라 호스트가 들고 있는 $.state에 두면 리로드를 거쳐도 남는다.
  • UI 갱신: 이벤트가 일어날 때마다 갱신되는 UI를 그린다.
  • 콜백: Claude Code를 다시 불러 pane 열기, 프로세스 실행, 슬래시 명령 등록, 모델이 호출할 수 있는 도구 등록을 한다.

원문에 따르면 Claude Code 자신도 일부 기능을 모드로 만든다. AGENTS.md 지원과 대화 옆의 /diff 창이 그 예이며, 소스와 테스트는 공개 저장소 anthropics/claude-code의 mods/ 아래에 있어 팀이 모드를 어떻게 짜는지 읽어 볼 수 있다.

훅 체인과 3대 동작 패턴 — Observe·Rewrite·Answer의 작동 원리

모드는 플러그인의 훅이 이어진 체인으로 움직인다. 모듈은 register(on, options)를 내보내고, 그 안에서 on(event, matcher?, hook)으로 훅을 더한다. 모든 훅은 같은 모양이다. 원문의 코드가 그 모양과 세 인자의 뜻을 주석으로 설명한다.

on("tool.call", { tool: "Bash" }, async ($, e, next) => {
                      // $    the mods API: ui, session, state, store, fs, process, clock, http, tool, command, model, ...
                      // e    this event's input, as plain data
                      // next passes e to the other plugins and then to Claude Code's own behavior
                      return next(e);
                    });

훅은 미들웨어처럼 이어진다. 내 훅이 실행되고, next(e)가 이벤트를 다음 플러그인에 넘기며, 맨 아래에서 Claude Code가 원래 하려던 일을 한다. 훅이 할 수 있는 일은 세 가지다. 먼저 관찰(Observe)은 const r = await next(e);로 결과를 받아 살펴본 뒤 그대로 돌려주는 것이다. 모든 파일 편집을 기록하거나 매 턴 끝에 값을 읽는 일이 그 예다. 다음으로 재작성(Rewrite)은 return next({ ...e, command: safer })처럼 체인의 나머지가 보는 입력을 바꾸는 것이다. 마지막으로 직접 응답(Answer)은 next를 호출하지 않고 { deny: "…" }를 돌려주는 것으로, 도구 호출을 거절하거나 명령·도구를 훅이 직접 처리한다.

패턴 구분코드 형태원문의 예체인에서의 위치
Observe (관찰)const r = await next(e); /* look */ return r모든 파일 편집 기록, 매 턴 후 값 읽기next 호출 뒤에 결과를 본다
Rewrite (재작성)return next({ ...e, command: safer })체인의 나머지가 보는 입력을 바꾼다next 호출 전에 입력을 바꾼다
Answer (직접 응답)return { deny: "…" } (next 미호출)도구 호출 거절, 명령이나 도구를 직접 처리체인을 이어 가지 않고 훅이 대신 답한다

원문이 말하는 이벤트의 범위는 도구 호출, 제출된 프롬프트, 턴의 시작과 끝, 세션의 시작과 끝, 슬래시 명령, 그리고 그려지는 인터페이스의 모든 조각인 ui.render다. 글과 코드에서 이름이 확인되는 것은 다음과 같다.

  • tool.call: 도구 호출. { tool: "Bash" }처럼 도구 이름으로 좁힐 수 있다.
  • prompt.submit: 제출된 프롬프트. 원문은 팀 규칙을 모든 프롬프트에 붙이는 훅을 아이디어로 든다.
  • turn.start · turn.complete: 턴의 시작과 끝. 서브에이전트의 턴은 e.agentId로 가른다.
  • session.start: 세션 시작. 원문은 세션의 시작과 끝을 이벤트로 든다.
  • command.run: 등록한 슬래시 명령이 실행될 때. { command: "replay" }처럼 명령 이름으로 좁힌다.
  • ui.render: 인터페이스 조각이 그려질 때. { component: "AbovePrompt" }처럼 컴포넌트로 좁힌다.

모듈은 자기만의 샌드박스에서 돌며 DOM도 Node도 없다. 그래서 바깥으로 나가는 모든 일은 $를 거친다. 원문 코드의 주석은 $가 ui, session, state, store, fs, process, clock, http, tool, command, model 등을 담고 있다고 적는다.

모드 플러그인 구성 요소 — 매니페스트·타입 계약·$.state

모드는 별도 형식이 아니라 평범한 플러그인 폴더다. 원문이 보여 주는 Token Weather의 구성은 다음과 같다.

token-weather/
                    ├── .claude-plugin/
                    │   ├── plugin.json
                    │   └── types/            (written by Claude Code when it loads the mod)
                    ├── hooks/
                    │   ├── hooks.json
                    │   └── token-weather.mjs
                    ├── types/
                    │   └── index.d.ts        (added in step 3)
                    └── tests/
                        └── token-weather.test.ts   (added in step 5)

각 파일의 역할은 다음과 같다.

  • .claude-plugin/plugin.json: 표준 플러그인 매니페스트다. name, version, description, author를 적는다.
  • hooks/hooks.json: modules 아래에 모듈을 정확히 하나 가리킨다. 원문은 「A mod has exactly one」이라고 적는다.
  • types/index.d.ts: $.state에 둘 값을 PluginState 인터페이스에 선언하는 타입 계약이다. 매니페스트에 "types": "./types/index.d.ts"를 더해야 한다.
  • .claude-plugin/types/: 모드를 로드할 때마다 Claude Code가 그 빌드의 선언을 써 넣는 폴더다. 에디터와 tsc -p가 추가 설정 없이 이것을 쓴다.

원문이 가장 강조하는 습관은 핫 리로드를 염두에 두는 것이다. 모듈 수준의 let readings = []는 쉬운 선택처럼 보이지만, 핫 리로드는 새로 로드하는 일이라 register와 session.start가 다시 실행되고 모듈 변수는 처음 상태로 돌아간다. 이력은 $.state에 두어야 한다. 이는 이름 붙은 값을 호스트에 들고 있으므로 리로드를 거쳐도 남는다. 값은 { plugin: "token-weather", key: "readings" }처럼 plugin과 key로 가리키며 $.state.get·$.state.set으로 읽고 쓴다.

선언을 빼먹으면 claude plugin validate가 고칠 곳을 알려 주며 멈춘다. 원문이 보여 주는 오류는 「token-weather.readings is not declared: the manifest's types contract must name it in interface PluginState { … }」다. 대신 얻는 것도 있다. 렌더 훅이 도는 동안 한 $.state.get은 그 그림을 구독하므로, 이후 $.state.set이 일어나면 밴드가 다시 그려지며 $.ui.invalidate를 부를 일이 없다.

예제 1: Token Weather — 컨텍스트 잔여량과 12턴 추이 시각화

원문이 빈 폴더에서 만들어 보이는 첫 모드가 Token Weather다. 매 턴 뒤에 컨텍스트 창이 얼마나 찼는지 읽고, 프롬프트 바로 위 밴드에 한 줄을 그린다. 한 줄에는 날씨 아이콘, 사용 비율, 창 대비 사용 토큰, 최근 턴의 작은 차트, 마지막 턴이 늘린 양이 들어가며 분량은 약 80줄이다. 원문은 이 한 줄이 채워지는 모습을 18%에서 Clear, 67%에서 Showers, 81%에서 Storm으로 보여 준다.

컨텍스트 사용률날씨 기호 및 텍스트표시 색상코드의 upTo 값
25% 미만☀ Clearyellow25
25% ~ 49%☁ Cloudycyan50
50% ~ 74%☂ Showersblue75
75% ~ 89%☇ Stormmagenta90
90% 이상↯ Compact soonredInfinity

프롬프트 바로 위 밴드는 AbovePrompt라는 컴포넌트다. Claude Code가 이곳에는 아무것도 그리지 않으므로 첫 실습 대상으로 좋다고 원문은 말한다. 이 컴포넌트의 ui.render 이벤트에 훅을 걸고 요소 트리를 돌려주면 된다. 원문의 두 번째 단계 코드는 다음과 같다.

// hooks/token-weather.mjs
                    export function register(on) {
                      on("ui.render", { component: "AbovePrompt" }, ($, e, next) => {
                        const { Box, Text } = $.ui.resolve(e);
                        return Box({
                          paddingX: 1,
                          children: [Text({ color: "yellow", bold: true, children: "☀  Clear skies" })],
                        });
                      });
                    }

요소는 전역이 아니다. 그리는 화면(surface)마다 지원하는 요소가 조금씩 달라서 $.ui.resolve(e)가 그 화면용 생성자를 돌려준다. claude --plugin-dir ./token-weather로 세션을 열면 「☀ Clear skies」가 프롬프트 위에 나타나고, 폴더를 감시하므로 저장할 때마다 재시작 없이 모듈이 다시 로드된다.

숫자는 $.session.usage()에서 읽는다. 상태 표시줄과 같은 수치를 돌려주며 context.tokens, context.window, context.percent가 들어 있다. 호출은 공짜이고, 세부 내역을 요청할 때만 토큰 계수 요청이 나간다. 훅은 session.start와 turn.complete에서 next(e)를 먼저 부른 뒤 관찰만 하며, if (!e.agentId)로 서브에이전트 턴을 빼고 메인 루프 턴만 읽는다. 이력은 최근 12개만 남기고 ▁▂▃▄▅▆▇█ 문자로 차트를 만든다.

원문은 따라 할 만한 세부 사항 세 가지를 든다. 컴포넌트의 props는 e.props에 있다. hasSurvey가 참이면 설문이 밴드를 쓰려는 것이라 next(e)로 양보하고, bodyColumns는 밴드의 실제 폭이어서 pane이 옆에 붙으면 터미널보다 좁다. 이 코드는 폭이 60열 이상일 때만 차트와 증감 표시를 더한다. 그릴 것이 없으면 next(e)를 돌려 Claude Code와 다른 모드에 자리를 돌려준다. 마지막으로 이모지가 아니라 폭이 하나인 기호를 쓰면 어떤 터미널 글꼴에서도 줄이 맞는다.

예제 2: Blast Radius — 위험 명령 보류와 건조 실행 보고서

Claude가 Bash로 다음 명령을 부르면 Blast Radius가 그 호출을 붙잡는다. 명령이 건드릴 대상을 계산한 뒤 Proceed와 Cancel이 있는 pane을 연다. 2를 누르면 Claude는 이유가 담긴 거절을 받고, 1을 누르면 명령이 쓴 그대로 실행된다.

  • rm -rf
  • git reset --hard
  • git clean
  • 강제 푸시(force push)
  • 데이터베이스 마이그레이션(database migration)

이 모드가 쓰는 훅은 셋이다. Bash에 대한 tool.call, 그리고 Pane과 AbovePrompt에 대한 ui.render다. 핵심은 앞의 표에서 본 직접 응답(Answer)이며, 원문의 코드는 다음과 같다.

on("tool.call", { tool: "Bash" }, async ($, e, next) => {
                      const risk = classify(String(e.command ?? ""));
                      if (risk === null) return next(e);                 // everything else runs as normal
                      const report = await measure($, risk, await $.session.cwd());  // git status, git clean -n, du, ...
                      held = { command: e.command, risk, report, decision: null };
                      const opened = await $.ui.open({ id: "blast-radius", title: "Blast Radius", focus: true });
                      if (!opened.isPlaced) held.where = "band";         // too narrow for a pane: draw above the prompt
                      while (held.decision === null && !next.signal.aborted) {
                        await $.process.run(["sleep", "0.25"]);          // time inside $ calls doesn't count against the hook's time limit
                      }
                      if (held.decision === "proceed") return next(e);   // let it run
                      return { deny: `Blast Radius held this command: the user pressed Cancel. It would have: ${report.summary}.` };
                    });

원문이 이 코드에서 짚는 점은 네 가지다. 첫째, 건조 실행은 $.process.run으로 한다. 보고서는 git status --porcelain, git clean -n, git log HEAD..origin/main, showmigrations 같은 도구 자신의 명령에서 나오며, 인자를 argv 배열로 넘기므로 경로의 어떤 글자도 셸 코드로 실행되지 않는다. 둘째, 호출을 붙잡아 두는 방법이다. 훅은 한 번 호출될 때 자기 시간으로 10초를 받지만 $ 호출 안에서 기다리는 시간은 세지 않는다. 그래서 버튼의 onPress가 결정을 정할 때까지 짧은 sleep 프로세스를 반복해 기다리고, next.signal이 중단되면(Esc를 누르면) 포기한다.

셋째, 버튼에는 단축키를 줄 수 있다. Button({ label: "Proceed", hotkey: "1", onPress })는 클릭, Tab과 Enter, 숫자 키로 모두 눌린다. 넷째, 밴드로의 후퇴다. 터미널이 충분히 넓으면 pane을 대화 옆에 붙이고, $.ui.open이 isPlaced: false로 답하면 같은 보고서를 프롬프트 위에 그린다.

원문은 한계도 분명히 적는다. 이 모드는 안전망일 뿐 권한 시스템이 아니다. 명령 문자열을 읽기 때문에 $(…), 별칭(alias), rm을 부르는 스크립트는 통과한다. 확실히 막으려면 권한 규칙을 써야 한다.

예제 3: Replay Theater — 턴별 파일 편집 diff 단계 재생

Replay Theater는 턴이 도는 동안 모든 Edit와 Write 호출을 기록한다. 파일과 쓰기 전후의 텍스트가 대상이다. 턴이 끝나면 프롬프트 위에 안내가 나오고, r을 누르거나 /replay를 치면 pane이 번호 붙은 단계 띠와 Prev, Next, Close 버튼으로 편집을 diff 하나씩 보여 준다. 이 모드는 편집을 막거나 바꾸지 않고 관찰만 하며, 원문의 코드는 다음과 같다.

on("tool.call", async ($, e, next) => {
                      if (EDIT_TOOLS.has(e.tool)) state.pending.push(...(await stepsFor($, e)));  // old/new text → diff
                      return next(e);                                                              // the edit runs untouched
                    });
                    on("turn.start", ($, e, next) => { if (!e.agentId) state.pending = []; return next(e); });
                    on("turn.complete", async ($, e, next) => {
                      const r = await next(e);
                      if (!e.agentId && state.pending.length) state.replay = state.pending;       // one replay per turn
                      return r;
                    });
                    on("session.start", async ($, e, next) => {
                      const r = await next(e);
                      await $.command.register({ name: "replay", description: "Step through the last turn's file edits" });
                      return r;
                    });
                    on("command.run", { command: "replay" }, async ($, e) => ({ text: (await openReplay($)) ? "Replaying" : "No edits" }));

원문이 정리한 배울 점은 네 가지다. 첫째는 이벤트 짝짓기다. turn.start와 turn.complete가 편집을 턴 하나씩의 재생으로 묶고, e.agentId가 서브에이전트의 턴을 묶음에서 뺀다. 둘째는 슬래시 명령 등록이다. session.start에서 $.command.register를 부르고 command.run에서 답한다. 셋째는 파일 읽기다. Write는 쓰기가 반영되기 직전에 $.fs.read로 옛 내용을 읽어 두므로 diff가 실제와 같다. 넷째는 배치가 화면의 몫이라는 점이다. 전체 화면에서는 pane이 오른쪽에 붙고 80열에서는 프롬프트 위에 인라인으로 열리며, 모드는 어느 쪽이든 같은 트리를 그린다.

모드 배포와 보안 경계 — 로컬 실행 권한과 출처 검증

원문의 5단계는 검증과 테스트다. claude plugin validate는 매니페스트와 모듈 소스를 Claude Code가 읽을 방식 그대로 읽고, 모듈이 훅을 거는 이벤트와 부르는 $ 메서드를 보고한다. claude plugin test는 플러그인의 *.test.ts 파일을 실제 Claude Code 런타임에서 돌린다. 테스트가 on으로 등록한 훅은 체인에서 모드 뒤에 실행되어 Claude Code가 답할 내용을 대신하므로 $.session.usage()가 돌려줄 값을 직접 정할 수 있다.

claude plugin validate ./token-weather
                    claude plugin test ./token-weather
                    claude --plugin-dir ./token-weather

모드는 플러그인이므로 같은 방식으로 배포한다. .claude-plugin/marketplace.json이 든 폴더만 있으면 마켓플레이스가 되며, GitHub 저장소에 올리면 그 저장소가 마켓플레이스가 되어 일반 푸시로 갱신한다. 설치는 Claude Code 안에서 /plugin marketplace add your-org/my-mods, /plugin install token-weather@my-mods, /reload-plugins 세 명령이다. 모드는 리로드할 때 시작하며, 나타나지 않으면 Claude Code를 다시 시작한다. 모드가 든 플러그인은 Claude directory(claude.ai/directory/manage)에도 제출할 수 있다.

보안에 관한 원문의 핵심 문장은 하나다. 모드는 내 컴퓨터의 Claude Code 안에서 Claude Code와 같은 접근 권한으로 실행되는 코드이고, Anthropic이 아니라 게시자가 쓴 것이므로 「install mods the way you'd install a package: read the repo first and only install from people you trust」라고 한다. 이 문장 둘레로 원문에서 확인되는 사실은 다음과 같다.

  • 모드가 가지는 접근 범위는 Claude Code가 가진 것과 같다.
  • 모드의 작성자는 게시자이며 Anthropic이 아니다. 그래서 저장소를 먼저 읽고 신뢰하는 사람의 것만 설치한다.
  • 명령을 실행하기 전에는 아무것도 설치되지 않는다.
  • 모듈은 DOM도 Node도 없는 샌드박스에서 돌고, 바깥과의 모든 접점은 $를 거친다. 원문은 이 샌드박스를 권한 격리라고 설명하지 않는다.
  • 훅은 호출 한 번에 자기 시간으로 10초를 받으며, $ 호출 안에서 기다리는 시간은 세지 않는다.

원문의 사례도 같은 방향이다. Blast Radius는 안전망이지 권한 시스템이 아니라서 확실한 차단에는 권한 규칙을 쓰라고 한다.

원문은 끝에서 네 가지 습관을 권한다. Claude Code가 써 주는 타입을 믿고, 값은 e.props에서 읽고, 핫 리로드를 전제로 데이터를 $.state에 두고, 그림이 나오지 않으면 claude --debug로 훅이 검증에 실패한 트리를 돌려주었다는 로그를 찾는 것이다. 설정과 스킬의 배경은 Claude Code 숨겨진 설정 완전 정리와 Claude Code 스킬 설계 패턴에서 이어서 볼 수 있다.

확인하지 못한 것

  • Claude Code 2.1.286 이하에서 모드를 로드했을 때의 오류 메시지나 폴백 동작.
  • $.state의 값이 세션을 끝낸 뒤 재개(resume)할 때 복원되는지 여부(원문은 리로드를 거쳐 남는다고만 설명한다).
  • 터미널과 데스크톱 앱 외에 VS Code 확장 같은 다른 화면에서 쓸 수 있는 $.ui 컴포넌트의 전체 목록.
  • claude.ai/directory/manage에 모드를 제출했을 때 거치는 심사 기준.
  • 훅 안에서 만든 비동기 타이머나 백그라운드 작업이 세션 종료 때 어떻게 정리되는지.
