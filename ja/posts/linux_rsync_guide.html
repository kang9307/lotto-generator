1. Rsync とは? 🤔

Rsync (Remote Sync) は、UNIX 系システムでファイルやディレクトリを効率よく同期・転送するためのツールです。1996 年に Andrew Tridgell と Paul Mackerras によって開発されて以来、システム管理者にとって欠かせないツールとしての地位を確立しています。

✨ Rsync の主な特長

🎯 主な利点

  • 差分転送: 変更された部分だけを転送し、帯域を節約
  • 圧縮対応: ネットワーク転送時にデータを圧縮して速度を向上
  • 権限の保持: ファイルのパーミッション、所有者、タイムスタンプなどメタデータを維持
  • 暗号化対応: SSH による安全なリモート転送
  • 再開機能: 中断した転送を続きから再開可能

🔍 動作原理

Rsync は rolling checksum アルゴリズムを使用し、ファイルの変更箇所のみを検出して転送します。これによりファイル全体を転送する必要がなく、効率的な同期が可能になります。

# Rsync のインストール確認
which rsync
rsync --version

# 多くの Linux ディストリビューションに標準インストールされています
# Ubuntu/Debian: apt install rsync
# CentOS/RHEL: yum install rsync もしくは dnf install rsync

2. 基本構文と主要オプション ⚙️

📝 基本構文

rsync [オプション] ソース 送信先
rsync [オプション] ソース ユーザー@ホスト:送信先
rsync [オプション] ユーザー@ホスト:ソース 送信先

🔧 主要オプション総まとめ

オプション ロングオプション 説明
-v --verbose 詳細な出力情報を表示
-r --recursive サブディレクトリまで再帰的に処理
-a --archive アーカイブモード (-rlptgoD と同等)
-z --compress 転送時に圧縮を適用
-h --human-readable 容量を人が読みやすい形式で表示
-P --progress 進捗を表示 (--partial --progress)
--delete - ソースに存在しないファイルを送信先から削除
--dry-run -n 実行せずにシミュレーションのみ行う
--exclude - 特定のファイル/ディレクトリを除外
--include - 特定のファイル/ディレクトリを含める

🌟 よく使うオプションの組み合わせ

💡 おすすめのオプション組み合わせ

  • -avzP: アーカイブモード + 圧縮 + 進捗表示
  • -avzh --delete: 完全同期 (ミラーリング)
  • -avzh --dry-run: 安全な事前テスト

3. 実務での活用例 💼

📁 ローカルディレクトリ間の同期

# 基本的なコピー
rsync -avzh /source/directory/ /destination/directory/

# 進捗を表示しながらコピー
rsync -avzP /home/user/documents/ /backup/documents/

# 削除も含めて同期 (完全ミラーリング)
rsync -avzh --delete /source/ /destination/

# 特定のファイル形式のみコピー
rsync -avzh --include="*.jpg" --include="*.png" --exclude="*" /photos/ /backup/photos/

🌐 リモートサーバーへのファイル転送

# ローカルからリモートへ転送
rsync -avzh /local/directory/ user@remote-server:/remote/directory/

# リモートからローカルへ取得
rsync -avzh user@remote-server:/remote/directory/ /local/directory/

# 特定のポートを使う SSH 接続
rsync -avzh -e "ssh -p 2222" /local/directory/ user@server:/remote/directory/

# SSH 鍵による認証
rsync -avzh -e "ssh -i ~/.ssh/my-key" /local/directory/ user@server:/remote/directory/

🔒 セキュリティを強化した転送

# SSH 圧縮と併用
rsync -avzh -e "ssh -C" /local/directory/ user@server:/remote/directory/

# 帯域制限 (1000 KB/s)
rsync --bwlimit=1000 -avzh /local/directory/ user@server:/remote/directory/

# チェックサムによる整合性検証
rsync -avzh --checksum /source/ /destination/

4. SSH 連携とセキュリティ 🔐

🔑 SSH 鍵認証の設定

# SSH 鍵の生成
ssh-keygen -t rsa -b 4096 -C "your-email@example.com"

# 公開鍵をリモートサーバーに配布
ssh-copy-id user@remote-server

# SSH エージェントに鍵を追加
ssh-add ~/.ssh/id_rsa

# Rsync で SSH 鍵を指定
rsync -avzh -e "ssh -i ~/.ssh/id_rsa" /local/ user@server:/remote/

⚡ SSH のパフォーマンス最適化

# SSH 設定ファイル (~/.ssh/config) の例
Host myserver
    HostName 192.168.1.100
    User myuser
    Port 22
    IdentityFile ~/.ssh/my-private-key
    Compression yes
    ServerAliveInterval 60
    ServerAliveCountMax 3

# 設定ファイルを利用して呼び出す
rsync -avzh /local/directory/ myserver:/remote/directory/

⚠️ セキュリティ上の注意点

  • SSH 鍵は適切なパーミッション (600 または 400) で保護してください
  • 可能であれば SSH ポートはデフォルト (22) から変更しましょう
  • ファイアウォールのルールを適切に設定してください
  • SSH 鍵は定期的に更新しましょう

5. 高度な機能と Tips 🚀

📋 除外 / 包含パターンの活用

# 複数のファイル形式を除外
rsync -avzh --exclude="*.tmp" --exclude="*.log" --exclude=".git/" /source/ /dest/

# 除外リストファイルの利用
echo "*.tmp" > exclude-list.txt
echo "*.log" >> exclude-list.txt
echo ".git/" >> exclude-list.txt
rsync -avzh --exclude-from=exclude-list.txt /source/ /dest/

# 複雑なパターンの例
rsync -avzh \
  --include="*.jpg" \
  --include="*.png" \
  --include="*/" \
  --exclude="*" \
  /photos/ /backup/photos/

🔄 バックアップ戦略: 増分バックアップ

# 日付別のバックアップディレクトリを作成
BACKUP_DIR="/backup/$(date +%Y-%m-%d)"
mkdir -p "$BACKUP_DIR"

# ハードリンクを用いた増分バックアップ
rsync -avzh --link-dest=/backup/latest /source/ "$BACKUP_DIR"/
ln -nsf "$BACKUP_DIR" /backup/latest

# バックアップスクリプトの例
#!/bin/bash
SOURCE="/home/user"
BACKUP_BASE="/backup"
DATE=$(date +%Y-%m-%d_%H-%M-%S)
BACKUP_DIR="$BACKUP_BASE/$DATE"
LATEST_LINK="$BACKUP_BASE/latest"

# バックアップ実行
rsync -avzh --delete --link-dest="$LATEST_LINK" "$SOURCE/" "$BACKUP_DIR/"

# 最新リンクの更新
ln -nsf "$BACKUP_DIR" "$LATEST_LINK"

📊 ログと監視

# 詳細なログファイルを生成
rsync -avzh --log-file=/var/log/rsync.log /source/ /dest/

# 統計情報付きで実行
rsync -avzh --stats /source/ /dest/

# 進捗をリアルタイムで監視
rsync -avzh --progress --stats /source/ /dest/ | tee rsync-log-$(date +%Y%m%d).txt

6. パフォーマンスチューニング ⚡

🔧 転送パフォーマンスのチューニング

# 帯域制限 (KB/s 単位)
rsync --bwlimit=1000 -avzh /source/ /dest/

# 圧縮レベルの調整 (1-9、デフォルトは 6)
rsync -avzh --compress-level=9 /source/ user@server:/dest/

# チェックサムアルゴリズムの選択
rsync -avzh --checksum-choice=md5 /source/ /dest/

# 複数プロセスによる並列転送
# (GNU parallel を使用)
find /source -maxdepth 1 -type d | parallel -j4 rsync -avzh {} /dest/

💾 大容量ファイルの扱い

# 部分転送を有効化 (中断時に再開可能)
rsync -avzh --partial /large-files/ /dest/

# インプレース更新 (ディスク容量を節約)
rsync -avzh --inplace /source/ /dest/

# スパースファイルの扱い
rsync -avzh --sparse /source/ /dest/

# 大容量ファイル向けの最適化された組み合わせ
rsync -avzh --partial --inplace --progress /large-files/ /dest/

💡 パフォーマンスチューニングの Tips

  • ネットワーク帯域: --bwlimit で他のサービスへの影響を最小化
  • 圧縮設定: CPU とネットワークの状況に合わせて調整
  • チェックサム方式: 小さいファイルは --checksum、大きいファイルはデフォルトで
  • SSH 圧縮: -e "ssh -C" で SSH レベルの圧縮も併用

7. トラブルシューティング 🔍

❌ よくある問題と対処法

🔐 権限関連の問題

# 権限エラーが発生した場合の対処法
# 1. 所有者情報を無視
rsync -avzh --no-owner --no-group /source/ /dest/

# 2. 権限情報を無視
rsync -rvzh --no-perms /source/ /dest/

# 3. 管理者権限で実行
sudo rsync -avzh /source/ /dest/

🌐 ネットワーク接続の問題

# タイムアウトの設定
rsync -avzh --timeout=30 /source/ user@server:/dest/

# リトライ関連の設定
rsync -avzh --timeout=30 --contimeout=10 /source/ user@server:/dest/

# 接続状態の確認
rsync -avzh --dry-run user@server:/source/ /dest/

💾 ディスク容量不足

# ディスク使用量の確認
df -h

# 部分転送で容量効率を改善
rsync -avzh --partial --inplace /source/ /dest/

# 一時ファイルの保存先を変更
rsync -avzh --temp-dir=/tmp/large-temp /source/ /dest/

🐛 デバッグとログ解析

# 詳細なデバッグ情報
rsync -avzh --debug=ALL /source/ /dest/

# 特定モジュールのデバッグ
rsync -avzh --debug=FILTER /source/ /dest/

# ログレベルの調整
rsync -avzh --verbose --verbose /source/ /dest/

# エラーのみ出力
rsync -avzh --quiet /source/ /dest/ 2>&1 | grep -i error

⚠️ 注意事項

  • --delete オプション: 誤って重要なファイルを削除する恐れあり
  • パス末尾のスラッシュ: /source/ と /source は結果が異なります
  • シンボリックリンク: -L オプションでリンク先の実体をコピーするか決定
  • ネットワークの安定性: 不安定な接続では --partial の使用を推奨

8. 実務シナリオ 🏢

🎯 シナリオ 1: ウェブサイトのデプロイ

#!/bin/bash
# ウェブサイトのデプロイスクリプト

# 設定
LOCAL_DIR="/var/www/html"
REMOTE_SERVER="web-server.example.com"
REMOTE_DIR="/var/www/html"
BACKUP_DIR="/backup/website-$(date +%Y%m%d-%H%M%S)"

# リモートサーバーのバックアップ
ssh user@$REMOTE_SERVER "mkdir -p /backup"
rsync -avzh user@$REMOTE_SERVER:$REMOTE_DIR/ $BACKUP_DIR/

# 新バージョンのデプロイ
rsync -avzh --delete \
  --exclude=".git/" \
  --exclude="*.log" \
  --exclude="config/local.php" \
  $LOCAL_DIR/ user@$REMOTE_SERVER:$REMOTE_DIR/

echo "デプロイ完了。バックアップ先: $BACKUP_DIR"

💾 シナリオ 2: データベースバックアップの同期

#!/bin/bash
# データベースバックアップ同期スクリプト

DB_NAME="myapp"
BACKUP_LOCAL="/backup/db"
BACKUP_REMOTE="backup-server:/backup/db"
DATE=$(date +%Y%m%d)

# データベースダンプの取得
mysqldump -u root -p$DB_PASSWORD $DB_NAME | gzip > $BACKUP_LOCAL/db-$DATE.sql.gz

# リモートバックアップサーバーへ同期
rsync -avzh --delete \
  --include="*.sql.gz" \
  --exclude="*" \
  $BACKUP_LOCAL/ $BACKUP_REMOTE/

# 30 日以上経過したバックアップファイルを削除
find $BACKUP_LOCAL -name "*.sql.gz" -mtime +30 -delete

📱 シナリオ 3: 開発環境の同期

#!/bin/bash
# 開発環境同期スクリプト

PROJECT_DIR="/home/developer/projects/myapp"
DEV_SERVER="dev.example.com"
STAGING_SERVER="staging.example.com"

# 開発サーバーからステージングへ同期
sync_to_staging() {
    rsync -avzh --delete \
      --exclude="node_modules/" \
      --exclude=".env.local" \
      --exclude="*.log" \
      --exclude=".git/" \
      developer@$DEV_SERVER:$PROJECT_DIR/ \
      developer@$STAGING_SERVER:$PROJECT_DIR/
}

# ローカルから開発サーバーへ同期
sync_to_dev() {
    rsync -avzh \
      --exclude="node_modules/" \
      --exclude=".env.local" \
      --exclude="*.log" \
      $PROJECT_DIR/ developer@$DEV_SERVER:$PROJECT_DIR/
}

case "$1" in
    "staging")
        sync_to_staging
        ;;
    "dev")
        sync_to_dev
        ;;
    *)
        echo "使い方: $0 {staging|dev}"
        exit 1
        ;;
esac

🔄 シナリオ 4: リアルタイム同期 (inotify 活用)

#!/bin/bash
# リアルタイムファイル同期スクリプト

SOURCE_DIR="/home/user/documents"
DEST_DIR="backup-server:/backup/documents"
LOCK_FILE="/tmp/rsync-monitor.lock"

# 既に実行中かを確認
if [ -f "$LOCK_FILE" ]; then
    echo "既に実行中です。"
    exit 1
fi

# ロックファイルを作成
touch "$LOCK_FILE"

# 終了時にロックファイルを削除
trap "rm -f $LOCK_FILE" EXIT

# リアルタイム監視と同期
inotifywait -m -r -e modify,create,delete,move "$SOURCE_DIR" |
while read path action file; do
    echo "変更を検知: $path$file ($action)"

    # 連続した変更をまとめるため少し待機
    sleep 2

    rsync -avzh --delete "$SOURCE_DIR/" "$DEST_DIR/"

    if [ $? -eq 0 ]; then
        echo "同期完了: $(date)"
    else
        echo "同期に失敗しました: $(date)"
    fi
done

📝 まとめとベストプラクティス

✅ Rsync 利用チェックリスト

  • 事前テスト: 必ず --dry-run で先に確認する
  • バックアップの用意: 重要データは事前にバックアップ
  • 権限の確認: ソースと送信先のパーミッション設定を点検
  • ネットワーク状況: 安定した接続環境で実行
  • ログ管理: 作業履歴を残し、後から分析できるようにする

🎯 シーン別の推奨オプション

  • 通常のバックアップ: rsync -avzh --progress
  • 完全ミラーリング: rsync -avzh --delete
  • リモート転送: rsync -avzh -e ssh
  • 大容量ファイル: rsync -avzh --partial --inplace
  • 低速ネットワーク: rsync -avzh --compress-level=9 --bwlimit=500

🚨 はまりやすい落とし穴

  • パス末尾のスラッシュ: /dir/ と /dir は結果が異なる
  • --delete オプション: 慎重に使用、重要ファイルの削除リスクあり
  • シンボリックリンク: -l、-L、-k オプションの違いを理解する
  • 権限の問題: sudo 使用時は所有者の変更に注意
  • 文字コード: 異なるシステム間ではファイル名関連の問題が発生しうる

Rsync はシンプルに見えて、非常にパワフルで柔軟なツールです。本ガイドで紹介した例をもとに、実際の環境でテストし、自分の要件に合わせてオプションを組み合わせて活用してください。効率的なファイル同期とバックアップにより、システム運用の生産性を大きく高められるはずです。
