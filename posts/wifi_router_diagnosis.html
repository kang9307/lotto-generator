출발점 — 증상을 세 갈래로 나누고 경계를 찾는다

공유기 문제는 연결이 안 되는 것, 느린 것, 끊기는 것 가운데 하나로 나타나고 증상마다 먼저 볼 곳이 다르다. 그러나 세 문서가 공통으로 시작하는 질문은 같다. 이상이 한 기기에만 있는지, 모든 기기에 있는지를 가르는 것이다. 이 경계가 정해지면 점검 대상이 단말, 공유기, 모뎀과 회선 중 어느 쪽인지가 좁혀진다.

ASUS 문서는 무선 기기가 인터넷에 접속하지 못할 때 공유기 웹 화면의 네트워크 맵에서 인터넷이 연결 끊김으로 표시되는지 보고, 유선 기기도 접속하지 못하는지 확인하라고 한다. 둘 중 하나라면 인터넷 접속 실패를 다루는 별도 문서로 넘어간다. 통신사 모뎀에 Wi-Fi 기능이 있다면 그 Wi-Fi 로 접속해 보라는 안내도 있다. 모뎀 Wi-Fi 로 접속되면 공유기의 인터넷 상태를 보고, 모뎀 Wi-Fi 로도 안 되면 통신사에 문의하라고 한다.

Microsoft 문서는 두 가지 대조 방법을 든다. 하나는 같은 네트워크에 다른 노트북이나 휴대폰을 연결해 보는 것으로, 연결되면 문제의 원인은 처음 쓰던 기기 쪽일 가능성이 높다고 한다. 다른 하나는 ipconfig 로 기본 게이트웨이 주소를 찾아 ping 을 보내는 것이다. 응답이 오면 공유기까지의 연결은 있으므로 모뎀이나 통신사 문제일 수 있고, 응답이 없으면 이더넷 케이블로 PC 를 모뎀에 직접 연결해 접속되는지 본다. 직결에서 접속되면 문제는 Wi-Fi 공유기에 있다고 문서는 설명한다.

  • 다른 기기 대조: 같은 Wi-Fi 에 다른 노트북이나 휴대폰을 연결해 같은 증상이 나는지 본다(Microsoft).
  • 유선 기기 동시 확인: 유선 기기도 인터넷이 안 되면 무선 문제가 아니라 인터넷 접속 문제로 본다(ASUS).
  • 기본 게이트웨이 ping: 응답이 있으면 공유기까지는 연결되어 있다(Microsoft).
  • 모뎀 직결 또는 모뎀 Wi-Fi 시험: 모뎀에서 접속되는지로 공유기와 회선을 가른다(Microsoft·ASUS).

느린 증상만 따로 다섯 단계로 좁히는 방법은 인터넷 속도 측정 가이드에서 다룬다. 이 글은 연결 불가·속도 저하·끊김이라는 증상별 순서와, 제조사 문서끼리 서로 다르게 말하는 지점에 집중한다.

전원 주기 — 두 공식 문서의 순서와 대기 시간이 다르다

공유기와 모뎀을 껐다 켜는 절차는 흔히 하나의 표준처럼 소개되지만, 직접 확인한 두 문서는 켜는 순서와 대기 시간이 서로 다르다. Microsoft 지원 문서(4단계)는 모뎀을 먼저 연결하고, TP-Link FAQ(5단계)는 라우터를 먼저 켠다. ASUS FAQ 1030641 은 전원 주기 절차를 다루지 않는다. 아래 표는 각 문서의 서술을 그대로 옮긴 것이다.

두 문서가 반대 순서를 안내하는 이유는 어느 쪽에도 설명되어 있지 않다. 이 글도 그 이유를 확인하지 못했다. 사용하는 공유기가 TP-Link 라면 그 제조사 문서의 순서를, 제조사 문서가 따로 없다면 Windows 쪽 안내인 Microsoft 문서의 순서를 따르는 것이 출처를 지키는 방법이다. 어느 한쪽 순서가 다른 쪽보다 낫다는 근거는 두 문서에서 확인되지 않는다.

Microsoft 문서는 몇 가지 조건도 덧붙인다. 케이블 모뎀과 Wi-Fi 공유기가 한 몸으로 된 장비라면 그 장비 하나만 같은 절차로 재시작하면 된다. 재시작하면 같은 Wi-Fi 에 연결된 모든 기기가 잠시 끊기며, 이 작업의 목적은 통신사와 새 연결을 만드는 것이라고 설명한다. 장비의 상태는 두 장비의 표시등을 보고 가늠한다고 한다.

  • 콤보 장비: 모뎀과 공유기가 한 대로 합쳐진 장비는 그 하나만 재시작한다(Microsoft).
  • 백업 배터리: 전원을 뽑아도 모뎀 표시등이 꺼지지 않으면 배터리를 빼고, 대기 후 다시 넣는다(Microsoft).
  • 기기 전체 단절: 재시작하는 동안 같은 Wi-Fi 의 모든 기기가 일시적으로 끊긴다(Microsoft).
  • 결과 확인 시점: TP-Link 는 마지막 장비를 켠 뒤 1~2분을 더 기다리고 나서 인터넷 접속을 확인하라고 한다.

증상 1 — Wi-Fi 는 연결되는데 인터넷이 안 될 때

Windows 에서 Wi-Fi 이름 아래에 인터넷 없음이 표시되는 상태를 Microsoft 문서는 제한된 연결(limited connectivity)이라 부른다. PC 는 로컬 네트워크에 연결되어 있어 같은 네트워크의 다른 기기는 보일 수 있지만, 웹 서핑·이메일·스트리밍처럼 인터넷이 필요한 일은 되지 않는다. 이 표시는 Windows 가 인터넷의 서버에 작은 HTTP 요청을 보내 응답이 돌아오는지로 판단하며, 응답이 없으면 나타난다고 한다.

문서가 제시하는 확인 순서는 비교적 단순하다. 먼저 Wi-Fi 를 껐다 켜서 다시 연결한다. 다음으로 관리자 권한 명령 프롬프트에서 ipconfig /release 와 ipconfig /renew 로 IP 설정을 갱신하고, ipconfig /flushdns 로 DNS 캐시를 비운다. 이어 설정의 프록시 화면에서 수동 프록시가 켜져 있으면 끈다. 이 단계에서 문제가 풀리면 연결 아이콘이 몇 초 안에 바뀐다고 한다.

그래도 안 되면 IP 주소와 DNS 서버를 직접 본다. 문서는 IP 주소가 169.254.x.x 형태라면 Windows 가 공유기에서 주소를 받지 못했다는 뜻이라고 설명하고, 고정 IP 를 쓰지 않는 환경이라면 공유기에서 DHCP 가 켜져 있는지 공유기 문서로 확인하라고 한다. DNS 는 ipconfig /all | findstr /c:"DNS Servers" 로 주소를 찾아 ping 을 보낸다. 유효한 IP 가 있는데 DNS 서버에 ping 이 가지 않으면 다른 공개 DNS 주소로 바꿔 다시 시험하라고 한다.

  • Wi-Fi 재연결: Wi-Fi 를 껐다 켜고 무선 네트워크에 다시 연결한다.
  • IP 갱신: ipconfig /release 다음 ipconfig /renew 를 실행한다.
  • DNS 캐시 비우기: ipconfig /flushdns 를 실행한다.
  • 프록시 확인: 설정의 네트워크 및 인터넷, 프록시에서 수동 프록시를 끈다.
  • 169.254.x.x 주소: 공유기에서 IP 를 받지 못한 상태이므로 DHCP 설정을 확인한다.

WAN IP 확인 — TP-Link 문서의 분기

TP-Link FAQ 는 공유기가 이미 설정된 상태에서 인터넷이 안 될 때, 관리 페이지에 로그인해 Advanced > Status 에서 Internet IP 주소를 먼저 보라고 한다. 이 값이 문제가 공유기 쪽인지 모뎀 쪽인지를 알려 주는 출발점이라는 것이다. 문서에 따르면 대부분의 TP-Link 공유기는 기본 LAN IP 로 192.168.0.1 또는 192.168.1.1 을 쓴다.

0.0.0.0 은 문서의 표현대로 공유기가 모뎀으로부터 유효한 주소를 받지 못했다는 뜻이다. 이를 곧바로 회선 장애로 읽을 근거는 문서에 없다. 문서가 먼저 점검하라고 하는 것은 케이블 연결, 모뎀 직결 시험, MAC 주소 복제, LAN IP 충돌, 접속 유형이며, 문서의 요약도 이 경우 모뎀 연결이나 물리적 구성에 문제가 있을 가능성이 높다고만 말한다. 아래 표에 문서의 분기와 조치 순서를 옮긴다.

Internet IP 상태문서의 설명문서가 안내하는 조치 순서

0.0.0.0 분기의 세부 절차에는 문서 고유의 조건이 있다. MAC 주소 복제는 일부 통신사가 인터넷 접속을 특정 기기의 MAC 주소에 묶어 두기 때문에 쓰는 방법이며, 유선 이더넷으로 연결한 PC 에서 Advanced > Network > Internet 의 MAC Clone 항목에서 Use Current Computer MAC Address 를 선택해 저장한다. LAN IP 변경은 모뎀이나 DSL 모뎀 겸 공유기가 같은 대역을 쓰면 두 장비가 충돌한다는 설명에서 나오며, Advanced > Network > LAN 에서 192.168.2.1 같은 주소로 바꾼다.

유효한 IP 가 있는 분기에서는 Advanced > Network > DHCP Server 에서 기본 DNS 를 8.8.8.8, 보조 DNS 를 8.8.4.4 로 입력하는 방법이 안내된다. 문서는 8.8.8.8 을 Google 이 운영하는 공개 DNS 서버라고 설명한다. 접속 유형은 통신사에 확인해야 하며, 문서는 Dynamic IP, PPPoE, Static IP 를 예로 들고 잘못 설정되면 접속되지 않는다고 적는다.

  • 0.0.0.0 의 의미: 공유기가 모뎀에서 유효한 주소를 받지 못한 상태이며, 원인은 문서가 든 여섯 가지를 차례로 가려야 한다.
  • MAC 복제 조건: 반드시 유선 연결로 진행하라는 주의가 문서에 있다.
  • LAN IP 충돌: 모뎀 쪽 장비가 같은 대역일 때 공유기 LAN IP 를 다른 대역으로 바꾼다.
  • DNS 수동 설정: 유효한 IP 가 있는데 접속이 안 될 때 문서가 가장 먼저 안내하는 조치다.

증상 2 — 속도가 느릴 때 거리·대역·채널 폭

Windows 문서는 인터넷에 연결되어 있지만 속도가 매우 느릴 때 세 가지를 든다. 기기가 공유기와 가깝고 장애물이 없는지 신호 강도를 확인하고, 작업 관리자에서 네트워크 대역폭을 많이 쓰는 백그라운드 프로세스를 종료하고, 다른 기기를 같은 Wi-Fi 에 연결해 보는 것이다. 다른 기기에서도 느리면 공유기에 정비나 교체가 필요할 수 있다고 한다. 같은 문서의 일반 절차에는 2.4GHz 와 5GHz 가 별도 네트워크로 보이는 공유기라면 다른 대역에 연결해 보라는 항목도 있다.

ASUS 문서는 대역별 특성을 이렇게 설명한다. 2.4GHz 는 신호가 더 멀리 가지만 5GHz 보다 느리고, 5GHz 는 도달 거리가 짧지만 속도가 더 빠를 수 있다. 연결이 불안정하면 기기가 2.4GHz 와 5GHz 중 어느 쪽에 붙어 있는지, 끊길 때 공유기와의 거리가 얼마인지부터 확인하라고 한다. 공유기는 기기와 가까운 곳, 가능하면 환경의 중앙이고 가구와 벽이 적은 개방된 곳에 두라고 권한다.

채널 폭과 채널은 공유기 웹 화면의 Wireless > General 에서 대역별로 설정한다. 채널 폭은 무선 속도와 신호 안정성에 영향을 주며, ASUS 공유기는 기본적으로 채널 폭을 자동 조정한다. 문서가 적은 기본 채널 폭은 2.4GHz 가 20/40MHz, 5GHz 가 20/40/80MHz, 6GHz 가 20/40/80/160/320MHz 다. 제어 채널의 기본값은 자동이며, 주변 무선 기기와 같은 채널을 쓰면 간섭과 속도 저하가 생길 수 있어 간섭이 적은 채널로 바꿀 수 있다고 한다. 5GHz 에서는 Auto select channel including DFS channels 를 해제한 뒤 다른 채널을 선택하는 방법이 안내된다.

  • 신호 강도: 기기를 공유기에 가깝게 하고 장애물을 치운다(Microsoft).
  • 백그라운드 앱: 작업 관리자(Ctrl+Shift+Esc)에서 대역폭을 많이 쓰는 프로세스를 종료한다(Microsoft).
  • 대역 전환: 2.4GHz 와 5GHz 가 따로 보이면 다른 쪽에 연결해 본다(Microsoft).
  • 채널 폭 기본값: 2.4GHz 20/40MHz, 5GHz 20/40/80MHz 로 자동 조정되며 변경은 웹 화면에서만 가능하다(ASUS).
  • 제어 채널 변경: 기본 자동에서 간섭이 적은 채널로 바꾸되 지원 채널은 국가별 법규에 따라 다르다(ASUS).

증상 3 — 끊길 때 ASUS 문서의 점검 순서

ASUS FAQ 1030641 은 무선 기기가 자주 끊길 때의 점검을 아홉 단계로 나열한다. 앞의 여섯 단계는 공유기 쪽, 일곱째는 환경, 여덟째는 단말, 아홉째는 초기화다. 문서는 일부 무선 기능이 펌웨어 버전에 따라 다르며, 설정 화면이 펌웨어 3.0.0.6.102_35404 이상과 그 미만으로 나뉜다고 밝힌다. 채널 폭과 제어 채널은 앱이 아니라 웹 화면에서만 바꿀 수 있다.

  • 1. 펌웨어 최신화: 웹 화면의 Network Map 에서 펌웨어 버전을 눌러 확인하거나, ASUS Router 앱의 Settings > Firmware Upgrade > Check Firmware Version 에서 확인한다.
  • 2. 채널 폭을 기본값으로 되돌린다: 기본값은 자동 조정이며 속도와 안정성에 영향을 준다.
  • 3. 간섭이 적은 제어 채널로 바꾼다: 기본은 Auto 이고 Wireless > General 에서 대역별로 설정한다.
  • 4. Smart Connect 를 끈다: 대역별로 Wi-Fi 이름과 암호를 따로 설정할 수 있게 된다.
  • 5. 안테나 각도를 조정한다: 45도, 90도 같은 각도를 시험하며, 모델별 권장 배치는 사용 설명서를 본다.
  • 6. 공유기를 기기 가까이 옮긴다: 신호 전달 거리가 세기에 영향을 주지 않게 한다.
  • 7. 환경 간섭을 줄인다: 간섭원으로 전자레인지·냉장고·무선 전화기·전원 박스, 장애물로 철제 캐비닛·철문·시멘트 벽·밀폐된 수납장·바닥·소파 뒤를 든다.
  • 8. 단말의 드라이버나 펌웨어를 갱신한다: 노트북·스마트폰·USB Wi-Fi 어댑터·콘솔이 대상이며 제조사에 문의한다.

아홉째 단계인 초기화는 8절에서 다룬다. 같은 단계에서 문서가 짚는 환경 요소로는 석고·널빤지·철조망처럼 밀도가 높은 건축 자재도 있다. 이런 자재가 Wi-Fi 신호 투과에 영향을 줄 수 있다는 서술까지만 있고 감쇠 정도를 수치로 제시하지는 않는다.

Windows 쪽에도 끊김과 관련된 설정이 문서에 있다. Microsoft 문서는 Wi-Fi 가 자주 끊길 때 제어판의 전원 옵션에서 사용 중인 전원 관리 옵션을 고르고 고급 전원 설정의 Wireless Adapter Settings 아래 Power Saving Mode 를 Maximum Performance 로 바꾸라고 한다. 장치 관리자에서 Wi-Fi 어댑터 속성의 전원 관리 탭에 있는 전원을 절약하기 위해 컴퓨터가 이 장치를 끌 수 있음 항목의 선택을 해제하는 방법도 별도 단계로 있다. 공유기 채널을 바꿔 간섭을 줄이라는 안내도 같은 항목에 있다.

단말 쪽 점검 — Windows 문서의 순서

공유기가 정상으로 보이면 단말을 본다. Microsoft 문서의 일반 절차는 열세 단계이며 간단한 것부터 위험이 큰 것 순으로 배열되어 있다. 문서는 Windows 11 에서는 먼저 도움말 보기 앱의 네트워크 및 인터넷 문제 해결사를 실행하라고 하고, Windows 10 에서는 설정의 네트워크 및 인터넷, 상태에서 네트워크 문제 해결사를 실행하라고 한다.

앞쪽 단계는 상태 확인이다. 작업 표시줄의 네트워크 아이콘에서 Wi-Fi 가 켜져 있고 연결됨으로 표시되는지, 비행기 모드가 꺼져 있는지 본다. 다음으로 설정의 네트워크 및 인터넷, Wi-Fi, 알려진 네트워크 관리에서 해당 네트워크를 삭제(Forget)한 뒤 암호를 다시 입력해 연결한다. 어댑터가 네트워크가 쓰는 주파수를 지원하지 않는 경우도 문서에 있다. 예를 들어 어댑터가 2.4GHz 만 지원하는데 네트워크가 5GHz 를 쓰면 네트워크가 보이지 않는다. 드물게 드라이버가 해당 주파수를 걸러내는 경우에는 장치 관리자의 어댑터 속성 고급 탭에서 Wireless Mode 나 Band 설정이 네트워크 주파수를 허용하는지 본다.

뒤쪽 단계는 변경 폭이 크다. 관리자 명령 프롬프트에서 netsh winsock reset, netsh int ip reset, ipconfig /release, ipconfig /renew, ipconfig /flushdns 를 이 순서대로 실행한다. 그다음 드라이버를 제거하고 재시작하는 방법이 있으며, 이때는 PC 제조사 사이트에서 받은 드라이버를 백업으로 준비해 두라고 문서가 당부한다. 문서는 이 방법이 최근 업데이트 뒤 연결이 멈춘 경우에 고려할 만하다고 한다.

  • Wi-Fi 상태: Wi-Fi 가 켜져 있고 이름 아래에 연결됨이 표시되는지 본다.
  • 비행기 모드: 설정의 네트워크 및 인터넷에서 꺼져 있는지 본다.
  • 알려진 네트워크 삭제: Manage known networks 에서 Forget 후 다시 연결한다.
  • 명령 순서: winsock reset, int ip reset, release, renew, flushdns 순으로 실행한다.
  • 드라이버 제거: Attempt to remove the driver for this device 에 체크하고 제거한 뒤 재시작한다.
  • 전원 절약 해제: 장치 관리자의 전원 관리 탭에서 장치를 끌 수 있음 항목을 해제한다.

복구 — 초기화와 네트워크 초기화는 마지막

세 문서는 모두 초기화를 마지막에 둔다. ASUS 문서는 RESET 버튼을 약 5~10초 누르고, 전원 LED 가 깜박이기 시작하면 버튼을 놓으라고 한다. 이때 모든 LED 가 꺼지는 것은 공유기가 스스로 재부팅하는 중이라 정상이며, 전원 LED 와 Wi-Fi LED 가 다시 켜질 때까지 기다린 뒤 관리 화면에 접속한다. 모델마다 버튼 위치가 조금 다르므로 사용 설명서를 확인하라는 안내가 붙어 있다. 초기화하면 모든 설정이 지워지며, 빠른 인터넷 설정(QIS)을 웹 화면이나 앱으로 다시 진행한다.

표준 초기화로 해결되지 않으면 ASUS 문서는 하드 팩토리 리셋을 별도 문서에서 안내하고 해당 모델 목록을 따로 둔다. TP-Link 문서에서도 초기화는 DNS 설정과 재시작 뒤의 마지막 항목이며, 초기화한 뒤에는 공유기를 처음부터 다시 설정한다. Windows 의 네트워크 초기화는 이에 해당하는 단말 쪽 마지막 수단이다. Windows 11 은 설정의 네트워크 및 인터넷, 고급 네트워크 설정, 네트워크 초기화에서, Windows 10 은 상태, 네트워크 초기화에서 실행한다.

네트워크 초기화에는 부작용이 있다. 설치된 네트워크 어댑터와 그 설정이 제거되었다가 재시작 후 기본값으로 다시 설치되므로, VPN 클라이언트나 Hyper-V 가상 스위치 같은 소프트웨어는 다시 설정해야 할 수 있다. 알려진 네트워크가 모두 공용 네트워크 프로필로 바뀔 수도 있는데, 공용 프로필에서는 PC 가 다른 장치에 검색되지 않는다. 문서는 Windows 10 에서 11 로 올린 뒤의 연결 문제나 공유 드라이브에 접속하지 못하는 문제에도 이 방법이 도움이 될 수 있다고 한다.

  • ASUS 초기화: RESET 약 5~10초, 전원 LED 깜박임 시작 시 놓고, 전원·Wi-Fi LED 가 다시 켜질 때까지 기다린다.
  • 초기화 뒤: 설정이 전부 지워지므로 QIS 로 인터넷과 Wi-Fi 를 다시 설정한다.
  • Windows 네트워크 초기화: 위 단계로 안 될 때 마지막에 쓰며 어댑터와 설정이 기본값으로 돌아간다.
  • 인증 문제: 암호가 맞는데 거부될 때 Microsoft 문서는 공유기 재부팅 또는 초기화와 펌웨어 업데이트를 든다.

확인하지 못한 것

  • KT 등 통신사 고객센터의 재부팅 순서 안내는 열리지 않아 확인하지 못했다. 이 글은 통신사 권고를 근거로 삼지 않는다.
  • Microsoft 와 TP-Link 문서가 켜는 순서를 달리 안내하는 이유는 두 문서 어디에도 서술되어 있지 않다.
  • 2.4GHz 겹치지 않는 채널 번호, 채널 간격, 5GHz DFS 채널의 한국 규정은 열린 공식 출처에서 확인하지 못했다. ASUS 문서는 지원 채널이 국가별 법규에 따라 다르다고만 적는다.
  • 벽 한 겹당 신호 감쇠나 실효 속도 상한 같은 수치는 세 문서에 없다.
  • ASUS FAQ 1030641 은 ASUS 공유기의 기본 관리자 주소를 적지 않았고, ipTIME 같은 국내 제조사 문서는 이 글의 출처에 없다.
  • 펌웨어 자동 갱신 시각과 끊김의 관계는 세 문서에 서술이 없다.
