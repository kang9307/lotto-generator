被移除安全层的模型改版,使用者要承担什么

消失的不只是拒绝 - 已被测量到的代价,以及本地运行并不能免除的责任

2026年8月20日 IT/技术

引言:熟悉的模型名后面挂着陌生的后缀时

只要花点时间挑选本地运行的模型,迟早会遇到一组文件,名字是你认得的,后面却挂着 uncensored 或 abliterated 这样的后缀。说明通常只有一行:去掉了拒绝。下载量和评价往往不输原版。

这篇文章要谈的是那一行字究竟改动了什么,以及拿到这个文件并开始使用的人还会一并接收什么。要追的线索有六条:安全层在模型内部到底是什么、这类改版为什么会被做出来、拿掉之后还有什么一起消失、本地运行真正免除的是哪些东西、组织使用时会卡在哪里,以及当拒绝真的挡住工作时还有什么别的解法。

先说清楚一点:本文没有制作方法。没有步骤、没有工具名称、没有参数。这里讨论的不是「怎么做」,而是「它是什么、会发生什么」。

起因是2026年8月,一个基于 Qwen3.8-27B、面向苹果芯片打包的改版在开发者社区被介绍。不过本文的目的不是点评某个具体发布物。同样形态的文件已有数百种在流通,需要判断的问题全都是共通的。

1. 安全层不是事后过滤器

很多人把模型的安全机制想象成挂在出口的过滤器。实际上是两个性质完全不同的层叠在一起。

  • 外层 — 包裹在托管服务前后的输入分类器、输出检查器、策略引擎、请求日志与速率限制。运营方可以随时开关,与模型文件本身无关。
  • 内层 — 预训练结束后,经由监督微调与偏好学习写进权重本身的行为。它随文件一起走,没有任何配置开关能关掉它。

当你下载开源权重文件并在自己的硬件上运行时,外层根本不存在。厂商的分类器、留存的日志、异常使用检测,一样都不会跟过来。剩下的只有内层,而所谓改版动的正是内层。

由此引出一个值得记住的性质:内层并不是一个独立模块。我们称之为「拒绝危险请求」的行为,与「不知道就说不知道」「没把握时不下断言」「用条件代替结论」这些习惯,是在同一个训练过程里一起塑形的。这种纠缠正是后面几节所有副作用的根源。

2. 改版究竟是什么

把公开研究里的描述归纳起来:这类改版的做法是在模型内部表示空间中锁定一个与拒绝相关的方向,并把它从权重里移除。这不是重新训练,所以成本很低,也因此传播极广。原理讲到这里为止,具体步骤与实现不在本文范围内。

这套做法要成立,必须有一个前提:拒绝是一个可以与其他能力分离的独立轴。「像手术刀一样把那条轴切掉,其余原封不动」的期待,完全建立在这个前提上。

2026年一系列测量反复表明的是,这个前提只对了一部分。有些指标确实几乎没动,有些指标却在互不相关的模型家族里朝同一个方向被推。下面两节就是这些证据。

3. 为什么会被做出来 - 两种动机

3.1 正当的一侧

把这类发布一律归入恶意,会把现象读错。学术界与安全实务里确实存在需要它的位置。

  • 可解释性研究 — 想知道拒绝行为在模型的什么位置、与其他回路纠缠到什么程度,只能把移除后的版本与原版并排比较。
  • 红队与稳健性评估 — 要衡量一项防御的效果,就需要一条没有防御的基线。没有基线,任何「已经挡住了」的主张都无法证成。
  • 把能力和意愿分开 — 从外部无法分辨模型是不肯做还是做不到。2026年6月公开的一项代码生成模型研究,把这个区分当作评测方法论本身的问题来正面处理。在剥离拒绝的条件下重新测量会发现,相当一部分原以为被安全策略挡住的任务,本来就在能力之外。
  • 过度拒绝真正阻断工作的领域 — 医学文献检索、刑事法律资料分析、安全事件处置文档撰写,以及创作中对暴力与犯罪的描写,都是典型例子。2026年7月公开的一项多语种刑事法律研究报告称,经过对齐流程的模型连合法的法律文书分析请求也显著更常拒绝。

3.2 不正当的一侧

另一侧动机的存在无需解释,也没有理由在这里罗列例子。真正值得指出的是另一个地方。

同一个文件同时满足两种动机。发布者无法选择自己文件的用途,而文件的复制与发布者的意图无关。所以这类发布物通常都会附上「仅限研究用途」的字样,而关键在于那句话是请求,不是许可证条款。再分发链条往下走一层,警告文字通常就不会跟着走了。

4. 拿掉之后消失的不只是拒绝

2026年7月公开的一项研究正面检验了这个前提。它取两个不同的 MoE 模型家族,把原版与改版并排放在同样的证据上,在18周内收集了21,600条判断进行比较。标题本身就带着结论:它不是手术刀。

观测到的变化模型家族A模型家族B两个家族方向一致吗
向乐观一侧倾斜+12.2pp+7.4pp一致
表达不确定性的词汇−0.95分−2.17分一致(减少)
自我辩护语句长度+4.0词+7.4词一致(增加)
让步性表述+1.39分+1.00分一致(增加)
自陈置信度分数−0.008+0.109相反

读表的方法在最后一列。方向一致的项目跨家族复现,可以视为技法本身的性质;方向分裂的项目则说明它因模型而异。这个区分之所以重要,是因为前四项讲的全都是判断的性格,而不是行文的语气。

归纳起来:面对同样的证据,改版得出的结论更乐观、迟疑用词更少、为自己的结论辩护得更长。而研究同时报告的是,这些判断并没有变得更准。消失的不只是拒绝,还有迟疑;而迟疑在成为安全装置之前,首先是表达不确定性的机能。

5. 代价有多大 - 基准测试确认的区间

2026年1月公开的一项比较研究,把四种不同实现应用到7B至14B区间的16个模型上,测量了能力保留情况。结果按领域出现了明显分化。

指标测的是什么平均变动幅度(四种实现)解读
MMLU宽口径学术知识−0.12 ~ −0.78pp基本不受影响
HellaSwag常识性续写−0.08 ~ −0.56pp基本不受影响
GSM8K多步数学推理−0.13 ~ −7.81pp随实现大幅摆动
TruthfulQA是否被常见误解带偏另一项测量为 −5 ~ −7pp一致下降

GSM8K 的平均值看着温和,但单个模型的离散度并不小。同一项研究报告的区间是从 +1.51pp 到 −18.81pp。也就是说,在某些模型上几乎无害,在另一些模型上多步算术整个塌掉。这正是作者把数学推理概括为最敏感领域的原因。

而在实务中更疼的损失是最后一行。2026年6月公开的一项测量针对一个27B级模型报告称,MMLU 只降了0.66pp,而 TruthfulQA 的 MC1 从40.27%降到34.52%,MC2 从58.36%降到51.34%。

让这个案例可信的,是同一位作者随即做的追加验证。他提出的假设是「损失来自广为流传的粗糙实现」,于是用更讲究的方式重做了一版再测。结果与假设相反:拒绝率从原版的90%降到零,但 TruthfulQA 落在 MC1 35.25%、MC2 52.20%,几乎没有恢复。作者估计约88%的代价来自技法本身,而非实现质量。

这个组合为什么糟糕。拒绝消失、真实性下降,连迟疑用语也一并变少。净效果是模型朝着更少拒绝、更少迟疑、更自信地出错的方向移动。对于打算不加验证直接采用的输出而言,这是最危险的组合。

至于为什么偏偏是真实性被削,现有的说法是拒绝方向在表示空间里与「不把不实之事当作事实陈述」的抑制发生重叠。不过这是对观测的一种解释,并非已经确立的因果结论。

6. 本地运行给你什么,不给你什么

这类改版几乎无一例外都以本地运行为前提发布。本地的好处是真实存在的,但给什么与不给什么常常被混在一起理解。

  • 给 — 提示词与文档不会发往外部服务器。处理合同禁止外传的材料时,这个差别是决定性的。
  • 给 — 无网络也能运行,没有按 token 计费,也不受厂商改政策或下线模型的影响。
  • 不给 - 匿名性 — 本地的意思不是「没有记录」,而是「记录在我的机器上」。对话历史、缓存、剪贴板、自动备份与同步文件夹都会留存。
  • 不给 - 验证 — 商用 API 背后至少还有厂商的评测流水线与回归测试。再分发的改版一样都没有,有的只是使用者自己搭的那点东西。
  • 不给 - 隔离 — 模型跑在本地,与你把输出粘贴到哪里是两个问题。成果一旦进入内部文档或客户交付物,边界就失去意义了。
  • 不给 - 免责 — 见下一节。

本地运行本身的硬件与量化取舍,在本地运行LLM指南里另行讨论过。本文只看叠在其上的安全与责任这条轴。

7. 法律责任不会转移

这是最常出偏差的地方。模型不再拒绝这件事,与输出流出去之后由谁负责这件事,完全没有关系。

  • 生成内容的责任属于发布它的人,而不属于工具。诽谤、著作权侵权、个人信息侵害与妨害业务的成立,与用什么工具生成无关。
  • 模型卡里的免责声明对第三方没有效力。它只约束上传者与使用者之间的关系,对受到损害的一方起不到屏障作用。
  • 标注「研究用途」属于自我声明。留下记录的是你做了什么、用在哪里,标签不会改变行为的性质。
  • 监管不问推理跑在哪里。以韩国为例,2026年1月22日生效的人工智能基本法在第31条要求经营者事先告知用户服务基于生成式人工智能,并对生成结果标注人工智能生成的事实,违反者可处三千万韩元以下罚款,目前处于指导期。在本地做出来这一点,并不会消掉把它作为服务发出去时的义务。其他法域的告知与标识义务各不相同,应按当地规则核对。
本文为信息提供目的,不构成法律意见。具体案件的违法性判断与应对应咨询执业律师,法条内容应以相关法域的官方原文核对生效时间与修订情况。

8. 组织使用时会卡住的地方

个人在自己机器上做实验,与团队把它放到公司资产上,是完全不同的两件事。从组织角度看,使用对齐版时由厂商默默承担的每一项,都会挪到你这一侧。

项目对齐版 + 商用API再分发的改版组织需要新承担的
输出安全基线厂商评测、系统卡没有自建评测集并定期复测
审计留痕API 调用日志没有(本地)自行设计提示词与输出的保留范围和期限
来源溯源签名、发布说明再分发物,中间环节往往多层文件完整性校验与来源记录流程
许可证条款中明示主张自基础模型继承重新审视修改、再分发与商用条件
事故响应厂商支持渠道没有事先建立内部上报、阻断与回收路径
合规应对部分可由厂商文档覆盖没有告知与标识义务全部自行履行

在这之上还有一条合同轴。与客户签订的安全附属协议里常常列有已批准的模型与服务清单,而社区再分发版通常都在清单之外。使用清单之外的东西,不是技术问题,而是违约。

公司内部哪些数据可以进入哪种模型,这个判断标准在企业内部数据能否输入LLM里另行梳理过。已经在讨论改版模型的组织,按顺序应先确认那套规程是否已经立起来。

9. 当拒绝确实是问题时的别解

过度拒绝是真实存在的摩擦,对正在承受它的人说「忍着」并不是答案。但改版几乎没有理由成为第一选项。这里是有顺序的。

  • 先诊断 - 是拒绝还是能力不足。出现一句拒绝的话,并不等于全都是对齐造成的。前面提到的代码生成研究点名的正是这种混淆。把同一个请求换几个条件问两三遍,通常就能分开。
  • 在系统提示里写明角色与上下文。过度拒绝类基准反复展示的是表层词汇才是触发点。在使用结构化配对的安全与非安全提示的测试中,意图明显无害的请求仍会因为一个词被拒。
  • 换一种提问形态。不要求执行步骤,而是问判断依据、文献摘要、风险因素梳理或审查清单,通常就能通过,而且往往那才是你真正需要的答案。
  • 换模型。2026年公开的一项审计覆盖21个开源模型、约710万条提示与回复对,发现过度拒绝率的跨度从0.26%到40.70%。同等规模的模型差距就有这么大。
  • 「拒绝越少越危险」并不自动成立。在同一项审计中,过度拒绝率与有害顺从率的相关性实际上为零(r=−0.032)。这是两条不同的轴,两项都低的模型确实存在,该审计中表现最好的模型是过度拒绝0.80%、有害顺从0.16%。
  • 先找官方发布物。在医疗、法务、安全这类过度拒绝频发的领域,有时会有按放宽策略正式调校的派生版本。来源可追溯的永远优先。
  • 把流水线拆开。检索、摘要、判断与成文全压给一个模型,就看不出是哪一步被挡住。拆开之后拒绝生效的位置会被收窄,你可以只对那一步换别的办法处理。

开源权重与商用模型的能力差距收敛到什么程度,在开源权重LLM与闭源LLM的差距里讨论过。如果打算换模型,那条轴值得一并读。

10. 公开的模型卡自己写下的东西

引发本文的那个发布物的模型卡,正因为什么都没有隐瞒,反而是很好的教材。它自己写下的要点如下。

  • 安全对齐已被实质性移除,模型会响应有害与不道德的请求
  • 不存在有意义的内置防护
  • 使用带来的责任与法律责任完全由使用者承担,作者与上传者对滥用或损害不负任何责任
  • 推荐用途仅限于AI安全研究、可解释性研究、拒绝机制研究、红队测试与稳健性评估,并非面向普通用户或生产部署
  • 若要向用户提供或放入运行环境,必须自行补上安全层
  • 压缩精度最低的构建会出现重复循环与损坏输出,已明确标注不要用于实际工作

这一节的要点在于如何读这份清单。发布者认真地做了警告,而那些警告与本文前面梳理的风险完全是同一批内容。问题在于这些文字没有强制力。文件的复制与请求无关,再分发链条往下一层,卡片正文通常就不会跟着走。最后剩下的,只有接收方自己立起来的标准。

没有能够确认的部分

  • 引发本文的那个发布物自身的性能测量 — 本文所有基准数字都来自针对其他模型与其他发布物的公开测量,没有依据认为同样的数值可以直接套用到它身上。
  • 中文用户群体的流通与使用情况 — 未能找到以中文使用者为样本的统计。本文数值全部来自公开的国际研究。
  • 法条原文 — 韩国人工智能基本法的条文正文未能在其国家法令信息中心打开。条号、生效日与罚款上限依据法律从业者公开的解读,引用前需核对原文。
  • 真实性下降的因果 — 拒绝方向与事实抑制重叠的说法是对观测的解释,未能找到确立因果关系的研究。
  • 重新对齐的成本 — 未能找到量化「给改版重新补上安全层需要多少成本、能恢复多少」的资料。
  • 许可证解释 — 关于基础模型许可证允许此类修改与再分发到什么程度,未能找到权威见解。模型卡上标示的许可证是发布者一方关于继承的陈述。
  • 不同实现之间差异的可复现性 — 四种实现的比较研究明确说明,能力保留的测量只在16个模型中的一部分上进行,其平均值难以推广到全体。

结论:不是要堵住的东西,而是要当作前提的东西

开源权重已经铺开到这个程度,这类改版存在这件事本身是无法回退的。因此把它当作设计的前提比试图消灭它更现实。接受这个前提之后,有两件事会改变。

第一,把安全只放在模型内部的设计,在开源权重环境里是不成立的。文件一旦到了别人手上,权重内部的纪律就成了使用者可以改动的东西,而且已经被改动了。组织的防线会从模型权重移向应用边界、数据访问权限,以及记录与审批流程。同样的推理也催生了试图把控制点下沉到应用之下的内核级AI安全讨论。

第二,个人使用者需要丢掉一个误解:「更少拒绝」不等于「更有能力」。目前公开测量指向的方向恰恰相反。拒绝更少、迟疑更少,而真实性指标下降五到七个百分点。被拿掉的不是障碍物,而是那个用来标示不确定性的机能。

落到实务上是三条。第一,遇到拒绝时,先分清是拒绝还是能力不足,再去找改版。诊断错了,处方也会错。第二,对组织而言,批准清单与审计记录要排在模型选型之前。用什么是之后的问题。第三,如果仍然决定使用改版,那个决定的含义就是「在研究环境里使用」,而从研究环境出来的产物在通过验证之前哪里都不去。如果所处的位置守不住这最后一条,那个文件本来就不该在那里。
