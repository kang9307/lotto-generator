Bento - A Single-File Office App Experiment, One HTML File As The Whole Program

What a 570KB HTML file that packs editor, data, and collaboration into itself says about single-file applications and the promise and limits of local-first office software

Jul 24, 2026 IT/Tech

Intro: When A File Becomes The App

In July 2026, a project called Bento showed up on GeekNews. The pitch is simple: "an office suite that fits in a file." Digging in, here is what that actually means. Built by developer nyblnet, the project compresses a presentation document together with its editor, viewer, and data into a single .bento.html file weighing roughly 560-570KB. Download that file from bento.page, open it in any browser, and it becomes the editor; save it, and the same file rewrites itself with the new content. The Show HN post on Hacker News landed 977 points, and the GitHub repository crossed 1,000 stars within days of going public. It is MIT-licensed.

One caveat matters up front. As of July 2026, what has actually shipped is Slides (presentations) alone. Docs and Sheets are announced as future, separate .bento.html releases, but neither exists yet. So the name "office suite" is closer to a roadmap statement than a finished product today. Rather than repeat the hada.io discussion, this piece is my own read on what Bento actually demonstrates right now, and why the idea of a "single-file application" is catching attention again.

1. What Bento Actually Does - A File That Is Its Own Software

Stripped to the technical facts, here is how Bento works.

1.1 Data and code, both inside one file

Near the top of the file sits the slide content as a human-readable, plain-text JSON block. Below that, the app code that implements the editor, viewer, and presenter mode is base64-compressed and unpacked in place using the browser's DecompressionStream. Fonts, images, charts, and animation are all resolved inside this one file, with no external file requests needed at runtime. Under the hood it uses reveal.js for slide navigation, layered with a custom animation engine and a custom chart engine.

1.2 Saving means rewriting itself

Hitting save triggers the browser's File System Access API to overwrite the same file path with new content, falling back to a plain download where that API is unsupported. Updates are signed with ECDSA, and the previous file is said to remain intact as a rollback copy whenever a new version is written. Real-time collaboration is implemented as end-to-end encrypted CRDT using Cloudflare Durable Objects as a blind relay, so the server reportedly sees only encrypted data. The Show HN thread praised this design while also flagging input focus resets during simultaneous edits and choppy animation on some setups - signals of an early project still being sanded down.

2. The Idea Of A 'Single-File Application' Itself

What is genuinely interesting about Bento is less any single feature than its premise. We have grown used to separating "software" from "documents." Opening a Word file requires Word installed; viewing a Google Doc requires a Google account and internet. Software is the thing you install, and a document is a byproduct that software produces - a hierarchy that has felt natural for decades.

Bento inverts that hierarchy. The file itself is the editor, the viewer, and the data at once. This is not an entirely new idea - TiddlyWiki has long shipped an entire wiki as a single HTML file, and tools like draw.io have run similar experiments. What Bento adds is pushing that idea into an office document, including real-time encrypted collaboration. A line from the project's own pitch, "The file is the software," sums up the whole premise in five words.

3. Why It Is Appealing - Portability, Offline, Archiving, Air-Gaps, Privacy

3.1 Portability and offline use

A single file moves whole. It opens the same way from a USB stick, a chat attachment, or an offline backup drive. Bento supports an offline mode that, once enabled, is said to let nothing leave the device and hard-blocks updates and collaboration. Not assuming an internet connection is a fundamentally different starting point from cloud office tools.

3.2 What it means for air-gapped networks

Thinking about the corporate isolated networks and closed networks I have dealt with professionally, the idea of a "document-shaped app that needs no installer" is genuinely appealing in practice. The initial transfer into an air-gapped network still has to clear its own review process, of course, but once inside, being able to author and view documents with nothing but the file - no separate installer, no license server, no internet - eases the operational burden of running a closed network. That said, this is a direction, not a settled fact: the presence of executable code embedded in the file itself could just as easily become a point of scrutiny in an actual air-gap review.

3.3 Privacy - data the server never sees

Cloud office tools need the server to know a document's contents for convenience's sake. Bento's collaboration design is described as making the server (Cloudflare Durable Objects) a blind relay that only passes along encrypted data. No telemetry is mentioned either. Whether this design has passed a genuine, independent security audit is a separate question, but the stated intent is at least collaboration the server cannot read.

4. Building Local Apps With Web Tech - Single HTML+JS, WASM, Local-First

4.1 The browser as the runtime

Bento treats the browser itself as the runtime, with no app store and no install step. Hacker News regularly surfaces indie developers building along the same line - one recent post about building two dozen single-file HTML tools that run offline with no backend drew real attention. "Installless local web apps" has become its own small current.

4.2 A different branch: WASM

There are attempts to solve the same goal - office work that completes entirely in the browser, with data never leaving it - through different technology. One example is an open-source project released in early 2026 that compiles ONLYOFFICE's document engines to WebAssembly to handle Word, Excel, and PowerPoint formats directly inside the browser. Where Bento went light with its own format and its own renderer, the WASM-based approach carries the heavier burden of real compatibility with existing office formats, in exchange for actually handling real .docx/.xlsx/.pptx files. Same direction, different trade-off.

4.3 The local-first software movement

The concept that gives this current its theory is local-first software. A 2019 essay from the Ink & Switch research lab coined the term, and several of its core principles map onto Bento almost exactly: "the network is optional," "collaborators can see each other's changes," and above all, "The Long Now" - software should keep working even after the vendor or the service behind it disappears. Bento reads as an experiment applying those principles to the most everyday, longest-lived file type there is: the office document.

5. Where It Sits Against Existing Office Tools - Microsoft 365, Google Docs, LibreOffice

Placing Bento next to established office suites clarifies its position. An honest assessment has to hold both the strengths and the limits at once.

5.1 A gap in collaboration depth

Real-time collaboration in Microsoft 365 or Google Docs is infrastructure proven across hundreds of millions of users. Bento's encrypted CRDT collaboration points in an interesting direction, but it is still an early implementation reporting focus-reset bugs at the Show HN stage.

5.2 Feature depth and extensibility

Today's Bento focuses on one thing: presentations. Deep word-processor features like footnotes, indexing, and proofing tools, or spreadsheet depth like functions and pivot tables, sit outside this project's current scope. Even once Docs and Sheets arrive, catching up to decades of accumulated office feature surface will not happen quickly.

5.3 Limits of compatibility and file size

Bento is its own format. How smoothly it can convert to and from existing .pptx/.docx/.xlsx files is not established. And packing everything into one file carries an inherent trade-off: the file itself gets heavier as a document grows with more images and charts.

6. Scenarios Where It Is Actually Worth Using

6.1 Offline environments and secure isolated networks

Field work with no internet, unstable connectivity on ships or aircraft, or corporate isolated networks where cloud logins are outright forbidden - these are places a "presentation tool that ends with one file" can be a real option. As noted above, the transfer-in review process for a closed network still has to happen separately.

6.2 Ad-hoc work and education

Being able to open a presentation from a single link with no account setup and edit it on the spot is useful for one-off workshops, hackathon demos, and classrooms. On shared machines where students or participants have no permission to install software, a file-only approach lowers the barrier to entry.

6.3 Quick, ad-hoc collaboration

Being able to share a file link or attachment and have teammates open and comment immediately, with no shared cloud account required, fits short meetings and workshop materials well. As noted in section 3, though, the collaboration feature itself is still experimental, so it is safer to treat it as a supplement rather than a replacement for a company's established collaboration workflow.

7. A Document-Preservation Angle - A File That Still Opens In 20 Years

7.1 The problem of formats rotting

Struggling to open an old word-processor format, or a file locked to discontinued software, is a common experience. Cloud documents are more fragile still - if the service shuts down, the document itself can vanish entirely. "Will this file still open in 20 years?" is an old, unresolved question for office software.

7.2 Bento's answer - plain-text data and a signed, self-rewriting file

Bento's approach: keep the data as human-readable JSON inside the file, not binary, and do not depend on any one company's server or account. When a new version ships, it does not overwrite the old file but writes a new, signed file, preserving the previous version. All of this reads as an attempt to implement the local-first principle of "The Long Now" at the level of the document format itself.

7.3 What still has to be assumed - dependence on the browser as a platform

Even so, an assumption remains: for a Bento file to keep opening in the future, a browser that interprets HTML5 and JavaScript has to keep existing. Given how long web standards have historically preserved backward compatibility, that assumption sits on fairly solid ground - safer than depending on one company's cloud, certainly, but not an assumption-free bet either, and that has to be stated plainly.

8. Conclusion - An Experiment In Direction, Not A Finished Office Suite

Summarized honestly as of today: as of July 2026, what has actually shipped is one presentation tool, with documents and spreadsheets still at the "announced" stage. The collaboration feature carries an interesting design but still has early-stage bugs. It is not at a level where it replaces the big three office suites - Microsoft 365, Google Docs, LibreOffice - right now.

Even so, I think the reason this project drew 1,000-plus stars and 977 points in a short span is not its feature set but its idea. Software that completes with one file, no install, no account, no server; a file that works fully offline; a promise that all you will need in 20 years is a browser. That is a small counter-argument to a decade of office software drifting toward the cloud. If you are looking for a finished alternative today, sticking with existing tools is still the right call - but if you are interested in the direction of local-first software itself, Bento is an experiment worth watching right now.
