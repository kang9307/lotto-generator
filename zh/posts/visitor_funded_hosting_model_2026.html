访客买单的托管模式 - 成本转嫁的明与暗

免费的代价由谁来付

2026年6月12日 IT/技术

引言：开发者免费，那么钱由谁来付

"我们不向开发者收取托管费用。"这句听起来诱人的话，却立刻引出一个问题：那么服务器费用究竟由谁来付？ 近来在技术社区被热议的"访客买单的托管模式（visitor-funded hosting）"，正是对这个问题给出了挑衅式的回答。它把付费主体从开发者转移到访客身上——只不过访客不是直接刷卡，而是以自己浏览器所拥有的资源（算力、带宽，以及最终的电力）来支付。

本文从开发者与用户的视角，冷静地剖析这一构想。我们将拆解访客如何最终承担费用的技术机制、这一构想出现的背景，以及最重要的——2017 至 2019 年席卷网络的 Coinhive 这一惨痛前例，并平衡地审视：这究竟是正当的变现，还是把成本转嫁出去的精巧外包。先说结论：这一模式的命运，不取决于技术，而取决于透明与同意这两个词。

1. 新在何处——付费主体的转移

传统网页托管的成本结构很简单。站点主人（开发者）向托管商支付服务器、带宽与存储费用，访客只是消费内容。即便是免费托管，本质也相同：平台通过广告、付费升级或规模经济来吸收成本，账单并不会直接送到访客的设备上。

访客资助型模式则颠覆了这一格局。其核心是"把众多访客各自拥有的一点点闲置资源汇集起来，就能替代相当一部分中央服务器成本"。对一个人而言负担微乎其微，但分摊到数万、数十万访客身上就成为可观规模。问题在于，那"微乎其微"是否真的微乎其微，以及访客是否知情并同意。

免费总有代价。伦理的分水岭在于：这代价从谁的口袋里、而且是在其不知情的情况下被掏走。

2. 访客如何付费——可能的机制

访客承担费用的方式不止一种。存在若干正当性与风险各异的机制，区分它们是理解这一主题的起点。

2.1 P2P CDN——分担带宽

这是正当性最高的方式。访客的浏览器之间直接互传内容（尤其是视频和大文件），从而减轻中央服务器的带宽负担。代表案例 Peer5 是一个利用 WebRTC 在观众设备之间构建 P2P 网状网络的直播 CDN，据该公司称在高峰时可卸载超过 95% 的总带宽。Peer5 于 2021 年被微软收购并并入企业级 eCDN。在这种方式中，访客付出的主要是"上行带宽"。

2.2 广告——最熟悉的成本转嫁

其实广告才是最古老、最普遍的"访客资助"。访客付出的不是钱，而是注意力、少量数据，以及加载广告脚本所需的带宽和算力。区别在于这是一种社会已达成共识的模式，用户通常知道页面会有广告。

2.3 算力外包——分布式计算

借用访客的 CPU/GPU 来处理某些运算（如科学计算、渲染）的方式。技术上可行，但若访客没有直接收益、只是消耗资源，正当性争议很大。

2.4 加密货币挖矿——最危险的末端

用访客的 CPU 挖 Monero 等加密货币，并用收益来支付服务器费用的方式。理论上看似"无广告的干净站点"的替代方案，但 Coinhive 的噩梦恰恰从这里开始。下一节将详细展开。

机制 访客付出什么 正当性 主要风险
P2P CDN 上行带宽 相对较高 流量费、隐私
广告 注意力、少量算力 社会已共识 追踪、恶意广告
算力外包 CPU/GPU 时间 争议较大 性能下降、发热
挖矿 CPU ＋ 电力 非常低 电量、发热、被滥用

3. Coinhive 前例——从正当替代到加密劫持的代名词

谈访客资助型模式，绝对绕不开 Coinhive 的历史。2017 年 9 月登场的 Coinhive，本意是让站点主人无需广告即可变现流量的合法工具。在站点贴上脚本，访客的浏览器就会挖 Monero，收益的一部分归站点主人。一键复制粘贴的便捷使它迅速扩散。

问题在于，这份便捷同样是滥用的便捷。据安全业界（如 Bitdefender）的梳理，Coinhive 很快成了未经同意的挖矿，即加密劫持（cryptojacking）的代名词。The Pirate Bay 未经访客同意占用其 CPU 的事件即为典型，大量被黑站点被偷偷植入挖矿脚本。访客在毫不知情中把自己的笔记本变成挖矿机，承受发热、电量消耗与性能下降。

Coinhive 最终于 2019 年 3 月停止服务。Monero 硬分叉后算力腰斩、XMR 价值一年内暴跌逾 85%，盈利能力崩塌，加之声誉已无可挽回地坠落。耐人寻味的是，一项研究分析了"最大的 Coinhive 用户之一"三个月的收益，结果仅为区区 7.69 美元。相比转嫁给访客的负担，运营者实际所得少得可怜。

同一种技术，有同意便是正当的收益模式，无同意便是资源窃取。Coinhive 证明了这条界线何其一线之隔。

4. 未了的威胁——2025 年卷土重来的加密劫持

若你问"Coinhive 都倒了，这事不是结束了吗？"答案是否定的。2019 年浏览器大规模封堵了挖矿脚本，但加密劫持并未消亡，而是变得更隐蔽。 据 2025 年的报道（The Hacker News 等），一起活动被查获，3,500 多个网站被植入了经过混淆的 JavaScript 挖矿程序。

手法也在进化。不再像过去那样把 CPU 占满的"暴力方式"，而是先评估设备的算力，再用后台 Web Worker 并行挖矿，并通过 WebSocket 从外部服务器获取任务、动态调节挖矿强度。方向转向以"不被发现"为优先，避免被用户察觉。一些分析报告称，2025 年加密劫持事件同比增长约六成。

这一趋势给访客资助型模式的教训很明确：通过浏览器调用访客资源的技术本身绝不会消失，而合法模式与恶意加密劫持共用同一套工具。正因如此，"是否同意、是否透明"这把标尺才格外重要。

5. 构想的背景——开发者对免费托管的渴望

那么，既然有如此危险的历史，为何类似构想还一再复活？背后是开发者强烈的免费托管需求。对运营个人项目、副业项目、作品集和小型开源工具的开发者而言，每月的服务器费是不可忽视的负担。流量超出预期时，还可能遭遇账单暴涨（正如VPS 内存不足导致谷歌取消索引的案例所示，小服务器的极限会直接演变为运营危机）。

"如果托管能完全免费呢？"的诱惑因此十分强烈。访客各分担一点、开发者一分钱不花就能运营服务的图景，对那些制作难以变现的免费工具的人尤其有吸引力。问题在于，那"一点点"对访客而言是未经同意的负担，而开发者的零成本只是被单纯地转移为访客的成本上升。

6. 优点——这一模式为何有吸引力

为求平衡，也要指出其明显的优点。

  • 开发者零门槛：无需信用卡、无需月费即可部署，大大降低了实验与创作的门槛。
  • 抗流量激增（就 P2P 而言）：访客越多，P2P 网状网络越大，分发反而更顺畅。它弥补了"爆红即成本暴增"的中央服务器弱点。
  • 广告替代的可能：对厌倦追踪广告的用户而言，透明同意下的最小资源分担，可能成为比广告更不具侵扰性的替代。
  • 抗审查：内容分散在访客之间后，仅封锁单一服务器已难以让站点下线。

这些优点是真实的。但它们都只在"如果透明地取得了同意"这一巨大前提之上才成立。

7. 风险——被转嫁费用的真实面貌

接下来是阴暗面。被转嫁给访客的"费用"并不抽象，而是非常具体。

  • 电量与电力：运算或挖矿即耗电。移动用户电量飞快流失，桌面用户替别人付电费。加密劫持的标志性症状正是发热与电量骤降。
  • 性能下降：后台运算会拖慢设备，配置越低、越旧的设备受冲击越大。
  • 流量费：P2P 使用上行带宽，在按量计费或移动环境下可能被计为实际流量费用。
  • 缺乏同意：这是最根本的问题。若访客在不知情下被夺走资源，那么无论机制为何，都不是正当交易。
  • 安全滥用的通道：使用访客资源的脚本一旦被常态化，当其因供应链攻击变为恶意时就更难被发现。这与智能电视被滥用为住宅代理的案例相通——把用户设备视为资源的思路如何蔓延为滥用。

8. 伦理与透明——这一模式真正的试金石

归根结底，这一模式的正当性不由技术、而由伦理决定。核心原则可概括为"事先告知、明示同意、最小使用、随时可拒绝"四点。

  1. 事先告知：须在访问前或进入时，明确告知使用哪些资源（CPU、带宽、电力）、用于何处、用了多少。
  2. 明示同意：不是埋在条款深处的一行字，而要是用户能真正认知并选择的形式。
  3. 最小使用：限制强度以免设备超负荷，并保护移动与低配设备。
  4. 可拒绝：即便不同意，内容本身仍可使用，才是真正的选择。

这四点得到遵守，便成为像 P2P CDN 那样的正当模式；一旦崩塌，便坠入 Coinhive 式的加密劫持。考虑到广告政策、展示规范，以及关于未经同意安装、运行程序的相关规定，透明不仅是伦理问题，也是法律风险管理的范畴。

9. 与现有免费托管对比——GitHub Pages、Vercel、Cloudflare

要正确评估访客资助型模式，就该与已运转良好的免费托管对比。它们不给访客设备增加负担，也能提供免费服务。

平台 由谁吸收成本 访客负担 免费额度（2026 年）
GitHub Pages 微软（基础设施） 无 每月 100GB 带宽（软限），仓库 1GB
Vercel（Hobby） 平台（引导付费升级） 无 每月 100GB 带宽，函数调用 100 万次
Cloudflare Pages 平台（CDN 规模经济） 无 带宽无限，每月 500 次构建
访客资助型 访客（算力、带宽、电力） 有 理论上无限（负担分散）

对比揭示的核心很清楚：现有免费托管由平台吸收成本，访客无需另付代价。若是静态站点，仅 GitHub Pages、Cloudflare Pages 就足以让大多数个人项目免费运行。访客资助型模式若要自证正当，就必须证明一个免费托管难以覆盖的狭小缝隙（如大规模直播的带宽）——而且即便在那里，也要有透明的同意。

10. 用户与开发者视角——谁该留意什么

10.1 用户（访客）清单

  • 浏览时设备突然发烫或风扇转起来，要怀疑后台运算。
  • 用浏览器任务管理器（如 Chrome 的 Shift+Esc）可查看某标签页的 CPU 占用。
  • uBlock Origin、No Coin 之类的拦截器能阻止已知的挖矿脚本。
  • 越是标榜"免费"的站点，越值得问一句它究竟靠什么赚取运营费。

10.2 开发者清单

  • 先自问：若是静态站点，自托管或免费静态托管是否已经够用？
  • 若要使用访客资源，请从一开始就把告知、同意、拒绝权纳入设计。
  • 务必设置对移动与低配设备的保护（强度上限、选择退出）。
  • 检查第三方脚本的完整性（SRI）与供应链风险，为正常脚本被变为恶意的时刻做好准备。

11. 未来展望——缝隙虽窄但正当

我认为访客资助型托管成为主流的可能性不高。原因很简单：正如 Coinhive 所证明的，运营者所得微薄，而访客付出的费用与信任的损耗却很大。况且现有免费托管已充分吸收了大部分需求。

但狭小而正当的缝隙确实存在。像 P2P CDN 那样访客也能获益（更快的播放）、资源使用被透明告知、且可以拒绝的模式，完全能够存活。Peer5 被微软收购并立足于企业级 eCDN，便是明证。也就是说，未来属于"透明分担收益与成本的模式"，而非"悄悄转嫁费用的模式"。

12. 监管与信任维度——为何账算不过来

除伦理之外，还有一层冷峻的经济与监管现实，解释了这一模式为何很难经得起真实世界的检验。回想 Coinhive 那个数字：其最大用户之一三个月仅赚约 7.69 美元。这并非个例，而是道出了结构性弱点。浏览器挖矿相比专用硬件效率极低，运营者为换取这点零钱，必须给大量访客施加可观而持续的负担。成本与收益之比，严重不利于访客。

监管方已经注意到这一点。加密劫持浪潮之后，浏览器厂商开始默认封堵已知的挖矿脚本，广告网络收紧了对未披露资源占用的政策，许多司法辖区的消费者保护与计算机滥用框架，也可能把未经同意使用他人设备视为违法。这意味着，悄悄在访客端跑运算的开发者，不仅面临声誉崩塌，还可能遭遇政策封禁与潜在法律责任。其所得的"免费"，代价可能远高于一笔不大的托管账单。

还有一层容易被忽视的搜索与信任成本。一个耗尽电量、拖慢设备的站点会产生糟糕的用户信号——高跳出率、短停留时长、负面评价——从而悄悄侵蚀搜索可见度与品牌信任。换言之，即便撇开伦理，这一模式也常常败于冷冰冰的算术：收入微薄、隐藏成本巨大、声誉脆弱。这正是为何唯一能长久存续的变体，是像选择加入式 P2P 分发那样透明且互利的模式。

13. 结论 ＋ 三点要义

"访客买单的托管"看似新颖，但其核心技术与伦理困境早在 Coinhive 时代就已受过一次检验。构想本身有吸引力，但这份吸引力只在透明与同意之上才正当。一旦缺了同意，它就不是"免费托管"，而只是"悄悄转嫁出去的费用"。

以须铭记的三点作结。

  1. 追踪免费的代价。开发者若出零成本，那成本并未消失，只是转移给了某人（通常是访客）。
  2. 同一技术，不同伦理。P2P CDN 与加密劫持使用相同的浏览器资源，区分二者的只有告知与同意。
  3. 先看免费托管。大多数个人项目都能在 GitHub Pages、Cloudflare Pages 上免费运行而不给访客增加负担。在动用访客资源之前，请先考虑这一选项。
