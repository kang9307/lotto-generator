A Complete Guide to Canonical URLs in Google Search Console

Fix duplicate content issues and consolidate your SEO signal

If you are wrestling with duplicate page issues in Google Search Console or want to squeeze more SEO value out of your site, this article is worth reading end to end.

1. What is a Canonical URL?

A canonical URL (rel="canonical") is an HTML tag attribute that tells search engines which "original" or "representative" URL among several similar or identical pages should be treated as the primary version for indexing. In plain English, it is your way of telling the search engine, "Out of all these pages, this one is the real original."

For example, all of the URLs below can display the exact same product page.

  • http://www.example.com/product/item
  • https://www.example.com/product/item
  • https://example.com/product/item
  • https://example.com/product/item?ref=banner
  • https://example.com/product/item?utm_source=google

To a user they all look the same, but search engines treat them as separate pages and dilute the SEO signal across all of them. Declaring a canonical URL consolidates those scattered signals into a single representative URL, which can give a meaningful boost to your search rankings.

2. Five Ways to Set a Canonical URL Correctly

There are several ways to declare a canonical URL; pick the best fit for each situation.

Method 1: Use the `rel="canonical"` HTML tag (the most common approach)

By far the most common approach is to add a <link> tag inside the <head> section of your HTML document to declare the canonical URL.

<head>
    <link rel="canonical" href="https://example.com/your-canonical-page-url" />
</head>

Self-referencing canonical: Even when the current page is already the original, it is a good practice to point the canonical URL at itself. This explicitly signals to Google, "Yes, this is the original."

Method 2: Use an HTTP header

Use this approach for non-HTML content such as PDFs or images. Add a Link entry to the HTTP response header on the server side.

Link: <https://example.com/downloads/white-paper.pdf>; rel="canonical"

Method 3: Use the sitemap

URLs included in a sitemap can be treated by Google as canonical candidates. However, this is a weaker signal than rel="canonical", so it is best used in combination with other methods rather than on its own.

Method 4: Use a 301 redirect

Use 301 redirects when you are permanently moving a duplicate page to another URL. A 301 redirect is the strongest signal you can send to search engines: "The old page is gone, and here is the new canonical version." It is essential when moving pages or switching protocols (http -> https).

Method 5: Google Search Console's 'URL Parameters' tool

This feature lets you tell Google how to handle specific URL parameters such as session IDs, sort order, or filters. It affects your entire site, so use it with extreme caution unless you are an experienced SEO practitioner.

3. Common Mistakes and Fixes (Do's & Don'ts)

Canonical URLs look simple, but a misconfigured one can actually hurt your SEO. Use the table below to avoid the most common mistakes.

Topic Do ✅ Don't ❌
Path Use an absolute URL
https://...		 Use a relative path
/page.html
Location Place it only inside the <head> section Place it inside the <body> section
Count Declare a single canonical URL per page Declare multiple canonical URLs
Pagination Let each paginated page canonicalize to itself, or use `rel="prev/next"` Canonicalize every paginated page (2, 3, 4...) to the first page
Protocol Use HTTPS as the canonical for HTTPS pages Point HTTPS pages at an HTTP canonical

Conclusion

In a complex web environment, configuring canonical URLs is an essential SEO task that helps search engines clearly understand and correctly evaluate your site's content. Put the techniques covered here to work to resolve duplicate content issues on your site, consolidate the SEO signal that is currently scattered, and lift your search rankings. It is also a good habit to regularly check the 'Indexing > Pages' report in Google Search Console to monitor for any canonical-related issues.
