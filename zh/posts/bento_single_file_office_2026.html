Bento 现身 - 一个文件就是一整个办公应用的单文件实验

一个 570KB 的 HTML 文件装下编辑器、数据甚至协作功能，Bento 让我们重新审视单文件应用与本地优先办公软件的可能性与局限

2026-07-24 IT/技术

引言: 一个文件成为一整个应用意味着什么

2026 年 7 月，GeekNews 上出现了一个叫 Bento 的项目。它的宣传语很简单:「装进一个文件里的办公套件」。实际核实之后，更准确的说法是这样的。开发者 nyblnet 打造的这个项目，把演示文稿连同编辑器、查看器、数据一起压缩进一个 .bento.html 文件，大小约 560~570KB。从 bento.page 下载这个文件，在任意浏览器中打开，它本身就变成了编辑器；保存后，同一个文件会带着新内容重写自己。Hacker News 上的 Show HN 帖子获得了 977 个点赞，GitHub 仓库在公开数天内就积累了超过 1,000 颗星标。项目采用 MIT 许可证。

不过有一点需要先说清楚。截至 2026 年 7 月，实际发布的只有 Slides(演示文稿) 这一项。Docs 和 Sheets 只是被宣布将作为各自独立的 .bento.html 版本「未来推出」，目前都还没有出现。因此「办公套件」这个名字，眼下更像是一份路线图宣言，而不是已完成的产品。这篇文章不打算复述 hada.io 上的讨论，而是想从本人的角度，说清楚 Bento 今天到底展示了什么，以及为什么「单文件应用」这个想法本身又重新引起了关注。

1. Bento 实际在做什么 - 一个文件如何成为软件本身

把 Bento 的技术核心按事实梳理一遍，是这样的。

1.1 数据和代码都在同一个文件里

文件顶部放着幻灯片内容，是一段人可读的明文 JSON。下方则是实现编辑器、查看器、演示模式的应用代码，经过 Base64 压缩，由浏览器的 DecompressionStream 在原地解压。字体、图片、图表、动画全部在这一个文件内解决，运行时无需再请求任何外部文件。底层用 reveal.js 作为幻灯片导航的基础，在其之上叠加了自研的动画引擎和图表引擎。

1.2 保存即是重写自己

点击保存后，浏览器的 File System Access API 会用新内容覆盖同一个文件路径；在不支持该 API 的环境中，则回退为普通下载。更新会经过 ECDSA 签名，据介绍，每次写入新版本时，旧文件都会原样保留作为回滚备份。实时协作则通过端到端加密的 CRDT 方案实现，以 Cloudflare Durable Objects 作为盲中继，据称服务器只能看到加密后的数据。Show HN 讨论帖在称赞这一设计的同时，也指出了一些问题：多人同时编辑时输入焦点会被重置，部分环境下动画会卡顿。这些都是一个仍在打磨中的早期项目的信号。

2. 「单文件应用」这个想法本身

Bento 真正有意思的地方，与其说是某项具体功能，不如说是它的前提。我们已经习惯把「软件」和「文档」分开来看：打开一个 Word 文件需要先装好 Word，查看一份 Google 文档需要 Google 账号和网络。软件是需要安装的东西，文档只是软件产生的附属品——这种层级关系长久以来显得理所当然。

Bento 把这层关系反过来了。文件本身既是编辑器，也是查看器,同时也是数据。这个想法本身并不全新——TiddlyWiki 很早就把整个 wiki 打包成单个 HTML 文件分发，draw.io 之类的工具也做过类似尝试。Bento 新加进来的是，把这个想法推进到了办公文档上，甚至包括实时加密协作。项目介绍里的一句话「The file is the software」,几个字就概括了整个思路。

3. 为什么有吸引力 - 便携性、离线、归档、隔离网络、隐私

3.1 便携性与离线能力

单个文件可以整体搬运。放在 U 盘上、作为聊天工具的附件、存在离线硬盘备份里，打开方式都一样。Bento 支持离线模式，据介绍开启后设备不会向外发送任何内容，更新与协作功能会被硬性屏蔽。不预设联网这一点，与云端办公工具的出发点根本不同。

3.2 对隔离网络意味着什么

回想以往接触过的企业安全隔离网络和内网环境，「不需要安装程序的文档型应用」这个概念在实务上相当有吸引力。当然，文件首次带入隔离网络仍需经过带入审查流程，但一旦带入之后，无需另外的安装程序、许可证服务器、联网连接，仅凭文件本身就能完成文档撰写与查看，这确实能减轻内网运维的负担。不过这只是方向性判断——在实际的隔离网络审查中，文件本身内嵌可执行代码这一事实，反而可能成为审查关注的重点，这一点要客观看待。

3.3 隐私 - 服务器看不到的数据

云端办公工具出于便利性考量，服务器需要知道文档内容。Bento 的协作设计据称把服务器(Cloudflare Durable Objects)做成了只转发加密数据的盲中继。据介绍也没有遥测数据收集。这套设计是否真正经过独立安全审计是另一回事，但至少其目标是「服务器不知道内容」的隐私优先设计。

4. 用 Web 技术做本地应用的潮流 - 单文件 HTML+JS、WASM、本地优先

4.1 浏览器成为运行时的时代

Bento 不依赖任何应用商店或安装步骤，直接把浏览器本身当作运行时。Hacker News 上不断有独立开发者分享类似方向的实践——最近一篇讲述自己做了二十多个可离线运行、无需后端的单文件 HTML 工具的帖子就引发了不少关注。「无需安装的本地 Web 应用」已经成为一股小小的潮流。

4.2 通向 WASM 的另一条路径

也有项目试图用不同技术实现同一个目标(办公工作完全在浏览器内完成、数据不外流)。2026 年初发布的一个开源项目就是一例：它把 ONLYOFFICE 的文档引擎编译成 WebAssembly，在浏览器内直接处理 Word、Excel、PowerPoint 格式。Bento 选择了自有格式加自研渲染器的轻量路线，而 WASM 路线则背负了与现有办公格式兼容这一较重的负担，换来的是能够真正处理 .docx、.xlsx、.pptx 文件。方向相同，取舍不同。

4.3 本地优先(local-first)软件思潮

为这股潮流提供理论支撑的概念是 local-first software。Ink & Switch 研究实验室在 2019 年发表的一篇文章确立了这个术语，其中几条核心原则几乎与 Bento 完全吻合：「网络应当是可选项」「协作者应当能看到彼此的修改」，以及最重要的 「The Long Now」——即便某个厂商消失，或某项服务下线，软件也应当继续可用。Bento 读起来像是把这些原则应用到了最日常、也最需要长期保存的文件类型——办公文档——上的一次实验。

5. 与现有办公工具的位置关系与局限 - MS 365、Google 文档、LibreOffice

把 Bento 放在现有办公套件旁边比较,位置就清楚了。诚实的评价需要同时承认它的优势与局限。

5.1 协作深度的差距

MS 365 或 Google 文档的实时协作，是经过数亿用户检验的基础设施。Bento 的加密 CRDT 协作方向有趣，但仍是在 Show HN 阶段就被报告出焦点重置之类 bug 的早期实现。

5.2 功能深度与可扩展性

今天的 Bento 只专注于演示文稿这一件事。文字处理软件的脚注、索引、校对工具，或者电子表格的函数、数据透视表这类深层功能，都还在这个项目的范围之外。即便 Docs 和 Sheets 推出，要在短期内追上现有办公软件数十年积累的功能面，也并不容易。

5.3 兼容性与体积的局限

Bento 是自有格式。它与现有 .pptx、.docx、.xlsx 文件之间的互相转换能有多顺畅,目前并未得到证实。此外，把所有内容都塞进一个文件的结构,也带着一种与生俱来的取舍:文档越大(图片、图表越多),文件本身就会越重。

6. 实际有用的使用场景

6.1 离线环境与隔离网络

没有网络的现场作业、船舶或飞机上连接不稳定的环境，或是彻底禁止云端登录的企业隔离网络——在这些地方，「一个文件搞定的演示工具」可能是一个现实的选择。不过如前所述，带入闭环网络仍需另行经过审查流程。

6.2 临时性工作与教学场景

不需要注册账号，一个链接就能打开演示资料并当场修改，这对一次性工作坊、黑客松演示、课堂教学都很实用。在学生或参与者没有权限在笔记本上安装软件的公共电脑环境中，只需运行文件即可的方式降低了使用门槛。

6.3 临时协作与快速分享

无需共享云账号，仅凭文件链接或附件，团队成员就能立即打开并留下评论，这对短会议、工作坊材料来说也很合适。不过正如第 3 节所提到的，协作功能本身仍处于实验阶段,与其用它取代公司正式的协作流程，不如把它当作补充手段更为稳妥。

7. 文档保存的视角 - 20 年后仍能打开的文件

7.1 格式会腐朽这个问题

打不开旧版文字处理格式,或某个已停止维护的软件专用文件,这样的经历并不少见。云端文档更脆弱:一旦服务下线,文档本身可能整个消失。「这个文件 20 年后还能打开吗」,是办公软件长期未解的老问题。

7.2 Bento 的答案 - 明文数据与带签名的自我重写

Bento 的做法是这样的:把数据以人可读的 JSON 形式,而不是二进制格式,原样保留在文件里;不依赖任何一家公司的服务器或账号。新版本发布时,不会覆盖旧文件,而是生成一个带签名的新文件,从而保留旧版本。这一整套设计,读起来像是在文档格式这个层面,尝试实现前面提到的本地优先原则中的「The Long Now」。

7.3 仍然存在的前提 - 对浏览器这一平台的依赖

不过这套结构仍然有其前提。Bento 文件要在未来继续可打开,归根结底需要一个能解析 HTML5、JavaScript 的浏览器持续存在。考虑到 Web 标准长期以来对向后兼容的坚持,这个前提相对来说相当稳固,但也仅仅是比依赖某家公司的云服务更安全而已,并非完全没有前提,这一点需要冷静看待。

8. 结论 - 关于方向的实验,而非完成形态的办公套件

如果在今天诚实地总结 Bento,大致是这样的:截至 2026 年 7 月,实际发布的只有一款演示工具,文档与表格仍停留在「已宣布」阶段。协作功能设计颇有意思,但仍带着早期阶段的 bug。它还没有到能立刻取代 MS 365、Google 文档、LibreOffice 这三大办公套件的水平。

即便如此,这个项目能在短时间内收获超过 1,000 颗星标和 977 个点赞,依我看,原因不在功能,而在想法本身。无需安装、无需账号、无需服务器,一个文件就能搞定的软件;这个文件即便离线也能完整运行;并且承诺 20 年后只要有浏览器就能打开。这是对过去十几年办公软件不断向云端靠拢这股潮流的一次小小反驳。如果你在寻找一个成熟完善的替代品,现在坚持使用现有工具仍然是更稳妥的选择;但如果你对本地优先软件这个方向本身感兴趣,Bento 是一个眼下值得关注的实验。
