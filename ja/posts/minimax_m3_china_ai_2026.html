2か月で動いたもの — 先に結論

いま価格表を開くと6月とは違う数字が並んでいます。下がったのは中国側ではありません。

この記事のもとの主張は単純でした。中国系モデルが欧米フラッグシップの一桁パーセントの価格で同等の結果を出しているので、価格はもはや既存勢の優位の根拠ではない、というものです。2か月経って、その命題は半分だけ残りました。中国系の単価はほぼそのままで、欧米側がその下に降りてきたからです。

2か月分をまず圧縮します。以下の数値はすべて2026-08-04に各ベンダーの公式ドキュメントで確認できる値です。

  • MiniMax-M3の単価は変動なし。 100万トークンあたり入力0.30ドル、出力1.20ドル(512K以下の区間)。6月の公開時点と同じです。
  • OpenAIが下りてきた。 2026-06-26に公開されたGPT-5.6系列のうちLunaが2026-07-30の値下げを経て入力0.20ドル、出力1.20ドルになりました。入力はM3より安く、出力は同額です。
  • 「フラッグシップの5-10%」が成立する相手は最上位ティアだけになった。 GPT-5.5(5.00ドル/30.00ドル)基準では4~6%で合っています。Gemini 3.1 Pro(2.00ドル/12.00ドル)基準では10~15%です。
  • 中国系で実際に動いた軸は価格ではなくライセンス。 DeepSeekは本番版V4-FlashをMITで公開し(2026-07-31)、Moonshotは売上しきい値付きの独自ライセンスでKimi K3の重みを出しました(2026-07-27)。
  • だから今日の判断軸は「どこが安いか」ではありません。 再配布・再販まで許されるライセンスか、そしてその法域へプロンプトを送ってよいか。この二つが単価より先です。

モデル全体の単価・ベンチマーク比較表は2026年 AIモデル徹底比較にあります。ここではこの記事の軸、つまり中国系モデルと欧米フラッグシップの間隔に必要な値だけを扱います。同じ表を二度作る理由はありません。

MiniMax-M3 — いま確認できる仕様

M3は2026-06-01に公開され、重みは6月7日にHugging Faceへ上がりました。2か月経ったいまもMiniMax公式モデル一覧の最上位にあります。M2.7は現行の一覧に残っており、M2.5以下はレガシー区分へ下りました。

2.1 構造 — MSAが価格表とつながる地点

M3は総パラメータ約428Bのうちトークンあたり約23Bだけが活性化するMoEです。ここまでは2025年以降の大型モデルの標準構成です。新しいのはアテンション側です。MiniMaxはMSA(MiniMax Sparse Attention)という独自のスパースアテンションを入れ、モデルカードには100万トークン域で前世代M2比プリフィル9倍・デコード15倍の速度、トークンあたり演算は約20分の1と明記されています。

この数字は性能自慢ではなく価格の根拠です。100万トークンのコンテキストを実際に使うワークロードでコストを決めるのはパラメータ数ではなくアテンションのコストです。コンテキストが伸びるほど標準的なアテンションは二乗で膨らみ、その分がそのまま単価に乗ります。スパースアテンションはその曲線を寝かせます。M3が100万トークンを開いたまま1.20ドルの出力単価を保てる機械的な理由がここにあります。

判断を一つ。コンテキストを20万トークン以下でしか使わないなら、M3の構造的な利点は請求書にほとんど現れません。 その区間ではM2.7や他ベンダーの中位ティアのほうが安いか速い場合があります。M3を選ぶ理由は「長い入力を頻繁に、繰り返し投げるか」です。

3.1 表に入っていない層

公開単価はキャッシュミスの見出しです。実際の請求書はその下のいくつかの層で決まります。

  • キャッシュ読み出し。 M3は0.06ドル(入力の20%)、GPT-5.6 Lunaは0.02ドル(入力の10%)、DeepSeek V4-Flashは0.0028ドル(入力の2%)です。同じプロンプト前半を繰り返し送る構造なら、この列が本体単価より効きます。
  • コンテキスト区間。 M3は512Kを超えると2倍になります。Gemini 3.1 Proは200Kを超えると入力4.00ドル・出力18.00ドルへ跳ねます。GPT-5.6 Lunaの長文脈区間も0.40ドル/1.80ドルです。100万トークンを開けることと100万トークンを安く使えることは別の話です。
  • バッチとフレックス。 OpenAIもGoogleもバッチ処理に約50%の割引を付けています。急がない大量処理なら、この割引だけで中国系との差が半分になります。
  • ピーク料金。 DeepSeekは北京時間09:00~12:00と14:00~18:00に定価の2倍を適用するピーク料金を予告しています。適用時期はまだ告知されていません。
  • 優先ティア。 MiniMaxの国内プラットフォームは優先処理ティアに標準価格の1.5倍を課しています。

五つの層をすべて入れて計算すると順位が入れ替わることがよくあります。共通の前半を送り直してキャッシュヒット率が90%に達する構造なら、M3の実効入力単価は0.30ドルではなく0.30×0.1 + 0.06×0.9 = 0.084ドルになります。同条件でGPT-5.6 Lunaは0.20×0.1 + 0.02×0.9 = 0.038ドルです。キャッシュがよく効く構造ほど、差が開く方向は見出し単価と逆になります。

逆にキャッシュがほとんど効かない一回限りの入力なら、見出し単価がそのまま請求書です。どの層が支配的かはモデルではなく自分のプロンプト構造が決めます。 だからベンダー比較より先にやるべき計算は、自分のワークロードのキャッシュヒット率の見積もりです。トークン数とヒット率を入れて計算するにはLLM API料金計算ツールが使えます。

3.2 M3の定価と割引

M3の国際プラットフォームの定価は入力0.60ドル、出力2.40ドルです。そこに「常時50%割引」が付いて0.30ドル/1.20ドルになります。国内プラットフォームも同じ構造で、定価4.20元/16.80元に50%が適用されて2.10元/8.40元です。

表記が「常時」であっても、定価がドキュメントに残っている事実は変わりません。この単価を前提に採算を組む組織なら、割引なしの定価でも事業が成立するかを一度計算しておくほうが安全です。定価基準のM3は0.60ドル/2.40ドルで、そうなるとGPT-5.6 Luna(0.20ドル/1.20ドル)の2倍になります。

価格を追って下りてきたのは欧米側だった

6月から8月の間にこのテーマで起きた最大の出来事は、中国側ではなくOpenAI側から出ました。

OpenAIは2026-06-26にGPT-5.6系列を公開し、構成の仕方を変えました。一つのモデルに推論強度のダイヤルを付ける代わりに、Sol・Terra・Lunaの三ティアに分けたのです。そして2026-07-30、Lunaを80%、Terraを20%値下げしました。値下げ後のLunaは入力0.20ドル、出力1.20ドルです。

この値をM3の横に置くと次のようになります。

  • 入力: Luna $0.20 < M3 $0.30 — 欧米側が安い
  • 出力: Luna $1.20 = M3 $1.20 — 同額
  • キャッシュ読み出し: Luna $0.02 < M3 $0.06 — 欧米側が安い

「中国系が10分の1の価格」という文が成立するには、比較対象がGPT-5.5やGPT-5.6 Solのような最上位ティアである必要があります。ティアを揃えて比べると差は消えました。これは中国系モデルが高くなったという意味ではなく、価格という軸そのものがもはや陣営を分けなくなったという意味です。

値下げ後のTerraの値も見ておく価値があります。入力2.00ドル、出力12.00ドル。Gemini 3.1 Proと小数点まで同じです。中位ティアで二つのベンダーの表示単価が一致したということは、この区間が価格競争から機能競争へ移ったシグナルと読めます。ここで選択を分けるのは単価ではなくマルチモーダルの範囲とプラットフォーム統合です。

4.1 では、なぜまだ中国系を見るのか

三つ残ります。重みは同じではありません。

  1. 重みを手元に置ける。 LunaはAPIとしてしか存在しません。M3・DeepSeek V4・GLM-5.2・Kimi K3・Qwen 3.6は重みが公開されています。データを外に出せない組織にとって、これは価格の問題ではなく可能か不可能かの問題です。
  2. 長文脈の単価曲線が違う。 Lunaの長文脈区間は0.40ドル/1.80ドルで、M3は512Kまで0.30ドル/1.20ドルを保ちます。30万~50万トークンを常時投げるワークロードならここで分かれます。
  3. 供給者を一つに束ねないこと自体の価値。 2026年の上半期だけでGPT-5系列の単価が一度2倍になり(2026-04-23)、一度80%下がりました(2026-07-30)。この振幅の上に単一供給者で事業を載せるのは価格リスクです。

裏返すと、この三つのどれにも当てはまらないのに「安いから」だけで中国系を選んでいるなら、いま計算し直すべきです。その理由は2か月前には有効で、いまは有効ではありません。

中国系モデルの地形 — 2026年8月時点

6月の記事はMiniMax一社に焦点を当てていました。2か月の間に他のラボが動いたので地形を広げておきます。ここに書いたのは公式モデルカードと価格ドキュメントで確認できる項目だけです。

5.1 DeepSeek

V4-ProとV4-Flashを2026-04-24にプレビューとして出し、2026-07-31に本番版V4-FlashをMITライセンスで公開しました。V4-Proは総1.6Tに活性49B、V4-Flashは284Bに活性13Bです。どちらもコンテキストは100万トークンです。

単価はこの表で最も低い水準です。V4-Flashが入力0.14ドル、出力0.28ドル。キャッシュヒット時の入力は0.0028ドルまで下がります。大量バッチの分類・要約・タグ付けなら2026年8月時点でここが底です。 背景はDeepSeek V4-Pro 75%恒久値下げに整理してあります。

5.2 Qwen(アリババ)

Qwenは2026年に二つの系統へ分かれました。オープンウェイト系と非公開のフラッグシップです。

  • Qwen3.6-35B-A3B(2026-04-16公開)とQwen3.6-27B(2026-04-22)はApache 2.0です。条件なしの商用利用ができます。
  • Qwen3.7-MaxとQwen3.7-Plusは重みを公開していません。API専用で、Maxは2.50ドル/7.50ドルです。

Qwen3.6-27Bはネイティブ262,144トークンのコンテキストで、最大1,010,000まで拡張可能とモデルカードに記載されています。27Bの密モデルなので単一ワークステーションに載る大きさで、ライセンス条件が最も単純な選択肢です。ローカル運用の観点はQwen 3.6 27B ローカル開発にあります。

5.3 GLM(Zhipu / Z.ai)

GLM-5.2はMITです。モデルカード基準で753Bパラメータ、コンテキスト100万トークン、最大出力128K。APIは1.40ドル/4.40ドルで、キャッシュ読み出しは0.26ドルです。テキスト専用なのでマルチモーダルが必要なら候補から外れます。

MITであることからモデルを載せて再販する事業ではここが最も摩擦が少ない選択です。詳細はGLM 5.2 公開の分析にあります。

5.4 Kimi(Moonshot)

Kimi K3はホスティングサービスとして先に出た後、2026-07-27に重みが公開されました。総2.8Tのうちトークンあたり104Bが活性、896の専門家のうち16をルーティング、コンテキスト1,048,576トークン、MoonViT-V2のビジョンエンコーダで画像を直接受け取ります。重みは96のsafetensorsシャードで約1.56TBです。

単価は中国系で最も高いです。入力3.00ドル、出力15.00ドル。キャッシュ入力は0.30ドルです。価格で選ぶモデルではありません。 導入判断はKimi K3の重み公開に整理されています。

5.5 三つのラボを一文で

DeepSeekは底単価を、GLMは制約のないライセンスを、Kimiは規模を取りました。MiniMaxはその間で長文脈の単価曲線を押さえました。「中国系モデル」を一塊にして選ぶ理由はもうありません。中国LLM三強比較がこの分岐の前半を扱っています。

6.1 売上しきい値条項は契約書として読む

MiniMaxとMoonshotはどちらも2000万ドルという同じしきい値を置いています。表現は異なります。

  • MiniMaxは「関連する製品・サービスの年間売上」がしきい値を超えると事前の書面承認を求め、未満なら通知1回です。
  • Moonshotは「モデルをサービスとして提供する事業」の12か月売上がしきい値を超えると別途契約を求めます。自社製品に組み込んで使うだけならここには当たりません。

二つの条項の射程は同じではありません。MiniMaxのほうが広いです。モデルを再販せず自社サービスに組み込んで使うだけでも「関連する製品の売上」と読める余地があるからです。しきい値を超える規模でなくても、この一文は法務レビューの対象です。

実務判断は三つに分かれます。

  • モデルを載せて売る事業(MaaS・再販・ホワイトラベル)ならMIT/Apacheだけを見ます。 DeepSeek V4系列、GLM-5.2、Qwen 3.6系列。条件条項がないのでレビュー時間はゼロです。
  • 社内用・自社製品への組み込みならコミュニティライセンスも候補に残ります。 ただし「Built with MiniMax M3」の表示義務は製品ドキュメントや紹介ページに反映する必要があります。抜けたら条件違反です。
  • 年間売上2000万ドルを超える軌道にあるなら、いま確認してください。 事前承認条項は後から遡って処理しにくい種類のものです。

6.2 表示義務はどこに入れるか

「Built with MiniMax M3」のような表示義務は実務でよく抜けます。ライセンス本文が指定する場所は、ウェブサイト、製品インターフェース、紹介記事、会社紹介ページ、製品ドキュメントのうち目立つところです。ソースコードのコメントやライセンスファイルの一行では条件を満たしたとは言いにくいでしょう。

Kimi K3の表示条件は射程が違います。月間アクティブユーザー1億人を超える製品にだけ画面表示を求めます。ほとんどの組織には当たらない条項なので、Kimi側の実質的な検討点は表示ではなくMaaS売上のしきい値です。

整理するとこうなります。MiniMaxは規模に関係なく表示義務がかかり、Kimiは規模に達して初めてかかります。 自社ブランドの画面に外部モデル名を出しにくい製品なら、この違いが選択を分けます。

8.1 国際アカウントと国内アカウントは別サービス

MiniMaxは国際用と中国国内用のプラットフォームを別々に運営していて単価体系も別建てです。国際はドル、国内は人民元で、為替で換算しても値は一致しません。国内プラットフォームには優先処理ティア(標準価格の1.5倍)があり、トークンパッケージの構成も異なります。

日本からアクセスするなら国際プラットフォームが基本経路です。ゲートウェイを使うと表示単価は下がりますが(入力0.24ドル、出力0.96ドル)、実際の配信事業者がリクエストごとに変わり得ます。ツール呼び出しの精度や応答レイテンシが製品品質に直結するワークロードなら、ゲートウェイより一次APIのほうが適切です。 実験・評価の段階では逆にゲートウェイが便利です。一つの鍵で複数のモデルを同じインターフェースから回せるからです。

8.2 地域制限はライセンス本文にある

重みが公開されていることは、どこでも使えるという意味ではありません。GLM-5.2はモデルカードに地域制限がないと明記されています。他のモデルはライセンス本文を直接確認する必要があります。公開の有無と地域条件は別項目で、要約ページではなくライセンスファイルに書かれています。

自前で動かすのはどこまで現実的か

重みの公開が増えたことで「受け取って自分で回す」が実際の選択肢になりました。規模を数字で置いてみます。

  • Qwen3.6-27B — 27Bの密モデル。量子化すれば単一の高スペックワークステーションで動きます。個人や小規模チームが現実的に担える唯一の区間です。
  • Qwen3.6-35B-A3B — 総35B、活性3BのMoE。活性パラメータは小さいですが全重みをメモリに載せる必要がある点は同じです。MoEは演算量を減らすのであってメモリを減らしません。
  • DeepSeek-V4-Flash — 総284B、活性13B。ここからはマルチGPUサーバーです。
  • MiniMax-M3 — 総428B、活性23B。
  • GLM-5.2 — 753B。
  • Kimi K3 — 総2.8T、活性104B。重みファイルだけで約1.56TB(96シャード)。MXFP4量子化の重み基準です。

判断。自前運用を「コスト削減」として始めるとたいてい失敗します。 バッチのスループットをGPUが遊ばない水準まで埋められなければ、トークンあたりの実費がAPI単価を簡単に超えます。0.14ドル/0.28ドルのAPIが存在する状況で、単価だけで自前運用が勝つ区間は狭いです。

自前運用が勝つ条件は別にあります。データを外に出せない場合、モデルの挙動を固定する必要がある場合、ファインチューニングが必要な場合。 この三つのどれかに当たれば費用計算と無関係に自前運用が答えで、三つとも当たらなければAPIが答えです。中間はあまりありません。

「モデルの挙動を固定する必要がある場合」は説明が要ります。APIモデルはベンダーが背後で更新します。同じモデル名で呼んでも出力フォーマットや拒否の境界が静かに変わることがあり、その上に載ったパーサーや後処理も一緒に揺れます。検証を通した挙動を数か月単位で凍らせる必要があるパイプラインなら、重みを手元に持つことがそのまま再現性です。この価値は単価計算に現れませんが、回帰事故を経験したチームには最大の項目です。

規模で整理すると、27B級は個人が担え、300B級からはチームと予算が付き、1TBを超える重みは事実上インフラ事業の領域です。Kimi K3の1.56TBはダウンロードすること自体がプロジェクトです。

日本での実務 — データの扱いと規制

単価とライセンスを整理しても、日本では法域の問題が前に立ちます。確認できる事実だけを書きます。

  • 個人情報保護法は外国にある第三者への個人データの提供について、原則として本人の同意、または移転先が継続的に相当措置を実施していることを求めています。単価や性能とは独立した制約です。
  • デジタル庁は2026-06-12にデジタル社会推進標準ガイドラインDS-920「行政の進化と革新のための生成AIの調達・利活用に係るガイドライン」第2.0版を公表しました。対象が音声・画像へ拡大され、自律的に作業を進めるAIエージェントのガバナンスルールが新設されています。AIガバナンス部分は2026-07-01から、その他は2026-09-01から適用されます。
  • 中国では生成AIサービス管理暫定弁法により、中国国内で提供される生成AIサービスに登録とコンテンツ審査の義務が課されています。これは提供側の規制であって、日本から国際プラットフォームを利用する場合の直接の義務ではありません。

これを実務の文に置き換えると次のようになります。

10.1 法域が先、単価は後

プロンプトに個人データが入るワークロードなら、越境移転の根拠と本人同意が先です。これはモデルの品質や価格と独立した制約で、90%の割引が規律を変えることはありません。行政調達であればDS-920のチェックシートが先に来ますし、民間でも同じ構造を社内規程に翻訳して使う企業が増えています。

したがって規制データに対する実務の順序は固定されています。法域を先に確定し、通過した候補の中で単価を見ます。順序を変えると後で全部やり直すことになります。

10.2 オープンウェイトが規制の議論を短くする

重みを自社インフラに載せれば越境移転そのものが発生しません。この構造変更一つで消える検討項目が多くあります。これが2026年夏にMIT・Apache系の価値が単価と無関係に上がった理由です。

ただしオープンウェイトに移せばライセンス条件がそのまま付いてきます。規制を避けるためにコミュニティライセンスのモデルを自前運用したのに売上しきい値条項に当たるのは、問題を移しただけで解いていません。規制ワークロードに自前運用を使うなら、MIT・Apache系に絞るのが検討総量として最も少なくて済みます。

10.3 日本語の品質は表にない

ここに載せたどのベンチマークも日本語の性能を測っていません。SWE-benchはコード、MMMUはマルチモーダル理解、Video-MMEは動画です。日本語の要約・文体・敬語の一貫性には公開数値がありません。

この空白は自前の評価でしか埋まりません。実業務30~50件をゴールデンセットにして候補モデルに同じ入力を投げ、結果を比べる手順です。この記事の下に付いたマークダウン成果物に、その手順をそのまま使える形で入れてあります。

ベンチマークの読み方

この記事に載せたベンチマーク数値はすべてベンダー自身の測定です。その事実が数値を無効にするわけではありませんが、読み方を決めておく必要はあります。

  • ベンダー測定と第三者測定は種類の違う主張です。 混ぜて順位表を作ると比較条件が崩れます。
  • ベンチマーク問題が学習データに混入したかは外部から確認できません。 公開問題集を使うすべての評価に当てはまります。
  • 平均値だけが公開され、ばらつきは公開されません。 5回に1回崩れるモデルと常に安定するモデルが同じ点数になり得ます。
  • 測定設定が自分の設定と違います。 推論強度、出力上限、ツール使用の有無が違えば再現しません。

実務ルールを一つ。ベンチマーク首位は「自分の評価を回す理由」であって結論ではありません。 M3がコーディングのベンチマークを牽引していてコードを書くチームなら、半日かけて自分のゴールデンセットを回す合図です。来週に供給者を変える合図ではありません。

  2. DeepSeekのピーク料金が施行されるとき。 定価の2倍が適用される時間帯ができれば、「この表の底」という判断が時間帯ごとに変わります。
  3. 主要なオープンウェイトのライセンス条件条項が変わるとき。 2000万ドルのしきい値や表示義務が調整されれば、第6節と第11節の判断が一緒に動きます。

よくある質問

Q. MiniMax-M3の単価は今いくらか

2026-08-04時点の国際プラットフォーム公開価格で、100万トークンあたり入力0.30ドル、出力1.20ドル、キャッシュ読み出し0.06ドルです。512Kを超える要求は2倍です。定価は0.60ドル/2.40ドルで、常時50%割引が適用された値が前述の金額です。中国国内プラットフォームは2.10元/8.40元で別建てです。

Q. 欧米フラッグシップとの差はまだ10倍か

最上位ティア同士ならそうです。GPT-5.5の5.00ドル/30.00ドルに対しM3は4~6%です。ただしGPT-5.6 Lunaは0.20ドル/1.20ドルなので入力ではM3より安く出力は同額です。Gemini 3.1 Pro(2.00ドル/12.00ドル)基準ではM3は10~15%です。

Q. M3の重みを受け取って商用製品に使ってよいか

コミュニティライセンスの条件を守れば可能です。「Built with MiniMax M3」の表示が必須で、関連する製品・サービスの年間売上が2000万ドルを超えると事前の書面承認が必要です。条件なしの商用利用を望むならMITのDeepSeek V4系列・GLM-5.2、Apache 2.0のQwen 3.6系列が適しています。

Q. 中国系で最も安いのはどれか

2026-08-04の公式価格基準でDeepSeek-V4-Flashが入力0.14ドル、出力0.28ドルで最も低いです。キャッシュヒット時の入力は0.0028ドルです。ただしテキスト専用で、ピーク料金が施行されれば時間帯によって2倍になります。

Q. 会社で使うにはまず何を確認するか

三つの順序です。プロンプトがどの法域へ出るか、ライセンスに売上・表示の条件があるか、そして長文脈区間で単価がどう折れるか。単価の比較はこの三つを通過した候補の中で行えば十分です。順序を変えると後で戻すことになります。

# モデル選定チェックリスト — 単価より先に確認すること

> 出典: braindetox.kr — MiniMax-M3と2026年の中国AI価格
> 確認日 2026-08-04。**単価は変わります。** 表の値は出発点として、決める前に各ベンダーの公式価格ページから埋め直してください。
> そのままコピーして使ってください。このファイルは順位表ではなく**順序**です。

## 0. 順序 — これを入れ替えると後で戻すことになる

1. **法域** — プロンプトがどの国へ出るか
2. **ライセンス** — 再配布・再販・表示義務・売上しきい値の条項があるか
3. **コンテキスト区間の単価** — 実際に使う長さでいくらか
4. **単価の比較** — 上の三つを通過した候補の中だけで
5. **自前の評価** — ゴールデンセットで最終確認

価格を1番に置くと3番で止まり、3番で止まると1番からやり直しになります。

## 1. 法域チェック

- [ ] プロンプトに個人データが入るか
- [ ] 入るなら越境移転の根拠と本人同意が用意できているか
- [ ] 規制業種(金融・医療・公共)か
- [ ] 国内代理人の指定が要るサービス形態か
- [ ] 行政調達ならガイドラインのチェックシートを確認したか
- [ ] 一つでも当たれば → **オープンウェイトの自前運用**を先に検討

## 2. ライセンスチェック

| 確認項目 | なぜ見るか |
|---|---|
| ライセンス名 | MIT・Apache 2.0なら条件条項がない |
| 表示義務 | あれば製品ドキュメントや紹介ページに反映が必要 |
| 売上しきい値 | 事前承認型か通知型かで扱いが変わる |
| しきい値の対象 | 「関連製品の売上」か「モデルをサービスとして提供する事業の売上」か |
| 地域制限 | 要約ページではなくライセンスファイルに書かれている |

**判断**: モデルを載せて売る事業ならMIT・Apacheだけを見る。社内用ならコミュニティライセンスも候補に残る。

## 3. 単価確認シート — 空欄は自分で埋める

| モデル | 入力 | キャッシュ読み出し | 出力 | 区間の折れ | 確認日 |
|---|---|---|---|---|---|
|  |  |  |  |  |  |
|  |  |  |  |  |  |
|  |  |  |  |  |  |

- 単位は100万トークンあたりに揃えること
- **区間の折れ**を必ず書くこと。100万トークンを開けることと安く使えることは別
- 定価と割引価が別にあるなら**定価も書いておくこと**

## 4. 実効単価の計算

```
実効入力単価 = 入力単価 × (1 - h) + キャッシュ読み出し単価 × h
h = キャッシュヒット率(0~1)
```

- hが分からなければ先に測る。ログでプロンプト共通前半の長さを見れば出る
- hが0.8を超えると**キャッシュ読み出し単価のほうが本体単価より効く**
- バッチに回せる比率も併記する。バッチ割引は通常50パーセント

## 5. 評価ハーネス

1. **ゴールデンセット30~50件。** 実業務から取る。易しめ40・普通40・難しめ20の割合
2. **合格条件を先に書く。** 出力を見てから基準を決めると基準が出力に引っ張られる
3. **設定を固定する。** モデル名、バージョン文字列、推論強度、出力上限、ツール使用の有無
4. **同じ入力を5回ずつ。** 回ごとに別々に記録する。平均だけ見るとばらつきを見落とす
5. **どのモデルの出力か分からない状態で採点する**
6. **トークン数とレイテンシも一緒に記録する。** 品質だけ測ると結論が半分になる

## 6. 移行直前の確認

- [ ] フォールバック経路があるか(設定変更だけで戻れるか)
- [ ] 出力フォーマットのパーサーが新モデルの出力でも通るか
- [ ] 拒否の境界が変わって通らなくなった入力がないか
- [ ] ツール呼び出しのスキーマがそのまま効くか
- [ ] 顧客に触れる経路はA/Bだけに留めたか
- [ ] ライセンスの表示義務を製品ドキュメントに反映したか

## 7. 再検討を呼ぶサイン

- ベンダーが**ティアを新しく分けたとき** — 同じ名前の下に単価が複数になる
- **常時割引の表記が消えたとき** — 定価が実際の請求価格になる
- **ピーク料金が施行されたとき** — 底の単価が時間帯で変わる
- **ライセンスが改定されたとき** — 売上しきい値や表示義務が動く
- **自前評価の合格率が落ちたとき** — ベンダーが背後でモデルを更新した可能性

## 8. 覚えておく一行

価格はもはや陣営を分けません。分けるのは**重みを受け取れるか**、そして**その重みで何をしてよいか**です。
