50 Practical iptables Rules - Linux Firewall Examples 2026

10 Scenario Categories x 5 Rules = 50 Ready-to-Apply Examples

May 18, 2026 Tech

Introduction: Why a 50-Rule iptables Cookbook

iptables is the oldest and most battle-tested firewall on Linux. Although nftables is now the default on most distros in 2026, iptables (or iptables-translate) is still in heavy use on RHEL 7/8, embedded gear, and many container hosts. The pain point is that the command syntax is anything but intuitive: one typo and your SSH session is gone, leaving you a trip to the console.

This guide is structured to reduce exactly that risk: 10 scenario categories times 5 rules each = 50 production-ready iptables snippets. Every rule comes with the command, what it does, and when to use it. The focus is not "how the syntax works" but "what should I type for this situation".

1. Base Policy Setup (5 rules)

Every firewall starts here. You must declare an explicit policy (POLICY) so that unintended traffic cannot slip through or accidentally get blocked.

[#1] Default DROP with explicit allow
sudo iptables -P INPUT DROP
sudo iptables -P FORWARD DROP
sudo iptables -P OUTPUT ACCEPT
Meaning: INPUT/FORWARD default-deny, only explicit ACCEPTs pass. OUTPUT remains open.
When: Standard server baseline. Safest starting point.
[#2] Allow ESTABLISHED and RELATED
sudo iptables -A INPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT
Meaning: Allow return traffic of any connection already opened, plus protocol-related flows (FTP-data, etc.).
When: First rule in almost every INPUT chain you will ever write.
[#3] Allow the loopback interface
sudo iptables -A INPUT -i lo -j ACCEPT
sudo iptables -A OUTPUT -o lo -j ACCEPT
Meaning: Permit 127.0.0.1 traffic, which most daemons use for IPC.
When: Register immediately after switching the policy to DROP.
[#4] Drop INVALID packets
sudo iptables -A INPUT -m conntrack --ctstate INVALID -j DROP
Meaning: Discard packets with broken sequence numbers, illegal flag combinations, etc.
When: Basic hygiene; also helps against some port scanners.
[#5] Allow ICMP echo (rate-limited)
sudo iptables -A INPUT -p icmp --icmp-type echo-request -m limit --limit 10/sec -j ACCEPT
Meaning: Reply to ping up to 10/sec, prevent ping flood.
When: Required when NMS or healthchecks use ICMP.
Quick start: open the iptables generator, tick INPUT + ESTABLISHED + loopback and copy the output.

2. SSH Hardening (5 rules)

Roughly half of all server compromises come through port 22. SSH is the first surface to protect.

[#6] Move SSH off port 22 and allow
sudo iptables -A INPUT -p tcp --dport 2222 -j ACCEPT
Meaning: Run SSH on 2222. Dodges roughly 95% of automated scanners.
When: Combine with Port 2222 in sshd_config.
[#7] SSH whitelist (specific IPs only)
sudo iptables -A INPUT -p tcp -s 203.0.113.0/24 --dport 22 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 22 -j DROP
Meaning: Permit SSH from office range only, deny the rest.
When: Strongest SSH defense for static-IP environments (VPN/office).
[#8] SSH brute-force rate limit
sudo iptables -A INPUT -p tcp --dport 22 -m conntrack --ctstate NEW \
    -m recent --set --name SSH
sudo iptables -A INPUT -p tcp --dport 22 -m conntrack --ctstate NEW \
    -m recent --update --seconds 60 --hitcount 4 --name SSH -j DROP
Meaning: Block source IPs that open 4 new SSH connections within 60 seconds.
When: Kernel-level alternative to fail2ban.
[#9] GeoIP country block for SSH
sudo iptables -A INPUT -p tcp --dport 22 -m geoip --src-cc CN,RU,KP -j DROP
Meaning: Drop SSH attempts from listed countries.
When: Internal servers with no need for global reach. Requires the xtables-addons package.
[#10] Port knocking sequence
sudo iptables -N SSH_PHASE2
sudo iptables -A INPUT -p tcp --dport 7000 -m recent --name PH1 --set -j DROP
sudo iptables -A INPUT -p tcp --dport 8000 -m recent --name PH1 --rcheck \
    -m recent --name PH2 --set -j DROP
sudo iptables -A INPUT -p tcp --dport 22 -m recent --name PH2 --rcheck -j ACCEPT
Meaning: SSH only opens after a knock to 7000 then 8000.
When: No static client IP, maximum stealth required.

3. Web Server (HTTP/HTTPS) Hardening (5 rules)

Ports 80/443 must be exposed, so they receive the most attacks. Rate limit and SYN flood defenses are essential.

[#11] Allow 80/443
sudo iptables -A INPUT -p tcp -m multiport --dports 80,443 -j ACCEPT
Meaning: Permit standard HTTP and HTTPS together.
When: Baseline for any public web server.
[#12] Allow only Cloudflare IPs on 80/443
for ip in $(curl -s https://www.cloudflare.com/ips-v4); do
    sudo iptables -A INPUT -p tcp -s $ip -m multiport --dports 80,443 -j ACCEPT
done
sudo iptables -A INPUT -p tcp -m multiport --dports 80,443 -j DROP
Meaning: Block direct-to-origin bypass of the CDN.
When: Cloudflare-fronted services that must hide the origin.
[#13] Per-IP concurrent connection cap (basic DDoS)
sudo iptables -A INPUT -p tcp --dport 80 -m connlimit --connlimit-above 50 -j REJECT
Meaning: Reject if a single source IP holds more than 50 simultaneous connections.
When: First-pass mitigation against HTTP flood bots.
[#14] Slowloris defense
sudo iptables -A INPUT -p tcp --dport 80 -m hashlimit \
    --hashlimit-name http_slow --hashlimit-mode srcip \
    --hashlimit-above 30/min --hashlimit-burst 20 -j DROP
Meaning: Drop traffic exceeding 30 new conns/min per IP, starving slowloris floods.
When: Free Slowloris shield in front of Apache or Nginx.
[#15] SYN flood defense
sudo iptables -A INPUT -p tcp --syn -m limit --limit 1/sec --limit-burst 3 -j ACCEPT
sudo iptables -A INPUT -p tcp --syn -j DROP
Meaning: Allow only 1 SYN/sec with burst 3, drop the rest.
When: Combine with kernel tcp_syncookies.

4. Database Hardening (5 rules)

Databases must never be exposed to the public Internet. iptables is the outermost line of multilayer defense.

[#16] MySQL: deny external + allow app server
sudo iptables -A INPUT -p tcp -s 10.0.1.10 --dport 3306 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 3306 -j DROP
Meaning: Only the app server at 10.0.1.10 can reach MySQL.
When: Baseline for every production DB host.
[#17] PostgreSQL: private subnet only
sudo iptables -A INPUT -p tcp -s 10.0.0.0/16 --dport 5432 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 5432 -j DROP
Meaning: Allow PG access only from the private VPC range.
When: Standard for VPC/VPN-isolated environments.
[#18] Redis 6379: dual defense with bind + iptables
sudo iptables -A INPUT -p tcp ! -s 127.0.0.1 --dport 6379 -j DROP
Meaning: Block 6379 from any source except loopback, regardless of redis.conf bind.
When: Mandatory when Redis runs without authentication.
[#19] MongoDB 27017: full external block
sudo iptables -A INPUT -p tcp --dport 27017 -i ! lo -j DROP
Meaning: Drop 27017 on any interface but loopback.
When: Final safety net to prevent the classic exposed-MongoDB disaster.
[#20] Memcached 11211 whitelist
sudo iptables -A INPUT -p tcp -s 10.0.1.0/24 --dport 11211 -j ACCEPT
sudo iptables -A INPUT -p udp -s 10.0.1.0/24 --dport 11211 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 11211 -j DROP
sudo iptables -A INPUT -p udp --dport 11211 -j DROP
Meaning: Whitelist both TCP and UDP, blocking the UDP amplification vector.
When: Critical wherever Memcached has no authentication.

5. Docker Container Hosts (5 rules)

Docker writes its own iptables rules, which often collide with hand-written policy. The DOCKER-USER chain is the safe insertion point.

[#21] Block Docker daemon ports 2375/2376
sudo iptables -A INPUT -p tcp -m multiport --dports 2375,2376 -j DROP
Meaning: Block remote Docker API. Exposed daemon = instant container takeover.
When: Required on every Docker host.
[#22] Restrict container ingress via DOCKER-USER
sudo iptables -I DOCKER-USER -s 203.0.113.0/24 -j ACCEPT
sudo iptables -I DOCKER-USER -j DROP
Meaning: Only the whitelisted range can reach published container ports.
When: Safe way to layer policy on top of Docker's auto-generated rules.
[#23] Isolate inter-container traffic
sudo iptables -I DOCKER-USER -i docker0 -o docker0 -j DROP
Meaning: Drop traffic flowing directly between containers on the default bridge.
When: Multi-tenant container hosts. Alternative to --icc=false.
[#24] Swarm node-to-node ports (2377/7946/4789)
sudo iptables -A INPUT -p tcp -s 10.0.0.0/24 --dport 2377 -j ACCEPT
sudo iptables -A INPUT -p tcp -s 10.0.0.0/24 --dport 7946 -j ACCEPT
sudo iptables -A INPUT -p udp -s 10.0.0.0/24 --dport 7946 -j ACCEPT
sudo iptables -A INPUT -p udp -s 10.0.0.0/24 --dport 4789 -j ACCEPT
Meaning: Swarm management, gossip and VXLAN overlay traffic among nodes.
When: Open to the swarm subnet, closed externally.
[#25] Container egress restriction (SSRF defense)
sudo iptables -I DOCKER-USER -s 172.17.0.0/16 -d 169.254.169.254 -j DROP
Meaning: Block containers from hitting the cloud metadata endpoint.
When: AWS/GCP hosts where a compromised container could steal IAM credentials.

6. Kubernetes Nodes (5 rules)

Each Kubernetes role has a known set of required ports. Cluster-internal ports must never face the public Internet.

[#26] kube-apiserver 6443 whitelist
sudo iptables -A INPUT -p tcp -s 10.0.0.0/16 --dport 6443 -j ACCEPT
sudo iptables -A INPUT -p tcp -s 203.0.113.5 --dport 6443 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 6443 -j DROP
Meaning: Cluster subnet plus admin IP only.
When: Standard policy for every control-plane node.
[#27] Kubelet 10250 from internal nodes only
sudo iptables -A INPUT -p tcp -s 10.0.0.0/16 --dport 10250 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 10250 -j DROP
Meaning: kubelet API reachable only by the control plane; external exposure leads to privilege escalation.
When: Every worker node.
[#28] NodePort range (30000-32767) restriction
sudo iptables -A INPUT -p tcp -s 10.0.0.0/16 --dport 30000:32767 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 30000:32767 -j DROP
Meaning: NodePort reachable only from the internal LB/Ingress, never directly from the Internet.
When: Standard setup where a LoadBalancer fronts the cluster.
[#29] etcd 2379-2380 cluster-internal
sudo iptables -A INPUT -p tcp -s 10.0.1.0/24 --dport 2379:2380 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 2379:2380 -j DROP
Meaning: etcd only talks among control-plane nodes; exposure leaks cluster secrets.
When: Master nodes (including HA etcd setups).
[#30] CNI overlay traffic (VXLAN 4789, Wireguard 51820)
sudo iptables -A INPUT -p udp -s 10.0.0.0/16 --dport 4789 -j ACCEPT
sudo iptables -A INPUT -p udp -s 10.0.0.0/16 --dport 51820 -j ACCEPT
Meaning: Inter-node tunnel for Flannel/Calico VXLAN or Cilium Wireguard.
When: Enable only the port your CNI actually uses.

7. Mail Server (5 rules)

SMTP ports are pounded relentlessly by spam bots. Sensible rate limits and TLS enforcement are the keys.

[#31] Allow SMTP 25/587/465
sudo iptables -A INPUT -p tcp -m multiport --dports 25,465,587 -j ACCEPT
Meaning: Allow standard mail submission and transport ports.
When: Baseline for Postfix, Exim, etc.
[#32] IMAPS/POP3S only (block plaintext)
sudo iptables -A INPUT -p tcp -m multiport --dports 993,995 -j ACCEPT
sudo iptables -A INPUT -p tcp -m multiport --dports 143,110 -j DROP
Meaning: Allow only the TLS ports; reject plain IMAP and POP3 entirely.
When: Modern mail servers should refuse plaintext.
[#33] SMTP rate limit (anti-spam bots)
sudo iptables -A INPUT -p tcp --dport 25 -m connlimit --connlimit-above 10 -j REJECT
sudo iptables -A INPUT -p tcp --dport 25 -m hashlimit \
    --hashlimit-name smtp --hashlimit-mode srcip \
    --hashlimit-above 5/min --hashlimit-burst 3 -j DROP
Meaning: Cap concurrent SMTP at 10/IP and rate at 5/min/IP.
When: Normal mail flow is unaffected, bots are throttled.
[#34] Dynamic block list with ipset
sudo ipset create spamips hash:ip
sudo iptables -A INPUT -p tcp --dport 25 -m set --match-set spamips src -j DROP
Meaning: Anything added to ipset is dropped instantly. Great for dynamic feeds.
When: rspamd or SpamAssassin can push offenders into the set.
[#35] Restrict outbound 25 to mail user (anti open-relay)
sudo iptables -A OUTPUT -p tcp -m owner --uid-owner postfix --dport 25 -j ACCEPT
sudo iptables -A OUTPUT -p tcp --dport 25 -j DROP
Meaning: Only the postfix user may send to remote 25; web shells and other users cannot.
When: Multi-tenant or shared hosting where compromised web apps must not spam.

8. NAT and Port Forwarding (5 rules)

The nat table powers any router or gateway role. Understanding PREROUTING vs POSTROUTING is non-negotiable.

[#36] Redirect external 80 to internal 8080
sudo iptables -t nat -A PREROUTING -p tcp --dport 80 -j REDIRECT --to-port 8080
Meaning: Rewrite incoming 80 traffic to localhost:8080.
When: Standard trick to bind privileged ports without running the app as root.
[#37] DNAT to a backend host
sudo iptables -t nat -A PREROUTING -p tcp --dport 80 -j DNAT --to-destination 10.0.1.50:80
sudo iptables -t nat -A POSTROUTING -p tcp -d 10.0.1.50 --dport 80 -j MASQUERADE
Meaning: Forward gateway 80 traffic to a backend at 10.0.1.50:80.
When: Lightweight L4 load balancer or reverse proxy substitute.
[#38] MASQUERADE (home router default NAT)
sudo iptables -t nat -A POSTROUTING -o eth0 -s 192.168.0.0/24 -j MASQUERADE
Meaning: Rewrite internal source IPs as the gateway egress address.
When: Linux router or homeserver acting as the WAN gateway.
[#39] SNAT (fixed source IP)
sudo iptables -t nat -A POSTROUTING -o eth0 -s 10.0.0.0/8 -j SNAT --to-source 203.0.113.10
Meaning: Unlike MASQUERADE, explicit source IP. Slightly faster.
When: Preferred where the WAN IP is static.
[#40] 1:1 NAT (external IP ↔ internal IP)
sudo iptables -t nat -A PREROUTING -d 203.0.113.20 -j DNAT --to-destination 10.0.1.20
sudo iptables -t nat -A POSTROUTING -s 10.0.1.20 -j SNAT --to-source 203.0.113.20
Meaning: Map one public IP completely to one private host, bidirectional.
When: DMZ server that needs to appear with its own public address.

9. Logging and Monitoring (5 rules)

Visibility matters as much as blocking. Sensible LOG usage gives you a forensic trail without flooding syslog.

[#41] LOG just before DROP
sudo iptables -A INPUT -m limit --limit 5/min -j LOG --log-prefix "iptables-drop: " --log-level 7
sudo iptables -A INPUT -j DROP
Meaning: Log up to 5/min before dropping. Records land in kern.log or messages.
When: Forensic baseline. The limit prevents log flooding.
[#42] Log every new SSH attempt
sudo iptables -A INPUT -p tcp --dport 22 -m conntrack --ctstate NEW \
    -j LOG --log-prefix "ssh-new: "
Meaning: Capture every brand-new SSH connection (brute force or legit).
When: Required for security audits.
[#43] Log rate-limit triggers
sudo iptables -A INPUT -p tcp --dport 80 -m connlimit --connlimit-above 50 \
    -j LOG --log-prefix "http-flood: "
sudo iptables -A INPUT -p tcp --dport 80 -m connlimit --connlimit-above 50 -j REJECT
Meaning: Log + reject when the flood threshold is hit, so the incident timeline is captured.
When: Tie into Loki/grok pipelines.
[#44] Alert-friendly prefix
sudo iptables -A INPUT -p tcp --dport 22 -m recent --rcheck --seconds 60 --hitcount 4 \
    --name SSH -j LOG --log-prefix "SSHBRUTE-ALERT: "
Meaning: Tag suspicious bursts with a unique prefix that rsyslog/Loki can pattern-match.
When: Centralized logging / SIEM setups.
[#45] NFLOG (userspace logging)
sudo iptables -A INPUT -p tcp --dport 80 -j NFLOG --nflog-group 1 --nflog-prefix "http-in: "
Meaning: ulogd2 reads group 1 and ships entries to PostgreSQL, JSON files, etc.
When: High-volume packet logging without filling dmesg.

10. Emergency and Temporary Blocks (5 rules)

Rules you reach for during an attack or a suspected incident. Pair them with automatic expiry so they do not accumulate forever.

[#46] Instant block of a single IP
sudo iptables -I INPUT 1 -s 198.51.100.45 -j DROP
Meaning: Insert at position 1 so it evaluates before any ACCEPT rule.
When: Block an attacker within seconds of identifying their IP.
[#47] CIDR block (small botnet)
sudo iptables -I INPUT 1 -s 192.0.2.0/24 -j DROP
Meaning: Block an entire range in one shot when many IPs from the same subnet attack.
When: Botnets staged on a single hosting provider.
[#48] Full GeoIP country block
sudo iptables -I INPUT 1 -m geoip --src-cc CN,RU,KP -j DROP
Meaning: Drop every port from listed countries, not just SSH.
When: Internal services that have no global audience. Requires xtables-addons.
[#49] Time-bounded block (auto-expire in 1 hour)
sudo iptables -I INPUT 1 -s 198.51.100.45 -j DROP
echo "sudo iptables -D INPUT -s 198.51.100.45 -j DROP" | at now + 1 hour
Meaning: Use at(1) to remove the rule after 60 minutes, avoiding rule bloat.
When: Temporary blocks for soft suspicions. Requires the at daemon.
[#50] Auto-blocklist with ipset timeout
sudo ipset create blacklist hash:ip timeout 3600
sudo iptables -I INPUT -m set --match-set blacklist src -j DROP
# When you spot an attacker
sudo ipset add blacklist 198.51.100.99 timeout 3600
Meaning: Adding to the set instantly blocks, and the entry expires automatically after 3600 seconds.
When: Integrates cleanly with CrowdSec, fail2ban, or custom scripts.

Operational Caveats

Do not paste all fifty rules at once. Follow this safety order.

  • Don't lock yourself out of SSH: before flipping the policy to DROP, run iptables -I INPUT 1 -p tcp --dport 22 -s YOUR_IP -j ACCEPT. Even on mistakes you keep your shell.
  • Persist your rules: rules live in memory only. Save with iptables-save > /etc/iptables/rules.v4 and use iptables-persistent to restore on boot.
  • Avoid clashes with ufw/firewalld: do not stack two frontends on one box. Pick one, or fully understand how the wrapper writes underlying iptables rules.
  • Plan rollback: snapshot first with iptables-save > /root/iptables.backup.$(date +%F). If something breaks, restore via iptables-restore < /root/iptables.backup.YYYY-MM-DD.
  • Validate visually: use the site's iptables generator to compose rules in a GUI and preview them before applying. This cuts mistakes dramatically.

Conclusion: 50 Rules Is a Starting Point

These fifty rules form a solid baseline for the typical Linux server. Real-world deployments still need tuning for workload, traffic shape, and regulatory context. PCI-DSS environments must log every allow and deny; healthcare servers need a tight allow-list for ePHI access.

The fastest way to master iptables is hands-on: spin up a throwaway VM, apply one category at a time, then deliberately break it. Vagrant, LXC, or Docker all work. Walk through this guide category by category until each pattern is muscle memory.
