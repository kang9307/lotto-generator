Ceph Storage 完全ガイド：Object / Block / FileSystem 機能まとめ

Complete Guide to Ceph Storage: Object, Block, and FileSystem Features

2025-07-09 開発・インフラ

Ceph は、オブジェクト、ブロック、ファイルシステムという 3 種類のストレージを単一のプラットフォームで提供できる、唯一無二の分散ストレージソリューションです。本ガイドでは、Ceph のコアとなる 3 つのストレージ機能を詳しく解説し、それぞれのメリットや実際の導入事例をまとめて紹介します。

English: Ceph is a unique distributed storage solution that provides object, block, and filesystem storage all within a single platform. This guide provides a detailed analysis of Ceph's three core storage features, highlighting their advantages and real-world implementation cases.

🏗️ Ceph ストレージアーキテクチャの概要

Ceph の強力さは、RADOS(Reliable Autonomic Distributed Object Store) をベースとした統合アーキテクチャに由来します。すべてのストレージタイプが同一クラスタ上で動作するため、運用の複雑さを大幅に削減できます。

🗄️ Object Storage: RADOS Gateway (RGW)

主な特徴とメリット

Ceph のオブジェクトストレージは Amazon S3 および OpenStack Swift API に完全対応しており、既存アプリケーションとの互換性を確保しています。

  • S3 API 完全互換: 既存の S3 ベースアプリケーションを改修なしで移行可能
  • ほぼ無制限のスケーラビリティ: ペタバイト級まで線形にスケール
  • マルチテナンシー: テナントごとに分離された名前空間を提供
  • リージョン間レプリケーション: 複数データセンター間での自動レプリケーション機能

実際の構築例

# RADOS Gateway のインストールと設定
sudo ceph-deploy install --rgw ceph-rgw01

# RGW インスタンスの作成
sudo ceph-deploy rgw create ceph-rgw01

# S3 ユーザーの作成
radosgw-admin user create \
  --uid=testuser \
  --display-name="Test User" \
  --email=test@example.com

# バケット作成 (AWS CLI を使用)
aws s3 mb s3://my-test-bucket --endpoint-url=http://rgw-server:7480

パフォーマンス最適化のヒント

設定項目 推奨値 効果
rgw_thread_pool_size 200〜500 同時処理リクエスト数の増加
rgw_cache_enabled true メタデータキャッシュで応答速度が向上
rgw_bucket_index_max_aio 16 バケットインデックスの I/O 性能向上

💽 Block Storage: RADOS Block Device (RBD)

主な特徴とメリット

RBD は、仮想化環境やコンテナオーケストレーションに最適化された高性能なブロックストレージを提供します。

  • シンプロビジョニング: 実使用量に応じた領域割り当て
  • スナップショットとクローン: 即時バックアップと高速コピー機能
  • 暗号化対応: データ保護のための透過的暗号化
  • QoS 制御: IOPS および帯域幅の上限設定機能

実際の活用例

# RBD イメージの作成 (100GB)
rbd create --size 100G mypool/vm-disk01

# スナップショットの作成
rbd snap create mypool/vm-disk01@backup-$(date +%Y%m%d)

# クローンの作成 (VM の即時複製)
rbd snap protect mypool/vm-disk01@backup-20250709
rbd clone mypool/vm-disk01@backup-20250709 mypool/vm-disk01-clone

# カーネルモジュールでマウント
rbd map mypool/vm-disk01
mkfs.ext4 /dev/rbd0
mount /dev/rbd0 /mnt/ceph-volume

📁 FileSystem Storage: CephFS

主な特徴とメリット

CephFS は POSIX 互換の分散ファイルシステムで、大容量ファイル共有や並列処理に優れています。

  • POSIX 完全互換: 既存の Linux アプリケーションと 100% 互換
  • 動的メタデータ分散: メタデータサーバ間で負荷を自動分散
  • マルチアクティブ MDS: メタデータサーバの冗長化により高可用性を確保
  • サブボリューム対応: 論理ディレクトリの分離とクォータ管理

実際の構築手順

# MDS サーバのデプロイ
ceph-deploy mds create ceph-mds01 ceph-mds02

# CephFS ファイルシステムの作成
ceph osd pool create cephfs_data 128
ceph osd pool create cephfs_metadata 64
ceph fs new cephfs cephfs_metadata cephfs_data

# クライアントでのマウント (カーネルドライバ)
mount -t ceph 192.168.1.10:6789:/ /mnt/cephfs \
  -o name=admin,secret=AQD4...

# FUSE マウント (ユーザー空間)
ceph-fuse /mnt/cephfs-fuse \
  --name client.admin \
  --keyring /etc/ceph/ceph.client.admin.keyring

サブボリューム管理

# サブボリュームグループの作成
ceph fs subvolumegroup create cephfs group1

# サブボリュームの作成 (100GB のクォータ付き)
ceph fs subvolume create cephfs vol1 --group_name group1 --size 100G

# ユーザー単位のアクセス権限設定
ceph fs authorize cephfs client.user1 \
  /volumes/group1/vol1 rw

🌟 ストレージタイプ別のおすすめ活用シナリオ

Object Storage (RGW) のおすすめ用途

  • Web アプリケーション: 画像、動画、静的コンテンツの保存
  • バックアップとアーカイブ: 長期保管が必要なデータ
  • ビッグデータ分析: データレイクの構築
  • クラウドネイティブアプリ: マイクロサービス間のデータ共有

Block Storage (RBD) のおすすめ用途

  • 仮想マシン: VM ディスクおよびブートボリューム
  • データベース: 高性能が求められるトランザクションワークロード
  • コンテナ: Kubernetes Persistent Volume
  • ハイパフォーマンスコンピューティング: HPC アプリケーション向けストレージ

File System (CephFS) のおすすめ用途

  • 共有ワークスペース: 開発チームのコラボレーション環境
  • メディア処理: 映像編集やレンダリング
  • ログ集約: 中央集約型のログストレージ
  • ホームディレクトリ: ユーザーごとのファイルサービス

  mon 'allow r' \
  osd 'allow rw pool=mypool' \
  mds 'allow rw path=/myapp-data'

#!/bin/bash
# Ceph ヘルス状態チェックスクリプト

HEALTH=$(ceph health -f json | jq -r '.status')
DATE=$(date '+%Y-%m-%d %H:%M:%S')

if [ "$HEALTH" != "HEALTH_OK" ]; then

fi
