Inkling 공개 - 미라 무라티의 Thinking Machines Lab이 낸 975B 오픈웨이트 MoE 모델

처음부터 학습해 가중치를 전부 공개한 프론티어 모델 - MoE 구조와 오픈웨이트의 의미를 짚는다

2026-07-17 IT/기술

이 게시물은 쿠팡 파트너스 활동의 일환으로, 이에 따른 일정액의 수수료를 제공받습니다.

서론: 오픈웨이트로 등장한 미라 무라티의 첫 프론티어 모델

2026년 7월 15일, 전 OpenAI 최고기술책임자(CTO) 미라 무라티가 2025년 2월 창업한 Thinking Machines Lab이 첫 프로덕션 언어 모델 Inkling을 공개했다. 헤드라인은 두 가지다. 총 975B(9,750억) 파라미터에 토큰당 41B(410억)만 활성화되는 Mixture-of-Experts(MoE) 트랜스포머라는 점, 그리고 이 모델을 처음부터 직접 학습시켜 가중치 전체를 공개했다는 점이다.

Thinking Machines Lab은 그동안 파인튜닝 플랫폼 Tinker로 먼저 이름을 알렸다. 자체 프론티어 모델 없이 남의 모델을 미세조정해 주는 인프라 회사로 시작한 셈이다. Inkling은 이 회사가 처음 내놓은 자체 파운데이션 모델이라는 점에서, 단순한 신모델 출시를 넘어 회사의 정체성이 한 단계 바뀌는 사건이다. 이 글은 hada.io에 소개된 이 소식을 계기로, Inkling이 무엇이고 왜 지금 이런 형태로 나왔는지를 본인 관점에서 분석한다. 2026년 7월 기준 공개된 자료와 벤치마크를 근거로 하며, 과장 없이 검증 가능한 것만 다룬다.

1. Thinking Machines Lab과 Inkling - 무엇이 나왔나

1.1 미라 무라티의 두 번째 승부수

Thinking Machines Lab은 2025년 2월, 미라 무라티가 OpenAI를 떠난 지 몇 달 만에 존 슐만·배럿 조프·릴리안 웽·앤드류 털록·루크 메츠 등 OpenAI 출신 핵심 인력과 함께 창업했다. 창업 직후인 2025년 6월 안드리센 호로위츠 주도로 20억 달러를 유치하며 기업가치 100억 달러를 인정받았고, 이후 500억 달러 밸류에이션 투자 협상 보도까지 나올 만큼 빠르게 몸집을 키웠다. 그만큼 이번 Inkling 출시는 "무라티가 실제로 프론티어급 모델을 만들 수 있는가"라는 시장의 질문에 대한 첫 실물 답변이라는 무게를 가진다.

1.2 Inkling 핵심 사양

Inkling은 66층 디코더 기반 트랜스포머로, 각 MoE 레이어마다 256개의 라우팅 전문가와 2개의 공유 전문가를 두고 토큰마다 6개의 라우팅 전문가를 골라 쓴다. 텍스트·이미지·오디오·영상을 아우르는 45조 토큰으로 처음부터 사전학습됐고, 이후 3천만 회 이상의 롤아웃을 동원한 대규모 비동기 강화학습으로 후속 학습됐다. 컨텍스트는 Hugging Face 공개 가중치 기준 최대 1M(100만) 토큰이며, Tinker API에서는 64K·256K 옵션으로 제공된다. 추론 노력(reasoning effort)은 0.2~0.99 사이에서 조절할 수 있어, 쉬운 질문엔 짧게 답하고 어려운 문제엔 더 깊이 사고하도록 비용과 성능을 저울질할 수 있다. 더 가벼운 Inkling-Small(총 276B·활성 12B) 프리뷰도 함께 공개됐다.

2. MoE(Mixture of Experts)란 무엇인가 - 975B 총, 41B 활성의 의미

2.1 "전체"와 "실제로 쓰는 부분"의 분리

일반적인(dense) 트랜스포머는 질문 하나를 처리할 때 모델이 가진 파라미터 전부를 계산에 동원한다. MoE는 다르다. 모델 내부에 여러 개의 "전문가(expert)" 서브네트워크를 두고, 라우터가 토큰마다 그중 일부만 골라 활성화한다. Inkling의 경우 전체 저장된 지식·능력은 975B 파라미터에 담겨 있지만, 실제로 한 토큰을 계산할 때 동원되는 것은 41B뿐이다. 나머지는 필요할 때만 불려 나오는 대기 상태다.

2.2 왜 이 구조를 쓰는가 - 효율과 서빙 비용

이 구조의 이점은 명확하다. 모델의 표현력(총 파라미터, 975B)은 크게 키우면서도 실제 추론 연산량(활성 파라미터, 41B)은 그보다 훨씬 작은 모델 수준으로 유지할 수 있다. 즉 "큰 지식 창고"와 "빠른 응답 속도"를 동시에 노릴 수 있다는 뜻이다. 서빙 비용 관점에서는 41B 활성 규모에 준하는 연산 자원으로 975B급 모델의 폭넓은 능력을 제공할 수 있어, dense 975B 모델을 그대로 굴리는 것보다 훨씬 저렴하게 서비스할 수 있다. 다만 대가도 있다. 975B 전체를 메모리에 올려두어야 하므로, 활성 파라미터는 작아도 필요한 GPU 메모리 총량은 41B급 dense 모델보다 훨씬 크다. 이 때문에 "연산은 가볍지만 메모리는 무거운" 모델이라는 표현이 정확하다. Inkling의 라우터는 sigmoid 기반이며, 특정 전문가로 쏠림 없이 부하를 고르게 분산시키는 보조손실 없는(auxiliary-loss-free) 방식을 쓴다고 밝혀졌다. MoE의 고질적 문제인 전문가 쏠림을 완화하려는 최신 설계다.

3. 1M 컨텍스트와 멀티모달의 실용 가치

3.1 100만 토큰이 바꾸는 작업 방식

Hugging Face에 공개된 가중치는 최대 1M 토큰 컨텍스트를 지원한다. 이 정도 분량이면 중간 규모 코드베이스 전체나 두꺼운 책 여러 권을 한 번에 넣고 질의할 수 있다. 문서를 조각내지 않고 전체 맥락 위에서 답하게 하려는 워크로드, 예컨대 리포지토리 전반 분석이나 방대한 로그·계약서 검토에서 실질적 차이를 만든다. 다만 Tinker API 제공 컨텍스트는 64K·256K로 더 작다는 점은 유의해야 한다. 1M 토큰을 실제로 쓰려면 Hugging Face 가중치를 자체 호스팅하는 경로가 필요하다.

3.2 텍스트·이미지·오디오 네이티브 처리

Inkling은 텍스트뿐 아니라 이미지와 오디오를 별도 변환 모듈 없이 기본으로 이해하고 추론하도록 설계됐다. 이는 이미지를 캡션으로 바꿔 텍스트 모델에 넣거나, 음성을 텍스트로 변환한 뒤 처리하는 파이프라인 방식보다 정보 손실이 적다. 회의 녹음, 스크린샷이 섞인 문서, 이미지가 포함된 리포트처럼 여러 형식이 뒤섞인 실무 입력을 하나의 모델로 처리할 수 있다는 의미다.

4. '오픈웨이트'의 정의 - 오픈소스와 다른 이유

4.1 가중치 공개 ≠ 완전한 오픈소스

Inkling의 가중치는 Apache 2.0 라이선스로 Hugging Face에 공개됐다. Apache 2.0 자체는 상업적 사용·수정·재배포를 폭넓게 허용하는 관대한 라이선스다. 그러나 오픈소스 이니셔티브(OSI)가 2024년 10월 확정한 오픈소스 AI 정의(OSAID) 기준으로 보면, 완전한 오픈소스가 되려면 가중치뿐 아니라 학습 코드와 학습 데이터에 대한 충분한 문서화까지 공개돼 재현 가능해야 한다. Inkling은 45조 토큰 규모의 학습 데이터 구성이나 학습 코드를 공개하지 않았다. 따라서 정확히 말하면 Inkling은 오픈소스 모델이 아니라 오픈웨이트 모델이다. 이 구분은 Llama, DeepSeek, Qwen, Gemma 등 2026년 "오픈소스"로 통칭되는 모델 대부분에 똑같이 적용되는 업계 전반의 특징이다.

4.2 실무자에게 중요한 이유

이 차이는 철학적 논쟁에 그치지 않는다. 라이선스 조항에 따라 상업적 이용 범위, 파생 모델 재배포 조건, 특정 용도 제한이 갈린다. 예컨대 Llama 계열은 개방적이라 불리지만 실제로는 수용 가능 사용 정책(acceptable use policy)으로 특정 상업적 활용을 제한하는 반면, Apache 2.0을 택한 Mistral·DeepSeek·Qwen 계열, 그리고 이번 Inkling은 상업 이용 제약이 훨씬 적은 편에 속한다. 재현성 측면에서도, 학습 데이터가 공개되지 않으면 모델이 왜 특정 답을 내는지, 어떤 편향이 데이터에서 왔는지 외부에서 검증하기 어렵다. 오픈웨이트를 "완전히 투명한 AI"로 오해하지 않는 것이 실무의 첫 단추다.

5. 2026 오픈웨이트 경쟁 지형 - Llama·Qwen·DeepSeek·GLM과 비교

5.1 지형: 중국 오픈웨이트가 주도하던 흐름

2026년 상반기 오픈웨이트 경쟁은 사실상 중국 랩들이 주도해 왔다. DeepSeek은 가격 파괴로, Qwen은 가장 넓은 라인업과 관대한 라이선스로, Kimi(Moonshot)는 에이전트 코딩 특화로, GLM(Zhipu)은 서구 폐쇄형 모델과 맞먹는 장기 코딩 성능으로 각자의 영역에서 앞서 왔다. 반면 미국계 오픈웨이트 진영은 Meta의 Llama, Nvidia의 Nemotron, Google의 Gemma 정도가 대표주자였고, 중국 모델 대비 존재감이 상대적으로 약했다. 유럽계 Mistral도 관대한 라이선스로 한 축을 이루지만 최상위권 성능 경쟁에서는 다소 밀린다.

5.2 Inkling의 위치 - "미국 오픈웨이트 선두", 그러나

Artificial Analysis Intelligence Index 기준 Inkling은 41점을 기록해, 기존 미국 오픈웨이트 선두였던 Nemotron 3 Ultra(38점)를 앞질렀고 Gemma 4 31B(29점)·gpt-oss-120b(24점)보다도 높다. 에이전트 작업 지표(GDPval-AA v2)에서도 1238 Elo로 Kimi K2.6(1190)·DeepSeek V4 Flash(1189)를 앞섰고, 적대적 프롬프트 방어 지표(FORTRESS Adversarial)에서는 78.0%로 비교군 중 최고치를 기록했다. 이 점에서 "Llama 3 이후 가장 경쟁력 있는 비중국계 오픈웨이트 모델"이라는 평가는 근거가 있다. 하지만 전 영역 우위는 아니다. 코딩·장기 작업 지표인 Terminal Bench 2.1에서는 63.8%로 GLM 5.2의 82.7%에 크게 못 미쳤고, HLE·AIME 2026·SWE-Bench Verified 등에서도 GLM 5.2·Kimi K2.6에 뒤처지는 결과가 보고됐다. 즉 Inkling은 "미국 오픈웨이트 중 최고"이지 "오픈웨이트 전체 1위"는 아니다.

6. 개발자·기업이 오픈웨이트를 택하는 이유

6.1 자체호스팅과 프라이버시

가중치를 직접 보유하면 프롬프트와 데이터가 외부 API 서버를 거치지 않는다. 규제 산업, 사내 코드·문서를 다루는 팀에는 이 자체가 결정적 이점이다. Inkling은 TogetherAI, Fireworks, Modal, Databricks, Baseten 등 여러 서드파티 API로도 제공되지만, Apache 2.0 가중치가 있으므로 이들을 거치지 않고 완전히 자체 인프라에서 운영하는 선택지도 열려 있다.

6.2 파인튜닝과 비용 구조

Thinking Machines Lab은 Inkling을 Tinker 플랫폼과 함께 내놓으며 미세조정을 전면에 내세웠다. 자체 데이터로 파인튜닝해 도메인 특화 모델을 만들 수 있고, 이 경우 매 요청마다 토큰 단가를 내는 API 방식과 달리 비용 구조를 보유 하드웨어 기준으로 바꿀 수 있다. Tinker는 출시 기념 한시적 50% 할인까지 제공해, 파인튜닝 진입장벽을 낮추려는 의도가 뚜렷하다. 다만 975B 규모 모델을 자체 운영하려면 상당한 GPU 메모리가 필요하므로, 소규모 팀에는 API 경유나 Inkling-Small(276B·활성 12B) 쪽이 현실적이다.

7. 한계와 검증이 필요한 지점

7.1 할루시네이션 63%라는 숫자

가장 눈에 띄는 경고 신호는 벤치마크에 보고된 할루시네이션 비율 63%, 정확도 40%라는 수치다(AA-Omniscience 계열 지표 기준). 이는 사실관계가 중요한 작업, 특히 법률·의료·금융처럼 오답의 대가가 큰 영역에서는 Inkling의 답변을 그대로 신뢰해서는 안 된다는 뜻이다. Thinking Machines Lab 스스로도 프로젝트 페이지에서 롤플레이·간접 프롬프트 인젝션을 잔존 안전 위험으로 명시했고, 충실성(faithfulness)을 학습 목표로 명시적으로 넣었다고 밝혔지만, 이는 위험을 줄이려는 시도이지 해결됐다는 보증은 아니다.

7.2 벤치마크는 아직 혼재

Inkling은 미국 오픈웨이트 중에서는 앞서지만, GLM 5.2·Kimi K2.6 같은 중국 오픈웨이트 상위권과 비교하면 코딩·장기 추론 지표에서 뒤처지는 항목이 여럿이다. "미국 최고"라는 프레이밍에 매몰되지 않고, 본인의 실제 과제(코딩, 문서 요약, 에이전트 작업 등)에서 직접 골든 셋으로 검증하는 것이 안전하다.

결론: 오늘 확인해야 할 것

Inkling은 미라 무라티의 Thinking Machines Lab이 내놓은 첫 프론티어급 오픈웨이트 모델이라는 점에서 상징적 사건이다. 975B 총·41B 활성의 MoE 구조는 큰 지식 용량과 상대적으로 가벼운 추론 비용을 동시에 노리는 합리적 설계이고, 1M 컨텍스트와 텍스트·이미지·오디오 멀티모달은 실무에서 바로 체감할 수 있는 강점이다. Apache 2.0 오픈웨이트 공개는 자체호스팅·파인튜닝·프라이버시가 중요한 팀에 실질적 선택지를 넓혀준다.

동시에 이 글은 과장하지 않는다. Inkling은 미국 오픈웨이트 진영에서는 선두이지만 GLM 5.2·Kimi K2.6 등 중국 오픈웨이트 최상위권과 비교하면 여전히 뒤처지는 지표가 있고, 63%에 달하는 할루시네이션 비율은 실무 도입 전 반드시 본인 데이터로 검증해야 할 대목이다. "오픈웨이트"라는 말이 곧 "완전히 투명하고 무결한 모델"을 뜻하지 않는다는 점도 기억할 필요가 있다. 2026년 오픈웨이트 경쟁은 이제 미국과 중국 양쪽에서 동시에 가속하고 있으며, Inkling은 그 경쟁에 미국 쪽 선수가 본격적으로 합류했다는 신호로 읽는 것이 정확하다.
