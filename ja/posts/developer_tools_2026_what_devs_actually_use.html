序論：2026年の開発者ツールの地形

開発者に「どんなツールを使っていますか？」と尋ねるのは、単なる好奇心ではありません。その答えには、その人のワークフロー、価値観、そして一日の過ごし方が映し出されます。2026年5月末、韓国の技術コミュニティnews.hada.ioに投稿された「好きな開発者ツールは何ですか？」というトピックが38ポイントを集め活発な議論を生んだのも、同じ理由です。人は自分のセットアップを見せたがり、同時に他人が何を使っているかを絶えず知りたがります。

しかし2026年のツールの地形は、わずか2〜3年前と決定的に異なります。最大の変化は、AIが別個のカテゴリではなく、ほぼすべてのカテゴリに浸透したことです。エディタにはAI補完とエージェントが入り、ターミナルはコマンド提案を備え、データベースツールにもAI機能が加わりつつあります。「AIツールを使っているか」という問いは、いまや「エディタを使っているか」と同じくらい意味を失いました。本当の問いは「どのツールを、どの深さで、どう組み合わせるか」へ移ったのです。

本稿はその問いに答える分類別の整理です。コードエディタ、AIコーディング、ターミナル、バージョン管理、API/HTTP、コンテナ、データベース、ノート、監視、ユーティリティまで10のツール分類を順に巡り、韓国の開発環境の特徴、ツール選びの5原則、そして最後にどんな状況でどの分類のツールが使われるかを整理します。人気順位の羅列ではなく、「なぜこのツールがこの位置にあるのか」を併せて説明することが目標です。

利用率の数値は出典を確認できたものだけを載せました。2026-09-29時点で結果を確認できる最新の大規模公開調査は、Stack Overflow 2025 Developer Survey（2025年収集、回答者約49,000人）です。2026年調査は2026年6月23日に回答受付を始めたとStack Overflow公式ブログが告知しましたが、結果は今回の確認では見つかりませんでした。以下の数値はすべて複数回答の設問における全回答者に対する割合です。

1. コードエディタ - VS Code, Cursor, Zed, Neovim, JetBrains

あらゆるワークフローの中心にはエディタがあります。2026年のエディタの地形は「VS Codeが既定値、その周りにAI時代の挑戦者たち」という構図に整理されます。

VS Codeは依然として既定値です。Stack Overflow 2025調査の開発環境（IDE）の設問で、全回答者の75.9%がVS Codeを使っていると答えました。膨大な拡張エコシステム、安定性、そしてCopilotやClaude Code連携といったAI拡張を載せられる点から、チーム標準が必要な組織にとって無難な選択肢であり続けています。

CursorはVS Codeフォークなので拡張互換を保ちつつ、エディタ自体がAIを一級市民として扱います。同じ調査でCursorは17.9%でした。公開当時は「最も速くシェアを伸ばした」と書きましたが、伸び率を示す一次資料を確認できなかったため、その表現は削除しました。名前には注意が必要です。公開当時の本稿はComposerをマルチファイル編集機能の名前として紹介しましたが、Cursor公式ブログは2025年10月29日、自社のエージェントモデルをComposerという名前で発表しました。資料を読むときは、機能とモデルのどちらを指しているかを見分ける必要があります。

ZedはRustで書かれたオープンソースのエディタで、公式サイトは自らを「速度と、人間およびAIとの協業のために作られたミニマルなコードエディタ」と紹介しています。現在はmacOS・Linux・Windows向けのダウンロードを提供し、Agent Client Protocol（ACP）を通じてClaude Agent・Codex・OpenCodeといった外部エージェントをエディタ内で使えるとしています。同じ調査でZedは7.3%、Neovimは14%、IntelliJ IDEAは27.1%でした。Neovimはターミナル中心のワークフローを守る開発者の選択で、LazyVimのようなディストリビューションで参入障壁が大きく下がりました。JetBrains（IntelliJ, PyCharm, GoLandなど）は大規模エンタープライズのJava/Kotlin、緻密なリファクタリングやデバッグが必要な領域で使われます。

2. AIコーディング - Claude Code, Codex, Cursor, Copilot, Aider

2026年で最も速く変化しているカテゴリです。重要なのは「どれが最高か」ではなく、作業の種類ごとに合う分類が異なるという事実です。大きく三つに分かれます。指示を受けてリポジトリ全体の複数ファイルを直すエージェント型、エディタ内で変更を見ながら編集するエディタ統合型、入力中に次のコードを提案する補完型です。ただし以下のとおり、一つの製品が複数の型を兼ねるようになり、境界は曖昧になりました。

Claude Codeはターミナルから始まったエージェント型ツールで、大規模なマルチファイルリファクタリング、コードベース探索、反復作業の自動化に使われます。公式ドキュメントは現在、ターミナルCLI、IDE拡張（VS Code・JetBrains）、デスクトップアプリ、Webで使えると案内し、ほとんどの利用環境でClaudeのサブスクリプションまたはAnthropic Consoleのアカウントが必要だとしています。OpenAI Codexも同じ方向です。OpenAIのドキュメントはCodexをデスクトップアプリ、Web、CLI、IDE拡張、クラウド環境、GitHub連携で使えると案内しています。公開当時「ターミナルエージェント」とまとめた二つのツールは、いまや複数の画面にまたがっています。モデルを替えるときに既存のプロンプトや設定を移す問題は設定をそのまま引き継ぐと起きることで、エージェントに計画を任せるやり方は計画モードは死んだのかで別に扱いました。

Cursorはエディタ内でコンテキストを保ち、変更を視覚的に確認しながら作業したい場合に使われます。GitHub Copilotには無料プラン（Copilot Free）と複数の有料プランがあり、GitHubのドキュメントはエージェントモードが無料プランから含まれると記しています。公開当時「補完中心の軽い補助」とだけ紹介したのは、現在の基準では狭い説明です。AiderはGit diffベースのミニマルCLIツールで、変更をコミット単位で残します。ただしGitHubのリリース一覧の最新は2025年8月9日のv0.86.0で、2026-09-29の確認時点までその後のリリースはありませんでした。新たに導入するなら、リポジトリの最近の活動をまず確認するほうが安全です。

実務のヒント：AIコーディングツールは一つで終わらないことが多いです。リポジトリ全体に触れる大きな作業はエージェント型、画面を見ながら直す編集はエディタ統合型、入力の補助は補完型というように作業単位で分類を分けてみると、何が欠けているかが見えます。一つのリポジトリで複数のエージェント作業を同時に走らせるなら、作業フォルダを分ける方法を扱ったgit worktree 実践ガイドが役立ちます。

3. ターミナル - Warp, Ghostty, iTerm2, Alacritty

ターミナルは長らく停滞したカテゴリでしたが、ここ数年で大きく変わりました。WarpはブロックベースのUIとAIコマンド提案で「ターミナルを再設計した」ツールとして注目され、現在の公式サイトでは自らを「エージェント型開発環境（the agentic development environment）」と紹介しています。ターミナルから出発し、エージェントを動かす環境へと重心を移したわけです。Ghosttyは2024〜2025年に登場したGPU加速ターミナルで、公式ドキュメントは「速く、機能が豊富で、ネイティブな」ターミナルエミュレータと説明し、現在はmacOSとLinuxに対応しています。

iTerm2はmacOSユーザーの長年の標準で、豊富な機能と安定性が強みです。AlacrittyはRustベースのミニマルGPUターミナルで、「速くて単純なもの」を求める人の選択です。ターミナル選びの核心は結局、速度、カスタマイズ自由度、そしてtmuxやシェル設定との相性です。

4. バージョン管理 - Git, GitHub, GitLab, Jujutsu (jj)

基盤は変わらずGitです。Stack Overflow 2025調査のコード文書化・協業ツールの設問では、GitHubが81.1%、GitLabが35.6%でした（ホスティングだけを問う設問ではありません）。自前ホスティングと統合CI/CDが必要な組織はGitLabを選ぶこともあります。注目すべきツールはJujutsu (jj)です。公式リポジトリはjjを「Git互換で、単純かつ強力なバージョン管理システム」と紹介しています。2026-09-29時点でGitHubのリリース一覧の最新版は0.45.1で、まだ1.0前です。

jjの魅力は「すべての変更が自動的にコミットされ、コンフリクト解決と履歴の書き換えがはるかに直感的」という点です。まだ1.0前なのでチーム標準にする前に試験が必要ですが、Gitの複雑なコマンド体系に疲れた開発者なら一度試す価値があります。

5. API/HTTP - curl, Postman, Insomnia, Bruno

APIテストとHTTPリクエストはバックエンド・フルスタック開発者の日常です。最も軽いツールは依然としてcurlです。素早い単発リクエストはcurl一行が最も効率的ですが、オプションが増えるほどコマンド作成が煩雑になります。そこでBrainDetoxのcurl Builderのような無料オンラインツールでヘッダー・メソッド・ボディのオプションを視覚的に組み立て、コマンドをそのままコピーすればミスを減らせます。

GUIが必要なとき、Postmanはチーム協業とコレクション共有の機能を幅広く備えていますが、2026年3月に料金プランがFree・Solo・Team・Enterpriseに変わり、公式ドキュメント上、無料プランは1ユーザーに限定されチームを作成できなくなりました。2人以上で無料でコレクションを共有していたやり方には、いまは有料プランが必要です。オープンソースでローカル優先のBrunoにはオープンソース版と有料版（Pro・Ultimate）があり、料金表ではアプリ内のGit連携（Native Git Integration）は有料版の項目です。Insomniaには無料プラン（Essentials）があり、ログイン不要のローカル専用Scratch Padを提供しています。

6. コンテナ／オーケストレーション - Docker, Podman, k9s, Lens

コンテナはもはや選択ではなく基本です。Stack Overflow 2025調査では、Dockerを使うという回答が全体の71.1%でした。デーモンレス・ルートレス構造とライセンス条件を理由にPodmanを使う環境もあります。公開当時は「Podmanへ移る流れが明確で、企業環境で採用が増えた」と書きましたが、それを示す一次資料を確認できなかったため、その表現は削除しました。

Kubernetesを扱うなら、ターミナルベースのクラスタ管理ツールk9sがよく使われます。キーボードだけでPod・ログ・リソースを素早く探索でき、ターミナル中心の運用に合います。GUIを好むならLensがマルチクラスタ管理に便利です。

7. データベースツール - DBeaver, TablePlus, DataGrip

データベースクライアントは好みが強く分かれる領域です。DBeaverは無料・オープンソースでほぼすべてのDBMSに対応し、汎用クライアントとして通用します。TablePlusは速くすっきりしたUIでmacOSユーザーに選ばれ、軽い作業に特に快適です。DataGripはJetBrainsエコシステムのユーザーに自然な選択で、緻密なSQL補完とリファクタリングが強みです。JetBrainsは2025年10月1日の公式ブログで、DataGripを学習・趣味・オープンソース・コンテンツ制作といった非商用の用途に無料で提供すると発表しました。業務（商用）利用には引き続き有料ライセンスが必要です。

DataGripの発表がAIによるコード補完を機能として挙げているように、データベースツールにも自然言語でのクエリ生成やスキーマ説明といったAI機能が入りつつあります。ツールごとの対応範囲は今回確認していません。SQLを直接書く時間が減り、レビューして磨く時間が増える変化が進行中です。

8. ノート／ドキュメント - Obsidian, Notion, Logseq

知識管理は生産性の隠れた軸です。ObsidianはローカルMarkdownファイルベースに強力なリンク・グラフ機能を加え、データ所有権を重視する開発者に使われています。2025年2月20日から商用ライセンスが任意となり、業務でも無料で使えます（Obsidian公式ブログ）。プラグインエコシステムが膨大で、ほぼあらゆるワークフローをカスタマイズできます。

Notionはチーム協業・データベース・Wikiが一カ所に集まるオールインワンで、ドキュメントとプロジェクト管理を統合したいチームに強いです。Logseqはアウトライナーベースのオープンソースツールで、デイリーノートと双方向リンク中心の思考整理に特化しています。選択の基準は結局「自分のデータを誰が握るか」と「一人 vs チーム」です。

9. 監視／デバッグ - Sentry, Datadog, Grafana

本番を運用するなら可観測性ツールは必須です。Sentryはエラートラッキングと性能監視で広く使われるツールで、少ない設定で素早く例外とスタックトレースを収集します。Datadogはインフラ・APM・ログ・セキュリティを横断する統合プラットフォームで、規模ある組織の総合可観測性ハブの役割を果たします。

GrafanaはPrometheusやLokiと組み合わせたオープンソース可視化の中心です。メトリクスダッシュボードを自分で構成したいインフラ・SREエンジニアの核心ツールです。コストとロックインを避けつつ自分で統制したいならGrafana + Prometheusのようなオープンソーススタックが、素早いSaaS統合を望むならDatadogのような統合プラットフォームが合います。

10. ユーティリティ - JWTデコーダ, JSON/YAML変換

毎日使うわけではないが、いざ必要なときに無いと困る小さなツールがあります。JWTトークンのペイロードを開く、JSONとYAMLを相互変換する、HTTPステータスコードの意味を素早く確認する、といった作業です。これらに重いIDEや別途インストールのツールを起動するのは非効率です。

軽い無料オンライン代替として、BrainDetoxのJWT Decoder、YAML/JSON変換、HTTPステータスコード参照、JSONフォーマッタなどを使えば、ブラウザで即座に処理できます。インストール不要で、データをサーバーへ送らずクライアントで処理されるツールを選ぶことは、セキュリティ面でも安全です。

11. 韓国の開発者が好むツール

グローバルな流れとは別に、韓国の開発エコシステムには特有の環境があります（本節は韓国の状況です）。第一に、協業メッセンジャーはSlackとともにKakaoWorkやJANDIなどの韓国製ツールが企業環境で使われています。第二に、課題管理ではJiraが長く使われてきており（Stack Overflow 2025調査の全世界の回答で46.4%）、スタートアップではLinearやNotionを使う例もあります。韓国だけのツール別比率を示す公開調査は今回確認できませんでした。

第三に、韓国の開発者コミュニティ（news.hada.io、OKKY、Inflearnなど）はツール情報共有の核心チャネルで、新ツールが国内で知られる経路になっています。第四に、社内セキュリティ方針でクラウドSaaSの利用が制限される環境が多く、ローカル・オープンソース・オンプレミスの代替（GitLab自前ホスティング、ローカルLLMなど）がよく検討対象に上がります。公開当時はこの関心が「グローバル平均より高い」と書きましたが、比較の数値を確認できなかったため削除しました。ツール選びで「データがどこへ行くか」を問うことが重要である点は変わりません。

12. 2026年のツール選び5原則

ツールは人気順位で選ぶものではありません。自分のボトルネックから出発する五つの原則を勧めます。

  1. 慣れの惰性を認めつつ、年に一度は再評価する。手に馴染んだツールは強力な資産ですが、定期的に主要ツールを点検しなければ、より良い代替を永遠に見逃します。
  2. 統合コストを考える。ツールを増やす前に既存ツールで解決可能か先に確認します。ツールが増えるほどコンテキスト切り替えコストが大きくなります。
  3. ロックインを警戒する。データエクスポートとオープンフォーマットを優先します。特定ベンダーにデータが縛られると、移行の自由を失います。
  4. チーム標準と個人の好みを分ける。協業に影響するツール（VCS、CI、課題管理）はチーム標準を、個人の生産性ツール（エディタ、ターミナル、ノート）は好みに従ってかまいません。
  5. 無料・オープンソースの代替を先に試す。有料へ進む前に無料の代替で要件を検証すれば、本当に必要な機能にだけお金を使えます。無料プランの人数や機能の条件は変わりうるので（2026年3月のPostmanの例）、導入前に現在の条件を確認してください。

13. 結論：状況別に使われるツールの分類

結局、良いスタックは流行ツールの合計ではなく、自分のワークフローの摩擦を最も減らす組み合わせです。ツール自体が目的になった瞬間、ツールのセットアップに追われて本来作るべきものを作れない罠に陥ります。上の10分類すべてを埋める必要もありません。自分がよく詰まる地点から一つずつ最適化すればよいのです。

特定の製品を選ぶ代わりに、どんな状況でどの分類のツールが使われるかで整理すると次のとおりです。括弧内の名前は本文に出てきた例にすぎず、順位ではありません。

  • エディタ：チーム標準と拡張エコシステムが重要なら汎用エディタ（VS Code）、AIによる編集の比重が大きければAI統合エディタ（Cursor、Zed）、大規模なJava/Kotlinプロジェクトは統合IDE（JetBrains）
  • AIコーディング：リポジトリ全体の作業はエージェント型、画面を見ながら直す編集はエディタ統合型、入力の補助は補完型。使う製品がどの型まで兼ねているかをまず確認
  • ターミナル：速度と単純さが優先ならGPU加速の軽量ターミナル、エージェントの実行まで一つの画面で扱いたいならエージェント型開発環境、セッション維持はtmuxのようなマルチプレクサ
  • バージョン管理：Git + ホスティング（GitHub・GitLab）、新しいワークフローの実験はGit互換VCS（jj、1.0前）
  • API：単発リクエストはcurl（+ オンラインcurl Builder）、複数人でGUIを使うなら無料プランの人数条件をまず確認
  • コンテナ：ローカル開発はコンテナランタイム（Docker・Podman）、Kubernetes運用はターミナルUI（k9s）またはGUI（Lens）
  • DB：複数のDBMSを一つのツールで扱うなら汎用クライアント、非商用でIDE級の機能が必要ならDataGripの無料条件を確認
  • ノート：データ所有権が優先ならローカルファイルベース（Obsidian）、チームWikiやプロジェクト管理が優先ならオールインワン（Notion）
  • 監視：エラートラッキング（Sentry）+ 自分で統制するメトリクススタック（Grafana/Prometheus）またはSaaS統合プラットフォーム（Datadog）
  • ユーティリティ：データをサーバーへ送らないブラウザベースのツール（JWTデコーダ、JSON/YAML変換など）

この一覧をそのまま真似せよという意味ではありません。核心は「他人が使うもの」ではなく「自分が何に詰まるか」から出発する思考法です。2026年のツールはかつてないほど豊富で、AIのおかげでツール間の境界も曖昧になりました。それだけ選択の自由が大きくなり、だからこそ「なぜこのツールなのか」を自分で説明できることが、いっそう重要になります。

# 開発ツール点検表 - 状況別の分類と導入前の確認事項

基準日：2026-09-29。
以下の値は各ツールの公式ドキュメント・ブログ・リリースページと、Stack Overflow 2025 Developer Surveyで確認したものです。価格の金額は記載しません。

---

## 1. 状況別のツール分類

括弧内の名前は本文に出てきた例にすぎず、順位ではありません。

| 領域 | こんな状況なら | 使われる分類（例） |
|---|---|---|
| エディタ | チーム標準と拡張エコシステムが重要 | 汎用エディタ（VS Code） |
| エディタ | AIによる編集の比重が大きい | AI統合エディタ（Cursor、Zed） |
| エディタ | 大規模なJava/Kotlin、緻密なリファクタリング | 統合IDE（JetBrains） |
| AIコーディング | リポジトリ全体の複数ファイルを直す | エージェント型（Claude Code、Codex） |
| AIコーディング | 画面で変更を見ながら直す | エディタ統合型（Cursor） |
| AIコーディング | 入力中に提案が欲しい | 補完型（Copilot） |
| ターミナル | 速度と単純さが優先 | GPU加速の軽量ターミナル（Ghostty、Alacritty） |
| ターミナル | エージェントの実行まで一つの画面で | エージェント型開発環境（Warp） |
| バージョン管理 | 新しいワークフローを試す | Git互換VCS（jj、1.0前） |
| API | 単発リクエスト | curl（+ オンラインcurl Builder） |
| API | 複数人でGUIのコレクションを共有 | 無料プランの人数条件をまず確認 |
| コンテナ | Kubernetes運用 | ターミナルUI（k9s）またはGUI（Lens） |
| DB | 複数のDBMSを一つのツールで | 汎用クライアント（DBeaver） |
| ノート | データ所有権が優先 | ローカルファイルベース（Obsidian） |
| ノート | チームWiki・プロジェクト管理が優先 | オールインワン（Notion） |
| 監視 | 自分で統制したい | オープンソースのメトリクススタック（Grafana/Prometheus） |
| 監視 | 素早いSaaS統合 | 統合プラットフォーム（Datadog） |
| ユーティリティ | データをサーバーへ送ってはいけない | ブラウザで処理するツール |

---

## 2. 導入前チェックリスト

- [ ] 無料プランの人数制限を確認した（Postmanの無料プランは2026年3月の改定後1ユーザー、チーム作成不可）
- [ ] 無料プランに含まれるAI機能の範囲を確認した（GitHubドキュメント：Copilot Freeにエージェントモードを含む）
- [ ] 商用・非商用の条件を確認した（DataGripは2025-10-01から非商用無料、業務利用は有料ライセンス）
- [ ] 業務利用のライセンスを確認した（Obsidianの商用ライセンスは2025-02-20から任意）
- [ ] 対応OSを確認した（Ghostty：macOS・Linux／Zed：macOS・Linux・Windows）
- [ ] アカウント・サブスクリプションの要否を確認した（Claude Codeのほとんどの利用環境はClaudeのサブスクリプションまたはAnthropic Consoleのアカウントが必要／InsomniaのScratch Padはログイン不要）
- [ ] アプリ内の機能がどの版に含まれるか確認した（Brunoの料金表：Native Git IntegrationはPro・Ultimateの項目）
- [ ] リポジトリの最新リリースを確認した（Aiderの最新リリースはv0.86.0、2025-08-09。確認時点までその後のリリースなし）
- [ ] バージョンの成熟度を確認した（jjの最新は0.45.1、1.0前）
- [ ] 名前が機能かモデルかを見分けた（CursorのComposerは2025-10-29に発表された自社エージェントモデルの名前）
- [ ] データが外部サーバーへ出るか確認した
- [ ] 協業ツール（VCS・CI・課題管理）はチーム標準に従い、個人のツールだけ好みで選んだ
