mq - A jq-style Query Language for Markdown 2026

What jq Did for JSON, mq Does for Markdown

Jun 10, 2026 Tech

Introduction: So Much Markdown, So Few Tools to Wield It

Picture a developer's day and Markdown is almost everywhere: READMEs, wikis, issues, design docs, blog drafts, and in 2026, the prompts and responses of LLMs too. It has become the de facto standard for human-readable structured text. Yet the moment you try to treat that Markdown programmatically, the tooling feels thin. Reach for grep to find headings and you also catch the # comments inside code blocks. Reach for sed to rewrite links and you collide with the pipe characters inside tables. Markdown is lovely to read, but surprisingly awkward for machines to handle structurally.

The tool that takes precise aim at this gap, and which trended on GeekNews, is mq. In one line, mq is "jq for Markdown." It carries over the philosophy of jq, the standard tool for JSON: pick elements with dot notation, chain transforms with pipes, compose filters together, but applies it to Markdown. In this article we will briefly recap what jq is, then look at the problem mq solves, how it works under the hood, how to use it in practice, and how it differs from neighbors like pandoc, remark, and mdq.

1. A Quick jq Recap - A Query Tool for JSON

To understand mq, start with its prototype, jq. jq is a lightweight command-line processor for JSON, often called "sed/awk for JSON" or "SQL for JSON." Its core concept is the filter. A jq program is a filter that takes input and produces output, and the simplest filter, ., is the identity operator that passes input straight through.

jq's power comes from chaining small filters with a pipe (|). Just like a shell pipe, the output of the previous filter becomes the input of the next.

# Extract just the name field from an object
echo '{"name":"Ada","age":36}' | jq '.name'
# => "Ada"

# Iterate an array and select items whose age is over 30
echo '[{"n":"A","age":36},{"n":"B","age":20}]' \
  | jq '.[] | select(.age > 30)'
# => {"n":"A","age":36}

Three things are worth remembering. First, dot notation (.name) drills into structure. Second, pipes chain stages. Third, functions like select() filter. What other languages do with loops and conditionals, jq does by gluing filters together. That exact mindset is transplanted almost verbatim into mq.

2. But Markdown Is Not JSON - The Real Problem

The reason jq is so pleasant is that JSON is, from the start, structured for machines to parse. Keys and values, objects and arrays nest cleanly, so dot notation can point anywhere precisely.

Markdown is different. It is plain text designed to be easy for humans to read and write. It looks simple, but inside it hides an implicit structure of headings, paragraphs, lists, quotes, tables, links, and code blocks. The trouble is that this structure does not reveal itself well line by line.

  • grep's blind spot: Run grep '^#' to find headings and you also catch a shell comment # sitting inside a code block. grep sees only text lines; it has no idea whether a line is inside a code block.
  • sed's blind spot: Try to bulk-rewrite links and a regex alone keeps colliding with nested brackets or the pipe (|) characters inside tables.
  • Structure blindness: In the end, grep, sed, and awk are blind to Markdown's structure. To them, a document is just a sequence of lines.

At the opposite end sits pandoc. pandoc is a powerful tool for converting whole documents into other formats, but it is overkill for surgical extraction like "give me just the h2 headings, or just the Rust code blocks." This gap between line-level tools and whole-document converters is exactly the slot mq aims for.

3. What Is mq - jq for Markdown

According to its official introduction, mq is a command-line tool that processes Markdown with a syntax similar to jq, written in Rust. It slices, filters, maps, and transforms data, but over Markdown. Where jq handled JSON objects and arrays, mq handles document nodes like headings, paragraphs, and code blocks.

You can summarize mq's identity in a single sentence.

grep and sed are blind to Markdown's structure, and pandoc converts whole documents. mq sits in between, surgically querying and transforming the elements inside Markdown.

The introductions highlight these primary use cases for mq:

  • LLM workflows: efficiently manipulate and process the Markdown used in LLM prompts and outputs. This is the most talked-about use in 2026.
  • Documentation management: extract, transform, and organize content across multiple documentation files.
  • Content analysis: quickly pull specific sections or patterns out of a Markdown document.
  • Batch processing: apply consistent transformations across many Markdown files.

The tooling around it is rich, too. It is described as offering a REPL for interactive experimentation, a VSCode extension with LSP (Language Server Protocol) support, and a debugger for stepping through queries. You can even extend it with custom subcommands by dropping executables starting with mq- into ~/.local/bin/.

4. How It Works - Seeing Markdown as an AST

Here is where mq fundamentally differs from grep: mq parses Markdown not as a sequence of lines but as a structured tree, an AST (Abstract Syntax Tree).

Suppose we have this short Markdown:

# Install

Install with the following command.

```bash
cargo install mq-run
```

## Usage

See the [docs](https://mqlang.org/) for details.

To a human it is just text, but mq understands it as the following structure:

Document
├─ Heading(level=1)  "Install"
├─ Paragraph         "Install with the following command."
├─ CodeBlock(lang=bash)  "cargo install mq-run"
├─ Heading(level=2)  "Usage"
└─ Paragraph
   └─ Link(url="https://mqlang.org/")  "docs"

Once the structure is explicit, selections like "headings only," "level-2 headings only," "bash code blocks only," or "all links only" become precise. The # inside a code block is no longer mistaken for a heading. This "querying over an AST" is the secret that lets mq behave like jq. Where jq's input was a JSON tree, mq's input is a Markdown AST.

5. Basic Selectors - Headings, Code Blocks, Links

Now to the actual syntax. mq's selectors resemble jq's dot notation, but the targets are Markdown elements. The examples below summarize patterns shown in the official docs and introductions.

5.1 Heading extraction (.h)

# Extract all headings
mq '.h' README.md

# h1 headings only
mq '.h(1)' README.md

# h1 and h2 headings only
mq '.h(1, 2)' README.md

# Headings level 1 through 3 (a range)
mq '.h(1..3)' README.md

5.2 Code block extraction (.code)

# All code blocks
mq '.code' example.md

# Rust code blocks only
mq '.code("rust")' example.md

# JavaScript code blocks only
mq '.code("javascript")' example.md

Combine this with the select() and contains() we saw in jq, and you get conditional filtering.

# Headings that contain "install"
mq '.h | select(contains("install"))' README.md

# Code blocks that contain "name"
mq '.code | select(contains("name"))' example.md

Dot notation, pipes, select: anyone who has used jq will feel instantly at home. The jq mindset of chaining filters instead of writing loops survives intact.

6. Transform and Compose - Flatten to Text

mq does not stop at extraction; it also transforms. You can flatten extracted nodes to plain text, change case, or wrap them as links.

# Convert all headings to text
mq '.h | to_text()' README.md

# Convert code blocks to text
mq '.code | to_text()' example.md

# Connect tools in a pipeline (extract then lowercase)
cat README.md | mq '.h' | mq 'downcase()'

As with jq, mq's real power is in composing small pieces. Mix shell pipes with mq's internal pipes and a flow like "pull headings, then lowercase, then hand off to the next tool" fits on one line.

7. Practical Use Cases

So what is this actually good for? Concrete scenarios show a tool's value better than abstract syntax.

7.1 Auto-generate a table of contents

Collect just the h1 and h2 headings and build a TOC with anchor links. The official introduction even shows a TOC example that gathers headings and turns them into links with to_link(). Handy for tidying long READMEs or wiki pages automatically.

7.2 Extract code samples from a README to verify them

Use mq '.code("bash")' to pull the shell examples out of a README and run them in CI to confirm they still work. A good guard against "doc rot," where the commands written in docs drift away from reality.

7.3 Distill LLM prompts and responses

From a long Markdown response, pull just the heading structure and links to use as summary context, or strip unnecessary code blocks to save tokens. Extracting headers and links to lighten LLM input is one of the headline uses in the introductions.

7.4 Batch transform and validate docs

Apply the same query across dozens of Markdown files to find broken links or check whether a given section exists, building a documentation-linting pipeline. These were exactly the jobs that were hard with grep, which knows nothing of structure.

8. CLI Examples at a Glance

Here are the patterns so far gathered as real commands.

# Install (per official guidance)
cargo install mq-run

# 1) All h2 headings of a doc, as text
mq '.h(2) | to_text()' docs/guide.md

# 2) Extract only python code blocks
mq '.code("python")' docs/guide.md

# 3) Find paragraphs containing "deprecated"
mq 'select(contains("deprecated"))' CHANGELOG.md

# 4) Pipeline: extract headings then lowercase
cat README.md | mq '.h' | mq 'downcase()'

See the pattern? jq's three-step structure of select, filter, transform repeats verbatim over Markdown. Learn it once and the cost of writing a new query drops sharply. 9. Python Bindings and MCP

mq is not a CLI-only tool. The introductions note that Python bindings are provided through a PyPI package called markdown-query, so you can query Markdown with the same syntax from inside a Python script. Useful for teams that build data pipelines or document-processing automation in Python.

What is especially interesting in the 2026 context is MCP (Model Context Protocol) integration. According to the introductions, you can expose mq as an MCP server so AI applications can process Markdown structurally, letting an LLM receive only the precise slice it needs instead of swallowing a whole document. 10. Comparing Tools - mq vs mdq vs pandoc vs remark

mq is not the only tool for handling Markdown; each aims at a different slot. Based on the introductions and comparisons:

Tool Nature Strength Limits / notes
mq jq-style query CLI (Rust) Element extraction and transform; REPL, LSP, debugger; MCP and Python bindings Rich features mean more expressions to learn
mdq jq-style query CLI (Rust) Simple, focused selection of specific elements Described as a lighter, simpler selection tool than mq
pandoc General document converter Whole-document format conversion (MD to/from HTML, PDF, and more) Overkill for surgical element extraction
remark JS Markdown framework Plugin-based transforms and linting, build integration More programming-oriented than a one-line CLI query

In short, mq and mdq are the same family of jq-style query tools. mq leans toward richer tooling (REPL, LSP, debugger) and integration (MCP, Python); mdq is described as the simpler, more focused selector. pandoc is about "conversion" and remark is "a framework in the JS ecosystem," so they have a different grain. Whether to reach for mq comes down to one question: are you converting a document, or selecting inside it?

11. Things to Consider Before Adopting mq

Even a good tool shines only in the right context. Practical points to weigh before adopting mq.

  • Learning curve: with jq experience, onboarding is quick; without it, you first have to internalize the mindset of dot notation, pipes, and filter composition.
  • Install dependency: being Rust-based, cargo install is presented as the easiest path. Whether prebuilt binaries are available depends on your platform and is worth checking.
  • Maturity: it is a relatively new, actively developed tool, so some expressions or features may change between versions. For unverified behavior, the official docs are the safe reference.
  • Fit: it can be overkill for a one-off extraction. The value grows when you run "the same query many times," as in repeated document automation, validation, or LLM preprocessing.

12. What It Means for Developers and Doc Writers

The arrival of mq means more than "one more handy CLI." It is the spread of a mindset that treats Markdown as data. For a long time Markdown was "a document people read," not "data a machine queries." Just as jq made JSON a first-class data type, mq elevates Markdown into a queryable structure.

This shift lands hardest on two groups. For developers, documents become part of the code pipeline: testing README code samples, validating changelogs, and adding doc linting to CI all become natural. For doc writers, the manual labor of hand-editing dozens of files shrinks into a one-line query.

And the decisive 2026 context is, again, LLMs. In an era where AI produces and consumes Markdown at scale, demand for tools that slice and filter that Markdown precisely can only grow. It is no accident that mq foregrounds LLM workflows and MCP. The more Markdown becomes the common tongue between AI and humans, the clearer the slot for a "jq-like tool" that wields it.

13. Conclusion + 3 Things to Try Now

mq is well summarized by the one-liner "the Markdown version of jq," but that line points to something broad. In the gap where grep and sed are blind to structure and pandoc is overkill, mq parses Markdown into an AST and surgically queries and transforms it. Anyone who has used jq can start right away with the familiar grammar of dot notation, pipes, and filters.

Three things you can try now:

  1. Pull headings from your longest README first. A single mq '.h' README.md lays the document's skeleton bare. It is the fastest way to feel the value.
  2. Extract code blocks and wire them into a verification pipeline. Pull the commands out of docs with mq '.code("bash")' and run them in CI to catch drift between docs and reality automatically.
  3. Slot it into LLM preprocessing. Slice only the elements you need from a long Markdown response before handing it off to save tokens and keep the context clean.

The truth tools keep telling us is the same: the more structured work we hand from humans to machines, the more we can focus on the judgment that matters. mq is a small but clever tool that raises Markdown, that familiar text, to exactly that level.

One last framing worth keeping in mind. The value of mq is not that it does something grep and sed cannot, in principle, be coerced into doing with enough regex gymnastics. The value is that it makes the right thing easy and the fragile thing unnecessary. Every time you reach for a brittle pattern to half-understand a document's structure, you are paying a hidden tax in bugs and rework. A tool that genuinely understands the document's shape removes that tax. As Markdown quietly becomes the connective tissue between humans, codebases, and AI systems in 2026, having a precise, composable way to query it stops being a niche convenience and starts looking like basic infrastructure, the same way jq did for JSON a decade ago. The smartest move is to try one query on a document you already know well, feel how the AST view changes your mental model, and let that small shift pull the rest of your workflow along with it.
