同行评审拦不住什么 - 「通过评审」保证了什么、又没保证什么

评审并非为检测造假而设计。那么读者应该改看什么

2026-08-02 IT/技术

引言: 在用一篇论文做出决定之前

在一次技术选型会议上，有人提议采用某种方案。依据是一篇论文，提议者附上的说明只有一句：「这是被会议录用的论文。」没有人反对。我也没有反对。

几个月后，那套方案在我们的环境里没有达到预期，我重新打开论文，才知道了几件事。报告中的数值来自与我们不在一个量级的硬件，比较对象是我们早已不用的旧方案，复现代码的链接已经失效。这些没有一条是论文隐瞒的，全都写在正文里。问题在于我读到「被录用了」这一句就停了下来。

那时才第一次浮现的问题，就是本文的起点。「经过同行评审」这句话到底保证了什么？又没有保证什么？这个问题对学术圈外把论文当作依据来使用的人，比对圈内人更迫切。我们没有机会看到评审制度的内部，因此很容易把「通过」这个信号读得远超它本身。

本文的立场。这不是一篇批判学术界的文章，也不点名任何一个会议或研究者。目的只有一个：准确理解评审制度被设计来做什么。指责一套制度没能做到它本就不为之设计的事情，会得出错误的诊断，而错误的诊断会让读者采取错误的应对。

1. 确认到的与没能确认的

把这一节放在最前面。如果不先说明本文依据什么写成，本文自身就会变成它所警惕的那类文章。

起点是一件通过报道得知的事情。它涉及某位参与过评审的人公开的记录，据称内容是：一份稿件在正文里自行说明作者名单中含有并不存在的人名，而该稿件仍被录用。

我没能打开那篇原文。访问被阻断，无法确认正文。因此本文遵守以下原则。

  • 本文不把篇数、比例、会议名称、作者、审稿人当作事实来陈述。不引用自己打不开的文档是本博客的规则，这次也不设例外
  • 该事项仅以「通过报道得知的主题」提及，文章主体建立为基于可核验制度文档的结构分析
  • 因此不应据本文对任何特定会议的评审水平下判断。本文并不具备这种判断的依据

而我直接打开并确认过的一手文档如下，全部是无需登录即可公开访问的官方指南。

  • 国际医学期刊编辑委员会公布的作者资格定义文档 — 作者的四项要求，以及判断责任的归属
  • 某大型会议公开的审稿人指南 — 审稿人被要求评估的项目与日程
  • 同一会议的征稿说明 — 作者名单变更规定、代码与数据提交的地位、重复投稿处理
  • 同一会议的大语言模型使用政策 — 作者责任范围与对审稿人的约束
  • 同一会议的伦理准则 — 评审过程中可以提出的问题类别
  • 开放科学组织的注册报告说明文档 — 两阶段评审的结构与它所针对的问题
  • 科学编辑协会的作者责任指南 — 影子作者、馈赠作者、客座作者的定义

也说明没能打开的。出版伦理机构的审稿人伦理指南、大型学术团体的可复现性徽章定义文档，以及前面提到的起点文章。三者的访问都被阻断，无法确认正文，所以本文不描述这三份文档的内容。第12节再次做了整理。

为何反复引用某一个会议的文档。下文多次引用某会议的政策原文，并不是因为那个会议有问题，恰恰相反。把评审规则、作者规则和语言模型政策无需登录全文公开的地方并不多，而要引用就必须真的能打开。公开出来因而可以被引用，这件事本身就是好的做法。

2. 评审被设计来核验什么

首先要纠正一个误解。同行评审不是造假检测装置。这不是制度失败的结果，而是它从一开始就不是为此设计的。

打开公开的审稿人指南，审稿人被要求判断的轴线列得很清楚：技术上的可靠性、行文的清晰度、对领域的重要性，以及原创性。同一份文档还指出，原创性并不必然要求提出一个全新的方法，通过评估既有方法给出新的洞见同样算作原创性。

把这四条轴线压缩成一句话就是：「作者提出的主张，能否在作者给出的证据上，按作者所说的程度成立？」这个问题把稿件预设为一份合作性的文档，也就是在作者没有说谎的假设之上衡量论证的质量。

2.1 指南里没有的东西

无论怎么读这份指南，下面这些项目都不会出现。而它们的缺席正是本文的核心。

项目评审被设计来做的事不被设计来做的事我确认的依据
论证评估主张与证据的契合—审稿人指南的四条评估轴
行文评估清晰度与结构—审稿人指南的四条评估轴
贡献判断对领域的重要性与原创性—审稿人指南的四条评估轴
作者真实性—不存在身份核验流程作者资格文档把责任归于作者
参考文献真实性—没有确认存在的义务语言模型政策把确认责任交给作者
结果复现—没有复现义务代码提交属鼓励，运行属风险提示
数据真实性—没有原始数据比对流程指南中完全没有作为要求项出现
重复投稿违规即不予受理发现依赖举报与偶然征稿说明中的重复投稿条款

请再读一遍右侧那一列。抓造假所需要的项目几乎全在右边。没有任何文档要求审稿人做这些工作，也没有为此分配权限或资源。

对代码的处理把这种性质压缩得很清楚。指南对提交的代码警告说与任何其他不受信任的代码一样，提交的代码可能包含安全漏洞，并建议在隔离环境中处理。这句话的含义很明确：运行代码被当作审稿人承担的风险，而不是核验步骤。如果它是核验环节，就不会附带这样一句话。

3. 没有主体核验作者名单

作者名单是论文上最显眼的信息，同时也是最不被核验的信息。这不是推测，而是写在指南原文里的。

国际医学期刊编辑委员会的作者资格文档规定，成为作者必须同时满足四个条件：对构思或设计、对数据的获取、分析或解释的实质性贡献；起草论文或对其中重要智识内容作批判性修改；对拟发表版本的最终批准；以及同意对论文各方面负责，确保与准确性或诚信相关的问题得到适当调查和解决。

但同一份文档随即钉死了判断的主体。用它自己的话说，判断所有署名者是否都满足四条标准，是作者们的共同责任，而不是收到稿件的期刊的责任。它还写道，判定谁具备或不具备作者资格、仲裁署名纠纷，并不是期刊编辑的角色。

把这两句话并排放，结构就浮现了。标准存在，而没有外部主体负责确认其被遵守。作者名单不是被核验的对象，而是被申报的对象。它和纳税申报同构，只有一点不同：税务申报背后有事后稽查机构，而作者名单没有对应的常设机构。

3.1 影子、馈赠与客座

科学编辑协会的作者责任指南把扭曲的署名分为三类。三者都是与名字是否真实无关的问题，因而更难发现。

  • 客座作者。因为期待某个名字出现能提高发表机会而加上，实际并无贡献
  • 馈赠或荣誉作者。基于与研究关系薄弱的联系而赠予署名，例如部门负责人
  • 影子作者。实际参与了研究、分析或写作，却既未署名也未被提及
  • 同一份指南写道，编辑应要求作者与致谢对象说明各自的贡献，并应留意评审过程中署名是否发生变化。但这是监视，不是核验

会议规定也是同样的性质。某份征稿说明写明摘要截止之后不允许增加或删除作者，只能在投稿截止前调整顺序。这条规定的目的不是确认名单，而是冻结名单。冻结让事后的操作变难，却从不追问最初写下的名单是否为真。

  • 所属机构是自行填写的，不存在向机构查证的标准流程
  • 邮箱也只确认是否可达。可达意味着地址是活的，不意味着那个人就是本人
  • 即使存在贡献声明，也没有办法把声明内容与事实作比对
  • 在匿名评审中审稿人根本看不到作者，因此作者核验在结构上位于评审环节之外

4. 自我披露也能通过意味着什么

这里只讨论引发本文的那件事的结构性含义。既然事件本身未能确认，下面的讨论应当按假设语气来读。

假设有一份稿件在正文中自行说明「本文的作者名单中含有并不存在的人名」，却仍被录用。此时我们能知道什么？

先整理我们不能知道的更有用。

  • 不能由此知道审稿人不诚实。漏看一处自我披露与对造假视而不见是两种不同的事件
  • 不能由此知道该领域的研究水平。样本实际上等于零
  • 也不能由此知道评审制度全面崩塌。一个案例就是一个案例

能知道的只有一件：审稿人的注意力并不均匀地分布在整份稿件上。这并不令人意外，事实上所有文档审阅都是如此。审稿人的目光会聚集在特定位置。

  • 摘要与结论。先抓住主张是什么
  • 表与图。看数值是否支撑主张
  • 比较基线。与什么比较占了评估的一半
  • 方法一节。看是否写到可复现的详细程度
  • 相关工作。看自己熟悉的方向有没有被漏掉

不在这份清单上的地方就是盲区。致谢、资金说明、作者单位、附录末尾，以及正文中间出人意料的那一句。发现造假是「注意到你没在找的东西」的工作，而评审是「评估被主张的东西」的工作。两种作业的训练不同，阅读方式也不同。

所以这件事的教训不是「审稿人偷懒了」，而是「评审这项工作与造假检测是不同种类的工作」。只有按后者来读才会有应对。按前者来读，能得出的应对只有把人逼得更紧，而正如下一节所示，这方面的余地已经所剩无几。

5. 审稿人的处境 - 无偿、赶工、参差

在指责审稿人之前，应该先看看审稿人在什么条件下工作。这里只写公开文档中可以确认的部分。

条件实际情况造假检测所需差距
报酬无偿志愿是常态额外调查时间的对价没有可以开账单的对象
周期某份公开日程中约五周引用比对与复现所需的反复工作与本职工作重叠
负荷一人负责多篇逐篇的深度阅读深度与篇数互相挤占
专业度按关键词与竞标分配，参差较大该细分方向的具体知识分到邻近方向很常见
权限只能看到稿件与附录机构查证、原始数据索取、身份核验权限本身就不存在
工具保密规定限制外部工具的引入用于大批量比对的自动检查规定与需求相冲突
惩戒迟交或质量不足可能限制查看自己论文的评审意见对准确性的奖励惩罚慢，却不奖励深

最后一行尤为重要。某份审稿人指南中有大意如下的条款：如果你的评审迟交或质量不足，可能会失去查看自己参与合著论文评审意见的权限。这类机制在促使评审被交上来这件事上很有效，但并不朝着「挖得更深」的方向起作用。挖得越深，只会让截止风险越大。

不要把结构问题归咎于个人。上表中没有一行是靠个人的勤勉可以补上的差距。对一个无偿工作的人期待调查员的角色，那是愿望而不是设计。要谈改进，就必须是真正改变报酬、权限、工具三者之一以上的方案。

6. AI 造成的压力 - 只在政策原文承认的范围内

这一节写得格外谨慎。关于生成式工具对投稿质量的影响，我没能确认任何可以断言的数字。所以我不谈数字，只看政策文档开始把什么写进条文。规则通常是追着已经发生的问题制定的，因此规则的存在本身是一个弱信号。

我读到的语言模型政策包含以下内容。

  • 作者对论文的全部内容负责。原文明确写道，论文的全部内容，包括所有文字、图表与参考文献，都由作者负责
  • 违规情形中明确列出了在未尽核实义务确认正确性、存在与否与适当性的情况下使用语言模型生成的参考文献。把参考文献的存在与否写成核查项，这一点很有意味
  • 如果在方法实现中使用了语言模型，且它是重要的、原创的或非标准的组成部分，就应在实验设置一节中说明
  • 与此相对，拼写检查、语法建议以及以编辑为目的的编程辅助无需记录。也就是说政策并不禁止工具，而是固定责任的落点

对审稿人的约束方向相反。

  • 审稿人必须对评审过程的所有方面保密，不得与任何人或任何语言模型分享、讨论或披露与投稿相关的信息
  • 为评审而提交的代码不得分发给任何人，包括任何语言模型，也不得用于评审以外的任何目的
  • 用于理解一般概念是允许的，但一旦放入保密材料就属禁止

由此产生了不对称。生产稿件的一方可以自由使用自动化工具，记录义务也有限；而审阅稿件的一方出于保密不能把稿件放进自动化工具。这是生成速度与审阅速度无法从同一批工具中获得同等收益的结构。

这种不对称并不是规则的错。保密是评审制度的根基，不能放弃。但需要认识到，审阅一侧的处理量更难跟上生成一侧。再往前我没有确认的依据，因此不再多说。

因未能确认而不说的事。近年投稿量的增长幅度、含生成文本的稿件比例、以及由此带来的评审质量变化。这三点经常被引用，但这次我没能打开一手统计。所以本文里没有一个这类数字。

7. 那么应该怎么读论文

把到此为止的结论压成一句：「是否通过评审」是一个信息量极低的信号。取而代之的信号是「公开了什么」。

先把通过所保证的与不保证的分开。

  • 它保证满足了形式要求：篇幅、格式、匿名化、非重复投稿等机械性门槛已经通过
  • 它保证至少两位同行读过稿件，并判断该主张在所给证据上成立
  • 它保证明显的逻辑缺陷与对知名前人工作的遗漏，很可能已被过滤
  • 它不保证结果会再次出现
  • 它不保证数据与作者真实存在
  • 它不保证不存在利益冲突
  • 它不保证日后不会被推翻
  • 它不保证在你的环境里会有同样的效果

下表是替代通过与否的观察项，从左往右读即可。

确认对象强信号弱信号无信号
代码仓库公开，且有能跑出论文数值的脚本有仓库但配置与论文不同只有一句索取即可提供
数据公开数据并包含预处理步骤经申请流程后可获取内部数据，无法公开
条件硬件、规模、分布以表格明示散落在正文叙述中完全没有条件说明
比较基线与当前主流方法比较且注明调参预算有比较但调参条件不明只与自己的旧版本比较
失败报告把不奏效的条件写进正文局限性一节流于形式完全不提局限
利益冲突注明资金来源与关系只标注所属单位没有任何标注
版本说明最终版与预印本的差异只有版本标记不知道是哪一版
后续有独立团队的复现报告引用很多但没有复现既无引用也无复现

用法很简单。如果「无信号」一列里落下好几个标记，这篇论文就不能成为决策的唯一依据。它可以是参考文献，但不能是依据。反过来，若有多个「强信号」，即便是未经评审的预印本也是一份可核查的文档。

主张本身该在哪一层来读是另一个问题。在特定领域的发布中像「攻破」这类词实际覆盖多大范围，其切分方法另见如何核验「AI 破解了密码」这类发布。本文看制度核验了什么，那篇看主张意味着什么。

8. 给工程师 - 当论文成为技术决策的依据

当读论文的目的不是学术兴趣而是决策时，确认项就不一样了，因为决策的推翻是要付出代价的。

  • 真的去点一下复现代码的链接。失效链接多得惊人，而点一下只要三秒
  • 把仓库的默认配置与论文的表格对照。两个值不同，论文的数值就不会复现
  • 看最后一次提交的日期。论文之后再没被碰过的仓库意味着没有维护计划
  • 确认数据许可证。仅限研究用途的数据上得到的结果，不能原样搬到商业环境
  • 把规模差距写成数字。「比我们大的环境」不是判断，「我们的八倍」才是
  • 写下数据分布的差异。语言、领域、长度分布不同，相对收益通常会缩水
  • 看比较对象是不是你们实际在用的东西。与你们早已弃用的旧方案比较，对你们没有意义
  • 看资金来源与作者单位。若比较对象是竞争产品，就更仔细地核对调参预算的对称性
  • 把后续引用扫一遍。反驳论文或复现失败的报告通常会出现在引用列表里
  • 最重要的一条。在自己的环境里用最小规模跑一次。这一次胜过二十篇论文

8.1 决策记录里该写什么

如果决策文档只写「依据论文X」，那么日后这个决策出问题时，你无法找出到底哪里错了。按下面的形式写下来，推翻就容易得多。

所用数值 : 表3的延迟 P99   ← 取自表格，而非正文叙述
其条件   : 加速卡8张 · 批大小64 · 数据A · 合计12小时
我方条件 : 加速卡2张 · 批大小8  · 数据B
差异摘要 : 算力相差4倍 · 数据域不同
复现代码 : 有 / 无 — 有则记提交标识
是否跑过 : 是 / 否 — 是则用一行概括结果
利益冲突 : 资金来源 · 比较对象是否为竞争产品
回滚成本 : 若此决策有误，恢复原状所需的工作量

这份记录的价值在时间过去之后才显现。半年后出问题时，仅凭这张表就能分清是「条件不同」还是「论文有误」还是「我们搬错了」。这三种情况的应对完全不同。

9. 改进尝试 - 确认到的与没能确认的

试图改变制度的努力有好几种。这里只描述我打开过一手文档的那些，其余只写名字而不谈效果。

注册报告我确认了一手文档。结构是这样的：把研究做完之后带着结果去接受评审的通常顺序颠倒过来，在收集数据之前先评审研究计划。第一阶段提交引言、方法与任何预实验数据，审稿人评估研究问题的重要性与方法的严谨性，通过者获得原则性接收。用文档自己的话说，这意味着只要作者按照获批的方案开展实验，期刊就实际上保证发表。第二阶段提交结果与讨论，无论结果如何，只要遵守了方案就会发表。说明文档写道，目前有超过300家期刊提供这一形式。

这一形式所针对的问题也写在文档里：统计功效偏低、结果的选择性报告、发表偏倚。因为在看到结果之前就固定了分析，事后更改假设或只挑有利分析变得困难。

一个重要的限度。注册报告并不是针对作者真实性或引用捏造的机制。它针对的是别的东西。对于引发本文的那类问题，注册报告不是答案，把它介绍成答案是不准确的。好的制度并非所有问题的答案，这一点在这里要说清楚。

尝试所针对的问题本文中的确认状态描述范围
注册报告选择性报告 · 发表偏倚 · 功效偏低已读一手文档描述到结构与针对对象
语言模型使用政策生成文本的责任归属已读一手文档描述到条款内容
作者资格标准客座、馈赠、影子作者已读一手文档描述到标准与责任主体
公开评审评审过程的不透明未能打开一手文档不描述其效果
可复现性徽章公开代码与数据的激励未能打开定义文档不描述其定义
审稿人伦理指南利益冲突 · 保密 · 举报渠道未能打开一手文档不描述其条款
为评审付酬无偿的结构没有可确认的材料仅作提及

表格的下半部分是本文的诚实之处。知道名字和知道内容是两回事。对于公开评审与可复现性徽章，我只知道名字而未能确认定义，因此既没有资格写「有效」，也没有资格写「无效」。

研究者个人的姿态在这套结构中意味着什么，在机器学习研究的禅与艺术中讨论过。如果说本文看的是制度，那篇看的是人。

10. 把这些用到自己的博客与文档上

这场讨论不会止步于学术圈内部。写技术博客或做内部文档的人每天都在引用出处。那时有一套需要守的规矩。

先把出处按层级区分开。层级不是可信度排名，而是说明受过何种审视的标签。

形式通过的门槛速度引用时要放进句子的措辞
预印本无(作者自行上传)最快「未经评审的预印本」
研讨会报告简短评审 · 允许进行中的工作快「研讨会阶段的报告」
会议主会正式评审一轮 · 截止固定中等「当年主会录用的论文」
期刊发表可多轮修改往返慢「期刊发表论文」
标准与规范文档机构流程 · 基于共识最慢「规范文档中的条款」
企业技术博客仅内部审阅(无外部评审)快「厂商自己的发布」
二手报道编辑审阅快「通过报道得知的内容」

只要点明层级，读者得到的信息就会大幅增加。「研究表明」这种说法把这七行全部抹平。

10.1 引用句模板

好 : 「当年会议主会录用的论文在表2中报告 …」
好 : 「这是预印本阶段的报告，未经外部评审」
好 : 「这是厂商在自家博客公开的数值，未能确认独立验证」
好 : 「原文未能打开，本文不描述其内容」

差 : 「研究表明 …」                    出处层级消失
差 : 「学术界已经证明」                把一篇变成共识
差 : 「论文中揭示了」                  没有谁、什么、在什么条件下
差 : 「据报道该论文称 …」              把二手引用当作一手
差 : 「近期研究表明 …」                时间点与篇数都没有落实

这里还要再加几条规矩。做起来并不难，做到了文章的寿命会更长。

  • 打不开的文档不引用。不要只看了摘要或报道，就写得像引用了原文。本文的第1节与第12节就是这条规则的落实
  • 写下确认日期。文档会悄悄改动，没有日期日后就无法比对
  • 照搬原文措辞时要说明是照搬的。把概述与引用混在一起，原文的边界就消失了
  • 数值从表格里取。正文里的概括句已经掺入了一层作者的解读
  • 不要把一篇论文吹成共识。「研究者们认为」只在确认过多篇时才用
  • 对负面结果适用同一标准。只让有利于自己主张的论文免于层级检查，那本身就是选择性报告
  • 链接指向原文。绕经摘要站点会让读者核对原文的路径远一步

11. 用一页看完评审路径

把上面全部内容压成一张图，就是这样。

投稿
 │
 ├─ 形式检查 : 篇幅 · 格式 · 匿名化 · 是否重复投稿
 ├─ 分配     : 按关键词与竞标匹配审稿人
 ├─ 评审     : 可靠性 · 清晰度 · 重要性 · 原创性
 ├─ 讨论     : 作者申辩与审稿人之间的调和
 └─ 决定     : 录用 · 拒稿

这条路径上没有任何一步是
   核验作者真实性 · 查证所属单位 · 确认参考文献存在 · 复现结果 · 比对原始数据

因此「录用」的含义是
   上述五个步骤已经通过   (仅此而已)

在这张图上要读的是缺席的方框。制度只执行存在的方框。期待缺席的那些，不是制度的问题，而是读法的问题。

12. 没能确认的内容

这里汇总本文无法提供依据的内容。若日后有人引用本文，应当把这份清单一并读到。

  • 引发本文的那篇个人博客文章的正文。访问被阻断，未能打开。因此本文没有涉及篇数、比例与会议名称
  • 出版伦理机构的审稿人伦理指南。访问被阻断。它本会是关于审稿人明确不被要求做什么的最佳依据，这次未能使用
  • 大型学术团体的可复现性徽章定义文档。两个地址都被阻断，因此没有描述各级徽章认证什么、不认证什么
  • 关于公开评审效果的一手材料。未能确认
  • 关于投稿量增长的官方统计。未能确认，所以第6节没有数字
  • 审稿人人均实际分配篇数。指南中未能确认，因此没有写超出「多篇」的说法
  • 学科之间的差异。本文引用的文档偏向医学系的作者标准与某个计算机方向会议的政策。没有依据把它们原样推广到其他学科
  • 评审通过与后续复现成功率之间的关系。未能确认

13. 结语: 不是有没有通过，而是公开了什么

本文的结论不是对学术界的冷嘲。恰恰相反。准确理解制度，就不会再期待制度里没有的东西，并且可以用自己的核查去填补那块空位。

同行评审在过去一个世纪做了极其有用的工作：过滤了明显的错误，逼迫论证被打磨，建立了各领域的共同标准。这一切都是在作者诚实这一前提上衡量论证质量的工作，制度正是为此而设计。做不到设计目的之外的事，并不等于失败。

只是当这个前提开始承压时，补位不能只发生在制度内部，也必须发生在读者一侧。而读者能做的事比想象中具体得多。

  • 不问「有没有通过」，而问「公开了什么」：代码、数据、条件、利益冲突
  • 引用时把出处层级写进句子里
  • 打不开的文档不引用
  • 决策文档里写论文的哪张表、什么条件、与我们的差别
  • 并且尽可能用最小规模跑一次

回到开头那场会议。那时需要的不是对「这是被会议录用的论文」的反驳，而是一个问题：「那篇论文里我们要用的数值在第几张表？那张表的条件是什么？和我们的条件差在哪里？」这个问题不指责任何人，不要求任何专业知识，三十秒就能问出口。

# 论文判别清单 — 不看「有没有通过」，看「公开了什么」

> 出处: braindetox.kr — 同行评审拦不住什么
> 依据: 作者资格标准1份、会议公开政策4份、开放科学组织文档1份、编辑协会指南1份(全部直接打开确认)
> 把这份文档贴给 AI，写「请按以下标准检查下面这篇论文」即可。
> ⚠ 本文档不评价任何会议或研究者，只是梳理制度的设计边界。

## 0. 前提 — 通过评审意味着什么

| 分类 | 内容 |
|---|---|
| **保证** | 通过形式要求 · 同行判断论证成立 |
| **不保证** | 结果复现 · 数据真实 · 作者真实 · 无利益冲突 |
| **设计目的** | 评估论证质量(建立在作者诚实的前提上) |
| **设计之外** | 造假检测 · 身份核验 · 原始数据比对 |

**通过评审不是质量保证，而是最低门槛的通过。**

## 1. 出处层级 — 引用句里务必写出

| 形式 | 通过的门槛 | 引用措辞 |
|---|---|---|
| 预印本 | 无(作者自行上传) | 「未经评审的预印本」 |
| 研讨会 | 简短评审 · 允许进行中的工作 | 「研讨会阶段的报告」 |
| 会议主会 | 正式评审一轮 | 「当年主会录用的论文」 |
| 期刊 | 可多轮修改往返 | 「期刊发表论文」 |
| 标准 · 规范 | 机构流程 · 共识 | 「规范文档中的条款」 |
| 企业博客 | 仅内部审阅 | 「厂商自己的发布」 |
| 二手报道 | 编辑审阅 | 「通过报道得知的内容」 |

## 2. 公开信号检查 — 8 项

- [ ] **代码** 仓库已公开且链接可用
- [ ] **代码** 仓库默认配置与论文表格一致
- [ ] **数据** 已公开或明示了获取流程
- [ ] **数据** 许可证允许你的用途
- [ ] **条件** 硬件 · 规模 · 分布以表格明示
- [ ] **基线** 比较对象为当前主流且调参预算对称
- [ ] **局限** 不奏效的条件写在正文里
- [ ] **利益冲突** 注明了资金来源与关系

**「无信号」达到3项以上，就不要作为决策的唯一依据。**

## 3. 工程师的决策前检查

- [ ] **真的点开过**复现代码链接
- [ ] 确认过仓库的**最后提交日期**
- [ ] 把条件差距**写成了数字**
- [ ] 确认基线是**我们实际在用的东西**
- [ ] 扫过后续引用里的**反驳或复现失败报告**
- [ ] **用最小规模跑过一次**

## 4. 决策记录格式

```
依据文献 : 标题 / 作者 / 年份 / 发表形式
访问路径 : 地址 / 确认日期 / 版本
所用数值 : 表号与条目(取自表格而非正文概括)
其条件   : 硬件 · 规模 · 数据 · 耗时
我方条件 : 同样的条目
差异摘要 : 倍数与领域差异
复现代码 : 有(提交标识) / 无
是否跑过 : 是(一行结果) / 否
利益冲突 : 资金来源 · 比较对象
回滚成本 : 若有误，恢复原状的工作量
```

## 5. 引用规矩 — 7 条

- [ ] **打不开的文档不引用**
- [ ] 写下确认的**日期**
- [ ] 照搬原文措辞时**说明是照搬**
- [ ] 数值**从表格**里取
- [ ] 不要把一篇**吹成共识**
- [ ] 对**不利于自己的材料用同一标准**
- [ ] 链接指向**原文**

## 6. 不要做的事

- ❌ 用**「研究表明」**抹平 — 层级消失
- ❌ **「学术界已经证明」** — 把一篇变成共识
- ❌ 把**通过评审读成事实核查**
- ❌ **指责审稿人个人** — 无偿 · 赶工 · 无权限才是结构
- ❌ **点名嘲讽**某个会议或研究者
- ❌ 得出**学术界已经烂掉**这类结论 — 诊断错了应对也会错
- ❌ 把**二手报道当作一手引用**
- ❌ 描述**自己打不开的页面**的内容
