1. 소형 기기 특화 파운데이션 모델의 등장 배경과 설계 목적

일반적으로 언어 모델을 임베디드 기기나 소형 하드웨어에 직접 탑재하여 구동하는 작업은 가용 메모리와 연산 자원의 물리적 한계에 부딪힌다.

Cactus Compute는 이러한 소형 기기 환경을 목표로 「Needle 3」 모델을 공개했다. 공식 GitHub 저장소(https://github.com/cactus-compute/needle) 설명에 따르면, Needle 3는 「스마트폰, 웨어러블, 스마트홈, 로봇, 차량 및 마이크로컨트롤러에서 도구 호출, 구조화된 추출, 텍스트 임베딩을 수행하는 2비트, 8~29MB 크기의 소형 기기용 자동화 파운데이션 모델(Automation foundation model for tiny devices: 2-bit, 8-29 MB, tool calls, structured extraction and embeddings on phones, wearables, smart homes, robots, cars and microcontrollers)」로 기술되어 있으며 아파치 2.0(Apache-2.0) 라이선스로 배포된다. 제품 페이지(https://cactuscompute.com/needle)에서 Cactus는 「The whole model is a single 8-29 MB binary built on our Simple Attention Network, and we trade general chat capacity to beat models 10x its size on mobile tool calls and match 2-3x bigger models on extraction」이라고 적는다.

이 글의 해석으로는, 원문은 모델의 역할을 일반 대화 작문이 아닌 기기 도구의 선택과 인자 채움으로 좁혀 소형 바이너리를 유지하는 방식을 취하고 있다. Cactus가 제품 페이지(https://cactuscompute.com/needle)에서 기술한 실제 적용 대상과 문장은 다음과 같다.

  • 스마트홈: 「"Dim the bedroom and lock up" becomes two calls, executed offline, with no hub round trip.」
  • 로봇: 「"clean the kitchen but leave the bedroom", "go back to the dock when you are done". Each becomes a sequence of moves it can execute.」
  • 스마트폰: 「make an album from last weekend's photos, open a site, dim the screen, find the lease in your files.」
  • 웨어러블: 「a card charge into merchant, amount and date; a message into a reply; a complaint into a sentiment flag.」
  • 차량(Automotive): 「Climate, media, navigation and calls from requests in the cabin, with the tool set pinned so it survives a long drive's worth of conversation.」
  • 검색 및 매칭: 「semantic search over notes, messages and documents; a query matched to the closest of hundreds of tools; near-duplicate alerts merged on a watch.」

2. 핵심 기능 3종과 입출력 규격 — 도구 호출·구조화 추출·임베딩

Needle 3의 기능 범위는 README(https://github.com/cactus-compute/needle)에 도구 호출(Tool calls), 구조화 추출(Structured extraction), 텍스트 임베딩(Text embedding) 3종으로 명시되어 있다.

도구 호출과 구조화 추출의 문법 제약

도구 호출에 대해 README는 다음과 같이 적는다. 「given the functions your app exposes, Needle picks the right ones and fills every argument from what the user said. Ask for two things and you get two calls in order; ask for something no tool covers and you get an empty list, not a guess.」 즉, 지원 도구가 없는 요청에 대해 추측 대신 빈 리스트를 반환한다고 밝힌다.

구조화 추출에 대해 원문은 「declare a shape, hand over messy text, get typed fields back: an invoice, a booking, a notification, a form. The decode grammar guarantees the output parses, and extraction generalises to classification」이라고 적는다. 디코드 문법이 출력의 구문 분석을 보장한다는 설명이다.

단일 모델을 통한 온디바이스 벡터 임베딩

텍스트 임베딩에 대해 원문은 「the same model returns a vector for a sentence, so an app can search, match and route locally: find the note you mean, pick the tool closest to a request, collapse duplicate alerts」라고 설명한다. 동일한 단일 모델 바이너리에서 문장 벡터를 추출해 로컬 검색과 라우팅에 활용하는 구조다.

이 글의 해석으로는, 원문이 설명하는 3가지 기능은 기기 제어, 데이터 파싱, 로컬 검색이라는 엣지 작업들을 단일 바이너리 안에서 처리하도록 묶은 구성이다.

표 1. Needle 3의 핵심 기능과 입출력 규격 정리 (출처: Cactus Compute 공식 문서)
기능 분류 입력 형태 출력 형태 원문 서술 및 제약 특징
도구 호출 (Tool calls) 사용자 텍스트 프롬프트 + 파이썬 함수 데코레이터 / 스키마 정의 정형 JSON 객체 (선택된 함수명, 인자 맵, 추론 사유, 신뢰도) 순차 호출 지원, 지원 범위 밖 요청 시 추측하지 않고 빈 목록([]) 반환
구조화 추출 (Structured extraction) 비정형 원문 텍스트 + Pydantic 모델 등 데이터 클래스 형태 타입이 지정된 필드 객체 (청구서, 알림, 예약 등) 바이트 수준 디코드 문법을 통해 JSON 파싱 성공 보장, 분류 문제 확장 가능
텍스트 임베딩 (Text embedding) 단일 문장 또는 문서 텍스트 문자열 고정 차원 부동소수점 임베딩 벡터 동일 바이너리에서 추출, 로컬 시맨틱 검색·가장 가까운 도구 라우팅·중복 제거용

제품 페이지(https://cactuscompute.com/needle)의 도구 작성(Writing tools) 단락에 명시된 수칙은 다음과 같다.

  • 도구 범위: 「a narrow tool with a plain description beats a broad one. One tool per action, described by the actions it covers ("Turn a room's lights on or off") rather than a category.」
  • 열거형 옵션: 「Name enum options after what a user says (action: ["increase", "decrease"]) and keep synonyms in the description.」
  • 필수 인자: 「Give a required argument a default when a request may leave it out; a required argument with no default and no evidence in the request is withheld rather than guessed.」
  • 값 형식: 「Put value formats in descriptions ("City, ST", "e.g. T-1042"). Add triggers to intents that must always reach a tool, and keep the toolset per turn small.」

3. 래더형 단순 어텐션(Laddered Simple Attention) 아키텍처

Needle 3의 구조에 대해 README(https://github.com/cactus-compute/needle)는 다음과 같이 적는다. 「Needle 3 is a Laddered Simple Attention Network: a Monarch Hadamard MLP in place of the FFN, GQA attention with causal conv taps, engram n-gram memory read by gather, and multi-lane hyper-connections, trained so that every depth from 2 to 20 layers is a deployable model.」

FFN 대체 모나크 아다마르(Monarch Hadamard)와 mHC 레인

제품 페이지(https://cactuscompute.com/needle)의 아키텍처 도표(Figure 1)에 명시된 수치와 구성은 다음과 같다. 모델은 20개 레이어와 768 은닉 차원, 총 121M 매개변수를 갖는다. 임베딩 계층은 SentencePiece BPE 8,192개 어휘를 사용하며 묶인 unembed(8,192 × 768) 구조다. 잔차 연결은 4개 잔차 레인을 읽고 쓰는 mHC(multi-lane hyper-connections) 구조이며 sandwich ZCRMSNorm을 거친다. 어텐션 투영은 12q : 2kv 비율과 채널당 3-탭 인과적 합성곱, 윈도우 1,024 GQA 어텐션, RoPE, QK-norm을 적용하며 레이어 4, 9, 14, 19에 글로벌 어텐션이 배치된다.

FFN 자리에 들어간 Monarch Hadamard 블록은 32 × 32 크기의 변환을 사용한다. 도표 캡션에서 Cactus는 「Figure 1. The architecture spends over 2x fewer MFLOPs per token than a transformer of the same configuration」이라고 적는다.

엔그램(Engram) 메모리와 파라미터 구조

도표는 121M 매개변수 중 70.8M이 엔그램 테이블(sites 3, 7, 11, 15, 19의 18,432 슬롯, 수집 연산으로 읽히는 해시된 2-그램 및 3-그램 메모리)에 상주한다고 표기한다. README는 이에 대해 「Most of its parameters sit in the engram, so the 121M model does the arithmetic of a 50M one」이라고 적는다.

학습에 대해 제품 페이지는 「360B tokens of proprietary structured dataset」을 사용했다고 밝히며, 학습 시에만 적용되는 t+2 보조 헤드(mtp t+2 aux head)를 언급한다. 배포 형태는 CQ2 2-bit 양자화 바이너리이며, 레이어 수에 따라 8MB에서 29MB(제품 페이지 본문 표기: 9 to 29 MB) 바이너리를 생성한다. 아키텍처의 요약 사항은 다음과 같다.

  • 사다리형 모델: 2개 레이어부터 20개 레이어까지 모든 깊이가 독립적으로 배포 가능한 모델로 훈련됨
  • 바이너리 크기: 선택한 레이어 깊이에 따라 8MB에서 29MB 사이의 CQ2 2-bit 단일 바이너리로 패키징됨
  • 문법 제약: 스키마로부터 컴파일된 바이트 수준 문법이 매 토큰 생성을 제약함
  • 보정 헤드: 학습된 헤드로부터 매 턴 보정된 신뢰도 점수를 출력함

4. 설치 방법과 파이썬(Python) 기반 도구 정의 코드

Needle 3의 설치 명령은 README(https://github.com/cactus-compute/needle)에 다음과 같이 안내되어 있다. 추론 엔진은 Hugging Face(https://huggingface.co/Cactus-Compute/needle3)에서 한 번 받아 캐시된다.

pip install cactus-needle

도구 정의와 실행에 대해 README는 함수의 시그니처가 인자 타입을 제공하고, 독스트링이 도구 설명이 되며, run() 메서드가 함수 실행과 결과 반환 루프를 완료한다고 설명한다. README에 실린 코드는 다음과 같다.

import needle

@needle.tool
def get_weather(city: str):
    "Get the current weather for a city."
    return {"city": city, "temp_c": 27, "sky": "clear"}

agent = needle.Needle(tools=[get_weather])
print(agent.run("what's it like in Lagos right now?")["results"])
# [{'city': 'Lagos', 'temp_c': 27, 'sky': 'clear'}]

원문은 매 턴이 function_calls, 모델의 reasoning, 보정된 confidence를 담은 하나의 JSON 객체를 반환하며, off-topic 요청은 추측 대신 빈 리스트를 반환한다고 적는다. 기존 배포 시스템을 유지하기 위해 needle.Needle(tools=[...], generation=2) 옵션으로 Needle 2를 계속 구동할 수 있다.

5. 벤더 발표 벤치마크 성능과 측정 조건

Needle 3의 성능 수치는 Cactus Compute가 제품 페이지(https://cactuscompute.com/needle)와 벤치마크 도표에서 발표한 자체 측정값이다.

라즈베리 파이 5 토큰 속도와 벤더 발표

Cactus는 라즈베리 파이 5(Raspberry Pi 5)에서 디코드 초당 400~4,000 토큰(400-4k tokens/s decode), 프리필 초당 1,000~10,000 토큰(1-10k tokens/s prefill)의 속도를 기록했다고 밝혔다. 또한 제품 페이지에 공개된 샘플 반환 JSON에서 peak_ram_mb 값은 28.5로 표기되어 있다.

파인튜닝 시 소형 레이어의 성능 변화

평가 기준에 대해 README는 「Tool calling is exact-match accuracy on the full test splits, extraction is field micro-F1 on the full test splits」라고 명시한다. Figure 2 캡션은 Needle 3 서브네트워크(20, 16, 8, 4 레이어)가 출하 CQ2 2-bit 바이너리로 구동되었고, 베이스라인 모델들은 vLLM f16으로, DeepSeek V4 Flash는 클라우드 API로 측정되었다고 기술한다.

Cactus는 DroidCall 파인튜닝 시 각 서브네트워크의 점수가 18점에서 36점 상승하며, 4개 레이어(29M 매개변수)부터 DeepSeek V4 Flash를 상회한다고 주장했다(「fine-tuning on DroidCall lifts every subnetwork by 18 to 36 points, and from 4 layers up the tuned subnetwork passes DeepSeek V4 Flash, starting at 29M parameters (Figure 3)」). 제품 페이지에 나열된 벤치마크 스위트 6개의 행 수와 측정 기준은 다음과 같다.

  • Mobile Actions: 961개 행, 전화 명령어를 안드로이드 인텐트로 변환, 완전 일치(exact call) 측정
  • DroidCall: 200개 행, 두 번의 호출을 요구하는 항목 포함, 순서 보장 완전 일치(exact calls in order) 측정
  • BFCL v4: 3,641개 행, 버클리 함수 호출 단일 턴, AST 일치 및 무관한 요청 시 미호출 측정
  • DSTC8: 1,813개 턴, 대화 슬롯을 스키마로 추출, 필드 F1 측정
  • SNIPS gold: 700개 행, 스키마가 주어진 상태의 슬롯 필링, 필드 F1 측정
  • SNIPS 7-way: 700개 행, 7개 스키마 중 선택 후 슬롯 필링, 필드 F1 측정

6. 신뢰도 게이팅과 정규식 트리거를 통한 실행 제어

Needle 3는 오작동 제어를 위해 신뢰도(confidence) 점수와 정규식(triggers) 옵션을 제공한다.

0.1 신뢰도 바닥값과 거부 로직

원문에 따르면, 모델의 모든 응답 JSON은 학습된 헤드에서 산출된 보정된 confidence 점수를 포함한다. 추론 엔진은 기본적으로 0.1이라는 신뢰도 바닥값(floor)을 적용한다. 산출된 신뢰도가 0.1 미만으로 떨어지면 함수 호출은 suppressed_calls로 보류되고 function_calls는 빈 리스트로 반환된다.

Cactus가 제시한 제어 패턴 코드는 confidence가 0.7 이상일 때 도구를 실행(execute)하고, 0.1~0.7 구간이거나 suppressed_calls가 있으면 사용자에게 확인(confirm)하며, 호출이 없으면 수행 거부 메시지를 출력하도록 안내한다. 또한 정규식(triggers)이 설정된 도구는 요청 문장과 매칭될 때 디코딩이 해당 도구로 제한되어 0.1 바닥값 아래에서도 호출이 전달된다.

커뮤니티 시험에서 보고된 한계와 주의점

GeekNews 토론(https://news.hada.io/topic?id=33923) 등 초기 시험 보고에서는 벤더 발표와 구별되는 다음 한계들이 언급되었다.

  • 발화 왜곡 취약성: 단어의 중의성이나 줄임말이 입력될 때 엉뚱한 도구가 호출되는 현상(예: 욕실 조명을 켜라는 의도로 말한 「wee」가 음악 장르 검색 도구로 해석되는 오작동 사례)
  • 체감 성능 평가: 대형 모델 수준의 일반 추론을 기대했을 때 기대 이하의 오작동을 보여 마케팅 대비 체감 성능이 과장되었다는 반응
  • 도구 스키마 의존성: 도구 정의문(docstring)과 매개변수 명칭, 스키마 품질이 시스템 결과를 좌우한다는 점
  • 소형 서브네트워크 한계: 2~4개 레이어로 줄였을 때 정밀한 다운스트림 파인튜닝 없이는 기본 정확도가 저하될 수 있다는 점
  • 도구 집합 크기: 턴당 도구 수가 늘어날수록 오라우팅 가능성이 커지므로 턴당 도구 수를 작게 유지해야 한다는 점
