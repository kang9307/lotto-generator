背景 - 为AI智能体接入实时网络搜索上下文的接口

基于大语言模型（LLM）的AI智能体有一个局限：模型用截至某个时间点的数据训练之后就固定下来了。因此它只知道知识截止日期（knowledge cutoff）之前存在的信息，要与模型一起处理近期事件、变化中的API或快速变动的新闻并不容易。About页面解释说，没有搜索时，需要实时信息的智能体通常会猜测网页的URL并直接获取，猜错时请求会返回404 Not Found，智能体只能重新尝试。

Cloudflare于2026年10月2日在更新日志中发布的Web Search API以测试版提供。更新日志介绍说，它让AI智能体和应用可以搜索互联网，以实时信息作为回答的依据，而不是猜测URL或依赖模型的训练截止日期。就像人从搜索引擎出发一样，智能体发送查询后会收到一份相关且最新的结果列表，开发者再把这些结果放入模型上下文，使回答以实时信息为依据。

About页面记录的处理顺序分为四步。第一步，请求经由指定的AI Gateway转发。第二步，把查询转发给所选的搜索提供商（Ceramic.ai、Exa或Linkup），未指定提供商时默认使用Ceramic.ai。第三步，把提供商的响应规范化为统一格式，每条结果包含URL和标题，以及可选的描述、图片、网站图标和最后修改日期。第四步，把请求记录到AI Gateway日志并向账户计费。按文档所述，这一流程有四个值得注意的地方。

  • 其一，Ceramic.ai、Exa、Linkup都被规范化为相同的结果格式，因此按文档的说法，只需改动一个参数就能切换提供商。
  • 其二，所有请求都经过被介绍为AI应用控制平面（control plane）的AI Gateway，搜索请求与模型推理请求一起出现在网关日志和分析中。
  • 其三，按统一计费（Unified Billing），搜索从AI Gateway点数余额中扣除，价格是各提供商的官方定价（list API price），不额外加价。
  • 其四，三家提供商已承诺（committed）遵守Cloudflare的验证爬虫（Verified Bot）爬取标准，About页面还写明每条搜索结果都必须包含指向所爬取内容位置的链接。

核心设计 - 作为统一点的AI Gateway与统一计费架构

Web Search API构建在AI Gateway之上。How to use页面写道，无论是可在任意后端使用的REST API，还是Worker的AI绑定，两种调用方式都经由AI Gateway转发请求。每个账户都有一个名为default的网关，需要时也可以新建网关。开始使用需要Cloudflare账户和AI Gateway，并且二选一准备好：账户中已充值的AI Gateway点数，或保存在网关上的提供商API密钥。

About页面把所有搜索请求都经过网关所带来的好处归纳为以下四点。

  • 可观测性（Observability）：搜索请求与模型推理请求一起出现在网关的日志和分析中。
  • 统一计费（Unified Billing）：搜索从AI Gateway点数余额中扣除，按各提供商的官方定价支付，不额外加价。费率见Providers页面。
  • 自带密钥（BYOK）：如果已经拥有搜索提供商的账户，可以把提供商API密钥保存到网关上，此时由提供商直接向用户收费。
  • 访问控制（Access control）：控制网关可以使用哪些提供商，以及谁可以发送请求。

Providers页面把同一内容改写成了计费规则。用AI Gateway点数支付时，每次搜索按提供商的官方定价计费且不额外加价；自带密钥时，则由提供商依据用户与其签订的协议直接收费。

文档的要点是，每次搜索调用的记录和账单都汇集在网关这一处。至于访问控制按什么规则配置，以及网关日志里保留请求的哪些字段，这些文档没有说明。文档能够确认的范围，是模型推理成本与搜索成本可以在同一份点数余额下查看。

三家搜索提供商特性与Zero Data Retention标注对比

在测试版发布之初，可选的搜索提供商包括Ceramic.ai、Exa和Linkup三家。在请求参数中指定provider字段即可无缝切换底层引擎；若省略该字段，系统默认使用Ceramic.ai。三家提供商在索引规模、检索技术路线、内容摘要结构及收费标准上存在明显差异。

下表汇集了官方技术文档（Providers）中披露的各项核心参数与报价。

提供商标识符 索引规模与搜索机制 结果摘要形式 数据非保留（Zero Data Retention） 每千次请求官方单价
ceramic（默认） 超400亿网页的独立索引，专为AI低延迟与低成本优化 长达8,000字符的详尽页面描述 Yes（支持） $0.25（单次请求$0.00025）
exa 融合关键词与语义嵌入的auto搜索模式 与检索词高度相关的网页高亮片段（highlights） No（参数表明确标为不支持） $7.00（单次请求$0.007）
linkup 基于受信任数据源的fast深度原始搜索，不合成答案 原始文本引用片段与来源链接 Yes（支持） $5.00（单次请求$0.005）

官方文档之间的表述在这里出现了分歧。2026年10月2日的更新日志正文写道，三家提供商对通过Cloudflare发出的请求均支持Zero Data Retention。然而同日更新的Providers页面属性表中，Exa的Zero Data Retention值为No，Ceramic.ai与Linkup在表中同样为Yes。目前没有发现能说明哪一种表述准确的后续更正，因此在搜索词不得留存在提供商服务器上的环境中，可以以详细表格中的值为准，在provider中明确指定Ceramic.ai或Linkup，这样的选择与两份文档都不冲突。

Providers页面对各提供商的介绍如下。关于适合什么场景的说法，都是文档自己给各提供商附上的措辞。

  • Ceramic.ai：运营专为AI智能体和LLM应用设计的自有独立网页索引（超过400亿页面），主打低延迟、低成本的搜索。文档称它很适合每个任务要搜索多次的智能体、让聊天机器人回答以最新信息为依据，以及用实时网络来源核对模型输出（a good fit）。结果包含每个页面最长8,000字符的长描述，价格为每千次请求0.25美元。
  • Exa：为AI打造的搜索引擎，使用把传统关键词搜索与基于嵌入的搜索结合起来的自有索引。请求使用兼顾结果质量与速度的平衡模式auto搜索类型，与查询最相关的文本片段即高亮（highlights）作为结果描述返回。文档称，想把简洁且切合查询的摘录直接送进模型上下文时它很适合，价格为每千次请求7.00美元。
  • Linkup：面向AI应用的网络搜索，返回来自全网的带来源结果和文本片段。请求使用fast搜索深度和原始搜索结果，因此不生成答案。文档称它适合需要来自可信来源的快速、可引用结果的智能体工具调用，价格为每千次请求5.00美元。
  • 结果格式：About页面写道，所有提供商返回相同的结果格式（URL与标题，以及可选的描述、图片、网站图标和最后修改日期），因此只需改动provider的值就能切换。描述是可选字段，最好不要假定每家提供商总会填写。

Providers页面还为每家提供商配有属性表，列出provider值、Zero Data Retention状态和价格，并附上提供商自己的文档与服务条款链接。条款与数据处理方式由提供商自行规定，因此在真正引入之前，需要另外打开各家提供商的条款页面确认。

调用接口 - REST API与Workers AI绑定规范

Cloudflare提供两种调用途径：面向通用后端服务的标准REST API，以及面向边缘无服务器环境的Workers AI原生运行时绑定。

REST API向端点POST https://api.cloudflare.com/client/v4/accounts/{account_id}/ai/websearch/发送请求。认证使用同时具备两项权限的Cloudflare API令牌，即账户级的Workers AI > Read与AI Gateway > Read。

官方文档提供的标准cURL调用示例如下：

curl https://api.cloudflare.com/client/v4/accounts/$CLOUDFLARE_ACCOUNT_ID/ai/websearch/ \
                      --request POST \
                      --header "Authorization: Bearer $CLOUDFLARE_API_TOKEN" \
                      --header "Content-Type: application/json" \
                      --data '{
                        "query": "What are some fun things to do in Salt Lake City as fall approaches?",
                        "provider": "ceramic",
                        "limit": 5,
                        "options": { "gateway": { "id": "default" } }
                      }'

在Workers环境中，先在Wrangler配置文件中添加AI绑定（ai: { binding: "AI" }），再把网关ID和查询传给env.AI.websearch()。文档的配置示例把compatibility_date设为2026-10-05，并附有提示将该值设为当天日期的注释。websearch()返回标准的Response对象，用response.json()读取结果。

export default {
                    	async fetch(request, env): Promise<Response> {
                    		const response = await env.AI.websearch({
                    			gatewayId: "default",
                    			query: "What are some fun things to do in Salt Lake City as fall approaches?",
                    			provider: "exa",
                    			limit: 5,
                    		});
                    
                    		const results = await response.json();
                    		return Response.json(results);
                    	},
                    } satisfies ExportedHandler<Env>;

文档列出的请求参数如下。在REST请求体中，网关放在options对象里；在Worker调用中，则放在gatewayId里。

  • query（必填，字符串）：搜索查询，minLength为1，maxLength为1,024。
  • provider（选填，字符串）：ceramic、exa、linkup之一，默认值为ceramic。
  • limit（选填，整数）：返回的最大搜索结果条数，最小1、最大10，默认10。单次请求返回的结果上限为10条。
  • options.gateway.id（REST，必填）或gatewayId（Worker，必填）：转发请求所经的AI Gateway的ID。使用默认网关时指定default。
  • byokAlias（选填，字符串）：保存在网关上的提供商API密钥的别名，格式为^[A-Za-z0-9_-]{1,64}$。若指定了别名而对应密钥没有配置，请求会失败，而不会回退到AI Gateway点数。

接口返回的标准化JSON数据结构如下：

{
                      "items": [
                        {
                          "url": "https://example.com/salt-lake-city-fall-guide",
                          "title": "Fall in Salt Lake City: A Local's Guide",
                          "description": "From scenic drives up Big Cottonwood Canyon to pumpkin patches..."
                        }
                      ],
                      "metadata": {
                        "query": "What are some fun things to do in Salt Lake City as fall approaches?",
                        "requestId": "<REQUEST_ID>",
                        "latencyMs": 612
                      }
                    }

响应正文对所有提供商都由items数组和metadata对象（包含query、requestId、latencyMs）构成。结果条目基本包含url和title，描述、图片、网站图标和最后修改日期只有在提供商返回时才会出现，文档的响应格式部分也说明可选字段只在提供商返回时才包含。

How to use页面还给出了把搜索当作模型工具来使用的示例。先为模型定义一个名为web_search的函数工具，模型调用该工具后，代码用websearch()执行搜索，再把结果作为tool角色的消息交还给模型。示例调用的是Workers AI模型，并把搜索结果限制为5条。文档列出的限制只有两项，即查询长度1,024字符和每次请求10条结果。

爬虫标准与来源归属 - 提供商承诺遵守的标准

About页面的「Crawler standards」一节从Cloudflare自己的立场谈起：爬虫应当诚实、透明，并尊重网站所有者设定的规则和偏好；网站所有者对自己的内容如何被使用，应当拥有有意义的可见性和控制权。

随后页面写道，每一家Web Search API提供商都已承诺（has committed）满足以下标准。

  • 验证爬虫合规（Verified bot compliance）：提供商使用的爬虫必须满足Cloudflare公布的验证爬虫要求，其中包括标明爬虫身份以及遵守robots.txt。
  • 来源归属（Source attribution）：每条搜索结果都必须包含指向所爬取内容位置的链接。
  • 页面在结尾概括的目的：使用该API时，智能体消费的是那些让网站所有者对其内容如何被爬取拥有透明度、控制权和可见性的运营者提供的搜索结果。

以上就是文档直接写出的内容。这些承诺实际如何核查，以及网站运营者如何识别并控制各家提供商的爬虫，这些文档没有涉及。如实转述更新日志所说的承诺和About页面的两项标准，不再向前推进，就是本节的范围。

自带API密钥（BYOK）运维与机密管理结构

根据How to use页面，已经拥有搜索提供商账户的用户可以用自己的API密钥代替AI Gateway点数，此时由提供商直接向用户收费。操作步骤与密钥选择规则如下。

  • 控制台登记：在Cloudflare控制台进入AI Gateway页面，选择网关，再选择Provider Keys。为Ceramic.ai、Exa或Linkup添加API密钥，并为其指定别名（alias，例如default）。如果提供商不在列表中，选择Configure custom providers进行添加。
  • 密钥保管：API密钥不会随请求发送。AI Gateway会取出网关上与提供商和别名对应的已存密钥来使用，已存储的密钥由Secrets Store加密。
  • 指定别名时：传入byokAlias，就使用该别名的已存密钥。若网关上没有配置该提供商或别名，请求不会回退到点数，而是以400错误失败。
  • 省略别名时：如果网关上有该提供商default别名的密钥，就使用该密钥，否则搜索计入AI Gateway点数。

文档的BYOK示例，是查询「What is Cloudflare Workers?」、provider为exa、byokAlias为default的请求。调用形式与点数方式相同，只多出byokAlias一行。关于密钥存储的更多细节，How to use页面指向AI Gateway的「Bring your own keys」文档。

官方文档表述与未确认事项对照

评估新技术基础设施时，必须将官方文档明确保证的参数与尚未披露的技术边界进行清晰对照。下表归纳了当前已确认的技术规范与文档未确认的关键事项。

技术领域 官方文档明确说明的事项 尚未核实或需注意的技术边界
数据保留政策 Ceramic.ai与Linkup明确标注支持Zero Data Retention 更新日志正文声称全员支持但参数表中Exa标为No，存在文档冲突
计费与费率 按提供商原厂价格直接扣除网关余额，平台无加价 官方文档未说明是否存在免费试用额度及最低点数充值门槛
调用参数约束 明确列出搜索词1至1,024字符、单次结果1至10条（默认10条）的上限 账户级别每分钟或每天的最大请求频率限制（Rate Limit）未予公开
框架生态支持 记载REST API端点与Worker的AI绑定，并附有模型工具调用示例 在这些文档中未能找到针对LangChain、LlamaIndex或MCP等智能体框架的适配器

基于上述对比，技术团队在接入生产系统前应重点评估以下环节：

  • 由于未公布并发限流阈值，高频批量查询任务需要完善退避重试机制。
  • 单次调用最多返回10条结果，深度研究型任务必须在智能体上层自行构建多轮多角度的查询拆分流程。
  • 鉴于Exa在参数表中被标记为不支持零数据保留，涉及用户隐私或商业敏感数据的检索任务应在配置中明确锁定使用Ceramic.ai或Linkup。
  • 在本地开发环境（wrangler dev）中使用AI绑定时，是产生真实网络调用扣费还是使用Mock数据，官方文档尚未说明，开发调试时需格外留心。

未能确认的内容

  • 关于Exa是否支持Zero Data Retention在更新日志正文（全员支持）与参数表格（Exa为No）之间的真实准确归属。
  • 不同账户级别（Free、Workers Paid、Enterprise）在Web Search API上的每分钟与每天全局调用频次上限（Rate Limit）。
  • 新建AI Gateway网关实例时是否附带免费搜索试用配额或赠送点数。
  • 各搜索提供商在抓取全网数据时使用的具体User-Agent标识符与IP网段详情。
  • 使用wrangler dev进行本地开发调试时env.AI.websearch()的本地模拟机制支持情况。
