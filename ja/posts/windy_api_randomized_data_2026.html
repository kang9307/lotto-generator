無料APIがわざと間違ったデータを返すとき - Windyサーフ予報に見るAPI信頼の落とし穴

Windy無料APIの公式ランダムデータ方針から見る、フリーミアム型データ劣化とAPI信頼性検証の開発者視点分析

2026-07-03 開発・インフラ

序論: 無料APIを信じてコードを書いていいのか

2026年7月時点、あるサーフ予報API比較記事が開発者コミュニティで静かに話題になっている。複数の無料サーフ・気象予報APIを並べて実際にテストした結果、Windyの API Trial(体験)キーが実際の観測・モデルデータではなく、無作為に生成された値を返すという事実が改めて確認された。驚くべきは、これが隠された落とし穴ではなく、Windy自身が公式コミュニティフォーラムで認めている立場だという点だ。

本稿はこの一件を出発点に、無料APIティアが意図的にデータ品質を下げる慣行が業界全体でどれほど一般的か、それを知らずにAPIに依存する開発者がどんなリスクにさらされるか、そして新しいAPIを導入する前に実際に何を確認すべきかを整理する。特定サービスを非難する記事ではなく、この事例が示す構造的な問題を整理する記事である。

1. 何が発覚したか - Windy Trial APIの「ランダムデータ」公式認定

1.1 発覚の経緯

きっかけは単純だ。複数の無料サーフ予報APIを実際にテスト・比較する中で、Windy Point Forecast APIの無料Trialキーで得た応答値が、時間が経っても物理的に整合しないパターンを示していた。Windy公式コミュニティで確認すると、Windyスタッフが関連する質問に対しすでに「it generates random data」(Windyコミュニティ、スタッフSuty)と回答していた。つまりバグではなく、設計された挙動だった。

1.2 TrialとProfessional、正確に何が違うのか

Windy APIはTrialとProfessional(有料)の2軸に分かれる。Trialキーは1日のリクエスト数が制限されているだけでなく、スタッフの表現を借りれば「テスト目的」のためだけに存在し、ランダムなデータを返す。一方Professionalプランは、ECMWF・GFSなど実際の気象モデルの観測・予測値をそのまま提供する。「無料はリクエスト回数が少ないだけで値自体は本物」という一般的な思い込みは、この事例では通用しない。

2. これは一般的な「無料制限」とは違う - 静かな失敗という問題

2.1 レートリミット対データ歪曲

レートリミット(rate limit)や解像度の低下は、開発者がすぐに体感できる制限だ。429エラーを受け取ったり、格子間隔が粗いデータを受け取れば、「ここまでが無料なのか」とすぐに気づく。しかし無作為に混ぜられた値を返すのは違う。応答は200 OKで正常に届き、値は数値として妥当な範囲に収まっている。失敗ではなく、静かな誤答が届くのだ。

2.2 テストを通過する偽データの危険性

開発者が連携テストを行う際は、多くの場合「リクエストが成功するか」「応答スキーマが正しいか」を確認する。値そのものが実際の観測値と一致するかを一つ一つ照合することは稀だ。その結果、Trialキーで作ったプロトタイプは正常に動作しているように見えても、中の数値は最初から意味がなかった可能性がある。個人プロジェクトがそのまま本番環境に移行したり、テストコードに無料キーが残っていたりすると、問題はデプロイ後に初めて発覚する。

3. プレミアム誘導のためのデータ劣化 - 業界全体のパターン

3.1 無料ティアを悪くする3つの方法

無料ティアを意図的に魅力の低いものにする方法は大きく3つある。第一は使用量上限(リクエスト数、呼び出し頻度)。第二は機能ロック(特定エンドポイント・フィルター・バッチ処理の無効化)。第三はデータ品質そのものの低下(解像度縮小、遅延提供、そしてWindyのように値自体の置き換え)。前の2つは業界で広く受け入れられている正常なフリーミアム戦略だ。第三、特に値をまったく別の値にすり替える方式は、はるかに稀で議論の余地がある。

3.2 ウォーターマーク・遅延・解像度低下 - 類似業種の事例

似たような慣行は他の業種でも見られる。金融データAPIは無料ティアでリアルタイムの代わりに15~20分遅延した相場を提供することが多い。地図・画像APIは無料リクエストにウォーターマークを入れたり、低解像度タイルのみを提供したりする。こうした事例は概して「遅延している」「解像度が低い」というように、ユーザーがすぐに気づける形で劣化する。Windyの方式が異例なのは、劣化ではなく置き換えだからだ。値が遅かったりぼやけていたりするのではなく、そもそも実際の観測とは無関係な数値が届く。

4. 本当の問題は透明性の「置き場所」だ

4.1 Windyは実際には隠していない

ここでWindyを非難しようとしているわけではない。Windyはこの方針を隠していない。スタッフがコミュニティの質問に明確に答えており、Trialが「テスト目的」であることも複数回言及されている。ビジネス的にも合理的だ。実用可能な正確なデータを無料かつ無制限に公開すれば、有料のProfessionalプランを買う理由がなくなる。

4.2 「文書にある」と「開発者が実際に目にする」の間の溝

問題は公開の場所だ。この情報はAPIメインドキュメントの目立つ場所ではなく、コミュニティフォーラムの回答スレッドに埋もれていた。初めてAPIを連携する開発者が、応答ヘッダーやフィールド説明、あるいは少なくともリクエストURLの近くで「この応答はテスト用のランダムデータです」という文言に直接出会うことは難しい。技術的には公開されているが、実際にその情報にたどり着くのは、すでに問題に遭遇して検索した一部の人だけだ。公開したという事実と、発見可能だったという事実は違う。

5. 開発者が無料APIに依存する際のリスク

5.1 プロトタイプから本番への移行の瞬間

最も多い失敗パターンはこうだ。サイドプロジェクトやMVPをTrialキーで素早く作り、反応が良ければそのままユーザーに公開する。この段階で有料転換を検討しなければ、サービスは表面上は動作しているように見えても、中の数値は信頼できない状態のまま固定される。特にサーフィンや気象のように、ユーザーがその値を信じて実際の行動(波に乗りに行くかどうか)を決めるドメインでは、静かな誤答が実質的な被害につながりかねない。

5.2 個人ツール・社内ダッシュボードも例外ではない

個人ツールや社内ダッシュボードも例外ではない。「どうせ自分しか見ないから」という考えで無料キーを使い続け、そのツールの判断を根拠に実際の意思決定(在庫、スケジュール、運用)を下し始めると、同じリスクが繰り返される。無料APIをプロトタイプ以上の用途で使う計画があるなら、そもそもそのデータが本物かどうかを確認する習慣が必要だ。

6. API信頼性を検証する現実的な方法

6.1 クロスチェック - 権威あるソースと最低1回照合する

最も確実な方法はクロスチェックだ。同じ時刻・同じ座標の値を、信頼できる別のソース、例えば政府気象機関やNOAAのブイ観測所のように生データを公開する機関のデータと、最低1回は直接照合する。相関がなければ、そのAPIは本番環境で使えないと見るべきだ。

6.2 フォーラム・イシュートラッカーまで検索せよ

公式ドキュメントだけでなく、サポートフォーラム・GitHub Issue・コミュニティ掲示板まで検索せよ。「trial」「sample」「demo」「random」「test data」といったキーワードで該当API名と一緒に検索すると、今回のWindy事例のようにベンダーがすでにどこかで静かに認めている制約が見つかることが多い。こうした情報は公式ランディングページよりサポートスレッドに先に現れる傾向がある。

6.3 定量的な制限と定性的な表現を区別せよ

料金ページの表現が定量的か定性的かを区別して読め。「月1,000回」「分間10回」のように数値で明示された制限は予測可能で検証しやすい。一方「テスト目的」「サンプルデータ」「限定的な精度」のように定性的にのみ表現された条項は、実際に何を意味するのかコードで確認するまでわからない。定性的な表現が現れたら、その時点で実際の応答値を検証対象とすべきだ。

7. 代替APIを選ぶ際の基準

7.1 Open-Meteoの事例 - ライセンスとモデル出所が明示された提供者

今回の事例で代替としてよく挙げられるのがOpen-Meteoだ。APIキーなしで非商用用途なら1日最大1万件まで無料で、GFS・ECMWF・DWD ICONなど各国気象機関の実際のモデルをそのまま提供する。データはCC BY 4.0でライセンスされており、サーバーコード自体がAGPLv3でオープンソース公開されているため、必要であれば自前でホスティングして無制限に使うこともできる。無料ティアの限界が「数値で明示された呼び出し上限」であって「値の真正性」ではない点が重要だ。

7.2 「何をどれだけ提供するか」が明確な提供者を優先せよ

一般化すると基準はこうなる。データの出所(どのモデル・どの観測網を使っているか)を明示する提供者を優先し、無料と有料の違いが「何をどれだけ」のように数値で説明されている提供者を優先し、ライセンスと再配布条件が明確な提供者を優先する。逆に、無料ティアの精度やデータの性質について曖昧にしか記述されていない場合は、実際の値を自ら検証するまでそのAPIを信頼の基準線としないほうが安全だ。

結論: 無料は「検証済み」を意味しない

WindyのTrial APIがランダムデータを返すという事実自体は、不正行為ではない。Windyはこれを否定したことはなく、ビジネスモデルとしても理解できる選択だ。本稿で本当に指摘したかったのは別のところにある。フリーミアムのビジネスモデルにおいてデータ品質の低下はよくある戦略だが、その低下が静かに、しかもドキュメントの奥深くだけで行われるとき、開発者は気づかないうちに偽データの上にサービスを積み上げることになる。

2026年7月時点で無料APIエコシステムは拡大を続けており、こうした事例は今後さらに増える可能性が高い。結論はシンプルだ。「無料」という言葉を「検証済みデータ」と同一視せず、最低1回は権威あるソースと値を照合してから、そのAPIを信頼の基準線に置くべきだ。
