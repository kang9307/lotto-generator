1. What is Rsync? 🤔

Rsync (Remote Sync) is a tool for efficiently synchronizing and transferring files and directories on Unix-like systems. Since it was developed in 1996 by Andrew Tridgell and Paul Mackerras, it has become an indispensable tool for system administrators.

✨ Key features of Rsync

🎯 Core advantages

  • Incremental transfer: Sends only the changed portions to save bandwidth
  • Compression support: Compresses data during network transfer for faster throughput
  • Preserves permissions: Keeps file permissions, ownership, timestamps, and other metadata intact
  • Encryption support: Secure remote transfer over SSH
  • Resume capability: Interrupted transfers can be resumed instead of restarted

🔍 How it works

Rsync uses a rolling checksum algorithm to identify and transfer only the changed portions of a file. That means efficient synchronization without having to send the entire file every time.

# Check that Rsync is installed
which rsync
rsync --version

2. Basic syntax and core options ⚙️

📝 Basic syntax

rsync [options] source destination
rsync [options] source user@host:destination
rsync [options] user@host:source destination

🔧 A complete rundown of core options

Option Long form Description
-v --verbose Show detailed output
-r --recursive Recurse into subdirectories
-a --archive Archive mode (equivalent to -rlptgoD)
-z --compress Compress data during transfer
-h --human-readable Print sizes in a human-readable format
-P --progress Show progress (--partial --progress)
--delete - Delete files in the destination that no longer exist in the source
--dry-run -n Simulate without actually transferring anything
--exclude - Exclude specific files or directories
--include - Include specific files or directories

🌟 Commonly used option combinations

💡 Recommended option combinations

  • -avzP: Archive mode + compression + progress output
  • -avzh --delete: Full synchronization (mirroring)
  • -avzh --dry-run: Safe dry-run testing

3. Real-world usage examples 💼

📁 Synchronizing between local directories

# Basic copy
rsync -avzh /source/directory/ /destination/directory/

# Copy with progress output
rsync -avzP /home/user/documents/ /backup/documents/

# Fully mirror, including deletions
rsync -avzh --delete /source/ /destination/

# Copy only certain file types
rsync -avzh --include="*.jpg" --include="*.png" --exclude="*" /photos/ /backup/photos/

🌐 Transferring files to a remote server

# Push from local to remote
rsync -avzh /local/directory/ user@remote-server:/remote/directory/

# Pull from remote to local
rsync -avzh user@remote-server:/remote/directory/ /local/directory/

# SSH connection on a non-default port
rsync -avzh -e "ssh -p 2222" /local/directory/ user@server:/remote/directory/

# Authenticate with an SSH key
rsync -avzh -e "ssh -i ~/.ssh/my-key" /local/directory/ user@server:/remote/directory/

🔒 Hardening the transfer

# Also enable SSH-level compression
rsync -avzh -e "ssh -C" /local/directory/ user@server:/remote/directory/

# Limit bandwidth (1000 KB/s)
rsync --bwlimit=1000 -avzh /local/directory/ user@server:/remote/directory/

# Verify integrity with checksums
rsync -avzh --checksum /source/ /destination/

4. SSH integration and security 🔐

🔑 Setting up SSH key-based authentication

# Generate an SSH key
ssh-keygen -t rsa -b 4096 -C "your-email@example.com"

# Copy the public key to the remote server
ssh-copy-id user@remote-server

# Add the key to the SSH agent
ssh-add ~/.ssh/id_rsa

# Use the SSH key with Rsync
rsync -avzh -e "ssh -i ~/.ssh/id_rsa" /local/ user@server:/remote/

⚡ Tuning SSH performance

# Example SSH config file (~/.ssh/config)
Host myserver
    HostName 192.168.1.100
    User myuser
    Port 22
    IdentityFile ~/.ssh/my-private-key
    Compression yes
    ServerAliveInterval 60
    ServerAliveCountMax 3

# Use the config alias
rsync -avzh /local/directory/ myserver:/remote/directory/

⚠️ Security considerations

  • Protect SSH keys with appropriate permissions (600 or 400)
  • Where possible, move the SSH port off the default (22)
  • Configure firewall rules accordingly
  • Rotate SSH keys on a regular schedule

5. Advanced features and tips 🚀

📋 Using exclude and include patterns

# Exclude multiple file types
rsync -avzh --exclude="*.tmp" --exclude="*.log" --exclude=".git/" /source/ /dest/

# Use an exclude list file
echo "*.tmp" > exclude-list.txt
echo "*.log" >> exclude-list.txt
echo ".git/" >> exclude-list.txt
rsync -avzh --exclude-from=exclude-list.txt /source/ /dest/

# More complex pattern example
rsync -avzh \
  --include="*.jpg" \
  --include="*.png" \
  --include="*/" \
  --exclude="*" \
  /photos/ /backup/photos/

🔄 Backup strategy: incremental backups

# Create a date-stamped backup directory
BACKUP_DIR="/backup/$(date +%Y-%m-%d)"
mkdir -p "$BACKUP_DIR"

# Incremental backups using hard links
rsync -avzh --link-dest=/backup/latest /source/ "$BACKUP_DIR"/
ln -nsf "$BACKUP_DIR" /backup/latest

# Example backup script
#!/bin/bash
SOURCE="/home/user"
BACKUP_BASE="/backup"
DATE=$(date +%Y-%m-%d_%H-%M-%S)
BACKUP_DIR="$BACKUP_BASE/$DATE"
LATEST_LINK="$BACKUP_BASE/latest"

# Run the backup
rsync -avzh --delete --link-dest="$LATEST_LINK" "$SOURCE/" "$BACKUP_DIR/"

# Update the "latest" symlink
ln -nsf "$BACKUP_DIR" "$LATEST_LINK"

📊 Logging and monitoring

# Write a detailed log file
rsync -avzh --log-file=/var/log/rsync.log /source/ /dest/

# Include transfer statistics
rsync -avzh --stats /source/ /dest/

# Monitor progress in real time
rsync -avzh --progress --stats /source/ /dest/ | tee rsync-log-$(date +%Y%m%d).txt

6. Performance tuning ⚡

🔧 Transfer performance tuning

# Cap bandwidth (KB/s)
rsync --bwlimit=1000 -avzh /source/ /dest/

# Adjust compression level (1-9, default is 6)
rsync -avzh --compress-level=9 /source/ user@server:/dest/

# Pick the checksum algorithm
rsync -avzh --checksum-choice=md5 /source/ /dest/

# Run multiple rsync processes in parallel
# (using GNU parallel)
find /source -maxdepth 1 -type d | parallel -j4 rsync -avzh {} /dest/

💾 Handling large files

# Enable partial transfers (resumable after interruption)
rsync -avzh --partial /large-files/ /dest/

# In-place updates (save disk space)
rsync -avzh --inplace /source/ /dest/

# Handle sparse files
rsync -avzh --sparse /source/ /dest/

# Combined flags optimized for large files
rsync -avzh --partial --inplace --progress /large-files/ /dest/

💡 Performance tuning tips

  • Network bandwidth: Use --bwlimit to minimize impact on other services
  • Compression: Tune based on CPU and network conditions
  • Checksum usage: --checksum is useful for small files; keep defaults for larger ones
  • SSH compression: Combine with -e "ssh -C" to compress at the SSH layer too

7. Troubleshooting 🔍

❌ Common problems and solutions

🔐 Permission issues

# How to handle permission errors
# 1. Ignore ownership info
rsync -avzh --no-owner --no-group /source/ /dest/

# 2. Ignore permission info
rsync -rvzh --no-perms /source/ /dest/

# 3. Run with administrator privileges
sudo rsync -avzh /source/ /dest/

🌐 Network connection issues

# Set a timeout
rsync -avzh --timeout=30 /source/ user@server:/dest/

# Set timeouts for connection and transfer
rsync -avzh --timeout=30 --contimeout=10 /source/ user@server:/dest/

# Check the connection
rsync -avzh --dry-run user@server:/source/ /dest/

💾 Out of disk space

# Check disk usage
df -h

# Use partial transfers to improve space efficiency
rsync -avzh --partial --inplace /source/ /dest/

# Move the temporary file location
rsync -avzh --temp-dir=/tmp/large-temp /source/ /dest/

🐛 Debugging and log analysis

# Detailed debug info
rsync -avzh --debug=ALL /source/ /dest/

# Debug a specific module
rsync -avzh --debug=FILTER /source/ /dest/

# Adjust log level
rsync -avzh --verbose --verbose /source/ /dest/

# Print errors only
rsync -avzh --quiet /source/ /dest/ 2>&1 | grep -i error

⚠️ Things to watch out for

  • --delete option: Can accidentally delete important files
  • Trailing slash on paths: /source/ and /source produce different results
  • Symbolic links: Use -L to decide whether to follow them and copy their targets
  • Network stability: Use --partial on unreliable connections

8. Real-world scenarios 🏢

🎯 Scenario 1: Website deployment

#!/bin/bash
# Website deployment script

# Configuration
LOCAL_DIR="/var/www/html"
REMOTE_SERVER="web-server.example.com"
REMOTE_DIR="/var/www/html"
BACKUP_DIR="/backup/website-$(date +%Y%m%d-%H%M%S)"

# Back up the remote server
ssh user@$REMOTE_SERVER "mkdir -p /backup"
rsync -avzh user@$REMOTE_SERVER:$REMOTE_DIR/ $BACKUP_DIR/

# Deploy the new version
rsync -avzh --delete \
  --exclude=".git/" \
  --exclude="*.log" \
  --exclude="config/local.php" \
  $LOCAL_DIR/ user@$REMOTE_SERVER:$REMOTE_DIR/

echo "Deployment complete. Backup: $BACKUP_DIR"

💾 Scenario 2: Database backup synchronization

#!/bin/bash
# Database backup synchronization script

DB_NAME="myapp"
BACKUP_LOCAL="/backup/db"
BACKUP_REMOTE="backup-server:/backup/db"
DATE=$(date +%Y%m%d)

# Dump the database
mysqldump -u root -p$DB_PASSWORD $DB_NAME | gzip > $BACKUP_LOCAL/db-$DATE.sql.gz

# Sync to the remote backup server
rsync -avzh --delete \
  --include="*.sql.gz" \
  --exclude="*" \
  $BACKUP_LOCAL/ $BACKUP_REMOTE/

# Delete backup files older than 30 days
find $BACKUP_LOCAL -name "*.sql.gz" -mtime +30 -delete

📱 Scenario 3: Development environment sync

#!/bin/bash
# Development environment sync script

PROJECT_DIR="/home/developer/projects/myapp"
DEV_SERVER="dev.example.com"
STAGING_SERVER="staging.example.com"

# Sync from dev to staging
sync_to_staging() {
    rsync -avzh --delete \
      --exclude="node_modules/" \
      --exclude=".env.local" \
      --exclude="*.log" \
      --exclude=".git/" \
      developer@$DEV_SERVER:$PROJECT_DIR/ \
      developer@$STAGING_SERVER:$PROJECT_DIR/
}

# Sync from local to dev
sync_to_dev() {
    rsync -avzh \
      --exclude="node_modules/" \
      --exclude=".env.local" \
      --exclude="*.log" \
      $PROJECT_DIR/ developer@$DEV_SERVER:$PROJECT_DIR/
}

case "$1" in
    "staging")
        sync_to_staging
        ;;
    "dev")
        sync_to_dev
        ;;
    *)
        echo "Usage: $0 {staging|dev}"
        exit 1
        ;;
esac

🔄 Scenario 4: Real-time sync (using inotify)

#!/bin/bash
# Real-time file sync script

SOURCE_DIR="/home/user/documents"
DEST_DIR="backup-server:/backup/documents"
LOCK_FILE="/tmp/rsync-monitor.lock"

# Check whether it is already running
if [ -f "$LOCK_FILE" ]; then
    echo "Already running."
    exit 1
fi

# Create the lock file
touch "$LOCK_FILE"

# Remove the lock file on exit
trap "rm -f $LOCK_FILE" EXIT

# Monitor and sync in real time
inotifywait -m -r -e modify,create,delete,move "$SOURCE_DIR" |
while read path action file; do
    echo "Change detected: $path$file ($action)"

    # Short delay before syncing (batch rapid changes)
    sleep 2

    rsync -avzh --delete "$SOURCE_DIR/" "$DEST_DIR/"

    if [ $? -eq 0 ]; then
        echo "Sync complete: $(date)"
    else
        echo "Sync error: $(date)"
    fi
done

📝 Summary and best practices

✅ Rsync usage checklist

  • Test first: Always verify with --dry-run before running for real
  • Back up first: Back up important data ahead of time
  • Verify permissions: Check source and destination permission settings
  • Network conditions: Run over a stable network connection
  • Keep logs: Record your runs so you can analyze them later

🎯 Recommended options by scenario

  • General backup: rsync -avzh --progress
  • Full mirror: rsync -avzh --delete
  • Remote transfer: rsync -avzh -e ssh
  • Large files: rsync -avzh --partial --inplace
  • Slow networks: rsync -avzh --compress-level=9 --bwlimit=500

🚨 Common pitfalls

  • Trailing slash on paths: /dir/ and /dir produce different results
  • --delete option: Use carefully; it can delete important files
  • Symbolic links: Understand the difference between -l, -L, and -k
  • Permission issues: Be careful about ownership changes when running with sudo
  • Character encoding: File names can cause issues across different systems
