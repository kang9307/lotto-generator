1. What Is Claude Code?

1.1 Core Concepts

Claude Code is a terminal-native AI tool built on an agent-based architecture. Unlike traditional IDE plugins, Claude Code works directly in the terminal and can autonomously edit files, run commands, create Git commits, and more.

┌─────────────────────────────────────────────────────────┐
│                  Claude Code Architecture                │
├─────────────────────────────────────────────────────────┤
│                                                         │
│   [User] ─────────────────────────────────── [Terminal] │
│       │                                       │         │
│       ▼                                       ▼         │
│   Natural language  ──────────► Claude Code Engine      │
│                                      │                  │
│                    ┌─────────────────┼─────────────────┐│
│                    ▼                 ▼                 ▼│
│               [Read files]     [Edit code]    [Run cmds]│
│               [Search/analyze] [Write tests] [Git work] │
│                                                         │
└─────────────────────────────────────────────────────────┘

1.2 Key Features

  • Terminal-native: Runs directly in the terminal rather than inside an IDE
  • Agent mode: Plans and executes work autonomously
  • Pipe-friendly: Composes with other tools following Unix philosophy
  • Direct execution: Can edit files, run commands, and create Git commits
  • Context awareness: Understands and operates on the full codebase

1.3 Primary Use Cases

Use Case Description Example Prompt
Code generation Produce code from natural language descriptions "Create a user authentication API endpoint"
Bug fixes Analyze and automatically fix errors "Fix this TypeError"
Refactoring Improve code quality "Convert this function to TypeScript"
Test authoring Generate unit tests automatically "Write tests for this module"
Documentation Write code comments and README files "Write a README for this project"

2. Installation and Getting Started

2.1 How to Install

Claude Code can be installed in several ways:

macOS / Linux / WSL (Recommended)

# Official install script
curl -fsSL https://claude.ai/install.sh | bash

Windows PowerShell

# Run in PowerShell
irm https://claude.ai/install.ps1 | iex

Homebrew (macOS)

# Install via Homebrew
brew install --cask claude-code

NPM

# Install via NPM
npm install -g @anthropic-ai/claude-code

2.2 First Run

# Move into your project directory
cd your-project

# Start Claude Code
claude

# You need to log in on first launch
/login

2.3 System Requirements

  • OS: macOS 10.15+, Windows 10+, Linux (Ubuntu 20.04+)
  • Node.js: 18.0 or later (for NPM installs)
  • Memory: 4 GB RAM minimum recommended
  • Internet: Stable internet connection required

You can create your own commands:

# Location: .claude/commands/commit.md

---
argument-hint: [message]
description: Generate a git commit message
---

Look at `git diff HEAD` and craft an appropriate git commit message: $ARGUMENTS

You can then use it as /commit "bug fix".

5. MCP (Model Context Protocol) Server Integration

5.1 What Is MCP?

MCP is an open protocol for connecting external tools and data sources to Claude Code. You can integrate services like GitHub, Jira, Slack, and more.

5.2 Installing MCP Servers

# Add an HTTP server
claude mcp add --transport http notion https://mcp.notion.com/mcp

# Add an SSE server
claude mcp add --transport sse asana https://mcp.asana.com/sse

# Add a local stdio server
claude mcp add --transport stdio airtable \
  --env AIRTABLE_API_KEY=YOUR_KEY \
  -- npx -y airtable-mcp-server

5.3 MCP Management Commands

# List all servers
claude mcp list

# View info about a specific server
claude mcp get github

# Remove a server
claude mcp remove github

# Manage inside a session
/mcp

5.4 Popular MCP Servers

Server Purpose
GitHub Manage repositories, issues, and PRs
Sentry Error monitoring and analysis
Notion Access to docs and databases
Jira Project management and issue tracking
PostgreSQL Database queries and management
Slack Team communication integration
Google Drive File storage and sharing
Figma Access to design assets

6. Skills

6.1 What Are Skills?

Skills are reusable capabilities that Claude automatically discovers and uses. They can include instructions, templates, and scripts for performing specific tasks.

6.2 Skill Structure

my-skill/
├── SKILL.md          # Required: skill definition
├── reference.md      # Optional: reference docs
├── examples.md       # Optional: usage examples
├── scripts/
│   └── helper.py     # Optional: helper script
└── templates/
    └── template.txt  # Optional: template file

6.3 Writing a SKILL.md

---
name: pdf-processing
description: Extract text from PDFs, fill out forms, and merge PDFs. Use when working with PDF files
allowed-tools: Read, Grep, Glob
---

# PDF Processing

## Instructions

1. Use the PyPDF or pdfplumber library
2. Preserve layout when extracting text
3. Include error handling
4. Report the results of processing

6.4 Where Skills Are Stored

  • Project: .claude/skills/skill-name/
  • Personal: ~/.claude/skills/skill-name/

7. Hooks

7.1 What Are Hooks?

Hooks are custom shell commands that run automatically on specific events. They are extremely useful for automating your workflow.

7.2 Hook Event Types

Event Description Use Case
PreToolUse Before a tool runs Block specific actions
PostToolUse After a tool runs Auto code formatting
PermissionRequest When permissions are requested Log permission requests
UserPromptSubmit When the user submits a prompt Input validation
Notification When a notification is sent External notification integrations
Stop When a response completes Completion alerts
SessionStart When a session starts Environment setup
SessionEnd When a session ends Cleanup tasks

7.3 Sample Hooks Configuration

{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "jq -r '.tool_input.command' >> ~/.claude/bash-log.txt"
          }
        ]
      }
    ],
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "npx prettier --write \"$file_path\""
          }
        ]
      }
    ]
  }
}

7.4 Real-World Use Cases

  • Code formatting: Auto-format TypeScript/JavaScript files on save
  • File protection: Block edits to production files
  • Logging: Record every bash command
  • Linting: Run lint automatically after file edits

10. Security and Permissions

10.1 Three-Tier Permission System

Tool Type Example Requires Approval
Read-only File reads, Grep, Glob No
Bash commands Shell command execution Yes
File modifications Writes and edits Yes

10.2 Configuring Permission Rules

{
  "permissions": {
    "allow": [
      "Bash(npm run build)",
      "Bash(npm run test:*)",
      "Read(./src/**)"
    ],
    "deny": [
      "Bash(curl:*)",
      "Bash(rm -rf:*)",
      "Read(./.env)",
      "Read(./.env.*)",
      "Read(./secrets/**)"
    ]
  }
}

10.3 Permission Modes

  • default: Ask for permission for each tool use
  • acceptEdits: Auto-approve file edits
  • plan: Analysis only (no modifications)
  • bypassPermissions: Auto-approve everything (use with caution!)
# Change the permission mode
claude --permission-mode plan
claude --permission-mode acceptEdits

10.4 Security Best Practices

  • Add sensitive files (.env, credentials.json, etc.) to the deny list
  • Restrict read-only skills with allowed-tools: Read, Grep, Glob
  • Regularly review permissions via /permissions
  • Enable sandbox mode in production environments
