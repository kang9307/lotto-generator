The CRUSH (Controlled, Scalable, Decentralized Placement of Replicated Data) algorithm is one of Ceph's core technologies that determines how data is placed and managed in distributed storage systems. This guide provides an easy-to-understand explanation of CRUSH algorithm principles and practical implementation methods.

🎯 What Is the CRUSH Algorithm?

CRUSH is the core algorithm that decides where data is stored in a Ceph distributed storage system. Unlike conventional designs that rely on centralized metadata servers, CRUSH uses mathematical computation to derive data locations, which gives it outstanding scalability and performance.

Key Characteristics of CRUSH

  • Distributed processing: Each client computes data placement independently, without a central server
  • Scalability: Scales linearly to thousands of storage nodes
  • Failure recovery: Automatically routes around failed nodes when placing data
  • Policy-driven: Lets you compose flexible placement policies that match your business requirements

🏗️ Understanding the CRUSH Map Structure

The CRUSH Map is the central component that defines the physical topology of the cluster and the placement policy. It represents data centers, racks, hosts, and OSDs in a hierarchical structure.

Components of the CRUSH Map

Component Description Example
Device An actual storage device (OSD) osd.0, osd.1, osd.2...
Bucket A logical grouping of devices host, rack, datacenter
Weight Relative storage capacity 1TB = 1.0, 2TB = 2.0
Type Level in the hierarchy root, rack, host, osd

⚙️ How the CRUSH Algorithm Works

The CRUSH algorithm decides data placement in the following steps:

1. Hash Computation

The object name and pool ID are hashed to produce a unique placement group (PG).

# Pseudocode example
def calculate_pg(object_name, pool_id, pg_num):
    hash_value = hash(object_name + str(pool_id))
    pg_id = hash_value % pg_num
    return pg_id

2. Applying the CRUSH Rule

Appropriate OSDs are selected according to the placement policy.

# Example CRUSH Rule
rule replicated_rule {
    ruleset 0
    type replicated
    min_size 1
    max_size 10
    step take default
    step chooseleaf firstn 0 type host
    step emit
}

3. Failure-Domain Awareness

CRUSH guarantees that replicas are not stored in the same physical location.

🔧 Configuring a CRUSH Map in Practice

Inspecting the Current CRUSH Map

# Retrieve the CRUSH Map
ceph osd getcrushmap -o crushmap.bin
crushtool -d crushmap.bin -o crushmap.txt
cat crushmap.txt

# View a simplified tree representation
ceph osd tree

Adding a New Host

# Add a new host to the CRUSH Map
ceph osd crush add-bucket new-host host
ceph osd crush move new-host root=default

# Add an OSD under the new host
ceph osd crush add osd.8 1.0 host=new-host

Creating a Custom CRUSH Rule

# CRUSH Rule for an SSD-only pool
ceph osd crush rule create-simple ssd-rule default host firstn

# CRUSH Rule for erasure coding
ceph osd crush rule create-erasure ec-rule ec-profile

📊 Performance Tuning for the CRUSH Algorithm

Load Balancing Through Weight Tuning

Setting each OSD's weight proportional to its storage capacity produces evenly distributed data.

# Adjust OSD weights (capacity-based)
ceph osd crush reweight osd.0 1.8  # 1.8 TB device
ceph osd crush reweight osd.1 3.6  # 3.6 TB device

# Utilization-based automatic rebalancing
ceph osd reweight-by-utilization 110

Monitoring Data Distribution

Command Purpose Key Metrics
ceph osd df Check OSD utilization Size, Use%, Var
ceph pg stat Check PG states active+clean ratio
ceph osd utilization Analyze imbalance Standard deviation, mean

🚨 Common CRUSH Troubleshooting

Data Imbalance

# Diagnose imbalance
ceph osd df | sort -k7 -n

# Reweight OSDs
for osd in $(ceph osd ls); do
    size=$(ceph osd df | grep "osd.$osd" | awk '{print $2}')
    weight=$(echo "scale=2; $size/1024/1024" | bc)
    ceph osd crush reweight osd.$osd $weight
done

1. Region-Based Replication Policy

# CRUSH Rule for distributing data across regions
rule geo_replicated_rule {
    ruleset 1
    type replicated
    min_size 1
    max_size 10
    step take datacenter1
    step chooseleaf firstn 2 type host
    step emit

2. Performance Tiering

# Configure an SSD cache tier in front of an HDD storage tier
ceph osd tier add cold-pool hot-pool

ceph osd tier set-overlay cold-pool hot-pool

# Configure cache policy
ceph osd pool set hot-pool hit_set_type bloom

# Use server rooms as a failure domain
