계기 — 단일 오픈 모델로 한 달 개발하기 도전과 실패의 기록

2026년 9월, 파이썬 기반 오픈소스 CMS 프로젝트 Wagtail의 핵심 개발팀은 흥미로운 자체 실험을 기획하였다. 상용 폐쇄형 최상위 모델에 의존하지 않고, 가성비가 높은 단일 오픈 가중치 모델인 GLM 5.3 Flash만 사용하여 9월 한 달 전체의 일상 엔지니어링 및 개발 작업을 완수하겠다는 목표였다. 고비용 대규모 프런티어 모델 대신 고효율 소형 모델을 실무 환경에 단독 투입하여 실제 개발 생산성을 유지할 수 있는지 검증하려는 취지였다.

개발팀은 일상적인 에이전틱 엔지니어링 환경에서 소비되는 AI 자원을 추적하기 위해 AgentsView 계측 도구를 도입하였다. AgentsView는 개발 세션과 백그라운드 에이전트 작업에서 소비되는 토큰 분포, 호출 빈도, 발생 비용을 지속적으로 모니터링하는 내부 관리 체계다. 이를 통해 9월 한 달 동안 실시간으로 어떤 작업에 얼마만큼의 토큰이 투입되는지 투명하게 추적하였다.

그러나 한 달이 지난 후 공개된 결과는 부분적인 성공이자 기술적인 도전 실패였다. 9월 한 달 동안 소비된 총 토큰은 20억(2B) 토큰에 달했으나, 원래 목표였던 GLM 5.3 Flash에는 정확히 절반인 10억(1B) 토큰만 사용되었다. 나머지 10억 토큰은 계획에 없던 다른 오픈 모델들로 분산 소비되었으며, 총 전력 소비량 역시 당초 목표치였던 10kWh를 크게 초과하여 약 35kWh에 도달하였다.

Wagtail 팀은 이 결과를 두고 「작업은 성공적으로 완수되었으나 도전 과제 자체는 기술적으로 실패했다」고 평가하였다. 단일 모델 고수라는 제약은 지키지 못했으나, 실무 환경에서 Flash급 고효율 모델이 보여준 가능성과 에이전트 자동화가 초래할 수 있는 자원 낭비의 위험성을 명확한 데이터로 확인했기 때문이다.

  • 도전 목표: 9월 한 달 동안 모든 개발 및 일상 엔지니어링 업무를 단일 오픈 가중치 모델인 GLM 5.3 Flash만으로 완수.
  • 추적 체계: 에이전틱 엔지니어링 권장 도구인 AgentsView를 사용하여 실시간 토큰 분포와 작업별 자원 소모량 기록.
  • 최종 집계: 총 20억 토큰 소비 중 목표 모델 GLM 5.3 Flash 사용량은 10억 토큰(50%)에 그쳐 단일화 도전은 실패.
  • 핵심 시사점: 일상 개발 작업은 저비용 모델로 충분히 수행 가능하나, 에이전트의 예기치 못한 호출과 추론 인프라 병목이 전환 요인으로 작용.

첫 보름의 성과 — 68달러와 4kWh로 입증된 GLM 5.3 Flash의 실무 가치

9월 상반기 15일 동안의 결과는 대단히 고무적이었다. 개발팀은 첫 보름 동안 다른 어떤 모델도 사용하지 않고 오직 GLM 5.3 Flash만을 일상 개발과 코드 검토에 단독 투입하는 데 성공하였다. Wagtail 코어 코드베이스 수정, Wagtail 기반 웹사이트 개발, 사용자 인터페이스(UI) 작업, AI 연구 개발, 그리고 방대한 문서 작성 작업에 이르기까지 다방면의 업무를 문제없이 처리하였다.

이 기간 동안 기록된 자원 소모량은 팀의 사전 예산 범위를 완벽하게 만족시켰다. 15일 동안 투입된 총비용은 불과 68달러였으며, 소비된 전력량은 약 4kWh, 추정 탄소 배출량은 365그램에 불과하였다. 최상위 상용 모델을 사용했을 때 발생했을 것으로 추정되는 수백 달러 이상의 청구액과 비교하면 극적인 비용 절감 효과를 거둔 셈이다.

이 성과는 실무 소프트웨어 개발에서 굳이 고가의 초대형 모델을 전면 배치할 필요가 없음을 입증한다. 코드 구조 파악, 리팩터링, 단위 테스트 작성, 일상적인 문서 초안 작성과 같은 반복 업무는 초당 수백 토큰을 출력하며 단가가 수십 분의 일에 불과한 Flash 등급 모델로도 생산성 손실 없이 완수될 수 있음을 증명하였다.

특히 Wagtail 팀은 다양한 추론 공급자가 동일한 오픈 모델을 서비스하면서 촉발된 가격 경쟁과 서비스 품질 향상이 이러한 실무 효용을 극대화했다고 평가하였다. 단일 독점 벤더에 종속되지 않고 개방된 가중치를 기반으로 여러 호스팅 인프라를 유연하게 선택할 수 있는 구조가 저렴한 비용 구조를 뒷받침하였다.

  • 단독 운용 성공: 9월 1일부터 15일까지 첫 보름 동안 예외 없이 GLM 5.3 Flash 단일 모델만으로 모든 개발 업무 수행.
  • 예산 내 달성: 첫 보름 동안 발생한 누적 API 비용은 68달러로, 대형 상용 모델 대비 극히 낮은 수준 유지.
  • 낮은 환경 부하: 상반기 15일 동안의 총 에너지 소비량은 약 4kWh였으며, 추정 탄소 배출량은 365g으로 계측.
  • 업무 다각화 검증: 단순 코드 완성을 넘어 Wagtail 본체 수정, UI 컴포넌트 개발, 기술 문서 작성, 에이전트 평가에 전방위 투입.

바이브 코딩의 청구서 — 하룻밤에 4.5억 토큰과 150달러를 소진한 모델 선택의 대가

그러나 9월 하반기에 접어들며 예상치 못한 지출 폭증 사건이 발생하였다. Wagtail 팀은 새로운 모델 콘텍스트 프로토콜(MCP) 기반의 실험용 서버를 구축하는 과정에서 이른바 「바이브 코딩(Vibe Coding)」 방식을 적용하였다. 바이브 코딩은 정밀한 아키텍처 설계와 단계별 제어 대신, 에이전트에게 포괄적인 목표를 부여하고 빠른 속도로 반복 생성과 수정을 위임하는 개발 패턴이다.

실험적 프로토타입 단계에서 빠른 결과를 얻기 위해 바이브 코딩을 선택한 판단 자체는 의도에 부합하였으나, 치명적인 실수는 모델 선택에서 비롯되었다. 프로토타입 환경에 적합하지 않은 지나치게 고비용의 모델이 선택되었고, 자율 에이전트가 백그라운드에서 반복 루프를 돌며 코드를 생성하고 오류를 자체 수정하는 과정에서 토큰이 폭발적으로 소모되었다.

결과는 가혹했다. 단 하룻밤 사이에 약 4억 5천만(450M) 토큰이 일시에 증발하였고, 하룻밤의 실행 비용으로만 150달러가 청구되었으며, 약 5kWh의 전력이 추가 소모되었다. 이는 상반기 15일 전체 동안 일상 업무를 위해 소비했던 총비용(68달러)의 두 배를 넘고, 15일간의 전력 소비량(4kWh)을 단 몇 시간 만에 넘어선 수치였다.

사후 분석 결과, 보다 저렴하고 적합한 모델을 지정하고 에이전트의 호출 범위를 경계 지었더라면 동일한 프로토타입 결과를 최소 5분의 1 이하의 비용으로 달성할 수 있었던 것으로 나타났다. 에이전틱 패턴에서 모델 선택의 부주의와 제어 장치 없는 자율 실행이 얼마나 급격한 자원 낭비를 유발하는지 여실히 보여준 사례다.

인프라 가용성 병목 — 파레토 최적 모델의 응답 지연과 예기치 못한 전환

단일 모델 도전을 가로막은 또 다른 외적 요인은 추론 인프라의 가용성 저하였다. Wagtail 팀은 데이터 주권과 규정 준수를 위해 유럽 데이터센터에서 호스팅되는 오픈 가중치 모델만을 추론 대상으로 한정하는 엄격한 필터링 기준을 유지하고 있었다. 이 조건 하에서 GLM 5.3 Flash는 성능 대비 비용과 에너지 효율 측면에서 파레토 프런티어(Pareto Frontier)의 최상단에 위치하는 핵심 모델이었다.

그러나 해당 모델의 뛰어난 가성비는 곧 수많은 사용자들의 호출 집중으로 이어졌다. 수많은 GPU를 독점하여 대규모 클러스터를 유지하는 거대 테크 기업들과 달리, 오픈 모델을 호스팅하는 독립 추론 공급자들은 급증하는 트래픽을 감당할 인프라 여력이 상대적으로 제한적이었다. 그 결과 9월 중순 이후 GLM 5.3 Flash의 응답 지연과 성능 저하가 눈에 띄게 심화되었다.

개발자가 대화형으로 코드를 작성하거나 에이전트가 신속하게 연속 도구를 호출해야 하는 환경에서, 모델의 응답 지연은 곧바로 작업 흐름의 마비로 이어졌다. 정상적인 엔지니어링 일정을 소화하기 위해 Wagtail 팀은 결국 단일 모델 고수 원칙을 깨고 다른 유사 모델들로 호출을 긴급 전환할 수밖에 없었다.

이때 대체 모델로 투입된 것이 DeepSeek V4.1 Flash와 Qwen 3.8 Flash였다. 두 모델 역시 유럽 리전에서 호스팅 가능하며 유사한 가성비를 갖추고 있어 신속한 전환이 가능했다. 오픈 API 표준 덕분에 모델 파라미터 변경만으로 즉각적인 교체가 가능했으나, 이는 인프라 가용성이 단일 모델 전략을 무너뜨릴 수 있음을 보여주는 결정적 계기가 되었다.

  • 유럽 리전 제약: 유럽 내 데이터센터에서 호스팅되는 오픈 가중치 모델로만 추론 환경을 엄격히 제한.
  • 파레토 최상단의 역설: 뛰어난 비용 대비 성능으로 인해 이용자가 폭증하면서 추론 공급자의 인프라 용량 포화.
  • 응답 지연 심화: 실무 코딩 흐름을 저해할 수준의 레이턴시 상승으로 인해 단일 모델 유지 불가 판정.
  • 긴급 대체 투입: 동일 리전에서 안정적인 처리가 가능한 DeepSeek V4.1 Flash 및 Qwen 3.8 Flash로 트래픽 우회.

14개 오픈 모델 벤치마크와 Wagtail 에이전트 CLI 프로토타입

일상 엔지니어링에서의 단일 모델 실험과 병행하여, Wagtail 팀은 실제 CMS 개발 과업에 특화된 14개 오픈 모델 벤치마크를 정밀하게 수행하였다. 모델 공급사들이 경쟁적으로 신규 가중치를 출시하는 상황에서, 단순 범용 벤치마크 점수가 아닌 실제 Wagtail 작업 환경에서의 정확도와 에너지 소비량을 객관적으로 비교하기 위함이었다.

벤치마크는 각 모델의 과업 완성 정확도(퍼센트), 과업당 에너지 소비량(Wh), 과업당 비용(달러)을 기준으로 측정되었다. 이 정밀 평가에서 종합 1위를 차지한 모델은 DeepSeek V4.1 Flash였다. DeepSeek V4.1 Flash는 Wagtail 작업에서 95%의 높은 정확도를 기록하였으며, 과업당 전력 소비량 14.9Wh, 과업당 비용 0.09달러라는 탁월한 효율을 입증하였다.

Wagtail 팀은 이러한 벤치마크 결과를 바탕으로 향후 에이전틱 개발 환경을 체계화하기 위한 신규 CLI 프로토타입을 설계하였다. 이 CLI는 자율 에이전트가 CMS 코드베이스를 분석하고 기능을 구현할 때 불필요한 추론을 남발하지 않도록 규격화된 에이전트 스킬(Agent Skills)과 결합되도록 설계되었다.

새로운 프로토타입 도구는 에이전트에게 필요한 최소한의 컨텍스트만 주입하고, 작업 완료 여부를 결정론적 테스트로 검증함으로써 무분별한 토큰 소모를 차단하는 역할을 맡는다. 벤치마크에서 우수한 성적을 거둔 고효율 Flash 모델들을 이 CLI와 연동함으로써 실무 적용 가능성을 극대화하려는 의도다.

모델명 컨텍스트 윈도우 주요 기술 특성 및 공급 현황 Wagtail 실무 및 벤치마크 평가
GLM 5.3 Flash 1M 토큰 비전 입력 지원, 다수 독립 공급자 호스팅 경쟁 상반기 $68/4kWh로 완벽 수행, 이후 트래픽 병목 직면
DeepSeek V4.1 Flash 1M 토큰 (유사 대역) 유럽 리전 제공, 뛰어난 추론 효율성 Wagtail 과업 정확도 95%, 14.9Wh, 작업당 $0.09로 1위

  • 14개 모델 평가: Wagtail 고유 과업을 대상으로 오픈 모델 14종의 정확도, 소비 전력, 비용 전수 측정.
  • 벤치마크 1위: DeepSeek V4.1 Flash가 95% 정확도, 과업당 14.9Wh 전력, 과업당 0.09달러로 최우수 기록.
  • CLI 프로토타입 연동: 에이전트와 원활하게 상호작용하도록 특화 설계된 새로운 에이전트 CLI 도구 프로토타입 개발.
  • 에이전트 스킬 결합: 경량 모델의 한계를 극복하고 결정론적 검증을 지원하기 위해 표준화된 도구 인터페이스 구축.

일상 엔지니어링에서 Flash급 모델이 발휘한 1M 컨텍스트와 비전 역량

비록 단일 모델 운용 과제는 완주하지 못했으나, GLM 5.3 Flash 자체의 기술적 완성도는 일상 엔지니어링에서 기대 이상의 성능을 발휘하였다. Wagtail 팀이 이전 모델 비교 분석에서 강조했던 핵심 강점들이 실제 프로덕션 개발 현장에서도 고스란히 유효함을 입증하였다.

가장 결정적인 강점은 100만(1M) 토큰에 달하는 대규모 컨텍스트 윈도우였다. 복잡한 파이썬 프레임워크인 Wagtail의 다중 파일 구조, 모듈 간 상호의존성, 대규모 변경 이력을 한 번의 프롬프트 세션에 온전히 담아낼 수 있었기 때문에 장시간 이어지는 확장 코딩 작업에서도 컨텍스트 단절 없이 일관된 수정이 가능하였다.

또한 네이티브 비전 지원 기능은 프런트엔드 및 UI 엔지니어링에서 결정적인 역할을 수행하였다. UI 컴포넌트 구현 시 브라우저 렌더링 스크린샷을 모델에 직접 입력하여 디자인 시안과의 시각적 오차를 점검하고, 자동화된 시각적 QA를 수행하는 등 기존 텍스트 전용 모델로는 불가능했던 시각적 피드백 루프를 Flash급 모델 단가로 운영할 수 있었다.

마지막으로 다수의 독립 추론 공급자 간에 형성된 생태계 경쟁은 개발팀에게 유리한 환경을 조성하였다. 특정 상용 공급자의 독점적 가격 정책이나 정책 변경에 휘둘리지 않고, 표준 규격을 따르는 엔드포인트를 통해 가장 유리한 조건의 인프라를 활용할 수 있는 이점을 확인하였다.

  • 1M 컨텍스트 지원: Wagtail 복합 아키텍처와 장기 코딩 세션을 컨텍스트 손실 없이 포괄적으로 처리.
  • 비전 역량 통합: 스크린샷 기반 UI 오차 교정 및 시각적 품질 보증(QA) 워크플로를 실무에 직접 활용.
  • 공급자 경쟁 효과: 다수 호스팅 업체 간의 건강한 경쟁 덕분에 안정적인 단가와 접근성 확보.
  • 다목적성 검증: 코어 기능 구현, 사이트 개발, UI 작업, 문서화, 평가 프레임워크 전반에서 균형 잡힌 역량 입증.

10월을 위한 네 가지 개선 과제 — 토큰 수가 아닌 에너지와 비용 중심 관리

9월의 도전과 시행착오를 종합한 Wagtail 팀은 10월 이후의 엔지니어링을 위해 네 가지 구체적인 개선 방향을 수립하였다. 이는 단순히 모델의 파라미터나 벤치마크 숫자에 매몰되지 않고, 실제 지속 가능한 엔지니어링 관리 체계를 확립하기 위한 실천적 지침이다.

첫째는 지속적인 로컬 사용량 계측과 보고 체계의 고도화다. 단순히 소비된 토큰 수를 세는 무의미한 지표에서 벗어나, 작업당 실제 전력 소비량(Wh), 발생 비용(달러), 그리고 이 자원 투입이 구체적인 긍정적 산출물로 연결되었는지를 측정하는 성과 중심의 계측 시스템을 정착시키기로 하였다.

둘째는 일상적 개발과 별개로 실험적 프로토타입을 위한 독립적인 R&D 예산 배정이다. 바이브 코딩과 같은 급진적 시도가 전체 프로젝트의 자원을 잠식하지 않도록, 프로토타입 단계에서 어떤 모델을 어떤 방식으로 검증할 것인지 사전에 합의하고 한도를 설정하는 체계를 마련한다.

셋째는 프롬프트 최적화와 정교한 다중 에이전트 분업 기법의 도입이다. 모든 작업을 단일 에이전트의 거대 루프에 맡기는 대신, 총괄 오케스트레이터, 탐색 담당(Scout), 구현 담당(Implementer), 검토 담당(Reviewer)으로 에이전트 역할을 명확히 쪼개고 경계가 정해진 유한한 목표(Bounded Goals)만을 부여하여 토큰 낭비를 원천 차단한다.

넷째는 더욱 효율적인 차세대 추론 기법과 초경량 모델의 지속적 도입이다. Wagtail 팀은 초저전력으로 구동 가능한 디시전 디퓨전(Decision Diffusion) 계열 모델의 가능성을 긍정적으로 평가하며, 실무 개발의 대다수 추론 작업을 Flash 등급 이하의 고효율 모델로 전담시키는 방향성을 확고히 유지하기로 하였다.

  • 지속적 로컬 계측: 무의미한 토큰 수치 대신 실질 전력 소비량(Wh)과 비용, 실제 산출물 기여도를 중심으로 모니터링 강화.
  • 실험 예산 분리: 일상 유지보수 예산과 분리된 프로토타입 전용 R&D 예산 수립 및 모델 선택 심의 절차 마련.
  • 다중 에이전트 분업화: 조율자, 탐색자, 구현자, 검토자로 에이전트 책임을 세분화하고 명확한 한계 목표 설정.
  • 초고효율 기법 추구: 디시전 디퓨전 등 신규 고효율 추론 모델을 탐색하여 대다수 과업을 경량 모델로 안정적 전담.

확인하지 못한 것

본 기술 분석은 Wagtail 핵심 팀이 블로그 포스트를 통해 공개한 정보만을 기초로 작성되었으며, 아래 사항들은 원문에서 밝히지 않아 명확히 검증하지 못하였다.

  • 바이브 코딩 시 오선택된 고비용 모델의 정확한 명칭: 원문은 「잘못된 모델(the wrong model)」이라고만 기술하였으며, 하룻밤에 150달러와 4.5억 토큰을 소진한 특정 모델의 모델명과 버전은 공개되지 않아 확인하지 못함.
  • 14개 모델 벤치마크의 전체 측정 목록 및 하위 모델 상세 수치: 원문은 최우수 성적을 거둔 DeepSeek V4.1 Flash(95%, 14.9Wh, $0.09)의 결과만 본문에 제시하였을 뿐, 나머지 13개 모델의 개별 점수와 순위표 전문은 본문에 첨부하지 않아 전수를 파악하지 못함.
  • 유럽 데이터센터 추론 공급자의 구체적인 상호명: 원문은 유럽 리전 오픈 모델 호스팅 업체의 트래픽 과밀로 인한 지연 사실만 기술하였고, 해당 인프라를 제공한 서드파티 공급자들의 구체적인 기업명은 명시하지 않아 확인하지 못함.
