引言 - 有些日子本地时间无法对应唯一的瞬间

本地时间是形如「2026-03-08 02:30」的值，只包含日期和时钟读数。要把它确定为唯一的瞬间需要时区规则，而在有夏令时的地区，这种对应关系在切换日会被打破。时钟拨快的那天存在被跳过的区间，区间内的读数不对应任何瞬间；时钟拨慢的那天，同一读数会经过两次，因此一个读数对应两个瞬间。

这一现象有固定的名称。不存在的本地时刻在英文文档中称为gap、nonexistent或invalid time，出现两次的时刻称为overlap、repeated或ambiguous time。下文把前者称为「空洞」，后者称为「重复时刻」。实际运行的结果是各工具对这两种情况的默认处理不同，同一个字符串会因工具而换算成相差一小时的UTC。

时区规则是数据、更新后过去时刻的解读也会改变、切换区间内24小时后与明天同一时刻不同，这些内容已在时区是数据而不是代码中用Python输出讨论过。本文超出单一工具，比较Node.js与PowerShell 5.1如何解释同一输入，以及哪些存储规则能避免这些差异。

Python zoneinfo - fold选择的是什么

Python 3.9及以上的zoneinfo通过IANA名称创建时区，并用datetime的fold属性区分重复区间内的两个时刻。官方文档(datetime模块)把fold描述为在重复区间内用于区分墙上时间的值，并写明0和1分别表示具有相同墙上时间表示的两个时刻中较早和较晚的一个。下面的代码对空洞(03-08 02:30)和重复(11-01 01:30)分别传入fold 0和1，随后按分钟判别正常、空洞与重复。在Windows上，zoneinfo需要tzdata包才能工作，这台电脑上已安装tzdata 2025.3。

import sys
                    from datetime import datetime, timezone
                    from zoneinfo import ZoneInfo
                    
                    ny = ZoneInfo("America/New_York")
                    UTC = timezone.utc
                    print("python", sys.version.split()[0])
                    
                    
                    def show(naive, fold):
                        dt = naive.replace(tzinfo=ny, fold=fold)
                        u = dt.astimezone(UTC)
                        back = u.astimezone(ny)
                        print(naive.strftime("%Y-%m-%d %H:%M"), "fold=%d" % fold, "offset", dt.strftime("%z"),
                              "-> UTC", u.strftime("%H:%MZ"), "-> back", back.strftime("%H:%M"), back.tzname())
                    
                    
                    show(datetime(2026, 3, 8, 2, 30), 0)
                    show(datetime(2026, 3, 8, 2, 30), 1)
                    show(datetime(2026, 11, 1, 1, 30), 0)
                    show(datetime(2026, 11, 1, 1, 30), 1)
                    print("default fold:", datetime(2026, 11, 1, 1, 30, tzinfo=ny).fold)
                    
                    
                    def classify(naive, tz):
                        a = naive.replace(tzinfo=tz, fold=0)
                        b = naive.replace(tzinfo=tz, fold=1)
                        back = a.astimezone(UTC).astimezone(tz).replace(tzinfo=None)
                        if back != naive:
                            return "nonexistent"
                        return "ambiguous" if a.utcoffset() != b.utcoffset() else "normal"
                    
                    
                    print()
                    for s in ["2026-03-08 01:59", "2026-03-08 02:00", "2026-03-08 02:59", "2026-03-08 03:00",
                              "2026-11-01 00:59", "2026-11-01 01:00", "2026-11-01 01:59", "2026-11-01 02:00"]:
                        print(s, classify(datetime.strptime(s, "%Y-%m-%d %H:%M"), ny))

重复(11-01 01:30)的表现与文档所述一致：fold=0取较早的时刻EDT(-0400)，为05:30Z；fold=1取较晚的时刻EST(-0500)，为06:30Z；两者换回本地时间都是01:30。对于空洞(03-08 02:30)，输出显示的行为如下：fold=0采用切换前的偏移-0500，得到07:30Z，把这个瞬间换回本地时间是03:30 EDT；fold=1采用切换后的偏移-0400，得到06:30Z，换回为01:30 EST。空洞内的时刻会毫无异常地换算，但换回的值与输入不同。

判别代码的原理是往返换算：本地时间换成UTC再换回来，若数值不同则是空洞；数值相同但fold为0与1时的偏移不同，则是重复。输出显示，02:00至02:59全部是空洞，01:00至01:59全部是重复，01:59与03:00是正常的。默认的fold值为0，这在判别列表上方的一行中已经显示。不指定fold的代码，会在重复时静默选择较早的一侧，在空洞时静默采用切换前的偏移。

官方文档有一句话：当两个具有相同tzinfo的aware datetime进行比较或相减时，tzinfo与fold属性会被忽略，直接比较基础的datetime值(the tzinfo and fold attributes are ignored and the base datetimes are compared)。这就是同一本地时间的fold 0与1用==比较会相等的原因，这种比较看不出一小时的差。该问题已在前一篇文章的DST边界一节中用数字展示，所以这里只采用先换成UTC再比较的做法。直接比较同一本地时间的fold 0与1，结果如下。

from datetime import datetime
                    from zoneinfo import ZoneInfo
                    
                    ny = ZoneInfo("America/New_York")
                    a = datetime(2026, 11, 1, 1, 30, tzinfo=ny, fold=0)
                    b = datetime(2026, 11, 1, 1, 30, tzinfo=ny, fold=1)
                    print("a == b:", a == b, "| offsets:", a.strftime("%z"), b.strftime("%z"))
a == b: True | offsets: -0400 -0500

比较结果为True，但两个值的偏移分别是-0400与-0500，相差一小时。

JavaScript Date - 空洞向前推，重复取较早

Node.js的Date在接收本地时间字段(年、月、日、时、分)时，会按当前进程的时区规则解释。MDN的Date文档写道：在设置落入偏移转换区间的本地时间时，采用与Temporal的disambiguation选项「compatible」相同的行为；若本地时间对应两个瞬间则选择较早的一个，若不存在(空洞)则向前移动空洞的时长(原文：the earlier one is chosen; ... we go forward by the gap duration)。时区在脚本内通过process.env.TZ指定为America/New_York。下面的代码同时输出输入字段与读回的字段。

process.env.TZ = 'America/New_York';

                    function probe(y, mo, d, h, mi) {
                      const x = new Date(y, mo - 1, d, h, mi);
                      const asked = y + '-' + pad(mo) + '-' + pad(d) + ' ' + pad(h) + ':' + pad(mi);
                      const got = x.getFullYear() + '-' + pad(x.getMonth() + 1) + '-' + pad(x.getDate()) + ' ' + pad(x.getHours()) + ':' + pad(x.getMinutes());
                      console.log(asked, '->', x.toISOString(), 'reads back', got, asked === got ? '(same)' : '(CHANGED)');
                    }
                    probe(2026, 3, 8, 1, 59);
                    probe(2026, 3, 8, 2, 0);
                    probe(2026, 3, 8, 2, 30);
                    probe(2026, 3, 8, 3, 0);
                    probe(2026, 11, 1, 0, 59);
                    probe(2026, 11, 1, 1, 30);
                    probe(2026, 11, 1, 2, 0);
                    console.log(new Date('2026-03-08T02:30:00').toISOString());
                    console.log(new Date('2026-11-01T01:30:00').toISOString());

  • 重复读回后数值相同，因此这种方法无法发现。代码必须另外知道UTC值可能有两个。

同一时刻一天出现几次 - 0次、1次、2次

设想每天02:30运行的任务或定在01:30的提醒，问题就清楚了。统计某个本地时间一天内出现的次数，切换日的数值与平时不同。下面的代码按15分钟步长扫描UTC轴，收集本地读数恰好等于该值的瞬间。

from datetime import datetime, timedelta, timezone
                    from zoneinfo import ZoneInfo
                    
                    ny = ZoneInfo("America/New_York")
                    UTC = timezone.utc
                    
                    
                    def occurrences(y, m, d, hh, mm, tz):
                        # UTC instants whose wall clock in tz reads exactly y-m-d hh:mm (15-minute scan, +-14 h)
                        base = datetime(y, m, d, hh, mm, tzinfo=UTC)
                        hits = []
                        for k in range(-14 * 60, 14 * 60 + 1, 15):
                            u = base + timedelta(minutes=k)
                            w = u.astimezone(tz)
                            if (w.year, w.month, w.day, w.hour, w.minute) == (y, m, d, hh, mm):
                                hits.append(u.strftime("%H:%MZ"))
                        return hits
                    
                    
                    for y, m, d, hh, mm in [(2026, 3, 7, 2, 30), (2026, 3, 8, 2, 30), (2026, 3, 9, 2, 30),
                                            (2026, 10, 31, 1, 30), (2026, 11, 1, 1, 30), (2026, 11, 2, 1, 30)]:
                        h = occurrences(y, m, d, hh, mm, ny)
                        print("%d-%02d-%02d %02d:%02d" % (y, m, d, hh, mm), "->", len(h), "time(s)", h)

安全处理的规则 - 该拒绝的与该选择的

前面的运行揭示了两件事：本地时间字符串在空洞时没有数值，在重复时有两个数值；并且各工具的默认选择彼此不同。因此规则不是交给默认选择，而是在输入阶段确定策略。下面的代码是一个Python函数：遇到空洞就以异常拒绝，遇到重复时若没有fold就拒绝，有fold则进行换算。

from datetime import datetime, timezone
                    from zoneinfo import ZoneInfo
                    
                    UTC = timezone.utc
                    
                    
                    def to_utc(naive, tz, fold=None):
                        a = naive.replace(tzinfo=tz, fold=0)
                        b = naive.replace(tzinfo=tz, fold=1)
                        if a.astimezone(UTC).astimezone(tz).replace(tzinfo=None) != naive:
                            raise ValueError("nonexistent local time: " + naive.isoformat(" "))
                        if a.utcoffset() != b.utcoffset():
                            if fold is None:
                                raise ValueError("ambiguous local time: " + naive.isoformat(" ") + " (fold=0 or fold=1 required)")
                            return (b if fold else a).astimezone(UTC)
                        return a.astimezone(UTC)
                    
                    
                    ny = ZoneInfo("America/New_York")
                    for n, f in [(datetime(2026, 3, 8, 2, 30), None), (datetime(2026, 3, 8, 3, 30), None),
                                 (datetime(2026, 11, 1, 1, 30), None), (datetime(2026, 11, 1, 1, 30), 0),
                                 (datetime(2026, 11, 1, 1, 30), 1)]:
                        try:
                            print(n.isoformat(" "), "fold=%s" % f, "->", to_utc(n, ny, f).isoformat())
                        except ValueError as e:
                            print(n.isoformat(" "), "fold=%s" % f, "-> ValueError:", e)

  • 存储瞬间时使用UTC时间(或带偏移的时间)。附带偏移的输出(前面的偏移一节)里，UTC数值在所有工具中一致；只传入本地时间、不带偏移的输出(前面的对比表)里，各工具的数值出现分歧。
  • 人工输入的本地时间要连同时区名称一起接收。没有时区名称，就无法判定空洞与重复。
  • 空洞应作为输入错误退回，让用户另选时间。静默地向后修正一小时(Node.js)会改变用户输入的数值。
  • 重复时应展示两个候选(05:30Z与06:30Z)让用户选择，或在代码中明确策略(较早或较晚一侧)。若交给工具默认值，PowerShell与Python会选择不同的一侧。
  • 在.NET中，不要把由UTC换成本地时间的DateTime再换回UTC，而应使用DateTimeOffset携带偏移。
  • 带偏移的输入也不能放心。在前面的偏移一节里，给空洞(03-08 02:30)附上-04:00的字符串被解释为06:30Z，这正是本地时间01:30 EST的那一瞬间。收到的偏移是否是该时区内可能的组合，要另行检查。
  • 在测试数据中加入2026-03-08 02:30与2026-11-01 01:30这样的空洞与重复，并检查把本地时间字符串当作键使用的代码。

数据库一侧的同类问题，即会话时区介入AT TIME ZONE运算结果类型的问题，由PostgreSQL AT TIME ZONE一文另行讨论。时间与整数互相转换时单位出现分歧的问题，则由时间戳转换一文讨论。
