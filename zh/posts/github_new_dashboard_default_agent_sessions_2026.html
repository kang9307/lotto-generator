要点：变更记录（2026年10月1日）称新版控制台现已成为所有用户的默认视图。它在一处展示活跃智能体任务会话、Issue与拉取请求，每个列表最多12项。旧版界面可随时通过「Preview」旁的下拉菜单切回。GitHub Docs的两篇文档仍把同一个主页控制台描述为public preview。

背景 — 从功能预览转变为全员默认界面

GitHub变更记录（Changelog）2026年10月1日的条目「New dashboard experience now the default」写明，此前以功能预览（feature preview）形式提供的新版控制台体验，现已成为所有用户的默认视图。变更记录称这是一个以效率为中心（productivity-focused）的控制台，帮助用户专注于最重要的工作，并更容易找到并处理接下来需要做的事。该条目的分类是改进（Improvement）。

时间顺序要把两个出处放在一起才看得清。社区公告（#208952）发布于9月28日，当时已经写明将把新版控制台设为所有人的默认体验。变更记录的日期是三天后的10月1日，写的是「is now the default」。变更记录没有给出默认界面实际切换的日期，因此不能断定是从10月1日开始切换的。

据公告，GitHub去年以功能预览形式推出了以效率为中心的新版控制台，此后许多用户就新旧两种控制台体验分享了反馈。公告写明，基于这些反馈，新版控制台将成为所有人的默认体验。公告列出了新版控制台可以做的四件事，变更记录把同样的内容归并为三个要点。各项功能与GitHub Docs的描述在后续章节整理。未能确认的事项连同原因一并汇总在「未能确认的内容」一节。

变更记录中明确的新控制台主要构成

社区公告以四个条目列出了新版控制台可以做的事。变更记录把其中第一、二项合并为一个要点，因此共有三个要点。

  • 集中在一处: 在一处查看活跃智能体任务会话（active agent sessions）、Issue以及拉取请求（pull requests）。
  • 筛选与条目上限: 通过筛选器选择每个区域显示的内容，每个列表最多展示12项。
  • 独立的Feed标签页: 仓库与组织的活动更新在独立的「Feed」标签页中跟进。变更记录称这是让动态流与以效率为中心的控制台保持区分。
  • 从控制台开始工作: 举例为把Issue分配给Copilot编码智能体，或在Copilot Chat中打开拉取请求。

公告称，该控制台旨在提供当前工作的聚焦视图，并帮助用户决定接下来做什么。12这个数字在两个出处里都只出现在同一句话中：筛选每个区域，每个列表最多显示12项。两个出处都没有写超出12项的内容如何查看，相关的只有GitHub Docs中智能体任务会话列表的View all（见下一节）。

整合智能体任务与Issue、PR — 以工作为核心的界面

变更记录只写了在一处查看智能体任务会话、Issue与拉取请求。每个列表中出现什么，由GitHub Docs「Personal dashboard」文档中的「Home dashboard view」部分说明。不过该部分把更新后的主页控制台描述为public preview、可能变动，并写明需要先在feature preview中启用「New Dashboard Experience」。由于这与变更记录所说的已成为默认在时间上不一致，下面的Docs描述可能写于设为默认之前。

  • 智能体任务会话: 你正在运行和已结束的Copilot cloud agent会话列表。点击「View all」会打开agents标签页。
  • 拉取请求: 你创建、审查、被提及或被请求审查的最近拉取请求列表。
  • Issue: 分配给你或与你有关的最近Issue列表。
  • 筛选与12项: 这是变更记录与公告的表述，Docs的主页控制台部分没有出现筛选，也没有12这个数字。

同一篇Docs文档在主页控制台之外还说明了「Recent activity」区域。该区域预览最近两周内的更新，最多4条；未关闭的Issue或PR出现在其中的条件包括：你创建了它、有人评论了你创建的它、它被重新打开、你被请求审查、你被指派、你在提交中引用了它、你对它发表了评论。「Top repositories」列表自动生成且不能编辑，包含你有过提交、创建或评论Issue、创建或评论拉取请求等互动的仓库，距你最后一次互动满1年后会从列表中移除。这两项在新版控制台中如何呈现，Docs没有与新版控制台关联起来描述。

围绕Issue和PR的协作方式，本博客此前在 Git与GitHub协同指南第4篇：Pull Request与代码审查 中讲过。

Feed标签页的独立 — 将动态流与核心任务区域明确区分

变更记录写明，更新动态在独立的「Feed」标签页中跟进，使动态流与以效率为中心的控制台保持区分。哪些活动会出现在动态流中，由GitHub Docs「Personal dashboard」文档的「Feed activity」部分列出。该部分写明新的动态流（new feed）同样是public preview、可能变动，并说明当你关注的人执行所列操作时，你会在动态流中看到更新。

  • Feed标签页的定义（变更记录与公告）: 变更记录写的是在Feed标签页中跟进更新，公告写的是跟进仓库与组织活动的地方。
  • Docs的动态流事件 (1): 你关注的人为仓库加星标、关注了另一位用户、创建了公开仓库。
  • Docs的动态流事件 (2): 你关注的人在你关注（watch）的仓库中创建了带help wanted或good first issue标签的Issue或PR，或向你关注的仓库推送了提交。
  • Docs的动态流事件 (3): 你关注的人派生（fork）了公开仓库，或发布了新版本。「Quickstart」文档写明，可通过动态流右上角的Filter下拉菜单选择要查看的事件类型。

变更记录没有列出Feed标签页中会出现哪些事件，因此上面的Docs列表是否与Feed标签页的内容一致，两篇文档都没有明确说明。已确认的是：变更记录把动态流放在独立标签页，Docs把动态流事件定义为上述类型。

控制台直连操作 — 联动Copilot编码智能体与Copilot Chat

变更记录举了两个可直接从控制台开始工作的例子，公告也写了同样的两个。GitHub Docs则另外说明了主页控制台中与Copilot相关的元素。

  • 把Issue分配给Copilot编码智能体: 变更记录以「assigning an issue to Copilot coding agent」为例。
  • 在Copilot Chat中打开拉取请求: 变更记录以「opening a pull request in Copilot Chat」为例。
  • Docs中的Copilot提示框: 主页控制台包含一个提示框，可以向GitHub Copilot发送提示、把任务分配给Copilot cloud agent、用Copilot创建Issue，以及用GitHub Spark开始构建。
  • Docs快速入门中的智能体跟踪: 在控制台可以直接向Copilot发送提示，跟踪你触发的最新智能体会话，通过智能体日志查看进度，并管理由此产生的拉取请求和任务。

变更记录写的是「Copilot coding agent」，Docs写的是「Copilot cloud agent」，称呼不同。浏览器端开发环境的权限问题见 github.dev一键令牌窃取漏洞分析，交给智能体的任务规范见 OpenSpec AI编码智能体规范。

切回旧版控制台的操作方法 — Preview下拉菜单

变更记录写明，若想保留以前的体验，可以随时点击「Preview」旁边的下拉菜单切回。社区公告同样写明，偏好旧版控制台的用户可以随时通过Preview旁的下拉菜单切回。

  • 操作位置: 点击「Preview」标识旁边的下拉菜单。
  • 切换时间: 变更记录与公告都写的是「at any time」，即随时。
  • 反馈渠道: 变更记录邀请用户在Community discussion中以评论形式留下问题和意见。公告则请用户评论哪些有助于提高效率、哪些造成阻碍、最希望改进什么。
  • 后续改进: 公告称，过去几周收到了大量反馈，正基于最一致的反馈主题探索若干后续改进方向。

公告写明，将在未来几周内分享这些改进的更多内容，在此期间，偏好旧版控制台的用户可以通过下拉菜单切回。

可以按以下顺序，在不改动任何设置的情况下检查。

  • 在控制台中确认活跃智能体任务会话、Issue与拉取请求区域都已显示。
  • 检查分配给自己的Issue或等待自己审查的PR，是否因每个列表12项的上限而没有出现在列表中。
  • 打开Feed标签页，检查你关注的人和你关注的仓库的活动，是否按Docs所列的类型出现。
  • 如果需要旧版界面，通过「Preview」旁的下拉菜单切回。
  • 遇到的问题或改进建议，以评论形式留在Community discussion（#208952）中。

  • 组织（Organization）或企业（Enterprise）管理员是否有策略控制，能把成员的控制台默认界面固定为旧版。任何文档中都没有记载。
  • 每个列表12项的显示数量能否在用户设置中更改，以及如何查看超出12项的Issue或PR。Docs中只有智能体任务会话的View all。
  • 通过「Preview」旁下拉菜单切回旧版界面的功能将保留多久。没有记载终止日期。
