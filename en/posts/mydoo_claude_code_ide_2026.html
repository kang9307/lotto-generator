myDoo: An AI-Native IDE with Claude Code as the Default LLM

How merging a terminal agent with a GUI editor reshapes the development experience — and where myDoo sits in the AI-native IDE landscape alongside Cursor, Windsurf, and Kiro

2026-06-23 Tech & IT

Introduction: Pulling the Agent Into the Editor

As of June 2026, AI coding tools split into two major camps. The first is AI-augmented editors — Cursor and Windsurf, which fork VS Code and add a custom AI layer on top. The second is CLI agents — Claude Code and OpenCode, which run autonomously in the terminal and understand codebases at the file-system level. Both have changed how developers work, but they have remained fundamentally separate worlds. To use an agent, you had to leave your editor. To use your editor, you stepped outside the agent's context.

Developer Lee Geun-young's myDoo, published on GeekNews (hada.io), is an attempt to close that gap. The project's one-sentence pitch captures the thesis: "I implemented Claude Code's intelligence and the convenience of an IDE in a new environment based on VS Code." The ambition is to make Claude Code a first-class citizen inside the editor — not a sidebar attachment, but the cognitive layer the editor runs on.

This piece is not a product overview. It is an analysis of why this integration matters, how myDoo differs from existing tools, and what position this approach occupies in the broader AI-native IDE movement. Because public information about myDoo is limited, I will be explicit about what is confirmed versus what is reasoned inference.

1. What myDoo Is — Claude Code as the IDE Engine

myDoo is a VS Code-based AI-native IDE that uses Claude Code as its default LLM. Built by a solo developer, it was submitted to the GeekNews Show GN section, where it received attention in the Korean developer community in June 2026.

1.1 The Core Concept: Agent as Engine, Not Plugin

The critical conceptual distinction is "plugin" versus "engine." The official Claude Code VS Code extension attaches Claude Code alongside the editor — the agent runs independently in the terminal, and the editor surfaces its output. myDoo's goal, as stated, is for Claude Code to become the editor's own cognitive layer. File navigation, editing, running tests, reviewing diffs — all of this would happen within a shared context between editor and agent.

This looks like a small distinction but matters enormously in practice. If the agent already knows which file is open, where the cursor sits, and what errors the diagnostics panel is showing, the developer never has to manually transfer that context. The quality of agent responses improves when context is automatically complete rather than manually assembled.

1.2 Why Claude Code as the Default LLM?

The choice is strategic. As of June 2026, developer surveys show Claude Code holds a 28% primary-tool adoption rate among professional developers — ahead of Cursor at 24%. Anthropic has invested heavily in the agent loop, MCP (Model Context Protocol) integrations, and tool-use reliability. By treating Claude Code as the engine rather than building a proprietary LLM layer, a solo developer can ship an AI-native IDE that inherits years of Anthropic's agent engineering. Every improvement Anthropic ships to Claude Code — better file editing, smarter context management, new MCP integrations — flows into myDoo without additional development work.

The trade-off is real, however: dependency on Anthropic's API pricing, policy decisions, and availability. Offline or air-gapped environments are a limitation. LLM layer autonomy is sacrificed for speed and quality.

2. What the Terminal-GUI Merger Changes for Developers

Let me be concrete about what this integration actually changes in the development workflow.

2.1 Eliminating Context-Switching Cost

The most common way to use Claude Code with VS Code today involves two separate windows: editor on one side, terminal running the agent on the other. A developer who wants the agent to fix an error copies the file path, copies the error message, switches to the terminal, constructs the request, and switches back to see the result. This is not just inconvenient — it breaks flow state, adds cognitive load for context assembly, and introduces error-prone manual steps.

When the agent is integrated into the editor, it already knows what the editor is looking at. The open files, cursor position, recent modifications, and diagnostics errors are part of the agent's context automatically. The developer asks the question from where they are standing, and the agent answers with full situational awareness.

2.2 Inline Diff Review Without Leaving the Editor

The most consequential moment in agentic coding is when the developer reviews and accepts the agent's changes. Terminal-based agents output diffs as text or push changes to files that the developer must then open in the editor to examine. The friction of this review step is not neutral — many developers skim or skip reviews precisely because the context switch makes thorough review feel expensive. An agent whose diffs appear inline in the editor makes code review a natural part of the coding flow rather than an interruption. This is the most concrete value of bringing the agent inside the editor: the handoff from agent to developer — the moment of code ownership transfer — becomes as low-friction as accepting an autocomplete suggestion.

2.3 Immediate Feedback Loops

Agents make mistakes, especially when context is incomplete or requests are ambiguous. In a terminal-based setup, a mistake does not become visible until the developer switches to the editor to check. In an integrated setup, the editor's diagnostics layer — compiler errors, type errors, lint warnings — reflects the agent's changes immediately. The agent can observe these diagnostics, treat them as feedback, and attempt self-correction without waiting for the developer to manually relay the information. This tightened feedback loop is a key driver of agentic reliability in practice.

3. How myDoo Differs from Cursor, Windsurf, and Kiro

Understanding myDoo's positioning requires an honest comparison against the tools that dominate the space.

3.1 Cursor — The Most Polished VS Code Fork

Cursor is the most complete product in the AI IDE market as of mid-2026. Its Tab Predictive Completion does not just autocomplete lines — it predicts entire next code blocks with high accuracy. Context awareness is deep; the agent understands the codebase structure and can reason about cross-file dependencies. Cursor builds and maintains its own AI layer rather than deferring to an external agent like Claude Code. myDoo's key difference from Cursor is not feature richness but architecture: myDoo bets that Claude Code's agent loop is worth wrapping rather than competing with.

3.2 Windsurf and the Autonomous Cascade Model

Windsurf's Cascade agent emphasizes autonomous multi-file task completion. It appeals to developers who want to hand off entire tasks rather than accelerate individual keystrokes. In 2026, Codeium transitioned Windsurf into Devin Desktop, extending this autonomous direction. The distinction from myDoo comes down to the engine: Windsurf runs Cascade; myDoo runs Claude Code. Which is better depends on the workload and is not something one can confidently answer without direct comparison on specific tasks.

3.3 Amazon Kiro — Spec-Driven Development with Cloud Integration

Kiro is the most architecturally distinctive entrant of 2026. Also built on VS Code (Code OSS), it introduces spec-driven development: before writing a line of code, the agent generates a requirements document, architectural plan, and test specification. The structured plan becomes the scaffolding for implementation. Kiro supports multiple LLMs including Claude, but its deep AWS service integration — Lambda, DynamoDB, S3, Bedrock — makes it a cloud-native tool with a clear ecosystem bet. myDoo, using Claude Code, is cloud-neutral by comparison. Kiro optimizes for large teams and AWS-centric organizations; myDoo targets individual developers who want agent power inside a familiar editor.

3.4 myDoo's Differentiator — Lightweight Integration, Claude Code Inheritance

The most important thing about myDoo's approach is what it does not do: it does not build its own LLM layer. This is simultaneously a weakness and a strength. The weakness: if Claude Code has a limitation, myDoo inherits it. If Anthropic's pricing changes, myDoo users feel it. The strength: every improvement Anthropic ships — better agent loops, new model versions, expanded MCP integrations — flows into myDoo at zero development cost. A solo developer can compete with well-funded teams precisely because they are not building what Anthropic has already built. The competitive leverage is real; the dependency risk is real too.

4. The AI-Native IDE Landscape in 2026

myDoo is not an isolated experiment. It exists within a market that is actively figuring out what an AI-native development environment should be.

4.1 Three Camps in the 2026 IDE Market

The current landscape divides into three broad positions. First, VS Code forks with custom AI layers: Cursor leads this camp with the most polished feature set. Second, cloud-integrated spec-driven environments: Kiro exemplifies this, tying the development environment to a cloud ecosystem and adding structured planning before coding. Third, lightweight integrations around mature external agents: myDoo, and to some extent Zed's pairing with Claude Code, represent this approach — wrap a proven agent in a familiar editor shell rather than building the AI from scratch. Each camp makes a different bet about what developers actually need and what the sustainable competitive moat looks like.

4.2 The Shift from AI-in-IDE to Agent-Centered Development

The 2025-2026 arc of AI developer tooling is a shift from "add AI to an IDE" toward "build around the agent and let the editor play a supporting role." Claude Code Desktop wraps the agent in a standalone app with multi-session management. Google Antigravity puts the agent orchestrator at the center. Kiro makes the spec the agent's starting point. myDoo takes the path of integrating the agent into the editor rather than promoting the agent to a standalone platform. This is a valid path — most developers spend most of their time in an editor, and meeting the agent where the work already happens has genuine UX logic.

4.3 The Role of Solo Developers in a Crowded Market

myDoo being a solo developer project illustrates something important about the current moment. Cursor has raised hundreds of millions in venture capital; Kiro is an AWS product. Yet in the AI-native IDE space, a single developer with access to Claude Code (a mature agent) and VS Code's open-source extension API can ship a compelling product quickly. The foundation model ecosystem has dramatically lowered the entry barrier for developer tools. This is not a temporary anomaly — it is a structural shift that will continue producing interesting tools from unexpected places.

4.4 Fragmentation as Discovery

The 2026 AI developer tool market is surprisingly fragmented: Cursor, Windsurf, Zed, Kiro, OpenCode, Aider, Continue.dev, myDoo, and more, each with their own approach. Short-term, this is confusing. Long-term, it is the market discovering which workflows and user segments each approach best serves. Standardization comes after the winners are known. Right now, the fragmentation is productive exploration.

5. Honest Assessment of myDoo's Position

A fair analysis requires addressing both the potential and the realistic limitations.

5.1 What Could Make This Approach Succeed

If myDoo achieves genuine context integration — where the editor's open files, cursor position, and diagnostics are automatically available to the Claude Code agent — the experience it enables is qualitatively different from running Claude Code in a separate terminal. The developer no longer manages context manually; review happens in-situ; feedback loops tighten. For developers who already rely on Claude Code heavily, having it natively embedded in their editor removes the last major friction point. This is a real and underserved use case.

5.2 What Could Limit It

Public information about myDoo is limited as of June 2026. The conceptual pitch is clear, but the technical implementation depth is not yet validated externally. The gap between "Claude Code inside VS Code" as a concept and as a deeply integrated product is significant engineering work. Sustaining that work as a solo project, while competing with teams building Cursor and Kiro, is the most challenging part of the equation. The dependency on Claude API costs also means the tool's value proposition is partly contingent on Anthropic's pricing remaining accessible.

5.3 Who Should Pay Attention

myDoo is most relevant to developers who (a) already use Claude Code heavily and want to stay in an editor environment without switching to the terminal constantly; (b) want a VS Code-based workflow without Cursor's pricing or ecosystem lock-in; or (c) are building tools in this space and want to understand what the "wrap a mature external agent" architecture looks like in practice. For primary daily-driver usage, Cursor's depth and maturity is hard to displace today. myDoo represents a direction worth tracking rather than a production-ready replacement.

6. Conclusion — The Value of This Bet

myDoo makes a coherent architectural bet: instead of competing with Anthropic on agent quality or with Cursor on editor polish, it combines both — taking Claude Code's agent capability and wrapping it in a VS Code environment that makes the agent feel native to the editor, not foreign to it.

As of June 2026, the question of what the ideal AI-native IDE looks like is genuinely open. The terminal agent camp (Claude Code, Aider) produces powerful but friction-ful workflows. The editor-AI camp (Cursor, Windsurf) produces smooth editors but with proprietary AI layers that require their own maintenance and improvement cycles. myDoo's "wrap the best available agent in the best available editor shell" approach is an underexplored path in this landscape.

Whether this specific project scales into a widely adopted tool is uncertain. What is not uncertain is the underlying thesis: the boundary between agent and editor is collapsing, and the tools that eliminate that boundary most cleanly will define the next phase of developer experience. myDoo is an early, earnest attempt to be on the right side of that collapse.
