HTTP 상태 코드는 어떻게 구성되나요?

HTTP 응답은 3자리 숫자 상태 코드로 시작합니다. 첫째 자리는 카테고리를 의미합니다: 1xx(정보), 2xx(성공), 3xx(리다이렉션), 4xx(클라이언트 오류), 5xx(서버 오류). 표준은 RFC 9110에 정의되어 있으며, 일부 코드는 IANA에 별도로 등록됩니다.

401과 403의 차이는 무엇인가요?

401 Unauthorized는 "인증되지 않음"으로, 로그인이 필요하거나 토큰이 누락/만료된 경우 사용합니다. 403 Forbidden은 "인증은 되었으나 권한이 없음"으로, 로그인한 사용자가 접근할 수 없는 리소스에 사용합니다.

301과 302의 차이는 무엇인가요?

301 Moved Permanently는 영구 리다이렉트로 검색 엔진이 새 URL로 색인을 옮깁니다. 302 Found는 임시 리다이렉트로 검색 엔진이 기존 URL을 유지합니다. HTTP 메서드 보존이 필요하면 307/308을 사용하세요.

502와 504의 차이는?

둘 다 게이트웨이/프록시 관련 오류입니다. 502 Bad Gateway는 업스트림 서버로부터 잘못된 응답을 받은 경우, 504 Gateway Timeout은 업스트림 서버 응답이 시간 내 오지 않은 경우 발생합니다. Nginx 리버스 프록시에서 자주 보입니다.

422 Unprocessable Content는 언제 쓰나요?

요청 형식(JSON)은 올바르지만 의미적으로 유효성 검사를 통과하지 못한 경우 사용합니다. 예: 이메일 형식 오류, 비밀번호 길이 부족. 400(Bad Request)이 구문 오류라면 422는 의미 오류입니다.

418 I'm a teapot은 무엇인가요?

1998년 만우절 RFC 2324(Hyper Text Coffee Pot Control Protocol)에서 유래한 농담 코드입니다. 표준 HTTP 코드는 아니지만 일부 라이브러리/프레임워크가 지원합니다. 실서비스에서는 보통 사용하지 않습니다.
