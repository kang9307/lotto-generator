该怎么读基准测试

分数表难以信赖，不是因为分数错，而是因为它们不可比。有五件事挡住了直接照搬排行榜。

  • 测量主体不同。厂商自测与第三方测量是两类不同性质的主张，混进同一张表，就分不清哪一行是哪种。
  • 配置不同。如今的模型都带推理深度旋钮。Anthropic 文档写明 effort 默认为 high，Google 文档写明 thinking_level 可从最小调到高。同一个模型，旋钮位置不同，分数就不同。
  • 污染无法从外部核实。公开题库是否混入训练数据，不看权重和数据就无从判定；封闭模型在原理上就查不了。
  • 只剩平均值，波动消失。五次崩一次的模型和每次都稳的模型可以有相同均值，在生产环境却是两回事。
  • 测量时点会漂移。模型 ID 不变，背后的服务配置仍可能变。Anthropic 写明4.6代之后的 ID 是固定快照，但并非每家都这样说明。

因此本文不搬分数表，而是把文档能证实的维度（价格、上限、生命周期、可用性）做成表格，把不能证实的维度（质量）换成读者在自己任务上跑的流程。

编程、长文与多语言的判断

这三类用途，只说有依据能说的；没依据就写没依据。

  • 编程，已证实：存在把编程用途写进名字的模型（gpt-5.3-codex，$1.75 / $14.00）。Anthropic 把 Opus 5 描述为面向复杂的智能体式编程与企业业务。xAI 另有 grok-build-0.1。
  • 编程，未证实：这些模型是否真的更擅长写代码，没有官方数值。名字与描述是意图表态，不是性能证据。
  • 编程，实务判断：编程负载输出占比大，输出单价主导总额。本文任务C（输入8千、输出4千）里，输出单价低的模型占优。工具层面的比较见编程助手对比。
  • 长文，已证实：百万token输入级别的模型有好几个，而输出上限从6.4万到38.4万差6倍。Anthropic 写明整个百万都按标准价，Google 在20万处抬价。
  • 长文，未证实：没有任何厂商公开过长输入下质量能否保持的数值。上下文上限是「能收进多少」，不是「能用好多少」。
  • 长文，实务判断：唯一的检验办法，是在上限的一半、四分之三与满值三个点上问同一个问题，比对正确率。流程在第39节的文档里。
  • 多语言，已证实：DeepSeek 文档给出的英文1字符约0.3 token、中文1字符约0.6 token；Anthropic 标注的百万token约合55.5万词或约250万Unicode字符。
  • 多语言，未证实：没有任何厂商公开分语种的质量数值。中文、韩文、日文谁更好，本文一句都说不了。
  • 多语言，实务判断：仅凭已证实的换算比就能说一件事：同等篇幅的中文文档比英文多花约一倍token。也就是说，同样单价下中文负载的实际成本更高。这与质量无关，纯粹是账面问题。

洞察一：把价格往下压的力量

已证实的单价分布有清晰的形状：同一代之内，最高与最低相差一百倍以上。gpt-5.5-pro 的输入 $30.00 与 GLM-4.7-FlashX 的 $0.07 相差428倍。

造成这种分布的力量可以分成三股。

  • 竞争压力体现为分档。各家不再只给一个价格，而是三档以上：gpt-5.6 三档（sol、terra、luna），Claude 四档（Fable、Opus、Sonnet、Haiku），Gemini 三档（Pro、Flash、Flash-Lite）。分档是守住上端价格、在下端开打的方式。
  • 规格相同，价格不同。gpt-5.6-sol 与 terra 在上下文、输出上限、截止日期、模态上完全一致，价格却差2.5倍。这说明价格挂在规格之外的某种东西上。
  • 旧世代不退场。OpenAI 留着 gpt-3.5-turbo（$0.50 / $1.50），Google 留着 Gemini 2.5 Flash-Lite（$0.10 / $0.40），智谱留着 GLM-4.5（$0.60 / $2.20）。旧世代不是消失，而是沉到低价区间。新品越多，底部越厚。
  • 公开权重的托底效应。DeepSeek 权重以 MIT 公开这件事，给同档性能的 API 价格设了上限。谁都能自建的性能，很难卖高价。
  • 导入价这种限期降价。Claude Sonnet 5 的 $2 / $10 被公告为到2026年8月31日的导入价，原定9月1日起变成 $3 / $15，后来这次涨价被撤销，$2 / $10 成了正式价格。这是限期降价也可能就此固定下来的书面例证。但无论如何，原定涨价曾写进文档这件事本身仍然成立：单价是公告，不是合同。

与此同时，把价格往上抬的力量同样写在文档里：高速模式 $10 / $50、优先处理为标准的1.8倍、限美国境内1.1倍、超过20万token的区间2倍、高峰时段2倍。基础单价在降，选项系数在增。标价看着便宜、账单却不便宜的原因就在这里。

洞察二：上下文长度为什么不等于性能

把已证实的事实摆开，结论自己就出来了。

  • 百万token输入级的模型，本次调研里就横跨五家厂商。百万已经不再是卖点。
  • 相反输出上限从6.4万拉到38.4万，差6倍。读长文档的能力与写长文档的能力是两码事。
  • Google 以20万token为界抬价，等于厂商用价格说出「长上下文更贵」。
  • Anthropic 则写明整个百万都按标准价。两家对同一功能的定价政策正好相反。
  • Google 文档提醒默认媒体分辨率上升可能撑破上下文窗口，说明存在悄悄消耗上下文的通道。
  • Anthropic 文档的表格显示，工具定义每次请求都要占掉几百token。上下文不是只被用户塞的内容填满。

由此得出的判断是：上下文上限是「能收进多少」，性能是「能在其中找出需要的东西」。前者写在文档里，后者没有。而要测后者，只能在上限的若干个点上反复问同一个问题。上下文设计本身，见上下文工程一文。

洞察三：各家侧重点不同的结构性原因

同一个市场，文档结构为何差这么多？可以从已证实的事实反推。

  • Anthropic 记录的是可预测性。退役日期、60天通知政策、各工具的token占用、缓存系数、地区名单，甚至自家弃用政策的弊端。这是评估长期合同的组织所需要的。
  • OpenAI 记录的是选项。一页三十多个模型，每个都带缓存单价；生命周期与法律条件却查不到。这是当天就要接上去的开发者所需要的。
  • Google 记录的是档位。标准、批处理、弹性、优先四档服务，加上分模态单价与按小时的缓存存储费。这是云计费的语法——用卖其他云服务的方式卖 AI。
  • xAI 记录的是产品组合。文本、图像、视频、语音放同一张表，各自用不同的计费单位。这是卖套装的方式。
  • DeepSeek 记录的是单价及其条件。缓存命中与未命中、高峰时段、分语种token换算比，文档篇幅不大，但算成本需要的值一个不缺。
  • 智谱记录的是模型数量。14个单价放一张表，规格几乎没有，还留了两个免费档。

这些差异不是口味，而是收入模式与分发渠道的投影。以企业合同为主的把生命周期与政策放前面，以自助服务为主的把价格与模型数放前面，云业务部门则把服务档位放前面。看文档结构，就能看出这家在卖给谁，也就知道你是不是他们的目标客户。

洞察四：开放与封闭的分界线在哪

「开放」这个词至少指三样东西，用已证实的案例区分。

  • 权重公开且许可无实质限制。DeepSeek-V3.2 的 MIT 许可属于这一类，使用、修改、再分发、销售都允许，只要保留版权声明。这是最宽泛意义上的开放。
  • 权重公开但附自有许可。Llama 系列通常被归在这里，但本次没能查证许可正文，条件不予引用。
  • 权重不公开、只提供 API。Claude、GPT、Gemini、Grok 属于这一类。

真正的分界点在「谁承担失败风险」。

  • 用 API，厂商承担可用性、扩容与更新，你承担退役日期与政策变更。本文核对到的2026年8月5日退役就是活例。
  • 拿权重，你承担服务、扩容与安全，换来的是没有退役——没人能把你的模型关掉。
  • 所以判断标准不是性能，而是「我们的服务是否必须活得比厂商的退役时间表更久」。合同三年、保证一年，答案已经写好了。
  • 成本上存在交叉点。本文假设负载里最便宜的 API 是月 $12.67，这个数字撑不起自建的硬件与人力。自建只在体量大得多、或有数据管控硬性要求时才成立。
  • 本地运行的硬件要求与量化取舍，见本地 LLM 运行指南；围绕开放的监管争论，见开放权重监管一文。

# 自己动手测 AI 模型 — 同条件对比测试框架

> 来源: braindetox.kr — 2026年 AI模型对比
> 这份文件不是分数表，而是**流程**。公开基准测试的分数不会迁移到你的实际工作上。
> 直接复制使用。单价请对照正文的价格表填写。
> ⚠ 这套流程不判定「哪个模型更强」。它只告诉你**在你的工作上哪一个更少出错**。

## 0. 前提 — 为什么要自己测

| 公开基准测试能告诉你的 | 它不会告诉你的 |
|---|---|
| 在某个公开题库上的正确率 | 你们内部术语、格式与例外情况的处理 |
| 厂商选择公开的项目 | 厂商选择不公开的项目 |
| 某个时间点、某套配置下的数值 | 在你的配置(推理强度、温度、工具)下的数值 |
| 平均值 | 波动。五次里是否会崩一次 |

- 基准题目是否混入了训练数据，**从外部无法核实**
- 厂商自测与第三方测量是**两种不同性质的主张**。不要混在一起排名次
- 你自己的50个任务，**对你而言**比5,000道公开基准题更准确

## 1. 同条件对比框架 — 步骤

1. **建立黄金测试集。** 真实任务30到50件。简单占四成，中等占四成，困难占两成
2. **先写下正确答案或通过条件。** 看完输出再定标准，标准就会被输出带着走
3. **固定提示词模板。** 使用第2节的模板，按任务只替换空格部分
4. **记录配置。** 模型名称、版本字符串、推理强度、输出上限、是否启用工具
5. **对每个模型用同一输入跑5次。** 每次分别记录
6. **只看输出打分。** 若能在不知道输出来自哪个模型的情况下盲评，更好
7. **写入表格。** 使用第6节的表单
8. **同时记录token与耗时。** 只测质量不测成本，结论只有一半

## 2. 提示词模板 — 把你自己的工作填进空格

```
[角色]
你是(领域)的(职位)。

[输入]
以下是(输入材料的类型)。
---
(在此粘贴真实材料)
---

[需要完成的事]
1. (任务1)
2. (任务2)
3. (任务3)

[输出格式]
- 最上方给出(摘要形式)一行
- 随后是(条目数)个条目，每个条目按(字段A) / (字段B)的顺序
- 全文不超过(长度上限)

[约束]
- 不得写出(材料)中没有的内容
- 不确定之处标注为「需核实」
- 不得使用(禁止表述清单)

[只输出上述格式。不要开场白，不要结语。]
```

- **只改空格，模板保持不变。** 模板一变，就分不清是模型差异还是提示词差异
- 在约束中放入一条**故意容易被违反的条件**。它是衡量指令遵循度的刻度
- 「不确定就标注需核实」这一条，是观察**回避方式**的探针

## 3. 一次只改一个变量

| 这次改动的 | 保持不变的 | 能知道的 | 无法知道的 |
|---|---|---|---|
| 仅模型 | 提示词、输入、配置 | 模型之间的差异 | 改提示词后结论是否会反转 |
| 仅提示词 | 模型、输入、配置 | 提示词敏感度 | 在别的模型上是否一致 |
| 仅推理强度 | 模型、提示词、输入 | 强度对应的质量与成本曲线 | 换任务后曲线是否相同 |
| 仅输入长度 | 其余全部 | 表现开始劣化的临界点 | 原因是长度还是内容 |

- 同时改两处就**无法分离原因**。即使结果变好，也不知道好在哪里
- 越着急越要守住单变量。用两个变量得出的结论，下个月还得重测

## 4. 为什么要重复跑

- 同一输入产生同一输出**没有保证**。跑一次只是一个样本
- **至少5次。** 五次里成功四次和五次全成，在生产环境是完全不同的两件事
- 只要出现一次失败，就**把那次失败留档**。失败方式才是选型的真实依据
- 次次之间波动大的模型，即使平均分高，也**难以放进自动化流水线**

## 5. 评估清单 — 连同计数方法

| 项目 | 怎么计数 | 记录单位 |
|---|---|---|
| 指令遵循 | 对要求的格式、长度、禁止项逐条判定通过或不通过 | 满足条款数 / 总条款数 |
| 输出格式稳定性 | 同一提示词5次中结构保持完整的次数 | 5次中N次 |
| 长度波动 | 5次输出的字数。最大值除以最小值 | 倍数 (越接近1.0越稳) |
| 事实错误 | 预先埋入已知答案的项目，数出错的个数 | 件 / 次 |
| 无依据的断言 | 材料中没有却被当作事实陈述的句子数 | 件 / 次 |
| 拒答与回避 | 被拒绝或以「需核实」带过的项目数及其发生位置 | 件 / 次 加上所处环节 |
| 响应时延 | 请求时刻与响应完成时刻之差 | 秒 (5次中位数) |
| Token消耗 | 响应中报告的输入与输出token数 | token / 次 |
| 需要人工返工 | 无法直接使用、需人工修改的次数 | 5次中N次 |

- **数不出来的标准就删掉。** 「读起来自然」「显得聪明」下周无法复现
- 只记一格「好/不好」，日后就不知道当时为何这样判定
- 时延要同时看**中位数**和**最大值**，不要看平均值。用户体感的是最大值

## 7. 实测自己的成本

单价请对照正文的价格表填写。这里只放**计数流程与计算公式**。

1. 选出3类代表性任务。例如: 短问答 / 长文摘要 / 代码生成
2. 每类任务**实际跑一次**，记下响应中报告的输入token与输出token
3. 若厂商提供token计数工具，用它交叉核对
4. 数清这项任务**每月做多少次**。从日志里数，不要凭印象估
5. 代入下面的公式

```
每项任务的月输入token = 单次输入token 乘以 月执行次数
每项任务的月输出token = 单次输出token 乘以 月执行次数

月成本 = (月输入token 除以 1000000 乘以 输入单价USD)
       + (月输出token 除以 1000000 乘以 输出单价USD)

总月成本 = 三类任务的月成本相加
```

6. 若任务能用上缓存，则要**把命中与未命中分开**计算

```
启用缓存后的月输入成本
 = (未命中token 除以 1000000 乘以 基础输入单价)
 + (命中token 除以 1000000 乘以 缓存读取单价)
 + (缓存写入token 除以 1000000 乘以 缓存写入单价)
```

7. 以下项目**不体现在标价里，必须另行相加**

- 网页检索、代码执行等服务端工具的使用费
- 工具定义与系统提示词在每次请求输入token中所占的份额
- 重试。失败后重发的请求同样计费
- 无法享受批处理或异步折扣的实时链路所占比重
- 按时段或地区选项产生的倍率

8. **分词器不同，同一份文档的token数就不同。** 比较厂商时不要只比单价，先确认**同一份文档在各家分别被计为多少token**

## 9. 不要这样做

- **不要去问模型「哪个模型最好」。** 这是循环论证，模型也没有依据给自己排名
- 不要把厂商公布的分数直接抄进自己的表格。各家的测量条件互不相同
- 不要把某一项任务上的胜出推广成全部任务上的胜出
- 不要只跑一次就下结论
- 不要为每个模型分别打磨提示词之后再来「比较模型」
- 不要只看价格。重试次数一多，便宜的模型反而更贵
- 不要只看质量。时延会造成用户流失

## 10. 什么时候需要重测

- 厂商发布新模型时
- 你在用的模型公布退役日期时
- 价格表发生变化时
- 公布分词器变更时 (同一份文档的token数会随之改变)
- 你大幅改写提示词时
- 每季度一次。即使什么都没发生
