査読が何を止められないのか - 「査読を通った」が保証するものとしないもの

査読は不正検知の装置として設計されていない。では読者は何を見るべきか

2026-08-02 IT・技術

序論: 論文一編で決定を下す前に

技術選定の会議で、ある方式を導入しようという提案が出たことがある。根拠は論文一編で、提案者が添えた説明は一文だった。「学会に採択された論文です。」誰も反対しなかった。私も反対しなかった。

数か月後、その方式が自分たちの環境で期待どおりに動かなかったとき、私は論文を開き直して初めていくつかのことを知った。報告された数値は自分たちとは桁の違うハードウェアで出たものであり、比較対象はすでに使っていない旧方式であり、再現コードのリンクは切れていた。そのどれ一つとして論文が隠していたわけではない。すべて本文に書いてあった。問題は、私が「採択された」という一文を読んで残りを読まなかったことだ。

そのとき初めて浮かんだ問いがこの記事の出発点である。「査読を通った」という文は正確に何を保証するのか。そして何を保証しないのか。この問いは学界の内側にいる人よりも、むしろ外側で論文を根拠として使う人にとって切実だ。私たちは査読制度の内側を見る機会がないので、通ったという信号を通ったという事実以上に解釈しやすい。

この記事の姿勢。これは学界を批判する記事ではない。特定の学会や特定の研究者を名指しもしない。目的は一つだけだ。査読制度が何を担うよう作られたのかを正確に知ること。制度が設計されていない仕事をできなかったと責めれば診断が誤り、診断が誤れば読者が取るべき対応も誤る。

1. 確認したことと確認できなかったこと

この節を先頭に置く。何を根拠にこの記事を書いたのかを先に明かさなければ、この記事自体がこの記事の戒める種類の文章になるからだ。

出発点は報道で知られたある件である。ある査読に参加した人が公開した記録に関するもので、著者名の中に実在しない名前が含まれていることを原稿自身が明かしていたにもかかわらず、その原稿が採択されたという内容として伝えられた。

私はその原文を開けなかった。アクセスが遮断され本文を確認できなかった。そこでこの記事は次の原則を守る。

  • 編数、比率、学会名、著者、査読者をこの記事で事実として記述しない。開けなかった文書の内容は引用しないというのがこのブログの規則であり、今回も例外を設けない
  • 当該の件は「報道で知られた主題」としてのみ言及し、記事の本体は確認可能な制度文書に基づく構造分析として立てる
  • したがってこの記事を読んで特定の学会の査読水準を判断してはならない。この記事にはそのような判断の根拠がない

代わりに直接開いて確認した一次文書は次のとおりである。いずれもログインなしで公開されている公式指針だ。

  • 医学雑誌編集者の国際団体が公表した著者資格の定義文書 — 著者の四要件と、その判断の責任主体
  • ある大規模学会が公開した査読者指針 — 査読者が評価するよう求められる項目と日程
  • 同じ学会の投稿案内 — 著者名の変更規定、コードとデータ提出の位置づけ、二重投稿の扱い
  • 同じ学会の大規模言語モデル使用方針 — 著者責任の範囲と査読者への制約
  • 同じ学会の倫理綱領 — 査読過程で提起しうる問題の範疇
  • 公開科学団体の事前登録報告の説明文書 — 二段階査読の構造と、それが狙う問題
  • 科学編集者協議体の著者責任指針 — ゴースト・ギフト・ゲスト著者の定義

開けなかったものも明かす。出版倫理機関の査読者倫理指針、大規模学術団体の再現性バッジ定義文書、そして先に述べた出発点の記事である。三つとも接続が遮断されて本文を確認できなかったので、この記事はその三文書の内容を記述しない。12節で改めて整理した。

特定学会の文書を引用する理由。以下ではある学会の方針原文を繰り返し引用する。その学会を問題視するためではない。むしろ逆だ。査読規定と著者規定と言語モデル方針をログインなしで全文公開している場所は多くなく、引用するには実際に開けなければならないからである。公開してあるからこそ引用できたという点は、それ自体が良い慣行だ。

2. 査読は何を検証するよう設計されたのか

まず正すべき誤解がある。査読は不正検知の装置ではない。これは制度が失敗してそうなったのではなく、最初からその目的で設計されていない。

公開された査読者指針を開くと、査読者が判断するよう求められる軸が明確に列挙されている。技術的な妥当性、記述の明瞭さ、分野に対する重要度、そして独創性だ。同じ文書は、独創性が必ずしもまったく新しい手法を出すことを意味するわけではなく、既存手法の評価を通じて新たな洞察を与えることも独創性として認められると書く。

四つの軸を一行に縮めるとこうなる。「著者が主張したことが、著者の示した根拠で、著者の言うだけ成り立つか。」この問いは原稿を協力的な文書として前提する。つまり著者が嘘をついていないという仮定の上で論証の品質を問う。

2.1 指針にないもの

同じ指針をいくら読んでも次の項目は出てこない。そして無いという事実がこの記事の核心である。

項目査読が担うよう設計された仕事設計されていない仕事確認した根拠
論証主張と根拠の整合性評価—査読者指針の四つの評価軸
記述明瞭さと構成の評価—査読者指針の四つの評価軸
寄与分野への重要度と独創性の判断—査読者指針の四つの評価軸
著者の実在—身元確認の手続きなし著者資格文書が責任主体を著者と明記
参考文献の実在—存在確認の義務なし言語モデル方針が確認責任を著者に課す
結果の再現—再現義務なしコード提出は推奨、実行はリスク告知の対象
データの実在—原資料照合の手続きなし指針のどこにも要求項目としてない
二重投稿規定違反時は不受理検出は通報と偶然に依存投稿案内の二重投稿条項

表の右列をもう一度読んでほしい。不正を捕まえるのに必要な項目がほぼ全部右側にある。査読者にその仕事をせよと求めた文書がなく、その仕事をする権限も資源も割り当てられていない。

コードの扱いがこの性格を圧縮して示す。指針は提出されたコードについて他の信頼できないコードと同様にセキュリティ上の脆弱性が含まれている可能性があると警告し、隔離された環境で扱うよう推奨する。この文の含意は明白だ。コードの実行は検証手続きではなく査読者が引き受けるリスクとして扱われている。検証段階ならこういう文は付かない。

3. 著者名を検証する主体がいない

著者名は論文で最も目につく情報でありながら、同時に最も検証されない情報である。これは推測ではなく指針の原文に書かれている。

医学雑誌編集者の国際団体による著者資格文書は、著者になるための四条件をすべて満たさなければならないと定める。着想または設計、資料の取得・分析・解釈への実質的な寄与。原稿の執筆または知的に重要な内容についての批判的な検討。出版する版に対する最終承認。そして正確性と公正性に関する疑義が提起されたときに適切に調査され解決されるよう責任を負うという同意である。

ところが同じ文書はその判断の主体を明確にする。原文の表現で、著者として名前が挙がったすべての人が四基準を満たすかを判断するのは著者たちの共同責任であり、原稿を受け取った学術誌の責任ではない。さらに誰が著者資格を満たすかを判定したり著者間の紛争を仲裁したりすることは編集者の役割ではないとも書く。

この二文を並べると構造が見える。基準はあり、その遵守を確認する外部主体はいない。著者名は検証される対象ではなく申告される対象だ。納税申告と同じ構造だが、違う点が一つある。税には事後の調査機関があるが、著者名にはそれに当たる常設機構がない。

3.1 ゴースト・ギフト・ゲスト

科学編集者協議体の著者責任指針は、歪んだ著者表記を三種類に分ける。三つとも名前が実在するかとは無関係な問題であり、それゆえ確認がさらに難しい。

  • ゲスト著者。その名前が載れば掲載可能性が高まるという期待から載せた場合。実際の寄与はない
  • ギフト著者。部署の責任者のように研究との結びつきが希薄な関係を根拠に名前を与えた場合
  • ゴースト著者。研究や分析や執筆に実際に参加したのに名前も言及もない場合
  • 同じ指針は、編集者が寄与内容を明らかにするよう求めるべきであり、査読過程で著者表記が変わるかを注視すべきだと書く。しかしこれは監視であって検証ではない

学会規定も同じ性格である。ある投稿案内には要旨締切以降は著者の追加や削除ができず、投稿締切前まで順序の変更だけが可能という条項がある。この条項の目的は名簿を確認することではなく名簿を固定することだ。固定は事後の操作を難しくするが、最初に書かれた名簿が真かは問わない。

  • 所属機関は自己申告である。機関に照会する手続きが標準として存在しない
  • メールアドレスも到達可否だけが確認される。到達するとはそのアドレスが生きているという意味であって、その人だという意味ではない
  • 寄与記述がある場合でも記述の内容と実際を照合する方法がない
  • 匿名査読では査読者が著者をそもそも見られないので、著者検証は構造的に査読段階の外にある

4. 自己申告が通るということの意味

ここではこの記事の出発点となった件の構造的な意味だけを扱う。事件そのものは確認できていないので、以下は仮定法として読むべき議論である。

仮定してみよう。ある原稿が本文の中で自ら「この論文の著者名には実在しない名前がある」と明かしたのに採択されたとする。このとき私たちが知りうるのは何か。

まず知りえないことから整理するほうがよい。

  • 査読者が不誠実だったことを知りうるわけではない。自己申告を見落とすことと不正に目をつぶることは別の事象だ
  • その分野の研究水準について知りうるわけではない。標本が事実上ない
  • 査読制度が全面的に崩壊したことも知りえない。一事例は一事例である

知りうることは一つだ。査読者の注意は原稿全体に均質に配分されない。これは驚くことではなく、実はあらゆる文書検討がそうである。査読者の視線は特定の地点に集まる。

  • 要旨と結論。まず何が主張されているかをつかむ
  • 表と図。数値が主張を支えるかを見る
  • 比較基準線。何と比べたかが評価の半分だ
  • 手法の節。再現可能な水準で書かれているかを見る
  • 関連研究。自分の領域から抜けているものがないかを見る

この一覧にない場所が死角である。謝辞、資金表記、著者所属、付録の末尾、そして本文中の予想外の一文。不正を見つける仕事は「予想していないもの」を発見する仕事であるのに対し、査読は「主張されたもの」を評価する仕事だ。二つの作業は訓練も違えば読み方も違う。

だからこの件の教訓は「査読者が怠けた」ではなく「査読という作業の種類が不正検知と違う」である。後者として読んで初めて対応が出る。前者として読めば出てくる対応は人をもっと追い立てることだけだが、次節で見るようにその余地はもうほとんど残っていない。

5. 査読者の条件 - 無報酬、締切、ばらつき

査読者を責める前に、査読者がどんな条件で働いているかを見るべきだ。公開文書で確認できるものだけを記す。

条件実際不正検知に必要なもの差
報酬無報酬の奉仕が標準追加調査の時間に対する対価請求する相手がいない
期間公開日程の例で五週間ほど引用照合と再現に必要な反復作業本業と重なる
担当量一人が複数編を担当一編ごとの精読深さと編数がトレードオフ
専門性キーワードと入札で割り当てらればらつきが大きい当該下位分野の詳細知識隣接分野への割り当てが多い
権限原稿と付録しか見ない機関照会・原資料要求・身元確認権限そのものがない
道具守秘規定により外部ツールの持ち込みに制約大量照合のための自動検査規定と必要が衝突する
制裁遅延や低品質だと自分の論文の査読閲覧が制限されうる正確さへの報酬遅さは罰し深さは報いない

最後の行が特に重要だ。ある査読者指針には査読が遅れたり品質が十分でなければ、自分が共著者として参加した論文の査読結果を閲覧できなくなりうるという趣旨の条項がある。こうした仕掛けは提出そのものを促すには効果的だが、「もっと深く掘れ」という方向には働かない。深く掘るほど締切のリスクだけが増すからだ。

構造を人のせいにしないこと。上の表のどの行も個人の誠実さで埋められる差ではない。無報酬の人に調査官の役割を期待するのは設計ではなく願望である。改善を語るなら報酬、権限、道具の三つのうち一つ以上を実際に変える話でなければならない。

6. AIが作った圧力 - 方針原文が認めた範囲で

この節は特に慎重に書く。生成系のツールが投稿品質に与えた影響について数値を断定する根拠を私は確認できなかった。だから数字を語らない。代わりに方針文書が何を明文化し始めたかだけを見る。規定はたいてい実際に起きた問題を追って作られるので、規定の存在自体が弱い信号になる。

確認した言語モデル方針には次の内容がある。

  • 著者は論文のすべての内容に責任を負う。原文は本文、図、参考文献の全体が著者責任だと明記する
  • 違反例として言語モデルが生成した参考文献を、正確性・存在の有無・適切性の確認なしに使用することが明示されている。参考文献の存在の有無を確認項目として書いた点が示唆的だ
  • 手法の実装に言語モデルを使い、それが重要または独創的または非標準の構成要素であるなら実験設定の節に記述しなければならない
  • 一方でスペルチェック、文法提案、編集目的のプログラミング補助は記録義務がないと明記する。つまり方針はツールの使用を禁じるのではなく責任の位置を固定する

査読者側の制約は方向が逆である。

  • 査読者は査読過程のあらゆる側面を秘密に保たなければならず、投稿物に関する情報を誰とも、どの言語モデルとも共有・議論・開示してはならない
  • 査読のために提出されたコードはいかなる言語モデルを含め誰にも配布できず、査読以外の目的に使用できない
  • 一般的な概念理解のためには使えるが、秘密資料を入れた瞬間に禁止だ

ここで非対称が生じる。原稿を作る側は自動化ツールを自由に使え、その使用を記録する義務も限定的だ。一方で原稿を検討する側は守秘のために原稿を自動化ツールに入れられない。生成の速度と検討の速度が同じ道具から同じだけ利益を得られない構造である。

この非対称は規定の誤りではない。守秘は査読制度の根幹であり手放せない。ただし結果として検討側の処理量が生成側に追いつきにくいという事実は認識しておく必要がある。これ以上は確認された根拠がないので語らない。

確認できず語らないこと。近年の投稿数の伸び幅、生成テキストを含む原稿の比率、それによる査読品質の変化。この三つはよく引用されるが、今回は一次統計を開けなかった。だからこの記事には関連する数値が一つもない。

7. では論文をどう読むべきか

ここまでの結論を一文に縮めるとこうなる。「査読を通ったか」は情報量が非常に少ない信号だ。その席を代わりに埋める信号は「何が公開されたか」である。

まず通過が保証することと保証しないことを分けておこう。

  • 保証する。形式要件を満たした。分量、書式、匿名化、二重投稿でないことなどの機械的な関門を通った
  • 保証する。最低二人以上の同僚が原稿を読み、示された根拠で主張が成り立つと判断した
  • 保証する。明白な論理的欠陥やよく知られた先行研究の欠落は濾された可能性が高い
  • 保証しない。結果が再び出るということ
  • 保証しない。データと著者が実在するということ
  • 保証しない。利益相反がないということ
  • 保証しない。のちに反証されないということ
  • 保証しない。あなたの環境で同じ効果が出るということ

下の表は通過の可否の代わりに見るものだ。左から右へ読めばよい。

確認対象強い信号弱い信号信号なし
コードリポジトリ公開と論文の数値を出す実行スクリプトリポジトリはあるが設定が論文と違う要請があれば提供という文言だけ
データ公開データと前処理手順を含む申請手続きを経れば接続可能内部データのため公開不可
条件ハードウェア・規模・分布を表で明示本文に散らばって記述条件の記述がない
比較基準線最新方式と比較しチューニング予算を明示比較はあるがチューニング条件が不明自分の旧版としか比べていない
失敗の報告うまくいかない条件を本文に書く限界の節が形式的に存在限界への言及がない

この表の使い方は単純だ。「信号なし」の列に印が複数集まれば、その論文は決定の唯一の根拠になれない。参考文献にはなるが根拠にはならない。逆に「強い信号」が複数あれば、査読を経ていないプレプリントでも確認可能な文書である。

主張そのものをどの層で読むべきかは別の問題だ。特定分野の発表文で「破った」のような語が実際に指す範囲を切り分ける方法は「AIが暗号を破った」という発表を検証する方法で別途扱った。この記事は制度が何を確認したかを、あちらは主張が何を意味するかを見る。

8. エンジニアへ - 技術的意思決定の根拠に使うとき

論文を読む目的が学術的関心ではなく意思決定であるときは確認項目が変わる。決定は覆すのに費用がかかるからだ。

  • 再現コードのリンクを実際に押してみる。切れたリンクは驚くほど多い。押すのに三秒しかかからない
  • リポジトリの既定設定と論文の表を照合する。二つの値が違えば論文の数値は再現されない
  • 最終コミットの日付を見る。論文以降一度も触れられていないリポジトリは維持計画がないという意味だ
  • データのライセンスを確認する。研究目的限定のデータで出した結果は商用環境にそのまま移せない
  • 規模の差を数字で書く。「うちより大きい環境」ではなく「うちの八倍」と書いて初めて判断になる
  • データ分布の差を書く。言語、ドメイン、長さの分布が違えば相対的な利得はたいてい縮む
  • 比較対象が自分たちの使うものかを見る。すでに使っていない旧方式との比較は自分たちに意味がない
  • 資金源と著者所属を見る。比較対象が競合製品ならチューニング予算の対称性をより丁寧に確認する
  • 後続の引用を一度ざっと見る。反論論文や再現失敗の報告があればたいてい引用一覧に表れる
  • 最も重要なこと。自分の環境で最小の規模で一度回してみる。論文二十編よりこの一回のほうがよい

8.1 意思決定の記録に書くこと

意思決定の文書に「論文Xを根拠とする」とだけ書けば、後でその決定が誤っていたときに何が誤っていたのかを探せない。下の形で書いておけば覆しが容易になる。

[技術意思決定の記録]
根拠文献   : 題名 / 著者 / 年 / 掲載形態(プレプリント · 学会 · 学術誌)
接続経路   : アドレス / 確認日 / 版(v1 · v2 · 最終版)
使った数値 : 表3の遅延時間P99   ← 本文の記述ではなく表から
その条件   : アクセラレータ8枚 · バッチ64 · データA · 合計12時間
自分の条件 : アクセラレータ2枚 · バッチ8  · データB
差の要約   : 演算4倍の差 · データ領域が異なる
再現コード : あり / なし — あればコミット識別子
実行の有無 : はい / いいえ — はいなら結果を一行で要約
利益相反   : 資金源 · 比較対象が競合製品か
覆しの費用 : この決定が誤っていたとき原状復帰に要する作業量

この記録の効用は時間が経ってから現れる。半年後に問題が起きたとき、「条件が違った」のか「論文が誤っていた」のか「自分たちが移し方を誤った」のかをこの表だけで切り分けられる。三つの場合で対応がまったく違う。

9. 改善の試み - 確認できたものとできなかったもの

制度を変えようとする試みはいくつもある。ここでは私が一次文書を開いたものだけを記述し、残りは名前だけ挙げて効果を語らない。

事前登録報告は一次文書を確認した。構造はこうだ。研究を終えてから結果を持って査読を受ける通常の順序を逆転させ、資料収集の前に研究計画をまず査読する。第一段階で序論と手法と予備データを提出すると、査読者が研究課題の重要性と手法の妥当性を評価し、通過すれば原則的採択を受ける。原文の表現では、著者が承認されたプロトコルどおりに実験を遂行すれば学術誌が事実上掲載を保証するという意味である。第二段階で結果と考察を提出し、結果がどう出ようとプロトコルを守っていれば掲載される。現在300を超える学術誌がこの形式を提供していると説明文書は記す。

この形式が狙う問題も文書に明示されている。低い検出力、選択的な結果報告、出版バイアスだ。結果を見る前に分析を確定するので、事後に仮説を変えたり有利な分析だけを選んだりすることが難しくなる。

重要な限界。事前登録報告は著者の実在や引用の捏造を狙った装置ではない。狙う対象が違う。この記事の出発点となった種類の問題に対して事前登録報告は答えではなく、そう紹介するのは不正確である。良い制度がすべての問題の答えではないという点をここで明確にしておく。

試み狙う問題この記事での確認状態記述の範囲
事前登録報告選択的報告 · 出版バイアス · 低い検出力一次文書を確認構造と狙う対象まで記述
言語モデル使用方針生成テキストの責任帰属一次文書を確認条項の内容まで記述
著者資格基準ゲスト・ギフト・ゴースト著者一次文書を確認基準と責任主体まで記述
公開査読査読過程の不透明さ一次文書を開けなかった効果を記述しない
再現性バッジコードとデータ公開の誘因定義文書を開けなかった定義を記述しない
査読者倫理指針利益相反 · 守秘 · 通報経路一次文書を開けなかった条項を記述しない
査読への報酬無報酬の構造確認資料なし言及のみ

表の下半分がこの記事の誠実さである。名前を知ることと内容を知ることは違う。公開査読と再現性バッジについて私は名前だけを知り定義を確認できなかったので、「効果がある」とも「効果がない」とも書く資格がない。

研究者個人の姿勢がこの構造の中でどんな意味を持つかについては機械学習研究の禅と芸術で扱った。この記事が制度を見るなら、あちらは人を見る。

10. 自分のブログや文書に適用する

この議論は学界の内側の話で終わらない。技術ブログを書いたり社内文書を作ったりする人は毎日出典を引用する。そのときに守る規律がある。

まず出典の格を区別しておこう。格は信頼度の順位ではなくどんな検討を受けたかの名札である。

形態通った関門速度引用時に文へ入れる語
プレプリントなし(著者が掲載)最も速い「査読を経ていないプレプリント」
ワークショップ発表短い査読 · 進行中の研究も可速い「ワークショップ段階の報告」
学会本会議正式査読1ラウンド · 締切固定中程度「その年の本会議に採択された論文」
学術誌掲載修正の往復が複数回可能遅い「学術誌掲載論文」
標準・規格文書機構の手続き · 合意基盤最も遅い「規格文書の条項」
企業の技術ブログ内部検討のみ(外部査読なし)速い「メーカー自身の発表」
二次報道編集検討速い「報道で知られた内容」

格を明かすだけで読者が得る情報は大きく増える。「研究によると」という表現はこの七行を全部つぶす。

10.1 引用文のテンプレート

良い : 「その年の学会本会議に採択された論文は表2で …と報告する」
良い : 「プレプリント段階の報告であり外部査読を経ていない」
良い : 「メーカーが自社ブログで公開した数値であり独立検証は確認できなかった」
良い : 「原文を開けなかったのでこの記事では内容を記述しない」

悪い : 「研究によると …である」            出典の格が消える
悪い : 「学界が立証した」                   一編を合意に変える
悪い : 「論文で明らかになった」             誰が何をどの条件でかがない
悪い : 「報道によれば論文は …という」       二次引用を一次のように使う
悪い : 「最近の研究は …」                   時点も編数も特定されない

ここに加える規律がいくつかある。実際に守るのは難しくなく、守れば文章の寿命が延びる。

  • 開けなかった文書は引用しない。要約や報道だけを見て原文を引用したかのように書かない。この記事の1節と12節がその規則を適用した結果だ
  • 確認日を書く。文書は静かに変わる。日付がなければ後で照合できない
  • 原文の表現を移すときは移したものだと明かす。要約と引用を混ぜるとどこまでが原文か消える
  • 数値は表から取る。本文の要約文はすでに著者の解釈が一度入った値である
  • 一編を合意に膨らませない。「研究者たちは …と見る」は複数編を確認したときだけ使う
  • 否定的な結果も同じ基準で扱う。自分の主張に有利な論文だけ格の検査を免除すれば、それが選択的報告だ
  • リンクは原文へ張る。要約サイトを経由すると読者が原文を確認する経路が一段遠くなる

11. 査読の経路を一枚で

ここまでの話を図一枚に縮めるとこうなる。

投稿
 │
 ├─ 形式確認 : 分量 · 書式 · 匿名化 · 二重投稿の有無
 ├─ 割り当て : キーワードと入札で査読者をマッチング
 ├─ 査読     : 妥当性 · 明瞭さ · 重要度 · 独創性
 ├─ 討議     : 著者の反論と査読者間の調整
 └─ 決定     : 採択 · 不採択

この経路のどこにも次の段階はない
   著者の実在確認 · 所属照会 · 参考文献の存在確認 · 結果の再現 · 原資料の照合

したがって「採択」が意味するのは
   上の五段階を通過した   (そしてそれだけである)

この図で読むべきはない箱である。制度はある箱だけを遂行する。ない箱を期待するのは制度の問題ではなく読み方の問題だ。

12. 確認できなかったこと

この記事が根拠を示せないものをまとめておく。後にこの記事を引用する人がいるなら、この一覧まで一緒に読むべきである。

  • 出発点となった個人ブログ記事の本文。接続が遮断されて開けなかった。だから編数・比率・学会名をこの記事で扱わなかった
  • 出版倫理機関の査読者倫理指針。接続が遮断されて開けなかった。査読者が明示的に求められていないことは何かについて最良の根拠になる文書なのに、今回は使えなかった
  • 大規模学術団体の再現性バッジ定義文書。二つのアドレスともに接続が遮断された。だからバッジの各等級が何を認証し何を認証しないのかを記述しなかった
  • 公開査読の効果に関する一次資料。確認できなかった
  • 投稿数の増加に関する公式統計。確認できなかった。だから6節に数値がない
  • 査読者一人あたりの実際の割り当て編数。指針では確認されなかった。「複数編」という表現以上には書かなかった
  • 分野ごとのばらつき。この記事が引用した文書は医学系の著者基準とある計算機系学会の方針に偏っている。他分野にそのまま一般化する根拠はない
  • 査読通過と後続の再現成功率の関係。確認できなかった

13. 結び: 通ったかではなく何が公開されたか

この記事の結論は学界への冷笑ではない。正反対だ。制度を正確に理解すれば制度にないものを期待しなくなり、その席を自分の確認で埋められる。

査読はこの一世紀のあいだ大変に有用な仕事をしてきた。明白な誤りを濾し、論証を磨かせ、分野の共通基準を作った。これらすべては著者が正直であるという前提の上で論証の品質を問う作業であり、制度はその仕事を担うよう設計された。設計目的の外の仕事ができないからといって制度が失敗したわけではない。

ただしその前提が揺らぐ局面が来れば、補完は制度の内側だけでなく読者の側でも起きなければならない。そして読者にできることは思ったより具体的だ。

  • 「通ったか」の代わりに「何が公開されたか」を問う。コード、データ、条件、利益相反
  • 引用するとき出典の格を文に出す
  • 開けなかった文書は引用しない
  • 意思決定の文書には論文のどの表、どの条件、自分たちとの差を書く
  • そして可能なら最小の規模で一度回してみる

冒頭の会議に戻ってみよう。あのとき必要だったのは「学会に採択された論文です」への反論ではなかった。「その論文で私たちが使う数値は何番の表で、その表の条件は何で、私たちの条件とどこが違いますか」という問い一つだった。その問いは誰も責めず、何の知識も要求せず、三十秒あれば投げられる。

# 論文判別チェックリスト — 「通ったか」ではなく「何が公開されたか」

> 出典: braindetox.kr — 査読が何を止められないのか
> 根拠: 著者資格基準1件、学会の公開方針4件、公開科学団体の文書1件、編集者協議体の指針1件(すべて直接開いて確認)
> この文書をAIに貼り付けて「以下の基準でこの論文を点検して」と書けばよい。
> ⚠ この文書は特定の学会や研究者を評価しない。制度の設計範囲を整理したものである。

## 0. 前提 — 査読通過が意味すること

| 区分 | 内容 |
|---|---|
| **保証する** | 形式要件の通過 · 同僚が論証は成り立つと判断 |
| **保証しない** | 結果の再現 · データの実在 · 著者の実在 · 利益相反なし |
| **設計目的** | 論証の品質評価(著者が正直という前提の上で) |
| **設計の外** | 不正検知 · 身元確認 · 原資料の照合 |

**査読通過は品質保証ではなく最低限の関門通過である。**

## 1. 出典の格 — 引用文に必ず出すこと

| 形態 | 通った関門 | 引用の語 |
|---|---|---|
| プレプリント | なし(著者が掲載) | 「査読を経ていないプレプリント」 |
| ワークショップ | 短い査読 · 進行中の研究も可 | 「ワークショップ段階の報告」 |
| 学会本会議 | 正式査読1ラウンド | 「その年の本会議に採択された論文」 |
| 学術誌 | 修正の往復が複数回 | 「学術誌掲載論文」 |
| 標準 · 規格 | 機構の手続き · 合意 | 「規格文書の条項」 |
| 企業ブログ | 内部検討のみ | 「メーカー自身の発表」 |
| 二次報道 | 編集検討 | 「報道で知られた内容」 |

## 2. 公開信号の点検 — 8項目

- [ ] **コード** リポジトリが公開されリンクが生きている
- [ ] **コード** リポジトリの既定設定が論文の表と一致する
- [ ] **データ** 公開であるか接続手続きが明示されている
- [ ] **データ** ライセンスが自分の用途を許す
- [ ] **条件** ハードウェア · 規模 · 分布が表で明示されている
- [ ] **基準線** 比較対象が最新で両者のチューニング予算が対称
- [ ] **限界** うまくいかない条件が本文に書かれている
- [ ] **利益相反** 資金源と関係が明示されている

**「信号なし」が3項目以上なら決定の単独根拠にしない。**

## 3. エンジニアの実行点検 — 決定の前に

- [ ] 再現コードのリンクを**実際に押した**
- [ ] リポジトリの**最終コミット日**を確認した
- [ ] 論文の条件と自分の条件の差を**数字で**書いた
- [ ] 比較対象が**自分たちが実際に使うもの**か確認した
- [ ] 後続の引用で**反論や再現失敗の報告**をざっと見た
- [ ] **最小の規模で一度回してみた**

## 4. 意思決定の記録書式

```
根拠文献   : 題名 / 著者 / 年 / 掲載形態
接続経路   : アドレス / 確認日 / 版
使った数値 : 表番号と項目(本文の要約ではなく表から)
その条件   : ハードウェア · 規模 · データ · 所要時間
自分の条件 : 同じ項目で
差の要約   : 倍率と領域の差
再現コード : あり(コミット識別子) / なし
実行の有無 : はい(結果を一行) / いいえ
利益相反   : 資金源 · 比較対象
覆しの費用 : 誤っていたときの原状復帰作業量
```

## 5. 引用の規律 — 7行

- [ ] **開けなかった文書は引用しない**
- [ ] 確認した**日付**を書く
- [ ] 原文の表現を移すとき**移したものだと明かす**
- [ ] 数値は**表から**取る
- [ ] 一編を**合意に膨らませない**
- [ ] 自分の主張に**不利な資料も同じ基準**で扱う
- [ ] リンクは**原文へ**張る

## 6. してはならないこと

- ❌ **「研究によると」**でつぶす — 格が消える
- ❌ **「学界が立証した」** — 一編を合意に変える
- ❌ **査読通過を事実確認と読む**
- ❌ **査読者個人を責める** — 無報酬 · 締切 · 権限なしが構造だ
- ❌ **特定の学会や研究者を名指しして嘲る**
- ❌ **学界は腐っているという類の結論** — 診断が誤れば対応も誤る
- ❌ **二次報道を一次引用のように使う**
- ❌ **開けなかったページの内容を記述する**
